## 3. 部署步骤
1. 选择**用户在场**的时段：重启会**终止所有运行中的子代理**，且平台存在"点火重启后恢复链曾断裂"的已知缺陷
   （可能需再发一条消息才能恢复会话）。
2. 触发重启（`bootstrap_reboot`，`deployment_mode=desktop-build` 默认即：停止 → 编译 → 事务部署 → 校验 SHA-256 → 重启）：
   - **前端必须一起走**：`frontend_mode=build`（从源码重建 Admin 前端并投放到 `wwwroot/admin`）
     或 `frontend_mode=load`（投放已构建好的 dist）。
   - **`frontend_mode=skip` 会导致前端改动不生效** ⇒ 本次部署**不要用 skip**。
   - **⚠️ 预验证已过期（2026-09-21 复测）**：`BUILD_EXIT=0`、`✓ Built in 25113ms`、`dist/` 150 文件 / 32.5MB 那次
     是在**更早的修订**上做的。其后**有生产级前端改动**：
     `src/layouts/AdminLayout/menuIcons.ts`（`c90d7dc`，补齐 `hdd`/`key` 图标映射）——
     该文件属于**产物面**（非测试），而其余后续提交均仅改 `*.test.ts(x)`。
     ⇒ **沿用旧 `dist/` 会把菜单图标修复静默丢掉**。因此：
       * **首选 `frontend_mode=build`**（部署时现场重建，慢但自证新鲜，不存在错配；失败会 fail-closed 中止）；
       * 若要用 `frontend_mode=load`：**必须先在当前修订上重跑 `pnpm run build`**，
         并核对 `dist/index.html` 的改动时间/SHA-256 与本次构建一致（不得沿用上表那次产物）。
   - 步骤失败会 fail-closed 中止（不会留下"后端新、前端旧"的半成品）。
3. 重启完成后，确认进程加载的是新二进制（如已知的"进程加载最新产物"校验方式）。

## 4. 部署后实证（**不做这一步就不得宣称"已生效"**）
1. **分类器真的在当裁判**：用审批门户的分类动作（`request_tool_approval` 的 `classify` 入口，参数以工具 schema 为准）
   对一次工具调用请求裁决，确认返回四选一结论与**逐分类可信度**，而不是 `deferred`。
2. **降级契约未被误触发**：普通（非白名单命中）工具调用应被**正常放行**；
   若出现大面积 `deferred_dependency`，优先怀疑第 2 节核查项 2（仲裁未注册）。
3. **健康面**：调用 `classifier_status` 工具应与 `GET /api/classifier-health` 返回**同一档位**
   （服务端权威：两者都直读同一 `Snapshot()`）。
4. **前端可见**：打开 Admin「安全审批」页，确认分类器健康横幅出现，且
   `configured=false` / `unknown` 时**显示为"未知"而不是健康**（这是设计红线）。
5. **审计链**：管理 API 的审计列表应能看到 `classifier_invoked` / `classifier_unavailable` /
   `full_access_*` 等事件，并且**能按这些事件筛选**（本批修好的能力）。

## 5. 回退
| 场景 | 动作 | 是否需要重新构建 |
| --- | --- | --- |
| 分类器决策异常，想立刻回到旧审查器 | 配置 `ToolApproval:Reviewer=llm` 后重启 | **否**（免重建，最快） |
| 想回退到 jev 仲裁分类器 | 配置 `ToolApproval:Reviewer=jev` 后重启 | 否 |
| 前端展示异常想撤掉横幅 | 回退前端资产（`frontend_mode=load` 投放旧 dist） | 否 |
| 代码级回退 | `git revert` 相应提交后重新部署 | 是 |

> **回退优先级**：先用**配置回退**（免重建、秒级），确认稳定后再考虑代码级回退。
