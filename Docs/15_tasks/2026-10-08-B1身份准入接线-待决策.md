# 任务卡：B1 身份准入接线

**状态**：待决策（阻塞 B1 的剩余部分与 B6 的子集校验）
**提出日期**：2026-10-08（本会话第 140+ 轮起反复请求，第 169 轮改为任务卡形式）

## 需要谁做什么

**一句话**：**决定「调用者身份能不能由 Core 在进程间声明」**，然后（若选 A）授权改动下面列出的 1–2 个装配文件。

## 背景（为什么会卡）

设计 §3.1/§3.2 规定：**身份来自 Core 的可信执行上下文**，且「不让模型填写 epoch 或 owner 来获得权限」。
这套东西已经**大部分实现并有测试**，但**没有接在活路径上**。

## 调用图事实（本轮核对，可复现）

| # | 事实 | 证据 |
|---|---|---|
| 1 | 请求契约**已强制**携带调用者身份 | `BrowserAutomationRequest(operation, **caller**, operationId, generation, …)` |
| 2 | 准入与授权逻辑**完整且有用例** | `BrowserAutomationAuthority.Admit/Revalidate` + `BrowserPageGrantTests`(22)/`ReadOnlyDelegationTests`(21)（撤权级联、过期回收、同行动者、跨 Desktop/进程拒绝） |
| 3 | **生产代码没有任何地方调用 `Admit`** | 全仓 grep：只有接口声明与实现 ⇒ 闸门**未接** |
| 4 | 身份**投影**已就绪（两处，均无用例之外的生产调用方） | `BrowserCallerIdentityProjection`（Contracts，13 例）、`BrowserCallerIdentitySource`（AgentTools，2 例） |
| 5 | **线缆类型不携带身份** | `DesktopCallContext` 只有 `DesktopId/OperationId/DeadlineUtc/CorrelationId/PermissionEvidenceSummary`（后者线上恒为 null） |
| 6 | 活路径的组成 | Core（AgentTools 工具）→ Host 桥（`PuddingHost/BrowserBridge/*`）→ Desktop 侧（`Pudding.CapabilityBroker/DesktopSession`）→ WebView2 |

## 三个选项

### A（我推荐）接受「Core 跨进程声明身份」

- **含义**：Core 把投影出的 `BrowserCallerIdentity` 放进请求（线缆字段 +1），Desktop 侧在 `Admit` 前 fail-closed 校验；**缺即拒**。
- **改动面**（约 4 处文件，其中 2 处非我所有）：
  1. `Pudding.Contracts`：线缆 DTO 增加身份字段（**非我所有**，需同意）；
  2. `PuddingHost/BrowserBridge/*`：装配请求时填入（**非我所有**，需同意）；
  3. `Pudding.CapabilityBroker/DesktopSession`：把身份传给准入（**非我所有**，需同意）；
  4. `Pudding.DesktopService`/`Automation`：准入调用点与拒绝语义（**我所有**）。
- **代价**：需要一次**跨进程契约变更**（§10 要求"同一切片一次性同步消费方"），并新增线缆字段的兼容/拒绝语义。
- **收益**：多任务/子代理可区分；**B6 的"子代理只能取父授权子集"才有依据**；审计与授权里的行动者一致。

### B 只认 Desktop **进程内**上下文

- **含义**：不接受 Core 声明；Desktop 侧用连接世代/会话自行构造身份。
- **改动面**：主要在 `Pudding.DesktopService`（我可做）——但**无法区分同一会话内的多个任务/子代理**。
- **代价**：B6 的子集校验失去依据；多页/多任务授权退化为"会话级"。**与设计 §3.2 的"绑定任务身份"不符**。

### C 暂不接

- **含义**：保持现状（`Admit` 无调用方）。
- **代价**：B1 的"准入"与 B6 的"子集"**永久悬空**；交付清单只能声明"组件级完成"，不能声明"活路径受控"。

## 验收标准（无论选哪个）

1. 活路径上存在**唯一**的准入调用点，且**缺身份/身份不可投影 ⇒ 拒绝**（有取红用例）；
2. 请求里的身份**只能**来自执行上下文（签名/字段层面排除模型可控输入）；
3. 拒绝原因**可区分**（无身份 / 非本机进程 / 已撤权 / 租约冲突），且不回退到默认允许；
4. `Admit` 的既有用例全部保持绿色；新增"活路径准入"端到端用例（替身即可）；
5. 变更同步 §10 的切片纪律：同一切片一次性同步消费方，**不加静默兼容层**。

## 我不会做什么（边界）

- **不**未经同意修改 Host / CapabilityBroker / 共享线缆契约；
- **不**在网络/线缆"顺手"增加模糊身份（如把 DesktopId 当调用者）；
- **不**为了"看起来接上了"而在 Desktop 侧凭环境推断调用者（那正是 §3.1 禁止的）；
- **不**把本卡的结论写成"已实现"。
