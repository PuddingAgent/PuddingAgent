# Desktop 部署与回滚（实测校准）

> 写这份的原因：下一次部署要有人在旁边看着（用户退出 → 我构建 → 验收），
> 而**部署动作本身**此前从没写下来过，只存在于记忆里。这里把机制和判据钉住。

## 一、关键事实：构建产物目录**就是**运行目录

`Source/PuddingDesktop/PuddingDesktop.csproj:3-4`

```xml
<BaseIntermediateOutputPath>…\temp\build\winui3\obj\$(MSBuildProjectName)\</BaseIntermediateOutputPath>
<BaseOutputPath>…\temp\build\winui3\bin\$(MSBuildProjectName)\</BaseOutputPath>
```

⇒ 普通 `dotnet build`（Debug / win-x64）直接写进
`temp\build\winui3\bin\PuddingDesktop\Debug\net10.0-windows10.0.19041.0\win-x64`，
**没有独立的"复制到运行目录"步骤**。构建成功即已部署。

这也解释了两件一直被当成"怪现象"的事：

1. **运行中构建必然失败**（`MSB3027/MSB3021`）—— 进程锁住了要覆盖的 DLL。
   正确判读是「**仪器被挡住**」，不是「代码坏了」。
2. **预验证要换输出目录**：`-p:OutDir=temp\verify-deploy\` 才能拿到真实的编译结论
   （2026-10-21 实测：exit 0、0 错误）。

## 二、部署步骤

```
① 退出 PuddingDesktop（托盘右键 → 退出；确认无 PuddingDesktop 进程）
② 备份可回滚的两个文件（见 §四）
③ dotnet build Source\PuddingDesktop\PuddingDesktop.csproj -v q --nologo
     → 期望：0 错误；177 警告属既有基线（本轮实测数字）
④ 验证跑的是新产物（见 §三）
⑤ 启动 PuddingDesktop
```

不要在 ③ 之前启动：先启动会把旧 DLL 重新锁上，白等一轮。

## 三、部署后必须证明的两条独立证据

| 证据 | 判据 |
|---|---|
进程启动时间 | **晚于** `PuddingDesktop.dll` 的 `LastWriteTime` |
程序集尺寸 | `PuddingDesktop.Foundation.dll` ≈ **197 KB**（旧产物 127 KB） |

可选第三条（符号探针，最硬）：

```powershell
Select-String -Path <dll> -Pattern 'ScribbleFromPixelTrail' -SimpleMatch -Quiet
```

新产物 `True`、旧产物 `False`。**2026-10-21 实测就是用它证明「编译过了但没部署」。**

只要有一条不满足，就按"没部署"处理 —— 不要因为"我明明构建了"就相信回执。

## 四、回滚

部署前把运行目录里的 `PuddingDesktop.dll` 与 `PuddingDesktop.Foundation.dll`
复制到 `temp\rollback-<时间戳>\`。

- `temp/` 已在 `.gitignore`（`Directory.Build.props:19` 也把它排除出编译项），
  **所以它不是持久备份**，只覆盖"这一次部署"。要长期保留请另存到 `D:\Data` 之外的位置。
- 回滚 = 退出进程 → 把备份文件复制回运行目录 → 启动。

## 五、Core 随 Desktop 一起发布（已复核）

`PuddingDesktop.csproj:58-67` 里两个 target：

| target | 时机 | 做什么 |
|---|---|---|
`BuildCoreBundle` | `AfterTargets="Build"` | 普通 `dotnet build` **就会**把 Core 发布进 `$(TargetDir)core/` |
`PublishCoreBundle` | `AfterTargets="Publish"`（除非 `SkipCorePublish=true`） | publish 时再打一次产品包 |

且缺件时直接 **Error**（构建失败），不是静默跳过：

- `core/PuddingAgent.exe` 缺失 → 「Desktop build is incomplete」
- `core/wwwroot/admin/index.html` 缺失 → 「Build PuddingPlatformAdmin first」

实测证据（2026-10-21）：用 `-p:OutDir=temp\verify-deploy6\` 预验证后，
`core\PuddingAgent.exe`（162,304 B）与 `core\wwwroot\admin\index.html` **均存在**。

⇒ 两条对部署的含义：

1. **构建 Desktop 等于同时更新 Core**，不需要再单独部署 Core。
2. **前端产物是硬前置**：`wwwroot\admin\index.html` 不在就会直接构建失败。
   部署前若前端没构建过，先 `pnpm run build`，否则会卡在一个和本次改动无关的错误上。

## 六、仍未复核

- 用 `-p:OutDir` 预验证时，子构建的 `ArtifactsPath` 被显式指向
  `temp\build\desktop-launcher-core`；这个目录与正式部署时用的是否同一份缓存，未查。
- `Tools/Dev/dev-up.ps1` 管的是**后端**（Python 进程管理 + 反向代理），
  与 Desktop 构建**不是**同一条链；不要用 `-Rebuild` 代替本节步骤。
