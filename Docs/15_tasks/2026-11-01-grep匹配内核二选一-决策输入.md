# 2026-11-01 grep 匹配内核二选一（决策输入，未裁决）

## 一句话

仓库里现在**有两个 grep 匹配内核**，在用的那个不是新组件 `PuddingGrep`。要「收归单一真源」，得先在两者间裁定一个，再决定另一边的去向。

## 事实（2026-11-01 现场核实）

### 两个实现

| | A：`PuddingCore/Tools/Retrieval/RetrievalMatcher.cs` | B：`PuddingGrep/GrepMatcher.cs` |
|---|---|---|
| 谁在用 | **`Runtime/SearchGrepTool` 正在用**（`RetrievalMatcher.TryCreate` + `TryMatch`） | **生产端零引用**：全仓 csproj 扫描只有 `PuddingGrep` 与 `PuddingGrepTests` 提到它 |
| 模式 | `RetrievalMatchMode`（Regex / Literal）+ `RetrievalCaseMode` | `GrepPattern.Regex(...)` / `GrepPattern.Literal(..., caseSensitive)` |
| 单次匹配返回 | `RetrievalMatchOutcome`：`Match` / `NoMatch` / **`Timeout`** | `IReadOnlyList<GrepSpan>`（`Index` + `Length`，可定位可高亮） |
| 超时 | `RegexMatchTimeoutException` ⇒ 返回 `Timeout` 枚举值 | 方法参数 `TimeSpan? timeout`，内部默认超时 |
| 参数校验 | `TryCreate(..., out matcher, out contractError)` | `GrepPattern.ValidationError` |
| 测试 | 覆盖在 `PuddingRuntimeTests` / `PuddingCoreTests` 一侧 | `PuddingGrepTests` **41 条**，以 BCL 当 oracle（`IndexOf` / `Regex.Matches`）逐条对照 |
| 依赖 | 在 `PuddingCore` 里（非叶子） | BCL-only **零工程依赖**，边界断言两层把守 |

### 关键差异（决定选型的那一条）

- A 只回答「这一行**匹配吗**」，并额外给出 `Timeout` 这个可分辨的失败态。
- B 回答「在这一行里**哪些位置**匹配」，返回 span 列表。

`SearchGrepTool` 当前只需要前者（输出整行）。B 多出来的定位能力现在没人消费 —— 但一旦要做「高亮命中片段」，只有 B 能做。

## 两个选项

### 选项 1：以 B（`PuddingGrep`）为单一真源，改造 `SearchGrepTool`

- 好处：匹配内核落到 BCL-only 叶子组件，边界可编译期强制；去掉 `PuddingCore` 里的重复实现；未来高亮有基础。
- 代价：`SearchGrepTool` 要接一条新依赖（Runtime → PuddingGrep）；**`Timeout` 这个可分辨失败态在 B 里是以异常还是返回值表达，需要先对齐**（B 目前只是传超时参数，没有把超时折成可判别的结果）；41 条 BCL-oracle 测试要在 Runtime 语境下再验一遍预算/行截断语义。
- 风险点：把「超时可判别」这条性质弄丢，会把 `SearchGrepTool` 现有的 `SearchAttemptOutcome.Timeout` 反馈打成普通空结果 —— 那正是 R0 要消灭的空洞否定。

### 选项 2：以 A（`RetrievalMatcher`）为单一真源，删除 B

- 好处：改动最小，`SearchGrepTool` 一行不动。
- 代价：`PuddingGrep` 连同 41 条测试一起删；丢掉 span 定位能力；`PuddingCore` 这个非叶子工程继续持有匹配内核，边界没被编译期强制。

## 我的倾向（未执行，仅记录判断）

倾向**选项 1**，但有一个前置条件必须先做：

> 让 `PuddingGrep` 能像 A 一样**把超时表达成可判别的结果**（而不是靠 catch 让调用方自己猜），
> 否则接线会顺手把「超时 ≠ 无命中」这条已经守住的性质弄丢。

这个前置很小（给 `GrepMatcher` 增加一个返回 `Matched / NoMatch / Timeout` 的入口，或让 `FindAll` 在超时时抛一个可识别的异常类型并配一条测试），但它必须先落地，再接 `SearchGrepTool`。

## 为什么现在不动手

1. 需要裁定（选 1 还是 2），不是纯技术细节 —— 选项 2 会删掉一个刚建好的组件。
2. `SearchGrepTool` 1,265 行，涉及 glob / 排除 / 行与总字节预算 / 大小写 / 候选优先级；凌晨接线风险大于收益。
3. 前置条件（超时可判别）尚未在 B 侧落地，未做就接会引入回归。

## 复现方式

```
findstr /s /m /c:"PuddingGrep" Source\*.csproj     # ⇒ 只有 PuddingGrep 与 PuddingGrepTests
findstr /n /c:"RetrievalMatcher" Source\PuddingRuntime\Tools\BuiltIns\Search\SearchGrepTool.cs
```
