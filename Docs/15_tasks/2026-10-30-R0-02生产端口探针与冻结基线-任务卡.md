## 3. 交付内容

### 3.1 `PuddingRetrievalEval.Contracts`：让 claim 可被观测（向后兼容）

`SearchProbeOutcome` 目前只有 `Hits / ElapsedMs / Success / Error`，**装不下** R0-01 的 claim，
于是「概念反例可复现」这条门禁无法被自动判定。

新增（**只加可选参数、不动既有字段顺序与名称**）：

```csharp
public sealed record SearchProbeClaim(
    string Kind,                                  // None | NoCandidates | NoMatchInScope（探针侧原样透传）
    IReadOnlyList<string> Searched,
    IReadOnlyList<string> Unsearched,
    IReadOnlyList<string> NextStepKinds);         // 例如 ["UseAlternativeFace"]
```

`SearchProbeOutcome` 追加 `SearchProbeClaim? Claim = null`。
**禁止**引用 `PuddingCodeIndex` 的任何类型 —— claim 由适配器侧映射为纯字符串。

### 3.2 `ProductionRetrievalProbe : ISearchProbe`（放在 Probe 工程）

- `Name` = `production-<intent>` 形式，报告里可区分。
- `SearchAsync`：构造 `RetrievalRequest`（默认 `RetrievalIntent.Auto`，query / maxResults 从请求传入）
  → 调 `IRetrievalPort` → 命中映射为 `SearchProbeHit(Path, Symbol, Line)`，
  0 命中时把 `RetrievalResult.Claim` 映射为 `SearchProbeClaim`。
- **探针必须只读**：见 3.4。

### 3.3 新 CLI 模式 `production`

```
--mode production
--db        <生产库路径或已冻结快照路径>
--workspace default
--project   <projectId>（可选；缺省 = 全部已登记项目）
--set       <冻结集路径>
--out       <报告基名>
--snapshot  <可选：输出快照目录；给了就先做在线快照，再从快照读>
```

输出三类产物（与既有 `measure` 风格一致）：

1. `<out>.json` —— `EvalRun` 全量（复用 `EvalRunner`，**不另写度量**）
2. `<out>.md` —— 人读报告
3. `<out>.probe.json` —— **环境冻结块**（这是本任务的核心新增物）：

```json
{
  "producedAtUtc": "...",
  "probe": "production-auto",
  "source": { "kind": "code-index", "pathOrSnapshot": "...", "sha256": "...", "bytes": 0 },
  "repo": { "headSha": "...", "headSubject": "...", "worktreeClean": true },
  "set": { "name": "...", "version": 0, "caseCount": 0, "sha256": "..." },
  "capabilities": {
    "lexical":   { "state": "executed" },
    "relations": { "state": "executed" },
    "vector":    { "state": "not-executed", "reason": "生产端口未接入向量；本探针不伪造向量数字" }
  },
  "negativeControls": [ { "query": "...", "claimKind": "None", "unsearched": ["vector"], "passed": true } ]
}
```

`capabilities` 三态必须来自**实际执行分支**，不得推断：
`executed` / `not-executed`（附 reason）/ `unsupported`。

### 3.4 数据冻结：不许直接对着运行中的生产库跑基线

Core 正在写这个库（WAL）。直接在它上面跑，「基线」会随 Core 的索引活动漂移，不可复现。

**要求**：默认先做**在线快照**再读快照：

```csharp
// 源连接只读；SQLite 官方备份 API，对源库不加写锁
using var src = new SqliteConnection($"Data Source={dbPath};Mode=ReadOnly");
using var dst = new SqliteConnection($"Data Source={snapshotPath}");
src.Open(); dst.Open();
src.BackupDatabase(dst);
```

快照落 `temp/r0-02-snapshot/<utc-stamp>/code_index.db`，**记录 SHA-256 + 字节数**写进 3.3 的 `source` 块。
`--db` 直接指快照时跳过复制（可重跑同一份冻结数据）。
