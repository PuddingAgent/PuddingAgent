# DeepSeek 浏览器修订施工指令

请按本次复核结果修复浏览器交付，严格执行 **R1 → R2 → R3 → R4 → R5 → R6**。本任务要求完成生产调用链和验收，不能以组件测试通过或连续多轮绿色代替完成。

## 1. 施工依据与起点

- [交付复核报告](../14_reports/浏览器交付代码复核与拒收依据-2026-10-12.md)：F1–F7 的事实、代码位置及证据边界。
- [代码级修订施工方案](../12_features/浏览器交付修订施工方案-2026-10-12.md)：逐文件改造、接口草案、执行时序和验收矩阵。
- [反例测试及复现命令](../../TestScripts/BrowserDeliveryReview/README.md)：11 条反例与既有对照测试。
- [原始复核证据清单](../14_reports/2026-10-12-browser-delivery-review-evidence.json)：测试终态与源文件指纹。

复核基线为 `c5869a2`，审查与施工方案提交为 `b1689c6`。历史结果是新增反例 **11 条失败**、既有对照 **10 条通过**。开始施工时先记录当前 HEAD、工作区差异，确认后续提交是否已经修复部分问题；不要直接沿用历史测试数字。

本指令是施工入口，详细代码规格以上述修订方案为准；不改变已选定的 A 方案：Core 可信执行身份跨进程声明，Desktop 根据任务授权、控制世代及原租约裁决。提交号和历史测试数字只用于定位起点，不代表当前代码的验收状态。

## 2. R1：修复执行许可与租约生命周期

按设计修改 Contracts、Automation、DesktopService：入队前只 `Admit` 一次，UI 执行前复检原始 permit/lease，禁止再次准入。连接世代在入站时捕获；取消、版本拒绝、异常等所有终态必须释放租约。浏览器调用缺少身份或世代时明确拒绝，不能跳过闸门。

必须修复三个反例：

- `TakeoverThenResumeWhileQueuedMustNotReviveTheOldOperation`
- `CancellationBeforeQueueMustNotLeakTheAdmittedLease`
- `VersionRejectionMustNotLeakTheAdmittedLease`

补充接管、切页、重连、撤销、关闭期间的队列竞态测试。旧写请求不得复活；授权阅读在接管期间仍应可用。使用可控 dispatcher 与 fake clock 验证，不用 sleep 掩盖竞态。

## 3. R2：修复完整请求指纹与原子去重

按设计修改 Broker、DesktopConnection、Bridge。指纹必须覆盖完整调用者身份、父运行身份、实例/连接世代、具体 action、目标及全部语义载荷；删除未覆盖 payload 返回空字节的兜底。进行中请求必须原子占位，重复请求等待同一结果。

必须修复四条反例：

- `CachedResultMustNotBeReplayedToAnotherCaller`
- `ConcurrentDuplicatesMustNotExecuteTwice`
- `IdempotencyFingerprintMustIncludeCallerAndCompletePayload` 的两个参数化用例。

验收必须证明：合法首次操作成功；同请求并发时 driver **恰好执行一次**；改变 caller 或载荷不得复用原结果。不能靠全部拒绝使去重测试转绿。副作用已经开始但结果未知时，不得删除操作记录后自动重新执行。

## 4. R3：接通可信任务绑定与两条传输的共同执行器

授权来自可信任务选择或受限运行策略，普通浏览器调用只消费授权。选中页面不等于授权所有任务。绑定必须校验 envelope、任务、目标、范围、有效期及父授权关系；重复绑定不得撤旧重签。

Bridge 和 gRPC 必须经过同一 Desktop 准入与执行管线。禁止无 channel 时通过 no-op 绕过授权，禁止用 `Sessions.FirstOrDefault()` 任意选会话。补齐管理授权生产路径，并按 tabs 的 list/new/activate/close 分别映射操作。

必须修复两个反例：

- `BridgeWithNoPageGrantMustRejectBeforeHandler`
- `SelectingAPageMustNotAuthorizeEveryUnrelatedTask`

使用生产组合根及协议适配器，分别验证 Bridge-only、gRPC-enabled：合法读写、无授权拒绝、跨任务隔离、只读禁止写入、接管语义、创建关闭、任务结束撤销、重连失效。允许假 driver；不允许在测试中换成另一条更安全的执行链。

R3 完成后，升级 R2 的 Bridge fixture 为 A 已授权、B 未授权，明确断言首次成功和重复执行次数，防止因新增闸门一律拒绝而获得虚假绿色。

## 5. R4：修复子代理身份解码并完成 Runtime 委派闭环

envelope、binding.apply、binding.revoke 共用身份解码，完整保留 `ParentTaskId`；非法输入返回领域错误，不让构造异常逃出 decoder。

必须修复 `ChildBindingMustPreserveParentRunOnApplyAndRevoke` 的两个参数化用例，不得通过移除子代理父身份校验使它们转绿。

随后接入真实 Runtime/Platform 子任务生命周期：使用真实子运行身份申请父授权子集，按能力投影开放工具，成功、失败、取消、超时及父终止均回收授权。必须有真实装配测试证明“子任务可读授权页、不能写或访问其他页、父撤销后子失权”。同步、异步及批量委派路径都要覆盖身份保持和回收，不能依赖父 turn 的 AsyncLocal 长期存活。

## 6. R5：完成截图到 Agent 视觉消息的闭环

`BrowserScreenshotTool` 不能只返回尺寸和 chunks 数量。通过窄 publisher 接口将图片保存到调用 workspace 的视觉工件存储，返回可解析 artifact；支持视觉的调用模型获得原生 `LlmImagePart`。AgentTools 不得反向引用 Host 或 Platform。

验收需证明分块完整性、图片有效性、预算限制、跨 workspace 隔离，以及 native image part 确实进入调用 Agent 的模型请求。区分 capture 与 read；不支持视觉的模型或协议必须明确反馈，不能谎报“已经看图”，不能自动更换模型。隐藏表面、后台 tab 的行为留到真机核验，不以黑图冒充成功。

## 7. R6：完成常规回归、固定构建与外部验收

将上述 **11 条反例迁入常规测试套件**，升级为可信授权 fixture，并补齐合法成功对照。完成 R1–R5 后运行规定关联套件和整链，交付明确的源码、测试及产物身份。

外部控制器部署指定构建；新进程内会话完成 G1–G11 功能 smoke；启动、重启、崩溃恢复、退出回收由外部控制器判定。250ms 扫描门限必须用真实驱动样本校准，不能以纯函数测试替代。

交付 manifest 必须包含源码 commit、dirty 状态、测试命令与 TRX、产物 hash、Core/Desktop/frontend 构建身份。未实际执行的真机、视觉或生命周期验收，必须明确标为“未验证”。

## 8. 施工纪律与反空转门禁

- 遵守组件 S1–S5 顺序：独立组件验证通过后再接宿主。必要的跨模块接线属于本任务范围，不再以“文件属于其他模块”要求重复授权。
- 每个切片独立提交代码、回归和日志，精确暂存，不夹带他方 WIP；日志进入 `Docs/00_changelog/`，证据进入 `Docs/14_reports/` 或 `Docs/16_qa/`。
- 不得删除关键断言、降低授权要求、绕过生产入口，或将错误行为改成测试预期。
- 不得用重试覆盖原始失败；flaky 测试需保留首次失败证据并单独归因。
- **没有代码变化、新失败或新待验证假设时，不重复跑同一套测试。连续绿色轮数不作为完成指标。**
- 环境缺失时提交具体缺口、已完成部分和交接材料，不重复生成无进展轮次。
- 本任务是浏览器交付修复；交互 HTML/表单/SVG/涂鸦作品的应用运行时继续按既有独立方案推进，不纳入本次完成声明。

## 9. 最终交付格式与完成判据

最终交付必须逐项列出 **R1–R6、F1–F7** 的代码位置、提交号、测试名称和证据。每个条目使用以下格式：

| 项目 | 必填内容 |
|---|---|
| 变更 | 缺陷编号、切片编号、修改的文件与关键方法 |
| 行为 | 原反例、修复后的可观察结果、合法成功对照 |
| 验证 | 命令、源码/构建身份、通过/失败/跳过数字、原始证据位置 |
| 边界 | 静态检查、进程内测试或真机测试；尚未验证事项 |
| 提交 | 对应 commit 与修改日志 |

明确区分三个交付层次：

1. **代码完成**：独立测试、生产装配矩阵及回归通过。
2. **ready-for-external-deploy**：提供可识别、可部署的确定构建。
3. **产品验收通过**：指定构建的真机功能、外部生命周期及性能校准证据齐备。

任何尚未执行的验收都标为“未验证”。最终答复不能仅写“全部通过”，必须说明通过了哪一层、哪些项目仍未完成。
