# G4 修复验证 · 数据需求

## 1. 背景（为什么需要这份数据）

### 1.1 问题已经定案并修复

宿主曾持续出现约 **800 MiB/s**、21 万次/秒、每次恰好 4096 字节的逻辑读风暴（内核态 56–98%）。
上一轮外部采集（`D:\Data\g4-capture\20261028-210922`）已定案：

- **根因**：`conversation_events`（370 万行）**缺 `command_id` 索引**，
  飞书流式投影的两个查询按它过滤 ⇒ 全表扫 + 临时 B 树排序。
- **已修复**：`(command_id, sequence)` 索引已在本机库建好（`CREATE INDEX` 用时 5.45 秒）。

### 1.2 已经证明的部分

- **查询计划已改善**：`SCAN + TEMP B-TREE` → `SEARCH USING COVERING INDEX`。
- **微基准 902 倍**：同一查询，走索引 0.26 ms/次 vs 强制全表扫 235.09 ms/次。

### 1.3 还缺什么（这才是本次要采的）

**缺端到端证据。** 已知 120 秒空窗监控里 IO 只有 avg 16.76 MB/s，
但**那段时间没有正在进行的流式对话**，也就是**根本没有触发条件**。

⇒ 必须采到**「存在活跃流式对话时」**的 IO 表现，才能判断修复是否真的消除了现象。

---

## 2. 要采什么

| # | 内容 | 为什么需要 |
|---|---|---|
| 1 | **10 分钟逐秒 IO 时间线**：`IO Read Bytes/sec`、`IO Read Operations/sec`，另附内核/用户态 CPU | 直接回答"还有没有发作" |
| 2 | **必须覆盖至少一次完整流式对话** | 没有流式就没有触发条件，采了也白采（见 §3 判据三） |
| 3 | **流式窗口内的托管线程栈采样**（聚合后 top 30–50 + 百分比，文本形式） | 确认原路径是否仍在执行、有无新的热点 |
| 4 | **同期逐秒 GC 与线程池指标**（GC 时间占比、线程池队列长度、线程数） | 排除"IO 降了但 GC 恶化了" |
| 5 | **元数据**：索引是否存在、进程 PID 与启动时间、窗口起止、每次流式对话的起止时刻 | 让判读能对上时间轴 |

### 2.1 关于"流式对话"的界定

指一次**完整的、有可见增量输出**的 AI 回复：

- 从用户消息被受理开始，到终态回复结束为止；
- **期间必须有中间内容逐段出现**（不是一次性给出完整答复）。

**如果 10 分钟内一次都没有出现这样的对话，本次采集即为无效窗口**（见 §3 判据三），
请如实记录"未出现流式对话"，不要把它当成"修复成功"。

---

## 3. 判读标准（请在报告里给出明确结论）

| 判据 | 条件 | 结论 |
|---|---|---|
| **一 · 修复有效** | 流式对话窗口内，逐秒 IO 读速率**始终 < 100 MB/s**（对照修复前 800 MiB/s 量级） | 修复生效 |
| **二 · 仍失效** | 流式对话窗口内**出现 ≥ 300 MB/s 的连续段** | 修复未生效，需重新归因 |
| **三 · 无效窗口** | 10 分钟内的**流式对话次数为 0** | **不可判读**，必须重采 |

补充要求：

- 若判据一成立，但**托管栈里仍频繁出现**原先那条查询路径（`ProjectContentAsync` / `ToListAsync`），
  请一并记录 —— 说明"查询还在跑但变快了"，这是正常且符合预期的，值得写进结论。
- 若 IO 降了但**内核态 CPU 仍长期偏高**，请单独指出，这可能是另一个问题。

## 4. 交付规范

### 4.1 落盘位置

```
D:\Data\g4-verify\<yyyyMMdd-HHmmss>\
```

放在仓库工作树之外，便于随时清理。

### 4.2 必须包含的文件

| 文件 | 内容 | 是否必需 |
|---|---|---|
| `manifest.md` | 采集身份与时间、**索引是否存在**、PID 与启动时刻、**每次流式对话起止**、各文件窗口、**未做到的项目** | **必需** |
| `io-timeline.csv` | 逐秒 IO 读写字节数/操作数、内核与用户 CPU | **必需** |
| `stream-windows.md` | 每次流式对话的起止时刻，以及该窗口内的 IO 峰值/均值 | **必需** |
| `hot-stacks.md` | 流式窗口内的托管栈聚合（top 30–50 + 占比） | 若采到则必需 |
| `counters.csv` | 逐秒 GC / 线程池 | 若采到则必需 |
| `notes.md` | 采集过程、异常、工具版本、限制 | 必需 |

### 4.3 格式

- 全部 UTF-8 文本，时间戳用**带时区的完整 ISO 8601**。
- IO 速率同时给 `bytes/sec` 原值（避免 MiB 换算歧义）。
- 栈采样给**聚合后**的文本表格，不要二进制或原始事件流。

### 4.4 完成后

请告知 `manifest.md` 的绝对路径。

## 5. 不需要什么

- **不需要改代码、不需要重启宿主、不需要改任何配置**。
- **不需要 SQL 语句统计**（已确认该采集层尚未部署，不必再找）。
- 不需要压测或人为制造负载；采真实场景即可。
- 不需要判定根因——**判读由维护者做**，执行者只需把数据与客观结论交回。

## 6. 一句话总结

**10 分钟逐秒 IO 时间线，期间必须真的发生一次流式对话；**
**若没有流式对话，请直接说"窗口无效"，不要报"修复成功"。**
