# 新窗口未进 TabItem 与多标签可管理性缺口（2026-10-08）

> 方法：**父级一手读源码**（file:line）+ **用户 UI 截图**为实测证据。全部结论标注已证实 / 未证实。
> 本报告只记录事实与建议，**不含代码改动**。

## 一、现象（用户一手，UI 侧唯一可见证据）

在 Agent 浏览器里点击知乎回答标题链接（`<a target="_blank" href="//www.zhihu.com/question/1999842555244860056/answer/2001017658561278552">`）后：

- Desktop **弹出了 2 个独立 OS 窗口**（各自带标题栏与地址栏，右上角有 ─ □ ✕），URL 均为该回答页；
- 应用自身的 TabItem 标签栏**没有新增标签**；
- Agent 侧探针**全部无变化**：`browser_tabs list` 仍只有 1 个 page、`browser_context get` 的 `pageCount` 仍为 1。

> ⚠️ 这条现象**只能靠 UI 看到**。Agent 的全部可见面（tabs/pageCount/locate）都看不见新窗口 ⇒ 对 Agent 属于**不可观测缺陷**。
> 我的上一轮结论「合成点击不生效」**据此被证伪**：点击生效了，只是结果落在 Agent 可见面之外。教训：**探针看不见的副作用 ≠ 无副作用**。

## 二、用户提出的三条硬需求

1. **A**：新页面必须在**同一个应用窗口的 TabItem 内**打开，不得新开 OS 窗口。
2. **B**：**Agent 必须能理解并管理多个 TabItem**；**每个 WebView 页面都是一个实例**。
3. **C**：当前实现"花费超多时间与 Tokens，完全没有达到设计目标"——提取内容与操作页面步骤过多，自带浏览器工具未满足要求。（→ 见 `Docs/11_design/浏览器工具面渐进披露与证据化回执设计-2026-10-08.md` §八「目标形态」）

## 三、取证（一手，file:line）

### F1 已证实｜Agent 浏览器的 WebView2 **没有**新窗口拦截

- `Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs:64-73` 的 `SubscribeCoreWebViewEvents` 只订阅 `NavigationStarting` / `SourceChanged` / `NavigationCompleted` / `ProcessFailed`，**无 `NewWindowRequested`**。
- 在 `Source/PuddingBrowser.WebView2` 全目录检索 `NewWindow|WindowOpen|NewWindowRequested` = **0 命中**（该目录已全量扫描，无 coverage 截断告警）。
- ⇒ 新窗口请求直接落到 **WebView2 默认行为**：开一个独立窗口；既不进 `browser.Tabs`，也不进 page 注册表。

### F2 已证实｜全仓在册的 `NewWindowRequested` 处理器是**工作台**那个 WebView，且行为是"外抛"

- `Source/PuddingDesktop/MainWindow.xaml.cs:906`：
  `_web.CoreWebView2.NewWindowRequested += (_, e) => { e.Handled = true; OpenExternal(e.Uri); };`
- 同文件 `:909-912`：跨 origin 导航同样 `e.Cancel = true; OpenExternal(e.Uri)`。
- `OpenExternal`（`:925-929`）用 `Process.Start(new ProcessStartInfo(uri.AbsoluteUri) { UseShellExecute = true })` ⇒ 交给系统默认浏览器/新窗口。
- ⚠️ 注意：`_web` 是 **Admin 工作台**（`WorkbenchHost`），**不是** Agent 浏览器（`_browser`）。但它说明"新窗口一律外抛"是该文件既有风格；Agent 浏览器一侧则是**完全没有策略**（F1）。

### F3 已证实｜多标签模型**已经存在且是 1:1**（缺口不在模型，在入口）

- `MainWindow.xaml.cs:1002-1004`（`InitializeBrowserWorkspaceAsync`）注释原文：
  *"Every live page becomes one instance tab; the old inner tab strip is gone so the outer tab and the page identity stay 1:1."*
- `SyncBrowserTabs()`（`:1010` 起）把 `browser.Tabs` 映射为 `ToolTabIdentity.Browser(page.PageId.Value)`；Tab 模型类 = `Source/PuddingDesktop/ToolTabItem.cs:13`，种类枚举含 `ToolTabKind.Browser`。

### F4 已证实｜Agent 侧 tabs 能力**齐备**（New / Activate / Close 都有）

- `Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs:234 TabsAsync`：
  `New`（`:239-265`，走 `NewPageAsync(new PageCreateOptions { InitialUrl, Activate })`）、`Activate`（`:288`）、`Close`（`:291-293`）。
- ⇒ 缺的**不是能力**，而是"**页面自身发起的新窗口请求没有走这条既有能力**"。

### F5 已证实｜真正创建 WebView2 的地方在 `PuddingBrowser.WinUI`（父级二次复核）

- `Source/PuddingBrowser.WinUI/WinUiBrowserSurfaceHost.cs:67-88` 的 `CreateAsync`：`new Microsoft.UI.Xaml.Controls.WebView2()` → 加入 `container`（**同一个 Panel ⇒ 同一个应用窗口**）→ `EnsureCoreWebView2Async` → 包装为 `Surface(pageId, control)`；**方法内无任何 `NewWindowRequested` 订阅**（只有 `:76` Ensure、`:80` Appearance）。
- 该工程内检索 `NewWindow` = **0 命中**（对照组，排除漏扫）。
- ⚠️ **更正上一版说法**：Agent 浏览器的 WebView2 **不止** `WebView2BrowserPage` 一处能拿到 —— `WebView2BrowserPage.cs:35-46` 构造函数里即 `_coreWebView = surface.CoreWebView; SubscribeCoreWebViewEvents(...)`，只是它订阅的 5 个事件（`NavigationStarting/NavigationCompleted/DocumentTitleChanged/SourceChanged/ProcessFailed`，`:64-72`）**不含** `NewWindowRequested`。⇒ **有两个可挂载点**，"唯一挂载点"的表述过强。

### F6 已证实｜"一次调用同时满足三件事"的落点：`BrowserWorkspaceController.CreatePageAsync`

- `Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs:283-318`（该目录**在编译内**，只有 `Views/` 未编译）：
  `_context.NewPageAsync(...)`（建 surface＝同窗口）→ `_pages[page.Id] = page`（**注册表**）→ `new BrowserTabViewModel{...}` + `Tabs.Add(tab)`（**TabItem**）→ 按需激活。
- 全仓 `NewWindowRequested` 在册仅 **2 处**：`Source/PuddingDesktop/MainWindow.xaml.cs:906`（工作台 `_web`，`e.Handled=true` + `OpenExternal`）与 `Source/PuddingDesktop.WpfArchive/Views/WorkbenchView.xaml.cs:122`（**未编译**，`PuddingDesktop.csproj:46-48` 不含 `Views/`）。

## 四、根因（一句话）

**Agent 浏览器的 WebView2 页面未拦截 `NewWindowRequested` ⇒ `target=_blank` / `window.open` 既没有转成同 context 的 `NewPageAsync`（= 一个 TabItem），也没有登记进 page 注册表；默认行为把内容开到了 Agent 可见面之外。**

## 五、最小改动建议（待用户批准，本报告不含改动）

1. **主修（已按 F5/F6 更正）**：在能拿到真实 `CoreWebView2` 的地方订阅 `NewWindowRequested`（`e.Handled = true`），回调**统一调到 `BrowserWorkspaceController.CreatePageAsync`**（F6：一次调用即完成 同窗口 surface + 注册表登记 + TabItem）。
   - 推荐挂载点：`Source/PuddingBrowser.WinUI/WinUiBrowserSurfaceHost.cs:76` 之后（`EnsureCoreWebView2Async` 成功、`Surface` 就绪时），监听回调参数并在 `Source/PuddingDesktop/MainWindow.xaml.cs:952-956` 装配处注入（那里同时持有 runtime / surfaces / controller）。
   - 备选挂载点：`WebView2BrowserPage.SubscribeCoreWebViewEvents`（同样持有 `CoreWebView2`），但它拿不到 controller ⇒ 仍需要同一条回调，且要同步改 WPF 宿主保持 parity ⇒ 推荐前者。
   - ⚠️ WPF 宿主 `Source/PuddingBrowser.WebView2/WpfBrowserSurfaceHost.cs:47` 有同构创建路径；若该宿主仍在用，需同样补一处。
2. **兜底**：URL 非 http/https 则忽略；新建失败要**回到当前页并给出可观测告警**，**禁止静默外抛**（静默外抛正是本缺陷）。
3. **验收口径（能取红）**：
   - 点击任意 `target="_blank"` 链接后：`browser_tabs list` 的 page 数 **+1**、`pageCount` 同步、新 page 可 `activate` 与 `close`；
   - 窗口数不变（UI 侧无新 OS 窗口）；
   - Agent 无需再用 `snapshot(include_html)` 抠 URL 绕行。

## 六、附带发现（仪器缺陷，阻碍成本度量）

`agent_diagnostics action=tool_stats` 对 `browser_interact` / `browser_locate` 返回 `total_calls=0`，并自述 **"not found in 500 RuntimeActivity records"**，`available_tool_names` 仅 `search_grep/file_read/list_dir`。
⇒ **运行时度量仪器不含 browser_\* 工具，且活动表只保留 500 条** ⇒ 无法用运行时数据做"浏览器工具成本"的证据化度量；本轮的调用计数只能**人工从会话转录统计**（本轮约 **58 次** `browser_*` 调用，其中 mutating 调用约 **14 次全部返回假失败** `mutating capability returned a page version that did not advance`，真实生效的只有 6 个动作：navigate ×1、开菜单 ×2、打开编辑器 ×1、写正文 ×1、滚动若干）。

## 七、对 Agent 自身的教训（已写入 SKILL 与设计文档）

1. **不得把"探针无变化"当成"动作未生效"**——先问"这件事的可见面覆盖到哪一层"。
2. 定位控件文本**一律用 `contains`**，精确匹配 `='编辑'` 会漏掉「编辑回答」。
3. `scroll` 位移不可预测、`click` 与视口强相关 ⇒ 每次动作后必须回读坐标/状态。

## 八、交叉核验与未证实项（诚实标注）

- 本报告 F1–F6 均由**父级一手读取源码**证实（每条给出 file:line）；F5/F6 由只读子代理提出、父级二次复核后采纳，并对子代理过强的表述做了更正。
- **未证实**：①用户截图"2 个独立窗口（同一 URL）"的**数量**没有唯一源码解释（可能对应两次点击、也可能含宿主自建重试），需**实机复现计数**；②"本机生效传输 = WebSocket Bridge、能力通道未启用"系**配置 + 代码路径推断**（`%LOCALAPPDATA%\Pudding\desktop.json:27` 为 `"desktop": null`；`D:\Data\config\system.json` 无 `Desktop:CapabilityChannel`），**未用运行时日志二次确认**。
- **潜伏风险**：能力通道模式下 `browser_tabs new`（`Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs:195-230`）**绕过** `BrowserWorkspaceController` ⇒ 新建页只有 WebView2 surface，**不产生 ToolTabItem、不进注册表**（一旦启用能力通道，Agent 新建的 tab 在 UI/准入上不可见）。
- **安全语义缺口（与既有审计一致）**：UI「人工接管」只写 controller 的 `_userTakeover`（`BrowserWorkspaceController.cs:490`，仅驱动 UI `ControlState`），**从未调用** `BridgeDispatcher.SetUserTakeover`；真闸门在 `BrowserBridgeCommandDispatcher.cs:20/45/68-79` ⇒ **UI 接管按钮当前不构成准入闸门**。
- **易误读**：未编译的 `Source/PuddingDesktop.WpfArchive/Views/` 中残留 `NewWindow` 处理器与双写 takeover 逻辑，**不在产物内**，勿当在线行为。
- **附带**：同一 `RequireVersionAdvanced` 假失败不变量（`Source/Pudding.DesktopService/DesktopMutationInvariants.cs:17-36`）对"新建未导航页"同样可能误报 ⇒ 修 TabItem 时需一并处理。
