# B7 外部生命周期验收交接单（2026-10-08）

面向**进程外控制器**。每一步都写明：**操作 → 判据 → 证据**。

## 0. 前置（必须满足）

| 项 | 要求 |
|---|---|
| 构建 | 用**明确的新构建**（`--artifacts-path temp/build/recovery`，先 restore/build，再同目录 `--no-restore`） |
| 隔离 | 使用**隔离的 DesktopHome / DataRoot / 端口**（见 `TestScripts/test-pudding-desktop-launcher.ps1`） |
| 前提 | Desktop 可发布（`temp/build/desktop-preview`）、`D:\data` **不被 dev-up 占用**（两者不共享 PID/端口所有权） |

## 1. `startup`

- **操作**：在隔离环境启动 `PuddingDesktop.exe`；
- **判据**：① Shell 出现且 WebView2 就绪；② **Core 子进程**由 Desktop 启动并监督（`core/PuddingAgent.exe --desktop-child`）；③ **不装配进程内 `PuddingHost`**；④ 若 Core 启动失败/配置缺失/DataRoot 未设置，**Desktop 仍可启动**并允许进入设置修复；
- **证据**：进程树（Desktop → Core）、`<DataRoot>/config/system.json` 读取成功、日志中无"进程内 Host"痕迹。

## 2. `restart`

- **操作**：重启 Desktop（或在运行中心执行停止→启动）；
- **判据**：① Core 子进程**被替换**（新 PID）；② 旧 Core 已退出（无孤儿）；③ 端口/锁（`.pudding-host.lock` 文件句柄租约）**未被绕过或删除**；
- **证据**：PID 变化对照、锁文件句柄仍由存活进程持有。

## 3. `crash-recovery`

- **操作**：**强杀 Core 子进程**（模拟崩溃）；
- **判据**：① Desktop **不退出**（单实例产品进程仍在）；② 按配置的自动恢复策略重启 Core；③ 失败时可从设置/运行中心**手动修复**；
- **证据**：Desktop 存活、Core 新 PID、恢复日志。

## 4. `exit-reclamation`

- **操作**：触发「退出 Pudding」（或配置 `ExitAndStopCore`）；
- **判据**：① **Core 被停止**；② **WebView2 被释放**；③ 无残留进程/句柄；④ 与"关闭按钮默认隐藏到托盘"的行为区分（后者**不**停 Core）；
- **证据**：退出后进程列表为空（Desktop/Core）、文件句柄释放。

## 5. 20× 整链 flake 门禁

- **操作**：`TestScripts/delivery-manifest.ps1 -BuildId <id>` 连跑 **20 次**（链式，失败即停并留证据）；
- **判据**：20 次**全部**产出 `ready-for-external-deploy`，且**同一 build**下通过数一致；
- **证据**：每次的 `temp/test-out/delivery-manifest.json` 与日志（**不要**只留最后一次）。

## 6. 250ms 校准

- **判据**：按设计规定的 250ms 时间预算校准项**逐项实测**（不是估算），并记录实测值与偏差；
- **证据**：校准记录表（原始值与结论）。

## 6b. 内部基线（外部 20× 执行前）

| 项 | 值 |
|---|---|
| 连跑轮次 | **5 轮全部** `ready-for-external-deploy` |
| 每轮规模 | 7 套件 / **1764 条** / 0 失败（5 轮一致） |
| 单轮耗时 | 159s / 120s / 109s（无异常尖峰） |
| 证据 | 每轮单独保存的 manifest 与日志（**不要只留最后一次**） |

**结论**：链在 5 连跑下**未观察到 flake** ⇒ 20× 门禁**可行**；**正式判定仍属外部**。
## 6c. Bridge 路由截图：**有意暂缓**（decided deferral）

- **现状**：Bridge 路由下截图返回**明确的 `UnsupportedCapability`**（"use the capability channel"）⇒ **fail-closed**，不会静默失败。
- **已提交的前置**：`page.screenshot` 命令名（含 `All` 冻结集合）与 Bridge 载荷类型（`PageScreenshotArguments`/`BrowserScreenshotDescriptor`/Chunk，Base64）。
- **暂缓理由**：表面的 `ScreenshotAsync` 依赖**能力通道的调用上下文**（身份/准入由 Core 侧接缝校验）；从 Bridge 处理器调用它必须**合成 `DesktopCallContext`** ⇒ 等于**在第二个地方重造身份与准入语义**（与"单一真源、边界显式"冲突）。
- **解除条件**：给出**跨传输统一的身份/准入方案**（如 Bridge 也走"Core 侧投影的可信身份 + 接缝校验"），或**明确规定截图仅在能力通道可用**并把该约束写进工具错误信息与文档。

## 8. 可复制命令（外部控制器用；均取自仓库既有脚本/文档，未臆造参数）

```powershell
# ① 构建隔离工件（AGENTS.md 约定：先 restore/build，再同目录 --no-restore）
dotnet restore Source\PuddingDesktop\PuddingDesktop.csproj --artifacts-path temp/build/recovery
dotnet build   Source\PuddingDesktop\PuddingDesktop.csproj --artifacts-path temp/build/recovery --no-restore

# ② 隔离启动器冒烟（TestScripts/test-pudding-desktop-launcher.ps1）
#    脚本自身会：建隔离 DesktopHome/DataRoot（temp/test-out/launcher-<guid>）、取空闲端口、
#    写 closeBehavior='ExitAndStopCore' 的 desktop.json、隐藏窗口启动 Desktop、
#    设 PUDDING_DESKTOP_HOME / PUDDING_LAUNCHER_SMOKE_REPORT，最后产出 smoke.json。
#    默认 DesktopExe = temp/build/winui3/bin/PuddingDesktop/debug_win-x64/PuddingDesktop.exe
pwsh TestScripts\test-pudding-desktop-launcher.ps1

# 指向明确的新构建时（参数名已核实）：
pwsh TestScripts\test-pudding-desktop-launcher.ps1 -DesktopExe <新构建的 PuddingDesktop.exe> -CoreExe <新构建的 PuddingAgent.exe>

# ③ 20× 整链门禁（链式，失败即停；每次都要留 manifest 与日志）
1..20 | ForEach-Object {
  & .\TestScripts\delivery-manifest.ps1 -BuildId ("ext-20x-" + $_)
  if (-not (Test-Path temp\test-out\delivery-manifest.json)) { throw "第 $_ 次未产出清单，停止" }
  Copy-Item temp\test-out\delivery-manifest.json ("temp\test-out\manifest-ext-20x-$_.json") -Force
}
```

**判据复核入口**：
- `startup`/`restart`/`crash-recovery`/`exit-reclamation` 的**逐项判据**见本单 §1–§4；
- `smoke.json` 与 `temp/test-out/launcher-<guid>/` 是**隔离证据目录**（含 dataRoot/desktopHome）；
- 20× 的**每次** manifest 与日志都要保留（§5）。

**诚实说明**：以上命令**只包含仓库中已存在的脚本与已核实的参数**（`test-pudding-desktop-launcher.ps1` 的 `-DesktopExe`/`-CoreExe`；`delivery-manifest.ps1` 的 `-BuildId`）。**未执行**这些命令 —— 它们属外部控制器职责。
