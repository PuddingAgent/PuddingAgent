# 工具参数中的 vault 引用会被替换成明文密钥

## 现象

我在给 `PuddingJwtSettings` 补一条回归测试时，在测试源码里写了一个**可解析**的
vault 引用作为被测输入。回显看起来正常，但读回文件发现落盘的内容不是引用，
而是一串 64 字符的高熵字符串。

这不是我的笔误：同一个 `file_patch` 调用里，`"{{vault:` 这个前缀活了下来，
只有**完整且可解析**的引用被换掉了。

## 证据链（全部现场实测）

| # | 判据 | 实测 |
|---|---|---|
| 1 | 落盘值与迁移前 JWT 密钥的关系 | 落盘串 SHA16 = `DEA7EC1F0B1F9A3C`；从 `config_security.json.dpapi` 解出的迁移前 `jwt.key` SHA16 = `DEA7EC1F0B1F9A3C`，**完全一致** |
| 2 | 是否只是文件工具的问题 | 用 `shell` 对同一引用求哈希：`ARG_LEN=64`、`ARG_SHA=DEA7EC1F0B1F9A3C` ⇒ 参数**进入工具之前**就是明文 |
| 3 | 对照：不可解析的引用 | `{{vault:definitely.not.a.real.entry}}`、`{{vault:`、`prefix{{vault:x}}suffix` 写入后**原样保留** |
| 4 | 是否已进入 git 历史 | `git grep -l <落盘串> HEAD` → 空（未提交过） |
| 5 | 产品源码里是否做这件事 | `git grep "InjectAsync"` 的调用点全是**逐个工具显式**解析（搜索、日历、余额、embedding、飞书、Home Assistant），没有全量改写参数的中间层 |

结论：替换发生在**工具调用入口**，规则是「能解析就替换」，且**完全静默**。

## 影响

| 通道 | 后果 |
|---|---|
| `file_write` / `file_patch` / `apply_patch` | 密钥被写进磁盘文件；一旦被提交就进入仓库，并与密钥轮换脱钩 |
| `shell` | 明文进入命令行，同机其他进程可通过进程枚举读到 |
| 工具参数日志 | 记录参数的日志/审计会捕获明文 |

触发它不需要恶意：**只要在文档或测试里引用一个真实条目**（例如为了说明某个缺陷，就像我这次）就会中招。
越是"引用配置里的密钥做演示"，越容易泄漏。

## 本次处置

| 项 | 动作 |
|---|---|
| 落盘泄漏 | 已从测试文件移除；改用 `PuddingJwtSettings.VaultReferenceMarker` 常量在运行时拼接，源码里不再出现完整引用 |
| 探针残留 | `temp\leak_probe1.txt`、`temp\vaultref_probe.txt` 已删除（temp 本身被 gitignore） |
| 顺带修的真实缺陷 | `JwtTokenFactory.FromConfiguration` 增加 fail-closed 守卫：拿到未展开引用就抛错，不再静默用公开字符串当 HMAC 密钥（`FromConfiguration_UnresolvedVaultReference_FailsClosed`，变异取红已验证） |

## 未解决

### 1. 替换层的归属还没定位

`Source/` 全树的 `InjectAsync` 调用点都是显式的，**没有**找到改写工具参数的中间层。
所以执行替换的代码不在本次 grep 到的源码范围内——可能在内嵌的平台层，也可能是
Desktop 侧的 tool bridge。**需要按工具调用入口链路逐层排查**，不能靠猜。

### 2. 建议的修法（未实施）

按"该工具是否消费凭据"区分，而不是一刀切：

- 白名单内（`http_*`、搜索、`llm`、`asr`/`tts` 等确实需要密钥的）→ 允许替换
- 文件写入、补丁、shell → **禁止替换**；命中引用时保留原文并记一条 warning

一刀切的替换看似方便，实质是让"写文件"和"发请求"共享同一份信任边界，
而这两者的风险完全不同。

### 3. 与另一处缺陷的关系

`security.json → jwt.key` 曾被迁移成引用而配置链不展开，导致 JWT 用公开字符串签名
（见 `JWT签名密钥退化为公开占位符-2026-11-17.md`）。本次发现的是**同一条链的另一半**：
配置侧的解析已经补上（`PuddingApplicationHost.cs:76` 走 `BootstrapSecretFile.Resolve`），
但工具参数侧却在无差别替换。两处共享"引用即明文"的假设，却都没有边界。
