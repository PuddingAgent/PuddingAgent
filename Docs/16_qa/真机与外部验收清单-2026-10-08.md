# 真机与外部验收清单

**为什么需要它**：按 `Agents.md` 的两段式验收，内部 Agent 只能给出 `ready-for-external-deploy`；下列结论**内部不可达**（需要真实 WebView2、真实页面或进程外控制器）。
每项给出：**观察点 / 期望值 / 判定方式 / 失败样例**。

## A. B7 外部四步（进程外控制器，来自交付清单 `requiredExternalSteps`）

| # | 步骤 | 观察点 | 期望值 | 判定方式 | 失败样例 |
|---|---|---|---|---|---|
| A1 | `startup` | 冷启动 Desktop（WinUI 3 Shell）+ Core 子进程 | 窗口出现、Core 就绪、WebView2 承载既有 Web UI | 进程外控制器观察 + 日志 | 只起 Shell 无 Core；或 Core 起来但 WebView2 空白 |
| A2 | `restart` | 从 UI/托盘"重启" | Core 被回收后以**新构建**重启；旧进程不残留 | 进程与端口观察 | 第二实例把命令转发给旧进程（单实例语义） |
| A3 | `crash-recovery` | 强杀 Core | Desktop 存活并按策略恢复；失败可见可诊断 | 杀进程 + 观察恢复 | Shell 一起退出或静默不恢复 |
| A4 | `exit-reclamation` | "退出 Pudding" | Core 子进程被回收，WebView2 释放，无残留进程/端口 | 进程与句柄观察 | 退出后仍有 Core/WebView2 残留 |

## B. B2 渐进阅读与定位（真实页面）

| # | 观察点 | 期望值 | 判定方式 | 失败样例 |
|---|---|---|---|---|
| B1 | `text` 匹配取**最小可见匹配节点** | 命中的是最小可读元素，而非其祖先容器 | 在含嵌套文本的测试页上 locate | 返回整个 `body`/大容器 |
| B2 | 空白折叠 | 多空格/换行/制表与单空格等价 | 页面上故意插入多余空白 | 因空白差异零命中 |
| B3 | `exact` 与 `substring` 区别 | `exact` 才是全等；默认按设计为子串匹配 | 用"Learn more"/"Learn more about X"对比 | 两者行为相同（无法区分） |
| B4 | **重复文本消歧** | 多处同文本时给出确定、可复现的选择（并按 `nth` 可指定） | 页面上放 3 个同名按钮 | 结果随机或永远第一个 |
| B5 | **祖先也含该文本时不得返回整页** | 仍返回最小匹配节点 | 设计文档 §6.2 的"Learn more"场景 | 返回整页/根节点 |
| B6 | **零命中不得泛化** | 零命中是**成功且空**，不影响后续其他 text 定位 | 先做一次必零命中的 text 定位，再做一次可命中的 | 第二次也失败（把一次零命中推广成"text 定位坏了"） |
| B7 | 分页缓存（若实现） | 设计值 8 snapshot/页、累计 2 MiB、TTL 60s，容量/到期有**原因码** | 连续分页 + 观察原因码 | 无上限增长或原因码缺失 |

## C. B3 真实输入与滚动（真实页面）

| # | 观察点 | 期望值 | 判定方式 | 失败样例 |
|---|---|---|---|---|
| C1 | 修饰符 | 组合键（Ctrl/Shift/Alt）按语义生效 | 真实按键序列 | 修饰符被吞 |
| C2 | selection 与插入符 | 输入后 selection/caret 位置正确 | 输入后读取状态 | 文本乱序或丢字 |
| C3 | 组合输入（IME） | 中文/拼音组合输入不被拆断 | IME 组合期间输入 | 提交中间态 |
| C4 | **pointer down/up 成对** | 每次按下都有对应抬起 | 拖拽/点击序列 | 只按下不抬起（页面卡在按下态） |
| C5 | **取消时清理按键/鼠标按下状态** | 中途取消后页面无残留按下/按键状态 | 取消一次拖拽后再点击 | 后续点击失效 |
| C6 | scroll：`document.scrollingElement` | 无 locator 时滚文档容器 | 长页滚到底 | 滚了错误容器（无效果） |
| C7 | scroll：最近可滚动祖先 | 对内部滚动区滚动生效 | 嵌套滚动容器页面 | 滚动页面而非容器 |
| C8 | scroll 边界如实上报 | `AtBoundary`/`StopReason`（如"already at the bottom"）与实况一致 | 到底后继续滚 | 谎报"已滚动" |
| C9 | `focus` 明确不支持 | 返回 `UnsupportedCapability`，**不用脚本伪造** | 请求 focus | 静默用脚本设置焦点 |
| C10 | native 输入未实现时明确失败 | `"native input is not implemented"`，且**拒绝发生在触达驱动前** | 请求 native | 静默退回 dom |

## D. B4 截图视觉（真实 WebView2）

| # | 观察点 | 期望值 | 判定方式 | 失败样例 |
|---|---|---|---|---|
| D1 | viewport 截屏 | 图与当前视口一致 | 截屏 + 人工/像素对比 | 空白图/旧帧 |
| D2 | 区域/元素裁剪 | 裁剪范围正确（含 bbox 精度规则：展示一位小数、驱动内保留精度） | 对已知元素裁剪 | 偏移/缩放错误 |
| D3 | 截屏前**就绪与授权**校验 | 未就绪/未授权时明确失败，**不切换到未授权页面** | 未授权目标请求截屏 | 截了别的页 |
| D4 | 低细节档 | 最长边 ≤512px、基准 ≤40 KiB；超预算报 `LowDetailBudgetExceeded` | 大图请求低细节 | 静默超预算或降级无提示 |
| D5 | **S-09 隐藏表面截屏观察**（一直未执行） | 隐藏/最小化时行为明确（截图不出现伪内容或明确失败） | 最小化后请求截屏 | 拿到失效帧却报成功 |
| D6 | 全页捕获/PDF（若已交付） | 与设计阶段划分一致（先视口/区域，后全页） | 请求全页 | 声称支持但输出错误 |

## 诚实边界

- 本清单**本身未被执行**（内部不可达）；它把"内部证明不了的结论"明确交接出去，避免把测试层证据当成产品结论。
- **B5 坐标操作与 B4 截图（能力通道）均已完成实现与进程内证据**（坐标：三动作 × 两传输 + 到达证据 + `observationId` 绿/红三路；截图：契约/proto/能力/线缆双向/表面/观察登记/工具/委派/行为用例，含"截图 ⇒ 签发 id ⇒ 坐标可用"）。⇒ **剩余部分全部属真机行为验证**（D 组与 E 组），不再是功能缺口。

## 更新（2026-10-08，本轮）：坐标操作已从"缺口"变为"待真机验证"

**B5 坐标操作**在本阶段完成后，E1 不再是"未实现"：三种动作（`pointer_click`/`pointer_move`/`pointer_drag`）在**能力通道**与 **Bridge** 两条路径上均已打通，且有进程内证据（计划器成对性、四坐标到达页面、契约/工具/线缆断言）。

**因此外部验收的关注点变为**：
1. **真实效果**：点击/拖拽在真实页面上是否命中预期元素；拖拽是否被目标 UI 接受；
2. **坐标语义**：CSS viewport 像素在**设备缩放**下是否与页面坐标系一致（本阶段所有坐标都是"调用方给的 CSS 视口像素"直传，未做 DPI 换算）；
3. **拖拽中间事件**：页面是否能观察到中间 `pointermove`（计划器默认 8 步）；
4. **`observationId`**：目前**尚无观察登记处** ⇒ 带该字段的请求**一律被拒**。若外部要用"截图坐标"，需先实现登记处（截图时登记 pageVersion/世代/滚动/缩放/布局 + 精确变换，坐标按 id 校验失效）——**该项仍属未实现**。
5. **负面路径**：表面在不支持坐标能力时应返回 `UnsupportedCapability`（当前**无用例**覆盖，仅代码保证）。
