# Memory 快照索引与历史溯源

日期：2026-09-14。用户明确纠偏后的架构方向；以下合同与预算为待实施设计，不代表当前运行时已完成。补充并优先解释 [长程自治设计 §4–5](PuddingAgent长程自治与缓存99优化设计-2026-09-12.md) 与 [ADR-085](../07架构/99ADR-085Memory主导的长程任务连续性ADR.md)。

## 1. 核心决策

**Memory 是 Agent 主动维护的当前知识快照及分层导航，聊天记录是形成结论的过程证据。搜索相关性不等于结论有效性，时间更新也不自动等于最终裁决。**

例如：先讨论“端口用1234”，随后决定“改用5678”，后来又有人引用旧讨论“为什么当时提1234”。普通查询“当前端口”应读取适用项目的已确认快照5678；不能因1234出现更多、语义更相近或被更晚引用而返回1234。问“为什么改端口”时，才打开引用范围内的讨论和决策证据。

本轮定位修订优先于此前《首轮上下文准备性能修复》的后续顺序：修复索引键和扫描性能仍有价值，但**低延迟不能证明每轮自动日志召回合理**。后续主线先建设最小可用快照写读，再移除默认自动日志注入；归档完整性作为溯源修复并行准备，不再作为把聊天全文重新接入默认上下文的理由。

## 2. 四种职责，不建立四份重复知识

| 对象 | 保存什么 | 默认如何使用 |
|---|---|---|
| Memory 快照索引 | 当前适用结论、约束、少量恢复线索、目录和正文引用 | 启动只加载当前范围的小索引，按需展开 |
| 外部正文 | 完整 ADR、方案、操作说明、文件或目录中的详细知识 | 打开索引指定的局部正文，不全库读取 |
| 记忆图书馆 | Book/Page、Pointer、场景/主题组织、版本和全文/向量索引 | 同时承载托管知识正文及外部正文的引用目录 |
| 历史记录 | 讨论、尝试、反驳、旧方案、工具执行、决策来源 | 有明确追溯意图或恢复缺口时检索限定范围 |

Task/Goal 仍是执行状态、等待对象和下一动作的权威，Memory 不实现另一套任务状态机。向量/FTS 都是检索手段，不是独立的权威知识层。

每份知识正文只有一个权威位置：可以是项目已有文档，也可以是图书馆托管页。外部文件被图书馆索引时，索引副本不能与源文件成为两份可独立修改的正文；源更新后更新索引版本。索引短结论是导航快照，涉及变化敏感事实时需校验目标版本。

## 3. 分层组织与逐级展开

示意结构（逻辑引用，不要求创建同名物理目录）：

```text
Memory/root
  projects/PuddingAgent/index → runtime/index → context/index → 决策页/代码位置
                             → desktop/index → 配置页/部署说明
  projects/另一个项目/index → 该项目主题目录
  concepts/缓存/index → 通用概念及项目适用范围
  scenes/Windows故障排查/index → 症状目录、经验页
```

根目录只列名称、用途、适用范围与子索引引用，不复制所有叶子摘要。项目/概念/场景可以交叉引用同一页，避免复制正文；读取器使用已访问 ID 集防止循环展开。候选很多时分页和继续缩小范围，不因“多级索引”每层都读一遍全部内容。

初始设计预算沿用 M01：所有启动 Memory 索引合计目标≤1K Tokens，Task 续行文本≤2K。每次定向检索先返回≤5个候选及合计≤1K Tokens的导航结果，正文按本轮剩余预算读取，初始目标≤2K；这是可配置组织目标，不截断必要结论。多个索引跳转共享一次检索预算，不能每跳重新获得全部额度。超额返回继续读取指针及未覆盖说明，不能宣称全量已读。

查询已知当前项目/主题时可直接进入对应索引，无需每次从根遍历。找不到精确名称时，先对授权范围内的索引标题、短结论和 current 正文做词法/向量混合发现，返回引用后再展开。不能让每次操作都先加载全项目目录。

## 4. 快照内容与鲜活性

复用现有 Book/Page、source_reference、Pointer 及版本机制。最小逻辑条目示例：

```json
{
  "key": "pudding/runtime/context-policy",
  "summary": "长期状态通过分层Memory恢复；历史日志仅按需溯源",
  "scope": { "project": "PuddingAgent", "topic": "context" },
  "status": "current",
  "certainty": "confirmed",
  "bodyRef": { "id": "project-doc-or-library-page", "version": "revision-or-content-hash" },
  "sourceRefs": ["decision-or-conversation-reference"],
  "supersedes": ["previous-revision"],
  "updatedAt": "timestamp"
}
```

这是语义合同，不要求新建一张平台级表或让 Agent 每次手填全部字段。框架注入授权 scope、ID和版本；Agent负责选择主题、写当前结论与依据。certainty区分已确认、推断、待确认：一份正在讨论的草案可以是最新页，但不能因为status=current就冒充已确认决策。缺少确定依据时保留“不确定/待确认”，不自动升级成事实。

更新发生在用户明确纠正、结论确认、实现/部署验收变化、依赖版本改变或阶段结束等语义边界。沿用同主题key替换current快照，旧版本仅进入历史；不把每轮对话追加成新的Memory。源码已提交与线上已部署是两条不同事实，必须分别记录。

写入过程保持简单：先保存唯一正文/页，再发布对应版本的索引引用并获得回执；沿用CAS/expectedVersion处理并发，不让较早的子代理覆盖更新后的主代理结论。文件与数据库不是单事务，引用发布失败应可重试；不得提前宣布索引已更新。Task checkpoint 在必要记忆引用持久化后再提交。

源文件变化或引用失效时，将受影响索引标为待复核并重新读取；过期向量不得继续提供旧片段。修复范围按变更页/目录限定，无变化不整库扫描、不启动额外模型整理。长期决策不按7天TTL删除，归档版本、向量缓存和原始日志有各自保留策略。

## 5. 默认回答与历史追溯的分流

**默认当前知识路径**：用户当前请求/明确引用 → 当前Task引用或相关Memory索引 → 图书馆或外部正文的当前版本 → 根据适用范围与来源回答。只在任务确实需要时检索；没有新需要则不自动召回。

**历史路径**：用户询问“为什么/当时怎么决定”，Agent发现当前快照冲突、断链，或恢复未写回的最后一小段工作 → 限定项目/Agent/时间/决策引用检索聊天记录 → 打开命中附近上下文并追到后续结论或终态。不得只读一条message就认定最终结果；找不到最终决策时明确未确认。

历史结果必须标识证据类型、发生时间、会话/消息范围、相关决策引用以及“是否已检查后续修订”；不知道关联关系就返回unknown，不能伪造终态。自动检索可以由Agent根据任务需要发起，不要求用户每次批准，也不允许由“每5轮”或结果少于2条机械触发全历史探索。

日志检索以窄范围索引分页、返回短摘录与原文指针；打开历史使用范围窗口和继续读取游标。即使原始记录增长至GB，默认启动索引与普通问答的历史读取量不随历史体积增长。保留全文搜索与向量搜索，取消默认装配路径中的日志查询、重建和片段注入。

## 6. 向量检索的职责

向量帮助不同表述找到同一概念，也能找到相关历史讨论；它不判断提案是否被否决，不取代版本、来源、适用范围及后续修订检查。

当前知识与历史证据保留可区分的类型/版本过滤；先约束权限、project/book/topic，再结合词法与向量召回。重排只能在合格候选内改善相关性，不能把历史提案越过current有效页。读取命中时复核sourceVersion，旧版本向量即使尚未物理删除也不能作为当前答案返回。

LM Studio等向量服务不可用时，仍可通过Memory目录、指针和限定范围FTS读取；返回向量不可用的真实状态，不能静默扩大到全历史、偷偷增加探索模型调用。辅助模型只有确实需要消歧才使用，并单独计费与呈现。这里的“核对”主要是Agent推理和来源读取，不再搭建F0–F10式多阶段语义审批。

## 8. 验收与路线

1. **M02-A，P0最小快照写读。** 单项目索引→主题页→外部文件或图书馆页；稳定key更新、版本回执、范围约束、读取正文。测用户新裁决覆盖旧提案、较新讨论引用旧结论、同名多项目和并发覆盖；不先做大规模知识自动整理。
2. **M01默认装配纠偏。** 有可用索引/明确空索引后，移除每轮日志召回、首轮整摘要与轮数强制召回；未知记忆明确显示，不自动日志兜底。保留压力压缩、canonical hydration和current-turn保护，移除日志增强不等于丢弃当前工作对话。
3. **M02-B/C03，溯源和向量。** 复用查询工具，将current/history结果分开，支持查“为什么”、冲突回溯、少量崩溃缺口恢复；清理低结果数自动探索与无变化重索引/模型调用。
4. **规模与长程门禁。** 1GB以上历史语料下：普通启动不调用日志搜索/构建；找小事实只展开相关主题；重复确认不增长current条目；正文变化后旧向量不命中当前答案；显式溯源能找到更晚撤销；向量离线仍可读快照。记录展开页数、实际读入Tokens、错误旧结论率、来源核实率、检索/辅助模型调用、任务完成成本，不能只用命中率证明有效性。1GB负载与30日墙钟验收分别登记，不能互相替代。
