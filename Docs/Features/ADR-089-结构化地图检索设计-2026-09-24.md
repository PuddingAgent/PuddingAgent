# ADR-089：结构化"地图"检索 —— 检索意图、结果分层与多语言抽象（2026-09-24）

> 用户指令原文（2026-09-24 第四轮）：
> "增强索引需要区分**文件检索**和 **LSP 检索**的区别，比如一个类名，别的类引用了这个类，那么检索出不同的文件和地址，
> 但是**检索优先级是有区分的**。同时，如果可以，Agent 可以在检索的时候**给予单次的检索偏好**，比如我是找一个文件，
> 还是找一个类、函数、方法、注释、还是内部实现，或者**所有引用这个类的代码**（同时为不同的编程语言留下抽象和结构、接口，
> 虽然 PuddingAgent 的绝大部分的代码是 C#，但是我们还会有 Java、py、js、go、rush、sql 等），工具是否可以有效的过滤和筛选，
> 并给予 Agent 足够的指引。**最终的目标是实现一个结构化的地图的检索，而不是单纯的做字符串检索，否则这个与全文检索没有什么差别了。**"

这条把项目的**最终目标**定死了：检索的产出应是**结构化的地图**（符号 + 关系 + 分层），不是行号列表。

## 0. 存量盘点（先别造轮子）

| 已有 | 位置 | 能力 |
|---|---|---|
符号种类 | `PuddingCodeIndex.Contracts.CodeSymbolKind` | **18 种**：Namespace/Type/Struct/Class/Interface/Enum/Delegate/Method/Constructor/Property/Field/Event/Parameter/Local/Variable/Constant/Operator/Unknown |
结构化查询 | `PuddingCodeIntelligence.Contracts.ICodeQueryService` | `SearchSymbols` / `Explore`(子符号) / **`GetCallers` / `GetCallees`** / `GetImpact`(传递闭包) |
关系记录 | `CodeRelationRecord` | 关系已有承载类型 |
LSP 门面 | `ILanguageServerService` + `LanguageServerMethod` | 方法枚举已含 **Definition / TypeDefinition / References / Hover / CallHierarchy / Rename / Completion** …；但**响应是裸 `ResultJson` 字符串**，`IndexBasedLanguageServerService` 是仿实现、**零消费者** |
各语言 outliner | `PuddingCodeIntelligence/{CSharp,Python,TypeScript,PowerShell,Json,Yaml,Markdown,Bicep,Cpp}` | 结构提取（粒度不一） |
各语言 indexer | C#(Roslyn) / Python / TypeScript | 符号入库 |

**⇒ 缺口不是"没有结构化能力"，而是这四件具体的事**：

1. **两个检索面没有区分与协同**：文件/文本面（`search_grep` 族）与结构面（`ICodeQueryService` 族）各自为政，
   Agent 拿不到"这是声明处 / 这是引用处"的分层，也没有统一排序。
2. **没有"单次检索偏好"（intent）**：Agent 无法表达"我要找注释""我要所有引用这个类的代码"。
3. **没有关系感知的优先级**：声明、实现、引用、注释提及全部等价，谁排前面靠字符串分数。
4. **多语言抽象只到"有 outliner"这一层**：没有统一的语言标识、没有"能力矩阵"、也没有 SQL/Go/Rust/Java 的位置
   （`CodeSymbolKind` 里也**没有** Table/View/StoredProcedure/Column 这类 SQL 对象，没有 Annotation/Attribute、Module/Package）。

## 1. 两个检索面必须区分（而不是合并）

| 面 | 输入 | 产出 | 何时用 |
|---|---|---|---|
**文本面**（现有 `search_grep` / 全文索引） | 字面量/正则 | 文件+行号+片段 | 找"字符串在哪出现过"、日志、配置、不确定符号名时 |
**结构面**（本设计） | 符号名 / 意图 | **符号 + 归属 + 关系 + 分层** | 找"这个类的定义在哪""谁引用了它""它的实现是什么" |

**同一个类名命中两类文件，必须分层**：

```
找 "MessageDeliveryDispatcher"
  ① 声明处（declaration）      —— 定义该类的文件        ← 优先级最高
  ② 实现/派生处（implementation）—— 实现该接口/继承它的类
  ③ 直接引用处（reference）     —— new / 字段/参数类型 / using
  ④ 调用处（call site）        —— 调用了它的成员
  ⑤ 注释/文档提及（doc mention）—— 只出现在文字里
  ⑥ 代码正文偶然命中（text hit）—— 只是同名片段
```

**这条分层就是用户要的"检索优先级有区分"**，也是"不是字符串检索"的分水岭。

## 2. 单次检索偏好（intent）：合同草案

工具接受一个**可选**的 intent 参数（缺省 = `Auto`），语义**面向 Agent 的意图**，不是引擎细节：

```csharp
public enum RetrievalIntent
{
    Auto,            // 由查询形态推断（标识符⇒符号名；含空格⇒自然语言）
    File,            // 找文件（路径/文件名）
    Namespace,       // 命名空间/包/模块
    Type,            // 类/接口/结构/枚举/委托（统称"类型"）
    Member,          // 函数/方法/属性/字段/构造/事件
    Comment,         // 注释与文档（**P1 层**，md 检索失效正是这里）
    Implementation,  // 某接口/抽象成员的实现
    References,      // 所有引用某符号的代码
    Callers,         // 调用方
    Callees,         // 被调用方
    Impact,          // 传递影响（GetImpact）
    Any,             // 不限
}
```

**intent → 过滤 + 排序**（示例，最终表在实现里，但**必须成文且可解释**）：

| intent | 过滤到哪些 `CodeSymbolKind` / 关系 | 默认分层顺序 |
|---|---|---|
`File` | 不按符号过滤（文本面 + 路径匹配） | 路径精确 > 路径包含 |
`Type` | Class/Interface/Struct/Enum/Delegate/Type | 声明 > 实现 > 引用 |
`Member` | Method/Constructor/Property/Field/Event/Operator | 声明 > 调用 > 引用 |
`Comment` | 只取 **DocComment 块**（P1） | 文档注释 > 行内注释 > md |
`Implementation` | 关系 = Implements/Overrides | 实现体 > 声明 |
`References` | 关系 = References/Calls/Inherits/Imports | 引用处（按引用计数） |
`Callers` / `Callees` / `Impact` | 关系子图 | 距离升序 |

## 3. 关系模型要补齐的部分

`GetCallers/GetCallees/GetImpact` 已有 ⇒ 补：

| 关系 | 现状 | 需补 |
|---|---|---|
`Calls` | 有（callers/callees） | — |
`Inherits` / `Implements` / `Overrides` | 部分（Roslyn 侧） | 统一进关系模型 |
**`References`（一般性：类型引用、字段/参数类型、`using`/`import`）** | **缺** | ✅ 本设计的主要新增 |
`Imports`（using/import/require） | 缺 | 作为弱关系（提高文件级召回） |
`DocMentions`（注释/文档里提到某符号） | 缺 | 支撑 `Comment` intent 与"文档引用了它" |
`Attribute/Annotation` | 缺 | 语言相关，放进每语言适配器 |

**每条关系都要能回答"证据在哪"**（文件 + 行）+ **"多可信"**（Roslyn 语义 > 词法猜测），
否则"地图"会变成猜谜。

## 4. 多语言抽象：端口 + 能力矩阵（诚实优先）

**结构**（与前几刀同构：端口 + 外部适配器）：

```
ILanguageSymbolExtractor        // 每语言一个适配器：文本 → 符号 + 关系
    LanguageId Supports { get; }        // 该适配器负责哪些语言
    SymbolExtractionResult Extract(...) // 符号 + 关系 + 证据位置 + 置信度
ILanguageCapabilityMatrix       // 回答"这门语言支持到哪一级"
```

**关键裁定：不要把语言专有 kind 灌进全局 `CodeSymbolKind`。**
做法 = **语言原始 kind 字符串 + 到通用 kind 的映射**：

```
record SymbolKindMapping(string LanguageRawKind, CodeSymbolKind CommonKind);
```

- SQL 对象（Table/View/StoredProcedure/Column/Index）**保留原始 kind**，通用 kind 先映射到最接近的
  （如 Table→`Type`、Column→`Field`、StoredProcedure→`Method`），需要时再扩展通用枚举；
- 这样 Java/Go/Rust 的 `trait`/`func`/`struct` 差异不会被"硬塞"进 C# 语义。

**能力矩阵（必须成文，能对 Agent 说"不支持"）**：

| 语言 | 结构提取 | 符号入库 | 关系（References） | 备注 |
|---|---|---|---|---|
C# | ✅ Roslyn（语义级） | ✅ | ⏳ 本设计新增 | 主力语言 |
Python | ✅ outliner + indexer | ✅ | ⏳ | 词法级，置信度低于 Roslyn |
TypeScript/JS | ✅ outliner + indexer | ✅ | ⏳ | 同上 |
PowerShell / Json / Yaml / Markdown / Bicep / Cpp | ✅ outliner | ❌ | ❌ | 只能给结构，不能给关系 |
**Java / Go / Rust / SQL** | ❌ **未实现** | ❌ | ❌ | **留接口，明确"未实现"** |

⛔ 不允许"假装支持"：intent 不被支持时，工具必须**明确说明**（§5）。

## 5. 给 Agent 的指引（与"过滤筛选"同等重要）

工具必须：

1. **声明能力**：描述里写清支持的 intent 与语言矩阵（或提供一个 `capabilities` 动作返回矩阵）。
2. **intent 不可用时给替代方案**，不是静默降级：
   > "语言 `go` 尚不支持 `References`。建议：① 用文本面检索 `SymbolName`；② 用 `Type` intent 看是否有结构提取。"
3. **每个命中带自描述元数据**：`hitKind`（Declaration/Implementation/Reference/CallSite/DocMention/TextHit）、
   `symbolKind` + `languageRawKind`、`relation`、`evidence`（文件+行）、**`confidence`**（语义 vs 词法）。
4. **结果有两种视图**：`symbols`（符号视图，含归属与关系边）与 `files`（文件视图，含命中原因摘要）——
   这样"找文件"和"找类"都能一次拿到，且**原因可见**（排序不再神秘）。
5. **降级必须标注**：结构化面不可用（语言未支持 / 索引缺失 / 库损坏）⇒ 退化为文本检索，
   并在结果里**明确标记"这是文本降级结果，非结构检索"**。

## 6. 与已交付切片的衔接（重要）

- **U4-1a 的分块必须携带元数据**：`ChunkKind`（Outline/DocComment/CodeText）之外，
  还要带 `symbolKind` / `languageRawKind` / `container`（归属类型）/ `relation`（若该块来自引用处）。
  **否则检索结果无法分层** —— 分块模型不升级，本设计的第 1、2 节就落不了地。
- **U4-1b（向量/混合）** 应在**同一批块**上比较，避免"引擎换了、块也换了"导致不可比。
- 已交付的 `IOutlineSource` 端口可扩展为 `ILanguageSymbolExtractor` 的前身（不要并行造两套）。

## 8. 硬约束

1. **结构化面与文本面并存**，不互相替代；结构不可用时可降级为文本，但**必须标注降级**。
2. **排序必须可解释**：任何"这个文件排前面"都要能说出原因（声明/实现/引用/注释/文本）。
3. **语言能力必须诚实成文**：不支持就说"不支持 + 替代方案"。
4. **不把语言专有种类灌进通用枚举**，用 raw kind + 映射。
5. 沿用：组件只依赖端口、既有检索行为只增不改、不新增 NuGet、新工程过全解决方案构建门禁、
   每个切片要有能取红的变异证据与"改前/改后两组数字"。
