## 0. ⭐ 对 S1b 计划的修正（父级决定，须服从）

**原计划**：把工具审批的既有实现改写成基于 `OperatorBase` 的实现。
**修正为**：**包装（Adapter）**，不改写。

**修正理由（可验证）**：
1. S1a 端口在生产中**无人使用**（无 DI 注册）⇒ 惰性抽象会腐化，必须尽快被真实消费；
2. 但直接改写 `ToolCallClassifierPipeline` / `ClassifierToolApprovalReviewer` = **重构安全关键路径**（审批仲裁核心），风险与收益不匹配；
3. **依赖倒置的正确用法是适配器**：新端口不要求旧实现重写 —— 由 adapter 把既有实现暴露为新端口。这样**既有行为逐位不变**，同时证明抽象真能承载真实消费者。

⇒ 本切片**禁止**修改 `Source/PuddingRuntime/Classification/**` 与 `Source/PuddingRuntime/Tools/Approval/**` 下的任何文件。

## 2. 交付物 1：场景注册表（键控）

新增 `Source/PuddingCore/Operators/OperatorRegistry.cs`（契约）+ `Source/PuddingRuntime/Operators/OperatorRegistry.cs` 或直接放实现（**按 S1a 既有布局自行判断，保持与 S1a 一致的风格**）。

```csharp
namespace PuddingCode.Operators;

public interface IOperatorRegistry
{
    IReadOnlyCollection<string> SceneKeys { get; }
    bool TryResolve<TPort>(string sceneKey, out TPort? op) where TPort : class, IOperator;
    TPort Resolve<TPort>(string sceneKey) where TPort : class, IOperator;   // 缺失 ⇒ 抛（fail-closed）
}
```

**必须 fail-closed 的两条注册守卫**（各配单测）：
1. **同一 `sceneKey` 重复注册** ⇒ 抛（不得静默覆盖）；
2. **同一个算子类型实现多于一个原语端口**（例如同时 `IJudge` 与 `IScorer`）⇒ 注册时**拒绝**。
   > 理由（母文档 §4.3.2）：一个类同时实现两个原语会让"分"与"是/否"的输出语义再次混淆。把这条规则**做成注册期守卫**，而不是文档里的口头约定。
3. `sceneKey` 为空/空白 ⇒ 拒绝。

## 3. 交付物 2：工具审批适配器（**包装，不改写**）

新增（命名与落点按 S1a 风格自行判断，建议 `Source/PuddingRuntime/Operators/Adapters/`）：

```csharp
/// <summary>把既有工具审批分类器（IToolCallClassifier）暴露为新算子端口；不改变被包装者行为。</summary>
public sealed class ToolApprovalOperatorAdapter : IClassifier   // 注意：只实现一个原语端口
{
    public const string SceneKeyValue = "tool_approval";
    public string OperatorId => _inner.ClassifierId;
    public Task<ClassificationResult> ClassifyAsync(IOperatorContext context, CancellationToken ct = default);
}
```

### 3.1 输入适配（`IOperatorContext` → `ToolCallClassificationContext`）

**关键约束**：`ToolCallClassificationContext` **不得被修改**。适配器需要一个能承载它的 `IOperatorContext` 实现。**建议**在适配器文件内或契约层新增一个极小的实现：

```csharp
public sealed class ToolApprovalOperatorContext : IOperatorContext
{
    public required ToolCallClassificationContext Approval { get; init; }
    public string SceneKey => "tool_approval";
    public string InputDigest { get; init; }   // 见 3.2
}
```
若为它新增重载构造，**不得**改动 `ToolCallClassificationContext` 自身。

### 3.2 `InputDigest` 必须确定性

按固定字段顺序做 SHA-256（缺省值参与计算，避免 null 歧义），**只含稳定字段**：
`ToolId, CommandName, ArgumentsJson, WorkingDirectory, Shell, WorkspaceId, SessionId, AgentInstanceId, UserId`

**禁止**纳入易变字段（时间、进程、随机值）⇒ 否则缓存键与去重失效。

### 3.3 输出映射（必须逐条实现，并配等价性测试）

| `ClassificationVerdict` | → `ClassificationResult` / `JudgementEnvelope` |
|---|---|
`Outcome` | → `PrimaryLabel`，**规范化小写键**：`allow_once` / `allow_permanent` / `deny_once` / `deny_permanent` / `unknown`（**与既有 `PerOutcomeConfidence` 的文档化规范键一致**，不要另造命名） |
`PerOutcomeConfidence` | → `LabelDistribution`（为空则空字典，**不得**伪造值） |
`Reason` | → `Envelope.Reason`（必填，**不得留空**） |
`ReasonCode` | → `Envelope.ReasonCode` |
`ClassifierId` | → `OperatorId` |
`ClassifierModel` | → `Envelope.ModelId` |
`LatencyMs` | → `Envelope.LatencyMs` |
`AppliedRuleId` | → `Evidence`：`JudgementEvidence { Kind = "rule", Reference = AppliedRuleId }`（为 null 则不加） |
identity 四元组 | → `Envelope.Identity`（`WorkspaceId/SessionId/AgentInstanceId/UserId`） |
`SourceEventIds` / `SourceSha` | → **留空**（当前无来源）；**不得编造** |
`Score` / `ScoreScale` | → **留空**（审批裁决无单一分数；这是它属 `IClassifier` 而非 `IScorer` 的原因） |
`Threshold`（`AppliedThreshold`） | → **留空**，并在代码注释与 §7 遗留中写明：审批路径的阈值目前**未**以 `ThresholdPolicy` 暴露，属已知缺口（S2 处理） |
`Confidence` | 取 `PerOutcomeConfidence[PrimaryLabel]`（若该键存在），`ConfidenceKind = ModelSelfReported`；缺失则 `Confidence = null`，**仍为 `ModelSelfReported`**（**不得**标成 `Calibrated`） |
`SchemaVersion` | 用 S1a 的 `CurrentSchemaVersion` |

**降级**：被包装者若抛出（理论上不应抛，其契约要求 fail-safe）⇒ 适配器按 S1a 降级契约产出降级结果 + 稳定 `ReasonCode`，**不得冒泡异常**。

## 4. 交付物 3：等价性测试（**本切片最重要的证据**）

新增测试（放在 S1a 的 `Source/PuddingRuntimeTests/Operators/` 旁，风格一致）：

**核心用例**：对一组代表性 `ToolCallClassificationContext`（至少覆盖：allow_once、deny_permanent、unknown/降级、`PerOutcomeConfidence` 为 null、`AppliedRuleId` 为 null 各一例），断言：

1. `adapter.ClassifyAsync(...)` 的 `PrimaryLabel` == 直接调用 `inner.ClassifyAsync(...)` 的 `Outcome` **经 §3.3 规范化后的键**；
2. `LabelDistribution` 与 `PerOutcomeConfidence` **逐键逐值相等**；
3. `Reason` / `ReasonCode` / `OperatorId` / `ModelId` **逐位相等**；
4. `Score` / `Threshold` 为 null（证明没有被伪造）；
5. **同输入两次调用 ⇒ `InputDigest` 相同**（确定性）；不同输入 ⇒ 不同。

另配注册表用例：重复注册被拒、一个算子实现两原语被拒、缺失 `sceneKey` 抛、`TryResolve` 命中/未命中。
