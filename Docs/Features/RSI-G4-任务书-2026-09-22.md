## §2 冻结契约

### §2.1 家族口径 —— 父代理裁决 F1：**确定性口径为主，LLM 归类不得参与容量判定**

设计 §13.6 原话是「**分类器**给每个技能打**家族分**」。本任务书**偏离该措辞**（理由见 §9-1）：

| 口径 | 定义 | 本片地位 |
|---|---|---|
| **(a) 关键词身份并查集** | 两个启用技能共享 ≥1 个**语义类**关键词 ⇒ 同族（`report-skill-portfolio.ps1:148` `Get-Families`） | 已实测**无用**：139 个家族、全为单技能（§3-F） |
| **(b) 名称分词 token 的 Jaccard + 并查集** | 名称 token 集合 Jaccard ≥ 阈值 ⇒ 同族（`report-skill-portfolio.ps1:606` `New-NearDuplicateReport`） | ✅ **本片主口径** |
| (c) LLM 家族分 | 分类器给出家族标签 | ⚠️ 仅可作**附加标签**，⛔ **不得**参与 `PerFamilyCap` 计数 |

**为什么 (b) 必须是主口径**：`PerFamilyCap` 的验收判据是「上限**强制生效**」，即**同一输入必须得到同一裁决**。
LLM 分组**不可复现**（同输入两次可能不同族）⇒ 用 LLM 作家族键，等于把**容量判据交给不稳定输入**，
「生效」二字将**无法被任何断言固定**。

**为什么 (b) 不用 keywords/tags**（照抄既有报告的裁决，`report-skill-portfolio.ps1:606` 原注释）：
keywords/tags 含大量共享工具名（`file_read` 等），算进去会让**所有技能都"相似"** ⇒ 退化成"一个大家族"的假象。
⚠️ (b) 是**保守下界**：它只能发现"名字就像同一件事"的重复，**发现不了措辞完全不同的同类**。
⇒ 该局限必须写进交付说明，⛔ 不得把"G4 没找到族"读成"没有重复"。

### §2.2 `PerFamilyCap` 的语义 —— 父代理裁决 F3：**0 是非法值，未设限必须显式表达**

**实测现状（这就是本片最大的静默地雷）**：

| 事实 | 证据 |
|---|---|
| 字段存在但**只承载不消费** | `Source/PuddingCore/Skills/Portfolio/SkillPortfolioPolicy.cs` —— 注释原文「本切片只承载字段、不消费（家族归类属 G4）」 |
| 过渡默认传的是 **0** | 同文件 `ZeroRegressionDefault(...)`：`perFamilyCap: 0` |
| 校验只要求 `>= 0` | 同文件 `EnsureValid()` / `IsValid` |
| 快照**不含**该字段 | 同文件 `ToApplied()` —— 刻意排除，防"读者以为已生效" |

⚠️ **危险**：`PerFamilyCap` 当前**语义未定义**（0 是"不设限"？还是"上限 0"？）。一旦 G4 开始消费它，
若把 **0 读成"上限 0"**，则**每个家族都立刻超限** ⇒ 一次性把全部多成员家族推进强制合并评审 ——
这是一次**没有任何断言会失败的静默行为爆炸**（本会话反复出现的同一族缺陷）。

**冻结**：

1. 未设限必须是**显式**的：把字段改为 `int?`，`null` = 不设限；
2. `Create` / `EnsureValid` **拒绝 0 与负值**（`PerFamilyCap <= 0` 且非 `null` ⇒ 抛 `InvalidOperationException`），
   逼调用方**表达意图**而不是靠默认值；
3. `ZeroRegressionDefault(...)` 的实参改为 `null`（它本就无意设限）；
4. ⚠️ 这会改动**已冻结的 G3 交付物**（`SkillPortfolioPolicy` + 可能波及 19 条既有用例中的相关断言）⇒
   **必须在 G4 交付说明里显式声明**，并保证除被更新断言外其余用例全绿；
5. `ToApplied()` **在真正消费之前仍不得**加入该字段（保持 G3 的防幻影区间约定）。

### §2.3 家族内上限的后果 —— 父代理裁决 F4：**只产生"评审"，不产生"删除"**

设计 §13.6 原话：「同家族启用数 > `perFamilyCap` ⇒ **强制进入合并评审**」。

**冻结**：超限的**唯一**后果是产出「该家族进入合并评审」的**待裁决记录**：

- ⛔ 不得 `Displace`、不得 `SetEnabledAsync(false)`、不得删除、不得改关键词；
- 记录必须含：家族键、成员清单、超限数、策略 `policyId@version`、reason code；
- 本片**零写盘**（I3）。删除 / 改名 / 归属改写的执行一律属 **L3-b**。

> **为什么这条要单独冻结**：容量压力的自然反射是"腾位置 = 禁用最弱的"。那会把 G4 变成
> **绕过 G2 遥测的删除通道**（§13.10 R1「冷启动只降不杀」、R2「误杀是静默的」）。
> G4 是**判据层**，不是执行层。

### §2.4 关键词唯一性守卫 —— 父代理裁决 F5：**先暴露事实、再谈裁决，注入结果本片不动**

**实测现状（先到先得，静默丢弃）**：

```
Source/PuddingRuntime/Services/Skills/SkillEnforcerService.cs

  :136  foreach (var entry in index.Skills)
  :138      if (!entry.Enabled) continue;
```

⇒ 现状既没有"显式裁决"，也**不知道被丢掉了什么**（G1 已实测：**1735 次注入机会被挤掉**）。

**冻结**（分两步，本片只做第 1 步）：

1. ✅ **只读事实暴露**：产出「每个关键词的**全部**竞争者」（当前 map 只留第一个）。
   必须能回答：共享关键词 **165 个** / 被挤掉 **1735 次**（与 G1 报告**逐数一致**，口径随关键词归一规则）；
2. ✅ **归属裁决判据**：冲突 ⇒ 产出**待裁决**（改写关键词 / 提升优先级 / 拒绝），
   ⛔ **禁止**"先到先得"作为默认裁决；⛔ 不得把"后来者一律拒绝"写成默认（那只是把静默换成另一种静默）；
3. ⛔ **本片不得改变 `SkillEnforcerService` 的 map 构建结果** —— 改注入结果 = 改生产行为，
   需要灰度与遥测（G2 之后）。用例必须**断言默认配置下注入结果逐字段不变**（I5/I8）。

⚠️ **与 G7 的 C3 必须分层写清**（防"两处判定将来漂移"）：

| | G7-C3 | G4 守卫 |
|---|---|---|
| 时机 | **新技能准入**时检测 | **存量已启用技能之间**的归属 |
| 输入 | 候选产物 + 已启用集合 | 全部启用集合 + 真实关键词空间 |
| 产出 | `ChangeVerdict`（Reject / Shadow） | 待裁决事实（⛔ 无写盘职权） |
⇒ 两者**共享同一个关键词归一/工具名谓词来源**，⛔ 不得各写一份。

### §2.5 合并四条件 —— 父代理裁决 F6：**必须实测它是"有牙的"还是"永不触发的"**

设计 §13.6 的四条件：**同家族** 且 **关键词重叠** 且 **程序性文本相似 ≥ 阈值** 且 **证据可归并**。

**磁盘上已存在的确定性合并闸门**（⛔ 不是同一判据，不得替换/放宽）：

```
Source/PuddingMemoryEngine/Services/SkillEvolutionDeduplicationService.cs
  :55   private const double MinimumTextSimilarity = 0.35;
  :432  IsDeterministicallyEligible(canonical, duplicate)
           ① canonicalTools 非空 且 canonicalTools.SetEquals(duplicateTools)   // 工具集合「完全相等」
           ② 文本相似度 < 0.20 ⇒ 拒绝
           ③ 共享 source-turn  或  文本相似度 >= 0.35
```

⚠️ **关键风险（必须实测，不得推测）**：既有闸门①要求**工具集合完全相等**，而家族聚类簇里的技能
往往"做同一件事但工具集不同"。若把"四条件 + 既有闸门①"简单叠加，可能得到**一个永不触发的判据**——
按本会话的纪律，**一个永不触发的判据等于不存在，且不会有任何断言失败**。

**冻结**：

1. 四条件**逐条**实现且**逐条可单独取红**（每条件一个负例 + 一个正例）；
2. **必须交付一个只读可行性探针**：在 §3-F 的 10 个既有近重复簇上，统计
   「通过四条件的对数」与「再叠加既有闸门后仍通过的对数」；
3. 若叠加后通过数 = **0** ⇒ **必须显式裁决**（要么说明本片判据按设计**取代**闸门①于家族内路径，
   要么把"0"作为结论写进交付说明并**不许**把这个判据当作已生效的合并能力）；
   ⛔ **不得**静默保留一个永不触发的判据；
4. 无论哪种裁决，既有 `IsDeterministicallyEligible` 的**行为不得改变**（I8）。

### §2.6 阈值来源与冷启动

- 家族相似度阈值、四条件阈值**全部来自策略对象**（复用 `SkillPortfolioPolicy` / 新增同形策略对象，
  照抄 `PuddingCore/Operators/ThresholdPolicy.cs` 形状：`IVersionedCriterion` + `EnsureValid` + `ToApplied` + `Create` 校验式工厂）。
  ⛔ 判定器内**不得出现裸阈值字面量**（I4）。
- ⛔ **不得**把报告脚本里的 `0.25 / 0.4 / 0.6`（`report-skill-portfolio.ps1:648`，原文「只陈述事实，不设阀值判据」）
  直接复制成产品默认值。若选 0.25 作默认，必须**说明理由并递增版本号**，且记录"这是保守下界，不是治理结论"。
- 冷启动 / 无数据 ⇒ **降级为"不裁决"**（产出 reason code），⛔ 不得退化成"低价值"（与 G3 §S2、G7 C4 同源纪律）。

| **I4** | 阈值来自策略对象，判定器内**无裸字面量** | 把阈值写死进判定器 ⇒ 用例必红（改策略值应改变结论） |
| **I5** | 关键词归属冲突**必须显式裁决**；且默认配置下**注入结果不变** | ①把冲突判成"取第一个"⇒ 冲突用例必红；②改动 map 构建影响注入 ⇒ 零回归用例必红 |
| **I6** | 合并**四条件同时**满足 | 逐条删除一个条件 ⇒ 对应负例必红（4 个变异） |
| **I7** | **零写盘**（注入探针：三个写方法先计数再抛异常） | 在任一分支写一次 ⇒ 探针必红 |

| **I9** | 家族标签**只用于分组**，不参与生死判定 | 让"家族分低"产生 Retire ⇒ 用例必红 |

> **取红纪律（本会话已两次踩过）**：**只写用例不证明它会红 ⇒ 不算完成**。
> 且必须警惕**被掩盖的防线**：同一语义若有两道防线（如"配对前排序"与"输出前排序"），

## §9 与设计措辞不符 / 诚实清单

1. **家族口径偏离设计原文**：§13.6 写「分类器给每个技能打家族分」，本任务书裁决
   **确定性口径（名称 token Jaccard）为主、LLM 归类不得参与容量判定**（理由：不可复现则上限不可复现，§2.1）；
2. **§15.6 中「G4 预期收益必须下调」的论据已被同目录报告修正**（关键词身份口径 → 名称 token 口径；
   同一批 139 技能出现 10 簇/33 技能近重复）⇒ 已在该处加修正注记，⛔ 不得再按"零重叠"低估 G4；
3. **`PerFamilyCap = 0` 的语义此前未定义**，本片必须显式改造（§2.2），并**声明对 G3 冻结物的改动**；
4. **关键词唯一性守卫在写入侧不存在**（G7 §9 已记录）：G7-C3 是**准入侧碰撞检测**，
   G4 的守卫是**存量归属裁决** ⇒ 两者分层，不得混为一谈（§2.4）；
5. **合并四条件可能"永不触发"**：既有闸门①要求工具集合**完全相等**，与家族簇的现实可能冲突 ⇒
   **必须实测**并显式裁决（§2.5-3）。本任务书**不预判**结论；
6. **近重复口径是保守下界**：名称 token 只能发现"名字就像同一件事"的重复 ⇒
   "G4 未找到族"**不等于**"没有重复"；真正的语义相似度需 embedding（属 **T4** 切片）；
7. **`.Take(50)` 限制**：`ConsolidateExistingAsync` 只取前 50 个启用技能 ⇒
   家族内上限的**计数口径**必须显式声明是"全部启用"还是"评审窗口内"，两者结论可能不同；
8. **遥测仍未激活**（G2 需一次重启窗口）⇒ 本片**不得**依据"使用次数/成功率"做任何判定（那会踩"无度量不调参"）。
