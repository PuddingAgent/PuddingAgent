# Agent 编辑工作台设计方案

- 日期：2026-10-01。
- 状态：一期已实施（见文末「实施记录」与偏差说明）；二期未开始。
- 范围：截图中的工作区 Agent 编辑界面，重点为「角色与 Prompt」。
- 架构：在既有 Web UI 中实现，沿用 WinUI Shell + WebView2 + 独立 Core 的边界。
- 配套：[桌面布局示意](../Design/Agent-Settings-Workbench.svg)。示意中的 Agent 名称、文本、字数和状态均为设计示例，不代表实际配置。

## 1. 推荐方向

将当前固定宽度抽屉改为**接近全屏的 Agent 编辑工作台**。保留六类设置导航，将「角色与 Prompt」改成「文档目录 + 单文档大编辑器」。顶部始终显示正在编辑的 Agent、所属工作区、未保存状态和保存操作。

这是编辑复杂配置的专用视图。用户从列表进入，完成后返回原列表位置；编辑时把空间和注意力交给当前 Agent。入口仍可复用现有 Drawer，第一阶段无需增加页面路由。

推荐默认打开基础信息；用户在同一次编辑中切换分区、文档时保留草稿、光标与滚动位置。「新增 Agent」仍从基础信息开始，不强制用户填写所有高级配置。

## 2. 当前问题与判断依据

| 当前表现 | 对操作的影响 | 改进方向 |
|---|---|---|
| 960px 固定抽屉覆盖在宽屏右侧，背景列表被遮罩占据另一半 | 大屏不能改善编辑效率，列表也无法操作 | 大屏编辑容器自适应放大，背景仅保留少量上下文 |
| 系统提示词和用户模板为固定行数文本框 | 长文档需反复拖动内部滚动条，难以审阅结构 | 编辑器使用剩余高度，正文成为主要内容 |
| 六份 Markdown 内容藏在折叠面板里 | 难以发现配置、比较修改范围；多面板展开又拉长页面 | 文档目录显示全部条目，选中一份进行编辑 |
| 标题仅「编辑 Agent」 | 用户切换多个 Agent 后不易确认操作对象 | 展示头像、名称、工作区与来源模板说明 |
| 保存按钮可见，但缺少持续的草稿反馈 | 难以确认哪些分区改过、当前是否已保存 | 总体状态、分区标记、文档标记保持一致 |
| 文件名、中文职责、字段说明混在同一行 | 技术身份与使用目的都不够突出 | 中文名称优先，文件名作为次级信息 |

源码依据：`WorkspaceAgentSettingsDrawer.tsx` 当前设置 `width={960}`，Prompt 输入框分别使用 `rows={7}`、`rows={3}`，其余文档使用 Collapse；共享 `styles.ts` 使用 184px 导航列和滚动内容区。截图中文本框高度可能还受实际运行版本、样式和缩放影响，本方案不将其归因为已确认的 CSS 缺陷。

已有保存加载状态、关闭前未保存确认、分区校验跳转应保留并完善，不重复建立第二套保存机制。

尺寸按 CSS viewport 计算，不按显示器物理像素计算；须兼容 Desktop WebView2 的 DPI 缩放。

| 视口宽度 | 容器与导航 | 编辑区 |
|---|---|---|
| ≥1440px | 容器宽 `min(94vw, 1600px)`；分区导航 168px，文档目录 200px | 剩余宽度全部用于正文；不增加常驻右侧说明栏 |
| 1024–1439px | 容器占满可用宽度；分区导航 160px；文档目录收为顶部选择器 | 保持正文宽度，选择器显示文档中文名及修改状态 |
| 768–1023px | 全宽容器；分区使用顶部可横向滚动导航；文档使用选择器 | 单列编辑，操作区保持可见 |
| <768px | 全屏；分区及文档通过两个明确标注的选择器切换 | 单列正文，按钮可触控，虚拟键盘不覆盖保存及当前输入 |

顶部约 72px，底部说明约 40px；正文区使用 flex/grid 剩余高度，子容器设置 `min-height: 0`。导航可独立滚动，编辑模式正文滚动，预览模式预览区滚动，避免整页、折叠面板、文本框三层同时滚动。

基础信息等普通表单分区不显示文档目录，表单内容最大宽度约 880px，行间距保持适中；不为了铺满宽屏把所有字段拉成长输入框。

## 4. 信息架构与字段映射

六类设置保持原有业务分组；仅将「角色与 Prompt」的内部组织调整如下。目录中中文职责是主标题，文件名是次级标签，字段名属于实施文档，不展示给普通用户。

| 目录分组 | 显示名称 | 次级标签 | 现有字段 |
|---|---|---|---|
| 常用 | 系统提示词 | 核心职责与行为 | `systemPrompt` |
| 常用 | 用户消息模板 | 可选 · 占位符模板 | `userPromptTemplate` |
| 行为与协作 | 人设与边界 | SOUL.md | `soulMdContent` |
| 行为与协作 | 协作规范 | AGENTS.md | `agentsMdContent` |
| 行为与协作 | 工具约定 | TOOLS.md | `toolsMdContent` |
| 行为与协作 | 记忆策略 | MEMORY.md | `memoryMdContent` |
| 生命周期 | 心跳恢复 | heartbeatPrompt.md | `heartbeatPrompt` |
| 生命周期 | 首次引导 | BOOTSTRAP.md | `bootstrapMdContent` |

这里的目录是现有字段的编辑入口，不意味着新增磁盘文件管理功能。调整显示顺序也不改变 Runtime 的 Prompt 组合顺序或优先级。

文档条目显示选中状态、已修改标记、校验错误；空值显示「未填写」，不一律显示「未配置」。心跳留空显示「使用默认提示词」，因为当前界面已说明该回退语义。其他文档的空值语义须核对 Core 后再写提示，不能统一宣称「继承默认」。

来源模板显示「创建自：通用助手」，配说明「创建时复制配置，之后独立修改」。不使用「继承中」「同步中」；编辑模式保留来源模板不可修改的现有约束。

## 5. Prompt 编辑体验

### 编辑器

- 标题显示当前文档名称、用途和是否可选；长说明通过「说明」入口按需展开。
- 正文默认编辑模式，保留自然换行；中文正文 14–15px、行高 1.7，代码片段使用等宽字体。不要把普通中文 Prompt 整体做成代码终端风格。
- 第一阶段可使用现有 textarea 加大编辑区域并补齐编辑工具，不因外观需求强制引入大型编辑器。现有前端若已有合适组件，再评估复用。
- Markdown 文档提供「编辑 / 预览」切换；用户消息模板提供原文预览，变量不自动替换成猜测值。
- 提供文档内查找；字符数放在正文底部。没有真实 tokenizer 支持时不展示貌似精确的 Token 数。
- 不自动插入角色说明或默认段落，不在切换文档时修剪空白、改写原文或覆盖输入。

### 占位符模板

「用户消息模板」显示格式说明和已出现变量名称，但一期只做文本辅助，不暗示任何变量都能被运行时解析。变量允许列表、缺失变量行为、转义规则和实际渲染结果须以既有 Core 实现为准。

有真实解析合同后，二期可增加「填写样例变量 → 查看渲染结果」，标明仅为本地预览。不得为了界面预览偷偷发起模型请求。

### 当前修改比较

二期增加「查看本次修改」，对比打开编辑时的快照与当前草稿；比较范围是本次编辑，不宣称为历史版本管理。恢复操作只针对当前文档，按钮明确写「恢复到打开时内容」，避免「恢复默认」与模板快照、系统默认的含义混淆。

## 6. 保存、反馈与异常

| 状态或动作 | 推荐行为 |
|---|---|
| 初次加载 | 标题与结构先显示；数据区显示加载状态，加载完成后才允许编辑和保存 |
| 无修改 | 状态「无未保存更改」，编辑模式保存按钮禁用；新增模式按必填校验允许创建 |
| 有修改 | 状态「未保存 · N 项」，分区及文档显示标记；N 为变化字段数量，不是按键次数 |
| 内容改回原值 | 与初始快照相等后取消对应修改标记；不能只以发生过 onChange 判定 dirty |
| 切换分区或文档 | 草稿保留；不弹关闭确认，不要求先保存当前文档 |
| 保存 | 一次保存整个 Agent 表单；按钮加载、禁用重复提交，明确文案「保存所有更改」 |
| 保存期间 | 一期暂时禁用表单编辑，避免后续输入被误标成已保存；保留正在显示的内容 |
| 保存成功 | 按实际 API 返回确认成功，刷新基线；保留工作台和当前文档，不自动关掉编辑器 |
| 校验失败 | 顶部给摘要，分区和文档显示错误数量；自动导航并聚焦第一个错误字段 |
| 网络或服务失败 | 保留草稿，显示可理解的错误和重试操作，不清除 dirty 状态 |
| 关闭 / Esc / 返回列表 | 无修改直接返回；有修改提供「继续编辑」「放弃修改」「保存并返回」，保存失败仍留在原界面 |
| 同时修改冲突 | 只有 API 支持版本标识后才实现冲突检测；不承诺当前接口已经能识别覆盖冲突 |

默认采用显式保存，不引入自动保存或将 Prompt 持久化到浏览器本地存储。权限、模型、执行护栏和 Prompt 都有实际行为影响，用户应能控制何时提交。

「保存成功」表示配置已写入，不代表所有正在执行的任务立即应用新配置。生效时机必须核对各字段的运行时读取逻辑后给出准确说明，不统一写「立即生效」。

Ctrl+S / Cmd+S 在工作台内触发保存并阻止浏览器另存为；输入法组合期间避免抢占按键。键盘可达分区、文档及操作，选中态除颜色外还用背景、字重和 `aria-current` 表达；错误具有文本说明，不只显示红点。

## 7. 其他分区的设计约束

| 分区 | 推荐结构 |
|---|---|
| 基础信息 | 头像与名称并列，下面为职责、角色、启用状态；来源模板作为只读信息，避免和可编辑字段混淆 |
| 能力与 Skill | 保留现有授权语义；显示已选数量、搜索及选择列表，清楚区分能力授权和 Skill 包 |
| 模型与记忆 | 主模型、记忆模型、Embedding 与检索策略按小标题分组，供应商变化后的加载和空列表状态可见 |
| Smart 子代理 | 七种角色使用一致的模型选择行，角色职责在次级说明显示；不把所有角色强制配置成必填 |
| 执行护栏 | 轮次、耗时、工具调用上限显示单位；保留既有最小值、最大值和默认语义 |

这些分区统一标题、间距、错误及保存反馈；本轮不重做整个工作区导航或 Agent 列表，也不改 Core 的字段含义。

## 8. 视觉语言

沿用现有紫色品牌与 Ant Design token。主操作、当前导航和焦点使用主题紫色；普通内容保持低对比背景与细边框，避免所有卡片都加紫色描边。

- 背景使用页面浅灰、导航浅灰与正文白色三个层级；选中条目使用淡紫色背景。
- 顶部 Agent 名称 18–20px，分区标题 16px，正文和表单 14px，次级说明 12–13px。
- 基础间距采用 8 / 12 / 16 / 24px；输入区域圆角约 8px，按钮高度 36px，移动触控目标至少 44px。
- 修改标记使用小圆点加文字/提示，错误使用图标和数量；大块高饱和背景只用于主要按钮。
- 同时验证亮色、暗色主题；实现用主题 token，示意图的颜色是亮色样例，不应硬编码为产品颜色。

## 9. 实施顺序与代码归属

### 第一期：编辑效率与状态完整性

1. 在现有 Drawer 上调整宽度与响应式，增加 Agent 身份栏和持续保存状态。
2. 将八个 Prompt 字段建立为静态目录元数据，复用现有表单字段；改为单文档编辑区。
3. 完成草稿快照比较、修改标记、保存失败反馈、保存期间编辑策略及跨分区错误聚焦。
4. 保留普通表单分区，确认隐藏文档不会丢值、跳过校验或意外覆盖其他字段。
5. 提供基础 Markdown 预览与查找，优先复用项目现有依赖。

主要位置：

- `Source/PuddingPlatformAdmin/src/pages/workspace/[id]/WorkspaceAgentSettingsDrawer.tsx`：容器、身份栏、保存和关闭交互。
- `Source/PuddingPlatformAdmin/src/pages/agent-template-settings/AgentTemplateSettingsNav.tsx`：分区导航状态。
- `Source/PuddingPlatformAdmin/src/pages/agent-template-settings/styles.ts`：共享 token 与布局。修改前检查其他调用方，工作区专用布局应独立封装，避免影响全局模板编辑。
- 建议新增工作区专用 `AgentPromptEditor.tsx` 与 Prompt 目录元数据；按实际复用需要再提取共享组件。

全局 Agent 模板有不同字段（例如 `personaPrompt`、`toolsDescription`、`agentsPrompt`），不能直接与实例字段共用一个硬编码表单；若后续统一外观，通过显式字段映射复用展示层。

### 第二期：审阅与高级辅助

增加本次修改比较、恢复到打开时内容、模板变量预览。真实运行时 Prompt 组合预览、版本历史和生效冲突属于独立能力，须先确认后端合同，不能用前端拼接假装权威结果。

一期无需 Core API 变化；若为了保持保存后视图需要更新父组件成功回调的关闭行为，应在前端调用链内完成并回归原入口。

## 10. 验收场景

- 在 1920×1080、1440×900、1280×720 和 390px 宽 CSS 视口，以及 125% / 150% 缩放下没有横向溢出；720px 高度下保存仍可见，正文可持续编辑。
- 输入超过 10,000 字符的系统提示词，切换到协作规范再返回，文本、选择位置和滚动位置保留；无法保存时内容仍在。
- 同时修改 Prompt、模型和授权，一次保存后重开确认三类修改一致持久化，没有因未挂载字段而丢值。
- 修改内容再改回，标记恢复为未修改；修改多个字段时计数准确。
- 不活动分区存在校验错误，保存时能切换到正确分区和文档并聚焦，不只在隐藏节点显示错误。
- 保存重复点击不会重复提交；失败不会误显示已保存；保存成功后仍留在当前文档。
- 关闭时正确处理保存、放弃和继续编辑；Ctrl+S 不触发浏览器另存为，中文输入法操作正常。
- Markdown 预览对 HTML 和链接采取项目一致的安全处理；不执行文档中的脚本。
- 保持 Agent 实例、来源模板快照及系统默认内容的语义区别；无意外模型请求、无凭据展示。

前端构建与测试使用 pnpm。实现验收须覆盖真实 WebView2 中的键盘、DPI、滚动和保存行为；设计示意与设计文档本身不等同于已完成上述功能验收。

要点与偏差：

1. **草稿快照必须带 `preserve`**。Prompt 文档字段由受控编辑器写入表单、不渲染 `Form.Item`，`getFieldsValue()` 不会返回它们；脏值判断改用 `Form.useWatch([], { form, preserve: true })`，并以 `useFormSnapshot.test.tsx` 锁定该行为。
2. **基线时间点由父组件驱动**。新增 `dataVersion`：父组件每次把服务端数据、模板快照或来源模板切换后的新值写入表单都递增，工作台据此重取快照。原设计里「子组件在 effect 中读表单」的做法会与父组件写值竞争（实测会把全部字段判为已修改），因此改为显式信号。
3. **隐藏分区改为按需渲染**。非活动分区不再常驻 DOM，只有活动分区挂载；Prompt 文档同理只渲染当前文档，未挂载字段由表单 store 保留，保存仍是整表单一次提交。
4. **保存不关闭工作台**（编辑模式）：父组件 `onSave` 返回是否成功，成功只刷新列表并刷新基线，用户留在当前文档。**新增模式成功后返回列表**，否则父组件的 `editItem` 仍为空，再次保存会重复创建。
5. **抽屉 `mask={false}`**：宽屏保留背景列表作为上下文；关闭由抽屉遮罩取消，改由「返回列表」与 `Esc` 触发三选一确认。
6. **占位符只做文本辅助**：展示已出现的 `{{变量}}` 名称，不替换、不猜测；没有真实分词器时不显示 Token 数。
7. **空值语义以 Core 为准**（`WorkspaceAgentFileService.WriteAgentMdFileAsync`：内容空白即不写文件、并从 manifest 移除引用；心跳另有 embedded 默认提示词回退）。因此只有心跳显示「使用默认提示词」，其余显示「未填写」，不统一宣称继承默认。
8. **生效时机表述**：`AgentRuntimeProfileResolver.ResolveAsync` 在运行入口按需解析，未做缓存；界面只说「下一次读取配置时生效」，不断言「立即生效」。
9. **共享样式未改动语义**。工作台样式独立成 `workbenchStyles.ts`；`AgentTemplateSettingsNav` 只新增可选 `className`/`markedSections`/`badges`，全局模板抽屉外观与行为不变。
10. **Markdown 预览安全**：不启用 `rehype-raw`，HTML 按文本处理；链接新窗口 + `noopener`。这与聊天 `MarkdownBlock`（为渲染 Agent 输出而启用 raw）刻意不同。
