## 1. 结论（ADR-089「60s 轮询 **+ 退避**」闭合）

ADR-089 原文写的是「监听不可用时 60s 轮询 **+ 退避**」——**退避从未实现**；且 U3-D 把该路径从
「只有被标位的 scope 才可能走到」扩到「**任何根消失的 scope 首次常规 sweep 后都会走到**」，
于是一个坏 scope = **1440 次探测 + ≈2880 行 Error/天**。本刀补上退避：

**一个永久坏掉的 scope：1440 → 52 次探测/天（−96.4%）；首周 10080 → 340（−96.6%）。**

## 2. 退避语义（父级**实读源码复核算术**，非仅采信）

```csharp
internal static TimeSpan CalibrationBackoffInterval(long consecutiveFailures)   // :1015
{
    var interval = DefaultCalibrationInterval;                                  // 60 s
    for (var rung = 1L; rung < consecutiveFailures && interval < DefaultCalibrationBackoffMax; rung++)
    {
        var doubled = interval + interval;
        interval = doubled > DefaultCalibrationBackoffMax ? DefaultCalibrationBackoffMax : doubled;
    }
    return interval;
}
```

- **阶梯**：`failures=1 → 60s ｜ 2 → 2m ｜ 3 → 4m ｜ 4 → 8m ｜ 5 → 16m ｜ ≥6 → 封顶 30m`
  （**封顶从第二次失败起才翻倍** ⇒ 单次失败仍等 60s，即 U3-C 语义逐字保留）。
- **封顶在循环内以 `>` 显式夹取 + 循环出口条件双重保证** ⇒ 失败 10⁶ 次与 6 次同价，**无溢出**。
- **复位**：`ResetCalibrationBackoff`（`:1056`）—— 任何一次**读到了根**的 sweep（**完成或截断**）立刻归 0；
  仅在 `previous != 0` 时记日志（健康 scope 静默）。
- `ConsecutiveCalibrationFailures` 是 `ScopeEntry` 上的**服务内私有节流状态**（`:197`），与既有
  `LastCalibrationAttemptAtUtc` 同 `_gate`、同位置 ⇒ **未新增任何公共状态字段**，「15min 常规钟 vs 阶梯」二者**永不同时参与**。

**尝试时刻（父级独立推导，与报告一致）**：`0, 60, 180, 420, 900, 1860` 秒，此后**每 1800s**；
首日 `6 + floor((86400−1860)/1800) = 6 + 46 = ` **52** 次；首周 `6 + floor((604800−1860)/1800) = 340` 次。

## 5. 必答三问（实测）

1. **序列与封顶**：`60s→2m→4m→8m→16m→30m(恒)`。首日 **52**（对照 1440）、首周 **340**（对照 10080）；每次被拒 2 行 Error ⇒ ≈104 行/天（对照 ≈2880）。
2. **不叠加、不双扫**：判 due 是 `if (NeedsReconcile) {阶梯} else {15min}`，二者**永不同时参与**；每 scope 每步至多一次判定 + 一次 `CalibrateAsync`。**反证**：A1 里被标位 scope 走完 31 分钟（>2×15min），`CalibrationRunCount` 恰 = 6 = 阶梯预测（叠加则至少多 2 次）。
3. **`LastCalibrationAtUtc` 被拒时会盖章**（`:851` 在 `if (!result.RootUsable)` 之前），**但不推迟常规钟** —— 被标位时常规钟根本不被读取，而解位唯一出口是成功 sweep（调用点仅 1 处，已核）。因此常规钟实际**始终锚在「上次成功」**。

## 6. 裁决

**接受 `Truncated → 复位`（而非 +1 档）**：截断意味着**根可读且真删了行**，是**进展**而非失败；算作失败会拖慢大仓收敛（大仓一次扫不完是常态）。若将来要求"截断也退避"，改动点仅为把它换成 `RegisterCalibrationFailure` —— **已登记为可逆的单点选择**。

## 7. 诚实留白（不得当已解决）

1. **根恢复检出延迟最坏 30 min**（原先 ≤60s）—— 这是"**用检出延迟换 96% 探测量**"的**自觉取舍**；恢复一旦被读到档位立刻归 0。
   *可选改进（不在本刀）*：让「变更管线再次观测到该 scope 的路径」或「watcher 重附着成功」作为复位信号，可压回 60s 量级 —— **但会改 U3-B3 的管线语义**。
2. **档位未暴露到 status/快照**：它是服务内私有节流状态。若要把档位暴露给运维，需单独下刀（会动 `Contracts/ICodeIndexMaintenance.cs`）。
3. **探测量是"被拒次数"口径**：未统计"根可读但深层子目录不可读"这类仍识别不了的情形（U3-C RISK 3 同）。
4. **未在真实 `FileSystemWatcher` / 真实 Roslyn 索引器下端到端验证**（与 U3-C/U3-D 同口径）。
5. **`ListFilesAsync` 无分页**仍缺（U3-C 遗留，未夹带）。
