# 右侧多 Tab 工具工作区设计

日期：2026-10-01。状态：**第一阶段（统一分栏 / Tab 容器 / 工具入口 / 收起 / 拖动宽度 / 浏览器适配）已实现**，见 [第一阶段实现记录](../Reports/Desktop-Right-Tool-Workspace-2026-10-01.md)；第二、三阶段（成果与输出预览、受控交互面板、终端会话）仍为设计建议。

## 目标与布局

依据用户补充的参考界面，保留左侧 Shell 导航、Agent 列表和中间聊天的结构、样式及交互，在右侧新增多 Tab 工具工作区。终端、Agent 浏览器、Agent 制成品、输出文件和交互面板均在此打开。原浏览器专用面板建议被本方案覆盖。

展开布局：左侧 Shell 导航 / Agent 列表 → 聊天与输入区 → 可拖动分隔线 → 多 Tab 工具区。聊天仅随剩余宽度自适应，不折叠或重做 Agent 列表。收起布局：保留原工作台，仅在右上角提供工具区按钮与活动提示，不保留空白占位。

工具区自上而下为统一横向 Tab 栏、当前 Tab 的工具栏、内容区域及按需状态栏。Tab 栏右侧提供“+”、放大和收起操作；“+”打开工具选择菜单。参考图的新标签页可作为工具首页，提供终端、浏览器、打开输出文件及最近制成品入口，不加入无关推荐。

## Tab 内容与管理

| 类型 | Tab 名称示例 | 内容与操作 |
|---|---|---|
| 终端 | 终端 · 工作区名称 | 终端输出、输入、实际目录与运行状态；停止进程单独操作 |
| Agent 浏览器 | 浏览器 · 页面标题 | 后退、前进、刷新、地址、目标页面、人工接管；复用现有运行时 |
| 制成品 | 预览 · 销售报告 | 文档、图表、网页等可查看成果；按格式提供预览、打开源文件、导出 |
| 输出物 | 文件 · result.csv | 文件内容或格式化预览，显示路径、类型与所属任务；不支持的格式提供打开/下载 |
| 交互面板 | 面板 · 参数设置 | Agent 生成的表单、筛选器、可视化等；提交与反馈明确关联原任务 |

Tab 对应具体实例，允许同时打开多个终端、页面和成果；不以五个固定分类 Tab 限制内容。文件及制成品按资源身份去重，重复点击激活已有 Tab；终端仅通过显式新建创建新实例。浏览器页面与已有 PageId 一一关联，避免外层 Tab 和内层标签列表重复。

点击聊天中的成果卡片或“在工具区打开”时，展开右侧并激活对应 Tab。Agent 自动产生新输出时只更新活动提示或未读标记，不抢当前 Tab 或键盘焦点。Tab 太多时横向滚动并提供列表菜单；标题截断，悬停可查看完整名称与所属 Agent/会话。

工具区收起、关闭预览 Tab、关闭浏览器页面和停止终端进程是不同操作。关闭运行中的终端 Tab 时应明确选择保留后台运行或停止进程；收起工具区不触发此选择。浏览器关闭沿用现有目标页面关闭规则。切换聊天不自动关闭工具区已有实例，跨会话内容展示所属信息；交互提交始终关联原任务。

## 尺寸与视觉

- 使用逻辑像素：工具区初始占聊天与工具区合计宽度约 45%，最小 360；聊天区域建议至少 560，左侧区域保持现有宽度。无法同时满足时使用覆盖式面板。
- 分隔线视觉宽约 1 像素，提供约 6 像素拖动命中区，悬停显示左右调整光标；支持键盘调整，双击恢复默认比例。记录用户调整后的宽度，每次展开按当前窗口重新限制。
- 窄窗口从右侧覆盖聊天，宽度不超过内容区；点击面板外或按 Esc 收起。第三方 WebView 的叠层和焦点需在实现阶段验证。
- 放大操作暂时占据工作区，返回后恢复分栏与原宽度。
- 延续现有浅暖色背景、紫色选中态和细边框；网页可视区使用页面自身背景，不附加大面积卡片留白。

## 展开与活动规则

1. 首次进入默认收起。用户点击右上角入口或聊天中的“打开”操作才展开；左侧原浏览器整页入口迁到右侧工具菜单，其余导航保持原状。
2. Agent 浏览器活动开始时，入口显示运行指示与简短提示。默认不自动展开，避免打断输入。
3. 可提供“任务开始时自动展开”偏好，默认关闭。用户在当前活动期间主动收起后，本轮后续活动不得再次自动展开。
4. 无活动的面板保持用户选择，不因短暂空闲自动关闭；下次启动默认收起，记住宽度与自动展开偏好。
5. 收起仅改变显示，保留标签页、登录状态和 Agent 目标，不停止任务、不销毁运行时、不导航到空白页。后台网页及自动化在隐藏后的行为须实测。
6. 可见标签页与 Agent 目标继续分离；用户切换标签不自动改变目标。“设为 Agent 目标”和“人工接管”保持显式操作。
7. 浏览器活动可能来自其他会话，面板显示实际 Agent 身份，不能从当前聊天选择推断所属者。

## 技术边界与实施

现有 MainWindow.xaml 的 BrowserPane 与 WorkbenchPane 作为兄弟页面，OnNavigate 切换其 Visibility。浏览器运行时使用 WinUiBrowserSurfaceHost 和 BrowserWorkspaceController；因此右侧承载区由 WinUI Shell 调整，业务聊天继续保留在 Web UI，Core 保持独立进程。

> **实现更新（2026-10-01，第一阶段）**：`MainWindow.xaml` 已删除 `BrowserPane`，左侧导航不再有「浏览器」整页入口（按设计 §39 迁入工具菜单）。`WorkbenchPane` 改为「聊天 ∥ 分隔线 ∥ 工具区」三列分栏；工具区自上而下为实例 Tab 栏（+ 放大 收起）、当前工具操作栏、内容区与状态栏。浏览器 surface 宿主改为工具区内**单一常驻面板**，外层实例 Tab 与 `PageId` 一一对应，不再随 Tab 重挂载 WebView2。布局与实例策略提取到 BCL-only 的 `PuddingDesktop.Foundation`（`ToolWorkspaceLayout`、`ToolWorkspaceTabs`、`ToolWorkspaceActivityPolicy`），WinUI 层只做投影。布局偏好落在 `desktop.json` 的 `toolWorkspace` 节。详见 [第一阶段实现记录](../Reports/Desktop-Right-Tool-Workspace-2026-10-01.md)。

建议将工作台与工具区放入 Shell 内容区的分栏容器，工具区展开状态独立于主导航。Shell 只管理布局、Tab 容器及原生能力承载；制成品、输出物及交互面板的业务展示使用 Web，数据与执行事实由 Core 提供。复用原 BrowserSurface、运行时及控制器，不在前端 iframe 中重新创建 Agent 网页；Agent 网页与可信工作台使用隔离的浏览器环境，生成 HTML 不获得工作台认证或桌面桥权限。

建立统一 Tab 描述：类型、实例 ID、标题、所属工作区/会话/Agent、内容引用及实际运行状态；业务状态由服务提供，Shell 不复制执行状态机。Web 点击成果经限定的桌面桥请求打开资源，终端输入经已有受控服务执行。终端若缺少可复用会话能力，先交付独立组件与测试，再接入宿主；不可只嵌入输出文本便宣称完整终端已实现。

第一阶段实现统一分栏、Tab 容器、工具入口、收起、拖动宽度及浏览器适配；第二阶段接入成果与输出文件预览、受控交互面板；第三阶段接入终端会话并完成窄窗口、放大和恢复验证。桌面布局偏好沿用 desktop.json，按已有配置合同登记字段；进程、终端及业务资源状态不写入布局配置。重启后失效的终端或交互任务显示真实不可用状态，不伪装恢复为运行中。

## 验收

- 收起后无空白占位，展开时聊天输入框和独立滚动仍正常；改变窗口大小、DPI 和面板宽度不截断关键操作。
- 左侧列表与聊天结构保持原状；多个类型 Tab 可切换、关闭和重新打开，重复资源不创建重复实例，后台事件不抢焦点。
- 输出预览正确关联资源及所属任务；交互提交不因切换聊天而投递到错误任务；关闭运行终端与收起工具区具有明确不同语义。
- Agent 正在导航或执行时反复展开/收起，不丢标签页、不重载网页、不改变目标，工具调用保持有效。
- 人工接管遵循现有控制权规则；切换聊天或浏览器标签不错误改绑目标。
- 自动展开关闭时活动仅提示；当前活动被手动收起后不反复弹出。
- 键盘焦点、Esc、中文输入法、第三方网页叠层及 Core 断连恢复通过真实桌面验证。

本次第一阶段交付布局、Tab 容器与浏览器适配；编译与单元门禁见实现记录，真实桌面项（键盘焦点、Esc、中文输入法、第三方网页叠层、收起后网页/自动化后台行为、Core 断连恢复）仍需外部控制器重启到新构建后验证，未验证项一律不视为已通过。
