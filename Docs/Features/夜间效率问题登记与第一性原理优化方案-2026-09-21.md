## N01 回归门禁：按失败用例身份对拍，必测未测不得通过

### 发现的问题与证据
夜间套件不是全绿：Core 910通过/1失败，Runtime 1659/0，Platform 1363/0，Admin 1349/3，WebApi因MSB3027未执行。TestScripts/test-pudding-suite-gates.ps1 的 Admin KnownRed=null、AllowedFailures=3；默认UNMEASURED，仅FAIL导致非零退出。

### 第一性原理分析
门禁本质是一个证明器：它必须证明候选没有违反指定性质。失败数量是集合的有损投影，旧失败消失、新失败出现可保持计数不变；未执行意味着未知，不能推出通过。把进程exit0、历史统计或总数当证明，会使后续RSI奖励“更容易过关”而非产品变好。

### 规划的代码级优化方案
1. 修改test-pudding-suite-gates.ps1：读取本次TRX/Jest JSON，产出suite、caseId、结果、source/dependency/toolchain/command fingerprint及证据路径；禁止复用上次日志。
2. 冻结基线失败集合及适用源码/环境；比较newFailures=currentFailures-baselineFailures。基线例外带原因和到期复核，不设全局“容许3失败”。
3. 明确Passed/Failed/Unmeasured/Skipped；必测Unmeasured、锁定、构建失败、缺统计、进程非零均不能返回门禁成功。环境问题单列，不伪装业务回归，也不自动放行。
4. 将判定器与候选修改范围隔离，基线/评测规则变更独立审核；输出结构化证据给Goal检查器和RSI evaluator，而不是让模型口述通过。

### 验收与反误伤
负例覆盖：旧红减少但新红增加、全部未测、空报告、旧统计文件、exit非零但日志有通过数字、参数化case标识稳定。正例覆盖：已批准基线原样、真实修复旧红、全部必测完成。每例断言判定与退出码；不删测试、不抬预算。

### 依赖与实施边界
