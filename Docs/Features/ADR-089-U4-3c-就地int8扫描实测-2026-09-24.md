## 3. 等价性（最关键的一条）

5 个规模 × 100 次查询 × 3 条扫描路径：top-20 id 序列 **`mismatch = 0`**，每个 rank 的
**最大 |score 差| = 0**（不是 < ε，是**恰为 0**）。

**R2 陷阱真的被守住了** —— 这条是本刀最有价值的证据：
变异 **M1B** 把算术改成 `(double)codes[i] * (double)scale`（错误写法），**id 序列当时并未改变**，
只有"分数差恰为 0"这条断言抓到它：

```
失败 A2_In_Place_Scan_Reproduces_The_Shipped_Ranking_Bit_For_Bit
  'maxDelta == 0d' … the largest |score difference| is 2.9006723412106084E-09
  but the two paths run the same arithmetic sequence, so it must be exactly 0
```

⇒ **若实现者写了第二种相似度定义，本刀会红。** 这是"一条相似度定义"从注释变成断言的地方。

## 5. 实现要点（父级实读源码）

- **独立类型** `QuantizedInMemoryVectorIndex`（282 行），持有 `IReadOnlyList<QuantizedVectorEntry>`，**codes 原样、不预先反量化**；
  未给既有 `InMemoryVectorIndex` 加开关（与其自身"separate type rather than a flag on it"的立场一致）。
- 扫描核心（正确写法，含点名错误写法的行内注释）：
  ```csharp
  var component = codes[i] * scale;      // 先在 float 里乘
  dot += (double)component * query[i];   // 再提升到 double 累加
  ```
- 范数在 `Add` 时按 `VectorMath.Norm` **同序**预计算一次 ⇒ 分数仍**逐位相同**。
- 有界 top-k = 大小 `min(topK, Count)` 的**最大堆**，比较器逐字复刻 shipped（分数降序 → 同分 `CompareOrdinal(Id)`），
  出堆即 rank 逆序 ⇒ **不全量排序、不物化全量**。

## 6. 同批被量化的设计决策（有实测支撑）

同一有界插入扫描，只把**范数改成扫描内联**重算 ⇒ 10,199 行 p95 **14.227 → 23.377 ms（+64%）**；
堆 vs 有界插入仅差 ~1%（14.068 vs 14.227）。⇒ 预计算范数是**性能必需**，不是提前优化。

## 7. 裁决与诚实留白（不得当已解决）

1. **未接入生产**：本刀**不主张任何端到端检索收益**；`InMemoryVectorIndex` 仍是主链。接入需新切片（端口 / DI 接线 + 加载期范数一致性契约）。
2. **20.207 ms 是扫描预算**（= 50 ms 端到端 − U4-3b 实测嵌入 p95 29.793）；两者相加得 10,199 行端到端 ≈ 43.9 ms 属**算术相加、未实测**。
3. **语料构成**：10,199 是**真实规模**（Core P0 实测），但 ≥475 的向量是"真实行 + 扰动再量化"；真实 10,199 行嵌入需跑服务落盘，属另一刀。
4. **全仓仍需并行或 ANN**：全仓 P0 实测 **45,677 行 ≫ 单线程拐点 ≈14.7k 行**（两点**插值**，非实测点）。
5. **范数预计算占 O(N) 个 double**（10,199 行 82 KB、65,536 行 524 KB），**未计入 1 GB 磁盘体积预算**（口径不同）。
6. p99 基于 n=100 nearest-rank（≈最大值）；单机可能有其它 Agent 进程（20,000 行 shipped p95 99.6 与 p50 84.8 偏大属 GC 抖动）。
7. **一次真实仪器事故（已修正并登记）**：首次"复原"用 `copy /y` 保留旧时间戳 ⇒ MSBuild 判定无需重编译、**测试跑的是变异 DLL**；
   靠"绿态输出与红态逐字节相同"才发现。此后所有复原显式重设 `LastWriteTime`。⇒ **DLL 时间戳核对必须成为变异流程的固定步骤。**
