## 1. 目标（一句话）

把"技能组合的容量"从**没有任何约束的「增」**，变成**类型级、可版本化、可审计、LLM 无法越过的预算判定**：
新增 `SkillPortfolioPolicy`（策略一等对象）+ 预算判定器，并在**唯一真实的技能创建通道**上接线，使
「LLM 要求 create 但预算已满」这种情况**在类型/判定层就被降级**（`Merge` / `Defer` / `Displace`），而不是靠提示词或人工巡检。

**为什么这是基础设施而不是一段 `if`**（引设计原文）：阈值全部来自**已有策略对象**（S2a）⇒ 预算**可版本化、可审计、可随结果落库、可被评测守卫**。**不新增阈值类型**。

## 2. 冻结契约（§13.5，逐字固化，不得弱化）

### 2.1 策略对象形状

```
SkillPortfolioPolicy { policyId, version, hardCap, softTarget, perFamilyCap, minMarginalGain, stalenessDays }
```

### 2.2 判定序（**fail-closed**）

| 情形 | 判定 |
|---|---|
| `enabled < softTarget` | 走既有去重；通过 ⇒ `Admit` |
| `softTarget ≤ enabled < hardCap` | 仅当 `candidateScore − minEnabledScore > minMarginalGain` ⇒ `Admit`；否则 `Merge` / `Defer` |
| `enabled ≥ hardCap` | **必须置换**：`candidateScore > minEnabledScore + minMarginalGain` ⇒ `Displace(价值最低者)`；否则 `Merge` / `Defer` |

### 2.3 验收三条（§13.8，不可协商）

1. **预算不可被 LLM 越过** —— 必须存在一条用例：构造「LLM 要求 create 但预算已满」⇒ 判定**不是** Create；
2. **置换＝禁用（可回滚）** —— `Displace` 的落点是对被置换者**禁用**，且留下「谁被置换 / 依据哪条策略哪个版本」的可回滚记录；
3. **阈值全部来自策略对象** —— 判定器内**不得**出现裸阈值字面量；不同策略实例必须产出不同判定。

### 2.4 父代理补充裁决（§13.5 未覆盖，本片必须实现）

| # | 补充条款 | 依据 |
|---|---|---|
| **S1** | **判定器输入必须是「带刻度的分数」，不是裸 `double`** —— 类型上携带 `ScoreScale` + `ReasonCode`，使「无数据」与「数据表明很差」**在类型层不可混同** | `SkillValueScorer` 冷启动契约（§4-D）：`Score=0` 是**占位、不可解读**，识别依据是刻度串与原因码 |
| **S2** | **冷启动（候选或全体已启用均为"无数据"）⇒ 判定降级为 `Defer`，禁止 `Displace`** | §13.10 **R1**：冷启动**只降不杀**；把"无数据"当"低价值"会造成**静默误杀**（R2） |
| **S3** | **降级单调性（no-upgrade）**：判定器只能把既有去重结论**向下**调（Create ⇒ Merge/Defer/Displace），**永不允许向上**（Merge/Skip/Defer ⇒ Create） | "不可被 LLM 越过"的可判定形式；也防止预算判定器成为第二条绕过既有去重的通道（§12.2 C2：不要第二条写入通道） |
| **S4** | **默认策略取"零回归"值**（宽松到不改变现状行为），并显式配置化；契约的有效性由**测试中的显式策略**（如 `hardCap=3`）来证明，而不是靠默认值收紧 | 现网已有启用技能，若默认 `hardCap` 低于现状 ⇒ 本片一落地就**改变生产行为**。G3 的正确姿势是"先装仪表盘与闸门，阀门开到现状之上" |
| **S5** | `perFamilyCap` / `stalenessDays` **本片只承载字段、不消费**（家族判定属 G4；陈旧度策略属后续切片）⇒ 任务书与代码注释必须**显式声明未被消费**，禁止让读者以为已生效 | 防**幻影区间**（写了但没人做、且断言抓不到） |

### C. S2a 策略对象模板（**照抄形状**）

`Source/PuddingCore/Operators/ThresholdPolicy.cs`（142 行，namespace **`PuddingCode.Operators`**）：

- `public sealed record ThresholdPolicy : IVersionedCriterion`
- `required string PolicyId` / `required int Version`（**版本化是类型事实**）
- `IsValid` + `EnsureValid()`：**非法配置一律拒绝**（抛 `InvalidOperationException`），不得静默产生退化解
- `Apply(double score) → JudgeOutcome.{Yes,No,Abstain}`：确定性三区间
- `ToApplied() → AppliedThreshold`：**物化为可落库的已应用快照**（事后解释"为什么放行"）
- `static Create(...)`：**校验式工厂**，非法配置在构造期即被拒绝
- 兄弟形状：`AcceptanceThresholdPolicy.cs`（逐标签单侧验收门）、`IVersionedCriterion.cs`、`IAcceptanceThresholdPolicyProvider.cs`

⇒ `SkillPortfolioPolicy` **照此形状**：`sealed record`（`PolicyId`/`Version` required）+ `IsValid`/`EnsureValid` + 判定方法 + `ToApplied()`快照 + `static Create` 校验式工厂。
⇒ **"不新增阈值类型"** = 判定所需的"分数≥阈值"比较**复用 `ThresholdPolicy`**（或其语义），**不得**再造一个 `MinMarginalGainThreshold` 之类的 record。
⚠️ **落点选择**：`PuddingCore/Operators/**` 受**算子架构门禁**扫描（只扫该目录与 `PuddingRuntime/Operators/**`）。本策略**不是算子**（不产出 `JudgementEnvelope`、不接 LLM）⇒ 暂**不放入 `Operators/`**，避免让门禁语义被稀释；建议新目录 `Source/PuddingCore/Skills/Portfolio/`（纯类型，无依赖）。**该落点由开发者确认后可调，但必须保持"纯类型 + 无 LLM + 可序列化"**。
