# T2 技能价值打分器 · 实施规格（RSI-G2 收官片）

> 2026-09-21 冻结。本规格只做**一个原子目标**：让 `IScorer` 出现**第一个真实消费者**（全景图已证其真实消费者数为 0）。
> 作者：6a8。落地前若发现与本规格冲突的事实，**先改规格再写码**，不得静默偏离。

---

## 0. 为什么是这一片（不是"顺手加个分数"）

RSI 全景图的结论：`IScorer` / `IJudge` 契约、基类、路由**全都在**，真实消费者**为 0**。
这不是"还差一点"，而是**结构性债务**：未被任何真实使用者验证过的抽象，会在第一个消费者出现时被证明"接不上"。
因此 T2 的第一价值**不是产出分数**，而是**把这条抽象压到真实磨床上**。

**若本片发现抽象接不上，正确产出是"记录接不上的证据 + 改抽象"，不是"在消费者侧绕开"。**

### 1.1 ⭐ 无 LLM 路径的合法依据（本片成立的支点）

```csharp
// OperatorBase.cs:243-247
var model = _environment.Model;
if (model is null || instruction.Questions.Count == 0)
    return new JudgementResolution(null, false, null);   // ← Judgement=null 且 Failure=null
```

⇒ **「无模型」不等于「降级」**：判定为 null、且**没有失败**，随后内核照常执行。
所以确定性打分器只需声明**空问题集**（且环境中不配模型），即走**一等公民路径**，**不需要**绕过 `OperatorBase`、**不需要**在基类加 `if (isRsi)` 分支。

**必须用测试钉死这条**（见 §6 N1）：若哪天 `ResolveJudgementAsync` 改成"无模型即降级"，T2 会**变红**而不是静默退化。

## 2. 输入：只喂**真实存在**的事实

数据源：`SkillUsageRecord`（`PuddingRuntime/Services/Skills/Telemetry/`）逐行落盘的 `skill-usage-YYYYMMDD.jsonl`。
可用字段：`SkillId`、`AgentInstanceId`、`MatchedKeywords`、`Injected`、`ContentBytes`、`FailureReason`、`OccurredAtUtc`、`Outcome ∈ {Injected, ReadFailed}`。

场景上下文 `SkillValueOperatorContext : IOperatorContext`（**新增**）：

| 字段 | 语义 |
|---|---|
`SkillId` | 被评分的技能 |
`InjectionCount` | `Outcome=Injected` 的记录数 |
`ReadFailureCount` | `Outcome=ReadFailed` 的记录数 |
`DistinctKeywordCount` | 命中关键词去重数 |
`DistinctAgentCount` | 去重 `AgentInstanceId` 数 |
`InjectedBytesTotal` | `Injected` 记录的 `ContentBytes` 之和 |
`WindowStartUtc` / `WindowEndUtc` | 观测窗口（`OccurredAtUtc` 的 min/max） |
`SceneKey` | 固定 `"skill.value"`（与阈值策略/审计同键） |
`InputDigest` | 上述事实的**确定性**指纹（用于缓存与审计去重） |

### 2.1 ⭐ 故意**不**进来的输入（这是本片最容易做错的地方）

规格（§M2）理想输入含「回合结局」「重叠度」。二者**当前都不存在**：

- **回合结局**：遥测只记命中/注入/读失败，**没有任何 turn outcome**；
- **重叠度**：关键词共享度属于 G5「定主」的产物，尚未产出。

**规矩**：这些字段**不得以 0 / false / 空集合的形式"预先占位"**。
理由：任何公式里，一个默认 0 会**静默变成"最差情况"**并被当真值使用；这正是我们要根除的错误模式。
正确做法 = **不放进上下文类型**（编译期就不可用），并在 §5 记录"缺哪项、缺它影响哪一项判断"。

## 3. 打分函数（可解释、单调、刻度版本化）

记号：`n = InjectionCount`，`f = ReadFailureCount`，`bytes = InjectedBytesTotal`。

```
adoption   = min(1, n / AdoptionSaturationN)                 // 被采用到什么程度（饱和）
reliability= n / (n + f)                                     // 采用中未发生读取失败的比例
avgBytes   = bytes / max(n, 1)
costRatio  = min(1, avgBytes / CostCeilingBytes)             // 注入代价（正文越大越贵）
score      = clamp01( (0.5*adoption + 0.5*reliability) * (1 - 0.5*costRatio) )
```

声明常量（**必须与刻度串同版本**）：

| 常量 | 值 | 含义 |
|---|---|---|
`AdoptionSaturationN` | 5 | 达到该注入次数即视为"充分采用"（饱和点，**不是阈值**） |
`CostCeilingBytes` | 4096 | 平均注入正文达到该字节数即视为代价上限 |

### 3.1 ⭐ 刻度串给打分函数**版本化**

`OutputShape.ScoreScale = "skill-value.v1/0..1"`。

**不变量**：**任何常量或公式改动都必须同时升 `v1`→`v2`**。
因为分数是用于**跨技能排序/比较**的，悄悄改公式会让新旧分数**不可比且无人察觉**——把版本写进刻度串，使"不可比"变成**可检测的事实**。

### 3.2 ⭐ 打分器**不得**包含阈值

- 输出只有 `Score` + `Scale`，**没有通过/不通过**（契约已由 `ScoreResult` 强制）；
- `Threshold` 属性按 `ResolveThresholdFromProvider()` 实现（**不硬编码**）；
- **测试要求（N3）**：给/不给阈值策略，`Scale` 与 `Score` **必须逐位相同** ⇒ 证明阈值没有漏进打分器。

### 3.3 `Project` 的实现规矩

`Project(ModelJudgement, TCtx, scope)` 在无模型路径**不会被调用**，但它**必须编译通过**。
规矩：`Project` 与 `ClassifyCoreAsync` **共用同一个纯函数**（`ComputeScore(context)`），**不得**让 `Project` 依赖 `judgement` 的内容。
配套测试 N2：给定任意非空 `ModelJudgement`，结果仍与无模型路径**完全一致** ⇒ 证明"去掉模型不改变分数"。

## 4. ⭐ 冷启动语义：**无数据 ≠ 低分**（规格明文要求，须有专门用例）

三态必须**可区分**，且任何两态**不得**只靠 `Score` 数值区分：

| 态 | 条件 | `Scale` | `ReasonCode` | `Score` |
|---|---|---|---|---|
**无数据**（未插桩 / 从未观测） | `n == 0 && f == 0` | `skill-value.v1/insufficient-data` | `skill_value_insufficient_data` | `0`（**占位、无意义**） |
**有负证据** | `n == 0 && f > 0` | `skill-value.v1/0..1` | `null` | 公式值（此时 `reliability=0`，分**真实地**低） |
**有证据** | `n > 0` | `skill-value.v1/0..1` | `null` | 公式值 |

**消费方契约（写进类型文档注释）**：判断"能不能用它排序"必须看 `Scale`/`ReasonCode`，**不得**看 `Score`。
`Score=0` 在无数据态与真实低分态下**数值相同、含义不同** ⇒ 这是**故意**的：逼消费方读刻度，而不是读数字。

## 5. 不做的事（防打补丁清单）

1. **不加开关/兼容分支**：不引入 `if (sceneKey == "skill.value")` 之类的特判；不分"RSI 模式"。
2. **不改既有基类语义**：若必须改 `OperatorBase`/`ScorerBase` 才能接上，**停下来记证据并报告**，不擅自改。
3. **不引入 RSI 之外的领域类型**到场景上下文；上下文只描述技能使用事实。
4. **不把缺失输入填 0**（见 §2.1）。
5. **不在打分器里判"该不该淘汰"**：淘汰是 `IJudge` + 阈值策略的事（M1/G6 的范围）。
6. **不读真实遥测作为依赖**：打分器只吃上下文对象；读 JSONL 属于**调用方**（报表/编排层）的职责。

| # | 用例 | 断言 |
|---|---|---|

`Model` 为 null 时**单独一项即已短路**并返回「无判断且无失败」⇒ 仍不降级 ⇒ N1 依旧绿。
因此改用**更强**的变异：让内核返回 `null`，使「内核是否产出结果」真正成为可观测差异。

> 教训：**变异必须真的改变被断言的性质**。照抄一个「看起来相关」的改动，会得到一条**永远绿的假证据** ——
> 比没有证据更危险，因为它会让人误以为该性质已被保护。
> （本条的推导依据是基类条件的**短路（OR）语义**，属代码阅读结论，不是实测；实测的是变异 A 的红。）
