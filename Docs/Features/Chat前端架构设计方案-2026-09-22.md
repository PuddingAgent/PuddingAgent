# Admin Chat 前端架构设计方案

日期：2026-09-22  
范围：`Source/PuddingPlatformAdmin/src/pages/chat/**`；仅设计，不改变后端契约。

## 1. 结论摘要

1. 服务器权威读模型（conversation snapshot）是 turn/message 的唯一业务真值；SSE、轮询、本地乐观状态和历史投影均是输入适配器或派生视图，不得互相直接覆盖。
2. 现有两个性能短路门不能以“看起来相同”丢弃快照：`chatClientStore.ts:94-97` 只比较消息数，`chatClientStore.ts:374-402` 以 cursor 和活动状态推断追平，均应由可判定的逐消息版本/内容指纹合并器取代。
3. 完成事件应触发一次幂等的权威物化，但不是唯一数据来源；物化与轮询/SSE 共存，按 `(workspaceId, agentId, sessionId, turnId, terminalCursor)` 去重。
4. 缺陷 B 的第一责任边界是 canonical projection 到 VirtualMessageItem 的完整性与单一渲染；viewport 只负责滚动，不能截断或复制内容。
5. 不引入状态库和新目录树，沿用 ADR-062 的组合式拆分及 ADR-055 的 viewport 边界；删除无接线价值的骨架，只有 ADR-057 可靠事件流有取证后再接线。
6. 三个关键取舍：以正确性优先接受终态一次回拉的网络成本；以稳定身份/版本优先于长度比较；以增量拆分和懒加载守住 496KB/1536KB 预算。

## 2. 现状事实基线

已复核事实：`chatClientStore.ts:90-99` 的 `isConversationSame` 比较 eventCursor、messages.length、activeRunId 和 mainSessionId，却不比较 message id、正文或状态。入口短路位于 `chatClientStore.ts:374-402`，四条件成立即不发 API；其中 `conversationNeedsProjectionCatchUp` 的判断实现位于 `chatClientStore.ts:21-28`，只看末条是否为 user。`index.tsx:177-197` 以 1200ms/5000ms 定时调用 agent-client 同步；`index.tsx:199-211` 管理 workspace 通知 SSE。`useChatState.ts:1208-1235` 在 agent projection 所有会话上主动停止 per-session SSE。

`MessageList.tsx:1-44` 同时依赖 conversation 类型、projection、viewport projection 和 viewport runtime；这证明渲染入口承担多个边界，但其具体 1442 行体量来自任务书勘察，未在本轮逐行读完，标为已知但未复核。诊断报告的四源对拍（报告 §2.1）证明样本正文四处均为 2355 字符，缺陷在客户端展示链；该对拍证据沿用父级亲验，不重复宣称为本轮实测。

bundle 门禁已复核：`Source/PuddingPlatformAdmin/scripts/check-chat-bundle-budget.cjs:5-18` 规定同步入口 1536KB、Chat chunk 496KB，并把 CheckpointTimelinePanel、ContextMenu 和 workspace-tasks 延迟加载；`Source/PuddingPlatformAdmin/package.json:7-11` 将门禁串在 build 后。依赖清单 `package.json:40-62` 已包含 React、react-virtual、react-markdown 等，不因本方案新增运行时依赖。

ADR-062 §2.1-2.4 明确渐进拆分、无新状态库、组合入口和 port object；ADR-055 §2-3 明确 viewport 是唯一滚动控制层。两者保留，不推翻。

## 3. 目标架构

```text
API / SSE / agent poll / history
              |
       [Ingest adapters]
              v
 [ChatCanonicalStore: immutable snapshot]
              |
       [Monotone merge + selectors]
       /          |              \
 MessageVM   TurnSurfaceVM   ViewportVM
       |          |              |
 MessageList / AgentBubble / ViewportRuntime
```

唯一真值是 `ChatCanonicalStore` 中按 session 保存的服务器会话快照及其每条 message/turn 的稳定身份、生命周期状态、内容版本和事件游标。它不依赖 React。agent-client response、历史 bootstrap 和 SSE replay 只能提交 `CandidateSnapshot`；本地乐观消息以 `optimistic` 标记进入同一合并器，不能另建事实源。TurnSurfaceStore 只保存展开、折叠、动画和临时显示偏好，不能写 message 正文或终态。Selectors 生成稳定 ViewModel，组件只渲染 ViewModel。

不新增状态管理库；以现有 `useSyncExternalStore` 风格和 ADR-062 的组合式 port object 实现。页面入口只组装 workspace/agent/session、发送端口和 selector，不拥有合并规则。

## 4. 状态覆盖规则（P2）

每条 message 的合并键为 `(workspaceId, agentId, sessionId, messageId)`；turn 以 `(sessionId, turnId)` 关联。候选快照先按身份匹配，再按单调证据比较：事件 `sequence/eventCursor` 较新优先；同游标时，内容版本（服务端 version；若后端当前未提供则采用规范化正文 hash + 字符长度 + status 的派生指纹）较完整优先；~~同版本时状态序按 `pending < streaming < succeeded|failed|cancelled`，终态不被非终态覆盖。~~ **实施期已证否（2026-09-22）**：本路径上 `status` 由投影构造点**硬编码为字面量 `"succeeded"`**（`AgentConversationProjectionService.cs:683-702`，且同处 `ProcessItems` 恒传空数组）⇒ 「按状态序合并」在该路径上是**永不生效的死规则**，实施时**不得实现**（切片 1+2 已按此执行，见 `client/canonicalMerge.ts` 文件头注释）。缺少身份或版本的候选不得覆盖已有完整记录，只能记录 deferred hydration。上述“服务端 version 是否存在”未证实，实施前必须以真实 DTO 核对，不能把 hash 当成服务器版本。

伪代码：

```ts
merge(current, candidate) {
  if (candidate.scope !== current.scope) return current;
  for (const m of candidate.messages) {
    const old = current.messageById[m.messageId];
    if (!old || evidence(m) > evidence(old)) upsert(m);
    else if (evidence(m) === evidence(old) && stableFingerprint(m) !== stableFingerprint(old)) {
      upsert(preferComplete(old, m));
    }
  }
  return advanceCursorOnlyWhenSnapshotIsAuthoritative(current, candidate);
}
```

“更完整”必须是可测的：正文字符数不得从非空降为空，过程块数不得减少，已知字段不得被 undefined 覆盖；同一 messageId 的重复事件只产生一次实体。等价性不是消息条数，而是 scope、message identity、content/status/process 指纹和 cursor 全相等。React 层再以 ViewModel key 稳定化避免重复渲染；合并器不以避免渲染为理由丢数据。若同游标不同正文且服务端未给版本，保留字符数较大者并发出冲突诊断，禁止静默覆盖；该冲突处理需取红测试。

## 5. 完成即物化设计（P3/P4）

`turn.completed` 或等价终态事件是“立即请求物化”的触发信号，不是唯一输入。投影器记录 `CompletionIntent`，由 hydration scheduler 发起一次 `getConversation`；事件乱序、断流或 read model 尚未可见时，依据可观测条件判定：事件 sequence 已见终态、候选 scope 与 current session 相同、权威响应 cursor 不小于终态 sequence，且目标 turn 已有终态或正文完整。若 cursor 到达而目标 message 尚不可见，进入 bounded retry（指数退避、次数上限），不得用末条 role 猜测；上限后记录 `read_model_lag` 并保留待下一轮同步。

幂等键为 `(scope, turnId, terminalSequence)`；相同键只允许一个 in-flight/一个已完成物化结果。快照保存幂等键为 `(scope, messageId, evidenceFingerprint)`，重复回拉只产生 merge no-op。SSE、轮询和 completion hydration 共存：SSE 负责低延迟事件，轮询负责读模型收敛，物化负责终态完整性；三者都进入同一个 merge port，禁止各自 setState。轮询可以保留 `index.tsx:177-197` 的节奏，但不得再以启发式 cursor-match 直接 return。

## 6. 缺陷 A / B 的修复落点

- `client/chatClientStore.ts:94-97`：**根因**，长度等价判断吞掉同一 messageId 的正文更新。改为 canonical merge 的 evidence comparator；不是增加另一个长度条件。
- `client/chatClientStore.ts:374-402`：**根因**，cursor 与末条形态推断 read model 已追平。改为始终执行条件请求或由 store 的 authoritative freshness 判定；completion intent 未消费时不得短路。
- `useChatState.ts:1208-1235`：**必要防线**，projection-owned 会话停掉 per-session SSE 后必须由 agent poll + completion hydration 共同承担收敛；不能再出现无补偿机制的停流。
- `index.tsx:177-197`：**必要防线**，把 timer 调用收敛至 store `sync()`，由 store 保证并发和幂等；页面不判断内容是否“看起来完成”。
- `MessageList.tsx:1-44` 及其 projection 调用链：**根因边界待确认/必要防线**。先保证一个 canonical `VirtualMessageItem[]` 输入、按 messageId/turnId 唯一化、正文渲染使用完整 answer；`visibleBlocks` 只能隐藏较早内容块，不能裁剪尾部。任务书给出的 `TurnContentStream.tsx:228-232` 已证不是丢尾根因。
- `AgentMessageBubble` 的正文/过程分支：**防御性加固**。同一 turn 只允许一个正文区域和一个 Activity summary；重复计数由 projection 去重，不在组件内拼第二份。其精确行号本轮未逐行复核，实施前补齐。
- viewport：**防御性加固**。遵循 ADR-055，滚动和测量不改变数据窗口，页面无滚动条不能通过隐藏 overflow 掩盖内容。

## 7. 死代码逐模块结论表

以下按任务书勘察的“13 个逻辑死模块”列出；其中 runtime 五项和 connection 两项各按子模块逐项展开，故表行多于 13，不代表新增死模块。

## 8. 分层与体量治理

按风险顺序：第一波只抽 `merge/evidence/fingerprint` 纯函数并写测试；第二波将 completion hydration scheduler 从页面 effect 移到 runtime port；第三波按 ADR-062 继续拆 `useChatState` 的 projection/sync、发送和 session 生命周期；第四波把 `MessageList` 的 projection 与 viewport 彻底分开；第五波才处理 DevPanel、样式和死骨架。`index.tsx` 保留组合入口，不能变成新业务层。

边界强制采用：ESLint/Biome import boundary（domain/merge 不得依赖 React；presentation 不得调用 API/cache；viewport 不得写 canonical store）、依赖方向测试、每个 adapter 的 port mock 测试。新增守卫不能只检查文件名，必须对反向 import 施加变异并失败。遵循 ADR-062，不引入 Zustand/Redux。

体量策略是净零依赖：复用现有 react-virtual、react-markdown 和 store 模式；completion scheduler、merge 函数应为轻量纯 TS。首屏不引入新的可视化库；CheckpointTimelinePanel、ContextMenu 和 workspace-tasks 继续懒加载。每一波以 `check-chat-bundle-budget.cjs:45-76` 的 source-map 门禁验收，Chat chunk 不得超过 496*1024，HTML 同步入口不得超过 1536*1024；设计阶段不做数值假设，任何新增字节必须由移除死模块或懒加载腾挪并实测。

## 9. 取红测试矩阵

| 不变量 | 变异 | 期望失败断言 |
|---|---|---|
| 同 messageId 正文增长不可丢 | 把 merge comparator 改回只比 messages.length | 新 snapshot 未写入，测试必须失败；正文长度从短变长。|
| 正文不可被空值覆盖 | 候选把完整正文改为空串 | 保留完整正文，断言字符级相等。|
| 终态不可退回 pending | 将 status rank 改为候选最后写入 | 终态 status 保持 succeeded/failed。|
| duplicate event 幂等 | 删除 evidenceFingerprint 去重 | message 实体数和 Activity summary 次数断言失败。|
| completion 只物化一次 | 关闭幂等键或并发调用两次 | API 调用次数为 1、merge 次数为 1。|
| cursor/read-model lag 可恢复 | 让第一次回拉返回旧 cursor | bounded retry 被调度；不能标记完整或静默结束。|
| SSE/轮询不覆盖更完整数据 | 以短 SSE 覆盖长 poll 正文 | 最终正文等于较长完整正文。|
| 缺口不伪造顺序 | 删除 sequence gap 检测 | gap 测试必须报告 deferred/recovery。|
| 一个 turn 一个正文区域 | projection 返回重复 message item | ViewModel 唯一化断言失败。|
| viewport 不改变数据 | 在 scroll handler 删除最后正文块 | canonical snapshot 和正文长度断言失败。|
| 分层方向 | 给 domain import React/API | import-boundary 测试失败。|
| bundle 不回归 | 把 deferred ContextMenu 静态引入入口 | bundle script 断言命中 deferred source。|

此外必须覆盖 feature flag 两个真实分支；任务书指出 Jest `localStorage=null` 与浏览器可写行为不对称，此项当前未在本轮源码测试中确证，实施时用显式 fake storage 取红。

## 10. 风险与回退

最大风险是服务端 DTO 没有独立 message version，hash 只能证明客户端内容不同，不能证明新旧先后；回退是保留 cursor 顺序并把冲突进入 deferred hydration，不静默选错。完成回拉可能增加请求量；回退开关应只关闭主动 hydration，不恢复两个旧短路门，仍保留 canonical merge。SSE 后置接线可能引入重复事件；回退为只启用 poll + completion hydration，并保留 sequence 日志。拆分可能改变 React 订阅粒度；每波保留旧组合入口和行为测试。bundle 超预算则回退该波静态 import，优先删除未接线骨架或懒加载，而不是提高门禁。
