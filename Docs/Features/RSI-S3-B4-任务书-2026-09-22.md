## 4. 冻结契约（逐字实现，不得另发明）

### 4.1 `RsiToolStep` 字段改造

| 旧 | 新 | 类型与语义 |
|---|---|---|
| `Output` | `OutputPreview` | `string?`。原文缺失 ⇒ `null`；原文非缺失 ⇒ **总长 ≤ 512 UTF-16 字符**：若原文长度 > 512 ⇒ 取前 **511** 字符 + `…`（U+2026，**1** 字符）；若 ≤ 512 ⇒ 原文**原样**（**不加**省略号） |
| — | `OutputChars` | `int`。**截断前**的 UTF-16 字符数。原文缺失 ⇒ `0` |
| — | `OutputBytes` | `int`。**截断前**原文的 UTF-8 字节数。原文缺失 ⇒ `0` |
| `Error` | `ErrorPreview` / `ErrorChars` | 同上规则（Error 也可能极大） |
| — | `ArgsHash` | `string?`，见 §4.2 |

⚠️ **缺失与空串必须可区分**：原文缺失 ⇒ `OutputPreview == null` 且 `OutputChars == 0`；
原文为空串 ⇒ `OutputPreview` 为空串 且 `OutputChars == 0`。
**不得**把「缺失」压平成空串（否则无法区分「没有输出」与「输出为空」）。

### 4.2 `ArgsHash`

- 值 = `SHA-256`（参数原文的 **UTF-8 字节**）小写 hex，**固定 64 位**；
- 输入 = 与本次 `completed` 配对的 `requested` 事件里 `arguments` 键的**原文**；
- ⛔ **不做任何归一化**（不 trim、不解析 JSON、不排序键）。归一化属后续「无进展循环」切片，本片**不得夹带**；
- `arguments` **缺失或纯空白** ⇒ `ArgsHash = null`。

### 4.3 ⛔ 必须拒绝照抄的邻近实现（本片最重要的一条）

`Source/PuddingRuntime/Services/Skills/ConversationSkillEvolutionTrajectorySource.cs:115`
（ADR-064 那条链）写的是：把缺失的参数兜底成一个**空对象字面量**（`?? "{}"`）。

**不要照抄这个兜底。** 它把「参数缺失」捏造成一个真实的参数值。
若照抄进 `ArgsHash`：两次**参数缺失**的不同调用会得到**同一个哈希**
⇒ 产生虚假的「参数相同」信号，而**没有任何断言会失败**。
本片的正确行为是 `ArgsHash = null`（见 §4.2）。

### 4.4 配对规则（`requested` ↔ `completed`）

- 与**最近的未配对** `requested` 配对；
- 配对键 = **工具名**（payload 的 `name`），FIFO 消费（**镜像既有管道**的行为，不新发明）；
- 找不到配对 ⇒ `ArgsHash = null`（**不得猜**，不得用最近一条顶替）；
- **遍历顺序（本片冻结）**：配对前把该 turn 的事件按 `Sequence` 升序**稳定排序**（作用于局部副本）后再消费，
  ⛔ 不得依赖输入顺序 —— 这与 B1 装配器既有冻结合同「Sequence 是唯一合法排序键，不得依赖输入顺序」一致。
  （现状：B3 的 `RsiTrajectorySource` 注释声称组内事件已按 Sequence 升序，但那只是**上游承诺**；
  配对逻辑若直接吃输入顺序，上游一旦不成立就会**静默配对错**。本片不赌它。）
- **缺失参数仍占槽位**：`arguments` 缺失/纯空白的 `requested` **照样入队**（它本身就是一个 requested 事件），
  其配对的 `completed` 得到 `ArgsHash = null`；
  ⛔ **不得**把「无参数的 requested」跳过不入队 —— 那会让后继 `completed` **错误地配到更早的调用**，
  产生**张冠李戴**的哈希，而单调用夹具**不会红**（守护见 A6）。

### 4.5 不得改变的行为

- `tool.call.failed` ⇒ 结局**强制** `Failed`（B1 既有语义，一行不动）；
- step 仍按 `Sequence` 升序；**失败步不得丢弃**；零工具步的 turn 仍不产出轨迹；
- 结局判定仍**一律复用** `RsiToolOutcomeDeriver`（本片不碰它）；
- **CoT / 正文一律不得进入任何字段**（规格 §2.13 第二层，2026-09-22 01:10 补入）：
  `message.thinking_summary.appended`（即 `ConversationEventTypes.MessageThinkingSummaryAppended`，
  常量位置 `PuddingCore/Platform/ConversationContracts.cs:100`）与 `message.content.appended`
  既不产生 step，其文本也**不得**出现在任何 `RsiToolStep` 字段里 ⇒ 守护见 **O6**。

## 8. 工具坑（本会话已踩，直接避开）

- ⛔ **不要把中文路径直接当 `git diff -- <中文路径>` 的参数**（cmd 码页会把路径弄坏 ⇒ **静默返回空 diff**，
  看起来像「没改动」）。取证据用**不带路径**的 `git diff --numstat` 再自行筛选行。
- ⛔ 同一个文件的多处 `file_patch` 要**一次调用多 operation**；若分成多次调用，后面几次可能静默不落盘。
- ⛔ 新增类 patch 的收尾断言 = `git diff --numstat` 的 **deletions 必须与报告里逐条说明的删除数相等**（本片允许非 0）。
- ⛔ 写文件内容里的 ASCII 双引号**直接写 `"`**；写成 `\"` 会原样落盘（已实测）。
- ⛔ 测试命令用 `terminal_start` + `terminal_wait`（等待按预期耗时给），不要 1–2 秒反复轮询。
- ⛔ **任务书里的文件路径必须先实测（`file_search`）再落笔**（本任务书曾把装配器测试文件的路径
  写成 `Services/Improvement/Rsi/…`，实际无 `Rsi/` 子目录）。
