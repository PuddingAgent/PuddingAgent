# 服务商余额查询与多服务商计费适配器设计方案

- 状态：已实施（2026-08-24，任务 ec50aeb052084d1da7e242e34371904b，P3）
- 范围：Admin 聊天页主代理余额徽标（DeepSeek 首个落地）+ 前后端双层计费适配器抽象
- 关联：[ADR-036 系统级配置文件唯一来源](../07架构/37ADR-036系统级配置文件唯一来源ADR.md)（llm.providers.json）、`LlmProviderApiController`（余额 HTTP 出口）

## 1. 目标与现状

- 当聊天页当前主代理使用 DeepSeek 服务商时，头部显示余额徽标（数据来自后端真实 API，非硬编码）。
- 余额查询/展示抽象为「服务商计费适配器」注册表模式，可平滑扩展 Qwen/GLM/Kimi 等服务商。
- 查询失败与非适配服务商优雅降级（隐藏徽标或显示 `—`），绝不在 UI 报错、绝不把 apiKey 打进日志。

## 2. 架构：双注册表

```
ChatMain（持有 selectedAgent.preferredProviderId）
  │ resolveBillingAdapter(providerId)          ← 前端展示适配器注册表（providerBilling.ts）
  │ 未命中 → 不渲染徽标（降级①：非适配服务商隐藏）
  ▼
useProviderBalance hook（5min 低频轮询 + 点击手动刷新 + 页面隐藏暂停）
  │ GET /api/llm/providers/{providerId}/balance
  ▼
LlmProviderApiController.GetBalance
  ▼
LlmProviderFileService.GetBalanceAsync
  │ ① LoadAsync 读 llm.providers.json，定位 provider（不存在→404）
  │ ② ResolveApiKeyForBalanceAsync 解析密钥（ApiKey → ${ENV} → {{vault:NAME}} → ApiKeyRef/KeyVault；
  │    无 key→400）
  │ ③ IEnumerable<ILlmBalanceProvider> 注册表按 CanHandle 分发   ← 后端查询适配器注册表
  │    未命中 → 返回 IsAvailable=false + Error="暂不支持余额查询" DTO（降级②：HTTP 200）
  ▼
DeepSeekLlmBalanceProvider.QueryAsync
  │ GET {baseUrl 剥掉尾部 /v1}/user/balance + Bearer
  ▼
ProviderBalanceIndicator（¥xx.xx 徽标 + Tooltip 明细/错误）
```

### 后端查询适配器（查询与归一化）

| 组件 | 位置 | 职责 |
|---|---|---|
| `ILlmBalanceProvider` | `Source/PuddingPlatform/Services/ILlmBalanceProvider.cs` | 契约：`CanHandle(provider)` + `QueryAsync(provider, apiKey, ct)` |
| `DeepSeekLlmBalanceProvider` | `Source/PuddingPlatform/Services/DeepSeekLlmBalanceProvider.cs` | DeepSeek `/user/balance`（Bearer、`/v1` 剥离、字符串金额解析、`error.message` 提取） |
| 注册表分发 | `LlmProviderFileService.GetBalanceAsync` | 注入 `IEnumerable<ILlmBalanceProvider>`，按 `CanHandle` 取第一个命中 |
| DI | `PuddingServiceCollectionExtensions.Platform.cs` | `AddSingleton<ILlmBalanceProvider, DeepSeekLlmBalanceProvider>()` + 30s 命名 HttpClient `LlmBalanceQuery` |

参照既有模式：`IImageGenerationProvider` + `VolcengineArkImageGenerationProvider` + `ImageGenerationService` 分发（CanHandle + IEnumerable 注入）。

职责边界：**密钥解析留在 `LlmProviderFileService`**（它拥有配置与 KeyVault 依赖），适配器只做「拿到已解析的 apiKey → 打厂商端点 → 归一化为 `LlmProviderBalanceDto`」。DTO 契约（`ProviderId/Endpoint/IsAvailable/BalanceInfos/Error/QueriedAt`）对前端稳定，多厂商扩展不改契约。

错误约定：网络错误抛 `HttpRequestException`（控制器映射 502）；上游业务错误（非 2xx/解析失败）返回 `IsAvailable=false` + `Error` 的 DTO（HTTP 200），由前端降级显示。

### 前端展示适配器（渲染策略）

| 组件 | 位置 | 职责 |
|---|---|---|
| `providerBilling.ts` | `src/pages/chat/utils/` | `{ id, match, displayName, fallbackCurrencySymbol }[]` + `resolveBillingAdapter` + `currencySymbolFor`（CNY→¥/USD→$） |
| `useProviderBalance.ts` | `src/pages/chat/hooks/` | 拉取/轮询/手动刷新/静默降级（`balance=undefined` + `errorText`） |
| `ProviderBalanceIndicator.tsx` | `src/pages/chat/components/` | 品牌图标 + `¥xx.xx` 徽标；可选 `detail` 进 Tooltip 第二行 |
| 挂载点 | `ChatMain.tsx` 头部 `extraActions` | `selectedAgent.preferredProviderId` 命中适配器才渲染；点击徽标手动刷新 |

组件与挂载点解耦：后续若按《AdminChatComposer浮层重设计方案》Phase 3 把指标挪到 DevPanel/开发者详情，hook+组件可整体复用，只需换挂载点。

## 3. 新服务商扩展步骤（如 Qwen/GLM/Kimi）

后端（3 步 + 测试）：

1. 新建 `Source/PuddingPlatform/Services/{Vendor}LlmBalanceProvider.cs` 实现 `ILlmBalanceProvider`：
   - `CanHandle`：按 providerId 关键字或 baseUrl host 匹配（provider 无类型字段，providerId 是自由字符串，惯例见 `providerTemplates.ts`）。
   - `QueryAsync`：按厂商规范拼端点（DashScope、BigModel 等各有路径/鉴权/响应结构差异，全部收敛在适配器内，输出归一化 `LlmProviderBalanceDto`）。
2. `PuddingServiceCollectionExtensions.Platform.cs` 余额区注册：`AddSingleton<ILlmBalanceProvider, {Vendor}LlmBalanceProvider>()`（如需专属超时/Handler，参照同区 AddHttpClient）。
3. `Source/PuddingPlatformTests/Services/` 加 `{Vendor}LlmBalanceProviderTests`（FakeHttpMessageHandler 直构，参照 `DeepSeekLlmBalanceProviderTests`）。

前端（1 步）：

4. `providerBilling.ts` 注册表数组加一项 `{ id, match, displayName, fallbackCurrencySymbol }`，需要新品牌图标时在 `ProviderBalanceIndicator.tsx` 的 `ProviderIcon` 加分支。

无需改动的部分：控制器、DTO 契约、hook、挂载逻辑、分发器——全部按注册表自动生效。

## 4. 刷新策略与降级

- 轮询：5 分钟（`BALANCE_REFRESH_INTERVAL_MS`）+ `usePollingLoader` 页面隐藏自动暂停；providerId 切换立即拉取一次。
- 手动：点击徽标触发 `refresh()`（Tooltip 提示「点击刷新」）。
- 降级矩阵：

| 场景 | 表现 |
|---|---|
| 非适配服务商 / agent 未配置 provider | 不渲染徽标 |
| 适配服务商但上游报错（401/超时等） | 徽标显示 `—`，Tooltip 显示后端 `Error` |
| 请求异常（网络/502） | 同上，Tooltip 显示本地错误信息 |

## 5. 安全与行为变更说明

- **apiKey 不进日志**（结构性约束）：适配器日志模板仅含 providerId、状态码、URL、耗时；密钥只在 `Authorization: Bearer` 头中传输，前端仅拿 `HasApiKey` 布尔量，明文永不出后端。
- **行为变更**（开发期无兼容包袱）：旧实现对任意 provider 都盲打 `{baseUrl}/user/balance`（非 DeepSeek 厂商基本 404 白打一次上游）；现在未注册适配器的服务商会立即返回「暂不支持余额查询」DTO，不再发起无谓外呼。OpenAI 体系本身无 `/user/balance` 端点，此变更无实际能力损失。
- **/v1 剥离修复**：旧实现 baseUrl 带 `/v1` 时会拼出错误端点（DeepSeek 余额端点在站点根）；适配器统一剥掉尾部 `/v1` 再追加 `/user/balance`。
