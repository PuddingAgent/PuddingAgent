## 1. ⭐ 设计修正（父级决定，须服从）：**阈值不是一个类型能包打天下**

S1a 的 `ThresholdPolicy` 是**三区间**策略，建模「**对单一命题的一个分数** ⇒ Yes / No / Abstain」。

但 §0 侦察出的三处判据是**另一种结构**：**逐标签的单侧验收门槛**（"该标签只有置信度 ≥ X 时才可接受"），**没有** `NoAtOrBelow` 语义。

⚠️ **禁止**把单侧门强塞进 `ThresholdPolicy`：那会造出一个**语义上不存在的 `NoAtOrBelow`**——这正是本项目持续防范的「输出语义混同」（母文档 §4.0.2）。

⇒ 基础设施需承载**阈值策略族**，两成员并列：

| 类型 | 用于哪个原语 | 形状 |
|---|---|---|
`ThresholdPolicy`（**S1a 已有，不得改动其语义**） | `IJudge` 的单一命题判定 | 三区间：`>= YesAtOrAbove ⇒ Yes`、`<= NoAtOrBelow ⇒ No`、中间 ⇒ `Abstain` |
`AcceptanceThresholdPolicy`（**S2a 新增**） | `IClassifier` 的**逐标签验收** | 单侧：`RequiredConfidence` + `AppliesToLabels` |

并抽一个共用极小接口，让「**一切判据都可版本化、可随结果落库**」成为**类型事实**而非约定：

```csharp
namespace PuddingCode.Operators;

/// <summary>可版本化判据：一切阈值/判据都必须有稳定 id 与版本，否则结果不可复现、不可审计。</summary>
public interface IVersionedCriterion
{
    string PolicyId { get; }
    int Version { get; }
}
```

让 `ThresholdPolicy` **也实现** `IVersionedCriterion`（它已有 `PolicyId`/`Version`，属纯增量、不改语义）。

## 2. 交付物 1：`AcceptanceThresholdPolicy`（新契约，落 `PuddingCode.Operators`）

```csharp
/// <summary>
/// 逐标签验收门槛（单侧）：某标签的置信度达到要求时才可接受。
/// <para>
/// 与 <see cref="ThresholdPolicy"/> 的分工：后者管「单一命题的一个分数 ⇒ 三区间」，
/// 本类型管「某个标签的置信度是否够格」。<b>不得</b>把本类型塞进三区间形状——
/// 单侧门没有 No 侧语义，硬造一个 NoAtOrBelow 会造成语义混同。
/// </para>
/// </summary>
public sealed record AcceptanceThresholdPolicy : IVersionedCriterion
{
    public required string PolicyId { get; init; }
    public required int Version { get; init; }

    /// <summary>要求的置信度下界（含等）。</summary>
    public required double RequiredConfidence { get; init; }

    /// <summary>适用标签集（规范化标签键，如 allow_permanent/deny_permanent）；空 = 不限定标签。</summary>
    public IReadOnlyList<string> AppliesToLabels { get; init; } = [];

    public string? SceneKey { get; init; }
    public string? Note { get; init; }

    /// <summary>
    /// 是否达门槛。<b>缺失置信度 ⇒ false（保守）</b>——与既有行为一致
    /// （<c>ClassificationRuleCurator</c> 与 <c>ToolCallClassifierPipeline</c> 都要求"有值且达门槛"）。
    /// </summary>
    public bool IsMet(double? confidence);

    /// <summary>校验式工厂：非法（NaN / 超出 [0,1]）在构造期即拒，不静默放行。</summary>
    public static AcceptanceThresholdPolicy Create(
        string policyId, int version, double requiredConfidence,
        IReadOnlyList<string>? appliesToLabels = null,
        string? sceneKey = null, string? note = null);
}
```

**硬性语义（必须有单测）**：
- `confidence >= RequiredConfidence` ⇒ `true`（**边界含等**，对齐既有 `>=`）；
- `confidence == null` ⇒ **`false`**（保守，与既有行为逐位一致）；
- `confidence` 为 NaN / 超出 `[0,1]` ⇒ 由 `Create` 在构造期拒绝；
- `AppliesToLabels` 为空 ⇒ 视为「不限定标签」（调用方自行判定适用性，本类型不替它猜）。
