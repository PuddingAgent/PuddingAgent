# Agent 统一检索与渐进展开工具链

日期：2026-09-13。状态：Proposed；仅设计，未实施、未安装 tgrep、未执行本地性能或产品验收。决策见 [ADR-089](../07架构/103ADR-089Agent统一检索与渐进展开工具链ADR.md)。

## 1. 目标与现状

Agent 用一个搜索入口发现文件、符号和文本，再沿同一结果引用读取源码、查看结构和追踪关系。引擎选择、路径解析、索引状态和分页由服务统一处理；保留各引擎专业能力，减少 Agent 选工具、搬运参数和重复查询的轮次。

本次基于当前源码核对。用户所说 code_search 对应代码索引检索能力；本次扫描到的原生注册 ID 是 code_symbol_search，不能将 PuddingCodexService 的 Codex 任务执行器误当代码索引引擎。

| 当前能力与入口 | 证据和整合点 |
| --- | --- |
| `Files/FileSearchTool.cs` | Everything SDK 优先、内置递归回退；按名称/路径搜索，不搜索内容；Provider、目录和回退暴露在工具参数/结果中 |
| `CodeIntelligence/CodeQueryTools.cs` | 符号、探索、调用方、被调用方、影响分析与索引状态分散；关系查询需要符号和项目身份 |
| `CodeIntelligence/CodeSummaryTool.cs` | 按名称搜索后取第一个结果，有重名歧义；同时输出文本和 JSON，重复呈现内容 |
| `CodeIntelligence/CodeOutlineTool.cs` | 直接解析当前文件，C# 使用 Roslyn，其他语言使用 IFileOutlinerRegistry；可作为无索引展开能力 |
| `CodeIntelligence/ProjectMapTool.cs` | 扫描目录并提取 C# 顶层类型，与 list_dir、Outline 有重复；不能视作完整多语言项目图 |
| `Files/FileTools.cs`、FileChunkService | 已有读取、分块、分页和大结果约束，应复用而非重写读取器 |
| `Search/SearchGrepTool.cs` | Lucene 分词查询命中直接返回，未按同一大小写/正则合同复核；回退是有界托管扫描，两条路径并不等价 |
| `Services/Search/SearchAttemptLedger.cs` | 去重键仅覆盖部分参数，版本来自进程内缓存的 Git HEAD；未提交编辑不会可靠失效，timeout 也会被短路 |
| `SmartWorkflow/SmartExploreTool.cs` 等 | 手工编排多个检索工具，提示中同时存在 grep 优先和索引优先流程，应统一为一条操作路径 |

上述 Runtime 文件均相对 `Source/PuddingRuntime/Tools/BuiltIns/`，Services 路径相对 `Source/PuddingRuntime/`。代码索引服务位于 `Source/PuddingCodeIntelligence/`。

## 2. Agent 表面：一个检索工具，一个展开工具

### workspace_search

必要参数只有 `query`；`scope` 默认执行快照的工作目录，`target=auto` 默认同时查询适用的文件、符号和文本来源。可选 `target=files|symbols|text` 表达搜索对象，而非引擎；`match=literal|regex` 默认 literal，`case=sensitive|insensitive` 默认 insensitive；`glob` 是独立文件过滤器。显式 target 不支持某种匹配模式时返回 contract_error；auto 可省略不支持的来源，但必须报告覆盖情况。

其他可选参数：`limit` 默认 20、上限 100；`cursor`；`freshness=indexed|current` 默认 indexed。初版只提供必要过滤与分页，不暴露 Lucene、Everything 或 tgrep 语法，也不自动调用模型改写查询。整句需求按原文匹配，不能承诺自然语言语义检索。未来语义检索需独立能力和证据标记。

auto 对同一词执行有界联合召回，例如 FileSearchTool 可同时命中文件名、类定义和引用文本。文件名匹配不是文本搜索前置过滤：不能只在文件名包含 query 的文件中搜内容。glob/scope 才是所有后端共享的过滤条件。

### workspace_open

必需 `target`，接受搜索返回的 ref 或显式路径；默认 `view=excerpt`。按目标支持 `outline|summary|relations|map|status`：

| view | 输入与输出 |
| --- | --- |
| excerpt | 命中附近文本；可指定行范围、方法范围或继续读取 cursor，复用 FileChunkService |
| outline | 文件/类型的结构树；按文件版本缓存，复用 Roslyn 与 IFileOutlinerRegistry |
| summary | 精确符号的签名、文档注释和少量关系；不隐藏调用 LLM，不按模糊名称取第一项 |
| relations | `relation=callers|callees|references|neighbors|impact`；默认 callers；默认 depth=1，最大 3，节点默认 20、上限 100；支持边来源和继续分页 |
| map | 目录树与已知符号；目录信息覆盖全部允许文件类型，类型信息注明语言支持和截断 |
| status | 指定 scope 的覆盖、后端健康与索引进度；只读，不触发注册、重建或新守护进程 |

references 需要补齐查询 facade，不能用字符串匹配冒充语义引用。关系 ref 定位到具体 workspace/project/symbol，重名返回 disambiguation 候选；解析精度不足的语言标注 syntactic/heuristic，不能输出伪精确调用图。impact 是基于已有关系图的有界影响遍历，不能承诺完整运行时影响面。

搜索与展开共用引用和服务，但分成两个小 schema：前者回答“在哪里”，后者回答“这里是什么、与谁相关”。不会同时向默认 Agent 暴露旧的多个平行检索入口。文件写入、补丁、Shell、索引管理保留独立权限与职责。

## 3. 典型流程与统一结果

```text
workspace_search(query="TryImportCurrentSessionTranscriptAsync")
  → ref=r1，符号定义，绝对路径/行范围/签名，file+symbol+text 命中证据
workspace_open(target="r1", view="summary")
  → 精确符号信息与可展开的关系引用
workspace_open(target="r1", view="relations", relation="callers")
  → 调用边、调用点和目标引用
workspace_open(target="r1", view="excerpt", extent="symbol")
  → 当前方法源码；较长则返回分页 cursor
```

示例 ref 为示意，以上工具尚未实现。简单定位可在一次 search 的紧凑预览中完成，不强制走完所有步骤。

统一 envelope 包括 `query_id/scope/status/items/coverage/continuation`。每项含 `ref/kind/path/range/symbol_id/signature/preview/match_sources/version`，按实际类型省略不适用字段。模型默认只接收紧凑单一表示；完整结构留在 canonical 工具结果和有界 artifact 中，避免文本树加同内容 JSON 的双份重放。

聚合同文件结果，以路径+范围+符号身份去重，保留匹配来源。精确名称/定义优先，其次名称部分匹配，再到文本命中；同级按规范路径和行号稳定排序。为不同来源预留首屏配额，不能让大量文本命中挤掉符号定义。各引擎原始分数不可直接相加。截断候选后再排序只保证已召回集合排序，必须声明其限制。

coverage 按来源返回 `available/index_generation/reconciled_at/freshness/complete/limit_reason`，区分搜索覆盖不全和展示分页。状态至少区分 ok/no_match/partial/index_unavailable/timeout/contract_error/stale_ref；某一路失败仍可返回其他路结果，但总体为 partial。未覆盖范围不能归纳成 no_match。总数未知时返回 lower_bound，不能用已返回数量冒充总数。

ref 是有界结果存储中的身份引用，绑定 workspace、授权范围、规范路径、可选项目/符号 ID、内容版本、索引 generation 和有效期。它不是访问凭证；每次展开重新执行既有权限检查。文件变化后按新文件验证、重定位并明确返回新版本，无法唯一重定位时返回 stale_ref，不能沿旧行号读错符号。cursor 绑定查询参数、排序和 generation；过期返回 cursor_expired，不跨新旧快照拼页。路径始终可作为独立入口，结果存储不是使用工具的前提。

## 4. 服务结构与 tgrep 的位置

```text
workspace_search / workspace_open
  → admission + ScopeResolver + QueryPlanner
  → EverythingPathProvider / CodeIndexProvider / ContentSearchProvider
  → HitMerger + EvidenceVerifier + ResultStore
  → FileReader / OutlineProvider / SymbolSummaryProvider / RelationProvider
  → canonical ToolExecutionResult + bounded model presentation
```

复用 ICodeQueryService、ICodeIndexScopeResolver、CodePathIdentity、IFileOutlinerRegistry、FileChunkService 和现有工具执行/Artifact 管线。抽出 FileSearchTool 内的 Everything provider 与读取/Outline 逻辑为服务；工具不得通过拼接工具调用文本来调用旧工具，也不在内部重跑权限或创建第二套 Agent Loop。

tgrep 的参考价值是 trigram 候选筛选、磁盘基底+内存增量、文件变更校准、未就绪回退和有界资源。它不提供 Pudding 的符号关系、授权、结果引用与 Agent 交互合同。官方基准预建索引，只统计查询耗时，不能直接作为 Pudding 的性能承诺。

首个验证后端建议选固定版本 tgrep，通过 ContentSearchProvider 适配其结构化输出；与托管/ripgrep 基线差分验证。最终二进制依赖与常驻 serve 的采用，以 Windows 本地正确性、资源和端到端收益门禁决定。先实现服务合同与基线，不以编写自有 trigram 引擎为前提。Lucene 可继续服务分词全文检索，但不能提供不完整的候选集来声称精确 grep 完整。

如果采用 serve，由 Core 统一监督，按实际物理仓库/worktree 隔离并共享给主子 Agent，不能每个 Run 启一个实例；Desktop 不承载索引业务。适配器使用结构化参数与受控进程通道，若使用 TCP，需验证 loopback、实例身份、端口归属与上游协议能力，不能假设 JSON-RPC 自带鉴权。索引数据进入 PathHelper 指定的索引存储分类，纳入存储管理与回收。

## 5. 范围、新鲜度与安全不变量

- 一次执行冻结 workspace、实际 working tree、scope、过滤规则、授权和输出预算；显式宿主路径沿用既有授权，不因 Everything 全盘可见就自动扩大内容读取范围。不同视图在统一 admission 中分别校验所需能力。
- 各 provider 共享文件范围合同，包括排除目录、glob、大小写、符号链接/重解析点和文件大小策略。Everything 结果需按规范真实路径后置校验。全局索引发现与内容读取保持各自权限，结果引用不能绕过权限。
- indexed 表示索引快照及已知增量，不能暗示当前文件系统完整；current 请求必须覆盖新增、修改、删除和未索引文件。仅复核已有候选不能发现新增命中。通过校准加增量扫描，或同范围全扫描满足；预算不够返回 partial，不能静默降级为 indexed。对并发写入仅声明扫描观察区间，不声称原子文件系统快照。
- 监听故障、溢出、轮询失败和过滤规则变化均使覆盖状态失效。代码、路径和文本各自版本独立报告，不能拼成虚构的统一事务快照。跨后端结果聚合后验证目标版本。
- 失败缓存键覆盖规范化后的全部语义参数、预算、授权范围与可验证内容 generation；未提交编辑、新文件、删除和配置变化必须失效。无可靠 generation 时禁用负结果短路；timeout 仅作诊断，不能无限抑制正常重试。延续有界 ledger，删除以缓存 Git HEAD 判断工作树不变的假设。
- 默认输出预算建议 8 KiB，可继续展开；Provider 共享总 deadline、取消令牌、并发与扫描预算，不能每个后端各占完整预算。以上预算属于 Proposed 默认值，需实测调整。

## 6. 文件级施工顺序

| 阶段 | 主要文件/模块 | 完成门禁 |
| --- | --- | --- |
| U0 合同与基线 | `Source/PuddingCore/Tools/Retrieval/`（新增 DTO/接口）；Runtime `Services/Search/`（scope、planner、coverage、ledger）；现有 SearchGrepTool/FileSearchTool | 同一请求跨后端语义一致；范围、错误、无匹配与截断可区分 |
| U1 统一搜索 | Runtime `Tools/BuiltIns/Search/WorkspaceSearchTool.cs`（新增）；Everything provider 抽出；CodeQueryService；ContentSearchProvider | files/symbols/text/auto 可用，局部后端故障、分页和匹配来源正确；基线后端先落地 |
| U2 渐进展开 | `WorkspaceOpenTool.cs`（新增）；FileTools/CodeOutlineTool/CodeSummaryTool/ProjectMapTool/CodeQueryTools 服务化；ResultStore | 重名不误选，旧 ref 不误读，outline/read/relations 共用身份与预算 |
| U3 tgrep 试验 | ContentSearchProvider 实现；Host DI/子进程管理/存储配置 | 固定版本差分、冷暖查询、编辑可见性、内存/磁盘/退出清理；收益不足可保留基线 |
| U4 入口收敛 | PuddingToolRegistry/SkillRuntime/ToolLoopInstructionBuilder/HarnessToolCompatibilityAdapter；BuiltInAgentTemplates/ToolProfileConfig；Host 预设；SmartWorkflow | 默认只暴露 search/open；旧工具授权逐项映射，禁止直接把任一旧权限升成全部新视图权限；无陈旧调用提示 |
| U5 产品验收 | RuntimeTests、CodeIntelligenceTests、HostTests 与外部部署流程 | 新构建外部重启后，新主/子 Agent 会话通过完整工具链，状态中心和退出回收由外部控制器验收 |

旧工具不是永久平行入口：U1–U3 可分支内验证，U4 同一原子切换更新调用方、预设、权限和持久配置（先备份、显式版本变更）。已有 rg/file_read 等 Harness 拼写仅在既有 admission 前归一化到新合同，不保留两套执行实现。注册/注销/重建索引仍为单独管理操作，不合并进 Low 只读工具。search_tools 是工具发现、search_memory 是知识记忆、会话日志是运行证据检索，本轮不强行并入代码/文件索引。

## 7. 验证与度量

正确性先行：相同范围对照扫描基线验证路径、行号与匹配内容；覆盖短词、符号全名、大小写、中文、正则/非法正则、无匹配、隐藏/忽略文件、大文件、重名、worktree、重解析点，以及修改/新增/删除后立即查询。禁止用提速补偿漏检。不同正则引擎仅对声明支持的公共语义做差分，其他模式明确错误或使用统一 matcher 回退。

工具链测试：search → open → relations → excerpt；ref 过期/跨 workspace/授权收窄；部分引擎掉线；索引未就绪；展示分页与扫描不全；超时后可重试；未提交编辑使负缓存失效。复用已有搜索测试，新增能暴露真实错误的集成用例。

性能在固定 Pudding checkout、相同 query/范围/输出预算下记录冷启动、建索引、warm p50/p95、扫描字节、候选缩减率、更新可见延迟、常驻私有内存与磁盘占用。Agent 任务集合再记录总检索调用数、重复读取率、输出 Token、完成率与总耗时。冻结数据集后确定数值门槛；当前不宣称提升倍数。主子 Agent 共享服务还需验证并发取消与公平预算。
