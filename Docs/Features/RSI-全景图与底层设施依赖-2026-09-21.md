> 用户指令：「RSI 是 puddingAgent 里比较复杂的一部分，需要先梳理它依赖的底层设施（分类器、打分器、判断器）。

> 本文件即该全景图；配合 `Docs/Features/RSI-Harness-…设计-2026-09-21.md`（§4 架构、§5 宪法、§8/§15.6 切片）阅读。

## 0. 一句话

RSI = **三原语**（打分器 / 判断器 / 分类器） + **一条六段流水线**（Ingest → Analyze → Plan → Implement → Evaluate → Promote|Rollback）
+ **三层存储**（Signal / SignalCluster / PromotionRecord）。

当前状态：**原语基础设施已就绪（S1a–S2b），但只被 1 个消费者验证过；RSI 本体（S3–S6）与三层存储全缺。**

### 1.3 三原语的消费者现状（**本表是全景图的关键**）

| 原语 | 契约 | 基类 | 路由 | 真实消费者 | 状态 |
|---|---|---|---|---|---|

## 3. 依赖 DAG（谁挡着谁）

```
canonical 事件 ──▶ [T1 事件级采集 + 水位]──┬──▶ [S3 轨迹片段源] ──┐
                                            │                      │
                                            └──▶ [T2 打分器: 价值打分] │
                                                       │            │
                                                       ▼            ▼
                                        [T5/T6 披露与检索]   [S4 RsiClassifier]
                                        [G3 判断器: 组合预算]        │
                                                                    ▼
[S0 评测可信 ✅] ────────────────────────────▶ [S5 Analyze→Plan→Implement] ──▶ [S6 Evaluate→Promote/Rollback]
                                                                    │
                                                       [L3-b 落点接线] ◀──┘（无落点则 Plan 只能是报告）
```

**关键边的理由**：

| 边 | 为什么不能颠倒 |
|---|---|
`T1 → S3` | 没有事件级采集与水位，「失败→纠偏→验证」轨迹**无法幂等**，会重复分析同一条轨迹 |
`T1 → T2 → G3` | **无度量不调参**：没有命中/价值事实就做预算与淘汰，等于凭印象 |
`S0 → S6` | 评测不可信 ⇒ 晋升无法判定（**已随 S0 解除**） |
`L3-b ← S5` | 没有落点，Plan 只能产出报告，无法成为"进化" |
`S4 → IClassifierModel 实现` | S4 是该抽象的第一个真实消费者（否则它永远只是声明） |

## 5. 「不打补丁」的可执行判据（本节最应被复用）

每片开工前与收口前自检，**任一不满足即停下改设计**：

1. **只新增文件 + 在组合根追加注册**。若必须进既有类加 `if (scene == rsi)` ⇒ **设计错了**。
2. 新能力必须**经既有端口**进入（`IClassifier` / `IScorer` / `IJudge`），**不得**自建第二套判定逻辑。
3. **反向依赖守卫**：基础设施命名空间内不得出现 `Rsi` / `Goal` / `ToolApproval` 标识（门禁已存在，随新命名空间扩展它）。
4. **不做兼容分支**：旧通道不被"改造"，新场景只用新核；旧场景**按需单向收敛**，并在 `code_map` 记录迁移水位。
5. **先证明问题存在**（只读报告）**再动代码** —— G1 / G5-a / T0 已用此法，是有效的。
6. **可机械验证**：测试计数 / 门禁退出码 / 产物前后对照，三者至少其一；否则不算完成。

## 6. 三个已知的「补丁陷阱」（必须绕开）

| # | 诱惑 | 为什么是陷阱 | 正确做法 |
|---|---|---|---|
1 | 改 `ConversationSkillEvolutionTrajectorySource` 以复用其路径 | 其语义是 ADR-064「**只从成功经验学**」（一处失败即整条丢弃）；改它等于让既有管道**静默开始把失败当经验学**且无报错 | **新建独立契约**，仅共享 `ISkillEvolutionDataAccess`（数据访问可复用，**语义层不可**） |
2 | 给 `SkillEnforcerService` 的 `CollectKeywords` **删词**去噪 | 实测 89.1% 噪声，但注入可能正靠这些词命中；无命中事实前删词会**切断现有注入**（比噪声更严重的能力回退） | 先 T1/T2 拿到命中事实，再谈"关键词定主"（T7） |
3 | 在 `ToolCallClassifierPipeline` 里加 RSI 分支 | 那是**审批安全关键路径**；直接改写风险与收益不匹配 | 走**适配器 + 新场景键**（S1b 已用此法验证可行） |
