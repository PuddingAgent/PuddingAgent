# ADR-089 · U4-3b 向量检索规模化实测与父级裁决（2026-09-24）

> 本文件把 `temp/`（gitignore）下的实测结论**固化进版本控制**，并登记父级裁决。
> 原始证据目录：`temp/U4-3b-logs/`、`temp/U4-3b/`、`temp/U4-3b-REPORT.md`（**均未受版本控制 ⇒ 见 §9-T2**）。

## 0. 结论（一句话）

在真实项目 scope 规模下，「**结构化预过滤 + 暴力扫描**」**可以**满足热态 p95 ≤ 50 ms —— **但前提是把扫描实现换成 in-place int8 编码扫描（必要时 8 线程并行）**。
**现行 shipped 路径（反量化成 float32 + 每行一条结果 + 全量排序）在 ≥ 5,284 行就已越线，三个真实 scope 全部越线。**

## 4. 父级裁决（3 项）

### D1 ✅ 接受「全仓 P0 = 45,677」，并**更正 §2.5 的 362k 前提**

实测 vs 设计偏差 **7.9×**。根因：**P0 占比在纯 C# scope 是 35.13%，全仓只有 5.59%** —— §2.5 拿前者外推到了后者。

⇒ **登记为通用纪律**：凡「占比 / 比例」类参数，**不得跨 scope 性质外推**（纯 C# scope ≠ 全仓）。
（这是同一类口径错误的**第二次发作**：第一次是 int8 的 B/行漏算 scale + manifest。两处都源于"用一个小语料的比值推全体"。）

⚠️ **但 45,677 是下界**：本刀适配器只处理 C#；TypeScript 有 outliner 却未计入 P0。见 D3。

### D2 ✅ **in-place 扫描是「待交付切片」，不是「可行性上界」**

理由（本刀最重要的负面发现）：**shipped 路径在真实 scope 上就已经失败** ——
Runtime 59.2 / Core 72.3 / 三 scope 135.7 ms，**全部 > 50 ms**。

⇒ 若不更换扫描实现，**向量检索在真实项目上根本达不到延迟目标**。这不是"未来规模问题"，是"今天就不达标"。

### D3 ⚠️ TypeScript P0 未测 ⇒ 本结论**有界**

8 线程拐点 65,662 行相对全仓 P0 45,677 行只剩 **1.44× 余量**，而 TypeScript 的 P0 完全没计入。
⇒ **这是「暂不需要 ANN」最脆弱的一环**，列为下一刀必做的低成本测量项（T1）。

## 6. 可复现翻转判据

`行数阈值 = (50 − embed_p95) / slope_p95`：

| 实现 | 阈值 |
|---|---|
| shipped | `(50−29.793)/… = 4,295` 行 |
| int8-inplace | `16,700` 行 |
| int8-parallel | `(50−29.793)/0.2552 = 79,200` 行 |

另两条独立轴：**嵌入 p95 上升**（实测占预算 **60%**）、**可用核数下降**（8→4 核时 8 线程拐点约 3.3 万行）。

### 父级自陈的读数错误（记入教训）
我曾以为 `M1-red` 尾部的 `0` 与「20/20 不一致」矛盾。**是我读错** —— 那是 `SUMMARY` 块的**列式渲染**，末列表头为 **`gen2`（Gen2 GC 次数）**，不是 mismatch。核对表头后消解。
⇒ **教训：读数值表前先找表头，不要按位置猜列。**

## 8. 诚实留白（照登，不粉饰）

**未做**：不实现 ANN、不做 recall/质量评测、不优化生产 `Search`、不测并发/batch、不测 >1.03M 行。
**未测**：TypeScript P0 行数、SIMD 扫描、共享负载下的并行 p95、Server GC 配置、干净 checkout 的全仓块数。
**外推（附公式）**：43,580 / 45,677 行延迟 = 实测点 24,349 与 57,783 **两点内插**；RAM = `rows × 4096 B`（与实测 4,023.4 MB @1.03M 行对齐 **±0.1%**）。
**可信边界**：1024 维单尺度数据（475 行真实 int8 + 真实行扰动合成）；**单一 embedding 模型**（qwen3-embedding-0.6b，本地）；**单机 i7-9700KF 8 核/8 线程、31.9 GB、.NET 10.0.401、workstation + non-concurrent GC**；单查询串行、n=20/点、nearest-rank 百分位；**8 线程 = 整机全核**（本机有其他 Agent 进程 ⇒ **这是「暂不需要 ANN」最脆的一环**）。
