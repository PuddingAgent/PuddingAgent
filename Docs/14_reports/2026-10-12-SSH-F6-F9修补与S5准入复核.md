# SSH F6–F9 修补与 S5 准入复核（2026-10-12 第二轮）

> **结论（一句话）**：独立复核的 **F6/F7/F8/F9 全部在组件内闭合**，每条都有「复核证据 → 失败断言 → 修补 → 复绿」
> 的链路；冻结树上单测与真实协议矩阵双门禁通过，**同意重新申请 S5**。S5 本身仍未开始。

## 1. 结论与范围

- 修补对象：[独立复核](2026-10-12-SSH-R1-R5独立复核与S5暂缓结论.md) 的 F6–F9（P1×2、P2×2），
  按[补充修补方案](../12_features/SSH资源生命周期补充修补方案-2026-10-12.md) 的 L1–L3 顺序施工，**一步一个提交**。
- 只动组件与其独立测试/探针；**未改** Runtime/Host/DI/slnx/工具/审批。
- 上一轮已闭合的 R1（cwd 守卫）、R4（输出事实）、R5（限额校验）未回退。

## 2. F6–F9 → 修补 → 证据

| 编号 | 复核缺陷（实测形状） | 修补（提交） | 门禁与证据 |
|---|---|---|---|
| **F9 / P2** | 隔离区容量不是硬上限：Core=1、capacity=1 时 **pending=4、connectCount=4**；`SshStageWorkerPool.Start` 是 `IsFull` + `Increment` 两步预留 | L1（`20addd7`） | 隔离区改 `TryReserve`（CAS 原子预留）+ `TrackReserved`/`ReleaseReservation`；转移失败**保留原准入槽**；排队唤醒后、读身份前再核对停止与资源准入。门禁 `QuarantineCapacity_IsHardLimit_EvenForAlreadyQueuedRequests`：**改前红**（pending 越限、连接 4 次）→ 改后 capacity=1、`ConnectCount=1`、后续请求 `ssh.busy`；capacity=0 语义为「禁用转移但正常请求照常」（改前红：容量 0 把所有请求都拒了）。另加并发 barrier：24 并发/容量 3 ⇒ 峰值 3、拒绝 21 |
| **F8 / P1** | 未结束的 exec 脱离记账：业务返回后 exec 仍挂起，而 **leases/workers/quarantine 全为 0**，`StopAsync` 报 `Pending=0, TimedOut=false`，诊断还声称「已释放独占连接」 | L1 | 租约改为**登记先于调度**：identity/connect/exec/close/迟到回收全部 `RegisterWork`；`ResourcesCompleted` 只在义务清零且登记集合为空后完成；`EndBusiness` 只结束业务计数，有挂起工作时保留准入槽（或成功预留隔离令牌才释放）；新增 `PendingResourceLeases` 与 `SshStopReport.PendingResources`；关闭走**独立关闭池**（`MaxCloseWorkers`），不被卡死的 connect/exec 饿死；宽限到期诊断改指 `cleanup_state`。门禁 `OrphanExec_StaysAccountedAfterBusinessReturn_AndStopReportsPending`（**改前红**：计数全 0、Stop 报 0）→ 改后占账非零、Stop 如实报告、gate 释放后归零；`OrphanExec_LateFault_IsObserved_AndCountersReturnToZero`；`CloseCapacityExhausted_RefusesNewResourceCreation` |
| **F7 / P2** | 迟到建连仍在使用身份时，业务 finally 已清零材料：`connect_pending=true`、worker=1，但**材料已全部清零**（转移只在迟到回调里置位） | L2（`0430f3f`） | 新增 `SshIdentityOwner` 状态机（`LeaseOwned → Connecting → SessionOwned → Released`），转移在**调用 connect 之前**执行；释放点移到「租约全部资源结束之后」（`CompleteResources`）；`StageHandoff` 改为 `BusinessOwned → AbandonedToLateOwner → Settled`，`WaitStageAsync` 返回 `Completed=false` 后**立刻**把结算权原子交给迟到 owner。门禁 `SshIdentityOwnershipTests` 6 例（非零合成字节：取消后材料**逐字节不变**；迟到成功/失败后 `DisposeCount==1` 且零 exec；Test/Execute 两个入口；迟到 Dispose 卡住时继续占账且不清零；8 轮竞争只释放一次；deadline 后交还的连接绝不执行命令） |
| **F6 / P1** | exec/Dispose 的同步入口未受有界调度保护：deadline 120 ms、宽限 50 ms 时 **820 ms 才返回且报 Completed**；Dispose 同步阻塞时 `ssh_test` **806 ms**；两例 `ActiveStageWorkers=0` | L3（`d0439ca`） | exec 与会话 Dispose 的**调用本身**放进有界 worker（先取令牌再调度）；新增 `SshCleanupBudget`（从清理开始起算的绝对预算，不受业务 deadline 影响）；`StopAsync` 进入即建立停止 deadline、`Cancel` 在 worker 上纳入有界等待并新增 `CancelCallbacksPending`；迟到 `Completed` 不再覆盖本地终止事实（远端证据保留）；`CleanupState=Completed` 需要关闭证据；诊断拼接统一 `BoundedJoin`。门禁 `SshSyncEntryBoundaryTests` 7 例：3 秒同步阻塞 exec（采样确认占住有界 worker、取消后有界返回且不报 Completed、资源继续占账）、两个入口的同步阻塞 Dispose、阻塞取消回调下 Stop 有界且如实报告、清理预算独立于业务 deadline、迟到成功不覆盖终止、关闭证据（自报未关闭/Dispose fault 都不算 Completed）、并发关闭共享单次状态机（`DisposeCallCount==1`） |

**取红记录**

- L1：`--filter SshResourceAccountingTests` → 失败 3 / 通过 1（隔离区越限、容量 0 全拒、孤儿 exec 零记账）。
- L3：临时把 exec 调用还原为「直接调用 + 事后等待」→ 门禁**失败 836 ms**（与复核实测 820 ms 同形），恢复后通过。
- F7 的失败形状由 L1 的等价观测承载，并由 L2 的合成字节用例钉住（材料逐字节不变 / 恰好清零一次）。

## 3. 修补过程中额外发现并修掉的缺陷

1. **交接义务被业务路径提前结算**（L2 内发现）：旧写法在业务 finally 里 `Settle()`，导致迟到 owner 的关闭登记
   落在**已完成**的租约上（trace：`EndBusiness obligations=1 → CompleteWork connect → RegisterWork close`）。
   这正是 F8 的同一类缺口，已由「放弃等待时原子转移结算权」修掉。
2. **清理预算被业务剩余额度归零**（L3）：原来 `RemainingCleanup = min(grace, 业务剩余)`，业务 deadline 一过
   清理额度就是 0（还没试过关闭就进隔离区）；现在清理预算独立起算。
3. **流程失误（自查并记录）**：用 `Copy-Item` 恢复文件会保留旧时间戳，增量构建据此跳过重建，导致我一度
   在陈旧二进制上读结果；此后所有恢复都强制重建（`Get-ChildItem | % LastWriteTime = now`）。评审侧若复跑
   本轮证据，建议同样强制 `-t:Rebuild`。

## 5. 残留限制（如实列出）

1. **同步阻塞的线程不可强杀**：exec/Dispose 现在都占**有界** worker（阶段池/关闭池各默认 8），满额 `ssh.busy`；
   计数与峰值可查询（整改门禁记录峰值），这是「有界占用」而非「消灭」。
2. **清理隔离区与关闭池是进程内的**：容量耗尽即拒绝新资源（设计意图）；卡住的资源在真正结束前持续占账。
3. **关闭预算的实现位置**：协调器用 `SshCleanupBudget`（≤ `CleanupGrace`），真实会话的关闭状态机用自己的
   `CleanupGrace`；两者共用同一 2 秒合同，但真正「传入同一份预算」需要扩展端口签名——本轮未改端口，已记录。
4. **每主机门字典不回收**（键 `hostId+hostRevision`）。
5. **「两类 `.ssh`」仍只验证到形状层**（路径/文件集合/隔离）；owner/ACL/跨平台解析属 S5。
6. **真实网络无法确定性构造「迟到成功交还 session」**，该时序由假端口用例覆盖（迟到连接被关闭、零 exec、
   材料恰好清零一次）；真实侧只证明 `lateconnect` 不执行 marker。
7. **托管分配 ≈0.22–0.27 B/字节**（库缓冲周转）非驻留；驻留按「会话关闭后」口径实测 ±0.2 MiB。
8. **阻塞的取消回调会占一个线程池线程**直到返回：Stop 不再等它（`CancelCallbacksPending=true`），
   但它仍是不可强杀的。

## 6. 新 S5 准入结论

**判定：同意重新申请 S5（组件侧全部门禁通过）。**

- 复核的 F6–F9 均有对应的失败断言与复绿证据；ADR-096 D1–D5（含补充约束）在组件内闭合；
  `ProjectReference = 0` 由 `ComponentBoundaryTests` 编译期强制。
- 单测 228/228 与真实协议 23 场景 `failures = 0` 在冻结树上通过。

**S5 仍需独立证明（不得用本报告替代）**：跨平台 `.ssh`/私有目录解析与 owner/ACL、主机可见性/revision、
三个 Agent 工具与审批（含拒绝路径）、DI 与宿主组合测试；随后按 A6 走外部部署新构建 → 进程内 smoke →
外部生命周期结论。

**边界不变**：S5 结论给出前不修改 Runtime/Host/DI/slnx/工具/审批；不引入 KeyVault/连接池/远端任务。
