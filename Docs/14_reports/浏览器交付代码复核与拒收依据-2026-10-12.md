# 浏览器交付代码复核与拒收依据

**建议不通过当前浏览器产品交付验收，也不接受 B1/B6 已完成的结论。** 保留已实现组件，但必须修复以下执行链问题后再进入外部部署验收。总体设计继续采用此前选定的 A：Core 可信执行身份跨进程声明，Desktop 以任务授权、控制世代及原租约裁决。

本报告是代码审阅和进程内反例测试，不是 WebView2 真机验收。没有重启产品，没有读写真实 DataRoot，没有修改生产代码。

- DeepSeek 交付记录宣称整链 `12 套件 / 2066 通过 / 0 失败`、多轮连续绿；本次没有重新执行整链，也不把该数字记为独立验证结果。
- 本次向三个既有测试项目显式注入 **11 条新的行为验收用例，11 条全部失败**。三个测试项目均成功编译，失败来自断言或被测解码异常，不是构建失败。
- 对照：既有 DesktopService 准入/复检/租约相关用例 **4 条通过**，既有连接绑定解码用例 **6 条通过**。说明当前绿色测试没有覆盖下面的关键反例。
- 原始结果的用例名、失败消息、汇总和源文件 SHA256 保存于 [机器可读证据](2026-10-12-browser-delivery-review-evidence.json)。复现方法见 [测试说明](../../TestScripts/BrowserDeliveryReview/README.md)。

## 2. 阻断项

| 编号 | 优先级 | 结论与可观察影响 | 证据强度 |
|---|---|---|---|
| F1 | P0 | 默认 Bridge 路径没有任务 grant 准入；无授权仍调用页面 handler。接管时又将只读操作一并拒绝，与组件策略不一致 | 1 条失败反例 + 活路径代码 |
| F2 | P0 | UI 执行前重新 `Admit`，使接管再恢复后旧排队动作复活；取消和版本拒绝还会遗留租约 | 3 条失败反例 |
| F3 | P0 | operationId 缓存没有完整身份/载荷指纹和原子进行中占位，可能串用结果或重复执行 | 4 条失败反例 + Broker 静态检查 |
| F4 | P0 | “选中 Agent 目标页”被当成任意任务可申请授权；没有核验用户究竟把页交给哪个运行任务 | 1 条失败反例 + 控制面静态检查 |
| F5 | P1 | 绑定生产者只挂在 Bridge runtime 分支；直接 gRPC 路径不能自行建立合法授权，管理授权也没有生产签发路径 | 静态调用链核验，需装配回归 |
| F6 | P1 | 子代理绑定 apply/revoke 解码丢失 `ParentTaskId`，有效子代理请求不能往返；Runtime 委派闭环未证实 | 2 条失败反例 + 接线检索 |
| F7 | P1 | screenshot 只返回图片元数据与分块数量，字节没有进入工件存储或原生图像消息，Agent 无法看图 | 工具出口代码核验 |

### F1：Bridge 没有调用统一准入

[BrowserBridgeCommandDispatcher.DispatchAsync](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandDispatcher.cs) 先按 operationId 读缓存，然后检查全局暂停/接管，最后直接调用 `_handler.ExecuteAsync`。没有 `Authority.Admit` 或原租约复检。WinUI [项目文件](../../Source/PuddingDesktop/PuddingDesktop.csproj) 第 41 行链接编译 `WpfArchive/Browser/*.cs`，因此这不是无效的归档代码。

反例 `BridgeWithNoPageGrantMustRejectBeforeHandler`：没有任何 page grant，实际返回 success，handler 调用 1 次。`BrowserWorkspaceController` 既有 Bridge 页面处理分支不统一经过 DesktopService；截图专用分支不能证明其他命令也经过该闸门。

### F2：再次准入不能代替复检原租约

[DesktopService.RunOnUiAsync](../../Source/Pudding.DesktopService/DesktopService.cs) 第 734 行获取租约，准入失败和入队前取消在 `try/finally` 之前返回。`ValidateAdmission` 又在签发租约后才验证页面版本，所以版本拒绝也会留下租约。

UI 回调 `ExecuteOnUiAsync` 第 798 行再次 `ValidateAdmission`，其第 898 行再次 `Authority.Admit`；没有携带原租约调用 `Revalidate`。接管先撤掉旧租约，恢复后这次 Admit 重新签发，旧动作继续执行。

实测：`TakeoverThenResumeWhileQueuedMustNotReviveTheOldOperation` 实际成功，页面 driver 调用 1 次；取消与版本拒绝两例均未调用 driver，但 `ActiveLease` 不为空。复活路径中新租约未被 finally 释放还可由代码推导；该项没有另计一条实测结果。

### F3：去重的身份和请求范围不完整

- Bridge 缓存只用 Guid，另一 caller 同 operationId 得到原 success；两个尚未完成的同 operationId 请求都进入 handler，实测调用 2 次。
- [DesktopConnection 的 Fingerprint](../../Source/Pudding.DesktopConnection/Mapping.cs) 第 787 行只序列化 Navigate、ExecuteJavascript、ShowNotification；其他 payload 全部走 `_ => []`。不同 caller 或不同目标的 binding.apply 都得到相同空字节 SHA256。
- [DesktopSession.InvokeAsync](../../Source/Pudding.CapabilityBroker/DesktopSession.cs) 第 509 行计算指纹不传 call，复用 pending 的逻辑在 `_authorizer.AuthorizeAsync` 之前；[CoreCommandEncoder](../../Source/Pudding.CapabilityBroker/WireMapping.cs) 同样没有将 caller 纳入指纹。该 Broker 风险来自静态检查，未另做运行复现。

四条失败反例分别覆盖跨 caller 缓存、并发重复执行、解码指纹忽略 caller、解码指纹忽略目标。仅增加 payload 字段不能修复并发竞争；必须同时有原子登记。

### F4：页面选择不是任务授权

[BrowserTaskBindingService.Accept](../../Source/Pudding.DesktopService/BrowserTaskBindingService.cs) 只要求 target 等于当前 AgentTarget，随后按请求中的 Task/Scope/Source 签发。反例先为 A 绑定选中页，再为无关 B 绑定同一页，两次都 accepted。测试直接调用生产绑定服务，证明该服务本身没有任务选择约束；并不宣称模拟了恶意远程客户端。

[DesktopService](../../Source/Pudding.DesktopService/DesktopService.cs) 第 388–417 行对 apply/revoke 直接调用此服务，没有核对 envelope caller 与 payload task 的允许关系，也未像页面操作一样串行送入 UI 控制序列。服务内部 `_active` 是普通 Dictionary，而 UI 目标切换又会撤销绑定，需一起消除竞态。

重复 Accept 还会先签新 grant 再撤旧 grant；这不是语义幂等，可能打断正在执行的操作和子授权。修复时必须按稳定 bindingId/revision 返回同一授权，不可每次重新签发。

### F5：两种传输具有不同的授权可达性

[RemoteBrowserRuntime](../../Source/PuddingHost/BrowserBridge/RemoteBrowserRuntime.cs) 第 181–186 行在发 Bridge 命令前调用 `IBrowserBindingGate.EnsureAsync`；[TransportRoutedBrowserCapabilitySurface](../../Source/PuddingHost/BrowserBridge/TransportRoutedBrowserCapabilitySurface.cs) 第 228 行开始的路由在 channel 可用时直接调用 channel，不经过前者。

[CapabilityChannelBindingGate](../../Source/PuddingHost/BrowserBridge/CapabilityChannelBindingGate.cs) 无 channel 时直接 no-op；有 channel 时由普通页面调用自动申请固定 Read|Write。其缓存未绑定连接世代，注册时还以 `Sessions.FirstOrDefault()` 选择会话。因而既不能保证 Bridge-only 的授权，也不能给直接 gRPC 调用提供正确 bootstrap。

此外，生产路径未找到 `IssueManagementGrant` 调用；[操作映射](../../Source/Pudding.Contracts/Desktop/BrowserOperationMapping.cs) 将整个 `BrowserTabs` 能力映射为 `TabClose`，不区分 list/new/activate/close。后果由代码推导，下一轮必须用真实组合根测试验证，不以“把映射写得更严”代替功能语义。

### F6：子代理线缆丢失父运行身份

[Mapping.cs](../../Source/Pudding.DesktopConnection/Mapping.cs) 第 581 和 611 行从绑定 payload 构造 `BrowserCallerIdentity` 时只传三个参数，遗漏已在线缆携带的 ParentTaskId。apply 返回 InvalidRequest，revoke 直接抛出 ArgumentException。两个行为均由有效子代理消息的测试复现；未验证异常是否会终止实际连接，不能将其当成已证明的断连问题。

本次在 Runtime 中未找到 browser grant/委派生命周期接线；相对前次决策提交 `9fc7d40`，Runtime/Platform/Core 也没有对应交付改动。应把 B6 描述为组件侧实现，不能据此证明运行中的子代理获得了受限 browser 工具。

### F7：有 capture 实现，尚无 Agent 视觉输出

[BrowserScreenshotTool](../../Source/PuddingBrowser.AgentTools/BrowserScreenshotTool.cs) 第 142–151 行成功时仅返回 observationId、尺寸、mime、byteCount、pageVersion、detail 与 `chunks = Count`。没有图像字节、可解析 artifact 引用或 native image part。

这比早期“截图全是桩”已有进展，但仍不能满足“Agent 看浏览器”。可以复用 [ImageReaderTool](../../Source/PuddingHost/Tools/ImageReaderTool.cs) 的 `VisionArtifactStorageService` + `ToolExecutionResult.OkWithParts` + `LlmImagePart` 模式，具体边界与适配器见施工方案。

| 用户目标 | 本次建议 |

| 渐进 DOM、ref、模拟输入 | 不推翻既有渐进阅读实现；本轮未重验所有预算、滚动、native 输入和真实页面，因此不追加通过结论 |

| HTML 交互作品、表单、SVG、涂鸦 | 仍按独立应用运行时方案推进，不能用通用网页 JS 执行冒充作品状态与页面 SDK；本轮未验收其实现 |
