# B 首笔交付：普通 Work 组合原型（WorkId 贯穿产物与归档）

## 入口

```powershell
pwsh -NoProfile -File TestScripts/test-foundation-prototype.ps1 -RunId <唯一标识>
```

脚本在仓库内隔离 TEMP、文件型 SQLite 与真实插件 Worker 下运行，成功时打印一份机读回执；任一断言失败非零退出。

## 本笔已跑通的链路（真实组件）

1. 隔离 SQLite + `AgentWorkApiFactory`/`CanonicalAgentWorkBackend` + 真实 `ConversationAcceptanceStore`/`SubmitTurnHandler` 受理 Work；
2. 公共 SDK 消费者 `Pudding.Api.Sdk.AgentWorkClient` 提交并读取同一 Work；
3. 脚本模型（替换外部 provider）经真实 `RuntimeAgentDispatcher` 驱动 `AgentExecutionService`；真实 `ExecutablePluginService` 加载工具插件与零工具观察者；
4. 循环调用工具插件 echo 与原型宿主工具 `publish_artifact`；后者经 `WorkspaceArtifactService` 在同一事务提交版本化产物与 outbox 事件；
5. 真实 `SqliteExecutionJournal.CommitTerminalAsync` 写终态，SDK `GetAsync` 读到 `Completed`；
6. 订阅同步 + `PluginEventDispatchWorker` + 定向 sink + 真实插件 Worker；观察者经受权 `plugin.archive.record` 请求归档；`PluginArchiveStore` 写入；
7. 用同一 `WorkId` 查回：产物 ID/版本/内容引用、EventId、归档 ArchiveId/OperationId、投递 ack 次数、Work 终态。

实测回执示例（`.work/b-prototype/20261109-b1/receipt.json`）：

```json
{"workId":"work-...","operationId":"prototype-work","artifactId":"work-...","version":"1.0.0","eventId":"...","archiveId":"...","archiveOperationId":"...","delivery":{"Delivered":1,"Acknowledged":1},"snapshot":"Completed"}
```

## 验证

- `TestScripts/test-foundation-prototype.ps1 -RunId 20261109-b5`：**exit 0**；builder 三步通过；原型断言通过。
- 证据：`.work/b-prototype/20261109-b1/`（receipt、测试日志、构建日志）。

## 已知边界（必须保留，不得据此宣称 B 完成）

- Work 提交在本进程内通过公共 SDK 包装真实管理 API，未走 HTTP/TestServer 传输。
- 脚本模型直接注入 `AgentExecutionService`；**生产 dispatcher/命令桥**（Work 命令 → Host 执行器）尚未接入原型；预算/并发槽（I1-06）也未经过本循环（模型侧仍为脚本客户端）。
- 重投、卸载/重载、取消阻塞 Work 已纳入本脚本并通过（replay archive=1；unload delivered=0/archived=0；reload archived=1；cancel status=Cancelled/artifact=false）。
- 原型只验证“基础设施最小组合”，不代表真实 provider、Desktop/Core 生命周期或产品替换。
