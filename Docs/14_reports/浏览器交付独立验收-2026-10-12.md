## 8. 真机首测（2026-10-12 21:2x）：Bridge-only 路径**没有任何授权来源** ⇒ 浏览器对 Agent 完全不可用

**现象**（本 Agent 实跑，非二手）：

```
browser_context(action=list) → {"code":"page_grant_required",
  "message":"no read page grant for this caller on 5b51c727b356444e8c20a4d839c484e0/60b1b5fab1a84d3b9e48e9373b4f79f0"}
browser_tabs(action=list)    → 同上（同一 context/page）
```

对照 2026-10-08：**同两项调用是成功的**（当时可自由 `list`/`locate`/`click`）⇒ 这是行为变化，来自今天 21:12 的部署（实际启动目录 `Source\PuddingAgent\bin\Debug\net10.0` 下 `PuddingRuntime.dll`(4,750,848 B) / `PuddingAgent.dll`(13,824 B) / `PuddingBrowser.AgentTools.dll`(185,856 B) 写入时间**均为 2026-10-12 21:12**；运行进程 `PuddingAgent.exe` PID 83832、`PuddingDesktop.exe` PID 19240）。

**根因链（逐环 file:line，均由本 Agent 亲读）**：

| # | 环节 | 事实 |
|---|---|---|
| 1 | 拒绝点 | `Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandDispatcher.cs:413-415`：`HasSufficientPageGrant(caller,target,required,now)` 为假即回 `page_grant_required`（只读要 Read、写要 Write，fail-closed） |
| 2 | 门的调用点 | `Source/PuddingHost/BrowserBridge/RemoteBrowserRuntime.cs:183-187`：发 Bridge 命令**前**调 `gate.EnsureAsync(caller, ctx, page, ct)`（已接线 ✓） |
| 3 | **注册的门** | `Source/PuddingHost/BrowserBridge/BrowserBridgeServiceCollectionExtensions.cs:53`：**只注册** `CapabilityChannelBindingGate` |
| 4 | 该门行为 | `CapabilityChannelBindingGate.cs:47-52`：`session is null ⇒ return`（**显式 no-op**，注释自述"无会话时门是 no-op（只走 Bridge 的现网路径行为不变）"） |
| 5 | 本机配置 | `%LOCALAPPDATA%\Pudding\desktop.json` → **`"desktop": null`**；`D:\Data\config\system.json` 无 `Desktop:CapabilityChannel` ⇒ **无能力通道会话** |
| 6 | 推论 | 因此**从不签发 `browser.binding.apply`** ⇒ 无任何 page grant ⇒ 第 1 环必然拒绝 |
| 7 | 旁证 | Bridge 路径的绑定门实现 `DesktopBrowserBindingGate.cs` **存在且自带用例**（`Tests/PuddingHost.Tests/BrowserBridge/DesktopBrowserBindingGateTests.cs`），但**未见任何组合根注册它**（`Source/PuddingHost` 内无引用；`Source/PuddingRuntime` 检索零命中；`Tests` 内仅测试自身引用。⚠️ 跨全 `Source` 检索触及 2000 文件枚举上限，属 partial，不能排除其他目录） |

**结论**：**F1 闸门与「授权签发」两半被分别落地，且未在 Bridge-only 传输上做端到端验证** —— 正是拒收报告 **F5**（两种传输授权可达性不同）所指，也说明施工方案 §8 第 4 项（外部部署真机 G1–G11）**若执行即会拦下此问题**。当前真机（Bridge-only）下浏览器能力对 Agent **完全不可用**，相较 2026-10-08 的"可用但无准入"属**功能退步**。

**用户侧操作无法绕过**：点「设为 Agent 目标」（`MainWindow.xaml.cs:1069 → AssignAgentTargetAsync`）只写 page 级 target 标记，**不签发 grant**；且该按钮文字写死（`MainWindow.xaml:323`）**没有任何生效反馈**（生效与否只反映在状态条文案 `MainWindow.xaml.cs:445` 拼装的 `ControlState · AgentTargetSummary · CurrentAgentSummary`）。

**两条可行修法（待裁定）**：
1. **启用能力通道**（`desktop.json` 的 `desktop` 节点）—— 让 `CapabilityChannelBindingGate` 解析到会话并真正申请 `browser.binding.apply`；但该半条路径**从未真机验证**（F5 的另一半）。
2. **把已存在但未注册的 `DesktopBrowserBindingGate` 接到 Bridge 传输**（Bridge 是本机默认路径），并补一条 Bridge-only 端到端用例（未授权拒绝 / 授权后可读）；这修的是**默认路径**，优先级应更高。
