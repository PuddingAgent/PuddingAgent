# 2026-10-20 交互面板设计与代码审阅

审阅基线：`a3575c6`。范围为[原设计](../12_features/交互面板-交互式编辑与制成品管理-设计方案-2026-10-20.md)、Desktop 面板/制品库、Foundation 标注与存储、Core 面板和视觉入口、Web 输入框桥与附件链路。用户截图用于理解使用场景，不证明运行进程已加载该提交。

**产品方向：面板应让 Agent 自主生成和持续控制丰富的交互界面，用户直接操作、探索和参与设计，并把结果反馈给 Agent。图片标注与制品管理是其中一个应用场景。** 推荐方案见 [ADR-099（Proposed）](../07_architecture/113ADR-099交互面板编辑状态与制成品归属ADR.md)。

以下代码证据仍针对上述基线，重点覆盖现有图片链路。保留“生成结果与用户收藏分开”“坐标与烧录并用”“多 tab”的方向，先修复已确认的数据与编辑缺陷；通用能力优先打通“Agent 发布界面 → 用户直接操作 → Agent 更新界面”。不能让图片上传成为所有面板场景的前置条件，也不能把可信运行时设计成只支持固定编辑器的外壳。

## 1. 优先修复的问题

以下行号均对应审阅基线。P1 为应优先修复的数据安全、隔离或核心编辑问题；P2 为可复现的功能/交互缺陷。静态发现与执行探针分开标注。

### R1 · P1：回收站清理会删除带数字后缀的用户目录

位置：[PanelCraftStore.cs](../../Source/PuddingDesktop.Foundation/PanelCraftStore.cs) L448–507，特别是 `TryReadTrashTimestamp`。

文档承诺只清理 `{craft-id}-{unixMillis}`，代码却只检查最后一个连字符后的数字，没有调用 `PanelCraft.IsValidId` 校验前半段。用户放入 `_trash/my-own-backup-<过期毫秒时间戳>/` 后，只要打开制成品列表触发维护，该目录就被递归删除。

**执行复现：**隔离目录中创建该名字与一份用户笔记，`PruneTrash` 返回 1，目录不存在。既有测试只覆盖 `my-own-backup`（没有数字尾缀），因此没有拦住问题。

建议：校验完整 ID、时间戳及可信删除记录，拒绝未知条目与重解析点；清理移到唯一维护入口。补“用户名字也以时间戳结尾”的反例。

### R2 · P1：制成品 JSON 的 fileName 能让删除操作移动库外文件

位置：[PanelCraftStore.cs](../../Source/PuddingDesktop.Foundation/PanelCraftStore.cs) L190–192、L389–392、L422–427。

`PanelCraftJson.Read` 只检查 `fileName` 非空；`ResolveImagePath` 直接 `Path.Combine`。删除时源和目标都信任此字段。备份导入、手工修改或损坏 JSON 写成 `../sentinel.jpg`，就能让用户点击“删除制成品”移动库外图片。

**执行复现：**所有文件均位于 `temp/test-out` 的自建夹具；`ResolveImagePath` 越出 `crafts`，`Delete` 把库外夹具移到 `crafts/_trash/sentinel.jpg`。未操作真实用户数据。

建议：记录名与 ID 匹配；文件名只能是受控 basename，最终规范路径留在资产根内；读取、打开、删除共用同一验证。移动两份文件还需可恢复的提交/回滚语义，避免 JSON 已移走但图片移动失败。

### R3 · P1：调整面板宽度会改变标注指向

位置：[PanelCanvasDocument.cs](../../Source/PuddingDesktop.Foundation/PanelCanvasDocument.cs) L287–303、L442、L480–493。

图元保存显示像素，resize 只重设覆盖层，`take()` 使用新的图片显示宽高归一化，旧点没有随视图变换。用户在宽 1000px 的图片中心点选 x=500，再拖窄到 500px，提交的归一化位置从 0.5 变成 1；C# 会夹到 999。`compose()` 同样按新宽度乘旧坐标，烧录位置也会漂移。

**执行复现：**执行生产内嵌 JS，在最小 DOM 夹具改变图片宽度后，输出 `beforeNormalizedX=0.5, afterNormalizedX=1`。这是脚本行为复现，不是真实浏览器像素验收。

建议：以原图坐标/连续归一化几何存储，显示与合成共用变换；固定目标图片，不在每次 `sync()` 重选“最大图”。覆盖分隔条、缩放、DPI、多图切换的行为测试。

### R4 · P1：新 revision 直接重载，未保存笔迹丢失

位置：[MainWindow.xaml.cs](../../Source/PuddingDesktop/MainWindow.xaml.cs) L1215–1224、L1283–1291、L1604–1617。

轮询和能力推送都直接 `NavigateToString`，页面的 `items` 与撤销栈随之重建。用户还在画时 Agent 发布同一 panel 的新内容，当前草稿会消失。另一方面 `take()` 与 `compose()` 是两次独立异步调用，中间允许导航或编辑，没有共同 revision/hash，可能把旧坐标与新图组合。

**静态确认：**重载前无 dirty 检查，读取/合成结果中无提交快照身份。

建议：持久编辑草稿，Dirty 时将新版本置为候选；提交固定 `baseArtifactId/baseRevision/draftRevision`，一次快照生成坐标与图片，版本变化拒绝提交并保留草稿。

### R5 · P1：保存与继续编辑没有保存完整编辑信息和血缘

位置：[MainWindow.xaml.cs](../../Source/PuddingDesktop/MainWindow.xaml.cs) L1709–1718、L1873–1907；[PanelAnnotation.cs](../../Source/PuddingDesktop.Foundation/PanelAnnotation.cs) L602–639。

保存复制的是基图，`parent` 固定为 null，generator/prompt 也固定为 null；涂鸦在 C# 解析时已经降成带标签的 Box，没有轨迹。继续编辑只重建一个 `<img>`，没有恢复保存的 annotations 或绑定父制品。因此“parent 已落盘”“继续编辑保留编辑来源”不能从存储类字段和独立单测推出。

**执行复现：**包含三个轨迹点的涂鸦经历解析、保存、回读，输出 `kind=Box, hasPoints=False`。其他 UI 接线缺口为静态确认。

建议：先定义保存对象——默认收藏生成结果，标注单独存编辑草稿；保存/重新打开必须保留原始几何、基图 Artifact 和父制品，模型坐标只是派生数据。按钮应说明保存的是原图还是标记图，避免用户误判。

### R6 · P1：面板和插入桥缺少工作区/会话归属

位置：[PanelCanvasStore.cs](../../Source/PuddingCore/Panels/PanelCanvasStore.cs) L38–74；[PanelCanvasApiController.cs](../../Source/PuddingPlatform/Controllers/Api/PanelCanvasApiController.cs) L31–44；[composerInsert.ts](../../Source/PuddingPlatformAdmin/src/pages/chat/integration/composerInsert.ts) L18–28；[IntentConsole.tsx](../../Source/PuddingPlatformAdmin/src/pages/chat/components/IntentConsole.tsx) L345–353。

面板存储身份只有 `panelId`，`render_panel` 默认 `main`，没有工作区/会话分区。读取接口未标 `[Authorize]`，宿主也未设置全局 fallback 授权策略。桥只广播 `{text}`，当前挂载的输入框直接接收；旧会话留下的面板可以把内容插入用户刚切换的新会话。

**静态确认：**上述 DTO/调用链未传递 owner/workspace/conversation；没有用真实网络请求验证部署暴露范围。

建议：把归属加到存储、工具上下文、HTTP、Desktop tab 和提交合同全链；上传/读取均做主体授权，不能只检查工作区存在。文本路径不是图片附件，目标上下文必须由可信宿主冻结，不能让 HTML 自报。

### R7 · P2：点标记没有进入烧录图，文字预览不显示文字

位置：[PanelCanvasDocument.cs](../../Source/PuddingDesktop.Foundation/PanelCanvasDocument.cs) L230–260、L313–359。

`compose()` 遍历只处理 box/scribble/arrow/text，没有 point 分支；画点后生成的图只有基图。`paint()` 将 text 走到通用圆点分支，也没有渲染 label，用户看不到自己输入的文字，但合成却会写出文字。

**执行复现：**单个 point 的合成绘图调用仅为 `drawImage`。文字预览分支为静态确认。

建议：五种图元共享几何与样式定义，预览和合成都有对应实现；用真实 Canvas 像素测试检查点和文字。单项删除也应进入撤销栈，目前删除按钮直接 splice。

### R8 · P2：超限或烧录失败被降级成看似成功的插入

位置：[PanelAnnotation.cs](../../Source/PuddingDesktop.Foundation/PanelAnnotation.cs) L67、L482–486；[MainWindow.xaml.cs](../../Source/PuddingDesktop/MainWindow.xaml.cs) L1504–1538、L1580–1585、L1604–1633。

前端可以画出第 11 个标注，C# 上限为 10，解析返回 null；调用方将其当作没有标注，插入普通画布引用并覆盖错误提示。合成失败也吞异常，只插坐标。任意涂鸦退化为 bbox 后，用户真正表达的形状会丢失。

**执行复现：**生产 JS 接受 11 个点；C# 拒绝分支和外层成功提示为静态确认。

建议：统一图元/轨迹/字节预算，UI 到边界时即时反馈；区分“无标注”和“解析失败”；任意标记模式合成失败必须保留草稿并允许重试，不能宣称完整添加。

### R9 · P2：已打开的制成品列表不会在保存后刷新

位置：[MainWindow.xaml.cs](../../Source/PuddingDesktop/MainWindow.xaml.cs) L790–807、L1712–1720、L1970–1983。

工具 tab 内容惰性创建后缓存。先打开一次制成品列表，再回画布保存，保存函数没有使列表缓存失效；再次切回看到旧列表。注释“每次进入标签页重扫”与实际缓存行为相反，刷新函数仅由删除路径调用。

建议：保存/改名/删除共用工作区资产变更通知或缓存失效；验证“空库打开 → 保存 → 切回”而不仅测试 `Store.List()`。

### R10 · P2：图片面板的“下载到本地”导出的是不完整 HTML

位置：[MainWindow.xaml.cs](../../Source/PuddingDesktop/MainWindow.xaml.cs) L1351–1399；[PanelCanvasDocument.cs](../../Source/PuddingDesktop.Foundation/PanelCanvasDocument.cs) L54–58。

按钮总是写 `.html`，原样保留 `pudding-image:///...`，普通浏览器没有该 scheme 的 Shell 拦截器。导出也不带当前标注，与用户在图片编辑界面理解的“下载图片”不一致。

建议：图片页默认导出原始图片，另提供标记图；HTML 导出必须打包/内嵌依赖并声明脚本行为。不要把取消 CSP 当作解决资源可移植性。

## 2. 设计层修订建议

### 2.1 D1 并非“Desktop 是否能持有凭据”的空白决策

- [DesktopApplicationCoordinator.cs](../../Source/PuddingDesktop/Hosting/DesktopApplicationCoordinator.cs) L73–79 已有 `GetDesktopControlTokenAsync`。
- [DesktopLifecycleEndpointExtensions.cs](../../Source/PuddingHost/Hosting/DesktopLifecycleEndpointExtensions.cs) 使用 Loopback + ControlToken；[PuddingApplicationHost.cs](../../Source/PuddingHost/Hosting/PuddingApplicationHost.cs) L170–193 则把 JWT 作为业务默认认证。
- [VisionArtifactApiController.cs](../../Source/PuddingPlatform/Controllers/Api/VisionArtifactApiController.cs) 的上传有 `[Authorize]`，图片读取明确 `[AllowAnonymous]`；上传只验证 workspace 存在，没有在该方法内验证用户归属。
- [IntentConsole.tsx](../../Source/PuddingPlatformAdmin/src/pages/chat/components/IntentConsole.tsx) L665–687 已上传图片并生成 typed image parts。

因此图片场景建议先增加 **A0：可信 Web 复用已有登录态/附件链路**，抽取公共上传服务供面板事件和聊天附件使用，不要求所有操作经过输入框。原生上传确有独立需求时才考虑 A1，且必须定义作用域、签发、失效和重放保护。“放在本机、不经过网络”不是授权模型，Loopback HTTP 仍需要校验调用者。A2 与 A3 不推荐，直接写 vision 目录也不推荐。

### 2.2 D2 不能对已发消息图片直接做最近 N 张淘汰

当前 `panel-marks` 没有清理，确实会增长；但文本中的绝对路径可能在以后才被 Agent 读取。B1 立即删除会立刻断链；B2 无引用保护也会让第 51 张以后的操作破坏前面的消息。应先登记 Artifact、保存引用，再对无引用 staging 使用张数、总字节、TTL 三重限制。已发送消息和用户收藏不因缓存上限而被删除。

### 2.3 T1 与 D6 需要回到已有架构边界

“制成品是用户资产”不能推出“Desktop 应当持有业务真源”。现有 Shell/Core ADR 明确 Core 负责业务，Web 承担业务 UI。建议 Core 统一管理资产，Shell 仅承载和系统集成，保留本地文件备份特性。

`SideArtifactPanel` 本身只是 tabs 容器；当前生产 [SideDocumentPanel.tsx](../../Source/PuddingPlatformAdmin/src/pages/chat/components/SideDocumentPanel.tsx) 只传入“文档”一个 tab。不能根据组件注释推断已有第二套完整制品库。D6 应表述为“如何共享将来的资产服务与现有不同面板入口”。

### 2.4 原方案与代码的其他差异

| 原方案描述 | 基线代码事实 | 修改建议 |
|---|---|---|
| `workspaces/{ws}/crafts` | `CraftStore` 传入 DataRoot，实际为 `DataRoot/crafts` | 目标合同改成明确的 Workspace 资产，现状说明写实际路径 |
| sha256 内容寻址去重 | Save 每件复制一份；注释明确不去重 | 引用保护落实前保留独立副本，去重另行实现 |
| JSON `artifactId/file/kind` | 实际 `id/fileName`，无 kind | 记录 schemaVersion，正式 API 合同与存量格式分清 |
| parent 已落盘、可追溯 | 类型支持，但 UI 保存传 null | 不能用存储单测代替调用链验收 |
| P1 列表缩略图、下载/改名 | 当前卡片是文字、继续编辑/打开文件/删除 | 分清目标与已实现，补齐列表刷新后再扩展 |
| 1536/JPEG 能保证脚本通道 | 实现只有格式/长边控制，无字节预算，且吞失败 | 本轮未确认 SDK 固定容量；改为实测传输预算与明确错误 |
| 一个 panelId 对应图片前 8 位 | 全局身份可能冲突，同源并行编辑无法区分 | 完整编辑会话 ID + 作用域；短 ID 只作显示 |

`craftId` 同样仅取 GUID 前 8 位且保存使用覆盖式写入；建议完整 ID、CreateNew/冲突重试及原子提交。该项属设计风险，未模拟随机碰撞。

### 2.5 可信运行时与 Agent 页面分离，同时保留脚本和双向交互

[PanelCanvasDocument.cs](../../Source/PuddingDesktop.Foundation/PanelCanvasDocument.cs) 原样插入 HTML，允许 inline script，且 `if (window.puddingAnnotation) return` 会接受预先存在的对象。Agent 内容与标注基础设施在同一个 JavaScript 上下文里；“只有宿主读取”并不能证明返回值来自用户真实笔迹。

建议可信运行时持有面板归属、版本、SDK 和资源授权，Agent 页面在隔离表面运行自定义 HTML/CSS/JS，负责布局、动画、输入与局部计算。页面经 SDK 提交结构化事件和状态，Agent 可直接读取与更新；隔离不能解释为禁用脚本或全面禁止页面发消息。可复用的图片编辑组件独立持有选定 Artifact 和几何状态，页面自报数据始终有明确来源。

资源授权按具体资产/工作区，避免默认授予全部 DataRoot 和 Pictures；独立检查导航、新窗口、资源读取、profile/登录态隔离。此处确认的是源码边界缺口，**未进行真实 WebView2 攻击或网络外传复现**。

## 3. 交互建议

用户截图展示了图片标注场景；完整产品要支持用户在面板里完成工作，而不要求频繁回到聊天框解释操作。

- Agent 自由生成任务界面与工具条，宿主提供通用加载、恢复和关闭入口；预置组件不限制界面形式。
- 拖拽、滑块、动画和局部计算即时响应；「采用此方案」「继续演示」「按此优化」等语义动作再触发 Agent。避免每次鼠标移动都调用模型。
- Agent 读取用户选择、参数和编辑结果，按版本更新页面或状态；保留输入、焦点和暂停控制。
- HTML 演示与小型交互应用纳入保存/重开主线，恢复选定步骤和参数；独立离线导出可另行交付。

图片应用另外应让用户确认：当前改哪张图、草稿是否保存、提交会进入哪个会话。

- 顶部保留标题、来源、用户版本及未保存点；原始尺寸与缩放比例放状态栏。服务端 revision 不直接命名成第几轮编辑。
- 把五种工具、撤销/重做放到可信 Web 的画布工具条；显式选中态与键盘提示。Shell 当前代码有十个横排按钮，需测试窄面板与 150%/200% DPI。
- 面板内「生成修改版」直接提交给 Agent 并展示结果；“添加到对话”仍为可选动作，附件有缩略图与目标会话，添加成功不等于已经发消息。
- 成品收藏不默认烧录笔迹；笔迹作为草稿保留。原图、标记图、模型结果提供明确切换，避免把编辑指令当最终作品。
- 草稿未提交时遇到新生成结果，保留草稿并提示候选版本；多图标注先选目标，不能让最大 DOM 图片隐式替用户决定。
- 成品库用缩略图、可改名标题、来源与继续编辑；先修列表刷新、恢复与错误反馈，再做树形血缘和批量导出。HTML 应用内保存不因此推迟。
