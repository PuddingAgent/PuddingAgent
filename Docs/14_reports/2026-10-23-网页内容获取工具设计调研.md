## 0. 一分钟结论

| 项目 | 一句话范式 |
|---|---|
| ZCode | **LLM 蒸馏**：正则把 HTML 拍平 → 喂给「当前模型 + 调用方 prompt」→ 只把**答案**还给模型；原文超 100K 只落到 session artifact 里给个路径 |
| DeepSeek Harness (dsh) | **原文 + 固定上限**：真 DOM（turndown）转 GFM Markdown，一次给全（受 200K 字符 / 5MB 字节 / 100K 解码字符三重上限），超限只加一句固定页脚，**没有续读** |
| Hermes Agent | **原文 + 落盘 + 分页续读**：抽取交给第三方后端（Firecrawl/Tavily/Exa/Parallel/Perplexity）返回 Markdown，超过预算就「75% 头 + 25% 尾 + 页脚给出全文路径和精确 read_file 调用」，这是三家唯一真正做渐进式披露的 |
| 我们（PuddingAgent） | **已提交基线 = 硬截断**（`value[..maxChars] + "... [truncated]"`）；但**工作区已有未提交 WIP**：outline 目录 + 按标题/空行分页 + 指纹绑定 cursor 续读（见 §5，与任务书里的 ALREADY_KNOWN 不一致，需以磁盘为准） |

三条共同点（三家一致，值得当作设计底线）：

1. **从不把 DOM/原始 HTML 交给模型**——都在工具内部转成 Markdown/纯文本；
2. **都做「字节上限 + 字符上限」双层约束**（ZCode 10 MiB / 100K 字符；dsh 5 MB / 100K 字符 / 200K 输出；Hermes 由厂商与 15K 预算共同决定）；
3. **超长一定显式标注**，没有静默截断（ZCode 加 `[WebFetch content truncated before prompt processing]`；dsh 加固定页脚；Hermes 加 `[TRUNCATED]` 页脚 + 已显示字符数）。

差异最大的一处是「谁承担上下文成本」：ZCode 让**二级 LLM 读取**（token 最省、但原文不可引用不可复现）；dsh 让**模型直接读原文**（可复现、但超限即永久丢失）；Hermes 让**模型按需读**（可复现 + 可续读，代价是一次 read_file 往返与磁盘存储）。

## 2. ZCode（`zai-org/ZCode`，Z.ai 的 coding agent harness）

仓库：<https://github.com/zai-org/ZCode>（TypeScript monorepo，Electron 桌面 / 浏览器 / 终端三形态共用一个 Agent 运行时；Agent CLI 位于 `apps/zcode-cli/`）。

### 2.1 涉及的工具面

- `WebFetch`：唯一「按 URL 取正文」的工具。源码 `apps/zcode-cli/packages/core/src/tool/handlers/webfetch*.ts`（12 个分片文件）。
- `WebSearch`：仅当当前模型 `supportsNativeWebSearch` 为真时可见，返回摘要 + 最多 20 条链接（源码 `websearch.ts` / `websearch-support.ts`）。
- **无内置浏览器工具**：`handlers/` 目录清单里只有 `webfetch*` / `websearch*`，没有 browser/CDP 类 handler；需要浏览器只能走 MCP（`mcp` 在 CLI 指南中是既有能力）。

### 2.2 数据流（从 HTTP 到模型）

```
GET（httpClientPort，60s，manual redirect，≤10 跳，≤10 MiB）
  → 只接受 text/*、JSON、XML、JavaScript、+json、+xml（否则 "Unsupported WebFetch content type"）
  → TextDecoder 按 UTF-8 解码（不看 charset）
  → HTML ? 正则 htmlToMarkdown() : 原样 trim
  → 若 > 100,000 字节：全文写入 session artifact（retention=session），返回 path/uri
  → truncateContentForModel()：> 100,000 字符则硬切 + "[WebFetch content truncated before prompt processing]"
  → 拼 prompt（页面全文 + 调用方 prompt + 引用纪律）→ 当前模型 generateText（tools=[]，maxOutputTokens≤4096）
  → 工具结果 = 模型写的答案（不是网页原文）
```

### 2.3 关键代码证据

**上限常量**（`webfetch-constants.ts`，raw：
<https://raw.githubusercontent.com/zai-org/ZCode/main/apps/zcode-cli/packages/core/src/tool/handlers/webfetch-constants.ts>）：

```ts

export const MAX_MODEL_INPUT_CHARS = 100_000;                  // 送模型上限
export const MAX_WEBFETCH_MODEL_BYTES = 100_000;               // 工具结果预算
export const CACHE_TTL_MS = 15 * 60 * 1000;                    // 按 URL 缓存 15 分钟
export const CACHE_MAX_BYTES = 50 * 1024 * 1024;
export const MAX_REDIRECTS = 10;
export const WEBFETCH_USER_AGENT = "ZCode-WebFetch/0.1 (+https://zcode.ai; coding-agent-cli)";
```

**HTML → Markdown：没有 DOM，纯正则**（`webfetch-content.ts`，raw：
<https://raw.githubusercontent.com/zai-org/ZCode/main/apps/zcode-cli/packages/core/src/tool/handlers/webfetch-content.ts>）：

```ts
function htmlToMarkdown(html: string): string {
  let content = html
    .replace(/<!--[\s\S]*?-->/g, "")
    .replace(/<script\b[\s\S]*?<\/script>/gi, "")
    .replace(/<style\b[\s\S]*?<\/style>/gi, "")
    .replace(/<noscript\b[\s\S]*?<\/noscript>/gi, "");
  content = content
    .replace(/<h1\b[^>]*>([\s\S]*?)<\/h1>/gi, "\n# $1\n")
    ...
    .replace(/<a\b[^>]*href=["']([^"']+)["'][^>]*>([\s\S]*?)<\/a>/gi, "[$2]($1)")
    .replace(/<li\b[^>]*>([\s\S]*?)<\/li>/gi, "\n- $1")
    .replace(/<[^>]+>/g, "");
  return decodeHtmlEntities(content).split("\n").map(l => l.replace(/[ \t]+/g, " ").trim())...
}
```

后果明写在代码行为里：表格结构丢失、`<pre>` 缩进被压平（每行连续空白压成一个空格）。这也解释了它为什么必须再让 LLM 提炼——正则产物本身可读性有限。

**超长处理的两条腿**：

```ts
// 1) 原文超 100,000 字节 → 写 artifact，只回路径
if (Buffer.byteLength(content, "utf8") <= MAX_MODEL_INPUT_CHARS) return undefined;
const artifact = await context.artifactStore.writeToolResultArtifact({... retention: "session" ...});
return { path: artifact.path, uri: artifact.uri };

// 2) 送模型前硬切
const suffix = "\n\n[WebFetch content truncated before prompt processing]";
return { content: `${content.slice(0, Math.max(0, MAX_MODEL_INPUT_CHARS - suffix.length))}${suffix}`, truncated: true };
```

**工具结果预算**（`webfetch.ts`，raw：
<https://raw.githubusercontent.com/zai-org/ZCode/main/apps/zcode-cli/packages/core/src/tool/handlers/webfetch.ts>）：

```ts
resultBudget: {
  maxInlineBytes: MAX_WEBFETCH_MODEL_BYTES,   // 100_000
  maxModelBytes: MAX_WEBFETCH_MODEL_BYTES,
  strategy: "artifact",
  preview: { maxBytes: MAX_WEBFETCH_MODEL_BYTES, direction: "head" },
  artifact: { enabled: true, retention: "session" },

timeout: { defaultMs: DEFAULT_WEBFETCH_TIMEOUT_MS, maxMs: DEFAULT_WEBFETCH_TIMEOUT_MS, allowCallOverride: false },
```

**模型提炼**（`webfetch-processing.ts`，raw：
<https://raw.githubusercontent.com/zai-org/ZCode/main/apps/zcode-cli/packages/core/src/tool/handlers/webfetch-processing.ts>）：

```ts
model.generateText({
  messages, tools: [],
  options: { ...auxiliaryModelOptions(model), maxOutputTokens: Math.min(4096, model.optionSpecs.maxOutputTokens.max) },
});
```

prompt 里带引用纪律（非预授权 URL 时）：`strict 125-character maximum for quotes`、不得逐字复述、不评述合法性、不复制歌词。唯一「直出原文」的例外：URL 在预批准名单 **且** 响应类型是 `text/markdown` **且** 原文 < 100,000 字符。

### 2.4 渐进式披露评估（ZCode）

| 机制 | 有无 | 证据 |
|---|---|---|
| DOM 树 / 可寻址节点 | 无 | `webfetch-content.ts` 全正则，无 parser 依赖 |
| 目录 / 大纲先行 | 无 | 工具参数只有 `url` + `prompt` |
| 分页 / 偏移续读 | 无 | 只有一次性 `truncateContentForModel`；要更多只能「换更具体的 URL」 |
| 二级读取（落盘再读） | 半套 | artifact 路径出现在结构化输出里，但工具描述未引导模型去读；模型看到的是答案而非原文 |
| 缓存 | 有（15 分钟按 URL） | `CACHE_TTL_MS` |

> 交叉验证（等级 C）：<https://daiw.org/manual/zcode/web-tools> 的源码解读与上述结论一致（含 100000 字节阈值、模型提炼、10 MiB 上限），仅作旁证。

## 3. DeepSeek Harness（dsh，`deepseek-ai/DeepSeek-Harness`）

仓库：<https://github.com/deepseek-ai/DeepSeek-Harness>（TypeScript + Cordis 插件框架）。web 能力是 **6 个包的家族**：

| 包 | 角色 |
|---|---|
| `packages/web/web` | 搜索/抓取服务，`ctx.web` |
| `web-search-exa` / `web-search-perplexity` / `web-search-deepseek` | 搜索后端 |
| `web-deepseek-api` | 走 DeepSeek Search/Fetch API 的后端 |
| `web-fetch-http` | 匿名公共 HTTP(S) 抓取后端（本地） |
| `tool-web` | 对模型暴露 `web_search` / `web_fetch`，负责 schema、渲染、截断 |

包族 README 明确划界（等级 B，<https://github.com/deepseek-ai/DeepSeek-Harness/tree/master/packages/web>：

> "Use this family for search and page retrieval, **not interactive browsing, content extraction**, or per-URL policy enforcement."

即：**dsh 核心没有浏览器工具，也没有「正文抽取（readability）」环节**——它做的是「抓取 + 格式转换」，不是「读懂网页」。

### 3.1 数据流

```
GET（web-fetch-http：匿名、SSRF 校验、连接钉扎、同源重定向 ≤5、≤5,000,000 字节、≤100,000 字符解码）
  → 返回 WebFetchResult { finalUrl, statusCode, body:{kind:'html'|'text', content}, truncated }
  → tool-web：html 走 turndown(+GFM) → markdown；text 原样
  → 组装 output = header("Fetched <url> (HTTP <status>)") + 外部内容警示 + 正文 + 可选截断页脚
  → 整体再按 fetchMaxOutputChars（默认 200,000 字符）上限收敛
```

### 3.2 关键代码证据

**HTML → Markdown：真 DOM + 安全守卫**（`packages/web/tool-web/src/fetch.ts`，raw：
<https://raw.githubusercontent.com/deepseek-ai/DeepSeek-Harness/master/packages/web/tool-web/src/fetch.ts>）：

```ts
const turndown = new TurndownService({ headingStyle: 'atx', codeBlockStyle: 'fenced', bulletListMarker: '-' })
turndown.use(gfm)
turndown.addRule('removeNonVisibleContent', {
  filter(node) {
    if (['SCRIPT','STYLE','NOSCRIPT','TEMPLATE','IFRAME','OBJECT','EMBED'].includes(node.nodeName)) return true
    if (node.hasAttribute('hidden') || node.getAttribute('aria-hidden')?.toLowerCase() === 'true') return true
    if (node.nodeName === 'INPUT' && node.getAttribute('type')?.toLowerCase() === 'hidden') return true
    ... display:none / visibility:hidden|collapse ...
  },
  replacement() { return '' },
})
const MAX_CONVERSION_DEPTH = 512   // 超过则不转换，返回固定省略标记
```

`renderBody()` 先用 `body.content.slice(0, maxInputChars)` 限制**同步转换工作量**（自定义 provider 无法在输出上限生效前造成无界转换），再对「完整输出」二次设限：

```ts
function computeFetchOutput(result, maxOutputChars) {
  const header = `Fetched ${result.url} (HTTP ${result.statusCode})\n\n${EXTERNAL_WEB_CONTENT_NOTICE}\n\n`
  const rendered = renderBody(result.body, maxOutputChars)
  const prefix = `${header}${rendered.text}`
  const truncated = result.truncated || rendered.sourceTruncated || prefix.length > maxOutputChars
  const full = `${prefix}${truncated ? TRUNCATION_FOOTER : ''}`
  ...
}
const TRUNCATION_FOOTER = '\n\n(Content truncated. Fetch a more specific URL or section for the full text.)'
```

**三层上限（不同层管不同事）**：

| 层 | 字段 | 默认值 | 证据 |
|---|---|---|---|
| 传输字节 | `maxResponseBytes` | `5,000,000` | `packages/web/web-fetch-http/README.md` |
| 解码字符 | `maxBodyChars` | `100,000` | 同上 |
| 工具输出 | `fetchMaxOutputChars` | `200,000` | `packages/web/tool-web/README.md` |
| URL 长度 | 固定 | `2,048` | `web-fetch-http/README.md`（"fixed at 2,048 characters"） |
| 超时 | `fetchTimeoutMs`（工具）/`timeoutMs`（provider） | `30,000` / `30,000` | 两份 README |

**模型可传参数只有一个 `url`**（等级 B，`tool-web/README.md` 的 Known Limitations）：

> "`web_fetch` takes only `url` (**no `format`/`prompt`/LLM-summarization mode**); both are named later steps in the seam Agent Note."

超时与结果数也刻意不做模型参数（`searchMaxResults=8`、`searchMaxQueries=4` 是部署配置）。理由写在 Dev Note：把成本控制放进 prompt 需要先有部署经验。

### 3.3 渐进式披露评估（dsh）

| 机制 | 有无 | 说明 |
|---|---|---|
| DOM 处理 | 有（真 DOM，turndown/domino） | 无 readability 正文抽取，保留整页结构（含导航） |
| 目录 / 大纲 | 无 | schema 只有 `url` |
| 分页 / 偏移续读 | **无（核心）** | 截断后唯一指引是「换更具体的 URL 或 section」 |
| 生态补充 | 有（社区插件） | `dsh-tool-fetch-raw`（Codeberg）显式提供 `max_chars` + `start_offset` 并绕过 `fetchMaxOutputChars`，其 README 承认这是官方缺口 |
| 浏览器 | 无（核心） | 浏览器能力由社区插件提供：`@libai168/dsh-tool-browser`（`browser_snapshot` + `maxTextBytes: 12000`）、`dsh-tool-browser`（`snapshot.maxNodes/maxNameLength/maxTextLength`） |

设计取舍非常清晰：**「原文可复现」优先于「按需展开」**，代价是超限即丢内容，只能靠模型换 URL。

## 4. Hermes Agent（`NousResearch/hermes-agent`）

仓库：<https://github.com/NousResearch/hermes-agent>（Python 3.14）。联网工具分两套：

- **`web_search` / `web_extract`**（`tools/web_tools.py`）：无 LLM 抽取，快速；
- **`browser` 工具组**（`browser_exec` / `browser_cdp` / `browser_dialog` / `browser_vault`）：真浏览器，模型写 Python 走 CDP。

官方文档明确路由原则：*"For simple information retrieval, prefer `web_search` or `web_extract` — they are faster and cheaper. Use the browser when the agent needs to interact with a page."*

### 4.1 `web_extract` 数据流

```
最多 5 个 URL
  → secret-URL 拒绝（API key/token 出现在 URL 里直接拒绝整次调用）
  → SSRF 过滤（私网/loopback 逐条拦截，返回 blocked_by_policy）
  → provider 解析（firecrawl / tavily / keenable / exa / parallel；严格选择，不静默切换）
  → 站点策略 → 磁盘缓存（键含 provider + format）
  → 厂商调用（返回 raw_content/content，即 markdown/正文 —— 本地不做 DOM）
  → base64 内联图片 → [IMAGE: alt] 占位符
  → _truncate_with_footer()：≤预算整页返回；超预算 → 75% 头 + 25% 尾 + 页脚
  → 序列化为 JSON {"results":[{url,title,content,error}]}
```

### 4.2 关键代码证据

**单次调用预算与 schema**（`tools/web_tools.py`，raw：
<https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/web_tools.py>）：

```python
"urls": {"type": "array", "maxItems": 5,
         "description": "List of URLs to extract content from (max 5 URLs per call)"},
"char_limit": {"type": "integer", "minimum": 2000,
  "description": "Optional per-page character budget sent back (default 15000). "
                 "Pages larger than this are head+tail truncated with the full text stored to disk. "
                 "Raise it when you need more of a long page inline."}
...
registry.register(name="web_extract", ..., max_result_size_chars=100_000)
```

工具描述原文（这段就是「渐进式披露」的对外承诺）：

> "Pages within the char budget (default 15000) return whole; larger pages return a head+tail window with a footer telling you the full text's saved file path and the **read_file call to page through the omitted middle**."

**截断实现**（`tools/web_tools_truncate.py`，raw：
<https://raw.githubusercontent.com/NousResearch/hermes-agent/main/tools/web_tools_truncate.py>）：

```python
DEFAULT_EXTRACT_CHAR_LIMIT = 15000
MAX_STORED_TEXT_CHARS = 2_000_000          # 落盘上限（防多 MB 页面无限写盘）
_CHAR_LIMIT_FLOOR, _CHAR_LIMIT_CEILING = 2000, 500_000

head_budget = int(char_limit * 0.75)
tail_budget = char_limit - head_budget
head, tail = content[:head_budget], content[-tail_budget:]
# 裁剪点对齐行边界（头部回退、尾部前进），保证不切在行中间
stored_path = _store_full_text(url, content)   # cache/web/<host>-<sha256[:10]>.md
footer_lines = ["", "─" * 8 + " [TRUNCATED] " + "─" * 8, f"Showing {len(head):,} ch..."]
```

额外两道「token 炸弹」防护：

- 二进制响应直接丢弃并改错（"URL returned binary content (SQLite/archive/executable)… use read_file"）；
- 内联 base64 → `[IMAGE: alt]`，真图片 URL 保留为链接（可再 `web_extract`/`vision_analyze`）。

### 4.3 `browser` 工具组（与前三者的关键区别）

官方文档：<https://hermes-agent.nousresearch.com/docs/user-guide/features/browser>

- `browser_exec`：一次调用发一段模型写的 Python（helpers 预导入：`new_tab` / `goto_url` / `page_info` / `js` / `fill_input` / `click_at_xy` / `capture_screenshot` / `cdp`），**「一次调用完成一整个子过程」**——这本身就是一种粗粒度渐进披露（用代码代替多次工具往返）。
- `browser_cdp` / `browser_dialog` / `browser_vault`（后者填密码，secret 不进对话）。
- `timeout_s` 默认 300、最大 1800；会话级浏览器（每 session 一个 Chromium），`$BH_AGENT_WORKSPACE` 跨调用保留文件，可「分批 append 到文件最后聚合」。
- 截图在原生视觉模型上直接附到工具结果；纯文本模型走 `page_info()`/`js()` 文本优先。
- 工程约束：`browser_exec` 执行模型写的 Python，因此**只对有 terminal 工具集的会话开放**。

### 4.4 渐进式披露评估（Hermes）

| 机制 | 有无 | 说明 |
|---|---|---|
| DOM 处理 | 本地无 | 抽取在厂商侧（Firecrawl/Tavily/Exa/Parallel/Perplexity）；Perplexity 还只给「相关片段 + …省略标记」 |
| 目录 / 大纲 | 无（但有 `outline` 的等价物？无） | —— |

## 6. 设计启示（要不要跟、跟哪一家）

1. **「给多少」有三种正当答案，取决于你要的是什么**
   - 要**低 token、面向问题**：ZCode 式二级模型提炼。代价：原文不可复现、引用不可校验（provider 换模型即变）、多一次模型调用且失败要单独归类（`ProcessingFailed`）。
   - 要**可复现、可引用**：dsh 式原文 + 硬上限。代价：超限即丢，模型只能换 URL 重抓（重复下载）。
   - 要**可复现 + 可续读**：Hermes 式落盘 + 页脚给 `read_file`。代价：磁盘、路径可见性（远程后端要 `to_agent_visible_cache_path`）、多一次往返。

2. **渐进式披露的两种正交做法**（可叠加，Hermes 与我们的 WIP 各占一半）
   - **先目录后正文**：`outline` 只给标题 + 总字符数（我们 WIP 已做，`maxHeadings=60`）。成本最低，适合长文档/规范类页面。
   - **头+尾+中段落盘/分页**：Hermes 的 75/25 窗口 + 页脚。它解决的是「结论常在页尾」的现实问题，纯 head 截断会漏掉 FAQ、价格表、结论段。
   - 最稳的组合：默认 `outline` 或 head 页 → 页脚提示「可用 cursor 续读 / 可换 outline」→ 模型自己决定读哪段。

3. **截断必须是「可诊断的失败」，不是「看起来成功的短文」**
   三家都给了固定标记与下一步动作（换更具体 URL / read_file / cursor）。我们 WIP 更进一步：**拒绝非法续读**（格式不匹配、内容已变）而不是拼接错位文本——这是比三家都严格的点，值得保留并写进 code_map。

4. **上限该不该是模型参数**
   dsh 明确把结果数/超时设成部署配置（防成本抖动）；我们与 Hermes 把 `max_response_chars`/`char_limit` 开放给模型（灵活，但需要下限夹取：Hermes 2000 下限，我们 `Clamp(1, 200_000)`——**我们下限 1 会让页脚/状态行挤占正文，建议抬到 2,000 与 Hermes 对齐**）。

5. **别把「浏览器」当「取正文」的默认解**
   Hermes 自己也写「简单检索优先 web_search/web_extract，只有需要交互才用 browser」；dsh 直接把 interactive browsing 划到包族之外。我们已有 browser 工具，路由描述里应保持同样的分流，避免模型为了读一篇文章去开浏览器。
