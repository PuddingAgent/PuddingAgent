# 会话加载优化阶段F浏览器冒烟

## 1 环境与方法

- 临时新 Core（非 Desktop/dev-up 实例）监听 `http://127.0.0.1:5000`，加载真实 `D:\data`（3.12M 事件），内部端点 `Pudding__ControllerEndpoint=http://127.0.0.1:5000`，Heartbeat 阈值 600s 防自动回合。
- Core 产物含前端 **6.9.3**（`wwwroot/admin`）。
- Playwright `@playwright/test` Chromium headless（1440×900），登录 API 取 JWT 注入 `localStorage.pudding_token`，直接打开 `/admin/chat`；每次新 context，5 次样本（6.9.2）+ 2 次（6.9.3）。
- 指标：DOMContentLoaded、README 消息容器可见、正文文本可读（`加载更多历史消息`）、FCP、静态传输字节、请求 URL 类型、非 404 失败。

## 2 结果

### 2.1 6.9.2（5 样本）

| 指标 | min | p50 | max |
|---|---:|---:|---:|
| DOMContentLoaded | 141ms | 146ms | 168ms |
| 消息容器可见 | 638ms | 693ms | 716ms |
| 正文可读 | 923ms | 961ms | 1116ms |
| FCP | 32ms | 40ms | 68ms |
| 静态传输 | 2.41MB | — | 2.41MB |

### 2.2 6.9.3（2 样本）

`正文可读 948ms / 1,161ms`；`DOMContentLoaded 131/167ms`；`消息容器 704/726ms`；badge `v6.9.3+dirty · 118920e`。

### 2.3 网络路径（关键验收项）

- 旧 `/api/workspaces/.../conversation`：**0 次**（已不再由前端首屏调用）。
- 新 `/conversation-open`：1–2 次（StrictMode/双 store 重挂载时可能顺序 2 次，无并发在途）。
- 正文分段 `/messages/{id}/content`：9–18 次（快照长正文自动读取）。
- `/bootstrap?messageLimit=1`：仍 **1 次**（SSE 游标准备在快照就绪前回退）。
- 非 404 失败：0；仅有用户头像 `user-avatars/*.png` 404（既有）。

## 3 判定

| 门禁 | 结果 |
|---|---|
| 首屏不再拉旧 `/conversation` | ✅ 0 请求 |
| WebView2/Core Ready→正文可读 p95 ≤800ms | ❌ Chromium 冒烟 p50≈0.96s、max≈1.16s；不是 WebView2，但已超目标 |
| 同 key 打开最多 1 个在途 | ✅（顺序可能 2 次；改后并发仍单飞） |
| 首屏数据/请求收敛 | ⚠️ 仍有 1 次 bootstrap + 9–18 次正文分段；需要“预览+显式展开” |
| badge/loaded identity 可对齐 | ❌ badge 为 `+dirty`（共享工作树其他 WIP），且短哈希与最终 HEAD 不一致；正式部署/预检不能通过 |
| 两段式外部重启 smoke | ❌ 未执行（外部控制器职责） |

## 4 结论与遗留

### 4.1 更正（2026-10-18 10:53，前端 6.9.4 显式展开）

长正文改为「预览 + `#pudding-expand-*` 链接」后，同一冒烟脚本 2 次样本：

| 指标 | 结果 |
|---|---|
| 首屏 `/content` 自动请求 | **1 次**（此前 9–18 次） |
| 点击“展开全文” | 1 次 `/content`；本地预算内立即更新，剩余 6 个长消息仍为预览 |
| 首内容可读 | 875ms / 982ms |
| 消息容器可见 | 649/687ms |
| 旧 `/conversation` | 0 次 |
| bootstrap | 仍 1 次 |

长正文请求膨胀已消除；`bootstrap`、`conversation-open` 顺序重复（本次样本 3 次）与正式部署门禁仍未解决。

- **D2c1/D2c3 的统一快照路径已在真实浏览器上生效**：旧 `/conversation` 不再被调用，正文可读约 0.95–1.16s。
- 距离阶段 F 达标仍有三个具体差距：
  1. 长正文自动分段请求过多（9–18 次）；应改为预览 + 显式展开（Plan §5.4/§7.3）。
  2. `/bootstrap?messageLimit=1` 的一次游标准备仍在；需“先快照后开流”或 bootstrap 返回快照游标。
  3. 正式部署被共享脏工作树阻塞：需清理/隔离工作树后重打前端 + Core，执行 `verify-external-deploy-identity.ps1 -ArtifactRoot ... -ExpectedCommit ...`（artifact + live）并核对 badge；随后由外部控制器重启做两段式 smoke。
- 以上差距未隐藏；不做“只加缓存/只隐藏骨架”的达标声明。
