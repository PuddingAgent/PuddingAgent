# 2026-10-22 摘要截断归因与压缩现场记录

`db16d13d4c6b406b9eebbcb1d7640a1a`，2026-10-22 10:25:42 +08:00。

## 归因与边界

上一实现用最终摘要容量直接充当生成硬上限。即使提示要求只用一半容量，模型也可能超过目标；
生成被截断后立即返回 Fatal，丢弃 FinishReason 和 Usage，而上层只剩 summary_rejected。
因此，规划正确仍可能稳定阻断长会话，且日志不足以区分网络失败、生成截断、容量拒绝或持久提交拒绝。

修复按四个阶段处理：规划候选 → 完整摘要生成 → 真实体积验收 → 原子持久提交。
最终摘要预算保持原值；生成预算至多为其两倍且不超过已配置模型输出上限。
截断或超额先从同一完整源重新精简，仍失败则拆分完整源并归并所有子摘要。
最多 64 次调用、4 层恢复；非输出上限的 incomplete、空输出和传输错误不作这种重试。
任何被截断输出都不参与后续输入、checkpoint 或覆盖事务；所有调用继续逐次计费。

## 诊断与现场

`CompactionSummaryResult` 将逐次尝试与稳定失败码带到调用方。
每次记录 call/stage/part/depth/regeneration、输入哈希/体积、真实 FinishReason、provider usage、
本地摘要计量、decision 和耗时；ReasoningTokens 为 nullable，不把缺失值伪装为零，也不重复计费。
Gateway 同时保存实际配置及 finish_reason，供跨层核对。

独立 `CompactionDiagnosticJournal` 保存本地 JSONL：plan、发送前 request、返回后 attempt、outcome/interrupted。
所有记录通过 compactionId 和 invocationId 关联。错误报告携带现场相对路径与 capture_complete。
文件每案 8 MiB、最新 32 案、最长 7 天；限额标记显式写出，写入/脱敏失败不改变业务结果。
KeyVault 脱敏按每条记录一次批量执行，避免逐字段查询解密数据库；本地文本不包含请求头或完整配置对象。

现场属于脱敏诊断资料，不承诺逐字重放：被识别的敏感内容会被替换，图片仅保存 artifact 引用，
plan 的 reasoning/continuation 仅保留指纹相关信息；模型分段引用中的文本按同样规则脱敏。
操作入口见[诊断手册](../08_how_debuge/12-案例-平台与会话.md)。
