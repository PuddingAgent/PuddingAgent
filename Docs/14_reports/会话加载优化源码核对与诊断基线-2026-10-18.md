## 2 原诊断的关键测量

| 项目 | 原诊断结果 | 使用边界 |
|---|---|---|
| Core 启动至 Ready | 4,401ms | Core 日志阶段时间，不等于页面可读时间 |
| 事件量 | 全表 3,120,332，本会话 1,818,705 | 本次未重新计数 |
| `/conversation` | 5.5–6.6s，初始出现两次并发 | 同一 Core 复测，不代表每次打开都恰好 6 秒骨架 |
| 三个事件子查询 | message 1,644.8ms；Turn terminal 1,839.0ms；root terminal 1,719.3ms | 查询计划仅按 conversation_id 缩小范围，再过滤；合计约 5.2s |
| knownCursor | 14ms，HTTP 304 | 仅证明该次条件请求快，不证明游标覆盖快照的语义完整 |
| 最近历史消息 API | 13–47ms，约 47KB | 说明正文读取可快于全投影 |
| bootstrap，messageLimit=1 | 439ms，261KB | 消息条数不能约束所有附加状态体积 |
| 子代理状态 | 404KB × 2，之后持续轮询 | 需要缩小合同并统一请求 owner |
| SessionChunkBackfill | Ready 同秒开始，持续 52.3s | 存在争抢窗口；争抢的单独贡献尚未隔离测量 |
| 无头 Edge | FCP 40–44ms，首个可交互画面约 0.8–1.0s | 热缓存复测；不同观测点与骨架链路推断不能混成同一条精确时间线 |

原诊断没有在真实 WebView2 内记录骨架出现和消失的完整区间。`isRefreshing → historyLoading → Skeleton` 由源码链路支持，但真实 WebView2 的优化前后差值仍需实测。索引后 `/conversation <200ms` 是原报告预测，不是本报告验证结果。

## 3 源码核对

| 位置 | 已核对行为 | 对方案的影响 |
|---|---|---|
| [AgentConversationProjectionService](../../Source/PuddingPlatform/Services/AgentChat/AgentConversationProjectionService.cs)，`GetConversationAsync` | 最多 60 个消息候选，去重后最多 20 条；关联事件查询没有同等数量边界 | 不再把问题泛称为“消息全部加载”；根因是关联工作量未界定 |

| [SessionEventStreamService](../../Source/PuddingPlatform/Services/SessionEventStreamService.cs) | 先订阅，冻结 replay/drain 上界，每批 256 事件 | 避免追赶不断增长的 head；仍需总事件/字节/时间预算 |
| [SessionEventsController](../../Source/PuddingPlatform/Controllers/Api/SessionEventsController.cs) | bootstrap 最多等投影 500ms；除 messages 外还取事件/子代理状态 | 合并首屏服务并建立总 payload 预算 |
| [SessionStateManager](../../Source/PuddingPlatform/Services/SessionStateManager.cs)，`GetSubAgentsAsync` | GET 路径先 reconcile，再取全部关联记录、所有运行分组及 Token 聚合 | 读取与修复分责，摘要和归档详情分开 |
| [chatClientStore](../../Source/PuddingPlatformAdmin/src/pages/chat/client/chatClientStore.ts) | selectAgent 有 selectionVersion/缓存，但首次请求不传 knownCursor；先 await 保存缓存再发布 fresh；后台同步有独立 in-flight 标志 | 统一选择/校正请求；发布内容不能被缓存 I/O 阻塞 |
| [agentChatApi](../../Source/PuddingPlatformAdmin/src/pages/chat/client/agentChatApi.ts) | 已支持 knownCursor、304；明细已支持 signal/timeout | 扩展现有适配，不再叠加另一套请求框架 |
| [useTurnSurfaceStore](../../Source/PuddingPlatformAdmin/src/pages/chat/hooks/useTurnSurfaceStore.ts)、[detailHydrationScheduler](../../Source/PuddingPlatformAdmin/src/pages/chat/runtime/detailHydrationScheduler.ts) | 可见 Turn 调度、并发限制、取消、失败分类已有实现 | 复用，工作单元从整条消息改为明细页 |
| [useSessionEventProjection](../../Source/PuddingPlatformAdmin/src/pages/chat/hooks/useSessionEventProjection.ts)、[chat/index.tsx](../../Source/PuddingPlatformAdmin/src/pages/chat/index.tsx) | projection-owned 主会话只消费子代理事实；Agent 同步按活动/静止使用 1.2/5 秒间隔 | 不能未接主消息 SSE 就删除轮询；必须统一 canonical 合并 owner |
| [SessionChunkBackfillService](../../Source/PuddingRuntime/Services/SessionChunkBackfillService.cs) | 先 Task.Yield；RunAsync 从 lastId=0 开始，已有键集页、已索引跳过和 Delay | 修复断点持久化与更新检测；只延迟启动不够 |
| [PlatformDbContext](../../Source/PuddingPlatform/Data/PlatformDbContext.cs)、[StorageMaintenanceQueries](../../Source/PuddingHost/Storage/StorageMaintenanceQueries.cs) | 模型现有 conversation/sequence、eventId、turn/type 等索引；维护层有重复索引映射 | 最小索引集应匹配最终读路径，去重复用维护设施 |
