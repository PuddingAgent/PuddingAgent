# 浏览器自动化：G1–G11 门禁 → 证据对账

**怎么读**：每行给出①设计文档里该门禁的通过标准（摘要）、②**进程内实现**、③**本轮清点出的自动化证据**
（括号内为该测试类的用例数，来自 `[TestMethod]`/`[Fact]` 计数）、④**只能真机/外部判定**的部分、⑤对应 smoke 清单项。
第五列是**唯一的验收入口**：进程内证据不等于通过，外部观察才作数（两段式验收）。

## 本轮对账的发现

1. **G2 的清单覆盖不足（已修）**：设计给了四项标准（同 context 非目标页拒绝 / 撤销·切目标·**跨 frame 身份**拒绝 /
   **子代理不得扩大父授权** / **建关页无残留**），而 smoke 清单 S-02 只登记了两项。
   现已补齐为四项，并加上自动化覆盖声明（`BrowserPageGrant* / ReadOnlyDelegationTests`，覆盖门禁验证类真实存在）。
2. **其余十条都同时具备**：进程内实现 + 至少一个自动化证据类 + 真机缺口**已登记在清单项**里。
3. **"驱动调用数=0"这类计数型标准**在进程内只能断言**被调用方的调用次数**（如 `BrowserControlAuthorityTests`），
   真机上的"CDP 实际发出次数"仍需外部复核 —— 已在 G1/G2 行注明。

| 父子**不并存**同页写租约、同页两子代理不并发写 | `ParentAndChildCannotHoldTheSamePageWriteLease`、`TwoChildrenCannotWriteTheSamePageConcurrently` |
| 只读可并行、写入按页串行 | `ReadObservationsRunInParallel`、`WritesArePerPageAndIdempotentForTheSameHolder` |
| 取消/接管/超时**回收许可**（且可区分） | `EndingOrTimingOutADelegationReturnsTheLeaseToTheParent`、`TakeoverOrRevocationInvalidatesBothParentAndChild`、`TimeoutCancelAndTakeoverAreDistinguishableInTheReleaseRecord` |
| 父结果默认 ≤2 KiB、**不含整页**、超限指向 Artifact | `TheParentConclusionBudgetIsBoundedByDesign`、`AnOversizedConclusionIsTruncatedOnACharacterBoundaryAndPointsAtTheArtifact`、`TruncationWithoutAnArtifactIsStillExplicit` |
| 注入工具须覆盖任务所需、写任务须有 navigate/interact | `InjectedToolsMustCoverTheTask`、`WriteCapableDelegationsMustHaveNavigateAndInteract`、`AReadOnlyBrowserTaskRequiresSnapshotAndInjectsTheRealToolIds`、`AWriteCapableTaskAlsoRequiresNavigateAndInteract` |
| 子代理授权不得超父、不得借用 | `AChildScopeCannotExceedItsParent`、`SubAgent_Cannot_Borrow_Its_Parents_Grant` |
| **真机观察步骤** | S-10：让父代理委派一个子代理，确认子代理**真的发现并调用** `browser_*`（不是"父能发现"就推断）；同时观察同页写租约不并存、取消/接管/超时后许可确实回收 |

## §6.1 预算数字对账：**四处与文档不一致**（登记，未擅自改行为）

设计 §6.1 写的是"内部扫描预算**初值拟为** 10,000 节点/深度 64/250ms；分页缓存拟为 8 个 extraction snapshot/页、
每页累计 2 MiB、TTL 60 秒；容量和到期都有明确原因码"。逐条对到代码：

|---|---|---|
| 扫描 **10,000 节点** | `DesktopSnapshotOptions.DefaultMaxNodes = 5_000`（硬上限 `MaxMaxNodes = 50_000`），`Source/Pudding.Contracts/Desktop/SnapshotContracts.cs:9` | ❌ **不一致**（且无注释说明为何取 5000） |
| 扫描 **深度 64** | 构造默认 `maxDepth = 24`（同文件 `:26`） | ❌ **不一致** |
| 扫描 **250ms 时间门限** | 浏览器/快照路径**没有**该门限（全仓库 250 只出现在无关测试） | ❌ **未实现** |
| 分页缓存 **8 快照/页 + 2 MiB/页 + TTL 60s** | **未实现**：改用**无状态游标** `{kind}:{index}`（实现在 LocateCursor），另有一个每页 2 条的**阅读基线**用于 diff（`BrowserReadingBaselineStore(capacityPerPage: 2)`）——语义与"分页缓存"不同 | ⚠️ **另一种设计**（游标不依赖服务端缓存，值得作为改法记录） |
| `incomplete_scan` 与 `output_budget` **不混淆** | 两者都在代码里且有区分：`BrowserSnapshotTool.cs:315/370/371`、`BrowserReadingFormat.cs:88`、`BrowserToolContracts.cs:67-68` | ✅ 符合 |

② 或产品明确"按文档数字实现"。

### §6.1 各模式输出预算：四条一致，**full 模式缺输出预算**

| mode | 文档预算 | 代码 | 判定 |
|---|---|---|---|
| outline（默认） | 50 条 / 4,096 UTF-8 字节 | 工具参数默认 limit=50、max_bytes=4096 | ✅ |
