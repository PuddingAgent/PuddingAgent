# Core 能力通道启动修复验收

## 原因与复现

`CapabilityChannelPreflight.ExpectedAddress` 使用 `\\.\pipe\<name>`，真实 Kestrel 的地址列表则包含 `http://pipe:/<name>`。REST 与 Named Pipe 都已启动，预检仍抛异常，Core 在 Ready 信号之前退出；连续失败使 Desktop 进入 CircuitOpen。真实监听器回归测试在修复前报告能力端点缺失，地址列表同时显示 REST 和对应管道，证明是预检格式误判。

Desktop 将 stdout/stderr 按 UTF-8 读取，但子进程没有固定输出编码，中文启动日志受 Windows 默认代码页影响。入口在任何输出之前设置无 BOM UTF-8。
