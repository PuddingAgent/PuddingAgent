# 按住说话与快捷键交互验收

## 已部署行为

用户选择「按住说话、松开发送」。新版本为 **v6.19.0 · 0149fe6 · 2026-11-16 21:44**，没有 `+dirty`；真实桌面窗口已显示该版本与「按住说话」入口。

- 按住麦克风按钮，松开后自动等待最终识别，再提交一次，不需要另点发送。
- 聊天页按住 **Ctrl+Shift+Space**，松开空格发送；输入区按住**鼠标中键**，松开发送。没有注册系统全局快捷键。
- Esc、右键、失焦、切会话和指针取消会取消录音；短于 250 ms 的误触不发送。已进入 HTTP 提交阶段的请求沿用普通消息的提交语义，不承诺通过取消录音撤回。
- 下拉选项保留「转写到草稿（修改后发送）」；空转写、识别失败或取消不自动发送旧草稿，提交失败保留文字。
- AudioWorklet 授权后立即采集，ASR 建连期间有界暂存开头音频并小步排空。初始化未完成就松开也会结束采集，等待连接、音频排空和最终转写；取消会释放整个生命周期。

自动提交复用既有发送/排队链路及执行偏好、附件入口，未引入服务商分支；Core 语音协议与凭据没有改动。

## 验证

先独立验证录音/手势模块 7/7，再接入 composer。最终 **11 套 77/77** 前端测试通过，TypeScript、干净源码 pnpm 构建及包体积门禁通过。

覆盖初始化中松开、重复按键/结果不重复提交、取消最终排空、鼠标两种入口、空转写不误发原稿、提交失败保留文字、原草稿与手动编辑、切会话、IME，以及原 ASR/TTS 回归。

实际部署页面使用 Edge 模拟麦克风和百炼公开示例音频，ASR 真实调用当前 Qwen 服务。仅拦截 canonical 聊天提交接口并返回验收响应，**没有将测试内容投递给真实 Agent**；因此此次验证的是输入到提交边界的流程，不另行宣称新的 Agent 回复端到端验收。

| 场景 | 松开前 | 最终结果 |
|---|---|---|
| 麦克风按钮按住/松开 | 零提交，文字实时出现 | 单次提交，保留执行偏好，草稿清空 |
| Ctrl+Shift+Space | 零提交，文字实时出现 | 单次提交，保留执行偏好，草稿清空 |
| 输入区鼠标中键 | 零提交，文字实时出现 | 单次提交，保留执行偏好，草稿清空 |
| 按住后 Esc 取消 | 零提交 | 仍为零提交，精确恢复原稿 |
| 提交返回模拟 HTTP 500 | 零提交 | 只尝试一次，最终 12 字仍在草稿中 |

各成功案例识别后的提交包含测试原稿前缀及最终文字；临时转写未直接提交。UI 图像核验了录音状态、取消按钮、音量、实时预览和「松开发送」按钮，截图仅截取公开测试输入区。
