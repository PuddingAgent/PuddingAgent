# Agent 浏览器控制架构与实现审阅（2026-10-18）

## 1. 审阅结论与证据边界

**一期尚未完成，剩余工作不能概括为“唯一未完成是外部真机验收”。** 用户反馈 Agent 尚不能控制浏览器；静态调用链也存在需要修改实现的缺口。已有八工具、DOM/CDP 驱动、协议、回执、纯规则与测试是可复用资产，不应全部推倒，但它们不能证明真实 Agent 的完整产品链已经可用。

审阅起点 HEAD `7194163`（此前用户材料绑定 `cfaaea2`）。工作树同时有其他任务的 Chat/API 改动；本次只编辑浏览器设计、ADR、索引和日志，不把他方 WIP 当作浏览器证据。核对的是实际文件与调用点，未运行 PuddingDesktop、未调用真实模型、未更改运行配置或数据，未重新执行 2124 条测试。因此本文的生产缺口是**静态代码审阅结论**，下列反例序列是待补的测试规格，不冒充本轮真机实测。

审阅范围：AgentTools → Host DI/路由/代理 → Bridge client/dispatcher/controller 与 channel 组合根 → DesktopService/生命周期/authority → WebView2 映射/driver；另核对候选 Authorization 组件、截图发布、子代理端口和相关文档。

## 2. 需要修正的实现与设计

### F1 · P1：默认配置缺少完整截图执行路径

`BrowserWorkspaceController.HandlePageScreenshotAsync` 在 `_capabilityExecutor` 为空时明确拒绝截图；WinUI 给它的委托来自 `_coordinator.CapabilityExecutor`，后者只返回 `_capabilityChannel?.Service`。通道默认关闭时，本地执行器也不存在。**不是再增加 screenshot 工具类就能修复。**

证据：[controller:882](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs:882)、[WinUI 装配:1369](../../Source/PuddingDesktop/MainWindow.xaml.cs:1369)、[执行器属性与关闭分支:31](../../Source/PuddingDesktop/Hosting/DesktopApplicationCoordinator.Capability.cs:31)。

修订：执行器在浏览器工作区生命周期内构造；截图与普通页面操作共用它。反例：真实产品组合根、channel 关闭、已选页时，截图产生有效图片且 driver 恰好调用一次。

### F2 · P1：Bridge 接管/暂停拒绝只读，且未统一执行前复检

`DispatchCoreAsync` 在识别命令前就检查 `IsPaused/IsUserTakeover` 并返回；`ReadOnlyPageCommands` 只参与后面的 grant 范围计算，无法让读取越过这两道门。文档“接管后只读可用”不能推广到默认 Bridge。

同方法随后直接调用 `_handler.ExecuteAsync`；普通 `page.interact` 在 controller 内调用 `page.ClickAsync/FillAsync`。Bridge 此段没有调用 `BrowserAdmissionAdapter.Admit/Revalidate`。共享 `_lifecycle` 只证明状态来源相同，不能证明队列内复检、写串行和逐步 guard 相同。用户 UI 控制器另有取消操作逻辑，也不等价于执行前复检原票据。

证据：[dispatcher:183](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandDispatcher.cs:183)、[controller:1100](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs:1100)。

修订：页面命令统一进入传输无关执行器。配对测试必须在默认 Bridge 路径断言“接管时 snapshot 成功、fill 被阻止”，并覆盖“入队后接管再恢复，旧写仍不得执行”。

### F3 · P1：桥在线放行与页面撤权设计相冲突

`HasSufficientPageGrant` 在 `ConnectionGeneration.IsLive` 时无条件返回 true，先于查询调用者 grant；用户选中的页也直接返回 true。Bridge 对带显式 PageId 的请求使用这个判据，controller 再按其页面字典解析。这样，**对该浏览器 controller 已持有的页面**，不能从代码推出“切走目标/撤销 grant 后不可继续访问旧页”或“无关任务不能使用该页”。这不是对系统全部浏览器或 Workbench 的跨界利用结论。

证据：[lifecycle:92](../../Source/Pudding.DesktopService/BrowserPageLifecycle.cs:92)、[Bridge 页面授权:401](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandDispatcher.cs:401)、[显式 PageId 优先:1286](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs:1286)。

修订：在线是活性，目标会话是权限；删除“在线即覆盖所有页”的过渡逻辑须与新会话接入同一切片完成。不能只收紧这一个方法、又让默认路径没有任何授权来源。

### F4 · P1：输入模式和滚动语义在 Bridge 映射中丢失

`BrowserInteractTool` 把 `InputMode` 放入 typed request；`BridgeBrowserCapabilitySurface.ApplyInteractionAsync` 却以空 `ClickOptions/FillOptions/TypeOptions` 调用 runtime，滚动只传 DeltaX/DeltaY。`RemoteBrowserPage` 再构造旧的 `PageInteractArguments`，controller 仍使用默认 DOM options。最后工具用请求中的 `inputMode` 填 `InputBackend`。

因此支持范围内的 native click/fill 经这条路径可实际执行 DOM，却回报 native；滚动目标/locator 也没有完整保留。下层 `RemoteBrowserPage.ScrollAsync` 会透传 ScrollTarget，不代表上层 surface 已传给它。

证据：[Bridge 映射:730](../../Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs:730)、[远程参数:264](../../Source/PuddingHost/BrowserBridge/RemoteBrowserPage.cs:264)、[工具报告后端:432](../../Source/PuddingBrowser.AgentTools/BrowserInteractTool.cs:432)、[driver 依据 options 选路径:427](../../Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs:427)。

修订：统一 typed request 进入执行器；回执返回实际后端，支持前明确拒绝 native。增加字段哨兵测试，不能只测工具参数序列化。

### F5 · P1：动作前观察被用于动作后回执，operationId 重新生成

Bridge surface 在动作前 `QueryAsync`，动作后用该 handle 的缓存 Info 构建 element；`ToElementRef` 也没有搬运 Value/SelectedValues。工具随后将此 element 交给 `BrowserInteractionReceipt.Build` 作为观察结果，并生成新的 Guid。该路径不能证明 `expect_value` 观察了写入后值，回执 ID 也不能直接关联原传输操作。

证据：[前置查询与结果:616](../../Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs:616)、[元素投影:463](../../Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs:463)、[回执构造:369](../../Source/PuddingBrowser.AgentTools/BrowserInteractTool.cs:369)。

修订：保留原 operationId；驱动动作原子返回观察，或明确 `dispatched/unverified` 后由 Agent 新快照验证。不得靠动作后重查旧 Locator 修补。

### F6 · P1：默认 Bridge 的子代理委派与八工具目录未闭合

Host 注册的 `IBrowserDelegationLifecycle` 只从 CapabilityBroker 取得 session；`RequestChildGrantAsync` 在无 session 时拒绝。因此默认关闭通道时不能从组件正向测试推导出子代理可用。`BrowserAgentToolIds.All`/`BrowserAgentCapabilityIds.All` 仍为七项，截图仅在写委派 required 列表中追加，和 Read 观察能力不一致。

证据：[Host 注册:66](../../Source/PuddingHost/BrowserBridge/BrowserBridgeServiceCollectionExtensions.cs:66)、[无会话拒绝:63](../../Source/PuddingHost/BrowserBridge/HostBrowserDelegationLifecycle.cs:63)、[工具全集](../../Source/PuddingBrowser.AgentTools/BrowserAgentToolIds.cs)、[委派清单](../../Source/PuddingBrowser.AgentTools/BrowserDelegationTasks.cs)。

修订：八工具目录本期统一；先验收主 Agent，子代理列为明确后续能力，不能声称已在默认产品路径完成。

### F7 · P1：候选简化授权组件尚未接入，且不能直接替换

全量检索 `Source/`、`Tests/` 的 C#/csproj，`AgentTargetSessionAuthority` 和 Authorization 引用仅在组件与其测试工程出现，未见生产消费者。旧设计和代码地图把它的存在与旧权威接线混在一起，造成“已经简化”的错觉。

候选实现还有两个可由代码推演的反例：

1. `Authorize(write A) → BeginUserControl → EndUserControl → Revalidate(A)`：接管只翻转布尔值，未推进票据写世代；恢复后检查可以再次通过。现有测试只检查**接管仍为 true 时**，不能覆盖恢复后旧写复活。
2. `Authorize(A) → Complete(A) → Authorize(B) → 再次 Complete(A)`：票据没有唯一操作标识，Complete 只比较 SessionId/ControlEpoch，可能把同会话 B 的占用清空；Revalidate 也不检查票据仍在途。

证据：[Begin/EndUserControl:181](../../Source/PuddingBrowser.Authorization/AgentTargetSessionAuthority.cs:181)、[Revalidate/Complete:267](../../Source/PuddingBrowser.Authorization/AgentTargetSessionAuthority.cs:267)、[票据形状](../../Source/PuddingBrowser.Authorization/AgentTargetAuthorization.cs)、[现有接管测试:219](../../Source/PuddingBrowser.AuthorizationTests/AgentTargetSessionAuthorityTests.cs:219)。以上序列为静态推演，本轮未执行新增测试。

修订：独立修组件再接入；保留读票据时，用独立写世代使旧写失效，并引入精确操作身份/占用匹配。简化不等于删掉不变量。

### F8 · P2：快照材料混合“目标、代码资产、生产支持与验收”

原文 R1–R5“完成”及 R6“唯一未完成外部阶段”，无法覆盖 F1–F7。原文还把迁移期双路由概括成配置级“不回退”，实际 Host 是每次调用优先选择活动 channel、否则 Bridge；禁止的是一次已尝试操作跨传输重试。两者必须分清。

另一个反向例子：WebView2 子项目地图仍称 WinUI 原生输入/截图均 unsupported，但当前 controller 已注入 `AutomationDriverPolicy`，driver 通过抽象策略执行。不能只依据旧注释或 code_map 断言 WinUI 完全没实现。

修订：架构页只描述当前结构与支持限制；历史测试/进度摘录放本报告，当前状态放日志；新设计与 ADR 清楚标注目标。旧“完成”改读为“已有组件及对应历史测试”，不再证明产品完成。
