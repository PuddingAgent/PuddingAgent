# 运行时插件验收

## 结论与范围

源码与发布包具备“编写 → 独立编译 → 导入 → 授权加载 → Agent 调用 → 卸载”的闭环。首次安装基础设施仍需要部署新版 Core；之后插件变更无需重启 Core。本次未部署到产品实例，未宣称真实模型或产品界面验收完成。

支持工具和 `tool.result.advice` 建议 Hook；不提供任意 Core 服务替换、渠道注册或前端组件贡献。实例按 workspace / 实际执行 Agent / session 隔离；卸载撤销贡献并回收 Worker，已安装包保留。Windows Worker 是故障隔离边界，不是恶意代码沙箱。

## 可复核的证据

| 检查 | 结果 | 判据 |
|---|---|---|
| 独立 Runtime 测试 | 22 / 22 | 路径逃逸、内容篡改、错误清单、无执行许可、错误作用域、过期代调用、初始化失败被拒绝；并发卸载不能晚到发布 |
| Windows 真实 Worker 集成 | 6 / 6 | 真实 DLL / IPC，超时、崩溃、输出超限、初始化失败、子进程回收及 Core 回调 |
| 宿主 Agent 循环集成 | 6 / 6 | Buffered / Streaming 均在一次 dispatch 内完成 load → echo → unload → final；下一轮模型 schema 增加/移除工具，模型看到真实中文结果 |
| 既有工具/权限/曝光回归 | 207 / 207 | 元数据目录、包安装、工具注册、发现、曝光、工作区与 Firewall 回归 |
| 前端插件管理 | 5 / 5 | 正确提交目标会话与授权；StopFailed 不显示成功；既有 viewModel 测试 |
| 前端 TypeScript / 生产构建 | 通过 | 类型检查、生产打包及 chat bundle budget |
| 独立 SDK 示例 | 构建通过 | 仅用已构建 SDK/Contracts DLL 编译，无 Core / Host / Runtime 引用 |
| Core Release 发布 | 通过 | 包含 Worker、SDK、示例源码、AUTHORING.md 与前端 6.13.0 静态资源 |
| 编译期引用负向探针 | 预期失败 | 给叶子组件注入 Host 引用后，项目边界门禁拒绝编译 |

宿主闭环使用真实 `AgentExecutionService`、工具注册/执行服务、独立 Windows Worker 和真实插件 DLL；模型客户端为按轮断言 schema 的脚本替身。正向闭环的 Firewall 使用明确允许的测试替身；权限拒绝由单独测试使用真实 Firewall 验证。这些测试证明运行时编排与工具执行，不证明任意模型能够自行写出正确插件。

同一次宿主 dispatch 内进程 ID 不变；卸载后旧代函数不能再调用，重载产生新代函数名。失败加载不回传成功 ToolResult。插件建议追加到原始输出后，原来的成功/失败、错误内容与退出码保持不变。

复跑入口：`TestScripts/test-pudding-tool-plugins.ps1 -RunId <唯一运行标识>`。当前证据位于仓库忽略目录：

- `.work/plugins/20261104-final/`：独立组件、真实 Worker、宿主闭环、SDK 示例的最终构建和测试日志。
- 同目录 `published-worker-tests.log` / `published-host-tests.log`：将上述集成测试改为使用 Release 发布包内的 Worker，6 + 6 项再次通过；不重复计入测试总数。
- `.work/plugins/20261104-runtime/test-runtime-regression-mtp.log`：207 项回归。
- `.work/plugins/20261104-runtime/frontend-tests.log`、`frontend-tsc-final.log`、`frontend-build.log`：前端验证。
- `.work/plugins/20261104-runtime/publish-core-final.log`：最终发布；候选包在同目录 `core-release/`。

## 环境问题与未完成项

1. 本机 VSTest 测试宿主因父进程退出回调的 Win32 AccessDenied 中断，测试尚未运行。改用项目支持的 Microsoft Testing Platform 可执行入口；既有测试的系统 Temp 写入受限，测试子进程改用仓库 `.work` 隔离临时目录。没有把该启动失败算作测试通过。
2. 前端第一次构建使用了不受配置支持的输出环境变量，写入默认 dist；并行后端复制遇到旧资源消失。完成前端构建后，冻结产物并通过 `PuddingAdminDistPath` 发布，最终成功。正确前端输出变量是 `PUDDING_ADMIN_OUTPUT_PATH`。
3. 发布包曾在隔离 DataRoot 启动并报告 ready，但 Console 的默认绑定覆盖了 `--urls`，实际监听 8080。已按 PID 和可执行文件路径停止该隔离实例；没有使用或修改产品数据。随后用明确 Loopback 配置重新启动隔离实例的命令被自动审批拒绝，返回 `blocked by policy`，未继续绕过。
4. 因此管理员 HTTP 上传/加载/卸载的端到端实测、浏览器界面视觉核对以及产品内真实 Agent smoke **未验证**。前端测试与宿主集成不能替代这些验收。
5. 本次检查时产品 Desktop/Core 已停止；保持原停止状态。未改现有 Agent 授权或自动加载插件，未执行 git commit / push。
6. 全 Docs 链接检查发现 29 个既有失效目标、0 个失效锚点；本次新增文档未引入其中的失效链接。不能声称全仓文档门禁已经通过。

## 使用与后续验收

见[运行时工具插件](../04_tools_and_skills/运行时工具插件.md)。现有 Agent 需要启用 `plugin_import` / `plugin_load`，具备写文件、编译和本地代码执行所需的原有权限。先读取 `plugin_catalog` 返回的 SDK 与示例路径，再制作自己的 ZIP；无需让 Agent 修改 Core 源码。

部署后应在测试会话中完成：实际模型自行修改示例 → 编译打包 → 导入和加载 → 调用并核对输出 → 卸载 → 核对旧工具不可用、Worker 退出、Core PID 未变。同时检查管理页面版本 6.13.0、包/实例状态和失败诊断；仅得到 Active/Unloaded 才分别确认加载/卸载完成。
