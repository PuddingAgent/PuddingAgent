## 6 父链与幂等关键断言摘要

- **确定性账户 ID**：`goal:<id>` / `work:<id>` / `task:<id>`；Store 校验 AccountId 必须等于按 Identity kind/id 生成的值（A05 的非法 ID-kind 配对为 `budget.account_invalid`）；前缀 + RootId 超过 128、含逗号/控制字符/首尾空白一律 `budget.account_invalid`，不 Trim、不截断（A10）。
- **祖先路径**：根返回 `Ancestors.IsDefault == false` 的空数组；子账户返回 root→immediate parent 且不含自身（A01/A02/A03）；Ancestors 永远从持久父链读取，不接受调用方自报（`BudgetAccountDescriptor` 删除了 `ParentWorkId`，只保留 `ParentAccountId`）。
- **单事务原子绑定**：`EnsureAccountBindingAsync` 在一个 DbContext/事务内读取既有账户与所需父链，校验后创建或复用；直接声明的父不存在 → `budget.account_missing`，更深断链/环/自引用/>64 层 → `budget.path_invalid`（A04/A09）；祖先或叶已取消 → `budget.cancelled`，且不清理取消标记（A14）。
- **逐字段冲突**：既有账户的 AccountId、ParentAccountId、Identity 五项、Limits 五项（decimal 数值比较，null≠0）、CostUnit、Mode 任一不同 → `budget.conflict`，不更新、不放宽、不静默复用（A05/A06/A07）；Enforced 收 Legacy/Shadow 也 Conflict，升级仍只由原有 `SetEnforcementModeAsync` 负责。
- **父链元数据**：新子/已有叶与祖先 Workspace 或 Mode 不一致 → `budget.conflict`；CostUnit 不一致 → `budget.currency_mismatch`；不同 Agent/Session 的合法委派成功（A08）。
- **幂等与持久值**：相同定义重复调用同账户 ID、同祖先，第二次 `Created=false` 且返回持久值；`Calls/Cost/Unknown/Revision` 不重置（A01/A13）。
- **并发权威在数据库**：A11/A12 用两个独立 Store + 各自独立连接的同一 SQLite 文件，确定性 `Barrier` 同时进入；A11 恰好一个 `Created=true`，A12 恰一成功、另一 `budget.conflict`，胜出记录字段完整无混合。进程内 `_gate` 仅优化；唯一键竞争与 BUSY/LOCKED 最多三次新事务复读，耗尽保留异常。
- **Runtime 边界**：B01/B02/B03/B04 的账户由真实 mapper 创建，`LlmAttemptBudget` 的 AccountId/Ancestors/Identity/CostUnit 全部取自 mapper 结果（只有 attempt/model/price 是 fixture）；root 与 leaf 各记一次 Calls，settle 后 `ActiveAttempts=0`、`ReservedCost=0`，缺 usage 保持 Unknown 不退款，根 `MaxCalls=1` 耗尽后新子账户不能绕过，持久取消根后 provider 0 次且无新增预留。
