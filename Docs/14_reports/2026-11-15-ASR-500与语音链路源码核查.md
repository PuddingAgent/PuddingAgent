# ASR 500 与语音链路源码核查

## 结论

用户提供的 `errorId=517eb4249437` 对应北京时间 **2026-11-15 12:27:21.944**，路径 `/api/voice/asr/recognize`。直接原因已经由同一请求日志确认：**百炼返回 403，供应商 code 为 `AllocationQuota.FreeTierOnly`，免费额度耗尽且启用了仅免费额度模式；该异常未作业务映射，被包装为通用 HTTP 500。**

这不证明 Key 无效、模型不存在或 WAV 格式错误。解除额度限制后是否还存在协议/格式错误，需要新的真实请求验证。

## 日志证据

运行时 DataRoot 的相对位置：

| 文件 | 位置 | 脱敏证据 |
|---|---|---|
| `logs/error/pudding-error-20261115_006.log` | 51–56 行 | 相同 errorId、路径；HttpRequestException: 403；调用栈经过 DashScopeAsrProvider.PostAsync → RecognizeAsync → VoiceController.Recognize |
| `logs/system/pudding-20261115_017.log` | 2973 行 | 相同时间与请求 trace；`[DashScopeAsr] API error 403`；code=`AllocationQuota.FreeTierOnly`，提示免费额度耗尽，需由控制台处理资金或仅免费模式 |

[`TraceableExceptionMiddleware`](../../Source/PuddingPlatform/Middleware/TraceableExceptionMiddleware.cs) 对未处理异常统一返回内部错误，解释了浏览器看到 500 而供应商实际是 403 的差异。日志未复制完整请求、音频、密钥或用户聊天内容。

## 当前语音配置快照

仅提取非密钥字段：默认 TTS Provider 为 dashscope，模型 `qwen3-tts-flash`；默认 ASR 为 dashscope，模型 `qwen3-asr-flash`。Endpoint host 为 `dashscope.aliyuncs.com`，所查两条默认模型配置使用 multimodal-generation 路径。

用户指定的 `qwen-audio-3.1-asr-flash-message` 尚未作为默认 ASR。其官方 [WebSocket 接口](https://help.aliyun.com/zh/model-studio/qwen-asr-message-websocket-api) 与当前 HTTP async polling 实现不同，不能仅改配置里的模型名完成适配。
