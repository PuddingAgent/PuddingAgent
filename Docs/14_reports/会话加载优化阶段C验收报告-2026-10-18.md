# 会话加载优化阶段C验收报告

## 1 结论

阶段 C（持久读模型与查询）按方案 §11 的交付要求完成并通过门禁：

- 读模型两表 + 投影事务：消息物化、`conversation_turn_summaries`/`conversation_read_state`、`conversation_projection_checkpoints` **同一 SQLite 事务**提交；失败全回滚、重放不重复累计。
- 统一打开/历史/过程分页查询：同一读事务固定 C/H、SQL 有界预览、键集游标、预算器截断、ETag、`syncing/partial` 明确语义；Agent 主会话身份解析只做有界点查。
- **百万事件查询门禁通过**：1.82M 单会话事件 fixture 上 `open p95=1.6ms`、`history p95=0.9ms`、`process p95=1.9ms`，EXPLAIN 均为索引等值/范围收敛，**无会话级全表扫描**。
- 纯组件 193 用例、阶段 C 定向测试、Host composition 均通过；全量 PlatformTests 仅 2 个既有的 `--artifacts-path` 环境敏感失败（与本阶段无关）。

## 3 百万事件查询门禁（阶段 C 关键证据）

命令（默认测试套件跳过该重测试，显式 ENV 运行）：

```powershell
$env:PUDDING_QUERY_GATE='1'
dotnet test Source\PuddingPlatformTests\PuddingPlatformTests.csproj `
  --artifacts-path temp\build\c3b --nologo -p:CollectCoverage=false `
  --filter "FullyQualifiedName~ConversationOpenQueryPerformanceGateTests"
```

fixture：`conversation_events` 1,820,000 行（单会话），`ChatMessages` 50、Turn 摘要 30、read_state/head/checkpoint 与新鲜 DB 的模型索引；事件插入 10.5s。

| 查询 | n | min | p50 | **p95** | max | 通过线 |
|---|---|---|---|---|---|---|
| `OpenAsync`（20 条首屏） | 20 | 1.0ms | 1.2ms | **1.6ms** | 10.6ms | ≤200ms |
| `GetHistoryPageAsync`（20 条） | 20 | 0.5ms | 0.5ms | **0.9ms** | 1.3ms | ≤300ms |
| `GetProcessPageAsync`（100 项） | 20 | 1.5ms | 1.7ms | **1.9ms** | 2.2ms | ≤250ms |

查询计划（`temp/test-out/query-gate-plans.txt`）：

```text
[process-candidates] SEARCH conversation_events USING INDEX IX_conversation_events_conversation_id_sequence (conversation_id=? AND sequence<?)
[event-head-max]     SEARCH conversation_events USING COVERING INDEX IX_conversation_events_conversation_id_sequence (conversation_id=?)
[messages]           SEARCH ChatMessages USING COVERING INDEX IX_ChatMessages_SessionId_CreatedAt (SessionId=?)
```

结论：打开首屏不再依赖会话事件总量；消息页与过程页按实体键/序号的**有界窗口**读取，未出现会话级扫描。

## 4 语义与安全边界

- **C/H 一致**：`snapshotCursor = projection checkpoint`，`eventHead >= snapshotCursor`；旧库 read_state 缺失且 checkpoint>0 ⇒ `Partial`；checkpoint=0 且 head>0 ⇒ `syncing + retryAfter`。
- **分页**：历史 `(createdAt, messageId)` 键集 + 稳定身份；过程 canonical sequence 键集 + `throughSequence` 上界；非法/缺失/跨会话游标返回稳定 400 code；空展示页仍返回可前进扫描边界。
- **预算**：消息 preview ≤8 KiB/条、页 ≤128 KiB；过程单条 ≤16 KiB、页 ≤256 KiB、候选扫描 ≤400、payload 片段 ≤64 KiB；均由纯组件预算器统一执行。
- **身份**：redirect → Agent Manifest `MainSessionId` → canonical `FindMainAsync`；只做点查，不再加载整个工作区会话列表；workspace/owner 不匹配 fail closed。
- **只读**：GET 不重放事件、不补建摘要、不修复运行状态；失败不伪造空会话/零计数。
- **原子写**：消息 + 摘要 + read_state + checkpoint 同事务；token usage/catalog/索引在 commit 后执行，单副作用失败不回滚投影。

## 6 遗留与风险（诚实边界）

1. **真实 `D:\data` 尚未迁移**：两张读模型小表会在下次 Core 启动时由 bootstrapper 幂等创建；`conversation_events` 两条索引（约 182 万/312 万行）仍需**显式维护窗口**创建并记录耗时/磁盘（方案 §11.2）。本次门禁在新鲜 fixture 上验证了模型索引与查询形状，未在生产库建索引。
2. **前端未切换**：旧 `/api/workspaces/{ws}/agents/{agentId}/conversation` 仍是前端首屏路径；本阶段新增 v2 统一打开与分页端点，阶段 D 切换前端并退役旧入口/在线全量摘要路径。C3 完成不等于用户可感知加载优化落地。
3. **查询门禁默认不跑**：1.82M fixture 成本高，已用显式 ENV 运行并留存输出；CI 若要强制，应把它作为独立 gate 步骤而非默认单测。
4. **真实 WebView2/DataRoot 副本上的 p95** 未验证（方案 §10.1 的产品验收属阶段 F）；本次为查询层门禁。
5. 旧数据摘要初始化/`syncing` 的端到端（重启后首屏）需阶段 D/E 联测；读模型基线不强制全量重放。
