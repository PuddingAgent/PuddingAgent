# 浏览器工具验收测试报告（本地页截图 / jd.com 搜索袜子与加入购物车 / 工具效率压测）

**测试日期**：2026-10-19（本机）
**测试范围**：仅使用 `browser_*` 工具；本地验证页 `http://127.0.0.1:4717/ef2f253e/` 与 `https://www.jd.com`、`https://search.jd.com`、`https://cart.jd.com`。
**总体结论**：**修复后业务链路已打通**（本地页"填写→提交→读回执→三档截图→滚动后截图"全绿；jd.com 搜索→挑选→加入购物车成功，购物车 **35 → 36**）；**但工具层的可用性仍有 3 个硬瓶颈**：`interact` 的 `ref` 定位器不可用、`snapshot` 游标不前进、`screenshot` 存在"可见性门 + 预算门"双门。实测冗余约 **3.8 倍**（34 次调用 vs 最小充分路径 9 次）。

---

## 一、结论摘要

| 维度 | 结论 | 关键证据 |
|---|---|---|
业务链路（本地页） | ✅ 通过 | `locate(role)` → `fill` → `click` → `status="验证成功"`；截图 `png/original`、`jpeg/low`、滚动后 `png/low` 三次全部成功 |
业务链路（jd.com 加购） | ✅ 通过 | `购物车 35 → 36`；购物车页 `locate(text="袜子")` 命中 `京东京造【100%纯棉】男士袜子…黑色6双` |
工具稳定性（读类） | ✅ 良好 | `context` 5/5、`tabs` 4/4、`navigate` 3/3、`wait_for` 2/2 |
工具可用性（写类） | ❌ 不足 | `interact` 1/9（`ref` 路径 0/6）；`screenshot` 4/11；`snapshot` 返回 5/5 但**有效信息 0/5** |
效率 | ❌ 不足 | 购物任务 34 次 / 138s；最小充分路径 9 次 / 40–50s |

## 五、第 5 节专项：工具方便性与效率（重复实测）

### 5.1 测量口径

- **时间**：`T0 = 2026-10-19T05:25:00.714Z`、`T1 = 2026-10-19T05:25:37.623Z`（终端取时）⇒ 压测墙钟 **36.9s**。该值**含模型往返**，为**工具延迟上界**（平台不回传单次耗时）。
- **计数**：逐条工具回执，可复核。
- **载荷**：回执中的 `byteCount / bytes / outputWidth` 原值。

### 5.2 压测设计（11 轮 / 17 次调用）

| 轮 | 调用 | 结果 | 载荷 |
|---|---|---|---|
| R1 | `context.list` + `tabs.list`（并行） | ✅✅ | 3 页面，<1KB |
| R2 | 同上（重跑） | ✅✅ | 与 R1 **逐字一致** |
| R3 | `snapshot(outline, limit=30)` | ✅ 截断 | `2452 B / 29 行`，`nodeCount=4095` |
| R4 | `snapshot(cursor=lines:29@…, max_bytes=2500)` | ✅ 但**与 R3 完全相同** | `2452 B`，`nextCursor` 不变 |
| R5 | `snapshot(同 cursor, max_bytes=8000)` | ✅ 仍**从头开始** | `4256 B / 50 行` |
| R6 | `locate(text=京东京造)` ×2 并行 | ✅✅ 完全一致 | `count=9`，~2.4KB |
| R7 | `interact(click, ref)` ×2 并行 | ❌❌ | 同一错误（见 D1） |
| R8 | `screenshot(low, 搜索页)` ×2 并行 | ❌ 可见性拒绝 / ❌ 停滞守卫 | — |
| R9 | `screenshot(low, 购物车页=可见)` | ❌ 预算超限 | `93120 B > 40960 B` |
| R10 | `screenshot(low + region 600×200)` | ✅ | **19443 B**，`512×171` |
| R11 | `wait_for(body)` / `wait_for(不存在)` | ✅ / ✅（`timedOut:true`） | — |

**墙钟**：36.9s ÷ 11 轮 = **3.35s/轮**；÷ 17 次 = **2.17s/次**。

### 5.3 成功率表（跨两轮累计）

| 工具 | 成功/尝试 | 成功率 | 判定 |
|---|---|---|---|
| `browser_context` | 5/5 | 100% | ✅ 稳定、廉价 |
| `browser_tabs` | 4/4 | 100% | ✅ 稳定 |
| `browser_navigate` | 3/3 | 100% | ✅ 稳定 |
| `browser_wait_for` | 2/2 | 100% | ✅ **设计最好**：不存在选择器走 `timedOut:true` 而非报错 |
| `browser_locate` | 9/12 | 75% | ⚠️ 成功路径结果确定性 100% 复现；3 次失败均为 CSS 选择器猜错（`.p-name`、`a[href*=item.jd.com]` 返回 0） |
| `browser_snapshot` | 5/5 返回，**0/5 有效** | 0%（信息） | ❌ 全部 `output_budget` 截断；游标不前进 |
| `browser_screenshot` | 4/11 | 36% | ❌ 三种失败模式（D3/D4） |
| `browser_interact` | 1/9 | 11% | ❌ `ref` 6/6 失败；`css` 多匹配失败；仅 **XPath** 成功 |

### 5.4 缺陷清单（含本轮新增）

| 级别 | 编号 | 缺陷 | 原始证据 | 影响 |
|---|---|---|---|---|
| **P0** | D1 | `browser_interact` 未暴露/未转发 `expected_page_version`，`locate` 产出的 `ref` **完全不能用于交互** | `A reference locator must carry the page version the reference came from. (Parameter 'expectedPageVersion')` ×6（`pageVersion`/`expectedPageVersion`/`page_version` 三种写法均无效） | locate 与 interact 契约断裂＝"能看见、点不着" |
| **P0** | D2 | `snapshot` 的 `cursor` **不生效**（每次从第 1 行重来） | R3 `nextCursor=lines:29@…` → R4 传该 cursor 返回**同一 29 行、同一 cursor**；R5 加大 `max_bytes` 后返回第 1~50 行，`nextCursor=lines:50@…` | `nodeCount=4095` 的页面**永远读不到后半段**，而商品标题正在后半段 |
| **P0** | D3 | `screenshot` 受"UI 当前选中标签"强制门控 | 非可见页 → `Screenshot requires a visible browser surface; open the tool panel and select this browser tab.`；切到可见页后通过 | 多标签作业下，Agent **无工具入口可切换可见标签** |
| **P1** | D4 | `detail=low` 硬预算（40 KiB）无降级 | `LowDetailBudgetExceeded: baseline 512px/40960 bytes but the payload is 93120 bytes`（购物车）；搜索页 `228114 B` 同样超限 | 真实电商页 `low` **3/3 不可用**；唯一出路是 `region crop`（实测 `19443 B` 通过） |
| **P1** | D5 | CSS **多匹配**点击报 `ui surface failed (BrowserOperationException)`，**不告知是多匹配** | `[class*='addCart']` 命中 5 个 → 失败；对照 `css(#key)` 能清晰报 `no element matches css(#key)` | 误导排查方向；迫使用户改写 XPath 才能指定第一个 |
| **P1** | D6 | 相同调用重复触发停滞守卫 `execution_stalled` | 第 2 个并行相同调用 → `the same canonical tool call failed twice with an unchanged result` | 误伤并行压测与只读重试；建议对**幂等只读**调用豁免 |
| **P2** | D7 | `locate` 不返回 `boundingBox`、不暴露 `href/属性` | `fields:["boundingBox"]` → `null`；`a[href*='item.jd.com']` 返回 0 | 形成"要便宜就裁剪 → 要裁剪要坐标 → 要坐标要先看贵的图"闭环死锁；拿不到 SKU |
| **P2** | D8 | 真实站点 `snapshot` 可访问名缺失 + `domText` 扫描不完整 | 商品卡片 `link` 无 `name`；`domText` `truncationReason: incomplete_scan` | 只能靠截图"用眼睛看"，成本最高 |

### 5.5 效率判定

| 指标 | 实测值 |
|---|---|
| 单轮往返 | **3.35s**（含模型） |
| 只读信息类调用 | **便宜**：`context/tabs/locate/wait_for` 均 **< 2.5 KB** |
| 信息获取类调用 | **昂贵**：全页截图 **245 KB**（搜索页）/ **93 KB**（购物车） |
| locate → interact 链路 | **断裂**：`ref` 在 `interact` 里 **0/6 可用** |
| 完成"点第 1 个加购按钮" | 需 **8 次**尝试（4 次 ref、1 次 text、1 次多匹配 css、1 次空 css），最后由 **XPath** 成功 |

**换算到业务任务**：34 次调用 / 138s；最小充分路径（`tabs.new → navigate → screenshot → locate → interact(xpath) → locate(购物车) → tabs.new(cart) → locate → screenshot`）= **9 次 / 40–50s** ⇒ 冗余 **3.8×**，其中 7 次失败全部集中在 `interact`。

### 5.6 修复收益预估（按优先级）

| 优先级 | 修复项 | 可量化收益 |
|---|---|---|
| P0-a | `interact` 支持 `expected_page_version`（或让 `ref` 自带版本由工具核对） | 交互成功率 **11% → 预计 ≥90%**；单次点击 **8 次 → 1 次** |
| P0-b | `snapshot` 的 `cursor` 真正从断点续读 | snapshot 可用性 **0% → 可读全页**；省掉为看标题而付的 **245 KB/次** |
| P0-c | `screenshot` 允许按 `pageId` 直接采集（或提供 `tabs.activate`） | 截图成功率 **36% → 接近 100%** |
| P1 | `locate` 返回 `boundingBox`／提供 `nth`/`index` | 解开"裁剪↔坐标"死锁，`low` 预算问题自然消失 |
| P2 | 幂等只读调用豁免 `execution_stalled`；多匹配返回 `matched N elements, use index` | 少 2 类误导性报错 |

**修完 P0-a/b/c 的预期**：同一购物任务 **9 次调用 / 40–50s / 不依赖大图**，并可腾出预算**打开详情页核规格**——这正是本次因工具不稳而被迫放弃、也最该补的一步。

## 七、复现步骤

1. `browser_context(list)` 取 `contextId`；`browser_tabs(list)` 确认页面；
2. `browser_tabs(new)` 建空白页（**先不传 URL**）；
3. `browser_navigate(goto, 目标 URL)`；`browser_snapshot(outline)` 取 `pageVersion`；
4. 元素操作：优先 `locate(kind=role, value, name)`；点击 `interact` 时**必须用 `kind=xpath` 并带索引 `(…)[1]`**——`ref` 当前不可用（D1）；
5. 截图：`detail=original` 可用但昂贵；`detail=low` 在密集页面必超预算（D4），改用 `scope=region` + 小区域；
6. 验证加购：`locate(text="购物车")` 读导航计数变化（35 → 36），再开 `cart.jd.com` 用 `locate(text=关键词)` 回读商品名。

## 八、结论

1. **业务能力已可用**：本地页全流程 + jd.com 搜索加购均成功，且证据链完整（版本号、操作 ID、计数变化、商品名回读、截图归档）。
2. **工具层仍不可工程化**：`interact`/`snapshot`/`screenshot` 三处 P0 缺陷使同一任务开销放大 **3.8 倍**，并直接导致"没做详情页规格核对"这一方法缺陷。
3. **优先级明确**：先修 D1/D2/D3（各对应一个可量化的成功率跳变），再修 D4/D5/D6，最后补 D7/D8。
