# 浏览器工具验收测试报告（jd.com 搜索袜子与加入购物车）

**测试时间**：2026-10-19 12:26–12:32（本机）
**测试目标**：只用 `browser_*` 工具，打开 jd.com → 搜索「袜子」→ 通过视觉理解挑选一款 → 加入购物车。
**总体结论**：**未达成**。前半段（打开站点、搜索、快照、滚动）**全部通过**；「视觉挑选」与「加入购物车」分别被两项**能力层缺陷**阻断，因此**未做任何加购动作，购物车数量未变（35 件）**。

## 四、阻塞归因（均已定位到代码行）

### B1 截图：Desktop 侧 ui surface 异常（未修）

- 调用链：`browser_screenshot` → Core 桥 `page.screenshot` → Desktop `BrowserRuntimeDesktopSurface.ScreenshotAsync` → `Page.captureScreenshot`
- 现象：在 Desktop 侧抛 `InvalidOperationException`，被工具层归一化为 `browser_capability_failed`
- 影响：**视觉挑选、坐标点击（依赖 observation）全部不可用**

### B2 定位：kind 线名不匹配（已修，**未部署**）

- 发送端：`Source/PuddingHost/BrowserBridge/RemoteBrowserPage.cs` 的 `ToDescriptor` 原用 `locator.Kind.ToString()`，送出**枚举名** `"Role"` / `"AltText"`
- 接收端：`Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandAdapter.cs` 的 `TryMapLocator` 用 `DesktopLocatorKindWire.TryParse`，按**线名**（`role` / `alt-text`，真源 `Source/Pudding.Contracts/Desktop/LocateContracts.cs`）逐字严格解析、不猜测不回退
- 修复：`d38b6cd`（改经 `DesktopLocatorKindWire` 输出线名，映射失败抛错不退化）+ `8adffb7`（将 `ToDescriptor` 改为 `internal`，新增 10 例 Theory **直接断言线上描述符**；31/31 通过，变异取红 10/10）
- **仍未生效的原因**：部署的 `core\PuddingHost.dll` mtime `09:50:10` **早于**修复提交时间 `10:25:23`。11:05、11:57 两次进程重启**都没有重编 Core**。

## 五、安全决策：拒绝盲点坐标点击（重要）

`browser_interact` 支持 `x` / `y` 坐标点击，理论上可绕过定位器。**本次验收主动不采用**，理由：

1. 无截图 ⇒ 没有 `observationId` 作为坐标来源，坐标只能靠猜；
2. 京东商品卡片上相邻控件包含「加入购物车」**与**「立即购买 / 结算」类高强度动作，盲点**可能直接触发下单**；
3. 一旦误触，属于**不可回滚的用户资产变更**（真实订单），远超本次测试授权范围。

⇒ 宁可判定“未达成”，不做可能造成实际购买的动作。

## 七、复现步骤

1. `browser_context(action=list)` → 记下 `contextId`
2. `browser_tabs(action=list)` 确认无页面
3. `browser_tabs(action=new, context_id=<ctx>)`（**不传 URL**）
4. `browser_navigate(action=goto, page_id=<page>, url=https://www.jd.com)`
5. `browser_navigate(action=goto, page_id=<page>, url=https://search.jd.com/Search?keyword=袜子&enc=utf-8)`
6. `browser_snapshot(mode=outline)` / `browser_snapshot(mode=full, fields=[domText])`
7. `browser_interact(action=scroll, scroll_target=page, delta_y=2000)`（预期成功）
8. `browser_screenshot(...)`（预期失败 B1）
9. `browser_locate` / `browser_interact(click + locator)`（预期失败 B2）

## 八、解除条件与验证判据

| 目标 | 动作 | 通过判据（可观测） |
|---|---|---|
| 元素定位/点击可用 | 重编 Core + 重启（或部署 `temp\build\core-locator\bin\PuddingAgent\debug`） | `browser_locate(kind=role)` 返回元素而非 `locator kind … is not registered` |
| 截图可用 | 修 `BrowserRuntimeDesktopSurface.ScreenshotAsync` 的 ui surface 异常 | `browser_screenshot` 返回 `observationId` + 像素尺寸 |
| 视觉挑选 | 截图成功后再用 `image_reader` 读该产物 | 能给出具体商品名 / 价格 / 主图特征 |

**部署新鲜度判据（本次教训）**：比对「进程实际加载目录内目标 DLL 的 mtime」与「修复 commit 时间」；**不能**用 `Get-Process` 的 StartTime 单独判断，**也不能**用「DLL 里是否含某类型名字符串」判断（类型名会出现在被引用程序集 TypeRef 中，旧 DLL 同样命中）。

## 九、结论

- 浏览器工具链的**建页 / 导航 / 快照 / 滚动**已达到可用状态（本报告 T1–T4、T6 均为真实回执）；
- **截图**与**元素定位**两项能力缺陷使「视觉挑选 + 加购」在当前构建上**不可完成**；
- 其中定位缺陷**已修复但未部署**，属工程流程问题（重启未重编），不是新的代码缺陷；
- 本报告所有判定均来自工具原始回执，未做任何推测性补全；未产生任何购物车/订单副作用。
