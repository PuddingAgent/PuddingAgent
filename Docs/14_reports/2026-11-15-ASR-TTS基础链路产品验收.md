# ASR TTS 基础链路产品验收

## 验收结论与范围

本轮基础能力状态为 **`in-product-functional-complete`**：指定 Qwen ASR 已真实转写成功；现有 Qwen3 TTS 的完整 WAV、增量 PCM、播放与取消已打通；录音结果进入聊天草稿。产品 Core 由进程外 Guardian 构建部署并达到 `healthy`，后续功能探针访问的是新 Core 提供的已部署 Web UI。

ASR 为「录音结束后转写」，最长 120 秒；不是持续边录边转写。浏览器端验收使用 Edge 模拟麦克风与公开音频，未覆盖用户物理麦克风、实际扬声器听感和 Desktop WebView2 特有权限提示。未宣称完成崩溃恢复、退出回收等 Desktop 生命周期验收。

## 实现与组件边界

- 独立 `PuddingSpeech` 只依赖 BCL，无宿主/Runtime/Platform 引用。`AllowedProjectReferences` 的反向引用红探针实际报 `PUDDING001`。独立测试通过后才登记解决方案与宿主引用。
- ASR 使用 **`qwen-audio-3.1-asr-flash-message`**。适配器完成 WebSocket run-task、task-started、音频发送、finish-task、最终转写排空与取消清理。
- TTS 沿用 **`qwen3-tts-flash`**，HTTP 使用 `ResponseHeadersRead` 增量读取 SSE。真实验收发现首块 WAV 容器头，补充独立解析测试后再接入 Runtime；现在对业务输出统一 PCM16 单声道 24 kHz。
- 业务层通过现有统一转录/合成服务调用；供应商、模型协议与凭据保留在底层工厂/适配器。浏览器语音请求不指定服务商或模型。
- 录音使用 AudioWorklet 生成真实 16 kHz、单声道 PCM WAV，提供计时、音量、完成、取消与重试；最终文字合入草稿，保留录音期间新增的输入。切会话/取消后的迟到回调不再回填。
- 消息朗读与语音面板共用全局单一播放任务；停止会同时中止网络和关闭音频播放，切会话清理任务，错误可见。
- 供应商错误映射为脱敏 `voice_*` code 与 errorId。额度/凭据错误不再伪装应用登录错误；无效音频返回 415，流式失败有明确终态。

代码提交顺序：`5be318d` 独立组件 → `6dbed44` 宿主/前端接入 → `bf44c34` 独立流式容器修正 → `219650e` Runtime 容器修正接入。
