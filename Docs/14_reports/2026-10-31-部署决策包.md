# 部署决策包（一句话决策用）

> 用途：让 owner 看一屏就能决定「部署 / 不部署」，不必翻长报告。

## 1. 现状（现场实测，2026-10-31 06:50）

```
进程              PuddingAgent  pid 68832
进程启动时间      2026-10-30 21:42:30
线上 DLL mtime    2026-10-29 23:16:44
仓库 HEAD         现行 master（2026-10-31）
```

**结论：线上二进制比仓库落后约 1.5 天。** 而且 DLL 的 mtime 早于进程启动时间 —— 说明前天那次重启**只是重启，没有重新构建**。

> 这条是「重启 ≠ 部署」的实证：进程是新的，代码是旧的。

## 4. 执行方式（需 owner 授权）

```
dotnet build Source\PuddingAgent\PuddingAgent.csproj -c Debug
# 确认 DLL mtime 已更新
bootstrap_reboot(target=core)
```

⚠️ 构建时宿主会锁 `bin\Debug\net10.0\*.dll`（MSB3027/MSB3021）⇒ 通常需先停 Core 或由重启脚本完成构建。

## 5. 部署后验收清单（逐项可判）

| 项 | 验收证据 |
|---|---|
| 进程加载新产物 | DLL mtime > 部署时刻；`runtime_identity` 报告的 build 与 HEAD 一致 |
| Python 索引可用 | 索引一个含 `.py` 的 scope，`code_symbol_search` 能返回 Python 符号 |
| 全文过滤不再漏检 | 对含噪声的 scope 用 `file_ext=.cs` 检索，命中数 > 0 |
| partial 跨度 | `workspace_open` 打开含 partial 类型的文件，行范围覆盖全部声明 |
| 继承边 | `workspace_search` 关系面查某接口，能返回实现者 |
| 水位诚实 | 制造一次索引失败，`code_index_status` 显示 Behind 而非 current |

## 6. 回滚

```
git checkout <上一稳定 commit>  # 或保留当前 1273518 构建产物副本
bootstrap_reboot(target=core)
```

风险点：本次含**两个新程序集**（`PuddingDomain.Contracts` / `PuddingRetrieval.Contracts`），若部署目录未包含它们，启动会 `FileNotFoundException`。构建产物需确认这两个 DLL 存在。

## 7. 不部署也是一种选择

代码全部已提交并推送，工作树干净。停留在测试全绿状态不会有任何损失 —— 唯一代价是线上继续缺这 11 项修复。

## 附录：全仓 `slnx` 构建不通过（2026-10-31 07:53 实测）

```
dotnet build PuddingAgentNetwork.slnx -v q
→ 66 处 error：56 × MSB3027/MSB3021（文件锁）+ 10 × CS（编译错误）
```

### 56 个是环境噪音

`PuddingDesktop (pid 55468)` 正在运行，锁住 `temp\build\winui3\bin\PuddingDesktop\Debug\...\*.dll`，
`PuddingDesktop.csproj` 复制产物时重试 10 次后失败。这是「宿主在跑」的必然结果。

### 10 个是真编译错误（**预先存在**，与本次改动无关）

| 文件 | 错误 |
|---|---|
| `Source/Pudding.Rpc.IpcProbe/ProbeExecutor.cs:152` | CS8604（可空引用传入非空参数） |
| `Tests/PuddingHost.Tests/Storage/StorageMaintenanceServiceTests.cs:302` | CS7036（构造函数缺 `logger` 参数） |
| `Tests/PuddingHost.Tests/Storage/StorageManagementAdministrationTests.cs:408` | CS7036（同上） |

判定依据：这三个工程我本轮**一个文件都没碰**；错误性质（构造函数签名不匹配、可空性）与契约迁移的「命名空间/using」无关。它们说明 `StorageMaintenanceCoordinator` 加过参数后，这两处测试没跟着改。

### 对部署的含义

1. **全仓 build 不能作为部署门禁** —— 它有两个永远过不去的来源（运行中的 Desktop 锁、预先存在的测试工程编译错误）。
2. 部署应按**单工程链**构建，而不是 `slnx`。
3. 这也解释了本轮一直用 `dotnet test <单个 csproj>` 取证 —— 那是当前唯一可靠的验证口径。
