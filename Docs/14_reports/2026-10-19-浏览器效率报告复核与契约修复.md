# 浏览器效率报告复核与契约修复

依据为提交 `345564e` 的[测试报告](2026-10-19-浏览器工具验收测试报告.md)、当前生产源码及新增回归测试。原报告记录的购物车操作由原测试执行者提供，本轮没有重复购物、加购或下单；这些回执不替代本轮部署验证。

## 逐项判定

| 项 | 复核结果 | 处理与边界 |
|---|---|---|
| D1 ref 不能交互 | 确认。工具缺少来源版本；更直接的阻断是动作前 `RemoteBrowserPage.QueryAllAsync` 发 `page.locate` 不带版本，Desktop adapter 又固定构造 Unknown，触发报告中的原始异常 | interact/locate 暴露顶层 `expected_page_version`；ref 必填，过期不派发；wire 传正数版本，adapter 缺失时明确拒绝。实际生产者到消费者测试覆盖 |
| D2 snapshot 游标重复 | 确认。游标解析成功，outline/interactive 却将 Cursor=0 的 reading request 交给 Compose | 传入解析后的索引；两种模式连续读取全部行，检查无重复/缺行并到达终点。不能据此宣称扫描无限完整 |
| D3 无切换页签入口 | 不成立。`browser_tabs(action=activate)` 已存在并沿工作区所有者激活表面 | 当前工具区已展开时可以切页；折叠工具区仍遵循 ADR 的不抢焦点策略，截图拒绝是已知限制，尚未实现离屏采集 |
| D4 low 超过 40 KiB | 回执真实，是现行 `BrowserScreenshotTransfer` 的硬预算策略 | 本轮保留该限制；显式 JPEG/区域截图是可选路径，不保证复杂页必达预算。修改预算应另作设计决策，不以“降级”名义暗改 PNG 格式或 detail |
| D5 多匹配掩盖为内部异常 | 确认。驱动已有 browser_locator_ambiguous，通用服务异常兜底只保留类型 | Browser surface 将该明确的派发前拒绝映射为 InvalidRequest，给出多匹配与 `locator.nth` 提示；不泄露未知异常/页面原文，不自动选第一个 |
| D6 execution_stalled | 现行守卫在相同 canonical 调用连续得到相同失败后触发，成功结果清空该调用的失败记录 | 没有证据支持成功只读调用被此规则误伤。保留熔断；并发压测需与正常代理重试策略分开，不能对所有只读错误无限豁免 |
| D7 bbox / 属性 | bbox 确认被丢弃：DOM 与 Contracts 已提供，结果 adapter 却写死 null | 恢复 BoundingBox 四字段。`locator.nth` 已有；任意 href/属性扩展本轮未实现，CSS 零命中不能证明 href 不可读取 |
| D8 缺名 / incomplete_scan | 是可观察的输出限制，但报告没有对应 DOM 夹具，尚不能归因到单一实现错误 | 不能编造商品名。扫描上限与输出分页分开；后续需固定页面夹具验证 accessible name、图片链接、懒加载与局部 scope |

## 正确调用

从最新 snapshot/locate 返回取 `pageVersion` 和 ref，再调用：

```json
{"action":"click","context_id":"ctx","page_id":"page","expected_page_version":7,"locator":{"kind":"ref","value":"pTOKEN-v7-n3"}}
```

这不是把 ref 内的数字自行解析成当前版本；版本来自观察回执。缺失/过期先重新观察。多匹配可显式使用 `locator.nth: 0`，不要求改用 XPath。分页原样回传 `nextCursor`，页面版本变化则从新观察开始。

## 验证证据

新增测试先在旧实现取红：工具 6 项中 5 项失败（2 项游标不前进、3 项忽略缺失/错误版本）；Desktop adapter/结果投影 4 项全部失败，其中 ref 错误与实测异常一致。

修复后在 `--artifacts-path temp/build/recovery` 验证：

| 套件 | 结果 |
|---|---|
| AgentTools 全套 | 108 / 108 |
| Desktop adapter / result / workspace / executor route 定向 | 62 / 62 |
| DesktopSurface.Browser 全套 | 90 / 90 |
| Host RemoteBrowserRuntime / locator wire / Bridge surface 定向 | 95 / 95 |

总计 **355 通过，0 失败**。TRX 位于 `temp/test-out/browser-reading/`；构建有既有警告，本轮不据此声称全仓无警告。Host 测试将实际 RemoteBrowserPage 发出的 ref 请求交给真实 Desktop adapter，不只比对两份假 DTO。多匹配测试断言动作未执行、提示可用且原始敏感异常文本不外泄。

此处的自动测试结论是源码/组件证据。配套部署与进程内功能复验另记，不将当前运行进程视作已经加载本轮修改。

## 原报告的度量边界

- 36.9 秒含模型和并行调度；除以调用次数得到的 2.17 秒不是单次工具延迟分布，也不能作为具体请求的延迟上界。
- 34/9≈3.8 是实际调用数与估算最短路径的比值，9 次路径和 40–50 秒尚未同条件复测，不能作为已实现收益。
- “失败都在动作派发前”需按操作分别判定。截图预算拒绝发生在图像采集之后；它没有业务写副作用，但不能称未派发。
- 读类“100%”须注明范围：snapshot/screenshot/locate 也属读取，本身不在这组 100% 中。CSS 零命中与传输失败不能混算。
- `incomplete_scan`、可见性策略、40 KiB 预算、缺少属性投影，以及启动偏慢仍是未解决或待决策事项；本轮不宣称 D1–D8 全部消除。
