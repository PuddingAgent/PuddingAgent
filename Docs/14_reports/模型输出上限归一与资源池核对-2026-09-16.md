# 模型输出上限统一由资源池管理（2026-09-16）

## 事故与决策

dsh 会话 `8fd0f96f82224bc0a282b4626ea4e4f5`，Turn `5167ba9f942447be9d93a0d7d31c8c62`，Run `c34e49f063c4416894cdf386e0b2f23d`：第 5、6 轮均输出 4096 token，finish reason 为 length。第一轮额度全部用于思考，恢复轮正文仍被截断，最终报 `llm_output_truncated`。资源池模型配置原本是 384000，但实例 manifest 的 maxReplyTokens=4096 收紧了实际请求。

最终决定：单次模型输出上限只来自 `config/llm.providers.json` 的模型 `maxOutputTokens`。Agent、模板、角色绑定及 profile 均不再配置 maxReplyTokens。任务总预算、轮次、耗时和工具次数仍是独立的执行护栏。本次按用户明确要求修复配置权威来源，未增加截断重试次数或修改续写策略。

## 实现

- 删除 Agent 编辑抽屉、模板表单、前端类型和保存默认值中的最大回复字段。
- 删除 manifest、角色绑定、profile、DTO、文件读写、预制 Agent 模板和旧模板实体中的字段；保留历史数据库迁移。
- 删除 AgentRuntimeProfileResolver 和 AgentLLMConfigResolver 的额外 clamp；LlmProfileResolver 的解析结果使用模型 MaxOutputTokens。
- 旧 JSON 中的废弃字段不会参与解析；本机已原地清理，无兼容限额层。
