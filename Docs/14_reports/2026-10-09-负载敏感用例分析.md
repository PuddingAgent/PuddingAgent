# 负载敏感用例分析 + 交付脚本可选重试

## 一、现象（本会话记录）

| 轮次 | 中断的用例 | 隔离运行 |
|---|---|---|
| 89 / 92(3) | `PuddingHost.Tests.BrowserBridge.DesktopBrowserBridgeHandshakeTests.SecondConnection_CannotReplaceAwaitingHelloConnection` | **通过**（本轮连续 3 次全绿） |
| 92(1) | `PuddingHost.Tests.Hosting.DesktopConfigurationLoadingTests.LlmConfigurationLoad_DoesNotDeadlockOnDesktopSynchronizationContext` | **通过** |
| 92(2) | `PuddingDesktop.Tests.Browser.WebView2PresentationGateTests.HiddenSurface_ParksLateSdkFramesAndStopsObservingAfterDisposal` | **通过** |

共同点：**只在全量链满载运行时失败**，单独运行稳定通过。

## 二、一条可直接核对的代码事实

`Tests/PuddingHost.Tests/BrowserBridge/DesktopBrowserBridgeHandshakeTests.cs` 的第二个用例：

```csharp
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(2));
var close = await second.ReceiveAsync(buffer, cts.Token);   // 等待服务端以 PolicyViolation 关闭
```

**它只给服务端 2 秒**来"接受第二个连接 → 判定为替换 → 关闭它"。满载时这条路径的排队延迟超过 2 秒，
就表现为**取消**（我历次看到的失败时长恰为 2 s / 5 s 量级）。该断言要证明的是"第二个连接被拒绝"，
**不需要**这么紧的上界。

## 三、结论与建议（**未实施**，属他方子系统）

1. **把固定短超时改成宽松上界或等信号**：例如等一个服务端事件/日志，而不是死等 2 秒；
   死锁类用例（`LlmConfigurationLoad_DoesNotDeadlock…`）同理——"证明不死锁"不需要 2 秒。
2. **让重试计数可见**：若 CI 采用重试，应把"第几次才过"记录并展示，否则节奏问题会被静默吸收。
3. **按子系统分派排查**：Host（同步上下文/握手）与 Desktop（呈现门时序）是两个不同的 suspect。
4. **不要用"加超时"掩盖产品竞态**：目前证据支持"测试时限过紧"，但没有排除真实竞态；
   若在安静机器上仍可复现，则应升级为产品缺陷排查。

## 四、我这边做了**可选重试**（默认关闭，且绝不隐藏）

`TestScripts/delivery-manifest.ps1` 新增 `-RetryFailedSuites <n>`（默认 **0 = 完全关闭**）：

- 只有 TRX 里 `failed > 0` 的套件才重跑，最多 n 次；
- 重跑成功后 **TRX 改名为 `<suite>-retried.trx`** ⇒ 清单里的检查名变成 `…Tests-retried`，
  **读清单的人一眼能看到"这个结果是重试来的"**；
- 失败仍未被掩盖：重试也没过 ⇒ TRX 保留失败计数 ⇒ **清单照例拒绝产出**。

设计取舍（诚实说明）：这一步**确实**让"偶发失败"不再无条件阻塞交付，但代价是它削弱了"第一次就必须全绿"的强度
—— 因此默认关闭，且必须**显式传参**才启用；是否在外部验收里接受重试，应由验收方决定（我不替你决定）。

## 五、验证

| 项 | 结果 |
|---|---|
| 隔离运行（本轮） | Host 全量 **3/3 全绿**；handshake 用例单独运行通过 |
| 脚本语法与行为 | `-SkipTests` 快跑：参数解析正常、清单产出正常；脚本仍为**纯 ASCII**（0 个非 ASCII 字符） |
| 默认行为 | `-RetryFailedSuites` 缺省 0 ⇒ 与之前完全一致（无重试） |

## 六、已知边界（诚实登记）

- **未定位根因**：只给出"测试侧时限过紧"的**假设**与一条代码事实；未做线程/时序级分析。
- **未改他方测试**（仓库纪律：不代改他方内容），只提出建议。
- **未量化 flake 概率**：未做"满载下跑 N 次统计失败率"的测量（成本高且会影响其它工作）。
- **重试路径未在真实失败场景下演练**：本轮没遇到失败，`-RetryFailedSuites` 的代码路径**未被实际触发**过
  （登记为未验证；下次遇到失败时优先用它并记录结果）。
- **`-retried` 后缀会改变清单里的检查名**：这是有意的可见性设计，但下游若对检查名做精确匹配需知晓。
