# 会话加载优化阶段D端到端验证（临时 Core）

## 1 环境与方式

- 构建：`dotnet build Source/PuddingAgent/PuddingAgent.csproj --artifacts-path temp/build/deploy2`（0 error），产物包含前端 `6.9.0` 静态包（`wwwroot/admin/umi.*.js` 内可检索到 `6.9.0`）。
- 运行：临时 Core（非产品 Desktop/dev-up 实例）监听 `http://127.0.0.1:5199`，环境：
  - `PUDDING_DATA_ROOT=D:\\data`、`ConnectionStrings__Default=Data Source=D:\\data\\databases\\pudding_platform.db`；
  - `TaskAutoDispatch__Mode=disabled`（真实库 system.json 为 authoritative，但 GoalRuns 未开启，现行源码会拒绝启动；此覆盖仅为只读验证）；
  - `Heartbeat__GlobalIdleThresholdSeconds=300`（争取验证窗口）；
  - 登录 `admin/Admin@123` 获取 JWT。
- 数据：真实开发库 3,120,332 事件、单会话 1,820k 级事件；维护前备份见 §4。
- 目标 Agent：`default.global_general-assistant.6a8` → main session `206a9b48ec904ebb93e7541131fbb835`。

## 2 测量结果（30 次 API 样本）

| 端点 | min | p50 | **p95** | max | 说明 |
|---|---:|---:|---:|---:|---|
| 旧 `/api/workspaces/{ws}/agents/{id}/conversation` | 169.0ms | 383.7ms | **514.1ms** | 685.3ms | 响应含 20 条消息 + `activeRun=true`；优化前基线 5.5–6.6s |
| 新 `/api/workspaces/{ws}/agents/{id}/conversation-open` | 66.3ms | 76.8ms | **111.7ms** | 150.1ms | 满足阶段 C/D 打开 API p95 ≤200ms 预算 |

新快照字段：`conversationId=206a…`、`snapshotCursor=1,818,847`、`eventHead=1,818,848`、`initialization=2(Partial)`、`syncState=0(Ready)`、`messages=20`、`history.hasMore=true`、`representationTag=A918292CBE4D41C5`。

其他端点：

- `/history?limit=20`：20 条、`hasMore=true`，返回键集边界；
- `/process?limit=20`：20 项、`truncation=ItemLimit`、`hasMoreBefore=true`；
- `/messages/{id}/content`：totalBytes=5,161、内容 2,897 字符、`hasMore=false`（短消息全文）。

结论：旧入口查询收敛后已从 5.5–6.6s 降到约 **0.5s**（activeRun 在跑，仍包含旧活动快照成本）；统一打开在同样数据上 **111.7ms**，满足预算。旧入口仍高于 200ms 目标，后续由前端切换新快照 + 活动 Turn 终态物化（D2c3/D3c）解决。

## 3 验证中发现并修复的身份口径缺陷

- 现象：`conversation-open` 首次请求返回 **404 conversation_not_found**，而旧 `/conversation` 能返回数据。
- 根因：JWT 的 `ClaimTypes.Name` 是显示名 `Administrator`，会话 `OwnerUserId` 是 `admin`（归一为 `single-user`）；适配层 `OwnerUserId` 校验因此失败。旧投影之所以能解析，是它对 redirect/MainSessionId 候选**只校验 workspace、不校验 owner**。
- 修复：`ConversationOpenApiController` 与 `AgentChatApiController` 的 `ResolveOwnerUserId` 优先使用 `ClaimTypes.NameIdentifier`（sub=`admin`），缺失才回退 `Identity.Name`；身份解析仍校验 workspace/owner。
- 测试：`ConversationOpenApiControllerTests` 6/6（新增“显示名 Administrator + nameidentifier admin 应成功”），`PuddingWebApiTests.AgentChatApiControllerTests` 21/21。

## 4 副作用与回滚材料

- 索引维护前备份：`temp/test-out/pudding_platform-before-event-indexes-20261018-100940.db`（9.9GB，含维护前数据；索引为后续创建）。
- 临时 Core 首次启动创建了 `conversation_turn_summaries` / `conversation_read_state` 两张小表（预期行为），并因 idle heartbeat 触发了一次 Agent 回合（session 206a…，产生少量新事件）与 SessionChunkBackfill 索引扫描；发现后立即停止 Core，未做用户数据删除。
- 本次验证**未**启动产品 Desktop、未替换 `wwwroot/admin` 正式部署、未更改用户运行实例；`D:\data` 保留新索引与少量验证写入。

## 5 局限

1. 这是临时 Core 验证，不是 Desktop/WebView2 真实首屏；未测冷进程、冷 WebView2、真实滚动与渲染。
2. 测量包含 `activeRun=true`（旧路径活动快照）；空闲会话/终态后旧路径数值可能更低，但未单独测。
3. 新前端产物虽已构建进 Core 输出，但适配层在活动 Turn 未终态时仍回退旧投影；用户可感知路径要等正式部署 + D2c3/D3c。
4. `TaskAutoDispatch__Mode=disabled` 是验证环境覆盖；真实库 `system.json` 的 authoritative 配置与 GoalRuns 默认值不匹配，现行源码在真实库上启动会被 Options 校验拒绝，需单独修复（与本次加载优化无关但阻塞产品验收）。
5. 旧 `/conversation` p95 514ms 仍超 200ms 目标；不在本次验证中宣告达标。
