# 实时 ASR 边录边转写部署验收

## 结论

实时 ASR 已在新部署产品 Core 与其 Web UI 上完成基础功能验收。页面为 **`v6.18.0 · 9a1a12a · 2026-11-16 00:03`**，无 `+dirty`；Guardian 最终状态 `healthy`。真实 Qwen 调用和浏览器录音均在发送停止指令前出现文字，已验证停止后保留最终文字、取消后恢复原草稿。

交付顺序为 `84225a2` 实时组件 → `3d48a29` 异步失败/握手取消补强 → `9a1a12a` 宿主与前端接入。组件最终 25 项测试通过后，宿主组合根验证新增实时服务与凭证存储的真实 DI 解析。

业务代码依赖 `IStreamingSpeechRecognizer` / `RealtimeAsrSession`，由 `RealtimeAudioTranscriptionService` 根据默认路由解析能力。Qwen WebSocket 细节只在独立协议实现与 Runtime 适配器中；Controller 和浏览器不选择服务商或模型。无流式能力的适配器明确返回不可用，没有在业务层猜测供应商名称。

## 实时协议与交互

| 阶段 | 合同与行为 |
|---|---|
| 授权 | 登录 JWT 调用 `POST /api/voice/asr/ticket`，取得 30 秒、一次性凭证；不放进 URL |
| 连接 | `/api/voice/asr/stream` 的首个 WS 文本帧为 start、凭证、PCM/16000；浏览器必须同源；上游准备读取音频后返回 ready |
| 采集 | AudioWorklet 连续发送 PCM16、单声道、16 kHz 二进制块；最长 120 秒，不保存整段录音后才上传 |
| 回填 | transcript 含句 ID、当前句、是否确认、完整投影及确认文字；同一句替换更新，最终句去重，避免临时文字重复追加 |
| 停止 | flush 最后音频后发 finish，继续接收最终结果；只有 completed 才确认最终草稿，等待中仍能取消 |
| 取消 | 取消启动/录音/收尾，关闭麦克风与网络，移除本次语音区间，保留原稿和区域外键入；迟到回调受 generation 约束 |
| 失败 | 明确 failed/code/errorId；移除临时文字，保留已确认文字并显示重试；网络与音频队列均有积压上限 |

主输入框提供时长、音量、确认字数、实时预览、停止并保留、取消本次和错误重试。Enter 停止并保留，Esc 取消；转写期间不能发送尚未确认的草稿。真实 TextArea DOM ref 提供光标位置，命令式写入同步更新读引用，连续事件不会误判为手动改稿。

手动编辑语音区间会保留编辑并结束自动回填。中文输入法开始组合时保留当前草稿、结束录音并显示提示，防止临时识别结果覆盖正在输入的拼音。语音面板同步取消/停止语义，并移除不真实的 browser/web-speech 服务商标记。

Qwen 按句更新与最终结果的依据见[服务端事件文档](https://help.aliyun.com/en/model-studio/qwen-asr-message-server-events)，run/finish 协议见[客户端事件文档](https://help.aliyun.com/en/model-studio/qwen-asr-message-client-events)。
