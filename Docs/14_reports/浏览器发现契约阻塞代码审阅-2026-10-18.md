# 浏览器发现契约阻塞代码审阅（2026-10-18）

## 1. 结论与证据范围

**当前源码本身存在生产者/消费者的结果类型错配；仅对齐 DLL 并重启不足以修复。** `context.getInfo` 走执行器后返回列表包装，Core 仍读取单个上下文。用同一工作树源码编译的隔离探针复现了用户提供的逐字错误，因而这个缺陷不依赖运行版本偏斜才能出现。

本轮审阅基线 HEAD `2d1d01d`。用户提供的六次工具调用、两份 DLL 大小/时间戳、进程重启时间和截图均作为**用户侧证据**，本轮未重新读取在跑进程的程序集、未访问京东、未调用模型、未重启产品。截图显示页面仍为 about:blank、控制会话等待确认，可支持“业务任务未开始”，不能独立证明 DLL 实际加载来源。

本轮只修改方案、ADR、诊断/索引与日志；临时探针在 `temp/`，未修产品代码。本文区分“源码静态确认”“隔离探针实测”和“待真机验证”。

## 2. 确定性缺陷

### F1 · P1：context.getInfo 的单对象被列表包装替代

调用链：`BrowserContextTool.List/Get → BridgeBrowserCapabilitySurface.GetContextsAsync → RemoteBrowserRuntime.ListContextsAsync → 对每个 context 调用 GetContextAsync → context.getInfo`。因此非空上下文列表会触发同一错误；空列表可能暂时掩盖它。传入 context_id 的页面操作在 surface 内仍要解析 context，不能靠猜 page_id 解决。

- [Core 消费端](../../Source/PuddingHost/BrowserBridge/RemoteBrowserRuntime.cs:58)明确调用 `ExecuteAsync<BrowserContextDescriptor>`。
- [请求适配器](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandAdapter.cs:120)将 `context.getInfo` 映射为 `ForContexts()`，没有验证或筛选所请求的 context。
- [结果路由](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeExecutorRoute.cs:124)没有独立的 getInfo 分支，进入默认 `FromContexts`。
- [FromContexts](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeResultAdapter.cs:50)返回 `BrowserContextListDescriptor`，实际 JSON 为 `{contexts:[{contextId,userDataDirectory,pageCount}]}`。

所以“缺三个 required 属性”指的是**顶层缺三个字段**，不是列表元素缺字段。请求不存在的 context 也返回成功列表，稳定的 `browser_context_not_found` 语义丢失。

### F2 · P1：关闭成功却被 Core 解释为失败

[路由:165](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeExecutorRoute.cs:165)对 `page.close/context.close` 返回 `Success=true, Value=null`；[RemoteBrowserRuntime](../../Source/PuddingHost/BrowserBridge/RemoteBrowserRuntime.cs:237)的 `ExecuteEmptyAsync` 却委托给 `ExecuteAsync<JsonElement>`，后者先拒绝缺失 Value。

隔离探针确认 context.close 的成功响应无值；结合 Core 源码可判定它会报 `returned no value`。**这是副作用可能已完成、消费端却报失败**，不能建议 Agent 自动重试。没有在真机关闭页面验证。

### F3 · P1：后退/前进/刷新/停止的响应同样错配

[路由:150](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeExecutorRoute.cs:150)把 goto/back/forward/reload/stop 全部返回 `BrowserNavigationResultDescriptor`（含嵌套 page）。[RemoteBrowserPage:46–81](../../Source/PuddingHost/BrowserBridge/RemoteBrowserPage.cs:46)只有 goto 消费此类型，其余四项经 `ExecuteNavigationAsync` 消费顶层 `BrowserPageDescriptor`。

四个动作在隔离探针中均成功经过路由，随后反序列化缺少 `contextId/pageId/title/pageVersion`。goto 不在这组类型错配中。修复发现入口后才会暴露这些后续阻塞；执行过的导航不得因解码失败重发。

### F4 · P1：发现元数据又绕回页面授权，可能继续阻断引导

[Bridge surface:259](../../Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs:259)枚举 page.list 后，逐页调用 `context.GetPageAsync`，额外发送 `page.getInfo`。而 [dispatcher 的发现白名单](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandDispatcher.cs:502)仅包含无 PageId 的 context.list/getInfo、page.list、context.create；page.getInfo 进入目标会话准入。

静态后果：修正 F1 后，无交页但已有页面、或存在未交出的其他页面时，整个发现调用仍可能被页面准入拒绝；用户看到元数据之前就被要求交页。此项未做产品实测，需成对测试“元数据可读，内容/写操作仍拒绝”，不能将全部 page.getInfo 放进免目标白名单规避。

此外，`FromPageList` 返回所有 contexts 的页面，RemoteBrowserContext 随后才按 context 过滤；这不是已证实的跨用户泄露，但生产端应按请求范围投影。`BuildPageInfo` 把 active/agentTarget 硬编码为 false，既有 `PageInfo` 又不承载这两个字段；发现事实在中转层丢失，不能用于宣称目标已交出。

### F5 · P2：握手和测试尚未覆盖真正的契约配对

[协议版本](../../Source/PuddingBrowser.Protocol/BrowserBridgeProtocol.cs)为 2；[Hello 接受逻辑](../../Source/PuddingHost/BrowserBridge/DesktopBrowserConnection.cs:57)只比较这个整数，没有构建配套身份。相同整数不能发现“同名命令已改形状”。

现有 [Host 代理测试](../../Tests/PuddingHost.Tests/BrowserBridge/RemoteBrowserRuntimeTests.cs)由替身手工返回消费者期望的 DTO；[Desktop 路由测试](../../Tests/PuddingDesktop.Tests/Browser/BrowserBridgeExecutorRouteExecutionTests.cs)检查局部 JSON，且将 close 无值列为正确结果；[反投影测试](../../Tests/PuddingDesktop.Tests/Browser/BrowserBridgeResultAdapterTests.cs)验证展平所有 context。它们分别通过不能证明真实生产者输出可被真实消费者接受。

## 3. 对用户报告的校正

| 报告中的判断 | 本轮核对 |
|---|---|
| 所有页面工具卡在共用 context.getInfo | 与当前源码调用链一致；创建与空列表不必经过该分支 |
| context.create 可用说明 Bridge 通路与准入都通 | 证明这条引导命令可用；它不要求已有目标，不能证明页面控制准入已成功 |
| create 可见结果没有 userDataDirectory，证明 Bridge 缺字段 | 不成立。[BrowserContextTool.Value](../../Source/PuddingBrowser.AgentTools/BrowserContextTool.cs:150)有意只输出 contextId/persistent/pageCount；[FromCreatedContext](../../Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeResultAdapter.cs:234)仍输出 userDataDirectory 空串，探针可正常解码 |
| DLL 大小/时间不同，说明版本偏斜 | 是合理线索；尚未核对实际加载路径、MVID、InformationalVersion 和 SHA-256，不能仅凭磁盘时间确认进程内版本，更不能证明它是唯一根因 |
| 重建 Core、同步 Protocol 即可恢复 | 不足。需要先修生产结果映射及消费者空响应处理，再成套构建/部署 Core 与 Desktop；只拷贝 Protocol.dll 不会修复已编译进两端的逻辑 |

[CoreExecutableResolver](../../Source/PuddingDesktop.WpfArchive/Core/CoreExecutableResolver.cs)优先显式配置，再选 `core/PuddingAgent.exe`、同目录 Core，最后才开发路径。两进程同时重启不保证选择同批产物；验收须记录真正解析出的路径和加载模块身份。构建时间与文件长度仅作诊断线索。

## 4. 本轮隔离复现

探针引用当前 `Pudding.Contracts`、`PuddingBrowser.Protocol` 工程，并**链接生产** CommandAdapter、ResultAdapter、ExecutorRoute 源文件；执行器替身只返回正常 `DesktopContexts/NavigateResult/ContextClosed`。通过同一 `JsonSerializerDefaults.Web` 和 Core 使用的目标 DTO 解码生产路由结果。没有引用或启动 WinUI/Core，也没有访问数据库。

```text
context.list → {contexts:[…]} → BrowserContextListDescriptor：成功，2 项
context.getInfo(ctx-a) → {contexts:[…]} → BrowserContextDescriptor：失败
context.getInfo(missing) → Success=True（应为 context_not_found）
context.create → {contextId:"ctx-a",userDataDirectory:"",pageCount:0}：解码成功
context.close → Success=True; Value 缺失
page.goBack / page.goForward / page.reload / page.stop → BrowserPageDescriptor：全部解码失败
```

getInfo 原始异常：

```text
JSON deserialization for type 'PuddingBrowser.Protocol.BrowserContextDescriptor' was missing required properties including: 'contextId', 'userDataDirectory', 'pageCount'.
```

构建命令为 `dotnet build temp/BrowserContractReview.csproj --artifacts-path temp/build/browser-contract-review`，复跑同目录使用 `--no-restore`。构建 0 错误、2 个既有 CS8604 警告（CommandAdapter:189）。探针 exit=0 表示**成功复现缺陷**，不表示浏览器门禁通过。它没有覆盖真实消费者调用上下文、WebSocket、页面权限和模型；正式修复必须增加两端连通测试。可复制的探针构造与输出已在本节记录；临时编译目录因自动审批拒绝删除而保留在 ignore 范围，未提交。

## 5. 处理顺序与未完成

先修命令结果合同、空响应与无目标发现，再完成契约/准入连通测试，然后成套构建并由外部控制器部署，最后真实 Agent 验证 TestSite 与用户的三条业务预期。具体步骤见[修复方案](../12_features/浏览器发现契约与配套部署修复方案-2026-10-18.md)，权威决策见 [ADR-097 D8/D9](../07_architecture/111ADR-097Agent浏览器控制一期闭环与单一执行链ADR.md#d8命令结果合同与发现面不可被内部能力形状替代)。

本轮没有执行任何产品修复或外部任务。京东打开/购物车读取、图像理解、搜索比价与加购仍未验收；登录、验证码、视觉模型能力、站点限制和页面控制授权也尚不能下结论。
