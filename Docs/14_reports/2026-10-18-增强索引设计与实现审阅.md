# 2026-10-18 增强索引设计与实现审阅

审阅对象为当前索引/检索源码及 ADR-089 文档族，结合用户提供的代码位置清单逐项核对。前一轮审阅读取的仓库基线为 `dce5a51`；本轮整理文档开始时 HEAD 为 `40d1828`。工作树含其他任务改动，本报告不声称是全仓库洁净构建验收。本文记录复现事实，不表示已修复或已部署。

## 1. 现状核验

| 项 | 源码事实与限制 |
|---|---|
| 索引组件 | CodeIndex 与 CodeIntelligence 已拆分；CodeIndex负责存储/维护，后者负责语言与查询，不应重新当成尚未实施的拆分提案 |
| 实际装配 | Host已有 Coordinator 管线装配；组件默认Legacy不等于生产Host选择Legacy。代码库仍由Host配置在中央DataRoot；ProjectLocal是待落地目标 |
| 全文索引 | Lucene按非空行写document；不是每文件一条document。配置类 Enabled 默认false，但未读取运行配置，不能据此断言生产未启用 |
| 容量 | 已有 QuotaEnforcingDirectory、维护及staging配额路径，Host传MaxIndexBytes；“配额完全未实现”不准确。本次未完整验收GC/所有容量场景 |
| 统一工具 | IRetrievalPort已有合同，workspace_search/open及会话项目集合尚未形成生产统一入口 |
| 项目工具 | 已有workspace范围的code_index_register/unregister/list；unregister缺省RemoveIndexData=true，不是会话卸载 |
| 向量 | Chunking/Vector主要由EvalProbe消费；int8仍为O(ND)扫描，非ANN；不等于生产具备持久upsert/delete和图证据融合 |
| ProjectMap | 每查询扫描.cs、截断后计数、根文件输出缺失；不等于多语言依赖图 |

临时探针 `temp/index-review-20261018.csproj` / `.cs` 直接引用 FullTextIndex 与 CodeIntelligence，未修改生产源码。使用 .NET SDK 10.0.401 构建，0 warning / 0 error；执行四组最小反例：TopK后过滤、跨项目同名、方法组/类型关系、新增重载重绑定。生产 analyzer 补测再次复现P1-01。

## 4. 其它设计缺口

- **P2地图**：[ProjectMapTool](../../Source/PuddingRuntime/Tools/BuiltIns/CodeIntelligence/ProjectMapTool.cs)的`.Take(50)`后再计数及只输出child目录会遗漏根文件；R4必须替换为清单/图投影。
- **热路径**：符号SQL的`%query%`、每项目加载全部文件、逐节点图查询需要独立基准与批量化；不能只靠Lucene宣称整个代码查询毫秒级。
- **合同**：跨层Retrieval DTO重复；现有RetrievalResult要求完整总数和截断落盘，与有界首屏目标冲突；重叠scope加权可能重复计证据。
- **向量来源**：现有chunk缺完整symbol/parent引用；P2文本/单行实现需加保留fixture；EvalProbe融合与持久化不等于生产可用。
