## 3 仍需架构裁定（未擅自补造）

1. **主执行链预算根**：`AgentExecutionLlmInvoker`/`ExecutionRunCoordinator` 没有 Work/RootBudget 身份可填 `LlmAttemptBudget`；需要你决定每个会话/Work 的预算账户类型、创建者与限额来源。未决前预算只到 port/账本边界，不到主 provider 调用。
2. **Goal Required Review 策略来源**：已提供 `IGoalReviewRequirementPolicy`（默认 false），但没有“何时 required”的产品字段/模式；开启前无法自动补评审。
3. **子代理端口映射**：`IChildWorkSubmitter`/`ISubAgentLeasePool` 的输入缺少 `SubAgentSpawnRequest` 所需的 LlmConfig/parent session/template；现有 `SubAgentPool` 是命名复用池，语义不同，强行套接会造第二套租约。
4. **插件事件/扩展生产接入**：`IPluginEventDeliverySink`/workspace source 无真实 PluginManager 实现；`ExtensionPipeline` 只有 DI 注册，需要真实加载/卸载生命周期才能接。

## 4 未接生产消费者（如实）

- 工具执行、授权决策、MCP transport、上下文组装、工作区策略仍由既有实现承担；新组件未接管。
- 核心循环仍在 Runtime，独立 kernel 未抽取。
- Goal 自动续跑闭环（提交 seam→结算事务→评审完成 continuation）未接。
- 08B 部署/加载证明与 08C 真实 smoke 仍 NotRun。

## 5 结论

**“独立组件 + 部分公共入口 + 首个离线闭环 + P2 账本语义”已具备离线证据；“上层只调用组件即可完整使用 Agent 基础设施”与“真实执行链预算/取消到达 provider”仍未完成。** 在 §3 四项裁定前，继续新增接口不会提高收敛度；下一步应按裁定结果迁移单一调用链。
