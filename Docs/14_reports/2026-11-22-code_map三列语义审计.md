# code_map 三列语义审计

## 1. 为什么审

`code_map_check` 验的是**语法**：列数、单元格长度、指纹、md 链接、anti-pattern 词表。
它**不验语义** —— 一列写着 `Services/Foo.cs` 而 Foo.cs 早被删掉，检查器照样 PASS。

本次会话前两轮已因这类盲区抓到过实例（`AgentSprites` 的假陈述、`VisualArtifactObservationService` 的陈旧引用），
故把三列系统盘一遍。

## 2. 方法与结果

| 列 | 判据 | token | 真错误 | 比例 |
|---|---|---|---|---|
| `关联` | 路径存在性（code_map 目录 → 父 → 祖父 → 仓库根 → 全仓同名兜底） | 1140 | 1 | 0.09% |
| `文件` | 同上，但只取带扩展名或 `/` 结尾的 token | 2280 | 3（2 陈旧 + 1 误导） | 0.13% |
| `关键符号` | 标识符 ∈（.cs/.csproj/.xaml/.ts/.tsx/.js/.mjs/.json/.props/.slnx 的标识符集合）∪ 文件名词干 | 2368 | 2 | 0.08% |
| 合计 | — | **5788** | **6** | ≈0.10% |

## 3. 六个真错误

| 位置 | 问题 | 处置 |
|---|---|---|
| `PuddingPlatform:313` | 关联指向已删的 `VisualArtifactObservationService.cs` | 改为两个真实依赖（`VisualArtifactResolverBridge` / `VisualArtifactReference`） |
| `PuddingHost:148` | 整行指向已删的 `BoundChannelSessions.cs`（`55f01ae` 移除按会话 ID 前缀授权） | 删行（条目数 64→63） |
| `PuddingPlatform:315` | 整行指向已删的 `VisualArtifactObservationService.cs`（`9339eb3` ADR-077 视觉重构） | 删行（条目数 275→274） |
| `PuddingCore:14` | 文件列写 `IGoalQueryService.cs`，该接口其实在 `IGoalCommandService.cs:15` | 去掉伪文件名（关键符号列已列该接口） |
| `ToolPlugins.AgentSdk:15` | 关键符号 `IPluginGuardDecision` —— 把接口 `IPluginGuard` 与实现 `PluginGuardDecision` 混写成一个不存在的名字 | 改为 `PluginGuardDecision` |
| `Platform:125` | 关键符号 `UsageSummaryRow`，真名 `UsageSummaryRowDto`（`UsageSummaryQuery.cs:50`） | 加 `Dto` 后缀 |

两条「已删文件」都用 `git log --all --diff-filter=D` 取证，确认是**有意的架构变更**而非误删。

## 4. 误报成因（做门禁前必须知道）

三列的第一版扫描分别报出 4 / 278 / 35 条「问题」，绝大多数是**合法写法**：

1. **章节相对路径**：`## 契约（Contracts/ → …）` 下的 `| CodeFileRecord.cs |`，基准是标题里的目录
2. **通配与省略**：`DeepSeek*Tool.cs`（匹配 2 个）、`Goal*Entity.cs`（匹配 6 个）、`…Buffered.cs`
3. **符号列写文件词干**：`GoalContinuationContracts`（省略 `.cs`）—— 实测很常见
4. **符号列写 XAML 资源键 / TS 类型**：`ShellBackground`、`QuietButton`

⇒ 任何单一判据都会误报。有效判据必须同时接受：章节标题目录、通配、省略、文件词干、跨语言标识符。

## 5. 是否值得做成门禁

**暂不建议。** 理由：

- 6 / 5788 的错误率太低，做成门禁的维护成本（要处理 §4 五类合法写法）远高于收益
- 这类检查需要读取工作树全部源码建索引（本次建了 6068 文件 / 153440 标识符），与检查器「只读文本表格」的定位不同
- 更合适的位置是**定期人工审计脚本**，或等 `code_index` 的符号索引成熟后复用它

## 6. 复现要点

- 排除 `.work/**`（归档快照会让所有统计翻倍）与构建目录
- `文件` 列只取带扩展名或 `/` 结尾的 token，否则符号名会被误判为路径
- `关键符号` 列必须接受文件词干，否则 33/35 是误报
- 判定「真错误」前，`git log --all --diff-filter=D -- <path>` 确认是删除还是从未存在
