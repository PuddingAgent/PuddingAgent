# 部署操作手册（2026-10-20）

## 0. 这份文档给谁

给**不在 Core 进程内**的执行者（外部 DeepSeek harness、人工）。Agent 自己在 Core 里跑，
执行部署会把自己杀掉，所以由外部执行。

## 1. 现场事实（2026-10-20 00:03 核实）

| 项 | 值 |
|---|---|
仓库根 | `D:\CodeProject\PuddingAgent\PuddingAgent` |
HEAD | `294c548` |
工作树 | 干净 |
运行目录（RUN） | `D:\CodeProject\PuddingAgent\PuddingAgent\temp\build\winui3\bin\PuddingDesktop\Debug\net10.0-windows10.0.19041.0\win-x64` |
Core 可执行 | `RUN\core\PuddingAgent.exe`（pid 101104，启动 18:28:46） |
Desktop 可执行 | `RUN\PuddingDesktop.exe`（pid 101304，启动 17:59:41） |
待部署提交 | 自 18:00 起 **23 个**，其中 C# 7 个（HA 三条 / ha_history 裁剪 / 浏览器 page 滚动 / startup 租约 / 契约注释），其余为前端 + 文档 |

**关键机制（已读 csproj 确认）**：
`PuddingDesktop.csproj` 的 `BuildCoreBundle` target（`AfterTargets="Build"`）会自动
`Publish` `PuddingAgent.csproj` 到 `$(TargetDir)core/`，并在缺 `core/wwwroot/admin/index.html`
时**直接报错**：`Build PuddingPlatformAdmin first.`

⇒ 顺序必须是 **先前端、后 .NET**；且前端产物要落到 `RUN\core\wwwroot\admin\`。

## 2. 前置检查（不满足就别开始）

```powershell
$RUN = 'D:\CodeProject\PuddingAgent\PuddingAgent\temp\build\winui3\bin\PuddingDesktop\Debug\net10.0-windows10.0.19041.0\win-x64'
Test-Path $RUN                                        # 期望 True
Test-Path "$RUN\core\PuddingAgent.exe"                # 期望 True
git -C 'D:\CodeProject\PuddingAgent\PuddingAgent' status --porcelain   # 期望空
```

若工作树**不**为空：先停止，确认那些改动是谁的。不要带着别人的未提交改动部署。

## 3. 执行步骤

### 3.1 停止进程（必须，否则文件锁会让构建失败）

```powershell
Get-Process PuddingDesktop,PuddingAgent -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Seconds 3
Get-Process PuddingDesktop,PuddingAgent -ErrorAction SilentlyContinue   # 期望无输出
```

> 先停 Desktop：它是父进程，先杀子进程可能被自动拉起。

### 3.2 构建前端

```powershell
Set-Location 'D:\CodeProject\PuddingAgent\PuddingAgent\Source\PuddingPlatformAdmin'
pnpm build
```

- 退出码必须为 **0**。`pnpm build` = `max build && node scripts/check-chat-bundle-budget.cjs`，
  第二步是 **chat 路由 chunk 体积门禁**，超预算会直接失败——失败就**停下来**，不要绕过。
- 成功标志：本地出现 `dist\index.html`。

### 3.3 回填前端产物到运行目录

> 为什么先做：`PuddingDesktop` 构建会检查 `core/wwwroot/admin/index.html` 是否存在。

```powershell
$RUN = 'D:\CodeProject\PuddingAgent\PuddingAgent\temp\build\winui3\bin\PuddingDesktop\Debug\net10.0-windows10.0.19041.0\win-x64'
$ADMIN = Join-Path $RUN 'core\wwwroot\admin'
if (-not (Test-Path $ADMIN)) { New-Item -ItemType Directory -Path $ADMIN -Force | Out-Null }
robocopy 'D:\CodeProject\PuddingAgent\PuddingAgent\Source\PuddingPlatformAdmin\dist' $ADMIN /E /NFL /NDL /NJH /NJS /NP
# robocopy 退出码 0-7 都算成功（8+ 才是失败）
if ($LASTEXITCODE -ge 8) { throw "robocopy failed: $LASTEXITCODE" }
```

**不要用 `/MIR`**：镜像会删除目标里多出来的文件；用 `/E` 覆盖 + 追加，旧 hash chunk 残留
不影响正确性（HTML 只引用新的）。

### 3.4 构建 Core + Desktop

```powershell
Set-Location 'D:\CodeProject\PuddingAgent\PuddingAgent'
dotnet build 'Source\PuddingDesktop\PuddingDesktop.csproj' -c Debug
```

- 退出码必须为 **0**。
- 该构建会连带 `Publish` Core 到 `RUN\core\`。
- 若报 `Desktop build is incomplete: Core Web workbench is missing` ⇒ 回到 3.3 检查 admin 目录。

### 3.5 再次回填前端产物（防 publish 覆盖）

`Publish` 有可能覆盖或清理 `core/` 下未被其清单收录的文件。**再执行一次 3.3 的 robocopy**
是廉价保险。

### 3.6 启动

```powershell
$RUN = 'D:\CodeProject\PuddingAgent\PuddingAgent\temp\build\winui3\bin\PuddingDesktop\Debug\net10.0-windows10.0.19041.0\win-x64'
Start-Process -FilePath (Join-Path $RUN 'PuddingDesktop.exe')
Start-Sleep -Seconds 12
Get-Process PuddingDesktop,PuddingAgent -ErrorAction SilentlyContinue | Select-Object Id,ProcessName,StartTime
```

期望：两个进程都在，`PuddingAgent` 的 `StartTime` **晚于** `PuddingDesktop`（Core 由 Desktop 拉起；
若 Core 启动早于 Desktop，说明它是残留进程，需重新停掉再启）。

## 4. 验收判据（逐条给命令与期望）

### A1 产物新鲜度（决定性）

```powershell
$RUN = 'D:\CodeProject\PuddingAgent\PuddingAgent\temp\build\winui3\bin\PuddingDesktop\Debug\net10.0-windows10.0.19041.0\win-x64'
(Get-Item "$RUN\core\PuddingAgent.dll").LastWriteTime
git -C 'D:\CodeProject\PuddingAgent\PuddingAgent' log -1 --format='%ci' 294c548
```

期望：**DLL 修改时间晚于 HEAD 提交时间**。否则部署没生效，不要看功能。

### A2 前端确实换版

```powershell
(Get-Item "$RUN\core\wwwroot\admin\index.html").LastWriteTime      # 期望 ≈ 刚才的构建时间
Get-Content "$RUN\core\wwwroot\admin\index.html" | Select-String 'chat'
```

期望：时间接近现在（不是 17:59 那种旧时间）。

### A3 后端健康

```powershell
$core = Get-Process PuddingAgent | Select-Object -First 1
Get-NetTCPConnection -OwningProcess $core.Id -State Listen | Select-Object LocalAddress,LocalPort
```

拿到端口后（常见 5000，但**以实测为准**）：

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" http://127.0.0.1:<端口>/health
```

期望 `200`。

### A4 前端路由可访问（登录后）

1. 浏览器打开 `http://127.0.0.1:<端口>/admin/`
2. 登录 `admin` / `pudding.dev`
3. 访问 `/chat/panel-demo`

期望：页面出现三块——「面板 / 文档 / 图表」切换。

### A5 本次前端改动是否在跑（人工点一遍）

| 检查 | 期望 |
|---|---|
| `/chat/panel-demo` → 图表 Tab | 出现一条 24 小时双序列折线 |
| 文档 Tab → 点「下载」 | 浏览器下载 `温度巡检报告-2026-10-19.md` |
| draft 面板 | 示例 HTML 正常显示；**并且它的 `<script>` 没有执行**（内容不该变成 SHOULD NOT RUN） |
| 对话里发一条超长 Markdown（>3000 字） | 渲染为折叠卡，有「在对话中展开」 |
| 折叠卡点「在右侧打开全文」 | 右侧出现文档面板（大纲 + 正文） |

### A6 后端改动是否在跑（旧待验项）

用 Agent 工具（或等 Agent 自己复验）：

1. `ha_states(domain=sensor, deviceClass="temperature,humidity", limit=200)` → 期望 26 条，每条带 `name`
2. `ha_states(domain=sensor, limit=500)` → 应返回 `nextAfter`，带 `after` 再读一页，两页 entity_id 无重复无遗漏
3. 浏览器打开 B 站视频页 → `browser_interact(scroll, scroll_target=page, delta_y=420)` → 期望 `notScrolled=false` 且 `container='largest-scrollable'`

## 5. 失败处理

| 现象 | 原因 | 处理 |
|---|---|---|
构建报 DLL 被占用 | 进程没停干净 | 重跑 3.1，确认 `Get-Process` 无输出 |
`Core Web workbench is missing` | 3.3 没做或 robocopy 失败 | 重跑 3.3 |
`chat-bundle-budget` 失败 | 前端 chunk 超预算 | **停下**，把输出贴给 Agent；不要跳过门禁 |
A1 判据不通过 | 构建产物没到运行目录 | 核对 `dotnet build` 的 `-c Debug` 与 RUN 路径一致 |
启动后 Core 反复退出 | 启动租约冲突（`5bdf59a` 相关） | 查看 `core` 同目录日志；若仍失败，回滚到 `294c548` 之前的 DLL |

## 6. 回滚

部署前先备份：

```powershell
$RUN = 'D:\CodeProject\PuddingAgent\PuddingAgent\temp\build\winui3\bin\PuddingDesktop\Debug\net10.0-windows10.0.19041.0\win-x64'
$backup = "D:\CodeProject\PuddingAgent\PuddingAgent\temp\deploy-backup-" + (Get-Date -Format 'yyyyMMdd-HHmm')
New-Item -ItemType Directory -Path $backup -Force | Out-Null
Copy-Item "$RUN\core" -Destination $backup -Recurse -Force
Copy-Item "$RUN\PuddingDesktop.exe" -Destination $backup -Force
```

回滚 = 停进程 → 把备份的 `core\` 与 `PuddingDesktop.exe` 复制回 RUN → 启动。

## 7. 明确不要做的事

1. **不要 `git push`**：出网代理按 SSH+TLS 双协议阻断（`Connection closed by 198.18.0.27 port 22`），推不上去，重试只是浪费时间。
2. **不要用 `/MIR` 部署前端**（会删文件）。
3. **不要跳过 `chat-bundle-budget`**：它是体积门禁，跳过等于把 chunk 膨胀的债留到以后。
4. **不要只重启不构建**：本轮 23 个提交里 7 个是 C#，不构建等于什么都没部署。
5. 不要在部署过程中改源码：工作树必须保持干净，否则出问题无法区分是代码还是部署。
