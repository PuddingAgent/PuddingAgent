# SSH R1–R5 独立复核与 S5 暂缓结论

**判定：不通过 S5 准入。** R1 的脚本守卫、R4 的输出分类及 R5 的配置校验已有实质修补；组件依赖边界保持成立。但 R2/R3 的所有权和资源有界性仍有可复现缺口，不能认定 ADR-096 D2/D3 已全部闭合。

本次复核的是[交付报告](2026-10-12-SSH-R1-R5修补与S5准入复核.md)所称已闭合的实现。组件文件与 `addecc2` 相比无差异，源码哈希、观察结果以及完整复现程序存于[证据 JSON](2026-10-12-SSH生命周期独立复核证据.json)。未改生产代码、宿主、DI、slnx 或运行中的 Core。

## 1. 实际执行与证据边界

- 独立执行 `dotnet test Source/PuddingSshTests/PuddingSshTests.csproj --artifacts-path temp/build/ssh-review2 --results-directory temp/test-out/ssh-review2 --logger "trx;LogFileName=review.trx" --nologo`，TRX 为 **208/208，通过 208、失败 0、跳过 0**。
- 独立复现程序只引用当前组件，复用 `SshFakes.cs`；构建 **0 警告、0 错误**。执行输出五条观察，覆盖下面四类缺陷。程序 exit 0 仅代表采集完成，不代表合同通过。
- 本轮**未重跑**真实 OpenSSH 23 场景；交付报告的连续两轮结果仍是提交方证据。正常网络矩阵不能替代受控不合作端口的资源所有权证明。
- coverage SDK 仍将文件写入测试源码目录的 `TestResults`，本次已移到专属 `temp/test-out/ssh-review2`。不把这项卫生问题作为阻断项。

## 2. 阻断项

### F6 / P1：exec 与 Dispose 的同步入口仍能卡住业务等待

位置：[协调器](../../Source/PuddingSsh/Execution/SshOperationCoordinator.cs) 的 `ExecuteOnSessionAsync`（当前第 596 行）、[资源租约](../../Source/PuddingSsh/Execution/SshResourceLease.cs) 的 `CloseSessionAsync`（第 107 行）。两处仍直接调用 `session.ExecuteAsync(...)` / `session.DisposeAsync()`，只有取得 Task 后才开始有界等待。新 worker 目前只包装 identity/connect。

独立反例：操作 deadline 120 ms、清理宽限 50 ms，exec 同步阻塞 800 ms 后返回完成，实际 **820 ms** 才返回且 `Status=Completed`；Dispose 同步阻塞 800 ms 时，`ssh_test` 实际 **806 ms** 返回。两例 `ActiveStageWorkers=0`。若同步入口一直不返回，业务等待同样没有上界。现有 fake 已有 `SynchronousBlockBeforeExecute`，R3 用例未使用它覆盖此路径。

修补要求：执行、释放及停止回调的同步入口都纳入有界调度；不能只在返回 Task 之后安装 deadline。执行等待超时后迟到的本地成功不得覆盖已经确立的终止事实。

### F7 / P2：迟到建连仍在使用身份时，业务 finally 已清零材料

位置：[协调器](../../Source/PuddingSsh/Execution/SshOperationCoordinator.cs) 的两个 connect 分支（第 280/493 行附近）与 [资源租约](../../Source/PuddingSsh/Execution/SshResourceLease.cs) 的 `TransferLateOwnership` / `ReleaseBusinessResources`。

`TransferLateOwnership()` 直到 **onLateSuccess/onLateFailure 执行时**才设置；业务阶段超时返回时尚未设置，finally 会立即 `ReleaseIdentity()`。独立反例用三个非零的合成字节作为材料，建连由 TCS 保持未完成：取消业务后，`connect_pending=true`、worker 仍为 1，但 **材料已全部清零**。这违反了本轮专门声明的“迟到连接读取期间不得提前清零”合同；延迟解析密钥的适配器可能看到已释放或损坏的数据。

修补要求：在把材料交给 connect 之前完成所有权转移，或者在决定放弃等待的同一个原子状态转换中移交；不能等迟到回调才转移。证明迟到工作结束前材料仍有效，结束后清零一次；两个入口都覆盖。

### F8 / P1：未结束 exec 脱离记账，Stop 错报全部收敛

位置：[协调器](../../Source/PuddingSsh/Execution/SshOperationCoordinator.cs) 的 `ExecuteOnSessionAsync` 宽限到期路径（第 654 行附近）、`EndLease`、`StopAsync`；[资源租约](../../Source/PuddingSsh/Execution/SshResourceLease.cs) 只追踪 Dispose Task。

独立反例：exec 忽略取消一直等待 TCS，Dispose 正常完成。取消后组件返回，但 **exec 仍未完成，leases/workers/quarantine 全为 0**；`StopAsync` 返回 `PendingOperations=0, PendingCleanups=0, TimedOut=false`。该 exec Task 没有转交租约/隔离区，也没有异常观察者；下一次调用可继续产生同类遗留工作。返回诊断还声称“已释放独占连接”，该分支本身并未获得关闭完成证据。

修补要求：租约跟踪连接、exec、reader、关闭及迟到回收的整个完成集合；Dispose Task 完成不等于所有工作结束。实际未结束的工作持续占槽，Stop 必须如实显示，迟到异常也必须被观察。只有全部要求的完成证据成立才释放资源计数。

### F9 / P2：隔离区容量不是硬上限，排队请求可越限进入

位置：[隔离区](../../Source/PuddingSsh/Execution/SshCleanupQuarantine.cs) `Track` 无预留/限额判定；[协调器](../../Source/PuddingSsh/Execution/SshOperationCoordinator.cs) 只在排队前检查 `IsFull`（第 190/406 行）。

确定性反例：Core 并发 1，隔离容量 1；一个执行中的请求和三个已排队请求全部在隔离区为空时被受理，四个会话 Dispose 均保持未完成。首个填满隔离区后，已排队请求仍依次建连，最终 **capacity=1、pending=4、connectCount=4**。这不是报告中声称的“固定容量、满额拒绝新增工作”。

同类源码缺口：`SshStageWorkerPool.Start` 是 `IsFull` 检查后再 `Interlocked.Increment`，两步之间有并发竞争。本次没有用概率压力结果宣称已经复现 worker 越限，修补时应一并用原子预留替换。

修补要求：用 CAS/信号量发放资源令牌；取得准入槽后仍须完成令牌预留才允许副作用。隔离区满时保留原资源槽或拒绝后续请求，不能先释放原槽再无条件 Track。预先排队请求也受这一规则约束。

## 3. 复现方法

证据 JSON 内保存 `reproducer_project` / `reproducer_source`，避免依赖会被清理的临时目录。仓库根执行：

```powershell
$sshReviewEvidence = Get-Content Docs/14_reports/2026-10-12-SSH生命周期独立复核证据.json -Raw | ConvertFrom-Json
$sshReviewEvidence.reproducer_project | Set-Content temp/ssh-review2.csproj -Encoding utf8
$sshReviewEvidence.reproducer_source | Set-Content temp/ssh-review2.cs -Encoding utf8
dotnet build temp/ssh-review2.csproj --artifacts-path temp/build/ssh-review2-harness --nologo
dotnet temp/build/ssh-review2-harness/bin/ssh-review2/debug/ssh-review2.dll
```

所有阻塞均有可释放 gate 或有限时长；采集后交还 gate。合成材料不含真实密钥，也不连接服务器。最终门禁应将这些观察移入组件测试并改成合同断言，先取红后修绿。
