## 4. 残留限制（如实列出，均已有界或已记录）

1. **同步启动段仍是「占用线程」而非「可抢占」**：阶段端口在有界 worker 池（默认 8）上执行，满额 `ssh.busy`；
   .NET 无法强杀阻塞线程，因此不合作的适配器最多占用 ≤8 个 worker + 隔离区容量（默认 8）个资源槽。
   计数可查询（`ActiveStageWorkers`/`QuarantinedResources`）且满额拒绝新增工作——这是「有界」，不是「消灭」。
2. **托管分配 ≈0.22–0.27 B/字节**（SSH.NET 缓冲周转），非驻留；驻留按「会话关闭后」口径实测 ±0.9 MiB 且不随输出增长。
3. **每主机门字典不回收**：键为 `hostId+hostRevision`，随主机/修订数增长（受配置与使用规模约束）。
4. **「两类 `.ssh`」只验证到形状层**（路径、文件集合、互相隔离）；owner/ACL/跨平台解析属 S5/Runtime。
5. **`lateconnect` 证明「迟到真实连接不执行 marker」，但不保证能稳定构造「迟到成功交还 session」**；
   后者由假端口的单测覆盖（迟到连接被关闭、身份只清零一次）。真实适配器无法在不改服务端的前提下确定性复现该交还时序。
6. **隔离区是进程内的**：卡住的资源在真正结束前一直占一个槽与一个线程；容量耗尽即 `ssh.busy`（设计意图，非缺陷）。
7. **`noeof` 用 3 s 操作超时**（运行器显式传入）以缩短矩阵时长；生产默认仍是 60 s。

## 5. 新 S5 准入结论

**判定：同意重新申请 S5（组件侧门禁全部通过）。**

依据 [`组件化交付规程`](../10_conventions/组件化交付规程.md) 的 S1–S5 定义与 ADR-096 的 D1–D5：

- S1–S4 已在组件边界内闭合，`ProjectReference = 0` 仍由编译期强制（`ComponentBoundaryTests`）；
- 审阅报告的 P1/P2 反例全部有对应的红→绿回归与真实协议证据；
- 单测 208/208 与真实协议 23 场景 `failures = 0` 在冻结树上连续通过。

**S5 仍需独立证明（不得用本报告替代）**：

1. 跨平台 `.ssh` 与私有目录解析；路径/owner/ACL 与「两类 `.ssh`」的真实隔离（Windows + WSL 双向）。
2. 主机可见性/revision 与「配置变化后拒绝复用旧快照」在宿主侧的端到端约束。
3. 三个 Agent 工具的注册、参数校验与审批路径（含拒绝路径的可观测证据）。
4. DI 与宿主组合测试：`ssh_execute`/`ssh_test` 在真实宿主中的装配、错误码透传与日志边界。
5. A6 顺序：外部部署到明确新构建 → 进程内功能 smoke → 生命周期结论由外部控制器判定。

**保持不变的边界**：在 S5 结论给出前，不修改 Runtime/Host/DI/slnx/工具/审批；不引入 KeyVault、连接池、远端任务；
Windows OpenSSH 服务端合同仍延后。
