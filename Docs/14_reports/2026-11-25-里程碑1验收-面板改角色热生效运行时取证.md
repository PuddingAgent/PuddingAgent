# 里程碑 1 验收：角色热生效的运行时证据

## 为什么要单独取证

「面板改角色后下一单立即生效」在源码层成立：`SubAgentPool.cs:1105` 在置 Busy **之前**对未显式指定角色的请求调用 `RefreshDeclaredRoleLockedAsync`，`SubAgentPool.cs:1200` 再把生效值写进 `executeRequest.RoleInPlan`。

但源码断言与单元测试都只覆盖「测试替身喂进来的请求」。今天已有多次教训：测试全绿而运行时没生效（例如产物里同一 chunk 混用两种 unicode 转义，搜索口径错了三轮才发现）。这条验收条件关系到「面板设了东西不生效」这一整类抱怨，值得一条独立的运行时证据。

## 取证方法（可复用）

四个动作，全部可逆：

1. **前置**：确认部署 at-or-after-head —— 提交时刻、live DLL 时刻、进程 StartTime 三者有序，且模块路径取自 `Get-Process.Modules` 而不是目录里有什么。
2. **制造库/内存不一致**：用与面板 PATCH 同一条语义的 UPDATE 改 `agent_pool.role` 一行。池内快照是启动时的一次性投影，此时内存仍是旧值 —— 这道差正是「热生效」要跨越的东西。
3. **不传 role 派活**：`spawn_sub_agent(pool_name=…)`，不带角色参数。
4. **读该次 run.json 的 `role`**，然后复原数据库并复核行数与状态。

判据是 run.json：`FileSubAgentRunStore.cs:97` 写入 `Role = request.RoleInPlan`，`SubAgentRunModels.cs` 的 `Role` 字段可空，旧 manifest 无此键仍可反序列化。

## 结果

| 步骤 | 现场 |
|---|---|
| 提交 | `3768eae` 13:28:16 |
| live DLL | 13:32:11 / 13:32:18 / 13:32:20 / 13:32:21 / 13:32:23 |
| 进程 | PID 127708 @ 13:32:48，`PuddingRuntime.dll` 模块路径与部署目录一致 |
| 改库 | `probe-model.role = 'roleprobe-1125-a'`（内存仍为 `verifier`） |
| 派活 | 未传 role；工具回执提示继承了模型路由 `deepseek/deepseek-flash` 与模板 `workspace-task-agent` |
| run.json | `role=roleprobe-1125-a`、`templateId=workspace-task-agent`、`modelId=deepseek-flash`、`providerId=deepseek`、`status=completed` |
| 复原 | `role='verifier'`，`agent_pool` 仍 5 行，该条目仍 `sleeping` |

**结论：验收条件成立。** 库里的角色值在同进程的下一单立刻生效，不需要重启。

## 这份证据的边界

- 证明的是**派发路径读库**。没有证明面板 PATCH 端点本身（我侧无 admin JWT，只能从界面点）；不过 PATCH 与本次 UPDATE 落在同一列、同一行、同一语义上。
- 只覆盖 role。**template 继承无法取红**：当前 5 条条目的 `template_id` 全为默认值 `workspace-task-agent`，继承与「未继承但恰好等于默认」在产物上不可区分。要造出非默认值需一条新条目，而面板 PATCH 白名单不含模板列、工具入口会立即执行，所以这次没有造。这是数据限制，不是结论。
- 未覆盖（本轮也未声称覆盖）：迟到取消不影响下一单（竞态，属测试层）、收尾写库失败后恢复（需故障注入）、cleanup 只清理目标成员（A/B 隔离）。

## 一处已知的不对称（未修）

三种继承里只有两种会给调用方公告：模型路由与模板由工具层发出（`SubAgentTool.cs:594`、`:600`），角色继承发生在 Platform 层，工具看不到生效值，因此静默。

要补公告必须把生效值从 Platform 回传到工具结果，属接口契约变更，带一批测试桩改动。本轮不做，记在这里而不是留在脑子里。

## 复用要点

- 「配置热生效」类修复的判据必须是**库/内存不一致**下的下一次调用，而不是重启后的第一次调用 —— 后者会把「读进程内快照」也判成通过。
- 探针要带可识别标记（`roleprobe-<日期>-<序号>`），否则继承值与既有值相同就分不清。
- 改生产数据必须是「一行一列 + 事后复原 + 复核行数状态」，并且改前先确认这是面板同一条写路径。
