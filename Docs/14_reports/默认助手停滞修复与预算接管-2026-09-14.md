## 2. 已修复的代码

### R1：搜索有界并响应取消

提交 `4ce9d6f`。`FileSearchTool.cs` 内置 Provider 改为逐目录广度优先枚举，目录和不匹配文件都消耗扫描预算；默认 10 秒 / 50,000 条，保留已找到的结果，超时或扫描截断必须声明覆盖不完整。max_results 是输出匹配上限，不能代替遍历预算。

两个搜索入口复用同一实现，实际遍历放到工作线程；取消传播到调用方，不转为普通错误再启动 fallback。差分枚举取消同样不被吞掉。不可读目录保留失败原因，不再用 IgnoreInaccessible=true 伪装完整覆盖。沿用统一 glob 匹配和 reparse-point 排除规则。

限制：时间预算在文件系统枚举步骤之间检查，不能声称它能中断 Windows 内核中单次阻塞的目录 I/O。没有对整个磁盘提供强制进程级 deadline，也没有暗中排除 `.git`、`node_modules` 等用户声明范围；很大的范围可以返回 partial / truncated，用户或 Agent 应收窄目录。

验证：FileSearch 定向 **32/32**；新增空目录也计预算、时间耗尽保留结果、预取消及遍历中取消测试。

### R2：失效接收者不再堵住回复队列

提交 `8d2ad3b`。MessageRouter 使用类型化 `MessageTargetUnavailableException` 表达路由拒绝。回复投影为该项保存 `reply_projection_status=failed`、稳定错误码和目标；结算投影扫描项，但保留原 canonical 回复与执行成功状态，不生成虚假的“已送达”。

同批 Fabric 回复逐项隔离，暂时性异常仍可按稳定 replyMessageId 重试，已处理兄弟项能够保存。永久拒绝不再每 5 秒重试。`ReplyProjectedAt` 文档同步明确“投影已结算”与“送达”不同，失败细节在 metadata，实际消息送达由 MessageDelivery 负责。

验证：MessageRouter / ConversationReplyProjectionWorker **23/23**。新增三条回复中间失败的回归，分别覆盖永久目标失效与可重试异常：前后成功项均保存、失败结论不覆盖执行终态、再次扫描不重复送达，暂时性异常解除后可成功。
