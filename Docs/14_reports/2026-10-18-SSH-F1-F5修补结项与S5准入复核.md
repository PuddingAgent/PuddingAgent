# 2026-10-18 SSH F1–F5 修补结项与 S5 准入复核

**结论：审阅的 3 项 P1 + 2 项 P2 已全部闭合，每项都有"先取红、后修绿、再变异取红"的门禁；当前组件测试 301/301、真实 OpenSSH 24 场景 `failures = 0`（干净树）。建议重新进入 S5 准入评审；S5 接入本轮仍未开始。**

## 1. 逐项闭合

| 审阅项 | 修补 | 门禁（取红 → 复绿 → 变异红） |
|---|---|---|
| **F1（P1）** 上传排他失败仍删除他人文件 | 通道 `OpenWriteNew` 返回**创建所有权**（失败抛 `SshSftpTargetExistsException` 且未创建）；复制循环收进会话；`AbandonUpload` 只删除 `createdByUs` 的文件 | `Upload_ExclusiveCreateLosesRace_*`（他人数据保留）、`Upload_CreateOutcomeUnknown_*`（所有权不可证明不删）、`Upload_LocalSourceOpenFailure_*`（零远端副作用）→ 变异：忽略所有权事实 ⇒ 红 |
| **F2（P1）** 下载无运行时字节上限 | 会话 `CopyAsync` 逐次累计字节，超限抛 `SshTransferLimitExceededException`；下载失败映射 `ssh.transfer_too_large`；STAT 仅快速拒绝 | `Download_RemoteGrowsAfterStat_AbortsAtRuntimeLimit`（STAT=1B、实读 4096B，请求上限 1024B）→ 变异：去掉运行时检查 ⇒ 红 |
| **F3（P1）** 能力探测绕过生命周期 | 探测改为**提交前有界阶段**（worker + lifetime + 租约登记 + `WaitStageAsync`）；结果只读 `session.Capabilities` 快照；异常 ⇒ `ssh.transfer_failed` 结构化；**下载不探测** | `Upload_CapabilityProbeHanging_*`（150 ms 内返回、不报 Completed、worker 归还）、`Upload_CapabilityProbeThrows_*`、`Download_DoesNotProbeCapabilities` → 变异：探测移回结果阶段 ⇒ 两条红 |
| **F4（P2）** 取消后丢弃残留证据 | 新增 `SshTemporaryResidue{None,LeftBehind,Unknown}`；取消后在**清理宽限**内合并迟到结果的字节数与残留证据；期限到未知 ⇒ `Unknown`（不得默认无残留） | `Upload_Cancelled_MergesLateResidueEvidence_*`、`Upload_Cancelled_ResidueUnknownWhenLateResultExceedsBudget` → 变异：去掉合并 ⇒ 两条红 |
| **F5（P2）** 关闭预算被默认 2 s 覆盖 | `RequestAbort()` **只登记意图**；关闭预算由带预算的 `DisposeAsync(budget)` 决定 | 真实 `SshNetTransportSession`：`RequestAbort()+DisposeAsync(50ms)` ⇒ `CloseBudget≈50ms`；协调器 `CleanupGrace=50ms` ⇒ 真实会话同样 ~50ms → 变异：恢复抢跑 ⇒ 两条红（修复前实测 2000 ms，与审阅 R6 一致） |

## 2. 验证证据

- **单元/组件**：`dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **301/301 通过，0 警告**。
  用例增长：289（审阅时）→ 294（F1/F2）→ 299（F3/F4）→ 301（F5）。
- **真实协议矩阵**（OpenSSH_10.2p1 / Ubuntu 26.04.1 LTS）：**24 场景 `failures = 0`**，
  `build.source_sha`/`source_dirty`/`probe_dll_sha256` 记录；`transfer` 场景出带证据：
  服务端 sha256 == 客户端期望、上传根仅 `payload.bin`（无部分目标/临时文件）、
  服务端认证次数等于探针自报连接数（6==6）；`cancel` 场景仍为 `exit_signal=TERM`、远端 `SHELL_GONE|MARKER_ABSENT`，
  证明 F5 的"中止只登记意图"没有破坏执行侧的 TERM 证据。
- **反向验证**：五个修补各自都有"旧行为复现"的取红记录（见上表），不是仅凭复绿声明。

## 3. 修补中发现的额外事实

1. **探针连接计数**：`transfer` 场景把"校验阶段被拒、未建连"的操作也计入 `connections`，已改为只在真正建连时计数，
   现在 `connections` 与 SSH 服务端 `accepted_publickey_delta` 严格相等（6==6）。
2. **新结构下 F1 的变异最初是绿的**：竞争失败在创建层返回、**根本走不到清理**；因此补了"创建结果未知"
   门禁（`OpenWriteNew` 已落地文件但调用失败），让"所有权事实"可被真正检出——这是取红敏感度的修正，不是门禁放松。
3. `RequestAbort` 改为只登记意图后，执行侧取消证据（`ExitSignal=TERM`）仍由 SSH.NET 的 token 取消路径提供，
   真实矩阵已验证；关闭机器的 TERM 现在统一在 `DisposeAsync(budget)` 起步。

## 4. 残留限制（与上次结项一致，未因本次修补消失）

- 远端路径检查不是沙箱：检查与打开之间仍有服务端竞态，严格隔离需远端 chroot/受限账号。
- 本地发布 `File.Move(overwrite:false)`：同机并发写同一目标仍有 TOCTOU。
- 无断点续传/不自动重试；不声明"哈希已校验"（探针的服务端 sha 是独立证据）。
- 能力探测需允许根可写；探测是**上传的前置阶段**，会在允许根内创建并清理 scratch 文件。
- 迟到完成的传输可能留下**完整**目标；门禁只保证不留下**部分**目标，剩余未知显式 `Unknown`。
- 仅单文件；无目录递归/设备文件。
- 未接入宿主：`ssh_upload`/`ssh_download` 与审批仍属 S5。
