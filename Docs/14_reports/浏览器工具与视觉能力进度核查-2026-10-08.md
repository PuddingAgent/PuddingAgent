# 浏览器工具与视觉能力进度核查（2026-10-08）

## 范围与结论

核查起点 HEAD `de6060f`，源码以当前工作树为准。仓库已有他方 Core、Runtime 和前端 WIP，本次不修改产品代码。用户提供的截图属于运行证据线索，截图中的 Agent 自述不等于本次独立验收；徽标带 `+dirty`，没有确认截图实例与当前源码的对应关系。

当前进度是：浏览器基础工具与组件已经落地，基础 DOM 自动化可用，但尚未完成稳定的产品验收；浏览器截图到 Agent 视觉的闭环缺失。没有启动、停止、重启用户 Desktop/Core，也没有读取模型密钥或执行真实模型 smoke。

## 四项需求对照

| 需求 | 当前实现 | 判定与边界 |
|---|---|---|
| Agent 控制、阅读浏览器 | 七项 `browser_*` 工具：context、tabs、navigate、snapshot、locate、interact、wait_for | 已实现；需要 DesktopChild + BrowserAutomationEnabled + 连接和授权。控制对象为产品内 WebView2，不能据此推断可接管外部 Chrome/Edge |
| 浏览器截图、视觉理解 | 浏览器抽象有 ScreenshotAsync，但 WebView2 驱动抛 NotSupportedException，RemoteBrowserPage 同样 Unsupported；七项工具没有截图入口 | 未实现浏览器截图闭环。独立的 image_reader 已支持图片阅读/裁剪，但无法替浏览器生成截图 |
| 便捷读取、定位、操作 DOM | 有界 DOM 摘要、自建可达性摘要、带版本 ref；十种定位方式和八种交互动作 | 已具备基础能力，不必回传完整 HTML；尚缺子树读取、增量变化、表单当前值及更可靠的真实输入 |
| 其他必要增强 | 有鉴权、权限证据、版本检查、人工接管 UI、活动记录与传输计数 | 保护机制与组件存在，真实驱动反馈和新通道产品接线仍有阻断项 |

## 已实现的工具能力

工具定义见 [AgentTools 代码地图](../../Source/PuddingBrowser.AgentTools/code_map.md)。

- 上下文与标签页管理；导航支持 goto/back/forward/reload。
- snapshot 默认不带 HTML；可分别开启 DOM、可达性摘要、隐藏节点、iframe、Shadow DOM、HTML。
- 默认预算是 5,000 节点、200,000 字符、深度 24，有 Truncated 提示；这只是上限，默认输出仍可能较大。
- locate 支持 ref、CSS、XPath、text、role + name、label、placeholder、alt_text、title、test_id；可指定 exact、nth、hasText。回传最多 100 个元素，含文本、可见/启用状态、勾选状态与边界框。
- interact 支持 click、fill、type、press、hover、scroll、select、check；wait_for 支持 CSS 出现/隐藏和 URL 通配匹配。
- ref 形如 `v7-n1`，携带 PageVersion。交互后获取新事实应使用 wait 或新 snapshot，避免重新查询旧 ref。

当前 accessibilityTree 来自 [WebView2DomClient](../../Source/PuddingBrowser.WebView2/WebView2DomClient.cs) 的 DOM 遍历与 role/name 推导，不能当作 Chromium 原生完整 AX 树。支持开放 Shadow DOM 和可访问的同源 iframe；跨域 iframe、显式 Frame 定位及复合 Has 定位仍受限。

## 截图中问题与源码对照

### 最高优先级：动作生效后被判失败

截图显示 `browser_interact_failed: mutating capability returned a page version that did not advance`。当前 [BridgeBrowserCapabilitySurface](../../Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs) 的 InteractAsync 在动作执行后要求返回版本严格大于请求版本，否则报这条错误。gRPC 路径的 [DesktopMutationInvariants](../../Source/Pudding.DesktopService/DesktopMutationInvariants.cs) 也有同类检查。

但 [WebView2BrowserPage](../../Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs) 的版本递增仅出现在导航完成和浏览器进程失败事件中；ExecuteInteractionAsync 执行 DOM 脚本后没有递增版本。fill、非导航 click、scroll 等即使完成，也可能立即被上层判失败；click/Enter 触发导航时，脚本返回与 NavigationCompleted 之间也存在竞态。

这是与截图现象吻合的源码缺陷依据，本次没有在真实 WinUI 页面重新复现。后果是 Agent 可能错误重试已生效动作，产生重复点击/提交。修复应统一操作结果与版本语义，区分已执行、尚待页面变化、确定失败和结果不明；保留陈旧引用保护，并对已产生副作用的结果阻止盲目重试。

截图还提到只读 locate/snapshot 后版本变化。当前源码没有在这两个只读入口直接递增 WebView2 页面版本，不能据截图把原因判定为只读操作；需在明确构建下记录导航事件、动作顺序和返回版本复现。

### 输入值与模拟行为边界

BrowserElementToolValue 没有独立 Value 字段；WebView2DomClient 的 text 读取 innerText/textContent，不读取输入框 `.value`。因此 fill 后 text 为空不代表没写入，但 Agent 缺少便利的回读验证接口。建议增加表单值读取，对密码等敏感字段保持遮蔽。

当前 fill/type 直接赋值并派发合成事件；type 是整串追加。press 只发 keydown/keyup，Enter 特判 form.requestSubmit，不提供 Backspace、Tab、组合快捷键的原生默认行为。hover 的合成事件也不能等同真实鼠标移动。React 受控输入、富文本编辑器及依赖可信输入事件的页面需要真实测试和更可靠的输入驱动。

## 建议交付顺序

1. **先修稳定性**：交互结果/版本反馈、避免重复执行；统一人工接管/暂停事实；统一 context/tab 生命周期及目标注册；释放订阅并串行化通道启停。
2. **建立截图闭环**：viewport、区域/元素截图优先，再按需全页；返回尺寸、坐标系、PageId/PageVersion 与 artifact，接入原生图片工具输出或 image_reader。当前 image_reader.read 要求调用模型 SupportsVision=true 且协议为 responses，其他路由明确拒绝，不应假定所有模型都能看截图。
3. **提高 DOM 阅读效率**：默认精简的交互元素视图；按 locator/ref 读取局部子树或指定字段；分页与增量 diff；结构化表格/列表提取；增加安全的 value 及 selected 状态读取。现有预算参数可以先降低输出，但不等同局部提取。
4. **补真实网页交互**：React 受控表单、contenteditable、键盘默认行为和快捷键；动作前可操作性检查、有限等待与动作后验条件；DOM 定位为主，截图用于布局、Canvas 和疑难页面的观察。
5. **按场景补外围能力**：跨域 iframe/frame、弹窗/新窗口、上传/下载、JavaScript 对话框、拖拽；网络失败与控制台诊断。截图、PDF、公开 CDP/evaluate、拖拽、上传当前均未在产品浏览器驱动打通。
6. **完成产品验收**：外部控制器部署明确构建，再由用户选定的 Agent/DataRoot 执行真实模型 TestSite 与真实网页 smoke；覆盖接管/恢复、跨标签页、隐藏窗口、断连重连和结果不明场景；Desktop/Core 重启、崩溃恢复与退出回收由外部控制器判定。
