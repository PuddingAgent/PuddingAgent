# 浏览器自动化能力交付清单（round-63 全量运行）

## 这是什么

本会话浏览器自动化与渐进阅读工作的**交付证据**：由
[`TestScripts/delivery-manifest.ps1`](../../TestScripts/delivery-manifest.ps1) 跑全量套件生成 TRX，
再由 [`Pudding.DeliveryManifest.Cli`](../../Source/Pudding.DeliveryManifest.Cli/Program.cs) 汇总产出并**自检**的交付清单。

**阶段：`ready-for-external-deploy`** —— 这是内部一侧能达到的上限：进程内的 Agent 不能证明新代码已被加载，
也不能独立判定自身生命周期（见 `Agents.md`「验证边界」）。

| 项 | 值 |
|---|---|
| 套件 | 7 个，全部运行 |
| 通过 / 失败 | **1409 / 0** |
| 产物 | 24 个 `.exe`/`.dll`（文件名，无本机路径） |
| 未验证项 | **20 条**（自动从修改日志提取，非人工回忆） |
| 外部必做步骤 | `startup`、`restart`、`crash-recovery`、`exit-reclamation` |

原始 JSON 由脚本写到 `temp/test-out/delivery-manifest.json`（`temp/` 属临时目录，会被清理；
本页即其**持久化留痕**，摘要保留，不逐字复制 20 条长文本）。

## 内部证明不了的结论（20 条，节选）

清单里的 `knownUnverified` 由 `KnownUnverifiedExtractor` 从本会话的修改日志里提取，例如：

- 真机未验证：WinUI 面「编译上具备」原生输入/滚动/截图/事件上报，但注入策略在真实运行时被调用、
  以及 CDP/事件在 WinUI WebView2 上的行为，都需要外部 smoke（本环境无 WebView2）。
- 真机未验证：两个宿主现在都注入同一策略，但「注入的策略在 WinUI/WPF 真实运行时确实被调用」无法在进程内自证。
- 真机未验证：CDP 方法名/参数是官方接口，但「WebView2 上整页截图的真实效果」需要外部采样。

**完整 20 条**在清单 JSON 的 `knownUnverified` 字段里（由脚本运行时产出）。

## 外部控制器需要做的事（本清单已交出去）

1. 部署到 `commit = e547c6e` 对应的**明确新构建**（清单里的 `artifacts`）；
2. 重新启动，并确认新进程加载的是该构建（而不是被单实例转发到旧进程）；
3. 做产品内功能 smoke（浏览器工具：导航/快照/定位/交互/等待/截图）；
4. 判定**启动 / 重启 / 崩溃恢复 / 退出回收**，产出 `external-lifecycle-verified` 结论。

内部一侧的判定组件 `DesktopAcceptance` 会**拒绝**内部主体作出第 4 步的结论。

## 运行方式与本次执行记录

```
& .\TestScripts\delivery-manifest.ps1 -PublishDirectory "Source/Pudding.DeliveryManifest.Cli/bin/Debug/net10.0" `
    -BuildId "round-63-full"
⇒ === manifest emitted (stage: ready-for-external-deploy)
```

**诚实记录一次失败**：第一次全量运行时结果目录里**没有生成 TRX**，CLI 因此**拒绝产出**清单
（`no TRX results found in '…\temp\test-out\trx'`，退出码 2）。清空 `temp/test-out` 后重跑，七个 TRX 齐全，
清单随即产出。这条失败本身是**设计期望的行为**：事实不完整就不给清单（而不是给一份"看起来能交"的清单）。

## 诚实边界

- **产物不是真正的发布产物**：`--publish` 指向 CLI 的输出目录（为验证链路）；Desktop 的
  `dotnet publish`（`temp/build/desktop-preview`）需串行且受运行中的 Shell 进程占用输出文件影响。
- **`buildId` 是本机生成的时间戳标识**，不是 CI 构建号；可追溯性靠 `commit` 字段。
- **清单不持久化**：脚本写到 `temp/test-out`（会被清理），本页是实际留痕；正式留痕机制（每次交付自动落
  `Docs/14_reports/`）属后续。
- **真机行为仍未验证**：本环境的全部结论都是进程内、纯函数或脚本断言级的（见 `knownUnverified`）。
