### 1.2 纯门禁合同照样 Complete
`Source/PuddingPlatform/Services/Goals/ConservativeGoalIterationVerifier.cs`

判定链（顺序即优先级）：
```
EvidenceComplete==false || HasPendingExecutionFacts      → Blocked(evidence_incomplete)
TerminalKind != "completed"                              → Blocked(iteration_*)
Criteria.Count == 0                                      → Blocked(acceptance_contract_missing)
Checks.Count == 0                                        → Blocked(check_contract_missing)
HasFailedChecks()                                        → Blocked(criterion_failed)
HasPendingChecks()                                       → Blocked(check_results_pending)
TaskStatus ∈ {Blocked, NeedsReview}                      → Blocked(task_blocked)
TaskStatus ∈ {Failed, Cancelled}                         → Blocked(task_terminal_without_completion)
allRequiredPassed && goalScope                           → **Complete**     ← 覆盖门应插在此分支之前
goalScope && RemainingWorkUnits == 0                     → Continue（待整体验证）
```

**实测量化后果**：GoalRun `7ef90f2c`（G92-0 载体）全部 epoch 的合同 `source` 均为 `bounded_planning`，`criteria_json≈1247` / `checks_json≈1281` 字符（仅 `bounded:build` + `bounded:test`），最终 `status=5 Completed`；而该 Goal 的 `TaskGoalBinding = 0` 条 —— 该卡（`30eb371e`）的业务验收**从未被验证**。这正是设计 §11 中**不可删的固定负例**：

> G92 反例：build/test 绿而业务条件缺失 ⇒ **不得 Complete**；没有 Task 绑定不能冒称指定 Task 已完成。

## 2. 目标行为（S1-a 唯一目标）

**当验收合同为纯工程门禁（`source == "bounded_planning"`，即 objective 未声明任何目标级证据）时，即使全部必需条件通过，也不得判 `Complete`。**

替代处置：`Verdict = Blocked`，`blockerCode = "contract_coverage_insufficient"`，`NextAction` 指向「在本迭代内做**一次有界合同整理**：为 objective 补齐版本化目标级条件与其检查定义，然后重跑验证」。

### 2.1 判定表（实现后必须逐行成立）

| # | 合同 source | 全部必需条件 | 期望裁决 |
|---|---|---|---|
| A | `bounded_planning`（纯门禁） | 全部 passed | **Blocked / `contract_coverage_insufficient`** ← 本卡不可删负例 |
| B | `bounded_planning:objective_evidence` | 全部 passed | **Complete**（行为不变） |
| C | `bounded_planning` | 有 failed | Blocked / `criterion_failed`（**既有分支优先，不被覆盖门改写**） |
| D | `bounded_planning` | 有 pending | Blocked / `check_results_pending`（同上） |
| E | 合同为空 / 无检查定义 | — | 既有 Blocked（`acceptance_contract_missing` / `check_contract_missing`）不变 |
| F | Task-bound 且未达 goal scope | 全部 passed | 既有行为不变（不因本改动提前 Complete 或额外 Block） |

> **优先级纪律**：覆盖门只插入在 `allRequiredPassed && goalScope` 这一个分支**之前**（即所有既有失败/等待/阻塞分支之后），**不得**上移到失败/等待分支之前，以免把「有失败要先修」误判为「合同不足」。
