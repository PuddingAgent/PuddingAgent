## 2. 逐条修复映射

### R1 —— 候选只决定「优先读哪些文件」，不决定「输出什么」

- **旧语义（缺陷）**：Lucene 候选阶段既产出文件路径，也产出索引中的**行文本与行号**，并据此预填去重键 → 索引陈旧即输出不存在的内容；同文件被提前按行去重 → 当前内容中真实存在的其他命中被吞。
- **新语义**：候选阶段**仅产出去重、有序的文件路径集合**；随后按五重准入校验（`File.Exists` / scope 在 `managedDirectory` 内 / 完整 glob 支持 `Keep*.txt` / 扩展名 / 排除目录），准入后与枚举结果合并去重（`processedFiles`），**统一读取当前文件内容**并交由 `RetrievalMatcher` 复核后再输出，行级去重仅在**输出阶段**（`emittedKeys`）兜底。
- **实现**：`Source/PuddingRuntime/Tools/BuiltIns/Search/SearchGrepTool.cs`（候选阶段重写、`IsCandidateAdmissible`、`ManagedGrepAsync` 签名与工作清单）。
- **回归**：`U0R1_StaleIndexLine_NotReturned_When_CurrentContent_NoMatch`、`U0R1_ChangedLine_Returns_Current_Content_Not_Index_Text`、`U0R1_DeletedCandidate_Is_Not_Returned`、`U0R1_NonPureExtensionGlob_Candidate_Is_Filtered`、`U0R1_RenamedCandidate_Returns_Only_Existing_Path`；改写 `ExecuteAsync_Uses_Lucene_Index_When_Available`、`U0S2_CaseSensitive_Same_Contract_On_Candidate_And_Scan`（旧断言锁定的正是被判定为缺陷的旧行为）。

### R2 —— 超时必须可观测，预算必须单次调用统一

- **合同层**：新增 `RetrievalMatchOutcome { NoMatch, Match, Timeout }`；`RetrievalMatcher.TryMatch(line, ct)` 把 `RegexMatchTimeoutException` 映射为 `Timeout`（不吞不抛），已取消 token 抛 `OperationCanceledException`；`IsMatch` 降为兼容层并在 XML 注释声明「超时返回 false，新代码须用 `TryMatch`」。
- **预算层**：`SearchCoreAsync` 入口创建**唯一** `CancellationTokenSource`（可注入 `searchTimeout`，默认 10s），覆盖 Lucene 查询 / 候选准入 / 目录枚举 / 文件扫描全流程；行循环每行先检查取消；正则超时立即停止扫描并映射 `status=timeout`，**绝不落 `no_match`**；调用方取消与内部超时按来源区分处置。
- **回归**：`U0R2_CatastrophicRegex_Bounded_By_SingleCall_Budget_IncludingCandidates`（两条 `^(a+)+$` × `a*32+!` 灾难候选 + 150ms 预算 → `timeout`、非 `no_match`、无 `(no matches)`，实测远小于旧实现 20103ms）、`U0R2_CancelledCallerToken_Propagates_OperationCanceled`；`RetrievalMatcherTests` 中「超时返回 false 即视为正确合同」的用例按任务书**明示改写**为 `TryMatch_RegexTimeout_Returns_Timeout_Not_False`，并补 `IsMatch_CompatLayer_Returns_False_On_RegexTimeout`、`TryMatch_CancelledToken_Throws_OperationCanceled`（16 → 18）。

### R3 —— 覆盖完整性 = 「所有允许路径都真的检查过」

- **新公式**：`coverageComplete = !timedOut && !regexTimedOut && !enumerationTruncated && enumerationErroredDirs == 0 && !scanBudgetExceeded && !maxResultsReached && !totalCapReached && skippedLargeFiles == 0 && errors == 0`。
- **要点**：`MaxErrors` 仅作为**停止阈值**，任何 1 次读取失败即非 `Complete`；子目录枚举异常不再静默 `continue`，改为 `failedDirs++` 参与覆盖判定（与符号链接防循环跳过区分）；`no_match` 仅在 `Complete` 时输出，非 `Complete` 附**恰好一次**覆盖声明。
- **回归**：`U0R3_LockedFile_Is_Not_NoMatch_And_Retryable_After_Release`（`FileShare.None` 独占 → `Truncated` 而非 `no_match`；释放后同 query 重试**仍命中**，不被 exact-retry 抑制）、`U0R3_SingleReadError_Below_Threshold_Is_Not_Complete_Or_NoMatch`、`U0R3_SubdirectoryEnumerationFailure_Declares_Incomplete_Coverage`。

### R4 —— `max_results` 统一作用于合并后结果集

候选与扫描共用 `results.Count` 预算；第 `max_results + 1` 个匹配 → `maxResultsReached=true` 并停止扫描，声明「达到 max_results 上限（N）」；**恰好 N 个且自然结束仍为 `Complete`**（与 U0-S3 口径一致）。`MaxInlineResults` 分页逻辑未改动。回归：`U0R4_MaxResults_Caps_Merged_Output_And_Declares_Truncation`、`U0R4_ExactMaxResults_NaturalCompletion_Is_Complete`、`U0R4_Candidate_And_Scan_Merge_Respect_Shared_MaxResults`。

## 4. 残差与待复核点（如实登记）

1. **glob 语义未完全同一**：枚举侧仍使用 `Directory.GetFiles` 的 Win32 通配符怪癖，候选准入侧使用 `FileSystemName.MatchesSimpleExpression`。方向**安全**（只使候选优先集变窄，被拒候选仍会经枚举路径正常扫描，不产生假阳/假阴），但「同一请求跨后端语义一致」尚未做到字面同一，留 U1 切片统一。
2. **超时重试抑制**：超时现已映射为 `timeout` 状态、不再误登记 `no_match`；但 `SearchAttemptLedger` 对同 key 的 `Timeout` 重试仍有短路提示。该文件不在本次允许写清单内，**留父级/Codex 决策**是否单列切片处理。
3. **环境相关用例**：`U0R3_SubdirectoryEnumerationFailure_*` 依赖 `mklink /J`（无需管理员；非 NTFS 卷以 `Assert.Inconclusive` 表达环境限制），本机 NTFS 实测通过。
4. **既有语义未动**：`skippedLargeFiles > 0` 使覆盖非 `Complete` 沿用既有语义；`MaxInlineResults` 分页逻辑未动。
