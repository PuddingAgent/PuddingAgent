### 错误根因（方法论）

首轮检索**只覆盖了 `WorkspaceTaskSchemaBootstrapper.cs`**（`workspace_tasks` 表自身的 schema），
由此推断「无 `task_dependencies` 表」。**实际情况**：依赖表由**另一个** bootstrapper
（`TaskSchedulingSchemaBootstrapper.cs`）建立，属于**任务调度**模块而非**任务实体**模块。

⇒ 教训：**「某表在某 schema 文件中不存在」不能推出「系统没有该表」**。判定「能力缺失」前，
必须按**领域模块**（此处：任务实体 / 任务调度 / 任务工具 / 前端）分别 grep，而非只查一个落点。

### 修正后仍需建设的部分（缺口确实存在，但范围大幅收窄）

1. **Read 不返回依赖字段**：`manage_tasks get` → `TaskAdminGetResult`（`TaskAdminContracts.cs:159-166`）
   内嵌 `TaskAgentTaskDetail` 仅含 `parent_task_id / is_container / child_task_count / completed_child_count`；
   全部任务工具契约 grep `dependenc` **零命中**。
2. **无依赖图返回**：用户明确要求「看板直接给出链式依赖文本」，当前**无此 action**。
3. **前端零消费**：`Source/PuddingPlatformAdmin/src/pages/workspace-tasks/` 下
   `父任务|parentTask|parent_task|childTask|child_task|dependenc` **全部零命中**；
   依赖 REST 三端点前端**零消费**（`api.ts` 仅消费 auto-dispatch 4 端点 `:3963-:4009`）。

⇒ 结论：**依赖的「底座」已就绪（表 / 契约 / 存储 / 环检测 / 评估 / 调度门控 / REST），
缺的是「可发现性」（Agent 工具契约 + Read 返回 + 依赖图 + 前端）**。

### 1.2 关键辨析：`ParentTaskId` 是「层级」而非「依赖」

- `Source/PuddingCore/Tasks/WorkspaceTaskModels.cs:526` `public string? ParentTaskId { get; init; }`
- 语义确证：`Source/PuddingCoreTests/Tasks/WorkspaceTaskCoreTests.cs:450`
  `WorkspaceTask_ParentTaskId_DefaultsToNull_AndIsSingleLevelPointer` ⇒ **单层指针**

### 2.2 唯一体验缺口

`include_child_summary` 只返回**计数**（`child_task_count` / `completed_child_count`），
**`task_get` 单卡详情不内联子卡列表与各自状态**。要看到子卡状态需两步：
1. `manage_tasks(action=get, task_id=<母卡>)` 拿 `child_task_count`
2. `manage_tasks(action=list, children_of=<母卡>)` 拿子卡列表

⇒ 建议：`task_get` / `manage_tasks(get)` 增加可选参数 `include_children=true`，
内联返回子卡数组（`task_id / title / status / blocker`），一步到位。
