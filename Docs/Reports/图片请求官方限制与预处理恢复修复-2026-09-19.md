日期：2026-09-19。状态：代码、定向自动验证和外部 Core 部署重启完成；真实模型图片功能 smoke 尚未执行。

## 问题与现行约束

此前 `VisionRequestPolicy` 将历史、附件和工具图片累计限制在 8 张，且超限进入通用 LLM API 错误处理。错误消息留在会话中后，下一次请求仍携带原图片，造成连续失败；反复记录 API 错误还可能触发会话熔断。原始证据见[事故诊断](历史图片累计触发8图上限诊断-2026-09-19.md)。

按用户明确要求移除旧产品门槛，并依据当日核对的 [DeepSeek 图像理解官方文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)修订默认策略：

| 维度 | 实现 |
|---|---|
| 图片份数 | 每次实际模型请求最多 600；历史、用户附件、工具输出合计，重复引用也计数 |
| inline 单图 | 编码文件字节最多 32 MiB；按 Base64 padding 精确计算，先压缩再校验 |
| 完整请求体 | DeepSeek 请求最多 48 MiB UTF-8 JSON，包含文字、工具定义、Base64 与 JSON 转义 |
| 图片合计 | 非 file_id 图片文件字节 64 MiB；含 Files 的混合图片合计 200 MiB |
| Files | 保留既有通道与失效重建；单文件 64 MiB |
| 边长 | 14 张以内 8192 px；15 张及以上 4096 px，先统计全请求再准备每张图 |
| token | 沿用版本化 1024/图估计；实际用量以 Provider usage 为准 |

这些是 DeepSeek 官方基线，不表示其他服务商已接受同样的能力合同。模型配置仍可收紧预算。本轮只读取本机 `vision` 字段确认无显式 8 图覆盖，未修改资源池、数据库或运行数据。

## 预处理和错误恢复

`IVisualArtifactPreprocessor` 通过现有 Workspace storage 解析授权制品。请求预算先给每张图分配编码字节额度，保留 Base64 和请求封装空间；图像先调整边长，再按需要降低编码质量/尺寸。最多 12 次本地候选处理，只保存合格的最终派生图，并按原 Artifact、detail、尺寸与字节预算缓存。原图不覆盖。既有安全解码上限保留，无法安全处理的输入返回可读错误。

Responses、Chat Completions、Anthropic 三种网关共用完整请求体检查/重建器；DeepSeek 完整 JSON 超限时扣除文字和工具部分，缩小图片分配并最多构建 4 次，合格后才发送模型 HTTP 请求。当前请求的图片不能靠截断列表通过校验。UI 超过 600 张时整批拒绝；服务端 admission 同样拒绝超限输入。

`VisionPipelineException` 分离内部诊断与用户提示，流式返回稳定 `vision_*` 错误码、`agent.stream.vision_preflight` 位置。Buffered facade 保留视觉错误分类。视觉请求失败不计入 API 熔断；Image Reader 明确返回 `vision_request_limit_exceeded` 状态时，也不计入工具熔断，Agent 能调整读取计划。

`VisionTextContinuation` 只在当前用户输入及当前轮后续消息均不含新图时，允许继续纯文本：历史数量超限时直接在出站请求转为明确“未发送像素”的 Artifact 引用；其他历史图片准备错误仅重试一次。激活后同一轮中新工具图片仍正常发送和计费。canonical 消息、工具 call ID、原图与磁盘历史不修改，也不伪造已看过图片。若当前请求包含新图且无法满足限制，拒绝该请求并返回提示；下一条文字仍能执行。
