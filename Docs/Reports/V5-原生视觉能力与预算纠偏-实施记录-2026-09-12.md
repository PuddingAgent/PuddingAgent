## 1. 背景与目标

主力模型升级为多模态后，视觉能力判定存在双源问题：`DirectLlmClient` 在热目录按 `CapabilityTags.Contains("vision")` 二次判定，而运行配置中两个主力模型缺少 `vision` 标签；`vision` 能力声明与 endpoint 实际合同脱节。

本切片目标：

1. **能力单源化**：视觉能力只来自执行快照（`LlmRouteSnapshot`/`CallerLlmSnapshot`）冻结判定，删除热目录二次判定；Agent Loop 入口 push 冻结快照，`DirectLlmClient` 只读快照，无快照 = fail closed。
2. **能力声明纠偏**：以宿主 shell 真实请求实测两主力模型的视觉字段合同，据实修订 `capabilityTags`。
3. 视觉预算策略（`VisionRequestPolicy`）随快照下发至三个 Gateway。

## 2. 实测证据（已实测，2026-09-12 宿主 shell 真实请求）

### 2.1 字段合同结论

| 路由 | endpoint | `input_image`（data URL） | 备注 |
|---|---|---|---|
| `deepseek/deepseek-flash` | `api.deepseek.com/responses` | **HTTP 200** | 单/双图均正确；双图可区分顺序与数量；`image_url` 为对象或携带 `detail` = 400 |
| `bigmodel/glm-5.3-flash` | `open.bigmodel.cn/api/v1/responses` | **HTTP 200** | baseUrl 含前导空格需 trim；与 DeepSeek 在同一对图片上给出一致且各自具体的描述；`/chat/completions` = 403 |

### 2.2 usage 缺失图像明细

两条路由的 `usage.input_tokens_details` **仅含 `cached_tokens`，无图像 token 明细**——图像用量目前无法从 Provider usage 单独计量，图像预算只能本地估计（与 ADR-088 决策 5「实际 usage 独立计量」存在差距，待后续切片处理）。

### 2.3 能力声明纠偏

据此为两模型在运行配置 `D:/data/config/llm.providers.json` 的 `capabilityTags` 前置加入 `"vision"`（原文件已备份）。此项为**运行配置变更，非代码变更**。
