### 29.1 现象
`dotnet test Source/PuddingWebApiTests/PuddingWebApiTests.csproj --filter "...ImageReader..."` → **exit_code=1**，但**不是测试失败**：
```

```
（另有 MSB3026 警告从第 8 次重试到第 10 次，涉及 PuddingGateway/Host/Platform/Core/MemoryEngine/Runtime 等多个 dll）

### 29.2 根因
- `PuddingAgent (38120)` 就是**正在运行中的本 Agent Core 进程自己**。
- `PuddingWebApiTests` 的 ProjectReference 链**传递依赖可执行项目 `PuddingAgent.csproj`**，构建需覆盖其输出目录 `Source/PuddingAgent/bin/Debug/net10.0/`，而该目录 dll 正被运行中的进程使用 ⇒ 必然 10 次重试后失败。
- 对比：`PuddingCoreTests` / `PuddingRuntimeTests` / `PuddingPlatformTests` **均正常通过**（已是它们不依赖可执行项目）。

### 29.3 规避（已实测有效）
1. 先 `dotnet build Source/PuddingWebApiTests/PuddingWebApiTests.csproj -p:BuildProjectReferences=false --nologo -v q` → **exit_code=0**（只重建测试工程，复用既有依赖产物）
2. 再 `dotnet test <同一 csproj> --filter "..." --no-build --nologo -v q`
- 注意：不能直接 `--no-build` 跑既有 dll —— 既有 `PuddingWebApiTests.dll` mtime=**09-12 17:59**，而 ImageReader 测试文件 mtime=**09-15** ⇒ 旧 dll **不含新测试**，直接跑会得到假证据。

### 29.4 意义
- 这是**自有工作流的结构性摩擦**：Agent 在运行中验收自己的代码，“1. 拿证据”与“2. 进程活着”直接冲突。
- 建议作为平台改进项：构建时对正在运行的 Core 输出目录采用**旁路输出**（如指定 `--output` 到 temp）或提供官方“运行中验收”模式，避免靠人工发现 `-p:BuildProjectReferences=false` 这类绕行手段。

## §38 2026-09-19 03:15 —— 卡 f1d45a15 第 2 项**根治**：cmd 包装下含引号命令被静默破坏

### 38.1 现象与复现
| 路径 | 命令 | 结果 |
|---|---|---|
| `terminal_start`（cmd.exe /d /s /c） | `echo "a b"` \| ` findstr "a"` | ❌ **exit_code=1 + 零输出**（重定向文件 0 字节） |
| `shell`（pwsh） | 同一命令 | ✅ exit=0，输出 `a b` |

### 38.2 二分实验（定位触发条件）
| 变体 | 结果 |
|---|---|
| 无引号 + 管道 | ✅ 成功（`a b`） |
| **有引号**（无管道） | ⚠️ 输出 `\"a b\"` ⇒ **引号被转义成 `\"`** |
| 有引号 + 管道 | ❌ **完全无输出** |
⇒ **触发条件是引号，不是管道**。

### 38.3 根因
`Source/PuddingRuntime/Services/TerminalProcessManager.cs` 的 Windows 分支把整条命令作为单个
`ProcessStartInfo.ArgumentList` 项传入；.NET 在 Windows 按 **CRT/MSVCRT 规则**转义 ⇒ 内部 `"` → `\"`；
而 **cmd.exe 只认 `""` / `^"`，不认 `\"`** ⇒ 命令被静默破坏。
（代码里已有 `/d /s /c`，但 `/s` 只剥离**最外层**引号，救不了已被转义的内部引号。）

### 38.4 修复
```csharp
psi.Arguments = "/d /s /c \"" + command + "\"";
```
用 `Arguments`（原样传递、.NET 不转义）+ `/s`（剥离最外层引号、内部引号原样）+ `/d`（跳过 AutoRun）。

### 38.5 验证（三层）
1. **独立对照**（shell/pwsh）：`cmd /d /s /c 'echo "a b" | findstr "a"'` ⇒ **exit=0 且输出正确**
2. **新增回归测试** `QuotedPipeCommand_SurvivesCmdWrapper`（断言 exit=0 + stdout 含 payload）
3. **回归**：终端三测试类 `49/49`；`TerminalProcessManagerOutputDrainTests` **2/2**
⇒ commit `5d799aaa`

### 38.6 一个值得记录的发现
原 `TerminalProcessManagerOutputDrainTests` 的注释白纸黑字写着：
> *“The command travels through `cmd /d /s /c` via `ProcessStartInfo.ArgumentList`, **where embedded quotes get mangled** … Therefore use a quote-free inline cmd command”*

⇒ **这个 bug 此前被发现了，但当时选择了「绕开」而非「根治」**。本次改为根治，并更新该注释 + 加回归锁。
⇒ **教训**：“绕开”会在代码里留下一句“此处已知损坏”的注释，但**不会阻止下一个人再次踩坑** —— 要么修，要么在卡上登记为显式债。
