### 8.4 新登记缺口（本卡范围外，另立卡）

**G9 · 目标合同覆盖不足（业务误完成）**
- 现象：显式 Task 目标未在 admission 时解析并绑定权威任务；验收条件与依赖版本未冻结入合同；纯回归门禁替代了目标级证明。
- 期望断言：**build/test 全绿但 G92-1 未通过或 Task 未完成时，Goal 不得宣称原目标完成**；独立 Goal 可无步骤，但**必须**有充分目标条件。
- 完成门槛：合同覆盖校验 + 上述回归用例。

**G10 · 等待期不得反复调用模型**
- 现象：检查 `pending` / 依赖不可用期间反复产生相同续行与全文汇报（实测第 9–14 轮占全部输入 57.0%）。
- 期望断言：等待期间**无周期性 LLM 调用**；恢复后**恰好一次**有效续行；每轮须说明新增证据或义务变化。
- 完成门槛：pending/依赖不可用持久化为等待 + 事件唤醒 + 回归断言。

### 8.5 代理侧补充证据（供 P0「先恢复依赖与认领链」采用）

### 8.6 B1 影响半径扩大（**实测更正**）与一次失败的委派

原记载「B1 只阻塞 shell/terminal」**不准确**。实测（2026-09-17T18:54+08:00）：

| 工具 | 目标 | 结果 |
|---|---|---|
| `terminal_start` / `shell` | 任意 | ❌ 被 `approval_review_profile_not_configured` 阻塞 |
| `file_write` | **工作区之外**（如 agent 私有 `D:\data\agents\<id>\goal.md`） | ❌ **同样被阻塞** |
| `file_write` / `file_patch` | **工作区内**（`Docs/`、`temp/`） | ✅ 可用 |
| `goal_update` / `manage_tasks` / `save_memory` | 专用工具 | ✅ 可用 |

**失败委派**：子代理 `sub-14d18d05`（goal.md 归档）因 `file_write` 命中同一依赖而 `failed`，
`resumable=false`，`tool_failure_count=4`，`tool_output_chars=703109` —— **烧掉大量上下文且零产出**。

⇒ 三条派生纪律：
1. **派委派前先校目标路径是否在工作区内**；需写工作区外路径的任务在 B1 未解除前**直接判为阻塞，不得派**。
2. **goal.md（26.7 KB，超 `goal_read` 16 KB 上限）的字节级归档在 B1 解除前无法完成**：
   skill `oversized-goalmd-archival-and-slim-down` 依赖的 `shell` 与 `file_write` 双双不可用。
3. **已知可行的工作区内的替代路径**（待专用预算轮执行）：`file_read` 读全文（工作区外读是否放行待验）
   → `file_write` 写入仓库内被 gitignore 的 `memory/` 作为归档 → `goal_update(content_base64)` 覆盖为精简版。
   不得为了「完成归档」而做**未留回滚点的压缩重写**。

**结构性缺陷（单点耦合）**：写**工作区外**文件被判为「高风险」，与执行通道共用同一审批依赖
⇒ **Agent 自身的长期状态维护（goal.md）与执行能力共用一个故障点**。已另立卡跟踪。
