### 5.3 标准 4 的定性（**未达成**，需裁决）

指纹的真实来源：

```
GoalAcceptanceContractPlanner.cs:151-156
/// 输入指纹取绑定的 Plan 指纹（工作树/计划变化即失效）；缺失时退化为 epoch+objective 作用域值，
/// 此时不宣称能检测内容变化，但仍是稳定身份（不会把不同轮次的结果混为一谈）。
private static string ResolveInputFingerprint(string? planFingerprint, int activationEpoch, int objectiveVersion)
    => string.IsNullOrWhiteSpace(planFingerprint) ? $"epoch:{activationEpoch}:objective:{objectiveVersion}" : planFingerprint.Trim();
```

- **standalone Goal**：指纹 = `epoch:{e}:objective:{v}` ⇒ **代码自述不检测内容变化**。实测后果：iter5–iter14 十轮迭代仅产出 10–12 条检查记录，旧失败结论被反复复用直至熔断（缺陷 `e53f22c1`）。

- 可确证的一半：**检查定义变化**（`definitionHash`）、**目标版本变化**（`objectiveVersion`）、**绑定计划变化**（`planFingerprint`）均使旧结果失效；**无关变化有依据复用**（`dedup_key` 命中即 `continue`）也成立。

⇒ 「**相关工作树变化使旧绿灯失效**」当前**既无实现、也无证据**。裁决项：
① 实现工作树输入指纹（`git HEAD` + 受影响项目 dirty 哈希）；或
② 明确该标准仅约束绑定 Plan 的 Goal，并为 standalone Goal 显式声明「不检测内容变化」。
