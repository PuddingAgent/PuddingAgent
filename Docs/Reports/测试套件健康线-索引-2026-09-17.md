## 四、★ 三条方法论（本环境硬经验）

1. **`--artifacts-path` 下的任何失败清单都必须先用默认布局复核** —— 它改变 `AppContext.BaseDirectory` 的层级形状，凡按 bin 相对路径取数据的测试都会假失败（本会话已证伪 3 例 + 1 个整夹具族共 76 处）。
2. **`exit code 1` ≠ 被门禁拒绝** —— 先读重定向日志；有内容就说明命令跑过（`dotnet test` 有失败用例即返回 1）。
   真门禁拒绝有两种明确文案：`Runtime approval required for high-risk tool …` / `High-risk tool 'X' is waiting for the approval review dependency (reasonCode=approval_review_profile_not_configured)`。
3. **门禁是「逐调用间歇」** —— `shell` 与 `terminal_start` 互为等价工具；两者同时不可用时应改为产出**无需命令**的交付物（文档 / 证据复核 / 记忆维护），不要空转或盲目重试。
