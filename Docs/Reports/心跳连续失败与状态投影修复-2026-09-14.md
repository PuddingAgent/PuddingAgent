# 心跳连续失败与无回复状态投影修复（2026-09-14）

## 事实与根因

会话 `206a9b48ec904ebb93e7541131fbb835`，Agent `default.global_general-assistant.6a8`。只读 SQLite 及系统日志对齐显示：

| 本地时间 | Command Id | 来源 | 执行结果 |
| --- | --- | --- | --- |
| 12:42（12:52 开始执行） | 1997 | 用户带图消息 | failed |
| 13:51 | 1998 | heartbeat | failed，3.7 秒 |
| 14:52 | 1999 | heartbeat | failed，2.7 秒 |
| 15:52 | 2000 | heartbeat | failed，2.4 秒 |
| 16:53 | 2001 | heartbeat | failed，2.1 秒 |
| 17:54 | 2002 | heartbeat | failed，1.9 秒 |
| 18:21 | 2003 | feishu 文本 | failed，4.0 秒 |
| 19:22 | 2004 | heartbeat | failed，2.9 秒 |

这八轮 canonical `turn.failed` 均包含 `LLM 调用失败: Visual inputs require a workspace and a vision-capable route.`，`reply=null`。不是心跳未产生，也不是 Agent 已经完成工作但没有报告。

第一条图片 `vision-a55fa2f2b97e4bbeb3252fbef05d7f18` 位于 ChatMessages 9128，随后进入历史上下文。原 Core PID 2124 自 9/13 22:55 运行，加载的 PuddingCore.dll 为 9/13 08:46 制品。当前源码 ResponsesLlmGateway 已有文本路由无 VisualArtifactResolver 时不把用户图像部件送入视觉 Planner 的处理，但旧进程未加载。未修改模型能力标签，不宣称文本路由能读图；图片与 canonical 历史保留。

另一个独立断点：AgentConversationProjectionService 只从 ChatMessages 构造已完成消息。没有回复的失败轮次无法显示终态；MessageList/types 又把 heartbeat 强制设为 success，MessageRow 只显示提示词。

## 修复

- 部署当前 Core，新增流式回归：历史用户图片 + 后续文本 heartbeat，在文本路由仍发出请求并收到响应；保留原视觉路由解析失败时 fail-closed 的测试。
- ConversationMessageView 增加非持久化 TurnOutcome，按当前可见 turnId 从 canonical terminal events 投影 status/errorCode/errorMessage。无回复也显示状态，不伪造持久化 Agent 文本、不修改数据库结构。
- MessageList 透传失败/取消；普通无回复消息显示错误，心跳保留原提示词并显示“执行失败”与告警。memo 纳入错误内容变化。

## 验证

ResponsesLlmGateway 定向 40/40；ConversationTurnOutcome 3/3；Core 构建 0 errors。前端、部署和页面验收结果在本节后续补充。
