## 一、问题（已取证）

`Source/PuddingWebApiTests/CustomWebApplicationFactory.cs` 当前：

```csharp
_platformConnection = new SqliteConnection("Data Source=:memory:");
_platformConnection.Open();
services.AddSingleton(_platformConnection);                  // ← 全进程共用一条连接
services.AddDbContextFactory<PlatformDbContext>(options =>
{
    options.UseSqlite(_platformConnection)                    // ← 所有 DbContext 都挂这条连接
           .ConfigureWarnings(w => w.Ignore(RelationalEventId.AmbientTransactionWarning));
}, ServiceLifetime.Singleton);
```

同时夹具**只移除 6 个**后台服务，而注册表显示 **≥15 个仍在测试宿主内运行**（实测日志证明
`ConversationProjectionWorker` / `TaskAutoDispatch` / `HeartbeatOrchestrator` / `SessionChunkBackfill` /
`RetentionPruning` / `MCP` / `ConnectorHost` 均在跑）。

⇒ **「单例连接 + 后台服务与测试请求并发使用同一连接」** 触发：

```
Microsoft.Data.Sqlite.SqliteException (0x80004005):
  SQLite Error 5: 'unable to delete/modify user-function due to active statements'
   at SqliteConnection.CreateFunctionCore(…)                 ← EF 初始化 SqliteRelationalConnection
   at …SqliteRelationalConnection.InitializeDbConnection(…)
   at Microsoft.EntityFrameworkCore.DbContext.get_DbContextDependencies()
```

⇒ 请求 500；且**失败集合随轮次漂移**（实测全量六轮：5 / 7 / 6 / 4 / 9 / 6）。

## 二、⚠️ 关键技术要点（**先看这里，否则改错**）

**不能简单地把连接改成「每个 DbContext 一条 `Data Source=:memory:`」** ——
SQLite 的 `:memory:` 是**连接私有库**：每条新连接都会得到一个**全新的空库**，
测试会因「表不存在」而**全面崩掉**。

正确做法是改用 **共享缓存内存库 URI**，让多条连接访问**同一个内存库**：

```
Data Source=file:<唯一名>?mode=memory&cache=shared
```

（要求：至少有一条连接**全程保持打开**作为 keep-alive，否则内存库在最后一条连接关闭时被销毁。）

## 三、建议改法（草案 diff）

```diff
--- a/Source/PuddingWebApiTests/CustomWebApplicationFactory.cs
+++ b/Source/PuddingWebApiTests/CustomWebApplicationFactory.cs
@@
     private SqliteConnection? _platformConnection;
+    private readonly string _sharedDbName = $"file:webapitests-{Guid.NewGuid():N}?mode=memory&cache=shared";
     private readonly string? _previousDataRoot;
     private readonly string _dataRoot;
@@
-            _platformConnection = new SqliteConnection("Data Source=:memory:");
+            // keep-alive：独占一条连接持有共享缓存内存库，直到 Dispose
+            _platformConnection = new SqliteConnection($"Data Source={_sharedDbName}");
             _platformConnection.Open();
 
             services.AddSingleton(_platformConnection);
 
             services.AddDbContextFactory<PlatformDbContext>(options =>
             {
-                options.UseSqlite(_platformConnection)
+                // 每个 DbContext 打开自己的连接（连接串形式），彼此不再争用同一条连接上的语句
+                options.UseSqlite($"Data Source={_sharedDbName}")
                        .ConfigureWarnings(w => w.Ignore(RelationalEventId.AmbientTransactionWarning));
-            }, ServiceLifetime.Singleton);
+            });   // 不再显式声明 Singleton 生命周期（交由默认）
```

**配套注意**：
1. `CreateHost` 中已有的 `context.Database.EnsureCreated()` 仍然有效（走共享缓存库）；
2. `Dispose` 中 `_platformConnection?.Dispose()` 仍需保留（它负责销毁内存库）；
3. 若某些测试依赖「同一事务跨请求可见」，改造后语义可能变化，需复跑确认；
4. 若改造后仍偶发 Error 5，则说明还有**同一连接内的长生命周期语句**（需另查 `ExecuteReader` 未释放点）。

## 四、可选叠加项（按实验证据，**优先级低于三**）

实验 F（2026-09-18 08:33）显示：**只关 `TaskAutoDispatch` 不产生新增失败**（失败 6，名单全为已知项）；
而实验 E（同时关 `GoalRuns` + `TaskAutoDispatch`）失败升至 **9** 且**新增 2 项** ⇒
**不要关闭 `GoalRuns`**（有 WebApi 用例依赖该 Worker）。

因此若需进一步降噪，可**单独**追加：

```csharp
builder.UseSetting("TaskAutoDispatch:Enabled", "false");
```

（环境变量等价写法：`set TaskAutoDispatch__Enabled=false`，已实测生效。）
