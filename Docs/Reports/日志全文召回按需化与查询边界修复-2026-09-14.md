## 2. 显式查询：先缩小范围，再取命中

提交 `95a0cd3`，复用 `query_session_logs` 的 `action=grep, fts=true`，没有增加平行工具或辅助模型。

| 位置 | 实现与边界 |
|---|---|
| `RawSessionLogService.Fts.cs` | 按 workspace、agent、可选 session 从 ConversationCatalogs 选择授权会话，再枚举指定日期的 Markdown 分片；不扫描 Agent 全部历史 |
| `IFullTextSearchEngine` / `LuceneSearchEngine` | 新增 `FullTextSearchScope`，允许路径与正文查询共同进入 Lucene BooleanQuery，在 TopK 前过滤，避免其他会话高分命中占满候选 |
| `QuerySessionLogsTool` | 传递原先遗漏的 session 与 regex 参数；显示查询状态、有效日期、覆盖范围、历史属性与定位说明 |

查询默认为最近7天，单次最多31天（含首尾）；可明确指定任意历史日期。这个上限约束单次检索，不是只保留31天历史。日期必须是 `yyyy-MM-dd`；`day` 与范围参数互斥，反向或过长范围明确拒绝。普通文本查询最长2048字符，使用 Lucene literal escaping，FTS 不接受正则语义。

会话和单日文件枚举各设置512项边界；超范围应缩小会话/日期或使用 canonical 消息检索。最多20条命中，每条正文最多320字符加省略号；匹配结果的序列化预算6000字符，不返回完整文件正文。`hasMore` 提示未覆盖候选/日期或预算截断。

所选日期索引每次使用既有增量构建检查更新，沿用稳定索引目录，不因旧索引存在而永远读取旧内容。Linked CancellationToken 提供10秒协作取消，并在构建/搜索后检查取消状态；这不是可强制中断任意同步 I/O 的硬超时保证。大分片的首次建索引仍可能较慢，本次不宣称已完成 GB 规模压力验收。

## 3. 命中语义与失败语义

- `evidenceKind=historical_discussion`、`decisionStatus=unverified`：只证明找到讨论，不证明是最终或当前有效结论。
- `coverage=indexed_markdown`：仅覆盖相应日期可用的私人 Markdown 日志；部分结果使用 `partial`，不冒充 canonical 聊天全量覆盖。
- `eventType=markdown_line`，`sequenceNum` 在该模式下是文件行号；`evidenceRef=session-log-fts:{day}:{session}:{line}`。不要把行号当作数据库事件序号。
- `no_match` 与 `contract_error`、`unavailable`、`timeout`、`scope_too_large` 分离；索引失败不再伪装成“没有匹配”。这些是工具 JSON 中的领域状态，调用方应读取 `status/error`，不能只看外层调用成功。
- 要认定决策仍需打开附近对话、检查后续修订，并比对当前 Memory/权威正文；本次没有实现自动裁决追踪。
