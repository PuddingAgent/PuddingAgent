## 2. 侦察结论（父级已独立核验的三条）

- **`GoalSettlementWorker.cs:85` 是唯一合同派生闸**：`if (capsule.Criteria.Count == 0) { … planner.EnsureContractAsync(…) }`；`GoalAcceptanceContractPlanner.cs:44-53` 二次拒绝重写 ⇒ **合同整理通道当前无执行者**（verifier 的 `NextAction` 只是文案）。**父级已读码确认。**
- **`GoalEvidenceCapsule` 无「迭代输出文本」载体**（字段仅 Criteria/Checks/EvidenceRefs/AcceptanceContractSource 等）⇒ 若要断言输出文本，需新增字段 + 填充 + 读取三处接线。**父级已读码确认。**
- **实测缺陷（R-1）**：`GoalAcceptanceContractEntity.cs:47` 为 `[Required, MaxLength(32), Column("source")]`，而 `GoalAcceptanceContractSources.BoundedPlanningWithObjectiveEvidence` = `"bounded_planning:objective_evidence"` 长 **35** ⇒ **超长 3 字符**；实体注释 `bounded_planning | planner | repair` 亦与真实取值不符。SQLite 不强制长度故暂未暴露，属**潜在数据契约缺陷**。

## 3. 三个裁决点（含推荐与分歧）

### 3.1 文本断言的判据来源
| 方案 | 形态 | 与设计 §11 的一致性 |
|---|---|---|
**A（本 Agent 推荐）** | 断言**迭代输出文本**：确定性 `contains` 判定，期望值来自**合同侧**（objective/合同），事实源为不可变的 turn 转录 | ✅ §11「只输出指定文本 ⇒ 一轮完成、**零工具调用**、零 build/test」 |
B（侦察报告推荐） | 断言**命名工件内容**：复用 file-evidence 全链（`GoalCheckInputIdentity` + `EvaluateFileEvidence`） | ⚠️ 需 Agent 写文件 ⇒ **违反「零工具调用」** |

**分歧说明（本 Agent 不同意侦察报告的 B）**：报告把 A 判定为「退化为模型自证」。本 Agent 认为该判定不成立 ——
**只要期望值来自合同侧（objective/合同）而非模型自述，断言输出文本就是可核验证据**；
「自证」的判定标准应是**义务是否由被验证方自己提供**（ADR-092 决策 6「模型不能删义务自证成功」），
而不是「证据载体是文本还是文件」。A 的代价是 3 处接线，收益是**与 §11 语义一致**。
> 无论选 A 还是 B，**期望文本必须进入 `DefinitionHash` 载荷**（`GoalCheckDefinitionRegistry.cs:57-66`），否则旧的绿灯不会失效。

### 3.2 版本化表示
推荐：**新增受控 check kind**（如 `text_assertion`）+ 复用既有 `GoalCriterion` 结构；
`GoalCheckSpec.Scope` 与 dedup key 轴**不动**（K2）。**不得**复用 `Semantic` 类型 ——
`GoalCheckEvidencePolicy.cs:200-201` 只要求「证据非空」，等价于模型自证，违反决策 6。

### 3.3 合同整理通道形态
推荐 **通道 A**：`GoalSettlementWorker.cs:85` 的闸放宽为 `Criteria.Count == 0 || IsEngineeringGatesOnly`，
并加**一次性**闸（复用 `ContractVersion` 与 `GoalSettlementStore.cs:1116-1160` 的既有「一次性 + needs_user」范式）。
- 优点：零新增接口、零前端改动、单点可回滚。
- **通道 B（Agent 侧合同工具）被排除**：与 §14.1 用户决定（不给 Agent 提供 Goal 工具）直接冲突。
- 与 §3.1 的耦合：通道 A 允许在**纯工程门禁合同**上追加目标级条件；若 §3.1 选 A，追加的条件即可为文本断言 ⇒ 闭环。

1. **【不可删反例】**一行自然语言目标不再被永久拦截：要么产出可完成的文本断言合同，要么经通道 A 完成一次合同整理并最终 `Complete` —— **必须真实回归证据**。
2. 设计 §11「只输出指定文本 ⇒ 一轮完成、零工具调用、零 build/test、无需 Task/Plan」有**可执行证据**。
3. S1-a 判定表 A 用例（`GoalContractCoverageGateTests`）**预期不得修改**且保持通过。
4. `GoalVerificationScopes` / `GoalCheckSpec.Scope` / `goal_check_records.dedup_key` 不变。
5. 期望文本变更 ⇒ 旧检查结果失效（DefinitionHash 载荷证明）。
