## 2. 已交付代码

### 2.1 Agent 状态查询：00bd0af

文件：Source/PuddingPlatform/Services/AgentChat/AgentRunProjectionService.cs；回归 Source/PuddingPlatformTests/Services/AgentRunProjectionQueryTests.cs。

原来为每个会话取最新事件、最新生命周期事件时使用 GroupBy + OrderByDescending + First，EF 查询需要按会话排列大量历史实体，包含本次状态投影不需要的大 payload。dotnet-stack 显示多个状态请求同时停留在 SQLite 读取和 ToDictionaryAsync。

改为每个可见 Agent 主会话执行有界索引查询，仅选择 Sequence/Type/RunId/OccurredAt。已有 ix_ce_seq(conversation_id, sequence) 支持倒序取 1 条；最新事件已是生命周期事件时直接复用，否则再取最新生命周期事件。先去重 conversationId，空列表不访问数据库；不增加状态缓存或表结构。

在当前数据上，等价 ROW_NUMBER 查询形态 2,740.902 ms，索引 LIMIT 1 为 0.341 ms，返回同一 sequence=849856。这是查询形态基准，不是 HTTP P95 或整个方法的加速倍数。测试验证独立会话、重复 ID、空列表、取消、最新游标与生命周期分离，并约束 SQL 不携带 Payload/ROW_NUMBER。

### 2.2 分阶段性能记录：ddc25a2

上下文各异步层记录 `[ContextPipeline:Stage] session=... stage=... durationMs=...`，同时附加到现有 agent.context.assemble 指标的 stage.<name>.duration_ms，不另建指标写入链。异常路径也保存已执行阶段。历史加载分别记录 active_summaries、compaction_lock、canonical transcript sync、active_messages、jsonl。

不改变提示正文、缓存键、组装顺序、压缩触发或 Token 上限；保留 canonical transcript 同步后再从 memory DB 重建的正确性边界。最终样本摘要 29 ms、锁等待 0 ms、正文读取等可从阶段日志复核；总耗时还包含未包裹的同步计算和既有观测开销，不能要求各阶段简单相加等于总值。

### 2.3 全文索引持久身份与路径：8ddd0d3

文件：Source/PuddingFullTextIndex/Infrastructure/Search/LuceneSearchEngine.cs、Source/PuddingHost/Extensions/PuddingServiceCollectionExtensions.Runtime.cs、Source/PuddingRuntime/Services/AgentLogRecallService.cs；测试位于 FullTextIndexTests 与 AgentLogRecallServiceTests。

根因一：GetIndexDirectoryPath 使用 String.GetHashCode(StringComparison.OrdinalIgnoreCase)。该值随进程变化，每次 Core 重启得到新目录，HasIndex=false，默认助手重新索引约 92 个日志 Markdown（约 4 MB）及日报。系统 Temp 的索引目录修改时间与每次冷调用结束时间一致，属于重复工作和缓存目录积累。

根因二：Host 直接注册默认 FullTextIndexOptions，其路径只读 PUDDING_DATA_ROOT 环境变量，Desktop 配置的 DataRoot 并不依赖该变量，因此实际回退到系统 Temp。存储管理却查看 DataRoot/fulltext-index，出现归属不一致。

修复：完整规范化路径、去尾分隔符、按引擎既有 Windows 大小写规则归一后，以 SHA-256 生成 64 位十六进制目录名；Host 从已解析的 PuddingDataPaths.DataRoot 显式配置索引根。默认助手当前复用 D:/data/fulltext-index 下 88fc1372... 与 96d2b5bc... 两个目录，PID33388 与 PID29400 名称相同，不随重启新增。

持久化后必须防止陈旧召回：AgentLogRecallService 每次搜索前调用引擎已有 BuildIndexAsync，由它按时间戳增量更新、串行目录写入和删除文件清理。不能只在 HasIndex=false 时构建，否则首次索引之后新增日志永远不可见。测试验证关闭引擎重开可搜索，以及只增量索引新增文件并召回新词。

没有迁移或删除无法可靠映射的旧随机缓存目录；首次切换需要一次重建。旧缓存回收应由存储维护单独登记所有权和清理范围，不扫描、猜测或迁移私人正文。没有增加旧随机键兼容层。
