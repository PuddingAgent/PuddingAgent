# MSBuild 非法输出路径缓存修复

日期：2026-09-12；结果：截图中的两个 MSB3541 已复现并修复，两个受影响项目构建通过。

## 原因

Visual Studio 报错对象为 `PuddingCodeIntelligence` 和 `PuddingFullTextIndex`，错误发生在 MSBuild 的 `FindUnderPath` 处理 `Files` 参数时。实际读取的历史构建记录位于：

- `Source/PuddingCodeIntelligence/obj/Debug/net10.0/PuddingCodeIntelligence.csproj.FileListAbsolute.txt`
- `Source/PuddingFullTextIndex/obj/Debug/net10.0/PuddingFullTextIndex.csproj.FileListAbsolute.txt`

记录包含 `E:\github\AgentNetworkPlan\PuddingAgent"E:\github\AgentNetworkPlan\PuddingAgent\temp\...` 这样的非法路径：中间有字面双引号，仓库根路径重复出现。非法条目关联历史 `temp/preboot-build-0903`、`temp/buildout-0903`、`temp/testout/preboot-0903` 三组输出。

这个形态说明历史输出参数/记录带入了字面引号；本轮未追溯首次产生它的具体终端命令。当前项目文件没有写死这些目录，`dev-up.py` 的 `backend_build_command` 使用参数数组生成 OutDir，未发现需要修改的同类引号拼接。错误来自持久化的增量清单，不是截图中 DLL 或 Jieba 资源文件本身的路径配置错误。

## 修复范围

扫描 `Source/*/obj` 下 49 份 `*.FileListAbsolute.txt`，仅上述两份含非法双引号。

| 项目 | 移除非法记录 | 修复时保留合法记录 |
|---|---:|---:|
| PuddingCodeIntelligence | 100 | 1230 |
| PuddingFullTextIndex | 50 | 726 |

先备份原始字节并记录 SHA-256，再移除已核验历史目录中的含引号条目；写入前检查清单未被其他构建改动，随后原子替换并检查结果。未清空 obj、未删除输出文件、未修改 NuGet 缓存或运行数据，也未给业务代码/全局构建目标增加清洗兼容层。

本机备份和复现/构建日志保留在忽略目录 `temp/msbuild-filelist-repair-20260912/`，包括两份 `.FileListAbsolute.before.txt` 和 `repair-manifest.json`。这些机器相关缓存与临时诊断脚本不提交到仓库。

## 验证

使用本机 `C:/Program Files/Microsoft Visual Studio/18/Community/MSBuild/Current/Bin/MSBuild.exe`，不是只用不同运行时的 dotnet MSBuild 代替 IDE 验证。

1. 修复前：只读取清单并执行 `FindUnderPath` 的临时探针，在两个项目上分别复现相同 MSB3541、相同首个非法路径。
2. 修复后：同一探针均成功，读取的历史条目不再触发非法路径异常。
3. 两个实际 csproj 依次执行 `/t:Build /m:1 /nr:false`，不 restore；输出隔离至仓库 temp，均退出 0。CodeIntelligence 无警告；FullTextIndex 保留两个既有 NuGet 审计警告 NU1903/NU1904，本次未升级依赖。
4. 确认隔离目录存在两份项目 DLL 和 `Resources/char_state_tab.json`；重新检查49份清单，含非法双引号的清单数为0。

本次没有构建整个解决方案或操作 Visual Studio UI；上述验证覆盖截图中两个项目的真实构建和原始错误。IDE 旧错误列表若仍显示上次结果，重新执行生成即可刷新结果。

## 防止复发

OutDir 应作为一个完整参数传入，目录分隔符可使用 `/`，引号只用于 shell 参数边界，不应成为属性值的一部分。Python `subprocess` 使用参数列表时不手工加入引号；历史缓存坏掉时优先备份并定点修复清单，不禁用 `IncrementalClean` 或修改 SDK targets。

通用诊断步骤与 PowerShell 示例见 [How-Debuge.md](../../How-Debuge.md)。
