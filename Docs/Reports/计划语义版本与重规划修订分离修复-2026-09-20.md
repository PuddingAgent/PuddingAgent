# 计划语义版本与重规划修订分离修复

## 事故与直接根因

用户报错：`task_execution_plan_version_unsupported: plan=tp-561ea9576451d093f33057113865f791 version=3`。
该计划属于任务 `06898d5dfe004c69ab6d5baf18b2674a`（Scheduler 遥测降噪），Goal 为 `tg-59f90cc6ee8713427f3c7bc5130d68ab`。

编译器与 `TaskGoalDispatchTransactionStore.AddExecutionPlan` 均写入语义版本 2；绑定的冻结 `execution_window_snapshot_json.executionPlanVersion` 也是 2。`GoalSettlementStore.TryReplanBoundPlan` 却执行 `PlanVersion++`，下一命令在 `ExecutionCommandReader.MapAsync` 的严格版本校验处失败。期间再次结算又能触发 replan，使错误持续。现场读到版本 4，随后到 7；这不是模型选择或需要用户重新提交任务的问题。

经正常 Goal control API 暂停精确 Goal，暂停回执为 25/32 已消费、activationEpoch=2、aggregateVersion=51；已用费用与轮数保留。原始绑定 fingerprint 为 `63e878e6f81bdabd8d34a95247719088b42ccaac4933624135d5d2e2a31752e9`。

## 源码修复

- `TaskPlanRunEntity` 新增 `plan_revision`（默认 1）；`plan_version` 明确定义为不可因调度重试改变的编译语义。
- `TaskGoalDispatchTransactionStore` 新计划写 revision=1。现有 replan 只递增 revision，并在 `goal.circuit_opened` 中同时输出 version/revision。
- `GoalQueryService` 和 `/goals/{id}/steps` 分别输出两个字段。plan_id 唯一，不再以语义版本排序来选修订。
- `TaskPlanningSchemaBootstrapper` 幂等补列，未知旧记录保持原语义值。Reader 的严格语义版本门禁、任务版本、reservation fence、冻结 fingerprint、节点与预算检查均保留。
- 本修复的 replan 只改变节点调度状态，未改变冻结合同；不伪造新 fingerprint，不把修订号当 fence。完整 Task 侧合同重规划、Goal 去步骤引擎仍属于后续 ADR-092 实施。

## 回归证据

先复现失败：`SameFingerprint_WithReadyAlternativeUnit_ReplansOnceAndStaysActive` 从语义版本 2 播种，修复前实际得到 3，测试失败。

修复后 .NET 定向 **77/77** 通过：GoalSettlementAcceptanceRegressionTests、GoalContinuationTests、TaskPlanningSchemaBootstrapperTests、TaskExecutionPlanCompilerTests、TaskGoalDispatchTransactionStoreTests、GoalTodoQueryTests。覆盖修订 1→2、8→9 时语义仍为 2，真实 Reader 可读取下次命令；同终态重放不增加修订/结算/输入 token；旧语义 1 和未知 3/99 继续拒绝；旧库补列与二次启动不改历史语义；API 明确区分 version/revision。

`python -B TestScripts/test_repair_task_plan_semantic_version.py` **8/8** 通过：只改两个版本字段、幂等、旧/未知语义与不完整历史拒绝、编译绑定不一致、活跃 Goal/命令、缺预算、唯一身份冲突、写入 CAS。

## 既有计划恢复规则

使用一次性运维脚本 `TestScripts/repair-task-plan-semantic-version.py`，不在产品请求路径添加兼容层。显式指定 plan-id，读取冻结 binding 的版本 2/schema 1、task/compile-version 幂等键、fingerprint、有效 typed work-unit 预算，并要求 canonical replan 事件恰好证明版本 3..当前值的每一次增量。

应用前要求 Core 停止、Goal 已暂停或终态、没有在途命令、没有同编译身份冲突；事务内保存行级 before-image，再 CAS 只改 `plan_version`/`plan_revision`。不改 Goal/Task/节点状态、成本、轮数、binding、命令或历史事件。不满足证明的记录拒绝修改，仍须真正重新编译。before-image 是本次字段修复备份，不冒充完整数据库备份。

目标计划的只读预检结果：可恢复为语义版本 **2**、修订号 **6**（5 次 replan）。其他已失败历史计划本次不复活。
