## 四、遇到的问题与教训

1. **shell 引号转义陷阱**：嵌套 PowerShell 引号经工具层传递被吞，反复 exit 1。→ 对策：复杂逻辑写成 `.ps1` 脚本文件再执行。
2. **运行中文件独占锁**：日志/数据库无法直接读。→ 对策：`FileStream + FileShare.ReadWrite` 共享模式；SQLite 无法加载时退化为字节级搜索（ASCII 表名在 sqlite_master 页明文存储）。
3. **PS 5.1 加载不了 net10 程序集**：不能用 Desktop bin 的 Microsoft.Data.Sqlite 做临时查询。→ 记入限制。
4. **子代理委派规律**（三次失败换来）：委派写代码可靠，验证环节亲自做；长命令必须走 terminal 而非 30s shell；任务书必须"可枚举、有锚点、禁开放式推理"。
5. **待查异常：重启后无 EmbeddingHook 日志**。12:52 重启至今日志无 `EmbedPendingChapters` 入口记录。候选解释：① hook 在运行二进制中的注册/触发路径存疑；② 触发条件（待嵌入章节查询）提前返回；③ 日志级别/接收器差异。需专项排查。
6. **引导信号服务默认自启**：`PuddingDesktopBootstrapConfig.Enabled` 默认 `true`，且 coordinator 启动路径自动拉起轮询。用户要求改为**手动触发 API**（见下一步 #1）。
7. **platform.db 膨胀**：已达 2.54GB。用户指示：该库只保留会话运行索引，不保存完整会话细节。需专项瘦身方案。
8. **鸡生蛋问题**：信号服务/任何 Desktop 自身改动需要最后一次手动构建才能激活；Desktop 运行时自身 DLL 被锁，自我重建需要输出重定向或 updater 进程（当前构建目标为 PuddingAgent.csproj，Core 二进制在 Desktop 输出目录，需验证构建产物落点）。
