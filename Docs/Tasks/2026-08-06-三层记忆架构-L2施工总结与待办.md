## 1. 背景与目标

用户提出核心诉求："跨越多个会话窗口，瞬间回忆起 N 个会话之前的某个内容"。
诊断现状后发现三个结构性缺口：

1. **召回是拉式不是推式**——RECALLED 注入只按时间（最近 5 天），不按语义相关性
2. **会话语料不是记忆**——原始对话在事件库沉睡，只有压缩冲洗的幸存事实进了记忆图书馆
3. **embedding 链路断裂**——章节向量在 Streaming 执行路径从不生成（当天定案修复）

总体设计为三层：

| 层 | 内容 | 状态 |
|---|---|---|
| L1 | 语义注入（时间序 → 相关性驱动） | 现有第 4/5 路向量召回已覆盖大部分，L2 后评估 |
| **L2** | **全会话向量索引（本次施工主体）** | ✅ 完成 |
| L3 | 实体卡片（属性累积节点） | 未开工 |

设计分工原则（用户定调）：**蜜糖出图纸，子代理施工**；`llm.providers.json` 只注册服务商和模型元数据，**具体用哪个模型由 agent 配置决定**（注册表与路由分离）。

### 关键设计点

- **表落 memory.db**（MemoryLibraryDbContext），schema 走自定义 DDL bootstrapper 三处同步（DbSet/映射/MemoryLibraryDbInitializer），**不走 EF Migrations**（仓库惯例，EnsureCreated 不兜底 memory 库）
- **会话归属按 SessionId**：投影落库时 agentInstanceId 恒为 null
- **切块策略**：≤1024 字符、句子边界优先、相邻块 128 字符重叠、单句超长硬切（纯函数可测）
- **写入时机**：消息落库成功后 fire-and-forget 索引（AgentConversationLogService 主路径 + ChatTranscriptWriter 兜底路径），双写靠唯一索引幂等保护
- **读取融合**：RRF 第 5 路与章节向量同权 0.7；SourceId 编码 `chunk:{SessionId}:{ChunkId}` 防碰撞可溯源
- **查询 embedding 单次共享**：第 4/5 路共享同一个 Task，一次召回只调一次本地模型
- **回填幂等可重跑**：键集分页（Id > lastId，避免 O(N²)）、批查已索引 MessageId、唯一索引兜底

## 3. 过程中的关键教训（方法论沉淀）

1. **Streaming/Buffered 双执行路径的生命周期钩子不对称是隐蔽 bug 源**——章节向量零生成的根因
2. **fire-and-forget Task.Run 吞异常 = 静默失效**——必须包 try/catch + 日志（健康自证原则）
3. **子代理委派纪律**：可枚举、有 file:line 锚点、禁开放式推理、禁它不擅长的工具、预算≥10min、先 grep 定位再读别猜路径
4. **子代理写代码可靠，验证环节亲自担**——三个施工代理全部死于"shell 30s 超时跑 dotnet"，代码本体都完成了
5. **terminal 壳是 CMD**：长命令用 `cd /d ... && dotnet ... > log 2>&1`，嵌套 pwsh 引号会被吞
6. **日志滚动清理很快**（~1MB/卷、保留少量卷）——事后取证要趁早，建议调大保留卷数（P2）
