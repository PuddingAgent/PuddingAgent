# 运行手册：浏览器交付外部验收

## 一、前置

1. 内部侧交付：`Docs/14_reports/浏览器交付-链级清单-round-793.json`（`ready-for-external-deploy` · `buildId=round-793` · `commit=208bea2` · `dirty=false` · `artifacts=114` · `checks=12` · `requiredExternalSteps=startup|restart|crash-recovery|exit-reclamation`）；
2. **重启到明确的新构建**（勿沿用旧进程）；
3. 若要重跑内部链：**先停 `PuddingDesktop`/`PuddingAgent`**（他们持有 `Source/*/bin/Debug` 文件锁）⇒ `TestScripts/delivery-manifest.ps1 -BuildId <新id>` ⇒ **先断言 `buildId` 为新值**；**脏树会按规则正确拒绝**（实测 `dirty=true` ⇒ `NOT emitted (exit=2)`）

## 二、功能 smoke（进程内新会话，逐项留证）

1. 八项浏览器工具在**真实模型**下可用；
2. **ref 规则**：交互提交后旧 Locator 必须被拒（`page_mismatch`/`document_changed`）；
3. **截图 → vision**：返回中必须出现**图像部件**；不可用时**必须**显式 `visionUnavailable`（不得静默降级）；
4. **授权两侧**：无授权⇒拒绝 · **合法授权⇒成功**（防"一律拒绝"）；
5. **委派**：子运行用**真实子 run 身份**（含父任务）；撤销/接管后子运行不得继续；
6. Bridge Activity 与免重启行为如常

## 三、G1–G11

**逐条判据以权威文本为准**：`Docs/12_features/浏览器交付修订施工方案-2026-10-12.md` 与 `TestScripts/BrowserDeliveryReview/README.md`（**本手册不重述条目内容，避免与权威文本漂移**）

## 四、250ms 校准

按方案口径测量「**操作受理 → 首个可观察反馈**」；记录**样本数 / 中位 / 95 分位 / 环境**（机器与负载）；**不得只报最好值**；超阈值须给可复现步骤与原始日志

## 五、生命周期（**只能由外部判定**）

**启动** · **重启** · **崩溃恢复** · **退出回收**（Core 子进程退出、WebView2 与端口释放）

## 六、反作弊要求

**不得以"一律拒绝"或放宽断言取绿**；拒绝/允许两侧都要证据；未验证项**显式标注**

## 七、已知开放项（均已登记、未掩盖）

1. `SessionEventStreamServiceTests.A_Replaced_Waiter_…` 间歇失败（已定名；消息会自报条件）；
2. R5 两步改名残余窗口**已核实为自愈**（无需外部动作）；
3. 方案 L162 字面差异**已按保守做法在代码内写明**（受账本门控）
