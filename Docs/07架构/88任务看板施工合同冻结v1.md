# 任务看板施工合同冻结 v1（TB-00 / M0）

> 状态：Frozen（冻结）
> 日期：2026-08-16
> 上游：ADR-073（施工顺序）、ADR-072（领域设计 ST-00）
> 用途：本文是 TB-01~TB-08 所有子任务的**唯一权威参照**。枚举、错误协议、Feature Flag、唯一 Owner 以此为准；任何子任务禁止自行发明第二套枚举或状态语义。

## 1. 范围冻结（第一阶段）

**范围内**：五列任务看板、WorkspaceTask 台账、Assignment Attempt、Execution Binding、Task Event、手工指派/取消/归档/RunNow、四个 Agent Task 工具、自动回写、失败/重开、执行会话深链、刷新恢复、受限五字段 Cron（后续 P1）。

**范围外（禁止预埋）**：Questioner/Goal/Approval Workflow、任意事件表达式、Graph 自动生成、通用 Plugin Host、通用 Domain Event Log、子任务树/批量编辑、执行中途暂停。

## 2. 枚举冻结（唯一权威）

> Core Contract（PuddingCore）与 OpenAPI/前端使用**同一套枚举**。前端不得用字符串或颜色猜测状态；`boardColumn` 只由后端 `TaskBoardProjection` 投影。

### 2.1 TaskStatus（WorkspaceTaskStatus）

```text
Backlog       待规划（目标/验收/执行信息未完整）
Ready         待办
Deferred      待办（被 Fence 推迟，必有 decisionCode + nextEligibleAtUtc）
Reserved      待办（Scheduler 短暂持久所有权）
Assigned      待办（已分配 Agent）
NeedsReview   待办（需用户复盘）
InProgress    进行中
Blocked       进行中（阻塞，必有 blockerKind + blockerReason）
Completed     已完成
Failed        已失败（闭合失败，非单次 Attempt 失败）
Cancelled     已取消（历史筛选，不占五列）
Archived      已归档（历史筛选，不占五列）
```

### 2.2 BoardColumn（五列投影，不是第二套状态机）

```text
Backlog     ← Backlog
Todo        ← Ready | Deferred | Reserved | Assigned | NeedsReview
InProgress  ← InProgress | Blocked
Done        ← Completed
Failed      ← Failed
```

`Cancelled` / `Archived` 默认进入历史筛选，不占五列。前端不自行推导列归属。

### 2.3 Disposition（task_update 的 disposition）

```text
accept
progress
todo          回退到待办
blocked        必填 reason
needs_approval 映射为 Blocked + blockerKind=approval_required
rejected       必填 reason（终止 Assignment，不终止 Task）
completed      必填 resultSummary，且满足 Acceptance Criteria 声明必需 Artifact
```

Agent 不直接写 Status，后端状态机解释 disposition。

## 3. Feature Flag（可独立关闭）

```text
WorkspaceTasks.Enabled     任务看板总开关
TaskAutoDispatch.Enabled   自动派发
TaskAutomation.Enabled     定时任务
PeakFence.Enabled          峰谷 Fence
```

- 关闭 `TaskAutoDispatch.Enabled` / `TaskAutomation.Enabled` 只停止**新 Claim**，不破坏已有 Task 读写和历史。
- 关闭 `PeakFence.Enabled` 时明确记录 `feature_disabled`。
- Flag 关闭后 API 仍可读取和导出 Task 历史。

## 4. 错误协议

| 场景 | HTTP | 说明 |
|------|------|------|
| CAS/状态冲突 | 409 | 返回 `code/message/traceId/currentVersion` |
| 规则校验失败 | 422 | 返回 `code/message/traceId` |
| 未认证/无权限 | 401/403 | 稳定 code |

所有错误体包含稳定 `code` + `message` + `traceId`；冲突场景附加 `currentVersion`。必须有契约测试锁住 code 与 HTTP 映射。

## 5. 唯一 Owner

- 新 `WorkspaceTask` 启用后，`task_list/task_get/task_claim/task_update` 工具是任务状态的**唯一 Owner**。
- 不建设 `manage_tasks`（per-agent JSON 三态列表）双写或长期兼容层；TB-08 退役旧 `manage_tasks`。
- Task 状态只由结构化 Command/Tool 推进；自然语言"完成"不改变 Task。
