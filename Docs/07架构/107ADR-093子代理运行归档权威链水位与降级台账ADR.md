# ADR-093：子代理运行归档的权威链、水位与降级台账

日期：2026-09-23。状态：**Proposed**（A93-0 部分已实施：降级台账 / 只读对账 / 索引重建）。决策责任：Platform 持久化（`FileSubAgentRunStore`、诊断 API、会话投影）、Runtime 恢复与父子接续、Host 组合；外部控制器负责部署与生命周期验收。

依据：[架构评审处置裁决](../Reports/ArchReview-Triage-2026-09-23.md)、[GPT-6 Astra 评审](../Reports/ArchReview-GPT6Astra-2026-09-23.md)。领域前序 ADR：`Docs/07架构/21子代理工作空间与运行归档ADR.md`。

## 背景（含对评审表述的更正）

评审第 1 条称「缺少可证明的一致性提交协议」。**我对源码逐行核对后认为该表述偏重** —— 现状已有四条相关机制，不能当成空白重做：

| 既有机制 | 证据（`Source/PuddingPlatform/Services/FileSubAgentRunStore.cs`） |
|---|---|
文件为权威、DB 仅索引 | 类头 `:15-16`「运行归档以文件为主存储…数据库仅做索引」；三链依赖 `:24-30` |
**持久游标即权威** | `:880-889` 投影成功后 `WriteProjectionCursorAsync(cursorPath, index+1)`；`:898-906`「Cache is only an optimization; **the durable cursor remains the authority**」 |
投影失败可续 | `:884-895` 失败仅 `LogWarning("Conversation projection deferred")` + `break`，游标不前进 ⇒ 后续扫描重试 |
终态不 fail-open | `:190-193` 注释明确「**终态事件走 CompleteRunAsync，仍保持抛错语义**」；写事件带 `EventWriteCondition(..., eventId, -1)` 幂等/并发闸 |
观测事件丢弃是**刻意**的 | `:191-195` 注释引真实案例（`run_20260821_230951_...`）：「运行事件是观测数据…**不得把运行中的子代理直接杀死**」 |

⇒ **真正的缺口只有三条**（均已逐行核实）：

- **G1 降级只有聚合计数、没有逐条台账。** `archive-degraded.json`（`:1027-1056`）只写
  `FirstFailureAt / LastFailureAt / DroppedEventCount / LastEventType / LastError`
  ⇒ 能知道"丢了几条"，**无法知道"丢了哪几条"** ⇒ 无法对账、无法补齐、无法重放定位。
  且该标记**自身写失败只留 `LogError`**（`:1049-1055`）⇒ 二次降级完全静默。
- **G2 没有跨链一致性视图。** `ProjectionFileStamp(EventLength, EventWrite, ManifestWrite, CursorLength, CursorWrite)`
  （`:39-40`、`:42-49`）是**内存优化**，不对外可查 ⇒ 诊断侧无法回答「文件事件数 / DB 索引水位 / 投影游标是否一致」。
- **G3 没有重建路径。** DB 索引写失败是 `LogWarning` + 注释「DB 写入非致命」（`:1180-1183`），
  但缺"按权威链重建并对齐水位"的可执行作业 ⇒ 差异只能靠人读日志发现。

## 决策

1. **权威链唯一化**：`events.jsonl`（+ `run.json` 清单）为唯一权威运行事实；
   DB 索引与 conversation 投影一律**降级为可重建投影**，不再承担第二份可查询事实源。
2. **提交顺序固定 + 每链持久水位**：文件 append → 投影推进（游标）→ 索引写入；
   三条链各持一条可比较的持久水位（文件事件序号 / 索引水位 / 投影游标）。
3. **降级必须可枚举**：新增 `archive-degraded-events.jsonl`，逐条记录
   `{seq, eventId, eventType, error, at}`；`DroppedEventCount` 降级为**派生视图**（不取消，供概览）。
   标记自身写失败必须**升级到可观测终态路径**（不得只留一行日志）。
4. **保留事故结论**：观测事件写失败**不得杀死运行中的子代理**（丢弃语义不变）；
   **终态事件维持抛错语义不变**。本 ADR 不放松这两条。
5. **只读一致性诊断**：对单 run / 全量输出
   `{权威事件数, 索引水位, 投影游标, 降级条数}` + 差异判定 + 可重建性；
   存在差异时必须**明确列出"未投影 / 未索引"**，不得静默缺失。
6. **幂等重建**：提供重建索引/投影作业，按权威链重放；结束后水位必须**等于**权威水位；
   同一 run 重放两次**不产生重复事件**。

## 对既有设计的修订

- **不推翻** ADR-021 的"文件优先"与"观测数据不得杀死运行中的子代理"结论；本 ADR 在其上补齐水位、台账、对账与重建。
- **修订**「DB 写入非致命」的**范围**：仍然非致命，但必须计入可查的水位差异，不得只留 `LogWarning`。
- **与 ADR-087 的边界**（子代理托管运行与持久问答）：本 ADR 只管**事实提交与对账**，不改问答、预算与托管语义。

## 备选方案与取舍

| 方案 | 评价 |
|---|---|
| 文件与 DB 双写事务化（2PC / 共享事务） | 文件系统与 SQLite 无跨资源事务；引入不确定性、抬高写路径失败率，且**与"观测数据不得杀死运行"直接冲突**；不采用 |
| 改 DB 为主存储 | 与 ADR-021 相反；历史归档迁移成本高、离线可读性下降；不采用 |
| 只加日志/告警、不动协议 | **现状已经如此**（`LogWarning`/`LogError`）；对账仍不可能；不采用 |
| 权威文件 + 水位/台账/对账/重建 | **推荐**：保持离线可读与运行存活，同时把"部分成功"变成可证明、可修复 |

代价：新增两条持久水位、一个降级台账与一个重建作业，并需故障注入测试；收益：恢复、父子接续与取证有单一收敛点。

## 发布与验收

阶段：**A93-0** 水位与台账（不改既有成功路径）→ **A93-1** 只读对账诊断 → **A93-2** 重建作业 → **A93-3** 故障注入回归入 CI。

至少覆盖：
- 对**文件写 / 索引写 / 投影**三个阶段分别注入 IO 失败、磁盘满、目录不可写；
- 恢复后重放使三条水位对齐，且终态唯一；
- 同一 run 重放两次幂等（不产生重复事件）；
- **降级台账可枚举**（断言不得只有计数）；
- 标记写失败可观测（断言不得只留日志）；
- **运行中的子代理在观测事件写失败时仍存活**（锁定事故结论，防回归）；
- 终态事件失败仍抛错。

## 2026-09-23 A93-0 实施记录（第一刀：可枚举降级台账）

**已落地（不触碰既有成功路径）**：

- `Source/PuddingPlatform/Services/FileSubAgentRunStore.cs`：
  - 新增 `DegradationLedgerFileName = "archive-degraded-events.jsonl"`（`:31`）与公开读取器
    `GetDroppedEventLedgerAsync(runId)`（`:1055`）、`NextLedgerSeq`（`:1092`，读取失败返回 `-1` 而非静默 0）；
  - `MarkArchiveDegradedAsync` 新增 `eventId` 参数，并拆为**两个独立 try**：写聚合标记与写逐条台账
    互不连累；各自失败分别 `Interlocked.Increment` 到可查计数器
    （`DegradationMarkerWriteFailures` / `DegradationLedgerWriteFailures`）；
  - `AppendEventAsync` 把 `eventId` 提到 try 之前生成并传入（否则丢弃时无法记录事件身份）；
    `AppendToolAuditAsync` 传 `eventId: null`。
- 新增 `Source/PuddingPlatform/Services/SubAgentArchiveDroppedEvent.cs`（公开记录，一行一条）。
- `Source/PuddingPlatformTests/Services/FileSubAgentRunStoreTests.cs`：扩展既有确定性降级用例（加台账断言），
  新增 `DroppedEventLedger_Enumerates_EachDroppedEvent`、
  `DegradationMarkerWriteFailure_IsCounted_AndDoesNotBlockLedger`（后者把 `archive-degraded.json` 建成**目录**做确定性注入）。

**对 ADR 原文的诚实细化**：决策 3 原文写「标记自身写失败必须升级为可观测终态路径」。
实施时发现**抛错会直接违反决策 4**（观测事件不得杀死运行中的子代理）。
因此落地为：**不抛错，但必须可在健康面查到**（计数 + 带错误码的 LogError，
`code=archive_degraded_marker_write_failed` / `code=archive_degraded_ledger_write_failed`），
并用用例锁定「标记失败不得连累台账」。此细化应由 ADR 批准时确认。

**验证（实跑）**：

| 项 | 结果 |
|---|---|
定向 12 用例 | `失败 0 / 通过 12 / 总计 12` |
**变异取红**（临时禁用台账写入） | `失败 3 / 通过 9 / 总计 12`，恰好是 3 条台账断言变红（`ledger.Count` 期望 1/2、实际 0） |

**第二刀（同日稍后）：只读一致性对账**（缺口 G2 的最小修复面）

- 新增 `SubAgentArchiveConsistencyReport`（公开记录）与 `InspectArchiveConsistencyAsync(runId)`：
  一次摊开**四条链的事实** —— 权威事件数（`events.jsonl` 非空行数）、投影游标、未投影条数、
  降级台账条数、聚合标记计数、索引行是否存在（`IndexRowPresent`）、**索引是否可读**（`IndexReadable`，
  与“缺失”分开报告，避免把“读不出来”误报为“没有行”）、权威状态（`run.json`）与索引状态；
  并输出 `Findings` 差异清单与 `IsConsistent` 判定。
- **严格只读**：不写文件、不改状态、不修补差异（修补属 A93-2）。
- 验证：新增 `InspectArchiveConsistency_ReportsWatermarksAndDivergence`。
  差异用**确定性注入**制造（把持久游标写回 `0`），**不依赖“刚写入的事件尚未投影”这一时序假设**
  （实测该假设不可靠：既有用例里 replay 返回 0，说明历史路径可能已就地把事件投影完）；
  并断言权威状态确实取自 `run.json`（`running`）且与索引状态一致。
- 结果：定向 13/13；**变异取红**（令 `unprojected` 恒 0）⇒ `失败 1 / 通过 0`，
  报错 `Expected <1>(AuthoritativeEvents) / Actual <0>(UnprojectedEvents)`；
  全量 `PuddingPlatformTests` **1391/1391**。

**第三刀（同日稍后）：幂等索引重建**（缺口 G3 的索引腿）

- 新增 `RebuildRunIndexAsync(runId)` + `SubAgentIndexRebuildResult`（created / updated / unchanged / failed）：
  按**权威** `run.json` 重放索引行 —— 缺失则补建、存在则只覆盖 manifest 派生字段；
  已一致时**不写库**（幂等：重复重建无副作用）。`startedAt` 沿用创建路径的 `"O"` 格式。
- 两条边界写进代码：
  ① **只修索引腿** —— 不重放会话投影（投影链有持久游标 + 重放，本身自愈）、不动投影游标；
  ② **不越权改运行期累加计数器** —— `TotalRounds` / `TotalToolCalls` / `TotalDurationMs`
  仅在 manifest **确有取值**时才恢复，绝不用 `null` 把它们清零（否则一次重建就把计数抹成 0）。
- 与既有“DB 写入非致命”的关系：创建/更新路径仍然只留 `LogWarning`（本刀**没有**改它们的行为），
  但重建是**显式修复操作**，失败必须由返回值携带（`code=archive_index_rebuild_failed`），不得只留日志。
- 验证：`RebuildRunIndex_RepairsMissingOrDivergedRow_AndIsIdempotent` ——
  破坏现场用**直接删行 / 改错状态 + 预置 `TotalRounds=7`**；定向 14/14；
  **变异取红**（把计数器改成无条件覆盖）⇒ `失败 1 / 通过 0`，被抓到的正是**幂等性**：
  第二次重建本应报 `unchanged`，变异后变成 `updated`（每次重建都无条件写库）；
  全量 `PuddingPlatformTests` **1392/1392**。

**本次未做**：A93-3 故障注入入 CI；A93-1 未接 HTTP 诊断端点；
**投影腿的显式重建入口**未新增（未投影/游标丢失仍靠既有 `ReplayPendingConversationEventsAsync` 自愈，
实测该路径会让 replay 返回 0 —— 说明它能自己追平，但也说明“是否需要显式重建”需先观测再定）；
创建/更新路径的“非致命”仍只留 `LogWarning`，本刀只给了**修复手段**，未改写入行为。
