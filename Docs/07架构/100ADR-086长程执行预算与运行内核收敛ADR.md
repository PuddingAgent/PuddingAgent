# ADR-086：600 轮长程执行与运行内核收敛

> **后续修订**：[ADR-087](101ADR-087子代理托管运行与持久问答ADR.md)将600改为可选预算示例，支持短任务及任意合法正整数轮次；不强制600默认/上下界。独立LLM grace改为系统有界清理；生命周期对主代理透明，预算与usage可查，双向消息、120秒问答和停止共用持久控制机制。下文相冲突的600固定profile/grace建议由ADR-087取代。


- 日期：2026-09-12
- 状态：Proposed；立即作为本阶段实施约束，尚待源码和运行验收。
- 详细设计：[长程自治设计 §6–9](../Features/PuddingAgent长程自治与缓存99优化设计-2026-09-12.md)
- 关系：**取代先前“WorkUnit应限制25–40轮、禁止600轮”的设计建议和测试目标**；修订ADR-081中默认保留Harness猜测适配、正文终态提升的方向。保留canonical工具、权限、明确no_match、错误族和真实usage原则。

## 背景

当前系统配置上限600，但SubAgentManager的默认32/managed上限40和工具上限120、TaskExecutionPlanCompiler的25–40轮及20–60分钟又截断实际预算。用户明确要求放宽到约600轮，旧方案已不再有效。单纯增加工具错误反馈文字也不能解决执行协议与状态分叉。

## 决策

1. 普通和managed长程子代理统一支持600个正常LLM轮次；建议profile默认2400工具、24小时单Run总硬时限，允许用户显式放宽。600不是40+checkpoint的包装；cleanup grace不得侵占600正常轮。
2. 一个budget resolver贯穿配置、模板、计划、spawn、dispatch、Loop，记录configured/requested/effective/source。删除Manager/Planner重复小上限，也删除配置normalize强抬600的隐式旧值补丁。尊重用户显式较小预算，拒绝时说明限制来源。
3. 单Run硬截止、无进展滑动窗口、Provider超时、工具时长、外部等待分别建模。异步子Run不受父HTTP调用生命周期限制；同步不足则明确返回，不能偷偷缩小。
4. 长任务依靠durable checkpoint和结果事件跨Run持续数十天。有效进度有证据，外部等待有identity/deadline；短检查点频率是保全措施，不是中止阈值。
5. 复用并收敛FailedToolCallTracker/RuntimeControlService到统一判定，Native/Streaming/Buffered统一工具入口、状态和审计。优先查postcondition与错误族，不增加无界反思提示轮次。
6. canonical schema是核心唯一工具合同；正文JSON不再是隐式执行通道。历史别名/参数猜测、测试专用fallback按调用者清单迁出或删除；明确外部业务协议适配只在边界规范化一次。
7. 清理Feedback按语义与调用链，不按名称批删：保留用户可见UI反馈、真实错误和用户事实；删重复提示驱动状态修复、文本猜终态、重复状态投影。组合根缺依赖显式失败，不静默走legacy实现。
8. 当前固定WorkUnit输入/费用小阈值须与真实授权预算对齐。缓存replay、miss、output、cost单列；缺价格显示unknown，用户明确货币硬上限无法核算时显式阻塞，不猜价或偷偷扩费。

## 验收

- 普通spawn、managed task、batch、模板实例覆盖有效600轮；在第41/61/201轮有进展时持续工作，第600正常轮可到达；预算600/2400/24h来源一致。
- 显式较小预算、超管理员上界、取消、权限撤销、父同步剩余不足、异步父返回后继续均有反例测试。
- 使用fake Provider驱动601轮确定性测试，不为证明上限空烧600次真实模型；真实复杂任务自然结束或按已授权预算续行。
- 编译前后对比生产执行路径和兼容分支数量；Native工具真实成功率与正文文本不执行副作用均验证。
- 原工具问题到源码修复→外部新构建加载→产品功能验证→原任务恢复的A08证据齐备；内部Agent不能自证重启生命周期。

## 代价与取舍

放宽预算会允许更大真实消耗，因此需要透明的成本/进度记录和用户取消，不通过隐式小上限代替治理。删除适配可能暴露模板错误，先迁移现用调用者、补canonical fixture与真实产品smoke，再删除；不长期并行保留两套运行内核。
