# ADR-091：自动审计与执行准入闭环

日期：2026-09-15。状态：**Proposed**。决策责任：Runtime 执行准入、Platform 持久审计与调度、Host 组合、Workbench 状态投影；外部控制器负责部署与生命周期验收。

详细设计与验收：[自动审计与执行准入闭环设计](../Features/自动审计与执行准入闭环设计-2026-09-15.md)。任务与派发：[交付记录](../Reports/自动审计方案与派发记录-2026-09-15.md)。实施总任务：`e187a8bbd2d640bb87b96fd3cf548966`。

## 背景

旧自动权限设计 v2 已否决“工作空间必须有审计 Agent”，当前 Host/Runtime 仍依赖它。现场 shell 构建票据因审计 Agent 不存在而 Pending，模型尚未审查。授权/allowlist 位于命令防火墙之前；一次性权限用两次消费补偿检查；前端本地计数可自动切回人工。历史行为审计任务完成的是提示词/卫生改进，不是事件驱动的行为审计闭环。

需要支持用户交互和长期无人值守；必须允许系统发现自己的问题并推动源码修复，同时防止重复重试、重复建单、自批权限和无证据完成。

## 决策

1. **分开执行准入与行为审计**。前者是所有工具共享的服务端内核；后者是基于 canonical 事件的持久后台消费者。共享 InvocationId、EvidenceRef、PolicyRevision、BuildId，不共享任意运行的审计 Agent 生命周期。
2. **保留旧 v2 的判断原则，重建执行顺序**。冻结操作计划 → 不可覆盖硬边界 → 确定性策略与事实 → 必要时单次隔离 LLM → 原子许可 → 执行及后置证据。授权、YOLO 与模型均不能覆盖硬拒绝。不能仅以 dotnet/node/npm 等命令首词判断安全。
3. **检查无消费，执行提交才消费**。裁决缓存、grant、permit 分开；数据库 CAS 保证一次授权只绑定一个逻辑执行。重复检查幂等；定义/根/策略/证据改变使决定失效。外部副作用崩溃不确定进入 DispatchUnknown，不承诺 exactly-once。
4. **失败分类属于协议**。Allow、DenyPolicy、NeedEvidence、AwaitingHuman、DeferredDependency 使用 typed disposition。缺审计模型/服务不是用户业务决定；持久等待依赖事件恢复，不靠业务 Agent 心跳轮询或浏览器自动降级。
5. **审查模型与 Agent 实例解耦**。复用配置与 ILlmInvocationService；单次无工具、有界事实、严格输出校验。生产没有 fake 放行。工作空间审计 persona 可选，不能决定普通开发工作的可用性。
6. **增量行为审计与证据裁决**。新增事实投影、source cursor/inbox、finding、action outbox，复用现有 Task/Goal 调度。重点识别无进展重试、依赖空转、无证据完成、子代理唤醒遗漏、无效/漏触发心跳、无收益压缩及成本异常。等待和无可执行工作不是低效。日志检索是取证手段，不作为最终快照或默认全量上下文。
7. **允许自修复，关闭问题依赖独立验收**。审计提出有唯一根因键的修复任务；既有 Agent 可修改源代码。需提交/测试 → 外部新构建部署 → 新会话功能证据，才能关闭 finding。模型不能自授权限、改审计基准证明自己正确或无限生成自己的审计任务。
8. **持久服务端状态统一所有入口**。Web、Connector、主/子代理共享准入和审计投影；UI 不持有权限状态机，静默时段仅控制通知。配置文件优先；运行事实/授权使用事务存储。没有长期新旧双执行路径。

## 对既有设计的修订

本 ADR 在冲突处取代 `Docs/superpowers/specs/2026-06-03-auto-tool-approval-design.md` v2.1。保留静态→事实→单次模型原则和人工审批降权；不再执行整分支 rebase `e716829`、空 Evidence 接入、禁用新链后自动回旧链、训斥式拒绝提示等方案。

不推翻既有 Task/Goal/outbox、Shell 统一计划、Memory 按需证据、子代理预算与外部验收边界。`a543e4bb86904588b68a96315d3d16f0` 的历史完成状态不变，自动行为审计服务通过新的实施任务验收。

## 备选方案与取舍

| 方案 | 评价 |
|---|---|
| 加一个审计 Agent 或全局授权 shell | 不能解决错误分类、消费竞争和行为闭环，且继续耦合可用性；不采用 |
| 直接合并旧三层漏斗分支 | 原则可用，入口、事实和持久恢复未对齐当前代码；只择取经验证的纯逻辑 |
| 所有工具都调用模型审计 | 延迟、费用、故障依赖和缓存扰动过大；确定性规则优先 |
| 仅强化系统提示词/前端 classifier | 无法保证 headless、并发、重启和一次授权语义；只保留用户展示与行为指导作用 |
| 全量聊天检索 + 大上下文审计 | 历史讨论不是最终结论，长期成本与污染无法控制；使用增量事实和按需引用 |
| 独立审计服务集群 | 当前单机 Desktop + Core 不需要新增部署单元；先在 Core 内明确接口与持久边界 |

代价是新增结构化操作计划、事务状态与规则测试；收益是减少普通工作人工阻断和重复模型调用，使失败、等待、授权、执行、验收可证明。审计结果可能误报，必须先影子运行并允许有证据的修订；模型建议本身不具备最终治理权限。

## 发布与验收

按 A91-0 至 A91-4 实施，见详细设计 §9。P0 同时交付实例解耦与硬边界/原子许可，之后再让行为发现自动触发修复。部署前做备份与明确旧数据转换；不清空 D:\data，不篡改旧批准票据。

至少覆盖：无审计 Agent、模型故障/恢复、once 并发、硬拒绝优先、迟到/撤销/取消、主子权限域、命令包装器、重启事件去重、有效等待/漏心跳、旧构建不能验收新修复、浏览器关闭、重复 finding、审计自身不递归。真实普通开发任务必须在非 YOLO 下成功；源码测试与长时间运行验收分开，72 小时及 7 天观察未完成时不得标系统已完成。
