# ADR-092：Goal 单一状态机与证据驱动续行（第二版）

日期：2026-09-17（第一版2026-09-15）。状态：**Proposed，重新规划完成，实施与运行验收未完成**。

完整设计：[Goal模式简化设计](../Features/Goal目标驱动执行与分层验证闭环设计-2026-09-15.md)。现场依据：[多轮效率与缓存评估](../Reports/Goal多轮效率与缓存命中评估-2026-09-17.md)。旧版保留于 Git `bf46c68`；本次整体替代旧决策与刀次计划，不继续在旧复杂流程后追加补丁条款。

## 背景与用户纠正

用户明确：`goal.md`是Agent自己的目标存储；Goal模式必须依赖自己的数据存储。现有设计把Goal、Task计划推进、两级Verifier、认领恢复和多个任务结算写入口耦合。真实目标15轮、52.43M主调用输入后，平台仅因build/test两项通过而Completed，业务任务仍未完成。复杂性没有换来完整性与效率。

## 决策

1. **单一职责。** Goal只保存用户目标并根据证据决定续行、等待与结束。Agent Runtime执行回合；检查执行器产出证据；Task/Scheduler管理任务计划与认领；审批、Memory、压缩、子代理和Desktop生命周期各归既有系统。
2. **存储独立。** Goal使用平台数据库现有Goal专属表。`goal.md`继续是Agent目标管理的独立权威；不作为Goal启动/恢复/结算依赖，不改成Goal缓存或副本。其维护故障单独处理。
3. **一个状态字段。** Running、Waiting、Paused、Completed、Cancelled、Failed；预算不足为Paused原因，不再叠加活动子状态。UI执行活动由工作记录派生。
4. **一个决策入口、两类执行工作。** 复用现有结算Worker/Store与纯决策函数；执行Agent回合或指定证据检查。命令/回合/检查/恢复事件都走同一规则。决策函数无模型、无工具；有界语义检查属于检查执行器，无第二套审阅Agent循环。
5. **移除Goal步骤引擎和两级Verifier。** Goal不持有CurrentWorkUnit、不数RemainingWorkUnits、不推进task_nodes。Task计划仍归Task；TODO只供交流。独立Goal无需Task/Plan即可完成。
6. **合同小而完整。** 保存原始要求到必要条件的映射，覆盖不足不得完成。允许一次有界合同整理；简单文本用文本断言，文档用内容检查，代码用实际相关验证。通用build/test不能兜底成为任何目标的完整合同。模型不能删义务自证成功。
7. **证据检查只做必要工作。** 优先使用既有canonical执行证据，缺证据才投递检查。内容输入身份决定有效性，原始文件字节不可随意归一；相关变化使旧成功与失败失效，无关变化有依据才复用。临时失败重试预算跨epoch保留；不接受假DONE、0 tests、未结束进程或旧构建证明新源码。
8. **等待由平台承担。** pending和依赖故障持久等待、释放执行占用；事件/有界超时重评，不调用模型轮询。无进展有界处理；同一拒绝不反复委派。保留权限、预算、用户暂停取消和明确的重启恢复策略。
9. **Task是可选适配器。** 读取合同、获取/恢复认领、Task领域完成方法通过既有服务实现。绑定期间Tracker/Repair/其他完成服务只提交事实，不独立关闭任务；Goal完成与Task完成在同一短事务内校验并写入。Goal不复制Task计划算法，也不把TaskCompleted作为循环前提。
10. **可靠性机制内聚。** 保留Goal版本CAS、epoch、执行租约fence与事务outbox，分别解决并发、旧事件、旧执行者和投递丢失。状态只能由统一入口改变；检查运行在事务外。可恢复不确定副作用先对账，不换Goal或重启来重置预算。

## 保留、移除和延期

| 保留 | 移除/停止扩建 | 留在其他模块 |
|---|---|---|
| Goal持久表、canonical Turn、outbox、幂等、受控检查 | Goal强制Plan/WorkUnit、双层Verifier、重复整体验证 | Task计划调度、工具审批、子代理编排 |
| 目标条件、输入身份、费用归集、外部构建证据 | 工程门禁兜底完成、多处Task终态写入、模型轮询等待 | Agent goal.md、Memory、TODO、上下文缓存 |
| 用户控制与既有预算 | goal_queue.json旧模式的生产循环、常驻双实现兼容层 | 跨目标优化、复杂依赖图及其他长程能力按各模块独立演进 |

## 旧设计的优先级与实施边界

本版在冲突处优先于ADR-074、ADR-092第一版与旧完整方案。保留ADR-074的统一入口、持久化及用户控制；撤销旧版强制两级验证、Goal管理步骤树以及Active附加活动子状态等要求。TODO交流定位与受授权Task启动入口保留，均使用本版Goal内核。ADR-091仍拥有审批安全边界，ADR-090仍拥有上下文压缩。本次不修改其策略，不选择放宽审批来解决依赖故障。

实施按S1合同/纯决策→S2事件等待/执行分离→S3Task适配/唯一写入口→S4投影/旧循环删除。先固定误完成负例，小步替换现有路径；阶段组合完成前不宣称功能交付。原G92任务保留历史，实施范围需按新设计对齐；本次未变更看板或执行授权。

数据库按设计§10显式升级，旧enum不能重解释；历史终态保留原证据，未知活跃目标暂停待核。部署由外部控制器在安全窗口进行，不清库、不覆盖他人WIP；切换后有新数据不得盲目恢复旧备份或运行旧二进制。

## 验收与取舍

验收详见设计§11：goal.md故障不影响Goal；一句话目标一轮零工具完成；build/test绿不能掩盖缺失业务条件；真实修复可自动多轮；等待无新模型调用；事件重放/崩溃/取消安全；Task/Goal原子终态；新构建证据及费用可对账。

接受的取舍：Goal不再为每个目标提供自己的步骤级工作流引擎；复杂步骤交给Agent或Task系统。保留目标义务和证据的严格性，减少对同一事实的重复计划、重复审阅与重复状态管理。简单目标走短路径，复杂目标复用同一个闭环。
