# ADR-092：目标驱动执行与分层验证闭环

日期：2026-09-15。状态：**Proposed**。所有者：Core Goal 合同、Platform Goal/Task 结算与持久验证、Runtime 受控检查、Host 组合、Workbench 投影；外部控制器负责产品部署和生命周期验收。

完整施工方案：[Goal 目标驱动执行与分层验证闭环](../Features/Goal目标驱动执行与分层验证闭环设计-2026-09-15.md)。任务修订与执行回执：[记录](../Reports/Goal持续执行方案与任务修订-2026-09-15.md)。

## 背景

用户要求 Agent 持续达成完整目标，每轮校验后自动进入下一轮，而不是完成一个小任务就 sleep。源码已具备 durable GoalRun/outbox，但保守 verifier 主要看 Task 状态；一轮 completed 可被解释为 WorkUnit 完成，恢复性失败又可能关闭整个绑定 Goal。提示词加强或单纯缩短 sleep 不能解决这些语义问题。

## 决策

1. **Goal 是持久承诺，Turn 是一次执行。** 复用 GoalRun、TaskGoalBinding、Plan/WorkUnit、canonical Turn、outbox 和 fencing；不建立第二个目标循环。一个步骤可以多轮修复，步骤正常返回不自动推进。
2. **将完成条件固化为版本化 AcceptanceContract。** 保存用户要求与必需条件映射，检查定义、输入和证据有版本。Memory 保存决定和索引，聊天/goal.md/Task状态均不能代替验收账本。
3. **步骤校验与目标校验分层。** 步骤未完继续当前步骤；失败产生具体修复；单元通过才前进；全部必需目标条件通过才结束。独立 Goal 与绑定 Task 的 Goal 走同一验证内核。
4. **检查执行与裁决分离。** 只读 verifier 消费真实检查结果；受控 CheckRunner 复用执行准入与 canonical 工具链运行测试/后置检查。模型无工具、有界事实、严格 schema；不要求审计 Agent 实例。代码/build/runtime 检查优先确定性证据，非代码要求可用有界语义审阅。
5. **完成是结算输出。** Agent 的 DONE/Task completed 是 proposal；Task-bound Goal 由唯一结算器在版本和证据 gate 通过后原子写 Goal/Plan/Task 终态。禁止以 TaskCompleted 作为 GoalComplete 的循环前提，所有写入口使用同一 gate。
6. **事件立即续行，合法等待持久化。** runnable 工作写 due-now outbox；sleep 仅控制闲时心跳。AwaitEvidence/Dependency 保留 Goal 和逻辑绑定，释放执行资源，收到事件后重新 admission/预约并获取新 fence。重复/晚到结果不得复活已暂停或取消目标。
7. **目标寿命与执行额度分离。** 替换固定不可增大的 256 iteration 设计为配置和授权的正整数预算；内层、子代理与外层预算分开。累计费用/检查/子代理成本跨恢复不归零。预算耗尽是可补授权恢复的暂停，不是假完成。无人值守重启恢复需显式的持久 ResumePolicy；已有目标默认暂停不变。
8. **无进展触发修正，不产生自激。** 基于失败原因与输入指纹识别重复；选择新策略、另一可行步骤或依赖等待，必要时结构化暂停。无关新问题进入 backlog，不无限扩大当前目标。
9. **源码验收和运行验收分层。** 自修复可以改源码和交付测试，但最终产品目标需要明确加载 BuildId 的功能证据；Desktop/Core 生命周期由进程外控制器验收。复用 ADR-091 证据/审计/任务体系，不增加新审计 Agent 生命周期或轮询全部日志。

## 对旧设计的修订

本 ADR 在冲突处优先于 ADR-074 与旧 Goal 完整设计，保留其多入口统一受理、outbox、CAS、epoch、用户抢占、压缩独立和 Task-bound 原子启动。修订固定 256 上限、重启一律 disarm、TaskCompleted 代理完成证明、非 completed Turn 一律终止整个目标等不足；默认未授权重启恢复仍保持暂停。

替代死胡同任务 `dc0ac9a8236d4994ad04f0d9f860779c` 中“一律 NeedsReview 且保留 assignment”的 F1 最终方案：保留逻辑所有权，执行租约可释放，恢复时新 fence。既有旧执行失败和任务历史保留，不直接修改成成功。

ADR-091 继续决定执行准入和增量行为审计，ADR-090 继续决定上下文压缩，既有预算任务继续负责 PlanVersion=2 输入容量修复验收。本 ADR 不修改这些事实或重新分派已有源码所有权。

## 取舍

| 备选 | 不采用的原因 |
|---|---|
| 将 sleep 从小时缩短到几十秒 | 仍无完成证明、依赖心跳，增加空转 |
| 每轮让另一个 Agent 阅读全部聊天 | 成本高、讨论不是快照；无实际测试也不能证明完成 |
| 所有 Completed Turn 自动前进 Plan | 流程跑完不等于完成用户目标 |
| 测试失败直接 Goal Failed，再新建 Goal 重试 | 丢失目标身份、归属和累计预算，形成任务碎片 |
| 保留 assignment 不释放来避免恢复校验失败 | 长期 false-busy，掩盖逻辑归属与执行租约混淆 |
| 完全无限轮次与自动重启全部旧目标 | 脱离授权/预算/暂停意图，无法可靠无人值守 |

代价是新增验收合同和验证记录，并同步调整所有 Task/Goal 终态入口。先用最小表和纯结算函数落地，避免长期双实现兼容层。真实检查增加合理费用；按影响范围复用新鲜证据，不能省掉必要验证。

## 实施与验收

复用四张 Goal/恢复卡，按 G92-0 结算语义 → G92-1 真检查与分层验证 → G92-2 持久等待恢复 → G92-3 入口/UI/长程验收推进。完整测试矩阵见施工方案 §11。

必须证明：至少三轮同一 Goal 的“失败→修复→再验证→整体完成”；假 DONE/假 TaskCompleted 不可通过；浏览器关闭且 sleep=3600 秒仍自动续行；等待/崩溃/取消/旧结果不会丢失或重复目标；旧构建证据不能验收新源码。源码测试、真实新构建、24 小时及 7 天观察分别记录，尚未通过不标整体实现完成。
