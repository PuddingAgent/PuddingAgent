# 浏览器工具面归因分析与增强方向（2026-10-08）

> 本文只做两件事：**归因**（把"慢、贵、不达标"拆成可度量条目）与**增强清单**（改什么、落在哪、怎么取红）。
> 数据来源：本会话一手实测 + 已提交的两份报告；**不含代码改动**。人工计数处已显式标注。

## 一、实测基线（先给能证伪的数字）

| 指标 | 实测值 | 来源 |
|---|---|---|
| `browser_*` 总调用 | **≈58 次** | 会话转录**人工计数**（运行时仪器不可用，见 §五） |
| 真正推进目标的动作 | **6 个** | navigate×1 / 打开菜单×2 / 打开编辑器×1 / 写正文×1（其余为滚动、探针） |
| mutating 调用 | **≈14 次** | **全部返回假失败** `mutating capability returned a page version that did not advance` |
| 每次改动后的强制回读 | **≈20 次** | 每次 click/fill/scroll 后都要 `locate`/`tabs` 复核 |
| 全量 HTML 快照 | **3 次：290 KB + 712 KB + 380 KB = 1.38 MB** | 工具结果落盘文件字节数 |
| 单次 `locate` 最大载荷 | **104,485 字节（≈35k token）** | `kind=text` 命中祖先容器（会话早期实测） |
| 读取信噪比 | 正文 478 字符 / 9,172 字节 ≈ **10.4%** | 读知乎回答列表 9 次调用合计 |
| 最终交付 | **1 条草稿（未提交）** | —— |

**结论 A**：成本 ≈ **调用次数 × 上下文长度**。58 次调用只换来 6 个有效动作 ⇒ **每个有效动作伴随约 10 次调用**，成本被放大一个数量级。
**结论 B**：**假失败是最大放大器** —— 它把"1 次动作"强制变成"1 次动作 + 1~2 次回读"。
**结论 C**：**读取面没有中间档** —— 要么不读，要么全量（→ 只能"快照落盘 + python 离线抠"绕行，把 harness 的副作用当能力用）。

## 二、五层归因（按贡献排序）

### L1 回执不可信（贡献最大）· 已证实
- 现象：`click`/`fill`/`scroll`/`press` **全部**报 `browser_interact_failed … page version did not advance`，但动作**实际生效**（HTML 落盘 + 回读证实）。
- 根因（一手）：Host 侧版本不变量 `Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs:532-539` 与 Service 侧 `Source/Pudding.DesktopService/DesktopMutationInvariants.cs:17-36` 都要求"mutating 后 pageVersion **严格前进**"；而 **fill 类非导航变更永远不前进**，click 类只是竞态。
- 影响：**每一个 mutating 调用都必须回读** ⇒ 调用数 ×2~3，且把"成功"与"失败"变得不可区分。

### L2 可见面覆盖不全（第二）· 已证实
- 现象：点 `target=_blank` 后 Desktop 弹出**独立 OS 窗口**，而 Agent 侧 `browser_tabs list` / `pageCount` **无变化** ⇒ 我据此误判"点击无反应"。
- 根因（一手）：`Source/PuddingBrowser.WinUI/WinUiBrowserSurfaceHost.cs:67-88` 创建 WebView2 时**未订阅 `NewWindowRequested`**；新窗口既不入 `BrowserWorkspaceController._pages` 注册表，也不产生 TabItem。
- 影响：**副作用逃出探针**，Agent 无法观测、更无法管理（用户提的第 1、2 条需求）。

### L3 定位器能力不足（第三）· 已证实
- 无属性回传：`//a[...]/@href` 返回 **0** ⇒ 拿不到链接目标（只能用全量快照绕行）。
- **20 条假上限**：`locate` 只回 20 条，而 DOM 实际 40+ 条 ⇒ 会被读成"没有更多"。
- `kind=text` 命中祖先容器 ⇒ 单次 104 KB（≈35k token）；相对 XPath 精确命中（360 B）**差约 290 倍**。
- 图标按钮**无无障碍名**（`name`/`text` 全空）⇒ 无法语义定位。
- 不过滤不可见元素、不回报 `totalCount`/`filteredHidden`。
- 影响：定位只能"能用就行"地退化为**全量快照 + 离线正则**，成本从 KB 跳到 MB。

### L4 动作不原子（第四）· 已证实
- `click` **要求元素在视口内**（y=14/71/76 成功；y=1369/2499 无效），无 `scrollIntoView`。
- `scroll` 的 delta **不可预测**（请求 2200→实测 4095；1000→1412；2500→2500；-1300→-1300）⇒ 只能"滚—读—调"循环。
- `press` 不保证先聚焦元素（对我给的链接 ref 按 Enter 未导航）。
- 无坐标/`<point>/<bbox>` 交互、无 hover 路径（视觉与坐标操作的前置）。
- 影响：每步动作实际是**四拍**（滚→读→点→读）。

### L5 读取面只有"全量档"（第五）· 已证实
- `Source/PuddingBrowser.AgentTools/BrowserSnapshotTool.cs` 默认 `IncludeDom=true` + `IncludeAccessibilityTree=true`，`MaxNodes=5000`/`MaxTextLength=200000`/`MaxDepth=24`，**无 `mode`/`scope`/`limit`/`cursor`**。
- 唯一可用旋钮是 `max_text_length`（默认 20 万字符，实测**会把目标截断在页面中部**，直接导致一次"关键词 0 命中"的假结论）。
- 影响：不敢用 `snapshot`，只能"落盘 + python"。

### L6 状态不跨调用（第六）· 已证实
- `data-pudding-ref` 与 `pageVersion` 绑定 ⇒ 任何版本漂移使**全部**句柄失效，必须重新定位（本轮多次 ref→xpath 换形）。
- 无"已知元素缓存"、无"页面稳定"等待条件（`wait_for` 只支持 selector/url）。

### 附：Agent 侧（我方）责任（同样计入归因，不推给工具）
1. **精确匹配漏掉「编辑回答」**（`='编辑'` 命中 0）——本可先用 `contains` 起手；代价是数轮。
2. **从"探针无变化"推出"动作无效"** —— 违反自己的仪器纪律（应先划定"这件事的可见面覆盖到哪一层"）；真因是 L2。
3. **连续 3 次全量快照（1.38 MB）** —— 第 1 次后就应该收敛为"落盘 + 最小化抠取"。
4. **未在约 15 次调用无实质进展时停下来报告阻塞** —— 与"减少步骤"的目标直接冲突。

## 三、需要修改与增强的内容（含落点与验收）

### P0-1 回执可信化（消灭假失败 ⇒ 消灭全部强制回读）
- **改法**：版本判据分轨 —— 导航类动作看 `pageVersion`；**非导航变更**看"变更指纹"（DOM mutation 计数 / 编辑器文本哈希 / 元素状态），并统一在回执里返回 `evidence`（如 `contentHash`、`textLength`、`pageVersion`、`observedNoVersionChange`）。**不允许**把"版本未前进"直接判为失败。
- **落点**：`Source/Pudding.DesktopService/DesktopMutationInvariants.cs:17-36`、`Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs:532-539`。
- **验收（能取红）**：① `fill` 正文 ⇒ 返回 success + 带证据字段；② 反向变异——把判据改回"严格前进" ⇒ 该用例必须变红；③ 新建未导航页（`tabs new`）不再假失败。

### P0-2 新窗口进 TabItem + 多标签可见可管
- **改法**：`WinUiBrowserSurfaceHost` 在 `EnsureCoreWebView2Async` 之后订阅 `NewWindowRequested` ⇒ `e.Handled=true` ⇒ 回调统一调 `BrowserWorkspaceController.CreatePageAsync`（一次达成：同窗口 surface + `_pages` 注册表 + `Tabs.Add`）；`browser_tabs` 回执带上每页 `pageId`；WPF 宿主 `WpfBrowserSurfaceHost.cs:47` 补齐 parity；非 http/https 忽略，失败**回落并告警**（禁止静默外抛）。
- **落点**：`Source/PuddingBrowser.WinUI/WinUiBrowserSurfaceHost.cs:76`、`Source/PuddingDesktop/MainWindow.xaml.cs:952-956`、`Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs:283-318`、`Source/PuddingBrowser.WebView2/WpfBrowserSurfaceHost.cs:47`。
- **验收（能取红）**：点任意 `target=_blank` ⇒ `browser_tabs list` page 数 **+1**、`pageCount` 同步、新 page 可 activate/close、UI **无新窗口**；对照：临时移除订阅 ⇒ 用例必须变红。

### P0-3 定位器可信化（href / 精确 / 分页 / 过滤）
- **改法**：`locate` 结果增加 `href`（及 `value`/`aria-label`/`checked`/`contenteditable`）；支持 `kind=href` 或属性选择；命中改为 `limit`+`cursor` 并返回 `totalCount`；文本匹配默认"最小可交互祖先"或显式 `contains` 开关；默认过滤不可见元素并回报 `filteredHidden`/`matchedBeforeFilter`。
- **落点**：`Source/PuddingBrowser.AgentTools/BrowserLocateTool.cs` + Desktop 侧 locate 命令。
- **验收（能取红）**：取列表第 22 条链接的 `href` ⇒ **1 次调用、≤1 KB**（现基线：1 次 712 KB 快照 + python）；`kind=text` 对同一目标 ≤2 KB（现 104 KB）。

### P1-1 动作原子化（scrollIntoView / 元素级滚动 / 坐标）
- **改法**：`click`/`fill` 前自动 `scrollIntoView({block:'center'})` 并回报 `scrolledBy`；新增 `action=scrollIntoView(locator)`；支持 `<point>/<bbox>` 坐标动作与 hover；`press` 先聚焦并回报 focused 元素。
- **落点**：`Source/PuddingBrowser.AgentTools/BrowserInteractTool.cs`、`Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs`。
- **验收（能取红）**：对 `y=2499` 的元素直接 `click` 成功（无需手工滚动）；`scrollIntoView` 同参数**同结果**（可复现，现 delta 版不可复现）。

### P1-2 读取面分级 + 作用域 + 预算回报
- **改法**：`snapshot` 增 `mode=outline|text|full|html`（默认 `outline`：只给可交互元素 + 标题层级 + 计数）；增 `scope`（子树选择器）与 `limit`/`cursor`；`include_html` 仅在显式请求时返回，且**默认落盘并返回路径**（把现在的事故性用法变成契约）；输出必带 `totalChars/returnedChars/truncated`。
- **落点**：`Source/PuddingBrowser.AgentTools/BrowserSnapshotTool.cs`。
- **验收（能取红）**：读一个回答页正文 ⇒ **1 次调用 ≤2 KB** 拿到正文 + 结构（现基线：380 KB 快照或快照截断导致 0 命中）。

### P2-1 会话级元素句柄与稳定等待
- **改法**：元素句柄跨 `pageVersion` 漂移仍可解析（或提供"按 locator 重新锚定"的原子动作）；`wait_for` 增 `textChange`/`stable`（DOM 静默 N ms）。
- **验收**：同一元素在两次小改动后仍可直接点点，无需重新 locate。

### P2-2 抽取作为一等能力
- **改法**：提供 `browser_extract(url|locator, format=text|markdown|json, path)`：内部完成"取子树叶 → 转 markdown/JSON → 落盘 → 返回路径 + 摘要"，把本轮"全量 HTML 落盘 + python 正则"的手工链路固化为契约。
- **验收**：从列表页取"第 N 条链接的 href + 标题" ⇒ 1 次调用；从回答页取正文 markdown ⇒ 1 次调用。

## 四、总验收口径（把"减少步骤与 tokens"变成可证伪的数字）

**基准任务**：打开指定知乎回答 → 进入编辑器 → 写入正文（不提交）。

| 项 | 现基线（本轮实测） | 目标 |
|---|---|---|
| 调用次数 | ≈58 | **≤8** |
| 累计可见载荷 | 1.38 MB 快照 + 多次 3 KB locate | **≤50 KB** |
| 假失败 | ≈14 次 | **0** |
| 强制回读次数 | ≈20 | **0**（回执自带证据） |
| 人工滚动调参 | 5 次 | 0（scrollIntoView 原子化） |
| 最终交付 | 1 条草稿 | 1 条草稿 |

**反例约束（必须同时成立）**：不允许用"乐观成功"换指标 —— 回执必须带**可核验证据**（`contentHash`/`textLength`/`pageVersion`），无证据时**宁可报"未确认"**。

## 五、仪器与度量的前提（否则指标不可测）

`agent_diagnostics action=tool_stats` 对 `browser_interact`/`browser_locate` 返回 `total_calls=0`（自述 "not found in 500 RuntimeActivity records"，`available_tool_names` 仅 search_grep/file_read/list_dir）⇒ **浏览器工具成本无法用运行时数据度量**，本文数字只能人工统计。要落实 §四 的预算，**先修度量**：把 `browser_*` 纳入 activity 统计并延长保留窗口（>500 条）。

## 六、不做的事（防止"看起来顺滑"掩盖风险）

1. **不放宽准入/接管闸门**换体验：UI「人工接管」当前只写 controller 的 `_userTakeover`（`BrowserWorkspaceController.cs:490`），**从不调用** `BridgeDispatcher.SetUserTakeover`；真闸门在 `BrowserBridgeCommandDispatcher.cs:20/45/68-79`。这是**独立的安全语义缺口**，不能与本次体验优化混改。
2. **不把静默外抛当兜底**（`OpenExternal` 式外抛正是本案缺陷形态）。
3. **不为减少调用而省略证据**（见 §四 反例约束）。

## 七、未证实项（沿用缺陷报告 §八，勿当结论）

- 用户截图中"**2 个**独立窗口"的**数量**无唯一源码解释（需实机复现计数）；
- "本机生效传输 = WebSocket Bridge、能力通道未启用"系**配置 + 代码路径推断**，未用运行时日志二次确认；
- 能力通道模式下 `browser_tabs new` 绕过 `BrowserWorkspaceController`（`BrowserRuntimeDesktopSurface.cs:195-230`）⇒ 新建页无 TabItem/无注册表，属**代码路径推断的潜伏风险**。
