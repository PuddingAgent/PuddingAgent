# 必盈工具设计：按研究流程切分，按体积整形

## 0. 出发点

用户裁定（2026-10-25）：集成到 PuddingAgent、使用付费证书。
并要求「根据 skill 的需求设计」——所以工具边界不是按 API 分组切，而是**按研究动作切**。

依据的 skill：`a-share-equity-research`（已安装，255 行，8 个阶段）。

## 1. 接口面（实测，非估计）

注册表 `Tools/Biying/endpoints.json`：**200 个端点**，7 大类。

调用形态（实测校正）：

```
https://api.biyingapi.com/{组}/{接口}/{代码}/{licence}
https://vip.biyingapi.com/{...}          # 11 个 Pro 端点
```

`licence` 是**末段路径**，不是 `?licence=`。用错返回
`{"code":404,"message":"Licence证书不存在","licence":"<代码>"}`。

## 2. 响应体积是首要约束（实测）

| 端点 | 一次返回 | 折算 token（约） |
|---|---|---|
| `hsstock/financial/balance/000001`（资产负债表） | **229,084 字符** | ≈ 60k |
| `hsstock/financial/pershareindex/000001`（主要指标） | 39,399 字符 | ≈ 10k |
| `hszg/list`（行业概念树） | 178,716 字符 | ≈ 45k |
| `hslt/list`（股票列表） | 250,566 字符 | ≈ 65k |
| `hscp/cwzb/000001`（财务指标） | 4,987 字符 | ≈ 1.3k |

**结论：原样返回等于把一次查询变成一次上下文灾难。** 整形（投影 + 限量 + 词典）不是优化，是
能否使用的前提。

## 3. 工具切分（5 个，全部走延迟加载）

| 工具 | view 取值 | 命中端点（id） | 服务的 skill 阶段 |
|---|---|---|---|
| `biying_market` | `quote` / `batch` / `index` / `kline` | 54, 248, 253, 314/254, 315 | 阶段 2 初筛、阶段 5 预期差、阶段 6 估值（pe/pb/市值） |
| `biying_financial` | `balance` / `income` / `cashflow` / `indicators` / `pershare` / `express` / `forecast` / `dividend` | 255, 256, 257, 44, 258, 105/106/107, 38 | 阶段 3 年报穿透（主力）、阶段 6 |
| `biying_flow` | `dragon` / `seat` / `moneyflow` / `holders` | 78/79/80/81, 273/303, 45/46/260/261 | 阶段 5 事件与情绪、阶段 3 治理关联 |
| `biying_sector` | `tree` / `members` / `belong` / `list` | 4, 5, 6, 1 | 阶段 1 行业扫描、阶段 4 横向对比 |
| `biying_raw` | —（`endpointId` + `pathArgs` + `query`） | 任意（**必须命中注册表**） | 兜底：注册表里有但前四个工具没覆盖的 170 余个端点 |

为什么不是"一接口一工具"：200 个工具会直接压垮工具预算，也会让模型在选择上耗时。
为什么不是"只有一个 generic 工具"：`quote` 和 `balance` 的参数、默认期数、整形规则完全不同，
塞进一个 schema 会让默认值互相污染。

`biying_raw` 的存在保证"覆盖完整"，同时它的入参是**端点 id**而不是 URL——
模型不需要知道路径拼接规则，也拼不出越权地址。

## 4. 响应整形规则（每个工具强制）

1. **限额**：默认只返回最近 `years=5`（财务）或 `limit=20`（K线/榜单）条；`max` 上限硬编码。
2. **投影**：每个 view 维护一份字段白名单，只回传参与判断的字段（如资产负债权只取
   `jzrq/plrq` + 应收/存货/商誉/有息负债等十余项），其余丢弃。
3. **词典**：必须随响应返回 `legend`，形如 `{"jzrq":"截止日期(yyyy-MM-dd)"}`，
   **且只列投影用到的键**。原始返回是拼音短键（`jzrq`/`plrq`/`mgjz`），
   不给词典模型只能猜，猜错比不给更糟。
4. **截断透明**：始终回 `total` / `returned` / `truncated=true`，并附 `nextHint`
   （如"要更早年度请传 years=10"）。禁止静默截断。
5. **分页兜底**：`hslt/list`、`hszg/list` 这类超大静态表，只提供**按关键词检索**的
   入口（`query="平安"`），不提供全量导出。

### 4.1 整形层的实测语义（S2c 已实现）

双层限制：`MaxRows`（默认 5 行）与 `MaxChars`（默认 8,000 字符）**先到先生效**。
实测 112 字段的资产负债表在 8,000 字符预算下只能放下 3 行——这是预期行为，
不是 bug。

选行不靠源顺序：实测资产负债表是**升序**（1990 在前）、财务指标 `cwzb` 是**倒序**，
端点之间不一致。所以整形层统一按日期字段倒序取最近 N 期。

连一行都装不下时，返回 `budgetExceeded: true` + `singleRowChars` + 提示用 `fields` 收窄，
**而不是硬塞**。硬塞会让预算形同虚设，一次查询就能毁掉一段上下文。

### 4.2 真实数据冒烟（2026-10-25，付费证书，共消耗 3 次配额）

不碰宿主，直接用临时控制台程序引用 `PuddingFinance` 跑真实请求：

| 调用 | 原始字符 | 整形后 | 行数 | 备注 |
|---|---|---|---|---|
| `quote 000001` | 301 | 605 | 1 | 词典占比高，小包体会膨胀 |
| `balance 000001` | **229,084** | **5,682** | 2 / 131 | **压缩 40 倍** |
| `indicators 000001` | 4,987 | 1,581 | 3 / 4 | 投影生效 |

另外验证了两条最关键的运行时行为：

1. **缓存命中不扣配额**：同一 quote 第二次返回 `cache=True`，`remaining` 纹丝不动。
2. **配额计数真实生效**：3 次网络调用后 `quota used=3`。

一个观察：小响应（301 字符）整形后反而变大到 605 字符，因为词典本身就占大头。
> 目前可接受（绝对值小），但将来做多股批量（248）时要注意：
> 词典应该提到外层只发一次，而不是每行重发。

复现方式：`temp/biying-smoke/`（已 gitignore），引用组件工程、读 `D:\Data\config\biying.api.json`。

## 5. 字段词典从哪里来（已找到，可机械抽取）

文档页每个接口下方都有「返回字段说明」表：

```html
<h2>返回字段说明</h2>
<table class="doc-params-table">
  <tr><td><code>jzrq</code></td><td>string</td><td>截止日期yyyy-MM-dd</td></tr>
```

⇒ 注册表要从 v1 扩到 v2，每个端点带上 `fields: [{key, type, desc}]`。

**已完成（2026-10-25）**：注册表升到 `pudding.biying.endpoints.v2`，
**200/200 个端点都有字段词典，合计 2,618 条字段定义**；
字段数分布 min 1 / p50 10 / p90 19 / max 112（最大的是资产负债表）。
`extract_endpoints.py --check` 已把「任一端点缺字段」做成**硬门禁**（失败退出 2），
避免文档改版后静默退化成无词典的裸返回。

## 6. 配额与缓存（付费证书 10,000/天）

| 类别 | TTL | 依据 |
|---|---|---|
| 实时行情 | 10 秒 | 官方 3 秒/次刷新 |
| K 线 | 到下一个交易日开盘 | 日线收盘后 30 分钟内更新 |
| 三表 / 指标 / 分红 | 24 小时 | 财报按季更新 |
| 列表 / 板块树 / 个股列表 | 24 小时 | 极少变化 |

- 进程内计数，达 `dailyQuota × quotaWarnRatio`（默认 80%）开始回执告警；
- 达 100% 直接拒绝并**说明已用/上限**，不静默失败；
- 缓存命中不计入配额消耗。

## 7. 与既有机制的关系

- 5 个工具默认**不可见**，由 `search_tools` 按需加载 ⇒ 常态零 prompt 成本；
- 若启用三级披露，冷门工具走 L1 摘要（只发名称与首句描述）；
- 任何一次工具集合变化都会改写 `ToolSpecHash`（实测约 15.2k token 未命中），
  所以**首次加载后不要来回卸载**。

## 8. 实施顺序

| 步骤 | 内容 | 验收 |
|---|---|---|
| S1c | 注册表 v2：补 `fields` 词典 | ✅ 已完成：200/200 端点、2,618 字段，`--check` 硬门禁 |
| S2 | 客户端（HttpClient + 缓存 + 配额 + 超时/重试） | ✅ 已完成：缓存先行不扣配额、业务错误识别、证书错误不可重试 |
| S2c | 响应整形（选行/投影/词典/预算） | ✅ 已完成：35 个用例，229KB→<8KB；单行超预算时返回可行动回执 |
| S3 | `biying_market` + `biying_financial`（最常用） | ✅ 已完成：view→端点+参数+投影，K 线默认不复权、不猜市场后缀 |
| S4 | `biying_flow` + `biying_sector` + `biying_raw` | 同上 |
| S5 | 接入宿主注册表并登记 code_map | ⚠️ 代码已完成（工具类 + DI 单例 + 组件引用），**未重启生效** |

每一步都可独立验证、可回滚；S5 之前不改宿主。
