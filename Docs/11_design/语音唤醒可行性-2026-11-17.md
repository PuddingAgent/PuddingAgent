# 语音唤醒可行性：sherpa-onnx KWS 在这套代码里的落点与五个风险

## 0. 结论

**技术上可行，但缺的不是"唤醒词引擎"，是"麦克风采集"这一层。**

本仓已有的四块（流式 ASR、流式 TTS、静音判停、播放）都能复用；
真正要新增的只有两件：**唤醒词检测**与**常驻采集**。

推荐顺序是**先把采集与检测做成独立可测组件，再谈状态机**，
不要一上来做"Live 对话"——那会把回声自激、打断语义、延迟预算三件事同时压进来。

## 1. 已核实的事实（2026-11-17 05:58–06:00 现场）

### 1.1 NuGet 侧有 .NET 包

```
org.k2fsa.sherpa.onnx                    2.0.1
org.k2fsa.sherpa.onnx.runtime.win-x64    2.0.1
```

（查询：`azuresearch-usnc.nuget.org/query?q=sherpa-onnx`，返回 10 条，含 win-x64 / win-arm64 / linux / osx / android）

### 1.2 有中文 KWS 预训练模型

sherpa 官方文档列出了关键词检测模型：

| 模型 | 语言 | 说明 |
|---|---|---|
| `sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20` | 中 + 英 | 解包后约 **38 MB**，含 encoder/decoder/joiner + tokens |
| `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01` | 中文 | 更旧、更小 |

### 1.3 模型下载在本机当前不通

```
HEAD https://github.com/k2-fsa/sherpa-onnx/releases/download/kws-models/...tar.bz2
→ The SSL connection could not be established
```

这是**带时点的环境事实**，不是永久结论：同一时段 `git push` 走 HTTPS 是通的，
说明是选择性连通问题（与既有记录一致：`api.github.com` 长期不通）。

**含义**：落地时必须准备镜像/代理或人工预置模型文件，不能让首次启动依赖 GitHub 可达。

### 1.4 本仓没有实时麦克风采集依赖

`Source/PuddingRuntime/PuddingRuntime.csproj:23` 只有：

```xml
<PackageReference Include="NAudio.Core" Version="2.3.0" />
```

全仓 NAudio 用法只有一处：`ManagedOggOpusTranscoder.cs:65` 的 `WaveFileReader`（**解析文件**）。

**`WaveInEvent` / `WasapiCapture` 属于 `NAudio.WinMM` / `NAudio.Wasapi`，当前未引用。**
所以"原生层已经能采音"这个印象是错的——它只能读已存在的 WAV 文件。

网页侧的采集是 `getUserMedia`，属于页面生命周期，关页面即停。

## 2. 两条路线

| | A｜原生（C#） | B｜网页（Web Audio + onnxruntime-web） |
|---|---|---|
| 新增依赖 | `org.k2fsa.sherpa.onnx(.runtime.win-x64)` + `NAudio.WinMM` 或 `NAudio.Wasapi` | `onnxruntime-web` + 模型文件进静态资源 |
| 常驻能力 | **可以**（进程活着就在听） | 不可以（页面关掉就没了） |
| 与 TTS 抢麦 | 需自己做 AEC 或播放期停检 | 同一页面内可控，相对简单 |
| 包体积 | 桌面端 +若干 MB | 首屏 +数 MB，需懒加载 |
| 可测试性 | 纯 C#，可用固定 wav 喂给检测器做断言 | 需 jsdom 模拟，较弱 |
| 结论 | **推荐**，符合"喊一声就开麦"的原意 | 仅作为快速验证原型 |

## 3. 五个必须先吸收的风险

1. **自激（最致命）**：我播 TTS 时麦克风会听见自己。若唤醒词出现在回复文本里，就会自我唤醒并循环。
   必须"播放期间暂停检测"，或引入回声消除。**这条不做，功能一定炸。**
2. **误唤醒**：`你好鲸鲸` 与 `晶晶/静静/经经` 同音。缓解手段是**唤醒后二次确认**——
   响一声提示音，1.5 秒内无语音即丢弃，不上传、不计费。误触发的代价压到"一声滴"。
3. **麦克风归属**：网页 `getUserMedia` 与原生采集可能互斥；会议软件占用时也拿不到设备。
   必须**明确单一采集者**，并把这个归属写进契约，而不是运行时抢。
4. **常驻观感**：必须有可见状态（正在听 / 已暂停）与随手关闭，否则像被监听。
5. **模型供应链**：见 §1.3，下载不可依赖实时网络。

## 4. 建议的交付拆分（按《组件化交付规程》）

| 阶段 | 交付 | 判据 |
|---|---|---|
| P0 | **唤醒词匹配器**（纯逻辑，输入帧序列 → 是否命中），不碰设备 | 用固定 wav / 合成帧做单测；变异取红 |
| P1 | **采集层**（新增包 + 环形缓冲），仍不接 UI | 能写出可回放的 wav；无设备时失败要显式 |
| P2 | **状态机**（idle → listening → thinking → speaking，含 barge-in） | 打断必须丢弃已生成的剩余内容 |
| S5 | 接入宿主 | 上面三步各自独立验证通过之后 |

P0 可以**现在**就做，且不依赖模型下载是否可达——用假数据即可先锁住行为契约。

## 5. 未证实的部分（不要当成结论）

- sherpa-onnx .NET API 的**具体调用形态**（`KeywordSpotter` 类名、流式接口形状）未在本机验证，
  只确认了包存在。
- 该 38 MB 模型在本机 CPU 上的**实时率与内存占用**未测。
- `你好鲸鲸` 在本模型词表里的**音素切分是否可行**未验证——这是 KWS 的关键前提，需实测。
- 与 Windows 默认输入设备的**采样率协商**（16 kHz / 单声道）未验证。

## 6. 与已完成工作的关系

2026-11-16 已落地：`voice` 围栏播放（浏览器 → Qwen3-TTS）、只播一次、
按住说话的手势修复、静音自动发送、音色对配置校验（`5ea8937`）。

这些都在"我说、你说完"这一层。语音唤醒是**下一层**：让对话不必从点击开始。
两者共享设备与状态机，所以 P2 之前不要动现有按键链路。
