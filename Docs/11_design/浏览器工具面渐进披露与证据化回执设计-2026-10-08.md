# 浏览器工具面：渐进披露、markdown 阅读与证据化回执设计（2026-10-08）

> 输入来源：用户给出的**正面例子**（渐进披露 / 返回 markdown / 支持把操作交给子代理）与
> **反面例子**（默认返回全量 HTML / 不支持选择器 / 无法方便阅读 DOM / 无法准确测量与模拟点击移动 / 不支持视觉理解）。
> 本文档把这些要求转成**有证据的现状判定 + 目标形态 + 可测验收指标**。状态：**提案，未实施**。

## 一、现状逐条判定（附一手证据）

### 正面期望

| 期望 | 现状 | 证据 |
|---|---|---|
渐进披露：只返回需要的 | ❌ **未实现** | `BrowserSnapshotTool.cs` 默认 `IncludeDom=true` 且 `IncludeAccessibilityTree=true`，预算 `MaxNodes=5000`、`MaxTextLength=200000`、`MaxDepth=24`；**无 `mode`/`format`/分级参数**。实测：极简页 `example.com` 一次调用即吃满 8.6 KB 仍 `truncated`；Bing 结果页 `snapshot` **一条结果都读不到**（`truncated=true`，`nodeCount=63`），结果列表反而是靠 `locate css "li.b_algo h2"` 拿到 10 条（≈2.6 KB）。 |
支持 markdown 返回 | ❌ **未实现** | `BrowserSnapshotToolValue` 仅 `DomText/AccessibilityTree/Html/Truncated/NodeCount`；`DomText` 是**深度缩进标签树**（仅带 `ref` 属性），既非正文也非 markdown。 |
操作可交给子代理 | ⚠️ **机制在、浏览器专用通道未证实** | `spawn_sub_agent(tools=...)` 可限定工具集，理论上可把"点某个按钮"整包委派；但**子代理是否被注入 `browser_*` 工具未证实**（见 §五）。 |
支持选择器 | ✅ **已支持**（与反面例子不符） | 工具描述承诺 `ref/css/xpath/text/role/label/placeholder/alt/title/test-id`；实测 `css`、`role`、`ref` 均可用（`role=textbox` 命中 13 个），**仅 `text` 实测失效**（`count=0`，而元素确在无障碍树中为 `link name="Learn more"`）。 |

### 反面现状

| 反面例 | 是否属实 | 证据 |
|---|---|---|
默认直接返回全量 HTML | ✅ **属实** | 见上：默认 20 万字符预算 + 双树全开 + 无分级参数。 |
不支持选择器 | ❌ **不属实**（需纠正） | 选择器可用；坏的是 `text` 类型 + 定位结果噪音（见下条）。 |
无法方便地阅读 DOM | ✅ **属实** | ① 缩进标签树不可直接阅读；② 无障碍树把**整页文本重复挂在 `html`/`body`/`banner` 三个祖先的 `name` 上**（同段文字回 3 次）；③ `snapshot` 截断即丢失正文；④ `locate` 返回的 `text` 字段**不含表单值**（`fill` 后仍为空）⇒ 无法确认输入是否写入。 |
无法准确测量与模拟点击/移动 | ✅ **基本属实** | ① 有 `boundingBox` 但**浮点全精度**（`389.03125`、`834.328125`）且 `visible` 会误判（百度 `#kw` 页面已渲染却 `visible:false` + bbox `0×0`，`fill` 被 fail-closed 拒绝）；② 隐藏节点不过滤（`role=textbox` 13 个里 9 个 `0×0`）；③ **无坐标点击**（只有 locator 点击）、**无鼠标移动**（仅元素级 `hover`）、无拖拽上传；④ `scroll` 底层未生效（`delta_y=1200` 实测坐标零位移，而工具层允许无 locator）。 |
不支持视觉理解 | ✅ **属实，且是宿主层显式未实现** | `Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs`：`ScreenshotAsync` / `PrintToPdfAsync` **直接 `throw new NotSupportedException("Not in Phase 2A-1")`**（一手读取原文）；工具目录中也不存在任何截图工具。 |

**应当保留的既有优点**（重设计时不要推翻）：`ref` 带版本身份（旧引用会被 `stale_element_reference` 拒绝，防误操作）；`snapshot` 的 `includeHidden` 默认 `false`；元素不可见时 mutating 调用**fail-closed 拒绝**（百度那次是**正确行为**）；`focus` 在映射层明确标注 unsupported 而非静默失败。

## 二、目标形态设计

### 2.1 读取面：**分级 + markdown + 预算收敛**（本设计的主收益点）

给 `browser_snapshot` 引入 `mode`（默认 `outline`），把"读什么"从调用方猜变成契约：

| mode | 返回 | 默认预算 | 用途 |
|---|---|---|---|
`outline`（默认） | 只列**可交互节点 + 标题/地标**，每行一条：`- [ref] 角色 "可访问名" (x,y,w,h)` | 50 行 / 4 KB | 让 Agent 先看到"能点什么、能填什么" |
`text` | 页面正文的 **markdown**（标题层级、列表、表格、链接保留 URL），去导航/页脚噪声、去重复 | 4 KB | 让 Agent 能**读内容** |
`interactive` | 同 `outline`，只含可点击/可输入节点 | 50 行 | 定位前的最小上下文 |
`full` | 现有行为（DOM + 无障碍树 + 可选 HTML） | 需显式开启 | 排障专用 |

配套硬要求：
1. **默认预算收敛**：`MaxNodes 5000 → 50`、`MaxTextLength 200000 → 4000`、`MaxDepth 24 → 6`；超限返回 `truncated + nextCursor`（**游标分页**），而不是静默截断。
2. **祖先 name 去重**：无障碍树禁止在 `html`/`body`/`banner` 重复整页文本。
3. **不要"两份都开"**：`outline`/`text` 模式下只回一份表示，不再同时回 DOM 树与无障碍树。

### 2.2 定位面：修正选择器矩阵与测量可信度

- **修 `text` 定位**（子串匹配、忽略首尾空白与多余空格）；`role` 支持 `role + name` 组合。
- **默认过滤不可见节点**（`visible=false` 不进结果），保留 `include_hidden` 开关；给 `limit` + `cursor`。
- **`bbox` 取整**（token 与可读性），新增 `inViewport` 布尔（判断是否需要先滚动）。
- **新增 `value` 字段**：回读 input/textarea/select 的当前值 —— 这是"输入是否成功"的唯一可靠回执。
- 定位结果**去重** `name` 与 `text`（多数场景二者相同，重复浪费一半体积）。

### 2.3 操作面：**证据化回执**（一次调用就知道成没成）

- **修 P0 假失败**：`BridgeBrowserCapabilitySurface.cs:532-539` 的"版本必须严格推进"按动作类型拆分 —— 导航类（`click`/`press`）改**带超时轮询**等待；非导航 DOM 变更（`fill`/`type`/`select`/`check`/`hover`/`scroll`）改 **DOM 断言**（值/勾选/位移已按请求改变）。Desktop 侧同判据需同步（位置待定位）。
- **回执内含后置断言**：`{ok, action, targetRef, assertions:[{kind:'value', expected, actual}], urlChanged, pageVersion, scrollY}` ⇒ Agent **不需要**再发一次 `snapshot` 验证（这是最直接的省 token 手段）。
- **补坐标级操作**：`click(x,y)`、`move(x,y)`（真实鼠标移动）、`drag(from,to)`、`upload(files)`；`scroll` 支持 `to_ref` / `to_top` / `to_bottom`，并修底层未生效缺陷。
- 修 `ref` 短命问题：失效时**自动重解析**（按稳定的 role+name+序号）而不是直接抛 `stale_element_reference`，减少"重定位"样板调用。

### 2.4 委派面：把"读一段/点一个"整包交给子代理

目标：**父代理的上下文只吃结论，不吃页面**。

- 形态：`browser_task(page, goal)` 语义由父代理用 `spawn_sub_agent` 表达 —— 子代理拿到 `contextId/pageId + 目标描述`，内部自行 `mode=outline → locate → interact → 断言`，只回 `{结论, 关键文本片段, 证据(ref/URL/断言结果)}`。
- 前置条件（**待验证**）：子代理需被注入 `browser_*` 工具；否则先用 `spawn_sub_agent(tools: "browser_context,browser_tabs,browser_snapshot,browser_locate,browser_interact,browser_wait_for")` 显式声明。
- 收益估算：父代理侧上下文成本从 O(页面字节) 降到 O(结论字节)，与 §三 的验收指标同向。

### 2.5 视觉面：把截图从桩变实

- `ScreenshotAsync` 真正实现（当前 `throw new NotSupportedException("Not in Phase 2A-1")`），输出走 **Vision Artifact / 文件通道**，支持区域裁剪与 `detail=low`（≤512px）以控成本。
- 分工原则：**DOM 用于精确操作，截图用于判定**（图表、canvas、验证码、布局/视觉回归、以及"点了没反应"这类歧义）。
- 与既有能力衔接：Agent 侧已有原生视觉读取（`image_reader`），缺的只是"页面 → 图片"这一步。

## 三、可测验收指标（本设计的硬标准）

1. **读一个搜索结果页并取回前 10 条标题**：现状 ≈ **11 KB**（`snapshot` 8.6 KB 且不含结果 + `locate` 2.6 KB）⇒ 目标 **单次调用 ≤ 1.5 KB**（`mode=outline` 或 `mode=text`）。
2. **单次 `fill` 调用即可确认写入成功**：回执含 `assertions[{kind:'value', actual}]`，无需二次 `snapshot`（现状：需 `locate` 回读且 `text` 字段为空 ⇒ 只能靠提交后的 URL 反推）。
3. **读一篇文章正文**：`mode=text` 返回 markdown，正文覆盖完整且 `truncated=false`（现状：标签树 + 截断）。
4. **视觉理解**：`screenshot` 产出可被 `image_reader` 读取的 artifact，`detail=low` 下单张 ≤ 40 KB。
5. **操作可信**：所有 mutating 调用返回 `ok=true` **当且仅当**后置断言通过（消灭假失败与假成功）。
