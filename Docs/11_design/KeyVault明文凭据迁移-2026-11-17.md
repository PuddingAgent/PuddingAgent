# 明文凭据迁入 KeyVault：事实纠错与分期方案

## 0. 结论

原来的迁移任务书有**两处**事实错误，按它执行会打断功能：

1. **`{{vault:}}` 不是通用占位符。** 它只在 `LlmProviderFileService` 的 apiKey 解析链里被展开；`VoiceProviderFileService` 是**裸读** `p.ApiKey`。把语音/搜索/CalDAV 改成占位符，等于把字面量 `{{vault:xxx}}` 当成密钥发给上游。
2. **飞书连接器的凭据不是来自 `D:\Data\config\feishu.json`**，而是 `D:\Data\channels\<channel>\manifest.json`（实测 `feishu-default.global_general-assistant.6a8\manifest.json`，792 B 存在）。改错文件等于没改。

因此迁移**不能**作为"一次性替换配置"来做，必须先让各条读取链具备解析能力，再改配置。

## 1. 已核实的证据（2026-11-17 08:30 现场）

| 事项 | 证据 |
|---|---|
| 占位符正则 | `Source/PuddingPlatform/Services/KeyVaultService.cs:34` `\{\{vault:(?<name>[a-zA-Z0-9._-]+)\}\}` |
| 唯一展开实现 | `Source/PuddingPlatform/Services/LlmProviderFileService.cs:734-756`（`${ENV}` → `{{vault:}}` → `ApiKeyRef`） |
| 语音无解析 | `Source/PuddingPlatform/Services/VoiceProviderFileService.cs:52,73,124,166` 直接使用 `p.ApiKey` |

| 其余端点 | `GET secrets`、`GET secrets/{id}`、`POST inject`、`POST strip` |
| 飞书凭据源 | `D:\Data\channels\feishu-default.global_general-assistant.6a8\manifest.json`（792 B） |
| 主密钥 | 已接线并上线（`e01f289`；`D:\Data\secrets\keyvault.master` 262 B / 11-16 21:24:33） |
| 当前 vault 引用数 | `D:\Data\config` 25 个 json，**0** 个使用 `{{vault:}}` |

## 2. 分期（每期都能独立验收、独立回滚）

| 期 | 内容 | 前置 | 验收 |
|---|---|---|---|
| **P1** | 只迁 `llm.providers.json` 的 apiKey（解析器已存在） | 无 | 守卫测试 + LLM 真实调用一次 |
| **P2** | 给 `VoiceProviderFileService` / 搜索 provider / CalDAV 增加与 LLM 同源的解析链 | 抽公共 resolver，避免三处各写一份 | 守卫测试 + **变异取红**（去掉解析必红） |
| **P3** | 迁语音 / 搜索 / CalDAV | P2 完成 | 三条链路各真实调用一次 |
| **P4** | 迁飞书（改 `channels/*/manifest.json`，不是 config/feishu.json） | 确认连接器是否支持引用 | 连接器收发各一次 |
| **P5** | 处理 6 份 `.before-*` 备份（其中 1 份无法解析） | 需用户授权删除或外移 | 明文检索 0 命中 |

**不做**：不动加密实现、不动主密钥、不做密钥轮换。

## 3. 未证实（不要当结论用）

- 搜索 provider 的读取类与是否已具备解析——尚未逐行确认，只在平台层 grep 未见 `vault:` 命中。

- `system.json` 的 `desktop.controlToken` 是否由进程直接消费（若直接消费则同样需要解析器）。
