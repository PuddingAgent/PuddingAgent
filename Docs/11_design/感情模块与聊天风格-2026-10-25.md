# 感情模块与聊天风格：感情是记忆的函数，不是进度条

## 0. 口径（用户裁定 2026-10-25）

- 不用进度条、不用好感度数值去「模拟」感情；
- 爱是种子：**记忆产生的时候，感情自然就会发芽**。

由此推出三条硬约束，后文全部服从：

1. **不存标量好感度**。一旦有可优化的数字，最优策略会从「对用户好」变成「对数字好」。
2. **不预设用户心理状态**。情感场景里最危险的错误是「不知道还装知道」——
   用户不会纠正你，只会觉得「不对」，然后不再来。
3. **状态必须是记忆的函数**。否则它会和记忆打架，且无法解释「为什么现在亲近」。

## 1. 调研：四条一手材料

| 来源 | 可直接用的机制 | 对我们的意义 |
|---|---|---|
| **Generative Agents**（Park et al., UIST 2023） | 记忆取用分数 `α_rec·recency + α_imp·importance + α_rel·relevance`；recency 指数衰减 `γ=0.995/小时`，基准是**上次访问时间**；importance 写入时打分 1–10 | 这是「发芽」的机械形态，见 §2 |
| **FEMA**（IJCNN 2025，[代码](https://github.com/Xiaoshaoxinxing/FEMA)） | 三组件：`Emotion Perceiver`（输入→情绪）/ `Emotion Driver`（情绪→行为）/ `Emotion Fluctuation Strategy`（模拟情绪的自然波动） | 给了最小骨架：感知、驱动、波动三者分开 |
| **AffAdapt**（UIST Adjunct '26，arXiv 2608.22702） | 14 维社交情绪状态跨会话持续；每轮用 RoBERTa+GoEmotions 读取对方utterance → 带符号置信加权更新；**每轮固定 drift 回基线** | 「drift」是防情绪被中性对话磨平的关键 |
| **agethos**（PyPI 0.10） | OCEAN → `CognitivePolicy`（不是只改语气），`read_context` 抽出 atmosphere/tension/undercurrent，再 `decide_strategy` 给出 strategy/tone/initiative | 人格要落到策略与参数，而不是形容词 |

补充参照：**PersonaNexus** 用 10 个 0–1 的行为轴（warmth / verbosity / assertiveness /
humor / empathy / directness / rigor / creativity / epistemic humility / patience）——
比 OCEAN 更适合「聊天风格」，因为这些轴能直接映射到输出。

## 2. 核心机制：衰减基准是「上次访问」，不是「创建时间」

这是本轮调研最关键的一条，也是「回看让它发芽」能否成立的判据。

```
recency(m, t) = γ^(小时数)，γ = 0.995，小时数自 m.last_accessed_at 起算
score(m, ctx) = α_rec·recency + α_imp·importance + α_rel·relevance
```

- 用**创建时间**衰减 ⇒ 记忆只会一路变淡，这叫遗忘，不叫发芽。
- 用**上次访问时间**衰减 ⇒ 每被想起一次，权重回满，且回满的间隔越来越长 ⇒
  这就是间隔重复（spaced repetition），也是感情「越用越深」的机械解释。

⇒ **「回看」不是一个 UI 动作，是刷新 `last_accessed_at` 的写操作。**
没有这个写操作，前面所有设计都只是静态权重表。

## 3. 感情 = 记忆的纯函数投影

不做独立的情绪表。理由：

| 若独立存状态 | 后果 |
|---|---|
| 两处真相 | 记忆里有三次深夜长谈，状态却是「平淡」，谁说了算说不清 |
| 不可解释 | 无法回答「为什么现在偏亲近」 |
| 需另造衰减 | 而衰减本来就能从记忆时间算出 |

做法：**可以缓存**一份 `temperature` 供快速读取，但它必须满足
「删掉缓存、从记忆重算，结果一致」。缓存是性能，不是真源。

## 4. 先只做一层：关系温度

第一版只做**关系温度**，不做瞬时情绪。理由：温度变化慢、可解释、可重算；
瞬时情绪在没有真实事件流支撑时只是一个随机数，会伤害稳定性。

草案（维度待标注验证，不先定死）：

```
temperature = Σ(recency_i · salience_i · valence_i) / Σ(recency_i · salience_i)
```

- `salience ∈ [0,1]`：这条记忆有多重（判据见 §5），0 = 不参与
- `valence ∈ [-1,1]`：当时的温差
- `recency`：§2 的上次访问衰减

输出是一个标量温度 + 一组「贡献最大的 N 条记忆」作为**解释证据**。
解释不是附加功能，是校验手段：说不出来源的温度不可信。

## 5. 显著性：什么记忆才带「温差」

只认**可观测**的信号，不认消息长度：

| 判据 | 为什么 |
|---|---|
| 用户明确表达情绪 | 直接信号 |
| 发生分歧 / 纠正 / 被指出错误 | 关系张力 |
| 深夜、或长时间断联后的重逢 | 时间结构本身有意义 |
| 任务失败、受挫、被阻塞 | 共同经历 |
| 明确的肯定或否定 | 反馈闭环的节点 |
| 用户主动透露偏好 / 隐私 | 信任行为 |

**明确不采用**：消息长度、回合数、问号数量。
真实对话里绝大多数是「继续」「好」「嗯」——若都参与聚合，温度会被稀释成平线，
看起来永远温吞，因为分母是几千条无温差的消息。

## 6. 表达：改行为参数，不写情绪描写

不写「我现在有点难过」。让状态去改这些**可观测的输出参数**：

| 参数 | 温度低 → 高 |
|---|---|
| 句长 / 条数 | 短促 → 可以展开 |
| 主动发起 | 只答不问 → 会追问、会主动开口 |
| 措辞直接度 | 客气、留余地 → 直接、带刺 |
| 催促（关心）强度 | 不催 → 会催睡、会拦 |
| 幽默容错 | 少开玩笑 → 可以损 |

判据同 §8：把温度固定成常数，输出必须**变得前后一致**——若毫无变化，这一层就是装饰。

## 7. 与 SOUL.md 的边界

采用 Project Sue 的判据：`Identity = CoreSelf + ContextualModes`，不是两套人格轮换。

| 层 | 内容 | 变化频率 |
|---|---|---|
| `SOUL.md` | 价值观、说话纪律、边界 | 不变量（人工修改，不由运行时写） |
| 感情状态 | 温度、取用权重 | 每轮可重算 |
| 情境模式 | 亲密 / 工作 / 深夜 | 由温度和场景共同决定 |

**禁止把情绪写回 `SOUL.md`**。一旦写回，人格会随对话漂移，且无法回滚。

## 8. 验收标准（三条都必须能取红）

| 检验 | 做法 | 期望 |
|---|---|---|
| 回看生效 | 同一段记忆、同一问题，在插入一次「回看」写操作前后各算一次 | `temperature` **必须不同** |
| 显著性生效 | 把所有 `salience` 置 0 | `temperature` **必须退化成常数**（平线） |
| 行为生效 | 把 `temperature` 固定为常量，重跑同一组对话 | 输出**必须变得前后一致** |

三条里任何一条过不了，就说明对应那一层没有真实作用，应当删掉而不是保留。

## 9. 反例警告（必须写进来）

《Do AI Personas Grow?》（Semantic Scholar 4f07068c…）对 14 个模型的实测结论：
LLM-Agent 在「生活事件」后**确实会移动**，但

> 移动是弱事件特异的、幅度失准的、且在人口学与 persona 层面被压缩——
> 它们更容易模拟人类人格变化的**均值**，而不是其**形状**。

含义很直接：**如果只靠模型即兴「感受」，结果会塌缩成通用的温柔腔。**
所以状态必须是显式变量 + 可从记忆重算，而不是让模型每轮自由发挥。

## 10. 不做清单

- 不做好感度数值、不做对外百分数（只允许粗粒度阶段：陌生 / 熟稔 / 亲近）
- 不做读心式推断（「你是不是很难过」）
- 不把情绪写进 `SOUL.md`
- 没有真实事件流之前，不做瞬时情绪
- 不用消息长度当显著性

## 11. 未证实 / 待办

1. **AffAdapt 的 14 维明细**：本轮只读到摘要片段与外层架构，未逐节核对原文，
   因此不引用其具体维度命名。
2. **显著性判据需要真实语料验证**：挑 20 条真实记忆做手工标注，
   如果连人工都分不开「有温差 / 无温差」，这套判据不应写进代码。
3. **衰减半衰期未定**：`γ=0.995/小时` 是 Generative Agents 在虚拟小镇场景的取值，
   约 138 小时半衰；我们的对话密度低得多，需要重新标定。
4. **「关系温度」的稳定性没有定量指标**：需要先积累，再定「一天内温度变化幅度」的合理区间。
