# 插件导入工作目录与自建工具验收

普通会话的文件工具曾写入 Core 安装目录，插件导入同时报告缺少冻结工作目录。`AgentExecutionService` 现在在缓冲与流式入口采用显式工作目录，缺省时向宿主的执行环境查询。导入仍检查相对路径和重解析点。程序包挂载、进程执行权限、单次审批各自检查。[使用与编写](../../../04_tools_and_skills/运行时工具插件.md)

`TestScripts/test_product_tool_plugins.py` 在独立 DataRoot、真实 Core 和 Worker 下用脚本化模型驱动工具。定向 Runtime 测试 26/26，通过了显式目录与默认目录在两条调用路径的断言。产品检查 40/40，覆盖写源码、编译、打包、导入、单次审批、调用新 DLL 的本次随机结果以及卸载后消失。仅批准加载、关闭进程执行时，启动 Worker 被拒绝。替换为当时正式环境的旧 Runtime 后，同一脚本在读取工作区标记时返回非零。

本轮验证使用独立进程。正式鲸鲸会话未部署本轮改动，未更改其实例 Shell 配置，也未验证真实模型自主编写插件。
