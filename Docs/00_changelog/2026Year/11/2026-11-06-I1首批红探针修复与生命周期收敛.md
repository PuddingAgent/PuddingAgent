# I1 首批红探针修复与生命周期收敛

针对评估报告八条红探针中的 I1/Review 部分做首批修复；未 commit、未部署、未调用真实模型。

## 1 已修复

- **预算端口缺失放行**：`LlmInvocationRequest.BudgetAttempt != null` 而 facade 无 `IModelAttemptBudgetPort` 时，buffered 返回 typed 失败、stream 在启动前抛出 `budget.dispatch_invalid`，provider 不再被调用。
- **跨作用域预算身份**：预算 claim 的 Workspace/Agent/Session 必须与 invocation 一致，否则 `budget.request_invalid` 且不派发。
- **结算/Unknown 顺序**：buffered/stream 的 `settled` 只在结算成功后置位；结算抛错会标记 Unknown，不再因过早置位跳过清理。
- **Stream 创建异常**：`ChatStreamAsync/GetAsyncEnumerator` 构造阶段的异常也会标记 Unknown（`llm.stream_create_failed`）后再抛出。
- **Review accepted sequence**：创建 Job 时 `AcceptedSequence==0` 自动分配 `max+1`（事务内），Latest 查询不再被哈希 JobId 决定顺序。
- **Review operation 创建指纹**：同 operation 复用除逻辑 key 外还比较 Required/BudgetAccountId/ActorId，改变 actor/预算账户返回 Conflict。
- **Durable pool 生命周期**：连接父取消与调用取消，按请求 timeout 取消观察；超时→`model.timeout`、父取消→`execution.revoked`，已派发尝试保持 Unknown。
- **Host 上限生效**：`HostRuntimeLlmChatClient` 把请求 `MaxOutputTokens` 应用到本次配置，不再忽略评审的有界调用。
