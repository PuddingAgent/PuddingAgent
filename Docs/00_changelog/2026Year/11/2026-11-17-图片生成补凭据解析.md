# 2026-11-17 图片生成补上凭据引用解析

## 现象

用户请求生成图片，工具失败：

```
Ark image generation failed with HTTP 401:
{"error":{"code":"AuthenticationError","message":"The API key format is incorrect..."}}
```

## 根因

`llm.providers.json` 里 8 个 provider 的 `apiKey` 在 2026-11-17 的凭据迁移中全部改成
`{{vault:…}}` 引用（长度 58，全部为引用）。LLM 对话、搜索、CalDAV、飞书、语音都补了解析链，
**图片生成这一条漏了**：

```csharp
// ImageGenerationService：迁移前
var apiKey = resolved.ApiKey;   // 直接取，可能拿到字面量 {{vault:...}}
```

于是把字面量当成密钥发出去，服务端报「密钥格式不正确」。

## 改动

```csharp
var apiKey = await PuddingSecretReferences.CredentialReference.ResolveAsync(
    resolved.ApiKey,
    keyVaultService is null ? null : keyVaultService.InjectAsync,
    ct);
```

与 `DoubaoSearchTool` / `CalendarListTool` / `OpenAiEmbeddingService` 等调用点同一套解析。
依赖以可选参数注入（`IKeyVaultService? keyVaultService = null`），既有测试构造不受影响；
解析器为 null 时保持旧行为（字面量原样传递），不做静默替换。

## 验证

- `dotnet build Source/PuddingPlatform` 与 `Source/PuddingPlatformTests`：均 0 error。
- `PuddingPlatformTests` 过滤 `ImageGeneration`：**7/7 通过**。
- 未做变异验证：本修复的行为差异只能通过真实密钥解出才可观测，
  单测层面只能证明「不再抛异常 / 不再短路」，因此**不声称变异已取红**。

## 局限

- 本修复需部署（重启）才生效；当前线上仍是未修复版本。
- 未验证除火山方舟外其他 provider 的图片生成是否同样受影响（同一路径，理论上一并修复）。
