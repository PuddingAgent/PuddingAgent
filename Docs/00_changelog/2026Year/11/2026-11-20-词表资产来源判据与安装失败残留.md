# 2026-11-20 词表资产来源判据与安装失败残留

## 目标 / 背景

`agent_diagnostics action=runtime_identity` 连续报 `assetSource=beside-application` +
`models[].isExact=false` + `fallbackReason=AssetMissing`。这句话读起来是「资产文件被删了」，
于是排查方向被引向部署回滚。

实际现场相反：部署树里的 `core/tokenizers/` **存在但零文件**（创建时间
2026-10-24T07:01:14Z，早于首份资产落地）。旧判据只问 `Directory.Exists`，于是把
「从没放过文件」读成了「配过又没了」。

## 改动

- `Source/PuddingTokenization/TokenizerAssetDirectory.cs`（新增）— 解析策略独立成组件，
  入参是 `(environmentValue, baseDirectory)`，判据改为「目录里至少有一份 `*.tokenizer.json`」。
  拿到目录读不到时按「没有」处理，因为该策略在 `static readonly` 类型初始化里被调用，
  抛异常会把「没有精确词表」升级成「所有上下文估算不可用」。
- `Source/PuddingCore/Platform/LlmOptions.cs` — 删除私有的
  `ResolveTokenizerAssetDirectory` / `TokenizerAssetResolution` / `TokenizerAssetSources`，
  改为委托新组件；原实现直接读进程状态且藏在 `static readonly` 后面，测试进程内无法驱动。
- `Source/PuddingTokenizationTests/TokenizerAssetDirectoryTests.cs`（新增）— 8 条用例。
- `Tools/Tokenization/Prepare-TokenizerAssets.ps1` — 目标目录改为「有东西要落地时才建」，
  并在 `finally` 里清掉本次自己建的、仍为空的目录；顺带把临时文件的清理收成一个出口。
  旧版本先建目录再下载，一次中止的安装就留下那个空目录。

## 验证

- `PuddingTokenizationTests`：33 总计 / 24 执行 / 24 通过 / 9 跳过（跳过均为需要真实资产的用例）。
- 变异取红：把判据退回 `Directory.Exists` → 恰好 `EmptyBesideDirectory_IsNotConfigured` 与
  `BesideDirectoryWithUnrelatedFilesOnly_IsNotConfigured` 两条变红；复原后 SHA-256
  `23fb85ff…` 比特一致、重新全绿。
- 脚本四种行为实跑（`temp/verify-prepare-script.ps1`，测完已删）：
  失败不留本次新建目录（`A_DEST_EXISTS=False`，改前为 True + 0 条目）；
  成功只落地一个资产且不残留 `*.download`；
  重跑走 `[skip]` 且目录内容不变；
  运行前已存在的目录在失败后**不被删除**（只剩 `keep-me.txt`）。
- 全量 `PuddingRuntimeTests`：2869 总计 / 2858 通过 / 0 失败。

## 影响与回滚

- 行为变化：空的 `tokenizers/` 现在报 `assetSource=none`，不再是 `beside-application`。
  想看「目录在但没资产」需看 `assetDirectoryPresent`。
- 未部署：运行中的进程仍是旧判据，需重启后才看到新读数。
- 回滚：`git revert 5be444a` 与本次脚本提交；无需数据迁移。

## 关联
