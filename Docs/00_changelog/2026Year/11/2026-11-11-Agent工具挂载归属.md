# Agent 工具挂载归属

`ExecutionRunCoordinator` 直接传递 Agent 实例的工具、能力策略和 Skill 配置。Runtime 优先使用显式实例策略。渠道绑定只用于识别发送者、保护私有会话及判断该成员能否实际调用工具。未绑定成员调用敏感工具时，Core 返回拒绝结果，跳过凭据展开和可执行插件 Hook。

`PluginManager` 和 `HostToolMounts` 按工作区和 Agent 管理普通工具的加载、去重及卸载。Worker 通过当前调用取得实际会话身份。工作区订阅者继续使用自己的激活身份。模型工具曝光预算和会话内的使用记录继续用于选择当轮展示的工具。

隔离 Core 使用真实 Chat API、审批和 Shell，以及本地模型替身。一次挂载后，三个不同会话都发现了 Shell。两个可信发送者回合实际读到工作区标记；受限发送者回合收到拒绝。组件测试 35/35，真实 Worker 集成 11/11，产品插件检查 40/40，Runtime 授权与审批定向测试 17/17。包含钉钉群工具与身份用例的宿主测试通过 9/9，VSTest 在当前环境无法监视父进程，使用直接运行测试方法的 runner 核对。

正式 Core 使用 `D:\Data`。Guardian 请求 `5275dc0222404900882aa7255be4ce9e` 已达到 `healthy`，Core PID 45128，Desktop PID 41332，ready/live 均为 HTTP 200。安装的六个相关程序集与候选包 SHA-256 一致。正式设置读回鲸鲸的 Shell 开关已启用，并核对了 Agent 级 Shell 挂载。配置更新接口清空了七个未提交的角色模型字段，已根据三份一致的正式备份恢复并通过 API 逐项读回。此次正式环境没有通过群聊发起 Shell 操作。

钉钉正式包沿用已部署的群图文源码基线，叠加了使用完整 Agent 工具目录及调用时检查来源的改动。群图文接线依赖工作树里尚未入库的实现。备查日志原在 `.work/agent-tool-ownership/20261111/`（15,125 文件 / 9,491 MB）。经 2026-11-13 核查，该目录主体是 `bin`/`obj`/`publish` 的构建产物副本（三个目录内出现同一份 `pos_prob_emit.json`，3,147,136 B，SHA256 `F9F4B9A2…F1F2D67`），不构成可入版本库的证据；如需回看，以本节描述与当时提交为准。

复核了 `PluginManager`、Worker 调用上下文和回调生命周期测试的三项指纹变更。旧清单已归档，更新后的插件 API 指纹 18/18、Work API 指纹 16/16 通过。另行运行的配置 API 指纹检查仍在工作树已有的 Host DI 文件上报差异，该文件未纳入本次改动。
