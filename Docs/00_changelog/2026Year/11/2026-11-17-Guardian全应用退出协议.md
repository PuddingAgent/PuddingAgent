# 2026-11-17 Guardian 全应用退出协议

- `Source/PuddingDesktop.Guardian/`：持久 exit 请求等待当前事务完成，先停 Core 再停 Desktop，自身退出；独立 launch 交接遵守 Core 自动启动配置，显式用户重新打开才恢复监督。
- `Source/PuddingDesktop/Hosting/DesktopApplicationCoordinator.Guardian.cs`、`MainWindow.xaml.cs`：托盘和运行中心退出统一排队，等待状态、防重复、失败修复入口；内部重启不递归触发退出。
- `Source/PuddingDesktop.GuardianTests/GuardianTests.cs` 与 `Tests/PuddingDesktop.GuardianIntegrationTests/DesktopGuardianEndpointTests.cs`：独立生命周期用例与 Guardian 专用 Core 停止控制头。
- `TestScripts/test-pudding-guardian-exit.ps1`：独立配置/端口/程序包的进程树与退出验收。

验证：独立用例和变异取红/恢复通过，Desktop 构建通过。隔离 EXE 的 HttpListener Win32 6 与 WinUI 测试 NuGet 还原失败保留为限制，未声称部署验收完成。未完成：独立 Guardian 升级及真实托盘/退出顺序/重开验收。详见[报告](../../../14_reports/2026-11-17-Guardian全应用退出验收.md)与[运行手册](../../../13_runbooks/Desktop-Guardian.md)。

更正（2026-11-17）：实现已提交 `71fd32d`，提交后完整包构建通过；Guardian 独立 35/35、变异取红与恢复、真实 WinUI 端点 1/1 通过。NuGet 还原改用本机缓存后成功，仍有标准 testhost 父进程句柄访问失败；提交门禁虽输出 OK，但 TRX 复核仅 Foundation 20/20 实际完成，其余三个 runner 中止未执行，不能计作通过。外部部署与托盘验收仍待独立 Guardian 停止后继续。
