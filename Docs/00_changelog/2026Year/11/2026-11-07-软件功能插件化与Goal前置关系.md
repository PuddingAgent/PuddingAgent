# 软件功能插件化与 Goal 前置关系

按用户要求，修订插件范围与 Goal 的依赖关系。插件可新增软件功能并在声明扩展点影响行为，不限于供 Agent 调用的工具；基础设施组件化和通用插件机制是完整 Goal 接入的前提。

## 改动

- 公共 API 规划：增加组件/插件/贡献区分，Tool、Feature/Action、Provider/Policy、Event/Job、Connector、UI 贡献范围；明确消费与注册权限分离、组件拥有扩展点、非 Agent scope、依赖与完整卸载。
- 收敛计划与总则：调整依赖图和基础门禁，先完成真实基础设施适配和零工具功能插件，再集成 Goal。纯策略可提前独立开发；不要求所有可选插件类型一次完成。
- PA-03/04/05/07/08：同步评审/Goal/组件前置、功能插件实现边界、管理可见性及负向验收；不扩大已派发叶任务白名单。
- 工具插件方案：明确只是通用系统的一种贡献切片，复用同一包/Worker/生命周期，不建立平行管理器。
- 根 `code_map.md` 更新对应导航条目。历史评估报告和日志保留，不改写此前验收结论。

只读核对了用户指定 `F:\github\deepseek\deepseek-harness` 中 Goal 文档及 round-driver 源码：状态服务、工具、命令和消费公共服务的续跑 driver 分离。规划保留该参考关系，Pudding 继续使用自己的状态、预算、授权和持久提交权威；未修改或导入参考仓库代码。
