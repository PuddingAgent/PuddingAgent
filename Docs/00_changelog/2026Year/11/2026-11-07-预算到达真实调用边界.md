# 预算到达真实调用边界（Runtime Facade + 持久账本）

补齐“预算/取消到达 provider 调用边界”的离线证据；未 commit、未部署、未调用真实模型。

## 1 测试链路（真实组件，无产品接线）

`RuntimeBudgetBoundaryTests` 使用真实：
`LlmInvocationService`（Runtime facade）+ `PlatformModelAttemptBudgetPort` + `ModelAttemptBudgetGate` + `ExecutionBudgetStore`（SQLite Enforced 账户）+ fake `IRuntimeLlmClient`。

验证 **3/3**：
- 有预算身份时 provider **恰好调用一次**，账本 `ActiveAttempts=0`、`ReservedCost=0`、`Cost>0`、`Calls=1`；
- provider 成功但**缺 usage** → attempt 标 Unknown（不退款、不报零），账本 `UnknownCost>0`；
- **取消 token 在派发前** → provider 调用 0 次、无活跃预留。

## 2 边界说明

- 这证明“端口→真实账本→真实 facade→provider”的预算门禁顺序正确，是 P2 的核心路径证据。
- 仍**不代表产品主执行链**已携带预算身份：`AgentExecutionLlmInvoker`/`ExecutionRunCoordinator` 仍未填 `LlmAttemptBudget`，该接线需要预算根语义裁定。
- 该测试无任何 provider 网络调用与凭据读取。

## 3 验证

- Runtime 边界测试 3/3；Platform S5 切片 **180/180**；SDK 25/25；全解决方案构建 exit 0（restore + --no-restore）；一键脚本 RunId 20261106-r39 exit 0（组件 276 + Platform 180 + 前端 47 + tsc）。
- 证据：`.work/i1/runtime-boundary/`、`.work/verification/runtime-boundary-solution/`、`.work/pa08/components-20261106-r39/`。
