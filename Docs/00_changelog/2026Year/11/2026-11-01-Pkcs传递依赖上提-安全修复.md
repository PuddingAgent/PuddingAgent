# 2026-11-01 安全修复：传递依赖 Pkcs 上提到 10.0.14

## 问题（实测，非推断）

`dotnet list Source\PuddingHost\PuddingHost.csproj package --vulnerable --include-transitive` 原报：

```
可传递的包                                 已解决   严重性
> System.Security.Cryptography.Pkcs       9.0.4   High      GHSA-846f-f764-76mx
                                                   Moderate  GHSA-2fmv-rv2c-59x7
```

补充事实：**没有任何 csproj 直接引用这个包**（`findstr /s "Cryptography.Pkcs" Source\*.csproj` 为空），
它是传递依赖；解析到 9.0.4 是「最低版本胜出」的结果 —— 同一张图里 `PuddingMemoryEngine` 要 10.0.12。

## 改动

`Source/PuddingHost/PuddingHost.csproj` 增加一条显式上提：

```xml
<PackageReference Include="System.Security.Cryptography.Pkcs" Version="10.0.14" />
```

选 10.0.14 而不是 9.0.22（9.x 最新）：图里已经存在 10.0.12，同线收敛后整张图只剩一个 Pkcs 版本。

## 已知残留（写清，不掩盖）

`PuddingPlatform`（9.0.4）与 `PuddingMemoryEngine`（10.0.12）**各自工程的还原警告仍在** ——
它们作为独立工程被测时仍解析到旧版本。但**对外发布的依赖图是 Host 的图**，Host 已判定无漏洞。
要让全仓警告归零，需在这两个工程里也各加一条上提；本轮未做（改动面越大越该单独一步）。

同一个 `System.Security.Cryptography.Xml`（10.0.12，3 条 High）目前只出现在 MemoryEngine 的图里，
**不在 Host 的漏洞清单中**；若将来进入发布图，按同一模式上提。

## 一个过程教训

XML 注释里不能出现连续两个连字符。首版注释写了 `package --vulnerable`，直接 `MSB4025` 加载失败。
写成「vulnerable + include-transitive 两个开关」即可。
