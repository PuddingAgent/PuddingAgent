# 2026-11-16 TTS 输入校验并入既有语音端点

## 背景

TTS 的 HTTP 入口本来就有 `VoiceController`：`POST /api/voice/tts/synthesize`、`tts/stream`、`asr/recognize`、`capabilities`，并在类上挂了 `[VoiceFailure]` 统一做异常映射（`SpeechFailure` 自带状态码、`HttpRequestException`→502、超时→504、`errorId`+日志）。

真实的缺口只有一个：**输入校验**。之前空文本会直接进 `IVoiceSynthesisService` 并抛异常，最终变成 500，而不是 400。

## 变更

- `Controllers/Api/VoiceController.cs`：`Synthesize` 增加校验——空白文本、超过 `MaxTextLength`（10000）、非 `wav`/`mp3` 格式，统一以 `SpeechFailure(..., 400)` 抛出，交由既有的 `[VoiceFailure]` 映射，**不另写 try/catch**。
- 删除并行的 `POST /api/voice/tts`（以及它的控制器），避免同一能力出现两条路由。
- `PuddingPlatformTests/Controllers/VoiceControllerTests.cs` 共 6 条：成功字节透传与请求归一化、空文本 400、超长 400、非法格式 400、`VoiceFailureAttribute` 把上游失败映射为 502 且不泄漏上游报文、路由与鉴权元数据。

## 为什么不是新加一个控制器

同一能力第二条路由意味着两个真源：错误形状、鉴权、日志口径都会漂移。错误映射已经有唯一真源（`[VoiceFailure]`），新增控制器等于再抄一份。
