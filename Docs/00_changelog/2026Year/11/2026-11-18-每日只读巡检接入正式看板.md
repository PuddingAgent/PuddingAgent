# 2026-11-18 每日只读巡检接入正式看板

## 改动

- `Source/PuddingPlatform/Services/Scheduling/HouseInspectionScheduleWorker.cs` 接入到点建卡。启用后仅向配置中已启用且未冻结的工作区写入，配置明确的 Agent 后交给现有派发链。
- `Source/PuddingPlatform/Services/Tasks/SqliteWorkspaceTaskStore.cs` 复用普通建卡的任务与事件写入。触发、任务、创建事件和游标共享调用方事务。
- `PuddingAgentNetwork.slnx`、Platform 工程和 Core 组合根登记调度组件。Core 打包 `Tools/Maintenance/inspect-house.ps1`，卡片传入本实例的 DataRoot，并只报告错误聚类计数。

## 验证

- 独立调度测试 55/55。正式任务 SQLite 定向测试 17/17，包括默认关闭、重启建卡、派发标志和事件写入失败回滚。Host 组合测试 2/2，核对巡检 Worker 注册且默认关闭。Core 构建 0 错误。
- 用隔离 DataRoot 启动实际 Core，确认 `/health/ready` 返回 200，并观测到一张巡检任务、一条创建事件和一条关联触发记录。
- 从 Core 构建目录运行巡检脚本，确认输出指标、隐藏测试日志签名，SQLite 主文件 SHA-256 前后一致。证据见 `.work/house-inspection/20261118/core-smoke-retry.log`。

## 未完成

候选实现达到 `ready-for-external-deploy`。当前实例尚未部署或启用巡检。真实 Agent 自动执行及结果回写待产品内验收。关联 [每日只读巡检](../../../13_runbooks/定时巡检.md)。
