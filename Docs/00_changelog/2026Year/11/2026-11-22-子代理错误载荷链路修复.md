# 2026-11-22 子代理错误载荷链路修复

## 缺陷

子代理回执气泡曾只有这一行诊断：

```
⚠ 错误诊断（tool_failure）：工具调用失败 1 次，最近一次：shell: exit code 1
```

逐层核对出四个**各自独立**的原因：

1. `HostShellExecutor` 把 `Error` 写成裸退出码 `exit code {N}`；而同一段代码早已把 stderr `MergeOutput` 进 `Output`——信息在，只是没被用。
2. `AgentExecutionService.BuildToolFailureSummary` 在 `error` 非空时**直接丢弃 `output`**，诊断现场整段丢失。
3. `SubAgentManager.BuildSubAgentResultErrorDiagnostic` 对 `error == null` 一律渲染「未记录错误文本」。运行成功完成时根本没有 run 级错误，这句话把「不存在」表述成「丢了」，读的人会去翻不存在的日志。
4. 异常路径只取 `ex.Message`，异常类型丢失。于是「进程退出码」与「工具实现抛异常」在摘要里长得一样，而这两者该采取的行动相反。

第五处独立缺陷：`Suggestion` 对任何非权限失败都回「Check the tool's parameter constraints」。会话样本中 `shell` 失败 14/144、`max_duration_ms=30126`，超时是主要成因——超时时叫人去改参数，方向是反的。

## 验证

每条都走「变异 → 取红 → 逐位复原 → `-t:Rebuild` 复绿」三态，且变异体均 `BUILD_EXIT=0`（红来自测试，不是编译失败）：

```
cc8cb27  ToolFailureSummaryTests   10/10 基线；变异（Tail 取头而非取尾）→ 失败 1 / 通过 9
6db9623  SubAgentResultBodyTests   15/15 基线；变异（第四实参恒 false）  → 失败 1 / 通过 14
734cf6b  失败建议分流测试             6/6 基线；变异（分流恒回落）        → 失败 3 / 通过 3
ecadf1d  ToolFailureSummaryTests   14/14 基线；变异（类型名恒 Exception）→ 失败 4 / 通过 10
```

部署核验（04:39:15 起 pid 135100，产物 04:38:28~36 均早于启动，未回滚）：元数据 UTF-8 探针 `BuildExceptionError` **0→1**，两个正对照均为 1、负对照为 0，`HTTP=404` 表示进程在听。

真实链路 A/B 对照——两次探针同为 `completed` 状态、同为 `tool_failure_count=1`，仅版本不同：

```
01:08 旧版：最后一次错误：未记录错误文本（无堆栈，工具退出码路径）
02:18 新版：运行本身未报错（无堆栈，工具退出码路径）
```

## 未完成

- `HostShellExecutor` 的 `Error` 仍是裸退出码——本次在摘要层补上诊断，源头未改。
- 未覆盖工具**取消**路径（`OperationCanceledException` 直接 rethrow，不计入失败摘要）。
- 相关 `code_map.md` 条目待补（工作树被并行的外部 Agent 占用，避免撞车）。
