# 2026-11-01 双线交付

## 动机

两条线来自同一个追问：「为什么 agent 记不住、也停不下来」。

- 记忆线起点：用户指出「能记住」和「会话能记起来」是两个概念，要求用真实会话测召回准确度。
- goal 线起点：用户指出反复唤「继续」不是习惯，而是**会话必须等心跳**这一架构症状。

## 改动

### 记忆线

- **发现并修正一条错误前提**：`pudding_memory.db` 中 `MemoryFacts` 等 11 张表**全为 0 行**，而 `Messages`/`SessionChunkVectors` 有数据。实际在用的记忆是文件型（agent 私有 `memory/`）。
- **根因**：`FactMemoryService.CreateFactAsync` 生产调用点为 **0** —— 服务注册了、测试全绿、没人调用。
- 接线：新增 `IFactMemorySink` / `FactMemorySink`，`save_memory` 成功后双写（开关 `PUDDING_MEMORY_FACTS_WRITE`，默认关）；补端到端测试证明 `MemoryFacts` 真被写入。
- 可观测：`FactMemoryWriteMonitor` + `FactMemoryWriteProbe`，把「表里 0 行」变成可报警状态。
- 召回侧：`MemoryCueExtractor` 按真实语料重标定（3000 条 turn 回放），强线索触发率 74.4% → 45.3%；`ProgressQuery` 线索；`继续` 降级为弱线索。

### goal 模式线

13 个纯逻辑组件（`Source/PuddingRuntime/Services/AgentLoop/`），要点：

- `GoalLifecycle`：phase（持久）与 activation（进程本地、永不落盘）分离 ⇒ 重启后不自动续跑由「不持久化」本身保证；**完成必须带可核验证据**。
- `GoalRoundLedger`：只有真正进入模型历史的 round 才计额度；轮号必须 == 已用 + 1。
- `ContinuationPolicy` / `RepeatedActionGuard`：别停太早 / 别空转（按**连续**重复判定，窗口计数会误判交替读写）。
- `GoalRegistry` / `GoalLoopDecider` / `GoalLoopDecisionHook`：按会话绑状态，统一决策（顺序即规则，用户消息优先于一切），挂在既有 `OnLoopCompleteAsync` 上（观测期，默认关）。
- `GoalOpenItemsReader`（真实待办数）/ `GoalRoundPrompt`（目标 JSON 转义，含尖括号）/ `GoalContinuationQueue`（续跑请求生产者）/ `GoalRunEquivalence`（开关两态等价比对）。

## 证据

- 测试：goal 线 113 条全绿；记忆线新增/更新约 40 条；每次改动均做**变异取红 + 位同还原**（如 `GoalRoundLedger` 去掉 revision 围栏 → 恰好 1 红）。
