# 子代理状态投影纳入启动对账

## 问题

`sub_agent_runs` 有 `RecoverInterruptedRunsAsync`（进程启动时把上一进程遗留的非终态运行提交为 `interrupted`），但 `session_sub_agents` 是另一张投影表，**没有任何对账入口**。

2026-11-20 实测：该表积了 10 条自 2026-07-23 起的 `running`，全部是无产物的探针，却一直占着「运行中」计数，UI 的「2 运行中」也是这么来的。

已有的 `ReconcileSubAgentTerminalStatesAsync` 只在查询某个父会话的计数时触发，那两个父会话从未被查询，所以永远不会被纠正。

## 改动

- `ISessionStateManager.RecoverInterruptedSubAgentsAsync(startedBeforeUtc, maxRows, ct)`：把启动前遗留的非终态投影提交为 `failed`。
  - 只处理 `spawned_at` 早于进程启动时间的行——本进程启动之后创建的仍可能真在跑，不得误伤。
  - `spawned_at` 是字符串列，历史行可能带不同 UTC 偏移；解析失败就原样保留并记 warning，宁可留脏数据也不误判真在跑的运行。
  - `maxRows` 截断，避免堆积时一次拖死库。
  - 状态写 `failed` 而非新增枚举值：`session_sub_agents` 的下游只认 `completed`/`cancelled`/`failed`，加新值会牵动 UI 与 `IsSuccess` 判定。原因写在 `error_summary` 里。
- `SubAgentConversationProjectionWorker` 在启动对账处同时调用两张表的恢复，注入 `ISessionStateManager`。
- 三个测试桩补齐接口实现。

## 验证与限制

- `PuddingPlatform` 构建 0 错误（56 个既有 warning）。
- 新增用例 `RecoverInterruptedSubAgentsAsync_FailsOnlyProjectionsOlderThanCutoff`：cutoff 之前的改成 `failed`（`Success=false`、`CompletedAt` 非空、`error_summary` 含标记）、cutoff 之后的仍 `running`、已终态的仍 `completed`。
- 变异（删掉 cutoff 判断）：1 失败 / 0 通过；复原后 SHA-256 比特一致（`E3DFE0F9…5F82201`）。
- 全量 `PuddingPlatformTests`：2013 总计 / 2012 通过 / **0 失败** / 1 跳过。

**限制**：本用例直接插入实体并调用方法，没有真正拉起 worker 验证「启动时自动执行」。worker 的调用是单行、无分支，但这一点仍是未验证的推断。

另：上一轮已用 SQL 清过那 13 行历史数据，本提交只负责让它们不再产生。未部署。
