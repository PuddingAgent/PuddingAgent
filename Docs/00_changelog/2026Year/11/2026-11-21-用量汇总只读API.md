## 交付

`GET /api/admin/usage/summary?fromUtc&toUtc&groupBy=model|subagent|day`

- 只读：未写库、未建表、未改 schema
- SQL 侧聚合（不把 58,177 行拉进内存）
- 响应信封：`{groupBy,fromUtc,toUtc,limit,returned,total,truncated,rows[]}`

## 三个语义细节（写错就是缺陷）

1. **命中率必须加权**：`sum(CacheHitTokens)/sum(CacheEligibleTokens)`。
   eligible=0 返回 `null` 而非 `0` —— 「命中率为零」和「算不出来」是两件事。
2. **成本未知 ≠ 零**：实测多个模型 `TotalCost=0` 是**价格登记缺失**。
   分组内 `TotalCost` 全 0 且 tokens>0 时 `costKnown=false`，另给
   `unknownCostRequestCount`。前端必须显示「成本未登记」，否则会把没登记看成免费。
3. **空结果 200 + 空数组**，不返回 404；`groupBy=subagent` 默认上限 200 行，
   回报 `total`/`truncated`。

## 实现取舍

- **原生 SQL 而非 LINQ GroupBy**：`CreatedAtUtc` 是 TEXT 且小数秒尾零被截断
  （实测同一列 32/33 两种长度），整秒边界会错；必须先 `strftime('%Y-%m-%d %H:%M:%S')`
  归一化。代价是放弃索引走全表扫描，实测 **97 ms / 5.8 万行**，可接受；
  表到千万级需改数值型 UTC 列或表达式索引。
- **`toUtc` 两套语义**：纯日期 = 含当天（折算次日 00:00 开区间上界）；
  日期时间 = `[from, to)`。
- **信封对象而非裸数组**：任务书本身有冲突（既要求数组，又要求带
  `total`/`truncated`）。取信封，行字段与设计稿逐字一致。
