# PA-01 P2 模型尝试预算门禁核心

按裁定“P2 为交付目标、按 attempt 而非整轮”实现模型尝试门禁核心；未 commit、未部署、未调用真实模型。

## 1 P2 门禁

- 新增 `BudgetEnforcementMode { Legacy, Shadow, Enforced }`：在根账户创建时冻结，存 `execution_budget_accounts.enforcement_mode`。
- 新增 `ModelAttemptBudgetGate`：
  - `BeginAsync`：读根模式 → Legacy 直接返回 `Gated=false`（不预留）；Shadow/Enforced 先按派发时刻取**可信报价**（无报价 typed `model.price_unknown`，不置零）→ 用 `QuoteWindowAdjuster.Cost` 按输入/输出上界算预留 → `ReserveAsync`（祖先原子、幂等 OperationId=AttemptId）→ `MarkDispatchedAsync` 返回 permit；
  - `SettleAsync`：按实际 usage/成本结算（可带 overrun）；
  - `MarkUnknownAsync`：保留 Unknown，不退款；
  - 账本不可达/限额不足时 fail closed（`budget.exhausted` 等），不退回进程内预算。
- 降级保护：`SetEnforcementModeAsync` 拒绝把 Enforced 根改为 Legacy/Shadow；Legacy/Shadow 可显式提升。

## 2 顺带修复

- `ExecutionBudgetStore` 的金额解析原先使用 `decimal.Parse(..., CultureInfo)`（不允许指数），当 `0.000001` 等极小上限经 `G29` 序列化为 `1E-06` 时抛 `FormatException`。已改为 `NumberStyles.Float` 的统一 `ParseCost`，并保留 `G29` 存储。该缺陷由“极小成本上限”负例暴露。

## 3 测试

- `ModelAttemptBudgetGateTests` 6/6：Legacy 不预留、Enforced 预留/派发/结算、Shadow 只记账、无报价 fail closed、限额不足 fail closed、Enforced 不可降级。
- 既有 `ExecutionBudgetStoreTests`（10）+ `ExecutionBudgetReconcilerTests`（3）在改动后 **19/19** 全绿。
- 结果：Platform S5 切片 **105/105**；全解决方案构建 exit 0；一键脚本 RunId 20261106-r9 exit 0（组件 274 + Platform 105 + 前端 47 + tsc）。
- 证据：`.work/pa01/p2-gate/`、`.work/verification/p2-gate-solution/`、`.work/pa08/components-20261106-r9/`。
