# 插件 Agent 配置租约与算子开放规划

## 改动

- 新增独立 `PuddingAgentDelegation`：绑定宿主身份/单个 Agent、方法权限、调用额度、截止时间；撤销后拒绝新调用，等待已准入操作结束。配置更新复用已有独立配置组件，取消/IO 丢失写回执保留 unknown。
- 新增 `Pudding.ToolPlugins.AgentSdk`：`Context.AgentConfiguration()` 复用公共 SDK facade，传输不接收目标 Agent/actor，不携带管理凭据，不自动重试未知写入。
- `Pudding.ToolPlugins.Contracts/PluginAgentApi.cs` 提供 BCL-only 可选传输/宿主租约端口；Core API 1.1 显式开放配置读/写/变更页。`Runtime/PluginValidation.cs` 保持 Core 1.0 包原语义；工作提交仍拒绝。
- `PluginManager.cs` 冻结批准集合、校验当前工具写 effect；卸载须确认 Worker 退出和宿主回调排空，排空未确认保留 StopFailed/unknown 及资源占用。旧代工具不可调用新代。
- Runtime 工具适配器经租约工厂端口调用 Platform 的 `PluginAgentApiLeaseFactory`；Host 仅负责 DI 装配。公共配置 Store 仍是原 `WorkspaceAgentFileService`，不创建第二个 writer。
- Worker 共享公共/插件 SDK 类型，映射配置错误语义；启动传输错误只输出异常类型/HResult/方法名，不输出任意异常正文。生产源码不保留身份/路径诊断探针。
- 新增真实 DLL fixture、Worker 配置链路测试、Host 组合测试、专用验收脚本；登记解决方案及相关代码地图。
- 对现有 `IScorer/IJudge/IClassifier/IOperatorRegistry` 和实际 `SkillValueScorer` 做源码定位，写入[后续开放设计及 DS-PG01 施工单](../../../12_features/插件Agent配置租约与算子开放设计-2026-11-05.md)。算子公共 API 尚未实现，施工单只分派现有配置 SDK 的离线示例。

### 验收中的红灯与修正

初次 `dotnet <测试.dll>` 控制 `.exe` Worker 时，本机管道连接被拒，宿主最终报初始化超时。独立探针确认同用户、同 .NET 版本，旧已验收 Worker 的同一 apphost 二进制也复现拒绝；不能据此把错误归因于新配置 API。直接运行测试 apphost 又暴露系统 Temp 写入拒绝。

改用仓库既有 Worker 验收方式：测试 apphost 与 Worker apphost、数据落在仓库 `.work` 隔离根，真实链路与旧回归均通过。独立纯组件测试仍由 `dotnet <dll>` 执行。脚本固定这两种入口；没有去除 CurrentUserOnly、PID 核对或增加权限，也没有改成假 Worker。初次失败日志 `integration-test.log`、`worker-regression-test.log` 保留；最终结果看 `PuddingPluginAgentApi.IntegrationTests.log`、`PuddingToolPlugins.IntegrationTests.log`。操作系统层面导致两种启动方式权限不同的具体策略未定位，本次只确认启动方式的可复现对照。
