# 已有工作区首次创建评审表

已有业务表的 SQLite 库启动时，EF 会跳过整库建表，Host 随后执行各组件的建表 SQL。评审组件在 `review_jobs` 重复声明六个字段，SQLite 在解析 `activation_epoch` 时终止启动。组件现在为每个字段保留一条声明，并创建实体读写需要的可空 `actor_id`。[评审表初始化](../../../../Source/PuddingPlatform/Services/Reviews/ReviewJobSchemaBootstrapper.cs)

回归用例从一个含既有记录、尚无评审表的 SQLite 库开始，运行宿主使用的建表代码，并在第二个 DbContext 再次运行。断言覆盖旧记录保留与评审人身份读回。原程序集运行同一测试报重复列，修复后通过，评审存储与建表组合定向测试共 16/16 通过。[回归测试](../../../../Source/PuddingPlatformTests/Services/ReviewJobSchemaUpgradeTests.cs)

正式安装原有 Core 启动时缺少评审依赖注册。独立程序包备份和替换后，真实数据目录暴露了上述建表错误；Guardian 自动恢复到可用快照。修复包通过 Guardian 部署，正式 Desktop 在 `D:\Data` 上达到 `WorkbenchReady`，Core 达到 `Ready`，Guardian 通过稳定观察并报告 `healthy`。桌面显示默认工作空间。验收范围为启动与数据访问，本次未发送模型或渠道测试消息。[Guardian 运行手册](../../../13_runbooks/Desktop-Guardian.md)
