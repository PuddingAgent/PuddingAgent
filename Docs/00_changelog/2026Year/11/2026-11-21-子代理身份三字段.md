# 子代理人类可读身份三字段（display_name / avatar_key / responsibility）

- 日期：2026-11-21
- 提交：`365c3a7`
- 范围：`PuddingCore` / `PuddingPlatform` / `PuddingRuntime` / `PuddingHost` + 两个测试工程

## 问题

`session_sub_agents` 是每个子会话的当前状态投影，但没有人类可读身份：界面只能显示
`...-sub-e8b01311` 加一段被截断的 `task_summary`。子代理一旦多起来，无法判断「这个是谁、负责什么」。

## 改法

三个可空字段贯穿 DTO → 工具参数 → 调用请求 → 状态投影 → 读回投影：

- `SubAgentSpawnRequest.DisplayName / AvatarKey / Responsibility`
- `SubAgentSpawnInfo` 增三字段 + `RoleInPlan`（生成 `<role>-<n>` 的种子）
- `SubAgentStatus` 增三字段（读回通路，HTTP 直接序列化）
- `session_sub_agents` 增 `display_name`(64) / `avatar_key`(32) / `responsibility`(200)
- `spawn_sub_agent` 暴露 `name` / `avatar` / `responsibility`

### 三条关键语义

1. **UPSERT 用 `COALESCE(excluded.x, x)`**。复用路径上父代理往往不传身份，直接覆盖会把已设的名字清空（「每次重跑都丢名片」）。
2. **去重做在写入之前**。本表没有 `display_name` 唯一索引，靠异常兜底无效。去重范围是**同父会话下的活跃（running）子代理**；终态行不参与——名字是「当前在场的人」的区分，不是历史主键，已完成子代理的名字被新子代理沿用正是期望行为。
3. **`responsibility` 的回退是展示层契约**，不在写入点派生。若在写入点自动取 `task_summary` 首句，池化复用/重跑时会把用户先前设的职责覆盖掉。

### 命名规则

- 父给名 → 去重后写入，原名优先，冲突追加 `-2`、`-3`
- 父没给名且本行已有名 → 返回 `null`，由 COALESCE 保留旧值
- 父没给名且本行没有名 → 生成 `<role>-<序号>`，从 1 开始

## Schema：为什么必须写 bootstrapper

运行时**从不执行 EF 迁移**（全仓 `Migrate()/MigrateAsync()` 零调用），只有 `EnsureCreated`——它覆盖全新库，但**不给已存在的库补列**。

因此新增 `SessionSubAgentIdentitySchemaBootstrapper`：`PRAGMA table_info` 守卫 + 幂等 `ALTER TABLE ADD COLUMN`，在 `PuddingApplicationInitializer` 注册（紧跟 `SubAgentRunSchemaBootstrapper`）。列类型一律 `TEXT`（不用 `TEXT(64)`）——SQLite 不执行长度约束，写 `TEXT(64)` 只会让两条建列路径的 `PRAGMA type` 不同，徒增比对噪声。

## 验收

| 项 | 结果 |
|---|---|
| 构建（Platform `-t:Rebuild` / Host） | 0 error |
| 目标用例（父代理亲跑） | Platform 20/20；Runtime 186/186 |
| 变异 A（去 COALESCE） | 失败 1 —— 「不传 display_name 不得清空已有名字」 |
| 变异 B（删序号逻辑） | 失败 2 —— 期望 `reviewer-1` 实得 `reviewer` |
| 变异 C（父代理自做：bootstrapper 列存在守卫改 `if (false)`） | **失败 2 / 通过 2** —— 幂等用例咬住重复 ALTER |
| 复原 | SHA-256 逐位一致，`-t:Rebuild` 后 4/4 绿 |
| 两路一致性 | EF 新库 vs「旧 14 列 + bootstrapper」→ 列名集合与 `名称:类型` 集合双向相等 |

## 遗留

1. **部署顺序**：存量库（12.2 GB）仍是 14 列，三列要等下次 Core 启动由 bootstrapper 补。补列前若运行新版查询会因缺列报错 ⇒ 必须**先重启 Core 再让 UI 读新字段**，不能反向。
2. **并发窗口未消除**：去重是「先查再写」，同一父会话两个并发 spawn 抢同一名字时理论上可各拿同一序号。失败模式只是显示重名，不损坏数据；强一致需唯一索引或事务化，另行设计。
3. **批量模式无 per-task name**：`tasks` 数组未扩展，批量子代理只能自动生成 `<role>-<n>`。
4. `display_name` 的 2–16 字符只是建议，列宽 64、写入点按 64 截断（含 `-NN` 预留 3 字符），不因名字过长拒掉一次委派。
