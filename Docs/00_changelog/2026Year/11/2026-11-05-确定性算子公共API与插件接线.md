# 2026-11-05 确定性算子公共 API 与插件接线

## 改动

- 新增 `Source/PuddingOperatorAccess.Contracts/`、`Source/PuddingOperatorAccess/`、`Source/PuddingOperatorAccessTests/`：可信 grant、不可变授权目录、调用数、输入预算、截止时间、取消、撤销排空与作用域隔离指纹；通过 csproj 拒绝反向宿主引用。先独立构建/测试，随后接 Host 与解决方案。
- 新增 `Source/Pudding.Api.Contracts/OperatorEvaluation.cs`、`Source/Pudding.Api.Sdk/OperatorsClient.cs`、`Source/Pudding.ToolPlugins.AgentSdk/PluginOperators.cs`：上层与插件均可用类型化 `SkillValue.ScoreAsync`，不接触内部存储、模型池或 JSON 传输。
- `Source/PuddingRuntime/Operators/PublicApi/` 调用原 `SkillValueScorer`，没有重写公式。零观测返回 `InsufficientData/null`，真实低分仍可为 `Valid/0`；保留原量纲、版本、原因和证据。调用方统计标记 `caller-supplied`，不伪装为已核对的宿主遥测。
- `PluginValidation.cs`、Worker `Program.cs`、`ExecutablePluginService.cs` 与 Host 组合根接入 Core API 1.2 的 `operators.list`、`operators.skill-value.score`；旧 Core 1.0/1.1 配置及工具调用行为继续验证。
- 新增 `Tests/PuddingOperatorApi.IntegrationTests/`、`Tests/PuddingToolPlugins.Fixture/OperatorPlugin.cs` 和 Host 装配检查。真实 Worker 证明授权拒绝、伪造 scope 拒绝、卸载后旧工具失效，并验证“先写状态、后评分失败”不能将整次工具副作用标为 none。评分错误码保持，整次执行为 unknown。
- 解决方案与受影响 code_map 已登记；接入合同见[设计文档](../../../12_features/确定性算子公共API-契约与接入-2026-11-05.md)。原设计中的分类/判断 handle 明确标为后续设计，不发布空实现。

## 冻结基线演进

主代理负责核心合同演进；DS-PG01 继续使用既有 Core 1.1 配置 SDK，不得修改基线。此次允许变动的仅为：

1. `Source/Pudding.ToolPlugins.Runtime/PluginValidation.cs`：接受 Core 1.2 与两个明确的算子能力，拒绝任意模型、分类、覆盖与 work.submit。
2. `Source/Pudding.ToolPlugins.Worker/Program.cs`：新增公共算子错误映射；评分失败不证明整个工具没有副作用。
3. `Source/PuddingRuntime/Services/Plugins/ExecutablePluginService.cs`：新增独立算子工厂与本次调用租约、路由分派。

更新前逐项计算全部 18 个文件指纹，差异集合精确等于以上三项；旧回归通过后更新 `Docs/12_features/插件Agent配置API-核心文件指纹.json` 三个哈希。配置/Work 合同、配置 SDK/委托组件、Manager 授权/排空逻辑均未重设。前后摘要留在 `plugin-freeze-delta.json`。

## 未完成与交付边界

- 当前只开放确定性评分；模型分类/判断、父调用预算预留与结算、模型资源租约、插件 Work 提交、Goal 验收 Hook 和算子替换权限仍未实现。
- 输入为调用方提供的数据，不是宿主遥测查询或数据真实性背书；没有算子 HTTP 端点或持久化回执。
- 独立 Worker 的调用验收不是已部署产品的在线功能验收。本轮没有部署、重启、commit 或 push，也没有改 DS-PG01 的白名单示例目录。
