# 首个公共闭环与预算边界测试

补上收敛计划要求的最小闭环证据；未 commit、未部署、未调用真实模型。

## 1 Work 公共闭环（真实 SQLite、容器内无 provider）

`WorkPublicClosureTests`：
- 管理 principal（actor=`actor-1`）取得 Agent 引用 → `Submit` 写 canonical acceptance/batch/command/message/accepted event/turn；
- 同 operation+内容重放返回同一 WorkId；同 operation 改内容 → `operation.conflict`；
- `Get` 读回 `Accepted` 快照；`Observe` 返回已提交的 `turn.accepted` 事件页；
- `Cancel` 经 `IExecutionControlService` 发出 `CancelRequested`（记录 conversation/turn/kind），返回 `Requested`；
- 容器**没有注册任何 LLM/provider**：提交只受理、不推理；若启动执行会直接失败。

## 2 预算边界（真实持久账本）

`BudgetBoundaryClosureTests`：
- Enforced Goal 根预算（`MaxCost=0.004`）经 `PlatformModelAttemptBudgetPort` 预留 → 账本 `ReservedCost>0`、`ActiveAttempts=1`；
- 兄弟 attempt 预留被拒（`budget.exhausted`），不能透支共享根；
- 按实际 usage 结算后 `ReservedCost=0`、`Cost>0`、`UnknownCost=0`。

## 3 验证

- 两个测试 **2/2**；Platform S5 切片 **166/166**；全解决方案构建 exit 0（restore + --no-restore）；一键脚本 RunId 20261106-r32 exit 0（组件 276 + Platform 166 + 前端 47 + tsc）。
- 证据：`.work/i2/closure/`、`.work/verification/closure-solution/`、`.work/pa08/components-20261106-r32/`。

## 4 未完成

- 该闭环**不是完整产品执行**：没有真实 Core Worker/执行循环，因此不证明预算/取消到达 provider 的真实调用边界；预算测试只证明 port→持久账本边界。
- 并发限制（`MaxConcurrentAttempts`）与队列/派发竞争未在闭环中覆盖；Create 真实适配仍缺端到端证据。
- 子代理池/提交端口、工具/授权/MCP/上下文/工作区/插件消费者迁移、Goal 自动评审接线、08B/08C（NotRun）保持原状。
