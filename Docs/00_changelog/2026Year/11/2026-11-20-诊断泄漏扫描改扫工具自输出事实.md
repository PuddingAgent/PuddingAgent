# 2026-11-20 诊断泄漏扫描改扫工具自输出事实

## 目标 / 背景

`RuntimeIdentity_DoesNotEchoSecretsOrEnvironmentVariables` 断言 `runtime_identity` 的输出不含
`token` / `secret` / `password` / `apikey` / `api_key` / `connectionstring`。它扫的是整个序列化
载荷，其中包含 `freshness.headSubject`。

提交 `eee9503` 的标题是「fix(jev): resolve the pool's {{vault:…}} apiKey reference instead of
sending it as a key」，于是载荷里合法地出现了 `apiKey`，断言变红。这根提交一落地就红，
与后来的代码改动无关——本次是把它查清楚而不是当成自己引入的回归。

提交主题是人写的自由文本，本来就在 git 历史里公开；把它算作「诊断泄漏了秘密」是判据错位。

## 改动

- `Source/PuddingRuntimeTests/Tools/AgentDiagnosticsToolTests.cs` —
  扫描对象改为「载荷去掉 `freshness.headSubject` 之后的内容」，新增
  `RemoveExternallyAuthoredText`（用 `JsonNode` 删该字段后重新序列化）。
  同时加两条阳性对照：剥离结果必须仍含 `assemblies` 与 `vocabulary`。

## 验证

- 全量 `PuddingRuntimeTests`：2869 总计 / 2858 通过 / 0 失败。
- 变异取红：令剥离函数直接返回 `{}` → 该用例变红，失败信息为
  `String '{}' does not contain "assemblies"`，证明阳性对照确实在起作用、断言不会因扫空对象而永久变绿。
  复原比特一致（SHA-256 `c35fb6e0…`）后重新全绿。

## 影响与回滚

- 仅影响测试，不改产品输出；`headSubject` 仍照常输出（它是「部署的是哪一版」的直接证据）。
- 回滚：`git revert ac65174`。

## 关联

- 提交 `ac65174`。
- 判据取舍：扫描对象应为「工具自己选择输出的运行时事实」（程序集路径、词表来源、环境变量名），
  不含外部作者写入的自由文本。
