# 子代理结果消息正文重做（A 期）

## 为什么

用户实测：子代理完成后，聊天气泡只有两行 —— `Sub Agent 发来的消息` / `shell: exit code 1`。
而那个子代理**已交付 9 个文件 +123/−32、测试 22/22 通过**。

根因一行代码：

```csharp
var contextText = deliveredResult
    ? reply ?? string.Empty      // 成功 → 回复正文
    : error ?? "unknown error";  // 其余一切 → 只剩错误串
```

**失败时 `reply` 被整条丢弃。** 而"交付完成但最后一步工具报错"是高频情形（本会话 4 例全部如此）。

## 改了什么

只改 `SubAgentManager`，新增三个 `internal static` 纯函数（便于单测），并把 `contextText` 改为调用它们：

| 成员 | 职责 |
|---|---|
| `BuildSubAgentResultBody(...)` | 拼三段正文 |
| `FormatResultStatusWord(status)` | 状态词（completed→已完成 / paused→已暂停待裁决 / budget_exhausted→预算耗尽可续跑 / …） |
| `ResolveDisplayNameForResult(...)` | 名字：`DisplayName` → `<templateId>-<短 ID>`，**不再硬编码 `Sub Agent`** |

正文格式（固定序，不可调换）：

```
**子代理 <名字> <状态词>** · 模板 <templateId> · 工具 <N> 次（失败 <F> 次）

<reply 全文 —— 无论 status 是什么都保留；为空则「（没有产生可读的交付文本）」>

---
⚠ 错误诊断（<category>）：<完整句子>
```

## 四条写死的规则

1. **错误永不占据正文位置**。正文第一个非空行必须是标题；错误只能在 `---` 之后。
2. **缺失项显式写出**：`未记录失败摘要` / `未记录错误文本` / `无堆栈，工具退出码路径`。
   不许留空（空与"没有"必须可区分），不许伪造堆栈，**不许凭猜写 `runtime_exception`**（我们手上没有异常对象，只有退出码与摘要）。
3. **错误段按条件出现**：`error` 为空且 `toolFailureCount == 0` 时不出现，避免每一条成功消息都拖一个无意义的分隔段。
4. **`category` 由 `toolFailureCount > 0` 判 `tool_failure`，否则 `unknown`** —— 只报能确定的。

## 验证

```
dotnet build Source/PuddingPlatformTests/PuddingPlatformTests.csproj -t:Rebuild   → 0 错误
dotnet test --filter "FullyQualifiedName~SubAgentResultBody"                      → 12/12 通过
dotnet test --filter "FullyQualifiedName~SubAgentManager|FullyQualifiedName~SubAgentResult" → 43/43 通过
```

三处变异取红（子代理两处 + 父代理独立一处）：

| 变异 | 结果 |
|---|---|
| `contextText` 改回旧写法 | 判据「失败仍保留 reply」「paused 保留正文」「正文先于错误」红 |
| 删掉缺失项显式化分支 | 判据「缺失项必须显式」红 |
| **父代理独立**：`ResolveDisplayNameForResult` 直接 `return "Sub Agent";` | **失败 2 / 通过 10**，命中 `ResolveDisplayNameForResult_PrefersDisplayName_AndFallsBackToTemplateAndShortId` 与 `BuildSubAgentResultBody_FailedWithMissingDiagnostics_MatchesExactLayout` |

复原后 `SubAgentManager.cs` SHA `180EC3ED…` **逐位一致**，`-t:Rebuild` 后 12/12 复绿。

## 范围与遗留

- **只改后端正文拼法**，未动前端、未动 envelope 字段（`MessageId` 幂等语义、`Intent`、`Visibility`、`ContentType` 均未变）。
- 因此气泡**渲染样式**不变（仍是 inbound agent 卡片），变的是**内容**。用户要多久能看到取决于部署。
- 未做：状态徽标/动作按钮（B 期）、交付面（`work_outcome` + 改动统计，依赖信封 v2）、
  正式错误载荷的完整字段（`stderr_tail` / `exception_type` / 堆栈采集，需在工具层透传）。
- 无新增文件，故未改 `code_map.md`（`SubAgentManager.cs` 行已存在，本次为内部方法增补）。
