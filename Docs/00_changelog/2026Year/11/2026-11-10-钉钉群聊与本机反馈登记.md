# 钉钉群聊与本机反馈登记

新增独立组件 `Source/PuddingDingTalk/`，接入 `Source/PuddingHost/Services/DingTalkGroupChannel.cs`。消息来源、时间、人员与企业在进入公开问答前核验。回调重投由 SQLite 唯一键拦截，答复须命中公共选项；两种显式反馈可产生固定目录内的 Markdown 与登记编号。

独立测试 15/15。正式 Host 构建成功。用鲸鲸真实配置、公开规则段与生产 Runtime 模型适配器离线于群渠道发送五个测试问题，覆盖提交指引、代码证据、问候、自称管理员和私聊索取，五项均符合预期。测试未向成员发送模拟请求。

正式 Desktop 与 Core 经 Guardian 健康观察，Stream 已连接。群聊可见三类答复，包括对本机信息请求的拒绝。问答范围见[钉钉群聊接入](../../../01_message_channels/钉钉群聊接入.md)。企业成员绑定及 AI 表格读写未启用。

### 更正（2026-11-10）

成员实测发现，询问报告导入和明确登记小屏幕错位 BUG 都得到了相同的拒绝。初版选择固定答案，无法满足直接与鲸鲸对话的要求。已移除该路径。`Source/PuddingHost/Services/DingTalkPublicAgent.cs` 使用绑定实例和实例当前的模型，调用 Runtime 的 Agent dispatcher 与工具循环。`DingTalkTurnTools.cs` 对每次工具调用核对 guest、实例和会话，提供公开用法查询及固定目录登记。公开上下文按企业、群、成员隔离。

独立组件 15/15。Host 测试工程构建通过。在本机 VSTest 的 testhost 打开父进程时被 Windows 拒绝，随后独立运行已构建程序集的三组 xUnit 测试方法，全部通过。覆盖真实工具结果回到模型、私有提示词隔离、未授权工具拒绝、同一成员追问与其他群和成员的隔离。另用鲸鲸的真实模型执行导入咨询、自然语言 BUG、功能需求、主机信息请求四种输入，隔离目录实得两份 Markdown。

初版在健康观察后被 Guardian 回滚。新版本经 Guardian 重新部署，Core 就绪、钉钉 Stream 连接、运行目录 Host 与钉钉程序集摘要均已核对。正式群的回执和台账需用新消息验收，旧回调不重放。

### 正式群验证

新版本在 18:50 连接钉钉。至 18:54，正式库收到五条 guest 回调，五条均拿到钉钉发送成功回执。18:51 的一轮调用公开用法工具，18:52 的一轮调用反馈登记工具。用后一条回调的企业、群、消息 ID 重算摘要，命中文件名，并在正式 Markdown 中读到成员报告的小尺寸屏幕显示问题。隔离测试的编号和台账未计入正式回执。
