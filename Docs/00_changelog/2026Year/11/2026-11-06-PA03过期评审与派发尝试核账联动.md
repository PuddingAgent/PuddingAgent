# PA-03 过期评审与派发尝试核账联动

落实裁定 §5.4“过期 Running 若已有派发 attempt，先核账，再决定重试”；未 commit、未部署、未调用真实模型。

## 1 联动规则

- 新增 `ReviewAttemptReconciler`：按 `job.BudgetAccountId` 读取持久账本的恢复候选，匹配 `AttemptId = "{jobId}:{ownerEpoch}"` 且阶段为 **Pending/Dispatched** 的尝试。
  - 存在未结算派发 → `Blocked`（`review.attempt_unsettled`），Worker **延后**该 Job 并记录数量；
  - 已 `Unknown` 或 `Settled` → `Clear`（Unknown 保持不可退款，但不会导致重复派发）。
- `ReviewJobWorker` 在回收 Running Job 前调用该检查；被阻塞时计入 `Skipped`，不领取、不再次调用模型。

## 2 测试与验证

- 新增 `ReviewBudgetReconciliationTests`（真实 SQLite + Review/Budget 两套 schema）：
  - 过期 Running + 已派发未结算尝试 → Worker 延后（Executed=0, Skipped=1，Job 仍 Running）；
  - 将该尝试 `MarkUnknown` 后 → Worker 回收并完成 Job。
- 与既有 Worker 测试合计 **7/7**；Platform S5 切片 **116/116**；全解决方案构建 exit 0；一键脚本 RunId 20261106-r15 exit 0（组件 274 + Platform 116 + 前端 47 + tsc）。
- 证据：`.work/pa03/budget-reconciliation/`、`.work/verification/reconcile-solution/`、`.work/pa08/components-20261106-r15/`。

## 3 未完成

- runtime binder 仍未接（模型路由/Job 预算身份/唯一预留），所以该联动目前只覆盖“已有派发记录”的账目层；真实 reserved attempt 仍由 binder/执行边界创建。
- 流式/子代理预算、Goal 自动续跑、08B/08C（NotRun）保持原状。
