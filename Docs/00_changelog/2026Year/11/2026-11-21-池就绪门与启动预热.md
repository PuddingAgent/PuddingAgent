# 池就绪门与启动预热（持久子代理池 S4）

## 要堵的洞

`SubAgentTransientDirectoryGcService` 把池里的条目集合当作「删除白名单」：
集合里有的目录跳过，其余按脚手架/终态/保留期逐步判定后回收。

池接入数据库之后多了一个新状态——**还在加载**。而在 GC 眼里，「加载没完成」和
「池里确实没有成员」都是同一个空集合，于是未就绪时它会认为没有任何目录需要保护。

这不是理论风险：进程刚重启时 run 已被启动对账终结成终态，四道闸门里的
「run 非终态」那一层正好失效，误删条件更容易凑齐。

## 修法

### 四态就绪门

```csharp
public enum PoolReadiness { NotStarted, Loading, Ready, Failed }
```

- `List()` 在非 `Ready` 时**抛 `PoolNotReadyException`**，绝不返回空列表；
- `Ready && Count == 0` 是**合法的空池**，必须继续正常扫描；
- 加载失败落 `Failed` 并**保留原始异常**，`List()` 报错时要能说明原因——不降级为空池。

`ISubAgentPool` 新增 `Readiness` 与 `GetSnapshotAsync`；既有成员签名一字未改。

### 池的加载

`SubAgentPool` 注入**可空**的 `IAgentPoolEntryStore`：

- 为 `null`（既有单元测试）→ 恒 `Ready`，32 个既有用例零改动；
- 非 `null`（生产）→ `EnsureReadyAsync` 用 `SemaphoreSlim` + 双检做一次性加载，
  成功 `Ready`、异常 `Failed`（终态，不自动重试）。

`CreateAsync` 改为：先确保就绪，再 `TryInsertAsync` 写库，**写库成功后才写内存**。
池满时沿用既有的 `InvalidOperationException` 与文案，不新增异常类型。

### 预热服务与顺序

新增 `AgentPoolWarmupService`（`IHostedService`），`StartAsync` 触发一次加载；
失败只记 `LogError`，不让宿主启动失败——池会停在 `Failed`，`List()` 会明确报错。

**注册顺序有一个必须说清的局限**：`SubAgentConversationProjectionWorker` 是通过
`AddHostedService` 注册的，并不经 `PuddingApplicationInitializer`；而
`BackgroundService.StartAsync` **不 await** `ExecuteAsync` 主体。所以「排在它后面注册」
只保证**更晚开始**，不保证**恢复已完成**。

本轮无功能影响（池只读 `agent_pool`、不重置 busy）。S5 接 `ResetStaleBusyAsync` 时
必须升级为真握手：worker 暴露 `RecoveryCompleted` Task，warmup await 它。

### GC 顺序

把「取池快照」从 `EnumerateDirectories` 之后**前移到之前**，并新增
`catch (PoolNotReadyException)` → `Errors=1, Scanned=0`，不枚举、不移动、不写 quarantine
直接返回。`PurgeExpiredQuarantineAsync` 保持原位（它与池无关）。

语义上「池不可用 ⇒ 不进入源目录阶段」应当体现在调用顺序上，而不是靠 catch 兜底。

## 已知遗留（S5）

- `ExecuteAsync` / `FinishAsync` / `SleepAsync` / `DestroyAsync` 仍只改内存，未写库；
- 从库恢复出的 `busy` 条目尚未接 `ResetStaleBusyAsync`，重启后可能显示 busy 却无法派活；
- `GetAsync` / `Count` 未设就绪门（本轮只要求 `List()`），"未就绪时 GetAsync 返回 null" 的歧义仍在；
- 加载回填用 `TryAdd` 而非索引赋值：`ExecuteAsync` 的自动预留不经过就绪门，
  若加载期间已有同名活条目，覆盖会丢掉它的收尾（`FinishAsync` 用引用相等判定）。
