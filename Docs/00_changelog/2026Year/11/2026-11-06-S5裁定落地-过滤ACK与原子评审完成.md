# S5 裁定落地：过滤 ACK、扫描进度与评审原子完成

按《Agent 组件化 S5 架构裁定与接线门禁》修正第一批源码缺口，未 commit、未部署、未调用真实模型。

## 1 事件与 ACK 正确性

- **过滤后 ACK**：`SubscriptionDispatcher.AckAsync` 改为校验“已确认投递是 claimed 批次的前缀”，不再要求原始 `EventSequence` 连续；被过滤 kind 的序号可被跨过，但 claimed 投递不可跳过。已确认事件早于 cursor 时返回 `CursorGap`。
- **整页无匹配**：`DispatchAsync` 在无可投递事件时先重发既有 lease；无 pending 时用页末序号推进内部扫描位置（`AdvanceScanAsync`），不再反复读同一页；扫描推进不改变公共 `CursorSequence`。
- **保留边界**：统一为 `AfterSequence + 1 < OldestAvailableSequence` 的溢出安全写法（`after < oldest - 1`）；测试覆盖 after=9/oldest=10 可读、after=8 需快照。
- **死信阻塞**：`AckAndAdvanceAsync`/`AdvanceScanAsync` 在存在更早死信时返回 `event.dead_letter_blocked`；死信只能显式重放，不能静默跨过。
- **契约修订**：`SubscriptionRecord` 增加 `ScannedThroughSequence`（默认 0）；`IEventCheckpointStore` 增加 `AdvanceScanAsync`；新增错误码 `DeadLetterBlocked`。表新增 `scanned_through_sequence` 列。

## 2 评审 Waiting 与原子完成

- **Waiting 一致**：`ReviewJobStore.FailAsync` 接受 `Waiting`；`ListClaimableAsync`/`ClaimAsync` 允许 Waiting 在新证据到达后重新认领（revision/owner 围栏不变）。缺证据不再只能写 Unknown。
- **Review 完成 + outbox 同事务**：`IReviewJobStore.CompleteAsync` 增加 `ReviewCompletedEvent` 参数；Platform 在同一 DbContext 事务写 Job 终态与 `review_events` 行；`ReviewJobCoordinator` 不再先完成再单独发布，事件 id 由 `jobId|claimedRevision` 稳定派生；同一完成重放返回原事实且不新增事件，事件 id 属于其他 Job 时整批回滚（Job 保持 Running）。
- **契约修订**：`CompleteAsync` 签名变化，组件测试宿主与 Platform 测试 fake 已同步；`ReviewEventOutbox` 仍用于显式重放/诊断，生产完成路径不再调用。

## 3 测试与证据

- 新增 9 条：Eventing +5（过滤前缀 ACK、无匹配扫描、死信阻塞 ACK、部分 ACK、保留边界）；Platform +4（扫描单调/pending/死信、ACK 死信阻塞、Waiting 重新认领、事件 id 冲突回滚）。
- 结果：`PuddingEventingTests` **25/25**、`PuddingReviewsTests` **23/23**、Platform 评审/订阅切片 **22/22**；全解决方案构造 **0 错误**。
- 证据：`.work/pa07/arch-ruling-events/`、`.work/pa03/atomic-completion/`、`.work/verification/solution-ruling/`。
