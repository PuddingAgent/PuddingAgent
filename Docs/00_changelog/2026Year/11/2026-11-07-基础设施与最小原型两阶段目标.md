# 基础设施与最小原型两阶段目标

用户明确先完成基础设施、组件服务、插件 API、组件及抽象实例生命周期、事件订阅和 Hook，再组合最小早期原型。本轮将这两个交付目标分开，避免局部 SDK 示例或 Goal 专用接线代替基础设施完成。

## 改动

- 新增 `Docs/12_features/基础设施服务生命周期与最小原型两阶段目标-2026-11-07.md`：定义基础域清单、组件合同卡、对象所有权、生命周期竞争条件、事件/订阅与 Hook/策略合同，列出 A1～A6 放行证据。
- 最小原型使用真实组件和隔离存储、脚本模型、工具插件与零工具功能插件；覆盖公共 API → Work → 工具 → 产物事实 → 后续功能、重投幂等、取消与卸载。Goal 后置，产品部署单列。
- 就地修订公共 API 规划、收敛计划、任务书总则，消除“目录/Work 局部切片就是最小原型”的歧义；根 `code_map.md` 登记设计入口。
- 保留既有任务编号、契约冻结和 DS-I1-04 白名单。未修改历史验收报告或生产代码。

源码复核表明，现有 `ExtensionPorts.cs` 的点目录集中于工具与 Turn，`ExtensionContext` 仍要求 Agent/Session 身份；不能将其视为通用非 Agent 功能插件合同已齐备。新规划要求围绕现有事件信封、插件主管及领域状态权威演进，不另建平行总线或统一大状态机。
