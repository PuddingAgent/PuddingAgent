# CORE-I1-06 开工盘点与决策记录

按任务书要求，主代理先盘点真实传输接缝与重发点，冻结“每次真实模型发送＝一个独立预算 attempt”的设计，再进入实现。

## 改动

- 新增[CORE-I1-06 决策记录（开工盘点）](../../../12_features/CORE-I1-06-单次模型发送与租约结算-决策记录-2026-11-08.md)：逐文件列出 facade 单 attempt 包裹、`DirectLlmClient` 缓冲/流式重试循环、三协议网关单发、`ResponsesLlmGateway.SendWithFileRebuildAsync` 的两次发送、预算 gate/port 缺口、`ModelLeaseRegistry` 无生产消费者，以及 Review/旧路径边界。
- 冻结方案：新增 Core 级 per-send `LlmSendAttemptScope` observer，在每次真实 `SendAsync`/流创建前开 attempt（新 AttemptId、时点报价、`PricingRuleVersion`/revision/币种/窗口校验），返回的输出上限回写到请求；结束按 usage settle、无法证明效果置 Unknown、证实未发送 Release；Responses 重建第二次发送独立计费；Review 路径保持自身预算不双记；真实租约池由 Host 注入。
- 列出精确读写文件单与 T1–T7 验收映射，明确不搬移 `DirectLlmClient` 重试循环（保留协议/首块/首 delta 语义）。

## 首批实现（slice 1：发送边界合同与 observer）

- 新增 `Source/PuddingCore/Observability/LlmSendAttemptScope.cs`：per-send `LlmSendAttemptRequest/Permit/Usage`、`ILlmSendAttemptObserver` 与 AsyncLocal `LlmSendAttemptScope`（Runtime/网关只调用 Begin/Complete，不持有第二套预算状态）。
- 新增 `Source/PuddingRuntime/Services/BudgetedSendAttemptObserver.cs`：每次发送生成新 AttemptId，沿用冻结 Work 身份/revision/价格，输出上限取 min(预算, 请求)，按 usage settle、缺 usage/失败置 Unknown、已未准入的 Legacy 不写账本、重复 Complete 幂等。
- 新增 `Source/PuddingRuntimeTests/Services/BudgetedSendAttemptObserverTests.cs`：6/6 通过（每次发送独立 attempt、实际 usage 结算一次、缺 usage/失败 Unknown、Legacy ungated、非法身份拒绝、scope 生命周期）。
- 本切片尚未接入 `LlmInvocationService`/`DirectLlmClient`/网关：真实发送链仍是旧的单 attempt 包裹，T1/T2 的账本对账要到 slice 2 才成立。

## slice 2（2026-11-08，T1/T2 buffered 接线）

- `LlmInvocationService.InvokeAsync` 检测 `IBufferedSendAttemptBudgetClient` 时安装 `LlmSendAttemptScope` 并跳过旧的单 attempt Begin/Settle；其他客户端保持原行为。
- `DirectLlmClient.ChatAsync` 的每次真实发送前调用 `BeforeSendAsync`（新 AttemptId、冻结 Work 身份/价格、输出上限收紧），成功后按 usage `CompleteAsync` 结算，失败标记 Unknown；预算拒绝第二次发送时停在 HTTP 之前。
- 新增 `Source/PuddingRuntimeTests/Services/TransportAttemptBudgetTests.cs`：3/3 通过（重试=两次真实发送/两个独立 attempt、首次失败 Unknown+成功 settle、预算拒绝不触达 provider）。连同 observer 6 条共 9/9 通过。
- 未接线：streaming、Responses 文件重建、T5/T6/T7 仍未开始。
