# CORE-I1-05 单轮 Work 预算身份贯穿

按[CORE-I1-05 任务书](../../../12_features/CORE-I1-05-单轮Work预算身份贯穿任务书-2026-11-07.md)先写[一页决策记录](../../../12_features/CORE-I1-05-单轮Work预算身份贯穿-决策记录-2026-11-07.md)，再按冻结语义实现普通单轮 Work 的预算身份、限额与模型报价来源。

## 改动

- `Source/PuddingCore/Runtime/RuntimeExecutionIdentity.cs`：新增可选 `WorkBudget` 载体与 `RuntimeWorkBudgetBinding`（账户/祖先/Work 根/币种/模型 revision/价格版本/单次容量），不新增平行 DTO。
- `Source/PuddingCore/Platform/IExecutionCommandReader.cs`：`ExecutionCommandRecord` 暴露可选 `ClientRequestId`（仅关联候选）；`Source/PuddingPlatform/Services/ExecutionCommandReader.cs` 映射现有列，无 schema 变化。
- 新增 `Source/PuddingPlatform/Services/ExecutionBudgets/ManagedWorkBudgetPolicy.cs`：Host 配置策略（默认关闭=旧行为）、limits/mode/currency 校验、受管失败码。
- 新增 `Source/PuddingPlatform/Services/AgentWork/ManagedWorkBudgetBindingResolver.cs`：命令+受理行+受理标记+frozen `IAgentWorkBackend` 交叉校验 → DS-I1-04 mapper 账户 → 目录 revision/定价；受管但证据不符显式失败，不落回非受管；账户取消/冲突保留 typed 码。
- `Source/PuddingPlatform/Services/AgentChat/ExecutionRunCoordinator.cs`：可选注入 resolver，在 `turn.started` 前解析并挂到 `ExecutionIdentity.WorkBudget`；`ManagedWorkBudgetException` 映射为 Failed 终态码。
- 新增 `Source/PuddingRuntime/Services/AgentExecution/WorkBudgetAttempt.cs`：共享转换（每次发送独立 attempt，同 Work 账户复用）、缺 facade/身份不一致 fail-closed；`AgentExecutionLlmInvoker` 与 `AgentExecutionService.Streaming` 两处请求填充 `BudgetAttempt`，托管执行禁止直连客户端。
- 新增 Host partial `PuddingServiceCollectionExtensions.ManagedWorkBudget.cs`：配置绑定与 scoped resolver 注册；调用点加在非冻结主装配文件，`PuddingServiceCollectionExtensions.Platform.cs`（config 冻结清单）未改。
- 新增 `Source/PuddingRuntimeTests/Services/AgentWorkBudgetPropagationTests.cs`（载体转换/facade fail-closed/真实 LlmInvocationService+port）。
- **复核退回后修复（2026-11-07 独立验收三项阻断）**：
  - P1 产品 DI：`PuddingServiceCollectionExtensions.ManagedWorkBudget.cs` 补注册 `ExecutionBudgetAccountMapper`（原只在测试 fixture），真实 Host 组合根在默认关闭与显式开启下均可解析 resolver 与 Coordinator。
  - P1 恢复语义：resolver 绑定前先读持久定义；已有 Work 使用**冻结的限额/模式/币种**继续（宿主策略 MaxCalls 10→8 不再产生 `budget.conflict`），新 Work 使用当前策略；mapper 对显式修改既有定义的冲突检查保留。
  - P2 OperationId：`ReadOperation` 保留键上限 64→128，与公共 Work 合同对齐；补 64/65/128 受理并绑定成功、129 在公共入口 `request.invalid` 的用例。
- 新增 `Source/PuddingPlatformTests/Services/ExecutionRunCoordinatorBudgetBindingTests.cs`：真实 Coordinator 在策略关闭/开启下各走一次普通聊天与受管 Work，并验证伪造受管命令在 executor 前被拒（0 次、0 账户）。
- 新增 `Tests/PuddingHost.Tests/Hosting/ManagedWorkBudgetCompositionTests.cs`：真实 Host 注册在两种配置下解析 mapper/resolver/Coordinator（本机 VSTest testhost 受限，已用同逻辑 console 探针实测 PASS；见[修复自检报告](../../../14_reports/2026-11-07-CORE-I1-05-三项阻断修复与复核自检.md)）。
- **安全修复（更早一次复核 rejected 后）**：受管 Work 证据增加服务端 provenance 锚点——`SubmitTurnCommand.IsTrustedCanonicalWorkIngress` 只由 frozen `CanonicalAgentWorkBackend` 在进程内设置；`SubmitTurnHandler` 在未受信时剥离 `agent_work_*` 保留键。普通聊天 HTTP 客户端伪造 `work-*` ClientRequestId + 标记不再能建立受管账户（`EvidenceMissing`，0 次派发）。
- **冻结文件演进（已评审并重签）**：`Source/PuddingPlatform/Services/AgentWork/CanonicalAgentWorkBackend.cs` 设置该受信标志（唯一调用者影响）；work 冻结清单哈希 `E696825D…` → `B5B1B514…`，旧清单与差异证据在 `.work/core-i1-05/20261107-sec/`；三套冻结重跑 PASS。
