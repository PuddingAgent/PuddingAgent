# 2026-10-12 SSH L1：原子令牌容量与完整资源记账

## 目标 / 背景

独立复核 **F8（P1）/ F9（P2）**：未结束的 exec 脱离记账（业务返回后 leases/workers/quarantine 全为 0，
Stop 错报已收敛）；隔离区容量不是硬上限（capacity=1 实测 pending=4，已排队请求继续建连）。
按《SSH资源生命周期补充修补方案》§1 修补；本轮**先把复核证据转成失败断言**再修。

## 改动

- `Source/PuddingSsh/Execution/SshStageWorkerPool.cs`
  - `IsFull` + `Interlocked.Increment` 的两步预留改为 **CAS 取令牌**（`TryAcquire`/`Release`），取不到立即 `ssh.busy`；
  - `StartAsync` **先取令牌再调度**（登记先于调度），令牌在**真实工作结束时**归还；
  - 新增 `Peak`/`Acquired`/`Rejected` 观测（并发 barrier 断言峰值 ≤ 容量）。
- `Source/PuddingSsh/Execution/SshCleanupQuarantine.cs`
  - `Track`（无预留）改为 `TryReserve`（CAS）+ `TrackReserved`/`ReleaseReservation`：**永远 `Pending ≤ Capacity`**；
  - `Capacity = 0` 的语义明确为「禁用转移、保留原槽」，`IsFull` 为 false，不会把正常请求悄悄全部拒掉；
  - 新增 `Peak` 观测；`Complete` 明确「异常已观察 ≠ 关闭成功」。
- `Source/PuddingSsh/Execution/SshResourceLease.cs`（重写）
  - `RegisterWork(task, kind)`：identity/connect/exec/close/迟到回收**在调度之前**登记；完成时观察 fault，
    记录 `CleanupFailures`（稳定 token，不携带载荷）；
  - `BeginObligation`/`EndObligation` + `ResourcesCompleted`：义务清零且登记集合为空才完成资源；
  - `EndBusiness()` **幂等**且只结束业务计数：有挂起工作时保留准入槽，除非 `TryTransferToQuarantine()`
    原子预留成功（失败则保留原槽直到资源真正结束）；
  - `Closed` 是**关闭证据**（会话自报 Closed），`CloseOnceAsync` 是真正共享关闭 Task 的单次状态机。
- `Source/PuddingSsh/Execution/SshOperationCoordinator.cs`
  - exec 调用改走有界 worker 并在调度前登记（L3 的同步入口隔离同时落地）；
  - 关闭走**独立关闭池** `MaxCloseWorkers`（默认 8）：关闭不会被卡死的 connect/exec 饿死；池满时保留未关闭资源；
  - 身份/连接/执行/关闭全部登记进租约；连接阶段用 `StageHandoff` 表达「迟到 owner 与及时路径只结算一次」的义务；
  - 取得准入槽后、读身份之前**再核对**停止与资源准入（隔离区满 / 关闭池满 ⇒ `ssh.busy`），已排队请求同样受约束；
  - `EndLease` 只减业务计数；资源未结束计入 `PendingResourceLeases`；`StopAsync` 报告新增 `PendingResources`；
  - exec 失败映射改用 `SubmissionEvidence`（`NotSent` ⇒ 未提交 + 可重试；`Attempted` ⇒ unknown + 不可重试）；
  - 宽限到期诊断不再声称「已释放独占连接」，改指向 `cleanup_state`。
- `Source/PuddingSsh/Execution/SshCoordinatorOptions.cs` — 新增 `MaxCloseWorkers`（校验 1..32）与
  `SshStopReport.PendingResources`。
- `Source/PuddingSshTests/SshResourceAccountingTests.cs` — 新增 6 例（先红后绿）：
  1. `QuarantineCapacity_IsHardLimit_EvenForAlreadyQueuedRequests`（改前红：capacity=1 实测 pending/连接越限）；
  2. `QuarantineCapacityZero_DisablesTransfer_ButKeepsNormalRequestsWorking`（改前红：容量 0 把正常请求全拒）；
  3. `OrphanExec_StaysAccountedAfterBusinessReturn_AndStopReportsPending`（改前红：计数全 0、Stop 报 0）；
  4. `OrphanExec_LateFault_IsObserved_AndCountersReturnToZero`；
  5. `StageWorkerPool_ConcurrentBarrier_PeakNeverExceedsCapacity`（24 并发、容量 3：峰值 3、拒绝 21）；
  6. `CloseCapacityExhausted_RefusesNewResourceCreation`。
- 既有用例对齐新契约：A3 的提交窗口失败统一按提交事实表达（阶段 `Submitting`）；R3 的 Stop 报告用例改为
  断言「在飞操作或未结束释放工作必须被报告」。

## 验证

- **取红**：`--filter SshResourceAccountingTests` → 失败 3、通过 1（其余 2 例为改后新增 API 的门禁）。
- **复绿**：`dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **214/214 通过**，0 警告 0 错误。
- 真实协议：`powershell -File TestScripts/ssh-probe/run-ssh-probe.ps1` → **23 场景 `failures = 0`**
  （`rounds` 九轮后 leases/workers/quarantine 全 0；`noeof` 关闭 10 ms；`submitfail` unknown 且不可重试）。

## 未完成 / 后续

- **L2**：身份所有权在交付 connect 前原子转移（本切片已把释放点移到 `ResourcesCompleted`，L2 再补显式
  `LeaseOwned → Connecting → SessionOwned → Released` 句柄与「合成字节不被提前清零」门禁）。
- **L3**：Stop 取消回调有界、单一清理预算、迟到 Completed 不覆盖终止事实、`CleanupState` 证据、
  诊断拼接后统一 `Bound`。
