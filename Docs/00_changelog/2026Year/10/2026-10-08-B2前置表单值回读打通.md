# 2026-10-08 B2 前置：表单值回读打通（value/selectedValues 端到端）

## 目标 / 背景

设计方案把「一次 `fill` 调用就能确认写入成功」列为最直接的省 token 手段，并把
`value` 称作「**输入是否成功的唯一可靠回执**」：`text` 字段不含表单值，URL 也推不出填了什么。
第零步是先让**表单值本身**能到达工具层——本轮交付这条链路。

## 改动（自下而上）

| 层 | 文件 | 内容 |
|---|---|---|
| Abstractions | `Source/PuddingBrowser.Abstractions/Locator.cs` | `BrowserElementInfo` 新增 `Value`（input/textarea/contenteditable 当前值，非表单为 null）与 `SelectedValues`（select 选中值） |
| Contracts | `Source/Pudding.Contracts/Desktop/LocateContracts.cs` | `DesktopElementRef` 新增可选 `value` / `selectedValues`（附加构造参数，既有调用点不受影响） |
| 驱动 | `Source/PuddingBrowser.WebView2/WebView2DomClient.cs` | 定位与交互脚本新增 `readValue`/`readSelectedValues` 并在 `describe` 与交互回执里上报；`LocateScript`/`InteractScript` 提为 `internal` 以便断言脚本文本 |
| 传输① | `Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs` | 映射 `DesktopElementRef` 时带上 `Value`/`SelectedValues` |
| 传输② | `Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs` | 同上（桥接路径） |
| 工具 | `Source/PuddingBrowser.AgentTools/BrowserToolContracts.cs`、`BrowserLocateTool.cs` | 元素输出新增 `Value`/`SelectedValues`；`browser_locate` 新增 `include_value`（**默认 false**），只有显式请求才返回 |

`include_value` 默认关闭是刻意的（设计方案 §6.2「value/selectedValues/checked 可显式请求」）：
默认省掉它才能守住输出预算，而需要确认写入时它又是唯一证据。

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AgentTools.Tests` | **18 / 18**（原 17 ＋ 1） |
| `PuddingDesktop.Tests` | **301 / 301**（原 300 ＋ 1） |
| `PuddingHost.Tests` | **252 / 252**（＋1；见下方既有 flake 说明） |
| `DesktopSurface.BrowserTests` · `ContractsTests` · `DesktopServiceTests` · `AutomationTests` | 56/56 · 97/97 · 197/197 · 156/156 |
| `build` Abstractions · Contracts · WebView2 · AgentTools · DesktopSurface.Browser | 0 错误 |

新增门禁：

- `Locate_OmitsFormValueByDefault_AndReturnsItWhenRequested`：默认 `value` 为 **null** 且输出里不含真实值；
  `include_value=true` 时回读到真实值。（契约里 null 表示「未请求/未知」，不是「值为空」。）
- `Locate_CarriesTheFormValueReadback`：**桥接路径**（活路径）把驱动回读带到能力结果里。
- `LocateAndInteractScripts_ReportFormValueAndSelectedValues`：钉脚本文本。

## 覆盖边界（诚实登记）

- **JS 行为没有自动化验收**：`WebView2DomClient` 的脚本要真实 WebView2 才能执行，
  而唯一的真实执行入口 `Tests/PuddingBrowser.WebView2.Smoke` 是**显示窗口的 WPF 应用**
  （`window.Show()`），本轮未运行。因此「`readValue` 在真实页面上真的读到了值」目前只有
  **脚本文本断言**（防「有人把回读删掉」），不构成运行时验收。
- **敏感值脱敏尚未接**：`value` 目前是原样字符串。设计要求的「密码类只留长度与 matched」
  由交互回执的 `BrowserActionAssertion` 负责，属下一段（回执进输出面）。
- **`browser_interact` 的回执尚未携带断言**：本轮只打通了数据链路，
  「一次 fill 就能确认」的验收（G3/G7）还需要在交互回执里落 `assertions`。

## 既有 flake 说明（与本次改动无关，已实测）

`PuddingHost.Tests.BrowserBridge.DesktopBrowserBridgeHandshakeTests.SecondConnection_CannotReplaceAwaitingHelloConnection`
是**既有的时序型 flake**：

- 只跑该测试类（4 条）时，**带本次改动** 5 次里失败 3 次，**在 HEAD（临时 stash 掉本次全部改动后）**
  4 次里失败 1 次 —— 两边都能复现；
- 失败时 `dotnet test` 耗时约 2 s、通过时约 0.3 s，说明是与等待窗口相关的竞态；
- 该测试与本次改动的文件/路径无交集（连接握手 vs. 定位映射）。

本次为做上述对照临时 `git stash push` 了**仅本人改动的 11 个路径**，随后 `git stash pop` 还原：
工作树文件数与 diffstat 与 stash 前完全一致（`10 files changed, 170 insertions(+), 13 deletions(-)`），
他方 WIP（benchmark-seeds、HeartbeatPrompt）未被触碰，无遗留 stash。

## 影响与回滚

- 线上行为**不变**：`browser_locate` 默认输出与之前逐字节同形（`value` 为 null，不会新增内容），
  只有显式传 `include_value=true` 才会多出字段。
- 无数据/配置影响。回滚：还原上表 6 个文件与 3 个测试文件的改动。
