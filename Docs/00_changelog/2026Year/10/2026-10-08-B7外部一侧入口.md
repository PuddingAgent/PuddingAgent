# 2026-10-08 B7 外部一侧入口：观察事实读取 + CLI --conclude

## 目标 / 背景

上一轮做出了外部验收的**判定**（清单 + 观察事实 → 结论），但没有入口：外部控制器拿不到"怎么把这个结论算出来"。
本轮补上引擎与命令行入口。

## 改动

| 文件 | 改动 |
|---|---|
| `ExternalAcceptanceFacts.cs`（新增） | 读取外部一方交回的 JSON（`observedBuildId` / `smoke[]` / `lifecycle[]`），**逐字段 fail closed**：结果写法不认识（`ok`/`pass`/`done`…）、字段缺失、`passed` 不是布尔一律拒绝；**绝不如默认值般把"没写"当成"通过"** |
| `DeliveryManifestValidator.TryDeserialize`（新增） | 外部侧读回内部交付的清单：缺 `buildId`/`commit`/`checks` 一律失败，**不补默认值**（读不全的清单不能用来判断交付了什么） |
| CLI `--conclude <facts.json> --manifest <manifest.json> [--record <file>]` | 清单 + 事实 → 结论：**0 = 允许** `external-lifecycle-verified`，**2 = 拒绝**并把原因逐条打到 stderr；可写验收记录（含校验问题） |

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **302 / 302**（＋5：完整事实被解析并**可下结论**、未知结果写法被拒、字段缺失被点名、非法/空文档被拒、异构建事实仍被判定层拒绝） |
| CLI **拒绝路径（端到端真实执行）** | 用真实清单 + 只有 1 条观察的"事实" ⇒ 退出码 **2**，逐条打印：`lifecycle step 'restart' has no external evidence` … `smoke check 'S-02' (G2) was not observed` … |
| CLI 允许路径 | 由单测覆盖（完整事实 → `TryConclude` 通过）；**未**用命令行演示（详见下方边界） |
| 构建 | `DesktopService` · `DeliveryManifest.Cli` 已成功生成 |

## 已知边界（诚实登记）

- **没有真机事实**：本项目当前仍只有 `ready-for-external-deploy`。CLI 能算结论，但**没有真机观察事实可喂**——
  这不是本轮的缺口，而是"外部控制器尚未实际去跑"的事实。
- **允许路径未在命令行演示**：我尝试手工拼出 11 条观察的 JSON 时，用 PowerShell 生成的开场就写坏了
  （`\n` 被当成字面量 ⇒ 文件不是合法 JSON ⇒ CLI 按设计**拒绝**，退出码 2）。我没有继续花时间打磨这个
  一次性脚本，而是依赖单测覆盖该路径 —— 记录在此以免留下"没验证却声称通过"的印象。
- **交互式采集脚本未做**：`TestScripts/` 里按清单逐项提示观察、收集证据、调用 `--conclude` 的脚本是下一步
  （它才是外部控制器的实际入口）。
- **证据仍是文本**：无法机器校验真实性。
- **调用方身份未校验**：`--conclude` 假定运行者是外部一方（B1 未决问题）。

## 影响与回滚

- **新增命令行模式**，不影响既有内部一侧模式（`--build/--publish/...`）。
- 回滚：删除 `ExternalAcceptanceFacts.cs`、`TryDeserialize`、CLI 的 `Conclude` 分支与用例。
