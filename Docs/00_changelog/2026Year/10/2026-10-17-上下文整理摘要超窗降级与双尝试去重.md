# 2026-10-17 上下文整理摘要超窗降级与同轮双尝试去重

> 诊断见 [报告](../../../14_reports/2026-10-17-上下文整理失败诊断与修复-warm前缀摘要超窗.md)；决策依据 [ADR-095](../../../07_architecture/109ADR-095会话上下文维护与首增量延迟治理ADR.md)。

## 1. 问题（2026-10-17 05:34 事故）

warm-prefix 压缩的摘要请求 = **整段未裁剪 outbound 历史 + 1 条固定指令**（`WarmPrefixCompaction.TryCreatePlan`），不经过任何出站输入预算。事故时该会话内存历史估算 2,840,821 tokens（provider 实测 1,683,727 messages + 8,192 completion、请求体 8,063,740 B），超过 deepseek-flash 1,048,576 窗口 ⇒ provider 400 ⇒ UI 两张「上下文整理失败」卡片；失败只裁剪本次出站副本（removed=1,838），完整历史保留，下一轮必然重犯。同一 round 由「软维护准入」与「硬保护准入」各发一次**字节级相同**的摘要请求，prepare 多花约 12s 重复计量。

历史积累链（只读诊断，详见报告）：10-13 有 86 次摘要成功但持久提交失败（`durable_commit_coveredmessagesnotfound`，historyPreserved=true）→ beforeTokens 607K→1.48M；10-14 05:23 起越过 provider 窗口，52 次 context-length 失败、beforeTokens 单调涨到 2.84M；10-13 之后 0 次完成。进程重启后冷启动重水合（`MaxHydrationTokenBudget=49152`）只保留 66 条，症状暂时消失。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `Source/PuddingRuntime/Services/AgentExecutionService.cs` | 新增可选依赖 `ExtractiveContextCompactionSummaryGenerator?`（生产 DI 已注册）；**仅确定性失败**（provider 输入长度拒绝 / provider 成功但输出为空或工具调用）时用本地抽取式摘要兜底（新增 `TryGenerateExtractiveFallbackSummaryAsync`，只概括 `WarmPrefixCompaction.SelectRemovedMessages` 的被替换跨度；异常不外抛），随后仍走同一 `VerifyApplication` + 持久提交；auth/限流/5xx/超时保持 fail-closed。completed 事件新增 `summarySource`/`degraded`，rejected 事件新增 `summarySource`/`summaryFallbackError`。**不**调用 `RecordProviderInputLimitFailure`（摘要 raw 不得校准主请求，ADR-095 D6）。 |
| `Source/PuddingRuntime/Services/WarmPrefixCompaction.cs` | 新增 `SelectRemovedMessages`（与 `TryCreatePlan`/`VerifyApplication` 的 removed/retained 切分同源）与 `SummaryLocalFallback` 原因码。 |
| `Source/PuddingRuntime/Services/WarmPrefixMaintenanceAdmission.cs` | 新增纯函数 `RecordAttempt`：软维护调用若 `RequiresSynchronousProtection=true`（已执行同步硬保护），同时置 `hardProtectionAttempted`，同 round 不得重复。 |
| `Source/PuddingRuntime/Services/AgentExecution/AgentExecutionService.Streaming.cs`、`…Buffered.cs` | 两处调用改用 `RecordAttempt` 记录软/硬封顶（流式与缓冲路径同构）。 |
| `Source/PuddingRuntime/Services/LlmRequestBudgetGuard.cs` | `TryGetProviderMaxInputTokens` 增加 DeepSeek `maximum context length is N tokens` 文案解析；数字支持 `,` 与 `_` 分隔。 |
| 测试（3 文件） | 新增 E2E：① `ProviderRejectsOversizedSummary_UsesLocalExtractiveFallback_AndPersists`（provider 超窗拒绝 → 同 round 仅 1 次摘要尝试 → 本地兜底 → 落库 + 内存 checkpoint + 无 failed 路径）；② `OverLimitAtRoundZero_ProviderInputLimitRejected_WithoutFallback_AttemptsOnceAndPreservesHistory`（第 0 轮已越界 + 超窗拒绝 + 兜底关闭 ⇒ 1 次尝试、历史原样、不落库）；③ `StreamingPath_OverLimitAtRoundZero_ProviderAuthFailure_AttemptsOnceAndDoesNotFallback`（流式路径 + 401 ⇒ 不兜底、1 次尝试）。另新增 `RecordAttempt_*` 去重单测与 provider 文案解析 DataRow。 |
