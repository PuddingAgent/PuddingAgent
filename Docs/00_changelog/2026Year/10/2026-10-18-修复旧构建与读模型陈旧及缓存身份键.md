# 2026-10-18 修复旧构建与读模型陈旧及缓存身份键

## 根因证据

- 运行实例前端 `6.4.7+dirty`，`/conversation-open` 返回 404；真实库事件 3.12M 下默认助手首屏 4.77s/执行中 7.16–9.62s。
- 读模型陈旧：`conversation_read_state` 的 `current_turn_id=7979...` 在 **11:00** 写入且 terminal=0；该 Turn 的 `turn.completed` 事件在 **13:04**（sequence 1,821,473）。旧 Core 只把 `conversation_projection_checkpoints` 推进到 head 1,825,473（19:04），没有写 read_state/turn summaries；新 Worker 以 `head > checkpoint` 发现工作，因此永远补不到这段尾部。
- 缓存：`selectAgent` 用固定 `DEFAULT_AGENT_CHAT_OWNER_ID` 读缓存，而请求/保存使用实际 owner（admin 或旧投影 owner），键不一致导致永不命中；且 `isOpening=false` 在 `await cache.saveConversation()` 之后才设置，IndexedDB 慢时界面持续加载。

## 改动

- 前端 `chatClientStore.ts`：
  - 删除 `refreshStatuses`/`syncStatuses`/`selectAgent` 内对 owner 的覆盖，缓存读/写统一使用 Store 配置的 `ownerUserId`；
  - 权威快照到达后**先** `set(conversation, isOpening=false, isRefreshing=false)`，再执行 IndexedDB 保存；
  - 新增两条定向测试（读/写同 owner、保存未完成时已解除 loading）；前端 `6.9.4 → 6.9.5`。
- 后端：
  - `ConversationReadModelProjectionStore.ResolveResumeSequenceAsync`：checkpoint 比 read_state 新超过 1 分钟时，以该会话 Turn 摘要最大 `last_sequence` 为恢复点并记录 warning；
  - `ConversationProjector` 用恢复点读取批次，补放尾部事件并同事务更新 read_state/summary/checkpoint；
  - `ConversationProjectionWorker.FindPendingConversationsAsync` 增加陈旧读模型发现（head == checkpoint 时也能调度修复）。
- code_map（Platform/Admin）同步更新语义。

## 编译与部署产物（本机）

- 前端：`pnpm run build` 成功（bundle budget ok），版本 **6.9.5**。
- Core：`dotnet build Source/PuddingAgent/PuddingAgent.csproj` 成功，输出 `Source/PuddingAgent/bin/Debug/net10.0`，`wwwroot/admin` 为 6.9.5。
- Desktop：`dotnet build Source/PuddingDesktop/PuddingDesktop.csproj --artifacts-path temp/build/winui3` 成功；启动器 `temp/build/winui3/bin/PuddingDesktop/debug_win-x64/PuddingDesktop.exe`，其 `core/` 已更新为 19:20 构建、前端 6.9.5。Desktop shell 代码未变，exe 时间戳仍 19:11，但 Core bundle 已替换。
- `desktop.json` 的 `coreExecutablePath` 指向的 `Source/PuddingAgent/bin/Debug/net10.0/PuddingAgent.exe` 已更新；需停止旧 Desktop/Core 后重新启动才会加载新构建。

## 验证

- 后端定向测试：`ConversationProjectorReadModelTests|ConversationReadModelProjectionStoreTests` **15/15 通过**（含新增陈旧 checkpoint 补放尾部用例）。
- 前端 `chatClientStore.test.ts`：**21/21 通过**；`pnpm run tsc` 仍只有基线既有错误。
- 真实库自愈（新 Core 启动）：
  - 修复前 `running_turns=1`、read_state terminal=0、checkpoint=1,825,473；
  - 修复后 `read_state.current_turn_id=5a0f6cef...`、terminal=**1**、checkpoint=head=1,825,473、`running_turns=0`（10 次 `/conversation-open` 均无运行中 Turn，p95 **11.7ms**）。
- 真实浏览器冒烟（部署 bundle 6.9.5，2 样本）：badge `v6.9.5+dirty`；旧 `/conversation` 0 请求；首屏 `/content` 1 次；首内容可读 **862 / 1067ms**；点展开 1 次请求；无 5xx。
