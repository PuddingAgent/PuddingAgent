# 2026-10-02 切片 D 迁移前实读：能力面 ⊊ 工具面（先加宽契约，否则会功能倒退）

## 目标 / 背景

上一轮把 Bridge 侧 9 个映射补齐，窄端口两实现齐备，按计划下一步就是"改七个工具的调用点"。
本轮动手前先实读七个工具的参数记录（`*Args`）与能力契约逐一对照——结果发现一个会让迁移变成
**功能倒退**的问题，因此本轮**没有改任何工具代码**，而是把结论与修正后的顺序固化下来。

## 发现：七个工具里只有 `locate` 是完整可迁移的

| 工具 | 工具面 | 能力契约缺口 |
|---|---|---|
| `browser_context` | `create`/`list`/`get`/`close` | **创建/关闭上下文无对应能力**（get 可由清单过滤） |
| `browser_navigate` | `goto`/`back`/`forward`/`reload`/`stop` + `TimeoutMs` | **四个动作 + 超时** |
| `browser_tabs` | `new`/`list`/`activate`/`close` + `Url` + `Activate` | **新建标签页**（含初始 URL 与是否激活） |
| `browser_interact` | `click`/`fill`/**`type`**/`press`/`hover`/`scroll`/`select`/`check` + **`DeltaX`** | **`type`**（与 `fill` 语义不同）、**`DeltaX`** |
| `browser_snapshot` | 上述 + `IncludeHidden`/`IncludeIframes`/`IncludeShadowDom`/`MaxDepth` | **四个参数** |
| `browser_locate` | `Locator` | ✓ 无 |
| `browser_wait_for` | 三条件 + `TimeoutMs` | **超时** |

⇒ 若照原计划直接改调用点，结果是 **5/7 个工具的能力被削掉**（context 的 create/close、
navigate 的四个动作、新建标签页、`type`、快照四个参数、三处超时、`DeltaX`），
而**编译期与单元测试都看不出来**——只有 Agent 真用到那些动作时才暴露。
