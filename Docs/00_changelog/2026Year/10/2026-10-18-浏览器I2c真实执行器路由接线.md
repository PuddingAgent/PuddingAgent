# 2026-10-18 I2-c 真实执行器路由（发现类命令）与 Shell 接线

## 改动

- 新增 `BrowserBridgeExecutorRoute`（WpfArchive）：
  - 只路由**已有可靠反投影**的命令：`context.list`、`context.getInfo`、`page.list`、`page.getInfo`；其余返回 null（回退 controller，迁移期）；
  - 构造 `DesktopCallContext`：`SessionPermitMarker`（宿主内部，不上线缆）+ 从 `command.Caller` 映射的可信 `BrowserCallerIdentity`（user/agent/sub_agent 严格解析，未知拒绝）；
  - 经 `BrowserCapabilityInvoker` 委托调用执行器（避免 WpfArchive 依赖 DesktopConnection）；
  - 结果用 `BrowserBridgeResultAdapter` 反投影并序列化；能力错误映射为稳定 Bridge 码（Unauthorized/Paused/UserTakeover/InvalidRequest/InvalidTarget/PageVersionMismatch/NotConnected/UiUnavailable/UnsupportedCapability → 对应稳定码，其余 `browser_operation_failed`）；
  - 执行器异常 → 失败结果（不静默回退）。
- 派发器：新增 `ClearExecutorRoute()`；Shell 组合根在浏览器工作区执行器就绪时 `SetExecutorRoute(...)`，退出释放时先清路由再关执行器。
- 测试 4 条（Desktop）：路由携带 marker+caller 并返回反投影 JSON；未覆盖命令返回 null；执行器失败映射 Unauthorized；缺 caller 在触碰执行器前拒绝。连同上一片的 3 条派发器语义测试共 **7/7 通过**。

## 验证

- `Tests/PuddingDesktop.Tests` ⇒ **377/377 通过**；
- `dotnet build Source/PuddingDesktop/PuddingDesktop.csproj --no-restore` ⇒ exit 0（Shell 编译含新接线）；
- 未运行产品/真实模型；生产路径首次真正可能出现"发现类命令走执行器"——仍需真机/组合根集成验证（I3/I4）。

## 未完成与影响

- 路由覆盖仍只有 4 类命令；navigate/interact/snapshot 等需补齐结果反投影后逐项放开；
- controller 仍执行其余命令（迁移期双路径），**尚未删除旧路径**；
- 路由错误码映射是近似（能力码→Bridge 码），需要错误码对表测试；
- 真机集成：`SessionPermitMarker` 跳过旧授权后，页面存在/信任/自动化/版本检查是否足以覆盖所有发现场景，需要组合根/真机验证；
- 回滚 = revert 本提交（新增路由+接线+测试；若只想回退生产行为，清除 SetExecutorRoute 即可）。
