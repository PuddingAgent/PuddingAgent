# 2026-10-02 原子文件替换事务接缝（D 第四阶段）

## 改动

- `Source/PuddingCodeIndex/Contracts/CodeSourceManifestContracts.cs` 追加：
  `CodeSourceFileReplacement`（文件记录 + 符号 + 引用 + 关系 + 该消费者的源指纹/已应用版本）、
  `CodeSourceFileReplacementResult`（替换文件数、**需重新绑定的依赖方**、消失的符号 id），
  并把 `ReplaceFilesAsync` 加到可选能力端口 `ICodeSourceMaintenanceStore`（仍不加进 `ICodeIndexStore`：
  给共享端口加成员会破坏每一个实现者，含组件外替身）。
- 新增 `Source/PuddingCodeIndex/Storage/SqliteCodeIndexStore.FileReplacement.cs`（部分类）：
  一个批次**一个事务**，语义按 D4 的所有权/依赖规则：
  1. 找出该文件**消失的符号**；先读取「其他文件指向这些符号的入边」的来源路径（依赖方），
     再删除这些入边 —— 指向**仍然存在**符号的入边**必须保留**（它们属于别的文件）。
  2. 删除该文件**拥有**的行（所有权 = `SourceFilePath` 属于该文件，或来源符号属于该文件的旧符号集）后重建。
  3. 整体替换该文件的符号行，写入文件记录/符号/引用/关系，并在**同一事务**里更新 manifest 行
     （指纹 + `Complete`）与该文件的各消费者已应用版本。
  4. 任何一步失败 ⇒ 整个批次回滚，旧索引结果与旧指纹保持完整（**不提前 clear**）。
  - 依赖方报告会剔除本批次内正在重建的文件（它们不算「失效」）。
  - `IN (…)` 列表用分块（`SymbolIdChunkSize = 128`）并把 id 列表作为 **JSON 数组参数**交给
    `json_each` 展开，既不拼 SQL 也不撞 SQLite 参数上限。
  - 校验前置（打开事务之前）：文件记录与 `Source` 路径必须一致、scope 必须一致、同一批次不得重复替换同一路径。
- 新增 `Source/PuddingCodeIndexTests/Storage/SqliteCodeIndexStoreReplaceFilesTests.cs`（10 条）。

## 验证

- `dotnet test Source\PuddingCodeIndexTests\PuddingCodeIndexTests.csproj` → **246 通过 0 失败**（本次 +10）。
- 关键用例：
  - 索引结果与源指纹/manifest 行**同批写入**；
  - 同文件再次替换是**全量重建**（旧引用/关系不叠加：指向 `sym-target` 的引用只剩新符号那一条）；
  - **指向仍存在符号的入边保留**（替换 A 后，B 指向 A 稳定符号的引用与关系仍在）；
  - **目标符号消失**时：入边被删除且来源文件被报告为需重新绑定（B、C 都被报告），
    依赖方自己的符号不受影响、其指向消失目标的行清除（等待重新绑定重建）；
  - 同批重建的文件**不**出现在失效依赖列表里；
  - 没有符号的文件仍保留文件记录并清掉旧符号；
  - **批次中途失败 ⇒ 旧完整产物原样保留**（旧符号在、新符号不在、指纹未半更新）；
  - 路径/scope 不一致与同批重复替换直接抛错（校验在事务之前）；
  - 400 个旧符号的条件下分块删除覆盖全部（验证 `json_each` 与分块）。
- 组件边界不变：实现只引用本组件契约与 `Microsoft.Data.Sqlite`；`ProjectReference` 仍为空，
  `ComponentBoundaryTests` 保持通过。

## 未完成与影响

- **仍未接入维护链路**：`ReplaceFilesAsync` 没有调用方（`RoslynCSharpIndexer` 等语言索引器仍走
  `ClearSymbolsForFileAsync` + 分次 upsert），因此运行中实例仍是零行为变化。
  接入属于后续阶段（语言侧批量/复用 workspace + 依赖计划），本切片只提供正确的存储接缝。
- **语言侧仍未批量**：同批多个文件共用一个有界 Roslyn workspace/编译快照、以及
  「签名变化 ⇒ 依赖方失效」的规划都还没实现；本切片负责在存储层如实执行该计划。
- 关系/引用的「所有权」判据是 `SourceFilePath` 与来源符号，未引入额外的 owner 列；
  这是既有 schema 下的行为等价选择，若将来需要更强的所有权证据，另做独立任务。
- 后续阶段：语言批量/依赖影响计划 → 既有维护链路接入。
