# 2026-10-03 · 高磁盘读取复测现场归因（旧构建，未验证修复）

## 背景 / 动机

用户在「发送一句话之后」提供了一份进程-文件磁盘监控快照。需要先判断这份快照能不能用来验收
`Docs/14_reports/2026-10-02-PuddingAgent高磁盘读取诊断.md` 的 A/B2/C/D 四项修复，再决定是否据此改代码。
**本次只做归因与取数，未改任何产品代码。**

## 结论

1. **快照跑的是旧构建，不能验收修复**：PID 34672 启动于 2026-10-02 18:08:17，但加载的
   `PuddingPlatform.dll` / `PuddingHost.dll` / `PuddingAgent.exe` 落盘时间是 2026-10-01 11:06～11:14；
   A/B/C 提交于 10-02 12:31、D 于 10-02 13:40～13:46。**四项修复都不在该进程内**。
2. **快照里绝大多数行不是应用的**：`System`(PID 4)、`dotnet.exe`、`VBCSCompiler.exe`、`XamlCompiler.exe`
   读写的 `temp\build\desktop-launcher-core\**`、`temp\build\winui3\**`、`PuddingPlatformAdmin\dist\**`、
   `bin\**\wwwroot\admin\**` 是并发构建/前端部署流量。
3. `PuddingAgent.exe` 自身在这段窗口：`pudding_platform.db` 读 577.45 kB/s（窗口累计 26.5 MB）、
   `code_index.db` 读 36 kB / 写 892 kB、`pudding_memory.db-wal` 写 416 kB、`$LogFile` 写 4.74 MB；
   **没有读取任何工作区源文件**。单次短窗口，不能当成"源文件读取已消除"的证据。
4. **新取证（客户端行为）**：2026-10-03 的全部日志中 `[SessionEvents] SSE subscribed` 出现 **0 次**，
   而同一进程在 10-01/10-02 反复记录 `cursor=0 phase=replay-from-zero head=1644341…`；
   当天部署的前端产物是 `umi.beea2d5c.js`（2026-10-03 03:55:40 / `package.json` 6.2.2）。
   即零游标全量回放当天未再发生，**服务端 A/B2 未部署，只能是客户端侧行为变化**。
