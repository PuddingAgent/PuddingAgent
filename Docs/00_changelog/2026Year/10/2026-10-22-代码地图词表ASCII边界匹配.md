# 代码地图 §6 词表：ASCII 标识符边界匹配

**日期**：2026-10-22 · **范围**：`Tools/Docs/code_map_check.py` + 自测 + 规范实现说明

## 问题

`code_map_check.py` 的反模式词表扫描对整行做 `w.lower() in low` 的子串匹配，于是**符号名里出现的字母组合**被判成自然语言断言：

| 位置 | 原文片段 | 误判类别 |
|---|---|---|
| `Source/PuddingCore/code_map.md:14` | `查询含 steps 与 GetTodoAsync 拆解投影` | 演进叙事（`word=TODO`） |
| `Source/PuddingPlatform/code_map.md:183` | `只读投影（active/iterations/steps/todo）` | 演进叙事（`word=TODO`） |

`GetTodoAsync` 是方法名、`steps/todo` 是读模型字段名，两者都不是"此处有未完成工作"的断言。这与 `prose_only()` 剔除行内代码跨度是同一类问题：**符号面（symbol surface）被当成叙述面（prose surface）**。

## 改动

1. `Tools/Docs/code_map_check.py`
   - 新增 `word_occurs(word, prose)`（带 `_ASCII_WORD_RE_CACHE`），替换 `analyze_file()` 里的两处裸子串判定（词表 + 逐文件免检旁路）。
   - ASCII 词（`word.isascii()` 且去掉 `_` 后全为字母数字）按 `(?<![A-Za-z0-9_])word(?![A-Za-z0-9_])` 匹配，且**区分大小写**：规范词表列的字面 token 是 `TODO`，而读模型字段名写作小写 `todo`。
   - 中文词保持原子串口径（规范 §6 的字面语义未动）。
   - `boundary_notes()` 追加一条口径说明，声明这是**工具的解释性细化**，并点明中文词领域用法仍会命中、属未裁定事项。
2. `Tools/Docs/code_map_check_selftest.py`
   - 新增 `stage_anti_pattern_identifier_boundary`（3 条断言）：裸标识符 `GetTodoAsync` 不命中、小写字段名 `steps/todo` 不命中、裸 `TODO` **必须仍命中**（反过度抑制对照组）。
3. `Docs/10_conventions/code-map-规范-v2.md`
   - §6 表后加一段「检查器口径（实现说明，不改本节词表语义）」，把剔除行内代码/链接目标、ASCII 边界 + 大小写、中文子串三条口径写在规范里，减少规范与实现的漂移。
4. `code_map.md`
   - §5 源指纹 `Tools/**=7ab6ae6b984b` → `Tools/**=a3440d85a143`（27 个文件，checker + selftest 字节已变）。
