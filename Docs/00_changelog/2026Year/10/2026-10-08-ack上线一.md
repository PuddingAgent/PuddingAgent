# 2026-10-08 ack 上线（第一步：契约与守卫）

## 交付

| 件 | 内容 |
|---|---|
| proto | `oneof outcome` ＋`BindingAckOutcome binding_ack = 27;`；新消息 `BindingAckOutcome { bool accepted=1; string grant_id=2; uint64 epoch=3; string reason=4; }` |
| 守卫 ① | `PayloadOneof_IsClosedWhitelist`：`OperationResult` outcome 计数 **17 → 18** |
| 守卫 ② | `CommandAndResultFieldNumbers_AreFrozen`：`OperationResult` 元组 ＋`("binding_ack", 27)` |
| 守卫 ③ | 同用例 `OutcomeOneofCase` 名单 ＋`"BindingAck"` |

| 套件 | 结果 |
|---|---|
| `Pudding.Rpc.ProtocolTests` | 见运行输出（应 20/20） |
| `Pudding.CapabilityBrokerTests` | 见运行输出（应 96/96） |
| `Pudding.DesktopConnectionTests` | 见运行输出（应 87/87） |

## 诚实边界（**ack 目前仍不能真正回传**）

- **两侧编解码未做**：契约有了，但 `CapabilityBroker/WireMapping.cs` 的 `DesktopResultDecoder`（现有 `switch (result.OutcomeCase)` 与能力匹配 switch）**还没有 `BindingAck` 分支** ⇒ 目前 ack 仍无法被 Core 解析；**Desktop 侧的结果编码器也未定位/未改**。
- 因此本步**只是**让"线缆能表达 ack"，**不等于**闭环闭合；在两侧编解码完成前，不得据此开闸门。
- **未跑全量链**；**未真机验证**。
