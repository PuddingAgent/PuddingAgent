# 代码地图规范 v2 的机器判定边界诚实标注

**日期**：2026-10-23 · **范围**：`Docs/10_conventions/code-map-规范-v2.md`（+ 覆盖核对报告的状态回写）；`Tools/Docs/*` **未改**（`code_map_check.py` sha256 仍为 `bd06254d…`）

## 问题：规范有几处“看起来机器管了、其实没管”

覆盖核对报告把 33 条条款分成 A（机器可判 + 已实现 + 有取红断言）24 条、B（缺取红断言）0 条、C（不可机器判定或规则缺失）9 条。其中三处不属于“做不到”，而是**规范本身没把边界写在读者眼前**：

| 位置 | 规范原文的读感 | 实测事实 |
|---|---|---|
| §5 触发整理 | 三条触发条件并列，像都由 `--check` 判 | ②「语义变更数 ≥ 30」在 §7 规则表里**没有 ID**，检查器也无该统计能力 |
| §2 条目 schema | 「文件 / 目录」「用途」标为**必填** | 检查器**不校验列是否存在**；表头缺 `用途` 不报错，只是 F/S 相关判据**全部静默失效** |
| §3 分层职责 | 「禁跨项目调用链」列为判定规则 | 文本层面无法判定“是否跨项目”，只能靠人 |

后果不是门禁变红，而是**读者会误以为已经守住了**。这比反模式误报更危险：误报会被抱怨，假承诺会被信任。

## 改动：四段标注，全部追加，0 删除

`git diff --numstat` = **6 / 0**（6 行新增、0 行删除）。

- **§2 schema 表后**：`> ⚠️ 必填列的「存在性」不由机器校验（实测标注 2026-10-23）` —— 说明缺 `用途` 时是静默少检、`--check` 不承担该项、维护者须自查表头列序，并链到核对报告 #9/#10。
- **§5 触发整理下**（list 内嵌引用）：`机器判定边界：① 与 ③ 由检查器判定；② 不由机器判定` —— 点明缺规则 ID 与统计能力，该条是人的判据。
- **§6 检查器口径之后**：分清两件事 —— 「逐文件免检旁路」的**词级启发式确实机器判**（`SKIP_BYPASS_WORDS` 三词、命中即 `anti-pattern` warn、自测逐词取红，见上一份 changelog），而「**是否真的加了旁路**」机器不判。原句“不由机器判定”指的是后者，不再有歧义。
- **§9 未纳入（诚实标注）**：新增一条汇总，把 §5②、§2 必填列、§3 跨项目三处“不由机器判定”登记在案，并指向覆盖核对报告的分级结论。

配套把核对报告 §四 ② 与「观察项 #9/#10」回写为**已落地**（注明词表与阈值语义未改、diff 6 行全为新增）。

**刻意没做的事**（仍等规范 owner hyfree 裁定，均属改判定边界）：

1. 清单型 F 阈值 §2「3 个以上」vs §6「≥3」（`LIST_MIN_ITEMS` 3→4 会翻掉 19 条命中，其中 14 条恰好 3 项）；
2. §6 中文词表改意图匹配（47 条里 32 条误报，但改了就偏离“机器可执行词表”的定位）；
3. `PLACEHOLDER_ALLOWED` 与 `PLACEHOLDER_RE` 无交集 ⇒ guard 恒真（删键或放宽正则都会改空值写法判定）。

## 一个坑：把“行首前缀”当插入锚点

§9 的末行原本是：

```
- 上限数值（300/80/100/160/400/8）是**首版工程取值**，尚未据本仓真实分布校准 —— 见 §8 第 3 条，属**待校准**项，不是"最优值"。
```

脚本拿 `- 上限数值（300/80/100/160/400/8）是**首版工程取值**` 当锚点做 `replace(锚点, 锚点 + 新段)`，而它只是**该行的前缀** ⇒ 新段落被插进了句子中间（`…待校准项…。，尚未据本仓真实分布校准…`）。坏行看起来“语法上还挺顺”，`file_read` 粗看也不刺眼。

抓到它的是 **`git diff -U0 | grep '^-'`**：纯追加的改动不应有任何删除行，却出现了 1 条删除。定位后按**整行重建**修好（重新拼出原始整行 + 新行），复核 `--numstat` = 6/0 且删除行为 0。

沉淀两条纪律：

1. **插入类改动以「整行相等」为锚** —— `lines[i] == 锚点` 断言，而不是 `锚点 in 文本`；前缀命中会静默插到行中间。
2. **纯追加的验收标准是“0 删除行”** —— `git diff -U0 -- <file> | Select-String '^-[^-]'` 必须为空。`--stat` 的 `insertions(+)/deletions(-)` 只是计数，`-U0` 的逐行证据才是证明。

## 后续

- 台账型剩余 C 级 9 条中，两条**可以机器化但需新规则 ID**（§2 必填列存在性、§2 相对链接形态）—— 属规范变更，等 owner 裁定；其余（跨项目调用链、§5②、§7 禁调参变绿、§8.2/§8.3、§9）是过程或不可判定项，保持人工评审。
- A 级 24 条的证据链仍以「变异取红」为准；新断言一律先做变异探测，避免出现“有断言、恒为真”的假绿（本周期已抓到一次）。
