# 加宽第 9 项完成：快照四个旋钮贯通线缆与两侧；并新发现缺口 #12（页状态缺标题）

## 目标 / 背景

`browser_snapshot` 只差最后一块：它把 `IncludeHidden`/`IncludeIframes`/`IncludeShadowDom`/`MaxDepth`
四个旋钮暴露给 Agent，而契约与线缆都没有它们。本轮按既定流程（先实读定性 → 跨侧同提交 → 补快照）

## 改动（跨侧协议变更，两侧同提交）

| 层 | 文件 | 改动 |
|---|---|---|
| 线缆 | `desktop_capability.proto` | `SnapshotBudget` 新增 `include_hidden = 6` / `include_iframes = 7` / `include_shadow_dom = 8` / `max_depth = 9` |
| 契约 | `Desktop/SnapshotContracts.cs` | `DesktopSnapshotOptions` 新增四个参数与属性（默认值与运行时/工具默认一致：false/true/true/24） |
| Core→proto | `CapabilityBroker/WireMapping.cs` | 四个字段写入 `SnapshotBudget` |
| proto→DTO | `DesktopConnection/Mapping.cs` | 四个字段读出；`max_depth == 0` 视作未设 ⇒ 用 24（与既有 `max_nodes`/`max_text_length` 的 0⇒默认 一致） |
| Desktop 侧 | `DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs` | 四个字段进运行时 `SnapshotOptions` |
| Bridge 侧 | `Host/BrowserBridge/BridgeBrowserCapabilitySurface.cs` | 同上 |
| 线缆快照 | `Rpc.ProtocolTests/WireContractSnapshotTests.cs` | 断言四个新字段号 |

## 新发现的缺口 #12：`DesktopPageState` 没有标题

迁移 `browser_wait_for` 时发现：`browser_navigate` / `browser_wait_for` / `browser_interact` /
`browser_tabs` 四个工具的结果里 `BrowserTabToolValue.Title` 是**必填**，而契约的
`DesktopPageState` 只有 `Target`/`Url`/`Version`/`Readiness`——**没有标题**。
⇒ 迁移这四个工具前必须先补（proto `PageStateOutcome.title` + 契约 + 两侧映射 + 两侧实现），
否则等于悄悄削掉标题（正是本系列一直在防的功能倒退）。已登记为 §8.5.1 第 12 项。

> 也就是说：`browser_locate` 之后，**下一个能迁移的工具是 `browser_snapshot`**
> （其结果 `BrowserSnapshotToolValue` 与 `DesktopSnapshot` 逐字段对应，四个旋钮本轮补齐），
> 而四个「页状态类」工具都卡在 #12。

## 留白（本轮发现，未处理）

  已在日志登记，待与 #12 一并处理。
