# 2026-10-18 I2-c 适配器第六片：page.waitFor → browser.wait_for

## 改动

- `BrowserBridgeCommandAdapter` 扩展 `page.waitFor` → `browser.wait_for`；
- 映射规则：`selector / selectorToHide / urlPattern` 三者中**恰好一个**非空 → 对应 `DesktopWaitConditionKind`（Selector/SelectorHidden/UrlPattern），`timeoutMs` 原样搬运；
- **多条件/无条件显式拒绝**并给出原因：旧 runtime 可同时承载多个条件，而当前能力契约只有一个——不静默挑优先级（会改变语义），待契约扩展再放开；
- 非法 JSON / 非法条件值 fail-closed。

## 验证

- `dotnet test Tests/PuddingDesktop.Tests --filter BrowserBridgeCommandAdapterTests` ⇒ **10/10 通过**；
- 未运行产品/模型；适配器仍未接管执行。

## 未完成与影响

- "多条件等待"是**已知能力缺口**（旧路径支持、能力契约单条件）；接入执行器时要么扩展 `BrowserWaitForRequest`，要么在工具层限制并如实报错。
- 仍缺 interact/tabs/截图映射；派发器入口切换、controller 收缩、删除旧路径未做。
- 回滚 = revert 本提交。
