# 2026-10-21 诊断「LLM 调用失败: Error while copying content to a stream」并重编重启 Core+Desktop

> 用户先报「LLM 调用失败: Error while copying content to a stream，诊断」，随后要求「编译 Core 和 Desktop，重启 Core 和 Desktop」。

## 1. 诊断：失败发生在**请求体上传阶段**，不是 token/模型问题

| 证据 | 内容 |
|---|---|
| 异常链 | `System.Net.Http.HttpRequestException: Error while copying content to a stream.`<br>→ `System.IO.IOException: Unable to write data to the transport connection`<br>→ `SocketException 10053`（本机软件中止已建立的连接）或 `10054`（远程主机强迫关闭现有连接） |
| 失败栈位置 | `HttpContent.CopyToAsync` → `SslStream.WriteAsync` —— **写请求体**；响应尚未开始 |
| 结构化日志 | `[DirectLlm] STREAM ERROR ... cause=transport.request_upload_reset phase=request_upload`；另有 `STREAM RETRY before first delta attempt=1/2` |
| 体积证据 | 失败请求上传体积约 **1,451,650 bytes**（errorId `llm-6eb95759…`）；长会话 `msgCount` 达数百级；既有合成实验：128 KiB / 512 KiB 上传成功，~1.45 MB 在约 29s 上传中途断开（与本机 TUN 开关无关，已由前序验证） |
| 时间分布 | `transport.request_upload_reset`：10-20 21:00 ×1、**22:00 ×30**、23:00 ×5；10-21 09:00 部署体积保护/分段压缩修复后**不再出现**（最新一次在 10-20 23:xx） |

**结论**：用户看到的报错是**大请求体上传被传输层中断**（本机到 DeepSeek 的链路在长上传时被重置），外层文案 `Error while copying content to a stream` 只是 HttpContent 复制失败的通用外层异常，不能据此断言限流或模型不支持。提示词里的「LLM 调用失败」= 该轮在**首增量之前**失败并被如实上报；历史未被压缩摘要覆盖或丢失。

**已有修复（HEAD，已入本轮构建）**：
- `LlmRequestTextBudget`：DeepSeek Responses 的 **512 KiB 文本上传预算**（正文/思考/续传/工具定义保守 JSON 估算）；`LlmRequestBudgetGuard` + `WarmPrefixCompaction` 按 token 与文本体积双口径选安全跨度，超限时**不发主请求**并保留原历史。
- `BoundedCompactionSummary`：大历史按 **128 KiB 分段**摘要（≤64 段，仅在全部完成后按收益/双预算/持久身份 CAS 提交）；避免「摘要本身又上传失败 → 原历史继续过大」的复读。
- `83bfb44` 首增量前重试保留 attempt 与 canonical 失败身份；`76f8e93` 诊断展示失败阶段/字节数/attempt/Socket 错误码与 `local.context_compaction_required`。
- 若再次出现：在失败气泡「查看诊断信息」复制 Error ID/Trace ID，按 [常见症状 · LLM 上传失败](Docs/08_how_debuge/05-常见症状.md) 核对 `estimated_request_text_bytes` vs 512 KiB、以及 `Text upload budget triggered` / `compaction_reason`。
