# 2026-10-08 B1 生命周期：创建侧并入同一端口，登记失败不留半登记状态

## 目标 / 背景

设计方案 §3.3：「新增统一生命周期端口，**人工 UI 和两种传输均通过该端口创建/关闭 context/tab**。
顺序为运行时事实完成 → **原子发布登记与授权事实** → UI 投影 → 回执；**登记失败需回收新资源或
明确报告不完整，不返回可操作页面**。关闭后同时清掉 UI、两个注册表、grant、ref/cursor 和租约。」

第 11 段只做了关闭侧，并把「创建侧未迁移」列为缺口。本轮把创建侧并入，并补上 §3.3 的
**登记原子性**与 §3.2 的**切换目标即撤销旧目标执行权**。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/Pudding.DesktopService/BrowserPageLifecycle.cs` | **创建侧**：`RegisterContext`（两个注册表一起；同级别幂等、换级别抛异常）、`RegisterPage`（两表一起；`isAgentTarget: null` = 不表态）、`SetAgentTarget`（两表一起 + **撤销旧目标执行权并推进授权世代**）。**原子性**：任一侧登记失败都 `catch` 回收另一侧再抛出 ⇒ 调用方永远拿不到"视图侧有、准入侧没有"的页面 |
| `Source/Pudding.DesktopService/DesktopTargetRegistry.cs` | 新增 `AgentTarget`（当前目标；切换时要先取它才能撤旧目标的执行权） |
| `Source/Pudding.DesktopService/BrowserTargetRegistry.cs` | 新增 `IsRegistered`（验证"登记失败不得留半登记状态"，也是视图侧在册事实的唯一读法） |
| `Source/Pudding.DesktopSurface.Browser/BrowserWorkspaceTargetBridge.cs` | `OnContextCreated`/`OnPageCreated`/`OnAgentTargetChanged`/`Clear` 全部改为调用生命周期端口；版本推进仍直接写页面注册表（属"事实更新"，不是创建/关闭） |

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **220 / 220**（原 215 ＋ 5） |
| `Pudding.DesktopSurface.BrowserTests` · `PuddingDesktop.Tests` · `PuddingHost.Tests` | 60/60 · 307/307 · 254/254 |

新增门禁：

- `CreateThroughThePort_RegistersBothRegistries`：一侧登记后**两表都在册**（版本、可信级别、活动页、
  目标标记），目标切换走同一端口；
- `RegisterPage_WithUnknownContext_LeavesNoHalfRegisteredState`：人为造出"视图有、准入没有"的上下文，
  登记页面必须抛出**且视图侧也不能留下它**；
- `RegisterContext_Failure_DoesNotLeaveTheViewSideRegistered`：换级别失败后可信级别不变，
  且上下文仍可正常登记页面（说明回滚没把它清掉）；
- `SetAgentTarget_SwitchingRevokesTheOldTargetsExecutionScope_ButKeepsRead`：切换后旧目标只剩 `Read`、
  新目标仍是 `Read|Write`、**授权世代已推进**；
- `SetAgentTarget_ClearingAlsoRevokesTheExecutionScope`：撤销目标同样撤执行权。

**回归网**：桥接层的既有 60 条用例（创建/撤销/版本/清空）在委托改写后**全部原样通过** ——
说明这次迁移是行为保持的（这也是我敢动它的依据）。

**取红实测**：删掉 `RegisterPage` 的 `catch { UnregisterPage(...); throw; }` 回滚 ⇒
`RegisterPage_WithUnknownContext_LeavesNoHalfRegisteredState` **恰好变红**，其余 10 条仍绿；
复原后 220/220 复绿。

## 已知边界（诚实登记）

- **UI 与 ref/cursor 的清理仍未纳入**：§3.3 的"关闭后清 UI、ref/cursor"里，UI 归 Shell 事件；
  `BrowserRefRegistry` 仍未被生产代码消费（ref 时代未接驱动），因此端口只覆盖两个注册表 + 授权 + 租约。
- **版本推进仍由桥接直写页面注册表**：`OnPageActivated`/`OnPageVersionAdvanced` 没并入端口
  （它们是"事实更新"而非创建/关闭）；若后续要让"所有对注册表的写入"都经端口，还需一次迁移。
- **`SetAgentTarget` 的上下文参数未校验一致性**：`contextId` 与页面的实际上下文不符时，
  页面注册表的 `SetAgentTarget` 会拒绝标记（不凭空造目标），但浏览器注册表侧的调用仍会执行 ——
  两侧的严格程度不同（既有行为，本轮未改）。
- 登记原子性的"回收"只覆盖注册表：若未来创建资源（真实 context/tab）后登记失败，还需要
  关闭该资源（§3.3 的"回收新资源"）。目前创建资源的动作在 Shell/驱动侧，端口拿到的是已完成的事实。

## 影响与回滚

- **行为变化**：创建/切换/清空都多了一层原子性与"切换即撤执行权"。桥接层行为不变（回归网证明），
  但**授权世代**会在目标切换时推进（此前不会），因此切换瞬间的在途租约失效 —— 这正是设计要的语义。
- 无数据/配置影响；线缆 DTO 与 proto 未改动。
- 回滚：还原上表 4 个生产文件与 2 个测试文件及 code_map。
