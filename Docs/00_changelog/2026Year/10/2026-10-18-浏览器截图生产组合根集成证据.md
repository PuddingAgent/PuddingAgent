# 2026-10-18 默认 Bridge 截图的的生产组合根集成证据（F1 验收层级 2）

## 目标与结论

[一期方案](../../../12_features/Agent浏览器控制一期整体实施方案-2026-10-18.md) §6 的证据合同要求「生产组合根集成：真实工厂/注册/协议 + 假 driver；配置关闭通道时主链仍全通」，不能只凭组件测试与 Shell 编译就宣称 F1 可用。

本轮新增 `Tests/PuddingDesktop.Tests/Browser/BrowserScreenshotProductPipelineTests.cs`：**能力通道从未构造**，按生产顺序组装：

```
BrowserPageLifecycle（唯一权威/注册表）
  → DesktopSurfaceComposition（真实表面适配，driver 用测试替身）
  → DesktopBrowserExecutorComposition（与传输无关的执行器）
  → BrowserWorkspaceController（handler，截图复用执行器）
  → BrowserBridgeCommandDispatcher（会话准入 + 账本 + 复检/释放）
```

三组断言：

1. **主链正例**：`page.screenshot`（带 `expected_page_version`）成功；`Page.getLayoutMetrics` / `Runtime.evaluate` / `Page.captureScreenshot` 各**恰好一次**；回执含非空 `observationId`、非空 `chunks`（真实图片字节）与 `byteCount/pageVersion`。
2. **陈旧版本负例**：`expected_page_version+1` 被拒，驱动 `captureScreenshot` **0 次**（准入/版本门禁在表面之前）。
3. **未交页负例**：没有用户交页时以 `agent_target_required` 在**触碰 handler/驱动之前**拒绝（会话准入生效）。

## 改动

- 新增上述组合根测试（3 条用例）。
- `Tests/PuddingDesktop.Tests/PuddingDesktop.Tests.csproj`：测试侧新增对 `Pudding.DesktopSurface.Browser` 与 `PuddingBrowser.Automation` 的引用（只为组装真实表面/生命周期；不改变产品依赖方向）。
- `Tests/PuddingDesktop.Tests/Browser/BrowserWorkspaceControllerTests.cs`：`FakeBrowserPage.SendCdpAsync` 由「一律抛 NotSupported」改为最小 CDP 剧本（layout metrics / evaluate / capture）+ 调用计数（供截图链路断言；不影响其它用例）。

## 验证

- `dotnet test Tests/PuddingDesktop.Tests --filter "FullyQualifiedName~BrowserScreenshotProductPipelineTests"` ⇒ **3/3 通过**。
- 全量 `Tests/PuddingDesktop.Tests` ⇒ **345/345 通过**（含本日新增的会话准入与组合根用例）。
- 未启动 PuddingDesktop、未使用真实 WinUI WebView2 或真实模型：driver 是测试替身，故本证据属**层级 2**，不替代 I3（真实模型/真机功能）与 I4（外部生命周期）。

## 未完成与影响

- **I2 另一半仍未做**：Bridge 页面命令的**执行**仍由 controller 完成（本轮证明的是"截图执行器 + 会话准入"这条链）；把全部页面命令迁入 `DesktopService` 执行器、退役旧 authority 的页面 grant/租约路径是下一轮主工作。
- F5 真实回执（执行端 actual backend/阶段/动作后 observation）未做；能力通道路径仍用旧 authority（默认关闭；两路径暂按传输分工共存）。
- 回滚 = revert 本提交（含测试与测试侧引用）；无产品行为变更。
