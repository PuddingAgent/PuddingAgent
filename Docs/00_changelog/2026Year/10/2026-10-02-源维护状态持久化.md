# 2026-10-02 源维护状态持久化（D 第二阶段存储）

## 改动

- `Source/PuddingCodeIndex/Contracts/CodeSourceManifestContracts.cs` 追加：
  `CodeSourceMaintenanceSnapshot`（manifest + 账本）与**可选能力端口** `ICodeSourceMaintenanceStore`
  （`LoadSourceMaintenanceAsync` / `SaveSourceManifestAsync` / `SaveMaintenanceLedgerAsync`）。
  **故意不把成员加到 `ICodeIndexStore`**：给共享端口加成员会破坏每一个实现者（含组件外的测试替身），
  而「谁能持久化 manifest/账本」本来就是可选能力；调用方按能力检测使用，没有该能力时保持既有行为，
  不引入兼容适配层。
- `Source/PuddingCodeIndex/Storage/SqliteCodeIndexStore.cs`：声明改为 `sealed partial class`，
  并实现 `ICodeSourceMaintenanceStore`；`InitializeAsync` 末尾调用新增的幂等建表。
- 新增 `Source/PuddingCodeIndex/Storage/SqliteCodeIndexStore.SourceMaintenance.cs`（部分类）：
  - 新表（幂等）：`CodeSourceManifest`（路径 + mtime/length/content hash + `Complete`）、
    `CodeSourceAppliedVersions`（每个消费者一行：策略指纹、语义输入指纹、已应用版本）、
    `CodeIndexMaintenanceLedger`（世代/期望版本/已提交版本/扫描水位/脏标记）、
    `CodeIndexMaintenanceConsumerWatermarks`（按消费者的全局水位）、
    `CodeIndexMaintenanceRetries`（原因/连续失败次数/首次失败/下次允许尝试）。
  - `SaveSourceManifestAsync`：**单事务**分批 upsert + 删除；每个路径的消费者水位**整体替换**；
    删除路径必须同时删除其消费者水位（否则同名新文件会继承旧文件的「已应用」状态）。
  - `SaveMaintenanceLedgerAsync`：写账本 + 整体替换消费者水位与待重试；**单调守卫**拒绝回退写入
    （存储里的世代更新 ⇒ 拒绝；同世代而期望版本更旧 ⇒ 拒绝），返回 `false` 且存储保持原值；
    scope 不一致直接抛错（fail-closed）。
  - `LoadSourceMaintenanceAsync`：manifest（含「没有基线」的 null 指纹与 `Complete=false` 行原样往返）
    + 账本默认值（无记录时世代/版本为 0、无待重试、无水位）。
  - 时间戳与既有表一致用 ISO-8601（`"O"` + InvariantCulture）；路径比较沿用组件身份（Windows 不区分大小写）。
- 新增 `Source/PuddingCodeIndexTests/Storage/SqliteCodeIndexStoreSourceMaintenanceTests.cs`（14 条）：
  空库默认账本、manifest 完整往返（含多消费者与不完整行）、无基线指纹往返、消费者集合整体替换、
  单事务原子性（注入失败 ⇒ 本批 upsert 与删除一起回滚）、删除同时清消费者水位且新文件不继承、
  按 workspace/project 隔离、账本完整往返（含水位/脏标记/消费者水位/待重试）、水位与待重试整体替换、
  拒绝回退世代、拒绝同世代旧期望版本、接受新世代的低版本、scope 不匹配拒绝、重复 bootstrap 幂等。

## 验证

- `dotnet test Source\PuddingCodeIndexTests\PuddingCodeIndexTests.csproj --filter "FullyQualifiedName~SqliteCodeIndexStoreSourceMaintenanceTests"`
  → 14/14 通过。
- 全量 `Source/PuddingCodeIndexTests` → 全绿（219 用例）。
- `Source/PuddingCodeIntelligenceTests`（使用同一 store 的语言索引器上层测试）→ 全绿（DDL 为纯增量）。
- 组件边界不变：新文件只引用本组件契约、`CodePathIdentity` 与 `Microsoft.Data.Sqlite`；
  `ProjectReference` 仍为空，`ComponentBoundaryTests` 的三重运行期断言不受影响。

## 未完成与影响

- **未接入维护链路**：`ICodeSourceMaintenanceStore` 目前没有任何调用方；判定器与账本也还没有被
  `CodeIndexMaintenanceService` / 校准服务驱动，因此对运行中实例仍是零行为变化。
- **未做完整清单校准**：把 `CodeIndexCalibrationService` 扩成「磁盘清单 vs manifest 差异扫描」
  仍是下一步；磁盘枚举需要以注入端口接入（`PuddingCodeIndex` 必须保持 `ProjectReference = 0` 的叶子，
  不能直接引用 `PuddingPathFiltering`）。
- **未做原子替换**：`ReplaceFilesAsync`（索引结果 + 已应用指纹同事务）尚未实施；目前 manifest 与索引表
  分别提交，D4 要求的「事务失败保留旧完整产物」还不成立。
- 数据库文件新增 5 张表：既有库首次初始化会幂等补建，不改既有表结构、无数据迁移；开发期如需干净状态
  仍按 `Agents.md`「可以清理 `D:\data` 下存储」处理（先备份 `llm.providers.json`）。
