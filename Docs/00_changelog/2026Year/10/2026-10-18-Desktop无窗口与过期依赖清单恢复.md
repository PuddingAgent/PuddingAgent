# 2026-10-18 Desktop 无窗口与过期依赖清单恢复

## 问题与定位

用户从 Visual Studio 启动 PuddingDesktop 后没有主窗口。Desktop 日志在
12:53:11、12:54:51 两次记录 `PuddingBrowser.Authorization` 的
`FileNotFoundException`，调用链为 `BrowserPageLifecycle.Create` →
`DesktopApplicationCoordinator` 构造函数 → `App.OnLaunched`；尚未创建主窗口。

实际 VS 输出目录已有该 DLL，但 `PuddingDesktop.deps.json` 没有其运行时条目。
Shell 的 `project.assets.json` 修改时间仍为 2026-10-17 23:40:43，内容不含当天新增
的授权组件依赖；旧 deps 文件修改时间为 2026-10-18 07:43:01。
完整 restore/build 后，运行时清单包含 `PuddingBrowser.Authorization.Reference/1.0.0.0`，
无需改变 Shell 的编译引用边界或业务源码。

## 改动与恢复操作

- `Docs/08_how_debuge/11-案例-桌面与Core启动.md`：补充窗口创建前失败的日志定位、
  DLL/assets/deps 三方核对、完整还原及 VS/artifacts 输出目录区分。
- 执行 `dotnet build Source/PuddingDesktop/PuddingDesktop.csproj --artifacts-path temp/build/recovery --nologo`，
  完整还原依赖并生成隔离构建。
- 在相同 artifacts 路径执行 `--no-restore` 构建，指定
  `-p:ArtifactsPivots=Debug/net10.0-windows10.0.19041.0/win-x64`，
  更新 VS 实际使用的 `temp/build/winui3/bin/PuddingDesktop/Debug/net10.0-windows10.0.19041.0/win-x64/`。
- 未修改产品源码、用户配置或 `D:\data`。保留已修复的 VS 运行输出供后续 F5 使用。
