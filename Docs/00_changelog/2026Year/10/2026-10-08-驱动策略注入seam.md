# 2026-10-08 驱动策略注入 seam：WinUI 面也接管页面事件（共享源码只依赖 Abstractions）

## 目标 / 背景

上一轮发现（并修好）一件事：**驱动源码被 WinUI 面链接编译，而那一面只允许引用
`PuddingBrowser.Abstractions`**；我从 round 36 起在共享源码里用了 Automation 类型，导致 WinUI 面坏了 11 轮。
当时的修法是条件编译把能力"关掉"。本轮把它推进到**正确的方向**：**策略注入**。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| Abstractions | `DriverPolicy.cs`（新增） | 注入点 `IBrowserDriverPolicy`（脚本对话框怎么答 + 三类事件的事实摘要）；`DriverDialogAnswer`；**未注入时的安全默认** `NullBrowserDriverPolicy`（alert 接受、其余取消；权限拒绝/弹窗抑制/下载取消的结构选择由驱动保证，策略只提供摘要）。`BrowserContextOptions.DriverPolicy` 携带它 |
| Desktop 侧 | `AutomationDriverPolicy.cs`（新增，`Pudding.DesktopSurface.Browser`） | **纯适配器**：把 `ScriptDialogPolicy`/`PageEventPolicy` 接到接口上，**不含任何判定逻辑**（策略与测试仍只有 Automation 那一份） |
| 驱动 | `WebView2BrowserPage` / `WebView2BrowserContext` | 五个事件处理器改成调用 `Policy`（Abstractions 类型）；策略经 `BrowserContextOptions.DriverPolicy` 注入，未注入用安全默认 |

**结果**：WinUI 面（产品 Shell 链接的那一份）**也接管了脚本对话框/权限请求/新窗口/下载** ——
不再需要把这些能力标成 unsupported；共享源码对 Automation 的依赖只剩"事件事实上报"（`PageEventLog`）与
原生输入/截图，仍按面区分（见边界）。

## 已知边界（诚实登记，含本轮**没做完**的部分）

- **原生输入 / 原生滚动 / 截图仍在 seam 之外**：它们仍靠 `#if WINUI_BROWSER` 在 WinUI 面显式 unsupported。
  把 `NativeInputSequence`/`ScreenshotPlan` 也搬进注入接口是下一步（形状已想清楚：接口返回
  `DriverCall(Method, ParametersJson)` 列表 + 截图参数 JSON），本轮预算不够，没有半途混用两套机制。
- **事件事实上报在 WinUI 面仍为空**：`PageEventLog` 在 Automation，WinUI 面拿不到 ⇒
  `DescribePageEvents()` 在那里返回 `null`。也就是说 WinUI 面"会接管事件但不会上报事实"。
- **注入还没在 WinUI 构造点接上**：`BrowserContextOptions.DriverPolicy` 目前没有生产调用方设置它
  （我试过在 `PuddingDesktop.WpfArchive` 的上下文创建处注入，但那里**刻意不引用** `Pudding.DesktopSurface.Browser`
  —— 上一个模块边界结论，因此回退了那处改动）。所以**当前生产路径用的是 `NullBrowserDriverPolicy`**：
  安全默认照旧生效，只是摘要更简略。适配器 `AutomationDriverPolicy` 已就绪，接线是下一步（需要先决定
  它放在哪个双方都能引用的程序集：候选是 `Pudding.DesktopService`）。
- 因为上一条，**WinUI 面接管事件是"编译与逻辑上可用"，未经真机验证**；真机行为仍需外部 smoke。
- `PuddingDesktop` 的整体产物本轮未重新生成（本机仍在运行的 Shell 占用输出文件）。

## 影响与回滚

- **行为变化（WinUI 面）**：脚本对话框/权限/新窗口/下载从"未接管（会弹 UI 或等人操作）"变成
  **安全默认接管**；事实摘要更简略（未注入 Automation 适配器）。
- **行为变化（桌面/驱动非 WinUI 路径）**：事件处理器改用注入策略，默认策略下行为与上一轮一致。
- 回滚：还原 `DriverPolicy.cs`、`AutomationDriverPolicy.cs`、驱动与上下文的策略字段/注入、`BrowserContextOptions.DriverPolicy`。
