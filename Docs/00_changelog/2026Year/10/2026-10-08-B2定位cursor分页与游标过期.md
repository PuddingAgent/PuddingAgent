# 2026-10-08 B2 定位分页：cursor 绑定版本与查询，过期即明确拒绝

## 目标 / 背景

设计 §6.2：「locate 默认 `includeHidden=false`、`limit=10`；提供 **cursor**、`includeHidden`、`fields`、
`inViewportOnly`。」§145 又明确：「分页使用 extraction snapshot 的 revision；动态页面变化使
**`cursor_expired`**，并提供重新读取入口，**不能把旧游标用于新内容**。」

此前 `browser_locate` 只有 `limit`：命中超过上限时调用方无从翻页，而"再调一次同样的定位"在页面上
会**从头再来**（可能每次看到同一批、也可能因为页面变了而错位）。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| 契约 | `Source/Pudding.Contracts/Desktop/LocateCursor.cs`（新增） | `BrowserLocateCursor`：**对模型不透明**，绑定「页面版本 + 查询指纹 + 偏移」，线格式 `c1-{version}-{fp8}-{offset}`；`TryParse` 严格（任何偏差即 false）；`FingerprintOf` 用 **SHA-256 截断**（刻意不用 `string.GetHashCode`——它按进程加盐，跨进程/跨重启不稳定），只看影响匹配集合的输入 |
| 契约 | `Source/Pudding.Contracts/Desktop/LocateContracts.cs` | `BrowserLocateRequest.Cursor`；`DesktopLocateResult.NextCursor`（null = **已取完**） |
| 契约 | `Source/Pudding.Contracts/CapabilityErrors.cs` | 新错误码 `cursor_expired`（不可重试、无副作用）；错误码快照测试同步冻结 |
| 能力通道 | `Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs` | 解析并校验游标：**版本或查询指纹不符 ⇒ `CursorExpired`；格式坏 ⇒ `InvalidRequest`**（两类分开）；按偏移切片；**只有还有下一页才签发** `NextCursor` |
| 工具 | `BrowserLocateTool` · `BrowserToolContracts` · `BrowserCapabilityFailure` | `cursor` 参数原样透传 + 输出 `nextCursor`；`CursorExpired` 映射为独立错误码 `cursor_expired` 并附「重新读取」提示（不能靠重试同一请求解决） |

新增门禁：

- **游标编解码**（契约层，纯函数）：往返、**12 种畸形输入**全部拒绝（少段/多段/未知方案版本/版本≤0/
  负偏移/非十六进制指纹/指纹长度错/非数字段）、`Matches` 只认同一版本同一查询；
- **指纹**：同输入永远同指纹（跨进程稳定）、8 位十六进制、定位条件与 `includeHidden`/`inViewportOnly`
  任一变化都改变指纹、**limit/cursor 本身不参与**（分页不改变"同一组结果"这一事实）；
- **错误码**：`cursor_expired` 进入冻结快照（不可重试、无副作用），与 `invalid_request` 分开；
- **能力通道**：三条命中分两页取完（第二页 `NextCursor == null`）；旧版本游标、换了查询的游标
  ⇒ `CursorExpired`；畸形游标 ⇒ `InvalidRequest`；
- **工具**：宿主签发的游标原样出现在输出并被原样回传（到达能力层）；过期时错误码为
  `cursor_expired` 且 `warnings` 含「re-read」。

**取红实测**：把能力通道的游标校验短路（接受任何游标）⇒
`CursorFromAnotherVersionOrLocator_ExpiresInsteadOfReturningShiftedResults` **恰好变红**；
复原后 63/63 复绿。

## 已知边界（诚实登记）

- **桥接（WebSocket Bridge）路径尚未支持 locate 游标**：本轮只打通能力通道；桥接的
  `page.locate` 命令/响应还没有 cursor/nextCursor 字段 —— 与上一轮修掉的"滚动传输不对称"同类，
  已明确登记为下一步（不在本轮假装两条传输同形）。
- **分页窗口受驱动上限约束**：驱动一次最多回 101 条（`LocateAsync` 内固定 `maxResults=101`），
  因此**超过 101 条命中时翻页会在窗口尽头停止**（`NextCursor` 变 null）。这是既有驱动边界，
  本轮未改；`Truncated` 与 `NextCursor` 分开表达，所以调用方不会被误导成"页面只有这些"。
- **游标不是安全令牌**：它可被猜测/伪造（只是 base 编码），因此不能当作授权凭据；
  它只表达"分页位置"，作用域仍由目标页与准入闸门决定。
- **`fields` 参数仍未实现**（§6.2 列的其余项）。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_locate` 新增 `cursor` 参数与 `nextCursor` 输出；
  超过 limit 时不再"沉默地只剩前 N 条"，而是给出可继续的游标；旧游标被用在变了的内容上会得到
  明确的 `cursor_expired`（附带"重新读取"提示），而不是错位结果。
- 线缆新增可选字段；错误码表新增一项（旧消费方按 `ParseOrInternalError` 折叠为 `internal_error`，
  fail closed）。
- 回滚：还原上表 5 个生产文件与 4 个测试文件及 code_map。
