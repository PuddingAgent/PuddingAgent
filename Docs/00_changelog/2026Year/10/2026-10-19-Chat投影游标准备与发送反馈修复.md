# Chat投影游标准备与发送反馈修复

- 定位：在实际 Desktop 6.9.9 的 DevTools 中确认原生可信 click 已进入发送处理器，读取草稿正确；`ensureSessionEventStream` 返回 `cursor-not-ready`，`useMessageSend` 在 POST 前抛出“会话事件游标准备失败，消息未发送，请重试。”。因此按钮和头像 404 不是本次阻塞的原因。
- 根因：`useChatState.ts` 的 Agent 投影快捷路径仅返回快照 C，没有发布带会话身份的 ready 状态和数值镜像；真实 bootstrap 路径包含这两步，空缓存浏览器测试容易漏过。错误被捕获并恢复草稿，但历史列表中的 Alert 在视口外。
- 修改：投影适配器复用现有 cursor 状态函数，在有效、未取消且仍为当前请求时同步 ready 状态和镜像；非法 C 走权威 bootstrap，resetCursor 保持重取快照。`useMessageSend.ts` 增加即时错误提示，保留原有草稿恢复及错误记录。版本 `6.9.9→6.9.10`；同步 Admin 代码地图、ADR-057 和平台会话诊断手册。
- 验证：新增已有投影 C=0/1800000 的真实 hook 组合回归，断言 SSE 起点、先订阅后提交且不请求额外 bootstrap；另覆盖负数/NaN/Infinity 走权威 bootstrap。修复前两条发送回归及错误提示断言均失败；修复后 selection、send feedback、cursor、connection 共 4 套件 53 项通过，`pnpm exec tsc --noEmit` 通过。Jest 有既有 open handles 提示。
- 未完成：前端构建、在线部署及 Desktop 原生点击验收待执行，结果另行追加。本次不修改 Core/Desktop 二进制或用户配置。
