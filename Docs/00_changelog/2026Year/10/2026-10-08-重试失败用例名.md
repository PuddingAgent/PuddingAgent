# 2026-10-08 交付链：重试记录补上失败用例名

## 上一轮登记的两项，本轮收尾

### ① 重试记录只有条数 → 现在给出**用例名**

脚本在重试**之前**解析该套件 TRX 里 `outcome="Failed"` 的 `testName`（有界：最多列 5 个，更多则 `(+N more)`）：

- **无条件打印**到日志（即使重试仍失败也能看到，不必等"重试成功"这一事件）；
- 重试成功时一并写进 `retry-notes.txt`：`<suite> : first attempt had N failing test(s) [names]; the result below is from the retry`。

**实测输出**（对确实失败的套件跑重试）：

```
--- PuddingWebApiTests : first attempt failed 2 test(s): Compact_Passes_Runtime_Profile_To_Compaction_Service, Compact_Persists_Failed_Terminal_Event
```

⇒ 一眼看出那是 **compaction** 子系统的失败，而不是浏览器相关 —— 这正是"能指认"与"只知道有几条"的差别。

### ② 跨语言文件名约定 → 加门禁

`retry-notes.txt` 由 PowerShell 写、C# 读。改名一侧而另一侧不改，后果**不是编译错误**，而是
"重试记录静默消失"（又是同一类静默缺陷）。新增门禁
`TheRetryNotesFileNameIsAgreedBetweenTheRunnerAndTheCollector`：两侧源码都必须出现该文件名，
且脚本必须写明"这是重试后的结果"。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **324 / 324**（＋1 门禁） |
| 失败用例名 | 实测打印出 2 个具体用例名（见上） |
| **取红实测** | 把采集器里的文件名改成 `retry-notes-v2.txt`（模拟单侧改名）⇒ 门禁**变红**；还原 ⇒ 324/324 |
| 脚本约束 | 仍**纯 ASCII**（0 非 ASCII 字符；本轮又踩过一次 PS 5.1 的行续接坑：`+` 不能放行首，已改为单行字符串） |

## 诚实边界（诚实登记）

- **`notes` 的写入路径仍未在"重试成功"的真实事件里被观测**：本轮同样只遇到"重试仍失败"（WebApi 两条 compaction 用例稳定失败）。
  ⇒ 写入那一段目前是**单测 + 源码门禁**保证，不是端到端观测。上一轮观测到的是"改名"路径。
- **用例名最多列 5 个**：更多时只给 `(+N more)`（避免把清单变成日志转储）；完整列表仍在 TRX/日志里。
- **TRX 解析用正则**：`<UnitTestResult … outcome="Failed" … testName="…">`；TRX 结构若变化会静默漏名（表现为 `no test names in the TRX`，**不会**假装有名字）。
- **门禁是源码文本断言**：重命名/改写会显式失效。
- **未真机验证**；两项待决取舍未触碰。
