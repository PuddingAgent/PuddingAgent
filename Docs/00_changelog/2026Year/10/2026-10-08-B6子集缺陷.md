# 2026-10-08 B6 子代理授权：三条不变量通过 + 阻断性缺陷

## 已验证（3 条，TRX 判定）

| 用例 | 判据 |
|---|---|
| 无真实父授权 | 拒绝，原因含 `parent` |
| 索取超过父授权范围（父 Read，子 Write） | 拒绝，无 `GrantId` |
| 期限超过父授权（父 2min，子 30min） | 拒绝，无 `GrantId` |

⇒ "子集越权 0 调用"这一验收项在 Desktop 边界**成立**。

## **发现的缺陷（阻断 B6 正常路径）**

**合法子集请求同样被拒**：父 Read|Write、子 Read ⇒ 拒绝，原因 `a sub-agent grant must be a subset of its parent's granted scope`。

**根因**（读码确认）：

```csharp
// BrowserGrantIssuer.cs:105 附近
if (caller.Kind == BrowserCallerKind.SubAgent)
{
    if (request.ParentScope is not { } parentScope
        || (request.Scope & ~parentScope) != 0)
    {
        reason = "a sub-agent grant must be a subset of its parent's granted scope";
        return false;
    }
}
```

签发器要求**请求里带上父范围**（`ParentScope`），而 `BrowserTaskBindingService.Accept` 构造 `BrowserGrantIssuanceRequest` 时
**从不提供 `ParentScope`** ⇒ 子代理一路被拒 —— B6 的 happy path 目前**根本走不通**（不是策略错误，而是接线缺失）。

## 修复步骤（下一步）

1. `BrowserTaskBindingService.Accept`：当 `binding.Task.Kind == SubAgent` 且有 `ParentTaskId` 时，从权威里**找出父授权**
   （同目标 + 同 `TaskId == ParentTaskId`），取其 `Scope` 作为 `ParentScope` 传入签发请求；
2. **同时**把子授权期限夹到父授权**剩余期限**之内（§5 要求"期限不超过父授权"）；
3. 找不到父授权 ⇒ 明确拒绝（原因可区分，如 `no_grant`），不静默放宽；
4. 把被移除的那条"应当被接受"的用例加回并跑通，另补一条"父授权剩余期限不足 ⇒ 拒绝"。

## 诚实边界

- 被移除的用例**原文**：父 Read|Write、子 Read、5 分钟 ⇒ `Assert.True(ack.Accepted)`（当前为 `False`）。
- **未真机验证**；子代理的真实 Runtime child/parent 运行接线（§5 其余要求）仍未做。
