# 2026-10-08 B3 输入路径：inputMode 显式化，native 明确 unsupported 且回执报告实际 backend

## 目标 / 背景

设计 §7 第一段：「驱动增加明确 `inputMode=dom/native`，回执报告实际 backend；面向用户网页优先使用
真实浏览器输入路径，DOM 模拟用于已验证适用的动作，**native 不可用时明确 unsupported，不静默切换语义**。」

此前 `browser_interact` **根本没有输入路径参数**：调用方无法表达"我要真实输入"，
也无从知道实际用的是 DOM 事件还是真实键鼠 —— 这正是"静默切换语义"的温床。
本轮把模式显式化，并把"native 不可用"变成**响亮失败**而不是悄悄降级。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/Pudding.Contracts/Desktop/InteractionContracts.cs` | 新增 `DesktopInputMode`（`Dom` 默认 / `Native`）+ `DesktopInputModeWire`（线名冻结、严格解析、未知即拒）；`BrowserInteractRequest` 新增 `InputMode`（默认 `Dom`，未登记值构造期拒绝） |
| `Source/PuddingBrowser.AgentTools/BrowserInteractTool.cs` | 新增 `input_mode` 参数：未登记线名 ⇒ `browser_invalid_arguments`；**`native` ⇒ `browser_input_mode_not_supported`**（带回执：未开始/无副作用/不可重试）+ 修复提示；成功输出新增 `inputBackend`（报告**实际**路径）；模式随请求下传，供将来 CDP 实现使用 |
| `Source/PuddingBrowser.AgentTools/BrowserToolContracts.cs` | `BrowserInteractionToolValue`/`BrowserReceiptToolValue` 新增 `InputBackend` |

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.ContractsTests` | **99 / 99**（原 97 ＋ 2） |
| `PuddingBrowser.AgentTools.Tests` | **43 / 43**（原 41 ＋ 2） |
| `PuddingHost.Tests` · `PuddingDesktop.Tests` · `DesktopServiceTests` · `AutomationTests` | 254/254 · 308/308 · 220/220 · 194/194 |

新增门禁：

- 契约层：线名冻结为 `["dom","native"]`、未知线名（`cdp`/null）拒绝、未登记枚举报错；
  `BrowserInteractRequest` 默认 `Dom`、显式 `Native` 可表达、未登记模式构造期抛异常；
- 工具层 `Interact_NativeInputMode_FailsExplicitly_InsteadOfSilentlyFallingBackToDom`：
  错误码为 `browser_input_mode_not_supported`、消息含 `not implemented`、回执为
  `not_started` + 无副作用 + `not_retryable`、提示含 `input_mode=dom`（`warnings` 与 `retryDetail` 都带），
  且**一次驱动调用都没发生**（`LastAction` 为空）；
- 工具层 `Interact_ReportsTheActualInputBackend`：默认与显式 `dom` 都报告 `inputBackend=dom`；
  未登记线名 `cdp` ⇒ `browser_invalid_arguments`。

**取红实测**：把 native 的拒绝改成静默降级（即恢复"请求 native、实际走 DOM、还回成功"）⇒
`Interact_NativeInputMode_FailsExplicitly_InsteadOfSilentlyFallingBackToDom` **恰好变红**，
其余 42 条仍绿；复原后 43/43 复绿。

## 已知边界（诚实登记）

- **native 路径尚未实现**：本轮交付的是"显式声明 + 明确失败 + 实际 backend 上报"，
  CDP 真实键鼠（§7 的原生键鼠、修饰符、焦点/selection、pointer down/up 成对处理、取消时清理按键状态）
  仍属后续切片；`DesktopInputMode.Native` 目前只会得到 `browser_input_mode_not_supported`。
- **拒绝位置在工具层而非驱动**：因为模式目前没有沿 `ClickOptions`/`FillOptions` 等动作选项下传到驱动
  （那需要给每个动作选项加模式，或改成统一选项对象）。请求里已经带 `InputMode`，等驱动实现时把拒绝
  下移到驱动即可；在此之前"绝不静默降级"由工具层保证。
- **`inputBackend` 目前恒为 `dom`**：因为 native 请求根本不会走到执行路径；这个字段的意义在于
  将来 native 落地后能如实区分（例如 native 不可用时回退必须是**显式**的，而不是静默的）。
- 滚动/输入的真实行为仍未在真机验证（本环境跑不了 WebView2）。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_interact` 新增 `input_mode` 参数（默认 `dom`，行为不变）与
  输出字段 `inputBackend`；请求 `native` 从"无声地按 DOM 执行"变成**明确失败**。
- 无数据/配置影响；线缆 DTO 与 proto 未改动（`InputMode` 随请求对象走）。
- 回滚：还原上表 3 个生产文件与 2 个测试文件及 code_map。
