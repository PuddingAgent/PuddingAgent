# 2026-10-18 Bridge 握手携带构建身份（D9）

## 改动

- 协议新增 `BrowserBridgeBuildIdentity`：`BuildId`（信息化版本）、`SourceRevision`（仅当构建 stamp 了 `+rev`）、`Dirty`（仅当 stamp 了 `.dirty`，否则 null=unknown）、`ModuleName`、`ModuleVersionId`（MVID）、`ModulePath`（诊断用）、`Describe()` 单行文本。
- `BrowserBridgeHello` / `BrowserBridgeHelloAck` 增加可选 `Build` 字段（JSON 往返已加入 source-gen 上下文）。
- Desktop Shell：Hello 携带本进程身份；收到 Ack 时记录 `LastDesktopBuildIdentity` 并写入 Debug 日志（Core 身份）。
- Host Core：HelloAck 携带自身身份；握手日志分别记录 desktop/protocol/build，明确"握手成功不代表 Agent 可控"。
- 身份仅用于与发布清单/日志核对，**不参与授权判断**；构建未 stamp 时不推断 revision/dirty。
- 测试 3 条：程序集身份非空且 MVID 可解析；Hello/Ack 线缆往返；dirty/clean/unstamped 解析规则。

## 验证

- Host 全量 **308/308**、Desktop 全量 **384/384**、Shell build exit 0；
- 未运行产品/真实模型；两侧实际构建身份需在 R4 成套部署后由握手日志核对。

## 未完成与影响

- 发布清单（Desktop/Core/共享程序集预期哈希绑定与核对脚本）未做；
- 构建 stamp（源 revision/dirty 注入）未接 CI/本地构建规则，当前 `SourceRevision`/`Dirty` 多为 unknown（如实 null，不伪造）；
- 实际 Core 加载路径/MVID 的清单核对与"旧/新混配"门禁仍属 R4/R5；
- 回滚 = revert 本提交（协议可选字段，旧端不影响解码）。
