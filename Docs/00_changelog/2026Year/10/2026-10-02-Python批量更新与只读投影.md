# 2026-10-02 Python 批量更新与只读投影

## 改动

- `Source/PuddingCodeIntelligence/Python/PythonIndexer.cs`（与 TypeScript 侧同形状）：
  - 实现 `ICodeIndexFileBatchUpdater.UpdateFilesAsync`：**一个批次只跑一次项目级提取进程**，
    逐文件产出 `CodeFileIndexPayload`，**不写任何索引**（原子提交由调用方经 `ReplaceFilesAsync` 完成）。
  - 路由：非 `.py`、噪声路径 ⇒ `NotApplicable`；工程根缺失 / Python 不可用 / 资产缺失 ⇒ 全部 `Retryable`
    （前两者**不启动提取器**）；项目模式没覆盖到的路径退化逐文件提取并把 `SessionKey` 置空。
  - **投影改为只读**：`ProcessProjectExtraction` 内嵌的 `ClearSymbolsForFileAsync`（`.GetAwaiter().GetResult()`）
    移到调用方新增的 `ClearProjectModeFilesAsync`，语义与顺序等价（清理仍全在写入之前、每次只作用于该文件自己）。
  - 全量 `IndexWorkspaceAsync` 与逐文件 `IndexFileAsync` 的行为未改动。
- 新增 `Source/PuddingCodeIntelligenceTests/Python/PythonIndexerBatchTests.cs`（8 条）。
- `Source/PuddingCodeIntelligence/code_map.md`：Python 索引器条目登记批量能力与只读投影。

## 验证

- `dotnet test Source\PuddingCodeIntelligenceTests\PuddingCodeIntelligenceTests.csproj` → **132 通过 0 失败**
  （本次 +8）；`Source\PuddingCodeIndexTests` → 280 通过 0 失败（未受影响）。
- 用真实 Python 子进程 + 可控桩提取器（每次 `--project` 调用追加标记行）断言：**两个文件的项目级提取调用次数 = 1**；
  批后 `ListFilesAsync`/`GetSymbolsByFileAsync` 为空（不写索引）；非 `.py` ⇒ `NotApplicable` 且提取器一次都不跑；
  工程根缺失 ⇒ `Retryable` 且提取器一次都不跑；资产缺失 ⇒ `Retryable` 且原因含脚本路径；
  未覆盖路径退化逐文件（标记出现 `file:ghost.py`）且 `SessionKey` 为空；重复/空白路径去重；空批不跑。
- **补上 Python 全量路径的首个用例**（`FullRunProjectModeStillClearsStaleSymbolsAndWritesAfterTheReadOnlyRefactor`）：
  先种一个旧符号，再跑 `IndexWorkspaceAsync`，断言旧符号被清掉、新符号与文件记录被写入 —— 因为 Python 全量路径
  此前**没有任何测试覆盖**，本轮又动了它的清理位置，必须补一条回归锁（TypeScript 侧由既有
  `TypeScriptIndexerAssetTests` 承担同类职责）。

## 未完成与影响

- **仍未接入维护链路**：批量接缝目前没有调用方，`CodeIndexMaintenanceService` 仍走逐文件旧接缝，
  运行中实例仍是零行为变化。
- 未实现跨批次快照缓存（同前两轮说明：需要明确生命周期所有者、失效条件与内存上限，属独立任务）。
- Python 的逐文件提取器仍是「一文件一进程」；批量路径只在项目模式可用时复用一次进程，
  未覆盖路径仍逐文件（并如实置空 `SessionKey`）。
