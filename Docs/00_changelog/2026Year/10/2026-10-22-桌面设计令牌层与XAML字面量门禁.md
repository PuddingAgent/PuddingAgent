# 桌面设计令牌层与 XAML 字面量门禁（S1+S2）

## 1. 问题（实测，不是感觉）

`Source/PuddingDesktop/MainWindow.xaml`（759 行）：

| 类别 | 实测 |
|------|------|
| 裸 `FontSize` 数字 | **65 处 / 13 档**（29×12、11×6、18×6、15×5、10×3、13×3、24×3、28×3、9×3、8/16/19/21×1） |
| 裸 `CornerRadius` | **20 处 / 4 档**（8×14、10×4、15×1、16×1） |
| 裸 `#hex`（Background/Foreground/BorderBrush/Fill/Stroke） | **9 处** |
| 引用字号令牌 | **0 处** |

`App.xaml` 只有 5 个语义画刷（ThemeDictionaries），`MainWindow.xaml` 另有一组内联画刷，
主壳层则**整段绕过两者直接写字面量** ⇒ 同一视觉事实有两份真源，改一处不改另一处不会报错。
所以「视觉重量倒挂」的根因不是某个值选错，而是**没有词汇表**：13 档字号里
12/13/15/16/18/19/21 彼此相差 1–2px，无法用肉眼判断谁更重要。

## 2. 做了什么（本次提交，不含宿主改动）

新增 `Source/PuddingDesktop.Foundation/Design/`（Foundation 是 BCL-only 叶子，不引 WinUI，可脱宿主测试）：

- `DesignTokens.cs`：唯一字号 **6 档**（11/13/15/18/24/28）+ 圆角 **2 档**（8/12），
  按**角色**命名（`FontSizeBody` / `RadiusCard`），不按数值命名 ⇒ 未来调值是改一处；
  另给 `MapFontSize` / `MapCornerRadius`（把历史字面量映射到档位，迁移脚本与门禁共用同一套判断）。
- `XamlLiteralLint.cs`：纯文本扫描，三条规则 `PDT-TOKEN-001`（裸 FontSize）/ `002`（裸 CornerRadius）/
  `003`（用量属性上的裸色值）。`{StaticResource …}` / `{ThemeResource …}` / `Auto` / `*` / `Transparent` 放行；
  `<SolidColorBrush Color="#…">` 属**定义处**，刻意合法——否则令牌文件自己都过不了自己的门禁。
- `DesignTokenXaml.cs`：由上述表**生成** `Source/PuddingDesktop/Themes/DesignTokens.xaml`，
  字节确定、禁止手改 ⇒ ResourceDictionary 与常量不可能漂移。

`Source/PuddingDesktop.FoundationTests/DesignTokenTests.cs` 新增 22 个用例，其中：
- 迁移完备性：MainWindow 里出现过的 13 档字号逐档断言归宿（少一档 = 迁移会漏）；
- lint **红样本**：喂 `FontSize="13"` / `CornerRadius="0,12,0,12"` / `Background="#FF00AA"` 必须报，行号必须对；
- 生成物可被 `XDocument` 解析、覆盖全部 key、两次输出逐字节相同、自身零违规；
- **现状基线（characterization）**：真实 `MainWindow.xaml` 的违规数钉死为 65 / 20 / 9，`App.xaml` 为 0。
  迁移时这些数字只许单调下调；任何人新写一个 `FontSize="14"` 会立刻变红。

## 3. 验证

- `dotnet test Source/PuddingDesktop.FoundationTests` → **499 通过 / 0 失败**。
- 变异取红：把 `MapFontSize` 阈值 13.5 改成 12.5 → **2 个用例变红**
  （`MapFontSize_CoversEveryLiteralObservedInMainWindow(literal: 13)` 与 `Lint_FlagsRawFontSize`），
  复原后字节级 `-ceq` 相同并复跑全绿 ⇒ 门禁确实能失败，不是"永远绿"。
- 交叉验证：基线数字与独立的 PowerShell 正则统计（65 / 20 / 9）一致 ⇒ lint 的正则与预期口径相符。
- 宿主 `PuddingDesktop.exe` 全程未重启、未构建、未改一个字节；本次改动全部落在 `temp\build\winui3`。

## 4. 留白（下一步，均未开始）

1. **S5 接入**：生成 `Themes/DesignTokens.xaml` 并合并进 `App.xaml`（会动宿主 XAML，需单独提交）。
2. **机械迁移**：65 + 20 处字面量 → 令牌引用，视觉零变化（第三档：`8/9/10/11→Micro`、`12/13→Caption`、
   `15/16→Body`、`18/19/21→Subtitle`、`24→Title`、`28→Display`；`19/21→18` 会略微变小，需同屏比对）。
3. **颜色令牌**：9 处用量色 + 39 个 `Color=` 定义值要收敛成按语义命名的画刷，且必须三套 ThemeDictionaries
   （浅色/深色/高对比）齐备，工作量远大于字号，单独一轮。
4. **间距**：`Padding` / `Margin` 尚未盘点，本次刻意没写规则（避免伪门禁）。
5. **代码侧**：`MainWindow.xaml.cs` 里 `FontSize = …` 之类赋值尚未纳入 lint（纯文本扫描只覆盖 XAML）。
