# 代码地图「逐文件免检旁路」补逐词取红断言（B 级清零）

**日期**：2026-10-23 · **范围**：`Tools/Docs/code_map_check_selftest.py`（+ 根 `code_map.md` 的 `Tools/**` 源指纹）；`code_map_check.py` **未改**（sha256 前后逐位相同）

## 问题：规范承诺机器判，旁路词表却无人守

`SKIP_BYPASS_WORDS = ["免检", "特例跳过", "跳过检查"]` 在 §6 里对应「逐文件免检旁路」这一类反模式：命中即报 `anti-pattern`（warn），提示评审者“这个文件声称自己免检、需要人看”。规范承认**处置**不可机器判定，但**词级启发式本身是机器判定** —— 词表写错一个、或者整段删掉，门禁只会静默少报一类违规，没有任何东西会红。

实测确认：把三个词全部删除，`code_map_check_selftest.py` 依旧 **68 passed，0 failed** 全绿。这正是条款覆盖核对报告里最后一类 **B 级**（机器可判 · 已实现 · 无取红断言）。

## 改动（只加测试，不改判定）

新增 `stage_anti_pattern_skip_bypass(mod)`，四行夹具：

| 行 | 用途 | 期望 |
|---|---|---|
| 5 | `指纹生成器` | 无旁路词 ⇒ 对照组，0 命中且不带 `category` 字段 |
| 6 | 含 `免检` | 命中第 6 行、`detail` 尾段为 `免检`、等级 `warn` |
| 7 | 含 `特例跳过` | 命中第 7 行、`detail` 尾段为 `特例跳过`、等级 `warn` |
| 8 | 含 `跳过检查` | 命中第 8 行、`detail` 尾段为 `跳过检查`、等级 `warn` |

断言三条：

1. **逐词对应**：`{行号: 词}` 必须逐字等于写死的字面量 `{6: "免检", 7: "特例跳过", 8: "跳过检查"}` —— 只数条数会漏掉“词表顺序错位/错行”这种缺陷。
2. **对照行为空且等级正确**：第 5 行不在命中集里，三条命中全是 `warn`（规范 §7 定的等级，不是 info）。
3. **与 §6 词表七类互不相交**：`SKIP_BYPASS_WORDS ∩ ANTI_PATTERN_WORDS == ∅`，防止同一个格子被双重打标、也防止日后往词表里塞进“演进叙事”这类词导致计数互相污染。

自测 68 → **72 passed / 0 failed / 0 inconclusive**，`def stage_` 阶段数 18 → **19**。

## 证据

- 变异取红：`SKIP_BYPASS_WORDS` 去掉 `免检` ⇒ `71 passed, 1 failed`，红的正是 `skip-bypass: each spec word hits its own row -- got={7: '特例跳过', 8: '跳过检查'} expect={6: '免检', …}`。
- 三连跑（同一脚本内 GREEN → MUTATION → GREEN，先落盘硬备份）：绿 `72 passed` / 变异 `71 passed, 1 failed` / 复原后绿 `72 passed`。
- 复原校验：`code_map_check.py` sha256 = `bd06254db6b53dc09445f8cd7e0672f9ed5406178f3df538f2ea4d15d420d16d`，与变异前逐位相同。
- 门禁：`--check --report` → `files_scanned: 48`、`error 0 warn 82 info 0`、`gate: PASS`、`stale-fingerprint 0`、`fingerprint_check verified=148 mismatched=0`。
- 根 `code_map.md` 的 `Tools/**` 指纹从 `a031d56ad5ae` 刷新为 `5f7daa2009f8`（27 个文件），条目数不变（本轮没新增文件条目）。

## 两个坑（比结论更值钱）

### ① 第一版断言是假绿：拿被实现自己当期望

初版写的是 `words == sorted(mod.SKIP_BYPASS_WORDS)` —— 期望值直接取自被测模块的同一个常量。一旦从常量里删掉一个词，实现与期望**同时变化**，断言恒真，变异跑出来是 **72 passed 全绿**（`words=['特例跳过','跳过检查']`，看起来“对”）。改成写死三词的字面量之后，同样的变异立刻 1 failed。

结论：**“有断言”不等于“能取红”**。凡是断言里出现“期望值 = 被测模块的某个常量/函数返回值”的写法，都要按假绿处理；判定 A 级的唯一凭据是变异后真的红。

### ② 变异脚本被 shell 超时打断会留下变异态

第一版变异脚本没有落盘备份、也没有 `try/finally`，30 s 超时把解释器杀掉时检查器**停在变异态**（`SKIP_BYPASS_WORDS = ["特例跳过", "跳过检查"]`，sha256 `5f60d4d1…`）。发现方式是“绿色基线”跑出 1 failed 与 sha 不符，另外还留了两个 `py`/`python` 残留进程。

之后改成：先写 `temp/cm_backup.bin` 硬备份 → `try` 内做变异并跑自测 → `finally` 从备份回写 → 复原后**断言 sha256 等于变异前**；命令超时给到 300–600 s。凡涉及“改源码 → 跑测试 → 改回来”的探针，都必须具备“进程被强杀也能恢复”的性质。
