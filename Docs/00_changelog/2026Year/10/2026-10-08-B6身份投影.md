# 2026-10-08 B6 跨层：执行身份 → 浏览器调用者身份

## 交付（4 条用例，TRX 90/90）

| # | 判据 |
|---|---|
| ① | 子代理（`SubAgent` + `ParentRunId`）⇒ `SubAgent`、`TaskId=run-child`、`ParentTaskId=run-parent`、`CallerId=agent-1` |
| ② | **子代理缺父 ⇒ 拒绝**（原因含 `parent`，`caller` 为 **null**） |
| ③ | 普通会话回合（`ConversationTurn`）⇒ `Agent`、无父 |
| ④ | **无执行身份 ⇒ 拒绝**（含 `no trusted execution identity`，不做环境推断） |

## 生产链路核实（读码，非推测）

| 环节 | 位置 | 状态 |
|---|---|---|
| Runtime 判定子代理并带父会话 | `PuddingRuntime/Services/AgentExecutionService.cs:1098`（`isSubAgent`）、`:1102`（`ParentSessionId`） | ✅ 已接 |
| AgentTools 投影 | `BrowserCallerIdentitySource.TryProject`（`isSubAgent` 取编排层声明的 Kind；`parentRunId: identity.ParentRunId`） | ✅ 已接 |
| 契约层 fail-closed | `BrowserCallerIdentityProjection.TryProject`（子代理必须有父，缺一即拒） | ✅ 已接 |

⇒ B6 的"**真实 child 身份到达 Desktop**"在**身份层已成立且有用例**；缺口在**授权层**（Core 侧尚无 `browser.binding.apply` 生产者 ⇒ 生产上不会有 grant）与工具注入/有界父结果。

## 顺带修正的认知

`RuntimeExecutionKind` 的成员是 `ConversationTurn` / `SubAgent`（**没有** `Agent`）—— 普通会话回合即"主代理"，
这一点此前被我按直觉写成 `Agent`，编译报错后读码纠正。

## 诚实边界

- **未跑全量链**（本轮仅新增测试文件）；**未真机验证**。
- 未覆盖：工具发现/注入、有界父结果、子代理**运行**的端到端（需 Core 侧签发生产者先行）。
