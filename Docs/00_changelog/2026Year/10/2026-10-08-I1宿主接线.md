# 2026-10-08 I1 第五步：Core 侧接线（gRPC 闭环）

## 改了什么

| 件 | 变化 |
|---|---|
| `ConnectedDesktopCallContextFactory` | 构造器增加可选 `IBrowserCallerIdentityAccessor`；`TryCreate` 把 `accessor.Current` 写进 `DesktopCallContext.BrowserCaller`（**没有身份就是没有**，不生成默认值） |
| `BrowserBridgeServiceCollectionExtensions` | 注册 `IBrowserCallerIdentityAccessor`（实现无状态，状态在工具执行作用域）并把实例交给工厂 |
| `ConnectedDesktopCallContextFactoryTests` | ＋3 条：身份来自调用作用域且退出后清空、子代理带父任务、**投影失败 ⇒ 上下文没有 caller**（而不是补默认值） |

## 闭环形状（gRPC 能力通道）

```
工具执行（BrowserAgentToolBase.BeginExecutionScope）
  ⇒ BrowserCallerIdentityScope.Push(投影结果)          §3.1
  ⇒ ConnectedDesktopCallContextFactory.TryCreate        §3.1（本轮接上）
  ⇒ DesktopCallContext.BrowserCaller
  ⇒ CoreCommandEncoder.Encode ⇒ proto CapabilityCommand.caller(7)   §3.2（上两步）
  ⇒ Desktop CoreFrameMapping.Decode（严格校验 + 浏览器能力必须有身份）  §3.2（上一步）
```

## 过程中抓到的一个**静默失效**（诚实登记）

我第一次是用字符串替换改 `TryCreate` 的方法体，替换**没匹配上**（换行差异），
结果是：字段加了、编译通过、**方法体其实没带身份** —— 典型的"看起来接上了"。
新加的用例立刻变红（`BrowserCaller` 为 null）⇒ 按行重写方法体后复验通过。
教训与仓库既有记录一致：**跨文件接线不能靠字符串替换，必须有行为用例钉住**。

## 验证

| 项 | 结果 |
|---|---|
| `ConnectedDesktopCallContextFactoryTests` | 全绿（＋3 新；含"投影失败不补默认身份"） |
| **全量链** | **1650 / 0**、一次通过、无重试（7 套件） |
| 端到端拒绝路径 | 由 `DesktopConnectionTests.CallerIdentityDecodeTests`（上一步 7 条）继续覆盖 |

## 诚实边界（诚实登记）

- **Bridge（WebSocket）传输尚未携带身份**：本轮打通的只有 gRPC 能力通道；Bridge 侧 envelope 身份是下一步。
- **协议仍是 v1**：v2 升级（含"旧新配对明确拒绝"）仍未做。
- **仍未调用 `Admit`**：本条只保证"身份能到达 Desktop 并被校验"，实际准入/租约（I2）未接。
- **`PermissionEvidenceSummary` 未参与授权**（未放宽）。
- **未真机验证**。
