# 2026-10-21 LLM重试事实与执行身份修复

- `LlmCallDiagnosticsScope.cs` / `DirectLlmClient.cs`：流式和非流式调用共享调用内尝试列表，保留逐次耗时、体积、阶段和真实 retried/failed 状态。流式 yield 后显式传递诊断作用域，避免丢失已产出增量事实。新增消息数/工具数分类证据。
- `LlmFailureDiagnostics.cs`：异常携带最多32条尝试快照，不保留请求正文、异常实例或凭据；包装超时异常继承明细。
- `TerminalDiagnosticExport.cs`：报告优先投影采集的完整尝试；无明细时只显示确实知道的终态，不把可重试误当成已重试。
- `AgentExecutionService.cs`：报告 TurnId 取 canonical 执行身份，ExecutionId 取 RunId，消息 ID 单独保留。
- 验证：Runtime 定向测试35/35通过，包含流式/非流式重试耗尽、首块之后禁止重试、canonical身份、Adapter诊断白名单、视觉路由及流式时限。产物位于 `temp/build/llm-runtime`，结果位于 `temp/test-out/llm-followup/diagnostic-complete.trx`。
- 未完成：此提交尚未部署；独立 Node/.NET/curl 合成大请求仍能复现上传中断，正在对比用户提供的 Harness 适配器，不把诊断修复表述为传输故障已解决。
