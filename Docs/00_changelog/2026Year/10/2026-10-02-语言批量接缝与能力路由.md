# 2026-10-02 语言批量接缝与能力路由（D3/D4）

## 改动

- 新增 `Source/PuddingCodeIndex/Contracts/CodeIndexBatchContracts.cs`：
  - `CodeIndexConsumerStatus` **四态互不替代**：`Applied`；`NotApplicable`＝**能力路由结果**
    （该文件不属于这个消费者，不是索引成功/失败、「忽略整个文件」的同义词）；
    `Retryable`＝本轮没处理成、带路径级原因，应退避重试而**不是**升级整仓；
    `ScopeRunRequired`＝该消费者只能给项目级结论（例如没有按文件能力），交调用方决定；
  - `CodeFileIndexPayload`：提取结果（文件记录/符号/引用/关系），**不写库**，由调用方经
    `ReplaceFilesAsync` 与源指纹**同事务提交**（结构上消除「提取失败但旧结果已删」的窗口）；
  - `CodeIndexBatchContext`（配置指纹 + 策略指纹 + 世代号：批内复用一个工程快照的键）、
    `CodeIndexFileBatchResult`（含 `SessionKey`，让「批内是否重复打开工程」可观测）；
  - `ICodeIndexFileBatchUpdater`：**可选**批量接缝（实现必须按批次复用一个有界工程/编译快照）。
- `Source/PuddingCodeIndex/Services/CompositeCodeIndexer.cs` 实现该接缝：
  按 owner 语言分组（**同一语言一次调用**，不再每个文件一次）；没有语言认领 ⇒ `NotApplicable`；
  owner 只有逐文件能力 ⇒ 调它并把结果映射为 `Applied`/`Retryable`（语言级失败变成重试，不再升级整仓）；
  两者都没有 ⇒ `ScopeRunRequired`；语言抛错或**静默丢掉**某条路径 ⇒ 该路径 `Retryable` 带原因，
  其余路径/语言不受影响；结果按路径稳定排序去重。
  逐文件 `IndexFileAsync` 的既有 `Failed` 合同**未改动**（它服务于调用方的升级语义）。
- 新增 `Source/PuddingCodeIndex/Services/CodeFileSemanticDiff.cs`（纯函数）：新旧符号集 →
  需要让依赖方重新绑定的符号 id（消失 ∪ 名称/种类/签名/容器变化）；**行号变化不算**、**新增符号不算**、
  首次索引（无基线）返回空 —— 依赖扩展必须建立在这份差异上。
- 新增测试：`CompositeCodeIndexerBatchTests`（11 条）与 `CodeFileSemanticDiffTests`（8 条）；
  语言替身 `FakeLanguageIndexer` 增加批量能力（可脚本化结果/异常/会话键）。

## 验证

- `dotnet test Source\PuddingCodeIndexTests\PuddingCodeIndexTests.csproj` → **280 通过 0 失败**（本次 +19）。
- 关键用例：同语言多文件只调用一次批量接口且上下文原样传递；无 owner ⇒ `NotApplicable` 且不进入任何语言批次；
  `Applied` 的 payload **原样**交给调用方（不在这里写库）；语言报 `Retryable` 原样透传（不升级）；
  只有逐文件能力 ⇒ 映射 `Applied`/`Retryable`；两者都没有 ⇒ `ScopeRunRequired` 带原因；
  语言抛错只影响它自己的路径；语言静默丢路径被判为 `Retryable`；结果排序去重、空批不调用任何语言；
  `SessionKey` 可观测；语义差异的 6 类边界（消失/签名/名称种类容器/行号/新增/首次索引）。
- 组件边界不变（`ProjectReference` 仍为空，不引用语言智能）；`ComponentBoundaryTests` 保持通过。

## 未完成与影响

- **Roslyn 侧的批量实现尚未落地**（本轮只交付合同 + 聚合路由 + 纯差异函数）：
  `RoslynCSharpIndexer` 目前仍逐文件打开工程并自己写库（`ClearSymbolsForFileAsync` + 分次 upsert），
  尚未实现「批内一次打开工作区并返回 payload」，也不产出 `CodeFileSemanticChange`；
  TypeScript/Python 同理。因此**批内复用工程**的状态仍未达成 —— 这是下一轮的重点，
  在 `PuddingCodeIntelligenceTests` 边界独立验证。
- **仍未接入维护链路**：没有任何调用方使用批量接缝；`CodeIndexMaintenanceService` 仍走
  `ICodeIndexFileUpdater.IndexFileAsync`，因此运行中实例仍是零行为变化。
- `NotApplicable`/`ScopeRunRequired` 目前只在新批量路径上是「不升级」的；旧逐文件路径的
  `Failed → 升级` 语义保持不变，接线阶段才切换。
