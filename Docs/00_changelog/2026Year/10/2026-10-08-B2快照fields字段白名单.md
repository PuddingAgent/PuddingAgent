# 2026-10-08 B2 快照 fields：字段白名单，且只抓要的表示

## 目标 / 背景

设计 §151：「`browser_snapshot` 参数新增 mode、format、scope(locator/ref)、**fields**、limit、maxBytes、
cursor、sinceRevision」；§161：「输出含 representation、scope、returnedCount、revision、truncated、
reason、nextCursor」；§151 还要求「**同次默认只返回一种表示**」。

第 25 轮把 `fields` 做到了 locate。本轮把同一参数扩到快照，并借它解决一个**真实浪费**：
`full` 模式下工具会同时抓取并返回 **三种表示**（DOM 文本 + 无障碍树 + HTML）——大页面上每一份都是
MB 级，而调用方通常只要其中一种。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| 契约 | `Source/Pudding.Contracts/Desktop/OutputFieldSet.cs`（新增） | 白名单的**通用实现**：核心字段恒在、可裁剪字段才是作用面、线名 ↔ 输出 JSON 键一一对应、未知即拒、空白等价于没给。解析与错误语义**只有一份** |
| 契约 | `Desktop/ElementFields.cs` | 改为基于 `OutputFieldSet` 的薄门面（locate 的两张清单），对外 API 不变 |
| 契约 | `Desktop/SnapshotFields.cs`（新增） | 快照的两张清单：核心 `mode/truncated/truncationReason/nextCursor`；可裁剪 `accessibilityTree/domText/html/nodeCount/returnedLines/bytes` |
| 工具 | `BrowserSnapshotTool` | `fields` 参数：未知字段 ⇒ `browser_invalid_arguments` 并回**合法清单**；按白名单裁剪输出；**并据此决定向驱动请求哪些表示**（`BuildOptions` 里把 `fields` 与 `include_dom`/`include_accessibility_tree`/`include_html` 取与） |

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.ContractsTests` | **127 / 127**（原 125 ＋ 2） |
| `PuddingBrowser.AgentTools.Tests` | **51 / 51**（原 49 ＋ 2） |
| `PuddingHost.Tests` · `PuddingDesktop.Tests` · `DesktopSurface.BrowserTests` · `DesktopServiceTests` · `AutomationTests` | 257/257 · 316/316 · 63/63 · 220/220 · 194/194 |

新增门禁：

- 契约层：快照白名单与元素白名单**共享同一套解析语义**（核心恒在 / 未知即拒 / 空白等价于没给 /
  默认不裁剪）；三种表示**都必须是可裁剪字段**（否则"同次只返回一种表示"无法表达）；
  `OutputFieldSet` 作为通用件自身的语义（含构造期拒绝 null）；
- 工具层：`mode=full` + `fields:["domText"]` ⇒ 输出只有 `domText`，
  **且驱动侧收到的请求 `includeDom=true / includeAccessibilityTree=false / includeHtml=false`**
  （"只抓要的"是可验证的，不只是输出层裁剪）；`mode=outline` + `fields:["accessibilityTree"]` ⇒
  文本仍在、`returnedLines`/`bytes` 被裁掉；未知字段 ⇒ 明确报错并回合法清单。

**取红实测**：把 `BuildOptions` 里的 `fields` 过滤去掉（三种表示都请求）⇒
`Snapshot_FieldsTrimTheOutputAndOnlyFetchTheRequestedRepresentation` **恰好变红**；复原后 51/51 复绿。

## 已知边界（诚实登记）

- **默认（不传 `fields`）行为不变**：`full` 模式仍会按既有 `include_dom`/`include_accessibility_tree`/
  `include_html` 三个开关（默认全开）返回三种表示。设计要求"同次默认只返回一种表示"，
  本轮把它变成**调用方可表达的**（传 `fields` 即可），但**没有改默认值**——改默认会静默改变既有
  排障行为，应作为单独一次有意的破坏性变更（并同步更新既有用例）。
- **`fields` 不能裁剪 `mode`/截断事实**：它们是"这份结果能不能信"的判断依据，刻意恒在。
- **`format`（markdown/compact_json）与 `scope`（locator/ref）、`sinceRevision` 仍未实现**：
  `fields` 解决的是"要哪些字段"，不解决"要哪种结构化形态"。
- **快照输出键名沿用既有**（outline 模式的文本仍放在 `accessibilityTree` 键下）：这是既有形态，
  本轮没有为它改名（改名会破坏既有调用方），§161 要求的 `representation`/`scope` 字段属后续设计工作。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_snapshot` 新增 `fields`；不传时行为完全不变。
  传了以后输出更小，**并且驱动侧少抓不用的表示**（真省内存与时间，不只是省 token）。
- 无数据/配置影响；线缆 DTO 未改动（`fields` 是工具侧参数，映射到既有的 `include_*` 开关）。
- 回滚：还原上表 4 个生产文件与 2 个测试文件及 code_map。
