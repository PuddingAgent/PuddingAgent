# 2026-10-18 浏览器执行管线接线与页级只读准入（F1 内部侧）

## 目标与结论

接通审阅报告 F1 的**默认 Bridge 截图路径**（ADR-097 D2：浏览器执行部分从能力通道生命周期解耦；D4：页级授权来源）：

- 浏览器工作区就绪即构造**传输无关**执行器，`CapabilityExecutor` 不再依赖能力通道是否启用；
- 默认 Bridge 路径补上**页面/上下文登记与真实版本喂入**（此前 `AttachBrowserTargets` 只在通道启动时调用，默认路径两个注册表为空、版本恒 Unknown ⇒ 即使接上执行器也会 `invalid_target` / `page_version_mismatch`）；
- 旧 authority 的页级 grant 准入在默认 Bridge 没有签发者。本切片只对**只读操作 + 用户选中的 Agent 目标页**放行（页级基线，不签发租约），写操作仍必须走 grant/租约（不给 F3 的“桥在线即放行”留回口）。

**边界声明**：这是“内部侧接线 + 组件级证据”，不是产品功能完成。真实 WinUI/WebView2 截图、视觉模型收到图片、Agent 使用工具链仍待 I3/I4（两段式验收）。

## 改动

- `Source/Pudding.DesktopService/DesktopService.cs`：构造参数新增 `readOnlyPageBaselineAdmission`；`ValidateAdmission` 在 authority 拒绝且 `BrowserOperationPolicy.IsReadOnly` + 目标页基线成立时放行（`lease = null`），其它拒绝不变。
- `Source/Pudding.DesktopService/DesktopBrowserExecutorComposition.cs`：工厂缺省把页级基线接到 `BrowserPageLifecycle.HasSufficientPageGrant(..., Read, now)`，Shell 无需引用 Automation。
- `Source/PuddingDesktop/Hosting/DesktopApplicationCoordinator.Capability.cs`：
  - 新增 `InitializeBrowserCapabilityPipeline()`（幂等，UI 线程）：控制面、目标登记、UI 缝隙、`IDesktopBrowserExecutor` 一次构造；失败只记日志并保持 null（截图路径明确失败，不伪造成功）。
  - `AttachBrowserTargets` 上移至此并增强：上下文惰性登记（避免“先页面后上下文”在 UI 事件里抛异常）、登记真实页面版本、`PropertyChanged` 时逐页补推版本/活动页/目标。
  - `CapabilityExecutor` 优先返回工作区执行器；能力通道启动复用同一批 dispatcher/surface/taskBindings，不再自己登记目标。
  - 新增 `DisposeBrowserCapabilityPipelineAsync()`，窗口退出时先关执行器再清登记。
- `Source/PuddingDesktop/Hosting/DesktopApplicationCoordinator.cs`：工作区初始化成功后调用管线构造；`DisposeAsync` 在释放运行时之前释放管线。
- `Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs`：新增 `internal TryGetPageVersion(PageId, out long)`（未知返回 false，不伪造 0）。
- 测试：新增 `Source/Pudding.DesktopServiceTests/BrowserReadOnlyBaselineAdmissionTests.cs`（截图在“仅用户选页”时到达 UI 缝隙；未选页时在 surface 之前拒绝；写能力不能借用只读基线）。
- 索引：`Source/Pudding.DesktopService/code_map.md`、`Source/PuddingDesktop.WpfArchive/code_map.md` 更新当前语义。

## 未完成与影响

- **F1 仍待产品级验证**：controller→执行器→surface 的运行路径只有编译 + 组件级准入证据；真实截图字节、分块完整性、工件与模型视觉输入属 I3/I4。
- **执行器尚未承接普通页面命令**：Bridge 的导航/快照/交互仍由 controller 直接执行（F2 后半/统一执行器仍待 I2）；本轮没有把“共享 authority”当作统一执行器的替代。
- **会话权威（I2）仍未接入**：owner/交页 round-trip、写世代与唯一票据尚未进入生产装配；页级基线是显式迁移期例外（`readOnlyPageBaselineAdmission`），不允许扩展到写操作。
- 已知环境问题：本轮第二次全量 Shell 构建曾因 `Source/PuddingPlatformAdmin/dist` 静态资源不一致在 **Core bundle** 步骤失败（他方前端 WIP 的产物状态），第三次重跑成功；该失败与本提交代码无关，但说明交付链仍应在干净 worktree 内执行。
- 回滚 = revert 本提交；无配置/数据变更。
