# 2026-10-08 控制面载荷进线缆（proto + 冻结守卫同步）

## 交付

| 件 | 内容 |
|---|---|
| `desktop_capability.proto` | ＋`BrowserBindingApplyCommand`（task=1/target=2/scope=3/validity_ms=4/source=5）、`BrowserBindingRevokeCommand`（task=1/target=2）；`CapabilityCommand` oneof ＋`binding_apply = 26`、`binding_revoke = 27` |
| `WireContractSnapshotTests.cs` | ① `PayloadOneof_IsClosedWhitelist`：16 ⇒ **18**；② `CommandAndResultFieldNumbers_AreFrozen`：`CapabilityCommand` 元组追加 `("binding_apply", 26),("binding_revoke", 27)`；③ 同用例 `PayloadOneofCase` 名单追加 `"BindingApply", "BindingRevoke"` |

**为什么必须一次改全**：wire 契约有三处刻意冻结（oneof 数量白名单、字段号元组、oneof 枚举名清单）。前两轮我只改到一部分，连续被拦。

| 套件 | 结果 |
|---|---|
| `Pudding.Rpc.ProtocolTests` | **20 / 20** ✅ |
| `Pudding.CapabilityBrokerTests` | **93 / 93** ✅ |
| `Pudding.DesktopConnectionTests` | **87 / 87** ✅ |
| 全量链 | **未跑**（本轮只涉及 wire 契约与其三个相邻套件） |

## 诚实边界

- **两侧映射未做**：proto 有了，但 `CoreCommandEncoder` 的 `Encode` 与 `Pudding.DesktopConnection/Mapping` 的 `Decode` 尚未处理这两个载荷（会有分支/指纹的缺口）⇒ **端到端仍不可用**。
- **`DesktopService` 分支未做**：收到申请调用 `BrowserTaskBindingService.Accept/Revoke` 并回 ack 未实现。
- **撤销 ack 的 `GrantId` 语义**未定义（撤销成功时是被撤的那个）。
- **未真机验证**。
