# 2026-10-08 按文档实现 full 模式输出预算

## 实现（§6.1 模式表）

| 文档要求 | 落地 |
|---|---|
| **默认 16 KiB** | `FullModeDefaultMaxBytes = 16 * 1024`（`args.MaxBytes` 未给时用它） |
| **硬上限 64 KiB** | `FullModeMaxBytes = 64 * 1024`；请求更大 ⇒ **参数错误拒绝**（不静默夹到上限） |
| **分页/截断声明** | 超预算时收敛内容并如实标注：`Truncated = true` |
| **`output_budget` 与 `incomplete_scan` 不混淆** | 仅输出收敛 ⇒ `output_budget`；仅扫描缺内容 ⇒ `incomplete_scan`；**两者同时** ⇒ `incomplete_scan+output_budget`，并分别进 `warnings` |
| **不能砍 JSON 尾巴** | 收敛方式是**缩减内容字段**（每次把最长一路（domText/accessibilityTree/html）砍半），JSON 始终保持可解析 |

## 诚实边界（诚实登记）

- **残留缺口：full 模式无续读游标**。文档说 `output_budget` 可续读（值类型的注释也这么写），但 full 路径**没有**游标实现
  ⇒ 我把语义限定为"**缩小预算或收窄 fields 重试**"，并在用例里断言 **不给假游标**。要真正续读需要给 full 设计游标
  （按表示 + 偏移、绑定页面版本），登记为后续工作。
- **计量口径是"默认序列化选项下的 UTF-8 字节"**：与真实响应写出时的选项若不完全一致，边界会有极小偏差（登记）。
- **收敛顺序与粒度是启发式**（最长一路砍半）：它保证"不超预算且可解析"，不保证"信息量最优"（登记）。
- **新增一处 flake 观测**：`PuddingDesktop.Tests.Debug.DesktopReverseProxyIntegrationTests.Get_AdminDeepLinkWithoutExtension_RewritesToSpaIndex`
  本轮失败过一次、重跑通过；与本次改动**无关**（反向代理/SPA 深链，不涉及浏览器快照）。**只登记、不代改**。
- **未真机验证**；决定（B1 可信调用身份）仍未拍板。
