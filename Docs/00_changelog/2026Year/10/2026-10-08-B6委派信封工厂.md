# 2026-10-08 B6 委派信封工厂：工具清单来自代码事实

## 目标 / 背景

B6 的委派由 Core 的 `spawn_sub_agent` 发起，但那个入口在 **`PuddingRuntime` / `PuddingPlatform`**（另一个子系统，
有自己的测试与边界），本轮不越界去改它。取而代之，给出**浏览器侧、可被它消费**的件：
委派信封的**工厂** —— 因为"浏览器有哪七个工具、哪些是必需"是**本程序集的代码事实**，
让 Core 侧自己拼字符串就会出现编译期发现不了的漏配（设计明写：注入列表必须包含任务实际需要的工具）。

## 改动

| 文件 | 改动 |
|---|---|
| `BrowserDelegationTasks.cs`（新增，AgentTools） | `Create(...)`：只读任务要求 `browser_snapshot`；可写任务额外要求 `browser_navigate` + `browser_interact`；注入列表 = 必需 ∪ **真实工具全集**（`BrowserAgentToolIds.All`）；`TryCreate(...)` 立即用 `BrowserDelegation.TryValidate` 自检并给出原因 |
| `SubAgentDelegation.WriteTaskRequiredTools`（**更正**） | 见下 |
| 测试 | AgentTools ＋6：只读/可写工具清单、额外必需工具去重、**子范围超出父范围被拒**、缺 grant/预算超限被拒、null 范围抛异常 |

### 更正（2026-10-08）：我 round-65 写错了一处

`BrowserDelegation.WriteTaskRequiredTools` 原先按设计示例写成
`["browser_navigate", "browser_screenshot"]`，但**本仓库的浏览器工具面没有 `screenshot` 这个工具**
（截图能力存在，但它不是七项工具之一）。后果是：**每一个可写委派都会被判不合格**。

这是"照着文档示例写代码"而不是"照着代码事实写"。现改为 `["browser_navigate", "browser_interact"]`
（设计里"须包含 navigate/screenshot"的意图由 `browser_interact` 的真实输入承担），并在代码注释里写明原委；
相应用例改名为 `WriteCapableDelegationsMustHaveNavigateAndInteract`。

**这个错误是被本轮工厂的用例逼出来的** —— 工厂用真实工具 ID 填清单，而校验器要求一个不存在的 ID，
两条一撞就红。这正是"把代码事实当唯一真源"的价值。

## 已知边界（诚实登记）

- **仍未接进 Core 的真实委派路径**：`spawn_sub_agent`（`PuddingRuntime/Tools/BuiltIns/Agents/SubAgentTool.cs`）
  与 `ISubAgentManager` 在另一子系统，本轮**只做只读勘查**，未改一行 —— 接线属跨子系统改动，需要单独一轮。
- **工厂不决定策略**：它只把"哪些工具必需"按代码事实填好；范围收窄/预算/页面 grant 由调用方给出，
  合格性由 `BrowserDelegation.TryValidate` 判定（工厂不重写规则）。
- **注入列表给的是浏览器工具全集**：真实委派时 Runtime 仍应结合任务与权限再裁（本工厂保证"至少不漏必需项"）。
- 真机无关（纯构造与校验）。

## 影响与回滚

- 新增工厂 + 更正一处常量：**行为影响**是"可写委派不再因要求不存在的工具而被拒"（此前是错误拒绝）。
- 回滚：删除工厂与其测试、把常量改回（但那样每个可写委派都会判不合格）。
