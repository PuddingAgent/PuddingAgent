# 浏览器初始空白文档版本修复

## 改动与原因

用户授权默认助手在本地测试页验收。配套更新到 bad4631 后，context/tabs 发现成功；不带 URL 的新建页返回 `tab action 'new' returned no live page version`。真实 WebView2 已初始化，但驱动只在后续导航事件递增版本，初始文档停在 0。

- `Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs`：仅真实 surface 初始化完成时从版本 1 开始，同步 Info；无 surface 保持 0。WinUI 链接同一驱动源码，无需新依赖或协议兼容分支。
- `Tests/PuddingBrowser.WebView2.Smoke/Program.cs`：改从空白页开始，检查页面/列表/Info 一致性、真实 DOM 可读、首次导航推进版本；失败输出栈。原 smoke 在滚动后复用旧 ref，改为动作前新观察，并先确认 ref 可用再验证导航令其失效。
- 更新驱动索引、ADR-097 D5 与实施方案 §3.4，保留后置校验。

## 验证

隔离产物使用 `--artifacts-path temp/build/recovery`，TestSite 监听 127.0.0.1:5560；各次浏览器 DataRoot 位于 `temp/test-out/browser-blank-*`。

1. 修复前真实 WebView2 回归退出 1：`page=0, list=0, info=0`；DOM 读取本身成功。
2. 修复后独立 smoke 退出 0：`blankVersion=1`、`finalContainsSaved=true`、`staleCode=stale_element_reference`；最终版本 4、30 个初始节点。构建 0 警告 / 0 错误。
3. Desktop Browser 定向测试 162 / 162 通过；三份改动文档 Front Matter 检查通过。全 Docs 链接检查有 24 个既有失效目标，均位于本次未修改的历史架构/QA/任务索引，改动文档无失效链接。
