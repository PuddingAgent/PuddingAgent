# R4 风险发现：成功路径"必须撤销"断言失败

| 项 | 内容 |
|---|---|
| 做法 | 按正解改造**两个既有成功 spawn 用例**：注入委派假件 + 断言 `HasCount(1, RevokedRunIds)` 且 `AreEqual(result.RunId, RevokedRunIds[0])` |
| 结果 | **2 条失败**（1440/1442）⇒ **断言不成立**；守卫**自动回退**（树绿、未提交） |
| **三种可能** | **① 撤销覆盖不完备**（该收尾路径未经过我的四个站点 ⇒ **授权泄漏**）· ② **时序**（撤销在 `SpawnAsync` 返回后异步发生）· ③ **夹具差异**（测试替身不走真实收尾链路） |
| **下一轮首要动作** | 用诊断确认失败是"**列表为空**"（⇒ ①/③）还是"**不相等**"（⇒ ②） |
| 若为 ① | **这是必须修的产品缺陷**，**优先于** R4 ⑥ Host 实现 |
| 代码层相邻事实 | `RevokeBrowserDelegationAsync` 出现 **6 次**（定义 1 + 调用 5）—— **代码齐备，行为层未证实** |

## 方式学收获

**LF 归一化匹配**是本轮能命中锚点的关键（here-string 为 LF、文件为 CRLF ⇒ 此前全部失配）。

## 诚实边界

- 本轮**无净产出**，但**发现一处可能的泄漏风险并要求先查清**；**未真机验证**。
