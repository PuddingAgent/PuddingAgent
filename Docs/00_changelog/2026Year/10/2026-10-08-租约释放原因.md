# 2026-10-08 B6/S4：取消/超时/接管在账本里可区分

## 起因（拆解表 S4）

S-10 的期望是"**取消/接管/超时都回收许可**"。此前账本只能证明"**收回了**"，
无法区分**哪种结束** —— 而三者对后续判定的含义完全不同：

| 结束方式 | 含义 |
|---|---|
| 超时 | 子代理**没干完** ⇒ 结论可能不完整（父代理不该把它当完成品） |
| 取消 | 父代理**主动放弃** |
| 接管/撤权 | **用户插手** ⇒ 该页此后要重新授权 |

## 改动（都在 `SubAgentDelegationLeases.cs`）

| 项 | 内容 |
|---|---|
| 新类型 | `BrowserLeaseReleaseReason { Completed, TimedOut, Cancelled, TakenOver }`、`BrowserLeaseRelease(SubjectId, IsPage, Reason)` |
| 新重载 | `EndDelegation(delegationId, reason)`、`RevokePage(pageId, reason)`；**旧签名保留**（默认 `Completed` / `TakenOver`）⇒ 源兼容 |
| 释放记录 | `RecentReleases`（最旧→最新），上限 `MaxReleases = 16`（**有界**，否则它自己就是内存增长点） |
| 记录条件 | 委派：确实有登记时记一条；页面：**确实有东西可撤**时记一条（无东西可撤时不刷无意义记录） |
| 明确边界 | 记录是**纯诊断事实**，**不参与**任何授权判定（超时记录不会让该页此后拒绝授予） |

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **328 / 328**（＋3；租约用例 15 → 18） |
| 新增用例 | ① 三种结束 + 接管在 `RecentReleases` 里**顺序与原因**都正确（委派级 vs 按页也正确）；② 记录**有界**（48 次释放后仍只剩 16 条）且不影响授权；③ 无东西可撤 ⇒ 不记录，但撤权本身仍生效 |
| **取红实测** | 去掉委派级的 `RecordRelease` ⇒ **2 条用例变红**；还原 ⇒ 328/328 |
| 冻结公开面 | 新公开类型已在 `ComponentSurfaceTests` 的冻结清单登记（**先红后绿**：加类型后该用例立刻报 `added=[…]`） |

## 诚实边界（诚实登记）

- **公开面有增量**（两个新类型 + 两个重载 + 一个属性）：已按门禁显式登记，调用方需知晓。
- **只读观察者仍看不到这一层**：`RecentReleases` 是**组件内存**里的诊断；外部 smoke 能看到的是工具回执，
  两者尚未打通（接线属 S7/S8，被决定①/②挡住）。
- **记录会被挤掉**（16 条上限）：它证明"最近发生过什么"，**不**是审计日志（真正的审计另有去处）。
- **未覆盖"超时后父代理能否重写"的端到端**：本轮只到账本层（S5 的端到端仍待做）。
- 无产品行为变化（组件 + 用例；生产路径尚未调用带原因的重载）。
