# 2026-10-08 ack 上线（第二步：两侧编解码）

## 交付

| 侧 | 改动 |
|---|---|
| Desktop→Core **编码** | `DesktopFrameMapping.Result(...)`：`BrowserBindingApply` / `BrowserBindingRevoke` 两个 case ⇒ `Proto.BindingAckOutcome { Accepted, GrantId, Reason }` |
| Core 侧 **解码** | `DesktopResultDecoder`：`BindingAck` 结果分支 ⇒ `FromBindingAck(new BrowserBindingAck(accepted, grantId, Epoch, reason))`；空 `grant_id`/`reason` ⇒ **null**（不造默认值） |
| 能力匹配 | `BindingAck => expectedCapability is BrowserBindingApply or BrowserBindingRevoke`（撤销共用同一 ack） |

| `Pudding.Rpc.ProtocolTests` | 见运行输出 |

## 诚实边界

- **`epoch` 字段暂按 0 编解码**：`grant_id` 与 `reason` 已如实往返，但 grant epoch 的语义在 ack 上未定（本轮不做臆断）；已在两侧注释标记。
- **端到端发送用例仍未写**（生产者 → `SendAsync` → 假流回 ack ⇒ 生产者如实还原）——这是"闭环真的通了"的最终证据，下一步。
- **未跑全量链**；**未真机验证**。
