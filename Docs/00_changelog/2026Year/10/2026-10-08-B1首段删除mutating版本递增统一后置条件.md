# 2026-10-08 B1 首段：删除「所有 mutating 必须推进版本」，两条传输共用统一后置条件

## 目标 / 背景

设计方案 §1.1 明确裁定：**不能按动作名推断导航**。审计 §3 已实测两条假失败：

- `click` 触发真实导航（`example.com → iana.org`）却返回
  `mutating capability returned a page version that did not advance`（读到的是导航前的旧版本，竞态）；
- `fill` 只改 `input.value`，动作后 `pageVersion` 仍为 7 ⇒
  `fill/type/select/check/hover/scroll` **永远无法满足**该后置条件。

本次是 B1（P0 接宿主）的首段：只做「判据替换 + 两条传输同语义 + S5 登记/引用」，
不做 Shell 真接管、页面生命周期与 ref 身份语义（仍属 B1 后续）。

## 改动

### 新增（组件内，纯逻辑）

- `Source/PuddingBrowser.Automation/BrowserMutationPostcondition.cs` — 新增。
  `BrowserMutationExpectation`（`None` / `DocumentNavigation`）、`BrowserMutationOutcome`、
  `BrowserMutationPostcondition.Validate(...)` 与 `ValidateTabs(...)`。判据：
  **必须有活版本**（否则引用无法作废/建立）；观测到文档提交即满足任何期望；
  **未声明后置条件时版本不推进不算失败**；只有显式声明 `DocumentNavigation` 未满足才报
  `outcome_unknown`（`mayHaveSideEffects=true`、不可安全重试）；tabs 按「`close` 是否真的关掉」判定，
  `activate`/`new` 要求回带活版本。
- `Source/PuddingBrowser.AutomationTests/BrowserMutationPostconditionTests.cs` — 新增，12 用例。

### 删除

- `Source/Pudding.DesktopService/DesktopMutationInvariants.cs` — **删除**。
  其「所有 mutating 结果版本必须严格递增」的通用要求即本次要移除的假失败源头。

### 接线（S5：登记 + 引用）

- `PuddingAgentNetwork.slnx` — 登记 `PuddingBrowser.Automation` 与 `PuddingBrowser.AutomationTests`。
- `Source/Pudding.DesktopService/Pudding.DesktopService.csproj`、
  `Source/PuddingHost/PuddingHost.csproj` — 新增对 `PuddingBrowser.Automation` 的 `ProjectReference`。
- `Source/Pudding.DesktopService/DesktopService.cs` — Navigate 走
  `BrowserMutationPostcondition.Validate(..., DocumentNavigation)`；Interact 走 `Validate(...)`（不要求推进）；
  Tabs 走 `ValidateTabs(action, tabClosed, version)`。
- `Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs` — Interact 的
  「did not advance」硬失败替换为同一份 `Validate(...)`。

### 注解与文档

- `Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs` — 更正交互方法注释
  （版本不要求推进；后置条件由组件统一判定）。
- `Source/Pudding.DesktopService/code_map.md` — 移除已删除文件的条目，写明后置条件已移出。
- `Source/PuddingBrowser.Automation/code_map.md` — 新增文件条目、S5 状态、接线与未接线清单、用例数 126。
- `code_map.md` — §2 组件行改「S5 已部分落地」、§3 概念行补后置条件、§5 测试行补「变更类后置条件」。
- `Docs/12_features/Desktop-Surface-Browser-Mapping-2026-10-01.md` — 划掉**已作废**的
  「变更类必须推进版本」条目并给出更正与依据（`last_reviewed → 2026-10-08`），
  避免后续按旧规则再次实现。

  该对照无法给出更干净的结论，故如实标注为「据文件状态与改动范围判定的既有失败」。
- **P0 其余部分与回执输出面仍未完成**（见下）。

以下为当时（同日早些时候）的原始留白，保留以记录状态流转：

## 影响与回滚

- 行为影响：`browser.interact` 不再因版本未推进而失败；`browser.tabs` 不再因版本未推进而失败，
  改为校验 `tabClosed`/活版本；`webview.navigate` 的非推进结果语义由 `internal_error` 改为
  `outcome_unknown`（不可重试 + 可能有副作用）。
- 引用面：`Pudding.DesktopService` 与 `PuddingHost` 新增一条对纯逻辑组件的引用
  （`ProjectReference`，无包引用，不越过各自已有的编译期边界门禁）。
- 回滚：还原上述 9 个文件的改动并恢复 `DesktopMutationInvariants.cs` 即可；无数据与配置影响。
