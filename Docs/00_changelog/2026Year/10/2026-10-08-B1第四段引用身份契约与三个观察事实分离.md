# 2026-10-08 B1 第四段：引用身份契约与三个观察事实分离（设计 §5 / G4）

## 目标 / 背景

设计方案 §5 与 §1.1 给出两条硬要求，而现状都不满足：

1. **ref 只携带文档版本**：现有格式 `v{pageVersion}-n{seq}`，`WebView2DomClient.ValidateLocator`
   只比较版本号 ⇒ 设计点名的情况「跨页、跨 frame 使用同一版本号的引用」会被**静默接受**。
2. **身份取自页面可自写的属性**：节点身份是 `data-pudding-ref`（`WebView2DomClient.cs:249-252,340,397`
   由页面脚本写入）。设计明确禁止只信任它——页面可以随便写属性，但写不出宿主侧身份。
3. 设计把三件事混成了一个版本号：已提交文档世代、内容变更、滚动/缩放/布局观察。
   后果是「只读调用推进版本」「普通 value 改变作废全部引用」「滚动让节点身份失效」。
4. 设计 §1.1 **明令禁止**「过期 ref 按 role/name/序号自动重解析」。

本段交付的是这三条的**契约与判据层**（可独立测试），驱动接入是紧随其后的一步。

## 改动

### 新增（`PuddingBrowser.Automation`，纯逻辑）

- `Source/PuddingBrowser.Automation/BrowserRefIdentity.cs` — 新增：
  - `BrowserRefScope`（context/page/frame 三元组；`FrameId = null` 表示顶层文档；
    `IsSamePageAs` 与 `IsSameDocumentAs` 分开，frame 差异不会被页面相等吞掉）；
  - `BrowserObservationRevisions`（**三个分开的事实**：`DocumentGeneration` / `DomRevision` / `ViewportRevision`）
    与 `BrowserRevisionPolicy`：
    **只读调用零推进**、文档提交推三者、DOM 变更只推 dom、滚动只推 viewport；
  - `BrowserRefInvalidation`（分类作废：整页 / 单 frame / 单引用 / **不作废**两类）；
  - `BrowserRefDenial` + `BrowserRefDenialWire`（`unknown_ref` / `page_mismatch` / `frame_mismatch` /
    `document_changed` / `node_detached` / `revoked` / `viewport_mismatch`）；
  - `BrowserRefToken`（宿主绑定节点键 + 文档世代 + 视口修订 + **最小刷新提示**）、
    `BrowserRefDecision`（含 `ViewportStale`）。
- `Source/PuddingBrowser.Automation/BrowserRefRegistry.cs` — 新增：宿主绑定的引用登记表。
  - `Issue` 必须给宿主侧节点键（空即抛），引用值**不可解析**（`ref-{seq}-{guid}`），
    因此调用方无法凭 role/name 拼出一个「看起来相同」的引用；
  - `Validate` 依次判：登记表 → **页面** → **frame** → **文档世代** → 宿主存活；
    视口变化**不**影响身份，只置 `ViewportStale`；
  - `ValidateForCoordinates` 在此基础上额外拒绝 `ViewportMismatch`；
  - `Revoke` **分类**：`DocumentCommitted`/`PageClosed`/`BrowserProcessFailed` 作废该页全部（含所有 frame）；
    `FrameNavigated` 只作废该 frame；**`DomChanged`/`ViewportChanged` 返回 0（有意 no-op）**；
    整页类别缺 scope 抛参数错（空表也抛，不是静默返回 0）；
  - `RevokeRef` 处理单节点断开；`_revoked` 墓碑把「已作废」与「从未签发」分开报。

### 测试

- `Source/PuddingBrowser.AutomationTests/BrowserRefIdentityTests.cs` — 新增 30 条，含设计点名的反例：
  「两个页面都恰好处于 doc v7」仍必须 `page_mismatch`；同角色同名字的新节点**不让旧引用复活**
  （旧引用报 `revoked`，新引用独立有效）；普通 DOM 变更与滚动**不作废任何**引用；
  只读调用三个事实**全部不变**；`data-pudding-ref` 式可猜身份被 `Issue` 拒绝（缺宿主键即抛）。
- `Source/PuddingBrowser.AutomationTests/ComponentSurfaceTests.cs` — 公开面冻结表新增 8 个类型、
  逐类用例守恒表新增 `BrowserRefIdentityTests = 30`（组件测试面仍显式）。

## ⚠️ 已知缺口（**未**修复，诚实登记）

**驱动侧尚未消费本契约**，因此设计 §5 的缺口在**运行时仍然存在**：

- `WebView2DomClient.ValidateLocator`（`WebView2DomClient.cs:19-43`）仍只按 `v{pageVersion}-n{seq}`
  比较版本号 ⇒ **跨页/跨 frame 同版本号的引用仍会被接受**；
- 节点身份仍取自页面可自写的 `data-pudding-ref`；
- 三个事实尚未在驱动里分别维护（`IElementHandle.PageVersion`/`IBrowserPage.PageVersion` 仍是单一版本）。

接入需要两件事，属后续切片：

1. **宿主绑定的节点键**：首选 CDP `backendNodeId`；但本驱动的 CDP 仍是
   `NotSupportedException("CDP not in Phase 2A-1")`（`WebView2BrowserPage.cs:266/268`），
   属 B3 的 native 输入切片；过渡期可用驱动侧 `IElementHandle.Id`（宿主绑定，页面写不出来）。
2. **`WebView2BrowserPage` 持有登记表**，把自己的 scope 与三个事实传进
   `WebView2DomClient.ValidateLocator`，并把 `data-pudding-ref` 降级为「只能当提示」。

本条缺口已同时写入 `Source/PuddingBrowser.Automation/code_map.md` §6，避免被读成「已修复」。
