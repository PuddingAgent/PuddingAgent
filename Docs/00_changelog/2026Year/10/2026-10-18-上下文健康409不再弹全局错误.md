# 2026-10-18 上下文健康 409 不再弹全局错误（旧会话优雅降级）

## 1. 问题

打开一个 **2026-09-15 创建的早期会话**（`cf7fc8fa…`，`ChatMessages.AgentInstanceId` 为空、`Sessions.AgentId` 为空）时，前端每次进入会话都会弹红色 toast：

```
GET /api/sessions/cf7fc8fa…/context-health — HTTP 409 — 无法解析当前 Session 的上下文窗口。请检查最近一次 LLM usage 或 Agent 模板的 LLM 模型配置。
```

- 后端 409 是**符合契约**的：`ResolveSessionBindingAsync` 无法从会话/最新消息解出 Agent 实例 → `IContextCapacityResolver.ResolveAsync` 拿不到窗口 → `context_window_unresolved`。
- 前端 `serviceStatus.ts` 早已把 409 `context_window_unresolved` 定义为**非服务故障**（映射为 `unknown`），但 `api.ts` 的 `getContextHealth` 未设置 `skipErrorHandler`，于是 umi 全局 `requestErrorConfig` 仍按 HTTP 错误弹了 toast —— **toast 才是缺陷**（已知状态被当成错误）。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `src/services/platform/api.ts` | `getContextHealth` 请求增加 `skipErrorHandler: true`：409 由调用方按服务态纪律处理，不再进入全局 toast。 |
| `src/pages/chat/components/serviceStatus.ts` | 新增纯函数 `isContextWindowUnresolved(reason)`：仅 `response.status === 409 && response.data.code === 'context_window_unresolved'` 为真（409 但业务码不同仍走错误路径）。 |
| `src/pages/chat/components/IntentConsole.tsx` | context-health 被拒时：该已知 409 ⇒ `contextHealthError=null`（圆环按「未知/未配置」呈现，不进入 error 态）；其余错误保持原错误提示。 |
| 测试 | 新增 `api.contextHealth.test.ts`（请求选项带 `skipErrorHandler`、sessionId 编码）；`serviceStatus.test.ts` 增加 409 判定矩阵；`requestErrorConfig.test.ts` 增加 skipErrorHandler 不弹 toast；`IntentConsole.test.tsx` 增加「409 ⇒ 非 error 态」用例（并把桩数据的错误形状修正为真实 axios 形状 `response.data.code`）。 |
| `package.json` | 前端版本 `6.4.6` → `6.4.7`（缺陷修复，修订号）。 |

## 3. 验证（实际执行）

- `pnpm run jest -- …`：`api.contextHealth.test.ts` + `serviceStatus.test.ts` + `requestErrorConfig.test.ts` → **20/20 通过**；`IntentConsole` 的 409 新用例通过。
- `IntentConsole.test.tsx` 全文件：仍只有**既有环境性失败** 1 条（`sends voice transcript…`，在 `git stash` 回退本次前端改动后同样失败，可复现为 HEAD 基线问题，与本次改动无关）。
- `pnpm run tsc`：仅存量错误（`src/pages/chat/index.tsx`、`projections/executionFlowProjector.ts` 等，HEAD 基线已存在）；本次改动文件无 TS 错误。
- `pnpm run build`：通过（含 `check-chat-bundle-budget`；见交付说明）。
- 未部署：运行中的 Desktop/Core 仍是旧前端产物；需 `pnpm run build` + 重建 Core（`PuddingHostContent.props` 将 `dist` 拷入 `wwwroot/admin`）+ 重启后才能在进程内确认 toast 消失。

## 4. 未完成 / 边界

- 后端仍对「无法解析 Agent 实例的早期会话」返回 409（**这是如实语义**）；本修复只消除错误噪音，不伪造上下文窗口。用户在该会话继续发消息后会写入新的 Agent 绑定，context-health 即可正常解析。
- 未做真机（Desktop WebView2）冒烟：需要重建前端产物 + 重启 Core；本次未重启用户进程。
- 未改动后端 `requestErrorConfig` 的通用策略：其它端点真实的 4xx/5xx 仍会照常提示，只有 context-health 这条已知可降级链路 opt-out。
