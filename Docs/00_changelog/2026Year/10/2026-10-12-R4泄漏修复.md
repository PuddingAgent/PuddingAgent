# R4 缺陷修复：`ExecuteSyncAsync` 两条收尾路径的授权泄漏

| 项 | 修复前 | 修复后 |
|---|---|---|
| 异常/超时/取消路径（原 L384） | `TryRemove(..., **out _**)` ⇒ **不撤销** ✗ | `out var failedSyncRunId` ⇒ **撤销** ✓ |
| 成功路径（原 L447 → 现 L452） | `TryRemove(..., **out _**)` ⇒ **不撤销** ✗ | `out var completedSyncRunId` ⇒ **撤销** ✓ |

**为何确定修复前是 0 次撤销**：成功路径在 `CompleteRunAsync` 后**直接返回**、异常路径同理 ⇒ 这两条路径上**不存在其它撤销站点**（四个站点分别在 `SpawnAsync` L189/L278 · `CancelAllAsync` L477 · 启动失败 L1061）✓

**用例证明**：`ExecuteSyncAsync` 用例补断言 `HasCount(1, RevokedRunIds)` + `AreEqual(LastRequest.ChildRunId, RevokedRunIds[0])` ⇒ **修复前必失败（0）· 修复后通过（恰 1）**

**验证**：Platform 编译通过 · **`PuddingPlatformTests` 1446/1446** · `RevokeBrowserDelegationAsync` 出现 **8 次**（定义 1 + 调用 7）

## R4 撤销覆盖（修复后）

`SpawnAsync` 成功/异常/取消 · `CancelAllAsync` · **`ExecuteSyncAsync` 成功/异常** · `CreateTrackedRunAsync` 启动失败 ⇒ **两条入口、所有收尾路径均撤销** ✓
