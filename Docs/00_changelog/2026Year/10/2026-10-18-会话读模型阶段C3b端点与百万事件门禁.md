# 2026-10-18 会话读模型阶段C3b端点与百万事件门禁

## 改动

- 新增 `Services/AgentChat/AgentMainSessionResolver.cs`：Agent 主会话身份解析 redirect → Agent Manifest `MainSessionId` → canonical `FindMainAsync`；只做有界点查，校验 workspace/owner，失败返回 null；不再加载整个工作区会话列表。
- 新增 `Controllers/Api/ConversationOpenApiController.cs`：
  - `GET /api/workspaces/{ws}/agents/{agentId}/conversation-open`（统一打开快照；ETag/If-None-Match → 304；未知 Agent → 404）；
  - `GET /api/conversations/{id}/history`（键集分页；非法/缺失游标 → 400 稳定 code）；
  - `GET /api/conversations/{id}/process`（canonical sequence 分页；越界游标 → 400；空展示页前进）。
- Host DI：注册 `ConversationOpenQueryService`、`AgentMainSessionResolver`；`ISessionRepository` 接口映射补到 `InMemorySessionRepository`（PuddingController 原先只注册具体类型）。
- 新增测试：resolver 5 例、controller 4 例（200+ETag、304、404、400 稳定码），以及**百万事件查询门禁**测试（`PUDDING_QUERY_GATE=1` 显式运行）。
- 新增 [阶段 C 验收报告](../../../14_reports/会话加载优化阶段C验收报告-2026-10-18.md)：门禁数字、计划、语义边界、遗留与风险；更新 Platform code_map。

## 验证

- 身份解析 + 控制器定向测试：**9/9 通过**。
- 百万事件门禁（1,820,000 事件 fixture，事件插入 10.5s）：
  - `open` p95 **1.6ms**、`history` p95 **0.9ms**、`process` p95 **1.9ms**；
  - EXPLAIN：`SEARCH conversation_events USING INDEX ... (conversation_id=? AND sequence<?)`，无会话级全表扫描；`ChatMessages` 使用覆盖索引。
- 全量 `PuddingPlatformTests`：1513 passed / 2 failed（既有 artifacts-path 环境敏感：benchmark seed、Mcp.Cli）/ 1 skipped（默认跳过的查询门禁）；查询门禁显式运行 1/1 通过。
- `PuddingHost` 构建 0 error；Host composition **2/2 通过**（ValidateOnBuild 覆盖新服务与接口映射）。
- 未改 `D:\data`、未建真实索引、未重启 Core；旧 `/conversation` 与前端合同未改，用户可感知路径仍为旧实现。
- `front_matter`/`check_md_links`/`code_map_check` 结果见提交前门禁输出。

## 未完成与影响

- 阶段 C 的实现与查询门禁已完成，但**用户首屏仍走旧入口**：阶段 D 切换前端（单一打开 owner、缓存/条件请求/取消、分页接线）并退役旧 `/conversation` 与在线全量摘要路径。
- 真实 `D:\data` 未迁移：小表下次 Core 启动创建；conversation_events 两条索引需显式维护窗口（备份 + 记录耗时/磁盘）。
- 查询门禁为显式 ENV 运行（1.82M fixture 成本高），不是默认单测；CI 若强制应作为独立 gate 步骤。
- 真实 WebView2/DataRoot 副本的端到端 p95 属阶段 F 验收。
