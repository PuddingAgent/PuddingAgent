# 2026-10-18 前端D2b打开请求取消与迟到响应守卫

## 改动

- `ChatClientStore`：
  - `selectAgent` 维护选择级 `AbortController`：切换到不同 `workspace+agent` 时取消上一选择与后台校正在途请求；同一 key 重入若首次打开/刷新仍在途则加入既有单飞请求，不增加 generation、不重复拉取（对应 Plan §7.2）。
  - `syncSelectedAgent` 使用独立后台校正 `AbortController`，会话切换时一并取消；`finally` 只清理自己的 controller，避免取消新请求。
  - 迟到响应继续由 `selectionVersion`/`backgroundSyncVersion` 守卫丢弃，不写当前状态或缓存。
- `AgentChatApiPort.getConversation` / `getAgentConversation` 增加可选 `signal`，真实贯通到 `request` transport；不传 signal 时请求参数与既有行为完全一致。
- 测试：
  - store 新增「切换 Agent 会 abort 上一个打开请求，迟到 A 响应不覆盖 B」用例；
  - API 新增「选择 AbortSignal 透传到 conversation 请求」用例；
  - 既有 A→B→A、StrictMode/重复选择由单飞用例继续覆盖。
- 前端版本 `6.5.0 → 6.5.1`（取消/性能修复类）；frontend code_map 更新 ChatClientStore 边界。

## 验证

- `pnpm run build`：成功，`[chat-bundle-budget] ok sync=1383742 chat=358176 common=432183`。
- 未部署静态产物；旧 `/conversation` 仍是唯一打开路径，用户可感知路径行为不变。
- 未改 D:\data、未重启 Core。

- 剩余 D2c：`ChatClientStore`/`TurnSurfaceStore`/`MessageList` 消费统一快照（短消息全文、长消息预览+显式展开全文、活动 Turn 由读模型+SSE 补齐），接入历史/过程分页；
- D3：SSE 主消息/压缩事件进入同一合并入口、健康连接下移除整页轮询、退役旧 `/conversation` 与 `getAgentConversation`；构建部署并核对页角版本徽标。
