# 2026-10-18 修复 Bridge 结果合同与发现准入（R1/R2）

## 背景（F1–F4）

审阅确认：`context.getInfo` 经执行器路由后返回 `{contexts:[...]}` 列表包装，而 Core 按单个 `BrowserContextDescriptor` 解码 ⇒ 顶层必需字段全缺，发现链整体阻塞；另有 close 空响应被当作失败、back/forward/reload/stop 返回导航包装而非单页、发现逐页 `page.getInfo` 又受页面准入限制。按[修复方案](../../../12_features/浏览器发现契约与配套部署修复方案-2026-10-18.md) R1/R2 与 ADR-097 D8 执行。

## R1：按命令显式投影（Desktop 生产者 + Core 消费者）

- `BrowserBridgeCommandAdapter`：`context.getInfo` / `page.list` 必须明确 context（envelope 或 arguments）；两边冲突 ⇒ `conflicting context ids` 拒绝；缺失 ⇒ 参数错误。新增 `TryGetRequestedContextId` 共用规则。
- `BrowserBridgeResultAdapter`：新增单 context `FromContext(contexts, id)`（精确匹配；缺失 null；重复 id 属内部合同错误）与 `FromPageList(contexts, id)`（按 context 过滤）；新增 `FromNavigationPage`（从 NavigateResult 取单页描述符）。
- `BrowserBridgeExecutorRoute`：把 `switch` 改为**19 命令显式结果矩阵**，删除 `_ => FromContexts` 兜底：
  - `context.getInfo` 单对象，缺失返回 `browser_context_not_found`；`page.list` 按 context 投影；
  - `page.goto` 保持完整导航结果；`goBack/goForward/reload/stop` 返回单页描述符；
  - close 类无值成功；未知路由命令明确失败（不回退 handler）。
- `RemoteBrowserRuntime`（Core 消费者）：抽出 `SendAsync`（身份/期限/错误/operationId 关联校验），有值命令严格校验载荷并把 **command/operationId/期望 DTO/协议修订/阶段** 放入解码错误；`ExecuteEmptyAsync` 改为接受规范无值成功（副作用已完成不再被"没有 value"推翻）。

## R2：发现只读元数据，不逐页取得控制

- `BridgeBrowserCapabilitySurface.GetContextsAsync`：移除逐页 `context.GetPageAsync`（page.getInfo），改用 `page.list` 的 `PageInfo`（Id/Title/Url/PageVersion）投影；无活版本页不进清单；active/agentTarget/canGoBack/isLoading 取保守值并注明工具不得据此做准入。
- 发现仍只含元数据；内容读取/导航/交互/新建关闭继续由既有会话准入裁决。

## R3：真实生产→消费连通门禁（新增）

`Tests/PuddingHost.Tests/BrowserBridge/BrowserBridgeWireContractTests.cs`：链接 Desktop 侧 CommandAdapter/ResultAdapter/ExecutorRoute **生产源码**作为生产者，broker 原样转运路由结果，由**真实** `RemoteBrowserRuntime/Context/Page` 消费（不手工构造期望 JSON）：

- context list + 单个 getInfo（含不存在 ⇒ null）；
- page.list 按 context 过滤且**不出现 page.getInfo**（F4）；
- close 空响应被接受；
- goBack 走单页描述符合同（导航包装会解码失败）。

**反向对照**：临时 stash 三个生产适配器（保留 Core 修复）后运行该门禁 ⇒ **3/4 失败**（getInfo 包装、page.list 范围、历史导航合同），恢复后 **4/4 通过**。

## 未完成与影响

- 协议修订仍为 2（D9 要求整体提升到 3 并携带构建身份），发布清单与模块身份核对未做；
- `context.getInfo` 的 `UserDataDirectory` 仍为空串（执行器契约无目录字段，按方案不回填/不读用户目录）；
- page.list 发现面没有 active/agentTarget 等标志（D8 允许保守值；工具不得据此准入）；
- 运行中进程仍是旧构建；需 R4/R5 成套构建部署后才能用真实 Agent 验证三条用户预期；
- 回滚 = revert 本提交；不得只回退一侧（生产者/消费者合同成对）。
