# 2026-10-18 浏览器会话权威接入 Bridge 单一准入（I2 核心）

## 目标与结论

按 ADR-097 D3/D4 与[一期方案](../../../12_features/Agent浏览器控制一期整体实施方案-2026-10-18.md) §3.2/§3.3：把 I1 修好的 `PuddingBrowser.Authorization` 接进**生产生命周期端口**，并让 Bridge 页面命令走**单一准入**——用户交页 + 宿主注入的可信 Core 会话 owner + 唯一票据/写世代，触碰页面前复检同一票据，所有退出路径精确释放。

本轮完成 I2 的"授权/准入"核心；**尚未**把 Bridge 页面命令的执行迁移进 `DesktopService` 执行器（那是 I2 的下一半，见"未完成"）。

## 改动

### 组件（PuddingBrowser.Authorization，先独立验证）

- `AgentTargetSessionAuthority`：新增 **handover** 语义 —— `OfferTarget`（用户交页，只记录待交页，不产生可执行授权）+ `TryClaimOwner`（可信 owner 确认归属后才建立会话；已被其它 owner 占有时拒绝）。关页同时清理待交页；桥断开/撤销清空待交页。`AgentTargetSessionSnapshot` 增加 `PendingTarget`/`HasPendingHandover`，UI 可区分"待确认 / 已交出 / 无目标"。
- 组件测试 48/48（新增 8 条：交页不授权、首次确认、他人不能接管、幂等确认、换页失效、撤销/关页/断桥清理）。

### 生产生命周期（Pudding.DesktopService）

- `Pudding.DesktopService.csproj` 引用 `PuddingBrowser.Authorization`（只引用 Contracts 的纯规则组件）；边界守卫测试同步更新。
- `BrowserPageLifecycle`：内部持有 `AgentTargetSessionAuthority` 并接进所有生命周期点——桥 OnBridgeReady/Lost、`SetAgentTarget`（交页/撤销）、`SetPaused`/`SetUserTakeover`（两轴）、`ClosePage`/`CloseContext`（目标/待交页作废）。
- 新增 `BrowserSessionAdmission.cs`（**标量门面**，Shell/桥侧唯一可见面）：不透明 `BrowserSessionPermit`、`BrowserSessionControlHandle`、`BrowserSessionDecision`、`BrowserSessionStatus`、稳定拒绝码（与组件契约逐字一致，有测试钉住）。
- 门面方法：`TryClaimControlOwner` / `AuthorizePageCommand` / `RevalidatePageCommand` / `CompletePageCommand` / `CaptureSessionStatus` / `CaptureSessionTarget`。

### Bridge 派发器（PuddingDesktop.WpfArchive）

- 删除旧"页级 grant 闸门"（`HasSufficientPageGrant` + `page_grant_required`）；改为会话准入：
  1. owner 来自**宿主注入的 Origin**（`ConversationId ?? SessionId`），缺失/超长 ⇒ `browser_control_handle_required`；
  2. 可信 caller 身份仍必要（kind/callerId/taskId 完整），否则 `browser_unauthorized`；
  3. 首条可信命令 `TryClaimControlOwner` 确认交页归属；随后 `AuthorizePageCommand`（只读/写分级、写串行化、暂停/接管只阻断写）；
  4. 触碰 handler 前 `RevalidatePageCommand`（入队期间接管/切目标/换代/释放都会被拦）；
  5. `finally` 中 `CompletePageCommand`（取消/超时/异常同路径，幂等）。
- 无 PageId 的**引导/发现类**命令（context.list/getInfo、page.list、context.create）不要求先交页；其余管理命令必须绑定已交出上下文（不允许借会话权限管理别的 context）。
- 拒绝码统一为 `agent_target_required` / `agent_target_revoked` / `browser_owner_mismatch` / `browser_busy` / `browser_permit_invalid` / `browser_control_handle_required` / `browser_transport_unavailable`（与工具侧同一套稳定码）。

### 测试迁移（Tests/PuddingDesktop.Tests）

- `BrowserTestState` 新增 `OwnerId`/`Origin()`/`HandOver()`：正向用例改为"用户交页 + 第一条可信命令确认归属"（不再依赖旧 grant 夹具，也不靠闸门缺失取绿）。
- 新增/更新反例：无交页拒绝、无 owner 拒绝、他人会话不能使用已交出页面、非目标页拒绝、并发同 operationId 恰好一次、暂停/接管只读继续、Sentinel/Origin 投影不回归。

- `dotnet test Source/PuddingBrowser.AuthorizationTests` ⇒ **48/48**。
- `dotnet test Source/Pudding.DesktopServiceTests` ⇒ **418/418**（新增 8 条会话准入门面用例 + 拒绝码一致性）。
- `dotnet test Tests/PuddingDesktop.Tests` ⇒ **342/342**。
- `dotnet test Source/Pudding.DesktopSurface.BrowserTests` ⇒ **76/76**。
- **Shell 产品工程**：`dotnet build Source/PuddingDesktop/PuddingDesktop.csproj --no-restore` ⇒ **exit 0**，生成 `PuddingDesktop.dll`（含 WinUI XAML；路径链接文件只出现 Contracts/标量类型）。
- **先红证据**（只回退派发器到旧 grant 闸门）：`BrowserBridgeAdmissionTests` ⇒ **6 失败/8**；恢复后 **8/8 通过**。
- **未验证（明确声明）**：未启动 PuddingDesktop、未在真实 WebView2/真实 Agent 上验证；Origin→owner 的生产注入只有静态接线证据（`IBrowserOperationOriginAccessor` 已注册并传入 `RemoteBrowserRuntime`），需 I3/I4 真机确认。

## 未完成与影响

- **I2 另一半未做**：Bridge 页面命令仍由 `BrowserWorkspaceController` 直接执行；账本/准入/复检已统一，但"执行"尚未迁移进 `DesktopService` 执行器（方案 §3.3 的单执行管线）。`DesktopService` 的截图路径仍使用旧 authority + 只读页级基线，下一轮统一切换到会话权威。
- **能力通道路径仍用旧 authority**（grant/租约）：新旧判定暂时按传输分工共存（ADR 要求"不能同时作为最终裁决者"）；待执行器统一后删除旧路径。
- **UI 尚未显示 pending/claimed**：门面已提供 `BrowserSessionStatus.HasPendingHandover`，Shell 按钮/状态栏接线与"确认成功后显示已交出"属下一轮。
- **owner 由 Origin 推导**：单 Core 会话、单主 Agent 的一期范围内成立；若同一 Desktop 同时有多个会话并发使用浏览器，"先确认者得"仍是已知残余风险（一期 ADR 明确单个主 Agent；扩展需会话选择/交页 round-trip）。
- 回滚 = revert 本提交（含测试与门面）；无配置/数据变更。
