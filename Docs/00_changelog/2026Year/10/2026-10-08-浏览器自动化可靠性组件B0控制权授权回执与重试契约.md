# 2026-10-08 浏览器自动化可靠性组件 B0：控制权、授权、回执与重试契约

## 目标 / 背景

[设计方案](../../../12_features/浏览器自动化可靠性与渐进阅读设计方案-2026-10-08.md) 把修复拆成 B0–B7。
本次**只执行 B0**（用户明确选定）：*P0 控制权/授权/回执契约 + `PuddingBrowser.Automation` 独立组件*，
按[组件化交付规程](../../../10_conventions/组件化交付规程.md) **S1–S4** 交付，**不登记解决方案、不改宿主、不改消费方 csproj**。

选 B0 而不是「直接删掉版本递增检查」的理由：审计结论 #3 要修的是**判据**，
而判据必须先有独立可测的载体；在宿主里就地改会把「未验证的语义」直接推给运行实例。

## 改动

### 新增契约（`Pudding.Contracts`，BCL-only，仅新增文件、未改动任何既有文件）

- `Source/Pudding.Contracts/Desktop/BrowserControlContracts.cs` — 新增。
  控制世代 `BrowserControlEpoch` / 授权世代 `BrowserPageGrantEpoch`、执行租约 `BrowserAutomationLease`、
  `BrowserControlSnapshot`、两个窄端口 `IBrowserAutomationAuthority`（读/验证）与
  `IBrowserAutomationControl`（接管/暂停/恢复/关闭/世代/授权签发撤销）、
  `BrowserAutomationOperation` + `BrowserOperationPolicy`（§3.2 表格的唯一真源）、
  `BrowserAutomationRequest` / `BrowserAuthorizationDecision`。
- `Source/Pudding.Contracts/Desktop/BrowserGrantContracts.cs` — 新增。
  `BrowserPageGrantScope`（read/write/manage）、`BrowserCallerIdentity`（含子代理父任务与 `IsSameTaskScope`）、
  `BrowserPageGrantBinding`（Desktop 实例 + 进程实例 + 连接世代）、`BrowserPageGrant`（不可变）、
  `BrowserManagementGrant`（任务级管理授权）、`BrowserAuthorizationDenial` + 线名表。
- `Source/Pudding.Contracts/Desktop/BrowserActionReceiptContracts.cs` — 新增。
  执行/验证/完成三组枚举与线名、`BrowserActionAssertion`（值长度上限 + 敏感字段只留 length 与 matched）、
  `BrowserObservationStamp`、`BrowserActionEffectSummary`、`BrowserActionReceipt`。
- `Source/Pudding.Contracts/Desktop/BrowserRetryContracts.cs` — 新增。
  `BrowserRetryDisposition` + 线名、`BrowserRetryDecision`（纯数据）。

### 新增组件（S1/S2）

- `Source/PuddingBrowser.Automation/PuddingBrowser.Automation.csproj` — 新增。
  `ProjectReference` **恰好 1 条**（`Pudding.Contracts`）、`PackageReference` = 0；
  新增 `EnforceAutomationBoundary` 目标（`BeforeTargets="ResolveReferences"`）做**编译期**边界门禁。
- `Source/PuddingBrowser.Automation/BrowserAutomationAuthority.cs` — 新增。唯一控制权事实源。
- `Source/PuddingBrowser.Automation/BrowserGrantIssuancePolicy.cs` — 新增。子代理授权上界判据。
- `Source/PuddingBrowser.Automation/BrowserReceiptJudge.cs` — 新增。证据 → 回执判定 + 重试裁定。
- `Source/PuddingBrowser.Automation/BrowserOperationLedger.cs` — 新增。operationId 账本（5 分钟 / 1,024 项）。
- `Source/PuddingBrowser.Automation/code_map.md` — 新增（组件索引）。
- `Source/PuddingBrowser.AutomationTests/`（csproj + 9 个测试文件）— 新增，只引用该组件。

## 关键语义（与设计的对应）

| 设计条目 | 落地 |
|---|---|
| §3.1 唯一事实源、接管不撤销阅读授权 | `BrowserAutomationAuthority` 同时实现两个窄端口；`SetUserTakeover` 只推进控制世代，不推进授权世代 |
| §3.1 入队前 + 触碰页面前两次验证 | `Admit` 签发租约 → `Revalidate(lease, request)` 复检租约世代；接管后复检必然失败 |
| §3.1 恢复不复活旧队列/租约 | `Resume` 推进控制世代并清空租约；旧租约复检返回 `lease_lost` |
| §3.2 表格（授权类别/范围/租约/接管可见性） | `BrowserOperationPolicy`，并由 `BrowserOperationPolicyTests` 逐行快照；新增操作必须显式分类（`_ =>` 会抛） |
| §3.2 子代理只能取父任务子集 | `BrowserGrantIssuancePolicy.CheckSubAgentScope` + `IssueGrant` fail closed |
| §4.1 回执三段式、ok 只对 verified/dispatched 为真 | `BrowserActionReceipt` 的 `Completion`/`Ok`/`SafeToRetry` 由入参**派生**，无法构造出自相矛盾的回执 |
| §4.1 断言值长度上限与敏感遮蔽 | `BrowserActionAssertion.MaxActualLength` + `IsSensitive`；日志摘要只有类型与是否通过 |
| §4.2 不按动作名推断导航 | click 无 expect ⇒ `dispatched`（不是 failed）；断言失败 ⇒ `failed`；超时已提交 ⇒ `dispatched` + `unverified` |
| §4.3 同 operationId 驱动执行次数 ≤ 1 / receipt_expired / 在途不淘汰 | `BrowserOperationLedger`；容量耗尽拒新写请求，终态 tombstone 保留到容量压力出现 |
| §1.1 修正「所有点击必须推进版本」 | 删除动作的是 B1；B0 交付**替代判据**（回执 + 断言），版本不再参与成功判定 |

## 验证

构建与测试命令（产物只落 `temp/build`）：

- `dotnet build Source\PuddingBrowser.Automation\PuddingBrowser.Automation.csproj --artifacts-path temp\build\b0` → **0 警告 0 错误**。
- `dotnet test Source\PuddingBrowser.AutomationTests\PuddingBrowser.AutomationTests.csproj --artifacts-path temp\build\b0`
  → **114 / 114 通过，失败 0**（TOTAL 114）。
- 回归：`dotnet test Source\Pudding.ContractsTests\Pudding.ContractsTests.csproj` → **97 / 97 通过**
  （本次对 `Pudding.Contracts` 只做**新增文件**，未改动既有类型，含 `ErrorTaxonomyTests` 的线缆错误表快照）。

**门禁取红实测（三处，均随后复原）**：

1. 编译期边界：临时给 `PuddingBrowser.Automation.csproj` 加一条指向 `Pudding.DesktopService` 的
   `ProjectReference` ⇒ 构建失败，报 `PuddingBrowser.Automation may reference Pudding.Contracts ONLY (component boundary, S1/S4)`。
2. 运行时边界：临时给**测试工程**加一条指向 `Pudding.DesktopService` 的引用 ⇒
   `ComponentBoundaryTests` **3 条变红**（进程加载 / deps.json 闭包 / csproj 引用清单），
   报出 `Pudding.DesktopConnection, Pudding.DesktopService, Pudding.Rpc.Protocol`。
3. 用例守恒：临时 `<Compile Remove="BrowserOperationLedgerTests.cs" />` ⇒
   `Test_Method_Counts_Are_Conserved_Per_Class` 变红（9 个测试类 → 8 个）。

**S4 边界事实**：组件内 `ProjectReference` = 1（仅 `Pudding.Contracts`）、`PackageReference` = 0；
`Pudding*` 程序集在依赖闭包中只有 `PuddingBrowser.Automation` + `Pudding.Contracts`（+ 测试程序集自身）。

**尚未验证（诚实登记）**：B0 不接宿主 ⇒ 没有真实驱动/两传输/UI 的端到端证据；
G1–G3 目前只由纯逻辑替身覆盖，真实 click/fill/check、排队接管、非目标页拒绝需在 **B1（S5 接入）**后由进程外控制器验证。
