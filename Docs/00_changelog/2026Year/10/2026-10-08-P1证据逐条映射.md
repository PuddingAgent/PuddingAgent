# 2026-10-08 B7：G5–G8 逐条证据映射

## 交付

[门禁证据对账](../../../14_reports/2026-10-09-门禁证据对账.md) 再增一节「**G5–G8 逐条证据（用例名）**」，覆盖 P1 四条：

| 门禁 | 举例（标准 → 用例） |
|---|---|
| G5 | 中/英 SERP 一次给全前 10 条 → `TheChineseSerpFitsInOneExtractAtTheDocumentedPageBudget`；按 UTF-8 字节计量 → `BytesAreMeasuredInUtf8_NotCharacters` |
| G6 | 分页不重不漏 → `PagingStopsAtBlockBoundaries_AndContinuesWithoutGapsOrRepeats`；坏游标不当作 0 → `MalformedCursorsAreRejectedInsteadOfTreatedAsZero` |
| G7 | 密码不回显 → `A_Verified_Receipt_Can_Prove_A_Password_Fill_Without_Echoing_It`；locator 稳定入口 → `ToolDescriptors_UseStableNamesAndStructuredSchemas` |
| G8 | 边界 no-op → `ReachingTheBottomStopsInsteadOfReportingSuccessForever`；零位移不假称 → `AStalledPositionStopsTheScroll`；真实输入 → `DragPressesAtTheSourceMovesInStepsAndReleasesAtTheTarget` |

## 对账查出的**真缺口**

**G5 的「无额外 locate」标准目前没有任何进程内具名用例** —— 它属于**工具编排层**（`browser_extract` 是否额外触发定位）。
已在对账表该行显式标注 **⚠️ 未找到进程内具名用例 ⇒ 待补/真机项（S-05）**，而不是含糊带过。
（另外 G7 的「0×0/禁用/遮挡拒绝」的真实命中判定也在 WebView2 DOM 客户端，进程内只有映射/条件层证据，同样标注为真机项。）

## 门禁同步增强

`GateEvidenceReportTests.EveryTestMethodNamedInTheGateReportExists`：

1. **扫描范围**从 1 个工程扩到 **3 个**（`PuddingBrowser.AutomationTests`、`Pudding.DesktopSurface.BrowserTests`、
   `Tests/PuddingBrowser.AgentTools.Tests`）—— 因为 P1 的证据有一部分在另两个工程（表里引用了它们的方法名）；
2. **方法名正则**从 `public void X(` 放宽到 `public [async] Task|void X(` —— 否则**异步用例会被当成不存在**（本轮就撞到 3 次）。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **336 / 336** |
| 门禁实战 | ① 正则漏 `async Task` ⇒ 3 个**真实存在**的用例被判缺失（门禁自身缺陷，已修）；② 我转写错一个名字（`And_ABad` vs 实际 `AndABad`）⇒ 门禁点名，已改 |
| **全量链** | **1593 / 0**、无重试 |

## 诚实边界（诚实登记）

- **"名字存在"仍≠"标准被覆盖"**：门禁只保证表格不指向不存在的用例。
- **门禁的扫描范围是硬编码的三个工程**：表里若引用其它工程的用例名会被误判（登记为可扩展项）。
- **G5 的"无额外 locate"是真缺口**：本轮只登记、**未补用例**（需要工具编排层的测试夹具，下一轮可做）。
- **G9–G11 仍是类一级**（登记为可继续细化）。
- **未真机验证**；决定②仍待确认。
