# 2026-10-18 I2-c 路由收口：tabs 类命令经执行器（仅剩 context.create/close）

## 改动

- `page.create` / `page.activate` → 路由到执行器，结果取 `DesktopTabsResult.Page` 投影为 `BrowserPageDescriptor`（与旧 controller 返回形状一致）；
- `page.close` → 路由成功时**空载荷**（与旧 controller `SuccessEmpty` 兼容），避免上游按"页面描述符"解析时误判；
- 为支持空载荷，路由内部结果变量改为 `JsonElement?`；
- 测试新增：create 经 `BrowserTabs(New)` 投影 pageId、close 成功且 Value=null；路由测试 **10/10**。

## 覆盖状态

- 只剩 `context.create` / `context.close` 仍走 controller（其结果形状 `DesktopContextInfo`/`DesktopContextClosed` 尚未反投影）；
- 其余全部 Bridge 页面命令（getInfo/list/goto/back/forward/reload/stop/snapshot/locate/waitFor/interact/screenshot/create/activate/close）在生产路径上经**同一工作区执行器**。

## 验证

- Shell build exit 0；`Tests/PuddingDesktop.Tests` ⇒ **380/380 通过**；
- 未运行产品/真实模型；本轮再次改变生产执行路径（tabs 首次经执行器），真机/组合根验证属 I3/I4。

## 未完成与影响

- context.create/close 反投影与路由（下一片）；
- **controller 收缩与删除旧执行路径未做**（现在 controller 仍服务 discovery/context 管理命令）；
- 错误码对表、F5 后置观察、`browser_context` 发现面、I3/I4 未完成；
- 已知行为差异：tabs 结果不再带 active/agentTarget 标志（`FromPageState` 没有这些事实），需确认 Core 侧不依赖；
- 回滚 = revert 本提交。
