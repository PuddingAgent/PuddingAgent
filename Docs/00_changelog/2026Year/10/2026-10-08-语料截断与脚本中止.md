# 2026-10-08 交付链：语料静默截断 + 首个失败即中止 ⇒ 重试块是死代码

## 缺陷 ①：日志语料被静默截断（319 → 120）

`DeliveryFactCollector` 里 `MaxChangelogFiles = 120` 且 `.Take(...)` **无任何提示**；仓库
`Docs/00_changelog/2026Year/10` 当时已有 **319** 个 markdown ⇒ 未验证项是从**被截断的语料**里提取的。

**更正上一轮的数字**：上一轮我报告"共 27 条"；语料全扫后真实为 **39 条**（同一套标记与去重规则）。

**修法**：上限提到 100,000（本次采集可注入 `ChangelogFileLimit` 以便测试），并且——
**语料超过上限时直接拒绝产出**（而不是静默少报）；清单新增 `changelogFilesScanned` / `changelogFilesTotal`
两个必填字段 + `ChangelogCorpusIsTruncated`，报告写出「日志语料｜扫描 319 个文件（全部）」。

## 缺陷 ②：脚本在首个失败处**整体中止**（重试块是死代码）

`delivery-manifest.ps1` 顶层 `$ErrorActionPreference = "Stop"`，而 `dotnet test` 失败会往 stderr 写 `[FAIL]`
⇒ PowerShell 把它当**终止错误** ⇒ 脚本在第一个失败的套件处中止：后面的套件不跑、清单不是「被拒绝」而是
「**根本没走到**」、`-RetryFailedSuites` 的重试块**永远不可达**。

**这解释了此前 20 多轮里重试路径为何始终无法被验证**（不是运气问题，是路径不可达）。
**修法**：测试循环内切到 `Continue`，按 `$LASTEXITCODE` 判断失败并**继续跑完**（注释用 ASCII 写明原因）。

## 缺陷 ③：没产出 TRX 的套件会从清单里"消失"

确定性复现（一个不存在路径的"套件"）时发现：失败套件没有 TRX ⇒ 清单里**没有它**，
剩下的绿色看起来就是完整交付。**修法**：跑完后逐个核对**期望套件都有 TRX**（含 `-retried`），
缺任何一个 ⇒ `REFUSING to build a manifest` 并 `exit 2`。

## 诚实边界（诚实登记）

- **39 仍是下界**：抽取器只认保守词表，所以"共 N 条"是**自动提取到的**条数，不是未验证事实的全集。
- **重试代价照旧**：`-RetryFailedSuites` 让"第一次必须全绿"变弱；是否接受由验收方决定（默认关闭）。
  本次为了验证路径而显式启用，因此这一份清单里 Host 是 **retried** 的结果 —— **它不等于"一次通过"**。
- **`RetryFailedSuites` 与"缺失 TRX 拒绝"的交互**：重试成功的套件只留 `-retried.trx`，检查逻辑已同时接受两种文件名。
- **`ChangelogFileLimit` 是公开面增量**（采集请求多一个可选参数）。
- **未真机验证**；两项待决取舍未触碰。
