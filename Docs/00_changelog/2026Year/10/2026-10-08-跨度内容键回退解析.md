# 2026-10-08 流式路径落库缺口修复：跨度按内容键在库里唯一匹配解析

> 范围：`Source/PuddingCore/Runtime/ContextCompactionContracts.cs`、
> `Source/PuddingRuntime/Services/ContextCompactionService.cs`、
> `Source/PuddingRuntime/Services/WarmPrefixDurableCommitDecision.cs`、
> `Source/PuddingRuntime/Services/AgentExecutionService.cs`、
> `Source/PuddingRuntimeTests/Services/WarmPrefixCheckpointCommitTests.cs`（+3 例）、
> `Source/PuddingRuntimeTests/Services/WarmPrefixMidTurnHardProtectionE2ETests.cs`（断言收紧）
> 依据：[ADR-095](../../../07_architecture/109ADR-095会话上下文维护与首增量延迟治理ADR.md) D5、
> [修复方案](../../../12_features/首Token等待与上下文指示器修复方案-2026-10-07.md) §3
> 前序：[流式路径串联用例与身份重绑](2026-10-08-流式路径串联用例与身份重绑.md)（该批登记了这个缺口）

## 1. 定位：登记表在 Turn 内被复制掉，不是"没建"

上一批只能观察到 `durableSkipReason=unresolved_durable_identities:29`。本批加了两个探针
（Turn 前 / Turn 后，直接调 `ResolveDurableSpan`），拿到**决定性**事实：

```
preTurn (history=35)  resolved=35  unresolved=0
postTurn(history=11)  resolved=0   unresolved=11
```

⇒ Turn 开始前身份登记**完全正常**（说明上一批的归一化后重绑有效），是 **Turn 内某处再复制/重建**
了历史对象，使登记表（按引用）整体失效。

## 2. 修法：把权威放回库侧，按内容键唯一匹配解析

不再试图追着"谁又复制了对象"打补丁，而是让落库原语**自己**能从权威来源解析：

1. `WarmPrefixCheckpointCommitRequest` 新增 `SpanKeys`（`WarmPrefixSpanKey(Role, Content)`），
   与既有 `CoveredMessageIds` 并存；调用方**总是**带上内容键（内存 id 仍尽力而为）。
2. `ContextCompactionService.CommitWarmPrefixCheckpointAsync`：当内容键存在时，取该会话
   `CompactedBy == null` 的行，按内容键建索引，**唯一匹配**才解析成 `MessageId`；
   **0 个匹配或重复内容（>1）一律判为不可解析** ⇒ 整批拒绝（`CoveredMessagesNotFound`）。
3. 判定放宽：`ShouldAttempt(..., spanKeyCount)` —— 内存解析失败但有内容键时**允许尝试**，
   由服务端的唯一匹配决定成败；放宽这一步不会引入错标（歧义仍被拒）。
4. **角色 token 必须两侧归一化**：库里的 `Role` 是字符串（`user`/`agent`/`system`/`tool`），
   调用方给的是 `ChatRole` 枚举名（`User`/`Assistant`/…），且 `agent ≡ assistant`。
   服务端按与 `ContextWindowManager.ParseChatRole` **同一套语义**映射成枚举名。
   这一条是实测踩出来的：只按"角色 + 正文"直接拼接时两侧永远不相等，
   连**缓冲路径**（原本能落库）也被一起打挂 —— 全量回归立刻抓到。

## 3. 验证（本机真实执行）

| 命令 | 结果 |
|---|---|
| `dotnet build Source\PuddingRuntime\PuddingRuntime.csproj` | **exit 0**，0 错误 |
| `dotnet test … --filter "…WarmPrefixCheckpointCommitTests\|…WarmPrefixDurableCommitDecisionTests"` | **exit 0**，失败 0 / 通过 **14** |
| `dotnet test … --filter "…WarmPrefixMidTurnHardProtectionE2ETests"` | **exit 0**，失败 0 / 通过 **5**（连跑 2 次均 5/5） |
| 全量 `PuddingRuntimeTests` / `PuddingMemoryEngineTests` | 见 §3.1 |

新增用例（落库原语 3 例）：

1. `Commit_WithSpanKeysOnly_ResolvesRowsFromDatabase`：**只传内容键**（模拟流式路径身份全失效）
   ⇒ 仍提交成功，且覆盖到正确的三行（含 `agent` 行按 `Assistant` 键解析）。
2. `Commit_WithAmbiguousSpanKeys_WritesNothing`：库里存在同角色同正文的重复行 ⇒ 拒绝，
   **零写入**（不绑错行）。
3. `Commit_WithUnknownSpanKey_WritesNothing`：键在库里找不到 ⇒ 整批拒绝，不得只写"找得到的那部分"。

E2E 断言**收紧**：流式用例不再接受"或明确降级"，现在**必须**完整落库
（摘要行 + 覆盖标注全部指向该摘要 + 代际=1）。缓冲路径用例保持原样并通过。

### 3.1 全量回归

| 套件 | 结果 |
|---|---|
| `PuddingRuntimeTests` | **exit 0**，失败 **0** / 通过 **2050** / 跳过 6（总计 2056）—— 较上一批 2047 增加本批 3 例 |
| `PuddingMemoryEngineTests` | 失败 **3** / 通过 **288** —— 仍是既有环境依赖的 ContextPipeline 分层用例 |

本批改动跨 Core 契约 + Runtime 落库原语 + 执行主路径接线，三处都靠这条全量回归兜住；
其中「角色 token 未归一化」这一处正是**全量回归先报红**（缓冲路径被打挂）才被抓到的。
