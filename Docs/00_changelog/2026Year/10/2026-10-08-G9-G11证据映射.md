# 2026-10-08 B7：G9–G11 逐条证据映射收尾

## 交付

[门禁证据对账](../../../14_reports/2026-10-09-门禁证据对账.md) 再增一节「**G9–G11 逐条证据（用例名）**」：

| 门禁 | 举例（标准 → 用例） |
|---|---|
| G9 视觉/坐标 | low 超基准必须报 budget_exceeded → `LowDetailOverTheFortyKiBBaselineIsRefusedWithBudgetExceededWording`；全页明确不支持 → `FullPageCaptureIsExplicitlyUnsupportedRatherThanFaked`；旧坐标失效 → `AnyGenerationChangeMakesTheOldCoordinatesStale` |
| G10 委派 | 父子不并存写租约 → `ParentAndChildCannotHoldTheSamePageWriteLease`；父结果 ≤2 KiB 且超限指向 Artifact → `AnOversizedConclusionIsTruncatedOnACharacterBoundaryAndPointsAtTheArtifact`；注入工具须覆盖任务 → `InjectedToolsMustCoverTheTask` |
| G11 生命周期/事件 | 订阅恰好一次 → `EverySubscribedPageEventIsAlsoUnsubscribedExactlyOnce`；日志有界且总数如实 → `CapacityIsEnforced_AndTotalCountStillTellsTheTruth`；文件选择器缺口如实记录 → `TheDriverDocumentsThatFilePickersCannotBeIntercepted` |

**每条门禁同时给出"只能真机"的具体观察步骤**（例如 G9：整页/视口各截一张 → 导航中再截一张确认不返回旧页 →
缩放后再用旧坐标确认被拒 → 确认模型收到类型化图片），指向对应 smoke 项与四步生命周期。

⇒ 对账表从"证据地图"变成"**施工与验收都能用的一张表**"：`G1–G11` 全部到用例名一级，真机部分到观察步骤一级。

## 门禁同步修正

`GateEvidenceReportTests` 原先会把整节里所有行内代码当成用例名 ⇒ 被"真机观察步骤"里的 `CoreReady` 误报。
已收窄为**只核对以 `|` 开头的标准行**（排除含"真机观察步骤"的行）；并要求解析到 ≥30 个名字（防假绿）。
收窄后 G1–G4 / G5–G8 / G9–G11 三节引用的用例名**全部通过**。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **336 / 336**（表格门禁现在覆盖全部三节） |
| 门禁实战 | 本轮它先误报 `CoreReady`（**门禁自身缺陷**，已收窄规则）；收窄后无漏网 |
| **全量链** | **1594 / 0**、无重试 |

## 诚实边界（诚实登记）

- **"名字存在"仍不等于"标准被覆盖"**：语义覆盖要人读用例；门禁只保证表格不指向不存在的用例。
- **对账表的"真机观察步骤"是建议顺序，不是自动验证**：真机从未运行，四步终态仍只能由进程外控制器判定。
- **对账表会过期**：代码/清单变化后需重跑（无自动门禁绑定"标准 ↔ 用例"的语义关系，登记为可改进项）。
- 决定②仍待确认。
