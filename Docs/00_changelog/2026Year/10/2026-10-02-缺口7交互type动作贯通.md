# 缺口 #7 完成：交互 `type` 动作贯通（**无需改 proto**）——`browser_interact` 因此完全解锁

## 为什么这一项特别便宜（值得记的设计红利）

线缆上 `InteractCommand.action` 是**字符串 + 冻结线名表**（`string action = 3;`），
因此新增一个动作**不需要改 proto**：只动契约枚举、冻结线名表、请求形状校验、两侧动作分支与冻结测试。

> 对比 #9（快照四旋钮）与 #12（页状态标题）都要动 proto 字段号与两侧映射；
> 这里的"字符串动作 + 冻结线名"设计把新增动作的成本压到了纯契约层。**这是当初把动作设计成
> 线名而不是枚举号换来的收益**，值得在后续加宽同类项（如导航四动作）时复用同一模式。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| 契约 | `Contracts/Desktop/InteractionContracts.cs` | 枚举新增 `Type`；冻结线名表新增 `"type"`；`ValidateShape` 让 `type` 与 `fill`/`press` 一样**必须有 text** |
| Desktop 侧 | `DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs` | `PerformAsync` 新增 `Type` 分支 → 运行时 `TypeAsync`（与 `fill` 语义不同：逐字输入） |
| Bridge 侧 | `Host/BrowserBridge/BridgeBrowserCapabilitySurface.cs` | 同上 |
| 契约冻结测试 | `ContractsTests/InteractContractTests.cs` | 动作线名快照数组插入 `"type"`（保持声明顺序一致） |
| 适配器测试 | `Host.Tests/…/BridgeBrowserCapabilitySurfaceTests.cs` | 新增"`type` 真的到达运行时 `TypeAsync`"用例 |

## 解锁情况

`browser_interact` 的缺口已全部闭合（动作 `click/fill/type/press/hover/scroll/select/check`✔、
`DeltaX`✔（第 8 项）、页状态标题✔（#12））⇒ **它是下一个可迁移工具**（第四个）。
