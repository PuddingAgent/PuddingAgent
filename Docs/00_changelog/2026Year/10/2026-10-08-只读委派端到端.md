# 2026-10-08 B6/S5：只读委派的组件级端到端

## 为什么这步有价值

拆解表 S5 指出：权威状态机、租约账本、信封校验**各自**都有用例，但"只读委派"这条**组合路径**没有——
而 Runtime 接线（S7）要调的正是这个形状。本轮用纯内存对象把它走通（不加载宿主/驱动/UI）。

## 新增 `ReadOnlyDelegationTests`（4 条）

| 用例 | 断言 |
|---|---|
| `AReadOnlySubAgentGrantIsAllowedAndItsWritesAreDenied` | 只读子授权能读；**同一子代理的写请求被拒**（否则"只读"只是装饰） |
| `ASubAgentGrantCannotExceedItsParentScope` | 父只有只读时，子代理申请读写 ⇒ **签发阶段**就失败（fail closed，不等到运行时） |
| `AReadOnlyDelegationDoesNotBlockTheParentFromWriting` | 子代理观察的同时，父代理**仍能拿写租约**；关闭委派（超时）后子代理观察被回收、父写租约不受影响、释放原因记为 `TimedOut` |
| `ClosingAReadOnlyDelegationRevokesTheChildGrantSoLaterWritesStayDenied` | 撤销子授权后，子代理的写**与读**都被拒 |

## 过程中发现并纠正的真问题

**新测试类漏了 `[TestClass]` ⇒ 4 条用例静默不运行**：`dotnet test` 却显示"全绿"（总数只统计被发现的用例）。
是 **`Test_Method_Counts_Are_Conserved_Per_Class`（测试面普查）** 抓到"多了一个类名却没被发现"。
—— 没有那条门禁，我这轮就会交出一个"4 条用例从未运行"的假证据。已补 `[TestClass]`，总数 325 → **332**（+4 及本轮其它）。

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **332 / 332**（＋4） |
| **取红实测** | 删掉 `EnsureSubAgentScopeIsSubset` 的调用 ⇒ `ASubAgentGrantCannotExceedItsParentScope` **变红**；还原 ⇒ 332/332 |
| 测试面普查 | 新类已登记（缺 `[TestClass]` 时该普查**先红**，这是本轮最有价值的一次拦截） |

## 诚实边界（诚实登记）

- **仍是组件级**：不加载宿主/驱动/UI，也没有 Runtime 接线（S7/S8 被决定①/②挡住）。
- **不含"子代理真的发起工具调用"**：本轮验证的是**授权与租约**的组合，不是 Agent 工具执行链路。
- **只覆盖只读委派**：可写委派的端到端仍依赖 S7/S8。
- **`ReadOnlyDelegationTests` 依赖 `B0Fixture`**（同项目测试夹具）：夹具变化会影响它，但那是显式的。
