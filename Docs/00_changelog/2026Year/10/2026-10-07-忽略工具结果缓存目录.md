# 2026-10-07 忽略工具结果缓存目录（.pudding/context-tool-results）

## 改动

- `.gitignore`：新增规则 **`**/.pudding/context-tool-results/`**（4 行说明注释 + 1 行规则），位置在既有的「Agent / Harness 仓库级资料入库」注释块之后。

## 为什么

1. **噪声**：`context-tool-results/` 是工具结果的运行时缓存（每次工具调用把完整结果落盘一份 artifact）。2026-10-07 实测三处共 **616 个文件 / 9.5 MB**——仓库根 464 个（7.6 MB）、`Source/` 98 个（1.2 MB）、`Source/PuddingPlatformAdmin/` 54 个（0.7 MB）。目录随会话无限增长，`git status` 每次都把它们逐条列出。
2. **注释与实现漂移**：`.gitignore` 第 24 行原先写着「不加前导斜杠：仓库内任意层级的 .pudding（含 Source/*/.pudding）一并纳入」，但**并不存在任何 `.pudding` 忽略规则**——那句话描述的是 2026-10-02 的入库裁定（`skills/`），被误读成通用规则。
3. **含斜杠模式的锚定陷阱**：`gitignore` 的语义是「模式中间或开头带斜杠 ⇒ 相对 `.gitignore` 自身层级」。首版规则写成 `.pudding/context-tool-results/` 时，`git check-ignore` 显示仓库根命中、而 `Source/.pudding/...` 与 `Source/PuddingPlatformAdmin/.pudding/...` **漏网**（`git status` 仍报 `?? Source/.pudding/`）。这正是「不加前导斜杠 ≠ 任意层级」的实证——必须显式加 `**/` 前缀。

## 验证

- `git check-ignore -v`（`temp/hb12-verify-ignore.txt`）：仓库根 / `Source/` / `Source/PuddingPlatformAdmin/` 三个层级**全部命中** `.gitignore:31:**/.pudding/context-tool-results/`。
- **对照（防误伤）**：`.pudding/skills/zzz-nonexistent/SKILL.md` 无命中 ⇒ `skills/`（有意入库）不被牵连。
- `git status --porcelain | findstr .pudding` ⇒ **空**（噪声消失）。
- 已跟踪文件不受影响（`temp/hb12-tracked-counts.txt`）：`git ls-files` 共 4903 条，其中 `context-tool-results` **0 条**（本规则不会覆盖任何已跟踪文件）；`.pudding/` **21 条**（即 `.pudding/skills/**`，与规则无关）。
- 落盘核对：`.gitignore` sha256 `5f6b0240…94df` → `9987302…d9db`（+223 B）→ `3520bbdc…6716`（+100 B）；行尾前后一致（LF，`crlf=0`）。两次运行均因断言在 `open(...,"w")` 之前而**中止未写盘**过一次（首次 `count==2` 断言写错），磁盘从未出现中间态。

## 边界与遗留

- 只影响 **未跟踪** 文件的呈现，**不删除磁盘上的任何 artifact**（9.5 MB 仍在原处）；若将来确实需要入库某个 artifact，需 `git add -f`。
- 规则刻意收窄到 `context-tool-results/`：`.pudding/skills/**` 与 `.pudding/memory/**` 的入库裁定（2026-10-02）不受影响。
- 同类运行时目录若日后新增（如 `.pudding/logs/`），需各自显式加规则——本条不预先放大范围。
