# 前端 Debug 按钮：聊天头部「更多」里加服务端日志开关

## 做了什么

用户要"前端留下一个 Debug 按钮，可以打印日志确认是否真的跑通"。按钮本身只是 UI，因此本轮把它接到
`dadbe52` 的服务端接口上，并在界面上**始终显示当前级别**（否则用户会以为"我点过 Debug 了"却在日志里什么也看不到）。

| 文件 | 改动 |
|---|---|
| `src/pages/chat/client/agentChatApi.ts` | 新增 `ServerLogLevelSnapshot` 类型 + `loadServerLogLevel()` / `setServerLogLevel(level)`（沿用本文件既有的 `request(...)` 写法） |
| `src/pages/chat/hooks/useServerLogLevel.ts`（新） | 状态源：挂载读一次当前级别；`toggle()` 在 `Debug` ⇄ `Information` 间切换；**不做乐观更新**（以服务端返回为准 —— 后端是"先落盘、后生效"，失败时级别并未改变，界面不能显示成已开启）；`busy` 防连点竞态；读取/切换失败只记 `error`，**不抛到界面** |
| `src/pages/chat/components/ChatMain.tsx` | 头部「更多」菜单新增一项（与自动朗读、开发者模式并列）：`服务端日志（Debug：Verbose）` / `服务端日志（Information）`；Tooltip 同步显示状态与"上次失败"原因 |
| `src/packages.json` → `Source/PuddingPlatformAdmin/package.json` | 版本 **6.1.7 → 6.2.0**（新增功能 ⇒ 递增次版本号，按仓库规则与改动同提交） |

## 为什么不引入新的提示样式

既有的「更多」菜单三项都用**状态后缀**表达开关状态（`自动朗读（已开启）`、`开发者模式（已关闭）`），
且测试就是按这个语义断言的。新项沿用同一约定（`服务端日志（Debug：…）`），因此没有新增 toast/通知依赖，
也没有与现有交互分叉。

## 验证

- **jest：2 个套件 / 26 条用例全绿** —— 既有的 `ChatMain.test.tsx`（头部菜单相关断言）**未被新增项破坏**，
  新增的 `useServerLogLevel.test.ts` 5 条覆盖：挂载读取、标准→Debug、Debug→标准（一键回退）、
  读取失败不阻塞界面、切换失败**不做乐观更新**；
- **`tsc --noEmit`：我改的文件 0 个错误**。需要如实说明：该门禁**在 HEAD 上本来就是红的**（6 个错误，
  分布在 `src/pages/chat/index.tsx` 与 `src/pages/chat/projections/executionFlowProjector.ts`，这两个文件
  在我的工作树里**未被修改**）⇒ 这 6 个错误与本次改动无关，我也没有顺手去改（属于别人的范围）。

## 一处必须说清的边界（部署）

运行中的 Core 提供的是**已构建的静态产物**（`wwwroot/admin`）。因此本轮的按钮**在当前运行的实例里不会出现**：
必须重新构建前端（`pnpm run build`）并重新构建/部署 Core 才会生效。**我没有对运行中的实例做构建/部署**
（遵守"不要关闭/重启别人正在调试的进程"这一约束）。⇒ 前端源改动是"已提交、已验证"，**尚未上线**。
