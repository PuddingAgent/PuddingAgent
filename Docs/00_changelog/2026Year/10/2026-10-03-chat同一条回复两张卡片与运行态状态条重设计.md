# 2026-10-03 Chat 同一条回复渲染成两张卡片修复 + 运行态状态条重设计

## 目标 / 背景

用户截图标了两处：

1. **「生产了2个卡片」**：一轮 Agent 回复（截图内容为「你好几点了」的回答）在会话里出现**两张卡片**——
   第一张带头部 `默认助手 刚刚 · 已完成`、折叠行为组（`2 步骤思考 · 3 次工具 6.8s`）、正文、终态计量行；
   第二张没有头部（`groupedWithPrevious`）、行为组展开、**同一段正文**，底部挂着仍在下跑的
   `正在生成回答 · 已运行 31s`。
2. **「需要美化，重新设计」**：指向第二张卡底部的运行态行（`TurnStatus`）。

判定证据（不是猜测）：截图所在前端正是本仓库 HEAD 的代码 —— 构建徽标 `v6.2.2+dirty · 570cf8d · 2026-10-03 03:55`，
`570cf8d` 是本仓库 `2026-10-03 03:53:52` 的提交，`570cf8d..HEAD` 之间 `src/pages/chat` 只删了一个死组件
（`IndexIndicator.tsx`）。运行中的 Core 进程路径 = `Source/PuddingAgent/bin/Debug/net10.0/PuddingAgent.exe`。

数据侧（`D:\data\databases\pudding_platform.db` 只读查询）确认**不是服务端重复落库**：
会话 `206a9b48ec904ebb93e7541131fbb835` 里该轮只有一条助手消息（`Id=12132`，`turn_id=e094f08ea6f244c19ec3b14ae85c4afb`，
`command_id=649b2fc596c240b481d3e07071410a58`），`conversation_events` 里有 `turn.completed`（`sequence=1663540`），
`execution_runs.status=succeeded` —— 即同一轮同时以「历史投影 turn」和「运行快照 / 直播 turn」两种身份进了前端。

## 根因（消息装配层三条缺口）

`Source/PuddingPlatformAdmin/src/pages/chat/components/MessageList.tsx` 的 `visibleTurns` 是
「历史投影 turn + 本地直播 turn + activeRun 快照 turn」三源合流，旧实现的判重全靠若干启发式，缺三条：

1. `hasProjectedUserTurn` 开头 `if (!localText) return false;` —— **没有用户正文的本地 turn 一进来就被判成
   「投影里没有这一轮」**，即使 `turnId` 与投影完全一致。agent 主动回合、SSE 恢复 turn
   （`useSessionEventProjection` 的 `umsg:recovered:*`）、`activeRun` 快照 turn 的
   `userMessage.text` 恒为空 —— 它们因此被追加到消息流末尾，同一条回复长成第二张卡。
2. 正文判重 `turn.assistant.answerMarkdown.trim() === trimmed` 是**严格相等**：直播正文与持久化正文
   常只差不可见空白（尾部换行、段落间多余空行），判重失效 → activeRun 被追加。
3. activeRun 的覆盖判定只看 `turnId === runId` / pending turn / `commandClientId === userMessage.id`，
   **没有「这个命令已经物化出终态回复」的身份兜底**；服务端把用户消息行（`turn_id` 为空）与助手消息行
   （`turn_id` 有值）投影成两条 turn 时，两条都不满足，于是再次追加。

## 影响与回滚

- 影响面：只在 Chat 前端的消息装配与 `TurnStatus` 视觉；不改协议、不改数据库、不改后端契约。
- 行为变化（正向）：同一条回复只渲染一张卡片；残影卡片不再把「正在生成回答 · 已运行 Ns」永久挂在已完成回复下方。
- 行为变化（需知悉）：头部 `TurnElapsedLabel` 与胶囊内计时 chip 会同时显示同一时长
  （既有冗余，本轮只做了胶囊美化，未删除头部时钟）。
- 回滚：`git revert` 本次提交即可；若要回滚已部署产物，重新构建上一版本前端并覆盖 `wwwroot/admin`。
