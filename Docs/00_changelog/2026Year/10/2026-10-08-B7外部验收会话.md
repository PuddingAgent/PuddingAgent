# 2026-10-08 B7 外部验收会话：清单 + 观察事实 → 结论

## 目标 / 背景

前几轮把 B7 的两侧都备齐了：**内部一侧**（交付清单 + 采集 + CLI + 脚本 + 留痕报告）与
**观察清单**（G1–G11 的外部 smoke 项）。缺的是把「外部观察事实」变成**结论**的那一步 —— 也正是
`Agents.md` 强调的「启动/重启/崩溃恢复/退出回收结论由外部控制器判定」。

## 改动

`Source/Pudding.DesktopService/ExternalAcceptanceSession.cs`（新增）：

| 类型 | 作用 |
|---|---|
| `SmokeObservation` / `SmokeObservationOutcome` | 一条观察记录：编号 + 通过/失败/**未执行** + 证据（看到的现象） |
| `LifecycleEvidence` | 生命周期一步的外部证据 |
| `ExternalAcceptanceInput` | 交付清单 + 观察构建 + 观察记录 + 生命周期证据 |
| `TryConclude` | 判定是否允许作出 `external-lifecycle-verified`；**逐条给出原因** |
| `ToMarkdown` | 验收记录留痕（谁在哪个构建上看到了什么、缺什么） |

**四条拒绝**（核心）：
1. 有**未执行**的观察项 ⇒ 不能算通过（"没测"不等于"通过"）；完全缺失某条同样拒绝；
2. 有任何**失败** ⇒ 拒绝；
3. 观察的构建与交付清单**不一致**（或没写构建）⇒ 拒绝 —— 旧构建上的结论不算数；
4. 生命周期四步**缺证据、未通过、或"报成功但没有任何记录"** ⇒ 拒绝。
另拒绝**重复记录**（证据含糊）与**清单外的编号**（可能是清单漂移的信号）。

它**不重造任何规则**：观察项来自 `BrowserSmokePlan`（覆盖 G1–G11 是它的职责）、生命周期四步来自
`DeliveryManifest.RequiredLifecycleSteps`、"谁能下结论"来自 `DesktopAcceptance.CanClaim`（内部主体一律拒绝）。

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **297 / 297**（原 289 ＋ 8） |
| `Contracts` · `AutomationTests` · `DesktopSurface.BrowserTests` · `AgentTools` · `PuddingDesktop` · `Host` | 153/153 · 306/306 · 67/67 · 64/64 · 320/320 · 258/258 |

新增门禁：完整外部运行可以下结论；**未执行不算通过**（且缺项被点名）；失败阻止结论；
"报成功但无证据"（观察与生命周期两侧）被拒；**旧构建的观察被拒**；生命周期缺步/失败被拒；
重复记录与未知编号被拒；渲染包含全部观察项与生命周期步骤，未通过时如实写"缺证据/未通过"。

**取红实测**：把 `NotRun` 分支删掉（等于"未执行也算过"）⇒ `NotRunningAnObservationIsNotAPass`
**恰好变红**；复原后 297/297 复绿。

**既有 flake**：`Host.Tests` 的 handshake 用例本轮全量失败 1 次、重跑通过（与本次改动无关）。

## 已知边界（诚实登记）

- **它判定，但不执行**：不部署、不重启、不观察进程；真机 smoke 与生命周期事实仍需外部控制器产生
  （本轮没有、也不可能有这些事实 —— 所以**本项目当前仍只有 `ready-for-external-deploy`**）。
- **证据是文本**：`Evidence` 只要求非空文本，无法机器校验其真实性（那是外部控制器的责任与留痕范围）。
- **`Claimant` 固定为 ExternalController**：这是接口的设计意图（本组件就是"外部一侧"的判定），
  内部主体若调用它得到的仍是"允许外部下结论"的判定 —— 调用方身份校验不在本组件（属 B1 的未决问题）。
- **未持久化验收会话**：`ToMarkdown` 只渲染文本，落盘与留痕仍靠人工/后续脚本。
- 真机无关（纯判定与渲染）。

## 影响与回滚

- **无对外行为变化**：新增组件尚无生产调用方（外部控制器脚手架是下一步）。
- 回滚：删除 `ExternalAcceptanceSession.cs` 与其测试。
