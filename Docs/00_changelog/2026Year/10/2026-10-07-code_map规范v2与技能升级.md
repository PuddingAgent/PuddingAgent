# 2026-10-07 · code_map 规范 v2 与技能升级

## 背景 / 动机（实测基线，2026-10-07）

全仓 **40 个活跃 `code_map.md`（根 1 + `Source/<Proj>` 39），385,559 B / 3,029 行**，其中 **≈50.7% 是 Markdown 表格行**；
体量高度集中：**前 6 个文件占 64%**（根 + PuddingRuntime/PlatformAdmin/Platform/Core/CodeIndex = 246,589 B）。

**真正的"不浓缩"症状（实测）**

| 症状 | 实测值 |
|---|---|
超长单元格 | 单行最长 **3,521 B** |
索引里塞正文 | 根 `code_map.md` §4 存在**单个 98 行代码围栏**，占该文件 **34%**（122–223 行中的 124–222） |
表头重复 | 同一表头 `\| 文件 \| 用途 \|` 重复 **98 次** |
陈旧副本 | `temp/` 下 **25 份** `code_map.md` 副本（非活跃件） |

成因链：**「按文件一行」模板 × 无字数上限 → 单元格越写越长 → 索引退化为正文**。
（「变更日志堆积」这一条已在 2026-10-02 迁出到 `Docs/00_changelog/`，**不再是问题**。）

## 借鉴来源

外部调研对象 **AOCI-CODE**（`aoci-spec/aoci-code`，AI-Oriented Code Indexing，Go CLI + 本地 MCP server，1212 stars）。
调研报告（临时件，不入库）：`temp/aoci-code-research-2026-10-07.md`，含 6 大问题逐条**原文依据**、30 条来源清单、业界 5 条可比做法。

**采纳**其四条件纪律：
① **省略式压缩** —— 每个字段被显式定义为「**不是全集**」（F 不是清单 / R 不是完整依赖图 / A 不是所有方法）；
② **硬上限**（机器常量单一真源）；
③ **分档配额 + 角色分层**（index / observe / exclude；并据「每条 ≈110 token」的成本模型决定谁值得占一行）；
④ **程序禁止生成/压缩/截断语义**，只做 read/统计/校验/报告。

**未照搬**：其 `文件名[标签]: F|R|A|S` 纯文本行式、五维紧凑标签、MCP/Baseline/Attestation 治理面 ——
本仓 code_map 的核心价值之一是 Markdown **相对链接**的可导航性，故保留表格格式，只吸收其**浓缩纪律**（诚实标注见规范 §9）。

## 交付物

1. **规范（normative）**：`Docs/10_conventions/code-map-规范-v2.md`
   —— 条目 schema（`文件 | 用途(F) | 关键符号(A) | 关联(R) | 约束(S)`）、硬上限（单行 ≤300；F≤80；A/R≤100 且 ≤5 项；S≤160；**围栏数=0**；条目行 ≤400；同表头重复 ≤8）、
   L1/L2 边界、角色分层、**源指纹**陈旧判据、反模式词表、11 条规则 ID 与门禁口径、修订流程。
2. **自检器**：`Tools/Docs/code_map_check.py`（只读、报告型；**禁止任何自动改写语义的代码路径**）—— 与逐文件/分位数**实测分布**报告（供上限校准）。
3. **技能升级**：新建 `code-map-authoring` **v2.0.0**（操作规程，指向上述规范）；**停用** v1 的 `code-map-incremental-update`（其后仍可作为历史，但不再是真相源，避免双真相源）。
4. **维护**：三个在飞子代理 —— ① 自检器实现 ② 根 L1 浓缩（300 行 → 目标 ≤150，删 98 行围栏）③ `Source/PuddingRuntime/code_map.md` 浓缩（L2 首个试点）。

## 判据（可判真伪）

| 判据 | 形态 |
|---|---|
规范可被机器执行 | 自检器实现 §7 全部 11 条规则 ID，且**能取红**（fixture 命中规则集合与预期一致） |
浓缩是"改写"不是"截断" | 根 §4 围栏数 98 行 → **0**，且调用链信息以表格保留 |
上限有据可依 | 报告输出四类单元格长度中位数/p90/p99/max，作为 §8.3 校准输入 |

## 诚实标注

- **上限数值是首版工程取值，尚未按本仓真实分布校准**（规范 §8.3 已列为待校准项）；§8 明确要求"先杀掉最坏 1%，再据分布收紧"，**不追求一步到位**。
- 规范 §7 的 `layering-violation` 被**降级为 warn**：L1 的跨项目调用链表本身也会引用文件路径，该规则**启发式、非可判定**，不应阻断门禁。
- 本轮我的 `file_patch` 曾把该规范表格的**两行合并成一行**（空白容忍匹配吞掉了换行），已当场 `file_read` 复核并修复 —— 教训已写入技能 §7 坑 4。
- v1 技能的**历史正文未删除**，仅置为 disabled；如需彻底退休需另行确认。
