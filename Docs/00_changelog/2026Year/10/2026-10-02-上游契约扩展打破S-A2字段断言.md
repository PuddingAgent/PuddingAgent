# 上游契约扩展（23→32 字段）打破 S-A2 字段断言

## 1. 这轮做了什么

在他人 10-02 大量提交（code-index 维护系列、前端 6.2.0、日志基础设施）之后，对**自己四个切片**做了一次独立回归复验（只跑测试、不改源码），结果**抓到一条真实回归**并当场修复。

## 2. 触发：切片回归复验（改动前）

```
dotnet test Tests\PuddingHost.Tests\PuddingHost.Tests.csproj -c Release \
  --filter "FullyQualifiedName~SAIndexStatus|FullyQualifiedName~SA2CodeIndex"
⇒ 失败: 1，通过: 24，总计: 25
   PuddingHost.Tests.Hosting.SA2CodeIndexStatusTests.A5_Maintenance_Status_Is_Passed_Through_Verbatim_With_All_23_Fields [FAIL]
```

## 3. 根因（读源码取证，不是猜）

- `Source/PuddingCodeIndex/Contracts/ICodeIndexMaintenance.cs` 的 `CodeIndexMaintenanceScopeStatus` 被**合法扩展**：原 23 个位置参数之后追加了 **9 个**「D4 源维护（2026-10-02）」字段
  （`sourceMaintenanceMode` / `sourceMaintenanceRunCount` / `sourceMaintenanceExtractedFileCount` / `sourceMaintenanceReusedFileCount` / `sourceMaintenanceOrphanFileCount` / `sourceMaintenanceUnresolvedPathCount` / `sourceMaintenanceDeletedFileCount` / `lastSourceMaintenanceCommitOutcome` / `lastSourceMaintenanceSessionKey`）⇒ 契约共 **32** 字段。
- 我 S-A2 的 A5 断言写死「序列化后恰好是那 23 个名字」，于是把**契约增长**误报成**投影出错**。
- 端点本身没有丢字段：`CodeIndexStatusProbe` 两个构造点都是 `Maintenance: maintenance`（**同一引用**透传），源码已复核。

## 4. 修法：两条互补断言（既不误报增长，也不放过丢字段）

1. **冻结核心（同序前缀）**：2026-10-01 上线时的 23 个名字必须**原样、同序**留在最前 —— 前端已按它们取值 ⇒ 只增不改不删/不重排。
   `Assert.Equal(FrozenLegacyMaintenanceFieldNames, actualFieldNames.Take(23))`
2. **原样透传（字段集）**：序列化字段集必须与**契约反射所得**的 camelCase 名集逐名一致（真源是 `typeof(CodeIndexMaintenanceScopeStatus)`，不是测试里再抄一份名单）。
   `Assert.Equal(ContractMaintenanceFieldNames(), actualFieldNames)`

保留下来的原有断言：`Assert.Same(status, entry.Maintenance)`（同一引用）、`Assert.Null(MaintenanceReason)`、`indexPending/committedVersion/recentObservationCount/watcherAttached` 逐值、以及 D3 反例「维护态里没有单一 `status` 字段」。测试方法更名为 `A5_Maintenance_Status_Is_Passed_Through_Verbatim_With_All_Contract_Fields`。

## 7. 仪器教训（本轮新踩）

- **cmd 单行里的 `%ERRORLEVEL%` 不可信**：`cmd /c "a & echo %ERRORLEVEL%"` 会在**解析期**展开 ⇒ 打印的是上一条命令的退出码（本轮 `M1_EXIT=0` 实际是失败运行）。判定一律以**输出的汇总行文本**（`失败: N，通过: M`）为准。
- `findstr` 对 UTF-8 中文 pattern 恒不命中（老坑复现），本轮改用**重定向到文件 + 直接读文件**取汇总行。
