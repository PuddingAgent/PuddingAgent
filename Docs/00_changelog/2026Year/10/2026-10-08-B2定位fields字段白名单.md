# 2026-10-08 B2 定位 fields：字段白名单，只回要的字段

## 目标 / 背景

设计 §6.2：「locate 默认 `includeHidden=false`、`limit=10`；提供 `cursor`、`includeHidden`、**`fields`**、
`inViewportOnly`。」§151 同样把 `fields` 列为读取类工具的通用参数。

上一轮做完 `cursor` 后，「定位参数面」只剩 `fields`。它的价值是**预算**：默认输出里
`name`（≤500 字符）、`text`（≤1000 字符）、`boundingBox` 是 payload 大头，
而调用方常常只要 `ref`（准备接着点）。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| 契约 | `Source/Pudding.Contracts/Desktop/ElementFields.cs`（新增） | `BrowserElementFields`：**核心字段** `ref/tag/visible/enabled` **恒在**（`ref` 是继续操作的唯一把手，`visible`/`enabled` 决定能不能动，且都是小字段）；**可裁剪字段** `role/name/text/inViewport/checked/value/selectedValues/boundingBox`；线名与工具输出的 JSON 键一一对应；`TryParse` 严格（未知即拒、全空白等价于没给） |
| 工具 | `BrowserLocateTool` | 新增 `fields` 参数：严格解析，未知字段名 ⇒ `browser_invalid_arguments` 并回**合法清单**；解析结果传给展示投影 |
| 工具 | `BrowserToolContracts.BrowserToolResponse.Element` | 投影接受白名单：未选中的字段不输出；**给了白名单它就是权威**（列了 `value`/`selectedValues`/`checked` 即等于要它们，不必再传 `include_value`/`include_checked`） |

新增门禁：

- 契约层：默认集合保持既有行为且**未知名字为假**（集合成员判定不能对任意字符串返回真）；核心字段在
  任何白名单下都在；未知字段被拒并报出名字；全空白等价于没给；线名**不含下划线**（保证调用方照抄
  输出键就能用）；payload 大头都在可裁剪集合里；
- 工具层：`fields:["name"]` ⇒ `name` 在，而 `text`/`boundingBox`/`role`/`inViewport` **真的不在**
  （不是"恰好为空"），核心 `ref`/`visible`/`enabled` 仍在；`fields:["value"]` 单独就能拿到表单值；
  未知字段 ⇒ `browser_invalid_arguments` 且消息含合法清单；**字段名与输出 JSON 键一一对应**
  （全部请求时每个线名都能在输出里找到同名键）。

**取红实测**：让展示投影忽略白名单（永远返回全字段）⇒
`Locate_FieldsWhitelist_TrimsThePayloadAndUnknownNamesAreRejected` **恰好变红**；复原后 48/48 复绿。

## 已知边界（诚实登记）

- **`fields` 只作用于定位输出**：`browser_snapshot` 的同名参数尚未实现（设计把 `fields` 列为读取类
  通用参数；契约真源 `BrowserElementFields` 已经就位，接入快照是下一步）。
- **核心字段不可裁剪**：想要"只要 ref 一个字段"做不到（`tag`/`visible`/`enabled` 仍会返回）。
  这是刻意的：它们小且是判断"能不能动"的依据；若要极致省预算，应改快照/大纲模式而不是继续削字段。
- **`inViewport` 仍是 `bool?`**：未观测为 null，不伪造成 false。
- 未验证真机（本环境跑不了 WebView2）；本轮改动不涉及驱动。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_locate` 新增 `fields`；不传时行为**完全不变**（默认全字段 +
  既有的 `text==name` 省略规则）。传了之后输出更小；未知字段名不再被静默忽略而是明确报错。
- 无数据/配置影响；线缆 DTO 未改动（`fields` 是展示层参数，不下发到驱动）。
