# 手动压缩切换故障与诊断保持

## 归因

关联 `compaction:msg-1793075606853-x73blklf`、traceId `09e0d29bdc0d510a9e4ae0ee0e2353f2`。
12:36:04 的服务日志已记录摘要提交完成，覆盖 455 条消息，记录的 Token 计量从 249505 降为 10206。
随后 `/api/session/main/rebind` 在 `AtomicFileWriter.File.Replace` 抛出“无法删除要被替换的文件”，上游 errorId 为 `92f1268954f4`。
后续会话绑定未完成，HTTP 的通用 500 文案又覆盖了前端收到的详细事件。未能追溯当时具体文件持有者。

## 改动

- `Source/PuddingCore/Configuration/AtomicFileWriter.cs`：内部 JSON 读取允许原子替换；Windows 32/33/1175 最多七次尝试，累计退避 1575 ms，取消可中断。失败保留原文件、清理临时候选并保留系统错误码与尝试次数；不把 1176/1177 纳入可安全重试集合。
- `Source/PuddingController/Services/InMemorySessionRepository.cs`：新增/更新/删除在成功持久化之后发布内存；主会话提升与降级逐步发布已落盘事实，部分失败时与重启后的路由一致，可对同一后续会话重试绑定。
- `Source/PuddingCore/Platform/CompactionRequestException.cs`、`Source/PuddingPlatform/Services/Conversation/RequestCompactionHandler.cs`：HTTP 与持久事件共用安全失败合同；区分配置、摘要、会话切换及结果发布阶段；保留 `summaryCommitted`。无实际压缩时不创建后续会话。
- `Source/PuddingController/Controllers/SessionController.cs`、`Source/PuddingPlatform/Services/PlatformApiClient.cs`、`Source/PuddingPlatform/Controllers/Api/SessionEventsController.cs`：贯通上游存储 errorId、系统错误码、尝试次数与压缩 errorId/traceId；原异常只留服务端。
- 前端 `useCompaction.ts` 与 `utils/compactionFailure.ts`：统一 HTTP/SSE 诊断展示；通用 HTTP 失败不得覆盖已收到的完成或详细失败事件；手动跳过不计为成功压缩。版本 **6.10.5**。
- 更新受影响代码地图与[诊断手册](../../../08_how_debuge/14-案例-调度与Token内核.md)。

## 验证

- Core 文件写入 **8/8**：真实 Windows 读句柄占用、释放后成功、持续占用有界失败、取消及读取快照并存。
- Platform **19/19**：压缩阶段与已提交事实、关联 ID、无收益跳过、上游错误白名单及异常响应体。
- Web API/会话仓储 **19/19**：真实 HTTP 失败响应与持久事件对应、持久失败不提前发布内存、部分主会话转移与重启一致、绑定 API 存储诊断。
- 前端 **22/22**：详细 HTTP 诊断、SSE/HTTP 乱序终态保护、手动跳过等。合计 **68 项**，无跳过。
- 首次 HTTP 集成回归三项因派生测试宿主与已运行宿主共享 DataRoot 租约失败；`CustomWebApplicationFactory` 支持在独立工厂内注入服务替身，修复夹具后重新通过。
- 测试证据保留于 `temp/test-out/compaction-handoff/`、`temp/compaction-handoff-*.log`。实际用户会话没有被当作测试数据重放。
- 修改文档 Front Matter 校验通过，`git diff --check` 通过；全 Docs 扫描仍报告 26 个历史断链，本次修改文档没有断链，未批量修正无关历史文档。

## 部署与边界

修复已达到 `ready-for-external-deploy`，部署结果待 Guardian 健康验收后追加。
