# 2026-10-17 DeepSeek 工具自述补充实测观察

## 目标 / 背景

同日真实调用实测报告（[`2026-10-17-DeepSeek-Search-Fetch工具实测.md`](2026-10-17-DeepSeek-Search-Fetch工具实测.md)，提交 `72b1ea9`）对 `deepseek_search` / `deepseek_fetch` 做了 8 次真实调用，全部 PASS，并提出三处观察项：

1. 部分页面正文被反斜杠转义（如 `\#`、`\|`、`https\:\/\/`）；
2. 小众词检索相关性弱，`Rerank` 仅 0.121～0.773，建议把 `Rerank` 当可信度闸门；
3. 站点自带 404 页面仍返回 `exit 0`，成功不代表目标存在。

本任务**不改工具执行逻辑**，只做三件事：① 独立复现并定性转义来源；② 对"是否自动去转义"做工程决策并记录理由；③ 把三条使用约束写进两个工具的自述（模型可见文本），并加回归断言防止后续被改掉。

## 改动

| 文件 | 改动 |
|------|------|
| [`DeepSeekSearchTool.cs`](../../../../Source/PuddingRuntime/Tools/BuiltIns/Search/DeepSeekSearchTool.cs) | 工具自述【坑】新增：`Rerank ≥1.5` 为高相关、`Authority ≥3` 为极权威；`Rerank` 明显偏低（如 `<1.0`）应视同"未检索到"而不是证据；中英文各一句 |
| [`DeepSeekFetchTool.cs`](../../../../Source/PuddingRuntime/Tools/BuiltIns/Search/DeepSeekFetchTool.cs) | 工具自述【坑】新增：正文由上游清洗，部分页面标点会被上游转成反斜杠形式，**工具按原文返回、不改写**（自动去转义会破坏代码块/合法 Markdown）；HTTP 成功只表示取到正文，站点自带的 404/"Page Not Found" 页面也会成功返回，判断目标存在性看 title 与正文 |
| [`DeepSeekSearchToolTests.cs`](../../../../Source/PuddingRuntimeTests/Tools/DeepSeekSearchToolTests.cs) | Descriptor 测试新增 2 条断言：自述必须含 `Rerank 分 ≥1.5` 与 `未检索到` |
| [`DeepSeekFetchToolTests.cs`](../../../../Source/PuddingRuntimeTests/Tools/DeepSeekFetchToolTests.cs) | Descriptor 测试新增 2 条断言：自述必须含 `按原文返回` 与 `Page Not Found` |

未改：执行逻辑、参数、输出渲染格式、权限分类（仍 `Low` / `AutoAllowed` 免授权）、配置解析、组件代码。

## 验证

**转义归因（Lead 直连原始 DeepSeek API，不经 Pudding 的任何代码路径；key 运行时读本机配置、不打印）**

| 探针 | HTTP | content 长度 | 反斜杠转义标点 | `\/` 序列 | 样例 |
|------|------|--------------|------------------|-----------|------|
| `POST /v1/tools/search`（`need_content=true`，DeepSeek 官方指南页） | 200 | 5,694 | **0** | **0** | 无 |
| `POST /v1/tools/fetch`（同一指南页 URL） | 200 | 6,402 | **502** | **53** | `\#` `\-` `\:` `\.` `\|` |
| `POST /v1/tools/fetch`（`https://example.com`） | 200 | 931 | **11** | 0 | `\.` `\,` `\;` |

⇒ 结论：**转义由上游 Fetch 响应正文本身携带**（同一 URL 的 Search `content` 路径未转义、Fetch 路径转义；不同页面转义密度不同），Pudding 组件/工具既无 `Escape` 也无 `Unescape`，实测报告的三步归因成立。

**"不自动去转义"的决策理由**：上游转义是 Markdown 语义（`\#` 渲染即字面 `#`），盲目删除反斜杠会破坏代码块、正则、Windows 路径等合法内容；若未来确需清洗，应先有"仅处理围栏外标点"的明确规格与取红用例，不能作为事后补丁实现。因此本任务只把限制告知调用方（工具自述 + 本日志）。

**门禁**

- `dotnet build Source\PuddingRuntime\PuddingRuntime.csproj --nologo` → **exit 0，0 错误**。
- `dotnet test Source\PuddingRuntimeTests\PuddingRuntimeTests.csproj --no-restore --nologo --filter "FullyQualifiedName~DeepSeek"` → **40 通过 / 0 失败 / 1 跳过（41）**（跳过项为未 opt-in 的 Live；本次未新增真实调用）。
- `dotnet test Tests\PuddingHost.Tests\PuddingHost.Tests.csproj --no-restore --nologo --filter "FullyQualifiedName~DeepSeek"` → **1 通过 / 0 失败**。
- `code_map_check.py --check`（根 + Runtime + 组件）→ **error 0**，指纹已随本次源码变更刷新。
- 文档门禁：`front_matter.py --check` 覆盖本日志 0 不合规；`check_md_links.py` 本日志无失效链接（全仓其余既有失效链接与本次无关）。
- 未重跑实测报告的 8 次真实调用（本次只改自述文本，无行为变化；转义归因已用 3 次原始 API 探针完成）。

## 未完成 / 未覆盖
