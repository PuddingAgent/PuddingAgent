# 2026-10-12 SSH L3：同步入口、停止回调有界与单一清理预算

## 目标 / 背景

独立复核 **F6（P1）**：exec 与 Dispose 的同步入口仍能卡住业务等待（deadline 120 ms、宽限 50 ms，
实测 820 ms 返回且 `Status=Completed`；Dispose 同步阻塞时 `ssh_test` 实测 806 ms，两例 `ActiveStageWorkers=0`）。
按补充方案 §3 修补。

## 改动

- `Source/PuddingSsh/Execution/SshCleanupBudget.cs` — 新增**单次清理预算**：从清理开始起算的绝对预算，
  TERM/排空/关闭/Dispose 只取剩余额度；它是资源回收，**不受业务 deadline 影响**
  （修掉「一处按业务剩余取 0、另一处又新开 2 秒」）。
- `Source/PuddingSsh/Execution/SshOperationCoordinator.cs`
  - exec 与会话 Dispose 的**调用本身**分别放进阶段池/关闭池（`StartAsync` 先取令牌再调度），
    外部线程立即拿到可等待句柄；超时后句柄由租约继续持有；
  - 全流程改用同一份 `cleanupBudget`（关闭、exec 宽限）；
  - **迟到完成不覆盖终止事实**：`lifetime.IsStopped` 且结果为 `Completed` 时改写为本地 Cancelled/TimedOut，
    但保留远端证据（`ExecutionState`/`ExitCode`/`ExitSignal`/输出）；新增 `RewriteAsLocalTermination`；
  - `StopAsync` 进入即建立停止 deadline：`Cancel` 放到 worker 上纳入同一次有界等待，
  新增 `SshStopReport.CancelCallbacksPending` 如实报告未返回的取消回调；
  - 诊断拼接改用 `SshDiagnosticText.BoundedJoin`，`append` 不再绕过 512 字符上限。
- `Source/PuddingSsh/Execution/SshCoordinatorOptions.cs` — `SshStopReport` 增加 `CancelCallbacksPending`。
- `Source/PuddingSsh/Diagnostics/SshDiagnosticText.cs` — 新增 `BoundedJoin`。
- `Source/PuddingSshTests/SshFakes.cs` — 假会话支持 `SynchronousBlockBeforeDispose`（同步入口）与 `DisposeCallCount`。
- `Source/PuddingSshTests/SshSyncEntryBoundaryTests.cs` — 新增 7 例：
  1. `SynchronouslyBlockingExec_IsBounded_AndNeverReportsCompleted`（3 秒同步阻塞；采样确认它占着有界 worker、
     取消后业务有界返回且不报 Completed、资源继续占账）；
  2. `SynchronouslyBlockingDispose_IsBounded_OnBothEntries`；
  3. `BlockingCancellationCallback_DoesNotBlockStopAsync`（会话在 token 上注册 2 秒阻塞回调；Stop 有界返回 +
     `CancelCallbacksPending=true` + 如实报告在飞资源）；
  4. `CleanupBudget_IsIndependentOfOperationDeadline`（300 ms 释放 + 600 ms 预算 ⇒ `CleanupState=Completed`）；
  5. `LateExecSuccessWithinGrace_DoesNotOverwriteLocalTermination`（状态保持 Cancelled、远端 `Exited` 证据保留）；
  6. `CleanupState_RequiresCloseEvidence_AndFaultedDisposeIsNotCompleted`（自报未关闭 / Dispose fault 都不算 Completed）；
  7. `ConcurrentCloseCalls_ShareExactlyOneCloseTask`（6 轮竞争：`DisposeCallCount == 1`）。
- `Source/PuddingSshTests/SshResourceAccountingTests.cs` — 新增 `StageWorkerPool_SyncBlockingWork_HoldsTokenUntilItEnds`
  （同步阻塞期间令牌仍被占用）。

## 验证

- **取红**：临时把 exec 调用还原为「直接调用 + 事后等待」→ 门禁 **失败 836 ms**（与复核实测 820 ms 同形），
  恢复后通过；随后用新鲜构建确认门禁真实生效（此前的两次"异常"经定位是 `Copy-Item` 保留旧时间戳导致
  增量构建跳过重建，已用强制重建排除）。
- **复绿**：`dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **228/228 通过**，0 警告 0 错误。
- 真实协议：`powershell -File TestScripts/ssh-probe/run-ssh-probe.ps1` → **23 场景 `failures = 0`**：
  `cancel` 1.5 s 收敛且服务端确认 `SHELL_GONE`；`noeof` 关闭 11 ms、reader 归零；
  `rounds` 九轮后三项计数全 0；`throughput` 驻留 ±0.6 MiB。
