# 2026-10-08 拖拽 8/8：表面执行（收官）

| 改动 | 内容 |
|---|---|
| ① | 移除拖拽早退（"needs a target point"）⇒ 与点击/移动共用检查 |
| ② | `PerformAsync`：`PointerClick`/`PointerMove`/`PointerDrag` ⇒ `PointerAsync(kind, x, y, toX ?? 0, toY ?? 0)` |
| ③ | 用例：拖拽请求补 `toX: 30, toY: 40`；断言改为 unsupported（替身不支持该可选能力）+ `LastAction == null` |

## 过程记录（一个"失败即证明"的好例子）

上一轮（round-345）⑧ 应用后该用例**红了**：`ArgumentException : Pointer drag requires both toX and toY` —— 这是 round-342 的**契约校验在构造阶段生效**，说明"拖拽缺终点"根本到不了表面。⇒ 用例该改（补 `toX/toY`），而不是把校验放宽。**这正是"先写用例"的价值：它逼出并证明了一层真实的防线。**

## 诚实边界

- **拖拽与坐标点击/移动的"正面路径"仍无用例**（需实现 `IPointerInputPage` 的**记录型假页**；现只有负面覆盖）；
- 契约层的拖拽校验（缺 `toX` 即拒 / click 带 `toX` 即拒）与线缆往返（含 `(0,0)` 终点）**尚无断言**；
- `observationId` 的**观察登记处**未实现（带 id 一律拒绝）；**未跑全量链**；**未真机验证**。
