# 2026-10-08 流式路径串联用例：逐轮硬保护成立、落库降级路径被真实触发（并修归一化丢身份）

> 范围：`Source/PuddingRuntimeTests/Services/WarmPrefixMidTurnHardProtectionE2ETests.cs`（+1 例、并改造脚本化 LLM 支持原生工具调用）、
> `Source/PuddingRuntime/Services/ContextWindowManager.cs`（身份重绑）
> 依据：[ADR-095](../../../07_architecture/109ADR-095会话上下文维护与首增量延迟治理ADR.md) D2/D5、
> [修复方案](../../../12_features/首Token等待与上下文指示器修复方案-2026-10-07.md) §3
> 前序：[端到端证据（缓冲路径）](2026-10-08-端到端证据逐轮硬保护与F2落库.md)、[持久消息身份登记](2026-10-08-持久消息身份登记.md)

## 1. 流式路径串联用例（新增）

`POST /stream` 走的 `ExecuteStreamAsync` 此前只有缓冲路径的等价证据。新用例复刻同一剧本
（第 0 轮软维护延期 → 助手正文把请求推过硬阈值），实测：

| 断言 | 结果 |
|---|---|
| 第 0 轮只做**软维护延期**（日志 `Warm-prefix soft maintenance deferred … headroom=2337`） | ✅ |
| 越界后**逐轮硬保护恰好压缩一次**（摘要调用 1 次） | ✅ 与缓冲路径一致 |
| 终态后维护仍执行、枚举结束时租约已释放 | ✅ |

**过程中发现并修掉的测试夹具问题**：流式路径的「继续下一轮」靠**原生 tool-call 增量**
（状态 JSON 只走缓冲路径）。最初复用缓冲路径的脚本（状态 JSON + 单条 `ContentDelta`）⇒
`toolCalls=0`、只跑 1 轮、自然没有越界。已让脚本化客户端按 `TaskE2EHarness.ScriptedLlmClient`
的既有形态产出 `ToolCallIndex/ToolCallId/ToolCallNameDelta/ToolCallArgsDelta` 并在有工具调用时
`FinishReason="tool_calls"`。

## 2. 落库：流式路径当前会走**降级**分支（真实触发，非新缺陷）

实测日志：

```
[AgentExec:Compaction] Warm-prefix checkpoint committed … durableCheckpoint=False
  durableSkipReason=unresolved_durable_identities:29
```

即：流式路径下被替换跨度的 29 条消息**没有解析到持久 MessageId**，F2 的提交边界按设计
**拒绝写库**（绝不允许部分标注）。这既是「安全默认被真实触发」的正向证据，也是一处**已知缺口**：

- 缓冲路径能落库（上一批已证），流式路径目前不能；
- 用例因此把断言写成**不变式**而不是「必须落库」：
  **要么完整落库**（摘要行 + 逐行标注 + 代际三者一致），**要么明确降级**（三者全零 +
  日志带 `durableCheckpoint=False` 与 `durableSkipReason=`）。

## 3. 修掉一个真实缺陷：归一化之后身份登记失效

`BuildContextFromDbAsync` 原先在 **`SanitizeForLlmContext`（内部走 `LlmMessageSequenceNormalizer`）
之前**登记身份。归一化会**复制/重排/丢弃**消息对象，于是登记表里记的是那批被丢弃的实例 ——
真正进入历史的对象一条都解析不到。这正是上面 `unresolved_durable_identities:29` 的根因方向之一。

改法（保守优先）：

1. 先按原行投影收集 `(对象, MessageId)`；
2. 归一化**之后**，再按 `(role, content)` 把身份**重绑**到归一化产物上；
3. **只有该键在源集合里唯一时才绑定** —— 内容重复的多条消息宁可不绑（绑错行 = 静默隐藏真实消息）；
4. 绑不上的保持「没有持久行」，由提交边界拒绝落库（安全默认不变）。

## 5. 未完成

- **流式路径的 warm-prefix 落库仍未打通**（降级到内存-only）。下一步必须先定位「谁在归一化之后
  又替换/重建了会话身份登记表」，再决定是补登记点还是把登记改为不随重建丢失的结构；
  在此之前**不得**把流式路径写成「已持久化」。
- 缓冲路径的重启恢复仍是单元级覆盖；T6 的实际部署与真实 smoke 未做（需进程外控制器）。
- 交付状态仍为 **ready-for-external-deploy**；无真实模型调用、无部署、无浏览器证据。
