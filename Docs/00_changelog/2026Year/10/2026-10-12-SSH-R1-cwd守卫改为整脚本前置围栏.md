# 2026-10-12 SSH R1：cwd 守卫改为整脚本前置围栏

## 目标 / 背景

审阅报告 **F1 / P1**：`cd -- '<cwd>' && <command>` 只约束了命令的**第一段**，复合脚本（分号、换行、`||`、
pipeline、后台列表、行尾注释）在 cd 失败后仍会执行，且后续段退出码覆盖 cd 的失败。按
[ADR-096 D1](../../07_architecture/110ADR-096SSH执行前置围栏与有界终止ADR.md) 改为整脚本前置守卫。
本切片只修组件与独立测试/探针，不触碰宿主。

## 改动

- `Source/PuddingSsh/Validation/SshPosixCommand.cs` — 有 cwd 时的执行串改为
  `cd -- <单引号编码 cwd> || exit $?` + `\n` + **原样**命令；分隔符固定 `\n`（非 `Environment.NewLine`），
  不拼 `set -e`、不用 subshell 包裹原脚本；无 cwd 时保持原脚本不变。
- `Source/PuddingSshTests/SshPosixCommandGuardTests.cs` — 新增 15 例回归（守卫独占第一行、LF-only、
  无 `set -e`/subshell、六类复合脚本都保留守卫行且脚本体逐字不变、恶意 cwd 不能逃逸、无 cwd 不加包装、
  非法 cwd 仍分别返回 `request_invalid`/`config_invalid`、审批与执行两条路径执行串逐字相同）。
- `Source/PuddingSshTests/SshCommandAndRequestTests.cs`、`SshOperationCoordinatorFaultMatrixTests.cs` —
  更新精确执行串期望（旧期望编码的是缺陷形式）。
- `Source/PuddingSsh.Probe/Program.CwdGuardScenario.cs` — 新增 `cwd` 场景：cwd 不存在 × 六种复合形态
  （分号/换行/`||`/pipeline/后台/注释）必须零输出、非零退出，随后用独立一次执行核对六个 marker **都不存在**；
  cwd 存在时验证分号、换行、`||`、pipeline、here-doc、后台列表、带空格与单引号的 cwd、`exit 7` 原样保留。
- `Source/PuddingSsh.Probe/ProbeOptions.cs`、`Program.cs`、`TestScripts/ssh-probe/run-ssh-probe.ps1` —
  新增 `--cwd`/`--missing-cwd` 与该场景，并按探针自报的 `connections` 数核对服务端认证次数。

## 验证

**先取红再复绿**（ADR 要求）：

- 新增回归在旧实现下 **12/15 失败**（守卫不是独立行、含 CR、复合脚本未受保护、恶意 cwd 可逃逸）。
- 修补后：`dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **137/137 通过**，0 警告 0 错误。
- 真实协议：`powershell -File TestScripts/ssh-probe/run-ssh-probe.ps1` → **17 场景 `failures = 0`**。
  `cwd` 场景实测：六种 cd 失败形态 stdout 全空、退出码 1（非零）、`MARKERS_CHECKED`（无 `PRESENT`）；
  cwd 正常时 `FIRSTSECOND` / `FIRST` / `ABC` / `heredoc-ok` / `BG` / `pwd=/tmp/pudding cwd's` / `exit 7` 全部保留；
  16 次执行只用 4 条连接（服务端认证 4 次，与探针自报一致）。
- 环境事实：夹具 `/bin/sh` 是 dash；`cd -- <dir>` 在 dash 与 bash 都成立，`cd` 失败退出码非零（本机实测 1–2），
  因此 ADR-096 D1 的字面形式可移植。
