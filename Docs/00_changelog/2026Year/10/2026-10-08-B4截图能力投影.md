# 2026-10-08 B4 收尾（桌面半边）：截图能力的只读投影

## 交付

新增 `Source/PuddingBrowser.Automation/BrowserScreenshotPlanner.cs`（+`BrowserScreenshotIntent`、
`BrowserScreenshotPlan`、`BrowserScreenshotPlanning`、`BrowserScreenshotScope`）：

`TryPlan(intent) → plan | 明确拒绝原因`。它**不采集、不落库、不发授权**，只做判定与尺寸计算。

| 设计依据（§8.1/§8.2） | 投影中的落地 |
|---|---|
| 先视口与区域裁剪，全页随后 | `FullPage` ⇒ **`FullPageNeedsSeparateHandling`**（诚实的不支持） |
| 截屏前验证 page read grant | 缺授权 ⇒ `NoReadGrant` |
| 截屏不切换到未授权页面（当前文档） | 非当前文档 ⇒ `TargetDocumentNotCurrent` |
| 必须等 ContentLoading 后采集（否则是导航前画面） | 未就绪 ⇒ `PageNotReady` |
| 坐标受**视口边界**约束 | 区域越界 ⇒ `RegionOutOfViewport`（拒绝，**不裁一半**） |
| 默认 `detail=low` 最长边 ≤512px | 等比缩放；**小视口不放大**（放大＝凭空造像素） |
| 上限 8 MiB | `MaxBytes` 取自 `BrowserScreenshotTransfer.MaxImageBytes` |

计划结果还带上 `ObservationRequirements`：把 §8.1 要求上报的元数据（源/输出尺寸、设备缩放、CSS viewport、
scroll offset、裁剪变换、三代修订号）**写进计划**，接线时照做即可、不会漏项。

| code_map | 已登记新文件 |

## 诚实边界（诚实登记）

- **仍是"桌面半边的判定"，不是采集**：`CapturePreviewAsync` 的真实调用、等待 ContentLoading 的时序、
  WebView2 生命周期耦合**都没做**（属 S5 接入，且需决定②）。
- **`FullPage` 现在只是"明确不支持"**：设计允许后续做，但要单独处理滚动拼接/固定元素/动态布局 —— 未做。
- **未做像素/字节的实测校验**：`ExpectedOutputWidth/Height` 是**计算值**（JPEG 编码后的真实字节由编码器决定），
  因此"预期尺寸"不等于"实测尺寸"，真正的上限仍由 `BrowserScreenshotTransfer` 的校验兜住。
- **`Region` 以 CSS viewport 像素表达**（与 §8.2 一致）；元素级裁剪（按 ref 取 bbox）尚未接入。
- **未真机验证**；决定②仍待确认。
