# 2026-10-02 Roslyn 批量更新接缝实现

## 改动

- `Source/PuddingCodeIntelligence/CSharp/RoslynCSharpIndexer.cs`：
  - 实现 `ICodeIndexFileBatchUpdater.UpdateFilesAsync`：**一个批次只打开一次工程/编译快照**
    （`using var roslynWorkspace` 在批次内只出现一次），随后逐文件 `FindCompilationForFileAsync` +
    `ExtractFileAsync`，把结果包成 `CodeFileIndexPayload` 返回 —— **一个索引字节都不写**。
    原子提交（索引行 + 源指纹/消费者水位）由调用方经 `ReplaceFilesAsync` 完成。
  - 结果语义：非 `.cs`、噪声路径、**不在已加载工作区里**的 `.cs` ⇒ `NotApplicable`（能力路由结果）；
    工程根缺失、工作区打不开、单文件提取抛错 ⇒ `Retryable` 带路径级原因（按退避重试，**不升级整仓**）；
    单文件失败不影响同批其它文件。
  - `SessionKey = roslyn:{ProjectPath}:{ConfigurationFingerprint}`：批内复用的快照标识可观测。
  - 构造器新增**可选** workspace opener 参数（默认 `RoslynWorkspaceBootstrapper`）：
    使「批内只打开一次工程」成为可断言的合同（测试注入内存 `AdhocWorkspace`），
    也让替代宿主能提供自己的工作区加载器；生产路径行为不变。
  - 逐文件 `IndexFileAsync` 与全量 `IndexWorkspaceAsync` 的既有行为**未改动**。
- 新增 `Source/PuddingCodeIntelligenceTests/CSharp/RoslynCSharpIndexerBatchTests.cs`（8 条，全部在内存
  `AdhocWorkspace` 上运行，**不依赖 MSBuild**）。
- `Source/PuddingCodeIntelligence/code_map.md`：语言索引器表登记批量能力，消费侧登记
  `CSharp/RoslynCSharpIndexer.cs` 的两条路径分工（本文件此前未登记该文件条目）。

## 验证

- `dotnet test Source\PuddingCodeIntelligenceTests\PuddingCodeIntelligenceTests.csproj` → **117 通过 0 失败**
  （本次 +8）；`Source\PuddingCodeIndexTests` → **280 通过 0 失败**（未受影响）。
- 关键用例：**两个文件只打开一次工作区**（注入 opener 计数 = 1）；批处理**不写索引**
  （批后 `GetSymbolsByFileAsync`/`ListFilesAsync` 均为空）；非 `.cs`、工作区外的 `.cs` ⇒ `NotApplicable`；
  工程根缺失 ⇒ 全部 `.cs` `Retryable` 且**不尝试打开工程**；工作区打不开 ⇒ 全部 `.cs` `Retryable`
  且非 `.cs` 仍是 `NotApplicable`；重复/大小写变体/空白路径去重；空批不打开工作区；
  payload 携带关系（`Calls`）与引用且符号属于该文件。

## 更正（相比 2026-10-02 语言批量接缝那一篇的表述）

那篇写「语言侧产出 `CodeFileSemanticChange`」。实现时改为：**语义差异由调用方计算**
（payload + 上次已提交符号 → `CodeFileSemanticDiff`）。理由：差异需要「上一次的符号」，
那是持久索引状态的读取；让语言侧去读旧索引会把「提取」和「维护状态」耦合在一起，
而调用方本来就有 manifest/符号表。语言侧现在只负责提取，接口更窄也更可测。

## 未完成与影响

- **TypeScript / Python 侧的批量实现未做**：它们仍逐文件启动 node/python 提取器进程
  （`ICodeIndexFileUpdater`），批内复用「一次进程/一次快照」的收益尚未落地 —— 下一轮处理。
- **仍未接入维护链路**：`UpdateFilesAsync` 目前没有调用方；`CodeIndexMaintenanceService` 仍走逐文件接缝。
  因此运行中实例仍是零行为变化。
- 未实现**跨批次**的工作区缓存（「有界复用一个快照」只做到批内一次）：跨批次缓存需要明确的生命周期
  所有者、失效条件（配置/解析器策略指纹 + 世代）与内存上限，属于独立任务，不做投机实现。
- 后续阶段：TS/Python 批量实现 → 维护链路接线（扫描 → 计划 → 原子替换 → 账本提交 + 宿主忽略规则适配）。
