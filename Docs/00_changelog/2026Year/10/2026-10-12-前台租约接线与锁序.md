# 2026-10-12 修复：会话前台租约接线、后台提交锁序与停机接线

> 依据：用户转达的复核结论第 3 项（P1）。位置：`TurnExecutorAdapter` 的 Turn 入口、
> `ContextCompactionService` 的提交段、`PostTurnMaintenanceScheduler.StopAsync`。

## 1. 缺陷

1. `AcquireSessionForeground` 在生产代码中**只有定义没有调用**：`TurnExecutorAdapter` 只取 agent 级租约；
   消息入口的 `ReserveSessionForeground` 是**限时预留**（默认 5 秒过期）⇒ 长 Turn 一旦跨过窗口，
   同会话后台可选维护就可能在 Turn 中途开工。
2. 后台压缩提交只取压缩锁，未落实「SessionExecutionGate → CompactionCoordinator」锁序 ⇒
   不能保证整个前台 Turn 期间的互斥语义。
3. 调度器的 `StopAsync` 未接入宿主停机流程。

## 2. 修复

1. **真实入口持租约**：`TurnExecutorAdapter.ExecuteAsync` 在原有 agent 级 `AcquireForeground` 之外，
   增加 `AcquireSessionForeground(context.WorkspaceId, context.ConversationId)`，作用域覆盖
   水合→终态释放整段（`using var` 跨整个迭代器生命周期）⇒ 不再受 5 秒预留窗口限制。
2. **后台提交锁序**：`ContextCompactionService` 新增可选 `ISessionExecutionGate`（DI 已注册，
   自动注入）；**后台**请求（`IsBackground`）在提交段先取会话门、再取压缩锁
   （`await using var gateLease = ... ; await using var commitLease = ...`，释放顺序天然相反）。
   门租约只覆盖短提交（生成阶段不持锁），且锁内已有的「重验④ 前台需求」会零写入让位并释放门
   ⇒ 既不阻塞安全消息，也不与前台互等。前台/手动压缩不受影响。
3. **停机接线**：`AgentExecutionService` 暴露 `StopBackgroundMaintenanceAsync(timeout)`；
   新增 `PuddingHost.Hosting.BackgroundMaintenanceShutdownHostedService` 并在 Runtime 组合根注册
   （`AddHostedService`），停机时协作取消并等待维护退出，异常只记日志、不影响停机。
