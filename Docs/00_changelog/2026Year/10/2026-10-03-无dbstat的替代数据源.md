# 无 dbstat 的替代数据源：按表行数 + 抽样平均行长 ⇒ 按数据类占比

## 背景（接着上一轮的更正）

本仓库的 SQLite **没有 dbstat 虚表**（实测 `no such table: dbstat`），因此"按表占用"曾经无源可依。
本轮补上**替代数据源**，让存储页在无 dbstat 时**仍然有真实依据**的占比可展示。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/PuddingPlatform/Services/StorageManagement/DatabaseTableEstimator.cs`（新） | 每表**精确行数**（`COUNT(*)`）+ 对**有界样本**（默认 200 行）逐列求字节长度（字符串按 UTF-8、blob 按长度、数字 8 字节、NULL 计 1）⇒ 平均行长 × 行数 = 估算占用。只读打开、不加写锁；`ToTableSpaces` 把结果转成与 dbstat 路径**同形**的输入，归并器因此不需要知道来源 |
| `StorageDatabaseSpaceService` | 两种来源同形状：dbstat 可用用它；否则退回估算器。DTO 增加 **`SpaceSource`**（`dbstat` / `rowcount-sample` / `unavailable`）如实带出来源 |
| `PuddingServiceCollectionExtensions.Platform.cs` | 注册 `DatabaseTableEstimator` |
| `StorageDatabaseSpaceServiceTests` | 7 条（含本轮新增）：行数精确（300）、抽样被上限约束（50）、估算量级落在"64 字节 blob × 300 行"的合理区间、来源标注为 `rowcount-sample`、未归类桶含我建的表且占用为正、缺库报 `unavailable` |

## 已知偏差（写在类型文档里，避免误读数字）

1. **索引占用不计入**（只有 dbstat 才有按 B 树明细）⇒ 索引特别多的表被低估；
2. 样本取**前 N 行**，宽窄分布不均的表有偏差（行数越少偏差越小）；
3. 空表返回 0（是"空"，不是"未知"）；
4. 每表一次 `COUNT(*)`：3M 行级表约几十到几百毫秒 ⇒ **只适合显式动作**，不进轮询热路径。

⇒ 因此跨数据类的**相对占比**可用（同一把尺子量所有表），绝对字节数是估算（按用户要求，界面不标注「估算」）。

## 验证

- `PuddingPlatformTests` 与 `PuddingHost` 构建均 **0 错误**；
- `dotnet vstest`：本轮相关两类用例 **7/7 通过**（实测本机构型无 dbstat ⇒ 走估算路径 ⇒ 明细仍非空）。

## 一条必须记录的**工具性失误**（关于我自己的批处理脚本）

前几轮我多次写"ABORTED（nothing written）⇒ all-or-nothing 生效"。本轮发现这**不总成立**：
我这一版 `patch()` 是**逐个立即写盘**的，所以脚本在中途因锚点不匹配而打印 ABORTED 时，
**它之前已经应用的补丁已经落盘了**。本轮因此出现两个症状：① `StorageDatabaseSpaceService.cs`
被"读校验"判为已变更（因为脚本早先真的改过它）；② 后续锚点在同一文件上失败（文件已被前一段改过）。
**结论**：批处理脚本要真正 all-or-nothing，必须"先在内存里全部应用、最后统一写盘"；
我早期的脚本是这个形状，近几轮改成逐个写盘后语义就变了。以后统一回到"内存聚合 + 末次写盘"。
