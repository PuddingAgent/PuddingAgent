# 2026-10-12 SSH B2：SFTP 传输会话、能力实测与发布语义

## 目标 / 背景

按设计 §11.1 的传输内核：流式复制、字节计数与上限、覆盖控制、**发布语义必须实测**、
取消/失败不得留下部分目标、清理失败明确报告残留、不自动重试不提供断点续传。

## 改动

- `Source/PuddingSsh/Contracts/SshTransferPorts.cs` — 新增 `ISshTransferSession`（能力实测/上传/下载/中止/带预算释放）、
  `ISshSftpChannel`（把用到的 SFTP 原语收成小接口，便于确定性单测）、`SshTransferCapabilities`、`SshTransferOutcome`。
- `Source/PuddingSsh/Transport/SshSftpChannel.cs` — SSH.NET 实现：`Open(CreateNew)` 排他创建、
  `RenameFile(old,new,false)` 标准 RENAME、`RenameFile(old,new,true)` posix-rename、
  `ChangeDirectory`+`WorkingDirectory` 取 **realpath**、64 KiB 流式复制（超限立即抛出）。
- `Source/PuddingSsh/Transport/SshSftpTransferSession.cs` — 传输逻辑：
  - **能力实测**（惰性、每会话一次、全部在 scratch 文件上做并清理）：posix-rename 原子替换是否可用、
    标准 RENAME 是否覆盖已有目标、排他创建是否可用；任何异常按「不支持」处理；
  - **发布语义按实测能力选择**：不支持即 `ssh.transfer_unsupported`，绝不退化到「先检查再覆盖」；
  - 上传超限立即中止；失败/取消清理**我们创建的东西**并如实报告是否残留（`TemporaryLeftBehind` + 路径）；
  - 下载：本地同目录唯一临时文件 → `File.Move(overwrite:false/true)` 发布；远端大小超限前置拒绝。
- `Source/PuddingSsh/Transport/SshNetTransportFactory.cs` — 把建连准备（冻结身份 + 默认拒绝的主机密钥回调 +
  有界 Connect）抽成共用 `PrepareAsync`，新增 `ConnectTransferAsync(request, scratchDirectory, ct)`：
  执行与传输共用同一套身份/信任/超时合同，只是通道换成 SFTP；文件系统资源由传输会话释放时一并回收。
- `Source/PuddingSsh/Contracts/SshTransferContracts.cs` — 计划补上 `RemoteRoot`（供会话做父目录 realpath 检查）。
- `Source/PuddingSshTests/SshFakes.Transfer.cs` + `SshTransferSessionTests.cs` — 内存 SFTP 服务端
  （可编排原子替换/标准 rename 覆盖/排他创建/realpath 指向/删除失败，并模拟**部分写入**语义）+ **16 例**门禁。

## ⚠️ 需要审阅人确认的设计取舍（与方案字面不同）

方案 §11.1 写的是「先写同目录唯一临时文件，完成后发布到目标；默认禁止覆盖」。
但**实测**：OpenSSH 的 SFTP 标准 `SSH_FXP_RENAME` 是 `rename(2)` 语义 ⇒ **会覆盖**已有目标
（本仓库能力探针就是围绕这一点设计的）。因此「不覆盖发布」在 OpenSSH 上**无法**用 rename 实现。

两种选择：
- (a) 字面执行：`overwrite=false` 在 OpenSSH 上一律返回 `ssh.transfer_unsupported`
  —— 默认即不可用，等于把默认路径做废；
- (b) **本次实现**：`overwrite=false` 用 SSH.NET 的**排他创建**（`SSH_FXF_EXCL`）直接对目标做
  **原子占位**，失败/取消时删除我们创建的目标；`overwrite=true` 才用「临时文件 + posix-rename 原子替换」。
  两者都由实测能力支撑，都不使用竞态检查冒充原子性，且失败时**不残留部分目标**。

我选了 (b) 并已在代码与门禁里固化；若你要求严格按字面 (a)，改动很小（把 `Fail` 分支改回
「需要 RenameNoOverwrite 能力」即可），但结果是默认上传在 OpenSSH 上不可用。**请裁定**。

## 验证

- `dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **278/278 通过**，0 警告 0 错误（新增 16 例）。
- **变异取红**（三处，证明门禁真能检出缺陷类别）：
  1. 去掉「发布前的能力检查」→ `Upload_NoOverwrite_WithoutExclusiveCreate_IsUnsupported_AndWritesNothing` **红**；
  2. 取消后不清理已落地的目标 → `Upload_Cancelled_DeletesTheReservedTarget`、
     `Upload_ExceedingLimit_AbortsWithoutPartialTarget` **红**（此变异第一次跑是**绿的**，
     原因是假服务端「只在成功时提交」掩盖了部分写入；已把假端修正为真实的部分写入语义，门禁才敏感）；
  3. 覆盖发布不检查 `posix-rename` 能力 → `Upload_Overwrite_WithoutAtomicReplace_IsUnsupported_AndLeavesTargetIntact` **红**。
  恢复后 278/278 绿。
