# 2026-10-31 R1-03 失败运行不再推进已提交水位

## 缺陷

`CodeIndexScheduler` 的 `finally` 只区分了「取消」：

```csharp
if (!cancelled)
    progress.CommittedVersion = startDesired;
```

`cancelled` 只在 `OperationCanceledException` 分支置位；**普通异常**走 `catch (Exception)` 后仍满足 `!cancelled`，于是 `finally` 把已提交水位推到本次期望版本。

实测（新增测试，索引器直接抛异常）：

```
Assert.AreEqual 失败。应为: <0>，实际为: <1>。'progress.CommittedVersion'
```

后果正是门禁禁止的那条：**索引没成功，水位却宣称 current** —— 依赖水位的判据（是否落后、是否需要重构）从此说谎，直到下一次成功运行。

## 改动

- `Source/PuddingCodeIndex/Services/CodeIndexScheduler.cs`：新增 `failed` 标志，`catch (Exception)` 分支置位；`finally` 的前进条件收紧为 `!cancelled && !failed`。
- `Source/PuddingCodeIndexTests/Services/CodeIndex/CodeIndexSchedulerTests.cs`：新增 `FailedRun_DoesNotAdvanceCommittedVersion`（断言 `CommittedVersion == 0` 且 `Behind == true`）。

## 证据（实测）

- **修复前**：`FailedRun_DoesNotAdvanceCommittedVersion` **红**（实际 1，期望 0）。

## 未做 / 边界

- 失败后**未自动重排**（避免 `ProcessPendingAsync` 在失败时无限自旋）：该 scope 保持 `Behind == true`，需要外部再次 `Enqueue` 或驱动轮次重试。这一取舍写在此处，避免被误读成「失败会自动恢复」。
- 「中断（进程被杀）时账本状态」未验证：本修复只覆盖**运行期异常**。
- 不部署。
