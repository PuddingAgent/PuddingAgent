# 2026-10-08 B1 组件侧：页面授权只绑 CallerId 字符串的越权借用

## 缺陷（组件侧审计发现）

`BrowserAutomationAuthority.FindPageGrant` 里，判断"这条页面授权是不是发给**这个**调用者"用的是：

```csharp
if (!string.Equals(grant.Grantee.CallerId, request.Caller.CallerId, StringComparison.Ordinal))
```

而它上方的注释写着"页面授权必须发给**这个**调用者：子代理要自己的子集授权，不能直接借用父任务的授权"。

**问题**：`CallerId` 只是一个字符串。两个**种类不同**的调用者（父任务 Agent vs 子代理），
或**同一调用者在另一个任务里**，只要 id 字符串相同，就能用别人的页面授权 —— 注释承诺的约束并没有真的成立。
（其余检查都在：绑定/帧/过期/范围，唯独"发给谁"只比了字符串。）

## 修法

新增 `IsTheSameActor(grantee, caller)`：**种类 + CallerId + TaskId** 三者都相等才算同一个行动者，
`FindPageGrant` 改用它。

**有意不改**的地方：任务级**管理**授权继续用 `BrowserCallerIdentity.IsSameTaskScope`
（同父任务下的子任务可以共享管理授权，那是设计选择）。两者语义不同，已在 `IsTheSameActor` 的注释里写明，
避免下一个人"统一"成同一条规则。

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **333 / 333**（＋1） |
| 新增取红用例 | ① 同 id **不同种类**（子代理）⇒ 拒绝；② 同种类同 id **不同任务** ⇒ 拒绝；③ **精确行动者**仍放行（防止修得过头） |
| **取红实测** | 把判定改成恒假（等价于取消该检查）⇒ 新用例**变红**；还原 ⇒ 333/333 |
| **未破坏既有流程** | 加严后 `DesktopServiceTests` 315、`DesktopSurface.BrowserTests` 67、`ContractsTests` 153 **全绿** —— 说明没有既有用例依赖"只比字符串"的宽松匹配 |
| 其它套件 | 全部复跑通过（无回归） |

## 过程中被自己的门禁拦下

拆解表门禁 `TheB6WiringDecompositionNamesOnlyExistingFilesAndVerifications` **变红**：我把 S4/S5 标为"已完成"后，
表里**再没有"可做"的步骤**，而该门禁原先要求"至少有一个可做步骤"。
这暴露的是**真实状态**（组件侧已全部完成，其余都等决定），所以我把门禁改成更诚实的形状：
状态列必须是 可做/已完成/被挡 之一，且"已完成"与"被挡"两类都要出现（**故意不要求**必须有可做步骤）。

## 诚实边界（诚实登记）

- **本轮不解决 B1 的决策问题**：它修的是**组件内部的越权判定**，不改"调用方身份从哪来"这一设计问题
  （那仍待决定②）。
- **`TaskId` 是否应当参与匹配，依赖宿主如何生成 id**：我按"更严更安全"取相等；
  若产品上同一 callerId 会跨任务复用（当前实现不是），则需要重新讨论 —— **登记为依赖假设**。
- **生产路径尚未调用**：`Admit` 的活路径接线仍属 B1 本体（未接），本轮验证的是组件层。
- **管理授权仍是任务范围语义**：那是设计选择，本轮的收紧**不**适用于它（若产品要改，需单独决定）。
- 无产品行为变化（组件内部判定 + 用例）。
