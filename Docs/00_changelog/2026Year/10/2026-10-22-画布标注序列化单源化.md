# 2026-10-22 画布标注序列化单源化

## 背景

上一轮为了让「页面 `load()` 回读的标注 JSON」和「制成品文件里的 `annotations`」形状一致，
另起了一份 `PanelAnnotationWire`，并配了 14 个单元测试。

复核时发现这本身就是**第二份实现**：`PanelCanvasRestore.BuildPayload` 早就是「标注 → JSON」的既有实现
（页面恢复走它），再造一份只能靠测试维持两边一致 —— 字段名或 kind 一旦分叉，症状是
「保存成功、继续编辑却没有标注」，即**存得下、读不回**，而且没有任何一处会报错。

按架构第一原则（边界显式、单源），撤掉新实现，让制成品直接嵌入既有输出。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/PuddingDesktop.Foundation/PanelAnnotationWire.cs` | 删除（连同其测试文件），从未提交过 |
| `Source/PuddingDesktop.Foundation/PanelCraftStore.cs` | 删掉 57 行手写标注序列化与 `KindToWire`（−61 行），`source.annotations` 改为 `WritePropertyName("annotations")` + `WriteRawValue(PanelCanvasRestore.BuildPayload(...))` |
| `Source/PuddingDesktop.Foundation/PanelCanvasRestore.cs` | `BuildPayload` 补文档：声明这是唯一实现，并说明两边各自手写字段名会怎样静默分叉 |
| `Source/PuddingDesktop.FoundationTests/PanelCraftStoreTests.cs` | 新增 `Saved_annotations_reuse_the_canvas_restore_payload_verbatim` |

`source` 为 `null` 时仍显式写 `null`（既有契约不变）；外层 `Indented = true` 不传给 `BuildPayload`，
嵌入的是紧凑文本，读回方按 JSON 解析而非按行。

## 断言为什么是「逐字相等」

用例落到 `Path.Combine(_store.CraftsDirectory, saved.Id + ".json")` 取成品文件，
`JsonDocument.Parse` 后断言 `root.source.annotations.GetRawText()` 与 `BuildPayload(annotations)` 字符串相等
（样本含 scribble 双点轨迹、arrow 反向端点、text 中文标签）。

逐字相等一次抓住三类分叉：属性名（`annotations` vs `annotation`）、kind 词表（`scribble` vs `box`）、
以及「有人再写回一份手写序列化」。代价是：若将来外层改成非缩进输出，断言需同步调整。

## 验证

- **变异取红两份**（`temp/mut_payload.ps1`，ASCII-only pwsh）：
  M1 把 payload 换成空数组、M2 把属性名改成 `annotation` —— 两次都 `exit=1` 且 `[FAIL]` 精确命中该用例。
- **复原**：`WriteAllBytes` 回写原始字节并刷新 mtime（否则 msbuild 复用旧程序集），
  复原后 SHA-256 与原始 `A093099A…` 逐位一致。
- **全量**：461 通过 / 0 失败 / 0 跳过（`Source/PuddingDesktop.FoundationTests`，171 ms）。

## 两条仪器教训

1. `python` 在本机 cmd 只有 Microsoft Store 的别名桩，运行即打印
   `Python was not found` ——但命令链**仍返回 exit 0**，探针「首跑成功」其实是根本没跑。
   `Tools/Docs/*.py` 一类脚本改走 WSL 的 `python3`。
2. 这条新测试第一版读的是图像文件（`saved.FileName`）而不是 JSON，却仍然「通过」——
   因为断言比的是内存里现成的对象，压根没碰落盘内容。回归测试必须锚在**落盘字节**上，
   且路径要来自 store 的真实命名规则。
