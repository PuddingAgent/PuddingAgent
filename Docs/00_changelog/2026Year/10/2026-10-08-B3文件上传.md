# 2026-10-08 B3 文件上传：三步 CDP + 上传前校验，DOM 面明确不支持

## 目标 / 背景

`upload`（`SetInputFilesAsync`）一直是桩。它是 B3 输入面的最后一块，链路与上一轮拖拽同构，
但多了一个特性：**不能靠合成事件**——页面脚本无权设置 `input.files`（浏览器安全模型），
只能让浏览器自己把文件交给元素（CDP）。

## 改动

| 层 | 改动 |
|---|---|
| Automation | `FileUploadPlan`（新增，纯函数）：**选择器转义**（ref 里的引号/反斜杠必须转义，否则选择器无效或选错元素）、三步请求形状（`DOM.getDocument` → `DOM.querySelector` → `DOM.setFileInputFiles`）、文件清单校验（空/相对路径/超量在**触达浏览器之前**拒绝）、节点 id 读取 |
| Abstractions | 策略增加 `BuildFileUploadDocumentParameters` / `BuildFileUploadQueryParameters` / `BuildFileUploadSetFilesParameters`；Null 实现返回 `null` ⇒ 明确不支持 |
| 契约 | `DesktopInteractionAction.Upload` + `FilePaths`；`ValidateShape` 强制「至少一个文件」；线名 `"upload"` 入冻结清单；`SupportsNativeInput` 收录（上传不是合成事件，是真实浏览器路径，故同属"原生面"，已在代码注释里写明理由） |
| 能力通道 | `Upload` → `page.SetInputFilesAsync(locator, filePaths)` |
| 驱动 | 三步 CDP 实现：元素不存在 ⇒ `browser_element_not_found`；`querySelector` 返回 0 ⇒ **按引用过期** `stale_element_reference`（节点被换掉/页面变了）；缺策略支持 ⇒ 明确 unsupported |
| 工具 | `action=upload` + `files` 参数；**上传前**拒绝空清单与相对路径（相对路径的含义取决于浏览器进程的工作目录，猜基准目录是不诚实的） |

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **276 / 276**（＋4） |
| `ContractsTests` · `AgentTools` · `DesktopSurface.BrowserTests` · `DesktopService` · `PuddingDesktop` · `Host` | 153/153 · 64/64 · 66/66 · 231/231 · 320/320 · 258/258 |
| 构建 | `WebView2` · `WinUI` · `Contracts` · `DesktopService` · `DesktopSurface.Browser` · `AgentTools` 已成功生成 |

新增门禁：选择器转义（含 `"` 与 `\`）；三步请求各自带上下一步需要的字段；文件清单校验（空/null/相对/空白/超量
逐项拒绝，绝对路径通过）；节点 id 读取（正常/缺字段/类型不对）。

**取红实测**：去掉节点 id 读取的**类型判断** ⇒ `NodeIdsAreReadFromResponsesOrRefused` **恰好变红**；复原后 276/276 复绿。

**测试抓出的真实缺陷（值得记录）**：`JsonElement.TryGetInt32` 在 JSON 类型不是 Number 时**抛异常**而不是返回
`false` —— 我最初的实现会让一个畸形 CDP 响应把异常抛到调用方。测试先红后修，现已显式判 `ValueKind`。
这正是"写着 Try 却会抛"的经典坑。

## 已知边界（诚实登记）

- **真机未验证**：三步 CDP 的序列与参数有纯函数测试，但"`DOM.setFileInputFiles` 在真实 WebView2/页面上确实
  完成上传"必须由外部进程内 smoke 复核（本环境无 WebView2）。
- **只支持 `input[type=file]`**：对拖放区/自定义上传控件不适用（那类需要原生拖拽，见上一轮的 drag）。
- **不校验文件是否真实存在**：存在性由浏览器在 `setFileInputFiles` 时判定（错误会被如实报出）；
  工具侧只做"路径形状"校验，避免把"文件在 Core 机器上存在"当成"浏览器进程能读到"。
- **不区分 `multiple`**：多个文件会一起交给同一个元素；元素不支持多选时由浏览器决定结果（不猜测）。
- **`Upload` 被归入原生面**：理由（不是合成事件而是真实浏览器路径）写在契约注释里；若将来有纯 DOM 上传路径，
  这条归类需要重新审视。
- `PuddingDesktop` 整体产物未重新生成（本机运行中的 Shell 占用输出文件）。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_interact` 新增 `action=upload`（要求 `files` 绝对路径清单与
  `input_mode=native`）；其它动作不受影响；DOM 模式下由驱动明确 unsupported。
- 回滚：还原 `FileUploadPlan`、策略三步方法、契约动作/字段、驱动实现、工具接线与测试/冻结清单。
