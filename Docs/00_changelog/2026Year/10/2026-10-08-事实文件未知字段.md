# 2026-10-08 外部观察事实：未知字段不再被静默忽略

## 缺陷（同类：静默丢/吞字段）

`ExternalAcceptanceFacts.TryParse` 只读 `observedBuildId` / `smoke[]` / `lifecycle[]`，
对**其它字段一律静默忽略**。最难查的一类问题就是"**我写了却没生效**"：

- 有人把 `acceptRetries: true` 写进观察事实（它其实是**命令行开关**）⇒ 被忽略 ⇒ 他以为已接受重试，
  实际结论仍被拒（round-128 刚加的规则）——**误解会一直查到人不耐烦为止**；
- 键名拼错（`obsBuildId`）⇒ 唯一后果是"缺少必填字段"的报错，尚可查；
- 多写整段（如 `notes`）⇒ 静默丢掉，观察者以为记录了。

## 改动

`TryParse` 增加**未知顶层字段拒绝**：只允许 `observedBuildId` / `smoke` / `lifecycle`；
对 `acceptRetries` 额外给出可操作提示：
> accepting retried results is a command-line switch: --accept-retries / -AcceptRetries, not part of the observation facts

## 门禁（跨语言键名约定）

`EveryKeyTheTemplateWritesIsActuallyReadByTheParser`：模板由 **PowerShell** 写、解析器由 **C#** 读；
若模板改了键名而解析器没跟上，后果不是编译错误而是"外部一方的观察被当成缺失"（静默否定）。
这条要求 `observedBuildId` / `smoke` / `checkId` / `outcome` / `evidence` / `lifecycle` / `step` / `passed`
在**两侧源码**里都出现。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **329 / 329**（＋2） |
| **取红实测 ①** | 删掉未知字段检查 ⇒ 相应用例**变红**；还原 ⇒ 329/329 |
| **取红实测 ②** | 把脚本里的 `checkId` 改名 ⇒ 键名门禁**变红**；还原 ⇒ 329/329 |
| 既有 fixtures | 全绿 ⇒ 现有观察事实里没有未知字段（规则未误伤） |

## 诚实边界（诚实登记）

- **只校验顶层键**：`smoke[]`/`lifecycle[]` 元素内部的未知键仍被忽略（登记为可扩展项）。
- **键名门禁是源码文本断言**：它保证"两侧都提到这些键"，**不**保证解析逻辑真的用了它们
  （那由 `ACompleteFactsFileIsParsedIntoAConcludableInput` 等行为用例负责）。
- **`acceptRetries` 的提示是特例硬编码**：若将来又出现类似的"常见误写"，需要同样加一条提示（登记）。
- **未真机验证**；两项待决取舍未触碰。
- 无产品行为变化（解析规则收紧 + 用例）。
