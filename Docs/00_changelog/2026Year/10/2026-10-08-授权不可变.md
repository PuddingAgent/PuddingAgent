# 2026-10-08 B1 组件侧：同 GrantId 换内容会静默提权

## 缺陷（本会话第二处授权缺陷）

`IssueGrant` / `IssueManagementGrant` 原先都是按 GrantId **直接覆盖**：

```csharp
_grants[grant.GrantId.Value] = grant;      // 同 id 再来一份，直接替换
```

而授权记录在设计上是**不可变**的（"撤销不是改这条记录的字段，而是把它从注册表移除并推进 epoch"）。
覆盖的后果很实在：

| 环节 | 结果 |
|---|---|
| 已签发租约 | 记录的是**签发时**的 `GrantEpoch`；覆盖**不推进** epoch ⇒ 租约仍然"有效" |
| `Revalidate` | 只比对 epoch（未变）⇒ 放行 |
| `FindPageGrant` | 找到的是**新**记录 ⇒ 范围/受让人已被悄悄换掉 |
| 净效果 | **在同一个授权世代内改变授权内容** = 绕过世代检查的静默提权 |

## 修法

新增 `EnsureGrantIsNotSilentlyReplaced`，两个签发入口都调用：

- 同 GrantId **原样重发** ⇒ 幂等放行（宿主重试同一签发是正常行为）；
- 同 GrantId **内容不同** ⇒ `ArgumentException`，并在消息里指明正确做法
  （"撤销旧记录再签发新的" —— 撤销会推进 epoch，租约随之失效）。

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **335 / 335**（＋2） |
| 新增取红用例 | ① 只读授权 → 同 id 换成读写 ⇒ **拒绝**，且**旧记录仍按窄范围生效**（写操作仍被拒）；② 原样重发幂等（不重复登记）；③ 管理授权同样处理（含换受让人） |
| **取红实测** | 去掉不可变守卫 ⇒ 新用例**变红**；还原 ⇒ 335/335 |
| **未破坏既有流程** | `DesktopServiceTests` 315、`DesktopSurface.BrowserTests` 67、`ContractsTests` 153、`PuddingDesktop.Tests` 320 全部复跑**全绿** |

## 诚实边界（诚实登记）

- **不改"身份从哪来"的设计问题**：本轮仍是组件内部一致性（授权不可变），B1 的调用方身份决定未动。
- **依赖"宿主不会合法地复用 GrantId 改内容"**：若产品确有"原地更新授权"的需求，应改成**显式更新 API**
  （并推进 epoch），而不是放宽本守卫 —— 登记为依赖假设。
- **生产路径尚未调用**（B1 活路径接线未做）；本轮验证组件层。
- **`RevokeManagementGrant` 不释放页面租约**（有意：撤管理授权不该杀掉在途页面写）—— 本轮未改，登记为语义说明。
- 无产品行为变化（组件内部判定 + 用例）。
