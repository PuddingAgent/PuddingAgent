# 2026-10-08 Core 侧签发生产者（第一刀）

## 为什么

Desktop 侧整套（受理、子集校验、期限夹取、ack、五条级联释放）**已就绪且有用例**，但**生产上没有任何调用方** ⇒ 不会有 grant ⇒ 开闸门后浏览器能力会被全线拒绝（round-197 结论）。本类就是那个缺失调用方的形状。

## 交付

| 件 | 内容 |
|---|---|
| `DesktopCapabilitySender`（委托） | "发一次能力调用"的形状：可指向真实 `DesktopSession`（发送路径见 `DesktopSession.cs:567`），也可替身化 |
| `DesktopBrowserBindingProducer` | 组装 `ForBindingApply(binding)` + `DesktopCallContext`（**身份随调用走**）⇒ 发送 ⇒ 还原 ack |
| `DesktopBindingIssuanceOutcome` | `(Issued, GrantId, Epoch, Reason)`，只陈述事实 |

## 验证（3 条，TRX 判定）

| 用例 | 判据 |
|---|---|
| accepted | `Issued=true`、`GrantId` 一致、请求带的是该绑定 |
| rejected | `Issued=false`、无 grant、原因可区分（`parent grant`） |
| 通道抛异常 | `Issued=false`，原因含异常类型名 —— 不把炸了当成功 |

## 诚实边界

- **未接真实通道**（下一步接 `DesktopSession` 发送路径）与**真实触发点**（目标事实来自 Bridge 的 `IsAgentTarget` 描述符）；
- **"回复无 ack"分支本轮无用例**（我原用 `FromSnapshot` 构造，其工厂签名与预期不符；分支代码仍在，登记待补）；
- **未跑全量链**；**未真机验证**。
