# 2026-10-18 前端D3b健康期整页轮询降级

## 改动

- `ChatClientStore` 快照新增 `lastLiveEventAt`：`applyLiveEvent` 成功缝合时更新；用于判断 SSE 是否仍在提供活动 Turn 事实。
- `chat/index.tsx` 后台校正 effect：
  - 当 `lastLiveEventAt` 在 10s 内且活动 Run 仍为 `running` 时，旧 `/conversation` 整页轮询从 **1200ms 降级为 5000ms**（SSE 负责正文/过程增量）；
  - 终态 Run（`status !== 'running'`）或 SSE 静默超时仍回到 1200ms，用一次有界快照校正物化终态消息行；
  - idle 仍为 5000ms，异常/失联路径保留有界校正。
- store 测试补充 `lastLiveEventAt` 断言。
- 前端版本 `6.7.0 → 6.7.1`；frontend code_map 更新 ChatClientStore 边界。

## 验证

- `pnpm exec jest chatClientStore.test.ts`：**15/15 通过**。
- `pnpm run build`：成功，`[chat-bundle-budget] ok sync=1383742 chat=361898 common=432307`。
- `pnpm run tsc`：仅基线既有错误，本次文件无新增类型错误。
- 未部署、未重启 Core、未改 `D:\data`。

## 未完成与影响

- 本轮只**降级**健康期轮询，尚未完全移除；完全移除需 D3c：
  1) SSE 终态事件直接驱动消息行/snapshot 校正（而非依赖定时轮询）；
  2) 显式 SSE 连接状态（connected/degraded/reconnecting）驱动轮询开关；
  3) 断线重连 replay 与快照游标对齐的集成测试；
  4) 真实 WebView2 验证 live/终态/重连无丢字、无重复、终态不回退。
- 打开路径仍是旧 `/conversation`；D2c 切换统一快照后，健康期整页轮询可随旧入口一并退役。
- 生成期间 5s 校正意味着极少数 SSE 丢失场景下终态消息最多延迟约 5s；这是有界降级而非静默失败，终态事件到达后会立即回到 1.2s 档。
