# 2026-10-08 更正：Host 已经引用了 Automation

## 更正（我多轮说错的一句话）

我此前反复写"B0 不接宿主 / B1 活路径未接"。审计后的事实：

| 事实 | 证据 |
|---|---|
| `PuddingHost` **已经引用** `PuddingBrowser.Automation` | `Source/PuddingHost/PuddingHost.csproj`；由 **B1 首段**提交 `74ca0e5` 引入 |
| Host 侧桥面**真的在用**它 | `BridgeBrowserCapabilitySurface.cs:564` 调 `BrowserMutationPostcondition.Validate`，与 DesktopService **同一份**判据 ⇒ 正是 §4.2/§1.1 要求的"两条传输不得各自验出相反结论" |
| **Core 侧不引用** | `PuddingAgent` / `PuddingRuntime` 的 csproj 里没有 Automation 引用 ✅ 边界仍成立 |

**准确表述**：**已接线的是"判据共用"；未接的是"可信调用身份的准入与租约"**（`Admit`/写租约走活路径）——
后者才是卡在决定①上的东西。总览第五/八节已更正。

## 把边界做成门禁

`TheBrowserAutomationComponentKeepsItsCompileTimeBoundary`：

1. **Core 不得引用**：`PuddingAgent` / `PuddingRuntime` 的 csproj 文本里不得出现 `PuddingBrowser.Automation`；
2. **Host 必须引用**：若有意取消接线，必须同时改本用例与设计文档 —— **不许"悄悄不接"**；
3. **理由要在代码里看得见**：Host 桥面必须仍调用 `BrowserMutationPostcondition.Validate`。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **339 / 339**（＋1 边界门禁） |
| **取红实测** | 给 `PuddingAgent.csproj` 临时加一行 Automation 引用 ⇒ 门禁**变红**；还原即绿 |
| 真实断言 | 三条（Core 无引用 / Host 有引用 / 桥面调用判据）在**当前代码上全部成立** |

## 诚实边界（诚实登记）

- **门禁是文本级**：它读 csproj 与源文件文本，不解析 MSBuild 条件（例如 `Condition` 下的引用同样会被计入）。
- **只覆盖 Core 与 Host 两侧**：Desktop 侧（DesktopService/WebView2/AgentTools）**预期**引用 Automation，未纳入断言。
- **"未接身份准入"是我基于代码与文档的判断**：未做逐条调用链核对（该结论与 §10 的 B1 行一致）。
- **本轮未跑全量链**（只改了 csproj 门禁与文档，无产品行为变化）；如需要可下轮复跑并更新快照。
- **未真机验证**；B1 身份与 250ms 门限仍未拍板。
