# 2026-10-18 浏览器会话准入源码不变量守卫（I2 防回退）

## 目标与结论

I2 把 Bridge 页面命令的准入从"旧页级 grant 闸门"切换为"会话权威单一准入"。这类切换最容易的退化方式不是编译错误，而是后续修改里**悄悄恢复旧闸门**（两条准入同时裁决），而常规行为测试未必立刻变红。

本轮新增 `Tests/PuddingDesktop.Tests/Browser/BrowserSessionAdmissionSourceGuardTests.cs`，以源码不变量钉住：

- 派发器**不得**再出现 `HasSufficientPageGrant` / `page_grant_required`；
- 会话准入四步必须都在：`AuthorizeSessionCommand`、`TryClaimControlOwner`、`AuthorizePageCommand`、`RevalidatePageCommand`、`CompletePageCommand`；
- owner 必须来自宿主注入的 `Origin`（`ConversationId ?? SessionId`），不得改用其它来源；
- 生命周期组件必须持有 `AgentTargetSessionAuthority` 并经 `OfferTarget`/`TryClaimOwner` 接入；
- 标量门面文件不得暴露 Authorization 类型；`DesktopService` 必须引用 Authorization 叶子组件。

同时把派发器类文档更新为当前职责（单一准入 / 单一幂等 / 运行控制只阻断副作用），避免"文档还写着旧 grant 闸门"。

## 验证

- `dotnet test Tests/PuddingDesktop.Tests --filter "FullyQualifiedName~BrowserSessionAdmissionSourceGuardTests"` ⇒ **3/3 通过**。
- **反向对照（实测变红）**：临时在派发器源码加入 `// GUARD-NEGATIVE-CONTROL: page_grant_required` ⇒ `BridgeDispatcher_HasExactlyOneSessionAdmissionPath` **1 失败**（`Assert.DoesNotContain`），移除后复绿。
- 全量 `Tests/PuddingDesktop.Tests` ⇒ **350/350 通过**。
- 未运行产品/真机；本守卫保护的是实现形态与接线，不替代行为测试与 I3/I4 验收。

## 未完成与影响

- 守卫是**文本级**的：它证明"旧闸门 token 不再出现 / 四步仍在"，不能证明运行时语义；运行时语义由 `BrowserSessionAdmissionTests`、`BrowserBridgeAdmissionTests` 与组合根截图测试覆盖。
- I2 剩余（Bridge 页面命令执行迁入 `DesktopService` 执行器、旧 authority 页面 grant/租约路径退役）仍未做，goal 保持 active。
- 回滚 = revert 本提交（仅测试 + 注释）；无产品行为变更。
