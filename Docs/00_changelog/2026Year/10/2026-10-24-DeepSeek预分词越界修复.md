# 2026-10-24 DeepSeek 预分词越界修复

## 归因

用户的 `execution_protocol_error / Specified argument was out of the range of valid values` 对应本地
`BpeTokenizer.CountTokens → MeasureLlmRequest → TryWarmPrefixCompactionAsync` 异常，发生在发送请求之前。
现有 Microsoft.ML.Tokenizers 2.0.0 CompositePreTokenizer 对未匹配片段使用了错误长度，Span 入口还提前归还缓冲区。
合成样本 `你好 world 😀` 加换行可复现；将 CountTokens 换成 EncodeToIds 同样会失败，不能解决根因。
参考对应包提交的 [CompositePreTokenizer 源码](https://github.com/dotnet/machinelearning/blob/efefa92f4486a43047c5b47618885a71bf7f0967/src/Microsoft.ML.Tokenizers/PreTokenizer/CompositePreTokenizer.cs)。

## 改动

- `Source/PuddingTokenization/IsolatedSplitPreTokenizer.cs`：执行原始词表的顺序 Isolated Split；保留 gaps/tail，特殊标记先隔离，Span 在返回前物化区间。
- `Source/PuddingTokenization/ScalarRegex.cs`：修复 .NET 正则 Unicode 大类缺少补充平面字符的差异，保持原始 UTF-16 坐标；不修改用户文本或 BPE 字节。
- `DeepSeekTokenizerJsonLoader.cs` 接入上述实现，拒绝不支持的 Split 行为。
- 组件测试增加独立 Rust HuggingFace 0.22.1 Unicode 向量、区间覆盖、Span 生命周期、长输入并发回归。
- `Source/PuddingCoreTests/Platform/ExactTokenizerRequestMeasurementTests.cs` 覆盖生产 CountTokens 和预压缩请求测量；更新组件/Core 地图与诊断手册。

## 验证

- 修复前：新增 Unicode/区间用例 2 失败，捕获实际越界异常。
- 修复后：组件测试 25 通过、0 跳过；已有 Node 黄金向量及新增 16 组 Rust Unicode 向量逐 ID 一致。
- Core 定向回归（精确词表）：15 通过，1 个“未配置词表”场景按预期跳过；独立未配置进程回归 4 通过。
- 原词表 SHA-256：`c90dfa01249db1be4245780a052ede752e1361c612ac6d08e2bdada7d599476b`。
- 未完成：提交时尚未部署；真实用户会话续行仍须在新 Core 加载后确认。本轮不改历史终态，不主动重放外部消息。
