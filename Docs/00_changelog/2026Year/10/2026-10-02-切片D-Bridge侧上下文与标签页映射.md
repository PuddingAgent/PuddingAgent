## 目标 / 背景

继续把 Bridge 侧的窄端口补齐（上一轮迁移了 `page_state` / `navigate` / `execute_javascript`）。
本轮补 `contexts` 与 `tabs`——它们是七个工具最先用到的两个操作（先解析上下文/页面，再动作）。

## 改动

- `Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs`：
  - `GetContextsAsync`：`ListContextsAsync` → 逐个 `GetContextAsync`/`ListPagesAsync`；
  - `TabsAsync`：`Activate` → `BringToFrontAsync`；`Close` → `ClosePageAsync` 并回 `TabClosed=true`；
    其它动作回 `InvalidRequest`（`DesktopTabAction` 只有这两个成员）；操作后**重算剩余清单**。
- `Tests/PuddingHost.Tests/BrowserBridge/BridgeBrowserCapabilitySurfaceTests.cs`（+4 项，合计 199）。

## 刻意保留的诚实语义

- **没有活版本的页面不进清单**——这不只是我们的约定：契约本身也禁止
  （`DesktopPageInfo` 构造时无活版本即抛「references die with the page version」）；
- 页面标志**逐个取实体**后如实上报（`CanGoBack`/`CanGoForward`/`IsLoading`），
  而不是从清单里的 `PageInfo` 猜（清单没有这些字段）；
- `IsActive`/`IsAgentTarget`/`Trust` 在 Bridge 侧**无从得知** ⇒ 取保守值 `false`/`Untrusted`，
  并在代码与日志里写明：**Desktop 侧的目标注册表才是这些字段的权威，工具不得用它们做准入判断**
  （这是两条传输之间的已知不对称，需在工具迁移时遵守）；
- 清单里有、实体取不到的上下文/页面 ⇒ **跳过**，不编造空条目；
- 标签页状态取自**操作之前**（关闭后再读不可靠）；关闭后剩余清单重算。

## 两条测试自身的教训（产品代码是对的）

1. 断言读错了对象：`BringToFront` 的计数在**页面**替身上，我却读了上下文的计数器 ⇒ 假红。
2. 两个页面替身共用了同一个 `PageId`，导致 `GetPageAsync` 都命中第一个 ⇒ 清单出现两条相同页面。
   显式接口实现下，替身的**身份字段必须可区分**，否则"按 id 解析"的测试是假绿/假红。
   两条都属测试替身缺陷，产品代码未受影响（已在替身里修正）。
