# 2026-10-31 R1-02 partial 类型跨度取所有声明并集

## 缺陷

`RoslynCSharpIndexer.AddDeclaration` 只取**第一个**声明语法：

```csharp
var declarationSpan = symbol.DeclaringSyntaxReferences
    .FirstOrDefault()?.GetSyntax().GetLocation().GetLineSpan();
```

`partial class Split` 有两个声明时，`INamedTypeSymbol` 的 `DeclaringSyntaxReferences` 有两条，但只读第一条 ⇒ 索引里 `Split` 的跨度停在第 6 行（第一个声明的结束），第二个声明（8–11 行）**在索引里不存在**。实测：

```
Assert.AreEqual 失败。应为: <11>，实际为: <6>。'split.EndLine'
```

后果：`workspace_open` 打开 partial 类型只返回一半；分块边界同样漏掉后一半。

## 改动

- `Source/PuddingCodeIntelligence/CSharp/RoslynCSharpIndexer.cs`：`AddDeclaration` 改为收集**所有** `DeclaringSyntaxReferences` 的有效行跨度，`StartLine` 取最小、`EndLine` 取最大；仅在没有声明语法（元数据符号）时回退到标识符位置。保留了「`ISymbol.Locations` 指向名称标识符、会塌成单行」这条历史说明。
- `Source/PuddingCodeIntelligenceTests/CSharp/RoslynCSharpIndexerTests.cs`：新增 `PartialType_SpanCoversAllDeclarations` + partial 夹具（两声明分别在 3–6 / 8–11 行）。

## 证据（实测）

- **修复前**：`PartialType_SpanCoversAllDeclarations` **红**，`EndLine` 实际 6、期望 11。
- **变异取红**：把 `Max(EndLinePosition)` 改成 `Min`（等价「只看第一个声明」）⇒ **恰好 1 红**（该条）。
- **还原**：按备份字节写回，SHA-256 位级一致 ⇒ `RoslynCSharpIndexerTests` **13/13 复绿**。
- **无新增回归**：`PuddingCodeIntelligenceTests` 全量 151 条中 6 条失败，与基线（6 条）双向差集为空。
