# 2026-10-08 B3 原生滚动：真实滚轮事件 + 只读回读事实

## 目标 / 背景

§7：真实输入路径要覆盖"滚动"。此前 `input_mode=native` 对 `scroll` 明确 unsupported
（见 [B3 原生输入接线](2026-10-08-B3原生输入接线input_mode-native可用.md) 登记的边界）。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| Abstractions | `ScrollOptions.InputMode` | 运行时滚动选项带上输入路径 |
| 驱动 | `WebView2BrowserPage.ScrollAsync` | `InputMode == Native` 时走 `ScrollNativelyAsync`：落点 = 元素中心（元素目标）或**视口中心**（页面目标，尺寸取自 CDP `Page.getLayoutMetrics` 的 `cssLayoutViewport`，**不猜窗口大小**）→ `NativeInputSequence.PlanScroll` 发 `Input.dispatchMouseEvent(mouseWheel)` → 之后用一次**只读** DOM 观察（位移 0 的滚动不改任何东西）把容器/前后位置/边界/内容变化取回 |
| 能力通道 | `BrowserRuntimeDesktopSurface` | `ScrollOptions` 带上输入路径；`scroll` 加入原生支持清单；**到达类目标（`to_top`/`to_bottom`/`to_ref`）在入口明确拒绝**（`unsupported_capability`，提示用 `dom`），不悄悄退回 DOM |
| 工具 | `BrowserInteractTool` | `SupportsNativeInput` 加上 `scroll`，失败提示同步为 `.../hover/scroll` |

## 验证

| 套件 | 结果 |
|---|---|
| `DesktopSurface.BrowserTests` | **65 / 65**（原 64 ＋ 1） |
| `AgentTools.Tests` · `PuddingDesktop.Tests` · `AutomationTests` · `ContractsTests` · `DesktopServiceTests` · `Host` | 61/61 · 320/320 · 240/240 · 152/152 · 229/229 · 258/258 |

新增门禁：原生滚动请求 ⇒ 驱动收到的 `ScrollOptions.InputMode == Native`；原生 + `to_bottom` ⇒
`unsupported_capability`（消息点明 native scroll），**不静默退回 DOM**。

**取红实测**：把"原生不支持到达类目标就拒绝"短路（＝允许悄悄退回 DOM）⇒
`NativeScroll_CarriesTheMode_AndRefusesArrivalTargets` **恰好变红**；复原后 65/65 复绿。

**已知既有 flake**：`Host.Tests` 的
`DesktopBrowserBridgeHandshakeTests.SecondConnection_CannotReplaceAwaitingHelloConnection`
本轮失败 1 次、重跑即绿（与本次改动无关，已多次记录）。

## 已知边界（诚实登记）

- **输入原生、观察 DOM**：滚轮事件本身不返回结果，因此事实来自滚动后的一次只读观察。这意味着
  "原生滚动"的原生部分只是**输入**；如果页面用自定义滚动（`overflow` 容器 + JS 惯性），观察仍按 DOM 语义读，
  可能与该页面的"逻辑位置"不同 —— 真机需复核（本环境无 WebView2）。
- **到达类目标未实现**：`to_top`/`to_bottom`/`to_ref` 在原生路径下明确拒绝。用一次大位移滚轮"近似"是不诚实的
  （未必到达，且惰性加载会继续填充），因此宁可拒绝。`atBoundary`（来自回读）能让调用方自己判断是否到了边界。
- **落点是中心点**：元素中心可能被遮挡（原生滚轮是"指针下的可滚动祖先"接收），因此与 DOM 路径
  "在目标容器上滚"的语义不完全等价；遮挡判断（`elementFromPoint`）目前只用于点击类动作，未用于滚动。
- **每次原生滚动会推进 PageVersion**：与其它交互一致（版本推进代表"页面被操作过"），即使位置没变。
- 起点是 `Page.getLayoutMetrics`：它给的是**布局视口**；有缩放（`Emulation.setPageScaleFactor`）时
  逻辑坐标与 CSS 坐标可能不同——当前未处理缩放，属真机待验证项。
- 本轮只加"支持清单"的同步，**没有**合并工具层与能力层两份清单（重复仍在，已多次登记）。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_interact` 的 `input_mode=native` + `action=scroll` 从"明确 unsupported"
  变成**真实滚轮输入**；到达类目标仍是明确失败。`input_mode=dom` 的滚动行为完全不变。
- 回滚：还原上表 4 个生产文件与 1 个测试文件、两个 code_map。
