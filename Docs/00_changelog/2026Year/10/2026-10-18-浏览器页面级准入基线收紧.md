# 2026-10-18 浏览器页面级准入基线收紧（F3）

## 目标与结论

审阅报告 F3：`BrowserPageLifecycle.HasSufficientPageGrant` 在 `Authority.ConnectionGeneration.IsLive` 时**无条件返回 true**，而 Bridge 对带显式 `PageId` 的请求就用这条判据 ⇒ 该浏览器控制器已持有的任意页面都能被 Agent 驱动，“取消目标/不选目标”无法拒绝，非目标页也无法拒绝。这直接违背 ADR-097 D4「Bridge 在线只证明传输活性，不授予任意页面的控制权」。

本切片删除这条全局放行，页面可驱动只剩两个**页级**来源：

1. 用户在 Desktop 上显式选中的 Agent 目标页（`BrowserTargetRegistry.IsAgentTarget`；切换/撤销目标后旧页立即不再命中）；
2. 能力通道签发的页级 grant（`Authority.ActiveGrants`，按调用者/目标/范围/有效期校验）。

## 改动

- `Source/Pudding.DesktopService/BrowserPageLifecycle.cs`：重写 `HasSufficientPageGrant` 的判据（删除“桥在线 ⇒ 任意页面”的过渡分支），注释说明为何不能再用传输在线代替目标归属。
- 新增 `Source/Pudding.DesktopServiceTests/BrowserPageScopedBaselineTests.cs`（5 条）：桥在线不授权任意页、选中目标页无需 grant 即可读/写、切目标后旧页失效、撤销目标后失效、页级 grant 仍可授权非目标页。
- `Tests/PuddingDesktop.Tests/Browser/BrowserBridgeAdmissionTests.cs`（3 条）：Bridge 层配对——桥在线但未选页 ⇒ `page_grant_required` 且 handler 调用 0；用户选中目标页 ⇒ 无 grant 也成功且 handler 恰好 1 次；非目标页即便桥在线也拒绝。
- `Source/Pudding.DesktopService/code_map.md`：更新生命周期端口的准入判据语义。

- **后绿**（恢复修复）：同命令 ⇒ **6/6 通过**；配对正向用例 `UserSelectedTargetPageIsDrivableOverTheBridge` 证明没有退回“一律拒绝”。

## 未完成与影响

- **产品行为变化（有意）**：默认 Bridge 路径上，未把页面交给 Agent 时页面命令现在被拒绝（此前被全局放行）。这是 F3 的目标语义；但“用户选页”在默认路径的完整链路仍有缺口：`AttachBrowserTargets` 只在能力通道启动时调用 ⇒ 默认路径两个目标注册表没有页面/上下文登记，`DesktopService` 准入（截图执行器/通道）会判 `invalid_target`，且页面版本长期为 Unknown。该登记上移属下一片（I2 前置）。
- **F1 仍未闭合**：截图执行器即使接上，旧 authority 的页级 grant 准入仍无来源；需 I2 会话准入。
- `BrowserBindingGate` / 委派生命周期未改动；能力通道签发的 grant 语义不受影响。
- 回滚 = revert 本提交；无配置/数据变更。
