# R4 ⑤-b：申请（fail-closed）+ 四个撤销站点

| 环节 | 行为 |
|---|---|
| 申请（真实子 runId 之后） | `TryRequestBrowserDelegationAsync` ⇒ 失败即**撤销 + 抛错**（**fail-closed**） |
| 未装配端口 / 父未声明 | **不申请**（行为与今天一致） |
| 声明但不完整 | **明确拒绝**（缺 contextId/pageId/scope 任一） |
| 缺可信父 run id | **拒绝** |
| 被拒 | 返回**带理由**的失败 |
| **撤销** | **四站点齐备**：成功 / 异常 / 取消 / **启动失败**（本轮按日志标记定位补齐） |

**验证**：Platform 编译通过 · **`PuddingPlatformTests` 1438/1438** · 自查 `RevokeBrowserDelegationAsync` 出现 **6 次**（定义 1 + 调用 5）

**自记的一次纪律应用**：首版第四站点文本锚点未命中 ⇒ 我**拒绝提交"申请已接但撤销缺一"的状态**（会悬挂授权），改用**日志标记定位**补齐后才提交。

## 仍未完成

Host 侧 `IBrowserDelegationLifecycle` 实现 + 组合根注册 · **装配级用例**（申请成功 / 被拒 fail-closed / **四路径都撤销**）· 真机/250ms。

## 诚实边界

- 申请与撤销均已接线，但 **Host 侧实现未接** ⇒ 生产默认端口为 `null` ⇒ **暂无实际委派行为**；**未真机验证**。
