# 2026-10-02 能力通道接入 Shell 组合根（切片 C-3 Desktop 侧接线完成）

## 目标 / 背景

计划里「唯一会改变产品行为」的一步、也是 Desktop 侧最后一段接线：把能力通道接进 `PuddingDesktop`。
按设计，**判定与装配都在可脱 UI 测试的组件里**，Shell 只负责「取只有它知道的事实 → 调一次 → 退出时释放」。

## 改动

- `Source/PuddingDesktop.WpfArchive/Core/CoreProcessSession.cs`、`CoreProcessSupervisor.cs` —
  把 Core 就绪信号里的 `capabilityEndpoint` 搬进会话（新增 `CoreProcessSession.CapabilityEndpoint`）。
  描述不含凭据；可用性由 `DesktopCapabilityChannelPreflight` 判定，这里只搬运。
- `Source/PuddingDesktop/MainWindow.xaml.cs` — 只暴露「只有 Shell 知道」的事实：
  `BrowserRuntime` / `BrowserWorkspace` / `CapabilityWindowHandle` / `CapabilityXamlRoot` /
  `CapabilityTrayVisible` / `CapabilityWindowState` / `ShowCapabilityNotification`（窗口本身不含业务判断）。
- `Source/PuddingDesktop/DesktopTrayIcon.cs` — `ShowBalloon`（`NIM_MODIFY` + `NIF_INFO`，显式截断定长字段；
  没弹出来返回 false 而非抛）。
- `Source/PuddingDesktop/Hosting/DesktopApplicationCoordinator.Capability.cs`（新增）+ `DesktopApplicationCoordinator.cs`
  （改为 `partial` + 两处调用点）— 组合根接线：读段 → 组装 `DesktopSurfaceComposition` →
  `DesktopCapabilityChannelComposition.StartAsync`；`OnRuntimeChanged` 里 Core 不再就绪时释放。

## 刻意保留的语义

默认关闭（段缺席即关闭，不注册不连接，行为与之前一致，回滚 = 恢复缺席/`enabled=false`）；
浏览器工作区未就绪 ⇒ **不启动**（fail closed）；令牌取不到 ⇒ 不启动；端点不可解析 ⇒ 预检判「不启动且不回退」；
启用却起不来 ⇒ 打出 `[CapabilityChannel] 未启动：<code> — <message>`（可见，不静默留在旧 Bridge）；
**页面版本不在这里喂**（由 `DesktopService` 唯一出口用能力结果回写）；Shell 调用方保持 `Untrusted`；
Core 停止/退出/重启/熔断 ⇒ 释放「同一 DesktopId 单一活动传输」的名额。

## 验证

- `PuddingDesktop` 构建 **exit 0 / 0 错误**，我的文件 **0 警告**；
- 全量门禁复核：7 套件 **537/537**、`PuddingDesktop.Tests` **279/279**、真实端点探针 **53/53 exit 0**。
- **未验证（诚实边界）**：启用态本身。真实 `DispatcherQueue` 线程访问、Desktop 拨入握手、
  Desktop 退出后 Core 侧注册表清空与管道释放，都必须由**外部控制器在重启窗口内**实测
  （接线手册 §6 的 8 步）。Agent 不能验收承载自身的生命周期——代码写完不改变这一点。
