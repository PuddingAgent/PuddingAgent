# 2026-10-07 · 前端：错误卡呈现 + 一键复制完整现场

## 背景 / 动机

用户诉求（附界面截图）：错误只显示一行英文异常 + 「重试」；需要一个**复制**功能，把准确、全面的信息
（含日期、`traceId`、`errorId`）交出来，以便在茫茫日志里定位。后端在 Stage 4-a 已提供
`causeTitle/causeShortCause/causeCode/causePhase/retryable/remediationHint/reportText/reportJson`，
本轮把前端接上。

## 改动

| 文件 | 内容 |
|---|---|
| `src/pages/chat/utils/chatDiagnostics.ts` | ① `formatChatErrorDiagnostic` 读后端的 `causeTitle/causeShortCause/causeCode/causePhase/retryable/remediationHint`，首屏输出**粗体标题 + 大概原因**，诊断信息块新增「因果码/失败阶段/可重试」与「处置建议」（保留 `## 请求失败` 与既有可定位字段，不破子串识别）；② 新增纯函数 `buildChatDiagnosticCopyPayload`：优先用后端 `reportText`/`reportJson`，缺失时本地拼一份同样可定位的文本（时间、errorId、traceId、因果码、阶段、证据、原始消息）并输出结构化 JSON |
| `src/pages/chat/components/MessageList.tsx` | 「复制诊断信息」按钮不再复制浅层 JSON（只有 turn 数/状态），改为复制 `buildChatDiagnosticCopyPayload().text`——**用户点一下就能拿到可直接贴给维护者的完整现场** |
| `src/pages/chat/utils/chatDiagnostics.test.ts` | 新增 3 例：后端字段渲染（标题/因果码/阶段/可重试/处置建议 + 保留 `## 请求失败` 与 `Error ID`）；后端报告存在时**逐字复制**；后端报告缺失时的兜底文本可定位且不含 `undefined` |
| `package.json` | 版本 `6.3.0 → 6.4.0`（新增功能，次版本号） |
