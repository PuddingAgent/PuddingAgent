# 2026-10-02 维护协调器与稳定读指纹

## 改动

- 新增 `Source/PuddingCodeIndex/Services/CodeIndex/CodeSourceFingerprintReader.cs`：
  **稳定读** —— 读前 stat → 读内容 → 读后 stat，**两者一致才认**，hash 来自真正读到的那份内容；
  长度/修改时间在读取期间变化、或内容长度与 stat 不符 ⇒ 返回**不稳定**（调用方必须弃用本轮结果）；
  文件不存在/读不到/超过单文件上限（默认 64MB）⇒ 带原因的失败。`ReadAsync` 为 `virtual`，
  使「不稳定 ⇒ 弃用」这条分支能被确定性验证（真实读写竞争无法在测试里可靠复现）。
- 新增 `Source/PuddingCodeIndex/Services/CodeIndex/CodeSourceMaintenanceCoordinator.cs`：
  把已独立交付的各件串成一条链并固定顺序与失败语义：
  1. `CodeSourceScanService` → **真实变更集** + 捕获版本（此时仍不读正文、不写索引、不动水位）；
  2. 重新读账本（扫描已登记期望版本，不能用陈旧快照提交），算出**仍在退避窗口**的路径；
  3. `CodeSourceUpdatePlanner` 第一遍 → 提取/删除/本轮不动；**语言批量接缝一批只调用一次**；
  4. 每个 Applied payload：**稳定读**算指纹 + 读旧符号算**语义差异**；不稳定/失败 ⇒ 记退避，不提交；
  5. 带上已知符号变化再规划第二遍 → 依赖方（只重绑）与删除集合；
  6. `ReplaceFilesAsync` **一个事务**提交索引结果 + 指纹 + 消费者水位；
  7. 只重绑路径：索引不变，只刷新 manifest 的消费者视图；删除路径：索引行 + manifest 行都清；
  8. 账本 `CompleteCommit`（成功路径清退避、失败路径记退避并计入未解决）→ 只有这一条路径能推进扫描水位。
  - `NotApplicable`（能力路由结果）仍**如实记指纹**并按「消费者视图已最新」推进各消费者，
    否则每轮扫描都会把它当新文件重新读盘。
  - `CodeFileIndexPayload` 增加可选 `Language`，语言侧写入自己的标签，协调器据此写文件记录。
- 新增测试：`CodeSourceMaintenanceCoordinatorTests`（10 条，真实 SQLite store + 真实临时文件 + 脚本化语言接缝）
  与 `CodeSourceFingerprintReaderTests`（5 条）。
- `Source/PuddingCodeIndex/code_map.md`：登记稳定读与维护协调器两条目。

## 验证

- `dotnet test Source\PuddingCodeIndexTests\PuddingCodeIndexTests.csproj` → **295 通过 0 失败**（本次 +15）。
- 协调器用例锁定：**一批只调用语言接缝一次**；两文件都提取且索引/指纹真的落地；捕获版本推进；
  **指纹未变 ⇒ 第二轮一次提取都不发生**（不读正文）；
  语言报待重试 ⇒ 只影响该路径、**水位不前进**、账本记下退避、成功那份仍提交；
  **退避中的路径不在同一时刻重试**且仍算未解决；时钟推过退避后必须重试并恢复提交；
  **不稳定读 ⇒ 不写指纹、不写索引、记退避、水位不动**（确定性替身）；
  **不完整扫描绝不删除**、完整扫描才删索引行与 manifest 行；
  无消费者认领的路径记指纹并按已解决处理；没有批量能力时按路径退避而非整仓重建；能力缺失时整轮只读。
- 稳定读用例：稳定文件的 hash 等于其内容的 SHA256、长度等于 stat；内容变化 hash 变化；
  文件消失与超上限是失败而非不稳定；非法上限被拒。
- 组件边界不变（`ProjectReference` 仍为空）；`PuddingCodeIntelligenceTests` 未受影响。

## 未完成与影响

- **仍未接入宿主**：协调器目前没有调用方（`CodeIndexMaintenanceService` 仍走旧路径），
  因此**运行中实例仍是零行为变化**，本轮不构成任何性能结论，也不需要重启。
- 下一代（收尾阶段）：宿主 DI 装配 + 把 `PuddingPathFiltering` 适配成 `ICodeSourceIgnoreRules` 注入 +
  watcher 事件节流/合并 + 调度节拍 + 替换「无 owner ⇒ 整仓」旧路径；随后**必须由外部控制器重启**
  到新构建，再跑四场景受控复核。
- 跨批次快照缓存仍未做（同前几轮说明：需要明确生命周期所有者、失效条件与内存上限）。
