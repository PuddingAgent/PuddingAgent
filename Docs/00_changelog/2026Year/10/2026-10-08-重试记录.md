# 2026-10-08 交付链：重试的可读性缺口

## 缺口（上一轮修好重试之后的下一步巡检）

重跑成功时，原 TRX 被改名为 `<suite>-retried.trx`，检查名于是带 `-retried` —— **只能说"发生过重试"**。
清单读者仍无法区分：这是"1 条 flake 重跑过了"，还是"40 条失败被重跑掩盖了"。对交付判定来说这是关键差别。

## 改动

| 层 | 改动 |
|---|---|
| 脚本 | 重跑成功时，把**首次失败数**写入 `<结果目录>/retry-notes.txt`（`<suite> : first attempt had N failing test(s); the result below is from the retry`） |
| 采集器 | 读该 sidecar（存在才读）→ `DeliveryBuildFacts.RetryNotes` |
| 清单 | 新增 `retryNotes`（可反序列化） |
| 报告 | 新增小节「**重试记录（这些结果不是第一次就通过的）**」 |

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **323 / 323**（＋1：采集器把 retry-notes 变成清单事实） |
| 全量链（未触发重试） | 320/320 语料全扫、未验证项 20/39、7 套件全绿、`retryNotes` 为空 ✓（无重试就不该有记录） |
| **重试会真的重跑** | 用仓库内确实失败的套件：`PuddingWebApiTests` ⇒ `retry 1/1 for PuddingWebApiTests` |
| **重试不掩盖真失败** | 同一次运行重跑**仍失败** ⇒ `manifest NOT emitted (exit=2)`、无 `-retried` 改名、无 notes ✓（fail-closed） |
| 留痕清单 | [交付清单 retry-audit-126](../../../14_reports/2026-10-09-浏览器自动化交付清单-retryaudit126.md) |

## 诚实边界（诚实登记）

- **notes 的端到端还没被观测到**：需要"重跑成功"这一事件，而本轮两次运行分别是"无重试"与"重试仍失败"
  ⇒ 该路径目前只有**单测**证据（脚本侧写入的一段没有真实执行过）。上一轮观测到的是**改名**路径（当时还没有 notes 功能）。
- **首次失败数来自 TRX 计数器**：只给条数，不含失败的用例名（要看名字得查 TRX/日志）—— 登记为可改进项。
- **`retry-notes.txt` 是约定文件名**：采集器按它取；若换名字，两边都要改（未加门禁，登记）。
- **重试的代价照旧**（削弱"第一次必须全绿"，默认关闭）；是否接受由验收方决定。
- **未真机验证**；两项待决取舍未触碰。
