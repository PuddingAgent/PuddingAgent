# 2026-10-18 旧会话投影查询收敛与事件索引维护

## 开发库索引维护（显式，非启动自动）

- 维护前在线备份：`temp/test-out/pudding_platform-before-event-indexes-20261018-100940.db`（9.9GB，99.7s；维护期间无 Pudding 进程运行）。
- 在 `D:\data\databases\pudding_platform.db` 显式执行：
  - `IX_conversation_events_conversation_id_message_id_sequence`：**51.9s**；
  - `IX_conversation_events_conversation_id_turn_id_sequence`：**6.2s**；
  - 库文件 9.9GB → 10.3GB；事件行数 3,120,332；journal_mode=wal。
- EXPLAIN 验证：
  - 每消息查询：`SEARCH conversation_events USING INDEX ..._message_id_sequence (conversation_id=? AND message_id=?)`；
  - 每 Turn 查询：`SEARCH conversation_events USING INDEX ..._turn_id_sequence (conversation_id=? AND turn_id=?)`；
  - 实测每消息 500 行 1ms、每 Turn 635 行 <1ms。

## 旧 `/conversation` 投影查询收敛（行为不变）

`AgentConversationProjectionService.GetConversationAsync`：

- 身份解析改为注入 `AgentMainSessionResolver`（redirect → Manifest MainSessionId → `FindMainAsync`），不再每次 `GetSessionsAsync` 拉全工作区会话列表；无解析器的旧测试路径保留。
- 每消息过程事件由单个 `message_id IN (...)` 会话扫描改为**按 messageId 逐条**查询（`(conversation_id,message_id,sequence)` 索引），合并后按 sequence 排序。
- 可见 Turn 终态事件改为**按 turnId 逐条**查询（`(conversation_id,turn_id,sequence)` 索引），合并后排序；`TurnOutcome` 语义不变。
- 根 Turn 发现改为：最近 `ChatExecutionCommands` 取当前 Turn → 走 `(conversation_id,turn_id,sequence)` 查 `turn.started`；无命令时保留原回退查询。根终态判断也改为 Turn 收敛（不再按 run_id 扫会话）。
- `GetEventCursorAsync` 优先读 `conversation_heads.HeadSequence`，缺失才回退 MAX。
- **响应契约/字段语义未改**：仍是旧 `AgentConversationView`；前端版本不变（仅后端改动）。
