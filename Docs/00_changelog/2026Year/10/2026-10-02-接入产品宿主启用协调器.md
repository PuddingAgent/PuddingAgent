# 2026-10-02 接入产品宿主：启用源维护协调器

## 改动

- `Source/PuddingHost/Extensions/PuddingServiceCollectionExtensions.Platform.cs`（S5 接入）：
  在 `AddPuddingCodeIntelligence()` **之前**登记
  `new CodeIndexMaintenanceOptions(CodeSourceMaintenanceMode.Coordinator)`（组件用 `TryAdd`，先注册者胜）。
  产品宿主的代码索引变更施用链路由此切到新的源维护协调器。
- `Source/PuddingCodeIndex/Services/CodeIndex/CodeIndexMaintenanceService.cs`：新增只读属性
  `SourceMaintenanceMode`（诊断/验收用；请求 `Coordinator` 但零件未装配齐时它会是 `Legacy`）。
- `Tests/PuddingHost.Tests/Hosting/CodeIndexMaintenanceHostCompositionTests.cs`：在既有组合用例里断言
  宿主确实要求了 `Coordinator`，**且组件确实收到了它**（同时覆盖「零件齐备」这条前提）。

## 启用后行为（将在下一次宿主重启时生效）

- 变更施用：完整清单校准 → 真实变更集 → 更新计划 → 语言批量接缝（一批一次工程快照）
  → 稳定读指纹 → `ReplaceFilesAsync` 原子提交 → 账本提交。
- 提示驱动的轮次**只做按路径观测**（不遍历整棵树）；周期性校准（15 分钟）走**完整**扫描。
- 单路径失败/内容核验失败 ⇒ 记退避 + 记持久待办 + **水位不前进**，**不再升级成整仓重建**。
- 删除只能由「完整 + 根可用」的扫描确认；watcher 观察到的消失只作提示。
- 完整扫描轮次会清理索引孤儿行（索引有、manifest 无、本轮也枚举不到）。
- scope 级全量重索引（reconcile 升级路径）仍由旧链路承担，它不更新新 manifest ⇒ 会让指纹暂时陈旧
  并被下一轮协调器重新提取而自愈（多一次提取，不是损坏）。

## 尚未完成 —— 必须由进程外控制器做的部分

按仓库规程（两段式验收），本 Agent **不能**证明新代码已被当前进程加载，也不能独立验收进程生命周期：

1. **重启**：由进程外控制器把 Core 重启到**明确的新构建**（本笔所在提交）。
2. **四场景受控复核**（对照诊断报告的口径）：
   - 无任何文件改动时：周期性扫描的读盘量（应当只有元数据枚举，**无正文读取**）；
   - 单个文件改动时：读盘量（应当只读该文件、**零次全树枚举**、无提取器进程）；
   - 删除只由完整扫描确认（watcher 单独提示不得删除）；
   - 根不可用（卸载/改名）时不得删除任何记录，且保持标位。
3. **回退**：删掉 `PuddingServiceCollectionExtensions.Platform.cs` 里那一行
   `AddSingleton(new CodeIndexMaintenanceOptions(Coordinator))` 即回到旧的逐文件路径
   （组件默认 `Legacy`），随后再次重启。
