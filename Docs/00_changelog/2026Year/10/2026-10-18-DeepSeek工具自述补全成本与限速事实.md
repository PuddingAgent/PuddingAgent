# 2026-10-18 DeepSeek 工具自述补全成本与限速事实

## 目标 / 背景

提交 `396c280`（[`2026-10-17-DeepSeek工具自述补充实测观察与上游转义归因.md`](2026-10-17-DeepSeek工具自述补充实测观察与上游转义归因.md)）按 8 次真实调用实测，把「上游正文转义」「软 404 仍成功」「Rerank <1.0 视同未检索到」三条约束写进了 `deepseek_search` / `deepseek_fetch` 的工具自述。

本次做两件事：

1. **复核**：该提交在自述里写了两个"文档口径"数字（`Rerank ≥1.5` 高相关、`Authority ≥3` 极权威）。这类断言若写错，会被每个 Agent 当作事实读走，因此必须回到官方文档原文逐条核对。
2. **补缺**：官方文档里还有一类事实**直接改变调用策略**，但完全没有进自述——计费口径、QPS 限制、重试语义。缺了它们的后果很具体：Agent 会把一次搜索拆成多次调用（多花钱）、会并发批量抓同站（吃 429）、会在 401/402 上重试（无意义且可能重复计费）。

## 改动

| 文件 | 改动 |
|------|------|
| [`DeepSeekSearchTool.cs`](../../../../Source/PuddingRuntime/Tools/BuiltIns/Search/DeepSeekSearchTool.cs) | 自述新增【成本与限速】：Search 按请求次数计费（每 1000 次成功请求 5 元；只有 HTTP 200 且 `results` 非空才计费），`count` 只影响条数、不影响单价 ⇒ 需要多条时一次取够；账号级 QPS 5（与 Fetch 各自独立），并发猛刷会 429；408/429/5xx 等待后重试，其余 4xx 不重试。英文各一句 |
| [`DeepSeekFetchTool.cs`](../../../../Source/PuddingRuntime/Tools/BuiltIns/Search/DeepSeekFetchTool.cs) | 自述新增【成本与限速】：Fetch 按请求次数计费（只有真正取到正文才计费），账号级 QPS 5 **且对同一目标域名另有 QPS 上限** ⇒ 批量抓同站极易 429，应串行 + 退避；408/429/5xx 可重试，其余 4xx 不重试。英文各一句 |

未改：执行逻辑、参数、输出渲染、权限分类（仍 `Low` / `AutoAllowed`）、配置解析、组件代码、测试。

## 验证

**① 官方文档原文核对**（`deepseek_fetch https://api-docs.deepseek.com/zh-cn/guides/search/`，2026-10-18）

| 断言 | 文档原文 | 结论 |
|------|----------|------|
| `Rerank ≥1.5` 高相关 | `rerank_score \| number \| 排序分数，0～3 分……大于等于 1.5 分为优质结果。` | **成立** |
| `Authority ≥3` 极权威 | `authority \| integer \| 网页权威性，0～4（-1 表示未知），大于等于 3 为极权威结果。` | **成立** |
| 按次计费 | `Search 和 Fetch 按请求次数计费，不按 token 或返回结果条数计费……每 1,000 次成功请求 5元` | **成立**（补入自述） |
| 计费条件 | `只有返回 HTTP 200 且产生结果的请求才会计费（Search 的 results 必须非空，Fetch 必须返回网页正文）` | **成立**（补入自述） |
| `count` 不影响价格 | `count 只控制返回的结果条数，不影响单次请求的价格。` | **成立**（补入自述） |
| QPS 5 | `对每个账号，Search 和 Fetch 分别独立限速……Search 5 / Fetch 5`；`Fetch 还针对目标域名有 QPS 限制` | **成立**（补入自述） |
| 重试语义 | `遇到 HTTP 408、429 或 5xx 错误时，请等待后重试……对于其它 4xx 错误，如不修改请求，请勿重试。` | **成立**（补入自述） |

文档中另有一条**有范围限定**的事实，本次**未**写入自述：`DeepSeek Harness/Claude Code/Codex 中使用 DeepSeek API 时……这部分 Search/Fetch 接口调用目前未计费，并将于北京时间 2026 年 11 月 1 日 00:00 起按次收取调用费用`。该条只适用于那些宿主环境；PuddingAgent 以自有 Key 直连 API，按上表计费口径执行，故自述只写通用口径、不写这条时限例外。

- 既有 4 条自述断言（`Rerank 分 ≥1.5`、`未检索到`、`按原文返回`、`Page Not Found`）全部仍通过 ⇒ 本次为纯追加，未破坏上一提交建立的防回退断言。

**④ 改动面**

**⑤ 工具教训（本轮实测）**

- `findstr /c:"Passed!"` 在本地化（中文）dotnet test 输出上**匹配不到**，会让"全部通过"看起来像失败。判断测试结果应读汇总行的**数字**（失败/通过/跳过/总计），不要 grep 英文单词。
