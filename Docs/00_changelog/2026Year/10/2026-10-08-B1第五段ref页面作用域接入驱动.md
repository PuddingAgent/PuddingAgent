# 2026-10-08 B1 第五段：ref 页面作用域接入驱动，跨页同版本号命中被拒

## 目标 / 背景

第四段交付了引用身份契约（`BrowserRefRegistry` 与三个事实），但驱动仍只按
`v{pageVersion}-n{seq}` 比较版本号 —— 缺口在运行时仍然存在。本段把它接入驱动，
**关掉其中最危险的一条**。

缺陷为什么是真缺陷（不只是理论）：ref 序号由每页**独立**生成（`__puddingRefState.next`
从 0 开始按页累加），因此「页面 A 的 `v7-n3`」与「页面 B 的 `v7-n3`」会同时存在。
跨页复用同版本号的引用时，`LocateScript` 的 `case 'ref'` 会按 `data-pudding-ref` 字符串相等
去匹配 ⇒ **在另一个页面上静默命中第 3 个元素**（点错目标 / 填错表单），而不是报错。

## 改动

- `Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs` — 新增
  `_refScopeToken = Guid.NewGuid().ToString("N")`（**驱动侧**生成，页面脚本写不出来），
  在 snapshot/locate/interact 三处传给 DOM 客户端。
- `Source/PuddingBrowser.WebView2/WebView2DomClient.cs`：
  - `ValidateLocator(locator, pageVersion, pageToken)`：解析
    `p([0-9a-f]{32})-v(\d+)-n\d+`，**token 与文档世代任一不符**即 `stale_element_reference`；
    消息只说「重新观察页面并重新定位」，**不**回指节点、**不**输出 token（两者都有断言钉住）；
  - 三段脚本（snapshot 的 `ensureRef`、locate 的前缀、interact 的前缀）统一改为
    `p${input.pageToken}-v${input.pageVersion}-n`；`refState` 也按 `(pageToken, pageVersion)` 归零，
    避免导航后沿用旧序号。
- `Tests/PuddingDesktop.Tests/Browser/WebView2DomClientTests.cs` — 新增 3 条：跨页同版本号必须拒绝
  （并断言提示含 `re-observe`/`never re-bound`）、**旧的无作用域格式必须拒绝**（不做静默兼容层）、
  拒绝消息**不泄露** token；既有两条改为新格式。

## 验证

| 项 | 结果 |
|---|---|
| `dotnet test Tests\PuddingDesktop.Tests` | **300 / 300 通过**（原 297 ＋ 3） |
| `PuddingHost.Tests` · `DesktopServiceTests` · `DesktopSurface.BrowserTests` · `AgentTools.Tests` | 251 / 251 · 197 / 197 · 56 / 56 · 17 / 17 |
| `dotnet build` `PuddingBrowser.WebView2` · `PuddingDesktop` · `PuddingDesktop.WpfArchive` · `WebView2.Smoke` | 0 错误 |

**取红实测**：临时把 `ValidateLocator` 的 token 比较去掉（只留版本比较）⇒
`WebView2DomClientTests` 中**恰好 2 条**变红（跨页拒绝条、token 不泄露条），其余 8 条仍绿；
复原后 300/300 复绿。说明这两条钉的正是被修的因果链。

## 调用方一致性

- `WebView2DomClient.ValidateLocator/SnapshotAsync/LocateAsync/InteractAsync` 的调用方**只有**
  `WebView2BrowserPage` 三处，已全部同步；
- 工具层与两条传输把 ref 当**不透明字符串**传递（`BrowserLocateTool` 只判 `kind == ref`），
  因此它们的假实现里那份旧格式（`v1-n1` 之类）不受影响，也无需改；
- `Source/Pudding.DesktopService/DesktopDomScripts.cs` 也有一套 ref 逻辑，但它**没有任何生产调用方**
  （只被自己的测试引用），本段未改动它。

## 仍未闭合（诚实登记，已同步进 `PuddingBrowser.Automation/code_map.md` §6）

- **宿主绑定的节点身份**：节点标记仍是页面可自写的 `data-pudding-ref`。真正的宿主身份需要
  CDP `backendNodeId`，而 CDP 在本驱动里仍是 `NotSupportedException("CDP not in Phase 2A-1")`（属 B3）。
- **宿主存活校验**（节点是否仍 connected / 仍在同一文档）与**三个事实的分别维护**尚未接入驱动；
  `BrowserRefRegistry` 仍未被驱动消费（驱动用同语义的 token 校验实现了作用域与文档世代两条）。
- **frame 粒度**：本驱动的 `Locator.Frame` 明确不支持（`browser_operation_not_supported`），
  所以 token 目前只区到页面；真正支持 frame 时 token 需扩展为 `(page, frame)`。

## 影响与回滚

- **线格式变更**：ref 值由 `v{版本}-n{序号}` 变为 `p{token}-v{版本}-n{序号}`。
  模型侧 ref 是不透明值，无兼容负担；按设计「不添加旧 ref 的静默兼容层」，旧格式现在会被
  明确拒绝（`browser_invalid_arguments`），不会静默当成有效引用。
- 无数据/配置影响。回滚：还原两个驱动文件与测试文件即可。
