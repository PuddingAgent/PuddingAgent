# 2026-10-08 横向：外部手册补"清单字段如何影响结论"

## 为什么

这几轮给交付清单加了若干**会影响外部结论**的字段（`retryNotes`、`knownUnverifiedTotal`、`changelogFilesScanned/Total`、
检查名 `-retried`）。外部观察者若不知道它们，就会遇到"**结论被拒但不知道为何**"——
例如清单里有重试记录时，结论**默认被拒**，而手册没说这件事。

## 改动

外部手册新增 **5.1「清单里这几项会直接影响你的结论（先读再下结论）」**：

| 字段 | 含义 | 该怎么做 |
|---|---|---|
| `retryNotes`（非空） | 有套件是**重跑后才绿**（写明第一次失败几条、哪几条） | 结论**默认被拒**；接受就显式 `-AcceptRetries`，不接受就要求重新交付"一次通过"的构建 |
| `knownUnverified` + `knownUnverifiedTotal` | 未验证项**显示条数 / 实际条数**（显示有上限 20） | 按 `total` 理解规模；清单里那份**不是全集** |
| `changelogFilesScanned` / `Total` | 提取未验证项时扫了多少日志 | 两者不等 ⇒ 语料被截断（此时清单**拒绝产出**，不会给"看起来完整"的） |
| 检查名 `-retried` | 该套件绿色来自重试 | 与"一次通过"不是同一声明 |

并给出显式接受重试的命令示例。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **326 / 326** |
| 门禁扩展 | 手册必须提到 `retryNotes` / `knownUnverifiedTotal` / `changelogFilesScanned` / `-AcceptRetries` / `-retried` 五个字段 |
| **取红实测** | 删掉 `retryNotes` 那一行 ⇒ 门禁**变红**；还原 ⇒ 326/326 |

## 诚实边界（诚实登记）

- **手册是给外部观察者的操作说明**，不替代判定组件：真正的拒绝仍由 `ExternalAcceptanceSession` 作出。
- **门禁只查"字段是否被提到"**，不校验解释是否准确（那靠评审）。
- **两次修正的教训仍未自动化**：本轮没有再踩"替换静默失效"（改动集中在单文件），但那条结论（跨文件接线必须用行为测试兜住）依然是我要遵守的纪律，**未加自动门禁**。
- 无产品行为变化（文档 + 用例）。
