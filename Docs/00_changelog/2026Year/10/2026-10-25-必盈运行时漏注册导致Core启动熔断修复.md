# 2026-10-25 必盈运行时漏注册导致 Core 启动熔断修复

## 背景与改动

Desktop 的诊断接口显示 Core 在 `ValidateOnBuild` 阶段因四个必盈工具无法解析
`BiyingFinanceRuntime` 而退出，退出码 `-532462766`，最终进入 `CircuitOpen`。
原注册只在 `PuddingRuntime/DependencyInjection.cs`，产品 Host 不调用该入口。

- `Source/PuddingHost/Extensions/PuddingServiceCollectionExtensions.Runtime.cs`：扫描工具前显式注册
  `BiyingFinanceRuntime` 单例，使四工具共享配额与缓存。
- `Tests/PuddingHost.Tests/Tools/BiyingFinanceToolsCompositionTests.cs`：新增真实 DesktopChild
  组合根测试，验证四工具被发现、注册表解析、跨 scope 及真实消费者共享单例；缺少金融配置时，
  仅工具调用返回配置错误，不妨碍 Host 构建。无真实供应商请求。
- `Source/PuddingHost/code_map.md`：更新注册约束、测试入口并修正测试目录相对路径；原有 Storage
  定向测试 4/4 的历史陈述从索引移出，本次没有重跑 Storage 测试。
- `Docs/08_how_debuge/12-案例-平台与会话.md`：补充必盈构造依赖与缺配置的诊断边界。

## 验证

- 修复前新用例失败 1/1，错误与现场一致：四工具无法解析 `BiyingFinanceRuntime`。
- 修复后 `BiyingFinanceToolsCompositionTests`、`PuddingApplicationHostCompositionTests`、
  `DeepSeekWebToolsCompositionTests` 共 **4/4 通过**。
  使用 `dotnet test Tests/PuddingHost.Tests/PuddingHost.Tests.csproj --artifacts-path temp/build/recovery
  --no-restore` 并按上述类名过滤。
- Core 在同一隔离 artifacts 目录 restore 后以 `win-x64 / Debug / --self-contained false`
  执行 `dotnet publish --no-restore` 成功；打包当前已部署的 Admin 静态资源。
- 本次修改文档的 Front Matter 检查通过；全量门禁发现原有 **8 个缺少 Front Matter** 的文档、
  **26 个失效链接目标**，无失效锚点，均不在本次改动文档中，未扩大修复范围。

## 部署与未完成部分

用户退出了原 Desktop 进程，控制接口随之关闭。重新启动 Desktop 的命令被自动审批拒绝
（仅返回 `blocked by policy`），因此未继续启动操作。

确认 Desktop/Core 均已退出后，调用现有 `PuddingBuildOutputSync.DeployDirectoryTransactional`
将新 Core 离线部署到原 Desktop 的 `core/` 目录：复制 **341** 个文件，跳过相同文件 **1270** 个；
**258** 个托管启动制品的清单 SHA-256 完全一致。目标目录是
`temp/build/winui3/bin/PuddingDesktop/Debug/net10.0-windows10.0.19041.0/win-x64/core/`。

已部署 `PuddingHost.dll` 的 SHA-256：
`19582DEFBE4A4C9E265E4F0FF3BDA365D0A1543060E5BC9EC870B53EBD3EFFA5`。

**未验证**：新 Core 的真实进程 Ready、`/health/ready`、工作台与超过 60 秒稳定运行；
需用户重新打开 Desktop 后核对。未修改 DataRoot 配置、凭据或数据库，未触发真实金融查询。
回滚须停止 Desktop/Core，撤销本次注册改动并重新构建部署；回滚会恢复已知启动错误。

本次生成的发布暂存、TRX 与 coverage 清理命令也被自动审批拒绝（`blocked by policy`），
这些忽略的产物仍留在 `temp/build/biying-startup/`、`temp/test-out/biying-startup/`、
`Tests/PuddingHost.Tests/TestResults/`；不纳入提交。共享 `temp/build/recovery/` 和已部署的
Desktop/Core 目录保留。
