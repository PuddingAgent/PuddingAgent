# SPA 深链 URL 纠正

## 1. 结论（先给答案）

| 项 | 事实 |
|---|---|
**错误 URL**（我此前反复报告"已上线，可直接打开"） | `http://127.0.0.1/index-status` —— **从来就打不开** |
**正确 URL** | **`http://127.0.0.1/admin/index-status`**（且在 `/admin/` 基座下，需要**登录会话**） |
根因 | 管理端 SPA 的 umi `base` 是 **`/admin/`**；基座之外的路径虽然也会被 Core 的 SPA 回退返回 `index.html`（HTTP 200），但路由器匹配不到任何路由 ⇒ **永久停在加载壳** |

## 2. 证据（真实浏览器 + 源码，双证）

**源码**
- `Source/PuddingPlatformAdmin/config/config.ts:94` → `base: '/admin/'`
- `Source/PuddingPlatformAdmin/config/routes.ts:132-135` → `path: '/index-status'` + `component: './index-status'`（在基座下注册）

**浏览器实测（同一 context，四个对照页）**

| 页面 | 结果 |
|---|---|
`http://127.0.0.1/index-status` | **卡在加载壳**（"正在加载资源"），`.ant-layout` 30 s 未出现 |
`http://127.0.0.1/nonexistent-xyz-route` | **同样卡在加载壳**（基座外的对照 ⇒ 与我的页面无关） |
`http://127.0.0.1/admin/` | **正常挂载**，渲染登录页；页脚 `v6.2.0+dirty · 35f065d · 2026-10-03 00:30` |
`http://127.0.0.1/admin/index-status` | **能挂载**，未登录 ⇒ 跳 `/admin/user/login` |

⚠️ **一处必须诚实标注**：`/admin/no-such-route-xyz` **也**跳到登录页 ⇒ 「跳登录」只能证明**基座是 `/admin`**，**不能**证明面板路由存在。
「路由确实注册」的证据是**源码**（`routes.ts:132`）+ 既有前端测试，不是这次浏览器观测。
⇒ 面板的**已登录渲染**验收（真实数据、四态、32 列 L2）本轮**没有做**，因为没有会话凭据，**不做假设**。

## 3. 连带登记的缺陷

**D11（UX，低危但真实）**：SPA 回退对**基座之外**的任何路径都返回 `index.html`（HTTP 200），路由器匹配不到 ⇒ 用户看到的是**永久"正在加载资源"**，既不是 404 也不是跳转。任何手输/收藏错误 URL 都会踩到，且**看起来像系统坏了**。
修复方向（未实施）：Core 侧对非 `/admin`、非 `/api`、非静态资产的未知路径做 301/302 → `/admin/`，或返回明确的 404 页；或在回退时注入基座提示。

## 4. 仪器纪律（本轮的真正教训）

**「HTTP 200」对 SPA 深链是无信息量的**：Core 的 SPA 回退对任意路径都返回 shell HTML ⇒ 只要没用**浏览器挂载**（或路由级断言）验证过，`200` 就会给出**假绿**。
⇒ 从 Slice B 起，我（以及子代理报告）把 `/index-status 200` 当成"前端已上线"的证据，**这个证据一直是假阳性**；P4 的"部署成功"结论本身没错（随包**字节级**比对 + `/admin/` 真实渲染可证），但**面向用户的入口 URL 说错了**。
**新增纪律**：SPA 的"可用"判据 = ① 在**正确基座**下访问；② 页面**挂载成功**（出现预期 DOM，如 `.ant-layout`/表单）；③ 需要鉴权的路由须注明**需登录**。三者缺一，不得宣告"已上线"。

## 5. 尚未验证（留白）

1. 面板在**已登录**状态下的真实渲染与数据（依赖 Core 部署 + 用户会话）；
2. `codeIndex` 块仍为 `absent`（后端未部署）⇒ 页面应显示「未接入」中性灰，本轮**未**在已登录态确认；
3. 未在浏览器里跑 `prefers-reduced-motion` 降级验证。
