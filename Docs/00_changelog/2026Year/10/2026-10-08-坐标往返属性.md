# 2026-10-08 B4 测试补强：坐标变换的往返属性

## 为什么

坐标变换属于"**算错也不会报错**"的代码：漏除设备缩放、漏减滚动量、低清比取反，后果都只是**点偏**。
上一轮我只写了手挑的几组用例 —— 那只能覆盖"我想到的情况"。本轮补**属性式**用例把边界压窄。

## 新增 4 条

| 用例 | 断言 |
|---|---|
| `ImageAndCssCoordinatesRoundTripAcrossAGridOfGeometries` | 6 组几何（含 DPR 1/1.25/1.5/2、裁剪原点、滚动量）逐个 CSS 点**往返**回到原点（容差 0.001），并断言至少校验到 12 个点（防网格写坏而假绿） |
| `TheRoundTripPropertyHasTeethAgainstAWrongForwardTransform` | 用**故意漏乘设备缩放**的正向变换喂进去，往返**必须失败** ⇒ 证明属性用例不是空转 |
| `OneImagePixelAlwaysMovesTheSameAmountInCssPixels` | 图片 X 每 +1 ⇒ CSS X 正好 +`1/(低清比×设备缩放)`（钉住线性与步长） |
| `PointsJustOutsideTheCropAreRefusedRatherThanClampedIntoRange` | 边界外 1px 也必须拒绝（夹到边界会让"图外"变成"边缘上"，操作落到错误元素） |

## 取红实测（两次变异，都在生产代码上做）

| 变异 | 结果 |
|---|---|
| 删掉 `deviceX / scale` 的除法（漏设备缩放） | **4 条变红**：`DeviceScaleFactorIsDividedOutNotIgnored`、**网格往返**、**变异对照**、**步长线性**；还原即绿 |
| 删掉 `- observation.ScrollX.Value`（漏减滚动） | **网格往返变红**（含 scroll≠0 的几何）；还原即绿 |

⇒ 属性用例对两类真实缺陷都有牙齿，且"变异对照"那条保证它不会退化成空转。

## 诚实边界（诚实登记）

- **网格不是穷举**：6 组几何 × 4 个点 = 24 个组合里的有效点（≥12），仍是**抽样**，不是形式化证明。
- **容差 0.001 是数值断言**：它证明"与测试自己实现的正向变换互逆"，而**正向变换也是我写的**
  ⇒ 若两者共享同一个误解（例如把 CSS 视口原点理解错），往返仍会通过。真正的外部校验只能来自真机观察。
- **未覆盖滚动拼接/全页**（设计明确要单独处理，未实现）。
- **未真机验证**；决定②仍待确认。
