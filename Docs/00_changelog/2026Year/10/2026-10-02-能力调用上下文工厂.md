# 2026-10-02 能力调用上下文工厂（工具迁移的最后一个前置件）

## 目标 / 背景

上一轮识别出：窄端口每个方法都要求 `DesktopCallContext`（Desktop 实例 ID + 操作 ID + 期限），
而**工具侧只有业务参数**。这三个字段都不能由调用方猜，因此工具迁移前必须先补一个工厂。

## 改动

- 新增 `Source/Pudding.Contracts/Desktop/DesktopCapabilityCallContextFactory.cs` —
  `IDesktopCapabilityCallContextFactory`：`DesktopCallContext? TryCreate(TimeSpan? timeout = null)`。
  放在 Contracts 是因为它只依赖契约 DTO，且工具层要能依赖它而不拖入 gRPC/宿主。
  文档里明确：**这里不产生调用方身份**——身份由 Core 的可信运行上下文提供，授权器据此判定（计划 §7）。
- 新增 `Source/PuddingHost/Hosting/ConnectedDesktopCallContextFactory.cs` —
  基于**活动会话**产生上下文：
  · Desktop 实例 ID 取自**会话自己的 ID**（`DesktopSession` 会校验调用里的 DesktopId 与自身一致，
    所以用会话而不是配置里的"期望值"——不一致应当由会话拒绝，而不是我们猜）；
  · 操作 ID 每次 `OperationId.NewId()`（broker 对"同 ID 不同 payload"判重复请求）；
  · 期限 = 现在 + 本次预算或默认值（默认 120s，够一次浏览器往返又不至于悬挂）。
  用**委托**而不是直接依赖 `CapabilityBroker`：本类因此能脱离宿主单测，组合根只提供一眼看得懂的
  「当前活动 Desktop」解析。
- 新增 `Tests/PuddingHost.Tests/Hosting/ConnectedDesktopCallContextFactoryTests.cs`（5 项）。

## 刻意保留的语义

| 情形 | 行为 |
|---|---|
| 没有活动 Desktop | 返回 `null`——**不猜实例 ID**去发一条注定被会话拒绝的命令（fail closed） |
| 每次调用 | **新的操作 ID**（断言两次调用 ID 不同） |
| 期限 | 显式预算优先，否则默认值；由 `TimeProvider` 注入因此可在测试里钉住精确时点 |
