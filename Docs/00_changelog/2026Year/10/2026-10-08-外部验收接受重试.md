# 2026-10-08 外部验收：重试结果必须显式接受

## 缺口

`retryNotes`（"哪些套件重跑后才绿"）此前只对**内部**可见：外部一方既看不到，也没有表达"接受/不接受"的入口。
而设计把「**是否接受重试由验收方决定**」定为验收方的取舍 ⇒ "看不到"就等于"悄悄带过去"。

## 改动

| 层 | 改动 |
|---|---|
| 判定 | `ExternalAcceptanceInput` 新增 `AcceptRetries`；`TryConclude` 新增拒绝 ⑤：清单有 `retryNotes` 而未被接受 ⇒ 拒绝并给出原话（"accepting retried results is the acceptor's decision"） |
| CLI | `--accept-retries`；**解析器登记为无取值开关**（原先每个 `--flag` 都必须带取值 ⇒ 裸开关被判"缺少取值"，整条结论退化成用法错误 exit 1）；并在下结论前把清单里的重试记录打印出来 |
| 外部脚本 | `-AcceptRetries` 开关；下结论前**先打印**清单里的重试记录，并提示"尚未接受" |
| **反序列化（顺带修的真缺陷）** | `TryDeserialize` 没有把 `changelogFilesScanned` / `changelogFilesTotal` / `retryNotes` 传给构造器 ⇒ **字段写得进、读不回**。这正是重试规则在 CLI 路线上失效的原因 |

## 验证（端到端排练 + 单测）

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **326 / 326**（＋2：接受规则、JSON 往返保留三个字段） |
| **排练：未确认** | 打印重试记录 + `- the delivered manifest reports 1 retried suite(s); …` ⇒ `exit 2` |
| **排练：已确认（`-AcceptRetries`）** | 仍打印重试记录，但**不再有重试原因**；此时因观察项未执行而拒绝（`exit 2`）✓ |
| 修复前后对比 | 同一排练在修反序列化**之前**：重试原因根本不出现（字段被静默丢弃） |

## 诚实边界（诚实登记）

- **`AcceptRetries` 是"知情接受"，不是"证明没问题"**：它只是让验收方明确表示"我知道这份交付里有重跑结果"。
- **`--accept-retries` 必须显式传**：默认拒绝 —— 若验收方希望"重试结果一律不接受"，什么都不用做。
- **同一天第二次被"替换没生效"咬到**：`facts.RetryNotes` 我先写错了文件（builder vs 反序列化），
  静态替换**静默无效**；两次都是靠**行为证据**（单测失败 / CLI 排练缺原因）才发现。
  ⇒ 结论：这类跨文件接线**必须用行为测试兜住**，不能靠"改完看一眼"。
- **未真机验证**：排练用的是构造清单（`temp/`），不是真机观察。
- 两项待决取舍未触碰。
