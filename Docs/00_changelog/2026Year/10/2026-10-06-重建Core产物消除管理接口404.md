# 2026-10-06 · 重建 Core 产物消除 /api/admin 管理接口 404

## 背景 / 动机

用户截图（Desktop 工作台右下角）显示连续三条失败提示：

| 截图提示 | 观察值 |
|---|---|
| `GET /api/admin/diagnostics/log-level — 404` | 该路由在磁盘源码中存在、但不在运行进程内 |
| `GET /api/admin/index/status — 404` | 同上，重复请求造成重复提示 |
| `GET /api/currentUser — 401` | 当前用户未持有有效登录态 |
| `GET /api/bootstrap/status — 403` | 已初始化后的**预期**行为（非故障） |

上一轮（同会话）只做了只读诊断；本轮执行修复。

## 根因（实测证据，非推断）

**不是缺接口、也不是权限问题，而是运行中的 Core 是旧产物。**

| 项 | 实测值 |
|---|---|
| Desktop | PID `43100`，`temp\build\winui3\bin\PuddingDesktop\Debug\...\win-x64\PuddingDesktop.exe`（2026-10-06 22:51:39 构建，22:53:26 启动） |
| Core | PID `39804` ← **子进程**，`Source\PuddingAgent\bin\Debug\net10.0\PuddingAgent.exe`（22:53:31 启动） |
| `desktop.json` | `coreExecutablePath` = 上述 Debug 路径（`D:\Data` 为 DataRoot） |

旧产物中**不存在**这两个控制器类型（对二进制做 UTF-8 类型名检索）：

| 文件 | mtime | `IndexAdminController` | `DiagnosticsLogLevelController` |
|---|---|---|---|
| `bin\Debug\net10.0\PuddingHost.dll`（**当时在运行**） | 2026-10-01 11:14:26 · sha256 `708B3EEF…` | **False** | **False** |
| `bin\Release\net10.0\PuddingHost.dll`（旁证） | 2026-10-01 12:17:59 | True | False |
| 本次重建后的 `PuddingHost.dll` | 2026-10-06 22:59:05 · sha256 `5221027F…` | **True** | **True** |

⇒ 与 [Core 部署决策包](../../../13_runbooks/Core部署决策包与验收清单-2026-10-03.md) 描述的是同一类问题：**磁盘源码已实现、运行进程没有**。

### 对上一轮建议的更正

上一轮建议“校正 Desktop 的 Core 启动路径，别再指向源码目录的旧 `bin/Debug`”。本轮核对后确认**该建议不成立**：
`Source\PuddingAgent\bin\Debug\net10.0` **就是**本机约定的部署目标——`TestScripts\invoke-pudding-desktop-deployment.ps1:38` 显式断言
“目标目录必须是 `Source\PuddingAgent\bin\Debug\net10.0`，否则拒绝部署”。
所以正确动作是**重建该目录的产物**，而不是把路径改到别处。`desktop.json` 本次**未修改**。

## 所做操作（外部控制器）

1. **备份**当前二进制：`D:\Keys\PuddingDeploymentBackups\20261006-core-bin-before-rebuild`（194 个顶层文件 / 94.2 MB；`PuddingHost.dll` 备份 sha256 = `708B3EEF…`）。
2. **经 Desktop 控制面停止 Core**（`POST http://127.0.0.1:8199/desktop/bootstrap/core/stop`，`X-Control-Token` 取自 `<DataRoot>\config\system.json`）：`success=true`，PID 39804 在 **2 秒**内退出。
3. **重建**：`dotnet build Source\PuddingAgent\PuddingAgent.csproj -c Debug` → **exit 0**，耗时 **5.75 秒**（0 错误 / 18 警告，均为既有的 NuGet 漏洞提示与警告）。
4. **经 Desktop 控制面重启**（`POST …/core/start`）：`success=true`，新 Core PID **26320**（父进程仍是 Desktop 43100），`coreReadyAt=15:08:43Z`，`coreState=Ready`、`desktopState=WorkbenchReady`、`lastError=null`、`restartAttemptsInWindow=0`。

**服务不可用窗口：29 秒**（含构建）。前端静态产物本次未重建也未变化（`wwwroot/admin/index.html` 与 `PuddingPlatformAdmin/dist/index.html` 同为 sha `EE6D2521…`、前端 6.2.3）。

输出目录未出现“新旧混装”：目标目录内**每个 `Pudding*` 程序集都与它自己的项目输出逐字节相同**（133 个 DLL 比对通过；首轮脚本报出的 11 个“不一致”经复核全部是**测试项目 bin 里的陈旧副本**，非本程序集来源）。

## 验收（对运行中的新 Core 实跑，`http://127.0.0.1/`）

| # | 端点 | 匿名 | 管理员 JWT | 判读 |
|---|---|---|---|---|
| 1 | `/health/live` | **200** | — | 存活 |
| 2 | `/api/admin/index/status` | **401**（原 **404**） | **200**，body 含 `generatedAtUtc` / `fullText` / `codeIndex` | 路由已接入且鉴权正确 |
| 3 | `/api/admin/diagnostics/log-level` | **401**（原 **404**） | **200**，body 含 `level` / `isVerbose` / `supportedLevels` / `configFile` | 同上 |
| 4 | `/api/admin/storage/overview`（对照） | 401 | 200 | 鉴权中间件行为一致 |
| 5 | `/api/currentUser` | 401 | **200** | 截图的 401 = 无有效登录态，非缺陷 |
| 6 | `/api/bootstrap/status` | **403** | — | 已初始化后的预期行为 |
| 7 | `/admin/`、`/admin/index-status`、`/admin/diagnostics` | **200** | — | SPA 外壳与深链正常 |

第 2 条是**独立于 HTTP 状态码的第二条证据链**：该路由只存在于新程序集，返回 401/200 即证明运行进程加载的确实是新构建。

## 未完成 / 边界（诚实记账）

1. **未执行“普通用户 JWT ⇒ 403”**：本 DataRoot 的 `AppUsers` 只有 `admin` 一行，没有非管理员账号可登录；为避免向用户数据库写入测试用户，本轮未造账号。该断言目前只有源码依据（`[Authorize(Roles="admin")]` + 匿名 401 / 管理员 200 同一条中间件链路）。
2. **中断了一个在飞执行**：停机瞬间存在 1 个 `running` 执行（`chat_execution_commands.Id=3520`，session `206a9b48…`，agent `default.global_general-assistant.6a8`，`metadata_json.source = "heartbeat"`）。它是**心跳自驱**轮次而非用户手动消息，重启会终止该轮；`agent_execution_reservations` 为 0。部署决策包 §4-P-5 要求“无在飞子代理”，本轮**不满足该前置条件**，属知情后的例外执行。
3. **日志中的既有告警**：新 Core 启动后 `RoslynCSharpIndexer` 报 `Failed to open project …\PuddingPlatform.csproj`（“项目 PuddingPlatform 已经是工作区的一部分”）。该告警与本次修复无关（属索引器工作区重复加入问题），本轮**未归因、未修**。
4. **前端提示去重未做**：本次只修数据面。未登录时前端仍可能对 401 弹提示；“状态失败降级为不可用 + 去重提示”仍是待办。
5. **未做启动诊断增强**（展示 Core 构建版本与路径）——待办。
6. 本轮**未改任何产品代码**，仅重建产物并切换运行实例；`desktop.json`、`system.json`、前端均未改动。
7. **产物的可复现性边界**：构建发生在 2026-10-06 22:57（首次成功编译）与本轮 23:03（补拷贝），当时工作树的代码改动为**空**（脏文件只有 `Docs/**` 与 `default-data/benchmark-seeds/**` 等文档，零运行时影响）⇒ **运行中的 Core 在代码上等于 HEAD `8bccc65`**。此后（23:06～23:14）另有写者开始修改 `AuthApiController.cs`、`BootstrapApiController.cs`、新增 `JwtTokenFactory.cs` 及 storage 前端页，**这些改动不在当前运行的 Core 内**；重新构建前需注意它们会一并进入产物。
