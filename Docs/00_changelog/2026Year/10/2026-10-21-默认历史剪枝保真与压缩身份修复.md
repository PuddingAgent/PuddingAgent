# 默认历史剪枝保真与压缩身份修复

## 根因

用户报告 trace `667d6d7946b94a5789938886afcd1233`：541438 字节请求经过摘要可降至 350430 字节，但 75 条来源全部未解析，重复用户正文引发歧义，摘要无法持久提交。默认启用的历史剪枝调用了显示预览函数：每条正文截为 2000 字符，再创建新 ChatMessage，丢失已登记的对象身份、源内容 hash、附件等信息。

更正（2026-10-21）：前次跨轮原生工具修复的端到端测试及真实副本探针传入 `compactionOptions=null`，没有执行生产默认开启的剪枝路径。先前 203 项测试及副本验证不能证明默认配置的线上问题已解决。本次将流式/非流式、跨两轮工具执行的测试扩展到 `new ContextCompactionOptions()`，保留默认加载预算及剪枝设置。

## 改动

- `Source/PuddingRuntime/Services/ContextWindowManager.cs`：剪枝只筛选原消息对象，保留完整正文、来源身份、附件、推理与 continuation；图片独立消息保留，条数边界的工具调用及所有结果整体保留。水合日志增加数据来源和未解析身份数量。
- `Source/PuddingRuntime/Services/ContextPipelineOrchestrator.cs`：预览函数更名为 `BuildSessionMessagePreviews`，明确仅服务上下文快照显示。
- `Source/PuddingRuntime/Services/ContextCompactionOptions.cs`：更新剪枝语义说明。
- `Source/PuddingRuntime/Services/ContextCompactionService.cs`：运行期原文事务归档额外写入规范附件信封，避免基类 JSON 序列化丢失图片 artifactId/detail。
- `Source/PuddingRuntimeTests/Services/ContextWindowManagerTests.cs`：默认配置全文、重复正文独立身份、图片及工具批次回归。
- `Source/PuddingRuntimeTests/Services/WarmPrefixMidTurnHardProtectionE2ETests.cs`、`WarmPrefixCheckpointCommitTests.cs`：默认配置真实执行循环压缩提交、跨轮工具归档、图片归档恢复断言。超预算用例显式断言输入确实越界，防止默认加载上限使测试静默不触发压缩。
- 更新根/Runtime 代码地图和诊断手册；没有提高上传预算或调整代理/TUN。

## 验证

- 修复前，默认配置的重复正文身份回归 2/2 失败；省略配置的对应 2 项通过，确认配置覆盖缺口。
- Runtime 定向回归 172 项中 170 项通过，2 项默认配置用例因数据被加载上限缩小而未触发压缩；修正夹具后对应 4 项全部通过，去重 **172 项通过**。包含事务回滚、附件归档、流式/非流式和默认配置跨轮工具测试。
- 身份对齐、覆盖过滤及当前轮守卫补充测试 **33/33** 通过，合计去重 **205 项通过**。
- 真实会话 SQLite 在线备份副本，默认配置加载 77 条消息，77 条身份全部解析。加入合成系统/工具定义和当前输入后，580019 → 314095 字节；成功覆盖 77 条来源，副本代次 91 → 92。重新创建管理器后摘要存在，加载消息身份均可解析。
- 副本探针使用模拟摘要，不调用模型或执行工具，只验证持久提交和恢复；生产数据库没有写入模拟摘要。证据位于忽略的 `temp/test-out/compaction-pruning/` 与 `temp/compaction-pruning-*.log`。
- Front Matter 全仓 1718 份检查通过；链接检查仍有 26 个既有失效目标、0 个失效锚点，本次文档未新增失效链接；`git diff --check` 通过。
