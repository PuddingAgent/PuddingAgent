# 2026-10-08 B3 to_ref 原生到达：目标模型在原生路径上完整

## 目标 / 背景

设计 §7 的滚动目标模型是 `page / element / to_ref / to_top / to_bottom`。前几轮补齐了 `to_top`/`to_bottom`，
`to_ref` 一直被**明确拒绝**。本轮把它做成能力，模型至此完整。

## 改动

| 层 | 改动 |
|---|---|
| Automation | `ArrivalScroll.PlanToRef(elementTop, elementBottom, previousTop, viewportHeight, stepsTaken)`：**已可见即停**（完全可见；或元素比视口高时"顶边已进入视口"）、在视口上方/下方则朝该方向滚**"刚好够到"**的距离（受单步上限约束）、**元素不跟着动即停**（不在可滚动容器里/被固定层挡住）、**步数封顶**、拿不到视口高度不猜 |
| Abstractions | `IBrowserDriverPolicy.PlanToRefStep(...)`；Null 实现返回 `null` ⇒ 明确不支持 |
| DesktopService 适配器 | 委托 `ArrivalScroll.PlanToRef`（只翻译） |
| 驱动 | `ScrollToRefAsync`：回读元素 `getBoundingClientRect()` 与 `window.innerHeight`（元素不在 ⇒ `browser_element_not_found` 并提示重新观测）、问策略、按步送真实滚轮事件、**本地硬上限 64 步**兜底；引用属性上的引号/反斜杠**转义**后再拼选择器 |
| 能力通道 | 解除对 `to_ref` 的拒绝（原生目标模型已完整） |

## 已知边界（诚实登记）

- **真机未验证**：`getBoundingClientRect` 轮询 + 滚轮在真实页面上的收敛行为需要外部 smoke；
  本轮证据是策略单测、适配器单测与**映射层断言**（不含真实位移观测）。
- **"已可见"取的是"完全可见"**：元素比视口高时退化为"顶边进入视口"；不做平滑滚动、不做居中。
- **元素不跟着动即停**可能对"延迟加载后才出现"的容器过于保守（停止原因会如实写成
  "the target element did not move while scrolling"）。
- **嵌套滚动容器**：滚轮落点仍是视口中心（对元素在容器内的场景通常正确，但不保证）；
  回读的是元素相对**视口**的位置，不是相对容器。
- **只支持文档级 `data-pudding-ref` 选择器**：影子 DOM/iframe 内的引用不在本轮范围。
- 停止原因复用上一轮的通道（`ScrollOutcome.StopReason` → `DesktopScrollReport.StopReason`）。

## 影响与回滚

- **行为变化（Agent 可见）**：`scroll` + `input_mode=native` + `scroll_target=to_ref` **不再被拒绝**，
  改为真实滚轮循环（需要 `locator`，契约层已强制）。
- 回滚：还原能力通道的拒绝分支、驱动分支与辅助方法、seam 成员、适配器方法与三处用例。
