# 文档门禁的 Python 环境漂移 + 新增组件（011e240）门禁复核

> **性质**：**环境事实登记 + 只读门禁复核**。未改任何源码、任何门禁脚本、任何既有文档。

## 一、环境事实：`python` 已不在 PATH（带时点）

探针时间：**2026-10-17 23:08 ~ 23:12（本地）**。

| 探针 | 原始输出 |
|---|---|
| `where.exe python` | **exit 1**（未找到） |
| `Get-Command python` | 命中 `C:\Users\hyfree\AppData\Local\Microsoft\WindowsApps\python.exe`，**文件大小 0 字节** |
| 执行该存根 `& $p --version` | **exit 9009**，stderr：`Python was not found; run without arguments to install from the Microsoft Store, or disable this shortcut from Settings > Apps > Advanced app settings > App execution aliases.` |
| `HKLM:\SOFTWARE\Python\PythonCore` | **0 项** |
| `HKCU:\SOFTWARE\Python\PythonCore` | **1 项**：`3.14` → `InstallPath = C:\Users\hyfree\AppData\Local\Python\pythoncore-3.14-64` |
| 绝对路径执行 | `C:\Users\hyfree\AppData\Local\Python\pythoncore-3.14-64\python.exe` → **`Python 3.14.7`，exit 0** |

**结论（环境型，带时点）**：解释器**仍在磁盘上**（3.14.7，per-user 安装），
但 **PATH 里只剩 Microsoft Store 的 0 字节执行别名存根**，因此 `python` / `py` 直接调用一律 **9009**。

**影响面**：仓库 **5 个 Python 门禁**（`front_matter.py`、`check_md_links.py`、`code_map_check.py`、
`verify_codemap_global.py`、`verify_codemap_wave.py`）**不能再用裸 `python` 运行**；
7 个 PowerShell 门禁（`TestScripts/check-*.ps1`）**不受影响**。

## 二、⚠️ 本次差点误判的仪器陷阱

`shell` 工具对非零退出**只回报 `exit code 1` 并丢弃 stderr**，于是我最早看到的是：

```
❌ Tool 'shell' FAILED (exit=1)
```

这与「**门禁跑完并判出不合规**」的表现**完全一样**。
如果我据此写"文档门禁发现违规"，就是**把环境损坏报成结论变化**。
实际根因是 **9009 = 命令不存在**。

> **纪律**：门禁类命令失败时，**必须先区分"工具没跑起来"与"工具跑起来并判红"** ——
> 判据是**有没有拿到工具自己的输出行**（`扫描 N 个` / `error: 0` 等）。拿不到输出 ⇒ 先怀疑环境，不要怀疑结论。

## 六、⭐ 一个对「决策项 ②：刷新 §5 指纹」有直接影响的发现

`code_map_check` 的指纹汇总：

```
fingerprint_check: declared_files=4 globs=10 verified=8 mismatched=2 unverifiable=0
```

剩下 2 条失配**都在仓库根 `code_map.md`**：

| glob | declared | computed |
|---|---|---|
| `Source/**` | `6b8fcb222277` | `1d4b409a7d6a(files=4734)` |
| `Tests/**` | `d0f59f75edda` | `84f417d31b03(files=155)` |

**关键事实**：根 `code_map.md` 的最近一次修改**就是本次 `011e240`**（`git log -3 -- code_map.md` 可证），
即 **"刷新指纹的那一次提交，自己就留下了 2 条失配"**。
（10-14 记的 `declared` 是 `869bcd5ee8b0` / `b0411cf64a03`，说明**确实刷新过**，只是刷新后源又变了 ⇒ 再次失配。）

**⇒ 对决策的含义**：手工/单次刷新指纹是**追逐型**工作 —— 每次新增文件都会立刻再失配。
要么把刷新做成**与代码同提交的脚本化步骤（或提交前钩子）**，要么把指纹**降级为非门禁信息**。
（本次**未执行**任何一种，仅登记事实。）

## 八、给后续会话的操作口径（可复用）

```
$py = 'C:\Users\hyfree\AppData\Local\Python\pythoncore-3.14-64\python.exe'
& $py Tools\Docs\front_matter.py --check
& $py Tools\Docs\check_md_links.py
& $py Tools\Docs\code_map_check.py
powershell -NoProfile -ExecutionPolicy Bypass -File TestScripts\check-project-layering.ps1
```

> 若日后 PATH 恢复，可直接用裸 `python`；**判断标准是 `python --version` 是否返回 0 并打印版本号**，
> 而不是 `Get-Command python` 是否有命中（0 字节存根也会命中）。

**`--paths` 必须用正斜杠**（实测）：

- `--paths 'Docs\00_changelog\...md'`（**反斜杠**）⇒ `ERROR: --paths 显式给出的前缀未匹配到任何 .md 文件` + **exit 1**；
- `--paths 'Docs/00_changelog/...md'`（**正斜杠**）⇒ `扫描 1 个 md；不合规 0 个` + exit 0。

这是**上一轮给该工具加的 fail-closed** 在起作用（**拒绝把"扫描 0 个"报成通过**）—— 行为正确，
但反斜杠写法会被判为"0 匹配"，属**用法陷阱**而非缺陷。
