# Debug 开关的服务端地基：日志级别接口（Admin 鉴权，重启后保持）

## 为什么先做服务端

用户要的是"Desktop Shell 与前端各一个 Debug 按钮"。按钮本身只是 UI，**没有服务端就无从下手**：
必须有一个受鉴权的接口能在**不重启常驻进程**的前提下切换日志级别，并把选择持久化（否则重启后悄悄退回，
用户会以为"我开过 Debug"却找不到日志）。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/PuddingCore/Configuration/PuddingDataPaths.cs` | 新增 `LoggingConfigFile => <DataRoot>/config/logging.json`。**单独一个文件**而不是塞进 `system.json`：级别是随时开关的运维旋钮，与端口/Token/启动策略不是一类东西，分开也避免读写互相覆盖 |
| `Source/PuddingCore/Observability/PuddingLogLevelStore.cs`（新） | 级别持久化 + 运行时生效：`TrySetAsync`（无法识别的级别名 ⇒ `false`，**既不落盘也不改运行级别**；别名规范化成 Serilog 正式名再落盘）、`ApplyPersistedLevel`（同步，供启动路径）、`ApplyPersistedLevelAsync`（供接口/测试）、`IsVerboseEnabled`（界面据此提示"用完记得关"）。写入复用既有 `AtomicFileWriter`（临时文件 + fsync + 替换） |
| `Source/PuddingHost/Hosting/PuddingLoggingBootstrapper.cs` | 启动时应用持久化级别（文件缺失/损坏 ⇒ 沿用配置/环境变量解析出的启动级别，不让日志配置拖垮启动） |
| `Source/PuddingHost/Hosting/PuddingApplicationHost.cs` | 注册 `PuddingLogLevelStore` 单例（与 bootstrapper 共用同一个 `LoggingLevelSwitch`） |
| `Source/PuddingHost/Controllers/DiagnosticsLogLevelController.cs`（新） | `GET/PUT /api/admin/diagnostics/log-level`；鉴权与命名空间照抄 `IndexAdminController`（登录态 Admin JWT，`Roles = "admin"`）。GET 返回当前级别 + 可选值 + 配置文件路径；PUT 成功即已生效且已落盘，无法识别 ⇒ **400 且不改任何状态**（fail closed） |

## 两个有意的设计选择

1. **先落盘、后生效**：反过来的话，落盘失败会出现"运行级别已放宽、重启后却不是"这种用户无法理解的状态；
   先落盘则失败时运行级别保持不变，接口如实报错。
2. **配置里的级别优先于环境变量**（`ResolveStartupLevel` 的既有顺序）：`logging.json` 只在用户显式切换过
   之后才存在，此时它代表用户的最新意图，应当压过部署时的 `PUDDING_LOG_LEVEL` 默认值。

- `PuddingHost` 构建 **0 错误**；
- `PuddingHost.Tests` **246/246 全绿**（本轮新增 6 条：未知级别必须 `false` 且不落盘/不改级别、
  别名规范化成正式名落盘、重启恢复 + 人工损坏/无法识别/文件缺失三种兜底、GET 快照、PUT 未知值 400 且级别不变、
  PUT 合法值生效并落盘且 `IsVerbose=true`）；每条都在 `finally` 里恢复进程级开关（Serilog 开关本就是全进程单例），
