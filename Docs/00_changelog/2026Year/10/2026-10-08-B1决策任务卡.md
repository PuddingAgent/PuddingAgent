# 2026-10-08 把决策①落成任务卡

## 改了什么做法

此前 70+ 轮我都在**对话里追问**同一个取舍（A/B/C）。这不够好：追问会被淹没，而结论无处可领。
本轮把它写成任务卡：[B1 身份准入接线（待决策）](../../../15_tasks/2026-10-08-B1身份准入接线-待决策.md)。

卡里包含：

| 内容 | 要点 |
|---|---|
| **调用图事实**（可复现） | 契约**已强制**携带 caller；`Admit` 实现与 43 条相关用例**已完整**；**生产代码无任何调用方**；线缆 `DesktopCallContext` **不携带**身份；活路径 = AgentTools → Host 桥 → CapabilityBroker `DesktopSession` → WebView2 |
| **三个选项** | A 接受 Core 跨进程声明（推荐）/ B 只认 Desktop 进程内 / C 暂不接 |
| **每个选项的改动面** | A 约 4 处文件（**其中 3 处非我所有**，需授权；含一次跨进程契约变更）；B 主要在我这边但**无法区分多任务/子代理**；C 则 B1/B6 持续悬空 |
| **统一验收标准** | 唯一准入调用点、缺身份即拒（取红）、身份只能来自执行上下文、拒绝原因可区分、既有用例保持绿、按 §10 一次性同步消费方且**不加静默兼容层** |
| **我不会做什么** | 不越权改 Host/CapabilityBroker/线缆契约；不用 DesktopId 冒充调用者；不凭环境推断身份；不把结论写成"已实现" |

## 同时宣布的一条自律

**在 A/B/C 落定前，我不再新增"没有生产调用方"的 API。**
rounds 167–168 新增的两处投影（`BrowserCallerIdentityProjection`、`BrowserCallerIdentitySource`）目前**仍无生产调用方**——
它们是"唯一正确入口"的铺垫，但**不是**接线；这一点已在任务卡与日志里如实标注。
若最终选 C（暂不接），这两处应被视为**未接线的组件级能力**（可由使用方决定保留或回退）。

## 验证

| 项 | 结果 |
|---|---|
| 文档门禁 | 前 Matter / 链接 / BOM 全部在基线内（见提交时的门禁输出） |
| 全量链 | **本轮为文档任务，未跑**（无产品代码变化；上一次链跑为 round-168 的 **1624/0**） |
| 任务卡可读性 | 含"一句话需要谁做什么"、可复现事实表、选项对照、验收标准、边界 |

## 诚实边界（诚实登记）

- **任务卡不是进度**：它把阻塞写清楚，**不改变 B1 的完成度**。
- **选项 A 的改动面估算可能偏小**：跨进程契约变更实际会牵动 proto/DTO/映射/版本协商（§10 已说明），我只列了 4 处**主要**文件。
- **B 与设计不符**：我把 B 列为"与 §3.2 的绑定任务身份不符"，若产品确实只想要会话级授权，应**改设计文档**而不是让实现漂移。
- **未真机验证**；②③④ 仍未拍板。
