# 传输用量只读出口：`GET /api/admin/transport/status`（切片 F 退役判据的证据面）

## 为什么做这个

技术方案 §5 最后一步是「分阶段迁移现有 WebSocket Bridge」。组合根已按
`DesktopTransportRouting.Decide` 在**能力通道 / 既有 Bridge** 间二选一，
「可以退役旧 Bridge」的判据也已实现（`DesktopTransportUsage.CanRetireLegacyBridge`：
**窗口内**通道调用 > 0 且旧 Bridge 回退 = 0 且无路由 = 0）。

但该计数此前**只存在于进程内**，外部验收只能从人读日志里找 `transport(...)` 行
（运行手册第 6 步的已知留白）。本轮把它变成机器可读的状态字段。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/PuddingHost/Controllers/TransportStatusController.cs`（新增） | `GET /api/admin/transport/status`；鉴权与命名空间**照抄** `IndexAdminController`（登录态 Admin JWT，`Roles = "admin"`；不接 Desktop ControlToken、不接 External Access Token —— 同级运维面不各自发明闸门）。纯只读、零副作用 |
| 同文件的 `DesktopTransportStatusSnapshot` | 证据字段：`available` / `capabilityChannelCalls` / `legacyBridgeCalls` / `noRouteCalls` / `channelProven` / `canRetireLegacyBridge`；字段名一旦发布不得随意改名 |
| `Tests/PuddingHost.Tests/BrowserBridge/TransportStatusApiTests.cs`（新增） | 三条断言：未启用浏览器自动化 ⇒ 如实 `available = false`（不编造 0、不 500）；出现过回退 ⇒ 判据**不可**退役；清洁窗口内纯通道调用 ⇒ 可退役 |

## 有意设计

- **不把计数器注入构造函数**：浏览器自动化关闭时它未注册，构造函数注入会让整个控制器构造失败
  ⇒ 用 `IServiceProvider.GetService`，缺注册时如实返回 `available = false`；
- **`available = false` 时其余 0 不代表"没有调用"** —— 这一点写进了 DTO 文档注释，避免误读；
- 判据是**窗口内**零回退：一旦窗口里出现过一次 Bridge 回退，即使之后全走通道也仍为 `false`
  ⇒ 这正是退役需要一个**干净验收窗口**的原因（测试显式钉住了这个语义）。

## 验证

- `PuddingHost.Tests` **234/234**（原 231 + 本轮 3 条新用例）；
- `PuddingHost` 构建 0 错误（控制器由 ASP.NET 程序集扫描自动发现，无需 DI 注册）；
- **未验证**：真实会话里该端点的 HTTP 往返与 JWT 门禁（需要登录态与外部窗口；本轮的用例直接对控制器取快照，鉴权由 `[Authorize]` 声明保证）；
- **未验证**：能力通道真实启用后的计数（正是运行手册第 6 步要采集的）。
