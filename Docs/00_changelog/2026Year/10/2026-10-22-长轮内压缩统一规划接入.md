# 2026-10-22 长轮内压缩统一规划接入

## 改动

- `Source/PuddingRuntime/Services/WarmPrefixCompaction.cs` 通过独立策略决定确切跨度、摘要额度和包装预留；移除重复候选算法，`LlmRequestBudgetGuard.PrepareSoftCompaction` 改为同一规划器的适配入口。
- `Source/PuddingContextPolicy/ContextCandidateSelector.cs` 在硬压力下按 token/字节预算调整近期条数偏好，仍保留最新完整执行单元与未完成工具批次；增加对应独立测试后再接入。
- `BoundedCompactionSummary.cs` 统一所有摘要输入为选中跨度，避免大重放被请求守卫裁剪后丢失源；所有分段成功才归并，输出超额仅从同一完整源重生成一次。原始执行记录与 checkpoint 继续同事务保存。
- `AgentExecutionService.cs` 使用规划额度控制摘要调用与提交；DeepSeek Responses 摘要关闭思考，主调用保持原配置。checkpoint 为 Assistant，当前 User 始终保留；续传载荷参与身份 CAS 及摘要源。
- `LlmRequestTextBudget.cs` 与校验结果保留实际拒绝后的体积；诊断增加替换位置、保留侧体积、摘要计划与实际额度。更新根/组件/Runtime 地图及诊断手册。

## 验证

- 独立 `PuddingContextPolicyTests` **49/49** 通过，仍为无宿主依赖的 BCL 组件。
- Runtime 定向过滤 WarmPrefix、BoundedCompaction、LlmRequestBudgetGuard、ContextWindowManager、ContextCompaction、CompactionSource：**199/199** 通过。
- 新增长任务用例：同一 User 下执行 48 轮、每轮两项原生工具调用，流式/非流式均多次持久压缩；每个主请求通过客户端 512 KiB 文本预算，当前输入不变，工具配对完整，事务归档与重启水合正常。
- 覆盖摘要超额有界重生成、拒绝后实际体积、Responses continuation 变更失效、源身份、CAS 冲突、失败回滚与百万字节历史。
- Front Matter 全量检查 1721 文件零不合规（本日志新增后另做定向检查）；链接检查工作树 48 处历史目标缺失，主副本基线 26 处，其余为隔离工作树未初始化的参考子模块；本次文件无新增失效目标，锚点零失败。
