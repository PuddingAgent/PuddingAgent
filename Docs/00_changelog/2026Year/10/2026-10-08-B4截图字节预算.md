# 2026-10-08 B4 截图字节预算：超预算不截断图片，如实报资源耗尽

## 目标 / 背景

上一轮（[B4 截图第一步](2026-10-08-B4截图第一步CDP截屏.md)）实现了 CDP 截屏，并登记了两条边界：
「没有截图大小上限」与「还没接线到 Artifact」。本轮先补前者——它不需要任何架构决定，而且是接线的**前置**。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| Abstractions | `ScreenshotOptions.MaxBytes` | 截图的字节上限（可选） |
| Automation | `ScreenshotPlan.CheckBudget` / `DescribeBudget` / `BudgetVerdict` | 预算判定（纯函数）。**截图绝不"截断到预算内"**：半张图会让读者得出错误结论，比没有更危险；超了就 `Exceeded`，说明里给出降画质／改成视口截图／提高预算三条出路 |
| 驱动 | `WebView2BrowserPage.ScreenshotAsync` | 解码后按预算判定，超预算抛 `browser_resource_exhausted`（沿用错误目录里既有的资源耗尽语义） |

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **249 / 249**（原 247 ＋ 2） |
| `PuddingDesktop.Tests` · `Host` · `DesktopSurface.BrowserTests` · `ContractsTests` · `DesktopServiceTests` · `AgentTools.Tests` | 320/320 · 258/258 · 65/65 · 152/152 · 229/229 · 61/61 |

新增门禁：恰好等于预算 ⇒ `Within`；超出 1 字节 ⇒ `Exceeded`；未设预算 ⇒ `Within`（不因"没设"而拒绝）；
说明文本含实际字节数并明确"never truncated"；负数/零预算 ⇒ `ArgumentOutOfRangeException`。

**取红实测**：把 `CheckBudget` 的判定改成恒 `Within`（＝预算形同虚设）⇒
`BudgetIsCheckedWithoutTruncatingTheImage` **恰好变红**；复原后 249/249 复绿。

（过程记录：复原变异时我用文本替换，误伤了同函数里的另一个 `return BudgetVerdict.Within;`，
导致测试红了 1 条；读代码定位后修正并复跑全绿——这正是"替换后必须复跑"的原因。）

## 关于"接线到 Artifact"：本轮查证结果与**没有**仓促动手的理由

我查了仓库的 Artifact 现状：

- **已有**生产级 artifact 存储：`Source/PuddingPlatform/Services/VisionArtifactStorageService.cs`
  （`vision-{32hex}` 身份、workspace 作用域、`ResolveAsync`/`ResolveLocalFileAsync`，且有路径穿越等防护测试），
  以及 `ImageReaderTool`/`ImportImageTool` 这类 **Host 侧工具**通过注入来落盘、只把 `artifactId` 回给模型的既有范式。
- **缺的**是一条明确的字节归属链：截图发生在 **Desktop 进程**（只有它持有 WebView2），
  而 artifact 存储与工具在 **Core/Host 进程**。所以字节要么过桥（base64/二进制，需要预算与失败语义），
  要么 Desktop 直接写进共享的 DataRoot artifacts 目录（那又绕过了 workspace 作用域与去重）。

这是一条**架构决定**，不是接线细节。我没有在本轮预算的末端仓促选一条（那会污染既有 artifact 语义并留下难回退的跨进程契约）。

**下一步的候选方案（供决策，不预设结论）**：
1. **过桥 + Host 落盘**（复用既有 `vision-` 存储与去重）：Desktop 只回字节 + 尺寸事实（受 `MaxBytes` 约束），
   Host 侧新增 `browser_screenshot` 工具写 artifact，输出 `artifactId`（与 `ImageReaderTool` 同范式）。
   代价：桥上一次较大的二进制载荷（需要看现有桥的消息上限）。
2. **Desktop 直写共享目录 + Host 注册**：省一次传输，但要处理 workspace 作用域、命名与去重的一致性。
3. 截图**只作为工具输出内联**（不落 artifact）：最省事，但把大 base64 塞进模型上下文，与 §6 的"给引用"取向相反。

## 已知边界（诚实登记）

- **还没接线**：`ScreenshotAsync` 仍无能力通道/桥接/工具调用方；`MaxBytes` 因此目前只有驱动内部生效。
- **真机未验证**：预算判定是纯函数；"CDP 返回的真实字节数分布"（PNG 整页有多大）需要真机采样，
  才能给默认预算一个有理有据的数值（当前默认是"不设限"）。
- **JPEG 是 quality 的隐含结果**（`ScreenshotOptions` 无显式格式字段），已在上一轮登记。
- 元素级截图（clip 到某个 ref）仍未实现；`PrintToPdfAsync` 仍 unsupported。

## 影响与回滚

- **无对外行为变化**：没有工具暴露截图；新增的是可选预算与其判定。
- 回滚：还原 `ScreenshotPlan.cs`、`ScreenshotOptions.MaxBytes`、驱动的预算检查、其测试与 frozen 列表、code_map。
