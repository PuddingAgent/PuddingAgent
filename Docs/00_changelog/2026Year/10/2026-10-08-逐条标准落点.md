# 2026-10-08 把 §11 的每条标准都变成可观察要求

## 为什么还能查出东西

round-146 的对账口径是"**每个门禁**有一个清单项"（并修了 G2 少两项）。本轮换成**逐条标准**（按 §11 表格里的分号逐条拆），
于是又查出**四处**标准**没有任何观察要求**：

| 门禁 | §11 里的原话（此前未覆盖） | 补进哪一项 |
|---|---|---|
| **G5** | 「**另记录进入模型后的文本 token 与调用次数**」 | S-05 期望（并注明"压缩字节 ≠ token 节省，文本与视觉分别记"） |
| **G6** | 「**全文模式必须显式选择**」 | S-06 期望（注明"默认不是全文"） |
| **G7** | 「一次 fill 回执足以确认非敏感值，**无二次 snapshot**」 | S-07 期望 |
| **G9** | 「**实际模型收到类型化图片**」 | S-09 期望（注明"不是 base64 长串；文本模型得到明确限制"） |

## 为什么这四处是"真缺口"而不是措辞问题

它们是**外部观察项**：外部一方拿着清单逐条看时，前四项标准**没有可对照的句子** ⇒ 只能靠"自己想到"。
补上之后，这些标准从"文档里的要求"变成"清单里的要求"（可对照、可留痕、可拒绝）。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **339 / 339**（严格门禁：**动作逐字**一致、**数字必须有出处**、覆盖声明真实存在） |
| 对外文档同步 | 四行期望已与代码真源同步（S-09 行整行替换） |
| **全量链** | **1624 / 0**、一次通过、无重试 |
| 对账表 | 已补记"逐条标准的清单覆盖在 rounds 146/170 两轮补齐"，并声明**至此每条标准都有落点** |

## 诚实边界（诚实登记）

- **"有落点"≠"已被验证"**：这些要求现在**可观察**了，但**从未真机执行**过（真机从未运行）。
- **判据仍在人手里**：例如"模型收到类型化图片"需要观察者判断模型侧表现（清单只能要求他把看到的事实写下来）。
- **逐条拆分可能仍有遗漏**：我按分号与"；"拆句；若 §11 句子内部还有隐含标准（例如"两传输同形"的细则），**未逐字穷举**（登记）。
- **本轮为清单/文档改动**：无产品行为变化，链跑结果与 round-168 相同（1624/0）。
- **未真机验证**；决策①（A/B/C）与②③④仍未拍板。
