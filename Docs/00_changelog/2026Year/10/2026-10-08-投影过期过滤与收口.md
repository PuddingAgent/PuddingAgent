# 2026-10-08 B1：投影不过滤过期 + 收掉对账表剩余缺口

## 一、真实缺陷：`ActiveGrants` 把**过期**授权也算作有效

契约对两个投影的说法是"当前**有效**的授权记录"，但实现直接返回字典内容：

```csharp
return _grants.Values.ToArray();     // 不过滤过期
```

而准入（`FindPageGrant` / `HasManagementGrant`）**是**检查 `IsExpiredAt` 的 ⇒
**投影与准入说法不一致**：UI 会显示"还有 N 条授权"，用户一调用却被拒。
这不是提权（准入仍然正确），但是**报告不真实** —— 与设计"绝不报告假事实"的要求相悖。

**修法**：两个投影都按当前时间过滤过期项。
**验证**：`AutomationTests` **347 / 347**（＋4）；**取红实测** —— 去掉过滤 ⇒ 相应用例变红；
`DesktopService` 315 · `DesktopSurface.Browser` 67 · `Contracts` 153 · `PuddingDesktop` 320 全部复跑**全绿**。

## 二、收掉对账表剩余缺口

| 缺口 | 处置 |
|---|---|
| `RevokeManagementGrant` 不释放在途页面租约（**有意**语义） | 补用例：撤管理授权后**管理类操作立刻被拒**，但另一个行动者写同一页仍被 `PageBusy` 挡住（证明在途租约未被释放） |
| `Capture` 无副作用 | 补用例：连续三次捕获，控制/授权世代与授权集合都不变 |
| **并发**（原本"全未验证"，最大未覆盖面） | 补**有界并发冒烟**：8 个行动者并发抢同一页写租约 ⇒ 不抛异常，且**最多一个**获得许可（G10 的最要命不变量） |
| `RevokeAllGrants` / `RevokeExecutionScope` 与派生授权 | 上一轮已补（双取红） |

⇒ 对账表 **17 个入口全部"已核对并取红"**（此前 14 红 / 4 仅正向，其中一条重复计）。

## 三、门禁的诚实性锚点也改了

原门禁要求表里出现"仅正向"这类标注，防止表格退化成全绿清单。现在**没有仅正向条目**了，
所以锚点改为：表里必须同时出现"**已核对并取红**"与"**仍缺的边界**"小节 ——
即"必须保留一节专门写没做到的部分"。这是更稳的诚实性要求（不依赖还有多少条目没验证）。

## 四、诚实边界（诚实登记）

- **并发只做了冒烟**：8 线程一次性抢租约，**没有**压力测试、没有长时间竞态分析、没有死锁分析；
  "不抛异常 + 最多一个写入者"是观察到的事实，**不是**线程安全性的证明。
- **仍缺的边界**（表内已列）：`RevokeExecutionScope` 对**管理授权**的影响；过期授权的**清理**（现在投影过滤但不从字典删除 ⇒ 字典会随签发缓慢增长，属已知取舍）。
- **准入与投影的一致性只覆盖"过期"这一维**：绑定/世代不符的授权两者都可能不一致（未逐一验证）。
- **未真机验证**；仍属组件层。
