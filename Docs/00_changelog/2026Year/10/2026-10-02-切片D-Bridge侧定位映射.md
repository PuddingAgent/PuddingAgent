# 2026-10-02 切片 D 第③步·Bridge 侧：定位映射（进度 6/9）

## 目标 / 背景

继续补齐 Bridge 侧窄端口。本轮补 `locate`——它是「快照 → 引用 → 交互」这条链里的枢纽，
也是两条传输最容易出现语义分叉的地方，因此本轮把与 Desktop 侧**同一套版本语义**也搬了过来。

## 改动

- `Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs`：
  - `LocateAsync`：`QueryAllAsync(Locator)` → `DesktopElementRef` 列表（引用、标签、**活版本**、
    role/name/text/visible/enabled/checked 均取自运行时的 `BrowserElementInfo`）；
  - `ToRuntimeLocator`：九种定位类型的显式映射；**`Ref` 没有等价物**（快照引用只在 Desktop 的
    注册表里有意义）⇒ 返回 `null` 让调用方**明确拒绝**，不猜一个选择器。
- `Tests/PuddingHost.Tests/BrowserBridge/BridgeBrowserCapabilitySurfaceTests.cs`（+5 项，合计 204）。

## 与 Desktop 侧对齐的语义（跨传输一致性）

| 情形 | 行为 |
|---|---|
| 期望版本与页面活版本不符 | `page_version_mismatch`（与 `BrowserRuntimeDesktopSurface` 同规则，绝不放行陈旧引用） |
| 页面没有活版本 | 响亮 `internal_error`（引用会失去版本依据，不返回无版本引用） |
| 命中元素没有活版本 | 响亮 `internal_error`（**绝不静默丢弃**——这正是映射规格里对 Desktop 侧的同一条要求） |
| 命中数超请求上限 | 截断并如实标注 `Truncated=true` |
| `Ref` 定位 | `invalid_request`（Bridge 侧无等价物，不猜） |

## 测试替身的第三条教训

假元素句柄把 `Id` 写死成 `"e0"`，而测试期望 `"e1"`（来自 `Info.Ref`）⇒ 假红。
**替身里由别处派生的身份字段必须真的派生**（`Id => new(Info.Ref)`），否则断言测的是替身的笔误。
与前两轮的两条（读错计数对象、两个页面共用同一 id）同属一类：**替身也要讲身份一致性**。
