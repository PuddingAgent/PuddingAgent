# 2026-10-08 I2 前置件：能力 → 操作映射

## 为什么单独立这一条

上一轮核实发现：`Admit` 判的是 `BrowserAutomationOperation`，而两条传输传的是**能力**，仓库里却没有映射 ——
只有 `Navigate`/`Interact` 两处按分支字面量传入。风险很具体：**新能力忘记映射 ⇒ 静默绕过闸门**（比报错更糟）。

## 交付

`Source/Pudding.Contracts/Desktop/BrowserOperationMapping.cs`：

| 能力 | 操作 |
|---|---|
| WebViewNavigate / WebViewExecuteJavascript / WebViewPageState | Navigate / Script / PageState |
| BrowserSnapshot / BrowserLocate / BrowserInteract / BrowserWaitFor | Snapshot / Locate / Interact / WaitFor |
| BrowserContexts / BrowserContextCreate / BrowserContextClose | ContextsList / ContextCreate / ContextClose |
| **BrowserTabs** | **TabClose**（按最严映射：激活与关闭都走同一条要求，避免"激活更轻"而少要授权） |
| Shell*（通知/状态/对话框/文件选择器/剪贴板） | 不适用（`false`）⇒ **不**要求 browser grant |

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.ContractsTests` | **195 / 195**（＋12：10 条映射 + Shell 不适用 + **目录全覆盖守卫**） |
| 防静默绕过 | `EveryWebViewCapabilityInTheCatalogHasAMapping`：遍历能力目录，凡 `Kind == WebView` 必须有映射 ⇒ 新增能力忘记映射即**变红** |
| 全量链 | **本轮未跑**（改动仅 Contracts 与其测试；纯策略函数，无行为接线） |

## 诚实边界

- **这只是前置件**：`Admit` 仍未接进执行路径（下一步在 `RunOnUiAsync` 内接线，并同步约 18 处用例）。
- **`default` 出参不代表操作**：`TryGetBrowserOperation` 返回 `false` 时出参无意义（枚举没有 `None`），已在注释与用例里写明。
- **标签页映射是保守近似**：能力粒度为"标签页操作"，映射取最严的一种；若将来拆成"激活/关闭"两个能力，应各自映射。
- **未跑全量链**；**未真机验证**。
