# 2026-10-08 横向：B6 接线可执行拆解 + 不腐烂门禁

## 起因

[B6 接线方案](../../../12_features/B6-子代理委派接线方案-2026-10-08.md) 的"施工顺序"只有四句话，
且结论是"被两项待决问题挡住"。这留下一个实际问题：**决定一旦下达，还得重新拆一遍**。

## 改动

新增 [B6 接线可执行拆解](../../../12_features/B6-接线可执行拆解-2026-10-08.md)：**9 个步骤**，
每步写清 **依赖**（无 / 决定① / 决定② / 前置步骤）、**触及文件**、**验证方式**（具体测试项目或命令）、
**现在可做**：

| 范围 | 步骤 | 状态 |
|---|---|---|
| 我的组件边界内 | S1 租约账本加固 · S2 信封工厂 · S3 有界结论 | **已完成** |
| 我的组件边界内 | S4 超时/取消/接管的归还路径用例 · S5 只读范围（`CanRead=true`）端到端组件级 | **可做（未开工）** |
| 需决定①（授权签发） | S6 页面 grant 契约**提案** · S7 Runtime 出站接线 | 被挡 |
| 需决定②（字节归属） | S8 入站结论收窄（Artifact 引用） | 被挡 |
| 需 S7+S8 | S9 结线验收（清单 S-10） | 被挡 |

同时照抄方案第六节的"不得越界"，并明确 **S7/S8 触及 `Source/PuddingRuntime`（他方子系统）**，
施工前必须取得该子系统 owner 同意。

## 门禁（防止拆解腐烂）

`DocsMarkdownEncodingTests` 新增 `TheB6WiringDecompositionNamesOnlyExistingFilesAndVerifications`：

- 步骤表必须能被解析、**步骤数 ≥ 6**、步骤 id 唯一；
- 每步必须有**依赖**与**验证方式**（不接受空）；
- 「触及文件」列里每个反引号路径**必须真实存在**（`...` 省略形式除外）；
- 必须存在至少一个「现在可做」的步骤。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **315 / 315**（＋1） |
| **取红实测** | 把 S4 的文件改成一个不存在的路径 ⇒ 用例**精确变红**并指出该路径；还原 ⇒ 315/315 全绿 |
| Front Matter | 新文档合规（`--check` 0 不合规） |

## 已知边界（诚实登记）

- **拆解 ≠ 进度**：除 S1–S3 外**均未开工**；S4/S5 标为"可做"但**没做**。
- **S6–S9 的验证方式是预期**：届时契约字段与 Runtime 接线尚不存在，验证方式可能要调整。
- **门禁只查形状**（路径存在、字段非空）：它**不**判断步骤划分是否合理、依赖是否正确 —— 那要靠评审。
- **"现在可做"不等于"应该现在做"**：取决于决定何时下达；若长期不下达，S4/S5 仍能提升组件自证度。
- 无产品行为变化（文档 + 用例）。
