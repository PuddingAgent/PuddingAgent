# 2026-10-12 SSH R3：提交事实与有界资源回收

## 目标 / 背景

审阅报告 **F3 / P1**（排空宽限之后仍无条件等待）与 ADR-096 **D3/D4**：
TERM、关闭、排空与 Dispose 必须共用一份清理预算；未结束的资源仍要有人负责并占用预算；
提交事实要在可能发送 exec 之前推进，只有底层明确「未发送」才允许保持未提交与可重试。
本切片仍只动组件与独立测试/探针。

## 改动

### 会话契约与真实适配器

- `Source/PuddingSsh/Contracts/SshPorts.cs`
  - `ISshTransportSession.RequestAbort()`：**非阻塞**中止请求（实际 TERM/关闭由会话自己的有界状态机执行）。
  - `ISshTransportSession.SubmissionEvidence`（`NotSent` / `SubmissionAttempted`）+ 新枚举 `SshSubmissionEvidence`。
  - `ISshTransportSessionDiagnostics`（`PendingReaders` / `AbortRequested` / `Closed`）：让上层能断言「回收真的发生了」。
- `Source/PuddingSsh/Transport/SshNetTransportSession.cs`
  - 提交事实在调用 `ExecuteAsync` **之前**推进；结果不再自行声明 `retry_safe`（由协调器按提交事实判定）。
  - 新增**单一关闭状态机**（`EnsureCloseAsync`）：TERM → 关闭命令 → 关闭连接 → 释放客户端/密钥/材料，
    全部共享 `CleanupGrace`，每步只拿剩余额度；谁先请求（取消/中止/释放）都只执行一次。
  - 排空改用 `SshBoundedDrain`：预算到期即 `RequestAbort()` 并**不再无条件 await** 原任务；
    仍用 `PendingReaders` 计数暴露「还有读取没结束」。

### 协调器：租约、隔离区、有界 worker

- 新增 `Source/PuddingSsh/Execution/SshBoundedDrain.cs`：`WaitAsync(drains, budget, onTimeout, onLateCompletion)`，
  超时只登记中止请求并安排迟到观察，绝不二次等待。
- 新增 `Source/PuddingSsh/Execution/SshCleanupQuarantine.cs`：容量固定的清理隔离区；纳入追踪的资源
  在真正结束时才释放计数，异常被观察；`Pending`/`Completed` 可查询。
- 新增 `Source/PuddingSsh/Execution/SshStageWorkerPool.cs`：阶段端口的**同步启动段**在有界 worker 上执行，
  容量固定，满额抛 `SshStageCapacityExceededException` ⇒ 协调器返回 `ssh.busy`；`Active`/`Completed` 可查询。
- 新增 `Source/PuddingSsh/Execution/SshResourceLease.cs`：单次操作的资源记账（准入槽位、身份材料、独占连接）；
  身份释放幂等；阶段超时后 `TransferLateOwnership()` 把收尾交给迟到 owner（关闭连接后再清零材料）。
- `Source/PuddingSsh/Execution/SshOperationCoordinator.cs`
  - 两条入口都改用租约：`BeginLease`/`EndLease` 幂等释放槽位；会话关闭走 `lease.CloseSessionAsync(剩余清理预算)`，
    预算内没结束则进隔离区并在诊断里标注 `cleanup_pending`（**不再声称已释放**）。
  - 隔离区满额 ⇒ 新增工作直接 `ssh.busy`；阶段 worker 池满 ⇒ 同样 `ssh.busy`（不排队堆积）。
  - exec 提交窗口失败按 `SubmissionEvidence` 判定：`SubmissionAttempted` ⇒ `unknown` + 不可重试；
    `NotSent` ⇒ 保持 `not_submitted` 且可重试（ADR-096 D4）。
  - 新增可观测计数：`ActiveLeases`/`QuarantinedResources`/`ActiveStageWorkers`/`QuarantineCapacity`/`StageWorkerCapacity`。
  - `StopAsync` 改为返回 `SshStopReport(PendingOperations, PendingCleanups, TimedOut)`：停止等待有界且**如实报告**残留。
- `Source/PuddingSsh/Execution/SshCoordinatorOptions.cs` — 新增 `MaxQuarantinedResources`（默认 8）与
  `MaxStageWorkers`（默认 8）；新增 `SshStopReport`。

### 测试

- `Source/PuddingSshTests/SshResourceLeaseTests.cs` — 新增 12 例：同步阻塞建连不拖住业务等待、worker 池满 `busy`、
  永不关闭的会话进隔离区并如实标注、隔离区满额拒绝新增工作、资源真正结束后隔离计数归零、
  `StopAsync` 有界且如实报告、连续超时后计数回基线、提交窗口失败只执行一次且不可重试、
  迟到连接被关闭且身份只清零一次、迟到身份被清零且不建连、`ssh_test` 同样受租约/隔离管理。
- `Source/PuddingSshTests/SshOperationCoordinatorFaultMatrixTests.cs` — 提交窗口两条用例按 ADR-096 D4 重写
  （有证据 `NotSent` 才保持 `not_submitted`/可重试；否则 `unknown`/不可重试）。
- `Source/PuddingSshTests/SshFakes.cs` — 假会话支持 `RequestAbort`/提交事实/永不结束的 Dispose/同步阻塞启动段。

## 验证

- `dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **161/161 通过**，0 警告 0 错误。
- 真实协议：`powershell -File TestScripts/ssh-probe/run-ssh-probe.ps1` → **17 场景 `failures = 0`**：
  取消仍在 1.5 s 内收敛并回报 `TERM`；`ignoreterm` 仍为 `unknown` + 远端 `SHELL_ALIVE`；
  240 MiB 双流捕获恒 64 KiB、驻留内存 < 0.4 MiB；`coordinator` 全链路 3 次认证不变。
