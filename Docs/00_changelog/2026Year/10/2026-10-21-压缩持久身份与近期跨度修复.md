# 2026-10-21 压缩持久身份与近期跨度修复

## 现场与原因

关联会话 `206a9b48ec904ebb93e7541131fbb835`，错误 `llm-450edaf16fb747cebdf90e2660989cd4`。只读查询 canonical 压缩事件确认：早先失败原因为 `durable_commit_coveredmessagesnotfound`，随后变为 `after_summary_exceeds_text_budget`。18:25 的请求估算 957,856 字节，工具定义 158,675 字节，预算 524,288 字节；摘要调用成功，但仍未提交。

- 水合先取得精确行 ID，又按角色/正文唯一匹配重绑；重复用户文本丢失身份。暖历史保留时登记表被新投影替换，新 checkpoint 也未登记 ID。
- 提交同时传 ID 与正文键，服务按正文键重新解析，角色已从 system 变为 assistant 的旧摘要以及重复文本都会失败。用户输入的运行时信封也不能直接按正文匹配 canonical 行。
- 摘要候选沿用了直接裁剪的“最后八条”保护地板，最近的大块旧轮次无法进入摘要，即使生成摘要也无法使请求进入预算。

## 改动

- `ContextWindowManager.cs` 保留水合对象的精确身份与仍在暖历史中的登记；`HistoryPrefixReconciler.cs` 在完整有序前缀验证通过后传递 canonical 身份，支持用户信封；未投影工具消息不推断 ID。提交完成后登记新 checkpoint，供后续压缩使用。
- `AgentExecutionService.cs` 在跨度 ID 全部可用时只传 ID，正文匹配仅作未解析跨度的回退；持久提交成功之前仍不替换内存。保留代次、身份、收益与预算校验。
- `LlmRequestBudgetGuard.cs` 在文本超限且常规八条保护不能达标时，允许摘要覆盖完整旧轮次；当前用户输入与当前轮工具交换受保护，直接裁剪规则保持原约束。不可压缩部分已经超预算时，摘要调用前返回 `protected_request_exceeds_text_budget`。
- Buffered/Streaming 传递压缩失败原因；`LlmRequestTextBudget.cs` 增加 `compaction_reason` 与 system 体积。流式错误码使用稳定因果码，预检失败定位为 request_preflight。
- `ConversationTerminalMessageFormatter.cs` 让飞书等文本渠道显示因果码、请求/工具体积、压缩原因、建议、errorId/traceId；证据仅白名单投影。同步更新代码地图与调试手册。

## 验证

- Runtime 压缩、请求预算、水合、历史对齐和终态诊断回归：173 项通过；当前用户输入本身超预算的新增端到端用例：1 项通过，摘要与主调用均为零，持久代次不变。
- 飞书等渠道终态格式化：4 项通过，覆盖稳定码、体积、压缩原因、定位 ID 及非白名单字段不外显。
- 用户信封身份传递补充修改后，相关水合/历史对齐/重复消息/受保护输入回归 75 项通过（含前述用例，不重复累加）；各组按用例去重共 178 项通过。
- 真实会话数据库在线备份副本验证（仅 `temp/test-out/compaction-repair/memory-snapshot.db`）：加载 100 条消息，精确身份全部可解析；合成固定 system/tools 配合真实历史，模拟摘要经真实应用/事务提交边界，88 条消息覆盖，代次 91→92，请求 564,066→257,767 字节；重新加载摘要存在，体积 421,117 字节。副本包含模拟摘要，不得部署或覆盖真实数据库；此项验证持久化链路，不代表真实模型语义质量验收。
- 首次测试启动在用例开始前超过 60 秒等待上限，中止后以 120 秒重跑通过；未把中止算作通过。
- 全仓 Docs Front Matter 检查 1,714 个既有文件，违规 0；新增日志另作定向检查。链接检查仍有 25 处既有失效目标，本次修改未新增失效引用。
