# 2026-10-12 SSH R4：输出完整性与公开诊断有界

## 目标 / 背景

审阅报告 **F4 / P2**（读取异常被当作正常 EOF）与 ADR-096 **D4/D5**：远端退出事实、提交事实与**输出完整性**
必须分别表达；公开诊断不得携带第三方异常 Message、known_hosts 整行等原始载荷，且必须有长度上限。
本切片仍只动组件与独立测试/探针。

## 改动

### 输出事实分离

- `Source/PuddingSsh/Execution/SshStreamDrainResult.cs` — 新增：单条流的排空事实
  （`ReachedEnd` / `ReadFailed` / `Aborted`，含 `NotStarted`/`Ended`/`ReadFailed`/`Aborted` 四个静态值）。
- `Source/PuddingSsh/Execution/SshBoundedOutputCollector.cs` — 排空返回事实并分别记录 stdout/stderr：
  - EOF ⇒ `ReachedEnd`；`ObjectDisposedException`（本端中止/关闭）⇒ `Aborted`；其他读异常 ⇒ `ReadFailed`（**不再 break 成 EOF**）。
  - 聚合：`ReachedEnd`（两条流都读到 EOF）、`AnyReadFailed`、`AnyAborted`、`IncompleteReason`。
- `Source/PuddingSsh/Diagnostics/SshOutcomePolicy.cs` — 新增纯判定：
  - 执行失败优先保持原状态；无 exit-status ⇒ `ssh.exit_status_missing`；只有 exit-signal ⇒ `ssh.remote_exit_signal`；
    非零 ⇒ `ssh.remote_exit_nonzero`；**exit=0 但输出未读完 ⇒ `ssh.output_incomplete`**（保留已知退出码）；
    只有「exit=0 + 两条流读完 + 无执行失败」才是 `Completed`。
  - `IncompleteReason` 给出稳定 token：`read_failed` / `aborted` / `unknown`。
- `Source/PuddingSsh/Contracts/SshResults.cs` — 结果新增 `OutputComplete`、`OutputIncompleteReason`、
  `CleanupState`（新枚举 `SshCleanupState`：`NotStarted`/`Completed`/`Pending`），`ssh_test` 结果同样带清理状态。
  **预算截断 ≠ 输出不完整**：`reached_end` 与 `output_truncated` 是两个字段。
- `Source/PuddingSsh/Diagnostics/SshDiagnostics.cs` — 新增错误码 `ssh.remote_exit_signal`、`ssh.output_incomplete`。
- `Source/PuddingSsh/Transport/SshNetTransportSession.cs` — 用采集事实 + `SshOutcomePolicy` 判定结果；
  排空未在预算内结束时按「未读到 EOF + 被中止」表达；清理状态由协调器按租约结论写入。

### 公开诊断有界

- `Source/PuddingSsh/Diagnostics/SshDiagnosticText.cs` — 新增：`MaxLength=512` 截断并标记 `…(truncated)`；
  `FromException` 只给 `exception=<TypeName>`（**不复制** `Message`）。
- `Source/PuddingSsh/Execution/SshOperationCoordinator.cs` — 所有异常诊断统一走 `FromException`，
  所有 `Diagnostic` 出口走 `Bound`；清理未结束时写入结构化 `CleanupState=Pending`（诊断只作为补充说明）。
- `Source/PuddingSsh/Validation/SshKnownHostsParser.cs` — 不支持记录的原因改为 **原因码 + 行号**
  （`unsupported_known_hosts_record code=<code> line=<n>`），不再把整行放进公开错误；
  原因码：`cert_authority`/`unknown_marker`/`malformed_fields`/`bad_base64`/`empty_key`/`hash_version`/
  `empty_pattern`/`negation_pattern`/`wildcard_pattern`。

### 测试

- `Source/PuddingSshTests/SshOutputIntegrityTests.cs` — 新增 15 例：EOF/读失败/中止三态、预算截断仍算完整、
  判定策略六种组合（含执行失败不被输出事实改写）、清理状态结构化（正常 Completed / 隔离 Pending）、
  known_hosts 原因码 + 行号且**不含原始行**、会话异常 Message 的哨兵串不出现在公开诊断、诊断截断标记。
- `Source/PuddingSshTests/SshValidationTests.cs` — 解析用例改为断言稳定原因码。

## 验证

- `dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **176/176 通过**，0 警告 0 错误。
- 真实协议：`powershell -File TestScripts/ssh-probe/run-ssh-probe.ps1` → **17 场景 `failures = 0`**：
  取消仍 `cancelled` + `TERM`、`ignoreterm` 仍 `unknown` + 远端存活、`coordinator` 的 `exit 3` 仍为
  `remote_exit_nonzero`、`cwd` 的 cd 失败仍为非零退出且零副作用。

  协议矩阵扩展（预先取消零连接、截止后晚连接不执行 marker、服务端停止发包/不发 EOF 的收敛、多轮后资源回基线、
