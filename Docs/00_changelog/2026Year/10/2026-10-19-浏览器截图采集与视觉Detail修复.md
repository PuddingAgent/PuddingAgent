# 2026-10-19 浏览器截图采集与视觉 Detail 修复

## 改动

- `Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs`：无参数 CDP 的 nullable null 转为 `{}`；原属性模式未覆盖 C# null，`Nullable.Value` 在真正调用 CDP 之前抛异常。共享源由 WinUI 链接编译。
- `Source/PuddingBrowser.Automation/ScreenshotPlan.cs`、`ScreenshotLayoutFacts.cs`、新增 `ScreenshotImageHeader.cs`：采集参数真正应用 PNG/JPEG 和低清缩放；独立采集 DPR，保留页面 zoom；读取编码字节中的实际格式/尺寸。独立组件测试先通过，再接表面。
- `Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs`：验证字节与计划、捕获后页面版本；以文档 CSS 保存裁剪原点；截图坐标的点击/移动/拖拽两端真正使用换算值。
- `Source/PuddingBrowser.AgentTools/BrowserScreenshotTool.cs`：`LlmImagePart` 第二参改为采集 detail，修复误传 MIME；细小文字/图案提示使用 original 或区域。
- 更新 ADR-097 D5、一期方案、浏览器诊断手册与受影响 code_map；按用户提供的 [DeepSeek Detail Level](https://api-docs.deepseek.com/zh-cn/guides/vision/) 核对模型边界。网关已有 low→low、original/high/auto→high 映射符合当前 DeepSeek 语义，未更改网关实现。

修复前用例复现：无参 CDP 1 失败/4 通过（`Nullable object must have a value`）；detail 三种输入均错误变为 `image/png`（3 失败）；滚动截图换算后驱动实际收到 10 而非 25（1 失败）。修复后的对应回归全部通过。模型 wire 测试覆盖 low/high/original/auto，Responses 工具图片与 Chat Completions 用户图片分别验证；不把 fake HTTP 当作真实模型验收。

定位器已有源码修复，本任务不重复实现；其运行中旧 Core 须由成套重建部署解除。构建包含现有前端 6.9.10，避免回退此前发送按钮修复。
