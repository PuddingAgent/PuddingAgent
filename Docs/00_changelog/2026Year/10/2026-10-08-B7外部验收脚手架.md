# 2026-10-08 B7 外部验收脚手架：一条命令产出观察骨架并算出结论

## 目标 / 背景

上一轮把判定链做成 CLI（`--conclude`），但外部一方还得自己拼观察 JSON。本轮给出**实际入口**：
一条命令产出骨架 → 人按清单在真机上观察并填写 → 再一条命令算结论。

## 改动

`TestScripts/external-acceptance.ps1`（新增，**纯 ASCII**）：

| 行为 | 说明 |
|---|---|
| `-Template`（默认在没有 facts 时执行） | 写出观察骨架：11 项 `S-01…S-11` 全部 `not-run` + 生命周期四步 `passed:false`；并从交付清单里**预填** `observedBuildId` |
| 打印观察表 | 逐项给出 `id / 门禁 / 区域`，并指向 `Docs/14_reports` 的期望说明 |
| `-Conclude`（默认执行） | 调用 CLI `--conclude`：清单 + 事实 → 结论；**退出码原样透传**（0 = 允许，2 = 拒绝） |
| 留痕 | 把验收记录写到 `-Record`（默认 `temp/test-out/external-acceptance-record.md`） |

**为什么纯 ASCII**：Windows PowerShell 5.1 读无 BOM 的 `.ps1` 会按 ANSI 解析，中文会变成解析错误
（本会话在 round-62/64 各踩过一次）。脚本里因此只放 ASCII；中文期望值在文档与代码里。

## 验证（**两条路径都端到端跑通**）

```
& .\TestScripts\external-acceptance.ps1 -Manifest temp/ext/manifest.json -Facts temp/ext/facts.json
```

| 场景 | 结果 |
|---|---|
| 骨架刚生成（11 项 `not-run`） | 退出码 **2**；逐条点名：`smoke check 'S-01' (G1) was not run` … + 生命周期四步缺证据 |
| 全部改为 `passed` + 生命周期四步有证据 | 退出码 **0**；打印 `观察构建 build-ext-76；交付构建 build-ext-76；结论 external-lifecycle-verified` 并写出验收记录 |
| 脚本自身 | 非 ASCII 字符数 = **0**；观察表 11 行齐全 |

这同时补上了上一轮登记的缺口（当时"允许路径"只在单测里，没有命令行演示）。

## 已知边界（诚实登记）

- **本轮的"通过"是替身事实**：两条路径用的是我手填的 `passed` + 文本证据，**不是真机观察**。
  它验证的是"判定链与入口可用"，**不是**"功能在真机上确实工作"。项目仍只有 `ready-for-external-deploy`。
- **清单镜像在脚本里**：脚本内的 `id/gate/area` 是 `BrowserSmokePlan` 的**镜像**（跨语言无法共享常量）。
  有测试保证代码与文档一致，但**脚本与代码之间的一致性没有自动门禁** —— 登记为风险（新增观察项时必须同步三处）。
- **证据只做非空校验**：脚本不校验真实性。
- **不自动执行真机步骤**：脚本只产出骨架与算结论，观察仍由外部一方人工完成。
- **调用方身份未校验**（B1 未决）。

## 影响与回滚

- 新增脚本，不影响既有内部一侧采集脚本（`TestScripts/delivery-manifest.ps1`）。
- 回滚：删除脚本与本文（CLI 与判定组件保持不变）。
