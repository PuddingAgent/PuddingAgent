# 2026-10-18 会话读模型阶段C2b投影事务化

## 改动

- `ConversationProjector` 事务化改造（Plan §4.1）：
  - 依赖 `IDbContextFactory<PlatformDbContext>`、`ChatTranscriptWriter` 共享事务写入、`ConversationReadModelProjectionStore`；
  - 同一 SQLite 事务提交：消息物化（`ChatMessages`）→ 读模型归约 → `conversation_turn_summaries`/`conversation_read_state` upsert → `conversation_projection_checkpoints` 推进；
  - token usage / catalog / 向量索引等外部副作用移到 commit 之后；单个副作用失败只告警，不回滚已提交投影、不影响 checkpoint；
  - 相同批次重放由 checkpoint 阻止，不会重复累计。
- `ChatTranscriptWriter` 新增 `PersistMessageInTransactionAsync`（只 Add 不 SaveChanges）与 `ScheduleIndexing`（提交后异步索引）；原独立 scope 路径保留给其他写入者。
- 纯组件补一条必要规则：`TurnCompleted` 若有终态 reply（有界 `TextDelta` 作为“助手正文存在”证据），置 `HasAssistantBody=true` 并在缺失时补 `AssistantMessageId`；reply 不进入活动预览，失败/取消终态仍不得伪造正文。事件映射器相应把 `turn.completed.reply` 映射为有界 `TextDelta`。
- `ConversationReadModelProjectionStore.LoadForBatchAsync` 额外加载 `readState.CurrentTurnId`，避免缺 TurnId 的事件把当前 Turn 重建为 partial 摘要。
- `PuddingApplicationInitializer` 之外新增 Host DI 注册 `ConversationReadModelProjectionStore`；`PuddingApplicationHostCompositionTests` 2/2 通过（ValidateOnBuild 覆盖新依赖）。
- 组件 S4 边界测试修复：源码扫描排除 `obj/bin/TestResults` 与 `*.g.cs`（默认输出目录构建不再误伤纯度断言；仍保留变异取红有效）。

## 验证

- 纯组件测试：**193/193 通过**（新增终态 reply/失败无正文两条；boundary 8 条仍绿）。
- 读模型/投影定向测试：`ConversationReadModel*` + `ConversationProjectorReadModel*` **50/50 通过**；新增端到端 6 条（同事务提交、重放幂等、checkpoint 写失败全回滚、子 run 隔离、失败无助手消息、旧库 partial 基线）。
- 全量 `PuddingPlatformTests`：1495/1497 通过；2 个失败为既有 `--artifacts-path` 环境敏感用例（benchmark seed 发现为空、Mcp.Cli 程序集解析），本次改动相关测试全绿。
- `PuddingHost` 构建 0 error；Host composition tests 2/2 通过。
- 未改 `D:\data`、未建真实索引、未重启 Core/Desktop；未部署运行时，投影路径在下次 Core 启动后才会使用新代码。
