# 浏览器管理操作接回工作区生命周期

## 原因与实施

第四轮默认助手真实验收（7d394b3）已通过会话准入，但新建页后导航返回 `page target '…' was not found in the bridge runtime`。根因不是页面真的未创建：表面映射直接调用 driver.NewPageAsync，绕过 BrowserWorkspaceController，页签、可见表面与准入注册表没有该页；紧随其后的 page.getInfo 因未登记被拒。

- Abstractions 增加 `IBrowserWorkspaceLifecycle`。Surface 的上下文/页签管理调用该端口，内容操作继续统一执行器路径；产品 `DesktopSurfaceComposition` 构造必须提供工作区所有者。独立驱动映射仍可直接构造表面。
- 工作区实现该端口，统一 UI/工具创建、激活与关闭，创建额外上下文同样注入驱动策略。页签保存真实 ContextId；关闭一个上下文只处理所属页；失败的页签/登记投影会关闭新资源。
- Shell 连接 context 创建/关闭事件，页签登记与回收使用所属上下文。没有改动权限决策或给未登记页面补造准入状态。
- 更新 ADR-097 D2、实施方案 §3.3、现有架构说明与相关代码地图。

## 验证与留白

独立 WebViewMappingTests **8 / 8**，包含全部管理操作确实经所有者端口及失败不回退。通过后接入工作区和 Shell。Desktop Browser **164 / 164**，新增跨上下文管理/误关拒绝与投影失败回收。Shell + Core 构建 **0 错误 / 39 个既有警告**。

产物使用 temp/build/recovery，TRX 位于 temp/test-out/browser-owner。尚待配套部署后第五轮真实助手测试；前四轮均没有本地表单提交，不能宣称用户任务已经完成。
