# P6 深链入口归一（D11 前端侧根治）

## 1. 缺陷与真因（全部实测，非推断）

管理端 SPA 的 umi `base`/`publicPath` = `/admin/`（`config/config.ts:22,92`）。
Core 有两条 SPA 回退（`Source/PuddingHost/Extensions/PuddingWebApplicationExtensions.cs`）：

| 回退 | 绑定 | 源文件 |
|---|---|---|
| Admin SPA fallback (`:248-270`) | `/admin/{*path:nonfile}` | `outputWwwRoot/admin/index.html` |
| **catch-all**（注释名「Chat SPA fallback」，`:273-283`） | **任意**未命中非 API 路径 | `outputWwwRoot/index.html` |

于是同一台宿主上、同一时刻存在**两份不同的 shell**（响应均为 `no-store`，排除 HTML 缓存干扰）：

| 路径 | shell | 字节 | SHA-256 |
|---|---|---|---|
| `/admin/`、`/admin/chat`、`/admin/no-such-xyz` | **新鲜** | 534 | `EEB04A1C…`（== `dist/index.html`） |
| `/index-status`、`/` 等**基座外**路径 | **陈旧遗留副本** | 523 | `EF1C303E…`（== `wwwroot/index.html` == `wwwroot/404.html`） |

第二行是 `wwwroot/index.html` 这份**旧构建遗留文件**（`dist/index.html` 已 534 B），它引用的
`/admin/scripts/root-redirect.js` **无版本参数**、且引用旧 chunk 名。

而该根脚本**只处理 `pathname === '/'` 精确匹配** ⇒ 基座外深链不重定向；umi 路由 base 是 `/admin/`，
基座外的 pathname 永不匹配任何路由 ⇒ 页面**永久**停在「正在加载资源」。

**交付层缺陷（本轮新发现）**：`/admin/scripts/root-redirect.js` 由静态中间件只回 `ETag` + `Last-Modified`
（**没有 `Cache-Control`**）⇒ 浏览器按启发式新鲜度（≈ `Last-Modified` 距今的 10%；该文件 `Last-Modified` 为
2026-07-12 ⇒ 可达数天）**直接复用缓存副本、连条件请求都不发**。实测：脚本改好、部署、哈希逐字节确认后，
同一浏览器 reload **仍停在加载壳**（旧脚本继续生效）。

## 2. 修复

1. **脚本泛化**（`public/scripts/root-redirect.js`，160 B → 1164 B，终态 SHA-256 `62F5ADBA…`）：
   凡不在 `/admin/` 基座内 ⇒ 带 `search` + `hash` 回到基座内；已在基座内（含无尾斜杠的 `/admin`）**早退防自噬**；
   前导斜杠归一（不产 `/admin//x`）；`/` 的既有行为保持不变（`/admin/`）。仍是 ES5 经典脚本（`<head>` 同步加载、不经打包器）。
2. **内容寻址失效缓存**（`config/config.ts`）：`headScripts` 里脚本 URL 拼 `?v=<脚本 SHA-256 前 8 位>`
   （`readRootRedirectVersion()`，取不到文件降级空串）。**内容一变 URL 就变** ⇒ 必然缓存未命中；
   且无需人工维护版本号（避免"改了内容忘改版本"的腐化）。
   构建产物实测：`<script src="/admin/scripts/root-redirect.js?v=62f5adba">`（`62f5adba` 即脚本哈希前 8 位，内容寻址自证）。
3. **环境侧替换陈腐 shell**（可回滚）：`wwwroot/index.html` 覆盖为当前 `dist/index.html`
   （523 B `EF1C303E…` → 534 B `EEB04A1C…`），原文件备份至 `temp/v7-wwwroot-root-backup-20261003T035234/`。
   回滚 = 把备份复制回去。

    页脚版本戳由 `d7f219a · 02:44` 变为 **`0f9b266 · 03:50`** ⇒ 基座外深链现在拿到的是**新构建**。
  - `/` ⇒ 同样落到 `/admin/user/login`（没有破坏既有入口）。

## 4. 仪器修复（本轮同时修好的探针/校验器）

- 部署校验器把 `?query` 当**字面路径**解析 ⇒ 对 `<script src="/admin/scripts/x.js?v=…">` 误判 `MISSING` 并 fail-closed 中止部署
  （行为正确、判据天真）⇒ 已改为 `($r -split '[?#]')[0]` 后再解析磁盘路径。
- chunk 探针名写死 ⇒ 每次构建都报 `NOT-IN-DIST` ⇒ 改为动态发现（`Get-ChildItem -Filter '*async*.js'`）。
- **PowerShell 陷阱两枚**：① `$ErrorActionPreference='Stop'` 下原生命令的 stderr + `2>&1` 会抛 `NativeCommandError`
  并**中断脚本**（曾导致变异脚本中途死掉、目标文件**残留变异态**未复原）⇒ 改用 `cmd.exe /c "<cmd> > out 2>&1"` 包住；
  ② 自定义函数名 `H` 与 `Get-History` 别名冲突 ⇒ 哈希行全部丢失 ⇒ 换名。
- PS 5.1 读 UTF-8 无 BOM 文件须 `[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8)`，写回用
  `[IO.File]::WriteAllText($p,$s,(New-Object System.Text.UTF8Encoding($false)))`（`Set-Content -Encoding UTF8` 会加 BOM）。

## 5. 遗留（未做，诚实标注）

1. **catch-all 的根因仍在 Core**：`wwwroot/index.html`（"Chat SPA fallback" 的目标）本就不该是陈腐副本；
   正解是 Core 侧——把非 `/admin`/`/api`/静态资产的未命中路径 **302 → `/admin/<path>`**，或让该回退也指向
   `admin/index.html`。属 Core 改动，**需部署**（当前唯一真阻塞）。
2. `wwwroot/404.html` 与替换前的 `wwwroot/index.html` 是**同一份陈腐字节**（`EF1C303E…`），本轮**未动**（未确认谁在消费它）。
3. 基座外深链在**冷缓存浏览器**上立即生效；对**已被旧脚本填充缓存**的浏览器，本轮已把 shell 换成带 `?v=` 的新 URL ⇒ 也应立即生效；
   但"用户侧真实浏览器"的冷/热两种状态**未同时实拍**（本机只有一个持久浏览器上下文，无法清缓存；本轮实拍是在 shell 换新 URL 后完成的，等价于冷 URL）。
4. 面板**已登录态**真实渲染与 `codeIndex` 显示仍未验证（需用户会话）。
