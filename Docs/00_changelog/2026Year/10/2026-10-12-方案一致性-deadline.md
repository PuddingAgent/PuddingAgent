# 方案一致性审计（续）：deadline

## 前半句 —— **满足** ✓

> "OperationId 是账本键，不必重复放进 hash；**deadline、correlationId 等非语义元数据不进 hash**"

`Fingerprint`（L149–159）只含 **`CallerKey` + `Name` + `ContextId` + `PageId` + `Arguments.GetRawText()`**；文档（L148）明写"**deadline 等非语义元数据不入**" ✓；`OperationId` 亦不在 hash（它是账本键）✓

## 后半句 —— "每次接收仍检查当前请求是否过期"：**Execute 路径已查，重放路径不查**

| 位置 | 行为 |
|---|---|
| L198–202（`DispatchCoreAsync` 内） | `DeadlineUtc <= UtcNow` ⇒ **`BrowserDeadlineExceeded`** ✓ |
| L217–220 | `CancelAfter(delay)` 对**执行中**期限硬约束 ✓ |
| L259–264 | 捕获并如实报 `deadline_exceeded` ✓ |
| **账本裁决（`DispatchAsync` L85）** | **早于**上述检查 ⇒ **`ReplayCompleted` 不重查 deadline** |

**两种解读（并列，不夸大）**：
1. **可辩护**：重放返回**已发生事实**、**不产生新副作用** ⇒ "防新副作用"的**要旨已满足** ✓；
2. **严格**：若按字面要求"**每次接收**（含重放）都拒绝过期"，应在账本裁决**之前**加过期检查 ⇒ **改动很小**（前移 L198–202），但**会改变"过期后的幂等重传"语义**（历史结果 ⇒ `deadline_exceeded`）⇒ **需复核者先确认**。

## 处置建议

**暂不改动**，与 round-787 的 L162 同法**主动上报**（附两种解读与用例设想：过期 + 同 operationId/同指纹重传 ⇒ 期望 `deadline_exceeded`）。

## 仍未完成（外部条件）

R6 整链聚合执行（构建锁仍持有）· 真机 G1–G11 / 250ms

- 静态审计；**非缺陷断言**，属**待复核者取舍的一致性细节**。
