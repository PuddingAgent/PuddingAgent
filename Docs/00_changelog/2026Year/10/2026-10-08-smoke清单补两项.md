# 2026-10-08 横向：smoke 清单补两项

## 背景

我此前反复登记两件事"没进外部观察清单"：**文件选择器的接管边界**（round-88 核实过 SDK 无 API）
与**页面事件的接管/上报**（round-38/39 实现，但没有对应的外部观察项）。本轮补齐。

## 改动

| 项 | 门禁 | 怎么触发 | 看到什么才算过 |
|---|---|---|---|
| **S-12** 文件选择器 | **G7**（输入路径） | ① 工具上传真实文件；② 页面脚本自行触发选择框 | ① 走真实 `DOM.setFileInputFiles` 完成；② **记录为"不支持"**（SDK 无选择器 API ⇒ 不接管、也不假装接管） |
| **S-13** 页面事件接管与上报 | **G3**（回执） | 依次触发 脚本对话框 / 权限请求 / 新窗口 / 下载 | 流程**不卡住**（应答/拒绝/抑制/取消）；快照 `pageEvents` **如实列出**（有界、`(xN)` 合并）且**不用于继续交互** |

**为什么归到既有门禁而不是新增 G12/G13**：设计文档的门禁集是 G1–G11；这两项都落在既有语义里
（选择器属输入路径 → G7；事件事实属回执 → G3）。`BrowserSmokePlan` 的"必须覆盖全部门禁"规则因此不变。

同步更新：

- `TestScripts/external-acceptance.ps1`（脚本镜像，仍纯 ASCII）；
- `Docs/14_reports/2026-10-09-浏览器自动化外部smoke清单.md`（11 条 → **13 条**）；
- `Docs/13_runbooks/浏览器自动化外部smoke-runbook.md`（补 S-12/S-13 的执行步骤与"这一项是如实报告边界、不是必须成功"的说明）。

## 验证

| 项 | 结果 |
|---|---|
| **漂移门禁先红后绿** | 加完 S-12/S-13 后，`TheExternalScriptMirrorsThePlan` 与 `TheCommittedChecklistDoesNotDriftFromThePlan` **立刻变红**（脚本镜像与文档清单未同步）⇒ 更新后 **312/312 全绿** |
| `Pudding.DesktopServiceTests` | **312 / 312** |
| 脚本编码 | `external-acceptance.ps1` 非 ASCII 字符 = **0** |
| 门禁总数 | front matter 2（他方）、链接 32（他方）、BOM 0 ⇒ 全在基线内 |

## 已知边界（诚实登记）

- **清单仍不含真机结果**：新增的是"要观察什么"，不是"已通过"。
- **S-12 第 ② 步的期望是"记录为不支持"**：它验证的是**边界如实**，而不是功能成功——这一点在手册里写明了，
  免得外部一方把它当成失败。
- **S-13 依赖页面能触发这些事件**：需要一个会弹对话框/请求权限/开新窗口/触发下载的测试页
  （现有 TestSite fixture **没有**这样的页面；这项工作**未完成**，登记为后续）。
- **`pageEvents` 的上限与合并规则**由 `PageEventLog` 决定（容量 8、连续重复合并）；清单只要求"如实列出"。
- 无产品行为变化（清单与文档）。
