## 3. 验收发现的两处交付缺口（未在部署中改源码，待修）

**① `/chat/panel-demo` 路由缺失（功能不可达）**
- `git show --stat 7c3b95d`：该提交**只新增** `Source/PuddingPlatformAdmin/src/pages/chat/panel-demo.tsx`；`git log --since='2026-10-19 18:00' -- config/routes.ts` 为空，**没有任何提交**修改路由。
- 全仓 `src`/`config` 搜索：除 `panel-demo.tsx` 自身外，**无任何 import**。
- 后果：文件是死代码，未进入 umi 构建（所有 chunk 的 `.map` 中不存在 `panel-demo`），`/chat/panel-demo` 打开会得到 404 页，A4/A5 demo 项无法完成。
- 建议修法（约 2 分钟）：`config/routes.ts` 在 `/chat` 后加 `{ path: '/chat/panel-demo', component: './chat/panel-demo', layout: false, hideInMenu: true }` → 重建前端 → 回填 `RUN\core\wwwroot\admin`（纯静态，无需重启 Core）→ 补版本号（见下）。

**② 前端版本号未按规则递增（交付标识别问题）**
- `Source/PuddingPlatformAdmin/package.json` 版本自 `b9b1460` 起一直是 **6.9.10**，但本批前端改动 **69 文件 / +8630 行**且新增依赖（dompurify/mermaid/rehype-sanitize）。
- 这违反「前端版本管理（强制）」：每次前端修改必须递增版本号并与改动同 commit；当前页角徽标只能靠 hash/builtAt 区分新旧构建。
- 建议：按「新增功能」递增**次版本号** `6.9.10 → 6.10.0`，与路由修复同一个 commit，再重建并回填。
