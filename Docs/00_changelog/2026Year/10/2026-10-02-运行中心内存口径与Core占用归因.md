# 2026-10-02 运行中心内存改用专用工作集口径，并归因 Core 733 MB 占用

## 改了什么

**问题一：测量口径**（面板数值与任务管理器不是同一口径）

- 新增 `Source/PuddingDesktop.WpfArchive/Runtime/ProcessMemoryReader.cs`：`NtQuerySystemInformation(SystemProcessInformation)` → `WorkingSetPrivateSize`，即任务管理器「内存」列与 PDH `\Process(*)\Working Set - Private` 的同源值；非 x64 或读不到返回 `null`。
- 新增 `Source/PuddingDesktop.WpfArchive/Runtime/CoreMemoryDisplay.cs`：卡片口径纯映射——优先显示专用工作集，副标题披露同一时刻的总工作集；读不到时降级为工作集并写明「含共享页」。
- `Source/PuddingDesktop.WpfArchive/Runtime/CoreProcessMetricsSampler.cs`：`CoreProcessMetrics` 增加 `PrivateWorkingSetBytes`。
- `Source/PuddingDesktop/MainWindow.xaml` / `MainWindow.xaml.cs`：卡片标题改「内存 · 专用工作集」，新增 `RuntimeMemoryDetailText` 副标题，`UpdateMetrics` 改用 `CoreMemoryDisplay.Format`。
- `Tests/PuddingDesktop.Tests/Runtime/CoreProcessMetricsSamplerTests.cs`：新增 3 个用例（专用工作集可读且 ≤ 总工作集；卡片显示专用工作集并披露工作集；不可读时降级且未运行显示「—」）。
- `Source/PuddingDesktop/code_map.md`：登记新增文件与口径不变量。

**问题二：占用归因**（报告含全部数字与命令）

- 复现：用户实际在跑的 Debug 产物 + `D:\data` 完整副本（13.8 GB，凭据移出、自动派单关闭），A/B 对照见报告 §2。核心数字：空数据根冷启动专用工作集 **113 MiB**；真实数据 + 代码索引 scope 开启时峰值私有提交 **734 MiB**、索引进行中专用工作集 438–493 MiB；**关闭代码索引后峰值 271 MiB、专用工作集 192–201 MiB**。
- 触发源（Core 自身日志）：`[CodeIndexScheduler] Starting index ... at <整仓>` → 数十次 `MSBuildWorkspace` `Opening project`（多数 `Failed to open project`）→ `dist-dev/vendors_1-async.js` 的 TypeScript 抽取 JSON 解析失败。
- 与初始假设相反：`DOTNET_gcServer=0` 同条件对照只把专用工作集降约 50–100 MiB、峰值反升（734 → 767 MiB）⇒ 主因是索引负载而非 GC 余量。
- 18 分钟 idle 观测：CPU 全程约 1 核满载、索引未结束，专用工作集仅由 465 MiB 缓慢回落到 278 MiB ⇒ 整仓索引的结束条件与代价另立待查项。

## 验证状态

- **通过**：新增/改动的三个运行时源文件在独立宿主中原样编译并跑 11 项断言（含 `733 MiB` 主值、副标题披露 `工作集 1007 MiB`、降级文案、`—`、专用工作集 ≤ 总工作集）全部 PASS。
- **通过**：新 interop 与 PDH「Working Set - Private」同一进程同一时刻逐次对照一致（441.0/441.0、438.3/438.3、438.3/438.4、438.4/438.4 MiB）。
- **未验证**：本会话受限令牌（Low Mandatory Level）无法写 WPF 中间文件，`dotnet build` 在 `Microsoft.WinFX.targets` 处被拒（`Access to the path ..._wpftmp.csproj is denied`），Desktop/WinUI 工程级编译与 xunit **未运行**；需在可写环境跑 `dotnet test Tests\PuddingDesktop.Tests` 与 Desktop 构建后补记。
- **未验证**：未取得托管堆类型直方图（ClrMD 附加被 Windows 完整性级别拒绝，`Win32Exception 5`）；归因来自 A/B 对照 + Core 日志 + 只读 SQL 计数。
