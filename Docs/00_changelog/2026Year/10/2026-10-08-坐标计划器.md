# 2026-10-08 坐标输入 P1：纯计划器

## 为什么从这里下手（rounds 315→318 的收敛结论）

| 轮 | 结论 |
|---|---|
| 315 | 运行时**没有**坐标 API（`ClickAtAsync` 等 0 命中）⇒ 不是"补一张映射表" |
| 316 | CDP 原生输入机制**已存在**（`SendCdpAsync` + `Input.dispatchMouseEvent(mouseWheel)`） |
| 317 | 原生输入是 **`Policy.Plan…(坐标) → 逐条 SendCdpAsync`** 两段式，**策略是纯函数** |
| 318 | 纯计划器 = **`NativeInputSequence`**，且**已有测试夹具**（`NativeInputSequenceFormatTests`）⇒ 可进程内取红 |

## 改动

| 方法（`NativeInputSequence.cs`） | 语义 |
|---|---|
| `PlanPointerClick(x, y, clickCount)` | mousePressed(buttons=1) → mouseReleased(buttons=0)，**坐标一致** |
| `PlanPointerMove(x, y)` | 单条 mouseMoved(buttons=0) —— 只移动不按下 |
| `PlanPointerDrag(fromX, fromY, toX, toY, steps)` | pressed → steps 次**保持按下**的 moved → released（终点坐标） |

## 验证（`Source/PuddingBrowser.AutomationTests`，**399/399**）

| 用例 | 判据 |
|---|---|
| 点击成对 | 恰好 2 条、同坐标、buttons 1→0 |
| **(0,0) 合法** | x=0/y=0 **如实携带**，不得被当成"未设置" |
| 移动不按下 | 1 条 mouseMoved、buttons=0 |
| 拖拽成对 | pressed + 4 moved + released；中间全部 buttons=1；末条在终点 |
| 步数守卫 | steps=0 ⇒ **明确拒绝** |
