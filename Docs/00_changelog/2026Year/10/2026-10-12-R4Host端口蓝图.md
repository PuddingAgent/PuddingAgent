# R4 ⑥ 蓝图：照抄 `CapabilityChannelBindingGate` 范式

| 既有范式（`CapabilityChannelBindingGate.cs`） | 行 |
|---|---|
| DI 形态：`Func<DesktopSession?>` + `DesktopCapabilityDescriptor` + `BrowserPageGrantScope` + `TimeSpan validity` + `string source` + `TimeProvider` | L14–20 |
| **会话按调用解析**；解析不到 ⇒ 放行（注释：最终判据在 Desktop 唯一 authority） | L41–45 |
| 构造 `DesktopBrowserBindingProducer`（发送委托 = `session.SendAsync(...)`） | L54–58 |
| `producer.IssueAsync(new BrowserTaskBinding(caller, target, scope, validity, source), new OperationId(Guid), null, ct)` | L60–66 |
| **未签发即拒**（`BrowserOperationException(BrowserUnauthorized, outcome.Reason)`） | L68–73 |

## 端口实现（机械照抄 + 三处适配）

1. **`RequestChildGrantAsync`**：无会话 ⇒ **拒绝并带理由**（**fail-closed**，与"未启用即放行"的门语义不同）· `ScopeName` 未知 ⇒ **拒绝** · 标量 → `BrowserCallerIdentity`（`TaskId=ChildRunId`、`ParentTaskId=ParentTaskId`）· `Issued` ⇒ 返回 `(grantId, scope, expiresAt)`；否则返回**带理由的拒绝**（**不抛**，契约已由 round-739 三条用例钉住）
2. **`RevokeForRunAsync`**：需撤销通道 —— `DesktopBrowserBindingProducer` 是否有 `RevokeAsync`，或走 `session.SendAsync(BrowserBindingRevoke, …)`（`AllowedCapabilities` 已含 `BrowserBindingRevoke`）⇒ **唯一还需 1 次侦察的点**
3. **组合根注册**：与既有门同形；**只在启用委派时注册**，否则保持 `null`（行为与今天一致）
4. **验收**：`PuddingHost.Tests`（不需 WinUI）—— 无会话 / 未知 scope / 未签发 ⇒ **拒绝并带理由**；成功 ⇒ id + 到期；撤销走通

## 诚实边界

- 本轮**只读侦察**；⑥ 是**唯一能产生实际委派行为**的一步；**未真机验证**。
