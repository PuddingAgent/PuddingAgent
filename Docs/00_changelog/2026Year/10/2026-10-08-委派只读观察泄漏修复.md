# 2026-10-08 B6：只读观察不随委派结束回收的泄漏

## 缺陷（沿同一承诺对账发现）

上一轮修的是"一委派多页"的**写**租约泄漏。本轮继续核对同一条承诺
（"委派结束/取消/超时都回收许可"），发现**只读**一侧同样漏了：

| 环节 | 旧行为 | 后果 |
|---|---|---|
| 申请只读 | `TryAcquireRead(pageId, holderId)` **不登记**页到委派 | 只读页永远不在 `EndDelegation` 的遍历范围内 |
| 结束委派 | 只按 `child:{delegationId}` **前缀**扫观察者 id | 调用方用别的 id（如 `reader-1`）⇒ 扫不到 |
| 结果 | 子代理"只看不写"的观察**永久留在账本**（`ReaderCountOf` 永不为 0） | 违反"委派结束即不再授权" |

## 修法

| 项 | 改动 |
|---|---|
| API | `TryAcquireRead(pageId, holderId, string? delegationId = null)`：**新增可选参数**（源兼容；不传时行为与之前完全一致） |
| 登记 | 传了 `delegationId` ⇒ 页进 `_pagesOfDelegation`，**确切 id** 进新的 `_readersOfDelegation` |
| `EndDelegation` | ① 按 `_readersOfDelegation` 里的 id **精确移除**；② 保留 `child:{delegationId}` 前缀扫描作**兼容兜底**（约定外调用方仍能被回收） |
| 兼容 | 不传 `delegationId` 的只读观察**不受任何委派回收影响**（父代理/其它委派不会被误伤） |

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **324 / 324**（＋3；冻结用例计数 12 → 15） |
| 新增用例 | ① 只读委派结束 ⇒ 两页观察计数归 0（取红主用例）；② 同页父代理与**另一个委派**的观察都留下；③ 用不存在的委派 id 结束 ⇒ 不产生"幽灵回收" |
| **取红实测** | 禁用"精确移除"（只留前缀扫描）⇒ **2 条用例变红**；还原 ⇒ 324/324 全绿 |

## 已知边界（诚实登记）

- **公开 API 有增量**：`TryAcquireRead` 增加可选参数（源兼容、缺省行为不变）；调用方若想被委派回收，
  **必须显式传 `delegationId`** —— 文档注释已写明，但这仍是"记得传"的约定，未由编译器强制。
- **未见 Runtime 调用方**：B6 接线尚未落地，因此现在**没有任何生产代码**调用带 `delegationId` 的重载
  （登记为未接线；本轮验证的是账本层）。
- **账本仍不做线程同步**（设计如此）；并发语义未验证。
- **未真机验证**。
