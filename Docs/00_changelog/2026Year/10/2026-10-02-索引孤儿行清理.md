# 2026-10-02 索引孤儿行清理

## 背景（复核 MINOR-4 的处置）

独立复核指出：新链路的扫描器按工作区 `.gitignore` 过滤，而旧语言索引器只用名单级噪声过滤 ⇒
**旧链路时代被索引、但被 `.gitignore` 忽略的文件没有 manifest 记录**，新链路既不枚举它、也就永远
不会清理它（孤儿行）。此前把「启用前先跑一次旧校准或重置索引」写成了操作步骤 —— 本笔把它变成代码。

## 改动

- `Source/PuddingCodeIndex/Services/CodeIndex/CodeSourceMaintenanceCoordinator.cs`：
  新增 `SweepOrphansAsync` —— 在**完整且根可用**的**非提示**轮次里，清掉
  「索引里有、manifest 里没有、本轮变更集里也没有」的文件行（连同其符号/引用/关系）。
  - manifest 是权威：「没有记录」不等于「还记得它」，所以这类行就是孤儿。
  - 提示驱动的轮次**绝不做**（不完整观测无法证明「它不在磁盘上」）；
    扫描不完整或根不可用同样不做。
  - **无变更集的轮次也要做**：孤儿路径恰恰不会产生任何变更集条目，因此清理被提到
    「本轮没有待办」这条早退路径之前执行（新增 `OrphanFileCount` 供诊断/验收计数）。
- `CodeSourceMaintenanceMode` 文档更新：启用前**不再需要**先跑旧校准或重置索引。
- 结果新增 `OrphanFileCount`；日志行带上孤儿行数。

## 验证

- `dotnet test Source\PuddingCodeIndexTests` → **330 通过 0 失败**（本次 +2）。
- `dotnet test Source\PuddingCodeIntelligenceTests` → **132 通过 0 失败**；
  `Tests\PuddingHost.Tests --filter CodeIndexMaintenanceHostCompositionTests` → **4 通过 0 失败**。
- 新增用例：完整扫描清掉孤儿行（`OrphanFileCount == 1`，行与其符号都消失）；
  **提示驱动的轮次绝不清理**（`OrphanFileCount == 0`，行保留）。

## 未完成与影响

- 默认仍是 `Legacy` ⇒ 运行中实例行为未变。孤儿清理只在 `Coordinator` 模式下执行。
- 启用清单（更新后）：① 宿主登记 `CodeIndexMaintenanceOptions(Coordinator)`；
  ② 进程外控制器重启到明确的新构建；③ 四场景受控复核。
  （原「先跑一次旧校准/重置索引」这一步已被本笔取代。）
