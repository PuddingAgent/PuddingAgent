# 2026-10-08 B1 推进（按文档授权）

## 为什么不再等决定①

决定①（"是否接受进程内身份 + 显式拒绝跨进程推断"）我已问了七十多轮。重读文档发现**它已经给了答案**：

> §3.2：「授予记录绑定 Desktop 实例/连接世代、context/page、**可信 Agent/任务身份**、read/write/manage 范围与可撤销 epoch」
> §3.1：「**代理身份来自 Core 的可信执行上下文**，不让模型填写 epoch 或 owner 来获得权限。」

⇒ 身份来源是**文档规定**的（Core 执行上下文），不是三选一。缺的只是把这条规定**落成代码**。

## 交付

新增 `Source/Pudding.Contracts/Desktop/BrowserCallerIdentityProjection.cs`：

| 规则 | 依据 |
|---|---|
| 入参**只能是**执行上下文标量（`isSubAgent` / `callerId` / `runId` / `parentRunId`） | §3.1：模型不得自报身份（签名里根本没有模型可控的入参） |
| 缺运行身份 ⇒ 拒绝（授权无法绑定到任务） | §3.2（可撤销/可回收需要任务边界） |
| 缺调用者 ⇒ 拒绝（无法区分是谁在操作） | §3.2 |
| **子代理缺父任务 ⇒ 拒绝**（无法校验"只取父授权的子集"） | §3.2 |
| 身份值**去空白**后再比较 | 防" `agent-1 ` 与 `agent-1` 被当成两个行动者"（同行动者判据会被绕过） |

## 诚实边界（诚实登记）

- **这只是"身份投影"这一环**：把投影出的身份**喂给 `Admit`/写租约**（活路径接线）仍未做 —— 那一步会触及 Host/Desktop 请求契约，
  属于 §10 的 S5 接入，**需要该处所有者同意**；本轮**没有**动契约与接线。
- **执行上下文的字段选择是我做的**（`isSubAgent`/`callerId`/`runId`/`parentRunId`）：`RuntimeExecutionIdentity` 里还有
  `ToolCallId`/`InvocationId`/`BatchId` 等字段，**未**纳入身份（登记：若审计需要更细粒度，可扩展但需说明取舍）。
- **`isSubAgent` 由调用方传入**：如何从 `RuntimeExecutionKind` 判定子代理**尚未实现**（属接线步骤）。
- **未真机验证**；② 250ms 门限、③ flake 修复、④ code_map 指纹仍未拍板。
