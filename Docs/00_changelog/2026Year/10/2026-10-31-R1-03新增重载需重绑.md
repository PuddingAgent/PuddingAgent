# 2026-10-31 R1-03 新增重载必须让既有重载的依赖方重绑

## 缺陷

`CodeFileSemanticDiff.ChangedSymbolIds` 原本把「新符号」一律当作无影响：

```csharp
// 新符号：没有旧依赖方需要失效（新增不会打断已有绑定）。
continue;
```

这个假设对新增无关符号成立，但对**新增重载**不成立：

```csharp
void Pick(object v)         // 既有
void Pick(string v)         // 新增
...
Pick("x");                  // 原本绑定 Pick(object)，现在改绑 Pick(string)
```

调用点确实需要重新绑定，而它们挂在**旧重载**的反向依赖上 —— 旧重载没被列为变化，于是这些调用点不会重绑，图里留下错误的目标。

## 改动

- `Source/PuddingCodeIndex/Services/CodeFileSemanticDiff.cs`：
  - 新增 `IsOverloadable(kind)`（`Method` / `Constructor` / `Operator`）。
  - 遇到新符号时，若它可重载，则把 `previous` 中**同容器、同名、同种类**的既有符号加入变化集 —— 这些才是需要重绑的依赖方锚点。
  - 没有同名旧重载时不产生任何变化（否则退化成「一改就全量重绑」）。
  - 顺带修掉一个会让本修复失效的实现细节：原实现**边循环边 `previousById.Remove`**，等遍历到新增重载时旧重载已被移除，`Add` 永远找不到目标。改为用 `currentIds` 判断哪些是「消失」，循环不再改动字典。
- `Source/PuddingCodeIndexTests/Services/CodeFileSemanticDiffTests.cs`：
  - 新增 `NewOverload_RequiresExistingOverloadsDependentsToRebind`、`BrandNewMethodWithoutPriorOverload_DoesNotForceRebind`。
  - **修正既有测试夹具**：`BrandNewSymbolsDoNotInvalidateAnybody` 原来用默认参数造「新符号」（name 默认 `M`、container 默认 `C`），那恰好与 `sym-a` 构成同名重载 —— 它其实在断言「新增重载不需要重绑」。改为显式不同名（`name: "Fresh"`），保留其真实意图「无关新增不触发重绑」。

## 证据（实测）

- **修复前**：`NewOverload_…` **红**，正对照 `BrandNewMethodWithoutPriorOverload_…` 绿。
- **中途修正**：只加「新增重载分支」还不够 —— 第一次跑仍红，因为 `Remove` 提前把旧重载删掉了；改成 `currentIds` 判据后才成立。
- **变异取红**：给重载分支加一个恒假条件 ⇒ **恰好 1 红**（`NewOverload_…`）。
- **还原**：按备份字节写回，SHA-256 位级一致 ⇒ 10/10 复绿。
- **全量回归**：`PuddingCodeIndexTests` **472/472 通过**。
