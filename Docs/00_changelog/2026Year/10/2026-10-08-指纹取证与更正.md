# 2026-10-08 根 code_map 指纹：取证 + 更正

## 更正（上一轮的因果说错了）

上一轮我写："新增文件导致根 `code_map.md` 的 `TestScripts/**` 指纹过期"。准确说法是：

**根表头的四个 glob 本来就是过期状态，而且用现有工具无法修复** —— 我的新增文件只是让其中一个 glob 再多一个文件。

## 取证（可复跑）

```
python Tools/Docs/code_map_check.py --fp-probe
fp_probe: code_map.md glob=Source/**     declared=869bcd5ee8b0 files=4589 matches=NONE
fp_probe: code_map.md glob=Tests/**      declared=b0411cf64a03 files=153  matches=NONE
fp_probe: code_map.md glob=Tools/**      declared=f27330dfc0b7 files=21   matches=NONE
fp_probe: code_map.md glob=TestScripts/** declared=46b63da8b4e5 files=79  matches=NONE
fp_probe: Source/PuddingCodeIndex/code_map.md glob=Contracts/** … matches=path:shafull_nl
fp_probe: Source/PuddingCodeIndex/code_map.md glob=Services/**  … matches=path:shafull_nl
```

| 观察 | 含义 |
|---|---|
| 根表 **4/4** glob `matches=NONE` | 工具**一个都复算不出来** ⇒ 根表头用的是**工具已不支持的旧算法** |
| 子项目指纹 `matches=path:shafull_nl` | 支持的那套算法（`path:shafull_nl`）在子项目里**全部匹配** |
| `fingerprint_check: globs=9 verified=4 mismatched=5` | 5 处过期 = 根表 4 + 另一处（`PuddingRuntime`） |
| 严重级别 | `stale-fingerprint` 是 **warn**，且该工具门禁在**基线**上已是 `gate: FAIL`（line-too-long 111 等，与本文无关） |

## 我做了什么 / 没做什么

- **没做**：不手改哈希（算法不确定 ⇒ 改了就是**伪造**一个看起来对的指纹）。
- **做了**：把取证写进日志并升级：需要**该表维护者**用其原始工具重算，或把根表头**换成工具支持的 `path:shafull_nl` 方案**（换方案会让日后自动可校验 —— 这是根本解法）。
- 我新增的 `TestScripts/known-flaky.txt` 属该 glob 的第 79 个文件，**继续保留**（它是本轮功能的必要组成）。

## 诚实边界（诚实登记）

- **未修**：根表头仍是过期值（4 处），本轮只提供证据与更正；**修它需要表维护者的决定**（换算法或重算）。
- **`missing-fingerprint warn 41`** 同样未处理（41 个 code_map 缺指纹，多为他方文件）。
- **该工具门禁基线 FAIL**：本轮我**没有**把它接进交付链门禁（那会让交付链长红；是否接入应由仓库决定）。
- **未真机验证**（与本文无关，但仍是整体状态）。
