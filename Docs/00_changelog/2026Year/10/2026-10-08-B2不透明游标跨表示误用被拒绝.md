# 2026-10-08 B2 不透明游标：跨表示误用被明确拒绝（消灭静默跳段）

## 目标 / 背景

上一轮（[B2 分页成本函数](2026-10-08-B2分页成本函数按各自字节分页.md)）确定：markdown 与 compact_json
的块成本不同 ⇒ **页边界不同**。当时登记的边界是：「游标仍是裸整数，把一种表示的游标用到另一种表示上会
**跳过**若干块（不会重复），当前没有机制识别游标来源」。

**静默跳段是最难发现的一类数据丢失**：不报错、不重复，调用方只会以为"读完了"。本轮把它堵死。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| Automation | `ArticleCursor.cs`（新增） | 不透明游标 `{kind}:{index}`：`md:{n}`（markdown）、`json:{n}`（compact_json）、`lines:{n}`（outline/interactive）。`Encode`/`TryParse`（**严格**：未知 kind、非数字、负数、多余字段、空白变体一律拒绝，绝不回退成 0）、`KindOfFormat`/`FormatOfKind`（表示 ↔ format 双向映射） |
| 工具 | `BrowserSnapshotTool.cs` | `cursor` 参数由 `int?` 改为 **`string?`**；统一在调用前解析并校验：畸形 ⇒ `browser_invalid_arguments`；**kind 与本次请求的表示不符 ⇒ 明确拒绝**，且消息带上"该用哪个 format"；三条路径（markdown/compact_json/outline+interactive）都在输出时把内部索引编码成对应 kind 的游标 |
| 工具契约 | `BrowserSnapshotToolValue.NextCursor` | `int?` → **`string?`**（不透明串） |

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **240 / 240**（原 235 ＋ 5） |
| `PuddingBrowser.AgentTools.Tests` | **61 / 61**（原 60 ＋ 1） |
| `PuddingDesktop.Tests` · `DesktopSurface.BrowserTests` · `ContractsTests` · `DesktopServiceTests` · `Host` | 320/320 · 64/64 · 152/152 · 229/229 · 258/258 |

新增门禁：

- 编码/解析往返；**12 类畸形游标**（含 `"3"`、`"md"`、`"md:"`、`":3"`、`"md:-1"`、`"md:1.5"`、`"md:1:2"`、
  `"yaml:3"`、`"MD:3"`、`"md: 3"`…）全部拒绝；
- 表示 ↔ format 双向映射，两种表示在**同一索引**上得到**不同**游标；
- 工具层：markdown 游标格式为 `md:*`；拿它去读 `format=compact_json` ⇒ `browser_invalid_arguments`
  且消息含 `format=markdown`；畸形游标（`"3"`）同样拒绝；
- outline/interactive 的游标变成 `lines:*`（既有用例已更新为断言 `lines:1`）。

**取红实测**：把"kind 不符即拒绝"短路（＝允许跨表示误用）⇒
`Snapshot_CursorFromAnotherRepresentation_IsRefusedInsteadOfSkippingBlocks` **恰好变红**；复原后各套件全绿。

## 已知边界（诚实登记）

- **破坏性线格式变更**：`browser_snapshot` 的 `cursor` 入参与输出字段 `nextCursor` 由**数字变成字符串**。
  传入数字（如 `cursor: 3`）会在参数绑定阶段就失败（框架不做 number→string 强转）——这是**有意的**：
  旧数字游标在新语义下无法判断表示来源，只能拒绝。既有调用方需改为回传 `nextCursor` 原值。
- **`lines` 游标只标识"行分页"**，不区分 outline 与 interactive：两者共用同一套行分页实现，页边界同构，
  因此不存在跳段风险；若将来两者分页参数分化，需要把模式也编进游标。
- **游标里没有页面/版本指纹**：跨页面回传同一游标不会报错（只是按索引从另一页的文本里续读）。
  要不要把页面标识也编进游标（并在不符时拒绝）是下一步的取舍；当前依赖调用方"同一页面续读"。
- **`ArticleCursor` 是唯一解析点**，但工具层仍有"根据 mode/format 推断期望 kind"的一小段逻辑：
  两处必须同步（已用 `KindOfFormat` 收敛映射，但推断仍在工具里）。
- 纯组装层与工具层，与 WebView2 无关。
