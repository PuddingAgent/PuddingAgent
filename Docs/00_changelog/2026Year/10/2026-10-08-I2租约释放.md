# 2026-10-08 修复：写操作租约泄漏

## 缺陷

`ValidateAdmission` 调 `Authority.Admit(...)` 后只用 `IsAllowed`/`Error`/`Denial`，**把 `decision.Lease` 丢了**。
后果：一次变更类操作结束后租约仍挂在权威里 ⇒ **后续写操作（含用户自己的）被挡**；用户接管语义也随之失真。
这是"闸门落地"（round-191）时留下的问题，**开闸门之前必须修**。

## 修法（4 处 + 1 处）

| # | 位置 | 改动 |
|---|---|---|
| ① | `ValidateAdmission` 签名 | ＋`out BrowserAutomationLease? lease`（顶部 `lease = null;`） |
| ② | `if (!decision.IsAllowed)` 之前 | `lease = decision.Lease;` |
| ③ | `RunOnUiAsync` | `ValidateAdmission(..., out _, out var lease)` |
| ④ | 另一调用点 | `context, out _, out _)` |
| ⑤ | `RunOnUiAsync` **全部 catch 之后** | `finally { if (lease is not null) Authority.ReleaseLease(lease.LeaseId, "operation completed"); }` |

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests`（**TRX 判定**） | **360 / 360** ✅（含既有的准入/控制面用例，说明修复没有破坏准入行为） |
| 全量链 | **未跑** |

## 诚实边界

- **尚无"租约确实被释放"的定向用例**：本轮证据是"编译 + 既有 360 条全绿"；下轮补一条（写操作执行后 `Authority.ActiveLease` 为空 / 第二次写仍可执行）。
- **触 UI 前的 `Revalidate` 仍未做**（方案 §4.2 的另一半）：排队期间可能被撤权/接管/关页，届时应在 `RunOnUiAsync` 里、真正执行动作前复检一次。
- **`finally` 的位置是踩坑点**：`finally` 必须在**全部 catch 之后**（我第一版插在 try 的 `}` 之后 —— 那是 catch 之前，语法错误）；另 `linked.Token).ConfigureAwait(false);` 在文件里**不止一处**，不能当定位锚（必须连带唯一 lambda 行，或用 `edit` 工具）。
- **未真机验证**。
