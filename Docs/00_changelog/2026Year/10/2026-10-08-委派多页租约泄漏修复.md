# 2026-10-08 B6：修掉委派租约账本里的"一委派多页"租约泄漏

## 怎么发现的

为了让外部 smoke **S-10** 的承诺"**取消/接管/超时都回收许可**"真的站得住，我逐条核对
`BrowserDelegationLeaseLedger` 的每个转换，发现 `_parentOfDelegation` 是 **`Dictionary<string, string>`（单值）**：

```csharp
_writes[pageId] = new LeaseHolder(holderId, role, delegationId);
if (role == BrowserLeaseRole.Child && delegationId is not null)
{
    _parentOfDelegation[delegationId] = pageId;   // ← 第二个页覆盖第一个
}
```

⇒ 子代理在**第二个标签页**继续写时（同一委派两页持租约），`EndDelegation` 只归还**最后一页**，
**第一页的子代理写租约永久泄漏**，父代理从此再也拿不回该页写权（正是 G10 要防的事，只是换了个方向）。

## 修法

| 项 | 改动 |
|---|---|
| 字段 | `Dictionary<string,string> _parentOfDelegation` → `Dictionary<string, HashSet<string>> _pagesOfDelegation`（委派 → 页集合） |
| 授予 | 追加进集合（不是覆盖） |
| `EndDelegation` | 遍历**该委派的每一页**：按持有者+角色+委派匹配归还写租约，并清掉该委派的子代理只读观察 |
| `RevokePage` | 只把**这一页**从各委派的集合里摘掉（撤权是按页的），集合空则删条目 |

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **321 / 321**（＋3；冻结用例计数同步 9 → 12） |
| 新增用例 | ① 一委派两页 ⇒ EndDelegation 后**两页都空**，父代理两页都能重新写；② EndDelegation 不牵连**另一个委派**的页；③ 撤权 page-a 后 page-b 仍持有，且 EndDelegation 仍归还 page-b |
| **取红实测** | 把归还循环改成只处理第一页（复现旧缺陷）⇒ `ADelegationHoldingTwoPagesReturnsBothOnEnd` **精确变红**；还原后 321/321 全绿 |

## 已知边界（诚实登记）

- **账本仍不做线程同步**（设计如此：策略账本只回答"允不允许"，同步属宿主）；并发调用下的语义未验证。
- **父代理暂停写入**仍由调用方（B6 接线）负责触发，本轮只修账本的归还语义。
- **未接活路径**：`EndDelegation` / `RevokePage` 何时被调用仍取决于 B6 接线（被决定①/②挡住），
  本轮验证的是**账本层**行为，不是端到端委派。
- **未真机验证**；S-10 的期望文字未改（它本来就要求"都回收许可"，本轮让账本真的做到）。
