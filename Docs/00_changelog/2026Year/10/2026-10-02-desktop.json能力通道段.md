# 2026-10-02 desktop.json 能力通道段（镜像 Core 段名）

## 目标 / 背景

接线前必须定下 `desktop.json` 里能力通道段的形态。约束：`DesktopCapabilityChannelSettings.SectionName`
常量已写着 `Desktop:CapabilityChannel`（与 Core 的 `system.json` 同名段对称），
但 `desktop.json` 现有段（`Window`/`ToolWorkspace`/`Debug`）都在根上、没有 `Desktop` 这一层。

采纳方案 A（镜像 Core 段名）：同一段配置可在两个文件之间**原样复制**，运维只需记一个段名。

## 改动

- `Source/PuddingDesktop.WpfArchive/Configuration/DesktopBootstrapSettings.cs` —
  新增可空 `Desktop` 段（`DesktopSectionSettings`）与其下的 `DesktopCapabilityChannelFileSettings`
  （`Enabled` / `DesktopId` / `ControlTokenHeader` / `HandshakeTimeoutSeconds`）。
  **可空**的用意：`FileDesktopBootstrapSettingsStore` 整体序列化且没有 `WhenWritingNull`，
  非空段会让用户没写过的内容在下次保存时出现在文件里；`Enabled` 是安全相关开关，
  因此「缺席 = 从未配置 = 关闭」，且「缺席」与「显式 false」不互相改写。
- `Tests/PuddingDesktop.Tests/Configuration/DesktopCapabilityChannelSettingsJsonTests.cs`（新增，7 项）
  与 `Tests/PuddingDesktop.Tests/PuddingDesktop.Tests.csproj`（新增对 `Pudding.DesktopService` 的引用）。
  该引用**只为**一条跨侧一致性断言：文件形态的缺省值必须与组件缺省值一致
  （两边各写一份就有漂移风险，而漂移表现为「什么都没配却握手失败」）。

## 验证

- `PuddingDesktop.Tests` **273/273**（新增 7 项）：段缺席 ⇒ null；完整段逐字段映射；
  只写 `enabled` ⇒ 其余取组件同款缺省；文件缺省 == 组件缺省（含 `Disabled` 仍关闭）；
  显式 false ≠ 缺席；经 store 同款序列化选项的往返形状对称；缺席段保存时**不会**出现 `capabilityChannel`。
- 接线本身**未验证**（尚未有代码读取该段，属下一轮的 Shell 调用点）。

## 未完成 / 留白

  （`Pudding.DesktopService` 的边界目标禁止引用任何含 `PuddingDesktop` 的项目，映射不可下沉）。

## 影响与回滚

缺省没有该段 ⇒ 行为与今天一致；回滚 = 删除该段或 `Enabled=false`。
