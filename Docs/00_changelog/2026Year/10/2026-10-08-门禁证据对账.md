# 2026-10-08 B7：G1–G11 门禁 → 证据对账

## 为什么

此前对 G1–G11 的把握是"分散在多轮叙述里"，容易记串或漏项。本轮把它做成**一张可核对的表**：
每条门禁 → 进程内实现 → 自动化证据（**清点所得**的测试类与用例数）→ 只能真机/外部判定的部分 → smoke 清单项。

成果文件：[门禁证据对账](../../../14_reports/2026-10-09-门禁证据对账.md)

## 对账发现（本轮实际修的东西）

**G2 在清单里少登记了两项标准**：

| G2 的四项标准 | 原 S-02 | 现 S-02 |
|---|---|---|
| 同 context 非目标页写入拒绝、驱动调用数=0 | ✅ | ✅ |
| 撤销后再写拒绝 | ✅ | ✅ |
| **跨 frame/跨身份写入拒绝** | ❌ 未登记 | ✅ |
| **子代理不得扩大父授权** | ❌ 未登记 | ✅ |
| **建关页后无残留（标签项/订阅/注册项）** | ❌ 未登记 | ✅ |

已补齐 S-02 的动作与期望，并加上自动化覆盖声明 `AutomationTests.BrowserPageGrant* / ReadOnlyDelegationTests`
（覆盖声明门禁验证这两个类**真实存在**）；对外清单文档同步为代码真源（严格门禁要求动作逐字一致）。

## 其余十条的结论

| 门禁 | 结论 |
|---|---|
| G1 / G3 / G4 / G5 / G6 / G7 / G8 / G9 / G10 / G11 | **都同时具备**：进程内实现 + 至少一个自动化证据类 + **真机缺口已登记在对应清单项里** |
| 特别说明 | G10 的"子代理**真正**发现工具"、G11 的"四步终态"、G9 的"采集本身与模型收到图片"，**进程内无法自证**，已逐条写明只能外部判定 |

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **335 / 335**（S-02 扩充后，动作/数字/覆盖三类门禁全绿） |
| **全量链** | **1592 / 0**、无重试、语料全扫 |

## 诚实边界（诚实登记）

- **用例数是清点值，不是覆盖率**：证明"有这些用例"，**不证明**标准已被语义覆盖。
- **本表不构成验收**：G1–G11 的通过由外部观察判定；进程内证据只支持"内部一侧可交付"。
- **只到"类"一级**：未做"每条标准 ↔ 具体用例名"逐条映射（登记为可加强项）。
- **本表会过期**：无自动门禁把它与代码绑定（登记为可改进项）。
- **真机从未运行**：表中"只能真机"栏全部**未验证**。
- 决定②仍待确认。
