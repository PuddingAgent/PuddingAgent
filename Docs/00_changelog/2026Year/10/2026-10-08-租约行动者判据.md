# 2026-10-08 B1：同一判据的第四处 + 判据收敛到单一来源

## 怎么找到的（上一轮登记的"同类盲区体检"）

上一轮我登记了候选：检查 `IsTheSameActor` 的两处使用是否存在"删一处不红"。
地毯式检索 **全仓库的 `CallerId` 比较**后，答案有两部分：

1. **权威内部没有遗漏**：`Source/PuddingBrowser.Automation` 里唯一的 `CallerId` 比较就在判据自身；
2. **但同一判据在别处还有一份弱的实现**：`BrowserAutomationLease.Allows`（在**契约**里）：

```csharp
&& string.Equals(Holder.CallerId, request.Caller.CallerId, StringComparison.Ordinal)   // 只比字符串
```

而它的文档写的是"**持有者、操作、页面都必须一致**"。租约是"允许触碰页面"的凭据 ⇒
另一个同 `CallerId` 的调用者只要拿到同一个 `operationId`，就能**骑在这条租约上继续执行**。

## 修法（同时消除"同一规则两份实现"）

| 改动 | 内容 |
|---|---|
| 契约 | `BrowserCallerIdentity.IsSameActor(other)`：种类 + CallerId + TaskId 三者相等；注释写清与 `IsSameTaskScope` 的**故意**区别（后者用于任务级管理授权） |
| 租约 | `Allows` 的持有者判定改用 `Holder.IsSameActor(request.Caller)` |
| 权威 | 删掉本地私有 `IsTheSameActor`，`FindPageGrant` 与 `HasWriteCoverage` 统一改用契约上的同一方法 ⇒ **判据只有一个来源** |

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **352 / 352**（＋1） |
| 新增取红用例 | 同一行动者 + 同 operationId ⇒ **允许**；同 CallerId **不同任务** ⇒ **拒绝**；同 CallerId **不同种类**（子代理）⇒ **拒绝** |
| **取红实测** | `Allows` 改回只比 `CallerId` ⇒ 该用例**变红**；还原 ⇒ 352/352 |
| 契约公开面 | `ContractsTests` **153/153** 全绿（新增一个公开方法**未**触发冻结面失败 ⇒ 该套件冻结的是目录/线名快照，不是全部成员） |
| 其它套件 | DesktopService 315 · DesktopSurface.Browser 67 · PuddingDesktop 320 · AgentTools 70 全绿 |
| 体检结论 | "同 id 借用"这一类在本组件的四处实现已全部统一到一个判据（授权查询 / 租约存活性 / 租约自身 / 契约） |

## 诚实边界（诚实登记）

- **判据收敛改变了公开面**：`BrowserCallerIdentity` 多了一个公开方法（契约类型上的增量，源兼容）。
- **仍是"记得用"的约定**：新代码若手写 `CallerId` 比较，编译器不会拦；本轮**没有**加源码级门禁禁止直接比较 `CallerId`
  ⇒ 登记为可做改进（同上一轮的接线门禁思路）。
- **租约的其它维度未一并收紧**：`Allows` 仍不比 `ControlEpoch`/`GrantEpoch`（那由 `Revalidate` 负责）——
  这是分工，不是遗漏，但值得知晓。
- **未真机验证**；仍属组件/契约层。
