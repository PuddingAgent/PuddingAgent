# 2026-10-02 维护账本水位与待重试语义（D 第二阶段纯逻辑）

## 改动

按修订版 D 节建议施工顺序，在「源 manifest / 变更判定纯逻辑」之后落地**持久待办的语义部分**
（持久化表结构仍未实施）：

- `Source/PuddingCodeIndex/Contracts/CodeSourceManifestContracts.cs` 追加：
  `CodeSourceRetry`（路径 / 原因 / 连续失败次数 / 首次失败时刻 / 下次允许尝试时刻）、
  `CodeSourceProviderAdvance`、`CodeSourceCommitCompletion`（世代 + 捕获版本 + 消费者水位 +
  扫描开始时刻 + 完整性 + 未解决路径数）、`CodeSourceCommitOutcome`
  （`Committed` / `Superseded` / `StaleEpoch`）、`CodeSourceMaintenanceLedgerState`（可序列化快照形状）。
- 新增 `Source/PuddingCodeIndex/Services/CodeIndex/CodeSourceMaintenanceLedger.cs`（纯内存、无 I/O）：
  - **期望 vs 已提交**：`RecordObservedChanges` 每批递增一次 `DesiredVersion` 并返回**捕获版本**；
    提交只确认被捕获的版本，执行期间到达的新变化把账本置为 `DirtyAgain`（D4「执行期间新变化推进
    desiredVersion/dirtyAgain；提交只确认捕获的版本，较新变化继续补跑」）。
  - **消费者分别推进**：`CompleteCommit` 只对**本轮真正提交成功**的消费者做单调 `max` 推进。
  - **扫描水位不掩盖失败**：只有「捕获版本即当前期望 + 扫描完整 + 无未解决路径 + 无待重试」才把水位推进到
    `ScanStartedUtc`；watcher-only 批次（`ScanStartedUtc` 为 null）、不完整扫描、有未解决/待重试路径时保持旧值，
    且水位**永不回退**。
  - **世代**：`BeginEpoch` 递增世代并标记「一切要重新核对」；携带旧世代的提交返回 `StaleEpoch`，
    不推进任何水位、不记入消费者版本。
  - **待重试与退避**：`RecordFailure` 按 `base · 2^(attempts-1)` 阶梯退避并封顶（默认 60s → 30min），
    首次失败时刻保持不变；`DueRetries` 按路径稳定排序返回到期项；`ClearRetry` 在成功提交后移除。
- 新增 `Source/PuddingCodeIndexTests/Services/CodeIndex/CodeSourceMaintenanceLedgerTests.cs`（15 条）：
  批次版本递增、只确认捕获版本、执行期间新变化不被顺手确认、消费者水位不回退、扫描水位的三条前置条件、
  水位不回退、watcher 批次不推进、陈旧世代整体作废、退避阶梯与封顶、到期重试的稳定顺序、
  重试清除与「待重试压住水位」、快照独立性、退避函数的总性与有界性、非法配置拒绝。

## 验证

- `dotnet test Source\PuddingCodeIndexTests\PuddingCodeIndexTests.csproj --filter "FullyQualifiedName~CodeSourceMaintenanceLedgerTests"`
  → 15/15 通过。
- 全量 `Source/PuddingCodeIndexTests` → 全绿（205 用例）。
- 组件边界不变：新文件只引用本组件契约与 `CodePathIdentity`；`ProjectReference` 仍为空，
  `ComponentBoundaryTests` 的三重运行期断言不受影响。

## 未完成与影响

- **持久化未实施**：`CodeSourceMaintenanceLedgerState` 目前只是形状与语义，没有表、没有 schema 变更、
  没有落盘；接入宿主前必须先做「完整清单校准 + 持久账本」这一阶段的存储部分。
- 未接入维护链路：账本与判定器都还没有被 `CodeIndexMaintenanceService` / 校准服务调用，
  因此对运行中实例仍是零行为变化，也不构成对高读取收益的性能结论。
- 后续阶段（按报告顺序）：完整清单校准与持久账本落盘 → `ICodeIndexStore.ReplaceFilesAsync` 原子替换 →
  语言批量/依赖影响计划 → 既有维护链路接入。
