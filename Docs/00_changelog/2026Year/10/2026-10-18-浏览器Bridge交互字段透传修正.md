# 2026-10-18 浏览器 Bridge 交互字段透传修正（F4）

## 目标与结论

按 [ADR-097](../../../07_architecture/111ADR-097Agent浏览器控制一期闭环与单一执行链ADR.md) D5 与[一期方案](../../../12_features/Agent浏览器控制一期整体实施方案-2026-10-18.md) §3.4：`browser_interact` 的 typed request 到 runtime 必须逐字段核对，回执只能报告执行端事实。本切片只改 **Host 侧 Bridge 实现与其测试**，不改协议、能力通道、Desktop/WinUI/DesktopService、AgentTools 公共契约。

两个已确认缺陷在本切片闭合：

1. **native 谎报来源**：`inputMode` 不在 Bridge 协议上（`PageInteractArguments` 无该字段），但 surface 仍按 DOM 执行，工具层再按请求值回报 `inputBackend=native`。现在 `InteractAsync` 在**触碰页面之前**对 `inputMode=native` 返回既有 `unsupported_capability`（消息给出改用 `dom` 的可行动方向），不静默降级、不伪装支持。
2. **滚动语义丢失**：此前 `ApplyInteractionAsync` 只传 `DeltaX/DeltaY`，`to_top/to_bottom/to_ref/element` 全部退化为“page + delta”（无 delta 时等于滚 0 像素），且 `page.ScrollAsync` 返回的 `ScrollOutcome` 被丢弃 ⇒ 回执 `scroll` 恒 null。现在完整传 `Target`（五项映射）、`Locator`（容器）、位移与 `InputMode=Dom`，并把 runtime 报告的 Container/Before/After/Consumed/AtBoundary/ContentChanged/StopReason 逐字段映射进 `DesktopInteractionResult.Scroll`。

## 改动

- `Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs`：native 入口拒绝（`NativeInputModeRejected`）；`ApplyInteractionAsync` 返回 `(Error, Scroll)` 并映射滚动事实（`ToDesktopScrollReport`）；新增 `ToRuntimeScrollTarget`；未登记的 target/locator kind 明确 `invalid_request`。
- `Tests/PuddingHost.Tests/BrowserBridge/BridgeBrowserCapabilitySurfaceTests.cs`：`FakePage` 记录 options 对象（`LastClickOptions/Fill/Type/Press/Hover/Scroll`、`CheckCount/LastChecked/QueryCount`）并可配置 `ScrollOutcome`；新增 7 条用例（含 2 行 Theory）：NativeClick/NativeCheck 触碰前拒绝、DefaultClick 仍 Dom、DefaultCheck 仍执行、ScrollToBottom 目标+事实、ToTop/ToBottom 目标、Element 滚动带 locator。
- `Source/PuddingHost/code_map.md`：更新该文件当前语义（native 拒绝 + 滚动完整透传）。

## 验证

- **先红**（仅测试改动、产品未改）：`dotnet test Tests/PuddingHost.Tests --filter "FullyQualifiedName~BridgeBrowserCapabilitySurface"` ⇒ **6 失败 / 47 通过 / 53 总计**；失败项即 native 两条与滚动目标/事实三条（+Theory 一行）。
- **后绿**（产品修复后）：**53/53 通过，0 失败**；扩大至 `FullyQualifiedName~PuddingHost.Tests.BrowserBridge` ⇒ **136/136 通过**（Lead 复核重跑）。
- 未运行 PuddingDesktop/PuddingAgent、未调用真实模型；本切片是 Host 组件级证据，不能替代 I3/I4 真机与模型验收。

## 未完成与影响

- **协议仍不承载 `inputMode`**：native 在本切片被诚实拒绝；若要真正放开 click/fill/type/press/hover/scroll 的 native，需要协议版本化切片（并在真实 WebView2 上独立验收）。check/uncheck/select 的驱动 API 无 options，即使协议上线也只能拒绝 native。
- 远端线缆不承载 `StopReason`：Bridge 回执中的 StopReason 如实为 null（不编造）；"无滚动事实"目前用 `Container="unreported"` 哨兵表达，后续若要区分需扩 runtime 契约。
- 工具回执层仍按请求值填 `inputBackend`：由于 native 现在在 surface 直接失败，不再出现“DOM 执行却成功回报 native”；回执改由执行端事实生成属后续切片（F5）。
- 暂停/接管期间**只读继续**的语义仍只在旧 authority/文档里，Bridge 派发器仍在识别命令前拒绝全部命令（F2 待修）；页面级准入仍受“桥在线即放行”影响（F3 待修）。
- 回滚 = revert 本提交；无配置/数据变更。
