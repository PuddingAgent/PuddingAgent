# 日志基础设施加固：运行时级别开关 + 每行显式 tag（Debug 按钮的地基）

## 先核实现状（避免重复造）

用户提的日志要求里，**有几项仓库里已经存在**，先说清楚，避免重复劳动：

| 用户要求 | 现状（实读） |
|---|---|
| 日志输出到 DataRoot 的 `logs` 目录 | ✅ 已有：`PuddingDataPaths.LogsRoot = <DataRoot>/logs`，细分 `logs/system`、`logs/error`、`logs/components/<组件>`、`logs/diagnostics`、`logs/sessions`、`logs/audit`、`logs/archive` |
| **至少按天切割** | ✅ **已实现**：`SizeRollingFileSink` 文件名即 `{baseName}-{yyyyMMdd}_{seq:D3}.log`，跨日自动换文件（且当前文件被外部清理器误删时会自愈重建） |
| 提供日志清理/保留 | ✅ 已有：`StorageDataClassCatalog` 已含"普通日志""Error 日志"两个可清理数据类，自动清理策略面板（存储管理页）已能配置保留天数 |
| 基础设施公用复用 | ✅ 部分：`SizeRollingFileSink` 在 `PuddingCore`（`PuddingCode.Observability`），Host 侧由 `PuddingLoggingBootstrapper` 统一装配（组件专用 sink ×10 + error + system + console） |
| **级别可配** | ⚠️ 只支持两档（`PUDDING_LOG_LEVEL` = Debug/Information），且**只能启动时生效** |
| **行内显式 tag** | ❌ 缺失：按组件分文件，但**行内没有 tag**，多文件拼看时分不清来源 |
| 运行时可切换（Debug 按钮用） | ❌ 缺失（这是本轮补的） |

## 本轮改动（新增，未改既有语义）

| 文件 | 改动 |
|---|---|
| `Source/PuddingCore/Observability/PuddingLogLevelSwitch.cs`（新） | 全进程共享的 `LoggingLevelSwitch`；`TryParse` 覆盖 Serilog **全部六档** + 常见别名（`trace`/`info`/`warn`/`err`/`critical`）；**认不出来就返回 false**（不猜测、不放大日志量）；`ResolveStartupLevel` 按"配置优先、环境变量兜底"解析 |
| `Source/PuddingCore/Observability/LogTagEnricher.cs`（新） | 每条日志补 `[tag:…]`：优先 `Component`（组件 sink 的过滤键）⇒ `SourceContext` 的**短名** ⇒ 兜底 `core`；推导逻辑是纯函数 `DeriveTag`，便于测试 |
| `Source/PuddingHost/Hosting/PuddingLoggingBootstrapper.cs` | ① 级别改为 `PuddingLogLevelSwitch.ResolveStartupLevel(config["Logging:Level"])` 并 `MinimumLevel.ControlledBy(...)`（**不改既有环境变量行为**，只是增加配置来源与运行时切换能力）；② 文件与 console 模板加入 `[tag:{Tag}]`；③ 注册 `LogTagEnricher` |

## 验证

- `PuddingHost` 构建 **0 错误**；
- `PuddingCoreTests` 构建 **0 错误**，并用**原生 runner 实际跑通**（见下）；
- 新增 `Source/PuddingCoreTests/Observability/LoggingFoundationTests.cs`：六档 + 别名解析、未知值必须返回 false 且兜底 Information、配置优先于环境变量、环境变量兜底、默认 Information、tag 推导三种优先级、enricher 在"什么都没有"时也补 tag。

### 顺带修正一条**我上一轮写错的手册结论**

上一轮我在外部验收手册里写"MSTest/Microsoft.Testing.Platform 工程在本机 `dotnet test` 下零输出退出码 0 ⇒ 必须用原生方式运行"。本轮找到了**可用的确切命令**：

```
dotnet vstest <测试工程输出目录>/<Project>.dll --TestCaseFilter:"FullyQualifiedName~<类名>"
```

`dotnet test` 对这些工程仍然是**零输出退出码 0（等于没跑）**，但 `dotnet vstest` **正常执行并报告计数**。
⇒ 手册要写具体命令，而不是只写"用原生方式"。

## 未完成（下一阶段，按依赖顺序）

1. **Debug 开关的服务端**：一个受 Admin 鉴权的接口把 `LoggingLevelSwitch` 切到 Debug/Information（并落到 `system.json` 以便重启后保持）；没有它，"Debug 按钮"无从下手；
2. **两个 Debug 按钮**：Desktop Shell（`PuddingDesktop`）与 Web 前端各一个，调用上面的接口；
3. **日志的统计与清理按钮**：复用既有存储管理接口，把 `logs` 各子目录的占用/文件数/最旧最新时间暴露出来，并支持按周/月选择性清理；
4. **平台数据库按数据类型的占用估算**（图3/图5 的"显示不同数据的占比"）：Pudding 平台库 9.3 GB 目前只显示为单块，需要给出**按表/按数据类**的估算与可清理项，供用户勾选。
