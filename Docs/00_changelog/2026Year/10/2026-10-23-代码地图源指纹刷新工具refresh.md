# 代码地图指纹工具补 `--refresh`（过期源指纹的机器化刷新）

**日期**：2026-10-23 · **范围**：`Tools/Docs/code_map_fingerprint.py`（+89/−13 中的大部分）、`Tools/Docs/code_map_fingerprint_selftest.py`（+24/−6）、三份 `code_map.md` 的源指纹各 1 行；`code_map_check.py` **未改**（sha256 逐位相同 `bd06254d…`）

## 问题：能报「过期」，却没有「刷新」的手段

`code_map_check.py` 的 `stale-fingerprint` 会算出「声明值 ≠ 实测值」，但仓内只有 `code_map_fingerprint.py` 会写指纹，而它**只补 `declared_fingerprint` 为空的文件**（docstring 原话）。于是「源文件改了，指纹过期」这件事只能手改，而手改有三个坑：

1. 得自己算全量指纹，口径是「仓库相对路径 + 全量 sha256 排序拼接后再 sha256 取前 12 位」，手算必错；
2. 声明写回格式不止一种：根 `code_map.md` 是 `Source/**=dd1089a75568`，组件级是 `Source/PuddingCore/**=416-311e31d58697`（**带文件数前缀**），写回时得原样保持；
3. 文件带 BOM、行尾是 CRLF，用文本 API 改会静默动字节。

结果就是这个状态持续了很久：门禁一直 `stale 3`，而且**每次都被当成「别人的 WIP 造成的，先别动」**放过去。这一轮把它变成机器化动作。

## 做法：`--refresh`（默认 dry-run）

```
py -3 Tools\Docs\code_map_fingerprint.py --refresh            # 只打印计划
py -3 Tools\Docs\code_map_fingerprint.py --refresh --apply    # 真写盘
```

三个判据分别来自三个真源，谁也不替谁猜：

| 环节 | 真源 | 说明 |
| --- | --- | --- |
| 有哪些文件/哪些 glob | `temp/cm_rep.json`（报告） | 只用来**枚举**，不用它给的值 |
| 实测值是多少 | `code_map_check.glob_fingerprint` | 直接 import 复用，不另写算法（否则「刷新」与「核验」各说各话，刷完仍 stale） |
| 现在写的是什么 | **磁盘现读**（`declared_on_disk`） | 报告是快照，见下节 |

匹配规则与核验侧完全一致（`digest` / `value` / `digest_full` 前缀三种都算命中），写回保持声明原有写法（带 `<文件数>-` 前缀的仍带），替换只针对 `glob=值` 这一个 token 并断言**在文件里恰好命中 1 次**——命中 0 次或多次一律拒绝写入。

## 第一版是错的：把报告当成了磁盘

第一版直接用报告里的 `declared_fingerprint` 当替换目标。第一次 `--apply` 成功；紧接着再跑一次，程序在

```
AssertionError: code_map.md 里 b'Source/**=f880f8aac37e' 命中 0 次（期望 1），拒绝写入
```

上崩了。**这个 fail-closed 是对的（没有乱写），但判据是错的**：报告 `temp/cm_rep.json` 是 `check` 那一刻的快照，`--apply` 之后它已经过期。改成「用报告枚举、用磁盘取当前值」后，命令变成幂等的：

```
--- 待刷新（dry-run，未写盘） 1 处源指纹
[refresh] code_map.md :: Tools/**  7ce2646f4dd4 -> 41d07b8cf5c8  (files=28)
--- 将刷新 1 处源指纹
WROTE code_map.md :: Tools/** -> 41d07b8cf5c8
=== 二次幂等 ===
--- 待刷新（dry-run，未写盘） 0 处源指纹
```

## 一条要记住的观察：别人在跑构建时，指纹会漂

同一份 `Source/**`，两次测量不一样：

- `00:08:54` 的 check：`computed=8e261e2adddd(files=4996)`
- `00:09:53` 的 `--refresh`：`dd1089a75568(files=4996)`

期间 `git status` **全程干净**（我自己那 3 个文件之外无改动），文件数也没变（4996 不变）⇒ 是**内容**在这两分钟里变了。当时另一条工作流正在跑 `dotnet build`（`Source/**/obj|bin` 产物时间戳 08:03–08:05 本地时间）。产物目录在指纹排除集内、不该参与，所以这更像「工作区被并发 checkout/还原」而不是「构建污染指纹」。

结论不是「指纹错了」，而是**测量纪律**：刷新指纹必须在「工作区静止 + git 干净」的窗口里做，并且刷新后立刻用 check 复核一致性（`verified` 必须等于 `globs_declared`）。本轮两次连续测量（check 与 refresh 各自独立跑）已经一致，`--apply` 后门禁 `stale 0` 也确认了这一点。

## 结果

```
error: 0  warn: 82  info: 0  gate: PASS          # 刷新前 warn 85
stale-fingerprint      warn   0                  # 刷新前 3
fingerprint_check: declared_files=48 globs=148 verified=148 mismatched=0 unverifiable=0
```

写回的四处声明：

| 文件 | glob | 旧值 | 新值 |
| --- | --- | --- | --- |
| `code_map.md` | `Source/**` | `f880f8aac37e` | `dd1089a75568` |
| `code_map.md` | `Tools/**` | `377b220beeb9` | `41d07b8cf5c8` |
| `Source/PuddingCore/code_map.md` | `Source/PuddingCore/**` | `416-8587ed7c674d` | `416-311e31d58697` |
| `Source/PuddingRuntime/code_map.md` | `Source/PuddingRuntime/**` | `7a1725474742` | `5124d4250619` |

`git diff` 逐行核对：三份 `code_map.md` **各只变 1 行**，且这一行里只有 hash 子串不同（`git diff -U0` 原始输出见 `temp/rf_apply.txt`）；BOM 与 CRLF 均未被动过（字节级替换）。

## 自测与变异取红

`code_map_fingerprint_selftest.py` 从 10 条扩到 13 条，新增：`--refresh --bogus` → exit 2 且无计划输出、`--refresh --help` → exit 0（帮助优先），并把 `--help` 必须列出 `--refresh` 并入原断言。

变异取红（删掉 `main()` 首行的 `parse_argv(sys.argv[1:])`）：

```
RED   rc=1 fails=11       # 含 '--refresh + unknown flag still exits 2  <- rc=0'
restored sha256=18ba0e90… (equal=True)
GREEN rc=0 fails=0 :: 13 PASS / 0 FAIL
RESULT red_rc=1 green_rc=0 mutation_detected=True restored_green=True
```

`--help/-h` 的 exit 0 在变异态**仍然是绿的**——缺陷现象本身就是「静默跑完然后退出 0」；抓住它的是「不执行计划」和「缓存未被覆写」两条断言。这也是为什么自测里要同时断言**副作用**而不只是退出码。

## 遗留

- `--refresh` 的 glob 枚举仍依赖报告；若某文件新增/删除了 glob 声明，必须先重跑 `check` 生成新报告（程序会因 `declaration not found on disk` 明确失败，不会误写）。
- 逐 glob 全量哈希不在 `temp/cm_fp_cache.json` 里，`Source/**`（4996 文件）一次约几十秒；`--refresh` 目前只做「纠错」，不做「批量导出/导入」。
- 门禁里仍留 3 类非门禁告警：`anti-pattern 80`、`header-repeat 2`（其余两类已清零），属于待裁定的规范口径问题，不在本轮范围内。
