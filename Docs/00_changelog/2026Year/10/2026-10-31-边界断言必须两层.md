# 2026-10-31 边界断言必须有两层：运行时抓不到「引用但没用」

## 发现（变异取红时暴露）

给 `PuddingRetrieval.Contracts.csproj` 临时加一条对 `PuddingPathFiltering` 的 `ProjectReference`（**代码里不使用**），跑 `ComponentBoundaryTests`：

```
mutj-cb exit=0 tests=2 failed=0     ← 断言全绿！
```

即：**只做运行时 `GetReferencedAssemblies()` 检查的边界断言，对「声明了依赖但代码暂时没用」完全取不到红。**

原因很直接：未被使用的 `ProjectReference` 不会在编译产物的程序集引用表里留下条目，运行时检查自然看不见。

## 这意味着什么

我在 R2-00/R2-01 里多处说过「边界由运行时断言固定，不靠文档」。按本次实测，这句话**只对「用过的依赖」成立**。声明式依赖（csproj）此前完全没有护栏 —— 而这恰恰是最容易顺手加错的地方。

## 修法：加第二层 csproj 断言

`PuddingRetrieval.ContractsTests/ComponentBoundaryTests` 新增：

```csharp
ContractsCsproj_DeclaresNoForbiddenProjectReferences()
```

- 用 `[CallerFilePath]` 拿到本测试源文件路径，推算 `Source/PuddingRetrieval.Contracts/PuddingRetrieval.Contracts.csproj`
  （比从 `AppContext.BaseDirectory` 上溯稳，不受输出目录层级 / RID 子目录影响）
- 读文本，断言不含任何被禁工程的 `ProjectReference` 名

## 证据（实测）

- **变异取红**：加 `PuddingPathFiltering` 引用 ⇒ **恰好 1 红**，正是新增的 csproj 断言；其余 2 条仍绿（证明它抓的是这一层）。
- **还原**：按备份字节写回，SHA-256 位级一致 ⇒ 0 红。
- **全量**：`PuddingRetrieval.ContractsTests` **51/51 通过**（48 契约用例 + 3 边界）。
