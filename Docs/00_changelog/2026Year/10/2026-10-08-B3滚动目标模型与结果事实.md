# 2026-10-08 B3 滚动：目标模型与结果事实（含「无内容加载不是失败」）

## 目标 / 背景

设计 §7 第三段：「scroll 的目标模型为 `page/element/to_ref/to_top/to_bottom`：无 locator 时检查
`document.scrollingElement`；元素滚动优先明确指定，必要时定位最近可滚动祖先。普通滚动失败再由调用方
选择 native wheel，**不能盲目滚另一个区域**。返回目标容器、前后位置、`consumedDelta`、`atBoundary`、
`contentChanged`；无限滚动另等新增内容/条目数，**不能把无内容加载当滚动失败**。」

此前滚动只有 `delta_x`/`delta_y` 两个数，没有目标模型也没有结果事实：调用方无法表达"滚到顶部"，
也无法判断"到底滚没滚动""加载出新内容没有"，只能看动作有没有抛异常。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| 契约 | `Source/Pudding.Contracts/Desktop/InteractionContracts.cs` | `DesktopScrollTarget`（5 目标 + 线名、fail-closed 解析）、`EffectiveScrollTarget`（省略时按 locator/位移推导）、构造期**参数一致性校验**、`DesktopScrollReport`、`DesktopInteractionResult.Scroll` |
| 运行时 | `Source/PuddingBrowser.Abstractions/BrowserTypes.cs` | `ScrollTarget` 枚举、`ScrollOptions.Target`/`Locator`、`ScrollOutcome`（容器/前后位置/消耗位移/边界/内容变化）；`IBrowserPage.ScrollAsync` → `Task<ScrollOutcome>` |
| 驱动 | `Source/PuddingBrowser.WebView2/WebView2DomClient.cs` + `WebView2BrowserPage.cs` | 新增独立 **`ScrollScript`**：实现五种目标；`element` 先看元素自身滚动盒、必要时上溯**最近可滚动祖先**；返回结果事实；未登记目标 fail closed。`DescribeScroll` 要求元素类目标必须是 **ref** 定位（不做二次定位，避免"滚了另一个区域"） |
| 能力通道 | `Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs` | 目标模型映射 + 把驱动事实放进 `DesktopInteractionResult.Scroll`（无事实即 `null`） |
| 桥接 | `Source/PuddingHost/BrowserBridge/RemoteBrowserPage.cs` | 远端尚未回传滚动事实 ⇒ 容器标 **`unreported`**、位移一律 0：**不编造**（"没报告"≠"滚了 0 像素"） |
| 工具 | `BrowserInteractTool` · `BrowserToolContracts` | `scroll_target` 参数（非 scroll 动作给即拒）+ 输出 `scroll`（含 `notScrolled`）；**不据内容变化改判 completion** |

新增门禁：

- 契约：5 条线名冻结；推导规则（无 locator ⇒ `page`、有 locator 有位移 ⇒ `element`、有 locator 无位移 ⇒
  `to_ref`）；**拒绝有歧义的组合**（元素类目标缺定位、`page` 带定位、位移类目标零位移）与未登记枚举；
- 驱动：脚本文本断言（五种目标、`nearestScrollable`、`consumedDelta`/`atBoundary`/`contentChanged`、
  未知目标 fail closed）+ `ScrollTargetWire`/`DescribeScroll` 的行为断言（非 ref 定位抛
  `browser_invalid_arguments`）；
- 传输：目标模型到达驱动（`to_bottom` 覆盖推导），结果事实原样进入 `DesktopInteractionResult.Scroll`；
- 工具：最容易被误判的场景（滚到边界、0 位移、没加载出新内容）⇒ 事实如实呈现
  （`atBoundary=true`/`contentChanged=false`/`notScrolled=true`）**但 `ok=true`、`execution=completed`**：
  这正是「不能把无内容加载当滚动失败」。

**取红实测**：把能力通道的滚动目标映射写死成 `ScrollTarget.Page` ⇒
`ScrollCarriesTheTargetModelAndReportsTheOutcome` **恰好变红**；复原后 61/61 复绿。

## 已知边界（诚实登记）

- **真机滚动行为未验证**（本环境跑不了真实 WebView2）：脚本只有文本断言；`document.scrollingElement`、
  固定定位、`overflow:hidden` 容器、iframe 内滚动等真实场景需外部进程内 smoke 复核。
- **桥接路径不回传滚动事实**：`RemoteBrowserPage` 明确返回 `unreported`；桥接命令/响应扩属后续切片，
  因此当前"滚动事实"只在能力通道路径可用（**没有假装两条传输同形**）。
- **元素类目标只接受 ref 定位**：脚本按宿主 ref 精确匹配，不做"先定位再滚"的二次查询；
  用 css/role 指定容器会得到明确 `browser_invalid_arguments`（后续可加"先定位再滚"）。
- **`atBoundary` 的判据是"请求了位移但方向不对/没动"**：不区分"到底了"与"被浮层挡住"，
  也没有对无限滚动的"新增条目数"做等待（设计说"另等"，属 B3 余项）。
- `to_ref` 的返回目前把位置事实置 0（只回"是否进入视口"的内部计算），未把窗口滚动位置带出。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_interact` 的 `scroll` 新增 `scroll_target`（默认按参数推导，
  与迁移前"无 locator 滚文档"一致）与输出字段 `scroll`；契约对**有歧义/缺参数**的滚动组合由
  "运行时随便滚"变为**构造期拒绝**（例如 `scroll` 只给 locator 不给位移现在是合法的 `to_ref`，
  而 `page` 带 locator 会直接报错）。
- 无数据/配置影响；线缆 DTO 与 proto 未改动。
