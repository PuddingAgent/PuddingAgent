# 2026-10-02 就绪描述契约的端到端断言 + 代码索引补登记

## 目标 / 背景

两件事同轮完成：

1. **补一个门禁盲区**：本系列的门禁核心是真实端点探针，但探针**自己构造**端点描述——
   它验证的是**解析器**，不是 Core 真正打到 stdout 的那一行。当日因此漏过
   「Core 打成 `|v1|`、Desktop 要求整数」这一缺陷（组件测试全绿、探针 53/53、编译通过，
   而 `Enabled=true` 时通道永远不启动）。这条 Core→Desktop 字符串契约此前没有把头尾接起来测。
2. **按新增的索引约定补登记**：`AGENTS.md` 当日新增「code_map.md 使用规则」与「修改日志使用规则」——
   `code_map.md` 只作索引（禁止追加时间线），过程记录写 `Docs/00_changelog/`。
   根 `code_map.md` 已由另一方完成瘦身（`b25c2f1`），本轮补做本组件的登记。

## 改动

- 新增 `Tests/PuddingDesktop.Tests/Configuration/CapabilityChannelReadinessContractTests.cs` —
  把三段**真实**代码接起来：Core 产出函数 `CapabilityChannelReadySignal.Describe` → 按入口点同款组装就绪行
  → Desktop 真实解析器 `CoreReadyMessageParser` → Desktop 唯一判定入口 `DesktopCapabilityChannelPreflight`。
  六条用例：正常描述可解析且判「可启动」；字段改名 ⇒ 取不到且不启动；关闭态 ⇒ 字段**缺席**且原文不含该字段
  （"逐字一致"是可回滚承诺）；`|v1|` 旧格式走完整条链仍不启动；旧格式本身不满足契约；
  结构断言——产品代码必须经**同一个**产出函数且不得再出现手写版本段。
- `Tests/PuddingDesktop.Tests/PuddingDesktop.Tests.csproj` — 新增对 `Pudding.CapabilityBroker.AspNetCore`
  的引用，**只为**上面这条端到端契约断言。
- `Source/PuddingAgent/Program.cs` — 两处修正（由上面那批测试当场抓出）：
  ① 就绪行字段名改用 `CapabilityChannelReadySignal.FieldName`（此前是匿名类型的属性名写死，**两份真源**，
  改常量时两边静默不一致 ⇒ Desktop 读不到 ⇒ 预检判"描述缺失" ⇒ 通道不启动）；
  ② 改用字典后**不能再依赖** `WhenWritingNull`——它只作用于属性、不作用于字典项，
  否则关闭态那行会多出 `"capabilityEndpoint":null`，破坏"逐字回滚"；改为**按需写入**（非 null 才写）。
- 索引补登记：`code_map.md`（根 §2.2 的 `Pudding.DesktopSurface.Browser` 一行由「待补 code_map」改为链接）；
  新增 `Source/Pudding.DesktopSurface.Browser/code_map.md`（该子项目此前没有）；
  `Source/PuddingDesktop.CapabilityHost/code_map.md` 与 `Source/Pudding.DesktopService/code_map.md`
  补上本轮新增/改动的文件条目。

## 验证

- `PuddingDesktop.Tests` **279/279**（新增 6 项）；`PuddingAgent`（含 `PuddingHost`）Release 构建 **0 错误**。
- 该批测试**当场抓出上面两处问题**（字段名两份真源、`WhenWritingNull` 对字典项无效）——
  两者都属于「契约测试全绿但产品那一行已经变了」的类型，正是它存在的目的。
- **未验证**：Shell 内两处接线（页面生命周期驱动注册表、组合根调用点）仍未做，见下。
