# 2026-10-08 B1：Core 执行上下文 → 调用者身份 + 决策①简报

## 本轮交付

`Source/PuddingBrowser.AgentTools/BrowserCallerIdentitySource.cs`（工具层）：

| 规则 | 依据 / 理由 |
|---|---|
| 入参只有 `RuntimeExecutionIdentity` + agent 实例标识 | §3.1「不让模型填写 owner/epoch」⇒ **签名里没有模型可控入参** |
| agent 标识取值与 `BrowserOperationOrigin` **同一条规则**（`ConfigurationAgentInstanceId ?? AgentInstanceId`） | 否则"审计里的行动者"与"授权里的行动者"会不一致（审计里是谁、授权里是另一个） |
| 子代理判定取 `RuntimeExecutionKind.SubAgent` | 不用"有没有 `ParentRunId`"这种**可遗漏/可伪造**的推断 |
| 无执行上下文 / 无 agent 标识 / 子代理缺父任务 ⇒ 拒绝 | §3.2（授权要绑定任务、子代理只能取子集）；**不回退**环境推断 |
| 无 `RuntimeExecutionIdentity` 时**不**猜 | "没有可信身份来源"就是拒绝理由，而不是给个默认身份 |

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AgentTools.Tests` | **80 / 80**（＋2，含签名形状门禁） |
| **取红实测** | 把子代理恒判为 `Agent`（`isSubAgent: false`）⇒ 用例**变红**；还原即绿 |
| **全量链** | **1624 / 0**、一次通过、无重试 |
| code_map | 已登记新文件 |

## 决策①一页简报（我可以问得具体了）

**调用图事实**（本轮核对）：

1. `BrowserAutomationRequest` 的构造器**已经强制**携带 `BrowserCallerIdentity caller`（`BrowserControlContracts.cs`）⇒ **契约层不需要改**；
2. `IBrowserAutomationAuthority.Admit(request)` 的实现与授权逻辑**已完整且有 21+ 用例**（撤权级联、过期回收、同行动者判据、跨 Desktop/进程拒绝……）；
3. **但生产代码里没有任何地方调用 `Admit`**（grep 全仓：只有接口定义与实现）⇒ 准入闸门**尚未接在活路径上**。

**因此①其实就是一句话**：**身份能不能由 Core 在进程间声明？**

| 选项 | 含义 | 我能做的下一步 | 代价 |
|---|---|---|---|
| **A（推荐）** | **接受**：Core 在请求里带上投影出的身份（同上「显式声明 + 缺即拒」） | 在 Desktop/Host 的请求装配处填入该身份，并在 `Admit` 前 fail-closed 校验 | 需要动 **Host/Desktop 请求装配**（他方文件）：至少 1 处改动 |
| **B** | **不接受**跨进程身份：只认 Desktop **进程内**上下文 | 在 DesktopService 内基于连接世代/会话构造身份（Core 声明被忽略） | 多页/多任务区分能力下降；子代理委派的子集校验失去依据（B6 受限） |
| **C** | 暂不接（保持现状） | 我只做复跑与文档 | B1 的"准入"永久悬空；B6 同样悬空 |

**我只等你一句 A / B / C**（选 A 的话请顺带授权我改 Host/Desktop 的请求装配处，哪怕只授权那 1–2 个文件）。

## 诚实边界（诚实登记）

- **本轮仍未接活路径**：`BrowserCallerIdentitySource` 目前**没有生产调用方**（与它要修的问题同类——我先把"唯一的正确入口"建好，但不越界到别人文件里偷偷调用）。
- **`isSubAgent` 的判据来自编排层类型**：若编排层把子代理错误标记为 `ConversationTurn`，身份就会是 Agent —— 这属编排层责任，**未**加额外校验（登记）。
- **字段选择仍是我的取舍**（未纳入 `ToolCallId`/`InvocationId` 等）。
- **未真机验证**；②③④ 仍未拍板。
