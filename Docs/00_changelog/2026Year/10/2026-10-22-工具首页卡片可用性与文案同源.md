# 2026-10-22 工具首页：卡片说「可用」，说明却写「等待接入」

## 结论

评审清单第 10 项里「入口要诚实」这一半已落地：改动面 **4 个代码文件 + 2 份 code_map**，纯展示层与纯映射，不碰标签页生命周期、不碰 Core。

| 症状（改前） | 改后 |
|---|---|
| 交互面板卡片芯片 `可用`，副标题写「（等待接入）」 | 副标题来自 `CardSubtitle(Panel)`：`Agent 推送的媒体画布：…`，不再自称待接入 |
| 「新建终端」写着 `待接入`，卡片仍可点，点进去只剩一句占位说明 | `IsEntryEnabled(Terminal)=false` ⇒ 卡片禁用；「+」菜单的「终端 · 新会话」同步禁用 |
| 「制成品」写着 `待接入`，可 `PanelCraftStore` 早就落地（保存 / 列表 / 继续编辑 / 重命名 / 删除） | 按真实能力改为 `可用`，副标题改成它真正能做的事 |
| `DeferredNotice(Panel)` 里还留着「渲染通道还没建立」 | 删除（`For(Panel)` 恒为 Ready ⇒ 该分支永远不可达），只留注释说明为什么不该回来 |
| 卡片文案散落在 XAML、可用性散落在 catalog | 四项（可用性 / 芯片 / 副标题 / 可点）同源于 `ToolAvailabilityCatalog` |

## 为什么这样收，而不是各处改字

原实现的根子问题是**两个真源**：`ToolAvailabilityCatalog.For(kind)` 决定芯片，XAML 里手写的 `TextBlock` 决定说明，`Button` 的可点状态则没人管。三者只要有一处漏改，就会出现"同一个入口两种说法"——用户看到的就是谎。

所以把说明文字和可点状态都变成 `For(kind)` 的派生物，卡片本身不再持有任何能力判断：

```csharp
public static ToolTabAvailability For(ToolTabKind kind) => kind switch
{
    ToolTabKind.Terminal => ToolTabAvailability.Deferred,   // 只有标签页实例与状态位，不执行命令
    _ => ToolTabAvailability.Ready,
};

public static string CardLabel(ToolTabKind kind) =>
    For(kind) == ToolTabAvailability.Deferred ? "待接入" : "可用";

public static bool IsEntryEnabled(ToolTabKind kind) =>
    For(kind) == ToolTabAvailability.Ready;
```

XAML 侧把 5 个副标题换成具名 `TextBlock`（`PanelCardSubtitle` / `TerminalCardSubtitle` / …），由 `ApplyToolAvailabilityLabels()` 统一贴；`ApplyCard(kind, 芯片, 副标题, 入口?)` 是唯一的贴法，Shell 里不再写「这个能力行不行」。

## 取舍：制成品为什么从「待接入」改回「可用」

评审清单把「制成品」列在待接入里，但现场证据是它**已经能跑**：

- `PanelCraftStore`（Foundation，已在 ADR-099 落库）：保存、列表、继续编辑、重命名、删除到 `_trash`，并有独立的 471 例测试套件覆盖；
- 交互面板工具栏的「保存到制品库」是唯一主操作（accent），保存成功会回 `已保存到制品库：{title}`。

`ToolTabAvailability.Deferred` 的契约是"Shell 没有组件执行它"。制成品有组件，所以它标待接入属于**假阴性**——把能用的功能藏起来，和把不能用的画成可用是同一类错误。真正没接线的是 Core 侧的「Agent 成果接口」，而卡片承诺的从来是本机制品库，于是：能力记 `Ready`，说明文字改成 `从交互面板保存到制品库的画面，可继续编辑、重命名或删除`。这一条是我按证据改的判断，若你认为制品库还不够格露出来，改回 `Deferred` 只需动 `For` 那一行（说明文字与禁用会自动跟上）。

## 取红证据（能失败的校验才算校验）

新增 `CardSubtitle_never_contradicts_availability`：遍历**全部**枚举成员，`Ready` 的说明里不许出现「待接入 / 等待接入 / 尚未接入 / 暂未接入」，`Deferred` 的说明必须含「接入」。

- 变异：把 `CardSubtitle(Panel)` 改回 `…（等待接入）`（正是用户看到的那句）
  → `失败: 1，通过: 22，总计: 23`，失败例正是 `CardSubtitle_never_contradicts_availability`。
- 复原：`已通过! 失败: 0，通过: 471，总计: 471`。

另外两个断言把口径钉死：`IsEntryEnabled_follows_availability`（可点 = 可用）、`Every_enum_member_is_decided`（新增 `ToolTabKind` 成员必须显式选边且说明非空）。

## 验证方式与边界

- **单测**：`dotnet test Source\PuddingDesktop.FoundationTests` → **471/471 通过**（含既有 461 例 + 本次扩充）。
- **XAML/代码编译**：部署目录 `temp\build\winui3\bin\PuddingDesktop\…` 被正在运行的 PuddingDesktop(PID 123672) 锁住，`MSB3027/MSB3021` 属预期；改用隔离输出重编 `-p:BaseOutputPath=temp\build\winui3verify\bin\PuddingDesktop\` → **exit 0**，证明 5 个 `x:Name` 与 `ApplyCard` 都编得过。
- **未做**：没有重启宿主做肉眼验收（用户未授权部署重启），所以"禁用后的灰态是否够明显"仍待真机确认；`TerminalMenuItem` 禁用后终端入口完全不可达，这是有意的（它本来就点不出东西）。
- **未做**：`ToolTabKind.Document` 在工具首页没有卡片，只补了 `CardSubtitle` 映射，等首页加文档入口时直接复用。
