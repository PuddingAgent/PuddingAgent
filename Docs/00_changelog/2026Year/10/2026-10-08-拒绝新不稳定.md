# 2026-10-08 重跑吸收"新不稳定"默认拒绝

## 从"可见"到"规则"

round-159 让重跑的判定**可见**（known flake / NEW INSTABILITY）。但可见不等于拦住：
一个**未知**的失败仍然会被重跑吸收，清单照出。本轮把它变成规则：

```
retry-notes.txt 含 "NEW INSTABILITY"
  ├─ 未给 -AllowNewInstability ⇒ REFUSING to build a manifest + exit 2（并打印该行与处置建议）
  └─ 给了 -AllowNewInstability ⇒ 警告 "absorbing …" 后继续，并把原文照进清单
纯 known flake（无该字样）⇒ 不拦
```

**位置修正（本轮实际踩到）**：判定最初被我放在 `-SkipTests` 的**分支内** ⇒ 跳过测试时整段不执行（探针里表现为"照样出清单"）。
已移到分支之外：只要有 notes 就判定，与"谁跑的测试"无关。

## 两条路径的实证

### ① 拒绝路径（确定性：预置 notes + `-SkipTests`）

| 场景 | 结果 |
|---|---|
| notes 含 `NEW INSTABILITY`，未给开关 | **REFUSING … (exit 2)** + 打印该行 + 提示"查清它／有证据就登记进注册表／或显式 `-AllowNewInstability`" |
| notes 含 `NEW INSTABILITY`，给了开关 | `absorbing 1 retried suite(s) with NEW instability` ⇒ 正常出清单 |
| notes 只写 known flake | **不拦**，正常出清单 |

### ② 放行路径（实战：本轮 Host flake 复现）

```
--- retry 1/1 for PuddingHost.Tests
--- PuddingHost.Tests : first attempt failed 1 test(s): …SecondConnection_CannotReplaceAwaitingHelloConnection
--- PuddingHost.Tests green on retry (manifest will show it as retried; all of them are on the known-flaky registry)
=== manifest emitted (stage: ready-for-external-deploy)
```

清单里：`PuddingHost.Tests-retried`，notes 记录"首次失败 1 条 + 用例名 + 全部在注册表上"。
⇒ **round-159 未观测到的判定，本轮观测到了**（真实重跑样本）。

## 诚实边界（诚实登记）

- **本轮交付清单不是"一次通过"**：Host 首次失败（已登记的时序 flake）、重跑转绿 ⇒ 清单带 `-retried`。
- **`-AllowNewInstability` 是新的放行口**：给了它，未知不稳定就会被吸收（有警告 + 清单留痕），**不是**被隐藏。
- **判定基于 notes 文本匹配**（`NEW INSTABILITY` 字样）：改动该字样会让规则失效（门禁测试钉住脚本文案，减轻该风险）。
- **Host flake 仍未修复**（他方子系统），本轮只把它**分类**并（默认）拦在未知情形之外。
- **未真机验证**；B1 身份与 250ms 门限仍未拍板。
