# 2026-10-08 修复 CallerId 手写比较（仓库门禁）

## 发现方式

**全量交付链**（round-234，自 round-182 以来首次）在 `PuddingBrowser.AutomationTests` 报 1 条失败并指向
`BrowserTaskBindingService.cs:110` ⇒ 项目级测试覆盖不到，**只有全量链会红**。

## 修法（四处）

| # | 位置 | 改动 |
|---|---|---|
| ① | 签名 | `(string callerId, string? taskId = null)` ⇒ `(BrowserCallerIdentity task)` |
| ② | 空值检查 | `if (string.IsNullOrWhiteSpace(callerId)) { return 0; }` ⇒ `ArgumentNullException.ThrowIfNull(task);`（**行定位**） |
| ③ | `Where` 判据（两行） | ⇒ `.Where(pair => pair.Value.Task.IsSameTaskScope(task))`（任务级管理授权语义，门禁指引的 API） |
| ④ | 用例两处调用 | 改传 `new BrowserCallerIdentity(BrowserCallerKind.Agent, …)` |

## 过程教训（三轮才落地）

**CRLF 文件上的精确文本替换会静默失效**：②的 LF 版本替换没生效，导致 `CS0103: 不存在名称"callerId"`；
我一度误判为 `Where`/测试调用点的问题。**结论：结构性改动一律用行定位或 `edit` 工具，不用脚本拼文本。**
