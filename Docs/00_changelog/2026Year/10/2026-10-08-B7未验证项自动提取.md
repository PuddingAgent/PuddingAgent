# 2026-10-08 B7 未验证项自动提取：交付清单不可能再漏掉「内部证明不了」的结论

## 目标 / 背景

上一轮的交付清单**要求** `knownUnverified` 显式给出（`null` = 没想过 ⇒ 拒绝）。但字段要求只是形式：
**靠人回忆必然漏**。我在本会话每轮 changelog 里都如实登记了「真机未验证 / 需外部 smoke / 环境限制」，
这些正是交接时最该被写进清单的东西 —— 那就让它们**自动来自日志**。

## 改动

`Pudding.DesktopService/KnownUnverifiedExtractor.cs`（新增，纯文本分析）：

- **保守词表**：只认明确表示未验证的说法（`真机未验证`、`未经真机验证`、`需外部 smoke`、`未经外部`、
  `无法自证`、`环境限制` 等）；宁可少提取（人工能补），也不把「已真机验证」误判成未验证项 ——
  有专门用例钉住这条反向要求。
- **去重 + 保序 + 有界**（≤20 条、每条 ≤200 字符，超长截断加省略号）。
- 清掉 markdown 装饰（标题/项目符号/粗体/行内代码/表格竖线），输出适合写进清单的单行文本。
- **永不返回 `null`**（空列表 = 确实没有）—— 正好满足清单「显式给出」的要求。

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **253 / 253**（原 246 ＋ 7） |
| `Automation` · `Contracts` · `AgentTools` · `DesktopSurface.Browser` · `PuddingDesktop` · `Host` | 276/276 · 153/153 · 64/64 · 66/66 · 320/320 · 258/258 |

新增门禁：从 changelog 片段提取到「真机未验证」条目且装饰已清；去重保序；**反向要求**（「已真机验证」
「验证方式：外部控制器…」不得被提取）；空/空白输入 ⇒ 空列表（非 null）；长度与条数有界；
**真实语料**（读取仓库 `Docs/00_changelog/2026Year/10` 里本会话的 B3/B4/B7 日志）能提取到含「真机」的条目；
提取结果直接放进 `DeliveryManifest` 能通过校验（端到端一小步）。

**取红实测**：让提取器不再过滤（等于把所有行都当成未验证项）⇒ **5 条用例恰好变红**；
复原后 253/253 复绿。

## 已知边界（诚实登记）

- **词表是保守的**：只覆盖我实际用过的说法；新写法需要补词表（否则会漏）。这是刻意取舍 ——
  漏（人工可补）比误报（把已验证说成未验证）代价小。
- **不做语义理解**：例如「已在本机验证，但未在真机验证」这种混合句会被整条提取（有信息但不精确）。
- **还没接上交付流程**：提取器没有生产调用方 —— 缺的是"清单生成器"（汇总构建产物 + 各套件测试计数 +
  本提取器的结果 + 生命周期四步，产出合格 JSON）。这是 B7 的下一步，也是最后一块拼图。
- **没有持久化**：提取结果不落库。
- 真机无关（纯文本分析）。

## 影响与回滚

- **无对外行为变化**：新增组件尚无生产调用方。
- 回滚：删除 `KnownUnverifiedExtractor.cs` 与其测试。
