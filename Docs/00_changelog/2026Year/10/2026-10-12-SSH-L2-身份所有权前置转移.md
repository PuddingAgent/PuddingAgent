# 2026-10-12 SSH L2：身份所有权在交付 connect 前转移

## 目标 / 背景

独立复核 **F7（P2）**：`TransferLateOwnership()` 直到迟到回调执行时才置位；业务阶段超时返回时尚未置位，
finally 立即 `ReleaseIdentity()`，而迟到的 connect 可能仍在读材料（实测 `connect_pending=true`、worker=1，
但材料已全部清零）。按补充方案 §2 修补。

## 改动

- `Source/PuddingSsh/Execution/SshIdentityOwner.cs` — 新增单一 owner handle：
  `Unattached → LeaseOwned →(BeginConnect，**调用 connect 之前**)→ Connecting →(MarkSessionOwned)→ SessionOwned →(Release)→ Released`；
  转移与释放都原子且幂等，`ReleaseCount` 可观测。
- `Source/PuddingSsh/Contracts/SshPorts.cs` — `SshIdentityMaterial` 增加内部 `DisposeCount`：门禁断言
  「清零效果恰好发生一次」。
- `Source/PuddingSsh/Execution/SshResourceLease.cs` — 身份改由 owner handle 持有：
  `AttachIdentity`/`BeginIdentityConnect`/`MarkIdentitySessionOwned`/`ReleaseIdentity` 委托给它；
  `ReleaseIdentity` 只在整个租约的资源真正结束时调用（identity/connect/exec/close/迟到回收全部结束之后）。
- `Source/PuddingSsh/Execution/SshOperationCoordinator.cs`
  - 两个入口都在**建立 connect 请求之前**调用 `lease.BeginIdentityConnect()`；connect 成功后 `MarkIdentitySessionOwned()`；
  - `StageHandoff` 状态机改为 `BusinessOwned → AbandonedToLateOwner → Settled`：
    `WaitStageAsync` 返回 `Completed == false` 后**立刻** `MarkAbandoned()`（与停止选择不可分割），
    业务 finally 只做 `SettleFromBusiness()`（已放弃则空操作），迟到 owner 做 `SettleFromLateOwner()`。
    修掉了「义务被业务路径提前结算 ⇒ 迟到 owner 的关闭登记落在已完成租约上」这一 L1 遗留竞态
    （trace 证据：`EndBusiness obligations=1 → CompleteWork connect → RegisterWork close` 顺序正确）。
- `Source/PuddingSshTests/SshIdentityOwnershipTests.cs` — 新增 6 例：
  1. `LateConnect_PendingConnectKeepsMaterialReadable_ThenLateSuccessZeroesOnce`（非零合成字节；取消后材料**逐字节不变**，
     业务返回时资源已占账；迟到成功 → 关闭连接、零 exec、恰好清零一次）；
  2. `LateConnect_LateFailure_ZeroesMaterialOnce`；
  3. `LateConnect_TestEntry_KeepsMaterialReadableUntilConnectSettles`（第二个入口）；
  4. `LateSessionDisposeHangs_KeepsMaterialAndReportsPending`（迟到 Dispose 卡住：资源继续占账、Stop 如实报告、材料不清零）；
  5. `LateConnect_RacingWithBusinessReturn_ReleasesIdentityExactlyOnce`（8 轮竞争：`DisposeCount == 1`）；
  6. `LateConnect_NeverExecutesMarkerCommand`（deadline 之后交还的连接绝不执行命令）。

## 验证

- `dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **220/220 通过**，0 警告 0 错误。
- 定位过程中用临时 trace 证明「义务在业务结束时仍为 1、迟到关闭登记先于完成」，trace 已移除；
  L1 的 6 例与 R1–R5 的 208 例全部保持通过。
- 真实协议矩阵（L1 后复跑）：23 场景 `failures = 0`。

## 未完成 / 后续

  迟到完成不覆盖已确立的终止事实、`CleanupState` 关闭证据、诊断拼接后统一有界。
