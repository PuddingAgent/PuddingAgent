# 2026-10-08 B6 起点：子代理委派的授权信封与有界结论

## 目标 / 背景

B6（P2 子代理委派）此前**完全未开始**，且不依赖 B1/B4 那两个待决问题，因此本轮从它入手。
设计方案 §9 与门禁 G10 里有两条最容易走样的硬条件，先把它们做成**可执行**的：

1. **委派是受约束的任务，不是交出控制权**：范围只能收窄、注入工具必须够用（"父代理能发现七项工具"
   推不出"子代理可用"）、写入类任务必须真的拿到 `navigate`/`screenshot`；
2. **父代理只收有界结论**：默认 ≤ 2 KiB，可声明更小；不得含整页快照与内部对话。

## 改动

`Source/PuddingBrowser.Automation/SubAgentDelegation.cs`（新增，纯逻辑）：

| 类型 | 作用 |
|---|---|
| `BrowserDelegationEnvelope` | 目标、范围、页面 grant、期望结果、结果预算、注入工具、必需工具、截止时间 |
| `BrowserDelegation.TryValidate` | 逐条拒绝：缺目标/期望结果/页面 grant/正截止时间；**范围超出父授权**；预算非正或 >2 KiB；注入工具未覆盖必需工具；**写入类任务缺 navigate/screenshot** |
| `BrowserDelegationConclusion` | 父代理可见的结论形状：有界文本 + 字节数 + 截断标记 + Artifact/URL/operationId + 验证状态。**结构上没有整页快照与内部对话的字段** |
| `BrowserDelegationConclusionShaper.Shape` | 超预算即按 **UTF-8 字节**截断（**不切断多字节字符**）、标记截断、并把全文指向 Artifact |

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **286 / 286**（原 276 ＋ 10） |
| `Contracts` · `DesktopService` · `DesktopSurface.Browser` · `AgentTools` | 153/153 · 278/278 · 66/66 · 64/64 |

新增门禁：合格只读委派通过；缺目标/grant/截止时间各自被拒；**子范围超出父授权被拒**（读→写、读→manage 两种）；
注入工具未覆盖必需工具被拒；必需工具为空被拒；**写入类任务缺 navigate/screenshot 被拒**（补齐即通过）；
预算 512 通过、>2 KiB 与 0 被拒；小结论**逐字**通过（字节数按 UTF-8 计）；100 个中文字 + 30 字节预算
⇒ 截断到 **正好 10 个字 / 30 字节**、`Truncated=true`、指向 Artifact、**无替换字符**；无 Artifact 时仍如实标记截断；
null 文本 ⇒ 空串/0 字节/未截断；空验证状态与 0 预算抛参数异常。

**取红实测**：把 UTF-8 字节计数改成"每字符 1 字节" ⇒ `AnOversizedConclusion…` **恰好变红**（截断按字符而非字节，
中文会超预算）；复原后 286/286 复绿。

## 已知边界（诚实登记）

- **只有判定与形状，没有执行**：不签发授权、不启动子代理、不管理页面写租约（父子同页写租约互斥）、
  不接 Runtime 工具注入。这些属于 Core/Runtime 一侧，是 B6 的主体，**尚未开始**。
- **Artifact 只有标识没有落地**：`ArtifactId` 是引用；"全文以受权限约束的 Artifact 保存"依赖 B4 的
  artifact 字节归属决定（仍未决）。
- **信封字段是设计 §9 的直译**，未与 Runtime 现有 `spawn_sub_agent` 载荷对齐（对齐属接入阶段）。
- **`MaxResultBudgetBytes` 与默认值同为 2 KiB**：按方案当前要求写死；若将来支持"更大预算需审批"，需改判定。
- 真机/真模型无关（纯逻辑）。

## 影响与回滚

- **无对外行为变化**：新增组件尚无生产调用方（下一步是 Runtime 侧的签发与注入）。
- 回滚：删除 `SubAgentDelegation.cs` 与其测试、还原冻结表。
