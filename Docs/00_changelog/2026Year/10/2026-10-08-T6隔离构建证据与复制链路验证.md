# 2026-10-08 T6 证据：隔离构建可用、dist→wwwroot 复制链路已验证（仍因 dirty 不可交付）

> 范围：`TestScripts/verify-external-deploy-identity.ps1`（新增 `-ArtifactsRoot`）、
> `Docs/13_runbooks/外部部署与产品验收-上下文治理修复-2026-10-08.md`
> 依据：AGENTS「构建与验证隔离」「前端版本管理」「两段式验收」
> 前序：[T6 外部部署身份预检与验收 runbook](2026-10-08-T6外部部署身份预检与验收runbook.md)

## 1. 本轮验证掉的两件事

| 结论 | 证据 |
|---|---|
| **旧实例在跑也能构建 Core** | `dotnet build Source/PuddingAgent/PuddingAgent.csproj --artifacts-path temp/build/deploy` ⇒ **exit 0**（不触碰被运行中进程占用的 `Source/PuddingAgent/bin`，因此可以「先备好新构建 → 再停旧实例」） |
| **dist → wwwroot/admin 复制链路有效** | 隔离产物里 `bin/PuddingAgent/debug/wwwroot/admin` **308 个文件**，注入身份与 `dist` **完全一致**（版本 6.4.4 / 短哈希 7545ea1） |

## 2. 仍然 NOT READY，且原因已收窄到一条

预检（带 `-ArtifactsRoot`）实测：

| 环节 | 版本 / 短哈希 | dirty |
|---|---|---|
| `dist`（前端产物） | 6.4.4 / `7545ea1` | **true** |
| `served`（运行中 Core 读取） | 6.4.1 / `6e978cb` | true |
| `artifacts`（隔离构建） | 6.4.4 / `7545ea1` | **true** |

两条独立问题：

1. **产物带 `+dirty`** —— 工作树有并行写入方 WIP，任何在此树上的构建都不可复现 ⇒ 必须干净检出。
2. **Core 构建早于前端构建** —— HEAD 已是 `c34a695`，而构建出的 `wwwroot/admin` 身份仍是
   `7545ea1`（上一份 dist）。因为 Core 构建只是把 **dist 当时的内容**复制过去
   （`PuddingHostContent.props`）。⇒ **必须先重建前端、再构建 Core**，顺序写进 runbook。

## 3. 交付物变化

- 预检脚本新增可选 `-ArtifactsRoot`：核对隔离构建产物，使控制器**在停机前**就能判断新构建身份对不对；
  并对 artifacts 施加与 dist 同强度的约束（版本/短哈希一致、不得 dirty）。
- runbook §3.3/§3.4 改为「先前端后 Core」的显式顺序 + 两种构建方式（隔离/直接），
  §4 实测表补上 artifacts 行与上面两条已验证结论。
