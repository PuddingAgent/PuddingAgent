# 2026-10-18 统一打开身份口径修复与Core端到端验证

## 改动

- `ConversationOpenApiController.ResolveOwnerUserId` 与 `AgentChatApiController.ResolveOwnerUserId` 改为优先 `ClaimTypes.NameIdentifier`（JWT sub），缺失才回退 `Identity.Name`（显示名）。
  - 根因：JWT `Name` 是 `Administrator`，会话 `OwnerUserId` 是 `admin`/`single-user`；统一打开首次实测因此 404。
  - 旧投影曾对 redirect/MainSessionId 候选只校验 workspace、不校验 owner，才“碰巧”可用；本次保持解析仍校验 workspace/owner。
- 新增控制器测试：显示名 `Administrator` + `nameidentifier=admin` 必须成功打开（6/6）。
- `Docs/14_reports/会话加载优化阶段D端到端验证-2026-10-18.md`：临时 Core 真实库测量与副作用记录。

## 验证

- `PuddingPlatformTests.ConversationOpenApiControllerTests`：**6/6 通过**。
- `PuddingWebApiTests.AgentChatApiControllerTests`：**21/21 通过**。
- 构建：`PuddingAgent`（含前端 6.9.0 产物）0 error。
- 临时 Core（127.0.0.1:5199，真实 `D:\data`，3,120,332 事件）：
  - 旧 `/conversation`：p95 **514.1ms**（修复前基线 5.5–6.6s）；
  - 新 `/conversation-open`：p95 **111.7ms**；快照 C=1,818,847 / H=1,818,848、20 条消息、Partial + Ready、hasMore=true；
  - `/history` 20 条 hasMore=true；`/process` 20 项 ItemLimit；正文端点短消息全文 2,897 字符。
- 详细数字与局限见阶段 D 验证报告。

## 未完成与影响

- 临时 Core 首次启动因 idle heartbeat 触发了一次 Agent 回合、SessionChunkBackfill 也被启动；发现后已立即停止 Core，未删用户数据。验证前备份仍在 `temp/test-out`。
- 未正式部署到产品 `wwwroot/admin`、未启动 Desktop/WebView2；旧 `/conversation` p95 514ms 仍高于 200ms 目标，不能宣告用户可感知达标。
- 真实库 `system.json` 的 TaskAutoDispatch authoritative 与 GoalRuns 默认值不匹配，现行源码在真实库启动会被 Options 校验拒绝（验证时用环境变量关闭）；需单独修复后才能做产品级启动验收。
- D2c3/D3c（活动 Turn 终态物化、连接状态驱动轮询、退役旧入口）与阶段 E/F 仍待做。
