# Desktop 启动状态面板

## 1. 背景

点击「启动 Core」后到 Web 工作台出现之前，旧主页只显示一句固定的「等待独立 Core 就绪…」：按钮仍可点、没有进度、没有耗时；Core 已就绪、WebView 还在加载时文案仍在说「等待 Core 就绪」（状态说谎）；失败只把异常原文塞进同一行文字。而实测启动为干净机 3.7–6.5 s、争用 21.5 s+、冷升级可超过 60 s（[归因报告](../../../14_reports/Core启动耗时归因-2026-09-30.md)），只加一个转圈不足以让用户知道在等什么、还要等多久、能不能退出。

设计稿（居中式启动面板、状态矩阵、动效与视觉 token、交互原型）在本地 `temp/design/desktop-startup/` 下产出，未纳入版本控制；本日志只记录落代码的部分。

## 2. 改动

### 2.1 Foundation（纯 BCL，可单测）

- `Source/PuddingDesktop.Foundation/StartupPanelPresenter.cs`（新增）：`StartupPanelPhase/Tone/Action/StepState` + `StartupPanelInput/Step/Model` + `Present`，把 13 个启动相位映射成标题、阶段文案、三步状态、耗时/慢启动提示、主/次按钮、错误摘要、状态条文案与色调；`StartupErrorText.Describe` 按序把 supervisor 的英文异常收敛成中文人话（并保留原始错误供折叠详情）。
- `Source/PuddingDesktop.Foundation/StartupPhaseActivity.cs`（新增）：从 `CoreLogBuffer.Snapshot()` 尾部解析 `[StartupPhase] <phase> total=…` 行，聚合为「启动进程 / 初始化数据与索引 / 初始化本地服务 / 本地接口」等可读阶段，并给出「最新输出」；日志格式不进入 XAML。
- `Source/PuddingDesktop.FoundationTests/StartupPanelPresenterTests.cs`（新增）：232 个用例覆盖 13 相位、15 s 慢启动边界、秒格式、错误文案 11 条规则优先级、`[stdout]`/行内 marker/多阶段取最后/空 tail、步骤状态含「进程阶段不提前完成第一步」。

### 2.2 Shell

- `Source/PuddingDesktop/MainWindow.xaml`：把原 `LoadingPanel`（标题 + 一句话 + 按钮）替换为状态面板——32 px ProgressRing、标题、阶段行、三步步骤条（待开始/进行中/完成/失败四套预置视觉，颜色全部 `ThemeResource`，新增 Light/Default/HighContrast 三套启动面板画刷）、耗时/慢启动提示、最新输出、错误摘要 + 提示 + 可折叠原始错误、主按钮 + 运行中心/启动设置链接。底部状态条改为「圆点 + 文案」，圆点按语义色调切换预置椭圆；「启动设置」导航项补 `x:Name` 以支持面板跳转。
- `Source/PuddingDesktop/MainWindow.xaml.cs`：新增启动面板状态机与动作接线——200 ms 精确计时器只在启动/取消/加载工作台/等待重启相位运行；`Stopwatch` 计时并在 CoreReady 记录「Core 启动耗时」；点击「启动 Core」后先乐观进入启动中（消除点击空窗）；取消走已有的 `StopCoreAsync`（`_startCts` 取消进程树），期间显示「正在取消」，结束后回未启动并短暂提示「已取消启动。」；重试按相位分流（Core 失败→启动 Core，工作台失败→只重载 WebView）；「查看日志/运行中心」跳运行中心、「启动设置」跳设置；底部状态条文案由 presenter 统一产出（含中文状态与已用秒数）。
- `Source/PuddingDesktop/MainWindow.xaml.cs`：顺带修两处既有缺陷——① Core 就绪时点「启动/重试」不再绕过 `_webGate` 直接关 WebView，统一走 `ReloadWorkbenchAsync`；② WebView2 阶段补 20 s watchdog，`NavigationCompleted` 失败/`ProcessFailed` 会显示失败面板（旧实现失败可能不显示面板、挂起则无限停在加载态）。
- `Source/PuddingDesktop/MainWindow.xaml.cs`（Debug smoke）：`WaitReady()` 之前抓 `smoke.startup.png` 并断言面板可见 + 进度环 active；Ready 后断言面板已收起、环停止。新增 `SavePngAsync` 复用两处截图逻辑。

## 4. 未完成与边界

- **自动恢复次数提示未显示**：`RestartScheduled` 的「第 n/m 次自动恢复」需要 `RestartMaxAttempts`，当前 `DesktopRuntimeSnapshot` 未暴露 MaxAttempts；presenter 侧该 Meta 在缺 Max 时按契约隐藏。待协调器暴露配置后只改输入一行。
- **深色/高对比未人工截图复核**：颜色全部走 `ThemeDictionaries`（Default=深色 / Light / HighContrast 系统色），浅色已由 smoke 截图验证；深色与 HC 需要下一次进程外验收时截图确认。
- **真实阶段为聚合粒度**：UI 显示的是 4 组阶段，且依赖 `[StartupPhase]` 行格式（已在 Foundation 单测钉住）。若要把每个 schema bootstrapper 都展示，需要协议 v2（`PUDDING_DESKTOP_STARTING` 携带真实 phase），本次未做。
- **两段式验收未完成**：本次只完成 build/test/Debug smoke；`dotnet publish` / `delivery-manifest.ps1` / 外部 controller 重启后的 lifecycle 观测未跑（按 AGENTS 由外部控制器判定）。
- 取消后的「已取消启动。」提示只在 UI 停留 3 s，未加自动化断言。
- 启动面板的文案契约、原型与设计稿在 `temp/design/desktop-startup/`（忽略目录），不随交付物流通。
