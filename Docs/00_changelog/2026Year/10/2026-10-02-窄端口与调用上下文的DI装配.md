# 2026-10-02 窄端口与调用上下文的 DI 装配（含 Bridge 回退发现）

## 目标 / 背景

上一轮做完上下文工厂后，本轮做装配。装配过程中发现一个**会让 Bridge 路径拿不到上下文**的缺口，
因此把两件事一起做完并记录结论。

## 发现：Desktop 实例 ID 有**两个真实来源**，不能只看能力通道

窄端口九个方法都要求 `DesktopCallContext`。上下文工厂需要 Desktop 实例 ID，而它**并非只有能力通道才知道**：

| 情形 | 实例 ID 的真实来源 |
|---|---|
| 能力通道已启用 | 活动会话的 `DesktopSession.DesktopId`（会话自己会校验调用里的 DesktopId 与它一致） |
| **通道未启用（Bridge 路径）** | **既有 Bridge 连接的 `DesktopBrowserConnection.DesktopInstanceId`**（同样来自握手） |

本轮实读确认 `DesktopBrowserConnection.DesktopInstanceId` 存在且由 hello 握手填充 ⇒
**不需要**给 Bridge 路径发明占位 ID，也不需改动窄端口签名；工厂的"当前活动 Desktop"解析
只需按"通道会话优先、Bridge 连接回退"两来源实现即可。少了这条回退，走 Bridge 的工具根本拿不到
调用上下文（这正是本轮装配时撞到的）。

## 改动

`Source/PuddingHost/BrowserBridge/BrowserBridgeServiceCollectionExtensions.cs`（仅在
DesktopChild + 启用浏览器自动化时注册，与原有 Bridge 装配同一处）：

- `IDesktopBrowserCapabilitySurface` → `BridgeBrowserCapabilitySurface(IBrowserRuntime)`；
- `IDesktopCapabilityCallContextFactory` → `ConnectedDesktopCallContextFactory`，
  解析顺序：**能力通道活动会话 → Bridge 当前连接 → null**（两者都取自各自握手，绝不猜）；
- 新增 `using Pudding.Contracts.Desktop;`。

## 验证

- `PuddingHost` 构建 **0 错误**；
- 现有套件不受影响（本次只加注册，尚无消费方 ⇒ **运行实例行为不变**）；
- **未验证**：装配后的解析行为（需要真实 Bridge 连接/通道会话），属外部窗口期验收范畴。
