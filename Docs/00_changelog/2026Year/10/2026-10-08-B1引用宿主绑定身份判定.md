# 2026-10-08 B1 引用宿主绑定身份：同版本下"节点被换掉"必须被认出来

## 目标 / 背景

设计 §1.1/§5：「**禁止自动重绑**；Snapshot ref 必须携带 PageVersion」——后续又要求 ref 能证明
「还是同一个节点」。现状（`WebView2DomClient.ValidateLocator`）只校验 **页面 token + 文档版本 + 序号**
（格式 `p{token}-v{version}-n{index}`）。

这在 SPA 里有一个**真实的错位读取缺口**：页面原地重渲染、我们的版本计数**没动**时，
同一个位置的序号指向的是**另一个节点** —— 校验通过、动作打在别的元素上。

这条此前一直被登记为「卡在 CDP」（需要宿主侧节点身份）。上一轮把 `SendCdpAsync` 真正打通后，
具备解锁条件。本轮按组件交付顺序先做**可验证的判定层**。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| Automation | `BrowserNodeIdentity.cs`（新增） | ① 身份记录 `Identity(PageToken, Version, NodeIndex, BackendNodeId?)` 与编码 `p…-v3-n7-b42`（**没有身份时不追加后缀**，旧引用照旧可解析）；② 判定表 `Judge(recorded, observed)`：`Valid` / `Replaced`（位置一致但节点被换，**必须拒绝**）/ `StaleVersion` / `WrongPage` / `Unverifiable`（任一侧无身份）；③ `IsSafeToProceed` / `ErrorCodeOf` / `Describe`，④ `WithHostIdentity`（追加或替换身份，**拿不到就原样返回，不编一个 id**） |

判定顺序是刻意的：**先判明确的错误**（别的页面 / 旧版本 / 节点被换 / 序号对不上），
最后才落到"无法证明"——否则一条指向别的页面的旧引用会被报成 `Unverifiable` 而蒙混过关。

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **227 / 227**（原 217 ＋ 10） |
| `PuddingDesktop.Tests` | 318 / 318 |

新增门禁（10 条）：

- 编码/解析往返（带与不带宿主身份）；旧引用解析后身份**如实为 null**（不猜、不补 0）；
- 9 类畸形 ref 全部拒绝；
- 同页同版同序号同身份 ⇒ `Valid`，且 `ErrorCodeOf` 为 null；
- **同位置不同节点 ⇒ `Replaced`**，不可继续、错误码 `stale_element_reference`、提示要求重新观察；
- 同页同版但序号对不上 ⇒ 与"节点被换"同义（序号不可信）；
- 版本/页面不符 ⇒ 沿用既有"引用过期"语义；
- 缺身份 ⇒ `Unverifiable`（**不是** Valid），可继续但提示"既未确认也未拒绝"；
- 「页面不同 + 双方都无身份」⇒ 仍判 `WrongPage`（判定顺序的回归保护）；
- `WithHostIdentity` 追加/替换/拿不到时原样返回；页面 token 大小写不造成误判。

**取红实测**：把"身份不同即 Replaced"改成"只要记录了身份就 Valid"⇒
`SamePositionButDifferentNode_IsReplaced_AndMustBeRejected` **恰好变红**；复原后 227/227 复绿。

## 已知边界（诚实登记）

- **还没接线**：驱动尚未采集 `backendNodeId`（需要 CDP 探针把句柄/节点映射到宿主身份），
  因此 `ValidateLocator` 目前仍只做既有的 token/版本校验；`Replaced` 判定**尚未在生产路径生效**。
  这是 S1（先独立测试）的刻意顺序：判定规则先钉死，采集与接入是下一步。
- **`Unverifiable` 是"允许但未证明"**：宁可在回执/告警里如实标注，也不把未知当有效；
  但这也意味着在接线上线前，旧引用与新引用的严格程度会不同（这是有意的过渡态）。
- **序号对不上判 `Replaced` 是保守选择**：它可能掩盖"定位结果本身变了"的另一种原因；
  两种原因对调用方的处置相同（重新观察），因此没有继续细分。
- 真机未验证（本环境无 WebView2）：CDP 侧"如何稳定拿到 backendNodeId"（`DOM.describeNode` /
  `DOM.getDocument` 的成本与失效时机）需要外部 smoke 决定。

## 影响与回滚

- **无对外行为变化**：新增的是纯判定组件（尚无生产消费方）。
- 回滚：还原 `BrowserNodeIdentity.cs`、其测试与 code_map / frozen 列表条目。
