# 2026-10-08 B6 跨子系统接线方案（只读勘查，不改代码）

## 目标 / 背景

上一轮把浏览器侧的委派件补齐了，但接线点在 **`PuddingRuntime`/`PuddingCore`**（另一子系统）。本轮**只读勘查**，
产出一份可施工方案，明确"改哪里、缺什么、被什么挡住"——**不改一行代码**。

## 勘查结论（写入 [接线方案](../../../12_features/B6-子代理委派接线方案-2026-10-08.md)）

1. **出站（信封）不需要新字段**：`SubAgentSpawnRequest` 已有
   `AssignedObjective` / `ExpectedOutputContract` / `ExecutionDeadlineUtc` / `CapabilityPolicy.AllowedToolNames`，
   信封六个字段里有五个可直接映射；施工点唯一：`SubAgentTool.ExecuteCoreInternalAsync` 组装请求处
   （仅对浏览器类任务加一段，用 `BrowserDelegationTasks.TryCreate` 产出信封并收窄 `CapabilityPolicy`）。
2. **入站（结论）挂在既有字段上**：父代理看到的是 `SubAgentExecuteResult.Reply`，
   在它被组装进 `spawn_sub_agent` 输出前走一次 `BrowserDelegationConclusionShaper.Shape(...)` 即可；
   **全文 Artifact 依赖 B4** 的字节归属决定 —— 决定未定前只能"截断 + 显式 Truncated"，**不能假装有 Artifact**。
3. **唯一真缺的契约**：**页面 grant 与读/写范围**如何随 `spawn_sub_agent` 下传。给了三个选项，
   推荐 A（新增一个容量受限的浏览器委派字段，由内部路径填充），**永久排除** C（让模型在 JSON 里自带 grant
   —— 等于模型自授页面写权，违反 §8/§9）。
4. 方案还写明**不得改动**的部分（批量/同步/模型路由语义、既有字段语义、不在浏览器侧复刻授权判定）
   与**测试计划**（信封映射、期限关系、结论有界、只读委派可跑通、写租约接线）。

## 已知边界（诚实登记）

- **方案未被执行**：没有任何一行 Runtime 代码被改动，因此 B6 的委派**仍未接通**。
- **被两个待决问题挡住**：第 1 步（grant 契约）依赖 **B1/授权签发决定**；第 3 步（全文入 Artifact）依赖
  **B4/字节归属决定**。只读范围（`CanRead=true`）可先做第 2、3 步的一部分 —— 但**仍需跨子系统 owner 同意**。
- **行号会腐烂**：方案里以**符号名**（类型/方法/字段）定位，不写行号，正是为了避免文档过期即误导。
- **未评估性能与并发影响**：委派链路的开销不在本轮范围。
