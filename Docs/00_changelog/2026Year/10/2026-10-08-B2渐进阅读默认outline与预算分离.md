# 2026-10-08 B2 渐进阅读：browser_snapshot 默认 outline + 输出/扫描预算分离

## 目标 / 背景

设计把「渐进阅读」列为省 token 的**主收益点**：默认只给「能点什么、能填什么」，
而不是把整棵 DOM 与无障碍树一起倒给模型（旧默认 `include_dom=true` + `include_accessibility_tree=true`
+ `max_text_length=200000`）。本轮把默认阅读面收敛到设计预算（§6.1：50 行 / 4 KB / 内部扫描另算）。

## 改动

### 阅读面收敛（纯逻辑，`PuddingBrowser.Automation`）

`Source/PuddingBrowser.Automation/BrowserReadingFormat.cs` — 新增：

- `BrowserReadingMode`：`Outline`（默认）／`Interactive`／`Text`／`Full`；
- `BrowserReadingFormat.Compose(tree, request, scanTruncated)`：按模式**只做投影不编造**——
  - `outline` = 带 `ref=` 的行（**驱动自己**对"可交互"的标记，不是我们猜的）+ 标题/地标结构行；
  - `interactive` = 只留带 `ref=` 的行；
  - `full` = 全量，**不施加输出预算**（排障模式；否则「full」会静默变成另一个有预算的模式）；
  - 常量：`DefaultLineLimit=50`、`DefaultMaxBytes=4096`、`ScanMaxNodes=10_000`、`ScanMaxTextLength=200_000`、`ScanMaxDepth=64`；
- **输出预算与内部扫描预算分离**（设计硬要求）：截断如实区分
  `IncompleteScan`（扫描侧被截断 ⇒ **可能缺整片区域**，不给游标）与
  `OutputBudget`（扫描完整，仅输出收敛 ⇒ 给 `NextCursor` 续读）；
- 字节口径是 **UTF-8**（模型看到的是字节预算）；单行超预算仍返回该行（否则永远读不到东西）但如实标注；
- `BrowserReadingFormatWire`：线名与 fail-closed 解析（未登记值抛异常）。

### 工具（`browser_snapshot`）

`Source/PuddingBrowser.AgentTools/BrowserSnapshotTool.cs`：

- 新增 `mode`／`limit`／`max_bytes`／`cursor`；
- `outline`/`interactive`：**不采集 DOM 树与 HTML**（体积大头），只要无障碍树，
  并用**内部扫描预算**请求（10k 节点 / 64 层 / 200k 文本），输出再按 `limit`/`max_bytes` 收敛；
- `full`：显式开启，沿用调用方给出的完整预算（旧的 `include_dom`/`max_nodes`… 变成 full 专用）；
- `text`：返回 `browser_operation_not_supported`，**不静默降级成 full**（否则调用方会以为拿到了正文）；
- 输出新增 `mode`/`truncationReason`/`nextCursor`/`returnedLines`/`bytes`；
  outline/interactive 下 `domText`/`html` 为 `null`，`accessibilityTree` 是收敛后的投影（形状不变，避免破坏既有消费方）。

新增门禁（关键几条）：

- `Snapshot_DefaultsToOutline_AndDoesNotRequestTheDomTree`（工具层）：断言**发给驱动**的采集预算
  `includeDom=false`／`includeHtml=false`／`includeAccessibilityTree=true`／`maxNodes=10000`，
  并断言输出 `domText=null`、`bytes>0`、结构行保留而容器行被丢；
- `Snapshot_OutputBudget_ReportsCursor_AndScanTruncationReportsIncomplete`：
  行数收敛 ⇒ `output_budget` + `nextCursor`；扫描截断 ⇒ `incomplete_scan` + **无游标**；
- `Snapshot_TextMode_IsExplicitlyUnsupported_NotASilentFallback`：错误码 `browser_operation_not_supported`
  且消息含「not implemented」；
- `BrowserReadingFormatTests`（14 条，纯逻辑）：模式过滤、full 不设预算、游标续读不重复、
  UTF-8 字节口径、单行超预算仍返回、非法预算取红、**合成大树下默认模式收敛到 ≤4 KB 且 full 远大于它**。

**取红实测**：把 outline 分支的 `includeDom: false` 改成 `true`（放开 DOM 采集）⇒
`Snapshot_DefaultsToOutline_AndDoesNotRequestTheDomTree` **恰好变红**，其余 25 条仍绿；复原后 26/26 复绿。

## 已知边界（诚实登记）

- **没有真实页面的字节测量**：合成大树上的收敛数字（≤4 KB）是**确定性断言**，不是真实页面实测；
  真实站点（TestSite / 目标站点）的字节数需外部进程内 smoke 复核。设计里的「11 KB → ≤1.5 KB」目标
  本轮未在真实页面上验证。
- **`text` 模式未实现**：正文 markdown 需要驱动侧正文提取（`article`/`main` 优先、区块回退），
  驱动脚本与 WebView2 真机执行本环境无法验证 ⇒ 本轮明确 unsupported，**没有**伪造实现。
- **`outline` 的行格式仍是驱动的无障碍树行**（如 `button ref=… name="…"`），不是设计里的
  `- [ref] 角色 "名字" (x,y,w,h)`；行格式迁移需要先有 normalized reading 输入模型。
- **`sinceRevision` / `fields` / `scope` 未实现**（设计 §6.1 的其余参数）。
- **`locate` 的 text 匹配修复、隐藏过滤、bbox 取整仍未做**（同属 B2 其余部分）。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_snapshot` 默认只返回 outline 投影，`domText`/`html` 为 null；
  需要完整树必须显式 `mode=full`。既有消费方若依赖默认全量输出会被影响 —— 这是设计要求的收敛。
- 输出字段为**新增**，没有删除既有字段名（`accessibilityTree` 语义变为「按模式的投影」）。
- 无数据/配置影响；线缆 DTO 与 proto 未改动（判定与收敛都在工具/组件层）。
- 回滚：删除 `BrowserReadingFormat.cs` 与其测试，还原 `BrowserSnapshotTool.cs`/`BrowserToolContracts.cs`
  /`BrowserAgentToolsTests.cs` 与三处 code_map。
