# 工具曝光有界化与固定前缀削减

## 目标 / 背景

2026-10-22 的压缩归因显示：本会话压缩后请求中位 **314 KiB（61.3% × 512 KiB 上传预算）**，其中固定开销 **114.5 KiB（37.8%）**；最大单项是**工具定义 JSON 72,600 B / 25,165 tokens（23.4%）**。根因是 `ToolExposurePlanner` 的「可见集 = core ∪ loaded ∪ committed ∪ 上一轮可见」只增不减：长会话通过 `search_tools` 逐步加载（并从 composition 记录水合）到 **121 个工具**，全部 schema 每轮随请求发送。

本轮把工具 schema 投递面收敛为**有界工作集**：默认每轮最多 48 个工具 / 40 KiB 序列化字节（`toolExposure` 配置节，可关闭或按轴调整），核心工具永不淘汰，淘汰按「最近使用 → 上一轮可见顺序 → canonical」排序，并且只在 **dispatch（turn）边界**重算；被淘汰工具仍在 catalog 与授权范围内，可由 `search_tools` 重新加载。

## 改动

- `Source/PuddingCore/Runtime/SubAgentInvocationContracts.cs`：新增 `ToolExposureOptions`（`Enabled=true`、`MaxVisibleTools=48`、`MaxVisibleToolBytes=40*1024`）与 `RuntimeExecutionOptions.ToolExposure`；0 表示该轴不限制。
- `Source/PuddingRuntime/Services/Tools/ToolExposurePlanner.cs`：新增 `ToolExposureBudget` / `ResolveBudget`；`CreatePlan` 末尾追加可选 `budget` 与 `toolUsageRecency`；预算内按「最近使用 → 上一轮可见顺序 → canonical」选择，**能力包原子取舍**（terminal/git/读写族不得切半）；plan 新增 `VisibleToolBytes` / `BudgetApplied` / `EvictedToolIds`；`RegisterSearchResult` 新增 out 参数返回本次新加载 ID。
- `Source/PuddingRuntime/Services/AgentSessionManager.cs`：新增进程内工具最近使用序（`TouchToolUsage` / `GetToolUsageRecency`，会话隔离、单调递增）；重启后首轮无信号时按上一轮可见顺序确定性回退。
- `Source/PuddingRuntime/Services/AgentExecutionService.cs`：`BuildFrozenToolManifest` 读取 `toolExposure` 配置并投影为预算，传入使用序；新增 `[AgentExec:ToolExposure]` 日志（available/visible/evicted/visibleSchemaBytes/budget）；`BuildFrozenToolManifestCore` 追加可选预算/使用序参数（既有测试调用不变）。
- `Source/PuddingRuntime/Services/AgentExecution/AgentExecutionService.Streaming.cs` / `AgentExecutionService.Buffered.cs`：工具清单与可见集在**上下文装配之前**冻结；`ContextRequest.LoadedToolIds` 改传**有界可见集**，使 L1-TOOLS 的 Available/Deferred 名单与本次 schema 投递面同口径；工具执行与 `search_tools` 新加载时记录使用序；同一 dispatch 内 `PromoteLoadedToolsForNextRound` 仍为 append-only，不做预算收缩。
- `Source/PuddingRuntime/Services/LlmRequestTextBudget.cs`：新增 `MeasureTool`（同 `MeasureTools` 序列化口径），预算与请求字节统计同源。
- `Source/PuddingRuntime/Services/RuntimeExecutionConfigService.cs`：`toolExposure` 规范化（负值夹回 0）并在首次读取时把默认节种入 `runtime.execution.json`。
- `Source/PuddingRuntime/Tools/BuiltIns/Search/SearchToolsTool.cs`：更新 `max_results` 描述（有界工作集、可能被淘汰、可重新加载）。
- 测试：新增 `Source/PuddingRuntimeTests/Services/ToolExposureBudgetTests.cs`（计数预算/字节预算/无 search_tools 不淘汰/能力包原子/Manifest 接线）；`AgentSessionManagerTests` 增最近使用序用例；`RuntimeExecutionConfigBudgetTests` 增默认节种入与负值夹取。

## 验证

- `dotnet build Source\PuddingRuntime\PuddingRuntime.csproj --no-restore --nologo`：**0 errors**（81 个既有 warning，无新增 error）。
- `dotnet build Source\PuddingRuntimeTests\PuddingRuntimeTests.csproj --no-restore --nologo`：**0 errors**。
- 聚焦回归（ToolExposure / AgentSessionManager / ToolDiscovery / ToolCapabilityBundle / RuntimeExecutionConfig / ToolProfileHeartbeat）：**49/49 passed**。
- 全量 `PuddingRuntimeTests`：**2214 passed / 6 failed / 7 skipped**。6 个失败均与本改动无关，已用 `git stash -u` 在干净基线上复现：`HostShellExecutor_Sets_Utf8_Python_Output_Environment`（本机无 python）、4 个 `Terminal*`（终端环境）、`DirectLlm_FailureAndRetryLogs_CarryTheDiagnosticContractFields`（既有日志契约）。
- `cmd /c Tools\Dev\build-all-tests.cmd`：**RESULT: all ok**（全部 `Source/*Tests` 编译通过；`NOCSPROJ` 为既有无 csproj 目录）。
- 预计效果（按现网 121 工具 / 72,600 B、平均 ~600 B/工具估算）：48 工具约 **29 KB**，固定前缀减少约 **43 KB**；压缩后请求约 **314 KiB → 271 KiB（~53%）**，落到 60% prepare 线以下。真实字节需新 Core 加载后从 `[AgentExec:ToolExposure] visibleSchemaBytes` 与 `llm_gateway` 请求日志核对。

## 未完成

- **未部署**：需外部控制器重启 Core（当前进程不会加载新代码）；部署后核对日志中 `available=121 visible≤48 evicted>0 visibleSchemaBytes≈29KB`，以及一轮压缩后的 `estimatedRequestTextBytesAfter`。
- 未实测真实 Agent 的 48 个工具选择是否覆盖其常用工具；如出现频繁重新加载，可上调 `maxVisibleTools`/`maxVisibleToolBytes`。
- 未改「已授权但未暴露工具仍可执行」的现状（可见集不是安全边界，撤权仍由 Firewall 负责）；未加未暴露调用拒绝。
- 未调整其他固定前缀项（系统提示 42.6 KiB、技能/工具目录）。
