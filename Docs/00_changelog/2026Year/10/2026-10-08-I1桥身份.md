# 2026-10-08 I1 第六步：Bridge 传输携带类型化身份

## 改了什么

| 层 | 变化 |
|---|---|
| Contracts | 新增 `BrowserCallerRequirement.TryRequireCaller`（**唯一一份规则**）；`DesktopCallContext.TryGetBrowserCaller` 改为**委托**它（避免两条路径各自判） |
| Protocol | `BrowserBridgeCommand.Caller`（线缆形态 `BrowserBridgeCallerIdentity`：kind/callerId/taskId/parentTaskId，**字符串 kind**）；新增错误码 `browser_unauthorized` |
| Host（Core 侧） | `RemoteBrowserRuntime` 从 `IBrowserCallerIdentityAccessor` 取身份写入每条命令；**缺身份/冒充 User/无运行身份 ⇒ 不发送** |
| Desktop 侧 | `DesktopBrowserBridgeClient` 解析 caller（未知 kind / 空必填 / 子代理缺父任务 ⇒ 拒绝）→ 套用同一规则 ⇒ 缺身份只回 `browser_unauthorized` 结果，**不执行** |

**为什么线缆 DTO 不直接用领域记录**：`PuddingBrowser.Protocol` **不引用** Contracts（薄线缆包）⇒ 在包内定义 wire 形态，两侧映射；
kind 用字符串的理由同能力通道：proto/JSON 默认值会把"没填"当成某个类别。

## 验证

| 项 | 结果 |
|---|---|
| **闭环（Host 桥集成）** | **3 / 3**：工具 → 运行时 → 命令（带身份）→ Desktop 执行 ⇒ 身份**真的**全程流动 |
| Host 侧新用例 | **3 / 3**：命令带可信身份（含子代理+父任务）、缺身份**不发送且 broker 零命令**、User 冒充被拒 |
| Desktop 侧新用例 | **1 条**：缺 caller 的命令**不执行**、回 `browser_unauthorized` |
| 客户端既有用例 | 8 → **9 / 9**（同步 1 条消费方后全绿） |
| runtime 既有用例 | 14 / 14（同步类级可信身份作用域后全绿） |
| **全量链** | 见下方补记 |

## 诚实边界（诚实登记）

- **协议仍是 v1**：`DesktopCallContext` / Bridge 身份字段都是**新增**，v1 端不会发送 ⇒ "旧新配对明确拒绝"仍待 **v2 升级**那一步（约 46 条硬编码 v1 的用例需同步）。
- **仍未调用 `Admit`**：身份现在**两条传输都能到达 Desktop 并被校验**，但准入/租约（I2）未接。
- **Desktop 侧只校验、不落库**：尚未把身份绑到 grant/租约（I2）。
- **`Origin` 仍是审计用途**：本轮明确没有用它替代授权身份（方案原话如此）。
- **未真机验证**。
