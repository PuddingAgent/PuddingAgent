# 2026-10-12 SSH B1：传输契约、路径策略与字节限额

## 目标 / 背景

按设计 §11.1 在组件内开工切片 B（单文件 SFTP 上传/下载），本步只做**契约、路径策略与限额**，
不连服务器、不碰宿主。设计要点：分别建模本地与远端路径、不信任字符串前缀、默认禁止覆盖、
默认 64 MiB / 硬上限 256 MiB、流式复制禁止整文件入内存。

## 改动

- `Source/PuddingSsh/Contracts/SshTransferContracts.cs` — 新增 `SshUploadRequest`/`SshDownloadRequest`、
  `SshOverwritePolicy`（默认 `Fail`）、`SshTransferLimits`（`MaxBytes` 默认 64 MiB、`HardMaxBytes` 256 MiB、
  独立的 `UploadRoot`/`DownloadRoot`/`LocalRoot`，`Validate()` 拒绝而非夹取）、`SshUploadPlan`/`SshDownloadPlan`
  （含**同目录唯一临时文件名**，审批看到的就是这份计划里的精确路径）。
- `Source/PuddingSsh/Validation/SshLocalFileSystem.cs` — 本地文件系统探针接口 + 真实实现：
  把 reparse point/普通文件/目录判定抽出来，使路径策略可确定性单测。
- `Source/PuddingSsh/Validation/SshLocalPathPolicy.cs` — 本地路径策略：以执行快照工作区为根，
  用 `GetRelativePath` 做**唯一权威**包含判定（不是字符串前缀），逐段拒绝重解析点，拒绝目录/非普通文件，
  上传源按限额前置拒绝，下载目标要求父目录存在。诚实声明：同机并发写同一目标仍有 TOCTOU，路径检查不是沙箱。
- `Source/PuddingSsh/Validation/SshRemotePathPolicy.cs` — 远端路径策略：POSIX 绝对路径、拒绝控制字符与
  目录标记、词法消解 `.`/`..`、允许根内包含判定、`/` 不能作为边界、父目录 **realpath** 必须在根内
  （符号链接逃逸拒绝）、同目录临时文件名生成。诚实声明：SFTP 检查与打开之间仍有服务端竞态。
- `Source/PuddingSsh/Validation/SshTransferValidator.cs` — 校验并产出传输计划；请求 0/负数 →
  `ssh.request_invalid`；超过硬上限 → `ssh.transfer_too_large`；限额配置非法 → `ssh.config_invalid`。
- `Source/PuddingSsh/Diagnostics/SshDiagnostics.cs` — 新增传输相关稳定错误码：
  `transfer_unavailable`/`transfer_unsupported`/`transfer_too_large`/`transfer_incomplete`、
  `local_path_invalid`/`remote_path_invalid`、`local_path_exists`/`remote_path_exists`、
  `transfer_failed`/`transfer_cleanup_failed`。
- `Source/PuddingSsh/Contracts/SshHostContext.cs` — 新增可选 `SshTransferLimits? Transfer`（未配置即关闭式失败）。

## 验证

- `dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **262/262 通过**，0 警告 0 错误（新增 31 例）。
- **双向变异取红**（证明门禁真的能检出缺陷类别）：
  - 变异 1（包含判定退化为朴素 `StartsWith`）→ `LocalPath_PrefixSibling_IsNotInsideRoot` **红**
    （`/workspace-evil` 只是字符串前缀相同，不得算根内）；
  - 变异 2（包含判定退化为「一律拒绝」）→ `LocalPath_NestedInsideRoot_IsAccepted` 等 **红**；
  - 恢复后 262/262 绿。
  过程中发现原先的包含判定有**两层**（第二层掩盖了第一层），已收敛为单一权威判定，门禁才真正敏感。
