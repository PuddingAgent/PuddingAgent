# 2026-10-18 前端D2c3快照游标与重复打开收敛

## 改动

- `conversationSnapshotAdapter`：`eventCursor` 从事件 head 改为**快照游标 C**（Plan §4.2：快照准备游标，SSE 从 C 追平 H），避免以 head 为起点漏掉 C..H 的追平。
- `ChatClientStore.selectAgent`：同 key 且已有会话时直接复用，**不再重复打开**；后台刷新交给 `syncSelectedAgent`/SSE（StrictMode/重复 effect 不再额外拉取）。
- `useChatState` 新增 `resolveProjectionCursor`：projection-owned 主会话的 SSE 游标准备优先返回 Store 的快照游标，**跳过额外 `/bootstrap`**；快照尚未就绪或 410 `snapshot_required`（resetCursor）时仍回退真实快照重取，避免死循环。
- `chat/index.tsx` 接线；前端版本 `6.9.2 → 6.9.3`；frontend code_map 更新。

## 验证

- `pnpm exec jest conversationSnapshotAdapter.test.ts chatClientStore.test.ts`：**22/22 通过**（含同 key 顺序重复选择只打开一次、eventCursor=C、长正文分段/活动回退）。
- `pnpm run build`：成功，`[chat-bundle-budget] ok sync=1383742 chat=363601 common=437631`。
- `pnpm run tsc`：仅基线既有错误，本次文件无新增类型错误。
- 浏览器冒烟（Chromium + 临时新 Core 6.9.3 + 真实库）：`/conversation` 旧入口请求 **0**、`/conversation-open` 1–2 次、正文分段 9–18 次、`/bootstrap?messageLimit=1` 仍 1 次；详见阶段 F 浏览器冒烟报告。

## 未完成与影响

- `/bootstrap` 仍有一次：SSE 游标准备在快照尚未就绪时回退真实 bootstrap；需要把“先有快照再开流”的时序收紧或让 bootstrap 对 projection-owned 会话返回快照游标。
- 长正文分段请求仍会在首屏对全部长消息自动读取（9–18 个请求）；尚未实现“预览 + 显式展开全文”。
- 同 key 在 StrictMode 双 store 重挂载下仍可能产生 2 次**顺序**打开（无并发在途）；生产构建影响待验证。
- 正式部署仍被共享脏工作树阻塞，未做产品 `wwwroot/admin` 替换。
