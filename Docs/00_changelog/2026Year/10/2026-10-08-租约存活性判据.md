# 2026-10-08 B1 组件侧：租约存活性检查也只看 CallerId

## 缺陷（同一类的第三处）

round-106 修的是 `FindPageGrant`（准入查询）只比 `CallerId` 字符串。本轮审计"租约不得比它的授权活得久"
这条不变式时发现：实现它的 `HasWriteCoverage` **也只比 `CallerId`**：

```csharp
|| !string.Equals(grant.Grantee.CallerId, holder.CallerId, StringComparison.Ordinal)
```

**后果**（另一个同 id 的行动者在该页仍有写授权时）：

| 步骤 | 结果 |
|---|---|
| A（`agent-1`/`task-1`）拿到写租约 | 正常 |
| B（`agent-1`/`task-2`，同 CallerId）也有写授权 | 正常 |
| 撤掉 **A 的**授权 | `HasWriteCoverage` 匹配到 **B 的**授权 ⇒ 认为"A 的授权还在" ⇒ **A 的租约不释放** |
| 结果 | ① 不变式"租约不得比授权活得久"被破坏；② 该页被一个**已无授权**的租约长期占住，其它写入者拿到 `PageBusy`（拒绝服务） |

严重性低于上一处（`Revalidate` 用的是已修的 `FindPageGrant`，所以 A 无法真的继续写），
但**不变式声明与实际行为不一致**，且会造成长期占页。

## 修法

`HasWriteCoverage` 改用与 `FindPageGrant` **同一个** `IsTheSameActor(grantee, holder)` 判据
（kind + callerId + taskId），并在注释里写明"两处判据必须一致，否则又会出现同 id 借用"。

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **336 / 336**（＋1） |
| 新增取红用例 | A 持写租约 → 撤 A 的授权（B 的授权仍在）⇒ **B 必须能立刻拿到写租约**（只有 A 的租约真的释放了才成立） |
| **取红实测** | 把判据改回只比 `CallerId` ⇒ 该用例**变红**；还原 ⇒ 336/336 |
| **未破坏既有流程** | `DesktopServiceTests` 315 · `DesktopSurface.BrowserTests` 67 · `PuddingDesktop.Tests` 320 全绿 |

## 诚实边界（诚实登记）

- **不改"身份从哪来"**：仍是组件内部一致性；B1 的调用方身份决定未动。
- **`HasWriteCoverage` 仍不比 FrameId**：租约不记录 frame，因此这里无法比对；
  `FindPageGrant` 是会比 frame 的 ⇒ 两处判据**仍不完全一致**（登记为已知差异，未在本轮改）。
- **`TaskId` 参与匹配依赖宿主 id 生成方式**（同 round-106 的假设）。
- **生产路径尚未调用**（B1 活路径未接）；本轮验证组件层。
