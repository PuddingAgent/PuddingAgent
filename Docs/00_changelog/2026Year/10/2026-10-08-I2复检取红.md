# 2026-10-08 复检用例 + 取红失败的重要发现

## 用例（通过）

`BrowserRevalidateBeforeTouchingTests.RevokingWhileQueuedIsRefusedBeforeAnyDriverCall`

| 判据 | 结果 |
|---|---|
| 世代提供者被读取 **≥2 次**（证明复检路径确实跑过） | ✅ |
| 操作**失败** | ✅ |
| `Surface.NavigateCount == 0`（未触碰页面） | ✅ |

## **取红失败（重要）**

把 round-231 新增的复检块临时改为恒假（`if (false && lease is not null …)`）后，**用例仍然通过**。
⇒ 执行被拒的**不是**我新增的 `Revalidate`，而是 `ExecuteOnUiAsync` 里**既有的竞态复检**（该方法的注释写着"先复检竞态，再调用 surface"）。

**含义（两种可能，本轮不臆断）**：

1. 我新增的 `Revalidate` 是**冗余的第二份判据** —— 与设计 §1.1「不得有第二份策略来源」相冲突，
   应**删除**它（或让它产生既有复检无法覆盖的独立可观察效果，例如同时刷新读取基线）；
2. 既有复检覆盖的是**另一个时间窗口**（它跑在 UI 线程内、surface 调用前），与 `RunOnUiAsync` 里的复检互补 ——
   但那就必须构造一条**只**能被我这段代码拦下的用例（例如在 `ExecuteOnUiAsync` 的复检之后、surface 之前撤权）。

## 诚实边界

- **本轮没有证明新增代码是必要的**；相反，证据指向它可能多余。**不改代码、不臆断**，下一步先读 `ExecuteOnUiAsync` 的复检逻辑。
- **未跑全量链**；**未真机验证**。
