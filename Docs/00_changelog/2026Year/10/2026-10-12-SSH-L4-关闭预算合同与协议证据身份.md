# 2026-10-12 SSH L4：关闭预算合同与协议证据身份

## 目标 / 背景

补齐补充方案里尚未收口的两项：§3「真实会话关闭状态机与协调器必须消费**同一预算合同**」；
§4「协议证据保留**构建身份**与源码哈希，并增加反复资源转移、socket/reader 归零检查」。

## 改动

1. **预算合同真正传进会话**（`ISshTransportSession.DisposeAsync(TimeSpan budget)`）
   - 端口新增带预算的释放重载：TERM、关闭命令、关闭连接、排空、Dispose 共用**调用方给的这份额度**；
     谁先启动单次关闭状态机，预算就按谁的算；无参 `DisposeAsync()`/`RequestAbort()` 仍用组件默认清理宽限
     （直接使用者路径，如探针）。
   - 真实会话 `EnsureCloseAsync(budget)` → `CloseCoreAsync(budget)`，并暴露 `CloseBudget` 供门禁断言。
   - 协调器把 `SshCleanupBudget` 的剩余额度交给会话：`session.DisposeAsync(budget)`。
2. **预算起算点修正**：`SshCleanupBudget` 改为**首次需要清理时**惰性创建（`Lazy<SshCleanupBudget>`，
   `ExecutionAndPublication`），不再从操作开始起算。此前长于清理宽限的操作（例如 1 s 超时轮次）在收尾时
   额度已被业务耗尽 ⇒ 关闭拿到 0 ⇒ 误报 `Pending`——**由本轮新增的协议断言 `every_round_cleanup_completed`
   在真实矩阵里抓到**（`rounds` 的三轮超时都报 `Pending`）。
3. **协议证据身份**：运行器计算 `git rev-parse HEAD`、工作树 dirty、探针 dll SHA256，写入 SUMMARY 并传给探针
   （`--source-sha`）；探针侧新增该选项。
4. **反复资源转移检查增强**（`rounds`）：新增每轮 `cleanup_state`、`PeakStageWorkers`/`PeakCloseWorkers`/
   `PeakQuarantinedResources` 事实，并断言峰值不越容量、每轮清理都完成；运行器在 9 轮之后核对
   **服务端 `ss` 上零残留 established socket**。

## 验证

- **取红**：把预算改回「操作开始即建」→ 新门禁 `CleanupBudget_StartsAtCleanupStart_NotAtOperationStart`
  失败（`Completed` vs 实际 `Pending`）；恢复后通过（恢复文件强制重建，避免旧时间戳骗过增量构建）。
- **复绿**：`dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **231/231 通过**，0 警告 0 错误。
  新增 3 例：预算确实交给会话（`LastCloseBudget` 为正且 ≤ 宽限）、业务 deadline 过后预算仍为正、
  预算从清理开始起算。
- 真实协议：`rounds` 现在报告 `cleanup_states` 全 `Completed`、峰值 2/8、1/8、1/8，并核对服务端零残留 socket；
  矩阵在干净树上复跑（`build.source_dirty = False`）后 `failures = 0`。
