# 2026-10-08 B1 生命周期：页面登记非破坏性，提权与闸门静默关闭同时修掉

## 目标 / 背景

设计方案 §3.3 对页面生命周期定的顺序是「运行时事实完成 → **原子发布登记与授权事实** → UI 投影 → 回执」，
即**登记是发布事实，不是覆盖事实**。审计（2026-10-08 结论 #2）已经指出：可信级别是 context 级，
页级授权必须由「用户选定的 Agent 目标页」承载，否则闸门只是 UI 上的暗示。

本轮查出这两个前提都被打破，且是同一条链路上的两个真缺陷。

## 缺陷一：重复登记会静默关掉页级准入闸门（并绕过版本单调性）

`DesktopTargetRegistry.RegisterPage(target, version, readiness, bool isAgentTarget = false)`
对**已登记**页面是**整体覆盖**：

- `isAgentTarget` 缺省 `false` ⇒ 一次重复的"页面已创建"事件就把用户选定的 Agent 目标标记清零
  ⇒ 页级闸门静默失效（UI 仍显示这是目标页，准入说不是）；
- `version` 整体覆盖 ⇒ 传一个更小的版本就**绕过 `UpdatePage` 的「版本只能前进」不变式**，
  旧 Snapshot/Locator 重新"有效"（设计方案 §5 明令禁止）。

触发面是真实的：`BrowserWorkspaceTargetBridge.OnPageCreated` 就是按缺省值调用的，
而页面生命周期事件会重复触发（标签重建、重新播种、窗口重连）。

## 缺陷二：两个注册表在同一事实上分叉

`BrowserTargetRegistry.RegisterPage(isAgentTarget: false)` 是**只增不减**（`false` 不清标记），
而 `DesktopTargetRegistry`（**准入读的那一份**）会清零。同一对事件序列下两者结论相反 ——
这正是"UI 说这是目标页、准入说不是"那类最难排查的漂移。另外两个注册表的
`RegisterContext` 都是直接覆盖：同一 context 用更高可信级别重复登记 = **静默提权路径**
（`Untrusted → AgentAuthorized`），与它们自己的文档注释（"级别在创建时确定、之后不可改写"）矛盾。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/Pudding.DesktopService/DesktopTargetRegistry.cs` | `RegisterPage(..., bool? isAgentTarget = null)`：**只合并不削弱** —— 版本只进不退；`Readiness = Unknown` 与 `isAgentTarget = null` 都是"不表态"（保留原值），`true`/`false` 才是显式设置/清除。`RegisterContext`：同级别幂等，**换级别抛 `InvalidOperationException`**（要先 `CloseContext`）。新增 `AgentTargetCount`，与 `OpenPageCount` **分别统计**（§3.3「目标数与授权数分别统计」） |
| `Source/Pudding.DesktopService/BrowserTargetRegistry.cs` | `RegisterContext` 与上面**同一条规则**（同级别幂等、换级别抛异常），消除两个注册表之间的规则分叉 |
| `Source/Pudding.DesktopSurface.Browser/BrowserWorkspaceTargetBridge.cs` | `OnPageCreated` 对 Agent 目标**不表态**（传 `null`）：创建事件无权清除用户选定的目标，目标只由 `OnAgentTargetChanged` 设置/撤销 |

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **208 / 208**（原 203 ＋ 5） |
| `Pudding.DesktopSurface.BrowserTests` | **57 / 57**（原 56 ＋ 1） |
| `PuddingDesktop.Tests` · `PuddingHost.Tests` · `PuddingBrowser.AutomationTests` | 301 / 301 · 252 / 252 · 187 / 187 |
| `build` `Pudding.DesktopService` · `Pudding.DesktopSurface.Browser` · `PuddingDesktop` | 0 错误 |

新增门禁：

- `RegisterPage_RepeatedRegistration_KeepsTheAgentTargetAndTheHigherVersion`（缺省/Unknown 重复登记后
  目标标记与 v7/Complete 事实都还在）；
- `RegisterPage_NeverMovesTheVersionBackwards`（用 v2 覆盖 v9 被吞掉，v11 仍能前进）；
- `RegisterPage_ExplicitFalse_StillClearsTheAgentTarget`（"不表态"与"显式清除"必须可区分，
  否则没有撤销路径）；
- `RegisterContext_RejectsTrustRewrite`（同级别幂等、换级别抛异常、注销后可重建）；
- `AgentTargetCount_IsCountedSeparatelyFromOpenPages`；
- `RepeatedPageCreated_DoesNotClearAPinnedAgentTarget`（**跨注册表**回归：admission 侧与 browser 侧
  必须同时仍认为它是目标页，且版本保持 v4）。

**取红实测**：把 `OnPageCreated` 改回 `isAgentTarget: false`（即恢复原缺陷）⇒
`RepeatedPageCreated_DoesNotClearAPinnedAgentTarget` **恰好 1 条变红**，其余 56 条仍绿；
复原后 57/57 复绿。

## 已知边界与既有失败

- 本轮**未**实现 §3.3 的「统一生命周期端口」本体（人工 UI 与两种传输都经它创建/关闭，
  且关闭后同时清 `UI + 两个注册表 + grant + ref/cursor + 租约`）：目前关闭仍由
  `BrowserWorkspaceTargetBridge`/`BrowserTargetRegistry` 分散处理；grant/ref/租约的清理
  要等 `Admit`/grant 接入（见 code_map 已知缺口）。
- 「授权数」尚未有来源（grant 未接入），本轮只把**目标数**独立出来。
- `PuddingHost.Tests` 出现 1 次既有 flake（`DesktopBrowserBridgeHandshakeTests.SecondConnection_
  CannotReplaceAwaitingHelloConnection`，2026-10-08 已实测为环境时序问题：带改动 3/5 失败、
  在 HEAD 也能复现 1/4），复跑即 252/252；与本轮改动无交集（本轮只动 Desktop 侧注册表与桥接）。

## 影响与回滚

- **行为变化**：`RegisterPage` 的 `isAgentTarget` 参数类型 `bool` → `bool?`（显式 `true`/`false`
  调用点不受影响）；`RegisterContext` 换级别由"静默覆盖"变为**抛异常**。
- 无数据/配置影响；线缆 DTO 与 proto 未改动。
- 回滚：还原上表 3 个生产文件与 2 个测试文件及 code_map。
