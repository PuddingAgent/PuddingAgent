# 2026-10-07 · 可诊断基础设施叶子组件

## 背景 / 动机

两件事同时发生：

1. **一次真实故障**：长会话（`206a9b48…`，deepseek-flash / protocol=responses，msgCount 95→216、toolCount 99、prompt 18 万–22 万 token）
   出现 `LLM 调用失败: Error while copying content to a stream.`。定位结论（**写请求体阶段**被对端 RST，
   内因 `SocketException(10054)`）只能靠人读三份日志 + 读堆栈得出；平台当时**没有记录请求体字节数、尝试序号、
   失败阶段与 socket 错误码**。
2. **用户裁定**：不要只修这一处，要**从架构上建立可诊断的基础设施**。

因此本刀的产出是「设计裁定 + 第一块可独立测试的基础设施」，而不是一次性补日志。

关键不变量（由用例锁住）：**未产出任何增量前的传输瞬态失败可重试；一旦产出增量一律不可重试**
（`Docs/08_how_debuge/06-延迟问题定位.md` §7.9）；**证据有界且必经脱敏**（键 ≤32、单值 ≤512 字符、总量 ≤8 KiB，
触顶写 `evidence_truncated=true`）；**信号不足时如实报 `transport.unclassified_failure` / `local.unclassified_failure`，
不伪装成具体原因**。
