# 2026-10-08 B4 续：截图坐标 → CSS viewport 的精确变换

## 依据（设计 §8.2）

> `browser_interact` 增加 pointer_click/move/drag，坐标统一为 **CSS viewport 像素**。
> 截图坐标输入需**携带截屏 observationId**，驱动用**精确变换**转换；**滚动/缩放/布局或页面世代改变时拒绝旧坐标**，
> 要求重新观察。坐标操作仍受 page grant、接管、租约、**命中与视口边界**约束。

## 交付

新增 `Source/PuddingBrowser.Automation/BrowserScreenshotCoordinates.cs`（+`BrowserPageGenerations`、
`BrowserCoordinateTarget`、`BrowserCoordinateRejection`）：

| 步骤 | 语义 |
|---|---|
| ① 去低清缩放 | `imageX / (OutputWidth / SourceWidth)` |
| ② 除设备缩放 | `/ DeviceScaleFactor`（Retina 下漏掉这一步**只会点偏、不会报错**） |
| ③ 加裁剪原点 | `+ CropX/CropY`（文档坐标） |
| ④ 减滚动量 | `- ScrollX/ScrollY` ⇒ **CSS viewport 像素** |

**三类拒绝**（每类都有用例，且都给出可操作原因）：

1. `UnknownObservation`：没给 observationId、给了别的 observation 的 id、或没给当前世代；
2. `StaleObservation`：`PageVersion`/`DomRevision`/`ViewportRevision` **任一**变化 ⇒ 提示"重新截图并用它的 observation id"；
3. `OutOfImageBounds` / `OutsideViewport`：图片外的点、或换算后落在 CSS 视口外（含"滚动过头"使坐标为负）；
   另加 `InvalidObservationGeometry`：几何信息不全时**算不出就拒**（绝不就近取点）。

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **374 / 374**（＋8；冻结公开面与每类计数已同步） |
| **全量链** | **1576 / 0**、无重试、语料全扫（第一次跑遇 Host 已知 flake ⇒ 清单**拒绝产出**，重跑才绿） |
| 关键断言 | 低清缩放中心点回到 CSS 中心（640,400）；DPR=2 时**除以 2**（320,200）；裁剪+滚动同时生效；三代各自变化都判 stale；原尺寸时为恒等变换 |
| code_map | 已登记新文件 |

## 诚实边界（诚实登记）

- **仍未接线**：本类只做**纯变换与拒绝语义**；`browser_interact` 的 pointer_click/move/drag 采集侧、
  page grant/接管/租约的**准入**（§8.2 后半句）仍待决定②（可信调用身份）与 S5 接入。
- **容差 0.5px 是折中**：太小会因 JPEG/缩放取整被误拒，太大就成了"就近取点"；它是**常量**，将来实测可调。
- **不覆盖滚动拼接**：全页滚动拼接需要单独处理固定元素与动态内容（设计 §8.1 明确要求），**未做**。
- **未真机验证**（无 WebView2/产品 Shell）。
- **未纳入 smoke 清单**：S-09 已含"缩放后旧坐标被拒"，但**命中与视口边界**的自动化覆盖未登记进 `AutomatedCoverage`（登记为待办）。
