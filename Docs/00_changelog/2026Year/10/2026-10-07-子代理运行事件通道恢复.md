# 2026-10-07 · 恢复子代理运行事件通道

## 背景 / 动机

用户截图里子代理卡片显示「启动中 / 0 轮 / 0 工具 / 暂无运行事件」，而实际运行记录
（`run_20261006_150522_889dffd12fc1`）是 18 轮 / 23 次工具调用、归档与父会话
`conversation_events` 各 121 条 —— 子代理在执行，事件也落了库，**是展示链路断了**。

链路断点（诊断已逐条对到代码）：

1. 新聊天架构默认开启（`isAgentClientArchitectureEnabled()`，`localStorage` 无 `0` 即为真），
   agent 主会话被加进 `projectionOwnedSessionIdsRef`；
2. `useChatState` 的持久 SSE effect 命中该集合即 `stopSessionEventStream()`；
3. `ensureSessionEventStream` 再次对投影会话直接 `return {ok:true, opened:false}`，
   连重连都进不来；
4. 于是子代理事实只剩 `useSessionEventReplay` 那个 10 秒一次的状态端点校正，
   它只能物化「运行存在」的占位（`phase: starting`、0 轮、0 token、空时间线）；
5. `SubAgentActivityDock` 按 ADR-060 规定活动运行**不轮询运行归档**（活动期与归档写入
   抢文件会 sharing violation 杀死子代理），终态才读归档 —— 占位永远等不到补全。

补充查证（决定修法）：`subagent.run.*` 由 `FileSubAgentRunStore` 逐事件写 JSONL 归档，
`SubAgentConversationProjectionWorker` 每 2 秒把未投影事件补写进父会话
`conversation_events`；父会话 SSE（`SessionEventStreamService.FollowAsync`）的 live 段
每 1 秒做一次 durable poll。**也就是说 canonical 通道本来就在稳定产出子代理事件，
缺的只是「没有人订阅」。**

## 改了什么（相对路径）

| 文件 | 改动 |
|---|---|
| `Source/PuddingPlatformAdmin/src/pages/chat/hooks/useSessionEventProjection.ts` | `applySessionEvent` 增加**会话域**：identity 的 `isProjectionOwnedSession(sessionId)` 为真时，只消费 `subagent.*` 事实并推进游标，主消息/轮次/执行流/压缩一律不投影（避免与 Agent 投影重复投影同一正文）；被过滤事件也不再占用 `seenEventIdsRef` 去重集合（否则一个投影会话的整条增量流会把集合撑到无界） |
| `Source/PuddingPlatformAdmin/src/pages/chat/hooks/useChatState.ts` | SSE effect 不再因投影会话停流；新增**稳定**的 `isProjectionOwnedSession`（`useCallback` + ref 读取）传给投影层，替换原先的内联箭头 |

| `Source/PuddingPlatformAdmin/src/pages/chat/hooks/sessionEventCursor.ts` | `SessionEventStreamEnsureResult.reason` 去掉不再产生的 `'projection-owned'` |

| `Source/PuddingPlatformAdmin/src/pages/chat/hooks/useSessionEventReplay.ts` | 首载/重连的快照合并改走 `mergeSubAgentRunSnapshots` |
| `Source/PuddingPlatformAdmin/src/pages/chat/types.ts` | `SubAgentCard` 透出 `eventSync` |
| `Source/PuddingPlatformAdmin/src/pages/chat/components/SubAgentActivityDock.tsx` | 空态诚实化：`awaiting` 时指标显示 `—`（不是 0）、时间线显示「正在同步运行事件…」、超过 20 秒无事件升级为「同步未就绪 + 父会话事件通道正在重连（第 N 次）」；标题栏不再谎报「实时事件已连接」；新增 `reconnectCount` 入参 |
| `Source/PuddingPlatformAdmin/src/pages/chat/components/ChatMain.tsx` | 把已有的 `reconnectCount` 传给运行坞 |
| `Source/PuddingPlatformAdmin/package.json` | 前端版本 `6.2.3` → `6.3.0` |
| `Source/PuddingPlatformAdmin/code_map.md`、`code_map.md` | 就地改写受影响条目（投影会话开流语义、会话域、运行坞的事件来源与未知量显示） |

被刻意**未**改动的边界：ADR-060「活动运行不轮询运行归档」保持不变；主消息仍由 Agent 投影
承担；`subagent.*` 的 reducer 语义、`runId` 隔离与 `eventId` 去重沿用既有实现。

## 一个被测试抓到的连带缺陷（值得记）

第一版把 `isProjectionOwnedSession` 写成内联箭头传入投影 hook，于是 `applySessionEvent`
每次渲染都换身份 → `syncCompletedHistoryEventCursor` / `handleSelectSession` /
`ensureAgentMainSession` 级联失稳 → 「主线会话自动重建」effect 多跑一次并**消费掉**
`suppressMainSessionEnsure()` 的一次性抑制，把刚删除的会话又选了回来。
`useChatState.selection` 的 `handleSessionNotFound` 用例直接抓到（`selectedSessionId` 仍为
`session-a`）。修法即上面表格里的 `useCallback` + ref。

## 未完成 / 后续

  而新架构原本靠「不开流」省掉这份流量。若实测到压力，可改为「仅当存在活动子代理运行时
  才开该流」（需要把活动运行信号提前到订阅决策之前）。
