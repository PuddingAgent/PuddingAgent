# V1 默认授权：取消桌面浏览器的用户页面交接前置

## 1. 裁定（用户 2026-10-18）

> 「PuddingDesktop 提供的浏览器，不需要用户授权。至少在 V1 阶段之前，我们不做限制。」

原设计（ADR-097 D3/D4）要求：用户在 Desktop UI 点「设为 Agent 目标」把页面交给 Core 会话，之后页面命令才被准入。实测该前置不仅多余，而且当前**不可用**：点击后目标绑定到一个无法枚举的页面标识，`browser_navigate/snapshot/locate` 永久返回 `agent_target_required`。

## 2. 改动（两处，均在授权判定内，不动 UI）

### 2.1 隐式目标绑定 — `AgentTargetSessionAuthority`

`Authorize` 在 `GateUnsafe` 之前调用新方法 `EnsureImplicitTargetUnsafe`：

- **无会话**：用宿主注入的可信控制句柄，把目标绑定到**请求的页面**；
- **有会话但页面不同**：同 owner ⇒ 自动跟随（推进控制/写世代、撤销旧执行权）；
- **owner 不同** ⇒ 不改绑，仍由 `GateUnsafe` 报 `browser_owner_mismatch`；
- **桥未连通 / 已关闭** ⇒ 不绑定（原有边界不变）。

**保留的人工闸**：新增字段 `_implicitBindingSuspended`。用户显式 `Revoke` 后置位，此后隐式绑定停止生效（返回 `agent_target_revoked`），直到用户再次 `SelectTarget` 或 `TryClaimOwner` 才解除。页面关闭、桥换代、目标切换**不**置位 —— 它们是运行状态变化，不应永久剥夺 Agent 的浏览器能力。

### 2.2 管理类命令放行 — `BrowserBridgeCommandDispatcher`

无 `PageId` 的管理命令（`page.create` / `context.*`）原本要求 `CaptureSessionTarget()` 非空。V1 改为直接放行：这些命令**不读写页面内容**，真正的页面级边界仍由 `AuthorizePageCommand` 在触碰页面时施加。

## 3. 验证

| 套件 | 结果 |
|---|---|
`PuddingBrowser.AuthorizationTests` | **49 / 49 通过** |
`PuddingDesktop.Tests`（Browser 过滤） | **160 / 160 通过** |
`Pudding.DesktopServiceTests`（Browser 过滤） | **124 / 124 通过** |

**变异取红**：注释掉 `EnsureImplicitTargetUnsafe` 调用后，Authorization 套件 **6 例转红**（`HandshakeActivates…`、`GenerationChangeReplaces…`、`APageTheAgentRequestsIsBound…`、`NotifyOwnerUnavailable…`、`NotifyPageClosedRevokesOnly…`、`OfferingATargetIsBound…`）；复原后文件 SHA-256 回到基线 `541e1099…` 且 49 / 49 复绿。

## 4. 测试语义迁移（设计变更的必要成本）

以下旧用例断言「必须用户选页 / 撤销后永久拒绝」，与新语义冲突，已改为锁定 V1 行为：

- `APageTheUserDidNotSelectIsRejected` → `APageTheAgentRequestsIsBoundWithoutUserSelection`
- `GenerationChangeRevokesTheTarget` → `GenerationChangeReplacesTheTargetOnTheNextCommand`
- `OfferingATargetDoesNotCreateAnExecutableSessionUntilClaimed` → `OfferingATargetIsBoundOnTheFirstCommand`
- `TargetSwitchRevokesTheOldSessionAndItsPermits` → `TargetSwitchRevokesTheOldPermitsButTheNextCommandRebinds`
- `HandoverMustBeConfirmedByATrustedOwnerBeforeAnyCommandIsAdmitted` → `HandoverIsAdmittedWithoutAnExplicitClaimUnderV1`
- `ScreenshotWithNoHandedOverPage_IsRejectedBeforeTheDriverIsTouched` → `ScreenshotWithoutGrantIsRejectedBeforeTheDriverIsTouched`（该用例真正守护的是 **page grant** 层，与交接无关；V1 只放开交接层，grant 缺失仍拒绝且不触达驱动）

新增：`RevocationSuspendsImplicitBindingUntilTheUserSelectsAgain`。

## 5. 边界与遗留

- **未改** `page grant`（任务绑定签发）层。`browser_screenshot` 等仍需要 grant，若生产环境未绑定任务则仍会被 `no page grant covers ...` 拒绝 —— 需重启后实测确认。
- 跨 Core 会话（不同 owner）不可复用目标，这是保留的安全底线，未放宽。
- 本次未动 UI：`设为 Agent 目标` / `人工接管` 按钮仍在，但不再是使用浏览器的前置条件。
