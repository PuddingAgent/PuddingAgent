# 权限证据链第一阶段：生产者接通（ToolInvocationService 记录 guard 结论）

## 改动

| 文件 | 改动 |
|---|---|
| `Source/PuddingRuntime/Tools/Platform/ToolInvocationService.cs` | 把只做「否决」的 `CheckGuardDenied` 改写为 `EvaluatePermissionEvidence(request, out denied)`：**判定语义与重构前逐字相同**（同一 `IAgentWorkspaceGuard.CanExecuteTool` 调用、同一条 `LogWarning`、同形的失败 `ToolInvocationResult`），额外把结论带进 `ToolExecutionContext.PermissionEvidence` |

语义细节（第一阶段的关键正确性点）：

- guard **允许** ⇒ `Decision = "allowed"`（`Source = "workspace-guard"`）；
- guard **拒绝** ⇒ `Decision = "denied"`，调用方照旧立即返回失败（错误文案与以前一字不差，仍提示
  `request_tool_approval`）；
- **未配置 guard ⇒ 返回 `null`（未评估）**，**不得**写成 `not-required` —— 那会谎称"策略判定无需审批"。
  缺失必须是可表达状态（`ToolPermissionEvidence.IsAbsent`）。

⇒ 第一阶段仍然**只记录、不拒绝**：除新增一个可选属性外，任何调用路径的结果都不变。

## 验证（含一处必须如实说明的边界）

- `PuddingRuntime` 构建 **0 错误**（`dotnet build ... --no-restore`）；
- **未能用测试验证**：覆盖该服务的测试工程（`Source/PuddingRuntimeTests`，MSTest/Microsoft.Testing.Platform）
  在本机 `dotnet test` 下**零输出、退出码 0**（`temp/rt-out.txt` 0 字节），换用已构建 dll 直接执行同样零输出；
  `Source/PuddingPlatformTests` 亦然。⇒ 这是**既有的测试工具链缺口**（非本次改动引入）：
  xunit 工程（本会话九个套件）能跑，MSTest/MTP 工程在本环境下**跑不起来**。
- 因此本改动的验证强度是：**编译期 0 错误 + 逐字保留原判定路径的代码级等价**；
  **不是**"跑了测试全绿"。这一点我按仓库纪律如实标注，而不是含糊成"已验证"。
- 交叉证据：编译保证 `ToolInvocationRequest`/`ToolExecutionContext` 的字段使用正确；
  另外九个 xunit 套件（最近一次合计 **800** 用例）不覆盖该服务，故不能作为本改动的证据。

### 给外部控制器的补充建议（本轮新增的一条）

运行外部验收时，MSTest/MTP 工程需用其**原生运行方式**（`dotnet run --project <测试工程>` 或
测试 exe 直跑），**不要**依赖 `dotnet test`；否则会得到"零输出、退出码 0"的假绿。
