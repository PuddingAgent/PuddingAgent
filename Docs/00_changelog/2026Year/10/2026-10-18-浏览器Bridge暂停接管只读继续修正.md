# 2026-10-18 浏览器 Bridge 暂停/接管只读继续修正（F2 前半）

## 目标与结论

审阅报告 F2 指出：`BrowserBridgeCommandDispatcher.DispatchCoreAsync` 在**识别命令之前**检查 `IsPaused/IsUserTakeover` 并直接返回，`ReadOnlyPageCommands` 只参与后面的页面授权范围计算 ⇒ 默认 Bridge 路径上"接管后只读可用"只在文档里成立。本切片修掉这一半：先校验命令名并判定只读类别，暂停/接管只拒绝**副作用命令**；只读命令继续走既有页面授权闸门并执行。

F2 的另一半（Bridge 页面命令统一进入传输无关执行器、入队后复检同一票据）属 I2，本轮未动。

## 改动

- `Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandDispatcher.cs`：命令名校验提前；新增 `readOnlyCommand = ReadOnlyPageCommands.Contains(command.Name)`；暂停/接管检查改为 `!readOnlyCommand && ...`。写命令仍返回 `browser_paused` / `browser_user_takeover`，活动记录行为不变。
- `Tests/PuddingDesktop.Tests/Browser/BrowserTakeoverGateTests.cs`：新增正向授权夹具 `CreateAuthorized`（真实 lifecycle + 用户选页授权，避免"闸门缺失"假绿）；新增配对用例 `Takeover_BlocksWrites_ButKeepsReads`、`Pause_BlocksWrites_ButKeepsReads`、`Takeover_BlocksMutatingInteract`。
- `Source/PuddingDesktop.WpfArchive/code_map.md`：更新派发器当前语义。

## 验证

- **先红**（测试先写、产品代码回退到修复前）：`dotnet test Tests/PuddingDesktop.Tests --filter "FullyQualifiedName~BrowserTakeoverGateTests"` ⇒ **2 失败 / 19 通过 / 21**；失败正是两条"只读继续"用例（旧代码返回 `browser_paused`/`browser_user_takeover`）。
- **后绿**（恢复修复）：同命令 ⇒ **21/21 通过，0 失败**。
- 写路径回归：既有 `ShellTakeover_ReachesTheBridgeGate_AndRejectsAgentCommands`、`Pause_AlsoReachesTheBridgeGate` 继续通过（错误码未变）。
- 未运行 PuddingDesktop 真机、未调用真实模型；本轮是组件级证据。

## 未完成与影响

- **F2 后半未修**：只读命令仍由 controller 直接执行，Bridge 页面命令仍未统一进入执行器；"入队后接管→恢复，旧写不得执行"的复检只能靠旧 authority 的租约逻辑（Bridge 写路径本来就没有租约）⇒ 归 I2。
- **F3 未修**：`HasSufficientPageGrant` 的"桥在线即放行任意页面"仍在；本轮没有为了让只读通过而放宽它，读测试用**真实页面授权**夹具，收紧 F3 后仍应通过。
- 回滚 = revert 本提交；无配置/数据变更。
