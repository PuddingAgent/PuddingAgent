# 2026-10-08 B7：G1–G4 逐条证据映射 + 表格门禁

## 为什么

上一轮的对账只到"**类**一级"（`BrowserControlAuthorityTests` 有 16 个用例），这证明的是"有这些用例存在"，
**不是**"那条标准被覆盖到"。P0 四条（G1–G4）是"通过之前不默认开启新通道"的前提，最值得钉到**用例名**。

## 交付

[门禁证据对账](../../../14_reports/2026-10-09-门禁证据对账.md) 新增「**G1–G4 逐条证据（用例名）**」一节：

| 门禁 | 举例（每条标准 → 具名用例） |
|---|---|
| G1 | 接管后新输入步骤数=0 → `Takeover_Blocks_New_Write_Steps`；恢复不复活旧租约 → `Resume_Does_Not_Resurrect_The_Pre_Takeover_Lease` |
| G2 | 跨 frame 身份拒绝 → `Grant_Bound_To_A_Frame_Does_Not_Authorize_The_Top_Document`；子代理不得扩大授权 → `ASubAgentGrantCannotExceedItsParentScope` |
| G3 | click 菜单不假失败 → `Click_That_Only_Opens_A_Menu_Is_Dispatched_Not_Failed`；重传 ≤1 → `Retransmission_While_Running_Must_Not_Execute_Again` |
| G4 | 读操作不推进版本 → `ReadOnly_Calls_Advance_Nothing`；不点同名替代 → `Ref_Values_Are_Opaque_And_Not_Derivable_From_Role_Or_Name` |

**结论**：G1–G4 的**每条标准**都能指到至少一个具名用例；唯一例外是 G2 的"UI/运行时/注册表残留"
（进程内不可证，已登记为真机项 S-02）。

## 写表时抓到自己的错，于是把这条做成门禁

初稿里我把 `UnknownOutcome_IsNeverTreatedAsNotExecuted` 写成了 `Unknown_Outcome_Is_Never_TreatedAsNotExecuted`
（多了下划线）。由此新增 `GateEvidenceReportTests.EveryTestMethodNamedInTheGateReportExists`：

1. 解析对账表「G1–G4 逐条证据」一节里所有 `` `用例名` ``（排除 `…Tests` 类名）；
2. 逐个到 `PuddingBrowser.AutomationTests` 里核对（`public void <name>(`）；
3. 断言至少解析到 30 个名字（防解析写坏而假绿）。

**当前核对结果：61 个引用、0 个缺失。**

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **336 / 336**（＋1 门禁） |
| **取红实测** | 把表里 `Takeover_Blocks_New_Write_Steps` 改成 `…_Renamed` ⇒ 门禁**变红并点名**；还原即绿 |
| 自查 | 用脚本把表里引用的 61 个名字逐个比对工程内 390 个用例 ⇒ 首次发现 1 个错名并修正 |
| **全量链** | **1593 / 0**、无重试 |

## 诚实边界（诚实登记）

- **"名字存在"≠"标准被覆盖"**：门禁保证表格不会指向不存在的用例，**不保证**那些用例真的验证了该标准
  （语义仍要人读代码；这是本会话反复强调的边界）。
- **只覆盖 G1–G4**：G5–G11 仍是类一级（登记为可继续细化）。
- **门禁只认 `AutomationTests` 工程**：表里若引用其它工程的用例名，会被判"不存在"（当前表未引用）。
- **表格仍会语义过期**：代码行为改了而用例名不变时，门禁**不会**发现（登记为可改进项）。
- **未真机验证**；决定②仍待确认。
