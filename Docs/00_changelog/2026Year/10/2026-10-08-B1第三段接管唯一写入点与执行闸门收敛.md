# 2026-10-08 B1 第三段：接管/暂停收敛到唯一写入点，执行闸门真正生效

## 目标 / 背景

审计（2026-10-08）结论 #1 **已证实**：进程内有三份互不相通的「接管」表示，
而产品 Shell **只写其中最不具执行权威的一份**：

| # | 状态对象 | 当时的写入者（产物构建内） | 执行闸门是否读它 |
|---|---|---|---|
| A | `BrowserWorkspaceController._userTakeover` | ✅ Shell 的接管开关（`MainWindow.xaml.cs:1055`） | ❌ 只喂 UI 状态机 |
| B | `BrowserBridgeCommandDispatcher._userTakeover` | ⛔ **无写入者**（唯一写入它的代码在被排除的 `Views/BrowserWorkspaceView.xaml.cs`） | ✅ 拒绝并返回 `browser_user_takeover` |
| C | `DesktopInteractionState.IsUserTakeover` | ⛔ **无写入者** | ✅ `ValidateAutomation` 对 Mutating 能力返回 `user_takeover` |

⇒ 用户点「人工接管」，Agent 照旧操作浏览器。设计 §3.1 的目标是**收敛为唯一事实源**。

## 改动

### 新增：执行闸门端口与唯一写入点

- `Source/PuddingDesktop.WpfArchive/Browser/BrowserAutomationGateSync.cs` — 新增。
  `IBrowserAutomationGate`（`SetUserTakeover`/`SetPaused`）、`BrowserAutomationGateSync`
  （注册/撤销/逐一推送；**单个闸门抛异常不影响其它闸门**——接管是安全动作，不得半途失效）、
  `DelegateAutomationGate`（给不能反向引用本组件的执行路径用）。
- `Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs` —
  构造函数新增可选 `BrowserAutomationGateSync?`；新增 `RegisterAutomationGate`（注册后**立即与当前
  控制状态对齐**，覆盖「用户先接管、能力通道后启动」的顺序）/`UnregisterAutomationGate`；
  `SetUserTakeoverAsync`/`SetPausedAsync` 在更新自身状态后推送全部闸门。

### 接线

- `Source/PuddingDesktop.WpfArchive/Browser/BrowserBridgeCommandDispatcher.cs` —
  实现 `IBrowserAutomationGate`（它的 pause/takeover **就是**执行闸门，方法已存在）。
- `Source/PuddingDesktop/MainWindow.xaml.cs` — 窗口创建闸门集合并注册
  `_coordinator.BridgeDispatcher`（默认传输路径），把集合交给控制器；暴露 `AutomationGates`。
- `Source/PuddingDesktop/Hosting/DesktopApplicationCoordinator.Capability.cs` — 能力通道**真的启动后**
  用 `DelegateAutomationGate` 把 `Service.Interaction` 挂到同一个写入点；停止时先撤闸门再停通道。
- `Source/Pudding.DesktopService/DesktopInteractionState.cs` — 新增布尔形态
  `SetUserTakeover(bool)` / `SetPaused(bool)`（与 `Notify/Clear/Pause/Resume` 等价，两轴保持独立）。

### 测试

- `Tests/PuddingDesktop.Tests/Browser/BrowserTakeoverGateTests.cs` — 新增 14 条，关键一条是
  **审计结论 #1 的验收**：走用户会走的那条路（`controller.SetUserTakeoverAsync(true)`）之后，
  Bridge 路径的 `page.goto` 必须被拒并返回 `BrowserUserTakeover`。
  另含：撤销接管后放行、暂停同样到达闸门、**接管后注册的新闸门立即对齐**、撤销后不再推送、
  广播到全部闸门、同一实例幂等、坏闸门不阻塞其余、空参拒绝、无闸门集合的旧构造路径不抛、
  委托闸门映射到 `DesktopInteractionState`、**两条传输同时失效**。
- `Source/Pudding.DesktopServiceTests/InteractionStateTests.cs` — 新增布尔形态的等价性与
  「撤销接管不得顺手恢复暂停」。

| 套件 | 结果 |
|---|---|
| `PuddingDesktop.Tests` | **297 / 297**（原 283 ＋ 14） |
| `Pudding.DesktopServiceTests` | **197 / 197**（原 196 ＋ 1） |

**取红实测**：临时删掉 `SetUserTakeoverAsync` 里的 `_automationGates?.ApplyUserTakeover(enabled);` ⇒
`BrowserTakeoverGateTests` **3 条变红**（审计验收条、新闸门对齐条、双传输条），其余 11 条仍绿；
复原后 297/297 复绿。这说明这几条断言钉的正是被修的因果链，而不是同义反复。

## 语义与边界（诚实登记）

- **这是「唯一写入点」而不是「唯一状态」**：三处读端（Bridge dispatcher、能力通道准入、
  UI 状态机）仍然各自持有布尔值，只是写入被收敛到一处并广播，因此不可能再出现
  「按钮只写一半」。设计 §3.1 的**完全收敛**（让它们变成同一个 `IBrowserAutomationAuthority`
  的投影）仍需后续切片——那时可删除重复字段。之所以分两步：完全收敛要改 `DesktopService`
  构造、`DesktopCommandDispatcher` 与宿主装配，属可验证性更差的一步，先闭合安全缺口。
- **暂停（pause）在 Shell 上没有 UI 入口**：`SetPausedAsync` 目前只被归档视图与测试调用；
  本次把它一并接进闸门，是为了让将来任何调用方都不必记得「还要再推一次」。
- **能力通道默认关闭**：它那条闸门只在通道真正启动后注册；因此本次对默认（WebSocket Bridge）
  路径的修复是主要收益，能力通道路径的缺口也一并闭合。
- **未做**：三处读端完全合并、`DesktopInteractionState` 与 `IBrowserAutomationAuthority` 的去重、
  Desktop/Core 生命周期的外部验收（按规程只能做到 `ready-for-external-deploy`，
  退出/重启/崩溃回收仍由进程外控制器判定）。

## 影响与回滚

- 行为影响：用户点「人工接管」后，桥接路径上新的 Agent 命令会被拒绝并记录
  `browser_user_takeover` 的失败 Activity（此前不会）。
- 无数据、配置、线缆格式影响。
- 回滚：还原上述 5 个产品文件与 2 个测试文件，并删除 `BrowserAutomationGateSync.cs` 与
  `BrowserTakeoverGateTests.cs`。
