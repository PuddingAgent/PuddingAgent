# Desktop 意外退出现场保留

针对 Desktop 意外退出缺少现场、无法区分 Core 重启与 Shell 被终止的问题，增加独立可测的记录组件和进程外观察器。

- `Source/PuddingDesktop.Diagnostics/`：BCL 叶组件，每次运行独立目录，原子快照、磁盘 flush、轮转事件、写盘前脱敏、退出分类、最近 20 次已结束运行保留；PID 与启动时间共同判定身份，权限未知时不推断死亡。
- `Source/PuddingDesktop.ExitObserver/`：无窗口进程，持有原 Desktop 进程句柄并保存真实退出码；不控制或重启产品。观察器也被终止时，由下次主实例启动补录最后现场。
- `Source/PuddingDesktop/App.xaml.cs`、`MainWindow.xaml.cs`、`DesktopTrayIcon.cs`：接入 UI/AppDomain/未观察任务异常与 ProcessExit，5 秒快照、Core/Shell 状态变更、Windows 会话结束 flags、关闭请求与关闭完成分离。
- `Source/PuddingDesktop.WpfArchive/Diagnostics/DesktopDiagnosticLog.cs`：异常日志增加 PID/runId、脱敏与轮转；`Runtime/DiagnosticBundleService.cs` 导出最近三次运行的指定现场文件。
- Desktop 构建/发布将观察器放入 `observer/`；同步解决方案、代码地图与[诊断手册](../../../08_how_debuge/11-案例-桌面与Core启动.md)。
- 为完成当前源码构建，修复已有两处阻塞：`MainWindow.xaml` 将设计令牌移至 ThemeDictionaries 之后，消除 WMC0035（值不变）；`BrowserScreenshotProductPipelineTests.cs` 的测试替身补齐已有接口方法。
