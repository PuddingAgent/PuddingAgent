# 2026-10-23 零 LLM 确定性载荷剪枝：S1–S5 落地

## 目标 / 背景

发请求前，历史里的工具结果经常带有大段重复载荷（同一次 `search_grep` 被重放两次、整份日志回放）。
旧路径只有两种手段：**花钱的 LLM 摘要**（`ContextCompactionService`）与**硬上限驱逐/抛错**（`LlmRequestBudgetGuard.Prepare`）。
两者都昂贵或破坏性。新增 `PuddingContextPruning` 组件，先用**零 LLM、确定性**的手段把明显冗余的字节压下来；
回收量不足就整份回退，绝不为了几百 token 重写整个前缀（前缀缓存优先）。

## 改动

### 新增组件（S1–S4，独立工程 + 独立测试工程）

- `Source/PuddingContextPruning/PuddingContextPruning.csproj` — 叶子工程，`ProjectReference` 只有 `PuddingCore` 一条（编译期强制依赖方向）。
- `Source/PuddingContextPruning/DeterministicPayloadCompaction.cs` — `TryApply`：去重 → 首尾摘要 → 参数截断 → 准入地板，按序不可交换；受保护尾部回退保证「工具调用 / 工具结果」不被劈开；所有 no-op 路径返回入参列表**同一实例**。
- `Source/PuddingContextPruning/DeterministicPruneOptions.cs` — 10 个阈值 + `Validate()` 启动期 fail-fast（单值 → `ArgumentOutOfRangeException`，跨字段 → `InvalidOperationException`）。
- `Source/PuddingContextPruning/PruneOutcome.cs` — `PruneNoOpReason` / `PruneStats` / `PruneOutcome`。
- `Source/PuddingContextPruning/TokenCounting.cs` — 自带 `ITextTokenCounter` / `CharacterRatioTokenCounter`（4 字符/token）与 `PruneTokenMath`，**不复用** `internal ContextBudgetManager` 的记账口径（两者数字不必相等）。
- `Source/PuddingContextPruningTests/` — 独立测试工程 29 例（行为 17 + 配置校验 9 + 边界 3），含 S4 边界断言（探测器自检 + 进程实际加载程序集 + `*.deps.json` 依赖闭包）。

### S5 接入宿主（本轮）

- `Source/PuddingRuntime/PuddingRuntime.csproj` — 新增 `ProjectReference` 指向 `PuddingContextPruning`（依赖面仍只有 `PuddingCore` 一条出边）。
- `Source/PuddingRuntime/Services/LlmRequestBudgetGuard.cs` — `Prepare` 新增尾随参数 `bool deterministicPruneEnabled = true`；在 `CaptureLlmRequest` **之前**调用 `DeterministicPayloadCompaction.TryApply`，命中时写 Information 日志标签 `[LlmRequestBudgetGuard:DeterministicPrune]`（`deduplicated` / `summarized` / `truncatedArguments` / `reclaimedTokens` / `before` / `after`）。
  - 顺序是契约：`CaptureLlmRequest` 会发布本次请求的冻结测量，先剪枝再测量，账户数字才对得上真正发出去的内容。
  - 不增删消息，因此 `RemovedMessageCount` 语义不变；受保护尾部（默认 8 条）内的当前轮工具载荷一律不动。
- `PuddingAgentNetwork.slnx` — 登记组件工程与测试工程。
- `Source/PuddingRuntimeTests/Services/LlmRequestBudgetGuardDeterministicPruneTests.cs` — 新增 3 例：默认剪枝且尾部逐字 / 关掉开关逐字回退旧行为 / 小载荷不动且无剪枝证据。
- 索引：根 `code_map.md` 新增组件行；`Source/PuddingRuntime/code_map.md` 在 `LlmRequestBudgetGuard.cs` 条目补接入语义；`Source/PuddingContextPruning/code_map.md` 更新状态并指向本日志。

## 影响与回滚

- **行为**：默认开启。仅在「可剪枝区」内生效（受保护尾部之外、非 `System`、非 `IsContextSummary`、非多模态 `ContentParts`），且回收量须达 `MinReclaimTokens=2000` 与 `MinReclaimRatio=0.05` 双地板，否则整份回退。
- **回滚**：`LlmRequestBudgetGuard.Prepare(..., deterministicPruneEnabled: false)` 即逐字回到接入前行为（用例 `Prepare_IsVerbatimBackwardCompatible_WhenDeterministicPruneDisabled` 锁死）。无需回滚配置或数据。
- **生效条件**：宿主需重启（`bootstrap_reboot`）才会用上新程序集；本次**未**执行重启，运行时行为尚未在真实流量上观测。
