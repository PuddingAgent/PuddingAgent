# 2026-10-19 浏览器面板折叠时截图自动展开修复

## 现象与定性

工具工作区（右侧工具面板）被折叠时，WebView2 表面 `Control.IsVisible=false`，`Page.captureScreenshot` 在执行前就被前置检查拒绝：

```text
browser_capability_failed:
Screenshot requires a visible browser surface; open the tool panel and select this browser tab.
```

实测已排除参数与超时因素：同一页在面板展开时 `png/original`、`jpeg/low`、`region` 三档全部成功；面板折叠时两种 `detail/format` 组合给出**逐字相同**的拒绝。因此这不是"页面不可截图"，而是**工具链把 UI 可见性当成了调用方的前置义务**——用户的实际期望是"浏览器工具应该自己把面板打开"。

## 修复

按"呈现是独立能力"拆开，避免把 UI 语义塞进生命周期端口：

| 层 | 改动 |
|---|---|
| 契约 | 新增 `IBrowserPagePresenter.PresentPageAsync(contextId, pageId, ct)`：把页面变成可见前台标签；与 `IBrowserWorkspaceLifecycle` 分离，无 UI 宿主/测试替身不必实现 |
| 工作区 | `BrowserWorkspaceController` 实现该端口：**先**请 Shell 展开承载区，**再**激活表面（顺序不可反：折叠时激活，表面仍不可见）；并发受同一把 `_gate` 保护 |
| Shell | `MainWindow.PresentBrowserPageAsync`：`SetToolExpanded(true)` + 选中该页标签 + `ApplyBrowserSurfaceAppearance()` + `ToolPanel.UpdateLayout()`（表面需要非零尺寸才能出图） |
| 表面 | `BrowserRuntimeDesktopSurface.ScreenshotAsync` 命中 `browser_not_available` 时先呈现，**只重试一次**；没有呈现端口或呈现抛错则保留原始失败 |

关键取舍：**用户手动折叠只抑制"后台活动自动弹面板"，不应让需要真实渲染的调用必然失败**。原 `ToolWorkspaceActivityPolicy.IsSuppressedByUser` 的语义保持不变，本次走的是显式呈现路径，不改自动展开偏好。

## 验证

- `Pudding.DesktopSurface.BrowserTests` **93 / 93 通过**（新增 3 例：呈现后重试一次 / 无呈现端口不重试 / 呈现抛错保留原失败且不重试）。
- **变异取红**：把 `TryPresentPageAsync` 的 `return true` 改成 `return false`（呈现后仍报"未呈现"），`HiddenSurfacePresentsThePageThenRetriesExactlyOnce` 失败，`Expected: 2, Actual: 1`（重试被跳过）；复原后 93 / 93 绿。
- 编译：`Pudding.DesktopSurface.Browser` 0 错误、`PuddingDesktop`（WinUI）0 错误、`PuddingDesktop.WpfArchive` 0 错误。
- 首次变异尝试用 `if (true)` 短路，触发 `CS0162 无法访问的代码` ⇒ 属**编译红**而非行为红，已换成可编译变异重做，不把编译失败当作测试有效性证据。
