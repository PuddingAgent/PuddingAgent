# 2026-10-12 SSH B4：真实 SFTP 传输探针与关闭顺序缺陷修补

## 目标 / 背景

设计 §4 要求「真实网络的不可控交还时序继续用假端口补证，但不能用假端口的自报替代实际 socket 证据」；
切片 B 的验收终点是「不覆盖/临时文件/路径/字节预算矩阵通过 + 实际传输验收」。本步把传输放进真实矩阵。

## 改动

- `Source/PuddingSsh.Probe/Program.TransferScenario.cs`（新）+ `ProbeOptions`/`Program` 接线：
  `transfer` 场景在真实 OpenSSH 上依次验证：**能力实测落盘**、上传（1 MiB，字节与 sha 记录）、
  默认不覆盖被拒（`ssh.remote_path_exists`）、显式覆盖成功、超限中止（`ssh.transfer_too_large`，零残留）、
  远端路径越出允许根（`ssh.remote_path_invalid`）、本地路径越出工作区根（`ssh.local_path_invalid`）、
  跨根拒绝（上传根里的文件用配置的下载根去下载 ⇒ 拒绝）、下载往返**字节一致**、
  取消（128 MiB + 250 ms 宿主 deadline ⇒ 本端终止、清理收敛、无部分目标）。
- `TestScripts/ssh-probe/run-ssh-probe.ps1`：新增 `transfer` 场景与**出带证据**——
  ①服务端 `sha256sum` 必须等于探针本地算出的期望值（覆盖后的内容）；②允许根内 `find -name '.pudding-tmp-*'` 计数必须为 0；
  ③超限/路径拒绝不得产生文件；④取消后的目标**若存在必须字节完整**（不允许部分写入）；⑤服务端认证次数不得多于探针自报连接数。
- `TestScripts/ssh-probe/setup-wsl-sshd.sh`：夹具 sshd_config 补 `Subsystem sftp internal-sftp`。
  **这一条是真实门禁抓出来的**：自定义配置不继承 `/etc/ssh/sshd_config` 的 `Subsystem`，缺它时
  `SftpClient.Connect()` 被服务端拒绝（`phase=Connecting` + 裸 `SshException`），传输路径根本进不去。
- `Source/PuddingSsh/Transport/SshSftpTransferSession.cs` + `Execution/SshOperationCoordinator.cs`：
  修掉出带 sha256 检查发现的**真缺陷**——本地 deadline 触发后协调器立即关闭会话通道，
  而**仍在写入**的传输任务随即发现通道已关，它的清理路径（删除本次目标/临时文件）来不及执行，
  服务端留下**部分写入的 big.bin**（客户端自述 `left_behind=False`，只有出带 sha256 才暴露）。
  现在带预算释放会先 `RequestAbort()` 并**等飞行中的传输观察中止、完成清理**（有界等待），再关通道；
  传输阶段被放弃时状态也如实映射为 Cancelled/TimedOut 而不是 Failed。
- 测试：`SshFakes.Transfer.cs` 的假通道补上「Dispose 后拒绝使用」的真实语义；
  `SshTransferSessionTests` 新增 `DisposeWithBudget_RunsAfterInFlightTransferCleansUp_SoNoPartialTargetSurvives`
  （**变异取红**：去掉等待 ⇒ 该门禁失败；恢复后通过）。单测 **289/289**。

## 验证（冻结树，真实 OpenSSH_10.2p1 / Ubuntu 26.04.1 LTS）

```
powershell -File TestScripts\ssh-probe\run-ssh-probe.ps1
→ 24 场景 failures = 0（原 23 + transfer），transfer.auth_delta = 6，出带 sha256 与服务端一致
```

`transfer` 场景关键事实：`capabilities = atomic_replace=True rename_no_overwrite=True exclusive_create=True`；
`upload_bytes=1048576`、`download_bytes=262144` 且往返 sha 相同；`no_overwrite_error=ssh.remote_path_exists`；
`too_large_error=ssh.transfer_too_large`；`remote/local/cross_root` 三种 `*_path_invalid`；
`cancel_status=TimedOut`、`cancel_cleanup_state=Completed`、服务端上传根只剩 `payload.bin`（无部分目标、无临时文件）。

**实测修正了一个假设**：OpenSSH `internal-sftp` 的标准 SFTP RENAME **不覆盖**已有目标
（`rename_no_overwrite=True`）——与我在 B2 里基于文档的推断相反。当前实现仍按实测能力选择发布语义，
因此无论服务端覆盖与否都不会用竞态冒充原子性。
