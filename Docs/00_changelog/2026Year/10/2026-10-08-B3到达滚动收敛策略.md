# 2026-10-08 B3 到达滚动收敛策略

## 目标 / 背景

B3 剩一件事：**到达类滚动目标**（`to_top`/`to_bottom`；`to_ref` 同族）。现状是诚实的但不完整：

- 原生路径**明确拒绝**了它们（`UnsupportedCapability`："native scroll does not implement target … use input_mode=dom"）
  —— 这是对的行为（不静默回落）；
- 但**功能本身没有**。

原生滚轮没有「滚到底」这种原子操作：只能按步送滚轮事件。因此第一步是把**"什么时候停"**这件事做对，
它是这个功能里唯一容易出严重错误的地方 —— G8 明确写着：**零位移不能假称滚动成功**。

## 改动

`Source/PuddingBrowser.Automation/ArrivalScroll.cs`（新增，纯函数）：

| 类型 | 作用 |
|---|---|
| `ArrivalTarget` | `Top` / `Bottom` |
| `ArrivalStep` | 下一步位移 + 是否继续 + **停止原因** |
| `ArrivalScroll.Plan` | 三个停止条件：**到限**（位置+视口覆盖内容高度 / 到顶后 ≤ 0）、**位置不再变化**（停在边界或被容器挡住）、**步数封顶**（`MaxSteps=40`，保护无限滚动页面）；拿不到可用几何（内容/视口 ≤ 0）⇒ 直接停并如实说明 |

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **303 / 303**（原 295 ＋ 8） |
| `Contracts` · `DesktopService` · `DesktopSurface.Browser` · `AgentTools` | 153/153 · 278/278 · 66/66 · 64/64 |

新增门禁：向下继续、向上用负位移并在顶部停；到达底部（内容 5000 − 视口 800 = 4200）停止；**位置没变即停**
（G8 的关键一条）；步数封顶（上限前一步仍可继续，用"内容持续增长的无限滚动页"构造）；几何缺失即拒绝而不是猜；
内容比视口矮时上下都算到位；非法步长/负步数抛参数异常。

**取红实测**：把"位置不再变化"的判定改成永不命中 ⇒ `AStalledPosition…` **恰好变红**；复原后 303/303 复绿。

**顺带修正自己的一个用例**：我最初的"步数封顶"用例给了 `position=100000` 与 `contentHeight=5000`，
于是先命中"已经在底部"而不是步数上限 —— 组件的判定是对的，**是用例的几何自相矛盾**，已改成"内容持续增长"。

## 已知边界（诚实登记）

- **只有策略，还没有驱动接线**：原生 scroll 的"到位"循环（送轮 → 读位置/几何 → 再决策）尚未实现，
  因此 `to_top`/`to_bottom` 在原生路径**仍然被明确拒绝**（行为未变）。
- **回读位置与几何需要看 DOM**：实现循环需要在原生路径上读取滚动位置与容器几何（现有 DOM 客户端有脚本求值能力），
  这属于驱动改动，且**在本环境无法真机验证**（没有 WebView2）。
- **`to_ref` 未纳入**：它的"到位"需要先解析参考点位置，与顶/底不同（登记为后续）。
- **不做平滑滚动/惯性等待**：每步之间是否等待渲染由驱动决定，本策略不含时序。
- 真机无关（纯逻辑）。

## 影响与回滚

- **无对外行为变化**：新增组件尚无生产调用方；原生路径对到达类目标仍按原样明确拒绝。
- 回滚：删除 `ArrivalScroll.cs` 与其测试、还原冻结表。
