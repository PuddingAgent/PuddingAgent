# 2026-10-08 B3 停止原因回给调用方

## 目标 / 背景

上一轮实现到达滚动循环时，策略给出的 `StopReason`（到限 / 位置不再变化 / 步数封顶）**只用于驱动内部终止**，
调用方看不到 —— 结果「停在边界」与「滚不动」在回执里长得一样。G8 要求滚动反馈如实，本轮补上。

## 改动

| 层 | 改动 |
|---|---|
| `PuddingBrowser.Abstractions.ScrollOutcome` | 新增 `StopReason`（可空；按位移滚动为 `null`） |
| 驱动 | 到达循环把停止原因**返回**；收尾回读结果用 `outcome with { StopReason = … }` 带上；驱动**硬上限兜底**时也如实说明（"stopped after the driver's hard cap of 64 steps"，即"是我停的，不是策略停的"） |
| `Pudding.Contracts.DesktopScrollReport` | 新增 `stopReason` 构造参数与 `StopReason` 属性 |
| 能力通道 | 把 `scrollOutcome.StopReason` 映射进 `DesktopScrollReport` |

## 验证

| 套件 | 结果 |
|---|---|
| `DesktopSurface.BrowserTests` | **66 / 66**（含新增断言：`to_bottom`+native 的回执带上 `"already at the bottom"`） |
| `Contracts` · `DesktopServiceTests` · `AutomationTests` · `AgentTools` · `PuddingDesktop` · `Host` | 153/153 · 281/281 · 303/303 · 64/64 · 320/320 · 258/258 |
| 构建 | `Abstractions` · `WebView2` · `DesktopSurface.Browser` 已成功生成 |

新增门禁：驱动报出停止原因时，能力通道的回执**确实带上**它（替身驱动模拟"到底了且没加载新内容"的场景）；
按位移滚动仍为 `null`（不编造）。

**既有 flake**：`Host.Tests` 的
`DesktopBrowserBridgeHandshakeTests.SecondConnection_CannotReplaceAwaitingHelloConnection`
本轮全量失败 1 次、重跑通过（与本次改动无关，已多轮记录）。

## 已知边界（诚实登记）

- **真机未验证**：停止原因来自策略判定 + 驱动回读；真实页面上"到底"的判定是否与被测站点一致仍需外部 smoke。
- **驱动硬上限（64）与策略上限（40）不一致是刻意的**：前者是"绝不失控"的兜底，后者是语义上限；
  兜底触发时会明确写成"driver's hard cap"，不会冒充策略的结论。
- **停止原因未进工具面输出**：目前到 `DesktopScrollReport`（契约/能力通道）为止；
  是否需要出现在 `browser_interact` 的 Agent 可见回执里，属工具面设计决定（未擅自加）。
- **`contentChanged` 的"等新增内容"仍未做**：G8 里「无限滚动等新条目后报告 contentChanged」需要等待语义
  （`browser_wait_for` 的条件种类），尚未实现 —— 本轮只把**已有的** `contentChanged` 事实继续如实传递。
- 嵌套容器内的到达滚动仍未处理（回读几何只看 `document.scrollingElement`）。

## 影响与回滚

- **接口/契约新增可空字段**：不破坏既有调用（默认 `null`）。
- **行为变化（Agent 可见）**：`browser_interact` 的滚动回执里多了一个 `stopReason`（仅到达滚动有）。
- 回滚：删除三处字段与映射、还原驱动循环的返回值与用例断言。
