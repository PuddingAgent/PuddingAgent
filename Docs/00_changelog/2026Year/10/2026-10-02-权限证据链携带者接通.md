# 权限证据链第一阶段：携带者接通（证据经工具作用域进入能力调用上下文）

## 改动

| 文件 | 改动 |
|---|---|
| `Source/Pudding.Contracts/Desktop/DesktopCapabilityCallContextFactory.cs` | 新增重载 `TryCreate(string? permissionEvidenceSummary, TimeSpan? timeout = null)`；注释写明摘要是字符串的原因（本程序集不能引用 `PuddingCore`，边界由编译期强制）与**不上线缆**的事实 |
| `Source/PuddingBrowser.AgentTools/BrowserAgentToolBase.cs` | 复用既有 `BeginExecutionScope` 模式：新增 AsyncLocal 权限证据作用域（工具是 DI 单例，**不能**用字段存每次调用的状态）+ 受保护的读取器 `CurrentPermissionEvidenceSummary()`；`CompositeScope`/`EvidenceScope` 保证退出时两者都被还原 |
| 七个工具（11 处调用点） | `callContexts.TryCreate()` → `callContexts.TryCreate(CurrentPermissionEvidenceSummary())` |
| `Source/PuddingHost/Hosting/ConnectedDesktopCallContextFactory.cs` | 实现新重载：把摘要写进 `DesktopCallContext.PermissionEvidenceSummary`（进程内字段） |
| `Tests/.../BrowserAgentToolsTests.cs` | 替身工厂实现新重载（透传） |

## 语义

- **仍然只携带、不拒绝**（第一阶段）：除上下文多一个字段外，任何调用路径的结果都不变；
- 摘要形如 `decision=allowed;source=workspace-guard`；**未评估 ⇒ `null`**，不伪造 `denied`；
- 证据**不上线缆**：Desktop 侧由 `operation_id`/`generation`/`deadline` 重建上下文，因此该字段在 Desktop 侧恒为 `null`
  ——这正是设计意图（证据留 Core、由接缝自校验）。

## 验证

- `PuddingBrowser.AgentTools` 与 `PuddingHost` 构建 **0 错误**；
- `PuddingBrowser.AgentTools.Tests` **15/15**（覆盖七个工具的调用路径）；
- `PuddingHost.Tests` **234/234**（含经认证 Bridge 的真实往返用例）；
- **过程中的一次假失败已查明**：`PuddingHost.Tests` 首跑出现 1 个失败
  （`S5IndexSupplyHostWiringTests.A3_OverBudget…`，索引供给域），重跑即 **234/234**；
  同一时刻工作树里有另一位协作者正在改 `Source/PuddingCodeIndex/Storage/SqliteCodeIndexStore.cs`
  （`git status` 可见），而我的三个文件与 `Index|Supply` **零交集**（逐文件统计 0 命中）
  ⇒ 判定为**他人 WIP 引起的瞬时失败**，非本次改动；
- **未验证**：证据是否真的随真实工具调用落到上下文里（需要一个断言"上下文含摘要"的用例，
  下一轮与"观察者"一起补；本轮靠编译期 + 既有 15/15 用例保证不回归）。
