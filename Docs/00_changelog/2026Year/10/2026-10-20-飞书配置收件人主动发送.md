# 2026-10-20 飞书配置收件人主动发送

## 改动

- `Source/PuddingCore/Platform/FeishuRecipientContracts.cs` 与 `Source/PuddingPlatform/Services/FeishuRecipientDirectory.cs`：增加配置收件人目录，限定当前工作区、Agent 的启用且唯一绑定渠道；复用特权用户 Open ID 白名单，不向工具暴露凭据。
- `Source/PuddingRuntime/Tools/BuiltIns/Messaging/ListFeishuRecipientsTool.cs`、`SendMessageTool.cs`：查询候选，显式 Open ID 主动发送；唯一候选可默认，多人/多渠道要求选择。当前飞书回合的别名回复保留；拒绝混合目标和广播，子代理按配置 Agent 查询。
- `Source/PuddingCore/Platform/GatewayCommandRouteContracts.cs` 与 `Source/PuddingPlatform/Services/GatewayCommandRouteReader.cs`：移除最近入站路由扫描。
- `Source/PuddingHost/Services/ConnectorDeliveryDispatcher.cs`：显式 open_id 投递独立于 chat_id/message_id，重试保持同一 uuid；Host DI 注册新目录和工具。`ToolProfileConfig.cs` 允许心跳及子代理发现收件人工具。
- `Source/PuddingPlatformAdmin/src/pages/workspace/[id]/index.tsx`：说明白名单兼作收件人、单人默认/多人选择；前端版本 `6.9.11`。同步根及相关子项目代码地图和 `.pudding/skills/heartbeat-feishu-report/SKILL.md` 的调用说明。

- `PuddingHost.Tests` 的 `ConnectorRecipientDeliveryTests`、`PuddingApplicationHostCompositionTests`：4/4，覆盖重试目标/uuid 不变、旧回复锚点清理及未知 ID 类型拒绝。
- `HarnessAgent.Core.Tests` 的 `FeishuClientReplyTests`：7/7，含 open_id 发送 HTTP 协议断言。合计 52/52。

## 未完成与交付边界

代码达到 `ready-for-external-deploy`。本条记录时尚未部署新 Core/前端；真实飞书应用权限、用户可用范围与实际送达未验证。语音/图片调试及终态投影仍沿用当前会话回信路由，不属于本次文本主动发送修改范围。

## 配置与回滚

不迁移数据，不修改现有 DataRoot 白名单。通过原有渠道配置增删特权用户 Open ID 即可；收件人目录即时读取，连接器凭据/绑定修改仍遵守现有生命周期。回滚本次代码和对应前端构建即可恢复旧行为。
