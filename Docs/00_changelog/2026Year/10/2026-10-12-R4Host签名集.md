# R4 ⑥ 签名集已抓齐

| 需要的东西 | 已确认 |
|---|---|
| 签发结果 | `DesktopBindingIssuanceOutcome(bool Issued, BrowserPageGrantId? GrantId, BrowserPageGrantEpoch Epoch, string? Reason)` |
| 生产者 | `DesktopBrowserBindingProducer` + `IssueAsync(BrowserTaskBinding, OperationId, deadline, ct)` |
| 调用者身份 | `BrowserCallerIdentity(kind, callerId, taskId = null, parentTaskId = null)`；**SubAgent 必须同时给 taskId 与 parentTaskId**（与我的标量映射一致） |
| 范围 | `BrowserPageGrantScope { None, Read, Write, … }` ⇒ 线名 `read/write` 映射，**未知 ⇒ 拒绝** |
| 撤销契约 | `BrowserBindingRevokeRequest(Task, Target)` + 能力 `BrowserBindingRevoke` + `CapabilityRequest.BindingRevoke` |

## 唯一未知点（下一轮第一件事）

**能力调用的"调用上下文"（`call`）从哪来**：既有门的发送委托形状为 `(capability, request, call, innerToken) => session.SendAsync(...)`，`call` 由 **Producer 内部构造**并回调；**撤销侧无 Producer** ⇒ 需查 `DesktopSession.cs` 的 `SendAsync` 与调用上下文类型定义，或找更高层撤销入口。查清后端口类可**一次成型**。

## 诚实边界

- 本轮**只读抓签名**；端口**未实现**；**未真机验证**。
