# 2026-10-08 §4.3/§6.1 数字对账（续）

## ① §4.3 受限缓存：**完全一致** ✅

| 文档 | 代码 |
|---|---|
| 5 分钟 | `BrowserOperationLedgerOptions.TerminalRetention = TimeSpan.FromMinutes(5)` |
| 1,024 项 | `MaxEntries = 1024` |
| running 不因容量淘汰、容量耗尽拒绝新写 | `Capacity_Exhaustion_Refuses_New_Writes_And_Never_Evicts_In_Flight_Work` |
| 过期重传 `receipt_expired` | `Expired_Terminal_Receipt_Reports_Receipt_Expired_Instead_Of_A_New_Action` |

而且已有用例直接断言默认值（`Default_Options_Match_The_Design_Budget`）⇒ 文档数字与代码**被门禁钉在一起**。

## ② §6.1 各模式输出预算：四条一致 ✅，**full 模式缺** ❌

| mode | 文档 | 代码 | 判定 |
|---|---|---|---|
| outline / interactive | 50 条 / 4,096 B | 参数默认 limit=50、max_bytes=4096 | ✅ |
| text | 4,096 B/页、游标续读 | `ArticleMarkdown.DefaultMaxBytes` = `ArticleCompactJson.DefaultMaxBytes` = 4096 | ✅ |
| extract | 默认 10 条 / 4,096；可请求 1,536 | G5 用例断言 10 与 1536 | ✅ |
| **full** | **默认 16 KiB、硬上限 64 KiB**，分页/截断声明 | ❌ **没有输出预算**：直接回原始表示（受 Desktop 侧 maxNodes / MaxTextLength 约束）；**全仓库找不到** 16 KiB / 64 KiB 这两个数；任何截断都记 `incomplete_scan` —— 因为**不存在**输出上限，`output_budget` 在 full 模式永远不会出现 | ❌ **偏差** |

## 为什么不擅自补

给 full 模式加 16 KiB 默认 / 64 KiB 上限会**改变显式调试模式的行为**，而文档同一段也说明这些预算需
**真实驱动样本校准** ⇒ 与上一轮同一口径：**登记偏差，不改行为**（推进需要产品明确或真机样本）。

## 验证

| 项 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **337 / 337**（偏差门禁已扩展：同时钉住 4096 这两个默认值与 full 偏差记录） |
| **取红实测** | 把记录里的「full 模式缺输出预算」改掉 ⇒ 门禁**变红**；还原即绿 |
| **全量链** | **1595 / 0**、无重试（第一次跑遇 Host 已知 flake ⇒ 清单**拒绝产出**，重跑才绿） |
| 门禁噪音 | 本轮第三次踩到：表格里给**生产成员**加反引号会被名字门禁当成用例名 ⇒ 表格中只用反引号标**用例名**（已固化习惯） |

## 诚实边界（诚实登记）

- **outline/interactive 的 50/4096 是"参数默认值"**：它们可由调用方覆盖（文档也允许）⇒ 与"硬上限"不是同一类断言。
- **full 模式的偏差只登记未修**；`incomplete_scan` 的语义在 full 下**是准确的**（确实只受扫描上限约束），
  但文档承诺的"分页/截断声明"里的**输出维度**缺失。
- **§3/§7/§8 里仍有其它数字**（epoch、滚动步数、坐标容差等）未逐条核对 —— 登记为可继续。
- **未真机验证**；决定②与「§6.1 预算要不要按文档实现」两项仍待你拍板。
