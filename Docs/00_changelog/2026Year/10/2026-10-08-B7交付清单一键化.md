# 2026-10-08 B7 交付链一键化：采集脚本 + CLI 入口

## 目标 / 背景

上一轮把采集器写好了，但它**没有可执行入口**（我连着两轮把它登记为"仍无生产调用方"）。
本轮补上入口，并**端到端跑通一次**，产出本会话第一份真实交付清单。

## 改动

| 文件 | 作用 |
|---|---|
| `Source/Pudding.DeliveryManifest.Cli/`（新增项目，已登记进 `PuddingAgentNetwork.slnx`） | 目录 → 自检清单 → JSON；**不合格就以退出码 2 拒绝产出**并把具体原因打到 stderr；`--out` 同时写文件 |
| `TestScripts/delivery-manifest.ps1`（新增） | 按 `Agents.md` 隔离要求：TRX 落 `temp/test-out`、产物落 `temp/build`、串行 build/test/publish；跑各套件（失败也继续，让清单如实反映）→ 调 CLI → 打印清单 |
| `KnownUnverifiedExtractor`（修） | **跳过 YAML front matter**：它的 `description`/`tags` 里也有"未验证"字样，实测会把文档摘要混进交接清单 |

## 验证（**真实端到端**）

在本环境执行（两个真实套件 + 真实 TRX + 日志目录）：

```
& .\TestScripts\delivery-manifest.ps1 -PublishDirectory "Source/Pudding.DeliveryManifest.Cli/bin/Debug/net10.0" `
    -Suites @("...AutomationTests.csproj","...ContractsTests.csproj") -BuildId "round-62"
⇒ === manifest emitted (stage: ready-for-external-deploy)
```

产出的清单（`temp/test-out/delivery-manifest.json`）：`build=round-62`、`commit=104d029`、产物取自发布目录、
`checks` 来自两个套件的 TRX、`stage: ready-for-external-deploy`、`requiredExternalSteps` 为生命周期四步，
并**自动带上 20 条"内部证明不了的结论"**（都是本会话 changelog 里如实登记的「真机未验证：本环境没有 WebView2」等）。

另验证了**拒绝路径**：`-SkipTests` 且结果目录没有 TRX ⇒ CLI 以退出码 2 拒绝产出并逐条打印原因
（"no TRX results found …"）—— 即"事实不完整就不给清单"。

| 套件 | 结果 |
|---|---|
| `DesktopServiceTests` | **272 / 272** |
| `Automation` · `Contracts` · `AgentTools` · `DesktopSurface.Browser` · `PuddingDesktop` · `Host` | 276/276 · 153/153 · 64/64 · 66/66 · 320/320 · 258/258 |
| 构建 | CLI 项目 0 警告 0 错误 |

## 已知边界（诚实登记）

- **脚本只验证了两条快速套件**（交叉验证 CLI/脚本本身）；全量七套件的脚本运行未在本轮执行
  （`-Suites` 默认就是七个，但耗时更长）。这份清单里因此只有两条 checks —— 这是**如实**的：
  清单只声明它实际跑过的检查。
- **发布目录未真正发布**：本轮用 CLI 自己的输出目录充当 `--publish`（为了验证链路）；
  真正的 `dotnet publish`（`temp/build/desktop-preview`）未执行 —— Desktop 发布需串行且会被运行中的
  Shell 进程占用输出文件（本会话已多次遇到 MSB3027/MSB3021）。
- **外部那一半仍未开始**：脚本不做启动/重启/崩溃恢复/退出回收，也不部署到新构建；
  这些以 `requiredExternalSteps` 明确交出去。
- **清单仍无持久化留痕**（写到 `temp/test-out` 会被清理；正式留痕需要 `Docs/14_reports/`，属后续）。
- **提取器仍是保守词表**：20 条上限会被填满（本仓库的未验证项确实很多），长列表需要人工挑选精简。
- 脚本用 ASCII 消息：Windows PowerShell 5.1 读无 BOM 的 UTF-8 会把中文读成乱码（本轮踩到并有记录）。

## 影响与回滚

- **新增可执行入口**：`dotnet run --project Source/Pudding.DeliveryManifest.Cli` 或脚本；不改动产品路径。
- 回滚：删除 CLI 项目（含 slnx 行）、脚本、提取器的 front matter 跳过逻辑。
