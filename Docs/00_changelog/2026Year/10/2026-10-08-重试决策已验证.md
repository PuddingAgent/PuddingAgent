# 2026-10-08 横向：可选重试的决策逻辑已验证

## 目标 / 背景

round-95 给交付脚本加了 `-RetryFailedSuites`（默认关闭、重试可见），但当时**如实登记为未验证**：
现实中没有套件会"按需失败"，所以重试分支从未被触发过。

## 改动

`TestScripts/delivery-manifest.ps1` 新增 **`-DryRunRetry`**（**早退**模式）：

- 只读磁盘上已存在的 TRX，打印每个套件的失败计数与**是否会被重试**；
- **不执行任何测试**、不产出清单（`exit 0`）；
- 因此可以用"构造 TRX"的方式对重试**决策**做端到端验证。

## 验证（真实执行）

用两个构造的 TRX（`Pudding.ContractsTests` 全绿、`Pudding.DesktopServiceTests` `failed=1`）：

| 场景 | 输出 |
|---|---|
| 默认（`-RetryFailedSuites` 缺省 0） | `Pudding.ContractsTests : failed=0 (would NOT retry)`；`Pudding.DesktopServiceTests : failed=1 but -RetryFailedSuites is 0 => would NOT retry` |
| `-RetryFailedSuites 1` | `Pudding.ContractsTests : failed=0 (would NOT retry)`；`Pudding.DesktopServiceTests : failed=1 => WOULD RETRY (max 1 attempt(s))` |

⇒ 两条路径都符合预期：**默认绝不重试**；启用后**只重试失败的套件**。

**实现中被我纠到的一处位置错误**：dry-run 块最初写在 `if (-not $SkipTests) { … }` **内部**，
于是 `-SkipTests`（验证时正是要用的模式）下它**根本不执行** —— 表现为"跑了但什么都没打印"。
已改为 banner 之后的**早退分支**，并在注释里写明"必须放在该保护之外"。

## 已知边界（诚实登记）

- **验证的是"决策"，不是"重跑"**：`-RetryFailedSuites` 真正**重跑测试并改名 TRX** 的那段路径
  仍未在真实失败场景触发过（登记为未验证；下次遇到失败时优先用它并记录结果）。
- **构造的 TRX 只含 `<Counters>`**：够验证决策（脚本正是读这个字段），但不代表完整 TRX 结构。
- **`-retried` 后缀会出现在清单检查名里**（有意的可见性设计）。
- 无产品行为变化（工具脚本）。
