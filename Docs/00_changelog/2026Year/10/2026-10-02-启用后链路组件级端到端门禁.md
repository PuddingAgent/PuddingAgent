# 2026-10-02 启用后链路组件级端到端门禁

## 为什么补这一条

前面每一刀都各自锁定一层语义（接缝路由、指纹、原子替换、账本、计划…），但**没有一条用例**
回答过「把它们按生产接线装起来、跑一次真实改动，索引里到底有没有正确的符号」。
新链路已在产品宿主启用，这个缺口必须由一条**组件级端到端**用例补上。

## 改动

- 新增 `Source/PuddingCodeIntelligenceTests/Services/EndToEndSourceMaintenanceTests.cs`（2 条）：
  在真实临时仓库里装配**生产接线**的对象图 —— `CodeIndexMaintenanceService`（Coordinator 模式）
  → `CodeSourceMaintenanceCoordinator` → `CodeSourceScanService` + `FileSystemCodeSourceScanner`
  → `CompositeCodeIndexer`（**真实** `RoslynCSharpIndexer` + **真实** `TypeScriptIndexer`）
  → `SqliteCodeIndexStore` 的原子替换与账本，并注入 `LanguageCodeSourceConsumerInputProvider`。
  - 用例 1（真实改动）：`Alpha.cs` + `beta.ts` 各发一次 watcher 提示并到期 ⇒
    索引里真的出现 `Alpha` 与 `betaHelper`（真实 Roslyn 语义模型 + 真实 TS 提取器）；
    manifest 两条指纹与消费者水位一起落地；scope 状态事实为
    `SourceMaintenanceMode=Coordinator`、运行 1 轮、提取 2、未解决 0、**零升级**；
    并且 **`FullScanCount == 0` / `ProbeCount == 1`**（提示驱动绝不遍历整棵树）。
  - 用例 2（重复提示）：同样两个提示再来一次、内容未变 ⇒ 提取计数**仍为 2**、
    **复用计数 2**（真实工具链上不再被唤醒）、未解决仍为 0。
- 测试内自带最小 `MutableTimeProvider` 与假 watcher 工厂（本程序集内，不跨测试程序集引用）。

## 验证

- `dotnet test Source\PuddingCodeIntelligenceTests` → **136 通过 0 失败**（本次 +2，无跳过）。
- `dotnet test Source\PuddingCodeIndexTests` → **332 通过 0 失败**。
- 覆盖范围与边界：这条用例证明的是**组件级**端到端（对象图 + 真实语言工具链 + 真实文件 +
  真实 SQLite）；它**不**覆盖进程生命周期、部署与静态产物，那部分仍必须由进程外控制器重启后复核。

## 未完成与影响

- `ChangedDuringScan` 仍无生产来源（watcher 在合并批次时未记录二次观测）：不完整观测的安全网
  目前靠 racy 重叠窗口 + stat/hash 比对 + 「删除只由完整扫描确认」三条规则，这一项属加固而非缺口。
- C# 真实 MSBuild 工作区（`RoslynWorkspaceBootstrapper` 打开真实 `.csproj`）仍只有内存工作区级证据；
  跨批次工程快照缓存未做。
- 仍待**进程外控制器重启 + 四场景受控复核**。
