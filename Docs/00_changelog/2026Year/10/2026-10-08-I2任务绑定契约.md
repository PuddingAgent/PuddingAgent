# 2026-10-08 任务绑定契约（活路径签发第一件）

## 为什么先做它

round-198 查明：活路径签发的**可信触发点**是 `BrowserWorkspaceTargetBridge.SetAgentTarget`（用户把某页选定给 Agent），
但那一刻 Desktop 只知道**页面**、不知道**哪个任务**；而普通能力调用**不能**把自己授权成 owner（§4.1 明禁）
⇒ 缺的正是"grantee 从哪来"。本契约就是那个输入的形状。

## 交付

`Source/Pudding.Contracts/Desktop/BrowserTaskBinding.cs`：

| 字段 | 约束 |
|---|---|
| `Task`（grantee） | 必须过 `BrowserCallerRequirement`（唯一规则）：缺身份／冒充 User／无运行身份 ⇒ 拒绝 |
| `Target` | 用户选定的目标页（非空） |
| `Scope` | 非 `None`（不签发"没有能力的绑定"） |
| `Validity` | 必须为正 |
| `Source` | 非空、≤128（审计可追溯到具体绑定；**不接受用户文本授予能力**） |

**边界**：这里只做结构校验；有效期上限、目标是否已登记、连接世代是否存活、子代理子集仍在 `BrowserGrantIssuer`／唯一 authority 判定。
