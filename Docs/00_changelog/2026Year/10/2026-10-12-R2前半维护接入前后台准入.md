# 2026-10-12 R2（前半）：维护接入前后台准入

> 依据：[复核与验收判定](../../../14_reports/上下文治理实施复核与验收判定-2026-10-12.md) §3（R2，P1）。
> 位置引用：调度器 [Schedule](../../../../Source/PuddingRuntime/Services/PostTurnMaintenanceScheduler.cs) ·
> [Work](../../../../Source/PuddingRuntime/Services/PostTurnMaintenanceScheduler.cs) ·
> [普通压缩锁](../../../../Source/PuddingRuntime/Services/ContextCompactionService.cs) ·
> [锁内摘要调用](../../../../Source/PuddingRuntime/Services/ContextCompactionService.cs)。

## 1. 缺陷（复核探针）

- 调度器只在**下一次 `Schedule`** 时取消旧工作；新消息的 `ReserveForeground`/`AcquireForeground`
  **未注册、也未取消**这项维护。
- 后台只探一次执行门然后释放 —— 这不等于前台准入租约已释放，也不保证下一条前台消息优先。
- 探针实测：后台工作开始 → 真实 `AgentExecutionAdmissionCoordinator` 准入前台 →
  前台成功进入 `SessionExecutionGate`，**而维护 Token 仍未取消**。

## 2. 修复（前半：调度与准入接线）

### 2.1 准入协调器：新增**会话键**面（纯增量，原有 workspace+agent 面不变）

`AgentExecutionAdmissionCoordinator` 增加：

| 成员 | 语义 |
|---|---|
| `ReserveSessionForeground(workspace, session, duration?)` | 新消息受理即预留；**立刻 Preempt 同会话后台工作** |
| `AcquireSessionForeground(workspace, session)` | 真实 Turn 执行期间持有；同样抢占 |
| `HasSessionForegroundDemand(workspace, session)` | 启动前与提交前的重验依据 |
| `TryRegisterSessionBackground(workspace, session, cts)` | 有前台需求或已有同会话后台时返回 null |

两个租约类改为委托式释放（`Action`），从而同时支持 agent 面与会话面；抢占行为、
`WasPreempted` 语义不变。

### 2.2 消息受理：受理即取消

`MessageDeliveryDispatcher` 的真实用户入口在原有 `ReserveForeground(workspace, agent)`
之外，追加 `ReserveSessionForeground(payload.WorkspaceId, evt.SessionId)` ——
**不必再等下一次 Turn 结束再次 `Schedule`**。

### 2.3 调度器加固（复核 §3 的修改方案 1/4/5）

- `Schedule(workspaceId, sessionId, reason, work, candidateKey?)`：
  - **同候选合并**（candidateKey 相同）⇒ 返回 **false**、不抢占不重复执行；
    不同候选才是「最新者胜」抢占；
  - 停机后一律返回 false。
- 运行序：① 按会话注册后台（用**本任务自己的 CTS**，前台预留会取消它）
  → ② 探执行门并立刻释放（终态之后）→ ③ **再次**确认无前台需求
  → ④ 带 deadline 执行；无前台需求才注册成功，否则直接放弃（不排队阻塞新消息）。
- `finally` 用 `ICollection<KeyValuePair<,>>.Remove` **原子按键值**移除，旧任务绝不会误删新 entry。
- `StopAsync(timeout)`：取消在途并等待退出，超时保留 `DescribeInFlight()` 可诊断状态；
  单项维护默认 5 分钟 deadline，超时按取消处理。
- `AgentExecutionService` 注入可选 `admissionCoordinator` 并交给调度器；
  两条执行路径的 `Schedule` 调用改传 `(workspaceId, sessionId, …, candidateKey=历史 revision)`。

## 3. 验证（本机真实执行）

| 命令 | 结果 |
|---|---|
| `dotnet build Source/PuddingRuntime` | **exit 0** |
| `--filter AgentExecutionAdmissionCoordinatorTests|PostTurnMaintenance` | **exit 0**，失败 0 / 通过 **19** |
| `PuddingRuntimeTests` 全量 | 失败 **4** / 通过 **2063** / 跳过 6（4 个失败见下） |

### 3.1 新增/更新用例

`PostTurnMaintenanceForegroundPreemptionTests`（6 条）：

1. **核心门禁**：维护生成被人工屏障卡住 → `ReserveSessionForeground` →
   **取消被观察到** → 新 Turn（会话门 + 前台租约 + 水合/dispatch）完成 ——
   四件事**全部发生在释放屏障之前**；释放后**迟到结果零应用**（计数器为 0）。
2. 同候选重复调度合并并返回 false（只执行一次）。
3. 不同候选抢占旧的；旧任务走完 `finally` 后**新 entry 仍在途**（断言 reason 与 InFlightCount）。
4. 启动时已有前台需求 ⇒ 直接放弃（`ran == false`）。
5. `StopAsync` 取消在途并等待退出；之后 `Schedule` 返回 false。
6. deadline（200 ms）到期即协作取消。

协调器会话键（3 条）：前台预留抢占会话后台且此后不可再注册；
前台租约抢占并在释放后可再次注册（旧后台退出后）；**会话间隔离**（别的会话预留不取消本会话）。
原有调度器用例 6 条按新签名更新（补 `workspaceId`），语义不变。

### 3.2 环境失败（与本批无因果）

`PuddingRuntimeTests` 的 4 个失败仍是终端/宿主 Shell 用例（PATH 上 `python` 为
Windows Store 别名桩，exit 9009），单独跑同样失败 —— 与本批改动无因果，如实登记。

## 4. 未完成（R2 的后半，仍属 P1）

- **`CompactAsync` 拆锁未做**（复核 §3 修改方案 2/3）：普通压缩仍持 `CompactionCoordinator`
  锁跨远端摘要，下一 Turn 的水合/硬保护仍可能在该锁上排队；
  也尚未做到「后台提交按 SessionExecutionGate → CompactionCoordinator 顺序 + 提交前重验
  foreground demand / generation / revision / fence」，以及「同步硬保护消费同一提交原语」。
- **R5**（身份预检读运行实例身份、显式 pin commit、脏即拒）与 **F6**（外部部署 + 新会话真实 smoke）
  未做，仍需进程外控制器。
- 本批**未重启进程、未部署、未做真实模型调用**；不报告省时。
- 交付状态：仍**不足以**确认 `ready-for-external-deploy`（R2 后半与 R5 未完成）。
