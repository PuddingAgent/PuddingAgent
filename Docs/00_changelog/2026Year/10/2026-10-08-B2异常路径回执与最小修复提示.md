# 2026-10-08 B2 回执：驱动异常也带回执与最小修复提示

## 目标 / 背景

上一轮让 `CapabilityResult` 失败带回执，但**异常路径**（驱动抛出的 `BrowserOperationException`，
例如 `stale_element_reference`）仍走 `FromException`，只有 code/message —— 调用方看不出
「到底派发没有」。设计 §4.1 要求「失败不能丢失已经派发的事实」，§5 还要求引用过期时
返回 `stale_element_reference` **与最小刷新提示**（而不是自动点一个"看起来相同"的节点）。
本轮把异常路径也纳入回执，并让提示能真正到达调用方。

## 改动

| 文件 | 改动 |
|---|---|
| `Source/PuddingBrowser.AgentTools/BrowserOperationFailure.cs` | **新增**：异常码 → （领域错误 + 是否可重试 + 最小修复提示）的唯一映射表。`stale_element_reference` ⇒ `page_version_mismatch` 且 **retryable=false**（同一个 ref 一定再次失败）+「重新观察页面再定位，绝不自动重绑」；页面已变 ⇒ 可重试；参数错 ⇒ 不可重试；**未登记异常码 ⇒ `internal_error`**（保守当作可能已产生副作用，不得当作"没执行"） |
| `Source/PuddingBrowser.AgentTools/BrowserInteractTool.cs` | `catch (BrowserOperationException)` 也构造回执放进失败的 `value`，提示同时作为 `warnings` 暴露 |
| `Source/PuddingBrowser.Automation/BrowserInteractionReceipt.cs` | `BrowserInteractionEvidence` 增加 `Detail` 并转发给判定器（回执自带最小修复提示） |
| `Source/PuddingBrowser.Automation/BrowserReceiptJudge.cs` | 重试裁定的**兜底分支回带回执自带的提示**（原先恒为 null）：不可自动重试 ≠ 无事可做 |

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **194 / 194**（原 192 ＋ 2） |
| `PuddingBrowser.AgentTools.Tests` | **31 / 31**（原 30 ＋ 1） |
| `PuddingHost.Tests` · `PuddingDesktop.Tests` · `DesktopServiceTests` | 252/252 · 305/305 · 215/215 |

新增门禁：

- 工具层 `Interact_StaleRefException_AlsoCarriesAReceipt_WithARefreshHint`：过期引用失败带回执
  （`execution=not_started` 因为异常发生在触碰页面之前、`completion=failed`、
  `retryDisposition=not_retryable`、`retryDetail` 含 `re-observe`），提示同时出现在 `warnings`，
  且**替身页面没有记录任何动作**（确实没派发）；
- 纯逻辑层：`RetryDecision_PreservesTheReceiptsMinimalRepairHint`（兜底分支必须回带提示）与
  `RetryDecision_DoesNotInventAHint_WhenThereIsNone`（没有提示就给 null，不编造）。

**顺带修的替身缺陷**：`FakeBrowserPage` 的动作方法原先不校验 ref，于是"过期引用"在替身上
永远不会失败；现在 `Record(...)` 与真实驱动一致地在触碰页面前校验引用（这也是这条测试能成立的前提）。

**取红实测**：把重试裁定的兜底分支改回 `_ => null`（丢掉最小修复提示）⇒ `AutomationTests` **1 条** +
`AgentTools.Tests` **1 条**恰好变红，其余全绿；复原后 194/194 与 31/31 复绿。

## 已知边界（诚实登记）

- **异常路径的回执先只在 `browser_interact` 落地**：`browser_locate`/`browser_tabs` 等仍是
  `FromException`（只有 code/message）。它们没有交互回执的语义，但"失败带结构化证据"若要作为
  全局不变量，还需一次横扫（后续切片）。
- **`stale_element_reference` 复用 `page_version_mismatch` 错误码**：`DesktopCapabilityErrorCode` 里
  没有独立的"引用过期"码。回执的语义靠 `retryable=false` 与提示表达；若要更精确，应新增错误码
  （涉及契约与线缆，本轮未做）。
- 未登记异常码按 `internal_error` 处理（可能已产生副作用）：这是**保守**方向，代价是
  调用方在看到陌生码时会得到"先观察"而不是"可重试"。
- 提示文案仍是英文短语（`retryDetail` / `warnings`），未本地化。

## 影响与回滚

- **行为变化（Agent 可见）**：`browser_interact` 的异常失败现在返回带 `value` 的结构化回执与
  `warnings`；`stale_element_reference` 现在被标为**不可自动重试**并附刷新提示（此前调用方
  只看到失败消息，可能直接重发同一次调用）。
- 无数据/配置影响；线缆 DTO 与 proto 未改动。
- 回滚：删除 `BrowserOperationFailure.cs`，还原工具异常分支、回执证据与重试裁定的 3 处改动，
  以及 3 个测试文件与 code_map。
