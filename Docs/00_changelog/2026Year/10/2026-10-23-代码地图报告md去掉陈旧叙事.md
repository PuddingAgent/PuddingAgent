# 代码地图自检报告 md：去掉陈旧叙事，给生成器补取红断言

**日期**：2026-10-23 · **范围**：`Tools/Docs/code_map_check.py`（`build_markdown`）+ `Tools/Docs/code_map_check_selftest.py` + 根 `code_map.md` 指纹

## 问题：报告自称「本次运行」，其实在复述作者那一轮

`--report-md` 产出的 §0 是一段**写死在生成器源码里的手写叙事**：

```
## 0. 本次做了什么
- 交付 3 件新增物：…
- 未修改任何 code_map.md；未做任何 git 写操作。
```

它描述的是一次已经过去的历史动作（当初创建这套工具的会话），但位置和措辞都让读者以为它是**本次运行**的结论。同一份文件里，§1 起的数字全部来自当次的结构化报告，唯有 §0 是记忆 —— 一份数据驱动的报告里混入一段不可复核的自述，比缺这一节更糟：它把「工具行为」和「某一轮做过什么」压成同一句话，读的人无法分辨哪句能当证据。

第二处同类缺陷：§7「复现」代码块把命令写死成 `temp/code_map_selfcheck.*`，而规范要求复现的是**真实调用**；实际用 `--paths` / `--report` / `--report-md` 的调用照抄这段命令，跑出来的是另一份文件。

两处都属于「陈旧投影」（stale projection）：生成器把一次性事实固化成模板，之后每次运行都替历史作证。

## 改动

1. **§0 改为数据驱动**：标题 `## 0. 本次运行`，正文是一张由当次报告数据填的三行小表 —— 门禁（`gate`）、扫描的 `code_map.md` 个数（`code_map_files`）、违规条目数（`len(report["violations"])`，并注明「明细见 §5，逐条不折叠」）。
2. **固定说明显式降级**：原「工具性质」段落保留，但标注为「**固定说明**，不是某一次运行的结论」，与当次结论在视觉上分开，不再冒充结论。
3. **§7 复现命令回显真实调用**：代码块改为插入 `A(command_line)`，与 §0 末的「调用：」一致；删掉写死的 `temp/code_map_selfcheck.*` 那行。
4. **自测新增 `stage_markdown_report`**（`report-md: …` 五条断言，覆盖「能取红」）：
   - §0 存在，且 `| 违规条目 | N 条` 的 N == `len(rep["violations"])`（不是常量）；
   - 陈旧字符串 `本次做了什么` / `交付 3 件新增物` / `未修改任何` 一个都不许出现；
   - §5 明细行数 == 违规条数（规范 §7「逐条不折叠」）；
   - 复现命令块回显传入的 `cmdline`，且不再出现 `temp/code_map_selfcheck.md`；
   - 零违规对照组（`dict(rep)` + `violations=[]`）渲染 `（无）` 且明细行为 0。

   ⚠️ 明细计数必须**只在 §5 区段内**匹配：§2 的规则命中表首列同样是规则 ID（`| \`line-too-long\` | error | 0 |`），用全文正则会把 11 条规则行算成违规行（首版实测 rows=94 vs violations=83）。最终实现 `detail_rows()` 先切 `## 5.`–`## 6.` 区段再匹配。

## 验证

| 项 | 结果 |
|---|---|
| 自测 | **63 passed, 0 failed, 0 inconclusive**（改前 61/2 failed —— 首版断言确实取到了红） |
| 变异 A：删掉 §5 明细列举（`by_file[path][:0]`） | exit 1，`1 failed`：`every violation is listed individually -- rows=0 violations=83` |
| 变异 B：重新塞回 `未修改任何 …` | exit 1，`1 failed`：`no stale hand-written narrative -- found=['未修改任何']` |
| 复原 | `code_map_check.py` sha256 逐位相同（`bd06254d…420d16d`），`RESTORE identical: True` |
| 门禁 | error 0 / warn 82 / gate PASS / 指纹 148-148 / stale 0 |
| 指纹 | `Tools/**` 因本轮改动重算：`c6a01c841046` → `f7e7ed812d04`（warn 一度 83，重填后回到 82 基线） |

## 教训

1. **报告生成器里的每一句自然语言都要有归属**：要么由本次数据算出来，要么显式标注「固定说明」。写死的叙述会让读者把历史当成现状，而这恰好违背本工具存在的意义（用机器取证替代自述）。
2. **对「同一份文件里两种真源混排」保持敏感**：§1–§6 是数据，§0 曾是记忆。发现混排时优先把记忆源删掉，而不是给它加免责声明；只有确实是「工具恒定性质」的内容才值得保留为固定说明。
3. **断言要先跑一遍再信**：首版明细计数断言（全文正则）本身写错了，用 61 passed / 2 failed 取到红才发现 §2 表格长得像明细行。断言的价值不只在「能抓到产品的红」，也在「能抓到自己写错」。
4. **改 `Tools/**` 必然使根指纹陈旧** —— 门禁脚本落在自己的指纹覆盖范围内，本轮再次复现（warn 82→83），提交流程里应把「重填指纹」当作 fix 的一部分而不是后续零活。
