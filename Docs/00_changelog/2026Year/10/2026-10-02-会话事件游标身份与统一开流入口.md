# 2026-10-02 会话事件游标身份与统一开流入口

## 改动

**新增 `src/pages/chat/hooks/sessionEventCursor.ts`（纯逻辑，唯一真源）**：游标带会话身份与阶段
（`unknown` / `hydrating` / `ready`），并提供唯一的开流起点决策 `decideSessionEventStreamStart`：
显式游标（含 0）＝调用方声明权威位置；否则必须该会话 `ready`；未就绪且正在同步 ⇒ 需先准备；
其余 ⇒ **拒绝**，不再以 0 兜底。`sequence = 0` 只有在服务端快照已应用、该会话确实 ready 时才是合法游标。

**`useSessionEventConnection.ts`（统一入口）**：

- `startSessionEventStream` 先做上述决策；被拒时只记录诊断（`chat.sse.startRefused` /
  `sse.start.deferredWithoutAuthoritativeCursor`）并返回 `false`，不再改动任何连接状态。
- 新增 `ensureSessionEventStream(sessionId)`：投影自有的会话不开第二条原始 SSE（`ok=true, opened=false`）；
  已有健康连接直接复用；游标未就绪则通过 `syncCompletedHistoryEventCursor` 准备（**同会话请求合并**，
  generation + 会话身份 + AbortSignal 三项复检，使 A 的迟到 bootstrap 既不能开 A 的流、也不能改写 B 的游标）；
  准备失败返回 `ok=false`，调用方不得退回 0。
- 通知等待者的替换与重连兜底：重连时旧连接可能仍在（只是收到 503），因此重连走 `forceReconnect` 强制重建，
  而不是被「健康检查」当成已完成。
- 410 `snapshot_required` 仍按原语义重取快照并强制重置游标。

**`useSessionEventReplay.ts`**：`syncCompletedHistoryEventCursor` 改为返回**判别联合**
（`{ok:true, cursor, turns}` / `{ok:false, reason: 'aborted'|'failed'|'stale-session'|'invalid-cursor'}`），
只有成功应用快照后才把该会话标 ready；失败/取消/过期一律不 ready。调用方（会话切换、历史投影）改为显式区分
「准备失败」与「成功但没有 turns」。

**`useMessageSend.ts`**：提交前先 `await ensureSessionEventStream`；准备失败则抛错进入既有失败路径
（保留失败轮、`restoreDraft` 交还原文、不提交 POST、不用 0 兜底）；被别的会话顶掉（`stale-request`）不算失败，
消息照常提交但不为旧会话开流。服务端刚创建的新会话（`createSession`）与压缩后继/分支会话在服务端确认后
显式声明权威游标 0，不再有绕过游标准备的 `cursor: 0` 调用。乐观 Turn 仍在任何 await 之前同步挂到时间线
（不改变「发送即出现」的手感）。

**会话身份贯穿清理**：`useChatState.ts`、`useSessionEventProjection.ts`、`useSessionSelection.ts`、
`sessionRuntimeCleanup.ts`、`runtime/types.ts` 在会话切换/消失/整体重置时一并清空游标状态；
实时事件推进游标只对当前流的会话生效（`advanceSessionEventCursor` 拒绝别的会话）。

**前端版本**：`package.json` 6.1.6 → 6.1.7（修订号，按 `Agents.md` 规则）。

## 验证

- `pnpm exec jest src/pages/chat/hooks --silent` → 35 个 suite / **259 用例全部通过**，其中新增与改写的
  B1 用例直接断言**实际订阅用的 `afterSequence`**，而不是只断言 ref 被赋值：
  - 未就绪会话调用 `startSessionEventStream` **不开流**（订阅 0 次，`sseSessionIdRef` 保持 null）——修复前的
    「旧会话从 0 全量回放」回归锁；
  - A 的游标 ready 但要开 B 时拒绝把 A 的序号带给 B；
  - `ensure` 先用 bootstrap 快照把游标记为 ready，再以**快照游标**（如 1,644,341）订阅，而不是 0；
  - 准备失败时**不订阅、不兜底**；同会话并发 ensure 只发一次 bootstrap、只订阅一次；
  - 投影自有会话 `ok=true, opened=false` 且不发 bootstrap、不订阅；
  - A/B 交错：A 的迟到 bootstrap 被丢弃（不写游标、不开流），B 以 222 订阅；
  - 发送路径：`ensure` 在 `submitConversationTurn` 之前被调用；准备失败时不提交 POST、草稿回填、
    失败轮终态为 error。
  - 纯逻辑用例覆盖状态机与决策（空/未初始化/同步中/ready 的真实 0/跨会话/失败/前进与清空）。
- `pnpm exec tsc --noEmit`：本次改动文件**无新增类型错误**。仓库在 `src/pages/chat/index.tsx`（`ContextMenuProps`
  `onEditAndRerun`）与 `src/pages/chat/projections/executionFlowProjector.ts`（`turn.accepted` / `turn.started`
  不可比较）上存在 **6 个既有错误**，这两个文件本次未改动、错误与 B1 无关；`pnpm run lint` 因此在本任务前
  也不是全绿，本次未顺手修（不扩大范围）。
