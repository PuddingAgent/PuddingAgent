# 2026-10-18 前端D3a主会话SSE事件接入唯一合并入口

## 改动

- `ChatClientStore` 新增 `applyLiveEvent(workspaceId, agentId, event)`：
  - 只接受当前身份的 conversation；`eventId` 重复直接丢弃，`sequence <= conversation.eventCursor` 的快照已覆盖事件不重复投影（`turn.started` 例外）；
  - `turn.started` 建立/复用活动 Turn；`message.content.appended` 追加**有界**正文（512 KiB 上限，最终正文仍由快照/终态合并）；
  - `message.thinking_summary.appended` 与 `tool.call.requested/completed/failed` 追加有界过程项（最多保留 64 项，结构化字段含 toolCallId/name/arguments/output/exitCode/error）；
  - `turn.completed/failed/cancelled` 只更新活动 Run 终态与计数，不伪造消息行；终态消息仍由快照合并器提供，避免 SSE 与轮询正文重复叠加。
- `useSessionEventProjection`：projection-owned 主会话的 canonical 非 subagent 事件在原有“本 hook 不投影正文”分支中，通过新增可选端口 `onProjectionOwnedMainEvent` 上报；子代理事实路径不变。
- `useChatState` 增加同名 option 并转发；`chat/index.tsx` 将上报接到 `agentClient.applyLiveEvent(当前 workspace/agent)`（agent client 初始化顺序前移）。
- `useAgentChatClient` 暴露 `applyLiveEvent`。
- 测试：
  - store 新增 live 缝合用例：turn.started + 正文/思考/工具 + 终态 → markdown `你好`、2 个过程项、状态 succeeded、eventCursor 推进；重复 eventId 不叠加；错误身份不污染；
  - hook 新增用例：projection-owned 主事件只回调唯一合并入口，且本 hook 不投影正文。
- 前端版本 `6.6.0 → 6.7.0`；frontend code_map 更新 ChatClientStore 与 SSE 投影语义。

## 验证

- `pnpm exec jest chatClientStore.test.ts useSessionEventProjection.test.ts`：**26/26 通过**（store 15 + hook 11）。
- `pnpm run build`：成功，`[chat-bundle-budget] ok sync=1383742 chat=361573 common=432307`。
- `pnpm run tsc`：仅基线既有错误（`onEditAndRerun`、`executionFlowProjector`），本次文件无新增类型错误。
- 未部署静态产物、未重启 Core、未改 `D:\data`。
- **轮询仍在**：投影-owned 主会话仍按状态轮询旧 `/conversation` 做终态/正文合并；本提交只让 SSE 活动 Turn 先进入统一 Store。

## 未完成与影响

- 尚未满足 D 门禁「live、终态、重连测试通过后移除健康状态下的整页轮询」：需在真实 SSE 连接上验证：
  1) live 增量与快照终态合并无丢字/重复；
  2) 断线重连 replay 与 eventId/sequence 去重一致；
  3) 终态后活动 Run 清理与消息行物化一致；
  4) 生成期间轮询间隔可安全降级/关闭，异常时保留有界校正。
- D3b 计划：健康连接下关闭 1.2s 正文轮询（保留状态/异常校正），SSE 覆盖 Turn/压缩事件；随后 D2c 把打开输入切到统一快照并退役旧 `/conversation`。
- 未在真实 WebView2 验证流式观感（阶段 F）。
