# 2026-10-12 R5：外部部署身份预检强化（artifact / live 分离）

> 依据：[复核与验收判定](../14_reports/上下文治理实施复核与验收判定-2026-10-12.md) §6（R5，P2，F6 仍阻塞）。

## 1. 缺陷

- 脚本从仓库下所有 `wwwroot/admin` 目录按 `LastWriteTime` **取最新**，不读取运行实例的实际 content root
  或 HTTP 资源 ⇒ **最新磁盘目录不能命名为「运行中 Core 正在提供服务的目录」**。
- 只比较版本与 dist/served 间短哈希：**没有强制同 pinned commit**，served 的 dirty 也未单独拒绝，
  也没有「HTTP 提供的字节 == 构件清单字节」这一层。
- 复核实测（当时）：源码 6.4.4、dist 与所选 release 目录皆 6.4.4/`7545ea1`/dirty=true、exit 1；
  这不同于 10 月 7 日记录的静态 6.4.1，但**不证明运行实例已更新**。

## 2. 修复（`TestScripts/verify-external-deploy-identity.ps1` 重写）

**参数**（破坏性变更，旧用法不再接受）：`-ArtifactRoot`（**必填**，不再猜目录）、
`-ExpectedCommit`（**必填**，pin 提交）、`-BaseUri`（做 live 阶段必需）、`-CoreProcessName`、
`-ArtifactOnly`（显式声明只验 artifact，结论标 ARTIFACT-ONLY）。

**ARTIFACT 阶段**：

1. 工作树脏 ⇒ 拒；`HEAD` 与 `-ExpectedCommit` 不一致 ⇒ 拒（同版本不同 commit 必拒）。
2. `dist` 注入身份必须存在、版本 == `package.json`、`commitShort` == pin 的短哈希、**独立拒 dirty**。
3. 构件根下必须**恰好一个** `wwwroot/admin`；出现多个（相邻 Debug/Release 等）一律判**歧义**，
   不再取最新。
4. `dist` 与构件根 `wwwroot/admin` 做**逐文件 SHA256 清单**比对（相对路径 + 文件哈希 → 总摘要）：
   文件数或摘要不同即拒（只比版本号不够）。
5. pin 构件根 `PuddingAgent.dll` 的 SHA256 作为「本次构建的 Core 身份」。

**LIVE 阶段**（缺 `-BaseUri` ⇒ unknown + 非零）：

1. 运行进程（默认 `PuddingAgent`）路径目录下 `PuddingAgent.dll` 的 SHA256 必须等于构件根 pin 值
   （旧进程仍在跑 ⇒ 磁盘已构建 ≠ 已部署）；进程不存在/路径不可读 ⇒ unknown。
2. HTTP `GET {BaseUri}/admin/index.html`：字节 SHA256 必须等于构件根清单里的 `index.html`；
   再拉取页面引用的脚本核对**运行中前端注入身份**（版本/短哈希/dirty）与 dist 一致；
   **live 环独立拒 dirty**；HTTP 失败或读不到注入身份 ⇒ unknown。

**退出码**：0 = 全部要求阶段通过；1 = artifact 失败；2 = live 失败/unknown；3 = 两者都失败/unknown。
输出分列 `ARTIFACT 阶段：PASSED/FAILED` 与 `LIVE 阶段：PASSED/FAILED/UNKNOWN/SKIPPED`，
**unknown 绝不显示为通过**。

## 3. 验证（本机真实执行，脚本只读）

| 场景 | 构造 | 结果 |
|---|---|---|
| 缺 `-ArtifactRoot` / 缺 `-ExpectedCommit` | 直接调用 | exit **1** + 明确提示（不再回退到猜目录） |
| 各环独立 dirty + 无 `-BaseUri` | 构件根复制 dirty dist | exit **3**；分别列出「工作树脏 / dist 带 +dirty / artifact 带 +dirty」**三条独立问题** + live UNKNOWN(未提供 -BaseUri) |
| 同版本不同 commit | pin 到 HEAD 短哈希，而 dist 身份是 `7545ea1` | 列出 dist/artifact 两条 commitShort 不一致 |
| 相邻 Debug/Release 目录 | 构件根下放两个 `wwwroot/admin` | 判**歧义**并列出命中路径（不再取最新） |
| HTTP 资源与清单不匹配 | 构件根=干净副本，用 python http.server 提供**被篡改**的 `index.html` | `HTTP /admin/index.html 与构件清单不一致：运行实例提供的不是本次构件根的内容`，exit **3** |
| 有运行端 HTTP、无运行进程 | 同上但服务内容与构件一致 | 成功读取 `HTTP /admin/index.html` 字节哈希与 **live 前端身份**（`6.4.4/7545ea1/dirty=true`），进程不存在 ⇒ live unknown + live 环 dirty 独立拒绝，exit **3** |
| 编码/语法门禁 | `TestScripts/check-script-encodings.ps1 -Root TestScripts` | 本脚本 `OK bom=True nonascii=True errors=0`；`Parser::ParseFile` errors=0（该门禁总体 FAIL 来自他方既有的 MOJIBAKE/UNRUNNABLE 脚本，与本批无关） |

**未在本机触发的分支（如实登记）**：live 阶段「运行进程 DLL 哈希 ≠ 构件根 pin 值」这一条需要
一个**运行中的 Core 实例**，本机当前没有 ⇒ 该分支只做了代码审查，未取得运行证据；
其余 unknown 分支（进程不存在、未给 `-BaseUri`）已实际触发。
也**未能**在本机取得一次完整 `PREFLIGHT OK`：工作区长期混有他方 WIP ⇒ 工作树脏 + dist 带 dirty
属当前事实，脚本按要求如实拒绝（这正是门禁应有的行为）。

## 追加（2026-10-12，实际跑通后）

**① 取得 artifact 阶段 PASS 的真实证据**（在本机 `temp/test-out/r5-clean` 的
`git worktree add --detach` 干净检出上完成，未触碰运行中的任何进程）：

| 步骤 | 结果 |
|---|---|
| `git worktree add --detach temp/test-out/r5-clean 934e604` + `git submodule update --init --recursive` | 干净检出（子模块必需，见 ③） |
| `pnpm install --frozen-lockfile` + `pnpm run build`（在 `Source/PuddingPlatformAdmin`） | exit 0 |
| `dotnet build <wt>/Source/PuddingAgent/PuddingAgent.csproj --artifacts-path <wt>/temp/build/deploy` | exit 0 |
| 预检 `-RepoRoot <wt> -ArtifactRoot <wt>/temp/build/deploy -ExpectedCommit 934e604 -ArtifactOnly` | **exit 0 / ARTIFACT 阶段 PASSED**：工作树不脏、dist 与构件身份皆为 `6.4.4/934e604/dirty=false`、dist 159 个文件逐字节一致（构件另有 149 个 `.gz` 派生）、Core DLL SHA256 `AD75544688952401269FFF3589D8CDF82D1D88E4660DCF1D984EA595F304C4CB`；LIVE 阶段显式 `SKIPPED`（**不声称运行实例已加载**）|

**② 真跑一遍才发现的两处脚本缺陷（已修，同一提交）**：

- **DLL 位置假设错误**：`--artifacts-path` 布局下 `PuddingAgent.dll` 在 `bin/<Project>/<config>/`，
  不在构件根；旧写法直接判「找不到 DLL」。现在改为**递归查找且强制唯一**（多命中 ⇒ 报歧义并要求更精确的
  `-ArtifactRoot`），排除 `obj/`、`ref/`。
- **清单比对过严**：Core 内容管线会为静态服务生成 `.gz` 派生，构件文件数因此多于 dist
  （实测 308 vs 159），旧写法把合法的 `.gz` 判成「复制不完整/陈旧」。现在改为：dist 的每个文件必须存在
  且逐字节一致；构件多出的文件只允许是 `<dist 文件>.gz`，其它多余文件才报「陈旧残留」。

**③ 干净检出构建的必要前置（新增记录）**：`external/github.hyfree.GM` 是 **git submodule**，
`PuddingHost.csproj` 直接引用其 csproj。未 `git submodule update --init --recursive` 时，
Core 构建在 `GatewayAuthService.cs` 报 `CS0246: github/GMService 找不到` —— 这不是产品缺陷，
是检出步骤缺失。外部控制器按 runbook 部署时须先初始化子模块。

**④ 仍属 F6（未做）**：把该构件部署到运行实例（外部重启）、核对页角徽标与 loaded identity、
新会话真实 smoke（分别记录受理→首推理、首正文、浏览器首绘）。本批**未重启进程、未部署、未做真实模型调用**。
因此本批交付状态是：**artifact 阶段已在 pinned 提交上取绿**，live 阶段与产品验收待外部控制器执行。
