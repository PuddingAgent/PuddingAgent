# Bridge 配套构建脚本与真机部署

新增 `TestScripts/build-browser-companion.ps1`：新输出目录、串行 Desktop + bundled Core、协议常量与进程构建身份、逐文件 SHA 清单及复制后核验；默认拒绝脏树，开发修复显式标注。更新 Desktop 索引、D9 运行手册和设计方案实施状态入口。

验证：完整包构建成功，1,624 文件校验成功；错误 Core Protocol DLL 能被拒绝，原字节恢复后通过；相对/绝对路径验证通过。隔离真机生命周期 14 个产品检查与 4 个外部检查通过；实际部署后 Desktop/Core 七个关键加载模块与清单一致，健康检查 ready、协议 v3 Hello 已记录。

实际配置将 `%LOCALAPPDATA%/Pudding/desktop.json` 的显式 Core 路径切至当前 Desktop 包内 Core，其余设置保留；原配置及完整旧 Desktop 包留作回退。构建源包含他方 WIP，清单如实为 `dirty=true/development-repair`。没有替他方提交代码，没有读取 LLM 密钥。详情、PID、备份和测试边界见[报告](../../../14_reports/浏览器Bridge握手修复与配套部署验证-2026-10-18.md)。

未完成：真实模型及京东业务测试待单独记录；CI 签名、运行时自动清单验证未实施。运行中的产品包及回退包保留，禁止用全量 temp 清理破坏部署。

文档 Front Matter 四份通过；全 Docs 链接检查仍为 24 个既有失效目标，本次文件无新增失效链接。脚本额外验证：拒绝覆盖已有输出、越出 temp/build 的目标和未显式 AllowDirty 的脏工作树，均通过。
