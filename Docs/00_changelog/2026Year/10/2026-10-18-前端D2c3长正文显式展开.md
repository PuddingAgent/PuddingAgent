# 2026-10-18 前端D2c3长正文显式展开

## 改动

- `conversationSnapshotAdapter`：长消息不再在打开时自动读取全文，正文 = 服务端预览 + `[展开全文](#pudding-expand-<messageId>)`；导出 `readFullMessageContent`（UTF-8 字节分段、512KiB 上限）。
- `ConversationMessageView` 增加 `hasMoreContent` / `contentLength`（仅快照路径）。
- `ChatClientStore.expandMessage(messageId)`：按需分段读取并只替换同 messageId 的 content；预算内完成后移除展开标记；跨身份/迟到响应丢弃。
- `chat/index.tsx`：文档级点击委托拦截 `a[href^="#pudding-expand-"]`，调用 Store 展开；不改变消息身份/顺序。
- 浏览器冒烟脚本增加“点击展开全文/请求数/剩余链接”采集；前端版本 `6.9.3 → 6.9.4`。

## 验证

- `conversationSnapshotAdapter.test.ts` + `chatClientStore.test.ts`：**23/23 通过**（长消息默认不请求、含展开链接；显式展开两段拼接、二次点击不再请求）。
- `pnpm run build`：成功，bundle budget ok；`pnpm run tsc` 仅基线既有错误。
- 浏览器冒烟（真实库，2 次）：
  - 首屏 `/content` 自动请求 **1 次**（此前 9–18 次）；
  - 点击展开：1 次 content 请求、预算内更新、剩余 6 个长消息为预览；
  - 首内容可读 875/982ms；旧 `/conversation` 0 次；bootstrap 仍 1 次。
- 未部署、未启动 Desktop/WebView2；验证后停止 Core。

## 未完成与影响

- 展开链接依赖 Markdown 渲染点击委托，真实 WebView2 触屏/键盘可访问性未验证。
- 首屏 bootstrap 仍需消除；`conversation-open` 顺序重复（StrictMode/双 store）未完全消除。
- 正式部署仍被共享脏工作树阻塞；F 门禁（首内容 p95 ≤800ms、badge/identity、外部重启）未通过。
