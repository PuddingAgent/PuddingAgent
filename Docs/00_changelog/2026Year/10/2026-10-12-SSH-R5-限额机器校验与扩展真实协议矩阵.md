# 2026-10-12 SSH R5：限额机器校验与扩展真实协议矩阵

## 目标 / 背景

审阅报告 **F5 / P2**（硬限额未落实）与 ADR-096 **D5**：限额必须由机器校验，非法配置**拒绝**而不是静默夹取；
协议证据必须覆盖「预先取消、迟到连接、不发 EOF、提交窗口断线、多轮资源、signal-only」这些反例形状。
本切片仍只动组件与其独立测试/探针，**不改宿主**。

## 改动

### 限额：合法或拒绝

- `Source/PuddingSsh/Contracts/SshLimits.cs`
  - 新增 `Validate()`：connect/默认/max 操作 ≤600 s、默认≤max、捕获 1..256 KiB、每主机并发 1..2；
    新增硬上限常量 `MaxOperationTimeoutSecondsHardLimit`、`MaxConcurrentOperationsHardLimit`（与既有
    `MaxOutputBytesHardLimit`/`CoreMaxConcurrentOperations`/`WaitQueueHardLimit`/`CleanupGrace` 一起构成**唯一真源**）。
  - `ResolveOperationTimeout`/`ResolveOutputBudget` 的注释明确：夹取只是纵深防御，0/负数请求由 validator 拒绝。
- `Source/PuddingSsh/Execution/SshCoordinatorOptions.cs` — 新增 `Validate()`：Core 1..8、队列 0..32、
  清理 >0 且 ≤2 s、隔离区 0..32、阶段 worker 1..32；越界抛 `ssh.config_invalid`。
- `Source/PuddingSsh/Execution/SshOperationCoordinator.cs` — 构造时 `_options.Validate()`；
  `ssh_test` 与 `ssh_execute` **共用** `SshRequestValidator.ValidateExecute`（此前 `ssh_execute` 绕过了它），
  并先校验主机限额：非法配置一律 `config_invalid` 且零身份/零连接/零提交。
- `Source/PuddingSsh/Validation/SshRequestValidator.cs` — 先 `limits.Validate()`；请求 `timeout_seconds`/`max_output_bytes`
  为 0/负数时返回 `ssh.request_invalid`；过期宿主 deadline（≤0 额度）返回 `ssh.timeout`，**绝不把零/负额度传给库**。
- `Source/PuddingSsh/Transport/SshNetTransportFactory.cs` — 公开建连入口的防御校验：目标合法性 + `connect_timeout > 0`。

### 扩展真实协议矩阵（17 → 23 场景）

- `Source/PuddingSsh.Probe/Program.LimitScenarios.cs` — 新增 6 个真实 OpenSSH 场景：
  - `precancel`：调用前取消与已过期 deadline ⇒ `cancelled`/`timeout`、`NotSubmitted`、服务端 marker `ABSENT`、
    只有场景自有的 2 次连接认证。
  - `lateconnect`：1 ms deadline 下真实建连迟到 ⇒ 3 ms 内返回 `ssh.timeout`、marker `ABSENT`、`ActiveLeases=0`。
  - `noeof`：命令后台子进程持有 stdout（服务端永不发 stdout EOF）⇒ `AbortRequested=true`、`Closed=true`、
    `PendingReaders=0`、清理 11 ms；运行器额外核对服务端 `ss` 上**没有残留 established socket**。
  - `submitfail`：远端杀掉自己的 sshd 会话进程 ⇒ `ssh.connection_lost`、`execution_state=unknown`、`retry_safe=false`、
    `cleanup_state=completed`。
  - `rounds`：3 成功 + 3 超时 + 2 取消 + 1 次 8 MiB 输出 ⇒ `ActiveLeases=0`、`ActiveStageWorkers=0`、
    `QuarantinedResources=0`，捕获仍恒为 64 KiB。
  - `signal`：signal-only ⇒ `ssh.remote_exit_signal`（`ExitSignal=KILL`、`ExitCode=null`）；`exit 7` ⇒
    `ssh.remote_exit_nonzero` 且**保留 exit_code=7**；`echo` ⇒ 唯一 `Completed`。
- `TestScripts/ssh-probe/run-ssh-probe.ps1` — 注册 6 个场景、逐场景断言认证增量（`precancel=2`、`noeof=1`、
  `submitfail=1`、`signal=3`，`lateconnect`/`rounds` 用探针自报的 `connections` 对齐）、新增 `Get-RemoteSocketCount`
  的服务端 socket 证据，并修正 `throughput` 的分配断言（改为「不随输出线性增长」的可辩护上界 + 记录实测比值）。
- `Source/PuddingSshTests/SshLimitsValidationTests.cs` — 新增 32 例：协调器与主机限额每条上限的
  下界/上界/上界+1/0/负数矩阵、非法配置两入口零副作用、构造拒绝、请求 `request_invalid`、
  超预算只收窄（实测 5000 s→600 s、4 MiB→64 KiB）、过期 deadline 不产生非正额度、底层 factory 防御校验。

## 验证

- `dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **208/208 通过**，0 警告 0 错误。
- 真实协议：`powershell -File TestScripts/ssh-probe/run-ssh-probe.ps1` → **23 场景 `failures = 0`**
  （OpenSSH_10.2p1 / Ubuntu 26.04.1 LTS）：固定服务端版本身份、逐场景客户端事实、服务端 `Accepted publickey`
  增量与 marker/socket 证据齐全。关键数字：`noeof` 关闭 11 ms 且服务端零残留 socket；`rounds` 九轮后
  三项计数全 0；`throughput` 240 MiB/1.2 s、捕获恒 65536 B、驻留 ±0.5 MiB。
