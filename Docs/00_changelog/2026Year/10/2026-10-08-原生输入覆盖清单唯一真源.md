# 2026-10-08 原生输入覆盖清单收敛为唯一真源

## 目标 / 背景

「哪些动作支持 `input_mode=native`」此前**有两份清单**：工具层 `SupportsNativeInput(string action)`（按线名）
与能力通道 `SupportsNativeInput(DesktopInteractionAction)`（按枚举）。我从 round 36 起在 changelog 里
**连续登记了五次**这条重复，每次加动作都要改两处（上一轮加 `drag` 时就必须同步两处，稍有遗漏就会出现
"工具放行、能力通道拒绝"或反之的静默不一致）。

## 改动

| 位置 | 改动 |
|---|---|
| 契约（唯一真源） | `DesktopInteractionActionWire.SupportsNativeInput(DesktopInteractionAction)`：判据是"键鼠能不能真实表达"——click/fill/type/press/hover/check/uncheck/scroll/drag 为真，select/focus 为假（原生路径下**明确不支持**，绝不静默回落成 DOM） |
| 工具层 | 删除本地 `SupportsNativeInput(string)`，改查契约（`MapAction(action, checked)` 之后再判定，保证与能力通道**同一个枚举**） |
| 能力通道 | 删除本地 `SupportsNativeInput(DesktopInteractionAction)`，改查契约 |
| 顺带 | 工具的原生失败提示文案补上 `drag`（此前漏了） |

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.ContractsTests` | **153 / 153**（＋1：唯一真源冻结用例） |
| `AgentTools` · `DesktopSurface.BrowserTests` · `Automation` · `DesktopService` · `PuddingDesktop` · `Host` | 64/64 · 66/66 · 272/272 · 231/231 · 320/320 · 258/258 |
| 构建 | `AgentTools` · `DesktopSurface.Browser` · `WinUI` 已成功生成 |

新增门禁：click/type/scroll/**drag** 为真；**select/focus 为假**（"不支持的动作必须明确为假"这条比"支持哪些"更重要，
它保证不会有人顺手把 select 也标成支持）。

**取红实测**：把 `drag` 从真源清单里去掉 ⇒ `NativeInputCoverage_IsOneFrozenTruth` **恰好变红**；复原后 153/153 复绿。

## 已知边界（诚实登记）

- **判定仍是"动作级"的**：它不区分"某个动作在某些页面上原生做不了"（例如自定义控件需要键盘交互）。
  这类失败仍由驱动在运行时明确报错（fail closed），清单只回答"这一类动作**能不能**走原生"。
- **`uncheck` 按枚举区分、工具层按 `checked` 推导**：工具在 `MapAction` 阶段把 `checked=false` 映射成
  `Uncheck` 再查真源，因此两者判定的是同一个枚举值 ✓（这点在改动里特意保证，否则又会出现"看着同一份清单、
  实际判的不是一个东西"）。
- 真机无关（契约与映射层）。

## 影响与回滚

- **无对外行为变化**：清单内容与之前一致（含 drag），只是从两份变成一份；工具提示文案补上 `drag`。
- 回滚：还原契约的静态方法、两处调用点与冻结用例。
