# 2026-10-08 更正：我在 changelog 里积累了 33 条失效链接

## 我错在哪

**更正（2026-10-08）**：本轮试图给"changelog 相对链接"加一条门禁时，门禁立刻变红并列出几十条 ——
那不是我写的新错，而是**我从 round 72 起一直在犯的旧错**：

- 正确层级：`Docs/00_changelog/2026Year/10/X.md` → 到 `Docs/…` 要 **3 级**（`../../../12_features/…`），
  到仓库根要 **4 级**；
- 我写成了 **2 级**（`../../12_features/…`）⇒ 解析到 `Docs/00_changelog/12_features/…`（不存在）。

**更严重的是我每轮的结论方式**：我运行 `check_md_links.py` 后，用**自己刚写的文件名**去 grep 输出，
看到"没有我的新文件"就写"**零失效目标**"。于是**连续十几轮的 changelog 都声称链接 OK，而实际上它们全是坏的**。
本轮看全量报告才发现：**66 条失效目标里，约 33 条是我的**（21 个文件）。

这是"用过滤器制造证据"的典型错误 —— 证据方法本身让我看不到真相。**记录在此，避免重演。**

## 处理

| 步骤 | 结果 |
|---|---|
| 批量层级修正（`Docs/00_changelog/2026Year/10/` 下 `](../../` → `](../../../`） | **21 个文件**被改写 |
| 自动修正其余（按唯一文件名解析、重算相对路径） | 再修 **12 条** |
| 门禁复测 | 失效目标 **66 → 24**，且**剩余 24 条全部不属于我的交付物**（07_architecture / 15_tasks / 16_qa 等他方文档） |
| 我这边 | `Docs/00_changelog/2026Year/10` + `Docs/12_features/浏览器*|B6-*` + `Docs/13_runbooks/浏览器*` + `Docs/14_reports/2026-10-0[89]-浏览器*` **零失效链接** |

## 新增门禁（防止再犯）

`DocsMarkdownEncodingTests` 增加 `TheBrowserAutomationDeliverablesHaveNoBrokenRelativeLinks`：

- 范围**刻意收窄到本会话交付物**（浏览器自动化相关文档），不替其它子系统背既有失效链接
  （仓库纪律要求不代改他方内容）；
- 解析 `](target)` 形式的相对链接，**先剔除围栏代码块与行内代码**（否则示例里的 `](src)` 会误报），
  再去掉锚点与 `file.cs:123` 行号后缀（与仓库检查脚本同规则）；
- 失败时逐条列出文件与目标，并写明正确层级。

**实现过程中被自己纠正两次**：`Path.GetRelativePath` 在 Windows PowerShell 5.1（.NET Framework）里**不存在**；
文件系统通配符不支持 `[89]` 字符类（必须 `*`/`?`）⇒ 改为"取全部 `*.md` + 正则过滤"。

## 边界失误（同一轮内发现并已回退）

我的批量层级修正脚本跑在 **整个目录** 上，于是它**顺带改了两个 `2026-10-08-T6-*` changelog**
（他方并行 WIP），而且我用目录级 `git add` 把它们**一起提交**了 —— 这违反仓库纪律
（"只推自己的 commit / 不代推他方改动"）。

**处理**：从 `0ad55be^` 取回这两个文件的原始内容并写回（**回退我对他方文件的改动**），
单独提交该回退，并把这条失误记在这里。
**教训**：批量改写必须**先按归属过滤文件**（本次应只处理我自己写入的 `2026-10-0[89]-B*` 等），
不要用目录级 `git add`。

## 已知边界（诚实登记）

- **我未修他方的 24 条失效链接**：它们不在本次改动范围（仓库纪律：不代改他方内容），
  但**已在本轮报告里可见**，建议相关 owner 处理。
- **门禁范围是"我的交付物"**：全仓库级别的链接健康仍由 `Tools/Docs/check_md_links.py` 负责（每轮应看**总数**，不是只看新文件）。
- **没有自动修好所有历史 changelog 的语义**：我只改链接路径，不改文字。
- **教训已写进门禁注释**：说明"为什么收窄范围"与"为什么必须剔除代码块"。
