# 2026-10-18 前端D2c2统一历史分页接入

## 改动

- `conversationSnapshotAdapter`：
  - 导出 `mapSnapshotHistoryItem` 供历史页复用（无 Turn 摘要时只保留基础消息字段）；
  - 打开结果携带 `hasMoreHistory` / `historyNextBeforeCreatedAt` / `historyNextBeforeMessageId`（前端视图可选字段，旧端点响应可省略）。
- `ChatClientStore`：
  - 快照新增 `hasMoreHistory`、`isLoadingOlder`；
  - 新增 `loadOlder()`：调用可选 `getHistoryPage` 端口（键集 createdAt+messageId、limit=20），只把**当前页** prepend 到现有消息，按 messageId 去重；加载中禁止重复请求；响应返回后复检选择版本/workspace/agent，迟到或跨身份结果丢弃；
  - 首次打开/后台同步把快照分页边界写入状态。
- `agentChatApi`/`chat/index`：绑定 `/api/conversations/{id}/history`；Chat 页 `loadingMore`/`hasMoreMessages`/`onLoadMore` 在 agent 架构下改用 Store 分页。
- 前端版本 `6.8.0 → 6.9.0`；frontend code_map 更新 Store 边界。

## 验证

- `pnpm exec jest conversationSnapshotAdapter.test.ts chatClientStore.test.ts`：**21/21 通过**（含新增 loadOlder：游标断言、去重、hasMore 更新、二次调用不再请求）。
- `pnpm run build`：成功，`[chat-bundle-budget] ok sync=1383742 chat=363385 common=436997`。
- `pnpm run tsc`：仅基线既有错误，本次文件无新增类型错误。
- 未部署、未重启 Core、未改 `D:\data`。

## 未完成与影响

- 历史页中更早的长消息只用快照 8 KiB 预览（未做分段自动读取/显式展开）；过程摘要对更早 Turn 为空（无读模型摘要），需 D2c3 处理。
- 旧 `/conversation` 仍用于活动 Turn 回退与后台校正（D3c 退役）；首屏仍会先尝试新快照，失败时回退旧端点。
- 真实 WebView2 的滚动锚点/加载旧页观感未验证（阶段 F）；当前运行中的旧 Core 无新端点，实际仍回退旧路径，线上行为不变。
