# 2026-10-18 SSH F1/F2 修补：上传所有权事实与下载运行时字节上限

## 目标 / 背景

独立审阅（2026-10-18）的 **F1（P1）**：排他创建失败后仍回滚删除目标，会删掉其他客户端刚创建的数据；
**F2（P1）**：下载只做 STAT 前检查，复制循环没有上限，远端在 STAT 后增长会越过请求/主机/硬上限并发布。

## 改动

- `Source/PuddingSsh/Contracts/SshTransferPorts.cs`
  - 通道端口**去掉** `UploadAsync`/`DownloadAsync`（复制循环归会话，避免两套实现各自漏检查）；
  - `OpenWriteNew` 排他创建失败时抛新增的 `SshSftpTargetExistsException`（创建层**没有**创建任何东西）。
- `Source/PuddingSsh/Transport/SshSftpChannel.cs` — `OpenWriteNew` 把 `SftpPathNotFoundException`/`SshException`
  统一映射为 `SshSftpTargetExistsException`；删除通道级复制循环。
- `Source/PuddingSsh/Transport/SshSftpTransferSession.cs`
  - 新增 `CopyAsync(source, destination, maxBytes, token)`：**逐次累计字节**，超过上限立即抛
    `SshTransferLimitExceededException`（上传/下载共用）；下载失败映射补 `ssh.transfer_too_large`；
  - 上传**先打开本地源**（打不开就不创建任何远端文件），随后 `OpenWriteNew`；
    `createdByUs` 只有在排他创建返回后才为 true；
  - `AbandonUpload(..., createdByUs, ...)`：**只有本次成功创建的文件才回滚删除**；
    创建结果未知（调用失败但文件可能已落地）或竞争失败一律不删，并在诊断里说明。
- 测试：`SshFakes.Transfer.cs` 重构为"写入即落地"的假通道（模拟真实部分写入），新增
  `OnBeforeCreateNew`（竞争窗口）、`OnOpenRead`（STAT 后增长）、`OnWrite`（写入中途取消）、
  `FailAfterCreatePath`（创建结果未知）；新增 `SshTransferOwnershipAndLimitTests`：
  竞争失败不删他人数据、创建结果未知不删、本地源失败零远端副作用、下载运行时超限中止且零发布、
  限额内往返一致。

## 验证

- **取红**：新增门禁在旧实现下红（F1 竞争用例删掉他人数据、F2 超限用例发布 4096 字节）。
- **复绿**：`dotnet test Source/PuddingSshTests/PuddingSshTests.csproj` → **294/294 通过**，0 警告。
- **变异取红**：①回滚忽略 `createdByUs` ⇒ `Upload_CreateOutcomeUnknown_DoesNotDeleteTheFile` **红**；
  ②去掉 `CopyAsync` 的运行时上限 ⇒ `Download_RemoteGrowsAfterStat_AbortsAtRuntimeLimit` **红**；恢复后全绿。
  （第一版所有权变异最初是绿的：新结构下竞争失败在创建层就返回、**走不到清理**；
  因此补了"创建结果未知"门禁，让所有权事实可被真正检出。）
