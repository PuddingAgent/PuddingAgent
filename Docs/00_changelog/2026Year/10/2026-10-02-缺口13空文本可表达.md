# 缺口 #13 完成：空文本可表达（`fill`/`type` 用空文本清空输入框）

## 背景

迁移 `browser_interact` 时发现并不情愿地接受的一个收窄：契约要求 `text` 非空，而 proto3 的
`string text` **无法区分空串与未设** ⇒ 「用空文本清空输入框」在能力通道上表达不了。
当时选择明确拒绝（而不是静默当成清空），并登记为缺口 #13。本轮按登记的方案修掉它。

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| 线缆 | `desktop_capability.proto` | `InteractCommand.text` 改为 **`optional string`**（获得 presence ⇒ 区分"没给"与"给了空串"）；与既有 `optional bool checked` 同一手法 |
| Core→proto | `CapabilityBroker/WireMapping.cs` | 仅在调用方**确实给了** text 时写 presence（不再用 `?? string.Empty` 伪造） |
| proto→DTO | `DesktopConnection/Mapping.cs` | `HasText ? Text : null`（空串保持空串，不再归一化成 null） |
| 契约 | `Contracts/Desktop/InteractionContracts.cs` | 构造不再把 `""` 折叠为 `null`；`fill`/`type` 允许**空文本**，`press` 仍要求非空键 |
| 工具 | `BrowserProwser.AgentTools/BrowserInteractTool.cs` | 删除"空文本即拒绝"的分支；`fill`/`type` 省略 text 时按空文本处理（= 清空），与迁移前行为一致 |
| 测试 | `ContractsTests/InteractContractTests.cs` | 新增：空文本 `fill` 允许、空文本 `press` 拒绝 |

## 过程教训（脚本层，三次都被 all-or-nothing 兜住）

1. Python **原始字符串**里的 `\n` 是字面反斜杠+n（不是换行）、`\"` 会原样进入 C# 源码 ⇒
   在代码里留下 `\n` 与 `\"` 两个工件（本轮编译期报出 10 个错）。
   ⇒ 规则：替换文本要用**非原始字符串**（真换行）且分组用 `\g<1>`；对 C# 代码优先**字面锚点**而不是正则。
2. 目标文件里语句间有空行（我早先写入时留下的），正则必须容忍 ⇒ 优先按"起止行"而不是按相邻行匹配。
3. `all-or-nothing` + 逐阶段编译再次避免了三处半成品落盘。
