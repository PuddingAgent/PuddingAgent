# R5 审计：落盘链路五方面成立

| 方面 | 证据 |
|---|---|
| **内容寻址** | `artifactId = "vision-" + SHA256(字节)`（发布端 L38） |
| **每工作区串行** | `SemaphoreSlim(1,1)` 按 workspaceKey（L93–96） |
| **幂等** | `ResolveLocalFileAsync` 命中既有 ⇒ **直接返回、不重写**（L99–108） |
| **原子发布** | 临时文件（`CreateNew` + `WriteThrough`）⇒ **magic bytes 判定真实类型**（L177–178，"不信任声明 MIME/尺寸"）⇒ `File.Move(..., overwrite: true)`（L202–203）⇒ 元数据同法；`tempMetadataPath = null` 作清理哨兵（L204）+ `finally`（L222） |
| **体量上限** | 超 `MaxCanonicalImageBytes` 即拒（L164–167） |

**两侧证据**：`AgentTools.Tests` 断言**恰一个 `LlmImagePart`**（正向）+ `visionUnavailable` 回退 ✓

## 残余窗口（**仅观察，非缺陷断言**）

发布是**两步改名**（字节 → 元数据）⇒ 若进程在两次 `File.Move` 之间终止，会出现"**字节已就位、元数据未更新**"的短暂状态；幂等路径 `ResolveLocalFileAsync` 的判定依据（是否要求元数据存在）决定"**自愈重落盘**"还是"**返回旧元数据结果**" —— **本轮未追踪该细节，故只记为待观察窗口**；真机阶段若见"工件与元数据不一致"，优先查此处。
