# 权限证据链 第一阶段（地基）：证据类型 + 可选携带位（纯增量，零行为变化）

## 背景

`bcaae6c` 的设计判定：能力接缝只认 `DesktopCallContext`，**审批结论不在其中**，
因此任何能拿到 DI 接缝的进程内代码都能发起副作用能力调用。方案取「Core 侧接缝校验」，
并分三阶段落地（观察期 → 对副作用类强制 → 全量）。本轮是**第一阶段的地基**。

## 改动（纯增量，无行为变化）

| 文件 | 改动 |
|---|---|
| `Source/PuddingCore/Tools/PuddingToolContracts.cs` | 新增 `ToolPermissionEvidence(ToolCallId, Decision, ApprovalId?, Source?)`：`Decision` 取 `allowed` / `denied` / `not-required`；`IsAbsent` 是"缺失"的**唯一**真源（明确禁止用 `denied` 冒充缺失）；`IsAllowed` 覆盖"无需审批"。**同时**给 `ToolExecutionContext` 增加**可选**属性 `PermissionEvidence`（默认 `null` = 未评估） |
| `Source/Pudding.Contracts/Desktop/DesktopCallContext.cs` | 增加进程内字段 `PermissionEvidenceSummary`（字符串摘要），并在文档注释里写明**不上线缆**：能力通道 wire 只带 `operation_id`/`generation`/`capability`/`deadline`，Desktop 侧由这些字段重建上下文 ⇒ 该字段在 Desktop 侧**恒为 null**，这正是设计意图（证据留在 Core 进程内、由接缝自行校验） |

## 两个有意的取舍

1. **证据类型放 `PuddingCore`，契约侧只放字符串摘要**：`Pudding.Contracts` 不能引用 `PuddingCore`
   （边界由编译期强制），因此跨这层时用摘要字符串。结构化真源仍在 Core 侧；
   若将来要在契约侧表达结构，应把证据类型**上移**到 `Pudding.Contracts` 并让 Core 引用它。
2. **可选属性而非必填**：`ToolExecutionContext` 有 10+ 处构造点（多在测试）⇒ 用 `init` + 默认 `null`
   避免无意义的大范围改动；"没证据"因此是**合法且可表达**的状态。

## 验证

- `Pudding.Contracts` 与 `PuddingCore` 构建 **0 错误**；
- 依赖本次改动的五个套件全绿：`ContractsTests` **97/97**、`CapabilityBrokerTests` **90/90**、
  `DesktopServiceTests` **170/170**、`PuddingHost.Tests` **234/234**、`AgentTools.Tests` **15/15**
  （合计 **606**）；
- 本轮未重跑另外四个套件（`Rpc.Protocol` / `DesktopConnection` / `DesktopSurface.Browser` /
  `CapabilityBroker.AspNetCore`）：改动是**纯增量可选属性**、无行为变化，但**未验证这一点**是如实说明；
- **未验证**：没有任何调用方**写入**证据（生产者为下一轮），也没有任何地方**校验**它（第三阶段）。

## 下一步（落点已定位，可直接施工）

1. **生产者**：`Source/PuddingRuntime/Tools/Platform/ToolInvocationService.cs` ——
   该文件里已有权限判定（`CheckGuardDenied(request)` 与"Permission denied …
   Call request_tool_approval"的 `decision.Reason`），把结论写进 `ToolExecutionContext.PermissionEvidence`；
2. **携带者**：`IDesktopCapabilityCallContextFactory` 用**默认接口方法**加一个带证据的重载
   （不破坏既有实现），把摘要写进 `DesktopCallContext.PermissionEvidenceSummary`；
3. **观察者**：组合根路由端口在派发前记录"缺证据"计数（可参照 `TransportStatusController` 的只读出口形态），
   **只记录不拒绝**；
4. 然后才是第二/三阶段的强制与全量。

## 未决问题（不变）

「某次工具调用是否已获批」的查询面、`Low` 权限是否本就免审批、委派调用时证据绑定哪个身份。
