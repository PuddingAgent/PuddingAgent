# 2026-10-08 B2 正文 markdown 组装与提取脚本（mode=text 第一步）

## 目标 / 背景

设计 §6.1：「`text`｜正文 markdown；标题/列表/链接/表格/代码块结构｜每页 4,096 字节，游标续读」；
§165：「正文提取先用 `article`/`main`/语义地标，再进行普通块结构回退，**不写站点专用选择器**到驱动；
去导航/页脚噪声……表格、代码空白与链接目的地址保持结构，**禁止从 html/body 祖先 innerText 制造整页**」；
G6：「标题/列表/表格/代码/链接结构 fixture 聚合后内容覆盖 100%，**无重复或丢段**；超预算保持合法输出」。

`mode=text` 是目前**唯一仍以 `browser_operation_not_supported` 拒绝**的读取模式。本轮按仓库的
组件交付顺序先做两块基础件（**能在进程内验证的部分必须真的被验证**）：

## 改动

| 层 | 文件 | 改动 |
|---|---|---|
| Automation | `ArticleMarkdown.cs`（新增） | 语义块 → markdown 组装器：标题层级、列表缩进（`d`）、表格（GFM + 单元格转义）、代码块（**保留空白**、内容含围栏时用更长围栏）、引用、链接（**保留目的地址**）；**块边界分页**（`cursor` = 块索引，续读不重复不跳段）；非法/未知输入**不抛异常**、未知块只要有文本就降级成段落，被丢弃的如实计入 `SkippedBlocks` |
| Automation | `BrowserReadingFormat.cs` | `BrowserReadingResult` 增加 `SkippedBlocks`（"无丢段"因此可审计） |
| 驱动 | `WebView2DomClient.cs` | 快照脚本新增 `extractBlocks`：语义地标优先（`article` → `main` → `[role=main]` → 普通块回退）、去 `nav/footer/aside/[role=navigation|banner|contentinfo]/hidden/aria-hidden`、行内链接写成 `[text](href)`、行内代码加反引号、`pre` 原样保留、表格按行取；输出**一行一个 `JSON.stringify` 对象**（转义天然正确）。**没有任何站点专用选择器，也不把 body/documentElement 的 innerText 当正文** |
| 运行时契约 | `SnapshotOptions.IncludeContentBlocks` · `PageSnapshot.ContentBlocks` | 驱动侧契约（Abstractions 保持不引用 Contracts） |

## 验证

| 套件 | 结果 |
|---|---|
| `PuddingBrowser.AutomationTests` | **207 / 207**（原 194 ＋ 13） |
| `PuddingDesktop.Tests` | **318 / 318**（原 317 ＋ 1） |
| `Host` · `AgentTools` · `ContractsTests` · `DesktopSurface.BrowserTests` · `DesktopServiceTests` | 258/258 · 54/54 · 152/152 · 63/63 · 229/229 |

新增门禁：

- **结构保真**：标题层级、列表缩进、表格（含 `|` 转义）、代码块（空白保留 + 围栏升级）、独立链接与
  无文本链接、引用与分隔线；
- **不丢段不重复**：8 段分两页取完，每段在拼接结果里**恰好出现一次**（G6 的覆盖 100% 直接断言）；
- **块边界分页**：第一页必须**真的提前停**（`ReturnedLines < 8`）、第二页必须还有内容
  —— 这条是"取红实测"逼出来的强化（见下）；
- **预算口径**：`Bytes` 等于 UTF-8 字节数（中文 3 字节，防止"字符数冒充字节数"）；
- **不静默丢内容**：非法行/空段/无 kind ⇒ 计入 `SkippedBlocks` 且 `Truncated` 如实置真；
  未知块只要有文本 ⇒ 降级成段落而不是丢掉；
- **驱动脚本**：`extractBlocks` 存在、语义地标顺序正确、无站点专用选择器、
  **不出现 `body.innerText`/`documentElement.innerText`**。

**取红实测（含一次有价值的失败）**：把"块边界分页"的条件短路（忽略预算）⇒
第一版测试**没有变红**——因为`output_budget` 兜底让 `Truncated` 仍为真、覆盖断言也照样成立。
把断言强化成「第一页必须真的提前停 + 第二页必须非空」后再做同样变异 ⇒ **恰好变红**；复原后 207/207 复绿。

## 已知边界（诚实登记）

- **还没接线**：`mode=text` 仍然返回 unsupported。本轮按 S1 的组件交付顺序先在边界内完成并测透
  （驱动契约字段已就位、脚本已能产出 blocks），**能力通道/桥接/工具**的接线是下一步；
  因此现在这两个字段在能力层还没有消费方。
- **不做块内切分**：单块超预算时整块给出并标注 `output_budget`。设计"允许标记分片并续读"需要
  游标表达块内偏移，本轮没有引入（引入它会带来续读重复的风险，宁可少说）。
- **正文选择仍是启发式**：`article`/`main`/`[role=main]`/回退；没有可读性评分（不做站点专用规则，
  也**不做正文长度打分**），因此"正文里混入少量非正文"是可能的——但它不会**丢掉**正文。
- **真机提取效果未验证**：本环境跑不了真实 WebView2；脚本只有结构断言，真实站点效果需外部 smoke。
- 图片（`img`）暂不产出 `![alt](src)` 块。

## 影响与回滚

- **无对外行为变化**：`mode=text` 仍明确 unsupported；新增的是组件与驱动契约（尚无消费方）。
