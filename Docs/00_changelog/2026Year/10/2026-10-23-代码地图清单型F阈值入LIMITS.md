# 代码地图「清单型 F」阈值收进 LIMITS（语义零变化）

**日期**：2026-10-23 · **范围**：`Tools/Docs/code_map_check.py` + `Tools/Docs/code_map_check_selftest.py` + 根 `code_map.md` 指纹

## 问题

规范 §8.1 写死了治理口径：**上限/常量的唯一真源是 `LIMITS` 常量表**，规范正文的表格只是它的解释，冲突时以代码为准。核查后发现唯一一处违约：

| 判据 | 规范出处 | 代码位置 | 是否在 `LIMITS` |
|---|---|---|---|
| 复述型 S：Jaccard ≥ 0.5 | §6/§7 | `jaccard >= LIMITS["JACCARD_THRESHOLD"]` | ✅ |
| 清单型 F：并列短语 ≥ 3 个 | §6/§7 | `len(items) >= 3`（硬编码字面量） | ❌ |
| 行/字段/条目/表头/项数上限 | §2/§7 | `MAX_LINE_LEN` 等 10 个键 | ✅ |

后果有两条，都不是美观问题：

1. 规范说「以代码为准」，而这条判据在代码里没有可指认的常量 ⇒ 想核对阈值必须读判定语句，`--report` 的 `limits` 段也自证不了它。
2. 这条阈值正是待用户裁定的焦点（§6 字段表「不得罗列 3 个以上并列**动作**」vs §7 反模式表「并列**短语** ≥3」）。硬编码让「改阈值」等于改判定逻辑，而不是改一个可审计的参数。

## 改动

1. `LIMITS` 新增 `"LIST_MIN_ITEMS": 3`（带注释：§6「用途不是清单」的可判定化）。
2. 判定处 `if len(items) >= 3:` → `if len(items) >= LIMITS["LIST_MIN_ITEMS"]:`，其余一行未动。
3. 自测 `stage_list_items_parallel_phrases` 补两条断言：第五行「解析、写入」（2 项）必须 0 命中；`mod.LIMITS["LIST_MIN_ITEMS"] == 3`（常量存在性 = API 契约）。原本就有「3 项必须命中」的对照行，于是阈值被 2 项/3 项两侧夹住。

**语义零变化**：判据仍是「顶层并列短语 ≥3」；`88d5df1` 的括号/行内代码切分修正不受影响。

## 验证

| 项 | 结果 |
|---|---|
| 自测 | **58 passed, 0 failed, 0 inconclusive**（原 56，新增 2 条） |
| 变异取红 | `LIST_MIN_ITEMS` 改 4 → **exit 1、55 passed / 3 failed**：`three top-level phrases still hit (control) -- hits={}`、`bracketed sub-phrases are not counted -- hit=None`、`threshold lives in LIMITS -- LIMITS=4` |
| 复原 | 变异后写回原字节，**sha256 逐位相同**，复跑全绿 |
| 门禁 | `code_map_check --check --paths . --fingerprint`：files_scanned 48、**error 0 / warn 82 / gate PASS**、stale-fingerprint 0、**fingerprint 148/148 verified、mismatched 0** |
| 判据分布 | anti-pattern 80 = 清单型 F **33**（15 文件）+ 路线图 26 + 演进叙事 17 + 过度宣称 4（与改动前逐项相同） |
| 报告自证 | `--report` 的 `limits.LIST_MIN_ITEMS = 3` |

## 顺带：改 `Tools/**` 源即需回填根指纹

编辑 `Tools/Docs/*.py` 后第一次跑门禁，根 `code_map.md` 的 `Tools/**` 指纹失配（warn 82 → **83**、verified 147/148、`stale-fingerprint: glob=Tools/** declared=d5833c103705 computed=c6a01c841046(files=27)`）。这是规范 §5 指纹机制**应有的反应**，不是缺陷：回填 `Tools/**=c6a01c84…` 后立即恢复 warn 82 / 148-148。

> 教训：门禁脚本自身也在自己的指纹覆盖范围内 ⇒ 改工具必须顺手回填根 `code_map.md`，否则门禁会「正确地」报自己陈旧。
