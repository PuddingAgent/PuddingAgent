# 2026-10-08 第三条 flake：未复现，只做加固

## 根因分析（读代码得出）

用例里有两处**时间型判据**：

1. `image.Dispatcher.Invoke(() => { }, DispatcherPriority.ApplicationIdle);` —— 用"排一个空回调"当**排水**：
   它只能证明"这个空回调跑了"，**不能**证明门以 `Render` 优先级排队的停放动作**已经发生**；
2. `Assert.True(thread.Join(TimeSpan.FromSeconds(10)), "STA test timed out");` —— 墙钟当验收。

（门的行为在 `WebView2PresentationGate.OnSourceChanged`：为避开 Freezable 的继承上下文重入，
停放动作被 `BeginInvoke(Render)` 合并延后 —— 这使"排空回调"这种写法天然不可靠。）

## 改法

| 原 | 现 |
|---|---|
| 单个优先级空回调当排水 | `PumpUntil(image, () => image.Source is null)`：**循环泵消息直到观察到目标状态**（低优先级投递以免与 Render 抢优先级） |
| `Join(10s)` | `ManualResetEventSlim` 完成信号 + **60s watchdog**（只诊断真挂住） |
| — | 两处失败信息都写明"这是**挂住**，不是变慢" |

## 验证（含**未复现**的诚实结论）

| 项 | 结果 |
|---|---|
| 旧形态隔离 20 次 | **0 / 20 失败**（⇒ **没复现**） |
| 修复形态隔离 20 次 | **0 / 20 失败**（⇒ 与旧形态**无区分度**） |
| 单次耗时 | 约 7.2–7.6s（`dotnet test` 启动占主要） |
| 注册表 | **保留该条目**，注释写明：两处时间判据已改为状态判据、**未复现**、方案门禁（整链 20 次或真实复现）未满足、**不得把加固当证据** |
| **全量链** | **1651 / 0**、**无重试**；`PuddingDesktop.Tests` **320 / 320** |

## 诚实边界（诚实登记）

- **这不是"已修复"**：既没复现，也没有能区分新旧形态的指标；只能说"去掉了两处**原则上**不可靠的判据"。
  在拿到真实失败样本或整链 20 次证据之前，**不得**从注册表移除它。
- **整链 20 次门禁未跑**（单次全链约 10 分钟）。
- **`DispatcherPriority` 语义依赖**：若门以后改用更高优先级或同步派发，`PumpUntil` 的低优先级投递仍成立（只影响泵的节奏）。
- **未真机验证**。
