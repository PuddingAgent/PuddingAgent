# 2026-10-13 Core 能力通道预检与日志编码修复

## 改动

- `Source/Pudding.CapabilityBroker.AspNetCore/CapabilityChannelPreflight.cs`：按 Kestrel 实际发布的 `http://pipe:/<name>` 匹配能力监听器，保留 REST、具体管道名和 Core 实例 ID 的失败门禁。
- `Source/Pudding.CapabilityBroker.AspNetCoreTests/CapabilityChannelHostTests.cs`、`TestInfrastructure.cs`：用真实 Named Pipe、双传输和 Loopback 监听器验证预检，补充错误管道拒绝测试；原模拟地址改为真实 Kestrel 格式。
- `Source/PuddingAgent/Program.cs`：在 DesktopChild 首条输出和日志初始化前设定无 BOM UTF-8，与 Desktop stdout/stderr 解码一致。
- `Source/PuddingDesktop/MainWindow.xaml.cs`、`TestScripts/test-pudding-desktop-launcher.ps1`：Debug smoke 验证已启用通道的预检与中文日志；脚本增加 `-CapabilityChannelEnabled`，只修改隔离配置。
- 三个受影响项目的 `code_map.md` 更新当前契约；调试手册补充能力端点误判和编码诊断。

## 验证

真实管道回归在修复前失败，修复后能力通道组件测试 48/48、Desktop 测试 334/334 通过；Desktop 与独立 Core 构建成功。真实 Desktop smoke 的 13 项进程内检查与 4 项外部生命周期检查通过，完整结论见 [验收报告](../../../14_reports/Core能力通道启动修复验收-2026-10-13.md)。
