# 2026-10-31 Python 解释器解析补 `py -3`：修复本机 Python 索引整体不可用

## 现象

合并门禁里 `PuddingCodeIntelligenceTests` 有 6 条长期失败，之前只用 `git stash` 证过「不是当日改动引入」，误以为与代码无关。实际错误全部指向同一句：

```
Python not available (tried 'python' and 'python3')
```

## 根因（本机实测）

```
python : C:\Users\hyfree\AppData\Local\Microsoft\WindowsApps\python.exe   ← App Execution Alias
python --version → "Python was not found; ... install from the Microsoft Store"
py -3 --version → Python 3.14.7                                            ← 真实解释器
```

即：`python` / `python3` **命令能命中、进程能启动**，但只是商店别名的占位符；真正的解释器只有 `py -3`。`GetPythonCommand` 的候选表里没有它，于是**本机 Python 代码索引整体不可用**（不只是测试）。

这正是本仓反复踩的那条：**`Get-Command` 命中 ≠ 可用**。

## 改动

- `Source/PuddingCodeIntelligence/Python/PythonIndexer.cs`：
  - 新增 `private sealed record PythonCommand(string FileName, string PrefixArguments)`，把「可执行文件」与「必须前置的参数」分开 —— `py -3` 这种形式无法作为单个 `FileName` 使用。
  - `GetPythonCommand()` 候选扩为 `python` / `python3` / `py -3`，判定改为**双重**：退出码为 0 **且**输出不含 `was not found` / `Microsoft Store`（占位别名会「成功启动」并打印安装提示）。
  - `RunProjectExtractionAsync` / `RunExtractionScriptAsync` 的形参类型改为 `PythonCommand`，`FileName = cmd.FileName`、`Arguments = cmd.PrefixArguments + 原参数`。
- 测试未改动（这 6 条本来就是正确的门禁，只是环境解析错了）。

## 证据（实测）

- **修复前**：6 条失败，消息均为 `Python not available`。
- **修复后**：同样 6 条（filter 命中 11 条用例）**全部 Passed**。
- **变异取红**：把 `py -3` 候选从表里去掉 ⇒ **恰好 6 红**，正是原来那 6 条；按备份字节还原 SHA-256 位级一致后 0 红。
- **全量**：`PuddingCodeIntelligenceTests` **151/151 全绿**（此前 145/151）。

## 影响面

这台机器上 Python 项目的符号抽取此前**一直走 Retryable 分支**，即：索引不报错、但一个 Python 符号都没有。修复后 `py -3` 可解析，实际抽取走通。

## 未做 / 边界

- 仅覆盖 Windows 的 `py -3` 约定；其它平台的自定义解释器路径（如 `PYTHON` 环境变量、venv 内相对路径）未支持。
- 未验证 Python 抽取在**大项目**上的耗时与超时行为。
- 不部署。
