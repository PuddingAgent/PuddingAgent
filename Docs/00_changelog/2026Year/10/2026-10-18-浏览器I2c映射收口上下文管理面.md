# 2026-10-18 I2-c 映射收口：context 管理面与 page.list 接入，命令全覆盖

## 改动

- `context.create` → `browser.context.create`（可选 ContextId，缺省由运行时生成）；
- `context.close` → `browser.context.close`（ContextId 优先取 args，其次命令 envelope；缺失拒绝）；
- `context.getInfo` 与 `page.list` → `browser.contexts`（`DesktopContextInfo.pages` 已含页面与版本，一次读取满足两者；**不做第二条发现能力**，已知代价是返回面更宽）；
- 移除"未映射命令"用例（此时 Bridge 全部已知命令都已有映射或显式 fail-closed），改为 context 管理面映射用例 + close 缺 id 拒绝。

## 覆盖状态（I2-c 映射层）

`context.list/create/getInfo/close`、`page.create/list/getInfo/activate/close/goto/goBack/goForward/reload/stop/snapshot/locate/interact/waitFor/screenshot` **全部命令**均已映射（`page.activate/close` 与 `page.interact` 依赖本轮前已补的线缆版本字段；缺失版本一律拒绝）。

## 验证

- adapter 用例 **13/13 通过**；
- 未运行产品/模型；适配器仍未接管执行（派发器仍走 controller）。

## 未完成与影响

- 下一步是**接线**：派发器对已映射命令设置 `SessionPermitMarker` 并调用工作区执行器，结果映射回 Bridge 描述符；随后 controller 收缩、删除旧执行路径。映射通过不等于端到端可用。
- `context.getInfo`/`page.list` 返回面更宽（整份 contexts），若工具端需要精确单页描述可在结果映射层过滤。
- 回滚 = revert 本提交。
