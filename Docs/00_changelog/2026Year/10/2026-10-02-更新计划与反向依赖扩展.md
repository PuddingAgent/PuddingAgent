# 2026-10-02 更新计划与反向依赖扩展（D3）

## 改动

- 新增 `Source/PuddingCodeIndex/Contracts/CodeSourceUpdateContracts.cs`：
  - `CodeFileSemanticChange`（该文件**真正提取出的**符号消失/签名改变；空列表 = 没有影响依赖方的语义变化）；
  - `ICodeGraphDependencyQuery`（反向依赖查询端口：给一批符号 id，返回依赖它们的**其他文件**路径，
    去重 + 稳定排序；图真源在存储侧）；
  - `CodeSourceUpdateAction`（`Extract` / `RebindOnly` / `Delete` / `RetryLater`）、
    `CodeSourceUpdateItem`、`CodeSourceUpdatePlan`（含计数与 `Truncated`）、稳定原因串 `CodeSourceUpdateReasons`。
- 新增 `Source/PuddingCodeIndex/Services/CodeIndex/CodeSourceUpdatePlanner.cs`：
  把变更集规划成**按依赖顺序执行**的计划（提取 → 只重绑 → 删除 → 本轮不动，组内按路径排序）：
  - 动作映射：`ReindexContent→Extract`、`RebindConsumers→RebindOnly`、`Delete→Delete`、`Deferred→RetryLater`；
    `RefreshFingerprintOnly` **不进计划**（只写 manifest，索引没有要改的东西）；
  - **反向依赖扩展只沿已知符号变化走**：没有提取依据（没有 `CodeFileSemanticChange`）就一次图都不查，
    绝不凭「文件被改了」猜测影响面；
  - 依赖方以 `RebindOnly` + `DependencyDepth=1` 入计划并沿用触发它的消费者；
    本来就要提取/删除/退避的依赖方不被降级为只重绑；
  - **退避中的路径不参与扩展也不重复入队**：一个自己还在退避的文件不会拖着依赖方一起动；
  - **扩展有界**：触到上限置 `Truncated` 并告警，调用方下一轮继续（不得静默丢掉依赖方）。
- `SqliteCodeIndexStore` 追加实现 `ICodeGraphDependencyQuery.ListDependentFilePathsAsync`
  （引用 + 关系两个来源、去重排序、`json_each` + 分块避开参数上限），并把它在原子替换里用的
  同一个私有查询抽成可选排除 owner 的共用实现。
- 新增 `CodeSourceUpdatePlannerTests`（12 条）与 3 条图查询用例。

## 验证

- `dotnet test Source\PuddingCodeIndexTests\PuddingCodeIndexTests.csproj` → **261 通过 0 失败**（本次 +15）。
- 关键用例：动作映射与执行顺序；只刷新 manifest 的路径不进计划；已知符号变化把依赖方扩展为只重绑
  （深度 1、原因、消费者沿用）；**没有语义变化依据时一次图都不查**；空符号列表不算语义变化；
  本来要提取/要删除的依赖方不被降级；退避中的依赖方与「自己退避的文件不驱动依赖方」；
  扩展触顶显式 `Truncated`；只查真正变化的符号；非法参数拒绝；
  图查询覆盖引用与关系两个来源、空输入不查库、300 个符号的分块查询。
- 组件边界不变（不引用语言智能、`ProjectReference` 仍为空）；`ComponentBoundaryTests` 保持通过。

## 未完成与影响

- **语言侧批量接缝与 workspace 复用尚未实施**（D4 的「同批候选统一装载、按项目/配置版本复用一个有界
  Roslyn workspace/编译快照」）：本轮只交付了「要动哪些文件、什么动作」的计划与图查询，
  没有把它接到 `RoslynCSharpIndexer`/`CompositeCodeIndexer`，也没有语言侧的 `NotApplicable` 能力路由结果。
  为了不给未来实现强加一个未经验证的形状，语言批量端口**故意没有提前定形**，将与真实实现一起落地。
- **仍未接入维护链路**：`CodeSourceUpdatePlanner` 目前没有调用方；`CodeIndexMaintenanceService` 仍走旧路径。
  因此对运行中实例仍是零行为变化。
- 后续阶段：语言批量/依赖计划（含能力路由）→ 既有维护链路接入（watcher/防抖/校准 + 宿主忽略规则适配）。
