# 2026-10-08 B7 验证收口：Contracts 的依赖方全部跑过

## 为什么要做

我的改动落在 `Pudding.Contracts`（`BrowserCallerIdentity` / 浏览器授权契约）等共享程序集上，
而**依赖它的测试工程有 12 个**。此前只跑过：链内 7 个（每次交付链）+ 链外 3 个轻量的。
`PuddingAgent.IntegrationTests`（集成级）**从未运行** —— 这条缺口我登记了好几轮，本轮关掉。

## 结果（round-139，全部实跑）

| 测试工程 | 结果 |
|---|---|
| 链内 7 个（现由交付链每次覆盖） | **1554 / 0**（见 handover-129 第八节） |
| `Pudding.CapabilityBrokerTests` | 90 / 0 |
| `Pudding.CapabilityBroker.AspNetCoreTests` | 43 / 0 |
| `Pudding.DesktopConnectionTests` | 80 / 0 |
| **`PuddingAgent.IntegrationTests`** | **18 / 0（本会话首次运行）** |
| `PuddingWebApiTests` | **170 / 3**（goal/compaction 用例）← 唯一非绿 |

⇒ `Pudding.Contracts` 的 12 个依赖方**现已全部运行过**，11 绿 1 非绿。

## 非归因是**可核对**的，不是断言

`PuddingWebApiTests` 的 3 条失败（`GoalQueries_Return_Snapshot_And_Empty_Iterations`、
`Compact_Passes_Runtime_Profile_To_Compaction_Service`、`Compact_Persists_Failed_Terminal_Event`）
所在测试文件里，对 `Pudding.Contracts` / `browser` / `IsSameActor` / `DeliveryManifest` / `KnownUnverified`
的引用数 = **0**（实测）。加上历史多轮观测到同样的 2–3 条变动，判定为**他方子系统问题**：
**未归因、未代改**（遵守"不代改他方子系统"的纪律）。

## 验证与留痕

- 选择依赖方的工具：`TestScripts/check-dependent-suites.ps1 -Assembly Pudding.Contracts`（静态扫 `<ProjectReference>` 传递可达）。
- 已同步 [handover-129 第五节](../../../14_reports/2026-10-09-浏览器自动化交付总览-handover129.md)：
  "IntegrationTests 未跑" 改为"18/18 已跑"，WebApi 一栏写明失败条数与文件引用数依据。

## 诚实边界（诚实登记）

- **`PuddingWebApiTests` 仍非绿**：本轮**只记录、不修复**；它不在我的交付链内，也不在浏览器/契约的影响面内。
- **仍是进程内验证**：IntegrationTests 通过**不**等于真机/生命周期结论（那需要进程外控制器）。
- **未做跨提交对照实验**：非归因依据是"引用数为 0 + 历史重复观测"，不是"在改动前的提交上跑一遍"（登记为可加强项）。
- 两项待决取舍未触碰。
