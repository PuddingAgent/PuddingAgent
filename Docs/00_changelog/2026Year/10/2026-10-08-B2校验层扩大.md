# 2026-10-08 B2 校验层用例扩展到 5 条

| # | 用例 | 判据 |
|---|---|---|
| ① | 空白 `Value` | 抛，消息含 `Locator value is required` |
| ② | 合法 Css（**对照**） | 不抛 |
| ③ | 复合 `Has`（`Locator.Has` 非空） | 抛，消息含 `not available`（Phase 2A-3 限制） |
| ④ | 畸形 ref（`not-a-ref`） | 抛（`Invalid browser ref format`） |
| ⑤ | `Normalize` 夹取 | `MaxTextLength`：10⇒**256**、9_999_999⇒**500_000**、默认⇒**200_000** |

## 实测发现（值得下一轮追）

`Locator { Kind = LocatorKind.Ref, Value = "e1" }` **被本层拒绝**（`Invalid browser ref format`）⇒ 驱动侧要求的 ref 形状**比 `"e1"` 更严**（可能绑定 pageToken/version，或另有前缀）。

这与我此前看到的 Desktop 侧用例（`LocateMappingTests` 用 `new DesktopLocator(DesktopLocatorKind.Ref, "e1")`）**形状不一致**：那一层测的是"版本核对 + 是否真的下发查询"，不校验 ref 形状。⇒ **待澄清**：真正合法的 ref 形状是什么？Core/页面快照**生成**的 ref 是否满足它？若不满足，ref 定位在真机上会失败。**这正是本轮最有价值的产出**（一个可追的潜在缺陷线索），但**我尚未验证**它是否为真缺陷，故只登记、不下结论。
