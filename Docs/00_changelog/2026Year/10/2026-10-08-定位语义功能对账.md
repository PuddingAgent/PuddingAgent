# 2026-10-08 对 §6.1/§6.2 做功能对账（并更正一处低估）

## 换口径：文档 ↔ 代码

前几轮的对账是"文档 ↔ 文档/用例名"。本轮直接把设计 **§6.1/§6.2** 的要求逐条对到**代码**：

| §6.2/§6.1 要求 | 代码中的落点 | 结论 |
|---|---|---|
| **保留十种定位方式** | `LocatorKind` / `DesktopLocatorKind` 恰为 **10** 个（Ref/Css/XPath/Text/Role/Label/Placeholder/AltText/Title/TestId） | ✅ |
| text 的 **exact/substring**、空白折叠 | WebView2DomClient 的 matchText：`exact ? 归一化全等 : 归一化包含`；归一化即空白折叠 | ✅ |
| **最小可见匹配节点**、不因祖先含文本返回整页 | `Scripts_KeepOnlyTheMinimalTextMatch_AndDistinguishFilteredZeroHits`、`SnapshotScript_ScopesTheScan_AndNeverFallsBackToTheWholePage` | ✅ |
| 一次零命中≠所有 text 定位都坏 | 同上的 "DistinguishFilteredZeroHits" | ✅ |
| `includeHidden` 默认 false | `LocateScripts_ExcludeHiddenElementsByDefault` | ✅ |
| **visible 与 inViewport 分开**、写前滚入并复检 | `Scripts_ReportInViewportAndGateWritesOnIt` + `BrowserOperationFailure` 的滚入失败分类 | ✅ |
| **遮挡**不按成功处理 | `InteractScript_RejectsObstructedWriteTargets`（`elementFromPoint` 命中测试，含 shadow root） | ✅ |
| 未支持策略（frame/复合 has）**明确拒绝** | `ValidateLocator_RejectsFrameAndCompoundHasUntilSupported` | ✅ |
| §6.1 **不写站点专用选择器** | `SnapshotScript_ExtractsArticleBlocks_WithoutSiteSpecificSelectors` | ✅ |

## 更正（我此前的**低估**）

round-148/150 的对账表里，G7 的"0×0/禁用/**遮挡**拒绝"被我写成
"⚠️ 真实命中判定在 WebView2 DOM 客户端（真机相关）；进程内只有映射/条件层证据 ⇒ 登记为真机项"。

**这是错的**：`PuddingDesktop.Tests/Browser/WebView2DomClientTests.cs`（**交付链内**、320 例之一部分）里
就有 `InteractScript_RejectsObstructedWriteTargets` 等针对性用例。已把该行改为 ✅ 并写出用例名。
教训与上一轮同源：**"我没找到"不等于"不存在"** —— 前一轮漏看了第四个工程。

## 门禁同步

表格门禁的扫描范围从 3 个工程扩到 **4 个**（新增 `Tests/PuddingDesktop.Tests`），否则新写的 G7 用例名会被误判为不存在。
另：表格里**生产类名不要加反引号**（门禁会把行内代码当成用例名；已改为普通文字表述）。

## 诚实边界（诚实登记）

- **"实现了 + 有用例"仍不等于"真机行为正确"**：这些用例是**脚本层**验证（DOM 脚本生成与判定），
  `elementFromPoint` 在真实合成页面/缩放/固定定位下的表现**仍未在真机验证**。
- **未逐条核对 §6.1 的预算数字**（10,000 节点/深度 64/250ms、8 个 extraction snapshot/页、2 MiB、TTL 60 秒）
  是否与实现一致 —— 登记为下一轮可做的对账（那些数字是可核对的）。
- 决定②仍待确认。
