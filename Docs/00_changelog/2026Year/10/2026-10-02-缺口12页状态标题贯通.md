# 缺口 #12 完成：页状态贯通标题（`browser_wait_for` 因此完全解锁）

## 目标 / 背景

缺口 #12 是**收益最大的一个**：四个工具的结果里 `BrowserTabToolValue.Title` 是必填，
而契约 `DesktopPageState` 只有 `Target`/`Url`/`Version`/`Readiness`。本轮补上。

## 改动（跨侧协议变更，两侧同提交）

| 层 | 文件 | 改动 |
|---|---|---|
| 线缆 | `desktop_capability.proto` | `PageStateOutcome.title = 4` |
| 契约 | `Contracts/Desktop/PageContracts.cs` | `DesktopPageState(..., string? Title = null)`（默认值让 25 处既有构造点继续编译） |
| Desktop→proto | `DesktopConnection/Mapping.cs` | **4 处** `PageStateOutcome` 构造写入标题（page_state / interact / wait_for / tabs） |
| proto→DTO | `CapabilityBroker/WireMapping.cs` | **4 处**读出（含"空串即 null"归一化） |
| Desktop 侧 | `DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs` | **5 处**从 `page.Info.Title` / `page.Title` 填充 |
| Bridge 侧 | `Host/BrowserBridge/BridgeBrowserCapabilitySurface.cs` | **2 处**（page_state 结果 + 共享 `BuildPageState`） |
| 线缆快照 | `Rpc.ProtocolTests/WireContractSnapshotTests.cs` | 新增 `PageStateOutcome` 字段号断言（含 `title = 4`） |

## 过程教训（工具层，值得记）

本轮我用「先校验、不匹配即整体放弃」的脚本分两阶段批量改。第一阶段（线缆+契约+8 处映射）
**已经写盘**，但其中 4 处读取端少了一个括号 ⇒ 文件编译失败；第二阶段因行尾检测（混合 CRLF/LF）
与缩进猜错而整体放弃。

- 教训一：**分阶段批量改，每阶段写完必须立刻编译**——否则会出现"半套已落盘"的状态；
  本轮就是靠编译才发现，并用**打印实际字节**（而不是继续猜锚点）才修好。
- 教训二：**不要假定行尾统一**；匹配跨行锚点时必须按文件探测或改用单行锚点/正则。

（净损失约 6 次工具调用，代价可控，且没有污染任何其他文件。）
