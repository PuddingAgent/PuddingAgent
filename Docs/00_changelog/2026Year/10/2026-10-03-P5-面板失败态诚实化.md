# P5 面板失败态诚实化

## 1. 缺陷（**当下正在发生**）

运行中的宿主里 `GET /api/admin/index/status` **不存在**（实测 **404**；对照 `/api/admin/storage/overview` 同条件 **401** ⇒ 请求确实到达应用层，404 = 路由不存在）。
逐行读 `index.tsx` 的旧渲染路径（`catch` → `snapshot === null`）可推出此刻面板**必然**显示：

```
[error] 索引状态读取失败   Request failed with status code 404（页面保留上一次成功快照仅作参考，不代表当前真值）
[info ] 尚无快照           正在读取 GET /api/admin/index/status …
```

**三处不诚实**：① 端点**永久缺失**却说「**正在读取**」（把缺失伪装成加载中）；② 副行**无条件**声称"保留上一次快照"，而此刻**从无快照**；③ 可行动事实（"宿主没部署"）被埋在通用报错里。
⚠️ 诚实标注：这是**代码路径**推断（我无登录凭据，**未**在浏览器实拍该态）。

**`api.ts`（纯新增，既有导出签名/行为一字未动）**：`INDEX_STATUS_ENDPOINT` 唯一真源 + `classifyIndexStatusFailure`（`not-deployed` / `unauthorized` / `network` / `unknown`）。
**取码防御式**：`response.status` → `status` → `statusCode` → 从 message 抠 `status code NNN` / 裸 `4xx|5xx`；**只接受 100..599 的整数**，否则 `httpStatus = null`，**绝不猜成 404**。
**`index.tsx`**：`catch` 改存分类结果；失败 Alert 按 kind 分四种（404 用 **warning**，不是 error —— 它是"能力未上线"而非故障）；「尚无快照」三分支：`loading` ⇒ 「正在读取」（**唯一**出现处）· `error` ⇒ warning「读取失败，尚未取到任何快照」· 否则 ⇒ 「端点返回了空快照」；"快照仅作参考"仅在**确有快照**时出现。

## 5. 本轮的流程教训

1. **子代理死在收口前的文件锁**：`file_patch` 报 Windows `ERROR_USER_MAPPED_FILE`（"请求的操作无法在使用用户映射区域打开的文件上执行"，目标 `index.tsx`），补丁原子提交失败并回滚。当时**无 node.exe / dotnet.exe** 在跑 ⇒ 占用者不是显而易见的 watcher。教训：**先核磁盘哈希**判"是否已污染/半完成"，再决定接管；本例哈希 == 其记录的复绿态，实现完整 ⇒ **父级接管收口**（不重建子代理）。
2. **无自述的交付必须全程自理**：子代理未写报告就死了 ⇒ 我逐项亲跑（切片 / chat 回归 / build）+ 读 diff 核逐字文案 + 核变异红点是否为**预期断言**。
3. **横向变化会使旧基线失效**：P4 记录的 chat 既有失败是 **3** 条（含 2 条 `InputArea`），本次基线已是 **1** 条 ⇒ 他人工作流在此期间修好了 2 条。**"与改动前逐字相同"** 才是判据，**不是**"与我上次记的数字相同"。
