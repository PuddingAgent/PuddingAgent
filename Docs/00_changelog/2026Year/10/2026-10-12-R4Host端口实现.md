# R4 ⑥ 核心落地：Host 侧委派端口

| 项 | 内容 |
|---|---|
| 新增 | `Source/PuddingHost/BrowserBridge/HostBrowserDelegationLifecycle.cs` |
| 验证 | **`PuddingHost` 编译通过** · **`PuddingHost.Tests` 276/276**（不需 WinUI） |
| 校验 | scope 线名仅 `read`/`write`（未知 ⇒ 拒绝）· 父子 run 必填 · **契约校验先于会话解析** |
| fail-closed | **无会话 ⇒ 拒绝**（与"门"的"未启用即放行"不同：委派是**显式请求**） |
| 身份 | `BrowserCallerIdentity(SubAgent, callerId, childRunId, parentTaskId)`（**双 id 必需**） |
| 签发 | `Producer.IssueAsync(binding, operationId, null, ct)`；未签发 ⇒ **如实还原理由** |
| **撤销（本轮编译错误逼出的正解）** | 撤销需 **(身份, 目标)** 而端口只有 `runId` ⇒ **签发时登记** `_issued[childRunId] = binding`，撤销时 `TryRemove` 查表 ⇒ **精确 + 幂等** |
| 调用上下文 | `new DesktopCallContext(session.DesktopId, OperationId, now+30s, correlationId: null, browserCaller: binding.Task)` |

**过程**：首版 `ForBindingRevoke(runId, reason)` ⇒ `CS1503`×2 ⇒ 守卫删文件后改**登记表**方案 ⇒ 一次通过。
