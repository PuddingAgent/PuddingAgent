# 2026-10-22 画布标注回传只读快照

## 起因

用户在工具区画布上圈选/画箭头/写文字之后，Agent 只能靠截图**盲估** `<point>`/`<bbox>`：
画布上真实的标注数据只在 WebView2 页面里，Agent 侧没有任何读取通道。上一轮交付的
「画布 → 制品 → 精修」链路能跑通（`vision-1ee905b6…`），但**上游取坐标**这一步一直是猜的。

## 方案：文件交接，Core 侧只读

- Desktop 在既有 2 秒画布轮询里，用 `window.puddingAnnotation.take()` 取标注原文，写到
  `{DataRoot}/panels/panel-{id}.annotations.json`；Core 只读该文件。
- **否决**「给 Core 开一个写标注的 HTTP 接口」：Core 绑在 `0.0.0.0`，没有鉴权，一个匿名写入口
  等于把画布交给整个局域网。此前试过又被回滚（`e71b875`），本次不再走这条路。
- **否决** External Access Token 子系统：为一次文件交接引入一整套凭据体系过重。
- 两个进程本来就共享数据根，文件是最窄、最少假设的连接面：Desktop 只写自己那块画布的
  快照，Core 只读。

## 改动

- `Source/PuddingCore/Panels/PanelAnnotationFile.cs`（新）：`PanelAnnotationFile`、
  `IPanelAnnotationFileReader`、`PanelAnnotationFileName`（`SchemaVersion=1`，`For`/`PathFor` 单点定义文件名）、
  `FilePanelAnnotationFileReader`。解析 fail-closed：JSON 坏、根不是对象、schema 版本不认识、
  panelId 缺失或与文件名不一致，一律返回 `null` 并给出原因，**不抛**。
- `Source/PuddingDesktop.Foundation/PanelAnnotationSnapshotWriter.cs`（新，BCL-only）：
  `TryPublish` 原子写（`.tmp` + `File.Move` 覆盖）；**空载荷拒写**（页面刚 `NavigateToString`
  时 `take()` 会返回空串，写下去就会洗掉用户上一轮的笔迹）；只返回 `false` + 原因、不抛
  ——它挂在 UI 定时器上。
- `Source/PuddingDesktop/MainWindow.xaml.cs`：`PublishPanelAnnotationsAsync` 每 tick 比对原文，
  只有真变了才落盘（失败下轮重试，不刷状态栏）；调用点在 `ApplyPanelFeed` **之前** ——
  内容 revision 变化会 `NavigateToString` 重载页面，顺序反了 `take()` 只能拿到空标注。
- `Source/PuddingBrowser.AgentTools/PanelInspectTools.cs`：`ReadPanelTool` 增加可空注入的
  `IPanelAnnotationFileReader`，输出 `annotations`/`annotationsUpdatedAt`/`annotationsTruncated`/
  `annotationsNote`。工具内**不做** 0–999 归一化（唯一实现是 `Desktop.Foundation.PanelAnnotation.Normalize`），
  只给换算口径，避免第二份约定漂移。画布不存在时仍报告标注。
- `Source/PuddingHost/Extensions/PuddingServiceCollectionExtensions.Platform.cs`：注册
  `IPanelAnnotationFileReader` → `{DataRoot}/panels`。
- code_map 同步：`Source/PuddingCore/code_map.md` 新增「交互面板域（Panels/）」整节（此前
  `Panels/` 三个文件一个都没登记）、`Source/PuddingDesktop.Foundation/code_map.md` 补 writer、
  `Source/PuddingBrowser.AgentTools/code_map.md` 补 4 个画布工具（此前完全未登记）。

## 验证

- Core `PanelAnnotationFileReaderTests` 12/12、Foundation `PanelAnnotationSnapshotWriterTests` 8/8；
  两侧各有**文件名字面量锁测试**，把 `panel-{id}.annotations.json` 公式钉住，单侧改动会立刻失配。
- **变异取红**：reader 注入缺陷后 11/12（1 红），writer 注入缺陷后 7/8（1 红）；复原后文件 SHA-256
  与变异前逐位一致，并重新转绿。
- Foundation 全量 460/460；Core 全量 1130/1131 —— 唯一失败
  `ResolveStartupLevel_FallsBackToEnvironmentThenInformation` 是环境变量干扰的既有 flake，
  单跑 27/27 绿，与本次改动无关。
- AgentTools / Foundation / Core 构建 0 个 CS 错误。

## 留白（未验证 / 未做）

- **运行期验收未做**：Desktop 正在运行、锁着 DLL，接手标注重启才有意义。需要一次
  `bootstrap_reboot` + 托盘退出重开，然后在画布上画一笔、`read_panel` 看 `annotations` 是否真的出现。
- 标注目前**只能读、不会回灌到画布**：`render_panel` 替换 `main` 内容仍会清掉用户笔迹，
  因为 Core 侧还没有把标注写回画布状态的路径。要么先加「读标注再重绘」，要么等用户对
  Desktop/Core 之间写通道的凭据方式拍板后再做「带鉴权的标注写入接口」。
- 制品导出仍只能用户手动点（「添加到对话」/「保存到制品库」），没有 Agent 侧入口。
