# 2026-10-08 横向：把验证扩到交付链之外

## 盲区是什么

我的交付链固定跑 **7 个项目**（Automation / AgentTools / Contracts / DesktopService / DesktopSurface.Browser /
PuddingDesktop / Host）。但 round-117 改的是 **`Pudding.Contracts`**（新增 `IsSameActor` 并把租约换成它）——
`Pudding.Contracts` 是共享程序集，**相邻子系统也会加载**。只跑那 7 个 = 验证盲区。

## 先查清"谁真的受影响"

按 **`bin/Debug/net10.0/Pudding.Contracts.dll` 是否存在**判定（而不是按 csproj 文本里是否出现该字符串）：

| 测试项目 | 是否加载 Contracts | 处置 |
|---|---|---|
| `Pudding.DesktopConnectionTests` | ✅ 存在（221,696 B） | **跑** |
| `Pudding.CapabilityBrokerTests` | ✅ 存在 | **跑** |
| `Pudding.CapabilityBroker.AspNetCoreTests` | ✅ 存在 | **跑** |
| `Pudding.Rpc.ProtocolTests` | ❌ **不存在** | 跑了，但**结论无关**（见下） |

## 结果

| 项目 | 结果 |
|---|---|
| `Pudding.DesktopConnectionTests` | **80 / 80** |
| `Pudding.CapabilityBrokerTests` | **90 / 90** |
| `Pudding.CapabilityBroker.AspNetCoreTests` | **43 / 43** |
| 合计（相关证据） | **213 例全绿** ⇒ 契约改动无外部回归 |
| `Pudding.Rpc.ProtocolTests` | 20 / 20（**但它不加载 Contracts** ⇒ 与本次改动无关） |

## 诚实边界（诚实登记）

- **一次性的**：这 4 个套件**没有**并入我的交付链（它们属相邻子系统；把别人的套件纳入我的清单会改变交付口径）。
  将来若再改共享契约，应重复这类"链外抽查"，而不是假定链内 7 个够了。
- **我先前的一次无效动作**：`Rpc.ProtocolTests` 我是因为 csproj 文本里出现 `Pudding.Contracts` 才去跑的，
  实际它**不加载**该程序集 ⇒ 那 20 例不能作为证据。**教训**：判断"谁受影响"要看**加载/引用图**，
  不能看文本匹配（本轮用 bin 里的 dll 存在性纠正了这一点）。
- **仍未真机验证**；仍未触碰两项待决取舍。
- 无产品行为变化（验证 + 记录）。
