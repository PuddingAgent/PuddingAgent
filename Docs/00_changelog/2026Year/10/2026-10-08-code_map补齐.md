# 2026-10-08 横向：补齐 code_map 漏登记

## 发现（真实漏登记，不是猜测）

`Agents.md` 要求"任务结束前**必须维护** code_map：新增/移动/删除关键文件 → 更新对应子项目 code_map"。
本轮收尾时逐项核对，发现 **6 处漏登记**（都是我这几十轮内新增或改动的文件）：

| 漏登记项 | 应登记位置 | 复核 |
|---|---|---|
| `Browser/BrowserSmokePlan.cs`（G1–G11 唯一事实源，13 项检查） | `Source/Pudding.DesktopService/code_map.md` | ✅ |
| `Browser/ExternalAcceptanceSession.cs`（外部验收会话） | 同上 | ✅ |
| `Browser/ExternalAcceptanceFacts.cs`（外部观察事实模型） | 同上 | ✅ |
| `Browser/AutomationDriverPolicy.cs`（策略适配器） | 同上 | ✅ |
| `DriverPolicy.cs`（`IBrowserDriverPolicy` 接缝 + fail-closed 空实现） | `Source/PuddingBrowser.Abstractions/code_map.md` | ✅ |
| `TestScripts/check-round-gates.ps1` · `commit-round.ps1`（门禁与提交门禁） | 根 `code_map.md` §5 测试工程索引（`TestScripts/` 行） | ✅ |

同时顺手把 TestSite 的说明补全为"`fixtures/` 含 SERP/正文/滚动/**页面事件**四条 fixture 路由"。

## 做法

- **就地改写受影响条目**，不追加时间线、不写轮次/提交号/测试数字（按 code_map 规则：只保留"现在是什么"）。
- 修改后**逐条复核命中**（6/6），并用 `check-round-gates.ps1` 复核文档门禁不受影响。

## 验证

| 项 | 结果 |
|---|---|
| 命中复核 | 6 个漏登记项全部命中（见上表） |
| 文档门禁（总数口径） | front matter 2（他方）、链接 32（他方）、BOM 0 ⇒ 全在基线内 |
| 变更范围 | 只改三个 code_map 文件的受影响条目（未动"源指纹"行等由工具维护的内容） |

## 已知边界（诚实登记）

- **只补了我确认漏掉的 6 处**：code_map 全量一致性（是否还有其它子项目漏登记）**未做系统性审计**；
  根 `code_map.md` 的"条目数/源指纹"行由工具维护，我**未**手改。
- **本轮的教训**：把 code_map 维护当作"结束前的强制动作"是对的，但我在连续多轮只改测试/文档时**跳过了它**
  —— 这类"只在新增源码时才想起"的习惯会持续漏登记文档与脚本类关键文件。
- 无产品行为变化（文档索引）。
