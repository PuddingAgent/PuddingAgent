# 2026-10-08 横向：门禁脚本内置"链接自动修正"

## 目标 / 背景

我在**同一类**相对链接深度错误上已经栽了**四次**（round 89/91/92/93 各一次），每次都是"少写一级"。
round-93 的 `commit-round.ps1` 已经能在提交前拦住它，但**修正**仍靠我手工改。本轮把修正也变成一条命令。

## 改动

`TestScripts/check-round-gates.ps1` 新增 `-FixLinks`（可配 `-OwnerPattern`）：

- 读 `check_md_links.py --all-repo` 落盘的违规清单；
- **只处理匹配 `-OwnerPattern` 的文件**（默认 = 本会话交付物：`2026-10-0[89]-(?!T\d)` 开头的 changelog、
  `12_features/浏览器*|B6-*`、`13_runbooks/浏览器*`、`14_reports/2026-10-0[89]-浏览器*`）——**绝不碰他方文档**；
- 按**唯一文件名**在仓库里定位目标（`bin/obj/node_modules/.git` 除外；多义或找不到就跳过并说明）；
- 改写后**重新测量**并打印新的总数。

## 端到端演练（真实执行）

| 步骤 | 结果 |
|---|---|
| ① 故意把 `2026-10-08-全绿清单93.md` 的 3 条链接改回错误层级（模拟我第 5 次犯错） | 门禁 `broken targets=35 > baseline 32` ⇒ **exit 1** |
| ② `-FixLinks` 自动修正 | `links rewritten = 3`（随后 1 条因下述缺陷需再修一次） |
| ③ 复测 | `broken targets=32 (baseline 32)`、`BOM=0`、front matter 2 ⇒ **exit 0** |
| ④ 文件内容 | 三条链接均为正确的 `../../../14_reports/...` |

## 实现中撞到的三个坑（都被自己抓到）

1. **`[System.IO.Path]::GetRelativePath` 在 Windows PowerShell 5.1 不存在**（.NET Framework）⇒ 手写相对路径计算。
   —— 这个坑我 round-89 已经踩过一次，**忘了**，本轮又付了一次学费（已在注释里写明）。
2. **子串替换会重复施加**：`../../../14_reports/x` **包含** `../../14_reports/x`，于是第二条违规记录
   在同一文件上再替换一次 ⇒ 变成 `../../../../14_reports/x`（**多补一级**）。
   改为**锚定整条 markdown 链接**的正则（`\]\(…\)`）替换后正确；这条缺陷是演练第 ②/③ 步对不上时暴露的。
3. **默认参数里的中文**（`浏览器`）又触发 PS 5.1 的 ANSI 解析陷阱（脚本变成非法正则）⇒ 改用 `\u6D4F\u89C8\u5668`
   转义，脚本恢复**纯 ASCII**（非 ASCII 字符数 = 0）。

## 已知边界（诚实登记）

- **只修"目标存在但路径写错"的链接**：目标真的不存在（他方那 32 条）不会被我"修好"，也不该被猜。
- **不做语义校验**：只保证链接能解析。
- **默认只覆盖我的交付物**：若要处理其它范围必须显式传 `-OwnerPattern`（有意为之，避免误改他方内容）。
- **会改写文件**：`-FixLinks` 是有副作用的开关；不带它时脚本只读。
- 无产品行为变化（脚本工具）。

## 影响与回滚

- **无行为变化**（新增开关 + 一处修正缺陷）。回滚：删掉 `-FixLinks` 分支。
