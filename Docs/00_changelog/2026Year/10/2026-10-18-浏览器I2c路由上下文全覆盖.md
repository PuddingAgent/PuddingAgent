# 2026-10-18 I2-c 路由全量覆盖：context.create/close 也经执行器（Bridge 命令 100%）

## 改动

- `FromCreatedContext`：`DesktopContextInfo` → `BrowserContextDescriptor`（ContextId/PageCount；**目录字段缺口与 contexts 一致，如实空串**）；
- 路由集合加入 `context.create`、`context.close`：
  - create 投影新建上下文描述符；
  - close 与旧 controller 一致返回**空成功**；
- 测试：create 投影 contextId、close 空成功；原"未覆盖命令回退"用例改用未来命令名（`page.future_command`）保持语义；路由测试 **11/11**。

## 覆盖状态（I2-c 里程碑）

**Bridge 全部命令**（`context.list/getInfo/create/close` + `page.create/list/getInfo/activate/close/goto/goBack/goForward/reload/stop/snapshot/locate/interact/waitFor/screenshot`）在生产派发器上**全部经同一工作区执行器路由**，未覆盖命令返回 null 回退 handler 的迁移缝保留。

## 验证

- Shell build exit 0；`Tests/PuddingDesktop.Tests` ⇒ **381/381 通过**；
- 未运行产品/真实模型；本轮首次让 context 管理命令走执行器（真机验证属 I3/I4）。

## 未完成与影响

- **controller 已不再被路由覆盖的命令触达**，但旧 handler 代码仍在（删除旧执行路径是独立、需谨慎的清理切片）；
- 错误码映射仍为近似（应加能力码↔Bridge 码对表测试）；
- `page.getInfo` 之外命令的上下文目录字段缺失（执行器契约无 UserDataDirectory）；Core 侧 `BrowserContextDescriptor` 解析会得到空目录，需确认无 UI 依赖；
- F5 后置观察、`browser_context` 发现面、I3/I4 外部证据未完成；
- 回滚 = revert 本提交。
