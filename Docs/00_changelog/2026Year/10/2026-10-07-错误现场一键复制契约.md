# 2026-10-07 · 错误现场「一键复制」契约

## 背景 / 动机

用户反馈（附聊天界面截图）：失败只显示一行原始英文 —— `本轮运行失败  LLM 调用失败: Error while copying content to a stream.` + 一个「重试」。
两个诉求：

1. **界面友好**：第一眼就必须认出「哪一类错误」，有明确标题与大概原因，不要让用户困惑；
2. **可复制**：要有「复制/下载」功能，复制出去的是**准确、全面**的信息（含日期、`traceId`、`errorId`），
   以便把它贴给维护者，**在茫茫日志里直接定位到现场**。

这正是可诊断基础设施的消费面，因此按契约落地，而不是在前端拼字符串。

## 改动

| 文件 | 内容 |
|---|---|
| `Source/PuddingDiagnostics/Presentation/ErrorPresentation.cs` | 界面简略层：标题 / 大概原因 / 严重度 / 可重试 / 建议动作 / 稳定因果码 / 类别；按码建目录，未知码走类别兜底并**保留原码** |
| `Source/PuddingDiagnostics/Presentation/DiagnosticReportDocument.cs` | 复制层：版本化 schema（`pudding.diagnostic-error/1`）+ 捕获时间(UTC) + `errorId`/`traceId`/`turnId`/`sessionId`/`executionId`/workspace/agent + 因果码/类别/阶段 + 尝试明细 + 证据（含异常链）+ **日志定位提示** + 处置建议；`RenderText()`（人读、可直接粘贴）/`RenderJson()`（机器读、确定性）；64 KiB 上限，超出显式标注截断 |
| `Source/PuddingDiagnosticsTests/ErrorPresentationTests.cs` | 6 例门禁（见下） |
| `Docs/12_features/可诊断基础设施设计-2026-10-07.md` §12 | 两层契约、硬规则、后端→前端数据流与 Stage 4 施工清单 |
| `Source/PuddingDiagnostics/code_map.md` | 登记新文件与新概念 |

顺带修正：视觉链路既有码的命名是 `vision_xxx`（下划线）而非文档写的 `vision.xxx`，类别判定与目录兜底
原先只认前缀 `vision.`，会把 `vision_provider_file_expired` 误判成「未知类别」⇒ 现按两种命名同时识别。

## 验证（实测）

```
dotnet test Source\PuddingDiagnosticsTests\PuddingDiagnosticsTests.csproj --artifacts-path temp\build\diagnostics-tests
  → 已通过! 失败 0，通过 30，总计 30   （新增 6 例）
```

新增用例锁住的判据：

| 用例 | 判据 |
|---|---|
| `Presentation_IsFriendly_AndNeverEchoesTheTransportMessage` | 标题/大概原因**不得**出现 `Exception` / `HttpRequestException` / `SocketException` / `Error while copying` / `IOException`；RST 场景标题为「模型服务连接中断」且标可重试 |
| `Presentation_ShowsTheRawCodeForUnknownCauses` | `vision_*` 归类为图片链路；`something.brand_new` 这类未知码**原样显示**（不得伪装成已知） |
| `CopiedReport_CarriesEveryFieldNeededToLocateTheIncident` | 复制文本含 UTC 时间、`traceId`、`errorId`、因果码、阶段「上传请求体」、`attempt=3`、`request_bytes`、`socket_error_code=10054`、异常链、`logs/error/pudding-error*` 与 `session-timeline` 定位提示 |
| `CopiedReport_JsonIsCompleteAndStable` | 同一报告两次渲染逐字符相同；JSON 含 `Schema`/`CauseCode`/`Evidence.phase`/`Attempts`/`Presentation.Title` |
| `CopiedReport_NeverContainsSecretShapedValues` | 复制载荷（文本 + JSON）不含密钥形态值，URL query 被剥离 |
| `CopiedReport_IsClampedWithAnExplicitNotice` | 超长证据触发兜底截断并**显式**写出「报告已截断」 |

第一次运行有 2 条取红（视觉码类别误判、截断用例绕过证据预算不足），已按上述修正后转绿。
