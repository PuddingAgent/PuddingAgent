# Bridge 握手拒绝诊断与超时误报修复

基线 HEAD `07cfc6c`。用户提供的旧现场与源码机制吻合：信封版本检查早于 Hello 载荷日志，异常被静默吞掉；重启本身不能更换产物。本轮开始时未发现运行中的 PuddingDesktop/Core，不能把旧 PID、时间戳当成本轮观测。

- Core：版本异常记录错误码、连接与 expected/received；坏 JSON 不回显载荷；用独立两秒上限的 policy close 拒绝旧端，避免等待旧端解析新版 Ack。
- Desktop：保留连接首次终止原因，分别处理协议错配、JSON、取消和真正超时；Ack 内层也校验版本；不将已经终止的会话标为 Connected。
- 更新对应 code_map 及 ADR-097 D9 的握手和配套哈希规则。仍严格使用协议 v3，无兼容分支。

验证使用 `--artifacts-path temp/build/recovery`，输出 `temp/test-out/browser-hello/`：

| 验证 | 结果 |
|---|---|
| 修复前 Host 握手测试 | 4 通过、3 失败；新增 v2/v4 外层错配与坏 JSON 均复现无明确 policy 拒绝 |
| 修复后 Host BrowserBridge | 147 通过、0 失败 |
| 修复后 Desktop Browser | 162 通过、0 失败，含 Ack 外层/内层错配不误报超时 |

编译存在仓库既有 NuGet 漏洞、可空与分析器警告；本轮没有修改依赖版本。此提交只证明代码/组件门禁，不证明已部署或一期 Agent 功能完成；完整包构建、实际运行及浏览器功能验证另行记录。其他方既有 WIP 未纳入提交。

文档验证：两份变更文档 Front Matter 通过；全 Docs 链接检查发现 24 个既有失效目标，均在未修改文档，本次文档无失效目标或锚点。
