# 2026-10-08 更正：两个 Docs 文件被我的 PowerShell 改写写入了 BOM

## 更正内容

**更正（2026-10-08）**：round-85 我用 `Set-Content -Encoding UTF8` 修正 changelog 里的相对链接时，
**Windows PowerShell 5.1 会给文件写入 UTF-8 BOM**。受影响的两个文件：

| 文件 | 表现 |
|---|---|
| `Docs/00_changelog/2026Year/10/2026-10-08-G5预算实测.md` | Front Matter 门禁报 `[缺少 Front Matter]`（BOM 让 YAML 不再从字节 0 开始） |
| `Docs/14_reports/2026-10-08-浏览器自动化交付清单-round63.md` | 同样带 BOM（本轮扫描发现，尚未被门禁点名） |

**处理**：用 `UTF8Encoding($false)`（无 BOM）重写两个文件；门禁复绿
（`front_matter --check` 在这两个文件上 0 不合规；`check_md_links --all-repo` 零失效目标）。

## 为什么值得单独记录

这是本会话**第三次**被同一个坑咬到：

1. round-83：`serp-en.html` 被我改写后带 BOM ⇒ **fixture 编码门禁**报出；
2. round-84：往 `.ps1` 里加中文 ⇒ Windows PowerShell 按 ANSI 读无 BOM 脚本，**解析失败**（同源：编码假设）；
3. round-85/86：`Set-Content -Encoding UTF8` 给 Docs 文件加 BOM ⇒ **Front Matter 门禁**报出。

**规避写法（今后一律用）**：

```powershell
# 读
$text = [System.IO.File]::ReadAllText($path)
# 写（无 BOM）
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))
```

即：**不要**用 `Set-Content -Encoding UTF8` 改文本文件的编码相关部分（PS 5.1 会加 BOM）；
需要改内容时优先用编辑工具（edit），它的写入是无 BOM 的。

## 验证

| 项 | 结果 |
|---|---|
| BOM 扫描 | `Docs/**/*.md` 全仓库扫描：修复前 2 个带 BOM，修复后 **0** |
| Front Matter 门禁 | 我涉及的 2 个文件 **0 不合规**（全仓库剩余 1 条为他人文件 `skill-merge-probe-rerun-2026-10-06.md` 缺字段，非本次改动） |
| 链接门禁 | 我涉及的文件零失效目标 |
| 代码套件 | 未受影响（本轮只改两个 markdown 文件的字节前缀） |

## 已知边界（诚实登记）

- **扫描只覆盖 `Docs/**/*.md`**：仓库其它位置的 markdown（如 `.pudding/skills/**`）未扫描（不在本次门禁范围）。
- **没有把"无 BOM"变成自动门禁**：目前靠 `front_matter --check` 间接发现；更彻底的做法是给仓库加一条
  "Docs 下 markdown 不得带 BOM"的检查（登记为可做的改进，未在本次完成）。
- **C# 文件带 BOM 无害**：编译器不受影响，因此本轮只处理 markdown（不扩大改动面）。
