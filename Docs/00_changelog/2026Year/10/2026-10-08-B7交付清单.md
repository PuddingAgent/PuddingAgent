# 2026-10-08 B7 交付清单：把「口头交接」变成机器可读且必须诚实的事实

## 目标 / 背景

上一轮把两段式验收规则落成判定（`DesktopAcceptance`）。但真正的交付还需要一份**机器可读的交接事实**：
外部控制器必须能知道「这是哪个构建/提交」「内部跑了什么、有没有失败」
「**哪些结论内部证明不了**」「外部必须做哪些步骤才能给出终态结论」。此前这些都只在对话/日志里。

## 改动

`Pudding.DesktopService/DeliveryManifest.cs`（新增）：

| 字段 | 作用 |
|---|---|
| `buildId` / `commit` | 产物可追溯（空值 ⇒ 拒绝：没人能指认的构建不可交付） |
| `artifacts` | 交付产物清单 |
| `checks` | 内部检查及结果：**有失败项一律不合格**；全部计数为 0 也拒绝（"没真跑"不算检查） |
| `knownUnverified` | **内部证明不了的结论**（真机/CDP/生命周期/环境）。**必须显式给出**：`null` = 没想过 ⇒ 拒绝；空列表 = 确实没有 ⇒ 允许 |
| `requiredExternalSteps` | 必须覆盖生命周期四步（`startup`/`restart`/`crash-recovery`/`exit-reclamation`） |
| `stage` | 内部清单**只能**是 `ready-for-external-deploy`（用交付用语序列化，不用枚举名） |

`DeliveryManifestValidator.Validate` 逐条给出**具体**原因（不是"格式不对"这种含糊话）。

## 验证

| 套件 | 结果 |
|---|---|
| `Pudding.DesktopServiceTests` | **246 / 246**（原 237 ＋ 9） |
| `Automation` · `Contracts` · `AgentTools` · `DesktopSurface.Browser` · `PuddingDesktop` · `Host` | 276/276 · 153/153 · 64/64 · 66/66 · 320/320 · 258/258 |

新增门禁：合格清单通过；缺构建/提交被拒；**失败检查被拒**；检查计数为 0 被拒；`knownUnverified` 显式性
（null 拒 / 空列表通过 / 空白项拒）；生命周期四步缺失被拒；内部声明后续阶段被拒；产物与检查必填；
序列化含 camelCase 键、中文**不被转义**（人可读）、阶段用 `ready-for-external-deploy`。

**取红实测**：让"有失败项"不再拦（`failed > 0` 短路）⇒ `FailingChecksAreNeverDeliverable` **恰好变红**；
复原后 246/246 复绿。

**两个被现实教育的小坑（都写进代码注释了）**：
1. **源生成序列化不吃运行时的 `Encoder`** ⇒ 中文被转义成 `\uXXXX`（清单给外部控制器读，必须人可读）；
   改用普通反射序列化 + `JsonSerializerDefaults.Web` + `UnsafeRelaxedJsonEscaping` 后解决。
2. **枚举默认序列化成数字/枚举名** ⇒ 外部控制器读的是**交付用语**；改为 `[JsonIgnore]` 枚举 + 一个
   `[JsonPropertyName("stage")] StageName => DesktopAcceptance.NameOf(Stage)`。
另外一次 `if (false)` 变异被编译器以 **CS0162/CS8604** 拒绝 —— 说明这些校验无法被"短路掉还能编译"。

## 已知边界（诚实登记）

- **校验器只保证"清单本身合格"**：它无法验证 `checks` 里的数字是否真实（那需要 CI 事实），
  也无法验证 `knownUnverified` 是否穷尽 —— 它保证的是"这些字段被**要求**填、且不合格就不放行"。
- **没有生成器**：目前只有形状与校验，**还没有**一条命令/脚本能自动产出清单（下一步：把构建产物、
  测试计数、真机未验证项汇总成清单）。因此它现在仍无生产调用方。
- **没有持久化/留痕**：清单不会被存下来（审计留痕属后续）。
- **生命周期四步是固定词表**：若将来验收范围变化，需要同步更新 `RequiredLifecycleSteps`。
- 真机无关（纯数据与校验）。

## 影响与回滚

- **无对外行为变化**：新增组件尚无生产调用方。
- 回滚：删除 `DeliveryManifest.cs` 与其测试。
