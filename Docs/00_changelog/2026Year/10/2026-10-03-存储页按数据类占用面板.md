# 存储页新增「数据库占用（按数据类）」面板 + 去掉「估算」标注（前端 6.3.0）

## 做了什么

| 文件 | 改动 |
|---|---|
| `src/pages/storage/DatabaseSpacePanel.tsx`（新） | 「数据库占用（按数据类）」面板：**按钮触发** `GET /api/admin/storage/database-space`，逐库展示文件级总量 + 各数据类占用、占比（进度条）、涉及表数；库不存在如实显示「库不存在」；读取失败提示错误而不是显示空表 |
| `src/pages/storage/DatabaseSpacePanel.test.tsx`（新，4 条） | 默认不发起请求（要点按钮）；点击后展示各库/各数据类/占比（1.4GB÷2.0GB=70%）与「未归类」；**界面不出现「估算」字样**；失败要提示 |
| `src/pages/storage/api.ts` | 新增 `getDatabaseSpace()` |
| `src/pages/storage/types.ts` | 新增 `StorageDatabaseSpace` / `StorageDataClassSpace` |
| `src/pages/storage/index.tsx` | 挂载新面板；**删掉「分类统计报表」右上角的「全部为估算约数（≈）」**（用户明确要求不标注估算） |
| `package.json` | 6.2.0 → **6.3.0**（新增功能，按仓库规则与改动同提交） |

## 两个刻意的选择

1. **按钮触发、不随页面自动加载**：这几个数字要对每个库逐表取行数并对有界样本求和，GB 级库需要可感知的时间；
   自动加载会让每次进存储页都付这个代价。与服务端定位一致（`overview` 那条热路径明确不触发扫描）。
2. **不显示数据来源**：`spaceSource`（`dbstat` / `rowcount-sample`）由接口如实带出供排障与后续使用，
   但界面**不写「估算」**（用户要求）；面板只用中性说明「按数据类聚合」。

## 验证

- **jest：2 个套件 / 12 条用例全绿** —— 新增 4 条 + 既有 `index.test.tsx` 8 条（我改了 `index.tsx`，既有用例未被破坏）；
- **`tsc --noEmit`：`src/pages/storage` 下 0 个错误**（该门禁在 HEAD 上本来就有 6 个错误，全在 `chat/index.tsx`
  与 `chat/projections/executionFlowProjector.ts`，与本次改动无关，我未越界修改）。

## 过程中的自身失误（如实记录）

① 测试文件先用 `import React from 'react'`，而本仓库的 jest 走 **classic JSX**（既有测试用 `import * as React`）
   ⇒ `React is not defined`；两处都改成命名空间导入后通过。
② 修一条断言时用 `[Environment]::NewLine`（CRLF）去匹配**LF** 文件 ⇒ 替换静默失败、断言仍在，
   第二次改用"只替换该行文本"才生效 → **行尾不匹配是本会话第 4 次咬到我**。
