# 2026-10-08 full 模式补上真正的续读游标

## 补的是什么

上一轮实现 full 输出预算时，我把 `output_budget` 的语义限缩为"**缩小预算或收窄 fields 重试**"，
并登记"full 无续读游标"为缺口（`nextCursor` 恒为 null）。本轮把它补掉：

| 环节 | 做法 |
|---|---|
| 分页单位 | 三路表示按**固定顺序**（accessibilityTree → domText → html）拼成一条逻辑**行流** |
| 起点 | 既有游标管线已把 full 的期望 kind 定为 `lines`；本轮真正**使用** `cursor` 作为起始行号 |
| 装载 | 从起始行装到预算为止；**至少装一行**（超大单行会让调用方无法前进，与"超大单块整体给出"的既有语义一致） |
| 续读 | 还有剩余 ⇒ `nextCursor = lines:<下一行号>@<页面/版本身份>`（复用 `ArticleCursor`，不透明、绑定身份） |
| 拒绝 | 跨表示游标（拿 `md:` 读 full）、跨页面、旧版本 ⇒ `browser_invalid_arguments`（沿用既有文案） |
| 标注 | 还有剩余 **或单行本身超预算** ⇒ `Truncated=true` + `output_budget`；扫描侧同时缺内容仍是 `incomplete_scan(+output_budget)` |

## 验证

| 项 | 结果 |
|---|---|
| `PuddingBrowser.AgentTools.Tests` | **77 / 77**（＋2，改 1） |
| 新用例 | ① **续读不重不漏**：第二页首行必须紧接第一页末行，两页行集合不交集；② 跨表示（`md:` 游标）与旧版本（`lines:0@p1-v999`）都被拒 |
| 既有用例修正 | 上一轮那条"不给假游标"断言改为"必须给出 `lines:` 游标" ✓（缺口消除后语义反转） |
| 实现修正 | 首版漏了"单行超预算也要标 `output_budget`"，被 `incomplete_scan+output_budget` 那条用例抓出 ⇒ 已修 |
| **全量链** | **1601 / 0**、无重试 |

## 诚实边界（诚实登记）

- **行流顺序是约定**：三路表示拼成一条流，因此**跨表示的顺序**由实现固定（accessibilityTree → domText → html）；
  若调用方只关心其中一路，仍会在页边界上"等"另一路（登记）。
- **按行分页**：单行很长时（例如压缩过的 HTML）一页可能只装一行且超出预算 —— 已如实标注，但信息密度不可控。
- **游标绑定页面版本**：页面一变旧游标即拒（要求重读），这是与正文路径一致的安全取舍，**不是**"从原位置继续"。
- **未真机验证**；决定（B1 可信调用身份）仍未拍板；250ms 扫描时间门限仍缺样本。
