# 2026-10-08 ref 线格式确认 + 撤回疑似缺陷

## 读码结论（`WebView2DomClient.cs`）

```
/// ref 线格式：p{页面 token}-v{文档世代}-n{序号}。
/// 页面 token 由驱动生成（页面写不出来），因此跨页/跨 frame 的引用无法通过校验。
[GeneratedRegex("^p([0-9a-fA-F]{32})-v(\\d+)-n\\d+$", RegexOptions.CultureInvariant)]
```

生成侧（`SnapshotScript` 的 JS）：`ref = `${prefix}${++refState.next}``，且 L621 对不以前缀开头的旧属性值**重新生成** ⇒ 一致。

## 更正（撤回上一轮的假设）

round-282 我把"`e1` 被拒"写成**疑似真缺陷线索**。本轮**证伪**：`e1` 本来就不是合法 ref —— 合法形状是 `p{32位hex}-v{世代}-n{序号}`；
Desktop 侧的 `LocateMappingTests` 用 `e1` 是因为**那一层不校验 ref 形状**（只核对版本与是否下发查询）。**没有缺陷**。

**教训**：把"两处不一致"当成缺陷线索时，先读**定义处**（这里就是一行注释 + 一个正则）再下判断；本轮我先登记、后证伪，没有把它当结论发布——这个次序是对的。

## 新增用例

| 用例 | 判据 |
|---|---|
| 合法 ref `p{32hex}-v1-n2`（token 与 `pageToken` 一致） | **通过** |
| token 截断（`p0123-v1-n2`） | 拒绝 |
| 旧式 `e1` | 拒绝 |
| 缺世代（`p{token}-n2`） | 拒绝 |
