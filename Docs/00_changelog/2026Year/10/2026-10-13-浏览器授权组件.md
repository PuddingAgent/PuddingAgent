# 新建 PuddingBrowser.Authorization 独立授权组件

## 1. 为什么做

用户裁定（2026-10-13）：现有浏览器授权设计**过于复杂、缺乏架构**，而 Agent 必须能控制浏览器。
方案（`Docs/11_design/浏览器控制简化架构方案-2026-10-13.md`）把现状量化为
**5 环 / 3 闸 / 2 传输 / 2 身份**，并给出迁移顺序 step 0–5。本条目交付 **step 1**。

## 2. 根因（双重证实，非推测）

- `git grep -n NotifyConnectionGeneration -- Source` ⇒ 26 处命中：契约声明 1、实现 1，**其余 23 处全在测试工程**。
- `code_callers(IBrowserAutomationControl.NotifyConnectionGeneration)` ⇒ `count: 0`。
- 附带：`git grep -l OnBridgeReady -- Source` ⇒ 无命中（API 尚不存在）。

⇒ **「Core 已连接（日志有 `Browser Bridge connection attached gen=N`）、桌面权威恒不活」是代码的必然结果。**

## 3. 交付内容

| 文件 | 职责 |
|---|---|
| `AgentTargetSession.cs` | 唯一授权载体（用户选中的一页 + 桥世代）与 UI 快照；**刻意不含**身份/任务/读写分级/过期/租约 |
| `AgentTargetAuthorization.cs` | 6 个稳定拒绝码、操作类别、准入票据（**不是 grant 也不是 lease**） |
| `AgentTargetSessionAuthority.cs` | 唯一决策点：桥生命周期 + 选页/撤销/接管/关闭 + 两段式 `Authorize`/`Revalidate` |
| `AgentTargetSessionAuthorityTests.cs` | 21 条状态机不变式 |
| `ComponentBoundaryTests.cs` | 运行时依赖方向断言 |
| `code_map.md` | 组件索引（`code_map_check` gate PASS） |

## 4. 验收证据（全部可复现）

- **编译期边界门禁可取红**：临时加 `PuddingHost` 引用 ⇒ `error : may reference Pudding.Contracts ONLY` + **1 个错误**；还原后 **0 警告 / 0 错误**。
- **测试全绿**：`已通过! 失败: 0，通过: 21，总计: 21`；组件覆盖率 **Line 90.72% / Branch 78.64%**。
- **变异取红**：移除传输门槛 ⇒ `AuthorityIsNotLiveBeforeTheHandshake` 变红（期望 `browser_transport_unavailable`，实得 `agent_target_required`）；还原后全绿。
- **code_map gate**：`error 0 / gate PASS`。

## 5. 测试先抓出的三处实现缺陷（规格级教训）

1. 换页后误清 `LastRevokedSessionId` ⇒ 丢失审计事实（应粘性保留）。
2. **接管误推进控制世代** ⇒ 在途写报 `agent_target_revoked` 而非 `browser_busy`。
3. 同一根因 ⇒ 只读票据被误判过期，**违反「接管不撤销阅读」**。
⇒ 结论：`BeginUserControl`/`EndUserControl` **只翻转布尔**；控制世代只由「目标作废」推进。
