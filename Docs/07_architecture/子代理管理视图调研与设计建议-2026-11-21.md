## 一、DSH 怎么做（实测，非推测）

### 1. 子代理即「子会话」，不是独立对象

`GET /sessions` 返回 107 个会话，其中 **45 个带 `parentSessionId`**。会话行的字段是
`sessionId / title / updatedAt / cwd / running / blank / agentAvailable / archived / parentSessionId / origin`。

⇒ 子代理在数据层就是一条带 parent 的会话记录，UI 侧靠这棵树组织，不另建实体。

### 2. 两套名字：`subagent` 与 `subagent_fork`

- `subagent`：从**全新上下文**开始
- `subagent_fork`：**继承已完成轮次**
- 两者都立即返回一个**名字**（如 `reviewer`）用于寻址；名字在同一创建者的子级之间唯一，描述可重复
- 活跃子任务用 `send_message` 引导；完成后可继续其对话

⇒ 「名字」是 UI 里的主要标识，不是 `sessionId`。这点和我们 `agent_pool.name` + `pool_id` 的双标识一致。

### 3. 团队 = 持久化共享任务板

`@deepseek-ai/dsh-agent-team`（版本 0.2.2-rc.5）的定位原文：

> 为现有 subagent（子智能体）树添加持久化共享任务板。成员使用标准 subagent 工具发现和联系彼此。Team 提供比较并交换（CAS）的任务归属更新。成员共享同一检出目录。

- 「Lead / Teammate」是角色词：Lead 发起，Teammate 是被发起的子代理
- 任务归属更新用 **CAS**（比较并交换）—— 和我们池里 `rowsAffected == 1` 才改内存是同一个思路
- 开启方式：根 Session 的模型菜单里「使用智能体团队」；`defaultEnabled: true` 可默认开；关闭后**整棵树后续步骤**不再显示 Team 工具与提示词，**但保留任务与子代理**

### 4. 最重要的一条：UI 明确把「任务」和「成员」分开了

DSH 变更记录原文：

> **Web Team 面板仅显示任务；subagent 导航负责浏览成员。** 线上 `agentTeam.members` 字段与 `TeamMemberProjection` 被移除；持久化成员状态仍可解码。

这是踩过坑之后的收敛：**同一个面板既管任务又管成员，会同时做不好。** 任务板回答「还有什么没做」，成员导航回答「谁在跑、跑得怎么样」，两者刷新频率与交互完全不同。

### 5. 已知限制（DSH 自己承认的）

> **全量视图广播** —— 每次任务变更向已连…（后续被截断）

即每次任务变更向所有已连接的客户端广播全量视图。子代理一多，这是性能上的真问题，值得我们提前避开。

### 6. UI 包形态

DSH 拆成独立包：`dsh-client-ui-agent-team`（团队面板）、`dsh-client-ui-settings-subagent`（设置，含 `SubagentCard` / `SubagentLimitsCard`）。前端按「面板」与「设置」分包，不塞进主界面。

## 二、本项目落点建议

### 位置：顶部导航第三项，紧邻「任务看板」

现状（`Source/PuddingPlatformAdmin/src/pages/chat/components/ChatMain.tsx`）：

- `:593` `aria-label="任务看板"` 的按钮
- `:325` 注释「任务看板模态窗口（原独立路由改为弹窗）」
- `:822`（`workspace-tasks/index.tsx`）「任务看板模态窗口：约占窗口 80% 宽高，内容区可滚动，关闭即卸载并重新加载数据」

⇒ 新增「子代理」按钮挂在同一行，复用同一模态壳（80% 宽高、关闭卸载重载）。**不要新开路由**——与既有取舍保持一致。

### 形态：左树 + 右详情（两栏）

```
┌─ 子代理 ──────────────────────────────── [×] ┐
│ 搜索 / 状态筛选 / [只显示运行中]              │
├──────────────┬──────────────────────────────┤
│ 树（左，320px）│ 详情（右，自适应）             │
│ ● planner     │ [概览][运行][日志][用量]       │
│  ├ ● 运行中    │  名字 / 模板 / 角色           │
│  └ ○ 空闲      │  状态 + readiness             │
│ ● reviewer    │  task_count / last_success    │
│  └ ✕ 已销毁    │  归属：owner_session/workspace│
└──────────────┴──────────────────────────────┘
```

要点：

1. **左树按 parentSessionId 组织**，与 DSH 一致；池条目已有 `owner_session_id`，可派生
2. **状态徽标用池的四态**（`NotStarted/Loading/Ready/Failed`）+ 条目态（`idle/busy/sleeping/dead`），**不要合成一个模糊的「健康」**
3. **用量页签直接读 `llm_gateway_usage_events`**——本会话已证明子代理面板的 token 统计**不累加续跑轮次**，所以详情页必须显示真账，不能显示面板汇总
4. **任务不进这个面板**（照 DSH 的教训），任务留在「任务看板」；两个面板互相跳转即可

### 不建议做（有证据的坑）

- **不要全量广播**：DSH 已把它列为已知限制。池变更走增量事件（已有 `agent_pool.status` 索引），面板按需拉取
- **不要按名字做主键**：名字可被 destroy→create 替换，`pool_id` 才是稳定标识（S5b 已因此把驱逐改成返回 `pool_id`）
- **不要显示「池为空」当未就绪**：S5d 已把这条写进文案判据，UI 层必须继承同一判据

## 三、分期建议

| 期 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| P1 | 只读列表 + 详情（树、状态、归属、用量） | `agent_pool` 表（已有） | 打开面板能看到当前池条目；未就绪时显示「未就绪」而非空 |
| P2 | 操作：唤醒 / 睡眠 / 销毁 / 改名 | `ISubAgentPool` 已有方法 | 每个操作后条目状态与库一致；失败文案走 S5d 五类映射 |
| P3 | 运行中会话跳转（点条目看它的对话） | 子会话与主会话共用会话存储 | 能从条目跳到对应会话历史 |
| P4 | 团队任务板（仅在需要多子代理协作时） | 需先有跨会话任务归属 | 同 DSH 的 CAS 归属语义 |

P1 只读，风险最低，建议先做。

## 四、命名 / 头像 / 名片（2026-11-21 10:18 用户提出）

### 现状（实测，非推测）

| 载体 | 已有字段 | 缺什么 |
|---|---|---|
| `session_sub_agents`（全部子代理的投影表） | `Id, parent_session_id, parent_agent_id, sub_session_id, Status, template_id, model_id, task_summary, spawned_at, completed_at, Success, reply_summary, error_summary, full_result_json` | **无 display_name / avatar / role / responsibility** |
| `agent_pool`（持久池条目） | `name, role, template_id, owner_session_id, owner_workspace_id, ...` | 有 name/role，**无 avatar / responsibility** |
| `SubAgentSpawnRequest`（DTO） | `TaskDescription, TemplateId, RoleInPlan, AssignedObjective` | **无 DisplayName / Avatar / Responsibility** |

⇒ 非池化的子代理在界面上只有一个 `sub_session_id`（形如 `...-sub-e8b01311`）和一段被截断的 `task_summary`。这正是「一串 UUID 记不住」的来源。

### 1. 命名

- `SubAgentSpawnRequest` 增加 `DisplayName`。
- **同级唯一**：同一 `parent_session_id` 下活跃子代理的 `DisplayName` 不得重复；冲突时自动加序号后缀（`reviewer-2`）。
- 长度 2–16 字符，允许中文；拒绝空白/控制字符/纯数字。
- `sub_session_id` 仍是技术主键，界面默认**不显示**，只在「复制 ID」入口给出。
- 参考 DSH：`subagent` / `subagent_fork` 立即返回一个名字（如 `reviewer`）用于寻址，名字在同一创建者的子级之间唯一，描述可重复。

**默认值策略**：`spawn_sub_agent` 新增 `name` 参数。父代理不给时，自动生成 `<role>-<序号>`（role 取自模板或 `RoleInPlan`），保证永远有可读名字，不阻塞派发。

### 2. 头像

两级，**默认确定性生成**：

1. **确定性（零存储）**：由 `hash(DisplayName + sub_session_id)` 派生 SVG identicon——首字母/几何图形 + 色相。永不缺失，同名不同实例也能区分（session 盐保证）。
2. **可选覆盖**：`AvatarKey` 指向预设图形集（几何符号 / emoji），后续可扩到上传。

理由：把头像设为必填会成为每次派发的摩擦；确定性生成保证 UI 永远有东西可画。

### 3. 名片

`session_sub_agents` 增加三列：`display_name`、`avatar_key`（可空）、`responsibility`；`agent_pool` 同步增加 `avatar_key`、`responsibility`（`name`/`role` 已有）。

名片展示字段：

```
头像  DisplayName            状态徽标（池四态 + 条目态）
      RoleLabel · TemplateId
      Responsibility（一句话职责）
      归属：created_by（父会话头像+名）
      运行：task_count / last_success / 最近一次运行时长
```

**Responsibility 由谁写**：派发者。父代理知道任务意图，`spawn_sub_agent` 增加可选 `responsibility`；未给时回退到 `task_summary` 首句。不要用 LLM 二次生成——多一次调用多一份钱，且 `task_summary` 已经够用。

### 4. 结构性约束

- **名字不是主键**：可被 destroy→create 替换；稳定标识仍是 `pool_id`（S5b 已因此把驱逐改为返回 `pool_id`）。UI 用名字显示、用 `pool_id` 定位。
- **唯一性靠部分唯一索引**：沿用 `IX_agent_pool_name`（`WHERE deleted_at IS NULL`）的既有模式；`session_sub_agents` 用 `(parent_session_id, display_name) WHERE completed_at IS NULL`。

### 5. 迁移注意（本项目特有）

项目**无 EF migration**（`EnsureCreated`），存量库不补表也不补列 ⇒ 加列必须**两路都做**：

1. EF 实体声明（新库 `EnsureCreated` 生效）
2. 幂等 raw DDL（存量库生效）。SQLite **不支持 `ALTER TABLE ADD COLUMN IF NOT EXISTS`**，必须先
   `PRAGMA table_info` 检查列是否存在再加，并用测试锁死两路结果一致（参照 `AgentPoolSchemaBootstrapper` 既有做法）。

## 五、外部调研：还缺什么（2026-11-21 10:20）

参考对象：Claude Code 官方文档（subagents / agent-teams）、DSH 本机实测、Hermes Agent 文档、学术侧 OrchVis（arXiv 2510.24937）、MA-Trace（多智能体可观测）、FoA（能力向量）。

### 5.1 我们有而参考实现没有的（先确认优势）

- **持久池 + 四态就绪门 + 归属 fail-closed + 执行令牌**：DSH 与 Claude Code 的文档里都没有「进程重启后池条目复活 / busy 僵尸」的公开解法；我们已用 `ResetStaleBusyAsync` + 状态判据解决。
- 这三样是此前 S1–S5d 攒下的，做界面时**不要为了对齐别人而削弱**。

### 5.2 参考有而我们没有的

| # | 能力 | 参考 | 现状 |
|---|---|---|---|
| 1 | **子代理定义仓库**（名字 + 描述 + 工具白名单 + 默认模型 + 职责，可复用可版本化） | Claude：markdown frontmatter；DSH：`agent-preset-registry` | 只有内置 `agent_template`，每次手写 task |
| 2 | **按描述自动委派**（模型依据 description 判断何时用哪个子代理） | Claude | 只能父代理显式调用 |
| 3 | **描述预算**（所有 subagent description 合计超 15,000 token 启动告警） | Claude | 无；一旦有几十个定义会吃光父上下文 |
| 4 | **按定义固定模型与工具集**（Explore 固定用便宜模型 + 只读工具） | Claude | `CapabilityPolicy`/`PreloadToolIds` 有，但**不按定义持久化**；model 每次传 |
| 5 | **共享任务列表 + 认领（claim）** | Claude teams、DSH `dsh-agent-team`（CAS 归属） | 完全没有 |
| 6 | **子代理之间直接通信** | Claude teams、DSH `send_message` | 无（只回报父代理） |
| 7 | **确定性回放 + 因果链**（coordination graph、memory op trace） | MA-Trace | 有 `events.jsonl` 原始事件，无按 run 回放界面；且面板统计与 `llm_gateway_usage_events` 脱节 |
| 8 | **冲突解决 / 选择性重规划面板** | OrchVis | 无 |
| 9 | **优雅停机的公开语义**（中断运行中子代理并保留部分结果） | Claude 自己把它列为已知限制 | 有 destroy/sleep，但「中断正在跑的」未验证 |
| 10 | **能力向量**（agent 声明能力/成本/限制，可搜索） | FoA | `capabilityTags` 只在模型层，不在子代理定义层 |

### 5.3 关键判断

**#1 是其余各项的地基。** 没有定义仓库，名片只能是每次派发时临时填的字符串，无法复用、无法版本化、无法做「这个岗位默认用哪个模型」。#4 和 #3 都依附于 #1。

**#4 对我们价值被显著放大**：今天实测 `gpt-6.2-sol` 无前缀缓存，有效单价比 deepseek 高 20–30 倍。若「定义」能固定默认模型，就能像 Claude 的 Explore→Haiku 那样，把研究与实现的模型成本分开管。

**#6（子代理互连）建议最后做。** Claude 与 DSH 都做了，但它把系统从「树」变成「网」，直接推翻前面「关系是树、不画拓扑图」的结论，且带来消息风暴与死锁风险。在做共享任务板之前不值得。

### 5.4 优先级（建议）

| 期 | 内容 | 理由 |
|---|---|---|
| P0 | 定义仓库（名字/头像/职责/工具白名单/默认模型）+ 两表加列 | 名片与界面的数据源 |
| P0.5 | 描述预算闸门（合计超限告警） | 与 P0 同时落，成本极低，晚了要返工 |
| P1 | 管理视图（树 + 三处动效） | 用户已定型 |
| P2 | 按定义注入工具集与默认模型 | 直接省钱 |
| P3 | 共享任务板 + 认领（CAS） | 对齐 DSH/Claude 的团队语义 |
| P4 | 回放 + 因果链 | 需先把 usage 真账接进面板 |
| 不做 | 子代理互连、拓扑图（除派发瞬间动画） | 收益 < 复杂度 |
