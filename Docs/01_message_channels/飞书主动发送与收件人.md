# 飞书主动发送与收件人

Agent 从绑定渠道的白名单选择飞书收件人，无需用户先向机器人发送消息。配置入口为工作空间 → 渠道管理 → 编辑渠道 → **特权用户 Open ID**。这份名单同时用于高权限系统指令和主动发送，不限制普通用户与机器人聊天。

## 配置与选择

- 渠道服务商、渠道和绑定 Agent 必须启用，Agent 不能冻结；渠道只能绑定一个启用的 Agent，App ID 不能冲突。
- 既有 `privilegedUserOpenIds` 配置直接生效，不增加配置迁移。目录查询和主动发送都会重新读取配置；收件人结果不包含 App Secret。
- 仅一位候选（一个渠道与 Open ID 组合）时，`user:owner` 为默认收件人。多个候选时必须明确选择，不自动群发，也不猜最近联系人。
- Open ID 属于对应飞书应用；同一个 Open ID 出现在多个绑定渠道时，通过 `channel_id` 明确选择。

## Agent 工具

先调用 `list_feishu_recipients`，返回 `recipients` 中的 `address`、`openId`、`channelId`、`channelName` 和 `connectorId`；唯一候选也会出现在 `defaultRecipient` 中。

```json
{"to":"user:ou_example","channel_id":"channel-example","content":"任务进展汇报"}
```

将以上参数交给 `send_message`。示例 ID 必须替换成目录返回值。显式 `user:OpenID` 始终按所选用户主动发送，即使当前回合来自另一个飞书用户。一次只能指定一个飞书收件人；混合 Agent/用户目标或飞书广播会在入队前拒绝。

`user:owner` 在可信的当前飞书回合仍表示回复该回合；网页、心跳等无当前飞书回信上下文的场景使用配置默认值。`connector:id` 仅用于回复当前可信连接器，不能替代主动收件人选择。Agent 间的 `agent:id` 和消息 intent 语义不变。

## 投递与诊断

主动发送创建独立消息，将 `gateway_receive_id` 和 `gateway_receive_id_type=open_id` 交给持久队列，不携带旧 `chat_id` 或 `message_id`。连接器使用飞书 [发送消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/create)，通过 `receive_id_type=open_id` 发送；机器人仍须具备飞书应用权限和目标用户可用范围。

工具返回 `deliveryStatus=queued` 仅表示队列已受理，不代表飞书送达。后续成功、重试和死信沿用 `ConnectorDelivery`；重试保持相同收件人及 uuid。每次主动调用产生独立消息 ID，当前回合回复保留原有命令幂等规则。

若目录为空，检查 Agent/渠道绑定、启用状态、App ID/Secret 和白名单；不要通过补发一条入站消息解决配置问题。语音/图片的当前会话投影及调试接口仍使用原有回信路由，本功能仅修改 `send_message` 文本主动发送。
