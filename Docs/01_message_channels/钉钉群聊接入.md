# 钉钉群聊接入

## 在群里使用

在本企业内部应用的机器人配置中启用 Stream 模式，发布机器人，在企业内部群添加鲸鲸。使用钉钉的成员选择器 @鲸鲸。

| 群消息示例 | 预期结果 |
|---|---|
| 如何提交需求？ | 返回提交格式 |
| 新建项目之后，如何从报告中导入数据？ | 鲸鲸查阅公开的界面证据后说明导入步骤，可继续追问 |
| WPF 版更改检查规则包后，为何上次的结果消失了？ | 使用经审阅的代码证据解释界面行为 |
| 登记一个软件BUG，在小屏幕的显示屏上，软件显示错位。 | 鲸鲸调用本机登记工具，保存后返回编号 |
| 功能需求：希望支持导出前预览。 | 返回另一登记编号 |

反馈描述用一行，最多 400 字符。请先去掉实际项目资料、联系方式、链接和凭据。可以用“登记一个软件 BUG，……”或“功能需求：……”等措辞明确提交。“如何反馈 BUG？”是咨询。编号可在本机台账查到。

## 宿主与权限

宿主读取 DataRoot 下的 `config/dingtalk-group.json`。设置包括 `enabled`、`agentId`、`clientId`、指向仓库外 ACL 受限文件的 `credentialFile`，以及可选的已审阅源码根 `reviewedSourceRoot`。凭据文件字段为 `clientId` 和 `clientSecret`。给实例 AGENTS.md 安装 [群聊规则段](../../Source/PuddingDingTalk/Jingjing.group.zh-CN.md)，保留原有内容。通过 Guardian 启动带有钉钉组件的 Core。

| 能力 | 钉钉配置或权限点 | 本阶段用途 |
|---|---|---|
| 接收群内 @ 并回复当前消息 | 企业机器人能力、Stream 模式、已发布可见范围、加入目标群；回复走回调的临时 sessionWebhook | 必需 |
| 按群会话 ID 主动发消息 | 企业内机器人发送消息权限 `qyapi_robot_sendmsg` | 会话内回复无需主动群发 |
| 查询指定发言人的企业成员资料和返回的角色列表 | `qyapi_get_member`，并授予对应的通讯录可见范围 | 只读成员查询使用 |
| 列出企业角色目录 | `qyapi_get_department_list`，接口 `topapi/role/list` | 按需开通 |
| 查询场景群信息、区分群主和群管理员 | `qyapi_chat_read`，接口 `topapi/im/chat/scenegroup/get`，受该接口的群类型和范围限制 | 按需开通 |

认证 Stream 上的群文本回调必须明确提及机器人，机器人代码须匹配绑定应用，发言人企业须与机器人企业相同，同时须具备员工 ID、会话 ID、消息 ID 和有效的平台时间。群成员范围依靠钉钉企业内部机器人的发布设置；这些回调字段只核验发言人归属，并不枚举群成员名单。当前所有通过来源检查的发言人均绑定为 Pudding guest。组织角色、群主或正文中的自报身份均不授予 Pudding 权限。

群消息携带企业、群、员工 ID、平台发送时间、宿主接收时间和 guest 身份，交给绑定实例的 `RuntimeAgentDispatcher` 和 `AgentExecutionService`。鲸鲸使用实例当前配置的模型，在正常的工具调用循环中回答。群聊上下文使用实例 AGENTS.md 的公开段，同一群同一发言人可在 15 分钟内追问，最多携带最近两轮。短期上下文在进程重启或渠道重新绑定后清空。此渠道尚无飞书工作台的持久消息时间线。

宿主给本轮工具调用绑定企业回调中的身份以及当前 Agent、会话。允许的工具为 `mpcal_public_help`（经审阅的公开用法）与 `mpcal_record_feedback`（把当前原始消息的明确反馈登记到本机）。反馈类别、保存目录与回执均由宿主确定。公开证据按 MPCAL 源文件摘要匹配，文件变化后相应证据自动停用。私聊历史、私有记忆、通用文件工具、Shell、DWS 和工作区搜索均未接入群聊。

消息正文最多 4096 UTF-8 字节。每分钟每人最多 4 条、每群 12 条、实例 24 条。收到回复不确定的发送尝试不自动重发。宿主在 `channels/dingtalk-group/receipts.db` 保存来源元数据、时间和发送状态，不保存原始群聊正文或 webhook。显式反馈独立存放在 `channels/dingtalk-group/feedback/<摘要>.md`。每次登记可以通过编号前缀找到对应文件。

## 分阶段接入

1. 验收公开问答与本机反馈登记。分别在群里询问提交方式并提交一条 BUG 和一条需求，核对两个编号与实际 Markdown。进程健康和 Stream 握手不能证明群回复成功。
2. 按实际反馈补充公开代码证据和问答范围。成员资料查询通过后台应用身份进行，若未来需要 Pudding 授权，须另建服务端身份绑定。
3. 用户授权的 DWS 文档和 AI 表格分析作为私有工作流，单独限定资源及读写权限。群消息处理器不调用用户的 CLI。

钉钉操作见[内部群机器人说明](https://opensource.dingtalk.com/developerpedia/docs/explore/tutorials/stream/bot/go/test-bot/)和[官方 Stream SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-python)。CLI 安装、Skill 和交互登录见 [DWS README](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli#installation)。
