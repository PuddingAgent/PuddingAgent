# 父任务预算与模型算子 API 契约与接入

此合同开放两个可调用的场景：文本分类 `text.classification`、交付证据评审 `delivery.acceptance`。与[确定性技能评分](确定性算子公共API-契约与接入-2026-11-05.md)并存。调用方拿类型化 API，不管理密钥、HTTP、模型限流或子代理上下文；授权、父任务身份和预算由宿主绑定。

## 组件与依赖

| 组件 / 权威文件 | 职责 |
|---|---|
| `Source/PuddingExecutionResources.Contracts/ExecutionResources.cs` | 宿主执行身份、父子预算、取消作用域、冻结模型描述、预留与用量回执；BCL 端口 |
| `Source/PuddingExecutionResources/ExecutionResourceScope.cs` | 树级锁原子预留所有祖先额度，实际/预留/未知账目分离 |
| `Source/PuddingExecutionResources/ModelResourcePool.cs` | 每模型并发槽、单次派发、超时和迟到请求排空 |
| `Source/PuddingModelEvaluation/ModelEvaluationService.cs` | 分类/验收输入和输出语义；只引用公开 DTO 与资源端口 |
| `Source/Pudding.Api.Contracts/ModelEvaluation.cs` | 类型化请求、弃权/降级、逐项证据与模型用量来源 |
| `Source/Pudding.Api.Sdk/ModelEvaluationsClient.cs` | 上层消费外观，接收已绑定的 `IModelEvaluationApi` |
| `Source/Pudding.ToolPlugins.AgentSdk/PluginModelEvaluations.cs` | `Context.ModelEvaluations()`；当前调用的 IPC 代理和回执校验 |
| `Source/PuddingRuntime/Operators/PublicApi/ConfiguredExecutionModelBinder.cs` | 只在 Runtime 解析当前执行模型、凭据、单次网关和计费记录 |
| `Source/PuddingRuntime/Operators/PublicApi/ModelEvaluationApiFactory.cs` | 可信执行上下文、父资源和授权绑定；租约退出即取消 |

两个新组件的 csproj 以项目引用白名单、包与框架限制拒绝反向依赖。Core 只引用资源端口；实现由 Runtime 组合。`ToolInvocationRequest`、`ToolExecutionContext` 的 `ExecutionResources` 为 `[JsonIgnore]` 的宿主对象，不是可从请求体恢复的资源凭证。

现有安全分类器包含审批场景、内部模型调用和重试语义，不能直接作为通用文本分类器公开。本次增加受预算约束的通用分类/评审组件，复用既有网关、凭据服务、`ProviderRateLimiter` 和 `ILlmGatewayUsageRecorder`；不改审批分类器、注册表或原技能评分公式。

## 父任务预算与结算

`ExecutionUsageBudgetTracker` 的资源根归属一次 Runtime dispatch，包含 workspace、执行 Agent、session、Run 身份。主调用/旧委派用量计入同一本根账；模型算子通过子作用域进行调用前预留。重建插件调用租约、重载插件不会重建这份父账。

| 轴 | 规则 |
|---|---|
| 输入 | 每次请求容量；累计输入保留用于诊断，不能累计扣减输入窗口 |
| 输出 | 已结算 + 预留 + 未知不能超过父额度；请求输出上限发送给网关 |
| 成本 | 按冻结模型价格预留最坏输入容量和请求输出；按服务商实际 usage 结算 |
| 调用次数 | 准入即消耗一次，取消排队不返还次数；避免反复探测制造无限工作 |
| 并发 | 所有祖先及同模型的并发限制同时生效；上层不能用另一个子作用域绕过 |
| 截止时间 | 子截止时间取父与请求的较早者，外部取消向下传播 |

资源合同的 `null` 表示未设此轴，`0` 表示耗尽。Runtime 保留旧 `ExecutionUsageBudget` 启用标志的语义，不把派生零余额当无限预算。

每次 dispatch 的辅助模型额度为 **8 次 / 8192 输出 token / 同时 2 个请求**，仍受父任务更小额度约束。普通聊天也有这份有限辅助额度。单请求输出 1～2048、超时 1～60000ms；默认 1024 / 15000ms。请求正文序列化不超过 16KiB，并有分类项、验收项和证据长度限制。模型输入容量暂取配置与 8192 的较小值，并叠加父输入上限；UTF-8 字节预检是保守启发，不宣称等同服务商 tokenizer。实际 usage 超过预留时保留实际值并关闭后续准入。

辅助资源根的寿命上限为 24 小时；父任务更早截止时提前结束。该上限只关闭辅助模型准入，不修改既有主循环的执行时限配置。

派发状态机：

1. 校验请求、授权、父身份和冻结模型；预留所有祖先额度。
2. 等模型槽和既有服务商限流槽，尚未派发时取消可返还 token/成本预留。
3. 发送前将租约标为 dispatched，恰好允许一次，不做隐式重试。
4. 收到完整 usage：按本次模型价格一次结算，返还差额；没有 usage 或派发后失败：保留未知额度并阻止后续模型准入。
5. 服务商违反容量/输出上限：记真实超量并返回 `budget.provider_overrun`，不能篡改账目使预算看似满足。

金额单位为配置价格单位 `configured-price-unit`，不擅自假定人民币或美元、也不做货币换算。当前仅接受平价配置；时间窗口价格返回 `model.pricing_unsupported`，不按错误的基础价预留。输入/输出价格全零无法区分缺配置与明确免费，返回 `model.pricing_unavailable`；明确免费报价需后续独立配置合同。

## 取消、卸载与资源寿命

父取消、调用方取消、插件执行租约撤销或超时都会停止等待并传播给模型。取消不证明服务商没有执行，也不保证远端停止计费。

如果 provider 忽略取消，模型池保留并发槽和父预算预留，直到真实 Task 退出。后台排空只记账，不发布迟到成功。返回未知后即使迟到 usage 可结算，父账仍保留不确定标记，避免调用方盲重试。模型实现必须异步返回 Task；不承诺中止同步卡死代码或无限期不退出的第三方实现。

Worker 卸载确认的是 Worker 和宿主回调已经退出；已移交模型池的迟到请求仍可占用资源，不把 `Unloaded` 等同于远端请求已终止。这与插件 Manager 对仍未排空的回调返回 `StopFailed` 的原合同并存。

模型槽按 provider/model 键共享，并与主 Agent 的 `ProviderRateLimiter` 同时约束。池最多登记 128 个模型键；同键并发配置改变时返回 `model.configuration_changed`，需要排空并重建池，不能用新配置创建旁路并发槽。

## 上层与插件消费

可信宿主从当前执行上下文签发 `ModelEvaluationApiFactory.Open(...)`，将得到的 `IModelEvaluationApi` 或 `ModelEvaluationsClient` 交给上层；宿主负责释放租约。普通调用方不创建 `ExecutionResourceScope`、不提供 parent Run、不选择任意模型或密钥。

插件清单须为 `coreApi: "1.3"`，按需申请：

```json
{
  "coreApi": "1.3",
  "requestedCapabilities": [
    "operators.model.list",
    "operators.text.classify",
    "operators.delivery.review"
  ]
}
```

以上是完整 v2 清单中的字段片段；原 `plugin_load` 授权流程仍生效。没有活跃父资源会返回 `execution.parent_required`，没有明确冻结模型路由会返回 `model.not_configured`。模型能力是单独授权项；工具环境 effect 为 `none` 也不代表模型没有计费。

```csharp
var api = Context.ModelEvaluations();
var category = await api.ClassifyAsync(
    new("请修复登录失败", [new("work", "需要执行的任务"), new("chat", "普通交流")]),
    new("classify-1", MaxOutputTokens: 256), ct);

var review = await api.ReviewAsync(
    new("修复登录", [new("test", "相关测试通过")],
        [new("log", "这里放实际采集的测试证据")]),
    new("review-1", MaxOutputTokens: 1024), ct);
```

`CallId` 用于关联，**不是幂等键**。同 ID 再调用仍会消耗新的额度；SDK 不自动重试。本切片没有 HTTP 模型 API、跨会话回执存储或隐式结果缓存。

分类 `Valid` 必须选择已声明的标签；无法选择为 `Abstain/null`。验收逐项引用已提供的 evidence ID：全部 supported 才 accept，任一 not_supported 则 reject，其余 abstain；缺项、未知证据、矛盾 verdict、非法 JSON 或截断结果为 Degraded/Abstain。SDK 同样拒绝缺少支持项的“通过”回执。

每份结果带作用域、父 Run、调用/租约 ID、模型配置版本、指令版本、输入与响应指纹、实际 token/成本；置信度标为 `ModelSelfReported`。证据来源为 `caller-supplied`，评审不证明现场事实，也不等于 Goal 验收完成。普通聊天是否转为任务、是否继续下一轮，仍由上层策略决定，不能仅凭一次模型标签改写控制流。

## 尚未覆盖的边界

- 旧主模型/子代理仍以返回后用量入账，新租约消费会扣减其剩余额度，但未把所有旧调用改成调用前硬预留。不能宣称全系统无超支，也不能将本 dispatch 辅助次数限制当作持久 Goal 总次数限制。
- 资源账在内存中，进程退出后的远端费用、崩溃恢复对账和跨进程额度一致性未实现。
- 首版复用父执行已选择模型；没有自动挑选小模型、模型故障切换或重试。
- 既有审批器、验收阈值、Goal 终态、算子注册/替换及插件提交新 Work 的权限均未开放。
- 自动触发验收器的 Hook 和“继续/结束”控制策略仍需后续切片；这里提供可调用的有界能力与证据评审合同。
