# DS-A2-01 九个组件反向引用探针

**负责人为 DeepSeek，可与 DS-I1-04B 同时领取。** A1 清单指出九个组件通过工程引用被构建，现有反向引用实测只覆盖三个。本单补九个**实现工程**的 A2 证据，适用于后续改动后复跑。是否加入 slnx 由各组件的 S5 接入单决定。

## 文件和命令合同

可写文件仅为 `TestScripts/test-foundation-component-boundaries.ps1`（新增）、`Docs/14_reports/2026-11-07-DS-A2-01-组件编译边界探针.md` 和 `Docs/00_changelog/2026Year/11/2026-11-07-DS-A2-01-组件编译边界探针.md`。所有工程、Directory.Build.*、现有脚本和解决方案均只读。

脚本使用 PowerShell 7。从 `$PSScriptRoot` 定位仓库，可传 `-RunId <唯一标识>`；缺省生成唯一值，标识限字母、数字、连字符、下划线，拒绝复用目录。输出在 `.work/ds-a2-01/<RunId>/`，生成每工程的 baseline/negative 日志及 `matrix.json`。完整矩阵成功返回 0，漏项、意外通过或错误原因不符返回非零。无需 restore 或启动产品。

| 工程（位于 Source 下的同名目录） | 显式执行目标 | 注入后的预期诊断文本 |
|---|---|---|
| PuddingAgents | EnforceAgentsBoundary | Agents may only reference its ports and the public API contracts. |
| PuddingContext | EnforceContextBoundary | Context may only reference its ports. |
| PuddingTools | EnforceToolFacadeBoundary | Tool facade may only reference its ports. |
| PuddingMcp | EnforceMcpBoundary | MCP may only reference its ports. |
| PuddingWorkspace | EnforceWorkspaceBoundary | Workspace may only reference its ports. |
| PuddingEventing | EnforceEventingBoundary | Eventing may only reference its ports and the public API contracts. |
| PuddingInvocationPipeline | EnforceInvocationPipelineBoundary | Invocation pipeline may only reference its ports. |
| PuddingAuthorization | EnforceAuthorizationBoundary | Authorization may only reference its ports. |
| PuddingModels | EnforceModelsBoundary | Models may only reference its ports and the public API contracts. |

## 实施步骤

1. 将表中九个项目、目标和预期诊断固定在新脚本内，核对每个 csproj 的目标挂在 `BeforeTargets="ResolveProjectReferences"`。缺工程或目标应记录失败。
2. 每个项目先运行 `dotnet msbuild <csproj> -nologo -t:<目标>`。记录 exit 0。随后只在本次运行目录生成 MSBuild targets，给被测工程注入真实 `Source/PuddingRuntime/PuddingRuntime.csproj` 的 ProjectReference。使用 `-p:CustomAfterMicrosoftCommonTargets=<targets绝对路径>` 运行同一目标；可参考此前本机的 `.work/r26-review/20261106/forbidden.targets`，脚本必须自行生成所需文件。
3. 负例必须同时满足退出非零、该项目诊断行出现表内精确原因。缺 SDK、项目未找到、循环还原、restore 失败或别的工程报错均不能算成功。产物应记录工程、target、预期诊断、两次原始退出码、命中的诊断行和日志相对路径。
4. 正反两组均跑九项。用本次新输出逐行核对，独立复核用另一个 RunId 重跑。这里显式执行的是构建挂钩目标，报告标为“MSBuild 目标拒绝引用”，工程的完整构建、包约束以及其他组件仍单列。

验证命令为 `pwsh -NoProfile -File TestScripts/test-foundation-component-boundaries.ps1 -RunId <本次标识>`。在隔离副本把一项注入改成合法依赖（或取消注入），外层脚本必须因该负例意外通过而退出非零。相同 RunId 再调用须拒绝覆盖已有证据。本单不修改任何组件，不能通过编辑工程来让探针变绿。
