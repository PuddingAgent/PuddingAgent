# PA-01 消费者迁移边界设计

**裁定入口（2026-11-06）**：[S5 架构裁定与接线门禁](Agent组件化S5架构裁定与接线门禁-2026-11-06.md)确定 P2 为验收目标、P1 仅作短期 attempt 对账。后文轮首/轮末预留与“关闭开关回到 tracker”是原提案，不作为实施许可；Enforced 根不得降级绕过持久预算，所有实际模型 attempt 必须走统一边界。原“等待选择”已解除，产品部署授权未变化。

状态：**等待架构师选择迁移范围**。持久账本（`ExecutionBudgetStore`）、启动调和、只读 API、预算顺序器（`ReviewBudgetSequencer`）已落地并通过测试；执行链仍使用进程内 `ExecutionUsageBudgetTracker`。

## 1 现状

- `ExecutionUsageBudgetTracker`（Runtime，同步、进程内）在每轮：`EvaluateBeforeRound` → 调用模型/工具 → `RecordInvocationUsage` → `CreateRemainingBudget`；`AgentExecutionService.Buffered.cs` 多处直接使用。
- `ExecutionRunCoordinator`（Platform）在提交/派发阶段解析 `EffectiveExecutionBudget`/`ExecutionUsageBudget`，无持久账本调用。
- 持久账本语义已覆盖：祖先原子预留、取消线性化、owner fencing、幂等结算、Unknown 不退款、重启调和。

## 2 三种迁移边界

| 方案 | 行为改变 | 影响面 | 风险 |
|---|---|---|---|
| **P1 影子记账（推荐第一步）** | 执行链仍由 tracker 决定限额；每轮把“预留/结算/未知”以确定性 OperationId 写入持久账本，仅账目/重启对账生效 | Runtime 增加异步调用点；Platform 账本已有；不改限额判定 | 双重记账口径需对齐；异步调用不能 `.Result/.Wait()`；失败时以 Unknown 入账 |
| **P2 账本限额闸门** | 派发前以持久账本 `Reserve` 结果决定是否放行；进程内 tracker 保留用于单轮内 token/工具计数 | 执行链判定点改为异步；取消/并发语义需重新映射到 owner epoch | 异步改造进入热路径；取消与派发竞争需用 ledger 线性化点 |
| **P3 完整替换** | 删除 tracker 限额逻辑，全部走持久账本（含工具/子代理/算子） | Runtime 大范围改造 + 既有测试迁移 | 最大回归面；任务书禁止 `.Result/.Wait()`，但热路径异步化影响性能与测试 |

**推荐：P1 → P2 分阶段；P3 另立任务。** 每阶段独立开关与回滚。

## 3 P1 具体边界（若选择）

- 新增 Runtime 端口 `IDurableUsageJournal`（BCL/Contracts），实现放在 Host/Platform 适配层，内部调用 `IExecutionBudgetLedger`。
- 每轮：轮首 `ReserveAsync`（operationId = `run:{runId}:epoch:{epoch}:iter:{n}:reserve`），轮末 `SettleAsync`（真实 usage；未知则 `MarkUnknown`）。
- 开关：`ExecutionBudget.DurableJournal=true|false`（默认 false，保持现状）。
- 约束：异步调用只在轮边界（非每次 token），避免热路径改造；失败只记录，不回滚执行。
- 测试：既有 `ExecutionUsageBudgetTrackerTests` 不变；新增“影子账目与 tracker 一致/未知保留/重启后账目不清零”集成测试。

## 4 P2 具体边界（若选择）

- 派发前：`ReserveAsync` 以根/子账户限额为闸门；返回 permit 携带 cancellation revision/owner epoch。
- 取消：`CancelAsync` 记录 cancellation revision；已派发请求保留占用并排空（与任务书 08A 用例一致）。
- 结算：provider 返回后 `SettleAsync`；超时/失联 `MarkUnknownAsync`。
- 失败语义：`budget.exhausted/concurrency/cancelled/owner_stale` 映射为现有错误码，不新增行为。
- 回滚：开关关闭即回到 tracker 判定；已写入的账目保留（Unknown 不自动退款），启动调和只处理未结算。

## 5 影响文件与测试（预估）

- Runtime：`ExecutionUsageBudgetTracker.cs`、`AgentExecutionService.Buffered.cs`（轮首/轮末/派发点）、`ITurnExecutor.cs`（预算 DTO 不变）。
- Platform：`ExecutionRunCoordinator.cs`（派发确认/取消 revision）、Host DI（journal 实现与开关）。
- 测试：`ExecutionUsageBudgetTrackerTests`、`LlmInvocationServiceCancellationTests`、子代理/模型算子回归、`PuddingPlatformTests` 预算切片；新增逐断点重启测试。
- 风险：热路径异步化、双重计费、取消竞态、Unknown 与超时区分；任务书明确禁止 `.Result/.Wait()`。

## 6 需要架构师确认

1. 选择 P1（影子记账）先行，还是直接 P2/P3？
2. 开关默认值与发布策略（默认关闭、按 Agent/Workspace 开启？）。
3. 轮首预留的额度来源：根 `EffectiveExecutionBudget` 还是模型报价（`QuoteWindowAdjuster`）+ 工具上限？
4. P1 影子账目失败时是否阻断执行（建议不阻断，仅记录 Unknown）。

## 7 不做的部分

在决策前不改 `ExecutionUsageBudgetTracker`/`AgentExecutionService`/`ExecutionRunCoordinator` 的行为；持久账本继续只服务只读 API、调和器、评审预算顺序器。
