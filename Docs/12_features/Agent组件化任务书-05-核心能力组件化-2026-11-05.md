# PA-05：授权、工具、MCP、上下文、核心循环与工作区组件化

本任务是一组**逐项放行的子任务**，不是一次迁移整个 Runtime。遵守[总则](Agent组件化任务书-总则与依赖-2026-11-05.md)与[组件化交付规程](../10_conventions/组件化交付规程.md)，依赖 01 的资源端口、02 的任务身份。基础设施组件与声明扩展端口是软件功能插件化及 Goal 的前置；03/04 可以先测纯策略，但实际使用的端口必须在 Goal 完整接入前完成真实适配，不能从旧内部服务拼出旁路。无需等待本任务所有可选能力齐备。

## 1 目标与交付判据

插件和其他模块只面向类型化的 capability API/工厂/句柄；不知道工具在哪个程序集、配置在哪个文件、MCP 怎样连接、上下文怎样压缩。领域实现能独立测试，依赖方向由编译门禁保证。

每个领域按需求声明事件、策略/provider slot 或有界 Hook，组件不引用具体插件。插件可新增非工具功能、选择合法策略或贡献上下文，调用能力与注册/替换权限分离。第一次建立扩展点属于所属组件的明确改动；此后新增同合同插件不得要求在其他模块增加专用分支。禁止通用反射、任意 DI 覆盖和绕过业务写入者。

每个子任务分两次验收：**先保持行为的抽取，再新增公开外观**。把原类包在 Service 后面仅算 FacadeConnected；算法仍在 Runtime、独立测试必须加载 Host，不能算组件完成。不顺手改 prompt、压缩算法、工具错误码、授权默认值或 MCP 协议版本。

## 3 公共操作合同

| 能力 | 拟公开方法 | 关键语义 |
|---|---|---|
| Authorization | `EvaluateAsync(AuthorizationRequest)`、`RequestApprovalAsync(ApprovalRequest)`、`GetApprovalAsync(ApprovalRef)` | 插件能查询自己拟执行动作是否允许、发起审批，不能自行批准；判定携带策略版本/原因/有效期 |
| Tools | `ListAsync(ToolQuery)`、`InvokeAsync(ToolCall)` | 完整 schema、能力/风险、catalog revision、分页完整性；执行统一走授权/预算/审计，不能绕过现有入口 |
| MCP | `ListServersAsync`、`AcquireSessionAsync`、`ListToolsAsync` | 不暴露 token/环境变量/原始客户端；调用 MCP 工具仍归一到 ToolDispatcher，不能多一条无审批路径 |
| Context | `GetSummaryAsync(ContextRef)`、`ProposeContributionAsync(ContextContribution)` | 查询预算/来源摘要与提出贡献；不能直接替换 system/user 消息或篡改 canonical 历史 |
| Kernel（内部） | `RunTurnAsync(BoundTurnRequest, IExecutionEventSink, ct)` | 一个受权已受理 Turn；buffered/streaming 共享状态推进；不负责再受理同一用户消息 |
| Workspace | `ListAsync`、`GetEnvironmentAsync`、`ReadFileAsync`、`WriteFileAsync` | 只在受权工作区内；写入带 expected revision/hash，原子落盘回执；不提供任意进程级变量修改 |

这些方法是接口设计要求，非现有可调用方法。DTO 必须有稳定 ID、Revision、Availability/Completeness、typed error。目录缺权限与“确实没有对象”分开；支持 List 不意味着能 Execute。需返回的 schema 不含凭据，错误不能泄漏服务端密钥路径或堆栈。

ContextContribution 至少有来源、目标 Turn、内容 hash、优先级、寿命、预算上限；宿主标为外部/工具数据，不能伪造用户或系统指令。原 canonical 当前用户围栏、历史顺序与失败诊断不得因公开 API 被弱化。提议被拒绝给原因，不静默把内容塞进上下文。

工具失败保留可诊断 stdout/stderr/证据引用；不要借抽取更改截断策略。catalog generation 冻结后执行前复核，卸载的旧工具不能按同名新工具重新解析。MCP 列表/调用超时不能把 session 标成功；停止等待后由连接管理器处理真实排空。

Workspace 文件操作处理规范化路径、越界 `..`、junction/symlink 及校验后替换的竞态；拒绝工作区外目标，校验不足的操作明确 unsupported。不得公开 `D:\data` 全局目录作为插件 workspace。环境快照返回受权逻辑信息，不 dump 环境变量、LLM 配置或控制令牌。

## 4 编译期依赖矩阵

| 项目 | 可引用 | 禁止 |
|---|---|---|
| `Pudding.Api.Contracts`、各领域 `.Contracts` | BCL；领域间共享 ID 经主代理指定的最小端口 | PuddingCore、Runtime、Platform、Host、Desktop、EF、ASP.NET |
| Authorization / Context / Workspace 实现 | 自己端口及明确白名单的公共 DTO/资源端口 | 调用方实现、全局 ServiceLocator、通过反射装载宿主 |
| Tools / MCP 实现 | 自己端口、授权/资源端口；MCP 实现必要 SDK 单独列白名单 | 反向依赖 Runtime/Platform；借公共 contract 引入 MCP 重依赖 |
| ExecutionKernel | 自己及 Context/Tools/Authorization/资源端口 | 具体 provider、具体 MCP、Host/数据库/桌面 SDK |
| Platform/Runtime adapters | 独立组件及原有宿主实现 | 作为组件被组件反向引用 |

每个新项目内用 MSBuild Target 在 ResolveProjectReferences 前拒绝白名单外 ProjectReference/PackageReference/FrameworkReference；公共契约保持 BCL-only。仅省略引用不够，负例主动加反向引用必须构建失败。编译门禁不能防止恶意反射/进程访问，不把架构边界误称安全沙箱。

## 5 每个子任务固定实施步骤

1. 按当前调用者定位算法与边缘 I/O，画出最短调用链；列明保留在适配侧的文件及原因。
2. 冻结领域端口，创建独立工程与 fake，不改 Host。保留原行为的输入输出轨迹作为特征测试。
3. 迁移单一职责代码，原入口变薄适配；不得同时更改策略默认值。独立测试不加载 Host/Platform/Runtime。
4. 跑编译反向引用负例、错误/取消/竞态测试；用 mutation 证明真实调用者经过新组件，而非只有废 helper 的单测在绿。
5. S5 才登记 DI/解决方案/映射；核对所有原调用点，删除已无调用且无独立职责的旧实现及只保护其旧语义的测试，不保留第二写入路径。
6. 独立记录迁移与行为扩展的验收，不把“facade 已能调用”作为全部组件完成。

必测：系统 Deny 不被插件 Allow 覆盖；审批未决零工具调用；批准对应调用的参数 hash/策略版本，参数改动必须重审；MCP 重连/卸载不串 generation；Context 贡献不能越过当前用户围栏；streaming/buffered 相同工具轨迹、取消与用量归属；文件越界/链接替换被拒绝；工具失败诊断保留。

每个测试工程按总则独立构建，S5 才跑相应既有 Runtime/Platform 回归。若历史测试依赖重实现，保留作为集成测试，不为追求小工程把断言删掉。05E 属高风险核心，主代理亲自实施，不委派状态机迁移。

## 6 DS-PA05-A：能力目录消费示例

状态 `blocked-on-contract`，仅消费主代理冻结的 `ICapabilityCatalogApi.ListAsync(CapabilityQuery, ct)` 与 DTO。允许新建：

```text
Samples/CapabilityCatalogClient/CapabilityCatalogClient.csproj
Samples/CapabilityCatalogClient/Program.cs
Samples/CapabilityCatalogClient/CatalogDemo.cs
Samples/CapabilityCatalogClient/code_map.md
Tests/CapabilityCatalogClient.Tests/CapabilityCatalogClient.Tests.csproj
Tests/CapabilityCatalogClient.Tests/CatalogDemoTests.cs
Tests/CapabilityCatalogClient.Tests/code_map.md
```

固定 `CatalogDemo.RunAsync(string[] args, ICapabilityCatalogApi api, TextWriter output, TextWriter error, CancellationToken ct = default)`：仅 `list <kind> [cursor]`，kind 限主代理发布的 `tool/mcp/context`；单次查询输出原 JSON，保留 Revision/Completeness/Capability 状态，不把目录项当可执行授权。参数错 exit 2、类型化错误 code/exit 1、调用方取消 130、正常 partial/空页 exit 0。Program 离线提示 exit 2。

测试 partial 空页不可输出“没有能力”、Forbidden 不伪装空列表、旧 generation 保留、不自动翻页、不调用工具。sample 只引用 SDK，test 仅引用 sample；按总则构建白名单测试工程，输出 `.work/ds-pa05-a/<run>/`。任何需要执行 MCP、加载插件或改 catalog 实现的要求均超范围，停止交回主代理。
