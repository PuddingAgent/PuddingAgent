# 交互面板标注坐标模型

## 问题（审阅 P1）

面板缩放后标记会漂移。

## 根因

`PanelCanvasDocument.cs` 的标注层用**当前显示尺寸的像素坐标**记录图元：

```js
function local(e) {
  var b = layer.getBoundingClientRect();
  return { x: e.clientX - b.left, y: e.clientY - b.top };
}
```

`local()` 返回的是**相对标注层矩形**的像素位移。于是：

1. 在 800px 宽的面板上拖一个框，记下 `{x1: 320, x2: 680}`
2. 面板缩放到 400px 宽
3. 已存的 320/680 仍是**旧像素**，但渲染时按新矩形铺开 ⇒ 框跑到别处
4. 再画一个新框，用的是新像素 ⇒ **新旧图元根本不在同一坐标系**

导出侧 `compose()` 用 `sx = outW / rect.width` 换算，**只对当前这一帧成立**；
混合了不同历史尺寸的图元之后，同一个 `sx` 无法同时正确。

## 目标模型

**存归一化，渲染时换算。** 与模型侧 `<point>` / `<bbox>` 的 0–999 同域。

| 环节 | 表示 |
|---|---|
存储（`items`） | 0–999 整数（`round(px / extent * 1000)`，clamp 到 0..999） |
渲染 | `px = norm / 999 * currentExtent` |
导出（`take()` / `compose()`） | 直接用归一化值，不再按帧换算 |

`PanelAnnotation.cs:127` 已经有这个换算函数，说明**契约层本来就是归一化的** ——
是标注层自己多存了一套像素，两条表示并存才出的事。

## legacy 数据迁移：不猜

已存在的图元是像素值，而**当时的面板矩形尺寸没有被记录下来**，
所以无法可靠还原成归一化值。

处理方式：

- 图元带 `coords: 'px' | 'norm'` 标记
- 读到 `px` 且**没有**同时记录的 `rect` 时，视为无法迁移：**按当前帧一次性归一化并立即回写**，
  并在状态栏提示「已按当前尺寸校准 N 个旧标记」
- 不尝试用 `naturalWidth` 反推 —— 显示尺寸与原始像素的对应关系取决于 `object-fit` 与容器策略，
  反推出来的是猜测，而猜错的后果是标记落在错误位置却看起来"像对的"

宁可让用户看到一次校准提示，也不要静默算错。

## 渲染边界（必须一起处理，否则修完还会漂）

1. **滚动**：`local()` 用 `clientX - rect.left`，滚动时 `rect` 会变但相对量正确 —— 保持相对计算即可
2. **`object-fit`**：`<img>` 若用 `contain`，图片实际显示区域小于元素矩形，需要按 `naturalWidth/naturalHeight`
   与矩形比例算**实际绘制区**，不能直接用元素矩形
3. **缩放中绘制**：拖拽过程中缩放（触控板捏合）会让 `origin` 与 `end` 落在不同尺度上。
   处理：拖拽开始时**冻结**当时的 extent，整个手势内都用它换算，手势结束再统一写入
4. **多图**：目前标注只认最大的那张图（见设计方案 T3），归一化坐标必须绑定**那张图**的 extent

## 不在本条范围内

审阅提到的另一半「新 revision 直接覆盖未保存笔迹」属于**冲突策略**，
不是坐标问题：`render_panel` 推新内容时，本地未提交的 `items` 该保留还是丢弃。
它需要与「界面状态保存与恢复进主线」一起定，本条不碰。

## 验收方式

必须有真实 Desktop 才能验（JS 行为无法用字符串断言覆盖）：

1. 800px 宽画一个框 → 缩到 400px → 框应落在同一相对位置
2. 再画一个框 → 两个框应共坐标系，`take()` 输出的 bbox 顺序合理
3. `compose()` 烧录图上的笔迹应与屏幕所见一致（缩放前后各验一次）
4. 旧格式（像素）图元 → 应出现一次校准提示，且校准后不再漂移
