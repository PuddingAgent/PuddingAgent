# A 阶段第二批施工任务书

| 施工单 | 负责人及领取条件 | 验收对象 |
|---|---|---|
| [DS-I1-04B](DS-I1-04B-既有子账户币种冲突任务书-2026-11-07.md) | DeepSeek，现在可发 | 既有子账户改币种的错误优先级，SQLite 回归与红例 |
| [DS-A2-01](DS-A2-01-九个组件反向引用探针任务书-2026-11-07.md) | DeepSeek，现在可发，可与 04B 并行 | 九个组件实现工程的正反 MSBuild 探针、精确诊断与可复跑脚本 |
| [CORE-I1-05](CORE-I1-05-单轮Work预算身份贯穿任务书-2026-11-07.md) | 主代理，现在可开始决策及真实入口核对 | 单轮 Work 的受理/租约/账户匹配、限额及报价来源、buffered 与 streaming 传播 |

04B 与 A2-01 的代码和报告均无共同写文件，两者均可独立复核。05 的合同工作可同步；核心单使用 04B 的既有账户错误语义，联合验收使用已复核的实现。A2-01 是独立编译门禁，不能把九个工程加入 slnx 当成本批的验收捷径。预算组交付后再排子代理/工具内算子/后台评审路径。两阶段放行规则见[总规划](基础设施服务生命周期与最小原型两阶段目标-2026-11-07.md)。

## 派发文本

- **给负责 04B 的 DeepSeek**：只执行 DS-I1-04B 文件白名单，先跑既有子账户改币种的红例，再按持久链和请求定义各自的职责修复并跑定向回归。交回测试名、退出码、数据库结果和精确文件差异，状态为 `ready-for-review`。
- **给负责 A2-01 的 DeepSeek**：只执行 DS-A2-01，按表逐个显式运行项目边界 target。交回脚本、九项原始正反退出码和预期诊断，以及一个能使脚本自身报错的对照。状态为 `ready-for-review`。

CORE 两单的文件范围、冻结影响和预算/取消/恢复语义由主代理维护。若叶单发现需要白名单外修改，提交最小复现和文件/函数依据给主代理，保留已有成果。

## 通用交接与独立验收

1. 从仓库根建立唯一 `.work/<task-id>/<run-id>/`，保存 HEAD、git status、白名单文件原始状态/哈希（含未跟踪文件），保护文件按三份现有清单检查。并行编辑的既有文件需区分所有者，禁止覆盖他方 WIP。
2. 只改对应施工单白名单。一次验收使用本次独立构建出来的 DLL/本次生成的矩阵。恢复竞争使用可控屏障和时钟；变异在隔离副本完成。所有离线测试使用临时配置/SQLite、脚本模型或内存 HTTP handler。部署、重启、真实模型、提交和推送均不属本批执行步骤。
3. 各工程单独构建，退出 0 后运行选定测试。适用于 04B 的可复制命令如下；05、06 的最终测试类在主代理决策记录中列出并分别对 Runtime/Platform/所涉及网关测试工程运行。同一工程不复用其他施工者的 artifacts。

```powershell
$run = Join-Path $PWD ('.work/ds-i1-04b/' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $run -ErrorAction Stop | Out-Null
dotnet build Source/PuddingPlatformTests/PuddingPlatformTests.csproj `
  --artifacts-path "$run/artifacts" -p:UseVSTest=false -p:CollectCoverage=false --nologo *> "$run/build.log"
if ($LASTEXITCODE -ne 0) { throw 'Build failed' }
$binary = Join-Path $run 'artifacts/bin/PuddingPlatformTests/debug/PuddingPlatformTests.dll'
$filter = 'ExecutionBudgetAccount|RuntimeBudgetAccountBinding|RuntimeBudgetBoundary|ExecutionBudgetStore|ModelAttemptBudgetGate|PlatformModelAttemptBudgetPort|BudgetBoundaryClosure'
dotnet $binary --no-ansi --no-progress --results-directory "$run/results" --filter $filter *> "$run/test.log"
if ($LASTEXITCODE -ne 0) { throw 'Tests failed' }
```

4. 开工与交付分别运行 `TestScripts/test-agent-configuration-contract-freeze.ps1`、`TestScripts/test-agent-work-contract-freeze.ps1`、`TestScripts/test-plugin-agent-api-contract-freeze.ps1`，保存每条退出码。叶单三项均需通过。核心单若需要演进受保护合同，先记录依赖影响与审定结果，保留旧基线和迁移证据。
5. 交回 Task ID、状态、实际修改及文件级 diff/哈希、红例与正常例、命令/退出码/实际运行数及跳过数、证据目录、剩余覆盖范围。对照用例名核实运行器确实执行。新报告/日志满足 front matter；相对开工基线无新增失效链接。
6. 复核者用新目录复跑并复核错误原因、事务/账目与实际调用次数或各工程诊断。只在结果可重复后签 `accepted`。主代理统一维护受影响的索引和综合报告。

## 本批证据的边界

四张单的独立复跑、额外红例与 B 阶段准入裁定见[第二批独立验收报告](../14_reports/2026-11-07-A阶段第二批独立验收与原型准入.md)。

A1 卡仍为输入。A2-01 验证九个实现工程的项目引用规则；A3/A4 的 Work/模型调用证据由 05/06 提供。工作区、授权的既有独立内核可复用，待补的是生产适配/消费。事件侧已有 `PluginEventDispatchWorker` 单批分发逻辑，后续施工应补持续驱动和真实插件 sink。本批结束时按各项实际结果更新门禁；B 原型与 Goal 的顺序沿用总规划。
