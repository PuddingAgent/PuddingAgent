# 浏览器自动化可靠性与渐进阅读设计方案

## 1. 目标、范围与设计依据

七项工具经两个窄端口覆盖十一项操作，连接 Bridge/gRPC 与 WebView2 的链路真实存在。本方案修复执行与授权语义，并在既有组件边界内增加阅读效率和视觉能力。状态为提案；文中的新类型、工具、默认值、指标和施工切片均是目标设计，不表示已实施或验收。

依据为[控制权审计](../09_audit/2026-10-08-浏览器控制权与准入闸门核验.md)、[工具面提案](../11_design/浏览器工具面渐进披露与证据化回执设计-2026-10-08.md)、[当前进度核查](../14_reports/浏览器工具与视觉能力进度核查-2026-10-08.md)与本次源码对照。点击导航、输入提交和滚动无位移等真实现象来自用户提交的实测记录；本次制定方案没有重新操作活实例。子代理工具注入、滚动失败的确切根因、只读调用期间版本变化的原因仍需专项验证。

产品仍是 WinUI Shell + Web UI + 独立 Core。浏览器驱动、控制权事实和 UI 投影属于 Desktop 能力层；Agent、委派、审批、视觉 Artifact 与模型路由属于 Core。没有外部 Chrome/Edge 接管、抖音专用实现或绕过人工验证的要求。

### 1.1 对已有提案的明确修订

| 原提案表达 | 本方案裁定 |
|---|---|
| 默认返回全量 HTML | 事实是默认 DOM + 可达性双摘要，HTML 默认关闭；问题是冗余、默认预算过大和没有分级 |
| click/press 等导航类动作统一等版本推进 | click/Enter 也可能只打开菜单或触发 SPA 更新；按显式后置条件与观测事实判定，不能按动作名推断导航 |
| 过期 ref 按 role/name/序号自动重解析 | 禁止自动重绑到另一个节点；稳定身份延长原节点引用寿命，真正过期时返回刷新提示 |
| 输出预算直接改遍历 MaxNodes=50、MaxDepth=6 | 输出限制与内部扫描限制分开，否则深层正文和结果列表仍会丢失 |
| ok=true 当且仅当后置断言通过 | 同时报告动作执行和业务后置条件；不能验证业务效果的已派发动作标为 unverified，超时/断连可能标为 unknown |
| value 是输入成功的唯一可靠回执 | value 是必需证据之一；React 重渲染后的稳定值、焦点、selection 和业务反馈也需按场景验证 |
| 不改准入，宿主改动前先报审 | 本方案涵盖三个 P0 准入/回执修复；实现按组件 S1–S5 门禁接入，本次仅设计，不新增额外审批流程 |

## 2. 架构与组件归属

保留七项工具入口和两个窄端口；snapshot/locate/interact 增强契约，截图通过新增窄视觉端口与 `browser_screenshot` 提供。按能力协商暴露已完成实现的入口，不能把运行期 NotSupported 桩声明成可用能力。

| 组件 | 目标职责与边界 |
|---|---|
| Pudding.Contracts | BCL-only 类型化控制权、页面授权、回执、视觉元数据与窄端口；无实现与模型依赖 |
| PuddingBrowser.Automation（拟新增） | 统一控制权状态机、授权与执行租约、回执判定、阅读格式化/分页等纯逻辑；仅引用 Pudding.Contracts，不引用 UI、Host、Runtime 或浏览器驱动 |
| PuddingBrowser.Abstractions | 驱动观察、稳定句柄、结构化读取、输入与截图契约；不引用调用方 |
| PuddingBrowser.WebView2 / WinUI | DOM 提取、节点身份、事件观察、真实输入及像素采集；两个适配器共享驱动源文件 |
| Pudding.DesktopService / DesktopSurface.Browser | 准入与调度，调用同一控制权端口；映射事实，不重新推断动作结果或制造版本 |
| PuddingDesktop / 已链接的无 UI 启动器代码 | 装配唯一状态实例、接管开关、生命周期和 UI 投影；不得迁入 Agent/业务逻辑 |
| PuddingHost / Runtime | 单次传输选择、可信调用身份、工具权限、Artifact 落库、图片输出、委派；不通过网页决定授权 |

依赖箭头定义为“调用方 → 被引用组件”。Contracts 保持零 ProjectReference；Automation 只允许 Contracts；Contracts 和 Abstractions 不引用 Automation；驱动/映射/工具作为消费方通过接口或显式映射使用，禁止形成环。新组件公开 normalized reading 输入模型，DOM 采集留驱动侧，不能为格式化引入 WinUI 或重型浏览器依赖。

新组件 S1–S4 期间仅增独立工程/测试，不登记解决方案、不修改消费方 csproj 或 Host。S5 才添加明确引用和装配，更新 Desktop 允许名单而不是取消编译期门禁。WpfArchive 的链接源若使用 Contracts/控制权端口，需同步其验证工程引用，不能只保证 WinUI 编译通过。归属存疑的平台逻辑留在驱动/消费方，并在该切片日志记原因。

## 3. P0：统一控制权与页面授权

### 3.1 唯一事实源与接管行为

Desktop 进程内只创建一个 `IBrowserAutomationAuthority` 实例。Bridge dispatcher、DesktopService、工作区控制器和 Shell 都读取它；现有三份可写 takeover/paused 字段收敛为投影。UI 发命令后以权威状态确认显示，不先显示已接管、再异步尝试更新闸门。

状态包含 paused、userTakeover、closed、controlEpoch、pageGrantEpoch 及当前租约。接管/暂停、授权撤销、关闭和 Core/连接世代改变均推进相应 epoch。接管不自动撤销阅读授权；恢复控制需显式恢复，不能复活接管前的队列或租约。

每个写请求在入队前及实际触碰页面前两次验证 authority、授权与 epoch；第二次验证和单个不可分输入步骤在同一 UI 调度边界内完成。逐字输入、拖拽、多步滚动在每个后续步骤复检并支持取消。接管完成确认后不允许新步骤开始；已经提交的点击/请求可能继续产生网页效果，回执如实标明已提交，不能承诺撤回已发出的网络请求。

`controlEpoch` 来自 Desktop；代理身份来自 Core 的可信执行上下文，不让模型填写 epoch 或 owner 来获得权限。断线后终止未执行队列；恢复连接需重新获取许可和状态。

### 3.2 trust、目标与调用者权限分离

context trust 只说明表面类别；page grant 才说明哪个调用者能阅读/操作哪个页面。`IsAgentTarget` 纳入准入，不能把整个 AgentAuthorized context 当作所有页面已获授权。

| 操作 | 页面授权要求 | 接管/暂停期间 |
|---|---|---|
| context/tab 元数据清单 | 可信 Agent 身份 + 允许管理的 context；非授权页面不泄露正文/敏感 URL | 允许有界元数据读取 |
| snapshot/locate/wait/screenshot | 明确 page grant 的 read 权限；普通页面仍不得注入工作台 | 允许授权范围内只读观察 |
| navigate/interact/坐标输入/脚本 | 明确 page grant 的 write 权限 + 当前控制租约 | 拒绝新副作用 |
| context create/close、tab new/close | 明确 management 授权；关闭已有页也要检查该页 grant | 拒绝副作用 |

默认只授权用户选定的目标页；切换“Agent 目标”撤销旧页的执行权并推进 grant epoch。导航留在同一授权 PageId；弹窗和新页面不因共享 context 自动获权。需要多页任务时，由用户配置的“允许本任务新建标签”授予管理权，新页登记完成后才签发该任务范围内 grant。页面激活、窗口焦点和 Agent 目标互不替代。

授予记录绑定 Desktop 实例/连接世代、context/page、可信 Agent/任务身份、read/write/manage 范围与可撤销 epoch。子代理只能取得父任务授权的子集；没有 grant 的显式 PageId 同样拒绝。Shell 工作台保持独立信任策略，不能作为普通 Agent 网页驱动目标。

### 3.3 页面与通道生命周期

新增统一生命周期端口，人工 UI 和两种传输均通过该端口创建/关闭 context/tab。顺序为运行时事实完成 → 原子发布登记与授权事实 → UI 投影 → 回执；登记失败需回收新资源或明确报告不完整，不返回可操作页面。关闭后同时清掉 UI、两个注册表、grant、ref/cursor 和租约。目标数与授权数分别统计，不混为一项。

通道启动和停止共用一个生命周期 gate，订阅返回 IDisposable 并在失败/停止路径释放。CoreReady 的迟到启动需检验会话世代，不能在停止后发布旧通道。gRPC 默认保持关闭，直到启用态组合验收完成；一次请求选择一种传输，断连不切另一条重放。

## 4. P0：执行回执、后置条件与重试

### 4.1 结果模型

新 `BrowserActionReceipt` 分开表达：execution=`not_started|dispatched|completed|unknown`；verification=`passed|failed|unverified|not_requested`；completion=`verified|dispatched|blocked|failed|unknown`。completion=verified 的前提是执行完成且必需断言通过；派发成功不等于业务成功。

回执带 operationId、显式 page 身份、动作、before/after 观察戳、assertions、navigation/scroll/focus 摘要、mayHaveSideEffects 与 safeToRetry。工具 `ok=true` 只用于 verified 或明确标注的 dispatched；unknown/blocked/failed 为 false，但不能丢失已经派发的事实。dispatched 明确提示“效果未验证，先观察，勿重做”。transport 成功只是拿到一份回执，不等于动作成功。

```json
{
  "ok": true,
  "completion": "verified",
  "execution": "completed",
  "verification": "passed",
  "operationId": "op-123",
  "action": "fill",
  "pageVersion": 7,
  "assertions": [{"kind": "value", "matched": true, "actual": "Pudding"}],
  "mayHaveSideEffects": true,
  "safeToRetry": false
}
```

示例输入为非敏感测试文本。日志只记录断言类型与是否通过，不记原文、密码、脚本、Token 或整页内容。工具回执的 actual 也必须有长度上限和敏感字段遮蔽；可用 matched=true + length 表达密码填入验证。

### 4.2 按动作验证，按事实等待

| 动作 | 必需/可选证据 | 不应采用的判据 |
|---|---|---|
| fill/type | 同一节点句柄回读 value/编辑文本；受控组件经一次重渲染后仍满足期望；type 定义插入与选区行为 | PageVersion 必须推进；回读 innerText 代替 value |
| select/check | selectedValues/checked 满足期望，包括原本已满足的 no-op | 必须产生状态变化才成功 |
| scroll | 目标容器、before/after offsets、实际 consumedDelta；边界时报告 atBoundary | 请求发出即成功；必须滚动固定像素 |
| click/press | 真实输入已派发；调用方可指定 URL、元素状态、值、文本出现等 expect | 根据 action 名推断必然导航或业务成功 |
| hover/move | 指针目标/命中与位置；需要菜单出现时使用显式 expect | 合成 mouseover 等于真实指针位置 |
| navigate | 导航接受/完成、实际 URL、HTTP/失败原因与指定就绪条件 | 只增版本就代表页面可用 |

默认只等待由驱动观测到的导航，或请求明确声明的 expect；带有界截止时间。没有业务 expect 的普通 click/press 可返回 dispatched；超时且输入已提交返回 unknown 或 verification failed + 已提交事实，不能标为可安全重试。

保留 `DesktopMutationInvariants` 的请求身份和结果形状校验，删除“所有 mutating 结果版本严格递增”的通用要求，换为 action/receipt 校验。同语义必须覆盖 BridgeBrowserCapabilitySurface 和 DesktopService；驱动直接产生证据，映射层不能各自再验出相反结论。Activate、关闭最后一页和 back/forward 无历史也分别定义结果，不拿另一页版本充当推进证据。

动作前解析并持有节点句柄；动作后通过该句柄或本次操作的事件读取事实，不重新解析旧 Locator。节点在重渲染中消失时使用明确的业务 expect、新 snapshot 或 wait；不能按同名新元素伪造“原输入框已验证”。

### 4.3 单次执行与结果不明

operationId 在工具执行开始创建并贯穿同一次内部请求/重传，不能每次重传换 ID。Desktop 缓存按调用身份、实例/连接世代、operationId、请求摘要区分 running/terminal；同 ID 不同请求拒绝。相同 ID 查询已有结果不再执行，跨进程崩溃不保证 exactly-once。

受限缓存拟定 5 分钟/1,024 项，running 不因容量淘汰；容量耗尽拒绝新写请求。过期重传返回 receipt_expired，不当成新动作。执行后断连无法证明结果时返回 unknown + mayHaveSideEffects=true + safeToRetry=false，提供只读状态/回执查询入口。只有明确 not_started 且故障可重试时才自动重试。

## 5. P1：稳定 ref 与观察版本

保留 ref 携带文档 PageVersion 的安全原则，增加 context/page/frame 身份绑定；工具将 ref 作为 opaque 值，禁止模型拼接。拒绝跨页、跨 frame、跨文档使用，即使两页都恰好处于 v7。

把三个事实分开：PageVersion 表示已提交文档世代；domRevision 表示内容变更；viewportRevision 表示滚动/缩放/布局坐标观察失效。导航进行中阻止新写操作，新文档提交时推进 PageVersion 并整体作废旧节点身份；只读调用不推进版本，普通 value 改变不使所有节点 ref 失效。节点替换/移除、frame 导航只使相关身份过期，浏览器进程失败作废该页全部引用。

驱动维护宿主绑定的节点身份表与存活校验，不能只信任页面可自行写入的 data-pudding-ref 属性。执行前检查实际节点仍 connected、所属文档一致、可操作状态与关键身份属性；对内容变化敏感的动作可使用 expect 校验名称/属性。role/name 仅帮助刷新定位，不是身份；真正过期返回 stale_element_reference 与最小刷新提示，不自动点击一个“看起来相同”的节点。

分页使用 extraction snapshot 的 revision；动态页面变化使 cursor_expired，并提供重新读取入口，不能把旧游标用于新内容。diff 是只读观察优化，绑定 baseline 和同一文档；基线缺失返回 refresh_required，不伪造变化。

## 6. P1：渐进 DOM 阅读与定位

### 6.1 单份表示、局部读取与预算

`browser_snapshot` 参数新增 mode、format、scope(locator/ref)、fields、limit、maxBytes、cursor、sinceRevision。mode 决定读取内容，format 决定 markdown/compact_json；同次默认只返回一种表示。旧 includeDom/includeAccessibilityTree/includeHtml 只用于显式 full 调试模式；模式与互斥字段组合非法时返回参数错误。

| mode | 内容 | 初始默认输出预算 |
|---|---|---|
| outline（默认） | 标题、地标、主要内容入口及可交互节点；不附每节点 bbox | 50 条、4,096 UTF-8 字节 |
| interactive | ref、角色、名称与必要状态 | 50 条、4,096 字节 |
| text | 正文 markdown；标题/列表/链接/表格/代码块结构 | 每页 4,096 字节，游标续读 |
| extract | scope 内指定字段；列表/表格/搜索结果等结构化投影 | 默认 10 条、4,096 字节；可请求 1,536 字节 |
| full | 显式 DOM/可达性树/HTML 调试视图 | 默认 16 KiB、硬上限 64 KiB，分页/截断声明 |

maxBytes 计入序列化元数据与转义开销，单位是 UTF-8 字节，不用字符数冒充字节/token。输出含 representation、scope、returnedCount、revision、truncated、reason、nextCursor。总量未知时不造 totalCount。不能靠通用工具结果裁剪器砍 JSON 尾部；返回前按整体预算重排或缩减内容，保证结果可解析。

内部扫描预算初值拟为 10,000 节点/深度 64/250ms，分页缓存拟为 8 个 extraction snapshot/页、每页累计 2 MiB、TTL 60 秒；容量和到期都有明确原因码。实现前通过真实驱动样本校准扫描时间门限，不能强行压缩内部深度来“通过”体积指标。命中扫描上限时报告 incomplete_scan，输出上限时报告 output_budget，两者不混淆。

正文提取先用 article/main/语义地标，再进行普通块结构回退，不写 Bing/抖音等站点专用选择器到驱动。去导航/页脚噪声不能删除任务明确选择的 scope；表格、代码空白与链接目的地址保持结构，禁止从 html/body 祖先 innerText 制造整页可访问名。分页以完整段落/行/表格边界优先，超长单块允许标记分片并续读；完整正文需游标聚合证明，而不是要求任何长文章单次 4 KiB 内 truncated=false。

### 6.2 定位结果

保留十种定位方式。text 匹配需定义最小可见匹配节点、空白折叠、exact/substring 和重复文本消歧；不能因祖先也包含文本返回整页，也不能把一次零命中推广成所有 text 定位都坏。对“Learn more”报告场景建立确定性测试与真实驱动复现。

locate 默认 includeHidden=false、limit=10；提供 cursor、includeHidden、fields、inViewportOnly。visible 与 inViewport 分开：屏外但有尺寸的元素仍可定位，写操作先滚入可见区域并复检；隐藏/禁用/遮挡目标不按成功处理。匹配歧义必须明确拒绝，不静默选第一个。

结果默认 ref/role/name/必要状态，省略与 name 相同的 text；需要几何时显式请求 bbox。展示 bbox 保留最多一位小数，驱动内部保留精度；不把展示四舍五入值用于实际点击。value、selectedValues、checked 可显式请求；输入回执按敏感策略自动提供最小验证证据。

## 7. P1：真实输入与滚动

驱动增加明确 inputMode=dom/native，回执报告实际 backend；面向用户网页优先使用真实浏览器输入路径，DOM 模拟用于已验证适用的动作，native 不可用时明确 unsupported，不静默切换语义。

原生键鼠拟通过 WebView2 的 CDP 适配实现，具体方法与已安装 Runtime 协商后才声明。按键修饰符、焦点、selection、组合输入、pointer down/up 成对处理；取消时清理按键/鼠标按下状态。针对 React 受控输入、contenteditable、Tab/Backspace/快捷键及嵌套 frame 做真实测试。CDP 入口存在不能代替这些验收。[WebView2 官方接口](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2)提供 CDP 调用；具体输入方法见[Chromium Input 协议](https://chromedevtools.github.io/devtools-protocol/tot/Input/)。

scroll 的目标模型为 page/element/to_ref/to_top/to_bottom：无 locator 时检查 document.scrollingElement；元素滚动优先明确指定，必要时定位最近可滚动祖先。普通滚动失败再由调用方选择 native wheel，不能盲目滚另一个区域。返回目标容器、前后位置、consumedDelta、atBoundary、contentChanged；无限滚动另等新增内容/条目数，不能把无内容加载当滚动失败。真实站点零位移的原因需观测容器、overflow、视口与输入路径后定位。

## 8. P2：截图视觉与坐标操作

### 8.1 browser_screenshot 与 Artifact

先交付 viewport 和区域/元素裁剪，再做全页捕获/PDF。截屏前验证 page read grant、当前文档及 readiness；截图不切换到未授权页面。viewport 拟使用 CapturePreviewAsync，必须等当前页面 ContentLoading 后采集，避免返回导航前画面；参见[WebView2 官方截图接口](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2#capturepreviewasync)。全页不能冒充 viewport，滚动拼接需要单独处理固定元素和动态内容。

Desktop 返回有界媒体载荷/分块和元数据，Core 校验 MIME、像素/字节上限、截屏身份后写入既有 Vision Artifact；模型结果只收 artifact 引用和类型化图片部分，不收 base64 长字符串。跨进程不得以 Desktop 临时文件路径假定 Core 可读。初始截图输入上限拟为 8 MiB/张，超限明确返回限制原因；同一消息的图片数量与总预算服从既有视觉管线。

默认 detail=low（最长边不超过 512px），按需 high/original/局部裁剪。报告源尺寸、输出尺寸、设备缩放、CSS viewport、scroll offset、裁剪变换、PageVersion/domRevision/viewportRevision。压缩图片字节不等于模型 image token 节省，指标需分别记录。

当前 image_reader.read 要求 SupportsVision=true 且路由支持 responses 原生工具图片；不支持时可生成 artifact/metadata，但明确 model_capability_mismatch/tool_output_not_supported，不偷偷调用辅助模型。截图供 Canvas/图表/布局理解及人工验证界面观察，不承诺自动解决验证码或替代人工验证。

### 8.2 坐标与其他外围能力

`browser_interact` 增加 pointer_click/move/drag，坐标统一为 CSS viewport 像素。截图坐标输入需携带截屏 observationId，驱动用精确变换转换；滚动/缩放/布局或页面世代改变时拒绝旧坐标，要求重新观察。坐标操作仍受 page grant、接管、租约、命中与视口边界约束，不能越过工作台隔离。

上传/下载、弹窗、JS 对话框、frame/shadow 路由分别作为能力切片：上传绑定获准本地文件来源，下载给出完成/失败与 Artifact；弹窗先登记和授权，不默认继承全部父页权限；跨域 frame 借助驱动/session 能力覆盖，未协商支持时如实报不支持；关闭页取消订阅和待处理事件。

任意 JS/evaluate 最后建设，不作为 P0 修复捷径。先提供类型化只读属性/表格/诊断提取；公开脚本需限制时间、结果字节、授权目标与审计范围。不能通过扫描脚本文本保证“只读”，任意脚本均按可产生副作用能力准入并产生相同回执；启用前必须通过双传输门禁。

## 9. P2：浏览器子代理委派

复用 spawn_sub_agent，不新增第二套 Agent 执行器。先验证真实工具发现/注入与权限作用域，不能只以父代理能发现七项工具推断子代理可用。任务封装包含目标、允许 read/write 范围、page grant、期望结果、预算和截止时间，注入工具列表须包含任务实际需要的 navigate/screenshot。

授权由可信 Runtime 给子代理签发，父子不能并发持有同页写租约；父代理暂停写入、委派完成/超时归还，接管和撤权使父子同时失效。多个只读观察可并行，写入按页和操作串行。浏览器自身任务路由属于 Core，不进入 Shell。

父代理只收有界结论、必要摘录、URL/Artifact/operationId 和验证状态，不收子代理整页快照/完整内部对话。默认结论上限 2 KiB，可声明更小预算；全文以受权限约束的 Artifact 保存。页面文本和子代理结果均作为数据，不能通过网页内容请求扩大工具或授权范围。

## 11. 验收矩阵与证据门禁

下列数字都是拟定门禁，历史报告的 252 项通过不能算本方案验收。自动化 fixtures 先覆盖两传输同形，再覆盖产品实际 WinUI 装配；外部站点用于补充 smoke，不能把站点变化混进确定性基准。

| 门禁 | 场景与通过标准 |
|---|---|
| G1 控制权 | 两传输：接管/暂停确认后的新输入步骤数=0；排队写调用全部拒绝；已派发动作保留事实；恢复不复活旧租约；授权范围内读取可用 |
| G2 页面授权 | 显式请求同 context 非目标页写入拒绝且驱动调用数=0；撤销/切目标/frame跨身份拒绝；子代理不得扩大父授权；建关页 UI/运行时/注册表无残留 |
| G3 回执 | 同文档 fill/select/check 正确 verified；click 导航和 click 菜单均不因版本未增假失败；延迟导航、断连、取消返回准确 execution/side-effects；同 operation 重传驱动执行次数≤1 |
| G4 ref | 同节点 20 次只读、fill、普通滚动后无需重复定位；替换节点/跨页/文档导航后旧 ref 拒绝且不点同名替代节点；读操作导致 PageVersion 增长次数=0 |
| G5 阅读效率 | TestSite 标准中文/英文 SERP fixture：一次 extract 返回前 10 条标题，完整序列化 UTF-8 ≤1,536 bytes、无额外 locate；fixture 标题长度明确固定。任意长标题不能承诺此预算，超限必须声明分页/截断。另记录进入模型后的文本 token 与调用次数 |
| G6 正文/分页 | 标题/列表/表格/代码/链接结构 fixture 聚合后内容覆盖100%，无重复或丢段；超预算保持合法输出；动态变化和 TTL 正确 cursor_expired；全文模式必须显式选择 |
| G7 定位/输入 | 十种 locator 矩阵含 exact/重复/隐藏；受控输入重渲染后值一致、密码不回显；0×0/禁用/遮挡拒绝；一次 fill 回执足以确认非敏感值，无二次 snapshot |
| G8 滚动 | window 与嵌套容器非边界有真实位移；边界正确 no-op；无限滚动等新条目后报告 contentChanged；零位移不能假称滚动成功 |
| G9 视觉/坐标 | 截图与目标/文档一致，导航期间不返回旧页冒充新页；low 基准图≤512px/≤40 KiB，超预算按明确压缩/裁剪规则；实际模型收到类型化图片；缩放/滚动后旧坐标拒绝 |
| G10 委派 | 子代理真正发现并调用 browser_*；父子同页写租约不并存；父结果默认≤2 KiB、不含全页；取消/接管/超时回收许可 |
| G11 生命周期 | 新通道启停订阅不增长；迟到 CoreReady 不复活旧会话；断连不双执行；桌面隐藏/恢复、跨标签、重启/崩溃/退出均有外部证据 |

≤1.5 KiB 搜索结果目标优先保障真实标题语义，不通过默默砍标题/URL 造指标。截图 40 KiB 只针对固定低细节基准；复杂图若在最低可读质量下无法满足则返回 budget_exceeded 或明确请求局部截图，不能无限压缩后仍称可读。

证据记录 operationId、实际传输/构建、身份/授权 epoch、执行阶段、验证结果与调用次数；敏感内容不入日志，必要 fixture 证据留 Docs/14_reports 或 Docs/16_qa。发布端点只声明已完成能力，transport/status 用量和未完项作为旧 Bridge 退役依据。

按[组件化规程](../10_conventions/组件化交付规程.md)先独立构建测试再接入；Desktop build/test/publish 串行，restore/build 使用 temp/build/recovery，随后同目录 --no-restore；测试结果/覆盖率显式放 temp/test-out。临时产物只清理本次独占目录，不能清掉他方 WIP。命名空间/工程拆分后执行全解决方案构建门禁，全部受影响工程编译通过。

两段验收为 ready-for-external-deploy → 外部控制器重启到明确构建 → 新会话真实模型 smoke → in-product-functional-complete。Desktop/Core 启动、重启、恢复和退出回收仍由外部控制器判断。真实 DeepSeek/抖音验证必须使用用户指定 Agent/DataRoot，不读取或复制 D:\data 模型 Secret 绕过准入。

## 12. 未决验证与完成定义

实现前需核验 native 输入/截图对当前 Runtime 与隐藏表面的支持、滚动无位移根因、只读期间版本变化事件及子代理实际工具注入。每项安排对应 B3/B4/B6 探针和明确失败路径，不能用未验证假设继续声称已支持。

本设计任务的交付是方案、索引入口和修改日志，文档校验通过后独立提交。功能施工完成须逐项给出 G1–G11 证据；P0 通过之前不默认开启新通道，组件测试通过之前不装配新组件，视觉只声明已验证的模型/协议组合。
