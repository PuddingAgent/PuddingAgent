# 上下文交接摘要与压缩保真

压缩保留的是继续任务所需的状态和恢复证据的能力。驻留 token 数可以下降，但有效要求、纠正、未完成操作、关键决定及其理由不能因旧日志移出窗口而失去。外部文件只有保留可读取入口，才能替代常驻正文。

## 工作模型留下交接摘要

`context_handoff(action=save, summary=...)` 由正在执行任务的模型调用，不额外调用辅助模型重读全部历史。内容包括有效要求/约束、已完成与未完成状态、关键决定及理由、下一步、证据标题/结论/路径或已知 Turn ID。更新前可 `read` 合并仍有效事项；保存完整的新笔记，不是隐式增量补丁。

正文最多 6000 UTF-8 字节，超长拒绝，不截断。存储位置为 `<DataRoot>/runtime/context-handoffs/<scope-hash>/<handoff-id>.json`，按工作区、会话、Agent 隔离。宿主绑定 Run、Tool Call 和可用的 Turn ID；模型不能指定身份或写入路径。先写不可变版本再原子更新 `latest`，失败或取消不破坏旧版本。`read` 按 ID 读取精确版本，省略 ID 则读取当前作用域的 latest。

完整序列化记录另受 7 KiB 上限约束，为工具返回包装留空间；JSON 保留中文字符，避免 Unicode 转义膨胀使回读遭到 8 KiB 工具预算截断。保存成功仅返回短确认与恢复调用，不重复正文。笔记是模型的理解，可能错误、遗漏或过期，不构成用户授权、工具成功证明或独立事实来源。

## 提醒与压缩消费

`ContextHandoffHook` 消费执行中已解析的有效输入上限和用量快照。占用达到一半后，在成功的常规观察工具结果中建议写笔记。每个作用域 30 分钟冷却，提醒缓存最多 256 项；驱逐只影响提醒频率。Hook 不访问数据库、不调用 LLM，不触发压缩或暂停。工具未加载时可通过 `search_tools` 查找，调用仍经过原有能力授权。

Buffered 与 Streaming 都接入工具结果变换链。提醒保留 JSON 对象原字段；目录、控制、PID 协议、数组和超过 16 Ki 字符的结果不追加，避免在提示路径重新解析大载荷。失败工具不变。纯文本轮不会收到提醒，模型仍可主动使用工具。

warm-prefix 和 Agent 语义摘要器采用同一保留规则：优先保留下一步所需的要求、纠正、状态和决定；有可恢复证据的已完成事项压为标题、结论及精确索引。重复进度、已解决日志、被替代尝试可省略；未解决问题需要的精确命令、错误和代码仍保留。

笔记进入正常工具历史，压缩器仍只处理选中的历史跨度，不把跨度以外的 latest 当成覆盖证据。笔记仅提供相关性信号，需与原消息及后续纠正核对。warm-prefix 包装由宿主加入固定 `context_handoff read` 恢复提示，即使模型漏写 ID，仍有同会话 latest 恢复入口。原有摘要预算、收益校验、CAS 和源消息归档继续生效。

## 保真评估边界

确定性测试可证明存储、读取、隔离、预算、失败保留和接线正确，不能证明模型总会响应提醒，也不能证明每次摘要保留了 90% 有用信息。新提示是否降低真实会话用量，需要部署后的回放比较。

应先从原始会话独立制定问题与评分：关键用户要求、未完成操作必须全部保留，一般事实可通过有界检索恢复。分别记录不检索的回答率、实际检索后的回答率、恢复开销、重复执行副作用及多次压缩漂移。不能只让生成器给自己的摘要评分，也不能把字数减少当作保真。更大跨度分层压缩、已外存正文的确定性降级、自动保真门禁属于后续阶段。

独立验证和接入顺序遵循[组件化交付规程](../10_conventions/组件化交付规程.md)；实现见 [Handoff code_map](../../Source/PuddingContextHandoff/code_map.md)。
