# DS-I1-04 预算账户绑定与幂等创建任务书

**交给 DeepSeek 的下一张、唯一施工单。只实现本单，不自行选择其他“无阻塞收敛”任务。**

目标：让主代理下一步能够从可信 Work/Goal/Task 身份取得正确、持久、可重入的预算账户。交付状态为 `ready-for-review`；不得宣称产品主执行链、预算体系或 Goal 模式全部完成。

核心决策由本单冻结。DeepSeek 负责规定的账户适配与测试；主循环、重试/派发状态机、取消主管、公共契约和产品接线继续由主代理负责。本单不要求修改 Runtime 或 Host，也不要求真实模型。

## 0 开工依据与现存问题

2026-11-07 源码核对：

- `RuntimeBudgetBoundaryTests` 现有三例使用真实 facade、端口、gate、SQLite 账本和 fake client；预算身份与账户仍由测试手工提供。
- Host 已注册 `IModelAttemptBudgetPort`，不得重复报告“端口尚未注册”；主执行调用仍未填 `BudgetAttempt`。
- `ExecutionBudgetAccountMapper` 把 `ParentWorkId` 作为 Goal ID，并在父账户不存在时用子 descriptor 的限额、Agent、Session 创建 Goal 账户。
- 已存在账户只读取 mode，没有比较完整身份、父账户、币种和冻结限额。当前第二条 mapper 测试允许变更限额/mode 后静默返回旧账户，不能作为严格幂等的验收。

本单修复后两项，并以 mapper 产生的真实账户绑定重用预算调用边界。**既有三例不证明产品身份贯穿、取消与派发竞争或 provider 内部重试计费。** 本单也不把这些问题算作完成。

## 1 已裁定的预算根语义

| 场景 | 账户与限额权威 | 创建责任 |
|---|---|---|
| 普通聊天、一次公开 Work 提交 | 一次稳定 canonical Work 为根，`BudgetAccountKind.Work`；Conversation/Session 只是归属，不是累计计费根 | Platform 的 Work 受理/执行绑定权威；不由 SDK、插件、模型或 facade 自动创建 |
| Goal 多轮执行 | 一次 GoalRun 一个 `GoalRun` 根；各 Work 是其后代；迭代、重启或恢复不能重置根余额 | Goal 激活的可信服务依据已冻结 Goal 限额创建根；本单不接该服务 |
| 独立后台任务 | 没有父 Work/Goal 时，受权持久任务身份可作为 `Task` 根；恢复同一任务不能取得新根 | 受权任务受理服务；周期任务是否是新任务由任务权威决定，Worker tick 不决定 |
| 子代理、工具内算子、Review | 复用或下挂已有父预算，禁止为每次调用重新创建独立根 | 父执行绑定/受权 Job 恢复入口；本单只验证账户父链，不接这些调用方 |

身份与限额裁定：

1. 不将 TaskId、TurnId、RunId、ConversationId、AgentId 冒充 WorkId。若当前入口没有 canonical Work 映射，由主代理补适配；DeepSeek 不得用随机 ID 或拼接时间填空。
2. 根限额来自宿主已验证、持久冻结的执行策略；Goal 用 Goal 合同，普通 Work 用受权 Work 请求与宿主/Agent 策略取最严值。用户/插件只能收紧，不能扩大。
3. `MaxInputTokensPerRequest` 是单次输入容量；`MaxOutputTokens/MaxCost/MaxCalls` 是累计量。不得拿模型 context window 充当累计预算。
4. 对 Enforced 新根，没有可信预算策略时应拒绝创建/执行，不能隐式降级 Legacy，也不能写死“10 元/10 万 token”等产品默认值。本单接收已冻结 `BudgetLimits`，不负责读取或新增配置。测试数值仅为 fixture。
5. 本单不更改 null/zero 的既有含义：null 代表该维度无本地上限，0 代表耗尽。祖先限额始终约束后代；不得把父余额复制为子“新额度”，也不得从子限额推导父限额。
6. `Mode` 必须显式传入。不存在父账户则拒绝创建子账户；不存在 root 时，仅明确的 root descriptor 可以创建自身。
7. 现有冻结 `BudgetIdentity.RootKind/RootId` 在本适配中仍描述所绑定账户的业务身份：Goal 下的 Work 账户使用 `Work/workId`，不会伪装为 Goal；顶层根通过持久父链确定。不改这些公共字段名称。
8. 父子必须同 Workspace、同 CostUnit、同 Mode；允许不同 Agent/Session，以支持委派。子账户与每个祖先都受账本校验，不能只检查叶子。

**Required Review 策略、普通聊天是否进入 Goal、本轮输出上限分配、真实 attempt ID 生成及 provider 重试策略不在本单修改范围。**

## 3 固定接口与函数契约

### 3.1 Mapper 输入/输出

保留 `ResolveAsync` 名称和 `BudgetAccountScope` 返回结构。将输入改为：

```csharp
public sealed record BudgetAccountDescriptor(
    BudgetAccountKind RootKind, string RootId, string WorkspaceId,
    string AgentId, string SessionId, BudgetLimits Limits, string CostUnit,
    BudgetEnforcementMode Mode, BudgetAccountId? ParentAccountId = null);
```

- 删除 `ParentWorkId`，不保留旧参数别名或兼容重载。它原本实际表示 Goal，含义错误。
- 沿用 `goal:<RootId>`、`work:<RootId>`、`task:<RootId>`，本单不改变已使用的 ID 格式。
- 拼接后必须满足 `BudgetAccountId` 的长度限制；不能只验证未加前缀的 RootId。ID 不允许逗号、控制字符或首尾空白，不自动 Trim，不截断。保留合法 ID 的原值与大小写。
- GoalRun、Task 只可作为根；Work 可为根，也可挂在已存在的 GoalRun/Task/Work 下。ParentAccountId 必须为已有受信账户引用，不能只传一个裸业务 ID 让 mapper 猜其类型。
- 成功返回的数据从持久记录构造。`Ancestors` 为 root → immediate parent，**不含自身**；根返回非 default 的空 ImmutableArray；真实 gate 仍使用 `BudgetAccountPaths.RootToLeaf` 添加自身。
- Mapper 不直接使用 DbContext，不接收调用方自报的 Ancestors，不创建父账户，不捕获任意异常返回 Legacy/null/新根。

### 3.2 Store 内部原子绑定入口

在新增 partial 文件内定义以下类型与方法；它们属于 Platform 适配层，不加入公共 Contracts：

```csharp
public sealed record BudgetAccountDefinition(
    BudgetAccountId AccountId, BudgetAccountId? ParentAccountId,
    BudgetIdentity Identity, BudgetLimits Limits, string CostUnit,
    BudgetEnforcementMode Mode);

public sealed record BudgetAccountBindingResult(
    BudgetAccountDefinition Definition,
    ImmutableArray<BudgetAccountId> Ancestors,
    bool Created);

// ExecutionBudgetStore 的新成员
public Task<BudgetAccountBindingResult> EnsureAccountBindingAsync(
    BudgetAccountDefinition expected, CancellationToken ct = default);
```

Mapper 构造 expected，调用该入口，再将返回的 Definition/Ancestors 映射成 Scope。该方法不创建账户的模型预留、不调用 provider。

方法行为：

1. 参数、限额合法性和枚举先验证；使用现有 `ValidLimits` 等适用验证，不把非法枚举当默认类型。AccountId 必须等于按 Identity kind/id 生成的确定性 ID。
2. 使用一个数据库事务读取既有账户及所需父链、校验后创建或复用账户。读链用同一 DbContext/事务；禁止对外层一串独立查询的结果声称原子。
3. 已存在账户时，必须逐字段比较：AccountId、ParentAccountId、Identity 的全部五项、Limits 全部五项、CostUnit、Mode。decimal 比较数值，不比较持久化字符串格式；null 和 0 不等价；字符串使用 Ordinal。任一不符返回 `budget.conflict`，不更新、不放宽、不静默复用。
4. Mode 的独立升级仍由原有方法负责；新方法不升级/降级。若已升级账户收到旧 Mode descriptor，明确 Conflict，调用方应刷新可信快照，不能伪造成功。
5. 新子账户的父必须存在。沿数据库 ParentAccountId 读取到根，检查同 Workspace/CostUnit/Mode、允许的父子类型、取消状态及完整性。不能从请求复制祖先；不能发现断链后将当前节点当作新根。
6. 深度上限沿用 64（含自身），使用 visited 集合检测环；自引用、环、超深或断链返回 `budget.path_invalid`。直接声明的父不存在返回 `budget.account_missing`。
7. 子与父的 Agent/Session 可以不同；但重复解析同一子账户时，Agent/Session 变化仍是 Conflict。
8. 新子/已有叶与父链 Workspace 或 Mode 不一致返回 Conflict，CostUnit 不一致返回 `budget.currency_mismatch`；账户/祖先已取消返回 `budget.cancelled`。不修改取消标记，不创建替代根。
9. 仅当全部校验通过才插入当前叶。根 descriptor 只创建该根。每次冲突或取消都保持账户数、父链、限额和账目不变。
10. 复用时不重置 Calls/Cost/Reserved/Unknown/Revision；构造结果必须使用持久值。相同定义重复调用：同账户 ID、同祖先，第二次 Created=false。
11. 多个 Store 实例同时创建相同账户时，数据库唯一约束与事务是权威；进程内 `_gate` 只是优化。相同定义最终一个 Created=true，其余复读匹配后返回 false；不同定义一个成功、另一个 Conflict。
12. 只对 SQLite 可识别的唯一键竞争或 BUSY/LOCKED 做有界重试/复读，不超过三次；每次重试新 DbContext/事务且观察 ct。重试耗尽保留异常，不吞数据库故障。不得全局 catch 后“认为已存在”，不得使用无限循环。

错误统一使用现有 `ExecutionResourceException` + `BudgetErrorCodes`。输入无效为 AccountInvalid；不要新增错误码或返回布尔值替代诊断。若现有类型无法表达本契约，报告最小差异，由主代理调整；不得自己改公共冻结契约。
