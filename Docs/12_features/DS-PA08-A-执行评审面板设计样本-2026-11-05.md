# DS-PA08-A 执行评审面板设计样本与渲染契约（冻结）

DS-PA08-A 是纯展示组件：`ExecutionReviewPanel({ view, onOpenEvidence })`。它只渲染主代理冻结的 `ExecutionReviewView`，不 fetch/SSE、不读 storage、不注册路由、不调取消/续跑 API、不轮询、不改 stores/hooks。

## 1 冻结输入（主代理维护，DS 不得修改）

- `ExecutionReviewPanel.types.ts`：`ExecutionReviewView`/`ExecutionReviewPanelProps` 全量字段；Unknown 金额必须 `{ amount: null, known: false }`。
- `ExecutionReviewPanel.fixtures.ts`：6 组设计状态样本（测试必须直接 import 消费，不得改写期望）：
  - `pendingReview`：Turn 完成、验收 Pending
  - `modelSatisfiedButCheckFailed`：模型满足、受控检查失败
  - `queuedNextTurn`：下一轮已排队
  - `cancelDraining`：取消已请求、仍在排空
  - `unknownAndMissingEvidence`：Unknown 金额 + 未知验收 + 无证据
  - `staleGap`：stale + 事件缺口

## 2 精确渲染契约（测试按此断言，不依赖视觉快照）

| 元素 | 选择器/可访问名称 | 精确文本/规则 |
|---|---|---|
| 根容器 | `data-testid="execution-review-panel"`，`role="region"`，`aria-label="执行评审"` | 始终渲染 |
| 运行状态 | `data-testid="execution-run-state"`，`aria-label` 同文本 | `running`→`执行中`；`waiting-review`→`等待验收`；`queued-next-turn`→`已排队下一轮`；`completed`→`已完成`；`failed`→`失败`；`cancelled`→`已取消`；`unknown`→`状态未知` |
| 验收状态 | `data-testid="execution-review-state"`，`aria-label` 同文本 | `not-required`→`无需验收`；`pending`→`验收待处理`；`running`→`验收进行中`；`satisfied`→`验收满足`；`needs-work`→`验收未满足`；`needs-user`→`等待用户决定`；`unknown`→`验收结果未知`；`stale`→`验收结论已过期` |
| Pending 提示 | `data-testid="review-hint"` | 仅当 run=`waiting-review` 且 review=`pending` 时文本 `本轮已结束，等待验收`；该元素的 run-state 不得出现"已完成" |
| 停止原因 | `data-testid="stop-reason"` | 存在时文本 `停止原因：<summary>`（`reasonCode` 仅在 `title` 属性） |
| 续跑原因 | `data-testid="continue-reason"` | 存在时文本 `续跑原因：<summary>` |
| 模型建议 | `data-testid="model-suggestion"` | 存在时文本 `模型建议：<finding>（证据级别 <evidenceLevel>）`；全文不得出现"模型已验证所有测试" |
| 失败检查 | `data-testid="failed-check-<checkId>"` | 逐条文本 `检查失败：<checkId>（退出码 <exitCode>）`；`title` 为 `summary`；每项独立元素 |
| 未满足条件容器 | `data-testid="unmet-criteria"` | 仅当 `unmetCriteria.length > 0` |
| 单条未满足条件 | `data-testid="unmet-criterion-<criterionId>"` | 包含 criterion.text 与结果标签（`not-supported`→`未满足`，`unknown`→`未知`） |
| 证据按钮 | `data-testid="open-evidence-<evidenceId>"`，`aria-label="查看证据 <evidenceId>"`，`type="button"` | 点击恰好一次调用 `onOpenEvidence`，参数是同一个 `EvidenceRef` 对象引用 |
| 无证据 | — | 当条件 `evidenceRefs` 为空：不渲染按钮，渲染文本 `无证据引用` |
| 截断 | `data-testid="unmet-overflow"` | 未满足条件超过 5 条时只显示前 5 条并追加 `还有 <N> 项未显示` |
| 预算-实际 | `data-testid="budget-actual"` | `known && amount != null` → `` `${amount} ${unit}` ``；否则 `未知`（禁止 0/0.00/100%） |
| 预算-预留/未知 | `data-testid="budget-reserved"`、`budget-unknown` | 同上；未知一律 `未知` |
| 预算上限 | `data-testid="budget-limits"` | `maxOutputTokens`/`maxCost` 为 null 显示 `无上限`，否则显示实际值（文本需包含二者） |
| 取消状态 | `data-testid="cancel-state"` | 未请求 `未请求取消`；请求后 `取消请求已受理`；`draining` 追加 `，仍有未决调用（<pendingCalls>）` |
| 数据新鲜度 | `data-testid="freshness-warning"` | 仅当 `stale || gapDetected`：`stale` 文本 `数据可能已过期（截至 <dataAsOf>）`；`gapDetected` 追加 `；检测到事件缺口，已请求快照刷新`；两者皆 false 时不渲染 |
| 组件边界 | — | 不 import 图标包/新增依赖；不修改 package.json/锁文件/已有测试；不调用任何网络/存储/路由 API |

## 3 必测矩阵（除类型/渲染外）

1. `pendingReview`：run 状态显示 `等待验收` + 提示 `本轮已结束，等待验收`，且不出现"已完成"。
2. `modelSatisfiedButCheckFailed`：同时出现 `模型建议：满足（证据级别 ModelAssessed）` 与失败检查 `检查失败：check-b（退出码 1）`；全文无"模型已验证所有测试"。
3. `queuedNextTurn`：`已排队下一轮` + `续跑原因：缺少乙文件，最多自动补做一次`；不得出现"执行中"。
4. `cancelDraining`：`取消请求已受理，仍有未决调用（2）`；预算占用仍显示（不得清零）。
5. `unknownAndMissingEvidence`：预算值与 Unknown 均为 `未知`；无证据条件渲染 `无证据引用` 且无按钮。
6. `staleGap`：显示 `数据可能已过期（截至 2026-11-05T11:55:00+00:00）` 与缺口提示；不得显示成功完成的无条件声称。
7. 点击 `open-evidence-evidence-build`（queuedNextTurn 样本）：回调恰好一次、参数引用相等。
8. 可访问名称：run/review 状态元素 aria-label 与文本一致；证据按钮 aria-label 精确。

## 4 停止条件

需要修改 `.types.ts`/`.fixtures.ts`/package.json/锁文件/已有测试、需要新增依赖或图标、需要 fetch/SSE/storage/路由/轮询、或需要修改后端 DTO 时立即停止并报告；不得改 fixture 迁就实现，不得用测试快照代替行为断言。叶任务只交付 `ready-for-review`，不得声称界面已在当前产品生效。
