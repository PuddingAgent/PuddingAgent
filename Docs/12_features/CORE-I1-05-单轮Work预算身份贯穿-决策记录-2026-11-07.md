# CORE-I1-05 单轮 Work 预算身份贯穿 · 决策记录

本记录先于实现冻结语义，逐项给出对应类型、成员、证据查询、非受管入口、恢复矩阵、失败码、限额来源和精确读写文件。**首个消费者**限定为公共单轮 Work 受理的普通主 Agent 调用（buffered 与 streaming 两条请求构造路径）；子代理、工具内算子、Review、Goal、插件与 UI 继续走既有非受管路径，本单不接线、也不得继承主 Work 凭证。

## 1 绑定谁：身份来源与信任锚

| 事实 | 来源（真实类型/查询） | 用途 |
|---|---|---|
| 命令身份 | `ExecutionCommandRecord`（`CommandId/TurnId/ConversationId/WorkspaceId/AgentInstanceId/UserId`） | 与 lease 交叉核对 |
| 客户端请求 ID | `ChatExecutionCommands.ClientRequestId`（**现有列**，由受理写入；公共 Work 受理时即 `WorkId`） | 候选 Work 引用，经下两项验证才可信 |
| 受理行 | `AcceptanceBatches(WorkspaceId, ClientRequestId)`：`UserId`、`MessageId`、`ConversationId` | 证明该 ID 是同一次 canonical 受理 |
| 受理标记 | 用户消息 `ChatMessages.MetadataJson` 中的 `agent_work_actor`/`agent_work_operation`/`agent_work_request_hash`（由 frozen `CanonicalAgentWorkBackend` 写入） | 证明来自公共 Work 受理链，而不是任意聊天入口 |
| canonical 回执 | frozen `IAgentWorkBackend.ReadAsync(WorkKey)` 返回非空且 `Receipt.CommandId/TurnId/ConversationId/WorkId` 与 lease、命令一致 | 复用冻结后端的交叉校验，**不重写 Work 哈希/状态机** |
| **服务端 provenance（决定性锚点）** | `SubmitTurnCommand.IsTrustedCanonicalWorkIngress`：只有 frozen `CanonicalAgentWorkBackend` 在进程内设置；`SubmitTurnHandler.NormalizeMetadata` 在未受信时**剥离 `agent_work_*` 保留键**，其持久化结果与此一致 | 普通聊天 HTTP 客户端无法写入受理标记——伪造 `work-*` ClientRequestId + 标记只会得到 `EvidenceMissing`，不会建立受管账户（W2） |

- 账户：`ExecutionBudgetAccountMapper.ResolveAsync(new BudgetAccountDescriptor(BudgetAccountKind.Work, WorkId, workspace, agent, session, limits, costUnit, mode, ParentAccountId: null))` → `work:<WorkId>`（DS-I1-04 已验收的原子绑定；祖先由持久父链决定）。
- 拒绝：客户端自报的 WorkId、消息 metadata、仅前缀匹配、仅 `ClientRequestId` 非空都不足以赋予预算身份；四项证据缺一即按 §4 失败，**不得归入非受管**。

## 2 最小契约增量（是否改 RuntimeDispatchRequest / LlmAttemptBudget）

| 决定 | 内容 |
|---|---|
| **不改** `RuntimeDispatchRequest` | 已有 `ExecutionIdentity` 直通，新增平行字段会在多个 DTO 重复保存 WorkId |
| **不改** `LlmAttemptBudget` | 已含 `AccountId/Ancestors/RootKind/RootId/Workspace/Agent/Session/AttemptId/ModelRevision/PriceVersion/MaxInputTokens/MaxOutputTokens/CostUnit`，足够表达 |
| **新增** `RuntimeExecutionIdentity.WorkBudget`（`RuntimeWorkBudgetBinding?`，可选） | 唯一新增载体；由编排层在受理/租约核对后填写，Runtime 只透传、不推断 |
| **新增** `RuntimeWorkBudgetBinding` 字段 | `AccountId, Ancestors, RootKind, RootId, WorkspaceId, AgentId, SessionId, CostUnit, ModelRevision, PriceVersion, MaxInputTokensPerAttempt, MaxOutputTokensPerAttempt`（不含 AttemptId——attempt 属于每次发送） |
| **新增** `ExecutionCommandRecord.ClientRequestId`（可选 init） | 现有 DB 列已存在，只是读取面缺失；无 schema/迁移变化，向后兼容 |
| **新增** `SubmitTurnCommand.IsTrustedCanonicalWorkIngress`（可选 init） | 与既有 `IsTrustedGatewayIngress`/`IsTrustedMessageFabricIngress` 同型：只有进程内组件可设置，HTTP 映射不暴露；受信时才允许 `agent_work_*` 标记进入持久事实 |
| **冻结文件演进（已评审并重签）** | `CanonicalAgentWorkBackend.cs` 设置上述标志（唯一调用者影响）；work 冻结清单对应哈希由 `E696825D…` 重签为 `B5B1B514…`，旧指纹与差异备份在 `.work/core-i1-05/20261107-sec/` |
| 共享转换 | `WorkBudgetAttempt.Create(binding, attemptId)`：每轮/每次发送生成独立 attempt 身份，不共享 attempt ID |

## 3 何时冻结：策略与限额来源

| 字段 | 来源 | 语义 |
|---|---|---|
| 启用开关 | Host 配置 `Pudding:ExecutionBudgets:ManagedWork:Enabled`；缺省 **关闭 = 非受管（旧行为）** | 允许分批启用，不隐式改变历史路径 |
| `Mode` | 配置；仅允许 `Enforced`/`Shadow`；`Legacy` 视为策略非法（不能静默放行） | 受管账户一旦建立即按该模式门禁 |
| 累计限额 | 配置 `Limits`（`MaxOutputTokens/MaxCost/MaxCalls/MaxConcurrentAttempts`，`MaxInputTokensPerRequest` 可选） | `null`=该维无本地上限，`0`=耗尽；用户/插件只能收紧 |
| `CostUnit` | 配置；必须与模型目录 `ModelCapabilityRecord.Currency` 一致 | 不一致 → 受管失败，不换币种 |
| 单次输入容量 | 首次绑定取 `MaxInputTokensPerRequest` 配置值（未配置时取目录 `MaxContextTokens`）并随账户持久冻结；恢复中的 Work 取持久值 | 单次容量，不随累计使用扣减；策略变更不改变在途 Work 的容量 |
| 单次输出预留上限 | 目录 `MaxOutputTokens` | 逐次报价/预留的 attempt 上限；累计约束仍由账本祖先校验 |
| 模型 revision / 价格版本 | 目录 `ModelCapabilityRecord.Revision` / `PricingRuleVersion`（真实派发时再由 `IModelQuoteSource` 校验窗口与币种） | 冻结在绑定里，不做零值回填 |
| 不写死产品默认值 | 无配置时不创建受管账户、不降级 Legacy | 与 DS-I1-04 §1.4 一致 |

恢复：同 Work 恢复/重领 run 复用同一 `work:<WorkId>` 账户；绑定前先读持久定义——**已有 Work 使用已冻结的限额/模式/币种**（策略变化既不 widen 也不 fail 在途 Work），`EnsureAccountBindingAsync` 的逐字段冲突检查保留给显式修改既有定义的请求；**新 Work 才使用当前宿主策略**。政策变更只影响尚未创建账户的新 Work；已冻结绑定不热改。

## 4 错误码与失败矩阵

新增 Platform 内部错误码（不进入公共 Contracts）：`work.budget_policy_invalid`、`work.budget_evidence_missing`、`work.budget_identity_mismatch`、`work.budget_model_unpriced`；其余沿用既有 `budget.*`。

| 场景 | 结果（provider 调用数） |
|---|---|
| 策略关闭 | 非受管结果，既有行为不变 |
| 策略启用但非法（mode/limits/currency 缺失） | `work.budget_policy_invalid`，0 次 |
| 受管证据缺失（无受理行/标记不符/后端返回 null） | `work.budget_evidence_missing`，0 次 |
| 客户端伪造 `work-*` ClientRequestId + `agent_work_*` metadata（HTTP 普通聊天入口） | 保留键在受理前被剥离 → `work.budget_evidence_missing`，不建账户、0 次 |
| 命令/回执/lease 身份不一致 | `work.budget_identity_mismatch`，0 次 |
| 模型目录缺失、revision/pricing 空、币种不符 | `work.budget_model_unpriced`，0 次 |
| 账户已取消 | `budget.cancelled`，0 次 |
| 恢复/重领既有 Work（宿主策略已改变） | 使用持久冻结的限额/模式/币种继续执行，不 `budget.conflict`、不 widen |
| 显式请求修改既有账户定义（Direct mapper 冲突路径） | `budget.conflict`（DS-I1-04B 语义保留） |
| 账户定义冲突 / 父缺失 | `budget.conflict` / `budget.account_missing`，0 次 |
| 派发时限额耗尽/并发满/未知价格 | `ModelAttemptBudgetException`（`budget.*`），0 次 |
| 受管绑定存在但 facade 缺失或身份不匹配 | `ModelAttemptBudgetException`（`budget.dispatch_invalid`/`budget.request_invalid`），**禁止回退直连客户端**，0 次 |

## 5 传播与消费

1. `ExecutionRunCoordinator`：在 `command`、profile、snapshot 解析完成后、构造 `TurnExecutionContext` 前调用 `IManagedWorkBudgetBindingResolver.ResolveAsync(lease, profile, ct)`，把绑定放入 `ExecutionIdentity.WorkBudget`。
2. buffered：`AgentExecutionLlmInvoker` 用共享转换填充 `LlmInvocationRequest.BudgetAttempt`。
3. streaming：`AgentExecutionService.Streaming` 的请求构造使用同一转换。
4. 非受管路径：无绑定 → 原行为；子代理/后台/Goal/Review/插件新建的 `RuntimeExecutionIdentity` 不含 `WorkBudget`（不复制父身份载体）。

## 7 验收映射与激活次序

- W1：公共 API 受理 → 精确账户/祖先/limit/mode 与持久定义一致；重提/重领不重置账目。
- W2：换 workspace/actor/伪造 WorkId/错配 lease-command → 受管失败；合法旧通道保持既有行为。
- W3：新 scope 重开同库仍读原 Work 限额；缺策略或账户取消 → 真实模型发送计数 0。
- W4：buffered 与 streaming 的 Work/模型身份一致；去掉任一分支传播即取红。
- W5：关闭 facade/预算端口或错误账户时不能转入直连客户端；快照/JSON 不含可伪造授权材料。

激活次序：本单只在隔离测试与真实绑定路径上启用；真实传输逐次预算须满足 I1-06 的重试/租约门禁后再启用。编译成功或两条分支都填值只证明传播，不证明激活。

## 8 未覆盖与风险

- 子代理、工具内算子、后台 Review、Goal、插件与 UI 路径仍非受管；它们不得继承主 Work 凭证。
- 既有以 `Legacy` 创建过的同 ID 账户在启用 Enforced 前需由既有 `SetEnforcementModeAsync` 显式升级；本单不做隐式升级，冲突按受管失败返回。
- 策略关闭后既有账户保留但不使用（不删除、不退款）；重新启用时按持久定义继续，可能需先处理模式冲突。
