# 章节来源溯源与召回评测配对

召回评测需要 `(用户 cue → 正确章节)` 配对。离线重放前先量了一件事：**现有产品库能不能产出这种配对。** 结论是不能，本文记录证据、决策与仍未验证的部分。

## 1. 旧数据的配对能力（2026-11-12 实测）

产品库 `pudding_memory.db`：13,213 章，其中 11,547 章带 `SourceSessionId`，覆盖 39 个会话。

- `Chapters.SourceReference` 只有 7 行有值；`SourceReferences` 全表 14 行 ⇒ 没有 message 级来源
- 13,213 个 `CreatedAt` 互不相同 ⇒ 章节是逐条写入，不是批量作业产物

因此只剩「同会话 + 时间邻接」这一种办法。按该办法机械配对 10,967 对后测得的间隔分布：

| 分位 | 间隔 |
|---|---|
| 中位数 | 2.5 小时 |
| p90 | 23.5 小时 |
| 超过 1 小时 | 6,952 / 10,967 = 63% |
| 1 秒内 | 61 对 |
| 5 分钟内 | 815 对 |

结论：时间邻接产出的是「某条用户消息之后 2.5 小时写的一章」，**不构成因果配对**，只能当候选集，不能当 gold。可信评测规模上限是几百例。

## 2. 选哪个键：Turn 还是 Message

首次实现选了 Turn 级（`Chapters.SourceTurnId`），理由是「一个 Turn 恰好对应一条用户消息」。这个假设被数据推翻：

| 角色 | 带 `turn_id` 的行 / 总行 |
|---|---|
| agent | 5,493 / 7,842 = 70% |
| user | 342 / 8,314 = **4%** |

`turn_id` 主要打在 agent 行上，而章节要回指的 cue 是**用户消息**。因此 Turn 级来源在真实数据里基本 join 不回去。

改选 `ChatMessages.message_id`：该列 `NOT NULL`，且编排层本来就持有 `command.UserMessageId`（见 `ExecutionRunCoordinator` 构造执行请求处）。注意 `RuntimeExecutionIdentity.MessageId` 是**助手**消息 id，不能当 cue。

## 3. 已落地的链路

```
RuntimeDispatchRequest.MessageId
  → ToolInvocationRequest.InboundMessageId（可选）
  → ToolExecutionContext.InboundMessageId（可选）
  → ExperiencePackage.SourceMessageId / SavePreferenceAsync(sourceMessageId)
  → IMemoryLibrary.AddChapterAsync(..., sourceMessageId)
  → Chapters.SourceMessageId
```

`Chapters.SourceTurnId` 保留，语义降为 Turn 级分组/遥测。存量库由 `EnsureColumnAsync` 幂等补列，历史行保持 NULL——历史数据无法回填，这是设计选择而非缺陷。

## 4. 评测侧如何消费

独立仓库 `PuddingMemoryLab` 的配对器按三级优先取值，每条配对记录自己的 `binding`：

| 级别 | 依据 | 性质 |
|---|---|---|
| `message` | `Chapters.SourceMessageId` ↔ `ChatMessages.message_id` | 确定 |
| `turn` | `Chapters.SourceTurnId` ↔ `ChatMessages.turn_id` | 降级（覆盖率 4%） |
| `proximity` | 同会话时间邻接 | 候选 |

列集合用 `PRAGMA table_info` 探测，未迁移的库不会因缺列整体失败。

## 5. 仍未验证

运行中的 Core 是旧二进制，数据库尚未迁移（探针 `provenance_columns_present` 为空）。**「新列真的会被写入」目前是代码层面结论**，需重启后抽一条 `save_memory`，确认 `Chapters.SourceMessageId` 非空且等于当轮用户消息 id，才算运行时事实。

## 6. 教训

给一张表加「看起来显然」的外键列之前，先量目标列在真实数据里的**填充率**。本次漏了这一步，代价是一次多余的 schema 变更与一轮返工。
