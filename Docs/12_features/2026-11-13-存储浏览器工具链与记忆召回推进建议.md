# 存储、浏览器、工具链与记忆召回推进建议

建议先完成已提交修复的成套部署与产品验收，随后优先补交互后回读，再做 R1 动作前检查与 R2 语义重定位。存储页剩余布局和磁盘维护单独安排；记忆实验接入作为独立开发批次。当前最大的交付问题是动作执行、结果观测、回执判定三者之间仍有断点。

本文是代码级评审与建议。本轮核对了仓库源码和官方文档，未运行产品验收、清理文件、执行 VACUUM 或重启。515.8 MiB、9.27 GB、3.94 GiB 和实验 13ms 均沿用提问中的测量，执行前需重新采样。

## 1. 先修正三个判断

**R1 可以减少动作前状态问题，其覆盖率需要实验验证。** 可见、稳定、命中测试和自动等待能应对隐藏、动画与遮挡。它们无法单独修复错误的定位目标、过期 ref、坐标变换错误，以及应用对合成输入的处理。现阶段“解决七项中的五项”应列为待测假设。验收时逐条关联原始故障、复现页面和修复结果。Playwright 的 click 同时检查唯一目标、可见、稳定、接收事件、启用等条件，不同动作使用不同条件集合。[Playwright 动作检查](https://playwright.dev/docs/actionability)

**R2 已有可复用合同。** 当前 `DesktopLocator` 支持 Role、Label、Text、Placeholder、TestId、Exact、Nth 和 HasText。先核实这些描述符在驱动中的解析和唯一性检查，再补缺失语义，避免重建一套定位合同。Ref 仍应遵守 PageVersion，版本过期时不得把同一个 ref 套到新页面。源码见 [LocateContracts.cs](../../Source/Pudding.Contracts/Desktop/LocateContracts.cs)。[Playwright 定位器](https://playwright.dev/docs/locators)

**“记忆召回零集成”需要缩小范围。** 仓库已有 `IMemoryRecallService`、`MemoryRecallService`、Host 注册、ContextPipeline 依赖，以及已注册供工具调用的 `IRetrievalPort`。本轮未证明每条召回路径在正式配置下实际运行，也未证明 MemoryLab 新方案已接入。因此建议表述为“MemoryLab 的新召回方案尚未证明进入产品链路”。接入前应沿现有端口追踪消费者，再决定适配点。[召回合同](../../Source/PuddingCore/Abstractions/IMemoryRecallService.cs)、[Host 装配](../../Source/PuddingHost/Extensions/PuddingServiceCollectionExtensions.Runtime.cs)、[检索端口装配](../../Source/PuddingRuntime/RetrievalServiceCollectionExtensions.cs)

## 2. 第一批只完成部署与验收

通过 Guardian 构建部署与这些修复对应的源码版本。A3 涉及前端，需要构建并部署静态产物；重启已安装的旧包无法使新源码生效。WebView2 驱动随 Desktop 交付时，应同时核对 Desktop、Core、Bridge 和前端版本。

| 项目 | 产品验收判据 | 取红方式 |
|---|---|---|
| A1 输入回执 | 初值 ab，type cd 后实际为 abcd；缺值观测时回执 unverified，同一个操作不能因缺观测自动追加第二次 | 恢复旧判定应出现错误 failed；同时记录实际值和动作次数 |
| A2 工具诊断 | 已注册且有授权时 exposed=true；被 Agent 策略过滤时 registered=true、exposed=false；工具缺失时 registered=false | 去掉策略判断，受限 Agent 用例必须失败 |
| A3 protected | 保护表归入 protected、有独立颜色；分类占用与剩余项按同一来源核对，不重复相加 | 移除保护表映射或颜色后，对应分类或渲染断言失败 |

验收必须保存 operationId、页面版本、运行包版本、输入动作次数及必要截图。A2 的 exposed 表示可发现条件，运行时审批、参数合法性和资源可用性仍需真实调用验证。A3 金额和字节值以当次采样为准。

第一批完成条件为已加载版本可证、三个产品用例有回执、原故障可取红。构建成功和单元测试通过不足以替代这一批产品验收。

## 3. 第二批先补 C4 交互后观测

优先修改 `WebView2BrowserPage`、`WebView2DomClient` 和 `BrowserRuntimeDesktopSurface`，形成“动作一次 → 新观测 → 判定”的路径。当前 `ExecuteInteractionAsync` 丢弃 DOM 交互返回值，surface 的部分操作以空结果返回，上层因此缺少可用于验证的值。

- 回读 input、textarea、contenteditable、checked、selectedValues，区分空字符串和不可观测。
- 驱动内部用真实值比较期望，对外优先返回 matched、可观测标记、长度及观察版本。密码和其他敏感字段的回执遵循既有脱敏合同。
- 动作后节点替换时，使用有效语义定位器重新观测。目标不唯一、页面已导航或语义身份不确定时返回 unverified。
- 自动重试只覆盖确认未派发的等待与定位阶段。派发后的 type、提交、支付等操作应先查证状态；回执丢失或缺观测时返回 unknown/unverified。

最小用例覆盖 fill 后匹配、确实不匹配、空值、节点替换、密码脱敏和取消。把驱动回读替换为空值时，verified 用例必须取红。输入的确只派发一次也应有独立断言。

## 4. 第三批完成 R1，再补 R2

建议在已有 `PuddingBrowser.Automation` 内放动作条件与重试裁定，在 WebView2 驱动里提供真实 DOM 观测。DOM 脚本只返回事实，策略层决定是否等待或执行。时间预算沿用一次操作的绝对 deadline，取消贯穿全部等待。

| 动作 | 动作前最低检查 |
|---|---|
| click | 唯一目标、可见、可用、位置稳定、实际点击点接收事件 |
| fill/type | 唯一目标、可见、可编辑、启用；使用键盘输入时验证焦点落到目标 |
| check/select | 控件类型与状态可操作，并执行动作后状态回读 |

稳定性可先用连续帧几何比较实现。点击命中测试应接受目标及其可交互后代，并核对实际执行点。跨 frame、shadow DOM、屏幕坐标与 CSS 坐标转换需使用驱动支持的边界。DOM 命中测试无法证明宿主窗口、系统输入或应用事件过滤层已经成功。

最小可交付从两个会取红的页面开始：动画停止后只点击一次；遮罩持续存在时零派发并报告条件超时。随后增加失焦输入、禁用控件和取消等待。

R2 再覆盖一次重渲染后语义目标恢复，以及同名目标增加后明确报告歧义。记录原定位描述、新目标和 PageVersion。候选评分不得直接成为自动点击许可，当前版本的唯一性和动作检查仍须通过。

## 5. B1～B3 与存储页的明确建议

| 决策 | 建议 |
|---|---|
| B1 provider_balance | 作为可选的运维工具，仅授予确实需要余额诊断的 Agent，并走现有插件加载。账户余额可能属于敏感运营信息，需要发送者授权。UI 查询继续使用现有服务；工具尽量复用相同服务，避免自行解析配置与 UI 形成两条权威路径 |
| B2 9.27 GB 目录 | 优先清理已证明可再生的构建、候选包与重复隔离数据。保留小型报告、测试输出、补丁、指纹和无法重现的证据。先列进程路径、Guardian 活跃事务及回滚目录引用，再决定每个子目录，禁止整目录盲删 |
| B3 VACUUM | 安排独立维护窗口。3.94 GiB 空闲页能继续供 SQLite 复用，是否立即回收由磁盘压力决定。外部维护程序执行更符合当前宿主持写连接的条件 |
| C1 页面滚动 | 采用页面固定可用高度、Tab 内容内部滚动。按实际视口和头部计算高度，验证 900 高度、缩放、键盘导航与表格分页；无需把全站布局一起重构 |
| C5 空间估算 | 保留来源、采样时间、库身份和估算标记，防止快照分类与数据库页统计重复相加。rowcount-sample 的分类面积应明确为估算，不能当作精确的回收预测 |

VACUUM 在 SQLite 层面需要满足事务与锁条件，“必须进程外”属于当前产品维护方式。建议流程为停止受理与执行、Guardian 停 Core、确认连接释放、创建并验证一致备份、外部执行、检查完整性与关键表计数、启动并验健康。确认磁盘空间满足临时重建需求。不可在主库仍活跃时复制单个数据库文件作为备份，WAL 与主库按一致性规则处理。[SQLite VACUUM](https://www.sqlite.org/lang_vacuum.html)

dbstat 是否可用由编译选项和实际连接决定，不能从 SQLite 版本号推定。用产品实际 SQLite provider 创建独立测试库，记录 sqlite_version、PRAGMA compile_options，并执行 dbstat 查询；只运行系统 Python 的 sqlite3 无法证明产品 e_sqlite3 的能力。本轮保留“子代理已测、尚未独立复现”的状态。[SQLite DBSTAT](https://www.sqlite.org/dbstat.html)

## 6. 记忆实验接入单独安排 S1～S5

先完成一张现状调用图，标明 ContextPipeline、潜意识召回、工具检索分别消费哪个端口。新 BM25、向量与 RRF 方案应适配已有产品路径，配置切换具有明确单点。

| 阶段 | 交付与通过条件 |
|---|---|
| S1 合同 | 明确 query、workspace、Agent、会话范围、授权过滤、deadline、取消、证据与引用字段，复用已有合同能表达的部分 |
| S2 独立实现 | 本地索引读取、BM25、向量候选、RRF、确定性排序及去重。不同路数值分数不得未经校准直接相加 |
| S3 离线评测 | 固定语料、标注 query、索引与模型版本；比较现有基线和新方案的 recall@K、MRR 或 nDCG、延迟分位与内存，报告样本数及相关性标注方式 |
| S4 集成适配 | 接入真实存储和授权，在复制数据上证明跨 workspace/Agent 无泄露；查询失败、取消和索引过期有明确结果 |
| S5 产品验收 | 真实 Agent 问题能在实际发给模型的上下文中找到预期来源；记忆与当前历史同源去重；故意移除召回结果时验收失败 |

实验 13ms 只能描述对应实验设置。产品测量应包含查询向量、存储访问、授权过滤和上下文装配，并分别报告冷启动与热查询。recall@K 用于衡量检索，另外记录最终回答引用的来源和事实正确性。

## 7. 下一轮建议的完成边界

下一轮只要求 A1～A3 部署验收、C4 最小回读闭环和 R1 遮罩/动画两个复现用例。B1 仅对授权策略作决定，B2 先形成可删除清单，B3 独立维护安排。记忆线先交付现状调用图与 S1 合同差异，之后独立排期。

完成报告逐项给出已加载版本、真实操作证据、取红结果和剩余缺口。未运行的产品场景继续标为待验收。
