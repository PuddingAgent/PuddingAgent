# PA-03：持久验收任务、证据快照与完成事件

依赖 01 的跨轮账户、02A 的受权任务身份、07A 的可靠事件/任务通道；遵守[总则](Agent组件化任务书-总则与依赖-2026-11-05.md)。先做只读模型评审，完整验收子 Agent 是后续实现选项，不能成为首个闭环的必要条件。

本任务的领域实现与假端口测试可独立推进；作为插件能力接入或驱动完整 Goal 时，必须满足总则的基础设施及 07A/07B 通用功能插件门禁。Review provider 是扩展贡献之一，不是只能在 Agent 工具回调中使用的特例；不得绕过公共资源/事件端口调用宿主私有服务。

## 1 现状与任务目标

`IModelEvaluationApi.ReviewAsync` 已接入插件，返回结构化检查和模型来源；它评估调用者提供的证据，**不证明证据来自现场**，也不自动续跑 Goal。目前 CallId 是关联标识，不是持久幂等任务。已有 `IGoalIterationVerifier`、`GoalEvidenceCapsule` 和受控检查报告，不能用 LLM 回答覆盖这些权威结果。

本任务交付持久 Review Job：从已经提交的轮次结束事实受理，冻结目标/标准/交付物版本，运行评审，记录结论及实际资源用量，发布完成事实供 04 消费。Job 完成只说明评审已结束，不说明 Goal 完成。普通聊天默认不建 Job。

## 3 Job 契约与身份绑定

拟新增 `IReviewJobsApi.SubmitAsync(SubmitReviewRequest, ct)`、`GetAsync(ReviewJobRef, ct)`、`CancelAsync(CancelReviewRequest, ct)`。Submit 只做有界校验和持久受理，返回 JobId/AcceptedSequence，不等模型完成。Observe 复用 07A 事件游标，禁止无限阻塞 IPC 工作槽。

Review 的逻辑唯一键必须包含：Workspace、父 Work/Goal、ActivationEpoch、IterationNo、ObjectiveVersion、AcceptanceContractVersion、交付物集合 hash、ReviewPolicyVersion。`ReviewId` 是这组绑定的稳定标识；每次实际模型尝试另有 AttemptId。重复完成事件只能受理同一个 Job；同 OperationId 换输入必须冲突。

冻结输入 `ReviewInputSnapshot` 至少包含：

- 原始目标与当前验收条件，保留各自版本及来源；不能把 Agent 改写的自我评价当作用户标准。
- 对应 canonical TurnId、TerminalSequence、产物引用、内容哈希、采集时间、生产者、证据类别、受控检查报告引用与退出码。
- EvidenceComplete、缺失/截断原因、分页或大内容读取引用；不能因摘要省略失败结果而假装证据完整。
- 模型策略版本、提示版本、预算账户、Job deadline、是否必需评审；不包含密钥或可修改宿主服务。

第一版证据读取只支持受权的 canonical 输出、受控检查报告与已登记产物。任意文件路径、全量 transcript、插件提供的裸字符串只可标为 `caller-supplied`，不能升级为 verified。产物改变即创建新的输入版本，旧 Job 结果保留审计，但不能用于新版本结算。

## 4 状态、失败与资源寿命

Job 状态为拟定的 `Pending/Running/Waiting/Completed/Failed/Unknown/Cancelled`，属于评审任务自身，**不得映射成一套新的 GoalPhase**。每次 claim 带 owner epoch、lease deadline 与 expected revision；旧 Worker 迟到提交必须被拒绝。

结果拆成两层：`ReviewFinding = Satisfied / NeedsWork / NeedsUser / Inconclusive` 是建议；证据级别区分 ModelAssessed、Observed、CheckVerified。模型给 Accept 且引用缺失、未知 criterion、证据版本不匹配，结果必须降为 Inconclusive，不能默认为成功。`Satisfied` 仍交给既有结算规则核对必需检查。

模型执行前从 01 根账户创建 **Job-owned scope**，其寿命不依附已经结束的主轮 dispatch。根取消/授权撤销后停止新尝试；已派发 provider 继续由资源层排空。Job 重试需策略允许、额度足够且先核清上次效果；Unknown 不因租约超时自动再付一次钱。

Worker 重启可接管未派发 Pending Job；Running 的模型调用状态先调和。取消后迟到评审不得变 Completed，实际用量仍入账。模型不可用/超时/JSON 不合法分别保存 reason code；必需评审失败时停在可解释的等待/阻断状态，不能默认放行。插件卸载是否取消 Job 由 07 的所有权策略决定，不能静默换 owner 继续。

## 5 调度链路与实施步骤

1. 冻结 Review Job DTO、领域端口和逻辑唯一键；假存储/假模型独立实现原子受理、claim、提交。
2. 在单一事务中记录 Job 与待投递事件；07A 投递失败可重放，重复投递不重复调用模型。
3. 从已提交 canonical 完成事实取证，不从 UI、临时流 delta 或 Hook “执行完毕”文本取证；既有 settlement worker 看到必需 Job 未完成时保留候选，不写终态。
4. 评审器使用已绑定 `IModelEvaluationApi`，默认无写工具。未来可选子 Agent reviewer 也受 02 的子级权限/预算，不能触发自身完成后的再次评审。
5. 提交回执前校验 claim epoch 和输入版本，发出 `review.completed` 领域事实；04 消费时再校验当前 Goal/产物版本，避免检查与使用之间的竞态。
6. SDK/插件只公开受权 Submit/Get/Observe/Cancel；插件请求没有可任意设置的 parent scope、owner 或 privileged 标志。

## 6 验收矩阵

| 负例 | 必须观察到的结果 |
|---|---|
| 同一 turn-completed 重放三次，Worker 重启一次 | 同一 JobId，允许的模型尝试数不增加；受理/结算分别幂等 |
| 评审期间用户改目标、改标准或替换产物 | 旧结果标 stale，不能完成新 Goal |
| 只有 assistant 写“测试通过”，没有测试报告 | ModelAssessed，不能产生 CheckVerified |
| 必需条件为空、引用未知 evidence/criterion、证据截断 | Inconclusive，不出现 vacuous pass |
| 主轮结束已 Dispose 原 scope | Job 用新作用域且同一根账户；预算归属连续 |
| 根取消、插件卸载、旧 claim 迟到、provider 忽略取消 | 无后续续跑，账目可核对，资源不提前释放 |
| reviewer 自己的 turn 完成事件 | 不创建递归 Review Job |
| 模型拒绝/弃权与 provider 网络失败 | 区分 finding 与执行状态，不 catch 成统一成功 |

独立构建 `Source/PuddingReviewsTests/PuddingReviewsTests.csproj` 并执行新 DLL。S5 用实际事务库验证 Job/outbox 同生共死，测两 Worker 竞争 claim；恢复测试要销毁并重建进程内服务。变异去掉唯一键、版本校验或证据来源校验，分别必须让对应测试变红。接入后回归现有 `GoalSettlementWorkerCheckIntegrationTests`。

## 7 DS-PA03-A：已有模型评审 API 的离线消费示例

本叶任务**不依赖未来 Review Job 合同**，可在主代理签发 ContractRelease 后先行施工；本次编写任务书不等于已派发。冻结消费现有 `IModelEvaluationApi` 和 `ModelEvaluationsClient`，不改它们。精确白名单：

```text
Samples/ModelEvaluationClient/ModelEvaluationClient.csproj
Samples/ModelEvaluationClient/Program.cs
Samples/ModelEvaluationClient/EvaluationDemo.cs
Samples/ModelEvaluationClient/code_map.md
Tests/ModelEvaluationClient.Tests/ModelEvaluationClient.Tests.csproj
Tests/ModelEvaluationClient.Tests/EvaluationDemoTests.cs
Tests/ModelEvaluationClient.Tests/code_map.md
```

固定入口：

```csharp
public static Task<int> RunAsync(
    string[] args, IModelEvaluationApi api,
    TextWriter output, TextWriter error, CancellationToken ct = default);
```

命名空间 `Pudding.Samples.ModelEvaluationClient`，类 `EvaluationDemo`。仅接受 `classify <requestJson>` 或 `review <requestJson>`，严格两个参数；JSON 分别按已有 `ClassificationRequest/AcceptanceRequest` 反序列化，camelCase 属性、未知成员拒绝，不修正/Trim 内容，不读取文件或 stdin。无命令、非法 JSON、null 请求或缺失 Input/Options 返回 2，零 API 调用；领域合法性仍由 API 判断，不复制分类/证据校验器。

通过 SDK `ModelEvaluationsClient` 调用一次对应方法，options 原样传入。stdout 为原回执 camelCase JSON，保留 Availability、Checks、Provenance、ReasonCode；所有正常回执（包括 Abstain/Degraded、Reject）返回 0，不能把拒绝评审误当传输失败。捕获 `ModelEvaluationException` 仅向 stderr 输出 code，exit 1；调用方取消 exit 130；其余异常不吞。CallId 不自动生成、不重用请求进行重试、不作持久送达保证。Program 固定 stderr“这是可注入 IModelEvaluationApi 的离线示例；请由上层提供已授权的 API。”并 exit 2。

sample 只引用 SDK，无新包；test 用 MSTest.Sdk/4.0.1，仅引用 sample。测试两命令各一次、原样中文/空格、参数错零次、Abstain/Degraded/Reject 保真、未知字段拒绝、异常文本不泄漏、取消无后续调用。不得写入假“verified”字段。
