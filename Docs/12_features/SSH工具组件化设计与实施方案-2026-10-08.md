# SSH 工具组件化设计与实施方案

本文定义 SSH 的施工边界与交付合同。首个可用切片是：用户配置一台已验证指纹的 Linux 主机，获授权的 Agent 能发现主机、验证连接、执行有截止时间的非交互命令，并收到可诊断、体积有界的结果。

SSH 的连接、执行与文件传输全部运行在 Core。Desktop 继续负责窗口与 Core 生命周期，不增加 SSH 客户端或业务配置依赖。按[组件化交付规程](../10_conventions/组件化交付规程.md)先完成独立组件 S1–S4，S5 才改 Runtime、Host 与解决方案。

## 1. 基线与设计裁定

### 1.1 可复用入口

| 关注点 | 现有位置 | SSH 的接法 |
|---|---|---|
| Tool 元数据、参数、执行结果 | `Source/PuddingCore/Tools/PuddingToolContracts.cs` | Runtime 薄适配器继续使用 `PuddingToolBase` 与 `[Tool]` |
| 工具发现与装配 | `Source/PuddingRuntime/Tools/Platform/PuddingToolServiceCollectionExtensions.cs` | S5 注册 `IPuddingTool`，由既有目录与 `search_tools` 发现 |
| Agent 授权、能力、网络/沙箱边界 | `Source/PuddingRuntime/Services/AgentFirewall.cs` | 每次调用继续经过统一执行入口 |
| 命令审批快路径 | `Source/PuddingRuntime/Tools/Approval/ToolApprovalCommandFirewall.cs` | 保留本地行为；SSH 使用自己的目标与参数，不能加入本地安全命令集合 |
| Agent 私有目录 | `Source/PuddingCore/Configuration/PuddingDataPaths.cs` | Runtime 用 `AgentInstanceRoot` 解析私有 .ssh；当前用户 home 使用平台 API |
| 展示与工具结果限额 | `Source/PuddingRuntime/Tools/Presentation/`、`Services/AgentExecution/ToolResultContextPolicy.cs` | 投影结构化 SSH 结果；组件预先限制输出，模型上下文层再限制预览 |

旧[调研报告](../07_architecture/71PuddingSSH远程执行能力调研报告.md)仍作为研究来源；本文是施工依据。报告的“约 12 小时”“唯一成熟库”“2024.2.0 最新版本”和直接复用本地白名单不作为实施承诺。

### 1.2 首期裁定

1. 新建 `PuddingSsh` 叶子组件，目标 `net10.0`，生产 `ProjectReference=0`；公开合同不泄露第三方客户端类型。
2. 首期采用每次操作独占连接，操作结束即释放。连接池待测量证明有必要时再加，避免最初就引入跨 Agent 共享凭据、并发通道与失效连接问题。
3. 工具仅接受已登记主机目标；认证复用当前 Core 运行用户的 `.ssh` 或配置绑定的 Agent 私有 `.ssh`。不引入 KeyVault，不接受工具参数覆盖目录、私钥路径或密码。
4. 主机信任优先复用所选目录的 `known_hosts`，也可显式配置 fingerprint pin；未知或变化的密钥拒绝连接。Agent 不拥有自动接受指纹的工具。
5. 首个执行环境为 Linux/POSIX 非交互命令，无 PTY；Windows OpenSSH 的 PowerShell/CMD 编码与引号合同另行交付。
6. 本地与远程路径分别建模；远程 `cwd` 是执行语义，不是沙箱。任意 shell 可以访问账号有权访问的其他路径，安全隔离最终由远程账号权限落实。
7. 任意远程命令不自动重试。命令已提交后遇到断线、超时或取消，显式报告远端状态可能未知。
8. 首次接入不修改前端。使用主机配置文件、既有 `.ssh` 文件和工具卡片；专门主机管理页面后续独立交付。

## 2. 交付范围

| 切片 | Agent 工具 | 范围与验收终点 |
|---|---|---|
| A：首个可用版本 | `ssh_hosts`、`ssh_test`、`ssh_execute` | 当前用户/Agent 私有 .ssh、known_hosts 或显式 pin、无口令私钥、POSIX exec、有界双流、超时取消、错误码、独立测试与真实协议探针、Core 接入 |
| B：文件传输 | `ssh_upload`、`ssh_download` | 单文件 SFTP、字节限额、临时文件与发布、覆盖控制、路径检查、独立测试后接入 |
| C：长任务 | `ssh_start`、`ssh_wait`、`ssh_read`、`ssh_cancel` | Core 内远程作业管理、输出游标、阻塞等待、归属校验、停止时回收连接 |
| D：管理与优化 | 主机配置页面、按测量决定连接复用 | 前端版本递增与部署验收；配置授权、原子保存、指纹管理、撤销与轮换 |

切片 A 不提供交互式 shell、SSH 隧道、端口转发、跳板机、agent forwarding、主机扫描、自动 `sudo` 或密码提示应答。文件传输使用 SFTP，不采用旧 SCP shell 协议。

## 3. 技术选型与开工探针

默认选 SSH.NET，固定候选包版本 `2026.0.0`，不使用浮动版本。该版本发布说明包含 .NET 10 目标与协议安全修复；不能沿用旧报告的版本假设。[官方发行说明](https://github.com/sshnet/SSH.NET/releases/tag/2026.0.0)

| 方案 | 结论 | 理由 |
|---|---|---|
| SSH.NET | 首选，须通过下面的实际探针 | 提供 exec/SFTP；既有研究可利用，纯托管依赖便于 Windows 分发 |
| Tmds.Ssh | 备选 | 已存在独立 .NET SSH 库；如首选无法满足取消或输出资源门禁，在 S1 内重新裁定，不引入双运行时实现。[官方项目](https://github.com/tmds/Tmds.Ssh) |
| 系统 `ssh.exe`/`scp.exe` | 不作为专用工具底座 | 系统安装、环境配置、交互提示与进程管理增加产品依赖；当前 Shell 调用能力仍保留 |

S1 内必须验证：

- 指定版本在 `net10.0` restore/build；检查直接与传递依赖的已知漏洞，严重未修复问题阻断该版本接入。
- 普通私钥认证、加密私钥明确报口令需求；当前用户/Agent 私有目录解析与 known_hosts 明文/hash 记录；握手前安装验证回调，未知/错指纹确实发生拒绝。
- `ConnectAsync` 与命令启动阶段的截止时间；不能因方法带 Async 后缀就假设所有阶段都无同步阻塞。
- 命令取消、断线、服务端忽略信号，以及 stdout/stderr 同时大量输出。
- 收集器与第三方内部缓冲的实际峰值；禁止“先完整取 Result，再截断”的实现。

SSH.NET 的 `SshCommand` 提供输出流、可空退出码和取消接口；取消只是发送信号并可能在无应答时结束客户端等待，因此不能承诺远程进程已经消失。[版本固定的源码](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/SshCommand.cs)

如选定库未通过资源或取消门禁，先在组件内部解决或改选库，不接入 Core、不 fork 补一个 TFM，也不留下兼容双栈。

| `Source/PuddingSsh/Diagnostics/` | 稳定错误码与纯函数异常分类器，数据仅 BCL DTO |
| `Source/PuddingSsh/code_map.md` | 本组件关键文件索引 |

独立组件不得引用 `PuddingCore`、`PuddingRuntime`、`PuddingPlatform`、`PuddingHost`、Desktop、EF Core、ASP.NET Core 或 Roslyn/MSBuild。DI、DataRoot/用户 home 解析、Agent 主体、审批与持久化由引用方承担；组件只接收已经授权、解析并冻结的请求。

公开的最小端口为 `ISshClient`（Test/Execute，B 扩展传输）、`ISshIdentityProvider`（读取宿主冻结的 identity 文件，不搜寻其他身份）、`ISshTransportFactory`/`ISshTransportSession`（可注入假连接）。目录发现与 Agent 身份映射在 Runtime，组件接收绝对路径和冻结的信任集合。接口不得返回 `SshClient` 或把第三方事件类型暴露给消费者。

## 5. 主机配置、可见性与目标冻结

配置位于 `<DataRoot>/config/ssh/hosts.json`，只保存主机授权、目录模式、identity 文件名、信任来源与执行限额；密钥继续留在所选 `.ssh`。首期读取 `known_hosts` 的普通精确主机记录及 hashed-host v1，也支持用户显式配置 SHA256 pin。OpenSSH config 的完整解释器不进入首期，具体支持边界见 §6。

```json
{
  "schemaVersion": 1,
  "hosts": [
    {
      "id": "dev-linux",
      "displayName": "开发 Linux",
      "enabled": true,
      "host": "192.0.2.10",
      "port": 22,
      "username": "deploy",
      "shellKind": "posix",
      "sshDirectory": {
        "scope": "current_user"
      },
      "identityFile": "id_ed25519",
      "hostKey": {
        "source": "known_hosts"
      },
      "allowedWorkspaceIds": ["default"],
      "allowedAgentIds": ["<持久 Agent ID>"],
      "defaultCwd": "/srv/pudding-test",
      "limits": {
        "connectTimeoutSeconds": 15,
        "operationTimeoutSeconds": 60,
        "maxOperationTimeoutSeconds": 600,
        "maxOutputBytes": 65536,
        "maxConcurrentOperations": 2
      }
    }
  ]
}
```

示例地址为占位，不是可用连接配置。`scope` 可取 `current_user` 或 `agent_private`，作用域由管理配置决定，不能由 Agent 每次执行切换；`agent_private` 根由持久 Agent 身份确定。显式 pin 的替代配置为 `hostKey: {source:"pin", algorithm:"ssh-ed25519", sha256:"SHA256:<经核对指纹>"}`。主机定义须通过重复 ID、端口范围、scope/identity 文件名、限额、信任源互斥与账号非空校验；非法配置产生 `ssh.config_invalid`。

- `ssh_hosts` 仅列出当前 Workspace 与持久 Agent 主体有权访问的启用主机；两类 ACL 都要匹配，空集合不代表所有主体。子代理使用宿主提供的 `ConfigurationAgentInstanceId` 确定配置主体，再受委派能力边界限制，不允许 Agent 参数自报主体。
- 调用开始重新验证可见性。伪造 `host_id` 与其他主机的 revision、不可见目标均在连接前拒绝；对无权主体不披露该主机是否存在。
- `host_revision` 为执行相关配置规范化后的 SHA256：地址、端口、账号、解析后的目录作用域、identity 文件名、有效信任集合摘要、shell、cwd、ACL 与限制都纳入；排除显示名称和秘密值。每次操作读取已选私钥，无连接池、不缓存已解析凭据。
- 有权限的调用者取得 `target`：`host_id / host_revision / host / port / username / trust_revision`；`trust_revision` 为匹配目标的有效主机公钥/撤销集合摘要。执行时全部匹配权威配置与信任快照，不能作为覆盖值；实际握手验证的 fingerprint 在结果中返回。
- 目标字段进入既有审批参数 hash；因此相同命令在另一账号、主机或配置 revision 下不能复用旧审批。
- `target` 复制自查询结果仍是调用者输入。执行器必须先匹配权威配置，然后冻结快照；审批通过之后发生配置变化，执行前校验 revision，返回 `ssh.target_changed`，重新发现再审批。连接使用同一快照，不再次按别名解析另一台机器。
- Pudding 主机配置保存采用原子替换，每次操作读取完整有效快照；外部修改 `.ssh` 时遇到不完整/不支持的记录应明确拒绝，不退回任意信任。热变更影响后续操作；禁用/删除主机首期不自动终止正在运行的远程命令，UI 必须说明这一语义。

## 6. 凭据与主机验证

### 6.1 跨平台目录与归属

| 模式 / 平台 | 目录 | 约束 |
|---|---|---|
| `current_user` / Windows | 当前 Core 用户 profile 下 `.ssh`，通常 `%USERPROFILE%\.ssh` | 用 `Environment.GetFolderPath(UserProfile)`，空值时才检查当前进程 USERPROFILE；不硬编码盘符或用户名 |
| `current_user` / Linux、macOS | 当前 Core 用户 home 下 `.ssh`，通常 `$HOME/.ssh` | 平台 UserProfile API，空值时才检查 HOME；不假设 home 必在 /home 或 /Users |
| `agent_private` / 任意 OS | `Path.Combine(dataPaths.AgentInstanceRoot(configurationAgentId), ".ssh")` | 既有持久 Agent ID，由宿主决定；临时子代理继承同一主体，不新建身份、不复制密钥 |

仅接受非空、绝对 home 路径；解析失败返回 `ssh.directory_unavailable`，不能使用 cwd、仓库目录或另一个用户的 home。WSL 中运行 Core 才用该 Linux 用户的 home；Windows Core 不自动跨到 WSL 的 `.ssh`。当前用户指 Core 的 OS 身份，服务账号与桌面登录用户可能不同。

Windows 用户配置位置见 [Microsoft OpenSSH 文档](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)；Unix 的用户配置为 `~/.ssh/config`，系统配置与用户配置有各自位置和优先级，见 [OpenSSH ssh_config](https://man.openbsd.org/ssh_config)。首期 Pudding 只复用所选用户/Agent 目录，不读取系统服务端密钥，不自动加载系统级客户端配置。

当前用户目录默认只读，Pudding 不建目录、不改 key/config/known_hosts。Agent 私有目录由用户配置并准备，后续如允许 Agent 调用已有 shell 生成 `ssh-keygen`，需受既有私有目录写入审批约束：生成私钥留本地，只把公钥提供给用户安装，不能复制当前用户私钥来初始化。不同 Agent 不允许穿越彼此的私有目录。

### 6.2 私钥认证与 OpenSSH 配置边界

切片 A 直接读取配置中 `identityFile` 指定的无口令私钥；可复用 `id_ed25519`、`id_rsa` 或用户已有其他文件名，但不枚举并逐个尝试全部私钥。文件名相对所选 `.ssh`，禁止 `..`、绝对路径和目录/文件 symlink/reparse point 逃逸。选定文件不可用就明确报错，绝不回退到另一作用域。

Windows 检查 ACL，Unix 检查目录/私钥 owner 与权限；私有目录建议 700、私钥 600，对越权读取给出修复指引，不自动 chmod/改 ACL。读取与打开间的竞态需在实际文件句柄/最终路径上校验，不能只检查字符串前缀。认证材料仅在内存中交给第三方库，连接释放时销毁认证对象；错误、结果和审计不能回显私钥或路径。

**加密私钥首期明确返回 `ssh.passphrase_required`**，不把口令放进 JSON、Agent 工具参数或日志，不要求解密/改写用户原密钥。若现有环境只有加密私钥，使用 Agent 独立测试密钥或在后续专门切片增加系统 ssh-agent 认证：Windows named pipe 与 Unix SSH_AUTH_SOCK 分别验证，不能因为系统 agent 有密钥就宣称 SSH.NET 已能使用。这不阻断无口令私钥路径施工。

`.ssh/config` 中已有 Host 别名并不等于 Pudding 已授权远端主机。首期用户将 HostName/User/Port/IdentityFile 对应值登记进 Pudding hosts.json，Pudding 复用实际密钥与 known_hosts；不手写一套不完整解释器来默默忽略 Include/Match/ProxyCommand/ProxyJump。完整 config 导入可独立交付，发现不支持项须明确报告；不执行 config 中的本地命令。

### 6.3 主机信任

`source=known_hosts` 从所选 `.ssh/known_hosts` 读取有效目标记录；支持明文精确名称、逗号分隔名称和 `|1|salt|hash` 记录。22 端口以 host 匹配，非默认端口用 `[host]:port`，IPv6 同样保留 bracket 语义；hashed-host 按 OpenSSH HMAC-SHA1 的 host token 验证，公钥按原始 blob 比较。不得把 DNS 解析 IP 的记录替代主机名记录而扩大信任。

首期普通匹配不支持通配/否定模式和 host certificate/CA。遇到相关记录无法安全解释，返回 `ssh.known_hosts_unsupported`，给出显式 pin 或精确记录配置指引。`@revoked` 的精确/hash 匹配明确覆盖普通许可并拒绝，不能忽略撤销标记；匹配目标的语法/公钥非法也拒绝。实现须以真实 OpenSSH 生成的 hashed 记录及撤销 fixture 验证，不靠自己生成的样例自证。

`source=pin` 使用用户事先核对的 SHA256 指纹；两种 trust source 互斥，不能读不到 known_hosts 就自动转入 pin 或首次信任模式。每次握手均在认证之前安装默认拒绝回调，只有匹配已冻结算法/公钥集合或 pin 才继续；不依赖库默认信任值。[SSH.NET HostKeyEventArgs 源码](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/Common/HostKeyEventArgs.cs)

未知主机返回 `ssh.host_key_untrusted`，密钥变化返回 `ssh.host_key_mismatch`，撤销返回 `ssh.host_key_revoked`，附公开 fingerprint 与用户核对指引。不得自动写 known_hosts、自动接受新密钥或重试弱算法。有效信任集合变更参与 revision，审批后发现变化返回 target_changed。

## 7. Agent 工具合同

### 7.1 `ssh_hosts`

Low、无网络副作用；参数无主机地址过滤覆盖。返回可见主机的 `target`、display name、shell kind、默认 cwd、公开限额、`identity_scope` 与可用状态；不返回私钥路径/内容、其他 Workspace/Agent ACL 列表。没有主机时显式给出配置指引。

### 7.2 `ssh_test`

High + `RequiresNetwork`；执行 DNS/TCP/SSH 握手与认证，不执行 shell、不写远端文件。请求包含完整 `target`，返回经过验证的目标、各阶段耗时及认证成功状态。以连接有副作用处理，走现有审批机制，不因名称“test”被归入本地构建快路径。

### 7.3 `ssh_execute`

High + `RequiresNetwork | RequiresShell`，通过常规工具发现按需加载。

```json
{
  "target": {
    "host_id": "dev-linux",
    "host_revision": "<ssh_hosts 返回值>",
    "host": "192.0.2.10",
    "port": 22,
    "username": "deploy",
    "trust_revision": "<ssh_hosts 返回的有效信任集合摘要>"
  },
  "command": "uname -a",
  "cwd": "/srv/pudding-test",
  "timeout_seconds": 60,
  "max_output_bytes": 65536,
  "reason": "确认测试主机环境"
}
```

`command` 必填，UTF-8 最多 16 KiB，拒绝 NUL；`cwd` 省略时使用主机配置默认值，指定时必须是 POSIX 绝对路径，拒绝 NUL/控制字符。不开放 env、stdin、shellKind 覆盖、自动 `sudo` 或 PTY。有效超时取请求、主机最大值与 `ExecutionDeadlineUtc` 的最小值；限额只能缩小，不得扩大。

执行封装以 POSIX 单引号规则编码 cwd，使用 `cd -- <quoted cwd> && <原始 command>`；实际精确字符串在审批前即可确定。`cd` 失败不得继续执行；不会在本地 shell 中拼接地址和命令。远端由目标账号默认 POSIX shell 处理 exec 字符串，不宣称支持所有 shell 方言。

结果合同示例（组件 DTO，Runtime 负责映射）：

```json
{
  "status": "completed",
  "host_id": "dev-linux",
    "host_revision": "<冻结 revision>",
  "verified_host_key_sha256": "SHA256:<本次握手验证通过的指纹>",
  "exit_code": 0,
  "exit_signal": null,
  "stdout": "Linux ...",
  "stderr": "",
  "captured_bytes": 10,
  "received_bytes": 10,
  "output_truncated": false,
  "execution_state": "exited",
  "retry_safe": false,
  "error_code": null,
  "phase": "completed",
  "duration_ms": 120
}
```

退出码在没有收到服务端 exit-status 时为 null，不能伪造为 0。状态至少包含 `completed / failed / timed_out / cancelled / unknown`；`execution_state` 为 `not_submitted / submitted / exited / unknown`，明确区分连接失败和已执行但结果丢失。

现有外层 `ToolExecutionResult.ExitCode` 为非空 int：成功仅在已确认退出码 0 时映射为 0；非零远端码映射为失败并保留结构化原码；未收到远端码时外层用通用失败值，真实 `exit_code:null` 留在 JSON `Output` 中。不为 SSH 改造整个工具结果合同，也不把 stderr 非空自动判为失败。结构化 JSON 输出在映射后仍必须符合总体体积限额。

## 8. 审批、安全与审计

每次执行依次经过：既有能力/审批与资源门 → SSH 主机 ACL/revision 验证 → 远程命令不变量 → 并发准入 → 凭据 → 主机验证 → 命令提交。

- 远程目标、账号、revision、完整 command、cwd 与执行限额均在审批参数中。reason 是目的说明，不是授权证据；借用本地工作区 grant 不扩大远程访问权限。
- 首期 SSH 不增加本地 `ToolApprovalCommandFirewall` 白名单。`dotnet`/`git`/`ls` 名称相同不代表远程生产环境可自动放行；可复用规则只能匹配 SSH 工具及精确目标参数。
- 框架的 Yolo/完全访问模式仍按既有规则执行，SSH 不新建反向审批机制；但主机 ACL、fingerprint、配置 revision、并发与截止时间检查始终执行。
- 新增 `SshRemoteCommandPolicy` 放在 Runtime，组件无需了解 Agent 权限。首期对明显重启/关机、账号权限升级、磁盘破坏与强杀命令做确定性拒绝；复杂脚本、替换与解释器调用不能靠正则证明安全，走既有审批，最终权限由专用远端账号控制。拒绝规则须有单独稳定因果码，不能把它写成完整 shell 安全解析器。
- 配置文件与私钥按管理资源处理，运行时 `ssh_*` 工具均无编辑能力。任意本地 shell/file 工具若已获配置写权限属于该主体的更广授权，SSH pin 不能抵御被授权修改配置的主体。
- 自动审批票据、参数 hash 与 callId 沿用现有合同。输出内容来自远端，作为不可信工具数据处理，不作为新用户指令。

审计记录 `trace/session/execution/callId`、host ID、revision、目标账号、identity scope、command hash、phase、耗时、退出码/信号、字节统计、错误码、是否提交与是否可安全重试。普通诊断日志不写完整命令、stdout/stderr 或私钥路径；框架既有工具参数记录包含命令，因此明确禁止在命令字符串内嵌凭据，验证集用秘密哨兵检查错误和输出脱敏。私钥结构标记/已知认证材料匹配脱敏在有界结果进入模型、展示与持久化之前发生，不承诺识别远端任意未知秘密。

## 9. 并发、输出、超时与重试

### 9.1 默认预算

| 资源 | 默认 / 上限 | 语义 |
|---|---|---|
| 建连（DNS、TCP、握手、认证） | 15 秒 | 统一建连 deadline，不能每阶段独立叠加 |
| 单次操作总时长 | 默认 60 秒，上限 600 秒 | 从组件受理起包含排队、建连与执行；还受 Runtime deadline 限制 |
| 每主机并行操作 | 2 | 独占连接；按主机及 revision 管理，不跨账号复用 |
| Core 总并行操作 | 8 | 统一信号量限制，排队可取消 |
| 等待队列 | 32 | 满额立即 `ssh.busy`，不创建无界连接任务 |
| stdout + stderr 捕获 | 默认合计 64 KiB，硬上限 256 KiB | 增量 UTF-8 解码，截断不破坏字符；模型层预览可进一步缩小 |
| 操作清理宽限 | 2 秒 | 属于资源回收，不延长业务执行许可；超过后关闭独占连接 |

stdout/stderr 同时排空；捕获满后继续计数并丢弃额外输出，直到执行终止或 deadline。不把输出满额当作命令成功，也不为了读后续输出重新执行命令。无序的两个 stream 不宣称具有统一精确时序。

禁止 `RunCommand` 后读取整份 `Result/Error`，禁止 stdout/stderr 串行 ReadToEnd、无界 StringBuilder/MemoryStream。收集器只保留固定预算；库内部缓冲须经真实高速输出测试检查。如果其流读取需要阻塞线程，线程数受上述并发预算约束，取消后必须实际退出，不能仅让 Task 超时返回。S1 的测量结果决定该实现是否可接入。

### 9.2 终止与重试语义

取消/超时尝试对当前 exec channel 发送 TERM，随后关闭 channel 与独占连接，不发送远程 `killall`/`pkill`、不自动强杀整机进程。远端明确给出退出信号/退出码时可标记已退出，否则 `execution_state=unknown`，提示用户核查远端。stdin 默认结束，不等待密码或输入。

组件不自动重连重放任何命令。建连失败若确定尚未提交，可返回 `retry_safe=true` 供调用方决定；命令提交过程断线一律视为可能已执行。非零退出码只是业务失败，不能默认重跑；独立的 `ssh_test` 可由调用方重试，不改变命令执行重试规则。

Core 停止时取消所有受理操作，等待清理宽限后关闭剩余连接。切片 A 无跨重启远程任务恢复；重启不能被报告为“远程进程已终止”。

## 10. 诊断合同

组件错误分类器输入异常类别与执行事实，输出稳定错误码；公开错误不透传第三方异常文本。Runtime 可单向适配既有诊断设施，组件仍无 Pudding 项目引用。

| 错误码 | 阶段 / 含义 | 自动命令重试 |
|---|---|---|
| `ssh.config_invalid` | 配置非法 | 否 |
| `ssh.host_unavailable` | 不存在、禁用或无可见权限的统一公开结果 | 否 |
| `ssh.target_changed` | 请求目标不匹配当前 revision/endpoint | 否，重新发现 |
| `ssh.credential_unavailable` | 选定私钥缺失、不可读或格式非法 | 否 |
| `ssh.directory_unavailable` | 当前用户 home / Agent 私有目录不可解析或不可用 | 否 |
| `ssh.passphrase_required` | 选定密钥加密，当前切片没有口令输入能力 | 否，不改写密钥 |
| `ssh.known_hosts_unsupported` | 信任文件的相关记录不支持或不能安全解释 | 否 |
| `ssh.host_key_untrusted` / `ssh.host_key_mismatch` | 未信任/指纹变化 | 否，用户核对 |
| `ssh.host_key_revoked` | 目标密钥被撤销 | 否 |
| `ssh.dns_failed` / `ssh.connect_failed` | 地址解析/建连失败，尚未提交 | 否；可标记安全再次尝试 |
| `ssh.authentication_failed` | 身份认证失败 | 否 |
| `ssh.command_denied` | 命中远程不变量 | 否 |
| `ssh.busy` | 并发/排队已满 | 否；可标记安全再次尝试 |
| `ssh.timeout` / `ssh.cancelled` | 截止/取消 | 否；结合是否提交判定状态 |
| `ssh.connection_lost` | 连接中断 | 否；提交后状态未知 |
| `ssh.exit_status_missing` | 已结束但没有退出状态或信号证据 | 否 |
| `ssh.remote_exit_nonzero` | 确认远端非零退出 | 否 |
| `ssh.transport_fault` | 未分类传输异常 | 否 |

phase 枚举为 `validation / queued / credentials / resolving / connecting / host_key / authenticating / submitting / executing / collecting / cleanup / completed`。失败结果必须包含最后可靠 phase、是否提交、目标 revision、可用的退出证据与有界诊断说明。

## 11. SFTP 与后台任务的后续合同

### 11.1 切片 B：单文件传输

`ssh_upload(target, local_path, remote_path, overwrite=false)` 与 `ssh_download(target, remote_path, local_path, overwrite=false)` 均通过主机 ACL、pin 和审批；上传增加远端写入语义，下载声明 `RequiresFileWrite` 并验证本地边界。两者不通过 shell 执行 scp。

- 本地路径以执行快照工作区为根，检查父目录/文件 reparse point，不信任纯字符串前缀匹配；上传普通文件、下载普通文件，禁止目录递归与设备文件。
- 远端路径按 POSIX 处理，配置单独的允许上传/下载根；规范化、检查已有父目录 realpath，拒绝已知符号链接逃逸。SFTP 的检查与打开之间仍存在服务端竞态，严格隔离须远端 chroot/受限账号；不能宣称字符串路径检查是远端沙箱。
- 默认单文件最大 64 MiB，可配置硬上限 256 MiB；流式复制，记录实际字节，超限中止，禁止整文件装入内存。
- 先写同目录唯一临时文件，完成后发布到目标；默认禁止覆盖，取消删除本次临时文件。SFTP 原子/不覆盖 rename 能力必须实测，服务器不支持时返回不支持，不用“先检查存在再覆盖”的竞态实现冒充原子性。
- 传输中断不自动重试，不提供断点续传；清理失败返回临时文件残留的明确诊断，不能误报原目标已回滚。哈希验证只有双方确实计算相同数据时才标为已验证，不把本地 hash 冒充远端内容证明。

### 11.2 切片 C：远程作业

Core 组件内作业由 `(workspace, configurationAgent, session, execution, jobId)` 限定归属；读取、等待和取消检查归属。`ssh_wait` 阻塞等待状态变化/结束，`ssh_read` 读取已有有界 spool 游标，禁止秒级轮询。复用本地 Terminal 的交互经验，保持独立远程作业类型，不能伪装成 OS PID。

长期输出按 DataRoot 管理的作业目录落有界 spool 并有配额/保留策略，截断必须显式。Core 重启后仅把旧作业记录标为 unknown，不自动重新执行、不声称已有远端进程恢复受控。连接池如有需求，在 C 后单独测量建连开销再设计租约与失效策略。

S5 之后跑 Runtime SSH 定向测试与 `Tests/PuddingHost.Tests` 组合测试，构建与发布均走隔离产物目录。Desktop 构建、测试、发布如被验收触发则串行执行；不把编译产物写入 D:\data，不为协议验证读取其中的 LLM Secret。

## 13. 接入完成定义与回滚

切片 A 只有在独立门禁、真实 SSH 协议、宿主装配、审批隔离和新产品会话 smoke 全部通过后，才可以标记为可用。没有主机配置时 Core/桌面仍启动，ssh_hosts 返回空列表与指引；有非法 SSH 配置时隔离该能力并明确报错，不让可选能力拖垮产品启动，也不静默使用旧配置。

记录组件/主机配置版本、失败码和验收证据；`code_map.md` 只登记真实工程与当前合同。完整证据进入 `Docs/14_reports/` 或 `Docs/16_qa/`，过程与验证数字进入 `Docs/00_changelog/`。

回滚通过撤销工具注册与消费方引用、停止新操作、等待有界连接释放；SSH 主机配置和用户密钥保留，不删除其他 DataRoot 数据。此前已提交的远程命令或上传不能因本地回滚而被宣称已撤销；根据结果中的 execution_state 与传输发布事实由用户处置。
