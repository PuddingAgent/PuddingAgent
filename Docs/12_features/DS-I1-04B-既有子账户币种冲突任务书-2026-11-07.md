# DS-I1-04B 既有子账户币种冲突

**负责人为 DeepSeek，可直接领取。** 前置为已独立复核的 DS-I1-04。交付一个可观察的修复，即对健康且已存在的根或子账户，用同一个 ID 请求不同 CostUnit，均返回 `budget.conflict`。新建子账户与现有父币种不符继续返回 `budget.currency_mismatch`。

只读入口为 `EnsureAccountBindingAsync(BudgetAccountDefinition, CancellationToken)`。方法签名、mapper、数据库 schema、公共错误码、账本其他 partial、现有合同书和冻结脚本均在白名单外。

## 实施与错误优先级

1. 先写回归并在原源码运行。创建健康父、叶（同币种），仅换叶请求币种，以相同叶 ID 重解析。预期 Conflict，应捕获当前实际 CurrencyMismatch。保存红例。
2. 在 `EnsureBindingAsync` 的 existing 分支读取一次既有定义。遍历已存父链时，用**叶的持久币种**验证祖先币种。仍用原请求执行当前指定父存在性检查、原有其他字段规则。然后用 `EnsureSameDefinition(expected, persisted)` 检验请求的币种及其余不可变字段。避免只对本测试的币种值写分支。
3. 原有路径损坏、现有父缺失、持久币种本身不一致、持久取消等错误沿用其处理顺序。当原已存链健康、唯一差异是请求改币种时才由定义比较返回 Conflict。新叶分支继续使用请求币种验证实际父链。
4. 错误返回后再次用原定义解析成功，核对行数、父 ID、币种、revision 和使用量。无写入、换根或补建。

## 验收用例

| 场景 | 必须断言 |
|---|---|
| O1-1 既有健康子账户改币种 | 同一 ID，精确 Conflict，原叶/父快照未变，原定义仍可读 |
| O1-2 新子账户请求跨币种 | 精确 CurrencyMismatch，子未插入，现有父不变；可引用现有 A08 的具体断言 |
| O1-3 既有叶和已存祖先币种本身不一致 | 仅测试库构造异常行，请求沿用叶的原定义，CurrencyMismatch，未自动修复 |
| O1-4 原覆盖 | A07 根改币种 Conflict，A09 路径损坏和 A14 持久取消仍通过 |
