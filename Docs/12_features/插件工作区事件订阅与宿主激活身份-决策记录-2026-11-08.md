# 插件工作区事件订阅与宿主激活身份-决策记录

## 1 背景与冻结结论

可执行插件 v2 已允许「零工具、只提供 Hook」的包；本轮把同类能力扩展到**工作区事件**，并补齐**不依赖 Agent 会话的宿主激活身份**。合同在 2026-11-08 冻结，后续示例观察者按此编写，不再改动字段语义。

冻结项：

1. `PluginManifest.Subscriptions`（可选，默认空）：订阅工作区事件的贡献；与 Tools/Hooks 合计 1..32 个贡献。
2. `PluginSubscriptionDefinition(Id, Event)`：`Id` 在全部贡献中唯一，`Event` 仅允许 `PluginEvents.All` 白名单（当前只有 `workspace.artifact.created`）。
3. `PluginScope.ActivationKey`（可选）：非空表示**宿主作用域激活**，此时 WorkspaceId 必填，AgentId/SessionId 可为空；为空时保持原有严格校验（Workspace/Agent/Session 全必填）。
4. `PluginAuthorization.SubscriptionsApproved`（可选，默认 false）：订阅贡献需要宿主显式放行；零工具插件不再要求 `ExecuteApproved`（仅当 Tools 非空才要求）。
5. `PluginWorkspaceEvent(EventId, EventName, Scope, Payload, OccurredAt)`：`EventId` 是宿主幂等键；`PluginManager.PublishWorkspaceEventAsync` 返回逐激活的投递结果 `PluginEventDelivery`。
6. Worker 协议：`initialize` 响应新增 `subscriptionIds`；新增请求 kind `"event"`，负载为 `PluginWorkspaceEvent`，SDK 侧回调 `OnWorkspaceEventAsync`。

## 2 投递语义（不变量）

- 只投递给 `Active`、已授权订阅、且 Workspace 匹配的激活；宿主作用域激活（Agent/Session 为空）接收整个工作区事件。
- Agent/Session 作用域激活只接收同 Agent/Session 的事件，不越权。
- 同一 `EventId` 重投时**运行时仍逐次投递**，由消费端（档案写入）按 `EventId` 幂等去重；运行时保证 `EventId` 原样、稳定传递。
- 卸载/代际撤销后不再投递；单次事件失败只记录该激活的失败与诊断，不阻断其它订阅者。
- 投递有 5 秒上限，复用既有 `InvokeAsync` 的取消、在途排空与停止语义。

## 3 已实现与证据

- 合同/校验：`PluginContracts.cs`、`PluginValidation.cs`（零工具+订阅合法；未知事件 `plugin.manifest_invalid`）。
- 运行时：`PluginManager` 支持宿主作用域校验、订阅授权、初始化贡献比对、事件投递与失败隔离。
- Worker/SDK：worker 上报/处理订阅；SDK 暴露 `SubscriptionIds` 与 `OnWorkspaceEventAsync`。
- 测试：`Pudding.ToolPlugins.RuntimeTests` 定向 30/30（含本轮 3 条：合同白名单、宿主作用域零工具订阅+重投同 EventId+卸载后 0 投递、宿主激活缺 Workspace 拒绝）；插件验收脚本 **全绿**，证据 `.work/plugins/20261108-205559`、`.work/plugin-events/20261108-freeze/`。

## 14 双订阅者各自确认（2026-11-09，B 前置缺口 #2）

- 问题：投递 Worker 按 durable subscription 逐条投递，但 sink 曾再次向工作区全部匹配插件广播；只要其中一个插件成功，当前投递就可能被确认，导致另一订阅者的失败被吞掉。
- 修复：`PluginManagerEventDeliverySink` 先按 `SubscriptionId` 读取 `SubscriptionRecord`，把 `Grant.PluginId/Generation` 传给 `IWorkspacePluginEventTarget`；Host target 调用 `PluginManager.PublishWorkspaceEventAsync(evt, pluginId, generation)`，只向该订阅者自己的激活投递。`Grant` 缺失/代际不符时投递失败而不是广播补位。
- 验证：Platform `PluginWorkspaceEventPipelineTests.TwoSubscribers_OneFails_OnlyTheSuccessfulOneIsAcknowledged`——甲成功、乙失败时仅甲被确认，乙保留自己的 lease 可独立重试；乙重试成功后归档仍只有一条逻辑记录；sink/dispatch/pipeline 相关 **12/12**；真实 Worker 演示脚本继续通过。
- 冻结影响：`Source/Pudding.ToolPlugins.Runtime/PluginManager.cs` 为受保护插件 API 文件，按加性参数扩展（`targetPluginId/targetGeneration`，默认广播）后重签：旧 `06ADBD0370...` → 新 `FE08F28716C31AE02CAA9CE21FADD29D70D424949BB017A995DD1E37C0B8E299`；旧清单备份 `.work/plugin-events/20261109-dual-sub/`，冻结 18/18 PASS。
- 仍缺：产物与事件同事务（#1）、归档由插件受权触发（#3）。
