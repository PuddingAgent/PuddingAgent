# 浏览器工具与页面边界代码规格

**建议先交付一个能跑的场景：在同一任务创建的第二个标签页中导航到测试站，把已有中文搜索词替换为新词，提交一次，然后读到对应的结果。** 第一批工作是核对该 Agent 的实际工具清单、打通新页授权，并把输入和回读证据完整送过进程边界。宽屏与窄屏各跑一次。页面缩放、全页截图和视频站点适配可以分别验收。

源码基线为 2026-11-14 的 `52b1ae8`。下表“现场”只引用提问者当日提供的原文或测量值；没有错误码的行保留参数、结果或观察，未补造错误码。未提供这些调用的逐条 operationId、传输路由和部署哈希，本次未重放现场。下文标为“拟增”的字段、方法和取值均为施工合同。历史设计与本文证据截点不同。[既有浏览器 ADR](../../07_architecture/111ADR-097Agent浏览器控制一期闭环与单一执行链ADR.md) · [上一轮推进建议](../2026-11-13-存储浏览器工具链与记忆召回推进建议.md)

## 一、产品可改，或已有实现可以直接验证

| 项 | 当日现场回执、参数或观察 | 可以改什么 / 如何判定 |
|---|---|---|
| A1 新标签 | 新建返回 `single_target_page`；读新页返回 `browser_page_not_authorized: no page grant covers '<ctx>/<page>'` | 创建、前台显示、授权是三件事。新建成功在当前工具中固定附这条警告；真正的拒绝来自后续读取。本轮样本证实该次读取被拒。按 §三给受管新页定向授权、返回实际权限。PuddingAgent 的浏览器面向 Agent，受管新页默认授权：本任务创建的页创建即取得控制权，不需要用户逐页点选；本机安装的 Chrome 或用户自备浏览器不在此范围，仍走显式选页。 |

| A6 值不可读 | 搜索框 `locate include_value=true` 返回 `value: null` | 核对匹配的是编辑控件还是容器、是否有字段白名单、值在哪一跳消失。另有独立缺口是交互回执会丢失“动作前观测”标记。见 §四。 |

| A9 组合键 | `Control+a` 一次生效、一次无效；未提供错误码 | 记录实际后端、焦点接收者、选区；修改跨进程输入模式和焦点检查，为 Ctrl+A 增加可核对的结果。见 §四。 |

## 二、第三方行为及可由产品缓解的边界

| 项 | 当日现场 | 控制边界与验收方法 |
|---|---|---|
| B1 宿主尺寸 | `CSS viewport 526x703` | **部分可改。** WinUI 已有分隔条和“放大工具区”，`ToolWorkspaceLayout.Resolve(..., zoomed: true)` 能把工具区分配到可用宽度。先比较展开前后 CSS 实测，再决定是否开放受限的程序化布局请求。526 只代表该次布局。 |
| B2 站点断点 | 同一 URL 在窄视口只见 logo、搜索、更多 | 站点控制断点。用同一页面、同一会话做窄宽对照。窄屏下先查找“更多”中的可见入口；宽屏再定位，原 ref/截图坐标不可沿用。 |
| B3 SPA 异步 | `press Enter` 后 URL 未变，数秒后 pageVersion 才跳 | 由站点控制完成时机。工具等待结果区出现与提交词匹配的内容，或明确的空结果提示。URL/版本改变单独不足以证明搜索完成。 |
| B4 视频图像复杂 | 整页约 50 KB，low 限 40 KB | 图像内容由页面决定；分辨率、保真度、是否给区域截图由产品决定。保留样本的实际字节数，不能推导所有整页必超限。验收见 §七。 |
| B5 卡片无名称 | 卡片只暴露 `img`，未取得可用名称/角色描述 | 优先用公开可见的 alt、标题、图注或邻接链接作候选，说明依据；多个候选保留歧义。需要视觉时提供带 observationId 的裁剪图，点击前复核目标。 |
| B6 搜索结果差异 | “鱼姬”结果评论数 193，期望 1348 | 这两个数只证明观察值不一致。固定测试数据按作品 ID / 规范链接断言；真实站记录时间、查询词及可公开核对的作品标识。相同作品的计数也会变化。账号、地域、排序的因果关系在本样本均未获证实。 |
| B7 滚动后坐标变化 | `#far` 从 `y=1471` 到 `y=592` | 保留驱动已有重采样。用点击监听器记录真正命中节点；已过期的截图拒绝坐标输入，连续动画使用短超时和可诊断的失败结果。 |

A1、A2、A3 可以共享一条产品验收用例，工程上分别属于页级授权、工具发现、渲染几何。只放宽授权无法修复截断布局；只加宽布局也无法让模型发现导航工具。

## 三、受管页与工具发现（A1、A2）

### 新页的可驱动范围

`BrowserTabsTool.NewAsync` 在创建成功时无条件附带 `SingleTargetPageNotice`。`BrowserWorkspaceController` 把激活页与 `AssignAgentTargetAsync` 区分开，旧 Bridge 的创建处理器又在 `activate=true` 时显式选页。Desktop 还有 `BrowserGrantIssuer`、`BrowserPageLifecycle.AuthorizePageCommand/RevalidatePageCommand` 和以单个 target 为中心的会话权威。只删除警告或只签一张 grant，都可能出现创建成功、下一次内容调用仍被另一道闸门拒绝。[标签工具](../../../Source/PuddingBrowser.AgentTools/BrowserTabsTool.cs) · [工作区控制器](../../../Source/PuddingDesktop.WpfArchive/Browser/BrowserWorkspaceController.cs) · [生命周期](../../../Source/Pudding.DesktopService/BrowserPageLifecycle.cs) · [会话权威](../../../Source/PuddingBrowser.Authorization/AgentTargetSessionAuthority.cs)

**授权基线（设计结论）。** PuddingAgent 的浏览器是给 Agent 准备的运行环境，不是用户的日常浏览器。受管新页因此默认授权：本任务在该 context 内创建的页，创建成功即取得控制权，不要求用户逐页点选；权限仍受 actor、task、context、能力位、到期、连接世代约束，可随时撤销，子代理只继承子集。本机安装的 Chrome 与用户自备浏览器不在此范围，继续按显式选页处理。

1. 新增管理授权范围“可控制本任务在此 context 创建的页”，在 Agent 专用 context 中随创建默认签发。由现有宿主授权流程授予，范围含 actor、task、context、能力位、到期、连接世代及可创建页数。只有创建权限的旧授权继续只允许创建。已有用户页、站点自动弹窗、其他任务创建的页保持原来的显式选页规则。首版不自动接管弹窗。
2. 在两条路由共用的页创建完成点调用拟增的 `TryBindCreatedPage(permit, createdTarget, operationId)`。从宿主创建结果取 pageId，核对注册表中的 context、创建操作和当前世代；权限取父授权与策略交集，有效期取较短者。同一 operationId 重放必须复用原创建结果。创建和签发之间若发生撤权、取消或关闭，保留“已创建、未获权”的事实，也不得再创建第二页。[签发器](../../../Source/Pudding.DesktopService/BrowserGrantIssuer.cs) · [页级授权规则](../../../Source/PuddingBrowser.Automation/BrowserGrantIssuancePolicy.cs)
3. 在会话权威中按任务保存受管页集合，保留用户显式选择的目标与接管优先级。内容读写始终按请求中的 context/page 复检。需要前台的动作在同一工作区串行完成“定位受管页 → 呈现 → 复核页及写租约 → 一次派发”；另一任务或用户在等待期间切走则中止。这样可以交替驱动两个页，也不会把发给后台页的键盘事件送进前台页。任务结束、过期、重连、关页或用户撤销时失效；子代理只能使用父任务已授权的具体页与能力子集。
4. 扩展 `DesktopTabsResult`、两种传输及工具结果。拟增 `created/active/controlStatus/allowedActions`，其中 `controlStatus=granted|requires_user_selection|denied|unknown`，由 Desktop 对本次调用者裁决。旧端无事实时返回 unknown。只在确需用户选页时展示选页提示；`activate` 字段只表示前台意图。

**验收。** 同一 task 创建 P、Q，各写一次，仅对应页计数 +1；回 P 读取原值。只获创建权时 Q 存在却不能读内容，重复请求仍只有一个 Q。已有私有页、外来 context、其他 task、用户接管后排队的写请求，均观察到内容读取/输入为 0。两条传输要分别执行这些用例。

### 导航与等待工具的发现

`pudding.browser` 已导出 `browser_navigate`、`browser_wait_for`。`browser_navigate` 的后退动作叫 `back`。从这次会话采集四个事实：包是否加载、Agent 是否获准、当轮是否实际下发 schema、调用后 Desktop 返回什么。用 `test_tool.exposed_to_agent` 辅助定位，并与最终发给模型的工具名清单核对。工具已曝光时修改工具描述/发现结果，让调用者看见导航和等待是同级工具。若缺权限，定位到具体 Agent 或插件挂载策略，避免改宽全局角色。若清单正确而执行失败，沿同一 operationId 修实际路由。[插件导出](../../../Source/PuddingHost/ToolPackages/browser.json) · [导航参数及实现](../../../Source/PuddingBrowser.AgentTools/BrowserNavigateTool.cs) · [曝光诊断](../../../Source/PuddingRuntime/Tools/BuiltIns/Agents/AgentTestTool.cs)

**验收。** 走真实工具注册、模板策略与会话工具组装。授权 Agent 得到两个 schema，执行 `goto(A) → goto(B) → back → forward → reload`，逐项核对本地测试站的 URL 和页面标识；刷新同 URL 以新文档实例为证。未授予对应能力时不曝光、显式调用也拒绝，导航计数为 0。禁止为兼容 `goBack` 再造一个同义工具。

## 四、让输入后端和写后观测可核对（A5、A6、A9）

**先修跨进程合同。** 当前 `press` 默认 native，其他输入默认 DOM。`InteractCommand` 的 1–14 号字段没有 input mode；Desktop 解码创建 `BrowserInteractRequest` 时使用默认 DOM；工具结果 `InputBackend` 又从请求值填写。旧 Bridge 会显式拒绝 native。另一个方向，`ElementRef` 带 optional value，但没有 `IsPreActionObservation`，因此动作前快照经过能力通道可能被消费为动作后值。这两条缺口可用无网络的编解码测试复现，即使完全不访问抖音。[工具入口](../../../Source/PuddingBrowser.AgentTools/BrowserInteractTool.cs) · [Protobuf](../../../Source/Pudding.Rpc.Protocol/Protos/desktop_capability.proto) · [Core 映射](../../../Source/Pudding.CapabilityBroker/WireMapping.cs) · [Desktop 映射](../../../Source/Pudding.DesktopConnection/Mapping.cs) · [旧 Bridge 入口](../../../Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs)

| 拟改合同 | 规格与失败语义 |
|---|---|
| 输入模式 | 在 `InteractCommand` 末尾加 optional `input_mode`；`InteractionOutcome` 增加由执行驱动产生的 `executed_input_mode`。JSON Bridge 的 `PageInteractArguments` 和结果 descriptor 同步。按路由协商支持项；对端无法表达明确的 native 请求时在动作前拒绝。没有实际执行证据时输出 unknown。删除以请求值填充“实际后端”的赋值。 |
| 观测来源 | 在交互结果上增加 `observation_phase=unknown|before|after`，默认 unknown。由 Desktop 打标并在 Broker、Bridge 两端往返；反序列化缺字段也为 unknown。旧值可用于诊断，断言器只用同目标、同文档、after 的观测。 |
| 编辑值 | 读回状态拟为 `observed|not_requested|not_editable|unavailable|redacted`。空串是成功读到长度 0；null 必带原因。显式 `fields` 已覆盖 `include_value`，文档和参数提示写明优先级。交互只返回匹配结果和长度；普通 locate 明确请求才可返回允许的值，密码等敏感输入在驱动处屏蔽。 |

**修改输入序列。** 保留 `fill` 替换、`fill("")` 清空、`type` 输入文本、`press` 发送按键的职责。现有 DOM 分支已区分替换/追加；native 默认 `ClearFirst=true`，非空 fill 已有全选、删除、插入步骤。不要再加一遍 Ctrl+A。将 native fill 的聚焦与写入拆成两个可观察阶段：确定唯一可编辑节点，判焦点仍属于该编辑器；对 input/textarea 核对全选范围，对 contenteditable 核对 Selection 的端点与覆盖范围；仅在范围可核对后替换。对原本空值直接输入；一旦焦点丢失或选区不符，停止后续删除和输入并报告已完成的阶段。DOM fill 保留原生 setter 和 input 事件机制。组件应用异步改回值时以新观察为准。[DOM 定位和写入](../../../Source/PuddingBrowser.WebView2/WebView2DomClient.cs) · [native 执行](../../../Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs) · [CDP 按键规划](../../../Source/PuddingBrowser.Automation/NativeInputSequence.cs)

**修改验证。** locate 针对 input/textarea 读取实时 property，针对可编辑宿主读取其文本；若匹配包装节点，仅在其内存在唯一可编辑目标时才允许显式解析，否则返回歧义。修改 `BrowserRuntimeDesktopSurface.InteractAsync`：当前动作后用原 locator 再 Query，遇到旧 ref 只能退回 pre-action handle。改为在动作内保留同一文档的元素身份，或以新的唯一语义定位重新观察；无法确认身份即 unverified。业务提交另验结果，按键派发后只重读，不自动再按 Enter。取消或中途失败释放已按下的修饰键，可能产生过效果的动作不可盲重试。[表面映射](../../../Source/Pudding.DesktopSurface.Browser/BrowserRuntimeDesktopSurface.cs) · [值的输出投影](../../../Source/PuddingBrowser.AgentTools/BrowserToolContracts.cs) · [回执判定器](../../../Source/PuddingBrowser.Automation/BrowserInteractionReceipt.cs)

**取红测试。** 用原生 input、受控重渲染输入、contenteditable 三种固定页面。每例从“鱼姬”开始，fill 后值精确等于“宠物不许上桌”，末尾 type 后精确等于“鱼姬宠物不许上桌”；验证空值和表单提交次数。对 Ctrl+A 记录焦点、修饰位和选区。另设两个相邻输入框，聚焦后抢焦时第二个框零写入。变异一：删去 wire 的 input mode，驱动桩应捕获 DOM/native 不匹配；变异二：让动作前值等于期望值、动作后移除节点，丢掉 phase 后绝不允许 verified。按两条路由分别记录支持或明确拒绝。

## 五、视口、布局与页面缩放（A3、A4；B1、B2、B7）

**先利用现有宿主。** 在同一受管页面调用布局观测，记录 CSS layout/visual viewport、页面滚动量、DPR、目标矩形。手动点击 Desktop 的“放大工具区”后重读，据此确定该机器能提供的实际宽度。如果变宽后仍找不到目标，检查目标是否已改为“更多”菜单项，或在裁剪容器里。WebView2 运行在 WinUI 线程，Desktop 负责表面尺寸；尺寸观测交给浏览器驱动。使用 CDP 的 CSS 像素指标，坐标不手工乘 Windows DPI。[现有布局算法](../../../Source/PuddingDesktop.Foundation/ToolWorkspaceLayout.cs) · [WinUI 分栏和放大入口](../../../Source/PuddingDesktop/MainWindow.xaml) · [CDP 布局指标定义](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-getLayoutMetrics)

## 六、版本、参数与等待（A8、A11、A12；B3）

### 一次观察只有一个版本签发者

源码中有可构造的版本分叉。`WebView2BrowserPage.PageVersion` 从原子计数读取，部分 native/滚动路径只递增计数；`WebView2BrowserContext.ListPagesAsync` 返回缓存的 `p.Info`。`BridgeBrowserCapabilitySurface.SnapshotAsync` 在抓快照**之前**取版本，最终用该版本包装快照；Desktop surface 则在抓取**之后**读取当前版本。若采集中发生导航，两种取值都有机会与 DOM ref 的签发版本错开。相同数字在不同页/世代之间也不可比较。今天的 v6→v5 需要同一页实例的链路证据才能归因。[页面驱动](../../../Source/PuddingBrowser.WebView2/WebView2BrowserPage.cs) · [页面列表](../../../Source/PuddingBrowser.WebView2/WebView2BrowserContext.cs) · [Host 投影](../../../Source/PuddingHost/BrowserBridge/BridgeBrowserCapabilitySurface.cs)

1. 在 `ScriptAndSnapshot.cs` 的 `PageSnapshot` 增加采集版本；由驱动在执行快照脚本、签发 refs 时记录同一个版本。采集前后身份改变可进行一次**只读**重采，仍变化则返回 stale。两种 surface、远端代理、列表与线协议沿用该版本。构造 `PageInfo` 时从同一页面实例取一致快照，不用 context 最大版本填 page 字段。[运行时快照契约](../../../Source/PuddingBrowser.Abstractions/ScriptAndSnapshot.cs)
2. 以进程实例、连接世代、context、page、页面实例为键，另记请求序号。旧响应迟到不得覆盖较新的同页状态；旧响应所含 refs 不得改盖新版本。导航、SPA 路由切换和页面实例重建保留失效语义；滚动/缩放至少使截图几何失效。首版保持现有写操作失效策略，先消除错误倒退，再依据观测决定能否减少非导航的版本递增。
3. `expected_page_version` 的模型参数与线上参数分层。下表作为工具 schema 描述、校验函数和示例的同一数据源。传入旧版本时保留实际错误码，回带 observed/expected、目标身份、是否已派发。ref 不允许通过改填最新数字重新使用。

| 模型调用形状 | 调用方是否给版本 | Desktop 侧约束 |
|---|---|---|
| locate / interact 使用 ref，或拖动终点为 ref | 必须来自产生该 ref 的观察 | 页、实例、版本和引用同时匹配，任一失败拒绝。 |
| role、label 等语义定位；含以此定位的 press | 可省；显式给定就要满足 | 只读可读当前版本；写操作由工具读取该页当前状态并钉住版本，在派发前复检。多个语义匹配返回歧义。 |
| screenshot 与来自截图的指针操作 | 截图签发需明确版本；使用图像坐标必须携带对应 observationId | 验证观测所属 page、文档及视口/DOM 修订。原始 CSS 点与图像点分型。 |
| 导航及基于业务条件的 wait | 按现有动作约定；不借用旧 DOM ref | 导航使用明确目标；wait 新观察当前状态，文档边界由条件声明。 |

**取红。** 在夹具中控制次序：先抓 v5，再更新到 v6，再送达 v5 的列表响应；缓存仍为 v6，旧 ref 写入次数为 0。切换到另一页的 v5 不能污染第一页。采集期间插入导航，正文标记与所有 refs 必须来自同一文档。覆盖 ref 缺版本、role press 省版本、任一 locator 显式给错版本三例，最后一例页面零输入。

### 截图按实际路由与 detail 验收

`BrowserScreenshotTool` 的 low 默认已经是 JPEG。`WebView2BrowserPage.ScreenshotAsync` 有按字节尝试质量阶梯的逻辑；`BrowserRuntimeDesktopSurface.CaptureScreenshotAsync` 的路径经 `BuildForObservation` 固定 JPEG 质量 80，拍一次后检查预算。另有一个范围差别：表面规划器对 `full_page` 显式返回 `FullPageNeedsSeparateHandling`。现场给出了负载和限额，但没有该次请求的 scope/route；测试需分别传 viewport 与 full_page。[截图计划与阶梯](../../../Source/PuddingBrowser.Automation/ScreenshotPlan.cs) · [范围规划器](../../../Source/PuddingBrowser.Automation/BrowserScreenshotPlanner.cs) · [截图工具](../../../Source/PuddingBrowser.AgentTools/BrowserScreenshotTool.cs)

- 给 `BuildForObservation` 增加受限的 JPEG quality 参数，让 surface 的观测路径复用已有 `QualitySteps` 和 `CaptureWithinBudgetAsync`（80、65、50、38）。同一几何及取消期限内选择首个预算内的完整编码。不改变显式 PNG，不截断图片字节。成功回报实际尺寸、MIME、字节、detail、画质、裁剪范围与 observationId。
- 阶梯耗尽，返回原始错误码及最小实际字节、尝试档位、预算，并给出可执行的 region 请求形状。范围以刚测得的 CSS viewport 为限；读小字用 region + high/original，服从对应像素和总字节上限。换 detail/范围应清晰可见，每幅图有独立 observationId。截图失败不得签发可点击的观察。

### 一处口径更正

先前把 A1 的实施点说成「改 `BrowserGrantIssuancePolicy` 的默认值」，核实后不成立。该类只有 `CheckSubAgentScope` 与 `EnsureSubAgentScopeIsSubset`，做的是子代理授权是否为父任务授权的子集校验，不存在「默认允许 / 默认拒绝」开关。真正的拒绝来自白名单语义：`BrowserAutomationAuthority` 在找不到覆盖该页的 grant 时直接返回 `no page grant covers '<ctx>/<page>'`（`BrowserAutomationAuthority.cs:828`）。

因此 A1 的施工点是**在页创建完成点自动签发一张 grant**（§三 第 2 条），白名单语义不动——没有 grant 仍然拒绝。把「默认授权」理解成「放宽裁决」会把方向做错。
