# 浏览器发现契约与配套部署修复方案

## 1. 目标与边界

依据 [ADR-097](../07_architecture/111ADR-097Agent浏览器控制一期闭环与单一执行链ADR.md)。首要目标是恢复默认 Bridge 上“发现 context/tab → 交页 → 主 Agent 操作 → 新观察”的产品链。当前源码可独立复现载荷错配，证据见[审阅报告](../14_reports/浏览器发现契约阻塞代码审阅-2026-10-18.md)。**本文件是待实施规格，不是修复完成声明。**

本切片修映射边界、发现路径、测试与配套部署，不更换浏览器引擎、不恢复旧 controller 直执行、不通过开启 gRPC 绕过错误。保留既有会话权威、写世代、唯一票据和幂等账本；无目标发现不等于获得页面控制权。

## 2. 先固定 19 条命令的结果合同

`PuddingBrowser.Protocol` 是 wire DTO 的唯一所有者。Desktop 的能力结果可以比命令更宽，但 **ResultAdapter 必须按原始命令与目标裁剪**；不能让内部 `DesktopContexts` 决定线缆返回形状。工具可见摘要又是另一层，不拿它反推 wire 字段。

| 命令 | 成功 Value 合同 | 消费与失败语义 |
|---|---|---|
| context.list | `BrowserContextListDescriptor` | 允许空 contexts；列表元素字段完整 |
| context.getInfo | 单个 `BrowserContextDescriptor` | 必须精确命中请求 context；缺失返回 `browser_context_not_found` |
| context.create | 单个 `BrowserContextDescriptor` | 创建结果含真实 id/count；目录未知保持合同定义的空串，不回填假路径 |
| context.close | 无 Value | 只确认命令成功；不反序列化为 JsonElement |
| page.list | `BrowserPageListDescriptor` | 仅指定 context 的页面；不存在的 context 返回稳定错误，空页列表可成功 |
| page.getInfo | 单个 `BrowserPageDescriptor` | 验证 context/page 归属；页面准入仍有效 |
| page.create / page.activate | 单个 `BrowserPageDescriptor` | 原目标、真实版本与结果字段；不套导航包装 |
| page.close | 无 Value | 同 context.close；副作用成功不得被空值解析推翻 |
| page.goto | `BrowserNavigationResultDescriptor` | 保留 ok/status/error/page |
| page.goBack / page.goForward / page.reload / page.stop | 单个 `BrowserPageDescriptor` | 从 NavigateResult 投影其 page；与现有 RemoteBrowserPage 接口一致 |
| page.snapshot | `BrowserSnapshotDescriptor` | 预算/截断/版本字段完整 |
| page.locate | `BrowserLocateResultDescriptor` | ref/元素事实与截断；不猜命中 |
| page.interact | `BrowserInteractionResultDescriptor` | 真实执行/观察，不把解析失败当未执行 |
| page.waitFor | `BrowserWaitResultDescriptor` | 超时是结果；条件不静默丢失 |
| page.screenshot | `BrowserScreenshotDescriptor` | 有序完整分块、元数据、版本与工件 |

最后五项本轮没有重新证明所有字段正确；必须在修复测试中与消费者逐字段对表。计数 19 是命令覆盖数，不是产品验收数。

## 3. 最小代码修复

### R1：按命令投影，禁止默认兜底成功

- `BrowserBridgeCommandAdapter`：解析 getInfo 的 envelope/arguments contextId；两处都有但不同则 `browser_invalid_command`，都缺失则参数错。page.list 必须有明确 context；不能忽略选择条件。工具层可先确定默认 context，但不让传输层任取第一项。
- `BrowserBridgeResultAdapter`：单 context 投影共用一个函数；`FromContexts` 只用于 list，`FromContext` 按 id 精确匹配；page.list 按 context 投影。结果中不存在目标返回相应 not_found，重复 id 属内部合同错误。
- `BrowserBridgeExecutorRoute`：为 19 个命令显式列出响应类型；去掉 `_ => FromContexts(...)`。未知命令/缺失响应成员明确失败；不得回退到 controller。导航四项返回单页描述符，goto 保持完整导航结果。
- `RemoteBrowserRuntime`：抽出公共“发送→验身份/期限/错误/关联”流程，再分别处理有值和无值结果。`ExecuteEmptyAsync` 在 Success=true 时接受规范的无值结果，保留错误与取消语义；有值命令仍严格拒绝缺失/非法载荷。不删除 DTO 的 required 属性来掩盖错误。
- 解码错误应含 command、operationId、预期 DTO、协议修订与执行阶段，不记录完整页面/凭据载荷。已派发的写命令解码失败标记“结果未知/可能有副作用”，禁止自动重试或跨传输重发；稳定错误码在 Protocol 中统一定义并贯通工具回执。

`UserDataDirectory` 不用于工具授权/页面选择；当前空串表示未提供。不要为了补该字段读取或暴露用户目录。以后删除字段需另一次明确协议变更。

### R2：发现只读取元数据，不逐页取得控制

Host 的 `GetContextsAsync` 不再通过 `GetPageAsync` 逐页补全发现信息。使用 context.list + 各 context 的 page.list，消费其中已有的版本与标志；缺页/失效版本有明确有界结果，不能回退为 DOM 查询。

为防止 `IBrowserRuntime/PageInfo` 中转丢失 active/agentTarget 等字段，在 **Host 内部**增加窄发现读取端口（建议 `IBridgeBrowserDiscoveryReader`），由 RemoteBrowserRuntime 复用同一 broker/可信调用作用域实现，直接返回 Protocol 的列表描述符。Bridge surface 将其映射为 `DesktopContexts`。这不是新 transport、第二套授权或新 Agent Loop；AgentTools 仍只依赖 Contracts，Protocol 不反向引用 Host。

发现返回值明确区分“该页是用户选中的目标”和“当前会话已获得控制”；active 不能充当授权。列表仅含产品允许公开的 Agent 浏览器范围，Workbench、凭据、DOM、表单值不进入发现。保留无交页时的元数据读取；内容读取、导航、交互和新建/关闭管理动作仍由既有会话准入裁决。

页面级显式操作仍可读取目标页状态，但不能为发现其他页面而取得其控制。没有现成页时，按一期方案由用户建页并交给会话，Agent 不靠 context.create 自动获得控制。

### R3：测试必须连接真实生产者和消费者

优先在现有 Host 测试工程新增 `BrowserBridgeWireContractTests`（拟新增文件）；以测试 broker 连接真实 ExecutorRoute/ResultAdapter，使用真实 RemoteBrowserRuntime/Context/Page 消费响应。可像现有 Desktop 测试那样链接无 UI 适配器源文件，不让产品 Host 反向引用 Shell。替身仅替代执行器/driver，**不得手工制作消费者期待的 JSON**。

| 门禁 | 正向断言 | 必须拒绝/失败的反例 |
|---|---|---|
| context 单项/列表 | 两个 context；精确查询第二个；创建后读取 | 未知 id、缺 id、envelope 与 arguments 冲突；把单项改回包装后测试失败 |
| 空响应 | close 成功；driver 一次；Core 不报 no value | 错误响应不能变成功；有值命令缺 Value 必须失败 |
| 导航 | goto 与四个历史动作分别被真实代理解码 | 将四项改成导航包装后失败；已派发解码错不重发 |
| 发现与准入 | 无目标但有页面能 list；多个页面不逐页 page.getInfo | 无交页不能读 DOM/写；不能借发现遍历 Workbench |
| 元数据 | context 过滤、pageVersion、active/target 原样到工具 | 缺版本不伪造；false 不掩盖未知；未知 context 不返回全列表 |
| 组合根 | channel 开/关均固定 Bridge；真实 dispatcher + service + 假 driver | 断开 route 接线即失败；不得旧 handler 偷偷成功 |
| 协议与发布 | 同一受支持修订、清单所列模块加载 | 旧/新混配、缺构建证据、契约变更未升修订被门禁阻断 |

先让上述缺陷用例在未修代码失败，再修到通过。保留 allow/deny 配对，测试不得靠全拒绝假绿。遵守组件 S1–S4 后 S5；本切片以现有组件为主，不为测试拆出依赖宿主的新组件。

## 4. 配套构建与协议修订

1. 本次修复作为完整 Bridge 合同修订发布，将 CurrentVersion 从现有 2 提升到 **3**，两端严格相等；版本 2 的错误实现不继续作为可用搭配。数值升级是迁移隔离，不是修复映射本身，也不能代替 R3 测试。
2. Hello/Ack 补充可诊断的构建身份（buildId、源 revision、dirty、协议修订）；进程日志登记实际模块路径、MVID/InformationalVersion。协议修订匹配才允许工具派发；构建身份用于与发布清单核对，不以任意文件时间决定兼容性。不做旧新载荷双解析或自动降级。
3. 发布清单绑定同批 Desktop、Core 和必要共享程序集的预期哈希。验证各文件与清单一致，不要求所有不同程序集哈希相同。协议 DTO、映射逻辑、Host 代理分处不同程序集，**禁止只替换 Protocol.dll**。
4. 从干净且明确的提交构建配套产物。按仓库规程串行 restore/build/test/publish；使用隔离 artifacts 目录，restore 后在同目录 `--no-restore`；不要覆盖运行中目录，也不要把产物放入 DataRoot。
5. Core 实际路径受 `CoreExecutableResolver` 的显式配置优先级影响。部署控制器必须先核对解析出的路径与清单，错误配置不能被静默忽略。开发运行允许不同构建身份时必须显式显示非配套状态，正式验收必须配套。
6. 分开记录 transport connected、协议可用、发现成功、目标交接完成。Handshake 成功不能标为 Agent 可控；发现失败要给出稳定合同错误，不让模型重复猜参数。Shell 在合同不匹配时仍能进入运行中心修复。

运行时不依赖扫描全盘找“最新 DLL”；哈希核验以发布路径/清单为界。构建版本匹配也不能证明实现正确，所以配套门禁和契约连通门禁缺一不可。

## 5. 实施与发布顺序

| 步骤 | 完成条件 |
|---|---|
| R0 固定缺陷证据 | F1–F4 有最小反例；保存当前构建/进程证据但不读密钥 |
| R1/R2 组件修复 | 显式响应矩阵、无值处理、无目标发现、真实元数据；各自独立测试通过 |
| R3 生产链门禁 | 真实 producer→wire→consumer；19 命令覆盖；副作用调用次数和拒绝配对 |
| R4 配套发布 | 协议修订与清单完成；干净提交成套发布、模块身份可核对 |
| R5 外部部署与真实 Agent | 外部控制器切换到新构建，再开启新 Agent 会话验证；生命周期另行判定 |

本轮仅交付设计，R1–R5 均未执行。部署前需处理正在运行的会话与子代理；本次审阅不触发停止或重启。部署操作应在用户已授权的维护窗口执行，记录在飞任务状态。回滚必须使用先前验证通过的**完整配套包**与适配数据，不能混拷 DLL 或直接恢复到已知契约错误构建。

## 6. 用户三条预期的验收顺序

先用 TestSite 做自然语言表单/导航/观察任务；保存模型实际工具序列、operationId、页面版本、页面结果与答复。通过后，再按用户任务验证真实站点：

1. 打开 jd.com，列出实际 tab、取得快照并查看购物车。登录/验证码需要用户处理时明确停在该状态。
2. 对同一页面分别验证正文读取和截图：工件有效，支持视觉的模型请求里有图像部件。文本模型不得声称已经看图。
3. 搜袜子、观察商品图片、比较价格与评论/联网检索证据，再按用户选择加购并观察购物车数量/商品变化；不把这项测试延伸为下单支付。检索等非浏览器工具的依赖单独记录。

如果任一步失败，记录具体阶段，不归因于“权限”或“版本”而省略证据。`ready-for-external-deploy` 只代表内部门禁；功能通过与启动/重启/崩溃恢复/退出回收分别提供证据后，才达到一期完成标准。
