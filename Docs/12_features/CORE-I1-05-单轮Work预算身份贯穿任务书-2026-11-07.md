# CORE-I1-05 单轮 Work 预算身份贯穿

**负责人为主代理。本单先交核心决策与精确文件范围，再实现所冻结的合同。** 首个消费者限定为公共单轮 Work 受理的普通主 Agent 调用。主代理负责身份来源、恢复、一致性和两个 Runtime 分支。叶任务不得定这些语义。

## 1 已知入口与最小增量

| 环节 | 现有代码和应改行为 |
|---|---|
| 受理与回执 | `PuddingAgentWork/AgentWorkService.cs` 派生 WorkKey，`CanonicalAgentWorkBackend.SubmitAsync/LoadAsync` 将 WorkId 放在 clientRequestId，并交叉验证 batch、command、input、accepted event 及 actor。此 backend 位于 Work 冻结清单，先作为只读依据 |
| 开始执行 | `ExecutionRunCoordinator.ExecuteAsync(ExecutionLease, CancellationToken)` 按 lease 取得 command、snapshot 和限额，再构造 `TurnExecutionContext`。在持久 Work 权威与当前 lease 一致时取得受权账户绑定 |
| 传播 | `TurnExecutionContext.ExecutionIdentity → TurnExecutorAdapter.ExecuteAsync → RuntimeDispatchRequest.ExecutionIdentity` 已有直通载体。首选在 `RuntimeExecutionIdentity` 附可选不可变绑定，复用既有透传，不在三种 DTO 重复增加一组字段；改动前核对序列化、日志和派生身份调用者 |
| 消费 | `AgentExecutionLlmInvoker.InvokeAsync` 构造 buffered 请求，`AgentExecutionService.Streaming.cs` 独立构造 streaming 请求。两处调用同一受权绑定转换。受管路径中 facade 缺失或身份异常必须在直接客户端调用前失败 |
| 每次调用 | `LlmInvocationRequest.BudgetAttempt` 及 `LlmAttemptBudget` 已存在 AccountId、Ancestors、RootKind/RootId、ModelRevision、PriceVersion 等字段。普通 Work 的 RootKind/RootId 已可表达 Work/WorkId。优先复用；独立 WorkId 只在确有跨身份关联需求并说明用途时新增 |

## 2 开工决定及只允许主代理填写的部分

1. **绑定谁。** 从 canonical 受理事实定位唯一 Work 和 command，再核对 actor、workspace、agent、session、turn、当前执行租约。普通 Work 绑定 `work:<receipt.WorkId>`，使用 DS-I1-04 mapper 返回的 scope。相同 Work 恢复或重领 run 复用同一账户。客户端能写的 metadata、字符串前缀、请求自报 WorkId 均不足以赋予预算身份。
2. **何时冻结。** 在受权受理/首次受权执行边界确定冻结的策略来源，且先于模型派发。恢复时读取同一份持久绑定与限额；调用者只能收紧。表列每个字段的来源：单请求输入上限、累计输出/费用/调用数、并发、币种、mode。`null` 与 0 保留原意。受管 Work 缺可信来源要返回可诊断失败。历史非受管路径保留原行为，区分“明确属于旧入口”和“本应受管但证据缺失”。允许分批启用，默认策略沿用既有约定。
3. **谁定价。** 模型选择取受权路由/目录，记录实际 provider、model、冻结 model revision、pricing rule version 和账户币种。可信报价由 Platform 的 `IModelQuoteSource` 在真实派发时验证。累计账户定义归 Work，逐次报价归 attempt；同一 Work 允许多轮，不共享单次 attempt ID。目录里的缺价不能从 `ResolveUsageBudget` 中的零值回填。恢复时可重新验证窗口；更换模型/报价须取得新的合法绑定并可审计。
4. **先产出一页决策记录。** 列出对应类型、成员、证据查询、明确非受管入口、版本与恢复矩阵、失败码、限额来源和精确读/写文件。逐项说明是否确有必要改 `RuntimeDispatchRequest` 或 `LlmAttemptBudget`。如果当前持久事实不能可靠区分受管入口，给出最小受理方标记/关联方案、写入事务和旧数据语义，列入主代理合同后实施。避免在 frozen backend 外另抄一套 Work 哈希/受理状态机。变更冻结文件必须有明确的调用者影响、单独评审和新基线，核验脚本及旧清单不作为修测试手段。
5. **激活次序。** I1-05 可用隔离组件测试运行完整绑定。对真实传输启用逐次预算时须满足 I1-06 的重试及租约门禁。编译成功或两条调用分支均填值只证明传播。

## 3 实施范围

先读 §1 的文件及 `Source/PuddingCore/Runtime/ITurnExecutor.cs`、`Source/PuddingCore/Platform/MessageContracts.cs`、`Source/PuddingPlatform/Services/ExecutionCommandReader.cs`、`Services/Models/CatalogModelQuoteSource.cs`、`Services/ExecutionBudgets/ExecutionBudgetAccountMapper.cs`。公共 Work 对调用者保持原合同。

预期写入面限定为 Platform 的单轮 Work 受权绑定适配及其 Coordinator/Host 装配、Core 的内部运行身份载体、Runtime 的两处请求构造及其共享转换。主代理按 §2 先把准确方法、签名、选用的持久策略与定向测试文件附在决策记录中。子代理、工具内算子、Review、Goal、插件 API/事件和产品 UI 的接线另有任务。对这些路径只列明继承/拷贝执行身份的风险，未迁移入口不得继承可用于派发的主 Work 凭证。

## 4 独立验收

新测试建议落在 `Source/PuddingPlatformTests/Services/CanonicalWorkBudgetBindingTests.cs` 和 `Source/PuddingRuntimeTests/Services/AgentWorkBudgetPropagationTests.cs`。前者走真实受理及恢复查询，后者捕获两条实际请求构造路径的参数；结合现有 `TurnExecutorAdapterTests` 覆盖桥接字段，再增加一条跨两边的正常调用回归。应用适配的输入是已持有的 lease、服务端读取的 command 与冻结策略，输出为明确的非受管结果或一份只读 Work 绑定；证据缺失/不匹配、持久取消均返回显式错误。调用者不得把绑定失败归入非受管结果。

使用真实受理、隔离 SQLite/配置及真实映射器，由实际 Coordinator 经 TurnExecutorAdapter 发起，用可控模型端记录两个分支。分别报告受理/恢复、传播及调用边界，保留不可替换的真实组件清单。

| 场景 | 观察点 |
|---|---|
| W1 正常及重放 | 从公共 API 受理得到回执，精确账户 ID、actor 归属、祖先、limit/mode 与持久定义相符；重提、重领不重置账目 |
| W2 非可信或不一致 | 换工作区、actor、伪造同前缀 clientRequestId 或错配 lease/command，受管情形拒绝；合法旧通道仍执行既有合同 |
| W3 重启与配置变化 | 以新 scope 重开同库，仍读原 Work 限额；缺冻结来源或账户已取消，真实模型发送计数为零 |
| W4 两个调用分支 | buffered 和 streaming 的 Work 及模型身份一致；一次 Work 多轮的逻辑调用可区分；去掉任一分支传播即取红 |
| W5 派生和直接旁路 | 关闭 facade、预算端口或替换为错误账户时，受管路径不能转入直接客户端；快照/JSON 不泄露或接受可伪造的授权材料 |

交付决策记录、变更范围、W1～W5 及负例证据、原 RuntimeBudgetBoundary/RuntimeBudgetAccountBinding 回归、仍未迁移路径。按[批次验收规程](A阶段第二批施工任务书-2026-11-07.md)用新构建运行对应工程。I1-06 消费经评审的绑定合同。
