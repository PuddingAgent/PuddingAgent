# PA-04：基于既有 Goal 状态机的验收与续跑控制

依赖 01/02/05/06 中实际所需的基础设施、03 持久评审，以及 07A/07B 的可靠事件和通用插件生命周期，遵守[总则](Agent组件化任务书-总则与依赖-2026-11-05.md)的基础门禁。纯 Goal 策略可先独立测试；完整接入必须在基础设施与插件机制成立后进行。本任务解决“完成一个小步骤就停住”，同时保证普通聊天不被强行拉成长任务。不能另写一条 `while (!done)` 调 Agent 的旁路循环。

参考仓库为用户指定的 `F:\github\deepseek\deepseek-harness`，重点参考 `packages/goal/goal` 的状态服务与 `packages/goal/goal-round-driver/src/index.ts` 对 agents/goals/sessions 公共服务的消费，以及独立的 tool-goal、command-goal 入口。Pudding 的 Goal 策略/driver/验收贡献以插件和公共服务组合实现；持久状态、预算与提交沿用本仓库权威，不逐字移植参考实现，也不为了 Goal 将通用插件退化成专用回调。

## 1 现有权威与目标

现有 `GoalPhase` 已定义 Active、Paused、Blocked、BudgetExhausted、Completed、Cancelled、Failed；`GoalContinuationWorker` 负责 durable outbox 的 canonical 受理，`GoalSettlementWorker/Store` 负责结算，`GoalRestartReconciler` 负责重启恢复。`GoalVerificationDecision` 与受控检查已有边界。

本任务只扩展这些入口和独立决策策略：当前轮交付不全时，消费验收结果并按授权、预算自动提交下一轮；满足全部必要条件时结束；需要用户或关键事实不明时明确等待。不能从文本“DONE”、工具 exit 0、回执 Completed 或模型 Accept 直接推 Goal Completed。

## 3 模式和授权契约

拟新增工作策略 `InteractionMode` 与 `ContinuationPolicySnapshot`，冻结到任务受理记录：

| 模式 | 默认行为 | 谁能启用/改变 |
|---|---|---|
| Chat | 单轮结束；不自动创建评审 Job 或续跑 | 默认值；工具调用本身不改变模式 |
| Task | 当前任务可验收，按显式 RepairLimit 有限补做 | 用户配置/受权上层；未声明修复额度则不自动修复 |
| Goal | 已授权范围内持续推进，受根预算、最大轮数、停滞阈值和用户控制约束 | 用户显式请求或其预先启用的自动 Goal 策略 |

模型可返回 `GoalModeProposal`，由宿主检查配置、权限、目标与预算再受理。没有用户预授权时，提议不能直接升为 Goal。用户设置的停止/暂停优先；插件不能恢复用户暂停，不能自动执行 `extend` 增加轮数/花费。现有硬上限 256 轮和人工 extend 的权限不因本任务放宽。

策略快照至少含 Mode、PolicyVersion、ReviewRequired、RepairLimit、NoProgressLimit、RootBudgetId、AllowedCapabilities、ResumePolicy。ObjectiveVersion、AcceptanceContractVersion、ActivationEpoch、IterationNo 来自现有 Goal，而非插件可修改参数。

## 4 决策表与原子提交

按下表优先顺序决策，必需条件不明不得默认完成：

| 权威事实 | 结果与动作 |
|---|---|
| 已取消、暂停、授权撤销 | 不创建下一轮；保留现有终态/暂停；已派发请求由 01 排空 |
| 目标/标准/产物版本已改变，评审 stale | 不消费旧结论；为当前版本重新取证，不能沿用旧通过 |
| 等待用户决策或人工授权 | 映射既有 Blocked/Paused 及具体 reason，不占模型槽；恢复须经过原受权入口 |
| 根预算或最大轮数耗尽 | BudgetExhausted；保留当前交付与尚未满足项，不自动加额度 |
| 必需评审未完成/Unknown/不可用 | 持久等待或明确阻断，有限调和；不把 unknown 当 accept/reject |
| 所有必需验收条件有当前版本的足够证据，且无未决执行事实 | 提交 Completed；模型判断可作为语义条件证据，不能伪装成受控测试已通过 |
| 条件未满足，允许修复且还有额度，有可执行 NextAction | 原子结算当前轮并写下一轮 outbox |
| 持续无新证据/无可执行动作 | 按持久停滞计数进入 Blocked，并给具体障碍，不无限“再想一想” |

无进展指纹以目标/产物/检查状态变化为依据，模型重复改写解释不算进展。目标 edit 可以使旧验收失效，但不返还预算；新的基线/停滞计数是否重置必须随受权命令显式记录。

下一轮唯一键使用既有 GoalRunId、ActivationEpoch、IterationNo 和策略绑定；写结算与 outbox 在同一事务中，并 CAS AggregateVersion。发往 canonical 受理口的 OperationId 稳定，发送成功但 ACK 丢失只能重放同一 ID。不要以轮询触发次数生成新 ID。下轮派发前再次检查取消、用户新消息/steering 和资源版本；过期 outbox 标失效，不换个 ID 继续。

## 5 实施步骤与可取红轨迹

1. 提取/映射现有判定事实；独立 Policy 只做选择，列明每项从哪个权威服务读取。
2. 把 03 Job 的 pending/stale/完成结果加入 settlement candidate；原 verifier 仍只读，不执行检查工具。
3. 接原 settlement 事务和 outbox；显式检查无 Goal/Chat 不入该路径。
4. 对 buffered 和 streaming 使用同一 terminal fact，不从流结束或 UI 按钮推断完成。
5. 加入用户中断、恢复、目标编辑和重启围栏；验证原恢复策略仍有效。

最小闭环用确定性 fake Agent：用户要交付 A+B，第一轮只产出 A；评审给出缺 B 的证据；系统自动续跑一次补 B；检查/评审通过后 Goal Completed。**不发送“继续”、不靠心跳启动下一步。** fake 模型只负责固定建议，真实闭环测试在 08。

必须逐条通过：

- Chat 同样第一轮产出 A 后立即结束，无 Review Job、无第二轮。
- Goal 第一轮写“全部完成”但 B 不存在，不能完成；验收器 Accept 但必要测试失败也不能完成。
- 两 settlement worker 竞争和重复 ReviewCompleted 事件只产生一次有效下一轮。
- outbox 提交后、派发前用户取消：新 provider 调用数为 0；取消后重启仍不复活。
- 旧 ObjectiveVersion 的成功评审不能完成新目标；未知产物/截断证据不给绿色。
- 相同失败重复达到停滞阈值后 Blocked；预算耗尽不进入无限 retry。
- 核心控制策略异常显式阻断待决动作；**既有 advisory Hook 异常仍只跳过 Hook**，不能混淆两者。

构建并运行拟新增 `Source/PuddingGoalPolicyTests/PuddingGoalPolicyTests.csproj`；S5 跑 `GoalRunStoreTests`、`GoalRestartReconcilerTests`、`ConservativeGoalIterationVerifierTests`、`GoalSettlementWorkerCheckIntegrationTests` 及新增 outbox 竞争集成测试。去掉取消复查、唯一受理键、证据必需性各有对应红例。

## 6 DS-PA04-A：决策解释器，不能参与控制

状态 `blocked-on-contract`。主代理冻结只读 `GoalDecisionSnapshot`（DecisionId、Phase、ReasonCode、UnmetCriteria、NextAction、EvidenceRefs、版本/预算引用）后，交付一个纯展示函数。只允许创建：

```text
Samples/GoalDecisionPresenter/GoalDecisionPresenter.csproj
Samples/GoalDecisionPresenter/GoalDecisionPresenter.cs
Samples/GoalDecisionPresenter/code_map.md
Tests/GoalDecisionPresenter.Tests/GoalDecisionPresenter.Tests.csproj
Tests/GoalDecisionPresenter.Tests/GoalDecisionPresenterTests.cs
Tests/GoalDecisionPresenter.Tests/code_map.md
```

Library 仅引用主代理已冻结的 public DTO 项目；test 仅引用 sample。入口 `GoalDecisionPresenter.Format(GoalDecisionSnapshot snapshot)` 返回纯字符串，顺序为 Phase、ReasonCode、未满足条件、NextAction、证据引用；不补写“已验收”、不解析模型自然语言、不推导下一状态。未知 reason 保留原值，缺失 NextAction 写“未提供下一步”，不生成建议。

测试 completed-with-evidence、blocked、budget exhausted、unknown reason、空列表、中文转义和输入不变性；格式由主代理提供 golden fixture，DS 不修改 fixture 来迎合输出。按总则构建白名单测试工程，产物 `.work/ds-pa04-a/<run>/`。不得修改 Goal 核心、UI、数据库或现有状态枚举。
