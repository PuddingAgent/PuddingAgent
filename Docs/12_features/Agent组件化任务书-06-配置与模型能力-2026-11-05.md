# PA-06：有效配置、模型策略与资源能力 API

依赖 01 的预算/报价消费端口，遵守[总则](Agent组件化任务书-总则与依赖-2026-11-05.md)。本任务对外提供存储无关的有效配置与模型能力；插件不必知道 JSON/数据库，也不应取得 provider 密钥。

## 1 当前事实与目标

现有公共配置补丁只开放 DisplayName/Description；已有字段缺失/置空区分、CAS 版本与更新回执，不能另造无版本 `Dictionary<string, object>` 设置入口。当前 `ConfiguredExecutionModelBinder` 使用父运行明确模型路线，平价报价之外的窗口策略未接入，全零价格不能直接当作可信免费模型。

目标分三片：06A 有效配置与受权补丁；06B 模型用途策略/能力目录；06C 可信报价和资源池动态更新。分类/验收 API 已存在，本任务完善其路由，不重写分类器/评审器，也不增加自动 Goal 决策权限。

## 3 有效配置合同

拟新增 `IAgentModelPolicyApi.GetEffectiveAsync(AgentRef, ct)` 与 `UpdateAsync(UpdateAgentModelPolicy, ct)`。所有权/权限由宿主绑定，写入请求需 OperationId、ExpectedRevision、类型化字段集合与 apply policy。每字段仍区分 Missing/Set/Clear；Clear 的含义是取消实例覆盖、回退已声明来源，不是随意写默认模型。

有效配置每个字段返回 Value、Source（实例/工作区/系统）、SourceRevision、EffectiveRevision、AppliedAt/TargetRun 信息。模板只是创建种子；实例修改不回写模板，不悄悄影响其他 Agent。来源和覆盖顺序沿用既有 resolver，经特征测试确认后冻结，不在本任务另定一套优先级。

更新结果区分 `PersistedRevision`、`AppliedRevision`、`AppliesFromNextRun` 和待应用原因。持久化成功不表示运行中请求换模型成功。执行中的 Run 保持原冻结路线/价格；下一次新租约使用新版本，降权限/撤销等安全变化则即时关闭新准入并按既有策略取消。

本任务可写字段只限主代理冻结的 ModelPurposeProfile（Primary/Classification/Review）、工具能力选择与明确定义的预算默认值；**额度默认值修改不增加正在运行根账户的额度**。不能写运行时 Status、实际 Cost、授权结论、控制令牌或 provider secret。未开放字段拒绝，不自动透传到底层 JSON。

## 4 模型目录、选择与报价

拟新增 `IModelCatalogApi.ListAsync(ModelQuery, ct)`、`ResolveAsync(ModelSelectionRequest, ct)`，以及内部 `IModelQuoteService.QuoteAsync(BoundModelRequest, ct)`。模型目录只暴露受权 ModelId/Revision、上下文/输出上限、输入模态、结构化输出/工具能力、可用性、价格来源和限制；不返回 endpoint 密钥、API token 或可变 provider 对象。

每个用途策略显式指定候选模型和优先级。未配置 Review 模型时返回 `model_policy_missing`；若用户明确配置“继承 Primary”，才沿用父模型。自动按成本选择是可选策略，必须列清能力过滤、价格有效性和 fallback；不能凭“小模型更便宜”猜配置。切换后保留实际选中模型及原因，可核对每次评审到底调用了谁。

报价快照必须包含 QuoteId、Provider/ModelRevision、Currency/Unit、Input/CacheHit/Output 单价、计费单位基数、有效时间段/时区、定价来源、ExplicitFree 标记、可收费上限及计价规则版本。未知价格不能默认零；**明确免费**才允许零报价。不同币种无显式换算合同不得合并预算。

时间窗口报价基于实际派发时刻：排队跨窗口后重取报价并原子调整 01 的预留；无法补足差额则不派发，不能仍用旧低价。模型已派发后冻结该 Attempt 的计费依据；返回实际 usage 的缓存 token 与普通输入 token 按 provider 合同避免重复计费。provider 未报告用量保持 Unknown，不能凭输出字符数捏造实际收费。

## 5 动态资源租约和实施顺序

1. 06A 先扩充类型化配置端口、CAS 与有效来源测试；接原写入服务，不新增一套配置数据库。
2. 06B 独立 resolver 用假配置/能力目录验证目的模型；再让 binder 消费冻结结果，不影响既有默认行为。
3. 06C 独立报价覆盖时区边界、缓存计价、免费/未知；与 01 的原子预留接口一起验证排队跨窗口。
4. 模型配置变化创建新 generation，旧租约继续按旧快照结算；停止向被撤销 generation 分发新请求，等待真实请求排空再清理。
5. 降并发时不抢占删除活跃槽，先限制新准入；升级并发按新策略。不能为每个 generation 新建互不相关的 provider 限流器绕过总限制。
6. 插件 callbacks 按字段/用途授权，与 SDK 同服务；保存/应用状态和配置变更审计通过 07 事件公开，不回显凭据。

## 6 必须能取红的验收

| 场景 | 判据 |
|---|---|
| 两个配置写入使用同一旧 revision | 恰好一个成功；失败者不覆盖胜出者 |
| 实例 A 改 Review 模型 | 模板和实例 B hash 不变；A 新 Run 见新版本，旧 Run 仍原版本 |
| 未配置用途、能力不满足、未知价格 | 零 provider 调用，返回各自 reason，不静默换模型 |
| 显式免费 vs 全零未声明价格 | 前者可用，后者 unavailable；不能用相同零值推断免费 |
| 排队跨计价窗口/时区边界 | 派发前重新冻结报价；差额不足不调用 provider |
| 缓存命中用量、混合模型、实际超预留 | 单次尝试正确结算，未知仍未知，不重复计费 |
| 配置撤销时 provider 忽略取消 | 活跃槽仍占用至真实完成；新请求不准入 |
| 插件尝试写 secret/status/根预算或别的 Agent | 明确拒绝，既有配置文件内容不变 |

独立构建运行 `Source/PuddingModelsTests/PuddingModelsTests.csproj`。S5 回归配置 API 冻结/租约测试、`AgentRuntimeProfileResolverTests`、`LlmProviderFileServiceTests`、`ConfiguredModelTests` 及 01 的全链路计账。负例删除版本检查、把未知价格映射零、取消提前释放槽，必须分别取红。
