# 基础设施服务、生命周期与最小原型两阶段目标

交付顺序为 **A：基础设施可独立使用 → B：组合最小原型 → 后续：Goal 等上层功能**。A 必须包含可编译契约、真实组件实现及独立验证，不能以文档或接口数量代替交付；B 使用 A 的公开能力完成组合，不在示例里补一套隐藏实现。

本文约束阶段范围、交付内容与放行条件；具体架构沿用[公共 API 规划](核心组件与插件公共API规划-2026-11-04.md)，施工位置沿用[收敛计划](基础设施组件化收敛实施计划-2026-11-06.md)。下文描述的是目标合同，不声称对应 API 已发布，不自行解冻现有契约或扩大 DeepSeek 叶任务白名单。

## 1 两个阶段的边界

| 阶段 | 必须交付 | 不作为本阶段完成判据 |
|---|---|---|
| A 基础设施 | 组件清单、类型化服务、受权工厂/实例目录、生命周期、事件和订阅、Hook/策略注册、插件加载与排空；各自实现和合同测试 | Goal 自动续跑、完整桌面界面、真实模型成功、生产部署 |
| B 最小原型 | 一个最小组合根、仅消费公共 API 的示例、工具插件和非工具功能插件、可重跑场景及证据 | 覆盖全部产品功能、所有插件类型、对原有宿主的整体替换 |
| 后续上层功能 | 基于 A/B 的 Goal、评审编排、产品管理界面与更多功能插件 | 不能倒过来为这些功能在基础设施中添加专用旁路 |

每个组件仍遵守 [S1～S5 交付规程](../10_conventions/组件化交付规程.md)：先独立测试，后登记/装配。A 可以逐组件完成真实适配和接入测试，B 才做跨域原型组合；已有通过验证的接入不撤回。产品部署与真实模型验收另列，不由本规划自动授权。

“各个组件”要求清单完整，不要求每个内部类公开、每个单例热卸载。清单中的每项必须标记为公共能力、内部组件或平台适配器，并给出理由。没有完成抽取的领域必须保留缺口，不能只加门面就标为独立组件。

## 2 A 阶段的组件服务清单

以下基础域均属于 A 的必需范围。已有接口与实现先复用；每个服务有唯一状态权威，SDK、插件、内部模块不得分别实现写入规则。

| 领域 | 向上提供的能力 | 必须隔离的实现与边界 |
|---|---|---|
| 环境与工作区 | 获得受权环境、枚举/获取工作区、查询能力与组件描述、访问文件/产物 | 存储路径、DataRoot 租约、平台文件操作；不提供任意全盘权限 |
| Agent 配置与目录 | 查询/创建 Agent 定义、版本化更新配置、获取既有引用与生效状态 | JSON/数据库、模板归属、配置写入与运行投影 |
| 会话、Work 与子代理 | 创建/获取会话、提交/观察/取消 Work、受权委派与租约 | canonical 身份、父子映射、会话排队、资源所有权；创建对象不隐式推理 |
| 上下文、记忆、Skill | 查询受权快照、装配/裁剪、受控贡献及版本化更新 | 存储、检索/压缩策略与模型调用；只读快照不可变 |
| 核心循环 | 消费上下文、模型、工具、事件端口执行一轮，返回明确终态 | buffered/streaming 共用业务语义；不依赖具体插件或 UI |
| 工具与 MCP | 目录、受权调用、动态贡献、连接/重连/撤销 | 内建/MCP/插件工具共用准入；旧连接和旧注册代际失效 |
| 模型与算子 | 目录/路由、调用、分类/打分/评审算子、使用回执 | 凭据、provider、报价与连接；算子不绕过统一调用边界 |
| 执行资源 | 根/子预算、attempt、排队/并发租约、deadline、取消与调和 | 预算预留与真实调用完成分开；未知用量不能报零或自动退款 |
| 授权 | 能力查询、操作授权、审批、撤权 | actor/grant 由可信入口绑定；插件建议不能代替强制判定 |
| 事件、订阅与 Job | 已提交事实读取/订阅、检查点、后台任务受理/取消/查询 | outbox、投递重试、幂等、调和；事件不代替同步事务 |
| 插件与扩展 | 包/激活目录、加载/卸载、贡献注册、Hook/策略选择、诊断 | 同一 PluginManager/Worker 生命周期；消费服务与贡献实现是两种权限 |

渠道、Browser/CU、索引、Desktop/Web 等现有领域也必须进入总清单，说明所属组件、依赖端口与可扩展面。本阶段不要求把每种渠道、UI 或平台专有能力都改为插件；它们不得成为上述基础服务的反向依赖。尚未开放的贡献类型在能力查询中明确不支持。

### 2.1 每个组件必须有一张合同卡

合同卡与类型定义同次评审，不只写“支持生命周期”。固定包含：

1. **身份与权威**：组件标识、合同版本、职责、不变量、唯一写入者、现有代码入口。
2. **依赖与服务**：允许的程序集依赖、公开查询/命令、内部端口、错误码、幂等键、并发版本、取消语义。
3. **实例与权限**：工厂、目录、实例种类、scope、创建者/所有者、借用或持有租约、所需 grant。
4. **生命周期**：状态转换表，每项写前置条件、触发者、原子写入、失败状态、释放者与恢复方法。
5. **事件与订阅**：发布的事实、消费的事实、模式版本、顺序/游标/保留期、重投与撤销规则。
6. **扩展合同**：Hook/策略点、输入输出、允许修改项、必需性、超时/冲突/故障规则；不支持扩展也显式说明。
7. **可验证性**：独立测试、真实适配测试、负向编译探针、并发/中断恢复证据、仍未接管的旧入口。

目录元数据从实际装配和已发布合同生成/投影，不能另维护一份“宣称已实现”的静态清单。查询应受权、分页，标记采集时间/版本及 partial；不存在、不支持、无权限与暂不可用需能区分。不得返回实现对象、凭据或全局 `IServiceProvider`。

## 3 抽象实例与所有权

公共 SDK 可以提供自然的对象方法，但对象首先是**受权引用**。实例目录和工厂围绕下面这些对象工作，不能让调用者理解数据库表或自行装配 LLM 池。

| 对象 | 身份与拥有者 | 获取/创建/结束语义 |
|---|---|---|
| 服务绑定 / 环境 scope | 可信组合根或插件激活主管绑定 actor、workspace、grant | 获取窄服务；关闭 scope 撤销新准入，按所有权排空调用；不销毁共享全局服务 |
| Workspace | 工作区目录与存储权威 | Get/List 为借用；创建/归档是命令；关闭句柄不删除数据 |
| AgentDefinition / AgentSession | 配置服务 / 会话协调器，分别有身份 | 创建定义不启动会话；会话终止不删除 Agent 定义；配置 revision 与会话状态分开 |
| Work / Turn / Run | canonical 工作权威，保留现有身份映射 | Submit 受理；Observe 只读；取消受理后继续可查询真实终态；一次 Work 不冒充跨轮 Goal |
| 子代理租约 | 父 Work 与子代理池 | Acquire 原子取得占用；释放需核对 owner/generation；父取消传播，不能扩大父权限/预算 |
| 模型绑定 / 槽位 / attempt | 路由权威、资源池、预算账本 | 配置引用不占执行槽；派发取得资源；实际调用退出后释放槽，账本按 usage 或 Unknown 结算 |
| MCP 连接 | 连接主管和工作区 | 获取状态不连接；Connect/Disconnect 为命令；重连新 generation，不复活旧工具注册 |
| PluginActivation / 贡献注册 | 插件主管绑定插件版本、scope、generation | 验证后原子发布贡献；撤销新调用后排空；卸载包与停用实例分开 |
| Subscription / Job / Review | 订阅服务、任务或评审领域权威 | 持久身份与投递租约分开；停订阅不删除已提交业务事实；任务所有权决定是否随插件取消 |
| ContextSnapshot / Artifact | 内容与版本权威 | 不可变内容/引用，有保留期；不是可以 Stop/Dispose 的活跃执行实例 |

每个实例描述至少表达类型、稳定 ID、所属 scope/owner、版本及该领域状态；只有需要防旧调用的实例才带 generation/owner epoch。**Revision 表示内容版本，Generation 表示绑定代际，OwnerEpoch 表示执行所有权代次，不互相替代。** 不新增一个统一状态枚举来覆盖所有领域；复用既有状态机并提供明确投影。

生命周期合同必须回答以下竞争问题：

- Get/List 仅借用，不取得独占权；Acquire 才建立租约。先枚举后争用失败是合法结果。
- 配置提交成功不等于运行实例已应用；回执同时表达持久版本和生效状态，旧 attempt 保留冻结配置。
- 取消等待与取消 Work 是不同 API 语义。`cancel requested` 不宣称底层停止；provider 忽略取消时仍占槽。
- scope/plugin 开始关闭即阻止新准入；已派发调用按各合同取消或排空，独立清理 deadline 超时返回可诊断状态，不能虚报卸载成功。
- 重载/撤权后旧回调不得开始新副作用；已经提交的操作以回执和事实保留，不能因为代际变化“抹掉”。插件卸载不擅自取消已转交持久 Work 所有权的任务。
- 进程恢复重建持久任务与检查点，并重新取得 grant/租约；不得复用上个进程的活跃授权或未知占用。无法证明外部效果时保留 Unknown。
- 归档/删除是独立受权命令，约定引用完整性与保留期；Dispose 只释放自己拥有的资源。

## 4 事件与订阅合同

**领域服务发布事实，订阅者扩展后续行为。** 同一事务必需的校验与写入仍由服务完成；不能靠异步订阅者保证“必须同时成功”。

每个事件目录项写明事件名称、schemaVersion、发布权威、subject 类型/ID/revision、workspace、事件 ID、时间、causation/correlation、payload 或受权引用及哈希。复用现有 `EventEnvelope` 和 Workspace 事件流裁定；需要补 subject 等信息时由主代理选择版本化 payload/合同演进，不另造平行总线。

区分两类事件：**已提交业务事实**使用业务写入同事务 outbox，提供持久游标、重放和幂等；**临时进度/诊断**可以丢失，必须标明 best-effort，不能作为完成/结算证据。生命周期目录覆盖创建、配置生效、状态转换、租约授予/撤销、激活/排空等有意义的事实，不要求每次属性读取发事件。

订阅合同必须包含：

1. 由可信 scope 绑定允许的 workspace/kinds/subject 范围；登记和投递前均检查有效 grant/generation。
2. 枚举快照与从游标订阅有一致性握手，避免两者之间漏事件；保留期之外返回 `snapshot_required`，不伪装完整。
3. 保证仅限已声明 stream 的顺序，不承诺全局顺序或 exactly-once。至少一次投递下，消费者用业务幂等键处理重复。
4. 有界批次/队列、投递租约、重试、死信、查询与受权重放；慢消费者不堵塞业务提交。
5. ack/checkpoint 必须对应确实处理的事实。副作用与检查点不在同一事务时，依靠幂等服务回执恢复，不能先 ack 再产生效果。
6. Dispose/Cancel 撤销新投递并定义在途回调处理；持久订阅跨进程恢复时重新授权，旧 Worker 不能 ack 新代际的投递。

## 5 Hook、策略与插件 API

三类调用关系保持明确：同步服务负责请求和不变量；事件订阅负责已提交事实的后续动作；Hook/策略负责所属组件声明时机上的有界扩展。长任务受理成 Job，不在 Hook 或数据库事务中等待模型/插件 RPC 完成。

| 扩展类型 | 允许做什么 | 故障与约束 |
|---|---|---|
| Observer / Advice | 观察、诊断、返回有界建议 | 沿用既有 `IAgentLoopHook` 建议层语义，异常跳过当前 Hook，不控制主执行链 |
| Transform | 改写声明允许的内容字段 | 类型化输出、大小/字段校验、确定合并顺序；不能修改可信身份、预算或已提交事实；现有 advisory 工具结果 Hook 仍按其原合同容错 |
| Guard / Policy | 在专门强制端口收紧准入或提供策略决策 | 与可跳过 Hook 分离；宿主声明必需性与 fail-closed/fallback，插件不能自行批准自己 |
| Provider slot | 为一个领域端口贡献实现 | 宿主显式选择兼容实现和版本，冲突拒绝或按声明优先级；不使用“最后注册覆盖” |
| Action / Event / Job | 新命令、事实消费者和后台功能 | 经公共服务与统一授权/预算执行；不依附 Agent 或工具调用 |

每个扩展点必须声明 owner、pointId、contractVersion、输入快照、返回类型、可修改字段、执行阶段、排序/冲突、并发、超时/取消、错误策略与审计字段。一次调用冻结注册集合；最终副作用提交前由权威服务复验权限、对象版本和 fence。新增同合同插件不得在组件中添加插件名称分支。

插件 API 与内部模块消费同一应用服务。插件只能得到按授权裁剪的服务集合；环境/工作区 scope 不要求 AgentId/SessionId，付费执行再申请合法执行作用域。消费能力和注册贡献分别授权；不开放任意 DI 替换、数据库句柄或私密配置。

组件目录必须描述实际可用的扩展点和订阅种类；工具清单不能代替整个扩展目录。统一包/Worker 支持零工具功能插件；依赖验证、原子发布、停止新调用、撤销贡献、排空与失败诊断覆盖全部贡献类型。

## 6 A 阶段的放行门禁

组件清单和合同卡是输入，以下证据才是输出。某项缺实现则记录缺口，不以“以后接入”判绿。

| 门禁 | 可核对交付与能取红的对照 |
|---|---|
| A1 范围与合同 | 基础域逐项有合同卡、真实类型和调用入口；其余领域有明确归属/开放边界；无伪造 Agent scope |
| A2 编译独立 | SDK/组件白名单与负向构建探针；消费者引用内部实现、组件反向引用调用方会失败 |
| A3 实现与权威 | 独立领域实现及真实文件/SQLite/现有服务适配通过相同合同测试；禁用适配器或绕开权威会取红 |
| A4 生命周期 | 并发创建/获取、CAS 冲突、撤权、取消与派发竞争、租约释放、关闭/重载/恢复；旧句柄调用失败且副作用计数为零 |
| A5 事件与 Hook | 提交后崩溃重投、游标过期、重复 ack、慢订阅、Hook 超时、非法修改、必需策略缺失；按合同产生确定结果 |
| A6 组件可消费 | 内部模块/插件 SDK 的合同测试都能调用同一权威；真实 PluginManager/Worker 的加载、注册和卸载测试通过，不只 mock 调用返回值 |

独立单测可以 fake 外部边界；适配测试必须使用所验证的真实适配器、隔离存储与可控外部 provider。单次真实组件组合测试属于 A 的边界证明，不等于 B 的跨域原型已完成。每项分别记录 ContractReady、ComponentExtracted、AdapterVerified 与现有产品消费者迁移情况，不强迫未迁移产品进入部署验证。

完成 A 的必要条件还包括：冻结首版基础合同及其版本变更规则，列出 A 必需调用路径中所有尚可绕开统一预算/授权/生命周期的入口，并消除这些旁路。保留在范围外的旧产品路径必须标明，不能据此宣称整个现有产品已经迁移。

## 7 B 阶段：组合最小早期原型

只建立一个最小组合根，装配 A 的真实组件与适配器。组合根可以引用实现；消费示例和插件只引用公共 Contracts/SDK。使用独立工作区与临时存储、可控时钟和脚本模型，不启动第二个占用产品 DataRoot 的 Core。

最小场景：

1. 上层示例通过受权环境枚举工作区、取得/创建 Agent、CAS 修改配置并读回生效回执。
2. 从同一插件主管加载一个工具插件，以及一个**零工具、无 Agent 会话依赖**的工作区功能插件；查询其贡献和状态。
3. 经公共 API 提交一个普通 Work。脚本模型确定性请求工具；真实核心循环、授权、预算/租约和派发组件执行，写入一个有版本的产物。
4. 产物提交事实经真实 outbox/订阅投递给功能插件；插件通过受权应用服务登记归档/审计记录。查询准确 Work 及产物/记录确认结果，不以入队或工具成功文本代替效果。
5. 重放该事件，业务效果不重复；取消另一条受控阻塞的 Work，证明新派发停止、在途资源按真实退出释放。
6. 卸载/重载插件，证明工具与非工具贡献均撤销、旧句柄不能开始新副作用，恢复后可以重新获得合法引用。

非工具功能插件是可替换的示例业务，不在基础组件里硬编码“归档插件”。所需产物/记录服务合同由主代理在 A 阶段冻结，不能到 B 时用直写数据库补洞。另用显式选择的类型化策略 fixture 验证合法行为替换；不要求先实现复杂管理界面。

原型验收交付：一个可重复运行入口、组件装配清单、两个示例插件、只依赖公共 API 的消费者、场景断言及失败证据。移除真实事件消费者、绕开预算、撤掉插件注册或放行旧 generation，相关断言必须失败。脚本模型只是替换外部模型服务，不能替代执行循环、账本、插件 Worker 或生命周期主管。

B 通过只能称为“基础设施最小组合原型通过”；真实 provider、Desktop/Core 生命周期、渠道实机和产品替换继续分别验收。Goal 不出现在这个最小场景中：后续参考 [deepseek-harness 的分工](../19_references/deepseek-harness-goal-mode-解剖-2026-11-01.md)，作为消费公共服务、事件及 Job 的上层 driver 接入。

## 8 施工次序与分工

1. **主代理完成清单与核心合同**：逐项核对现有类型/权威，先冻结 scope、身份、所有权、状态/事件/Hook 描述和错误语义；不按想象重新建同名服务。
2. **按依赖收敛 A**：身份/配置/授权 → 预算取消租约 → Agent/Work/子代理与上下文/工具/MCP/模型端口 → 循环、可靠事件与通用扩展。独立项可以先验证，但不能跳过其前置合同。
3. **主代理评审 A 的实际证据并放行 B**：没有接管行为的空壳、只测 fake 的适配器、没有消费者的内核均不能放行。
4. **B 只做装配与消费**：发现基础合同缺口先回到 A 修正与复测，不在原型增加内部调用捷径。

已有 P0～P5、PA-01/02/05/06/07 和 I0～I4 提供 A 的工作包；跨域示例统一归 B。PA-03 的通用评审算子/任务组件可独立验证，PA-04/Goal 专用评审及续跑组合留待 B 之后。PA-08 的离线观察/验收能力随 A/B 交付，08B/08C 产品验收保持独立授权边界。

DeepSeek 只接冻结后的窄适配、DTO 映射、单组件测试或消费示例；主代理负责合同、状态机、预算/授权/取消、事务和组合骨架。新阶段划分不扩张 DS-I1-04 等既有任务范围。
