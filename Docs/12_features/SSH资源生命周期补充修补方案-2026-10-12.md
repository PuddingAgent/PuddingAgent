# SSH 资源生命周期补充修补方案

本方案实现 [ADR-096](../07_architecture/110ADR-096SSH执行前置围栏与有界终止ADR.md) 的 D2/D3，不增加新的宿主能力。对应缺陷与可重放证据见[独立复核](../14_reports/2026-10-12-SSH-R1-R5独立复核与S5暂缓结论.md)。在当前 R1–R5 的基础上修补，不回退 cwd、输出完整性和限额校验。

## 1. L1：原子令牌与完整资源租约（F8/F9）

**修改 `SshStageWorkerPool`、`SshCleanupQuarantine`、`SshResourceLease` 和协调器准入。**

1. `Start` 改成 CAS 或 `SemaphoreSlim.Wait(0)` 原子取得令牌；失败立即 busy。令牌跟随实际阶段 Task 到终态释放，不因业务停止等待而释放。不要用 `IsFull + Increment` 两步实现预留。
2. `SshResourceLease` 持有 operation slot，以及 identity/connect/exec/stdout/stderr/close/late-dispose 的任务集合或可证明等价的单一完成 Task。登记发生在调度之前；`ResourcesCompleted` 只有在集合不再接收任务且所有成员已结束后完成。观察所有 fault，记录清理失败与关闭证据，不能把“异常已观察”当成“关闭成功”。
3. 业务返回只结束业务计数；资源计数独立保留。`EndLease` 不再无条件释放仍有工作挂起的 admission。可以新增 `PendingResourceLeases` 并使 Stop 报告涵盖业务已返回但资源尚未结束的租约；不再使用 ActiveLeases=0 证明物理资源收敛。
4. 隔离区改为 `TryTransfer(lease)`，先原子预留隔离令牌，成功后才释放原 admission；失败时租约继续持有原 admission。隔离区只是可选转移目的地，不能成为丢弃资源的出口。`Pending <= Capacity` 必须始终成立。
5. 排队唤醒后、读身份之前再核对停止与资源准入状态。隔离区满时，预先排队的请求也不能开启新连接。已经在执行的请求如果无法转移，则保留原槽直到物理资源结束。
6. 关闭工作也必须有可用的有界执行容量，不能被同一池里卡死的 connect/exec 完全饿死。可在接纳操作时预留关闭执行令牌，或使用单独且有容量上限的关闭池；令牌耗尽时拒绝新的资源创建。不要用无记账 Task.Run 绕过池容量。

**门禁：**复核证据的 orphan-exec 例中，业务返回后至少一个资源计数保持非零、Stop 如实报告 pending；完成/失败该 Task 后计数归零、异常被观察。capacity=1/Core=1/三个排队请求的例子中，pending 始终 ≤1，已填满后没有新认证/建连。并发 barrier 测试 worker 预留，记录峰值，不只看结束后为零。还要验证隔离容量 0 的明确语义（禁用转移、保留原槽，或配置拒绝；不能悄悄禁用所有正常请求）。

## 2. L2：身份所有权在交付 connect 前转移（F7）

**修改 `SshResourceLease`、两个 connect 分支及 `SshTransportConnectRequest` 的所有权说明。**

用单一 owner handle 表达 `LeaseOwned → Connecting → SessionOwned → Released`；失败由 Connecting owner 释放，成功在同一受控路径中将 handle 交给会话。各状态转移必须原子且幂等。业务取消时只停止业务等待，不销毁 Connecting owner 正在读取的材料。

`TransferLateOwnership()` 不应是迟到回调里才设置的 bool。把转移放在调用 connect 之前，或者让 `WaitStageAsync` 的停止选择与 ownership handoff 成为不可分割操作。无论业务结果先返回、connect 成功/失败先发生还是二者竞争，都只有一个释放者；禁止先置 `_identityReleased` 再附加新材料而导致永不释放。

迟到完成任务必须由 L1 租约登记，不能 fire-and-forget。操作 lifetime 中仍被迟到任务使用的 token/owner 也要活到资源结束，避免业务返回即 Dispose 导致排队 worker 读取已释放 CTS。任务执行前读取稳定 token 并检查停止事实。

**门禁：**用非零合成字节保持 connect 未完成，取消后材料仍可读且逐字节不变；迟到成功或失败后恰好清零一次且零 exec。同时覆盖 Test/Execute、取消/建连 deadline、回调和 finally 并发、迟到 session Dispose 卡住。不能只检查最后 `Disposed=true`。

## 3. L3：所有同步入口与停止等待有界（F6）

**修改协调器 `ExecuteOnSessionAsync` / `StopAsync`、租约 `CloseSessionAsync`、会话关闭路径。**

- 将 exec 和 Dispose 的调用本身放进有令牌的 worker，外部线程立即取得可等待句柄。超时后句柄继续由 L1 租约持有。RequestAbort 保持非阻塞端口合同，真实实现必须满足该合同。
- worker 真正开始工作时再次执行取消/deadline 围栏；排队前的检查不够。`SshOperationLifetime` 的到期判定同时检查单调剩余额度，避免把计时器回调迟到当成预算仍有效。身份交还后、进入 connect 前也要检查。
- `StopAsync` 从进入方法就建立停止 deadline；取消回调的等待也受这个 deadline 约束。当前直接 await `_shutdown.CancelAsync()` 必须纳入有界等待和未完成资源报告。可阻塞回调是原方案要求的回归项，本轮独立复核尚未执行此项，补测不能省略。
- 清理统一使用一份从清理开始起计算的绝对预算。TERM、drain、close、Dispose 只取剩余时间；不要一处按业务剩余取 0，另一处又新开 2 秒。真实会话关闭状态机与协调器必须消费同一预算合同。
- 本地终止事实确立后，晚到的 Completed 不能抹掉 TimedOut/Cancelled；如果取得远端 exit 证据，可以保留 `ExecutionState=Exited/ExitCode`，与本地终止结果分别表达。提交事实的更新必须在可能发送前，失败映射使用这份事实而非另一份滞后的 `submitted` bool。
- `CleanupState=Completed` 需要已关闭且所要求的资源任务完成证据；faulted Dispose 或仅调用过 Abort 不能满足。结果的所有诊断拼接之后统一 Bound，避免 append 绕过 512 字符限制。

**门禁：**同步 exec/Dispose 卡在 gate 上（不只 async TCS）、Stop 取消回调卡在 gate 上，业务均按预算返回；gate 释放前计数保持占用，释放后归零。宽限后 exec 才成功、清理 fault、无 EOF、并发 Close 调用分别测试。`CloseSessionAsync` 使用共享关闭 Task 实现真正的单次状态机，不能只缓存结束后的 outcome。

## 4. 交付顺序与 S5 门禁

建议 L1 → L2 → L3，每步独立测试并原子提交；每步必须保留当前 208 项回归。先把本轮证据转成正式失败断言再修补，测试至少断言业务结果、真实工作状态、峰值计数和最终清零四个方面。

随后在冻结组件树重跑真实 OpenSSH 23 场景，保留构建身份、源码哈希与客户端/服务端证据；增强迟到连接、取消、反复资源转移、socket/reader 归零检查。真实网络的不可控交还时序继续用假端口补证，但不能用假端口的自报 Disposed 替代实际 socket 证据。

组件合同全部闭合才允许开始 S5。S5 准入表示允许实施宿主接入，S5 验收结论则由接入后的组合测试给出；两者不得混写成“必须先有 S5 完成结论才能修改宿主”。跨平台 `.ssh`/私有目录、ACL/revision、工具审批和 A6 保留原定职责。
