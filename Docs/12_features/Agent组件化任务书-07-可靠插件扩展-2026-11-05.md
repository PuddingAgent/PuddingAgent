# PA-07：可靠插件事件、后台任务与受控行为扩展

遵守[总则](Agent组件化任务书-总则与依赖-2026-11-05.md)。07A 提供可靠事件/任务，07B 提供通用贡献注册与实际插件生命周期；两者与所需基础设施共同构成完整 Goal 接入的前置。可分切片开发，不能用 Goal 专用 Hook 绕过尚未成立的通用机制，也不要求先实现所有可选扩展类型。

## 1 现状与非目标

已有 PluginManager/Worker 的代际、grant、调用 scope 和卸载排空；Core API 1.3 开放模型分类/评审 callbacks。`ExecutablePluginHook` 当前主要提供工具结果建议，宿主 `IAgentLoopHook` 的生命周期方法不等于全部已公开给插件。现有 Hook 是建议层，抛异常只跳过该 Hook；不改这个容错口径。

目标是插件免重启加载/卸载、受权消费可靠事件、启动可追踪后台任务、在声明的扩展点观察/建议/约束/改写。插件不能获得宿主任意服务，不可用 Hook 绕过授权或直接修改 Goal 终态。Worker 与宿主同用户权限运行，仍不是恶意插件的 OS 安全沙箱；本任务不交付容器/AppContainer。

### 1.1 软件功能贡献也是一等能力

插件可以新增工作区归档、命令、通知处理、审计等业务功能，提供受权策略/provider，或组合已有组件增强软件；不要求导出 Agent 工具、由模型触发或绑定活跃聊天。工具只是贡献类型之一。模块通过类型化扩展端口和已提交事件协作，新增同合同插件不修改各模块的业务分支。

扩展目录至少区分 Tool、Feature/Action、Provider/Policy、Event/Job；Connector 与受控 Web UI 贡献后续按独立合同增加。消费 API 与贡献注册授权分离；不存在通用 `GetService`、任意 DI 覆盖或反射访问内部对象的逃生口。现有 ToolPlugins 底座继续承担包/Worker/生命周期，不复制第二个插件管理器。

组件拥有 PointId/slot 的输入输出、顺序和不变量，插件拥有功能实现。平台只需在组件边界建立一次可复用的注册/分发接缝；加入后续插件不增加 `if(pluginId == ...)`。新种类扩展点可在其所属组件有界新增，不能承诺所有未知行为都能零改动插入。

## 3 07A：可靠订阅与任务 IPC 合同

拟新增公开 `IPluginEventsApi.SubscribeAsync(SubscriptionRequest, ct)`、`ReadAsync(SubscriptionRead, ct)`、`AckAsync(DeliveryAck, ct)`、`UnsubscribeAsync(SubscriptionRef, ct)`。持久任务请求立即返回 JobId/受理序号，后续查询/事件另取结果；不得把一次 IPC 请求悬挂到整个验收或子任务结束。

事件信封必含 EventId、StreamId、Sequence、Kind、SchemaVersion、OccurredAt、CausationId、CorrelationId、Workspace/业务引用、PayloadRef/Hash 和生产来源。OwnerPluginId/Generation、订阅 grant 和游标由宿主绑定，不接受请求者冒名。过滤后的 cursor 仍由服务端管理，不能把未授权事件的内容/数量作为侧信道输出。

可靠性合同：持久业务事实与 outbox 原子提交；投递至少一次；消费者以 EventId/业务操作 ID 幂等。处理成功才确认 checkpoint。处理后 ACK 前崩溃允许重投，不能声称网络 exactly-once。调用宿主的变更动作必须携带稳定 OperationId；任意外部副作用不在 exactly-once 保证内。

源日志过保留期时返回 `snapshot_required` 及可获取的受权快照边界，禁止静默跳过。progress/token delta 属可丢失遥测，独立于完成/取消/费用/评审等持久事实。慢消费者分页、有界队列、退避和死信；死信能查询原因和受权重放，不能阻塞主 Turn 提交。

Job 能力只负责统一 envelope/所有权/投递，不复制 03 的 Review 状态机。`SubmitJob` 持久受理时确定 OwnerWorkId、RootBudgetId、PluginGeneration、Deadline、所需 grant；成功回执仅 Accepted。插件回调必须释放当前 Worker 槽再等待事件；宿主检测“父同步等待子，子又等同一个插件”的依赖，拒绝或使用非阻塞 Job，不能靠增大超时解决。

## 4 07B：扩展点分类与故障语义

| 类型 | 能做什么 | 失败怎么处理 |
|---|---|---|
| Observer | 读脱敏快照，记录统计/触发已授权异步任务 | 不阻断主流程；可靠订阅按投递策略重试/死信 |
| Advice / 既有 Hook | 提供有界建议文本，不直接决定执行 | 保持既有跳过并诊断，不把异常当 veto |
| Transform | 只改声明字段，如工具结果附加展示/上下文贡献 | 验证字段/大小/来源；非法结果拒绝应用，策略明确是否保留原值 |
| Guard | 对特定动作给 Allow/Deny/NeedsApproval，且只收紧 | 系统 Deny 不可逆；必需 Guard 不可用则动作不派发，给 typed reason |
| Review provider | 提供版本化验收建议 | 走 03 Job；不能在同步 Hook 执行长评审，不能写 Goal 状态 |
| Feature / Action | 新增不经 Agent 工具调用的业务功能或命令 | 受理/效果分开，写入走领域服务，耗时工作转持久 Job |
| Provider / Policy | 在声明 slot 提供业务算法或策略，实现软件行为差异 | 宿主明确选择；必需实现缺失时不执行依赖动作；可选默认回退须预先声明，不能最后注册者胜出 |

新 Guard 是独立控制策略 API，**不改造 `IAgentLoopHook` 为控制层**。不能把原本 fail-open 的 Hook 注册自动提升为必需 Guard。

Registration 描述需 ExtensionId、PointId、Kind、SchemaVersion、OwnerGeneration、RequiredCapabilities、Order、Timeout、FailurePolicy、AllowedWriteFields。未知 point/version、重名、不支持的字段和互相冲突的独占 transform 在加载时失败，不能“后注册覆盖前注册”。排序稳定，以显式 Order 和稳定 ID 决定，不依赖字典遍历。

每次操作取得不可变 registry snapshot；提交副作用前再次检查 grant、generation、目标 revision。Transform 保存输入/输出 hash、变更字段与插件身份，不能改 tool call 身份/授权/真实退出码/预算归属，不能删除失败诊断把失败变成功。前端展示补充和传给模型的内容贡献分开授权。

### 4.1 非 Agent 作用域与策略选择

由宿主绑定 application/workspace/agent/session/work 等明确 scope 类型；工作区功能可以没有 AgentId，不得填虚构 Agent/Session 通过旧协议。长期 Job 或付费调用仍须受权 owner、deadline 和根预算。scope 协议变更由主代理冻结，不能让叶任务自行兼容或放宽权限。

Provider slot 声明 contractVersion、能力、单选/组合规则、默认实现与选择权威。加载权限不等于全局替换权限；required、priority、failurePolicy 都经宿主策略确认。配置变更只影响新的调用绑定，既有调用冻结实现版本并在提交时重验撤权。没有注册点时返回 unsupported，不通过修改其他组件私有状态弥补。

每次激活原子发布该插件的全部贡献；必需初始化失败则撤销本次注册。插件依赖的服务/扩展版本在发布前验证。取消和卸载控制与长业务调用独立；依赖插件卸载必须同时拒绝依赖者的新调用或按声明规则处理。

### 4.2 首个非工具功能插件验收切片

目标示例为“工作区产物归档/审计插件”：manifest 不含 Tool，不创建 Agent 会话或模型请求；从受权产物发布事实读取版本引用，经公共应用服务登记归档/审计条目并可查询效果。实际事件/写入端口若缺失，先由主代理创建独立契约与测试，再下发示例叶任务；本段不是开放任意文件/数据库写入。

事件处理采用稳定 EventId/OperationId 和至少一次投递，阻断发布前/提交后 ACK 前分别验证无伪成功和无重复效果。插件不调用发布者私有方法，也不伪造权威事件。另用不依赖模型的业务策略 fixture 验证同一声明 slot 可选择两种合法行为，错误输出不应用、失效策略有明确处理。

该切片与现有工具插件各完成一次真实 PluginManager/Worker 加载—使用—卸载，才证明通用插件基础；只测 `ExtensionRegistry` 或只做 ReviewAudit 格式化样例不够。

## 5 卸载、撤销与后台任务所有权

1. 卸载先拒绝新调用/订阅/任务，增加 generation 围栏，再发取消并等待实际 Worker/host callback/provider 排空。
2. 对插件 owned Job 默认请求取消；平台已明确接管的持久业务 Job 可继续，但接管必须是既有授权和持久所有权转移，不能在 unload 时偷偷改 owner。
3. 已卸载插件的旧 ACK、transform 或 job result 不能提交到新 generation。重新加载同插件不继承旧 grant，也不自动恢复被撤销任务。
4. 超时仍未排空继续维持 StopFailed/未知占用；不能为了 UI 显示“卸载完成”释放槽。真正退出后再标 Stopped 并结算。
5. 控制/取消通道不被数据 RPC 占满；协议必须有大小上限、deadline 和未知字段处理。Task 回执不含运行时对象或密钥。
6. 卸载范围包括工具、业务命令、策略/provider、订阅和界面贡献；管理投影逐项显示撤销与排空，不能只从工具目录消失就算完成。

## 6 阶段验收与取红

07A 先测 event/outbox/checkpoint 的事务故障，再测 Worker 非阻塞协议；通过后可供 03 的独立开发使用，完整 Goal 接入仍须通过 07B 与总则基础门禁。07B 必须用真实 PluginManager + 测试 Worker fixture 验证卸载，不能只测 fake manager。

必测：outbox 提交后崩溃、处理后 ACK 前崩溃、两个 dispatcher 重投、旧 cursor 过期、跨 Workspace 订阅、无 grant 的 job/transform、必需 Guard 超时、advisory Hook 抛异常仍继续、系统拒绝不被插件 Allow 覆盖、同名注册冲突、卸载期间等待 callback、旧 generation 的迟到回执、取消控制不被长请求饿死。

新增软件功能维度：零工具/零 Agent 会话下功能仍可执行；插件贡献注册权限与调用权限分离；策略显式切换、独占冲突和非法变换；依赖缺失不得半发布；卸载取消全部贡献；没有聊天也能查询状态和效果；增加第二个同合同插件不改组件业务分支。没有真实业务消费者的注册表不算本项通过。

删除 EventId 去重、放行旧 generation、将 Guard 异常改为 Allow 三种变异应分别取红。编译负例拒绝 Eventing/InvocationPipeline 引用 Host/Runtime。S5 保留现有 Plugin Runtime/Worker、配置租约、模型 callbacks 集成测试，协议升级由主代理更新冻结指纹，不为新实现删旧安全断言。

## 7 DS-PA07-A：只读事件格式化插件示例
