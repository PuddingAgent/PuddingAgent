# PA-08：执行可见性、真实模型与产品生命周期验收

遵守[总则](Agent组件化任务书-总则与依赖-2026-11-05.md)与[Guardian 运行手册](../13_runbooks/Desktop-Guardian.md)。验收分阶段贯穿开发：08A 可在 01/03/04 最小闭环后先完成；全部组件集成后再做完整产品验收。编写本任务书不触发当前 Core/Desktop 重启。

## 1 产品完成的定义

用户能看到“本轮做了什么、为什么还要继续、缺什么证据、花费多少、为什么停止”，并能取消/暂停；真实 provider 和独立插件在授权范围内完成一条闭环。普通聊天不多跑验收轮次。插件卸载、Core 重启、断线恢复不造成重复付费或取消后复活。

产品验收同时覆盖**非 Agent 软件功能插件**：没有工具调用、聊天会话或 Goal，也能加载功能、处理受权事件、观察效果并卸载。管理界面按贡献类型展示工具、功能/命令、策略/provider、订阅和 Job，不只显示聊天中的工具卡。UI 贡献在 Web 层扩展，不把业务迁入 Desktop Shell。

三种结论必须分开：离线测试通过、当前进程已加载新构建、真实模型与应用功能通过。模型回了“完成”、HTTP 202、Guardian built、旧进程仍健康，都不能替代新构建的产品验收。

## 3 UI 合同与交互

拟定 `ExecutionReviewView` 是后端 projection 的展示映射：Work/Goal/Turn/ReviewId、SnapshotRevision/LastSequence、运行与验收两种状态、停止/续跑原因、未满足条件与证据引用、当前模型/策略版本、预算 Limits/Actual/Reserved/Unknown、取消请求状态、数据新鲜度。映射端由主代理冻结；组件只渲染，不推导控制结论。

| 情况 | 必须显示 | 禁止 |
|---|---|---|
| Turn 已完成，验收 Pending | 本轮已结束／等待验收，保留工作状态 | 整个 Goal 的绿色完成标记 |
| 模型认为满足，检查未通过 | 模型建议与失败检查分别展示 | “模型已验证所有测试” |
| 下一轮已排队但未开始 | 续跑原因与待补条件、排队状态 | 宣称正在执行工具 |
| 取消已请求、provider 尚在排空 | 取消请求已受理、仍有未决调用 | 把所有占用/费用清零 |
| Unknown/报价不明/证据缺失 | 明确未知及原因，可展开原证据引用 | 用 0 元、100% 或成功替代 |
| SSE 断线、cursor 过期 | 重连/快照刷新与数据时间 | 静默使用旧数据继续显示实时成功 |

按 EventId/sequence 去重，先快照后接续事件，乱序事件不回退已确认状态；发现缺口获取新快照。详情有界分页，不把完整 stdout 塞进列表，但失败原输出/持久证据必须可打开。权限失败显示不可见，不能当作“没有任务”。暂停/取消按钮提交受权业务命令，用回执状态反馈；不要按钮一按立即本地改终态。

## 4 分阶段验收步骤

### 08A 离线闭环

使用假 provider、隔离事务库、可控时钟与真实领域组件完成以下矩阵。构建 `Tests/AgentGoalAcceptance.Tests/AgentGoalAcceptance.Tests.csproj` 后运行同一 artifacts 目录下新 DLL；禁止复用上次成功测试产物。脚本每步非零立即停止并记录命令，不 catch 成总成功。

| 用例 | 通过判据 |
|---|---|
| A+B 目标只先交 A | 自动创建一次评审、续跑补 B、满足全部必要条件后完成；零用户“继续”消息 |
| 同内容普通 Chat | 一个 Turn，零自动验收/续跑模型请求 |
| 缺证据却宣称完成 | 不能通过，展示未满足标准与证据来源 |
| 两 Worker/重复投递/ACK 丢失 | 幂等 Job、续跑命令和结算；无重复计费 |
| 取消与派发竞争、provider 忽略取消 | 线性化点前零派发；之后已派发请求保留占用并排空，最终不续跑 |
| 预留/派发/结算各断点重启 | 根预算不清零，Unknown 不自动退款，旧 owner 不能提交 |
| 插件卸载/重载/撤权 | 无旧 generation 副作用；未排空如实 StopFailed |
| 零工具功能插件 | 无 Agent 会话/模型调用，真实 Worker 消费工作区事件并经受权服务产生可查询的归档/审计效果 |
| 业务策略贡献 | 显式选择两种合法实现得到预期行为；冲突、非法输出、必需实现缺失不静默成功 |
| 全贡献生命周期 | 加载原子发布；卸载撤销工具、命令、策略和订阅；旧回调拒绝且依赖失效可见 |
| 前端断线/乱序/过期 cursor | 快照恢复后与服务端权威状态一致，既无丢终态也无伪造成功 |

### 08B 进程外部署与加载证明

Goal 组合验收前须记录总则基础门禁的证据；通用功能插件独立验收不能由 Goal 专用示例替代。增加本矩阵不代表授权执行产品部署或改变既有叶任务白名单。

1. 记录源码 revision、相关 WIP 文件 hash、构建 manifest 和目标 DataRoot；先完成独立 build/test。当前工作树含多人改动，不能把 `+dirty` 构建冒充可复现正式包。
2. 生命周期用隔离 DesktopHome/DataRoot/端口/包目录，按既有 `TestScripts/test-pudding-guardian.ps1` 验证；不拿现用 `D:\data` 跑破坏性重启测试。
3. 实际产品部署遵守 Guardian：命令受理后按 requestId 看状态，只有新包 `healthy` 且 Core readiness/稳定观察通过才算部署；rolled-back 明确判失败并报告恢复的版本。
4. 记录 Core/Desktop PID、启动时间、程序路径、实际构建身份；前端核对角标版本/hash/构建时间，证明静态产物也已部署。仅重新 build 前端或重启 Core 不够。
5. 启停/崩溃恢复/退出回收由进程外控制器判定；进程内 Agent 只测试其已加载功能。不得强杀整个 Desktop 进程树、删除锁文件或清理活跃 `temp/build`。

### 08C 真实模型与插件 smoke

使用用户选定的测试 Agent、Workspace、provider/profile 和有上限的根预算；缺失这四项就报告尚未具备实机条件，继续完成离线部分，不猜配置、不从 `D:\data` 复制 LLM secret。01 的取消/支出链路须先通过离线测试。

真实测试任务使用隔离工作区的可检查产物，例如创建满足明确内容约束的 A/B 两文件；测试报告中的实际文件 hash/内容来自独立读取，不只看模型回复。先运行强制半交付的确定性工具 fixture 验证调度，再让真实模型完成同类任务并保存 provider receipt、ReviewId、预算账目与证据。真实模型选择、弃权或失败如实计入，不承诺一次调用必然成功，不重试到成功后只留最后一次结果。

至少完成 SDK 触发与插件触发各一次；分类返回 Valid/Abstain/Degraded 均按真实语义展示，模型无法给结论并不是协议失败。验证控制逻辑的确定性与模型完成任务的质量分别统计。暂停/取消、未授权动作和插件卸载也需真实边界 smoke，但不制造无限请求耗尽预算。

### 08D 产品可见性与交付报告

每条结论附 Work/Goal/Review/Attempt ID、事件序号、配置/模型版本、命令退出码、实际 provider 用量、实际产物 hash、产品构建身份及日志引用。截图只证明展示，后端回执只证明受理，二者不能替代产物与终态证据。报告逐项写 Pass/Fail/NotRun 及原因，不以“整体绿色”覆盖未测项。

完成状态采用 `ready-for-external-deploy` → 新进程确认 → `in-product-functional-complete`；生命周期结论另列。正式发布前需主代理处理可复现构建与用户既有提交约束，本任务不授权自动 commit/push。
