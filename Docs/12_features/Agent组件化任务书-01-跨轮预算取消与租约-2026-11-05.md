# PA-01：跨轮父任务预算、取消链路与模型租约

执行与交接遵守[总则](Agent组件化任务书-总则与依赖-2026-11-05.md)。本任务是 02A、03、04 的资源前置，核心全部由主代理实现。完成标准是账户与取消在换轮、派生子任务及重启后仍有同一权威，不是多加一个累计数字。

## 1 现状、目标与非目标

已有 `ExecutionResourceScope` 的树级原子预留、`ModelResourcePool` 的取消/迟到排空；`ExecutionUsageBudgetTracker` 当前按 dispatch 建根，辅助模型预留，主循环及委派用量仍存在派发后记账。[当前合同](父任务预算与模型算子API-契约与接入-2026-11-05.md)没有持久根账户。

本任务实现：主模型、工具内模型、分类器、验收器、子代理和重试的**每次模型尝试**都先在同一根账户预留，执行后结算；根取消阻止后续派发，已派发任务继续被核账。普通单轮 Work 也使用相同机制，但不变成 Goal。

不做模型自动选型、价格窗口算法、Goal 续跑策略或 UI。不允许通过删掉重试、禁用 streaming、取消既有 provider 限流来简化接入。

## 3 必须冻结的接口与不变量

根标识为不透明 `BudgetAccountId`，宿主持久映射到已有 `GoalRunId` 或 Task/单轮 Work。`WorkId`、`TurnId`、`RunId`、`AttemptId` 各保留各自含义；下一轮换 Run，不换根账户。配置改版、Goal edit/extend、插件 reload 都不能重置实际支出；加轮数不自动增加金额/Token 上限。

拟新增内部端口形状如下；完整 DTO 由主代理在 ContractReady 时编译并冻结：

```csharp
public interface IExecutionBudgetLedger
{
    ValueTask<BudgetReservation> ReserveAsync(ReserveBudget command, CancellationToken ct);
    ValueTask<DispatchPermit> MarkDispatchedAsync(DispatchBudget command, CancellationToken ct);
    ValueTask<SettlementReceipt> SettleAsync(SettleBudget command, CancellationToken ct);
    ValueTask<BudgetSnapshot> MarkUnknownAsync(MarkUnknownBudget command, CancellationToken ct);
    ValueTask<CancelBudgetReceipt> CancelAsync(CancelBudget command, CancellationToken ct);
    ValueTask<BudgetSnapshot> ReadAsync(BudgetAccountId account, CancellationToken ct);
}
```

| 数据 | 必需字段/约束 |
|---|---|
| ReserveBudget | OperationId、AttemptId、服务端 BoundIdentity、祖先账户路径、配置/报价版本、最大输入/输出及费用预留、deadline；一次事务检查所有祖先 |
| DispatchBudget | ReservationId、AttemptId、owner fencing epoch、预期 cancellation revision；取消在此线性化点之前提交则拒绝派发 |
| SettleBudget | AttemptId、provider receipt/hash、实际输入/缓存/输出、实际费用及单位、发生时间；相同回执重放不重复计费，冲突回执拒绝 |
| Snapshot | Revision、Limits、Actual、Reserved、Unknown、ActiveAttempts、Cancelled、ReasonCode；金额与币种不能混加，未知不得显示为零 |
| CancelBudgetReceipt | 请求已记录、取消版本、尚在运行的 attempts；不是“provider 已停止”的回执 |

现有同步 `Reserve` 与 `Action dispatch` 不适合持久事务。主代理必须引入异步预留/派发确认路径并迁移消费者，**不得 `.Result/.Wait()` 隐藏数据库 I/O**。独立纯内存 scope 可留作测试实现，但一个产品根只能选一个账本，禁止内存与数据库各扣一遍。

计账规则：`null` 表示无该维度上限、0 表示耗尽；单请求输入限制不当作跨轮累计输入；并发占用与额度不同。每次 provider 重试另建 AttemptId，但沿用同一业务 OperationId。混合模型按各自冻结报价结算，不能把子代理的总 Token 按父模型单价再算一次。已有网关 usage recorder 保留实际尝试记录，以 AttemptId 关联而非二次扣款。

## 4 取消与崩溃协议

1. 原子预留所有祖先额度后排队；未派发即取消可返还预留。排队不能提前占 provider 并发槽。
2. 取得执行槽后持久写入派发意图并再次校验取消与 owner epoch，才调用 provider。取消恰好发生在此后，允许该次调用处于“已派发”，必须请求取消并最终核账，不能声称网络零请求。
3. 正常响应原子结算；真实支出超过预留照实入账并关闭新准入，不能截断实际费用制造预算达标。
4. 请求超时/取消但 provider 未结束：回执标 Unknown，槽和未决支出保留；迟到实际用量只结算一次，不把晚到正文交给已结束的调用者。
5. 崩溃后，未派发且旧 owner 已被 fencing 排除的预留可回收；已持久派发意图但没有结算的尝试保守留 Unknown，先查询可用的 provider 证据。**TTL 到期不是已停止/未收费证据。**
6. 新进程只接管持久任务，不复用旧进程的 CTS/对象租约；根取消仍有效。无法确认远端存活的尝试占用恢复后的不确定并发额度，不能通过重启绕过限制；有证据核销或明确受权的人工处置才释放。
7. 宿主关机与用户取消区分记录：前者可按既有恢复策略续接，后者不得复活。审批/等用户时释放执行槽，保留账户与业务状态。

## 5 子任务与取红验收

| 阶段 | 实施步骤 | 必须能失败的验收 |
|---|---|---|
| 01A | 先冻结端口与账户映射，内存事务 fake 跑独立领域测试 | 两个子任务并发争最后额度，只准入一个；移除祖先原子检查后测试失败 |
| 01B | 接入主模型 buffered/streaming、工具模型、子代理、显式重试 | 每次实际 provider 调用前已有预留；预算 0 时 provider spy 调用数 0；两通道行为一致 |
| 01C | 持久事务与重启调和，按每个提交边界注入崩溃 | 已预留/已派发/已结算三种断点恢复不重复收费、不返还未知、不重置根 |
| 01D | 统一取消到 root/child/plugin/model；暴露快照 | 取消排队不派发；忽略取消的 fake provider 未释放槽；迟到完成后只释放一次 |

必须补测：子任务申请超过祖先额度；同键不同参数冲突；Goal 下一轮剩余预算连续；恢复旧 owner 无法提交；主/子不同模型价格；未知金额不得再开新调用透支；输入上限和输出余额互不混淆。用持久测试库重建整个 coordinator，不能只复用同一个内存对象假装重启。

独立阶段按总则构建 `Source/PuddingExecutionResourcesTests/PuddingExecutionResourcesTests.csproj`，执行其新 DLL。S5 再跑真实存储、`ExecutionUsageBudgetTrackerTests`、`LlmInvocationServiceCancellationTests`、子代理和模型算子回归；沿用 `TestScripts/test-model-evaluation-api.ps1`，不可删旧断言。原三个冻结清单的有意变动由主代理审阅。
