# 基础设施组件清单与合同卡（A 阶段）

本文是[两阶段交付合同](基础设施服务生命周期与最小原型两阶段目标-2026-11-07.md) §2.1 要求的**输入**：11 个基础域的逐域合同卡，以及 11 个现有领域的归属与开放边界表。它回答「真实代码里权威在哪、合同是什么、缺口在哪」，**不证明任何域已完成 A 阶段**，也不代替[评估报告](../14_reports/2026-11-06-基础设施组件化评估与接入缺口.md)已经给出的结论。

## 0 核对口径

- **只核对真实代码**：类型、方法、文件路径必须能在当前工作树解析；无法确认写 `[证据不足]`，没有实现写 `[缺口]`。设计文档与已声明接口不能当作实现证据。
- **四档等级严格区分**：`ContractReady`（合同可编译）→ `ComponentExtracted`（独立程序集 + 编译期边界）→ `AdapterVerified`（真实适配器 + 测试，不是 fake）→ `ProductConsumerMigrated`（产品真实消费者已迁移；旧入口逐条列出）。四档不能互相推导。
- **快照**：核对基于工作树快照（HEAD `a385cff`，工作树含他方未提交 WIP）。合同与类型变更时，卡片应在同次评审更新；目录元数据从实际装配投影，不另维护「宣称已实现」清单。
- **不新增统一状态机**：每域沿用既有状态机与身份类型，卡片只记录真实转换，不引入覆盖全部领域的统一枚举。

### 6 扩展合同
- Hook/策略点（真实类型）：`IAgentLoopHook`（`Source/PuddingRuntime/Services/AgentLoop/IAgentLoopHook.cs:47`）——插件侧仅实现 `OnToolResultTransformingAsync`（`Source/PuddingRuntime/Services/Plugins/ExecutablePluginHook.cs:9`）；`PluginHookDefinition.Event` 白名单只有 `tool.result.advice`
- 策略点：`ExtensionKind{Observer,Advice,Transform,Guard}` × `ExtensionPoints{tool.before,tool.result,turn.start,turn.settled}`；排序 Guard→Transform→Advice→Observer，同类按 priority 降序、再按 id 升序；未授权者进 `Skipped` 而非静默改写
- IO 与可修改项：`IPluginCoreApi` 只提供工作区文本读、声明资产读、私有状态读写（单值 ≤64 KiB、≤64 文件/≤256 KiB），不暴露 `IServiceProvider`、凭据、数据库对象；只有建议文本可追加，`ProtectedToolFields.All`（`toolCallId`/`authorizationDecision`/`exitCode`/`budgetOwner`/`failureCode`）逐字段禁止变化且禁止 `failure→success`
- 必需性/超时/冲突/故障：非必需，Hook 异常只跳过该 Hook 并记诊断；`AdviseAsync` 每条 3 s、建议 ≤2048 字符，超限 `plugin.output_limit`；`ValidateTransform` 由调用方在提交前调用
