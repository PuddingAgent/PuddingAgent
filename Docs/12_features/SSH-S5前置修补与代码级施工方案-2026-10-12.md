# SSH S5 前置修补与代码级施工方案

按 [ADR-096](../07_architecture/110ADR-096SSH执行前置围栏与有界终止ADR.md) 在独立组件内修补。对应反例与当前验收结论见[审阅报告](../14_reports/2026-10-12-SSH-S1-S4审阅与S5准入结论.md)。全部修补与扩展协议门禁通过前，不新增 Runtime/Host 引用、工具、DI 或 slnx 登记；暂不引入 KeyVault、连接池与远程作业。

## 1. 文件与原子任务

每个 R 切片先新增能暴露缺陷的测试，确认现有实现取红，再修补、复绿并写对应 changelog。代码地图只维护当前合同与文件入口，不新增验收时间线。

| 切片 | 主要文件 | 交付 |
|---|---|---|
| R1 | `Validation/SshPosixCommand.cs`、`SshCommandAndRequestTests.cs`、Probe | 整个脚本的 cwd 守卫；更新精确执行串期望 |
| R2 | `Execution/SshOperationCoordinator.cs`、拟新增 `SshOperationLifetime.cs`、协调器故障测试 | 已取消零副作用、统一绝对 deadline、阶段晚返回不得继续执行 |

## 2. R1：POSIX 前置守卫

`SshPosixCommand.Compose` 保留 Quote、参数校验与 EffectiveCwd；唯一有 cwd 的格式改为：

```csharp
var executed = $"cd -- {Quote(cwd)} || exit $?\n{command}";
```

固定使用 `\n`，不使用 Windows Environment.NewLine。不拼 `set -e`，不强制把原始脚本塞进另一个 shell 或 subshell；无 cwd 时不改原始脚本。更新 `ExecutionPlan_IsTheExactApprovalString` 等断言。

**回归矩阵**：真实 POSIX shell 中，cwd 不存在/不可访问 × 分号/换行/`||`/pipeline/后台列表/末尾注释；后续 marker 输出或文件均不得出现，退出码保留 cd 失败。cwd 存在时验证单引号、空格、多个命令、here-doc、原脚本 exit code 与输出不变。纯测试验证字节精确串，真实 Probe 验证 shell 语义，不让快照字符串断言冒充执行保证。

## 3. R2：操作 lifetime 与阶段围栏

### 3.1 单一时钟与终止原因

在 `Execution/` 定义内部 `SshOperationLifetime`：

```text
StartTimestamp / EffectiveDeadline / StopReason
RemainingOperation / RemainingConnect / RemainingCleanup
CheckBeforeSideEffect()
WaitStageAsync(task, stageDeadline, lateResultOwner)
```

操作截止时间在受理时计算一次：请求/主机硬限额取 min，并折算宿主 UTC deadline；经过阶段后用 TimeProvider 的单调时钟计算剩余预算，避免系统时间调整或重复给完整超时。timer 与测试使用同一 TimeProvider。

StopReason 显式区分 caller_cancelled、host_stopping、operation_deadline、connect_deadline。保持既有公开 cancelled/timeout 码，诊断原因再细分；不凭“外部 token 没取消”就将 Core shutdown 写成 timeout。

### 3.2 检查点与晚完成

`TestCoreAsync` 与 `ExecuteCoreAsync` 共用以下流程：

```text
校验 → Check → 准入 → Check → 身份 → Check → 连接 → Check → 提交
```

`AdmitAsync` 的两个 `Wait(0)` 之前及取得槽位之后均检查终止；已经取消的请求不得调用身份端口。身份与 Connect 阶段通过 WaitStageAsync 控制返回，而非直接无限 await。

WaitStageAsync 到期后：返回终止事实，安排迟到成功/失败观察；身份晚成功清零，连接晚成功只 Abort/Dispose，失败必须被观察。结果不再回到正常状态机，不能晚恢复成 Completed，也不能晚提交 exec。

对于 GetIdentityAsync 或 ConnectAsync 的同步启动段，在 R3 的有界 worker/租约预算内调用。简单 Task.WaitAsync 只能限制 await，不能限制方法返回 Task 之前的同步阻塞；不得声称只加 WaitAsync 就完成本切片。

**故障矩阵**：Execute/Test 两入口 × 预先取消/排队取消/各阶段取消/停止/截止；身份与建连分别支持立即成功、合作取消、忽略 token、晚成功、晚失败。用 TCS 控制晚返回与调用计数，断言截止后 Connect/Execute 数为 0；测试的时间上界用于观察收敛，核心正确性靠阶段门与计数，不靠长 sleep。

## 4. R3：提交事实与资源回收

### 4.1 扩展 transport 边界

保持 BCL 合同，给会话增加非阻塞的中止请求，例如 `RequestAbort()`；它只能登记请求，实际 TERM/关闭连接在有界清理 worker 执行，不允许同步卡住调用线程。会话实现保有当前 command/channel，正常退出、取消、Stop 与 Dispose 使用同一个幂等关闭状态机。

`SshResourceLease` 持有 admission、identity、session、启动任务、两条 reader 与关闭任务。身份所有权统一为：Provider 交还后进入 lease；开始 Connect 时交给 factory/session 的合同必须明确，避免多个 finally 在任务仍读 keyStream 时提前清零。Connect 失败清零，Connect 迟到交还 session 则关闭并释放；尚未读到 identity 的超时由 late owner 处理。

在任意可能发 exec 的库调用之前将事实推进为 `SubmissionAttempted`。调用 Task 的同步启动部分与异步任务分别观察，但一旦可能触及发送，失败不可 RetrySafe；只有明确 transport 提供 `NotSent` 证据才能保持 NotSubmitted。

### 4.2 有界关闭与隔离预算

- 对 TERM、socket/channel close、reader 排空、Dispose 共用一次 CleanupGrace；每步只拿剩余预算，不能各自再等 2 秒。
- `DrainWithGraceAsync` 必须检查 winner。超时后请求 Abort；不得无条件再次 await 原 drains。
- 业务返回可以到期，lease 仍追踪尚未结束的工作；只有确认资源结束才完全释放槽位。若使用独立隔离清理槽位，它也须有固定容量，满额即 busy 并拒绝新增工作。
- 晚完成任务都要有 continuation 观察异常并关闭返回资源；worker/reader/lease 的数量须能查询和断言，不能仅用 InFlightOperations=0 证明回收。
- StopAsync 在共享期限内发取消/Abort并等待；取消回调卡住/抛错不能发生在 stop timer 启动之前的无界 await。返回仍有 pending 时准确报告，不输出“已释放独占连接”。

对任意不合作的托管假端口无法承诺强制杀线程，因此门禁应为“业务等待有界 + 资源数量有界 + late ownership 完整”。真实 SSH.NET 适配还需证明 Abort 后 OS socket/reader 结束；无法证明则保留 S5 阻断。

**回归矩阵**：exec 方法同步阻塞、发送前明确失败、发送窗口抛错、TERM 不应答、排空一个 reader 不结束、Dispose 同步/异步不结束、Stop 回调阻塞、late session/identity、多个连续超时。需断言最多 N 个 worker/租约、超限 busy、异常被观察、材料释放一次、不自动重放。

## 5. R4：输出完整性与诊断

### 5.1 结果合同

`SshBoundedOutputCollector.DrainAsync` 返回每流 drain 事实，至少包含 `EofObserved / ReadFailed / Aborted` 与累计字节；捕获预算耗尽只丢弃额外字节，继续计数。`IOException` 不能当 EOF；其他错误也须有分类事实。

`SshExecuteResult` 拟新增：

```csharp
bool OutputComplete;
string? OutputIncompleteReason; // stable code, not exception text
SshCleanupState CleanupState;   // complete | pending | failed
```

增加稳定 `ssh.output_incomplete` / `ssh.remote_exit_signal`，不增加第二套事件库。外层完整操作 Completed 要求 exit=0 且两流排空完整，无其他执行失败；已知退出码保留。只有 signal、无退出证据、读失败和正常预算截断分别测试。

captured_bytes 是保留的原始字节数，可能包含截断处未解码的 UTF-8 尾部；文档明确它不等于 JSON stdout/stderr 的 UTF-8 长度。snapshot 读取与读任务必须一致，避免“返回之后 reader 还在改计数”。

### 5.2 公开诊断

替换 `SshNetTransportSession` 的两处 `ex.GetType().Name + ex.Message`，用稳定因果码、phase 和短类型名。known_hosts 解析错误只含行号/规则码；不要包含 RawLine。诊断长度常量在组件定义，例如 512 字符，结果出边界前统一截断并标注。

用恶意 Stream/第三方异常及非法 known_hosts 行内的秘密哨兵验证公开结果不含原载荷；不把任意远端 stdout 当作诊断消息。组件内测试 SDK 的 coverage 配置显式指向 temp/test-out，TRX 与 coverage 分别核对。

## 6. R5：限额与重新准入

### 6.1 校验职责

- `SshCoordinatorOptions.Validate()`：Core 并发 1..8、queue 0..32、cleanup >0 且 ≤2 秒；在构造协调器前调用。
- `SshOperationLimits.Validate()`：connect/默认/max operation 有效且 ≤600 秒、默认≤max、output 1..256 KiB、host concurrency 1..2；invalid config 返回 config_invalid。
- `ValidateExecute`：请求负数/0 为 request_invalid；超过主机预算的合法请求只收窄；expired hostDeadline 不返回负 TimeSpan 给库。
- Core/Test/Execute 用相同 validator，避免既有 ValidateExecute 存在但协调器绕过它。底层公开 factory/session 的必要参数也做防御校验，不能只等 Runtime 加检查。

为每一上限构造 lower boundary、upper boundary、upper+1、0、负数；断言失效配置零身份/零连接。公开 hard limit 常量只有一个真源。

### 6.2 协议与门禁

重跑已有 122 用例及新增回归，不预先承诺最终用例数。先取红再复绿，记录实际数字，故障使用受控同步/异步端口而非只测试配合 token 的正常依赖。

真实 OpenSSH Probe 至少覆盖旧 16 场景，并新增：

1. cd 失败的三类复合命令，零 marker/零后续副作用；cwd 正常时复合脚本语义保留。
2. 预先取消时零客户端连接/零认证；截止后晚连接回交不得执行 marker。
3. 服务端保持连接但停止发包/不发 stdout EOF，关闭与 reader 在宽限内收敛。
4. exec 提交窗口断线，unknown 且 RetrySafe=false；取消忽略 TERM 时不宣称远端已死。
5. 多轮失败/取消/超时后资源计数回到基线；输出数据量扩大时，固定捕获与驻留内存仍有界。
6. 输出读故障与 signal-only 退出的失败映射，已知 exit code 保留。

每个协议场景固定服务端版本/构建身份，保存客户端事实和服务端认证/marker/socket证据。真实输出丢失不能只由客户端自述“已回收”验收。

通过后再独立做 S5：跨平台 `.ssh` 与私有目录解析、路径/owner/ACL、主机可见性/revision、三个 Agent 工具和审批、DI 与宿主组合测试。A6 仍按外部部署新构建 → 内部功能 smoke → 外部生命周期结论执行。

## 7. 建议提交顺序

R1 可先修，不等待资源重构；R2 固定业务围栏，R3 固定物理资源所有权，R4 接入输出事实，R5 收口预算与协议证据。每步一个提交，任一门禁未完成均保持 S5 未准入。修补期间不重构与 SSH 无关的 Host、审批或前端。
