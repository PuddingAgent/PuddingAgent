# B6 子代理委派接线方案（浏览器侧 → Runtime 侧）

## 结论先说

**出站（任务信封）能映射到既有契约字段，不需要新字段**；**入站（结论）也能挂在既有结果字段上**。
真正缺的**只有一件事**：**页面 grant 与读/写范围**如何随 `spawn_sub_agent` 下传 ——
它今天不在 `SubAgentSpawnRequest` 里，也不该由模型在 `spawn_sub_agent` 的 JSON 里自由指定。

本方案**不改任何代码**，仅记录勘查结果与施工顺序。

## 一、现状（两侧各有什么）

| 侧 | 已有的件 | 位置 |
|---|---|---|
| 浏览器侧（本会话） | 委派信封 + 校验（范围/工具/预算/期限） | `Source/PuddingBrowser.Automation/SubAgentDelegation.cs` |
| 浏览器侧 | 信封工厂（工具清单来自代码事实） | `Source/PuddingBrowser.AgentTools/BrowserDelegationTasks.cs` |
| 浏览器侧 | 有界结论（默认 2 KiB、按 UTF-8 截断、结构上不含整页） | 同上（`BrowserDelegationConclusionShaper`） |
| 浏览器侧 | 父子写租约账本（同页写互斥/接管令父子同时失效） | `Source/PuddingBrowser.Automation/SubAgentDelegationLeases.cs` |
| Runtime 侧 | `spawn_sub_agent` 工具与批量/同步语义 | `Source/PuddingRuntime/Tools/BuiltIns/Agents/SubAgentTool.cs` |
| Runtime 侧 | 子代理请求/结果契约 | `Source/PuddingCore/Abstractions/ISubAgentManager.cs` |

## 二、出站接线：信封字段 → 既有契约字段（无需新字段）

| 信封字段 | 目标字段（`SubAgentSpawnRequest`） | 说明 |
|---|---|---|
| `Goal` | `AssignedObjective`（同时进 `TaskDescription`） | 目标必须对子代理可见 |
| `ExpectedResult` | `ExpectedOutputContract` | 结论形状的约定 |
| `Deadline` | `ExecutionDeadlineUtc` | **必须不晚于** `ParentExecutionDeadlineUtc`（信封校验已保证正值；父子期限关系需在接线处再断言） |
| `RequiredTools` / `InjectedTools` | `CapabilityPolicy.AllowedToolNames` | 由 `BrowserDelegationTasks` 按代码事实产出；接线处只做"注入 ⊆ 允许"校验，**不重写清单** |
| 预算（结论 ≤2 KiB） | 无对应字段 | 属**结论形状**，入站处理（见三） |

**施工点（唯一）**：`SubAgentTool.ExecuteCoreInternalAsync` 组装 `SubAgentSpawnRequest` 的地方 ——
仅对"浏览器类任务"加一段：用 `BrowserDelegationTasks.TryCreate(...)` 构造信封 → 映射上表 → 把 `CapabilityPolicy`
收窄为信封的注入列表。**不新增字段，不改批量/同步语义**。

## 三、入站接线：父代理只收有界结论

父代理看到的是 `SubAgentExecuteResult.Reply`。**施工点**：在 `Reply` 被组装进 `spawn_sub_agent` 工具输出之前，
对浏览器类任务走一次 `BrowserDelegationConclusionShaper.Shape(reply, verificationState, budget)`：

- 默认预算 **2 KiB**（`BrowserDelegation.DefaultResultBudgetBytes`）；调用方可声明更小；
- 超限即截断并把**全文指向 Artifact**，父代理只拿到引用 + 必要摘录 + URL/operationId + 验证状态；
- 结构上不含整页快照与子代理内部对话（形状里没有这些字段）。

**依赖 B4**：全文要落成 Artifact，需要"artifact 字节归属"的决定（`Docs/00_changelog/...B4*` 登记中）。
决定未定之前，接线只能做到"截断 + 显式标记 Truncated"，**不能假装有 Artifact**（宁可父代理看到
"已截断、全文未保存"，也不要给出无效引用）。

## 四、唯一缺失的契约：页面 grant 与范围怎么来

`SubAgentSpawnRequest` 今天没有"页面 grant / 读写范围"这类字段，而设计 §9 要求：
**授权由可信 Runtime 给子代理签发**，且子代理只能取得父任务授权的子集；没有 grant 的显式 PageId 同样拒绝。

| 选项 | 做法 | 取舍 |
|---|---|---|
| **A（推荐）** | 在 `CapabilityPolicy` 之外新增一个**容量受限的浏览器委派字段**（例如 `SubAgentSpawnRequest.BrowserDelegation`：pageGrantId + 读/写 + 预算），由**工具参数之外的内部路径**填充 | 明确、可测；但动 Core 契约（跨子系统，需该侧 owner 同意） |
| B | 复用 `CapabilityPolicy` 的扩展点携带 grant | 不新增字段；但把"页面授权"混进"工具允许名单"，语义会变糊 |
| C | 让模型在 `spawn_sub_agent` 的 JSON 里自带 grant | **不可接受**：等于让模型自授页面写权，违反 §8/§9 |

**在 A 落地前，B6 的浏览器委派不得开放写入**（只读委派可先用：范围收窄到 `CanRead`，
不需要 grant 下传也能验证"子代理真的发现并调用 browser_*"这一条）。

## 五、测试计划（接线那一轮的验收）

1. **信封映射**（Runtime 侧单测）：浏览器任务 ⇒ `CapabilityPolicy` 含 `browser_snapshot`（可写时含 navigate/interact）；
   非浏览器任务 ⇒ 行为不变（回归）。
2. **期限关系**：`ExecutionDeadlineUtc ≤ ParentExecutionDeadlineUtc`，否则拒绝。
3. **结论有界**：≥3 KiB 的 `Reply` ⇒ 父代理看到的 ≤2 KiB 且 `Truncated=true`；真实引擎无法在单测里跑，故用**替身子代理**。
4. **只读委派可跑通**：选项 A 未落地时，`CanWrite=false` 的委派能完整走完（工具可见 + 结论有界）。
5. **写租约**：父持写租约时委派写同页 ⇒ 拒绝；委派结束/接管 ⇒ 父子同时失效（复用 `SubAgentDelegationLeaseTests` 的判定，
   Runtime 侧只验证"接线处调用了它"）。

## 六、明确不得改动的部分

- **不动** `SubAgentTool` 的批量/同步/模型路由语义（设计 §9：复用 `spawn_sub_agent`，不新增第二套执行器）。
- **不动** `ISubAgentManager` 的既有字段语义（选项 A 只**新增**可选字段）。
- **不把页面授权交给模型**（选项 C 永久排除）。
- **不在浏览器侧复刻 Runtime 的授权判定**：浏览器侧只给信封与工厂，签发权在 Runtime。

## 七、施工顺序（建议）

1. 选项 A 的契约提案（Core 侧 owner 评审）——**依赖产品/安全对"页面授权如何签发"的决定**（与 B1 的调用方身份同源）；
2. Runtime 接线：出站信封映射（第二节）+ 期限断言；
3. 入站结论收窄（第三节）——**依赖 B4** 的 artifact 归属决定；
4. 结线验收：第五节 1–5。

**依赖小结**：第 1 步依赖 **B1/授权决定**，第 3 步依赖 **B4/字节归属决定**。
因此 B6 的完整接线**不是纯技术施工**，而是被两个待决问题挡住的；在只读范围内（`CanRead=true`）可以先行第 2、3 步的一部分。
