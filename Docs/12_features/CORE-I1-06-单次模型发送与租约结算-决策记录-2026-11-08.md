# CORE-I1-06 单次模型发送与租约结算 · 决策记录（开工盘点）

CORE-I1-05 已第二次独立签收（`accepted`，残留 #1 已修）。本单把“每次真实模型发送 = 一个独立预算 attempt”落到传输层。**先盘点接缝与既有重发点，冻结设计与精确文件单；本记录不宣称已实现。** 未 commit/push、未部署、未调用真实模型。

## 1 传输接缝与既有重发点（源码核对，HEAD `a385cff`）

| 层 | 位置 | 现状与风险 |
|---|---|---|
| Facade | `Source/PuddingRuntime/Services/LlmInvocationService.cs`：`InvokeAsync` L52–111、`InvokeStreamAsync` L140+ | 一次 `BeginAsync` 包住整个 `_llmClient` 调用；客户端内部重试仍计一次 attempt；`ToClaim` L268 用 `request.PriceVersion` 记账 |
| 缓冲重发 | `Source/PuddingRuntime/Services/DirectLlmClient.cs`：`ChatAsync` L177–343 | `for (attempt=0; attempt<=strategy.EffectiveMaxRetries; attempt++)`；每次 `_rateLimiter` 槽 + `gateway.ChatAsync`＝**一次真实 provider 发送**；重试延迟/分类在客户端内 |
| 流式重发 | 同文件 `ChatStreamAsync` L421–…；首 delta 前重试、`hasYieldedDelta`、首块 watchdog | 仅首 delta 前允许重试；每个尝试创建一次网关流（＝一次发送）；rate-limit 槽跨流持有；首 delta 后禁止重放 |

| 预算端口/门禁 | `PlatformModelAttemptBudgetPort.cs`、`ModelAttemptBudgetGate.cs` | 现有 `Reserve→MarkDispatched→Settle/Unknown` 语义完整；缺口：未核对 `quote.PricingRuleVersion == request.PriceVersion`，未把预算输出上限回写到发送请求 |
| 租约 | `Source/PuddingModels/ModelLeaseRegistry.cs` | `CreateGeneration/Acquire/Release/Revoke` 与代际围栏齐全；**生产无消费者**（仅 Host DI 注册），本单接真实池 |
| 其他调用者 | `HostRuntimeLlmChatClient`（Review）、`LlmToolApprovalReviewer`、`CroppedLayersProvider`、`MemoryLlmInvocationClient` | Review 直接调 `IRuntimeLlmClient.ChatAsync`，有独立 `DurableModelResourcePool` 预算路径，必须回归并避免重复扣账；其余为无 BudgetAttempt 的旧路径，保持不受管 |

结论：**不搬移 DirectLlmClient 的重试循环**（其分类、首块 watchdog、delta 后不可重放语义是协议行为，搬移风险大）；采用**发送边界 observer**：在每次真实 `SendAsync`/流创建前开启一个 attempt，使重试与 Responses 重建都自然各计一次。

## 2 冻结设计：per-send attempt observer

1. **载体**：Core 新增 BCL-only `LlmSendAttemptScope`（AsyncLocal）与 `ILlmSendAttemptObserver`；Runtime 的 `LlmInvocationService` 在请求带 `BudgetAttempt` 时设置 scope，gateway/DirectLlmClient 通过 scope 调用 observer。
2. **开始发送**：每个真实发送点调用 `await scope.BeforeSendAsync(maxOutputTokensHint, ct)`；observer 每次生成**新的 AttemptId**、按当前时点重新报价（`IModelQuoteSource`）、校验 `quote.PricingRuleVersion == claim.PriceVersion`、模型 revision/币种/窗口，然后 `BeginAsync`（含 Reserve+Dispatch）；返回 permit 的 `ReservedMaxOutputTokens`。
3. **输出收紧**：DirectLlmClient 在发送前以 `config with { MaxOutputTokens = min(config.MaxOutputTokens, permit.MaxOutputTokens) }` 下发，确保预留下的上限就是实际请求上限。
4. **结束**：拿到 response/usage → `Settle`（provider receipt＝attempt+provider 标识）；异常且已发送但无法证明效果 → `MarkUnknown`；证实未发送 → `Release`；缺 usage → Unknown（不报零，不退款）。
5. **流**：attempt 覆盖整个流（首 delta 前重试＝新 attempt；首 delta 后不重发）；取消后以独立有界 token 收尾，槽位在真实退出后释放。
6. **Responses 重建**：在 `SendWithFileRebuildAsync` 的两次 `SendAsync` 前各调一次 `BeforeSendAsync`；第二次为独立 attempt，重新报价；上传/文件准备等非推理请求不计费。
7. **单一计费者**：只有 facade/observer 记账；DirectLlmClient 与网关不得再调用预算端口。Review 路径（`HostRuntimeLlmChatClient` + `DurableModelResourcePool`）保持其唯一路径，不得被 observer 包裹后双记。
8. **租约**：`ModelLeaseRegistry` 由 Host 以真实 generation 注入；发送前 `Acquire`（父取消/deadline/generation 检查），真实退出后 `Release` one-shot；busy 时沿既有排队语义并响应父取消。

- 已落地：`LlmSendAttemptScope`（Core，含 observer 合同与 AsyncLocal）、`BudgetedSendAttemptObserver`（Runtime，per-send attempt/报价/上限/结算/Unknown）、6 条 observer 测试全绿。

- slice 3 已接线（streaming 正常路径）：facade 对流式 `IStreamingSendAttemptBudgetClient` 安装 scope；`DirectLlmClient.ChatStreamAsync` 通过 `WithSendAttemptAsync` 在每次真实流发送前 Begin、正常结束按最后 usage settle、失败/放弃 Unknown；预算拒绝在 provider 之前抛出。`StreamingSend_OpensOneAttemptAndSettlesTheReportedUsage` 与 `StreamingBudgetRejection_StopsBeforeTheProvider` 2/2 通过。
- slice 4 已补（T3/T4 部分）：流首 delta 前重试（首个流请求 500→重试）产生**两个独立 attempt**（首败 Unknown、次成 settle、provider 真实发送 2 次）；重试被预算拒绝时停在第二次 provider 发送前；首 delta 前取消时 provider 发送 0 且不 settle。
- slice 5 已补（T5 核心）：`ModelAttemptBudgetGate` 在冻结报价后校验 `quote.ModelId/Revision`、`Currency`、`PricingRuleVersion == request.PriceVersion` 与 `IsUsableAt(DispatchAt)`；四项任一不符都 fail-closed 且不建预留/派发（`PriceUnknown`/`CurrencyMismatch`/`QuoteWindowMissed`）。
- slice 6 已补（T6/T7 部分）：缺 usage 的 200 响应 → attempt `Unknown`（不报零）；受管请求缺预算端口 → provider 0 次；非 marker 客户端保持 legacy 单 attempt（per-send 只属于实际传输）。
- slice 7 已接线（Responses 缓冲发送）：新增 `IPerSendBudgetGateway`，`ResponsesLlmGateway` 在首个与重建后的 `SendAsync` 前各开一个 attempt（缓冲路径解析 usage 结算，失败/缺 usage→Unknown）；`DirectLlmClient` 对 marker 网关跳过外层 attempt，避免首发送双记。用例覆盖正常 Responses 缓冲发送（1 次发送/1 attempt/settle）；文件过期重建路径已接线但**尚未有可复现测试**（需要 file 引用与 uploader fixture）。
- slice 9 已接线（并发槽/租约）：Core `IModelAttemptConcurrencyPort`；Platform `ModelLeaseConcurrencyPort` 用真实 `ModelLeaseRegistry` generation 建槽（busy 排队、父取消、revoked、重复释放幂等）；`DirectLlmClient` 在 buffered 与每次流 attempt 前 acquire、真实结束后 release，有槽端口时不再叠加 rate limiter；Host 已注册。平台端口 4/4、Runtime transport 22/22、Runtime 回归 57/57、Platform 回归 75/75。
- slice 10 已补：Gate 的 reserve→dispatch 两段提交之间取消会释放 Pending 预留（派发已提交则保留为 Unknown 路径）；Responses 重建 fixture 取红（两次真实发送=两个独立 attempt、首败 Unknown、次成 settle；第二次准入被拒时 provider 仅 1 次）；在途发送退出前槽保持占用、退出后释放一次；Host DI 探针实测解析 `ModelLeaseConcurrencyPort` 并成功 acquire/release。
- 仍未接线：T6 进程重开同库的传输层串联、T7 剩余（旧 generation/owner epoch/Review 回归）。
