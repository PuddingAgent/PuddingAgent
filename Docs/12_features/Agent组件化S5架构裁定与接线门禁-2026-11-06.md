# Agent 组件化 S5 架构裁定与接线门禁

本裁定解除离线源码开发中的架构选择阻塞，核心契约、事务、身份和执行接线仍由主代理负责。**不授权产品部署、重启、真实模型调用、读取真实凭据或 commit/push。** 08B/08C 继续 NotRun；不把技术项继续开发误写成运行中 Goal 已恢复。

这是对现有设计的裁定及源码核对，不是实现完成报告。报告中的组件 269、Platform 87、前端 47 等属于此前执行者的测试记录，本次未重跑。组件/存储的存在和离线切片通过不能合并称为“生产执行链已完成”。

## 1 六项裁定

| 项 | 裁定 | 边界 |
|---|---|---|
| 07A 流身份 | 插件订阅采用 **Workspace 流** | Conversation canonical 事件仍为原业务事实来源；不迁移原会话日志和 SSE 顺序 |
| 07A outbox | **Platform 内部 UoW**，业务变更和待投递事件同一数据库事务 | 只有 UoW 能提交；不能通过顺序调用两个 SaveChanges 假装原子 |
| PA-01 迁移 | **P2 是验收目标；P1 只可作为短期对账步骤** | 正式根账户不能从 Enforced 降级为进程内预算；按模型 attempt，不按整轮粗记 |
| PA-03 binder | 复用 **06B Review purpose**；显式 InheritPrimary 才继承 | Goal 评审挂原 Goal 根，普通 Work 评审挂原 Work 根；Worker 的实际执行边界负责一次预留和结算 |
| PA-06 配置/actor | **复用既有配置权威 + 宿主绑定调用方工厂** | AgentId 是操作目标，不是调用者；HTTP、插件、后台 Job 各自有可追溯 principal 来源 |
| 08B/08C | **保持 NotRun** | 缺部署授权/测试配置不妨碍离线实现和验证；本裁定不替用户批准这两项 |

“不改冻结端口”不是高于正确性的要求。能由内部适配满足则不改；不能表达原子性、作用域、租约或完整证据时，由主代理修订契约、消费者和测试，审阅差异后重签 ContractRelease。DeepSeek 不得自行修改指纹或绕过接口。

## 2 Workspace 订阅流：只统一分发顺序

### 2.1 身份与事实来源

沿用现有 Dispatcher 的绑定：内部 `StreamId = SubscriptionGrant.WorkspaceId`。它是在插件事件子系统命名域中的标识，不与 Conversation stream 混用；调用者不能任意填另一个 Workspace 的流。每条事件保留稳定 EventId、原始业务引用、原会话/事件引用和 payload hash，workspace sequence 仅表示该分发流的提交顺序。

会话事实不复制成第二份可修改的 canonical 状态。Workspace outbox 可保留受权、不可变的引用/必要快照，以保证待投递期间证据可读；引用对象被保留策略清除而无法恢复时返回明确 unavailable/snapshot-required，不能悬空引用后仍标送达成功。新增 Review/插件事实各自有唯一写入者。

### 2.2 过滤、扫描与 ACK

**连续性指扫描区间内没有遗漏的应投递事件，不是筛选后的 EventSequence 必须相差 1。** 当前 `SubscriptionDispatcher.AckAsync` 使用 `CursorSequence + 1` 比较每条事件；若原序列 1 是其他 kind，2 才是订阅 kind，ACK 2 会被拒绝。整页无匹配时当前 Dispatcher 也不推进扫描位置，会反复读同一页。

施工合同：

1. 服务端冻结读取页的原始区间、`ScannedThrough`、订阅 revision/grant generation、应投递的 EventId 集合；这些事实不能由插件提交伪造。
2. 持久化待投递记录与扫描进度要有原子性。可以在内部区分 ReadThrough 与 AckThrough；公共 CursorSequence 继续表示已安全处理的进度，不改成“仅看过”。
3. 不匹配 kind 的事件可自动跨过，但前面仍有应投递未确认/死信事件时不得推进确认游标越过它。整页无匹配且无未决缺口时，用服务端扫描证据推进，不要求伪造空 delivery。
4. Ack 必须绑定当前投递租约/批次与服务端 scan boundary。确认 2 不允许跳过同页应投递但未确认的 1；确认 2 可以跨过不属于订阅的 1。
5. lease claim 用持久 CAS/唯一 owner/fencing，不得仅查询全部 pending 行返回给每个 Worker。死信默认阻塞该订阅确认进度，受权重放或显式处置必须留审计，不能静默跳过。
6. 过滤后的数量与游标不对无权调用者暴露其他事件内容。跨 Workspace 订阅、旧 generation ACK、任意 nextSequence 跳跃都拒绝。

对连续提交序号且从 1 开始的流，过期判据为 `AfterSequence + 1 < OldestAvailableSequence`（实现可用等价比较避免溢出）；若序号允许洞，应改用明确的 `RetainedAfterSequence` 边界，不能依赖数值相邻。原设计写成“oldest 小于 cursor 时过期”，方向相反。例：oldest=10，after=9 可继续；after=8 必须重建快照；after=20 不因该保留边界过期。

验收至少覆盖：过滤前缀、整页无匹配、同页部分 ACK、死信、两 Worker 竞争、读取后/ACK 前崩溃、过期边界。不得仅放宽 `CursorGap` 检查，否则会从卡死变成丢事件。

## 3 同事务 UoW：先闭合 Review 完成窗口

采用内部 `IOutboxUnitOfWork.ExecuteAsync`。回调取得**已打开事务**的 Platform 写入上下文及只允许 Append 的 outbox 视图；不提供 Begin/Commit 给参与者。UoW 独占 commit/rollback/dispose。现有每次自行 `CreateDbContextAsync` 的 Store 必须有可参与该事务的内部写入口，不能把两个独立 DbContext 包进一个方法就声称同事务。

公共组件保持存储无关；PlatformDbContext 不进入 public/领域 Contracts 或插件 SDK。内部 Append 接收尚未分配 sequence 的待发布事实；commit 时分配最终序号，不能用虚构的正数满足当前 EventEnvelope 校验。必要时主代理区分 pending fact 与 committed envelope。

当前 Review 路径为：`ReviewJobCoordinator` 先 `CompleteAsync`，再 `PublishCompletedAsync`；`ReviewJobStore` 和 `ReviewEventOutbox` 各自创建 DbContext/提交。完成之后、事件写入之前崩溃，终态 Job 不再被认领，事件可能永久缺失。这是源码显示的原子性缺口，不能用“两次调用顺序正确”解释为已闭环。

裁定：主代理把完成入口收敛为单一原子 `CompleteWithEventAsync`（名称可随编译契约统一），命令包含 JobId、owner fence、expected revision、Outcome 及稳定完成事件身份。Platform 在同一事务写 Job 终态和 outbox；coordinator 不再随后独立创建随机 EventId 发布一次。事件身份按业务完成版本稳定生成，同一完成重放不能产生新事件。不存在“旧 Complete 还能直接写终态”的生产旁路。

验收在写 Job 后、写 outbox 后、commit ACK 丢失三个位置注入故障：未提交两者皆无，已提交两者皆有；重试仅得到同一完成事实。派发仍是至少一次，接收端幂等，不宣称网络 exactly-once。

## 4 PA-01：按 attempt 迁移，以 P2 为交付终点

同意渐进迁移，但不接受把“轮首/轮末影子记账”当作持久预算已生效。一轮可能有多次模型调用、重试、子代理与不同价格；它不能承担准入和真实计费权威。

- **P1 可选诊断**：使用隔离测试账户或诊断记录，按真实 AttemptId 对账；不占正式根额度、不与原 usage recorder 重复收费。持久写失败只能报告核账缺口，不能声称 Unknown 已成功入库。P1 不新增一个长期并存的预算控制器。
- **P2 必须交付**：在实际 provider 调用边界执行报价冻结 → 所有祖先原子预留 → 获取执行槽 → 校验取消/owner → 持久派发确认 → provider → 结算/Unknown。buffered、streaming、工具内模型、子代理、评审及重试都经过此边界。
- tracker 可保留本地轮数/工具计数/提示统计，不能同时作为同一金额/Token 的第二权威；不要求把所有计数逻辑一次删除才完成 P2。
- 模式在根账户创建时冻结为 Legacy/Shadow/Enforced。新功能准入开关默认关闭；启用 Enforced 的根在所有轮次、派生任务和重启后保持 Enforced。
- 账本不可达、派发确认未知时，对 Enforced 根停止新派发；不能关开关退回进程内预算继续花费。回退部署只能停止/排空这些任务，原账目保留并调和。
- 已派发意图调用抛异常不证明数据库没提交。`ReviewBudgetSequencer` 的 catch/release 分支必须按持久状态调和，不能把传输异常一概当作未派发；不得因取消 token 已取消而漏掉清理/核账。

根账户由 canonical 受理/Goal 生命周期创建并保存映射。下一轮或 reviewer 只取得子级作用域，不创建新的无支出根。预留按本次冻结报价及输入/输出上界计算，不直接拿剩余整个 EffectiveExecutionBudget 当一次调用的费用。

## 5 PA-03：模型路由、预算归属与证据

复用 `ModelPolicyResolver` 的 Review purpose；**未配置即 typed unavailable，只有 InheritPrimary=true 才继承 Primary**。不能把本文裁定当成对所有 Agent 配置自动补继承。有效策略/模型版本在受理或第一次执行绑定时冻结到持久 Job attempt；后续派发复核授权/撤销，不能偷偷换模型。

Goal Job 使用已有 Goal root；无 Goal 的 Task/Work Job 使用原持久 Work root；两者都没有则拒绝执行，不创造独立 review 无限额度。预算身份、Agent/Session、actor 与插件 generation 从可信受理记录关联，不从 Job JSON 中相信任意 ID。review-owned scope 不借用已结束父 dispatch 的内存对象。

**预留创建方：执行 Worker 所调用的共享模型执行边界。** Job Submit 只检查准入/保存身份/排队；Worker claim 后在即将调用 provider 时预留。binder 只负责绑定可信路由、身份、限额和取消，不再额外扣一次；已有 `ReviewBudgetSequencer` 必须合并或成为这个边界的唯一适配，不能与 `IModelResourcePool` 双扣。实际 usage/receipt 由执行层结算后再映射评审 DTO，不可在 `ReviewExecutor` 丢掉 Provenance.Usage 后声称账已结清。

接线前必须补齐：

1. **Waiting 不一致**：coordinator 缺证据会写 Waiting，当前 Store.FailAsync 只接受 Failed/Unknown。采用明确的延后/等待状态迁移，定义由新证据/版本事件触发再次就绪，不让缺证据变成无限重试异常。
2. **证据内容**：当前 executor 传给模型的是 kind/source/reference/hash/exit/truncated 元数据，没有产物/报告正文；hash 不能让模型知道交付内容。提供受权、有界正文或可读取的证据视图，保留截断/缺失原因；不能仅靠元数据声称语义验收。
3. **检查绑定**：仅按 epoch 读取 finished 报告不足以证明与本次产物/标准版本一致；校验 criterion/definition/objective/artifact 的冻结关系，历史 exit 0 不自动用于新产物。
4. **恢复**：claim epoch 由存储单调分配/校验；过期 Running 若已有派发 attempt，先核账，再决定重试。不能单凭租约超时再付一次模型费用。

以上闭合且假 provider 全链测试通过，才注册/启用 Review Worker。注册 DI 不是验收终点；最终仍要接入既有 Goal settlement/continuation，证明无需用户“继续”即可补交付。

## 6 PA-06：复用配置权威，明确 actor 来源

既有 Agent 配置文件服务与模型配置服务继续为唯一写入者，沿用版本 CAS、Missing/Set/Clear 和实例覆盖规则。新公共服务仅适配这些权威，不新增第二套配置文件。模型选择和配置写入都检查当前调用方权限，不只验证 ActorId 非空。

由主代理新增/复用宿主绑定工厂，返回 scoped 模型目录/策略 API：

| 入口 | 身份来源 | 禁止的替代 |
|---|---|---|
| HTTP/桌面上层 | 已认证 principal，经现有授权映射到 actor | 请求体 ActorId 或 AgentId 冒充用户 |
| 插件 callback | PluginManager 已核验 plugin id、generation、grant、执行 parent 与委派链 | 以插件名作为拥有全部 Workspace 权限的用户 |
| 后台 Review Job | 持久受理记录中的原始委托者及有界系统任务身份；执行时重验授权/撤销 | 当前 HTTP 上下文、默认管理员或虚构 Agent 用户 |

实体 `ActorId` 可以是用户或明确注册的服务主体标识，关键是有可验证的来源和授权；不能为迁就 string 字段传一个无意义的常量。无法绑定就拒绝，不回退。此项属于基础设施实现，不需要用户手动提供一个 actor 字符串才能继续离线开发。

同时修正目录分页：当前 `ModelCatalogAdapter` 的 Cursor 恒为 null，满页却可能 Complete=false。必须提供真实 continuation 或明确的有界完整结果，不能把消费者卡在无游标的 partial 页；修订必要端口由主代理负责。

## 7 实施次序与放行条件

1. **事件与原子完成**：修正过滤/ACK/保留边界、持久投递 lease；实现 Platform UoW 和 Review 完成+outbox 单事务，运行崩溃与竞争负例。
2. **P2 预算边界**：必要时短期 P1 对账，随后覆盖所有模型 attempt 和根取消；证实 Enforced 根无法降级绕过。
3. **actor 与 binder**：接现有配置权威、显式 Review 选择、Job 身份及唯一模型预留；补 Waiting/证据正文/版本/恢复链路。
4. **Goal 接入**：半交付 A → 评审缺 B → 自动补 B → 权威验收完成；Chat 不进入该路径，用户取消/目标改版不复活。
5. **维持产品 NotRun**：上述均可用独立测试、隔离 SQLite、假 provider/Worker 完成；08B/08C 等原约束下的授权/配置，不向运行中 Core 写入或重启。

新增门禁对应源码缺口，不能以原 269 条测试全绿替代。测试清单、负例和更新后的契约指纹由主代理提供；执行者不改原断言来迎合错误语义。尚未完成部分在报告中写 Partial/NotConnected，不用“全链完成”概括。
