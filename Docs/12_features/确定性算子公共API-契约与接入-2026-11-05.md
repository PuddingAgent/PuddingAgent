# 确定性算子公共 API：契约与接入

## 1. 范围与消费方式

当前开放 `skill.value` 确定性评分。插件和上层模块只依赖公共合同/SDK，不接触模型池、凭据、内部注册表、存储或 Host 服务容器。内部 `SkillValueScorer` 继续拥有公式，适配器负责输入校验与结果投影。

插件执行方法中使用：

```csharp
using Pudding.Api.Contracts;
using Pudding.ToolPlugins.AgentSdk;

var operators = Context.Operators();
var catalog = await operators.ListAsync(ct);
var receipt = await operators.SkillValue.ScoreAsync(
    new SkillValueInput("skill-id", InjectionCount: 5,
        ReadFailureCount: 0, InjectedBytesTotal: 1024),
    new OperatorCallOptions(CallId: "explicit-call-id", TimeoutMilliseconds: 3000), ct);

if (receipt.Value.Availability == ScoreAvailability.Valid)
{
    // 使用 Score 与 Scale；业务通过阈值由调用方明确选择。
}
else
{
    // Score 为 null；检查 ReasonCode/Reason，不将其折成 0 或 false。
}
```

清单使用 `coreApi: "1.2"`、`sdkApi: "1.0"`；按需申请 `operators.list` 和 `operators.skill-value.score`。只申请目录权限时目录为空，因为目录只返回当前调用有权执行的场景。纯评分工具可声明 `effects: ["none"]`；真实工具有其他副作用时必须另行声明。

可信宿主/组合根可调用 `OperatorAccessService.Open(OperatorGrant)` 获取 `IOperatorLease`，随后向消费模块注入 `IOperatorApi` 或 `new OperatorsClient(lease)`。只有宿主从真实调用上下文签发 caller/scope/deadline；消费模块不应自行把用户输入转换成授权。租约所有者负责 `await using`。此接口没有 HTTP 适配器，也不隐式创建 Agent/Host。

## 2. 组件与依赖

| 位置 | 责任 |
|---|---|
| `Source/Pudding.Api.Contracts/OperatorEvaluation.cs` | 输入、目录、回执、领域结果和绑定的 API；BCL-only |
| `Source/Pudding.Api.Sdk/OperatorsClient.cs` | 强类型 `SkillValue.ScoreAsync` 门面；不重试、不缓存 |
| `Source/PuddingOperatorAccess.Contracts/OperatorPorts.cs` | 可信 grant、后端与可撤销租约端口 |
| `Source/PuddingOperatorAccess/OperatorAccessService.cs` | 授权、调用数、输入预算、期限、指纹、返回值校验与撤销排空 |
| `Source/Pudding.ToolPlugins.AgentSdk/PluginOperators.cs` | 当前 Worker 调用的 JSON 传输适配；不允许调用方选身份或作用域 |
| `Source/PuddingRuntime/Operators/PublicApi/SkillValueAccessAdapter.cs` | 映射到原评分器，保留量纲和证据 |
| `Source/PuddingRuntime/Operators/PublicApi/PluginOperatorApiLeaseFactory.cs` | 宿主插件身份绑定及严格 RPC 路由 |
| `Source/PuddingRuntime/Operators/PublicApi/OperatorServiceCollectionExtensions.cs` | 注册后端、独立组件与插件工厂 |

依赖方向：SDK → 公共合同；Access → Ports → 公共合同；Runtime → Access，不能反向引用。新组件的 csproj 引用白名单、包/FrameworkReference 限制在构建时拒绝错误依赖。先独立测试后接 Host，插件仍在独立 Worker 装载。

配置 API 保持独立租约，算子没有借用配置的身份、方法或写入预算。Worker 复用现有异步上下文中的调用传输与 requestId 隔离；工厂端口为单独的 `IPluginOperatorApiLeaseFactory`，不会变成任意服务定位器。

## 3. 输入和结果合同

- 输入 schema 为 `pudding.skill-value-input`、版本 1，UTF-8 JSON 上限 8192 字节；未知字段、缺少必填项、负数、计数和溢出、零注入却有字节数、单边时间窗或倒置时间窗均拒绝。技能 ID 有界且不允许控制符和 `|`，避免原指纹材料分隔符歧义。
- 输入统计来自调用方。`InputOrigin="caller-supplied"` 明确不代表宿主已核对遥测；本 API 不读取技能使用日志，也不会把输入写入宿主遥测或审批审计。
- `Availability=Valid` 才有有限数值；`InsufficientData` / `Degraded` 的 `Score=null`。枚举中的 `Unknown` 是默认哨兵，不能作为成功后端结果。
- 保留原 `Scale`、原因码、证据、算子/模型/指令版本、输入摘要、阈值、置信值及种类、缓存标记和时间。原结果没有的版本/置信值保持 null；不把评分当成概率或验收通过。
- 该公开后端未装配模型、结果缓存或阈值策略；不会根据插件输入覆盖系统审批/阈值。`ImplementationVersion` 使用原公式版本量纲 `skill-value.v1/0..1`；原结果的 `SchemaVersion` 保留在 provenance 中。目录的输入版本和结果的 schema 版本是不同概念。
- `InputFingerprint` 在原始输入摘要外绑定可信 caller、workspace/Agent/session、scene 和输入 schema/version。`EvaluationId` 再绑定显式 CallId 和实现版本，用于关联；它不是幂等提交、持久回执或授权票据。同输入重跑仍会执行，原 JudgementId/时间可能不同。

## 4. 授权、生命周期与错误

加载仍须经过既有能力批准；Manager 的不可变批准集在实际 callback 时再次校验。RPC 仅有 `operators.list` 与 `operators.skill-value.score`。JSON 请求不接受 scope/actor/父任务/密钥；插件 caller 由 pluginId/activationId/工具调用 ID 的规范 JSON 摘要生成。

每个工具调用最多 16 次算子调用（目录调用也计数）；独立组件允许可信宿主收紧或设置至多 32 次。期限不超过工具/父调用截止时间，组件拒绝超过 5 分钟的 grant。单次请求默认 5 秒、最多 60 秒，仍受租约期限限制。租约串行执行，排队也占用超时时间。

撤销先关闭准入并取消，再等待已进入的后端退出；不合作的进程内后端不能被 .NET 安全强杀。本切片只登记有限的确定性后端，不把此机制宣称为任意 provider 阻塞隔离。Worker/Manager 继续使用既有卸载和回调排空协议，排空不确定时保留 `StopFailed/unknown`。

| 情况 | 结果 |
|---|---|
| 未授权 / 未安装 / schema 不符 | `permission.denied` / `operator.not_found` / `schema.unsupported`；不执行后端 |
| 不合法输入 | `request.invalid` |
| 超时 / 撤销 / 调用数耗尽 | `operation.timeout` / `delegation.revoked` / `delegation.limit` |
| 调用方取消 | `OperationCanceledException`；无自动重试 |
| 后端无效结果 / 未处理异常 | `operator.result_invalid` / `operator.failed`；不泄漏异常原文 |
| Worker 未批准 callback | `plugin.core_callback_denied` |
| SDK 无法验证返回值 | `transport.invalid_response`；不能报告评分成功 |
| 无数据或领域降级 | 返回领域结果，Score=null，原原因和证据仍在 |

算子本身无副作用不代表整个插件工具无副作用。评分异常离开工具执行方法时，Worker 保留错误码，但整次工具的 `EffectOutcome` 为 `unknown`；工具可能在调用评分前已写入状态。不能用此错误回执推断先前写入未发生或可以安全重试。

## 5. 验证入口与下一边界

`pwsh -NoProfile -File TestScripts/test-operator-api.ps1 -RunId <唯一标识>` 构建并测试独立组件/SDK、清单能力门禁和真实 Worker 评分链。产物在 `.work/operator-api/`，不启动产品、不读取生产数据、不调用 LLM。旧配置能力另运行 `TestScripts/test-plugin-agent-api.ps1`。Host 装配测试为 `Tests/PuddingHost.Tests/Hosting/OperatorApiCompositionTests.cs`。

必须取红的条件：授权前调用后端、跨 scope 指纹相同、默认零伪装未知、接受缺失字段/溢出、过期回调成功、模型后端混入、旧清单越权申请能力、卸载后旧工具继续可调用。适配测试既对照原 scorer，也固定已知输入的有效 1 分、有效 0 分和无数据空分，避免仅做相互引用的空测试。

分类/证据评审、模型租约及父预算预留/结算采用单独的 [Core API 1.3 合同](父任务预算与模型算子API-契约与接入-2026-11-05.md)，不会改变此处确定性评分的公式或引入模型调用。Goal 验收 Hook、插件贡献/替换系统算子仍按[总体设计](插件Agent配置租约与算子开放设计-2026-11-05.md)推进；任意模型调用和审批覆盖没有开放。
