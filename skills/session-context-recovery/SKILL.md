# 会话上下文恢复协议 (session-context-recovery)

## 来源与背景

- **问题**：Agent 在心跳唤醒或会话启动时不知道之前发生了什么，导致记忆连续性差（实测缓存命中率 66%，下降明显）。
- **方案**：会话启动时先检索历史会话中的关键信息，带回当前会话。
- **原则**：全文检索 > 向量检索（向量仅辅助），不依赖向量模型。
- **工具**：`query_session_logs`（已存在，全文检索）、`search_memory`（已存在，记忆库检索）。

## 何时触发

以下任一场景启动时执行本协议：

1. 心跳唤醒（Agent 从 waiting_user / 休眠状态被唤醒）。
2. 新会话启动（用户新开对话，无上下文）。
3. 长任务中断后恢复（崩溃、重启、Faulted 恢复）。
4. 子代理派生前需要父上下文（可选，视任务书要求）。

## 标准流程

### 步骤 1：确定检索范围

```
确定目标会话/时间范围：
- 最近 N 天（默认 3~7 天）
- 或指定 session_id
- 或关键词主题
```

### 步骤 2：派子代理执行全文检索

```
用 query_session_logs 做全文检索（不依赖向量模型）：
1. 先 list_days / list_sessions 找到候选会话
2. 对候选会话用 grep / messages 检索关键信息：
   - 最近的用户需求与交付物
   - 未完成任务/待办
   - 关键决策（ADR、架构选择）
   - 已知阻塞/风险
3. 将检索结果整理为结构化摘要带回当前会话
```

### 步骤 3：向量检索仅作辅助

```
- search_memory 作为补充：偏好、用户档案、长期事实
- 向量命中结果只做提示，不替代全文检索证据
- 全文检索结果优先，向量结果标注"辅助"
```

### 步骤 4：上下文注入与交接

```
将检索摘要注入当前会话，格式：

# 历史上下文恢复
- 最近活动: ...
- 未完成: ...
- 关键决策: ...
- 用户偏好: ...
- 风险/阻塞: ...
```

## 预期输出格式

子代理检索结束后，必须返回以下结构的交接单：

```
CONTEXT-RECOVERY REPORT
- 检索范围: (天数/session/关键词)
- 最近活动: (2~5 条关键事实)
- 未完成: (待办列表)
- 关键决策: (ADR/架构结论)
- 用户偏好: (从 search_memory 补充)
- 风险/阻塞: (如有)
- 证据: (session_id + 消息位置引用)
```

## 质量门禁

- [ ] 全文检索优先：query_session_logs 是主证据源，不跳过
- [ ] 向量仅辅助：search_memory 结果标注来源，不当作唯一证据
- [ ] 结果带回当前会话（写入本轮上下文或 goal.md）
- [ ] 输出包含证据引用（session_id/时间），可溯源
- [ ] 单次执行预算控制：检索 ≤ 3 个主题，摘要 ≤ 500 字
