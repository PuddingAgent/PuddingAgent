# 心跳飞书汇报 (heartbeat-feishu-report)

## 来源与背景

- **问题**：Agent 心跳结束时缺乏统一汇报格式，导致用户无法快速了解 Agent 状态、进展与风险。
- **方案**：标准化心跳飞书汇报模板与流程，Agent 在心跳结束时按模板生成简报并通过 `send_message` 投递到飞书。
- **原则**：简洁可读（≤500 字），结构固定，失败有降级策略。
- **工具**：`send_message`（向工作区 Agent 发送可见消息，最终送达飞书）。

## 汇报触发条件

满足以下任一条件时触发汇报：

1. **心跳周期结束**：Agent 完成 `heartbeat.sleep_interval` 周期任务后（主动唤醒或定时唤醒）。
2. **长任务里程碑**：任务执行超过 30 分钟且发生关键节点（编译完成、测试通过/失败、部署完成等），可在心跳内附带里程碑汇报。
3. **异常/故障恢复**：检测到 Faulted 状态恢复、服务中断恢复后，立即发送恢复汇报。
4. **用户显式请求**：用户要求发送心跳汇报时。

**不触发的情况**：
- 心跳周期内无任何状态变化且上次汇报内容未变（避免重复噪音）。
- Agent 正在处理用户实时请求中（不打断，等请求结束后再汇报）。

## 汇报模板（≤500 字）

```
## 🫀 PuddingAgent 心跳汇报

**时间**: {YYYY-MM-DD HH:mm}  **周期**: #{心跳序号}
**状态**: {active / waiting_user / sleeping / faulted→recovered}

### 本周期完成
- {关键事项 1，≤1 行}
- {关键事项 2，≤1 行}
- {关键事项 3，≤1 行}

### 进行中
- {任务名} — 进度 {%} — 剩余预算 {轮次/时间}

### 风险与阻塞
- {风险描述} / 无

### 下一步
- {计划动作，≤1 行}

---
💡 预算: 轮次 {已用}/{总额}  时间 {已用}/{总额}  缓存命中率 {%}
```

### 字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| 时间 | 当前实际时间 | 2026-08-12 14:30 |
| 周期 | 心跳序号（从 1 递增） | #7 |
| 状态 | Agent 当前运行状态 | active |
| 本周期完成 | 本心跳周期内完成的关键事项（≤3 条，每条≤1 行） | 编译通过、测试 12/12 |
| 进行中 | 当前未完成任务及进度 | 编排平台重构 — 60% — 剩余 40 轮 |
| 风险与阻塞 | 当前已知风险或阻塞 | 无 / 磁盘空间 < 5GB |
| 下一步 | 下一周期计划动作 | 继续重构 Controller 层 |
| 预算摘要 | 轮次/时间/缓存命中率 | 轮次 120/400 时间 2.5h/23.5h 缓存命中率 82% |

## 投递方式

使用 `send_message` 工具将汇报发送到飞书可见消息：

```
send_message(
  address = "agent:default.global_general-assistant.258",  // 或指定目标 Agent
  content = <上述模板填写的完整内容>
)
```

### 投递规则

1. **目标地址**：默认发送到工作区主 Agent（蜜糖 / 默认助手），由其转发至飞书群/用户。
2. **格式**：纯 Markdown 文本，不附带 voice 代码块（遵守用户偏好：飞书回复只用文字）。
3. **频率控制**：同一心跳周期内仅发送 1 次；连续 2 次汇报内容无变化时第 2 次标注 `（无变化）` 而非省略，保持心跳可见性。
4. **字数限制**：正文 ≤500 字（含 Markdown 语法字符），超出时优先精简"本周期完成"条目数。

## 失败处理策略

| 场景 | 处理方式 |
|------|----------|
| `send_message` 调用失败（网络/权限） | 重试 1 次（间隔 5s）；仍失败则将汇报内容写入 `goal.md` 末尾，标注 `⚠️ 飞书投递失败，已本地存档`，等待下次心跳补发 |
| 飞书返回限流/超时 | 降级为仅写入 `goal.md`，跳过本轮飞书投递，下轮正常发送 |
| 模板字段缺失（无心跳序号/预算数据） | 缺失字段填 `N/A`，不阻塞发送 |
| Agent 处于 Faulted 状态 | 不发送心跳汇报； Faulted 恢复后发送 1 次 `异常恢复汇报`，状态栏标注 `faulted→recovered` |
| 连续 3 次飞书投递失败 | 写入记忆库 `save_memory`（章节：运维告警），等待人工介入 |

### 降级层级

```
Level 0 (正常): send_message → 飞书送达 ✓
Level 1 (重试): 第 1 次失败 → 等 5s 重试 1 次
Level 2 (本地存档): 重试仍失败 → 写入 goal.md，下轮补发
Level 3 (告警): 连续 3 次失败 → save_memory 告警，等人工
```

## 质量门禁

- [ ] 每次心跳汇报包含全部模板字段（缺失字段填 N/A）
- [ ] 正文 ≤500 字
- [ ] 投递使用 `send_message`，不使用 voice 代码块
- [ ] 失败时执行降级策略（重试→存档→告警）
- [ ] 汇报内容可溯源（引用 goal.md / 会话日志）
