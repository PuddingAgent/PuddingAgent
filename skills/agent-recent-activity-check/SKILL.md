# Agent 近期活动检查 (agent-recent-activity-check)

## 来源与背景

v1.1.0（2026-08-11）新增：会话启动/心跳唤醒时，**先检索历史会话**，再检查近期活动。
背景：Agent 在心跳唤醒或会话启动时不知道之前发生了什么，导致记忆连续性差（缓存命中率 66%，下降明显）。

## 流程

### 步骤 0：启动时先检索历史（v1.1 新增，必做）

```
在检查近期活动之前，先执行会话上下文恢复：
1. query_session_logs 全文检索最近 3~7 天会话
   - 最近用户需求与交付物
   - 未完成任务/待办
   - 关键决策（ADR、架构选择）
   - 已知阻塞/风险
2. search_memory 补充用户偏好与长期事实（辅助，非主证据）
3. 将结果整理为 CONTEXT-RECOVERY REPORT 注入当前会话

原则：全文检索 > 向量检索（向量仅辅助，不依赖向量模型）。
详细流程见 session-context-recovery SKILL。
```

### 步骤 1：检查近期活动

```
1. query_session_logs(list_days/list_sessions) → 最近的会话列表
2. 逐会话查看最后几条消息 → 提取：
   - 当前进行中的任务
   - 最近一次工具调用/交付
   - 用户最新指示
3. 汇总为活动时间线（近 3 天）
```

### 步骤 2：对照 goal.md / 任务清单

```
1. goal_read → 读取当前目标与状态
2. 对照待办列表 → 标记已完成/进行中/未开始
3. 输出缺口：哪些任务在历史里进行但 goal 未记录
```

### 步骤 3：输出报告

```
RECENT-ACTIVITY REPORT
- 历史恢复: (启动检索摘要，见 CONTEXT-RECOVERY REPORT)
- 近期活动: (时间线)
- 进行中: (任务列表)
- 缺口: (历史有但未记录的任务)
- 下一步建议: (1~3 条)
```

## 质量门禁

- [ ] 启动检索历史在检查活动之前执行（步骤 0 必做）
- [ ] 全文检索为主，向量仅辅助
- [ ] 输出可溯源（session_id/时间引用）
